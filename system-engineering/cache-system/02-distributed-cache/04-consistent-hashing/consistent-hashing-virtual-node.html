数据倾斜问题

物理节点少时，每个节点在环上跨度不均，部分节点承载过多 key，形成热点。直接用取模更无法应对扩缩容。

虚拟节点原理

为每个物理节点映射多个虚拟节点（如 nodeA#1、nodeA#2…）均匀散布在环上。key 落到虚拟节点即归属对应物理节点，数量多了分布更均匀，单节点宕机只转移其虚拟节点对应的少量 key。

节点数建议

虚拟节点通常取 100~200 个/物理节点，足以平滑分布且 overhead 可接受。

🎯 面试问答

Q：虚拟节点解决什么？
A：让数据更均匀，避免物理节点少时的倾斜。
Q：为什么扩缩容影响小？
A：只迁移相邻区间的 key，范围极小。
Q：虚拟节点多少个合适？
A：一般 100~200 个/物理节点。
