🚀 如何安全地上线

单体架构的部署与发布

单体“一个包“的上线，也有讲究：多副本扛流量、滚动/蓝绿/金丝雀降低风险、配置外置、能回滚才是真安全。

部署形态发布策略配置外置回滚

🖥️ 一、部署形态

单实例
最简
一台机器跑一个进程
故障即全断，不推荐生产
多副本
推荐
N 个相同实例 + 负载均衡
无状态、可水平扩
💡
多副本的前提是无状态：把会话、文件等外置到 Redis / 对象存储，让任意实例都能处理任意请求。

🎯 二、发布策略：降低风险

策略做法风险
滚动发布逐台替换旧实例低，期间新旧并存
蓝绿部署备一套新环境，整体切换低，切换快、易回退
金丝雀先放少量流量到新版本最低，可灰度观察

单体也能做这些——因为“切换的是同一个包的不同实例”，并不依赖服务拆分。

🔧 三、配置外置

  • 把数据库地址、开关、密钥等放到环境变量 / 配置中心，别写死在包里。
  • 同一份构建产物，靠不同配置跑在测试/预发/生产，避免“环境差异导致的问题”。

↩️ 四、能回滚才是真安全

⚠️
任何发布都必须能快速回滚。保留上一个版本的包，出问题直接切回旧实例。配合数据库向后兼容的变更（先加字段、后删字段），回滚才不会卡在 schema 上。
