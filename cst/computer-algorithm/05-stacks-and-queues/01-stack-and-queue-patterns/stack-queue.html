🥞 栈、队列与单调栈详解

LIFO / FIFO 与"保持栈内单调"的解题利器

一句话总结

栈（LIFO，后进先出）和队列（FIFO，先进先出）是最基础的两个线性结构。它们本身简单，但衍生出两个高频考点：用栈/队列互相实现，以及单调栈——通过在入栈时弹出破坏单调性的元素，把"找左边/右边第一个更大或更小的元素"从 O(n²) 降到 O(n)。

🥞

栈 Stack

后进先出。适合"最近的匹配"：括号、表达式、撤销操作、DFS。

🚶

队列 Queue

先进先出。适合"按顺序处理"：BFS、消息队列、滑动窗口最大值。

📶

单调栈

栈内元素保持递增/递减，O(n) 找"下一个更大元素"。

📉

单调队列

双端队列维护窗口最值，O(n) 求滑动窗口最大/最小值。

一、栈与队列的互相实现

1.1 用两个栈实现队列（LeetCode 232）

class MyQueue: def __init__(self): self.in_s, self.out_s = [], [] def push(self, x): self.in_s.append(x) # 入队：直接压 in def _transfer(self): if not self.out_s: # out 空了才倒腾（关键！） while self.in_s: self.out_s.append(self.in_s.pop()) def pop(self): self._transfer() return self.out_s.pop() def peek(self): self._transfer() return self.out_s[-1] def empty(self): return not self.in_s and not self.out_s

1.2 用两个队列实现栈（LeetCode 225）

思路：入栈时压入 q1；出栈时把 q1 中除最后一个元素外的全部搬到 q2，剩下的那个就是"栈顶"，弹出后再交换 q1/q2。这样每次 pop 是 O(n)，push 是 O(1)。
（另一种更简洁的做法：用一个队列，push 后把前面所有元素依次重新入队，让新元素排到队首。）

三、单调栈：O(n) 找"下一个更大元素"

3.1 核心思想

朴素做法对每个元素向右扫描找第一个更大的，是 O(n²)。单调栈的做法是：维护一个栈，栈内元素保持单调（递增或递减）。遍历数组时，如果当前元素破坏了单调性，就不断弹出栈顶——被弹出的那些元素，它们的"答案"恰好就是当前这个元素。

3.2 单调栈模板

def dailyTemperatures(temperatures): n = len(temperatures) ans = [0] * n stack = [] # 存下标，对应温度保持单调递减 for i, t in enumerate(temperatures): while stack and t > temperatures[stack[-1]]: j = stack.pop() # 当前元素就是 j 的"下一个更大" ans[j] = i - j stack.append(i) # 当前下标入栈，等待未来被更大的元素结算 return ans # 留在栈里的说明右边没有更大的，保持 0 # 变体速记： # 找"下一个更大元素" → 栈底到栈顶单调递减，遇大则弹 # 找"下一个更小元素" → 栈底到栈顶单调递增，遇小则弹 # 求"上一个更大" → 从左往右扫，弹出前记录栈顶即为答案 # 存下标而非存值 → 才能计算距离（如天数差、宽度）

四、单调队列：滑动窗口最值

4.1 为什么需要它？

求"每个长度为 k 的窗口里的最大值"，暴力是 O(n×k)。用堆是 O(n log k)。而单调队列能做到 O(n)：维护一个双端队列，队首始终是当前窗口的最大值下标，队内元素值单调递减。

from collections import deque def maxSlidingWindow(nums, k): q = deque() # 存下标，对应值单调递减 res = [] for i, x in enumerate(nums): while q and nums[q[-1]] <= x: # ① 维护单调性：小的全弹走 q.pop() q.append(i) if q[0] <= i - k: # ② 队首已滑出窗口 → 移除 q.popleft() if i >= k - 1: # ③ 窗口已成形 → 记录队首 res.append(nums[q[0]]) return res
对比记忆：
单调栈：在一端进出，解决"某个元素左/右边第一个更大/更小"的问题。
单调队列：两端都能进出，解决"滑动窗口中的最大/最小值"问题。
两者共同点：每个元素最多进出一次 → 均摊 O(n)。
⚠️ 实现细节：
① 单调栈 / 队列里存下标而不是存值，才能算距离或判断元素是否已滑出窗口；
② 判空顺序：先 while 维护单调性，再入队，再检查队首是否过期，最后才记录答案；
③ 相等元素是否弹出要看题意（求最大值通常 <= 全弹；去重类题目可能保留）。

什么时候用栈、什么时候用队列

特征用栈（LIFO）用队列（FIFO）
处理顺序要求最近的需要先处理先来的需要先处理
典型语义撤销、回溯、嵌套匹配缓冲、调度、公平排队
经典问题括号匹配、表达式求值、DFSBFS、消息队列、滑动窗口最大值
单调变体单调栈：找下一个更大/更小元素单调队列：滑动窗口最值

判断口诀：需要处理嵌套/配对/回退 → 栈；需要处理顺序/公平/层次 → 队列。DFS 用栈、BFS 用队列，本质就是这个区别：DFS 要「深入最近发现的分支」，BFS 要「先访问完同一层」。

单调栈：O(n) 求下一个更大元素

单调栈

# 暴力 O(n²) → 单调栈 O(n)
def next_greater(nums):
    n = len(nums)
    res = [-1] * n
    stack = []                    # 存<strong>下标</strong>，且对应值单调递减
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:
            res[stack.pop()] = x  # 找到了：x 就是这些元素的下一个更大值
        stack.append(i)
    return res

# 例：[2,1,2,4,3]
#   i=0: stack=[0]        (值 2)
#   i=1: stack=[0,1]      (值 2,1)
#   i=2: x=2 > 1 → res[1]=2; stack=[0,2]
#   i=3: x=4 > 2 → res[2]=4; 4 > 2 → res[0]=4; stack=[3]
#   i=4: stack=[3,4]      (值 4,3)
#   结果: [4,2,4,-1,-1]  ✓

# 复杂度为什么是 O(n)？
#   <strong>每个元素最多入栈一次、出栈一次</strong> → 摊还 O(1)
#   这是「摊还分析」的经典例子，不是靠直觉而是靠「每元素进出各一次」
变体栈的单调性求什么
单调递减栈栈顶到栈底递减下一个更大元素
单调递增栈栈顶到栈底递增下一个更小元素
接雨水递减栈左右边界形成凹槽
柱状图最大矩形递增栈以某柱为高的最大宽度

单调栈的本质：用栈维护一个「还没找到答案」的候选序列，并保持其单调性。当新元素破坏了单调性时，说明它正是前面某些元素的答案——于是弹出并填入结果。

单调队列：滑动窗口最值 O(n)

单调队列

from collections import deque

def max_sliding_window(nums, k):
    q = deque()               # 存下标，对应值<strong>单调递减</strong>
    res = []
    for i, x in enumerate(nums):
        # 1) 移除滑出窗口的（队首下标过期）
        while q and q[0] <= i - k:
            q.popleft()
        # 2) 保持单调：弹出所有 <= x 的（它们不可能再成为最大值）
        while q and nums[q[-1]] <= x:
            q.pop()
        q.append(i)
        # 3) 窗口形成后，队首即最大值
        if i >= k - 1:
            res.append(nums[q[0]])
    return res

# 例：nums=[1,3,-1,-3,5,3,6,7], k=3
#   结果：[3,3,5,5,6,7]  ✓
#
# 为什么用 deque 而不是 list？
#   list.pop(0) 是 O(n)，会让整体退化到 O(n²)
#   deque.popleft() 是 <strong>O(1)</strong>
#
# 复杂度：每元素进出各一次 → <strong>O(n)</strong>，空间 O(k)
方法复杂度适用
暴力扫描窗口O(n·k)k 极小
堆O(n log k)需动态删除，实现较繁
单调队列O(n)最优
稀疏表（ST）O(n log n) 预处理 + O(1) 查询静态数组、多次查询

自检 Q&A

Q：栈和递归是什么关系？

A：递归就是隐式地用栈。每次函数调用压栈一层，返回时出栈。所以任何递归都能改写成显式栈的迭代形式——反之亦然。实践意义：① 递归深度过大可能栈溢出，改显式栈能规避；② 显式栈能更灵活地控制遍历顺序（如二叉树的各种非递归遍历）；③ 但递归代码通常更清晰，除非有栈风险，否则不必刻意改写。

Q：单调栈里存值还是存下标？

A：优先存下标。存值只能比较大小，存下标能同时拿到位置和值（nums[i]），很多题目要求的是距离（如「多少天后升温」）或宽度（柱状图矩形），必须知道下标。只有在完全不需要位置信息时才存值。这是一个小的选择，但存下标几乎总是更安全。

Q：单调栈和单调队列的区别到底在哪？

A：弹出方向不同，这决定了它们能处理的问题类型。单调栈只在栈顶操作（后进先出），适合处理无界范围的「下一个更大元素」——因为不知道答案在多远。单调队列在两端操作（队首弹出过期元素、队尾维护单调），适合有界滑动窗口——队首负责淘汰过期，队尾负责维护单调性。所以：求「下一个」用栈，求「窗口内最值」用队列。

Q：用栈做队列（或反之）的面试题有什么意义？

A：考察的是对两种结构本质差异的理解。用两个栈实现队列的标准做法：入队压 s1，出队时若 s2 空则把 s1 全部倒入 s2 再弹出。关键洞察是倒一次序就反转了顺序，倒两次回到原序。它的摊还复杂度是 O(1)——每个元素最多被倒一次。这类题的工程价值不大，但能检验你是否真正理解「栈反转顺序」这个性质。

标准容器与单调栈模板

from collections import deque

# 队列：一定要用 deque，别用 list
q = deque()
q.append(1)        # 入队 O(1)
q.popleft()        # 出队 O(1)  <-- 对比 list.pop(0) 是 O(n)

# deque 可以限制长度，当滑动窗口用（满了自动从另一端挤掉）
q = deque(maxlen=3)

# 栈：list 即可
st = []
st.append(x)       # 压栈 O(1)
st.pop()           # 弹栈 O(1)
st[-1]             # 看栈顶 O(1)，且不会抛异常前先判空

# 单调栈模板：找「下一个更大元素」，存下标
def next_greater(nums):
    n = len(nums)
    res = [-1] * n
    st = []                                  # 单调递增栈（存下标）
    for i in range(n):
        while st and nums[i] > nums[st[-1]]:  # 当前更大 -> 弹出并结算
            res[st.pop()] = nums[i]
        st.append(i)
    return res

量化口径：list.pop(0) 要整体前移 n 个元素，1e5 数据量下比 deque.popleft() 慢约 100～1000 倍——这是队列题超时最常见的原因。

第四层 · 原理与取舍：为什么「存下标」比「存值」好

单调栈里存什么，决定了你能不能算出距离、宽度这类信息。这是模板选型的核心取舍。

存什么能算什么算不了什么适用
存下标下一个更大元素的值和距离、柱状图宽度、接雨水的横向宽度—默认首选
存值下一个更大元素的值距离 / 宽度（不知道位置）只需值、不关心位置时
存 (下标, 值) 元组两者都有代码略啰嗦需要同时用时
弹栈条件写 > 还是 >=？

找「下一个更大元素」用 >（保留相等元素，栈内非严格单调）；如果要去重或找「下一个更大或相等」，用 >=。写错会导致相等元素互相弹掉，结果少解。

什么时候该用单调队列而不是单调栈？

要「区间最值」且区间在滑动（有明确的左右边界在移动）→ 单调队列。要「某个元素左/右边第一个比它大/小的」→ 单调栈。区别在于是否需要从队首淘汰过期元素。

两个栈实现队列，复杂度为什么仍是均摊 O(1)？

入队全进 inStack；出队时若 outStack 为空，才把 inStack 全部倒过去。每个元素一生只被倒一次，所以 n 次操作总代价 O(n)，均摊 O(1)——注意是均摊，单次出队最坏是 O(n)。
