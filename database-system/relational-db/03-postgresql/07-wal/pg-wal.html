WAL 预写日志

Write-Ahead Logging 原理、checkpoint，以及它如何支撑崩溃恢复与复制。

WAL 原理写入流程checkpoint与 MySQL redo 区别

① 什么是 WAL

Write-Ahead Logging：任何数据页修改 必须先写日志（WAL）并落盘，才能修改内存中的数据页。崩溃后只需重放 WAL 即可恢复已提交事务，无需全量刷脏页。

核心保证：先日志后数据（Force-log-at-commit）。这是 PG 崩溃恢复与流复制的共同基石。

② 写入流程

  1. 事务修改 Shared Buffers 中的页，同时产生 WAL 记录写入 WAL Buffers。
  2. COMMIT 时 WAL Buffers 刷到磁盘（受 synchronous_commit 控制）。
  3. 脏页由后台 writer / checkpoint 异步刷盘。

③ Checkpoint

Checkpoint 把内存脏页刷盘，并记录“从此点之后重放 WAL 即可”的位置。之后更早的 WAL 段可复用/归档。参数：checkpoint_timeout（默认 5min）、max_wal_size。

④ 与 MySQL redo log 的区别

维度PG WALMySQL redo
是否含逻辑信息物理+少量逻辑（便于跨版本/物理复制）纯物理页修改
复制基础WAL 流（物理流复制）binlog（逻辑，另有 redo 用于崩溃恢复）
