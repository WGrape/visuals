01中断、异常与系统调用的区别

第一层

概念与判定

类别触发源是否同步例子
中断（interrupt）外部设备 / 定时器异步网卡收包、时钟 tick、键盘
异常（exception）当前指令执行出错同步缺页、除零、非法指令、断点
系统调用（trap）程序主动请求同步syscall 指令
三者最终都走 IDT（中断描述符表），但入口不同、语义不同。异常和 trap 是「这条指令引起的」，中断是「外部塞进来的」。

02中断的分类

类型说明典型
可屏蔽中断（IRQ）可通过 cli/中断屏蔽寄存器关闭设备中断
不可屏蔽中断（NMI）硬件故障/看门狗，关不掉内存 ECC 错误、NMI watchdog
IPI（处理器间中断）一个 CPU 通知另一个 CPUTLB shootdown、调度唤醒
软中断（softirq）内核内部的延迟工作，非硬件NET_RX、TIMER、RCU

软中断名字里有「中断」，但它不是硬件中断，而是内核把下半部工作排队后，在合适时机（如中断返回、ksoftirqd）批量执行的机制。

03一次硬件中断的完整路径

图：设备 → 中断控制器 → CPU → IDT → 上半部 → 下半部。
  1. 设备完成一次 DMA，拉高 IRQ 线（或发 MSI-X 消息）。
  2. 中断控制器（x86 的 APIC / ARM 的 GIC）把中断路由给某个 CPU，写其中断向量。
  3. CPU 在两条指令之间检查到中断，保存当前现场（RIP/RFLAGS/寄存器）到内核栈。
  4. 按向量查 IDT，跳到对应的汇编入口，再进入 C 的 do_IRQ()。
  5. 执行该 IRQ 的上半部：确认设备、读状态、清中断、把耗时工作挂到下半部。
  6. 返回前触发下半部（softirq/tasklet）或在 ksoftirqd 里稍后执行。
  7. 中断返回，恢复现场，继续原来的指令流。

04IDT 与中断向量

IDT 是一张 256 项的表，每项描述「这个向量号该跳到哪、用什么特权级、是中断门还是陷阱门」：

向量范围用途
0–31CPU 异常：0 除零、13 通用保护、14 缺页、3 断点
32–47传统 8259A 硬件 IRQ（现代多用 APIC 动态分配）
48–255设备 IRQ、IPI、系统保留
int 0x8032 位老式 syscall 入口（64 位用 syscall 指令，不走向量）

关键区别：中断门进入时自动关中断（防止嵌套同一 IRQ），陷阱门不关。缺页异常用陷阱门，因为处理中可能还要响应其他中断。

05上半部与下半部：softirq / tasklet / workqueue

机制运行上下文能否睡眠适用
上半部（hardirq）中断上下文否必须极快：清中断、读状态
softirq软中断上下文（ksoftirqd）否网络收发（NET_RX/TX）、定时器、RCU
tasklet软中断上下文否老式延迟工作，正被淘汰
workqueue进程上下文（kworker）是需要睡眠/阻塞的耗时工作
threaded IRQ独立内核线程是实时性要求高、处理复杂
中断上下文不能睡眠：不能调用 kmalloc(GFP_KERNEL)（可能睡眠）、不能 mutex_lock、不能访问用户态内存（可能缺页）。违反会导致 BUG: scheduling while atomic。

06中断上下文与并发约束

第三层

排障与边界

  • 关中断时间要短：上半部里长时间 local_irq_disable() 会抬高整个系统的中断延迟，实时场景致命。
  • 自旋锁 + 中断：进程上下文与中断共享数据时，必须用 spin_lock_irqsave，否则中断在当前 CPU 上死锁。
  • 每 CPU 变量：中断可能在任何 CPU 上跑，统计计数要用 this_cpu_inc 而不是全局变量。
  • 中断嵌套：现代内核默认不在上半部嵌套同类中断，但 NMI 可打断一切。

cat /proc/interrupts

# 看软中断统计（NET_RX 飙升常是收包打满）
cat /proc/softirqs

# 中断是否集中在单个 CPU（亲和性问题）

现象可能原因怎么查
某 IRQ 计数疯涨设备故障/中断未正确清除（中断风暴）/proc/interrupts 两次取样对比
%soft 很高NET_RX 软中断打满（收包过多或单队列）top 看 si；开 RPS/RSS 多队列

MSI-X 多队列网卡可把不同队列的中断绑到不同 CPU，配合 RPS/RFS，是解决 si 单核打满的标准做法。

08原理与取舍

第四层

原理与取舍

为什么非要分上下半部？因为中断处理期间，本 CPU 上其他工作都被打断。上半部越短，系统响应越及时；但设备状态稍纵即逝（如网卡环形缓冲区会溢出），所以「必须立刻做的」留在上半部，「可以稍后做的」推给下半部。

设计收益代价
上半部极简中断延迟低状态需暂存，逻辑分散
softirq 同 CPU 执行缓存友好、无调度开销不可睡眠，长任务阻塞 ksoftirqd
workqueue 进程上下文可睡眠、可阻塞有调度延迟
threaded IRQ可设实时优先级线程切换开销

深入 Q&A

Q：缺页为什么是异常而不是中断？
A：它是「当前这条访存指令」引起的同步事件，必须精确知道是哪条指令、哪个地址，处理完要重新执行该指令——这是异常的语义，不是异步中断。

Q：NMI 为什么关不掉？
A：NMI 用于报告「系统已处于危险状态」（如内存校验错、硬件看门狗），如果允许屏蔽，就可能掩盖致命错误。所以它绕过 cli。
