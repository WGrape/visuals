什么是 CDC

CDC（Change Data Capture，变更数据捕获）把数据库的增删改实时抽出来。相比定时全量比对，CDC 延迟低、对源库压力小、不漏变更。

Canal 原理

Canal 伪装成 MySQL 的从库，拉取主库的 Binlog 并解析成结构化变更事件，再投递到 Kafka。下游消费者（数仓、缓存、搜索引擎）订阅这些事件即可保持同步。

全量 vs 增量

方式延迟对源库压力典型用途
全量高（T+1）扫全表大首次初始化
CDC 增量秒级仅读 Binlog实时同步

应用场景

  • 缓存一致性：订单变更实时更新 Redis。
  • 搜索索引：商品变更同步到 ES。
  • 数仓近实时入湖。

🎯 面试问答

Q：Canal 会影响主库性能吗？
A：不会，它只是 Binlog 的消费者，主库写 Binlog 本就发生，额外开销极小。
Q：Canal 和 Kafka Connect 怎么选？
A：Canal 专注 MySQL Binlog 解析、生态成熟；Kafka Connect 更通用、支持多种源，按团队栈选择。
