01分区类型

类型写法要点适用
Hash按哈希取模打散离散主键、避免热点
Range按范围切分时间序列、自增 id
List枚举值分组地域/类型固定集合
Key类似 Hash，内置与 Hash 类似
要点：分区数建议取 2 的幂；单分区数据量过大仍会成热点，分区不是越多越好。

02一级 / 二级分区

CREATE TABLE orders (
  id BIGINT,
  user_id BIGINT,
  gmt_create DATETIME,
  PRIMARY KEY(id)
) PARTITION BY RANGE(TO_DAYS(gmt_create))
  SUBPARTITION BY HASH(user_id) SUBPARTITIONS 8
  (PARTITION p202401 VALUES LESS THAN (TO_DAYS('2024-02-01')),
   PARTITION p202402 VALUES LESS THAN (TO_DAYS('2024-03-01')));
要点：二级分区常是「时间 Range + 用户 Hash」组合：前者方便按时间清理，后者打散写入。

03OBProxy 路由

# OBProxy 是无状态接入层，前端统一连它
obclient -h 10.0.0.10 -P 2883 -u root@tenant1 -p'pwd' -D mydb
# 写 SQL 时带上分区键，OBProxy 才能精准路由到目标分区的 leader
SELECT * FROM orders WHERE user_id = 123 AND gmt_create >= '2024-01-01';
要点：OBProxy 依据 租户 + 分区键 路由；不带分区键的查询会广播到多个分区，延迟明显上升。

05常见疑问

问：分区键怎么选？

选高频过滤列（如 user_id），让大多数查询能落到单分区；避免选低基数列导致广播。

问：OBProxy 和直连 observer 区别？

直连 observer 需自己知道分区 leader 位置；OBProxy 屏蔽路由细节，生产应走 OBProxy。

第一层 · 概念与判定

OceanBase 用分区把大表水平切分，结合 Paxos 多副本实现高可用；OBProxy 是无状态 SQL 路由层，把请求转发到数据所在节点。

  • 分区类型：hash / range / list / 二级分区（组合）。
  • OBProxy 不存数据，只做路由与连接管理，可水平扩展。
  • 判定：大表热点或单节点扛不住 → 分区；连接管理/路由问题 → 看 OBProxy。

第二层 · 参数·命令·量化

创建分区表与路由：

示例

CREATE TABLE orders (
  id BIGINT, user_id BIGINT, ...
) PARTITION BY HASH(user_id) PARTITIONS 16;

-- OBProxy 路由依赖 location cache；弱一致性读走备副本
SELECT /*+ READ_CONSISTENCY(WEAK) */ * FROM orders WHERE user_id=10;

分区数经验：单分区数据量控制在合理范围（如数十 GB 内），过多增加元数据开销。

第三层 · 排障与边界

  • 分区键选错致热点：按低基数字段分区某分区被打满；选高基数且查询常带的列（如 user_id）。
  • 跨分区事务：涉及多分区需两阶段提交，延迟与复杂度上升；尽量让事务命中单分区。
  • OBProxy 连接风暴：客户端直连 OBProxy 但连接池没复用；前端配连接池。
  • 路由不准：location cache 过期导致转发错节点；关注 RS（rootservice）元数据。

第四层 · 原理与取舍

OB 把分区作为多副本与负载均衡的基本单位，Paxos 保证每分区多数派一致；OBProxy 保持「薄」——只查 location cache 路由、不落数据，所以可无状态水平扩展、故障切换对客户端透明。分区数与副本数的解耦让扩缩容更灵活。

OBProxy 和直连 Observer 区别？

直连需客户端自己知道数据位置；OBProxy 统一路由、屏蔽拓扑变化，生产推荐走 OBProxy。

二级分区解决什么？

先按一个键 hash 打散、再按时间 range 便于过期，兼顾均衡与生命周期管理。
