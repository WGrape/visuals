CDN 避坑与安全指南

防盗链、防流量浪费、防回源雪崩 —— 上线前必须想清楚的几件事

① 防盗链② 防流量浪费③ 缓存陷阱 ④ 回源雪崩⑤ 源站安全⑥ 合规与预警

1防盗链：别让别人的网站白用你的带宽

盗链 = 别人把你的资源（图片/视频/下载包）直接嵌在自己页面里，流量和费用却算在你头上。四类防护从弱到强。

1.1 Referer 校验（最简单，易被绕过）

检查请求头 Referer，只允许白名单域名访问；空 Referer（直接打开）按业务决定放行与否。

# Nginx 边缘节点：只允许本域与空 Referer
location ~* \.(jpg|png|mp4)$ {
    valid_referers none blocked server_names
                   *.example.com example.com;
    if ($invalid_referer) {
        return 403;        # 盗链一律拒绝
    }
    ...
}
局限：Referer 可被伪造、可被浏览器省略；仅作第一道低成本防线，不能单靠它。

1.2 签名 URL / 时间戳防盗链（推荐）

在 URL 里带一段签名 + 过期时间，CDN 校验签名合法且未过期才放行。即使链接被复制，过期即失效，且无法伪造。

# 例：https://cdn.x.com/a.jpg?sign=xxxx&exp=1700000000
# 服务端用密钥对 path+exp 做 HMAC；CDN 侧校验
# Nginx 用 secure_link 模块：
location / {
    secure_link $arg_sign,$arg_exp;
    secure_link_md5 "$uri$arg_exp $secret";  # 与服务端同算法
    if ($secure_link = "")  { return 403; }  # 无签名
    if ($secure_link = "0") { return 410; }  # 已过期
}

适合私有资源（付费视频、用户文件）。公有静态资源（官网图片）则用 1.1/1.3 即可。

1.3 Token 鉴权（会话级）

结合用户登录态下发临时 Token，CDN/源站校验 Token 有效性。常见于「会员才能看」的内容。可与签名 URL 叠加。

1.4 UA / IP 校验

拦掉明显非浏览器的批量爬取 UA、或已知恶意 IP 段。属辅助手段，单独使用强度低。

2防止流量浪费：钱是省出来的

① 防盗刷 / 限频

恶意刷量会瞬间烧光流量包。用单 IP/QPS 限流、人机校验（验证码/滑块）、IP 黑名单，对异常 UA 直接拒。

# Nginx 限流
limit_req_zone $binary_remote_addr zone=cdn:10m rate=20r/s;
limit_req zone=cdn burst=40 nodelay;

② 缓存策略优化

静态资源（带 hash 的 JS/CSS/图片）长缓存甚至永久，命中率越高回源越少、流量越省。避免对动态接口缓存。

③ 大文件用 Range 分片

视频/安装包开启 Range 请求与分片缓存，用户拖进度只拉所需片段，避免整文件重复下载。禁用则每次从头拉满。

④ 开启压缩

对文本类（JS/CSS/HTML/JSON）启用 gzip / brotli，体积常降 60%~80%，直接少计流量。

⑤ 流量封顶 / 带宽限速

设单 URL / 单 IP / 全站带宽上限，超出即限速或断，防止突发把预算打穿。云 CDN 多有「流量封顶自动停用」开关。

⑥ 监控与告警

盯「带宽曲线、命中率、回源比、TOP URL」。命中率突降或带宽陡增立即告警——多数盗刷/误配都是曲线先露馅。

最省钱的两件事：把静态资源命中率做高（长缓存 + 不变文件名）、文本开压缩。这两项往往比砍单价更立竿见影。

3缓存配置的常见陷阱

陷阱1：缓存了不该缓存的

带 Set-Cookie 或用户相关参数的响应被当成公用缓存，导致串号/串数据。务必对含用户态的接口设 Cache-Control: private/no-store 或不缓存。

陷阱2：缓存键冲突

用 $uri 当键但忽略 ? 后的业务参数（或忽略关键参数），不同内容被当成同一份。确认 proxy_cache_key 含必要维度（如 $is_args$args 的关键字段）。

陷阱3：Vary 头处理不当

按 Vary: Accept-Encoding 等拆分缓存时，键组合爆炸或漏配，造成重复回源或内容错乱。明确需要哪些维度再开。

陷阱4：误删/漏刷新

发版后旧资源仍在边缘，用户看到脏数据。建立「发版即刷新/改 hash 文件名」流程，减少主动刷新依赖。

上线前自测：用 curl -I 看响应头 X-Cache-Status / Age / Cache-Control，确认识别到的命中/未命中与预期一致，避免「以为缓存了其实没缓存」。

4回源风暴与雪崩防护

热点资源同时失效、或大促瞬间海量请求未命中 → 全部回源 → 源站被打垮（雪崩），连锁整站不可用。三道防线：

① 回源合并

Nginx proxy_cache_lock on：同一资源只放一个请求去回源，其余排队等结果，避免「惊群」。

② 源站限流 / 队列

源站侧限制并发回源数，超出排队或快速失败，保护自身不被瞬时打爆。

③ 用旧值兜底

proxy_cache_use_stale error timeout updating：源站异常时返回过期内容（降级），保住可用性。

5源站安全：别让 CDN 把源站暴露给全世界

源站隐藏（最关键）

源站只接受CDN 回源 IP 段的访问，其他一律拒绝。否则别人绕开 CDN 直打源站，既暴露 IP 又被 DDoS。云 CDN 提供回源 IP 列表， firewall 白名单即可。

全链路 HTTPS

用户→CDN、CDN→源站都走 HTTPS，避免中间人篡改与明文泄露；开启 HSTS、证书自动续期。

WAF / 防护

在 CDN 层挂 WAF 拦截 SQL 注入、XSS、恶意爬虫；配合 DDoS 清洗（商业 CDN 自带）。

IP 白名单 / 鉴权回源

回源请求加共享密钥或 mTLS，防止有人伪造 CDN 身份直接回源拉数据。

典型事故：只接了 CDN 却忘了锁源站端口 → 攻击者扫到源站 IP 直连打满带宽。上线 checklist 必须含「源站仅对回源 IP 开放」。

6内容合规与成本失控预警

内容合规

用户上传内容经 CDN 分发，需做审核（涉政/涉黄/侵权）。违禁内容被大规模分发后果严重；可配合「先审后发」与违规 URL 快速刷新下架。

成本失控预警

设「日带宽/月流量」预算阈值，超限自动短信告警甚至停服。定期看账单按 URL 维度拆分，揪出异常大户。

一句话总结：防盗链挡外部白嫖、回源合并挡内部雪崩、源站隐藏挡直连攻击、命中率与压缩挡账单——四件事做齐，CDN 才真正「既快又稳又省」。
