Go 一切传参都是值拷贝

指针基础

& 取地址，* 解引用

指针存的是变量的内存地址；通过指针可以修改原变量，也能在不拷贝大对象的前提下共享数据。

x := 10
p := &x          // p 的类型 *int，指向 x
*p = 20         // 通过指针改原值
fmt.Println(x)  // 20

// 指针的零值是 nil
var q *int       // nil，未指向任何变量
函数传参：值拷贝

为什么有时候改了、有时候没改

传值类型（struct/array）时，函数内改的是副本，不影响原值；传指针或引用类型时，副本仍指向同一份底层数据，所以能「改到」。

func inc(v int) { v++ }          // 改副本
func incp(v *int) { *v++ }      // 改原值

x := 1
inc(x);  fmt.Println(x) // 1
incp(&x); fmt.Println(x) // 2
引用语义类型

slice / map / chan 的头部含指针

它们本质是个「小头部（含指向底层数组/桶的指针、长度、容量）」。传参时头部被拷贝，但头部里的指针仍指向同一底层数据。

func appendTo(s []int) { s = append(s, 1) } // 可能换底层数组，原 slice 看不到
func change(m map[string]int) { m["k"] = 1 } // 改的是同一份桶，原 map 可见

// 安全做法：返回新的 slice
func add(s []int) []int { return append(s, 1) }
何时用指针

经验法则

需要「修改原值 / 避免大对象拷贝 / 表示可空 / 共享可变状态」时用指针；小的值类型直接传值更清晰。

场景建议
修改调用方变量用指针接收者/参数
大 struct（>几百字节）用指针避免拷贝
方法可能修改接收者用指针接收者
小值/想不可变用值
常见坑

nil 指针与逃逸

指针与逃逸的注意点。

⚠️ 解引用 nil 指针会 panic。map 的零值是 nil，读取可返回零值但写入必 panic；slice 的 nil 可直接 append（会分配）。另外，取地址的局部变量可能「逃逸」到堆上，由 GC 管理——这是编译器自动决定的。

指针接收者一致性

一个类型的多个方法，接收者风格要统一（要么全值、要么全指针），混用会让调用方困惑。

指针的本质：一个装着地址的变量

x := 42 p := &x // p 的类型是 *int，值是 x 的地址 fmt.Println(p) // 0xc0000120a0（地址） fmt.Println(*p) // 42（解引用，取值） *p = 100 // 通过指针修改 fmt.Println(x) // 100 // 零值是 nil var q *int // nil if q != nil { fmt.Println(*q) // 解引用前必须判断 } // new 分配零值并返回指针 r := new(int) // *int，指向的 int 为 0 *r = 7
指针保存的是地址，Go 不支持指针运算
& 取地址得到变量的地址。
* 解引用读写指针指向的值。
nil 零值未初始化的指针是 nil。
无指针运算不能 p++，安全性更高。

什么时候该用指针

场景用值用指针
小的基本类型（int、bool）✅除非需要修改
需要函数内修改外部❌✅
大结构体作为参数❌ 拷贝开销大✅
需要表达「可能没有」需另加标志✅ 用 nil 表达
含不可拷贝字段（锁）❌✅
切片元素需要长期引用拷贝会失效✅
// 需要修改外部变量 → 指针 func reset(u *User) { u.Age = 0 } // 大结构体 → 指针避免拷贝 func process(cfg *Config) { ... } // Config 很大 // 可选语义 → nil 表示没有 func find(id int) (*User, error) { // 没找到时返回 nil, ErrNotFound } // 含锁的结构体必须用指针 type SafeCounter struct { mu sync.Mutex // 拷贝会复制锁状态 n int } func (c *SafeCounter) Inc() { c.mu.Lock(); defer c.mu.Unlock(); c.n++ }

不要过度使用指针：指针会让变量逃逸到堆、增加 GC 压力，也带来 nil 判断负担。小对象传值的开销往往比想象中小。

指针与三种引用类型的区别

slice 自带指针

slice 头部就含指针，所以传值也能改元素。

func modify(s []int) { s[0] = 99 // ✅ 能改，底层数组共享 s = append(s, 1) // ❌ 只改了副本的头部 } // 需要改变长度或重新分配时： // ① 返回新 slice s = append(s, 1) // ② 或传指针 func modify(sp *[]int) { *sp = append(*sp, 1) }

map 与 channel

它们本身就是引用语义的句柄，传值即可改内容。

func add(m map[string]int, k string, v int) { m[k] = v // ✅ 直接生效 } // 只有需要「替换整个 map」时才传指针 func reset(mp *map[string]int) { *mp = make(map[string]int) }

指针与逃逸

  • 返回局部变量的指针是安全的，Go 会把它放到堆上
  • 这就是逃逸分析：-gcflags=-m 可查看
  • 逃逸不是 bug，但过多会增加 GC 压力
  • 不要为了「避免逃逸」扭曲代码，先测量

深入自检

返回局部变量的指针安全吗？

安全。编译器会通过逃逸分析判断这个变量的生命周期超出了函数，于是把它分配在堆上，由 GC 负责回收。这与 C 返回栈变量地址是未定义行为完全不同。

为什么 Go 不支持指针运算？

为了内存安全。指针运算能让你访问任意地址，破坏类型安全与 GC 的对象追踪。Go 用 slice（带边界的视图）替代了大部分指针运算的用途，需要极致操作时才有 unsafe 包。

指针一定比值更快吗？

不一定。传指针省了拷贝，但可能引发逃逸与堆分配，还会增加一次间接寻址（可能缓存未命中）。小对象（几个机器字）传值通常更快；大结构体才明显值得用指针。

nil 指针解引用会怎样？

会 panic（invalid memory address or nil pointer dereference）。因此所有可能为空的指针在使用前都要判断。设计上尽量让零值可用，可以大幅减少这类判断。

什么时候该用 *[]T 这种指针？

几乎不用。只有当你需要在函数里替换整个 slice 头部（比如重新 make、置 nil）时才需要。绝大多数场景直接返回新 slice 更清晰：s = append(s, x)。
