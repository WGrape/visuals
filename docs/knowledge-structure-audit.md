# 知识目录结构核查（2026-10-09）

## 依据与范围

按 [README](../README.md) 的物理目录规则检查五个知识域：一级固定、二级是有 `index.html` 的学科、三级及更深目录编号、课程从四级开始，课程必须有可达卡片。对所有课程做路径、标题和文件内容重复扫描；对跨学科同名主题检查课程内容与教学目标。

本轮结果：**5 个知识域、34 个二级学科、209 个三级章节、969 篇课程**。目录层级错误、专题树错误、未链接页面、站内坏链、完全相同的课程文件、完全相同的 HTML `<title>` 均为 **0**。所有有编号子目录的层级目前也没有编号断档。仍有 **43 条占位提醒**，属于 README 允许的待填充专题。三级 `index.html` 已清零；现在索引只设在二级学科，校验脚本也会阻止再次越级建立索引。

## 仍需内容编辑时关注

- **四级目录与子专题混合承载已复核**：TCP 的报文头课、HTTP 文件传输课、操作系统网络 IO 概览课位于四级目录，同时各自有更细的五级专题。四级本身已表达课程归属，子目录分别细分连接机制、P2P 或 Socket；README 允许四级直接承载课程，因此不为这些课程增加只有一篇内容的中间层。
- **交叉主题有不同视角**：API 网关和微服务分别在通用原理、机制实现或架构应用中出现。当前课程文件没有完全相同的副本；后续扩写时应让每篇课程聚焦本学科视角，增加互链，避免把同一段原理在两处继续扩写。
- **相似图解保留不同粒度**：云架构的 `architecture-diagram.html` 给出简版请求链路，`architecture-detailed.html` 增加 CDN、安全层、L4/L7 对比等内容，适合分别作为入门图和详细图，不宜按相似标题删除。
