LLM 安全 · 隐私

大模型隐私与数据泄露：记忆、成员推断与 PII 防护

越狱之外，模型还可能「老实交代」训练数据和用户隐私

隐私风险的三层

大模型的安全不只是"被越狱"，还有更隐蔽的隐私与数据泄露风险，大致分三层：

① 训练数据记忆

模型把训练语料里的原文"背"了下来，能被精心设计的 prompt 诱导吐出——包括私人邮件、代码片段、病历。

② 成员推断

攻击者判断"某条特定数据是否进了训练集"，从而泄露个体是否在某群体中（如某医院的患者）。

③ 提示/输出泄露

用户输入或模型输出里夹带 PII（姓名、身份证、病历、密钥），经日志、缓存、第三方接口扩散。

可提取记忆（Extractable Memorization）

指的是：给定某个前缀，模型能稳定复述出训练数据中的原文片段。它不是"模型理解了内容"，而是把训练样本当成了"填空题答案"直接回放。验证方法通常是用训练集里的一段前缀去探测，看模型能否一字不差补出后续。

# 探测思路（示意）：用训练样本的前半段作 prompt
prefix = train_sample[:200]
completion = llm(prefix)
leaked = completion.startswith(train_sample[200:280])
# 若多次采样都能稳定复现，则该片段属于"可提取记忆"

成员推断攻击

原理很朴素：模型对"见过"的样本通常给出更低的 loss / 更高的置信度。攻击者准备目标样本，比较模型对它的置信度与对随机样本的分布，就能以高于随机的概率判断它是否为训练成员。这在医疗、金融等敏感领域尤其危险。

防护手段：从数据、训练到推理

  • 数据侧：去重、PII 脱敏、MinHash 近邻去重、剔除明显敏感文本。
  • 训练侧：差分隐私训练（DP-SGD，给梯度加噪）、机器遗忘（machine unlearning，按请求删除某数据影响）。
  • 推理侧：输入/输出 PII 检测与过滤、最小化回灌给模型的用户上下文、默认不长期保存对话。
  • 治理侧：数据保留期、用户删除权（被遗忘权）、审计与合规（如 GDPR）。
⚠️ 不要把用户数据无脑喂回模型做"个性化"——这会成为记忆泄露的新入口。最小化、脱敏、可撤回，三件事缺一不可。

第一层 · 先判定是哪类隐私风险

风险类型攻击者目标典型表现
训练数据记忆套出训练语料原文复述邮件/代码/病历
成员推断判断数据是否入训推断个体是否在敏感群体
PII 泄露获取姓名/证件/密钥输入或输出夹带敏感字段

第二层 · 可落地的防护参数

  • 差分隐私 DP-SGD：噪声乘数 ε 常用 1~10，越小越保护隐私、模型质量下降越多（典型取舍 ε≈3~8）。
  • 去重：MinHash 相似度阈值常设 0.8~0.9 判定近重复并删除。
  • PII 过滤：正则 + 实体识别（姓名/身份证/银行卡/邮箱），命中即脱敏或拒绝。
  • 保留期：对话日志默认短期（如 30 天）并可按用户请求删除。

第三层 · 隐私事故怎么查

  • 怀疑记忆泄露：用训练样本前缀做"提取探针"，统计可复现比例；对高危字段（密钥、证件号）专门压测。
  • 怀疑成员推断：比较模型对目标样本与对照样本的 loss 分布差异，差异显著即脆弱。
  • 怀疑输出 PII 泄露：对生产输出做 PII 扫描，看是否回显了用户输入里的敏感字段。
  • 查第三方：模型调用了外部 API/插件？数据是否经手未签保密协议的供应商。

第四层 · 原理与取舍

根本原因：模型是参数化的训练数据压缩，训练样本的信息会"渗"进权重，遇到相似前缀就被召回。完全消除记忆几乎不可能，且会与模型质量冲突——差分隐私加噪越多越保护隐私，但任务表现越差。实务目标是把可提取记忆压到不可用的程度：数据去重 + 训练加噪 + 推理过滤三层叠加，而不是单靠某一项。注意这和"越狱/提示注入"是不同轴——攻击是对抗性的故意突破，隐私泄露常是模型"老实交代"训练内容。

机器遗忘（unlearning）现实吗？

完全精确删除某条数据的影响很难，近似方法（影响函数、梯度反演、重训子集）成本高。对中小模型可行，对超大模型通常不划算，所以更务实的是"训练前严苛去敏 + 训练后监测"。

隐私和提示注入防护要分开做吗？

建议分开。注入防的是"外部内容冒充指令"，隐私防的是"模型把训练/用户输入的敏感信息吐出来"。前者靠隔离与权限，后者靠去敏、加噪与输出过滤，手段不同。
