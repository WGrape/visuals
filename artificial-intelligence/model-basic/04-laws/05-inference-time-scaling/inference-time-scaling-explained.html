推理时扩展 Inference-time Scaling：用测试时算力换分数

预训练 Scaling 之外的第二条增长曲线：o1/o3 与推理模型们开启的新范式。

定义

训练完之后，再花算力"多想一会儿"

传统 Scaling Law 投入算力的位置在训练阶段（更多参数、更多数据）。推理时扩展（也叫 test-time compute / reasoning scale）把算力投在使用阶段：回答问题时多生成思考过程、多采样、多搜索验证，用更大的单次推理成本换更高的答案质量。OpenAI o1（2024）是标志性起点。

手段

把"想"变成可扩展的搜索

长思维链
训练模型生成更长的内部推理（RL 训练出的自发思考），token 越多思考越深
Best-of-N + 验证器
采样 N 个候选答案，用打分模型/规则挑最好的
树搜索
MCTS 类方法沿推理步骤展开分支，用过程奖励模型（PRM）引导剪枝
自我一致性与反思
多次采样投票（Self-Consistency），或让模型自我检查修正
关键发现：在数学、代码等可验证任务上，"测试时算力 vs 性能"也呈现出类似预训练的幂律扩展曲线——算力翻倍，分数可预期地涨。这是它能被称为"第二条 Scaling Law"的原因。

互补而非替代：推理时扩展的"地基"仍是基础模型——底座弱，想再多也是方向错误的想。业界共识是训练时与推理时两条曲线配合投入。

代价

天下没有免费的思考

延迟与费用成倍增加：思考 token 也是真金白银的输出 token，o1 类模型价格和响应时长都数倍于普通模型。不是所有请求都值得"深思"——路由策略（简单问题走小模型/直答，难题走推理模型）因此成为工程标配。
只在可验证域收益明显：写诗、闲聊没有明确的"更好"，多想未必更对；过度思考还可能把简单问题想复杂（overthinking）。
面试问答

高频问题

Q1：什么是推理时扩展？
在使用阶段投入更多算力换取更好答案：长思维链、多次采样、搜索与验证等。o1/o3 展示了它在数学代码等任务上随算力幂律提升的规律，故称 test-time scaling。
Q2：它和预训练 Scaling Law 的关系？
互补的两条曲线：预训练提升模型固有能力（一次性成本），推理时扩展在每次请求上灵活加码（持续性成本）。推理扩展的天花板受基础模型能力约束。
Q3：为什么推理时扩展在数学/代码上效果好？
这些任务有明确的对错可验证，更多思考与搜索能真正排除错误答案；开放生成缺乏可靠验证信号，扩展收益有限。
Q4：工程上怎么平衡推理成本？
按任务难度路由：简单请求走轻量模型直答，复杂请求才启用推理模型或 Best-of-N；同时控制思考预算（如限制 reasoning token 上限）。
Q5：什么是过程奖励模型（PRM）？
对推理的中间步骤打分的模型，区别于只看最终答案的结果奖励（ORM）。配合树搜索引导分支选择与剪枝，是推理时搜索的关键组件。

把算力花在「想」这一步

传统的缩放是把钱花在训练前：更大的参数、更多的数据。而推理期缩放（Inference-time / Test-time Scaling）是另一条轴：模型训练完了，但可以在回答这一道题时，多花一些算力去「想」。

两条缩放轴与四类推理期手段

四种手段各自的适用场景

手段怎么做适合什么题代价
拉长思考让模型显式写出规划、假设、中间计算逻辑链长、步骤可分解的题输出 token 线性增加，延迟上升
并行采样同一题采样 n 条回答答案主观或有多样性需求n 倍成本
自洽投票取 n 条路径中出现最多的最终答案有明确答案且可比对一致性的题需要能定义「同一个答案」
搜索 + 回溯树展开多条路径，允许丢弃重来需要探索或多解空间大的题实现复杂、耗时最高
验证器重排训练/提示一个打分模型从候选中选优能被程序或另一个模型判定的任务需有可依赖的判定信号

这里有一个关键共识：单纯「多想」不等于「想得更对」。真正决定性价比的是有没有可靠的验证信号。存在一个便宜而准确的判定器（例如代码能跑测试、数学有标准答案、检索有出处）时，采样多条再筛选收益极高；反之，在开放式写作里多想几遍的收益就非常有限。

怎么分配「思考预算」

既然多了这条路，工程上立刻出现一个新问题：这道题配多少推理算力合适？四条经验：

先判难度用轻量模型或规则先给题分类：简单题直答，难题进入深度模式。
定上限再早停设定最大思考 token 数与最大尝试次数，达标即停，防止个别难题拖垮整体延迟。
看边际收益从少量、中等、深度三档测出指标曲线，找到收益拐点，超过后继续加预算基本无用。
记录与回收把实际消耗与最终是否被采纳记录下来，用于第二版预算分配。
伪代码：按难度分配推理预算 if easy(question): # 小模型/规则判定 answer = call(model, max_tokens=512) else: cands = [] for i in range(N): # N 由难度档位决定 cands.append(call(model, reasoning_effort='high')) scored = [verifier(c, question) for c in cands] answer = best(scored) if max(scored) < THRESHOLD: # 都不够可信 answer = escalate_to_human(question)

与训练期缩放的关系：两者不是替代而是补充。训练期决定「能力上限在哪」，推理期决定「这一次离上限有多近」。资源有限的团队往往更划算的做法是：用中等规模的模型 + 较强的推理期策略，而不是砸钱训一个更大的模型。

深入自检

推理期缩放会不会取代训练期缩放？

不会。推理期策略能挖的是「模型本身已具备、但一次前向如果不够就发挥不出来」的能力。模型压根不会的事情，想一万遍也不会。两条轴在现实里是一起长的：更强的基座 × 更好的推理策略。

为什么我加了 CoT 反而更慢更差？

三种可能：① 模型规模或指令跟随能力不足，长推理链会自我带偏；② 任务本身不需要多步（如翻译、格式转换），中间思考是纯浪费；③ 没有验证信号，多想的次数并没有转化为更好的筛选。建议先小规模 A/B 测三档预算，看指标斜率。

自洽投票为什么能提升准确率？

它把「单次采样的方差」换成了「多次采样的众数」。当错误模式比较分散、正确答案比较集中时，多数投票能显著拉高正确率；但如果模型存在系统性偏差（所有采样都朝同一个错误方向），投票只会把错误变得更自信。

怎么衡量推理期投入的性价比？

用同一批题做三档预算对比，画「每条需成本 vs 正确率」曲线，算每提升 1 个百分点的边际成本。多数场景在中等档附近就有明显拐点，深度档只对少数高价值题目值得。同时别忘把 TTFT 与超时率纳入分母——用户感受到的是延迟，不只是花掉的钱。

推理时扩展的三条路径

路径做法典型收益代价
并行采样生成 N 个答案后投票/打分pass@1 提升 5~20 个点算力 ×N
串行反思生成 → 自我批评 → 修正复杂任务提升明显延迟 ×2~3

核心洞察：把训练时的算力换为推理时的算力。传统思路是“让模型更强”（更大参数、更多数据）；推理时扩展的思路是“让模型想更久”。后者在可验证的任务（数学、代码）上效果尤其显著，因为可以用验证器筛选答案。

关键指标：pass@k 与 maj@k

指标定义含义
pass@1一次就对的概率常规评测指标
pass@kk 次采样中至少一次对采样能力的上限
maj@kk 次采样取多数投票无需验证器时的实用方案
pass@k − pass@1采样带来的增益越大说明扩展越有效

pass@k 计算

# pass@k 的无偏估计（避免用“至少一次对”的简单比例，它有偏）
import math
def pass_at_k(n, c, k):
    '''n 次采样中 c 次正确，估计 pass@k'''
    if n - c < k: return 1.0
    return 1.0 - math.prod((n - c - i) / (n - i) for i in range(k))

# 例：采样 10 次对了 3 次
print(round(pass_at_k(10, 3, 1), 3))    # 0.300  pass@1
print(round(pass_at_k(10, 3, 10), 3))   # 1.000  pass@10（至少一次对）
print(round(pass_at_k(10, 3, 5), 3))    # 0.917  pass@5

# 关键观察：pass@k 随 k 快速增长，说明“多想几次”确实有用
# 但 maj@k（多数投票）通常只能拿到 pass@k 增益的<strong>一部分</strong>
# 差距就是“如何选出正确答案”的问题——有验证器时能接近 pass@k

为什么 maj@k 拿不到 pass@k 的全部收益：多数投票只能选出“最常见的答案”，但正确答案可能在少数派里。有验证器（数学题可对答案、代码可跑测试）时能直接筛出正确解，效果接近 pass@k；没有验证器时只能靠投票，收益打折扣。

策略做法适用

关键结论来自实验：在固定算力预算下，让简单题少花算力、难题多花算力的分配方式，明显优于均匀分配。判断难易可以用前几次采样的一致性——答案高度一致说明简单，可以早停；分歧大说明难，继续采样。

自检 Q&A

Q：推理时扩展和把模型做大，哪个划算？

A：看任务是否可验证。可验证任务（数学、代码、有标准答案的）→ 推理时扩展性价比高，因为可以用验证器筛选，小模型 + 多采样常能超过大模型单次生成。不可验证任务（创意写作、开放问答）→ 没有可靠的验证器，多采样只能投票，收益有限，此时提升基础模型能力更直接。另外还要看部署形态：离线批处理适合扩展（不关心延迟），在线服务受延迟约束大。

Q：思维链（CoT）算推理时扩展吗？

A：算，属于「串行扩展」。CoT 让模型生成中间推理步骤，本质是用更多 token 换取更高的正确率。区别在于它不像采样那样产生多个候选，而是把一次生成拉长。实验显示：在数学题上，仅靠 CoT 就能带来 10~30 个点的提升，且代价远小于多次采样。所以实践中的优先级是：先上 CoT，再考虑采样/搜索。

Q：为什么我采样多次投票反而变差了？

A：三种可能——① 温度设太高：每次采样质量都很差，投票只是在差答案里选；② 任务不适合投票：如开放式生成，正确答案不唯一，多数投票会把有创意的答案压掉；③ 投票方式不对：直接对文本投票会因表述差异失效，应先归一化答案（如数学题提取最终数值、代码提取返回值）再投票。

Q：推理成本怎么控制？

A：四条——① 自适应采样：简单题早停（可省 50%+）；② 前缀缓存：多次采样共享 prompt 前缀的 KV Cache（vLLM 的 enable_prefix_caching），能省掉重复的 prefill；③ 小模型预筛：先用便宜模型判断难度或直接尝试，难的才上大模型；④ 限制最大长度：给 CoT 设上限，防止无限展开。其中 ② 对采样类方法收益最大，因为 prefill 往往是主要成本。
