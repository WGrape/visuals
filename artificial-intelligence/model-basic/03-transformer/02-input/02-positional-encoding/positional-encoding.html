Transformer 架构

位置编码：Transformer 怎么知道词的顺序

注意力本身是「无序」的集合运算——「猫追老鼠」和「老鼠追猫」对它是一回事。位置编码就是显式把「顺序」注进去的机制，从绝对位置到 RoPE，本文一次讲清。

一句话回答

自注意力对输入顺序 置换不变（permutation-equivariant）：把句子里的词打乱，每层的输出只是跟着被打乱，模型本身读不出顺序。所以必须额外喂给模型「第几个词」这个信息——这就是位置编码。

核心矛盾：注意力擅长「看关系」但不擅长「看顺序」。没有位置编码，「我爱你」和「你爱我」在模型眼里几乎等价。

为什么注意力没有顺序

自注意力对输入集合做加权求和：每个 token 的表示是其他 token 表示的加权和，权重由 Q·Kᵀ 决定。这个运算对输入的排列是等变的——你重排输入，输出跟着重排，模型并不能「发现」被重排了。

Attention(Q,K,V) = softmax( Q·Kᵀ / √d ) · V

公式里没有任何「位置」项。N 个 token 没有任何顺序假设，像在算一个「词袋」(bag of words)。所以顺序信息必须外挂。

等变 ≠ 不变：模型输出会跟着输入顺序变，但它读不出「这是第 3 个词」这种绝对位置，也无法自然区分「A 在 B 之前」和「B 在 A 之前」。

绝对位置编码：直接给每个位置一个向量

① 可学习位置嵌入（Learned，BERT 用）

先准备一张查找表 PE ∈ ℝ^{max_len × d}，第 i 个位置的向量是可训练参数，训练时和词向量一起学出来，推理时直接查表加到词嵌入上。

优点：简单、灵活，模型自己学出有用的位置模式。缺点：长度外推差——训练时最多见过 512，推理给 1024 就查不到表（得截断或插值）。

② 正弦/余弦位置编码（Sinusoidal，原版 Transformer 用）

用不同频率的正余弦函数手工构造位置向量，第 pos 个位置、第 i 维：

PE(pos,2i) = sin(pos / 10000^{2i/d})    PE(pos,2i+1) = cos(pos / 10000^{2i/d})
优点：可外推（任意位置都能算出向量，不依赖训练最大长度）；原论文证明：两个位置的相对位置可由它们的绝对位置编码做线性变换得到，天然携带相对信息。

相对位置编码：注意力只关心「差多少」

绝对位置的问题：模型真需要的是「token A 和 token B 相距 3」这个相对关系，而不是「A 在第 5、B 在第 8」这两个绝对数字。于是出现了直接在注意力分数里注入相对偏移的方案（Shaw 2018、T5 的 RPE、原始论文的简化版）。

思想：把「相对距离 k = i − j」编码成一个可学习（或函数式）的偏置，加到 Qᵢ·Kⱼ 上。这样「相距 3」在所有位置对里含义一致，更贴近语言事实（语法关系看相对距离）。
相对位置编码让「相距相同」的归纳偏置更均匀，外推性通常也比纯绝对可学习嵌入更好。

RoPE（旋转位置编码）：现在的主流

RoPE（Rotary Position Embedding，Su 2021）被 Llama、Qwen、ChatGLM、DeepSeek 等几乎所有主流 LLM 采用。它的直觉极其优雅：不给位置一个「加性」向量，而是把 query / key 在向量空间里「旋转」一个和位置成正比的角度。

具体做法：把 d 维向量按相邻两维一组分成 d/2 个子空间，每组按角度 m·θᵢ 旋转（θᵢ 是预设的频率）。关键性质——旋转后的两个向量做内积，结果只和相对位置 (m−n) 有关，和绝对位置无关。

为什么好：(1) 相对位置被「编码进内积本身」，无需额外偏置；(2) 长文本外推性强（配合 NTK-aware scaling / 位置插值可进一步拉长）；(3) 计算开销极小，只是一次旋转。

ALiBi：连位置向量都不要

ALiBi（Attention with Linear Biases，2022）走向极致：完全不给 token 加位置向量，而是在注意力分数 Q·Kᵀ 上，直接减去一个「与距离成正比」的偏置。

score(i,j) = (qᵢ·kⱼ) − m·|i − j|

距离越远的 token，被惩罚得越狠，模型自然更关注近处。

最大卖点：长度外推极强。因为没学任何绝对位置表，训 1k 直接推理 10k+ 也能用，训推不一致问题最小。被 BLOOM、MPT 等采用。

四种方案对比

方案怎么编码相对位置长度外推典型模型

面试一句话：现代 LLM 几乎都用 RoPE；要极致外推选 ALiBi；BERT 类用 learned 绝对位置。核心权衡是「相对位置表达力」vs「长度外推能力」。

总结

  • 注意力本身读不出顺序，位置编码是必选项，不是可选项。
  • 演进主线：绝对(learned/sin) → 相对(RPE) → 旋转(RoPE) → 偏置(ALiBi)。
  • RoPE 靠「旋转使内积只依赖相对位置」，成为 LLM 时代事实标准。
  • 外推性是核心工程考量：RoPE 配 NTK/插值，ALiBi 天然强。

第一层 · 为什么必须要位置编码

因为自注意力本身是「位置无关」的——把输入序列打乱顺序，注意力的输出（除顺序外）完全不变。它看到的是一「袋」token，而不是一个序列。位置编码就是把顺序信息重新注入回去的唯一手段。

机制是否感知顺序说明
RNN天生感知逐步处理，顺序隐含在时间步里
CNN局部感知卷积核覆盖局部窗口，有相对位置感
自注意力完全不感知softmax(QKᵀ/√d)V 对行的置换是等变的——输入换序，输出跟着换序，内容不变
  • 形式化地说：注意力对输入是置换等变（permutation equivariant）的。这意味着「我 爱 你」和「你 爱 我」在注意力眼里是同一组向量——这显然不行。
  • 位置编码的做法：给每个位置生成一个向量，加到（或拼到）token 嵌入上，让同样的词在不同位置有不同的表示。
  • 三种主流方案：正弦编码（Sin/Cos，原 Transformer）、可学习绝对编码（BERT/GPT-2）、相对位置编码（RoPE，LLaMA/现代 LLM 的事实标准）、ALiBi（直接给注意力分数加偏置）。

第二层 · 公式、代码与量化对比

可运行代码

import torch, math

def sinusoidal_pe(seq_len, d_model):
    # PE(pos, 2i)   = sin(pos / 10000^(2i/d_model))
    # PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
    pe = torch.zeros(seq_len, d_model)
    pos = torch.arange(seq_len).unsqueeze(1).float()          # [n, 1]
    div = torch.exp(torch.arange(0, d_model, 2).float()
                    * -(math.log(10000.0) / d_model))          # [d/2]
    pe[:, 0::2] = torch.sin(pos * div)
    pe[:, 1::2] = torch.cos(pos * div)
    return pe

pe = sinusoidal_pe(50, 64)

# —— 关键性质 1：不同频率的波长跨度极大 ——
for i in [0, 8, 16, 24, 31]:
    w = 2 * math.pi * (10000 ** (2*i/64))
    print(f'dim {i:2d}: 波长 ~ {w:>12.1f} tokens')
#   dim  0: 波长 ~ 6.3 tokens        <- 高频，捕捉相邻关系
#   dim  8: 波长 ~ 25 tokens
#   dim 16: 波长 ~ 100 tokens
#   dim 24: 波长 ~ 502 tokens
#   dim 31: 波长 ~ 10000 tokens      <- 低频，捕捉长程位置

# —— 关键性质 2：相对位置可表示为线性变换 ——
# PE(pos+k) = T_k @ PE(pos)，其中 T_k 只依赖 k
# 这使模型能「学到」相对位置关系，是原设计的点睛之笔

# —— RoPE（旋转位置编码，现代 LLM 标配）——
def rope(x, seq_len, dim):
    # 把每两个维度看成复平面上的一个向量，按位置旋转角度
    freqs = 1.0 / (10000 ** (torch.arange(0, dim, 2).float() / dim))
    t = torch.arange(seq_len).float()
    angles = torch.outer(t, freqs)                 # [n, dim/2]
    cos, sin = torch.cos(angles), torch.sin(angles)
    x1, x2 = x[..., 0::2], x[..., 1::2]
    out = torch.stack([x1*cos - x2*sin, x1*sin + x2*cos], dim=-1)
    return out.flatten(-2)

# RoPE 的核心优势：q_m^T k_n 只依赖 (m-n)，即【天生就是相对位置】
# 且可通过旋转矩阵自然外推（配合 YaRN/NTK 缩放可扩到百万上下文）
方案注入方式是否相对位置能否外推到更长代表模型
正弦 Sin/Cos加到嵌入间接（可学）能（但效果衰减）原 Transformer、早期
可学习绝对加到嵌入否不能（超出训练长度即失效）BERT、GPT-2
RoPE旋转 Q/K是（qᵀk 只依赖相对距离）能（配合缩放）LLaMA、Qwen、Mistral、GLM
ALiBi给注意力分数加线性偏置是很强（无需训练即可外推）BLOOM、MPT
NoPE（无位置编码）不加隐式（靠因果 mask）有限部分研究模型

判断当前主流：新模型基本都用 RoPE。原因就是「q_mᵀ k_n 天然只依赖 m−n」这条性质——相对位置正是语言最需要的。

第三层 · 常见误解与排障清单

  • 「位置编码加在嵌入上会被后面的层破坏」 → 确实会被稀释，但这是设计意图：位置信息只在底层需要，深层已经把顺序信息编码进了表示。实测去掉位置编码后，模型在需要顺序的任务上（如词性标注）性能暴跌，但在词袋任务上几乎不变——说明它精确地在做它该做的事。
  • 「RoPE 和可学习编码只是实现不同」 → 不是。可学习绝对编码外推能力为零：训练 2048 长度，推理到 4096 直接崩（因为没见过那些位置向量）。RoPE 因为只依赖相对距离，配合 NTK-aware 缩放或 YaRN 可以外推到几十万甚至百万。这是长上下文模型的关键技术之一。
  • 「正弦编码的 10000 是随便定的」 → 不是。它决定了频率分布的下界：10000^(2i/d) 让不同维度的波长从 2π 到 20000π 呈几何级数分布，覆盖从「相邻词」到「整段」的所有尺度。改小会让长程位置分辨率不足。
  • 拼（concat）还是加（add） → 原始论文用了 sin/cos 后相加。相加省参数且不增加维度；拼接表达力更强但维度翻倍。实践上相加就够了，因为后面的线性层可以把两者解耦。
  • 长上下文外推失效 → 常见症状：模型在训练长度内正常，超过后开始重复、逻辑混乱。解法：用 NTK-aware RoPE 缩放（动态调整基数）或 YaRN（分频段插值），而不是简单线性插值（后者会破坏高频信息）。
  • 相对位置编码和注意力 mask 混淆 → 因果 mask 是「不能看未来」，位置编码是「知道彼此距离」。两者独立：编码器（BERT）没有因果 mask 但仍需位置编码。
  • 实现时维度奇偶对不上 → 正弦编码要求 d_model 为偶数（因为 0::2 和 1::2 各占一半）。奇数维度要特殊处理。

第四层 · 原理与取舍

位置编码的设计目标是三条：① 唯一标识每个位置；② 能表达相对距离；③ 能外推到训练时没见过的长度。三个方案在三条上的取舍完全不同。

唯一性✓（不同位置不同向量）✓✓
有界（值域稳定）✓（±1 内）✗（需正则）✓（旋转不改模长）
表达相对位置✓（可线性变换）✗（模型自己学）✓✓（数学保证）
外推到更长部分✗✓（配合缩放）

实现复杂度低最低中（要改 Q/K 计算）
  • 为什么 RoPE 能表达相对位置：把每两个维度看作复平面上的向量，位置 m 的编码等价于把向量旋转角度 mθ。那么 q_m 与 k_n 的点积 = |q||k|cos((m−n)θ)——只依赖 m−n。这是数学上的保证，不是靠训练学出来的，所以泛化得特别好。
  • 为什么 RoPE 还能保持模长：旋转是正交变换，不改变向量长度。这让数值稳定、且不会像加法那样「污染」语义嵌入的分布。这是它相比加法式编码的另一个优势。
  • 长上下文外推的三种缩放：① 线性插值（把位置除以缩放系数）——简单但会压缩高频、损失近距离分辨率；② NTK-aware（动态放大基数 10000）——高频少缩放、低频多缩放，符合直觉且无需微调；③ YaRN（分频段处理 + 注意力温度校正）——目前效果最好，能用极少的微调 token 扩展到 128K+。
  • 什么时候不需要位置编码：某些架构（如状态空间模型 Mamba、以及带强局部卷积的混合架构）本身通过递归/卷积结构隐式携带顺序信息，可以不加显式位置编码。但纯注意力架构必须有。
为什么现在几乎没人用可学习绝对位置编码了？

因为它有一个致命缺陷：无法外推。训练时最大长度是 2048，那么位置 2049 及以后的向量从来没被训练过，推理到 4096 时模型拿到的是随机初始化的向量，表现会断崖式下跌。而现实需求恰恰是「训练用短序列省成本、推理要长上下文」。RoPE/ALiBi 这类相对编码天然支持外推（因为只需要见过「相对距离」而不是「绝对位置」），配合 NTK/YaRN 缩放还能进一步扩展。所以当「长上下文」成为 LLM 的核心竞争力后，可学习绝对编码就被淘汰了——这不是实现细节的差异，是能力上的硬约束。

RoPE 的旋转到底旋转了什么？

旋转的是 Q 和 K 向量本身（不是位置向量）。具体做法：把 d 维向量的每两个相邻分量 (x_2i, x_2i+1) 看作复平面上的一个 2D 点，然后按位置 m 和该维度对应的频率 θ_i 旋转 m·θ_i 弧度。位置越靠后转得越多，不同维度转速不同（低频维度转得慢、编码长程；高频维度转得快、编码近程）。旋转后 q_mᵀk_n 自然只依赖 m−n。关键点：位置编码不再是一个「加进去的向量」，而是作用在 Q/K 上的一个变换——这比加法更优雅，也不占用嵌入的数值范围。代价是实现要在注意力计算里插入旋转逻辑，且不能简单地「预计算一次位置表复用」。

位置编码对长上下文的实际影响有多大？

非常大，而且是长上下文能力的三个瓶颈之一（另两个是注意力 O(n²) 的算力和 KV Cache 显存）。一个直观例子：用绝对位置编码训练的模型，在超出训练长度后 PPL（困惑度）会急剧上升——不是「稍微变差」，而是「完全不可用」。而用 RoPE + 合适缩放的模型，可以把 4K 训练的模型外推到 32K 而 PPL 基本不涨。另一个实践要点：长上下文能力不只是「能塞进去」，还要「能用好」——很多模型虽然支持 128K 窗口，但在中间位置的信息检索能力会下降（即「lost in the middle」现象）。这与位置编码的衰减特性有关，也是当前研究的活跃方向。
