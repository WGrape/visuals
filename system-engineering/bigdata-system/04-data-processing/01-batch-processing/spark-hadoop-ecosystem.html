Spark Core、SQL 与 Hadoop 的职责分工

将计算引擎、资源调度、存储与 Spark 上层库分别归位。

五、Spark 生态全家桶

Spark 不止一个计算核心，而是一整套以 Spark Core 为底座的组件库，覆盖从批处理到图计算的主流场景。

⚙️

Spark Core

提供 RDD API、任务调度、内存管理、容错与存储（BlockManager）。它是所有上层组件的运行时底座，定义了任务分发、shuffle、cache/persist 等基础机制。

🗃️

Spark SQL

提供 DataFrame / Dataset 结构化 API，内置 Catalyst 优化器（逻辑计划→物理计划，谓词下推、列裁剪）与 Tungsten 二进制执行引擎（堆外内存、代码生成），让 SQL 与结构化处理接近手写代码的性能。

🌊

Structured Streaming

以"微批 + 表"模型把流看成无限追加的表，提供端到端精确一次（exactly-once）语义。编程接口与 Spark SQL 高度一致，降低流批统一门槛。

🤖

MLlib

分布式机器学习库，提供分类、回归、聚类、协同过滤、特征工程与 Pipeline API。基于 RDD/DataFrame 并行训练，适合大规模特征与模型。

🕸️

GraphX

图计算 API（基于 Pregel 的顶点中心计算）。本组件在本站有独立专页，此处不展开。

六、与 Hadoop 的关系：Spark 取代的是谁

关键澄清：Spark 不是存储系统，它本身不提供 HDFS 那样的分布式文件系统。Spark 通常读取 HDFS / 对象存储（S3、OSS）上的数据，并把调度跑在 YARN 或 Kubernetes 之上。一句话——Spark 取代的是 MapReduce 这个计算引擎，而不是 Hadoop 整个生态。

在实际生产部署中，最常见的形态是"HDFS 存 + YARN 调度 + Spark 算"三层协作：YARN 负责资源隔离与分配，HDFS 负责数据持久化与三副本容错，Spark 负责在上面高效完成计算。两者是互补而非替代关系。

维度MapReduce（旧）Spark（新）
中间结果强制落盘 HDFS默认驻留内存
执行模型Map→Reduce 固定两阶段按依赖自由切分 Stage
迭代性能差（每轮重写磁盘）优（内存缓存）
生态覆盖仅批处理批/流/SQL/ML/图
