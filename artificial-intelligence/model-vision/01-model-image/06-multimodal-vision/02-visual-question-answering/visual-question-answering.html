多模态视觉

视觉问答 VQA：让模型看着图片回答自然语言问题

VQA 要求模型同时理解图像内容与自然语言问题，并给出答案。它是检验「多模态真正看懂没有」的经典任务，也是今天多模态大模型（VLM）的核心能力之一。本文讲清任务形态、技术演进与评测陷阱。

VQA 到底在考什么

输入：一张图 + 一个自然语言问题；输出：答案（可以是单词、短语、选择题选项，或一句话解释）。

例如："图里有几只猫？"、"这个人正在做什么？"、"为什么 这条路是湿的？"

真正的难点在于：不能只靠语言先验蒙答案——模型必须真的从图中读取信息。

从两段式流水线到端到端 VLM

早期流水线
CNN 提图像特征 + RNN/LSTM 编码问题 → 融合后分类到答案词表
注意力融合
用问题去「 attend 」图像区域，聚焦相关局部
大模型时代 （当前）
视觉编码器 + 投影层 + LLM，图文在同一序列里统一推理
现代做法：把图片当作一串视觉 token 直接拼进大模型的上下文，由此顺带获得了解释、推理、多轮对话等能力，远超早期固定答案词表的形态。

评测陷阱：语言先验与幻觉

语言先验陷阱
数据集分布不均导致「不看图也能答对」（如问颜色总答白色）。
对策：构造平衡数据集 / 设计反例样本
多模态幻觉
模型编造图中不存在的物体或关系。
对策：要求输出依据（引用区域）、视觉定位校验、人工抽检
单纯刷准确率会高估能力：务必在同一问题上换图测试（改变图片答案是否跟着变），才能验出模型是真看懂还是背答案。

落地要点

  • 分辨率 vs 成本：视觉 token 数随分辨率增长，长上下文成本敏感任务需要在清晰度与开销间取平衡
  • OCR 与图表：文档、表格、图表场景建议先做版面检测再分块提问
  • 结构化输出：抽取类问答应要求 JSON 并做 Schema 校验，避免"答了但机器用不了"
  • 视频 VQA：本质是抽帧 + 时序，成本随帧数线性上升

面试速记卡

  • 任务：图 + 自然语言问题 → 答案，考察跨模态理解而非语言猜测。
  • 演进：CNN+RNN 流水线 → 注意力融合 → 视觉 token 拼进 LLM 的统一范式。
  • 两大陷阱：语言先验（不看图也能答）与多模态幻觉（编造图中内容）。
  • 验证方法：换图测试、要求给出依据区域、平衡数据集。
  • 工程：注意分辨率成本、OCR/图表先做版面、抽取类用结构化输出。

常见问题与对策

① 语言先验偏置

模型不看图只靠「问题 + 语言统计」就能猜中很多答案（问"草地是什么颜色"，答"绿色"永远对）。这导致评测虚高。对策：建平衡数据集（同一问题在不同图上有不同答案），如 VQA v2。

② 计数不准

视觉 token 化的过程丢失了精确的实例边界，LLM 也不擅长数数。对策：接检测/计数工具（工具增强），或用专门的计数模型。

③ 空间关系差

「左右」「上下」「之间」这类关系在 patch 化后位置信息模糊。对策：加入位置编码/坐标 token、或用 grounding 模型给出框再判断关系。

④ 幻觉

模型会描述图里没有的东西。对策：提高视觉 token 数量（分辨率）、加 grounding 输出（回答时给出依据区域）、或用更保守的解码。

评估方式

精确匹配答案与标注完全一致才对（严格，对开放式答案过严）
VQA 准确率多人标注取多数投票，软化匹配（常用）
人工评分开放式问答的最终标准
分题型统计按存在/计数/空间/推理分开看，才能定位短板
对抗性测试故意问图里没有的东西，测幻觉率

深入自检

VQA 和图像描述（Caption）有什么本质区别？

VQA 需要理解问题意图并针对性回答，而描述只是「把看到的说出来」。技术上，描述是无条件生成（给我一段话），VQA 是条件生成（回答这个特定问题）——模型必须判断问题在问什么（是问颜色？数量？位置？原因？），再去图中找对应信息。这带来两个额外难点：①问题理解——同一个「这是什么」在不同语境下指向不同；②定向检索——要能从上千个视觉 token 里找到与问题相关的那一小部分。所以 VQA 更像「带检索的推理」，比描述更接近真正的理解。

为什么 VQA 模型常常出现「语言先验」问题？

因为训练数据里问题和答案的统计相关性太强。比如训练集中「天空是什么颜色」的答案绝大多数是「蓝色」，模型只要记住这个统计就能答对，完全不用看图。这导致评测虚高——模型看似很强，实际是靠猜。解决方法是构建平衡数据集：对同一个问题，收集答案不同的多张图（VQA v2 就是这么做的），迫使模型必须看图才能答对。评估自己的 VQA 系统时，一定要做这种对抗性测试（换个图，答案就不同），否则测出来的准确率没有意义。

视觉 token 是怎么送给 LLM 的？为什么数量很重要？

流程是：图像过视觉编码器（如 CLIP ViT）得到一组 patch 特征 → 过对齐层（MLP 或 Q-Former）映射到 LLM 的文本嵌入空间 → 作为前缀 token 与问题的文本 token 拼在一起送进 LLM。数量重要的原因：①信息量——token 越多保留的视觉细节越多（LLaVA 用 576 个，高分辨率方案用 1000~3000 个）；②成本——LLM 的注意力复杂度是 O(n²)，视觉 token 翻一倍计算量翻四倍，所以要在细节与成本间权衡；③分辨率——更多 token 意味着能处理更高分辨率的图（这是读文字、看小物体能力的关键）。

为什么大模型数不清图里有几个物体？

两个原因叠加：①视觉编码丢失实例边界——图像被切成 patch 变成 token 序列后，「这是第 3 个苹果」这种需要精确实例分割的信息被模糊了；②LLM 本身不擅长计数——即使是纯文本，让 LLM 数一段话里某个词出现几次也容易错，因为它没有专门的计数机制。对策：工具增强——让模型调用专门的检测/计数模型（如 Grounding DINO + SAM）而不是自己数；或者在训练中加入专门的计数数据。这也是「大模型 + 工具」范式比纯端到端更可靠的一个典型场景。

做文档/图表类的 VQA 有什么特别注意事项？

文档和图表与自然图像差异很大：①文字密集——需要高分辨率输入（低分辨率下文字直接糊掉），很多系统为此支持动态分辨率或分块处理；②需要 OCR 能力——模型要能真的「读」出文字而不只是看个大概；③布局很重要——表格的行列关系、标题与正文的层级，patch 化后容易丢失，需要版面分析辅助；④数值推理——图表题常要做比较、求和，纯视觉推理不准，最好转成结构化数据再算。实践建议：文档场景优先选文档专用多模态模型或「OCR + LLM」的组合管线，而不是通用 VQA 模型。

准确率的分层现实：现代 VLM 在存在性与属性类问题上可达 85%~95%，但计数与空间关系常只有 50%~70%——这是当前最大的短板。所以如果你的业务强依赖计数或方位，纯 VLM 还不够可靠，需要结构化方案（检测 + 计数 + 坐标判断）配合。

评测指标

# VQA 评测的关键：答案归一化
import re
from collections import Counter

def normalize_answer(s):
    '''VQA 标准的答案归一化'''
    s = s.lower().strip()
    s = re.sub(r'\b(a|an|the)\b', ' ', s)     # 去冠词
    s = re.sub(r'[^a-z0-9 ]', '', s)            # 去标点
    s = ' '.join(s.split())                     # 合并空白
    return s

def vqa_score(pred, gts):
    '''VQA 官方指标：考虑标注者分歧'''
    p = normalize_answer(pred)
    cnt = Counter(normalize_answer(g) for g in gts)
    # 官方公式：min(匹配人数/3, 1)
    return min(cnt.get(p, 0) / 3.0, 1.0)

# 例：10 个标注者，6 人说 "yes"、4 人说 "no"
#   答 "yes"  → min(6/3, 1) = 1.0
#   答 "no"   → min(4/3, 1) = 1.0   （<strong>都对！</strong>）
#   答 "maybe"→ 0.0
# 注意这个指标<strong>不看「是否答对」，而是「与人类一致程度」</strong>

技术方案对比

方案做法优点缺点
端到端 VLM图 + 问题直接进模型简单，支持开放问题计数/空间弱，易幻觉
检测 + 结构化问答先检测出物体与坐标，再按结构回答计数与空间准确只能回答预定义问题

混合方案

# 混合方案：把检测结果注入 VLM 提示（显著提升计数与空间问题）
# 1) 先用检测模型拿到结构化结果
detections = detector.predict(image)
#   [{"label": "cat", "bbox": [x1,y1,x2,y2], "score": 0.95}, ...]

# 2) 生成场景描述，作为上下文给 VLM
def scene_description(dets, img_w, img_h):
    lines = []
    for i, d in enumerate(dets):
        x1, y1, x2, y2 = d['bbox']
        cx, cy = (x1+x2)/2, (y1+y2)/2
        # 把坐标转成<strong>相对方位描述</strong>，模型更容易理解
        h = 'left' if cx < img_w*0.33 else ('right' if cx > img_w*0.67 else 'center')
        v = 'top'  if cy < img_h*0.33 else ('bottom' if cy > img_h*0.67 else 'middle')
        lines.append(f"{i+1}. {d['label']} at {v}-{h}")
    return "\n".join(lines)

# 3) 组合提示
prompt = f"""Image contains:
{scene_description(detections, w, h)}

Question: {question}
Answer based on the detection results above."""

# 效果：计数类问题准确率常从 60% 提升到 85%+
# 原因：<strong>检测是确定性的，VLM 只负责语言理解</strong>

幻觉与可靠性

失效模式表现缓解
无中生有图上没有的东西说有要求给出区域（grounding）并校验
语言先验不看图，按常识猜用反常识问题测试
计数错误数量数错走检测+计数
位置错误左右/上下颠倒提供坐标或方位描述

检测「语言先验」的方法：问一些与常识矛盾但需要看图的问题，比如给一张「倒立的马桶」图问「马桶朝向哪」。若模型不看图只靠语言先验，会答错。这是判断模型是否真的在看图的有效手段。

一致性校验

# 一致性校验：多角度提问交叉验证
def consistency_check(image, model, entity):
    '''同一事实换几种问法，不一致说明不可靠'''
    qs = [
        f"图中有{entity}吗？",
        f"请数一数图中{entity}的数量。",
        f"描述图中{entity}的位置。",
    ]
    answers = [model.ask(image, q) for q in qs]

    # 交叉验证：若「没有」与「有 3 个」同时出现 → 矛盾
    has_no = any('没有' in a or 'no' in a.lower() for a in answers)
    has_count = any(re.search(r'\d', a) for a in answers)
    if has_no and has_count:
        return False, answers      # <strong>自相矛盾，结果不可信</strong>
    return True, answers

# 生产建议：高可信度要求时，
#   对关键结论<strong>提问 3 次取多数</strong>，并要求给出证据区域

自检 Q&A

Q：VLM 能替代 OCR 吗？

A：不能，至少现在不能。VLM 在短文本、大字号上表现不错，但遇到密集文字、小字、特殊字体时错误率显著上升，而且会脑补不存在的字符——这在文档/票据/证件场景是致命的。正确做法是专用 OCR 负责「读出文字」，VLM 负责「理解文字的含义」，两者串联。评测时也要分开测：OCR 用字符准确率，VQA 用语义准确率。

Q：为什么模型数数总错？

A：因为 VLM 是「看整体语义」而不是「逐个枚举」。它的视觉编码器把图像压成有限个 patch token，数量一多就难以精确区分个体。这是架构层面的限制，不是调参能解决的。可靠方案是交给检测模型——检测是逐框输出的，计数天然准确（数检测框即可）。所以计数类需求不要硬上 VLM。

Q：怎么提升空间关系问题的准确率？

A：把坐标信息显式喂给模型。纯 VLM 需要从像素里「感觉」方位，误差较大；但如果你先用检测拿到 bbox，计算出相对位置（左上、中间、右侧）再写进提示，模型只需做简单的语言推理，准确率大幅提升。另一个技巧是统一坐标系描述（如都用 9 宫格划分），避免「左边」这种模糊表述带来的歧义。

Q：业务上要落地 VQA，怎么设计才稳？

A：三条原则——① 先分类再路由：判断问题类型，计数/空间走检测+结构化，语义/常识走 VLM，OCR 类走专用 OCR；② 要求结构化输出：让模型同时给出答案与置信度/证据区域，便于校验；③ 设兜底：低置信或自相矛盾时转人工，而不是硬给答案。核心是不要把 VLM 当全能组件——它是理解环节，不是识别环节。
