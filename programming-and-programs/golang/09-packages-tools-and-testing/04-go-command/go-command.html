构建与运行

编译即交付

go build 直接产出静态链接的可执行文件；go run 编译到临时目录并立即执行；交叉编译只需设置 GOOS/GOARCH。

go build ./...            # 编译当前模块所有包

# 交叉编译：在 macOS 上构建 Linux 二进制
go build -o app-linux GOOS=linux GOARCH=amd64 .

# 裁剪体积：去掉符号表与调试信息

  go build -ldflags="-s -w" .
模块管理

go.mod 是事实来源

go mod init 初始化模块，go mod tidy 清理并补全依赖，go get 升级版本。版本选择遵循语义化版本与最小版本选择（MVS）。

go mod init example.com/app
go mod tidy              # 根据 import 整理 go.mod / go.sum
go get github.com/gin-gonic/gin@v1.9.1

# 查看依赖图
go mod graph | head
格式与静态检查

提交前必跑

gofmt 统一格式（IDE 通常保存即格式化）；go vet 发现可疑代码（如 Printf 占位符不匹配、不可达分支）。

gofmt -w .               # 就地格式化
go vet ./...             # 静态检查
goimports -w .           # 顺手整理 import（需安装）
环境与缓存

可复现的构建

go env 查看/设置环境变量；GOFLAGS、GOPROXY、GOMODCACHE 影响下载与缓存；go clean 清理构建缓存。

go env GOPROXY GOFLAGS GOMODCACHE
go env -w GOPROXY=https://proxy.golang.org,direct
go clean -cache -testcache   # 清掉构建与测试缓存
安装与获取

go install 装工具

go install 把带 main 的包编译并安装到 GOBIN；go get 现在主要用来拉取/升级库依赖而非安装工具。

go install golang.org/x/tools/cmd/goimports@latest

# 一条命令跑测试（带竞态检测）
go test -race ./...

模块文件与校验文件：各管什么

模块文件记录要什么

它记录模块路径、Go 版本、直接依赖与间接依赖的版本。依赖版本用语义化版本号表示，确保可复现。它是人可读、可编辑的清单。

校验文件记录是不是它

它记录每个模块版本的哈希值，用于校验下载内容是否被篡改或替换。不要手动编辑它，它由工具自动维护，但必须提交到版本库，否则别人构建时无法校验。

// go.mod 的常见结构 module github.com/me/myapp go 1.22 require ( github.com/gin-gonic/gin v1.9.1 github.com/stretchr/testify v1.8.4 ) require ( // 间接依赖，由上面的库引入，工具自动维护 github.com/bytedance/sonic v1.9.1 // indirect ) // 常用操作： // go get pkg@version 添加或升级某个依赖 // go get -u ./... 升级所有依赖，谨慎使用 // go mod tidy 整理依赖清单 // go mod why pkg 查某个依赖为什么被引入 // go list -m all 列出所有依赖版本 // 替换依赖，本地调试常用： // go mod edit -replace github.com/x/y=../y // 注意：replace 只影响当前模块，不会传递给下游

交叉编译与构建标签

Go 的一大优势是交叉编译开箱即用：不需要安装目标平台的工具链，设置几个环境变量即可。

深入自检：工具链的六个问题

为什么推荐产出纯静态二进制？

因为部署简单：不依赖目标机器上的动态库版本，拷过去就能跑，容器镜像也可以做到很小。代价是禁用 C 互操作后，部分依赖系统库的功能需要额外处理。

校验文件要不要提交？

必须提交。它是依赖完整性校验的依据，缺失会导致其他人构建时无法验证下载到的模块是否被篡改。同理模块清单也一定要提交。

为什么本地能编译，持续集成上找不到依赖？

常见原因是本地有模块缓存或用了指向本地路径的替换，而 CI 是干净环境。解决方法是确保依赖清单完整、替换只用于临时调试、CI 里先执行依赖整理再构建。

装工具应该用什么命令？

建议用带版本号的 install 安装工具，它不会影响当前模块的依赖清单。直接 get 装工具会把工具变成模块依赖，污染依赖清单。

测试缓存会导致漏测吗？

会让人误判。测试通过的结果会被缓存，如果依赖的外部文件变了但代码没变，测试不会重跑。在 CI 或需要确认时加上强制重跑的参数。

如何固定团队使用的工具版本？

把工具作为模块的依赖声明，然后用工具子命令运行。这样工具版本随依赖清单一起锁定，团队每个人用的都是同一个版本，避免我这里能过、你那里过不了。

交叉编译与依赖

# 交叉编译（GOOS x GOARCH，无需额外工具链）
CGO_ENABLED=0 GOOS=linux   GOARCH=amd64 go build -o app-linux-amd64   .
CGO_ENABLED=0 GOOS=linux   GOARCH=arm64 go build -o app-linux-arm64   .
CGO_ENABLED=0 GOOS=darwin  GOARCH=arm64 go build -o app-darwin-arm64  .
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -o app.exe           .
#   查看所有支持的平台：go tool dist list
#   CGO_ENABLED=0 -> 纯静态二进制，可直接塞进 scratch/distroless 镜像

# 瘦身：-s 去掉符号表，-w 去掉 DWARF 调试信息，体积通常减 30%
go build -ldflags="-s -w" -o app .
#   再配合 upx 可再压一半（但会影响启动速度和部分杀毒软件误报）

# 注入版本信息（发布必备）
go build -ldflags "-X main.version=$(git describe --tags) -X main.commit=$(git rev-parse --short HEAD)" .

# 依赖操作
go mod init github.com/me/proj
go mod tidy                 # 加缺失的、删多余的（每次改完 import 都要跑）
go get github.com/zeromicro/go-zero@latest
go get github.com/zeromicro/go-zero@v1.6.0
go mod verify               # 校验 checksum
go mod why -m <pkg>         # 为什么依赖了它
go list -m -u all           # 列出可升级的依赖

三条最实用的环境变量：① GOPROXY——国内必配 https://goproxy.cn,direct；② GOFLAGS=-mod=mod——避免 CI 里因为 -mod=readonly 报「go.mod 需要更新」；③ GOMODCACHE——CI 缓存这个目录能大幅加速。用 go env -w 写入用户级配置，不用每次 export。

测试、性能与排障命令

测试与性能命令

# 测试
go test ./...                       # 全量
go test -run TestUser -v ./service  # 只跑匹配的
go test -count=1 ./...              # 禁用缓存（默认会缓存成功结果！）
go test -race ./...                 # 竞态检测（CI 必开，慢约 10 倍）
go test -cover ./...                # 覆盖率
go test -coverprofile=c.out ./... && go tool cover -html=c.out   # 可视化

# 基准测试
go test -bench=. -benchmem -run=^$ ./...
#   BenchmarkXxx-8   1000000   1053 ns/op   512 B/op   8 allocs/op
#                              ^时间     ^每次分配字节  ^分配次数
go test -bench=. -benchtime=10s -count=5 | tee old.txt   # 多次采样
#   对比优化前后：benchstat old.txt new.txt

# CPU / 内存分析
go test -cpuprofile=cpu.out -bench=. && go tool pprof cpu.out
#   pprof 交互命令：top / list <func> / web / flamegraph
go test -memprofile=mem.out -bench=. && go tool pprof -alloc_space mem.out

# 竞态与死锁的典型定位
go test -race ./...                 # data race 会直接打印两个 goroutine 的栈
GODEBUG=gctrace=1 go run .          # 看 GC 频率与停顿
GODEBUG=schedtrace=1000 go run .    # 每秒打印调度器状态

go build 和 go install 有什么区别？

build 把产物写到当前目录（或用 -o 指定），主要用于产出交付物；install 把产物放到 $GOBIN（默认 $GOPATH/bin），主要用于装命令行工具。Go 1.17 之后装工具推荐 go install pkg@version（在模块外执行，不会污染当前项目的 go.mod），而不再用 go get。

go mod tidy 会不会删掉我需要的依赖？

它会删掉当前代码没有 import 的依赖。三类会被误删：① //go:generate 用到的工具；② 只在特定 build tag / GOOS 下才 import 的包；③ 通过反射间接引用的包。解法：把这些依赖写进一个 tools.go，用 //go:build tools 标签 + import _ "pkg" 显式钉住。

为什么 go test 第二次跑特别快？

因为测试结果被缓存了。Go 会对「相同参数、相同输入（源码+依赖+环境变量）」的测试复用上次结果，输出里会带 (cached)。这在本地很快，但会造成误判（改了外部数据文件、数据库 fixture 时不会失效）。CI 和排查问题时一定要用 -count=1 强制重跑。
