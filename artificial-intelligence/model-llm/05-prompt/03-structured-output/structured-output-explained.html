大模型应用

结构化输出：JSON Mode、约束解码与 Schema 校验

只要把大模型接进真实业务，"让它稳定输出能直接被代码解析的格式"就是绕不过去的一关。本文讲清从提示词约束到 JSON Mode 再到约束解码（Grammar / JSON Schema）的三层手段，以及生产环境必须做的校验与重试。

为什么要结构化输出

大模型的原生输出是自然语言，但程序需要的是数据结构。只要涉及下面任一场景，就必须做结构化：

  • 抽取字段（简历解析、票据识别、舆情打标）
  • 函数调用的参数生成（Tool Use 的前提，见「函数调用与工具使用」）
  • 让模型输出进入数据库 / 工作流 / 前端渲染
  • 多步 Agent 的中间状态传递
靠正则从自然文本里"抠"字段是脆弱方案：换个说法就崩。正确做法是让模型直接产出机器可读格式。

三层手段，可靠性递进

① 提示词约束（最基础，但不可靠）

在 prompt 里写清格式要求，最好给一个示例（few-shot）：

请从文本中抽取信息，严格按以下 JSON 输出，不要输出任何解释文字：
{"name": string, "amount": number, "date": "YYYY-MM-DD"}
示例输入：张三报销差旅 1280 元，日期 2026-03-05
示例输出：{"name":"张三","amount":1280,"date":"2026-03-05"}
模型仍可能在 JSON 前后加"好的，结果是："之类废话，或输出单引号、尾逗号、注释等非法 JSON。必须配合后处理与重试。

② JSON Mode（API 层保证语法合法）

主流厂商提供 response_format={"type":"json_object"} 之类的参数。原理是在解码时屏蔽掉所有不可能构成 JSON 的 token，从而保证输出一定是合法 JSON。

JSON Mode 保证的是语法合法，不保证字段符合你的业务 schema（字段名拼错、类型不对、缺字段照样会发生）。

③ 约束解码 / Structured Outputs（连 schema 一起保证）

效果：结构上不可能出错——字段名、类型、枚举值、必填项都被硬约束住。代表实现有 OpenAI Structured Outputs、vLLM/SGLang 的 grammar / JSON schema 约束、Outlines、Guidance、XGrammar 等。

约束解码是怎么做到的

把 schema 编译成一个状态机（或下推自动机），解码每一步：

  1. 根据当前已生成的前缀，算出"下一个合法 token 集合"
  2. 把集合外的 token 的 logit 置为 -inf（或加掩码）
  3. softmax 后模型只能从合法 token 里采样
  4. 生成完一个 token，状态机前移，重复
优点
几乎 100% 结构正确；无需重试；可做枚举约束、正则约束
代价
每步要维护状态机（有开销，但优化实现很快）；schema 过复杂会略微限制模型表达
注意：约束解码保证"格式对"，不保证"内容对"。模型依然可能抽取出错误的金额或日期——这是模型能力问题，不是格式问题。

生产环境必备：校验 + 重试 + 兜底

即使开了 JSON Mode 或约束解码，工程上仍建议保留防御：

  • 容错解析：先尝试直接 json.loads；失败则截取第一个 { 到最后一个 } 再试；还不行就走重试。
  • Schema 校验：用 pydantic / jsonschema 校验字段名、类型、必填、枚举。
  • 带反馈重试：把校验失败的具体原因（"字段 amount 应为数字"）塞回 prompt 重新请求，成功率很高。
  • 次数上限与兜底：重试 2~3 次仍失败就转人工或走规则兜底，避免死循环烧钱。

实践建议

场景推荐做法
只是要个 JSON，字段简单提示词约束 + few-shot 示例 + JSON Mode，加解析容错
字段多、下游强依赖结构结构化输出 / 约束解码 + JSON Schema，几乎不用重试
函数调用参数直接用厂商的 tools/functions 能力（内部就是约束解码）
需要枚举/分类打标用枚举约束把输出锁在候选集内，杜绝"自造类别"
输出很长且嵌套深拆成多个小 schema 分步生成，别一次让模型吐巨大嵌套结构
常见误区：以为开了 JSON Mode 就万事大吉。它只保证语法，不保证字段名和业务语义；校验环节永远不能省。

面试速记卡

  • 为什么需要：模型原生输出自然语言，程序需要数据结构；正则抠字段是脆弱方案。
  • 三层手段：提示词约束（最弱）→ JSON Mode（保证语法）→ 约束解码/Schema（保证结构）。
  • 约束解码原理：把 schema 编译成状态机，每步把非法 token 的 logit 屏蔽掉。
  • 关键区分：格式正确 ≠ 内容正确，约束解码不提升抽取准确度。
  • 工程四件套：容错解析 + Schema 校验 + 带错误反馈重试 + 兜底与次数上限。
