二分查找写错是大厂面试高频翻车点：死循环、下溢、边界差一。用『不变式 + 两种标准写法』能一次写对，再用对拍测试兜住。

01两种标准写法

写法一：闭区间 [left,right]，left<=right 时继续，中点命中即返回，否则缩区间。写法二：左闭右开 [left,right)，left

# 写法一：闭区间，找等于 target 的下标（无则 -1）
def bs_close(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2          # 防下溢用 lo + (hi-lo)//2（Python 无此问题）
        if a[mid] == target: return mid
        if a[mid] < target: lo = mid + 1
        else: hi = mid - 1
    return -1

# 写法二：左闭右开，找第一个 >= target 的插入位置
def bs_lower_bound(a, target):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < target: lo = mid + 1
        else: hi = mid
    return lo

02四个经典 bug

  • 死循环：lo=mid / hi=mid 没 +1/-1，区间不收缩（尤其写法二里 a[mid]
  • 整数下溢：mid=(lo+hi)//2 在 lo+hi 超 INT_MAX 时溢出；C/Java 用 lo+(hi-lo)/2，Python 无需。
  • 边界差一：循环条件用 < 还是 <= 要和区间定义一致，混用必错。
  • 重复元素：找第一个/最后一个出现位置时，命中后不能立即返回，要继续缩区间。
要点：心法：先决定『区间是闭还是开』，再保证『每次循环都严格缩小搜索范围』，两者定下 bug 自然消失。

03怎么测才放心

用暴力线性搜索做对拍，覆盖空数组、单元素、全相同、target 在首尾/缺失等。随机大量用例自动比对，比手搓几个样例可靠得多。

import random
def brute(a, t):                 # 线性暴力，作为基准
    for i, x in enumerate(a):
        if x == t: return i
    return -1
for _ in range(20000):
    n = random.randint(0, 20)
    a = sorted(random.randint(0, 5) for _ in range(n))   # 含重复
    t = random.randint(-1, 6)
    assert bs_close(a, t) == brute(a, t), (a, t)
print("all passed")

左闭右开lohi=mid / lo=mid+1找插入点/上下界

第一层 · 概念与判定：先确认满足二分的前提

二分查找能在 O(log n) 成立，前提是区间单调且下标连续：有序数组、或答案随某变量单调（答案在区间里）。不满足就去排个序，或改二分答案。

场景用二分别用二分
有序数组查值✓哈希表（已知 key）
「第一个 ≥ x」「最后一个 ≤ x」✓线性扫（数据小）
单调函数求满足条件的最大/小解✓（二分答案）遍历
无序 / 有重复且要全取✗排序后处理

第二层 · 参数·命令·量化：下标与 mid 的写法

项正确做法
区间闭区间 [lo, hi] 或左闭右开 [lo, hi)两种都行，但全程一致
midlo + (hi-lo)/2(lo+hi)/2 在 lo+hi 大时整数溢出
命中后返回 mid要找边界则继续缩区间
边界收缩查左边界 hi=mid；查右边界 lo=mid+1错一处就死循环

Go 防溢出 + 左边界二分

// Go：防溢出的 mid，且查「第一个 >= x」
func lowerBound(a []int, x int) int {
    lo, hi := 0, len(a)               // 左闭右开 [lo, hi)
    for lo < hi {
        mid := lo + (hi-lo)/2           // 注意：不是 (lo+hi)/2
        if a[mid] < x {
            lo = mid + 1
        } else {
            hi = mid
        }
    }
    return lo
}

数量级：10 亿规模二分约 30 次比较；mid 用 (lo+hi)/2 在数组长度超 10 亿且用 32 位 int 时会溢出变成负数，是经典线上 bug。

第三层 · 排障与边界：四个经典 bug

  • 死循环：区间收缩写成 lo=mid / hi=mid 却没处理 mid 取值，导致 lo==hi 后不前进——查左边界用 hi=mid，查右边界必须用 lo=mid+1
  • 整数溢出：mid=(lo+hi)/2 在 lo+hi 很大时溢出，结果变负、下标越界
  • 漏解 / 越界：循环条件写 lo<=hi 但区间定义是 [lo,hi)，导致访问 a[hi] 越界
  • 只测命中、不测边界：x 小于最小、大于最大、重复段都容易错——必须覆盖

第四层 · 原理与取舍

闭区间 [lo,hi] 和左闭右开 [lo,hi) 哪个更好？

两者等价，关键在全程保持一致。左闭右开的好处是「区间长度 = hi-lo」、循环退出时 lo==hi 直接是答案，少一处 ±1；闭区间更直观但循环里要小心 lo==hi 时是否再缩。新手崩在 off-by-one，多半是混用了两种约定。

为什么 mid 必须用 lo+(hi-lo)/2？

因为 (lo+hi) 可能超过 int 最大值（约 21 亿），相加瞬间溢出变负，下标 a[mid] 直接越界 panic。lo+(hi-lo)/2 把差值先除再相加，幅度小一个数量级，不会溢出。这是二分里最隐蔽也最常见的线上故障之一。

对拍测试为什么必要？

二分的 bug 不会在「命中中间」时暴露，只在边界（极值、重复、空区间）暴露。对拍 = 用一份暴力线性解对照二分结果，随机海量用例跑 diff，能在发布前抓出 90% 的 off-by-one 与死循环。
