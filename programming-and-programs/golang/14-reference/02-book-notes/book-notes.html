按阶段推荐的读法

入门期（0~3 个月）

  • 主读 GoPL 的前半部分，配合官方文档
  • 每章都手写示例，不要只看
  • 读完接口与并发两章后可开始小项目
  • 把 Effective Go 当作风格检查表反复对照

进阶期（3~12 个月）

  • 读 Concurrency in Go 建立并发体系
  • 读 100 Go Mistakes 快速避坑
  • 开始读运行时原理（调度、GC、内存）
  • 配合 pprof 在自己项目里实测验证

深入期（一年以上）

  • 系统读设计与实现、底层原理剖析
  • 读标准库源码（net/http、sync、runtime）
  • 关注 Go 官方博客的版本变更说明
  • 尝试给开源项目提 issue 或修复

深入自检

要不要把一本书读完再开始写代码？

不要。Go 上手成本低，读完基础语法与函数、结构体两章就可以写小项目。边写边读，遇到不懂的概念再回头查，记忆与理解都更牢固。

原理类书籍读不懂怎么办？

通常是因为缺少实践参照。可以先带着具体问题去读（比如「为什么 GC 会停顿」），只读相关章节，再用 pprof、GODEBUG 在自己程序里观察现象。抽象变具体后就容易理解了。

官方文档和书哪个更重要？

文档更重要也更及时。Effective Go、Code Review Comments、官方博客是权威且免费的，尤其是版本变更说明——书籍会过时，文档不会。把书当作系统性补充。

笔记记了很多但想不起来，怎么办？

把笔记从「按书组织」改成「按问题组织」。围绕真实问题（比如「连接池耗尽怎么排查」）把多个来源的结论汇聚到一起，用到时能直接检索到，价值远高于章节摘抄。

怎么判断自己是否真的掌握了某个知识点？

三个检验：能不能不看资料给别人讲清楚；能不能写出一个最小复现代码；能不能说出它的适用边界与反例。三条都做到，才算真正掌握。

配套工具命令

# 读书配套的硬规矩（比读哪本书更重要）
go test -race ./...                 # 并发代码必须过 race 检测
go vet ./...                        # 静态检查
gofmt -l .                          # 格式，输出为空才算过关
go test -bench=. -benchmem ./...    # 性能断言要有数字
go tool pprof -http=:8080 cpu.pprof # 性能问题先 profile，别猜

判断有没有真的学会，就看能不能在不查资料的情况下解释：为什么 for range 里直接取循环变量地址会错、defer 在循环里为什么危险、sync.WaitGroup 的 Add 为什么要在 goroutine 外调用。

常见误区与自检

  • 只读书不读标准库：Go 的精华一半在标准库源码里。net/http 一个包就能学到接口设计、并发模型和错误处理。
  • 过早引入框架：先把标准库和 net/http 用熟，再评估 go-zero / gin / kratos，否则只会抄脚手架。
  • 忽略工具链：go vet、-race、pprof 是 Go 相对其他语言的最大优势之一，不用等于白用。
  • 死记并发原语：记住 channel 是「传值的通信」，不是「共享内存的锁替代品」，很多误用源于此。
新手第一本读哪本？

有编程经验 → TGPL；零基础 → 先 Go Tour 再 Go in Action。别一上来就读底层原理。

要不要先学 C？

不必。想理解指针和内存时补一点 C 有帮助，但Go 的指针是安全的、不带指针算术，拿 C 的心智模型学 Go 反而容易过度设计。

读书和做项目怎么排？

3:7。读完一章立刻做一个用到该章知识的小东西，否则 ch8 的并发知识一周就忘。
