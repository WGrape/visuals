冷启动

新用户新物品怎么办

先建立直觉：图书管理员的三步筛选

图书馆有百万册书，要给你推荐 10 本。管理员不会逐本评估，而是分三步：

  1. 召回：根据你的兴趣和相似读者的喜好，快速从百万册里捞出几百本候选（粗筛，宁可多不可漏）；
  2. 排序：对这几百本逐本精算你会喜欢的概率，排出前 50；
  3. 重排：调整顺序——避免全是同一类、插入一些新书、去掉你看过的，最终给出 10 本。

这就是推荐系统的经典三段式：召回 → 排序 → 重排。

为什么必须分三段

本质是「计算预算的分配」。线上推荐要求几十毫秒内返回，不可能对百万候选逐个跑复杂模型。所以：便宜的模型处理大量候选（召回），昂贵的模型处理少量候选（排序）——把算力花在刀刃上。

召回：多路并行

召回方式原理优点
协同过滤（ItemCF）看过 A 的人也看 B简单有效，无需内容理解
协同过滤（UserCF）和你相似的人喜欢什么适合用户数远小于物品数的场景
向量召回（Embedding）把用户和物品映射到同一向量空间，近邻检索主流方案，泛化能力强
内容/标签召回按类目、标签匹配可解释，缓解冷启动
热门召回全局热门兜底新用户冷启动必备
多路召回的意义：每一路覆盖不同的兴趣面，合并后才能兼顾相关性、多样性、新颖性。只用一路会导致结果单一（信息茧房）。

排序：从 LR 到深度学习

阶段模型特点
早期逻辑回归 LR + 人工特征交叉可解释，依赖特征工程
中期GBDT + LR（Facebook 方案）自动做特征交叉
中期FM / FFM自动学习特征间交互
当前主流DeepFM / DIN / DCN / 双塔深度学习，端到端，效果最好

排序模型预估的目标通常是 CTR（点击率），电商场景还会预估 CVR（转化率），最终按 CTR × CVR × 价格 等业务目标排序。

重排：不只是排序

重排阶段处理单纯按分数排序解决不了的问题：

  • 多样性：避免前 10 条全是同一类目（打散策略）；
  • 去重：过滤已看过的、已购买过的；
  • 新颖性/探索：故意插入一些不确定的内容，收集反馈（解决信息茧房）；
  • 业务规则：置顶运营内容、过滤敏感内容、保证某些品类曝光量。

冷启动

类型问题常用解法
新用户没有历史行为热门兜底 + 引导选择兴趣 + 用设备/地域等上下文 + 快速试探
新物品没有曝光与交互内容/标签召回 + 冷启动流量池（保量曝光）+ 快速积累样本
新系统什么都没有先用规则/热门，积累数据后逐步切模型
冷启动和「探索与利用」（EE）是推荐系统的经典难题：只推已知喜欢的（利用），短期指标好但会形成信息茧房；推不确定的（探索），短期指标差但能发现新兴趣。工业界常用 ε-greedy、UCB、Thompson 采样 等策略平衡。

🎯 面试问答

Q：为什么推荐系统要分召回和排序，不能一步到位？
A：因为算力和延迟的约束。线上推荐要在几十毫秒内返回，而候选集有百万级。如果对百万候选逐个跑复杂深度学习模型，计算量不可承受。所以采用漏斗式：先用便宜快速的模型（召回）把候选降到千级，再用昂贵的复杂模型（排序）精算这千级候选。本质是「把算力花在刀刃上」。

Q：协同过滤和向量召回有什么区别？
A：协同过滤基于共现统计——「看过 A 的人也看 B」，直接统计行为矩阵，简单但泛化差（无法处理没共现过的组合）。向量召回把用户和物品映射到同一向量空间，用近邻检索（ANN）找相似项，泛化能力强（能发现潜在的、未共现过的关联），且能融合内容信息，是目前的主流方案。两者常同时使用：CF 作为一路召回保证相关性，向量召回补充泛化能力。

Q：什么是信息茧房，怎么破？
A：信息茧房指系统只推荐用户已经表现出兴趣的内容，导致用户视野越来越窄、长期体验下降。破解手段：① 重排阶段加多样性打散（限制同类目连续出现数量）；② 主动探索（用 ε-greedy / UCB 等策略，故意插入一定比例的不确定内容）；③ 引入「偶然性」信号（如跨类目关联、时效性内容）；④ 评估指标不只看短期 CTR，还要看长期留存与多样性指标。

Q：推荐系统的效果怎么评估？
A：分三层：① 离线——用历史数据算 AUC、GAUC、召回率@K，快速迭代模型（但不能完全代表线上）；② 在线实验——A/B 测试是金标准，看 CTR、CVR、人均时长、GMV 等业务指标；③ 长期指标——留存率、多样性、用户满意度，防止短期指标好看但长期受损。关键原则：离线涨不等于线上涨，最终必须以 A/B 实验的业务指标为准。

推荐链路：四层漏斗与延迟预算

工业推荐系统不是「一个模型」，而是一条逐级收窄的漏斗。每一层的候选量、可用模型复杂度、延迟预算都不一样。

层输入 → 输出单请求延迟预算常用方法为什么这么设计
召回 Recall百万~亿级 → 几千10~30 ms双塔向量（ANN 检索）、i2i、u2u、热门、标签倒排要覆盖尽可能多的可能兴趣，宁可粗
粗排 Pre-rank几千 → 几百5~15 ms轻量模型（双塔打分 / 浅层 MLP）给精排减负，砍掉明显不相关
精排 Rank几百 → 几十20~50 msDIN / DIEN / DeepFM / MMoE 多目标特征最全、模型最重，决定最终顺序
重排 Re-rank几十 → 十几5~10 ms多样性打散、打压、业务规则、MMR / DPP满足体验约束（不能连续 5 条同类）

漏斗设计的核心理由是算力约束：精排模型参数量大、特征多，不可能对 1 亿物料打分。所以「先用便宜的方法把范围缩到几千，再用贵的方法仔细排」是唯一可行的架构。召回决定天花板，精排决定转化率——召回漏掉的物品，精排再好也推不出来。

指标体系与常见问题解决

指标定义关注点
CTR点击 / 曝光最基础，但容易被标题党带偏
CVR转化 / 点击与 CTR 常此消彼长，要看 CTR×CVR
AUC排序能力的全局指标对样本分布不敏感，但不反映线上实际收益
GAUC按用户分组加权平均的 AUC比 AUC 更贴近线上，工业界更看重
NDCG@K考虑位置权重的排序质量搜索/推荐都常用
覆盖率 / 多样性曝光物料占全库比例 / 结果间差异防马太效应，长期生态指标
新颖性 / 惊喜度用户没见过但不讨厌的比例长期留存的关键，短期指标会下降
问题表现解法
冷启动（新用户/新物品）没有行为数据，模型给不出分新物品：用内容特征（类目/文本/图片 embedding）；新用户：用注册信息 + 热门 + 探索策略（Bandit）
马太效应头部物料越来越热，长尾永不曝光重排多样性打散；召回里预留「探索流量」（如 5%）
信息茧房推荐越来越窄，用户腻加入随机探索、跨类目召回、EE（Explore-Exploit）策略
CTR 涨但时长跌标题党/低质内容被推上去多目标建模（点击 + 时长 + 完播 + 负反馈），加权融合
线上线下不一致离线 AUC 涨，线上 A/B 没效果排查特征穿越（用了未来的label）、样本偏差、延迟特征

# 离线评估：GAUC（按用户加权，比全局 AUC 可靠）
def gauc(preds, labels, users):
    tot_w, tot_a = 0.0, 0.0
    for u in np.unique(users):
        m = users == u
        if m.sum() < 2 or labels[m].sum() in (0, m.sum()):
            continue                       # 该用户无区分度，跳过
        tot_a += roc_auc_score(labels[m], preds[m]) * m.sum()
        tot_w += m.sum()
    return tot_a / tot_w

# 多路召回融合（加权 + 去重）
items = {}
for src, w in [('i2i', 1.0), ('u2i', 1.2), ('hot', 0.5), ('tag', 0.8)]:
    for iid, score in recall(src):
        items[iid] = items.get(iid, 0) + w * score

召回和排序，先优化哪个？

先看瓶颈在哪：如果精排 top50 里人工看大部分都相关，说明排序已经够好，该扩召回（加新路召回、提高 efSearch）；如果 top50 里很多明显不相关，说明召回太粗或精排太弱。实用判据：看「用户点击的物品是否在召回集合里」——不在就是召回的问题，在但没排上去就是排序的问题。

深度学习模型（DIN/DIEN）比传统 CF 好在哪？

核心是兴趣建模的动态化。CF/矩阵分解给用户一个固定向量，无法表达「这次想买运动鞋、下次想买书」；DIN 用注意力根据当前候选物品，从用户历史行为里动态挑相关的那部分（如候选是「跑鞋」就重点看历史里的运动类行为）。DIEN 进一步建模兴趣的演化序列。

为什么线上 A/B 才是最终标准？

因为离线指标测的是拟合历史数据的能力，而推荐是闭环系统：模型改变曝光 → 曝光改变用户行为 → 用户行为变成新样本 → 又影响模型。这个反馈环会让离线指标失真（典型的「离线涨、线上平」）。所以任何模型上线都必须经过 A/B，且要看长期指标（次日/7日留存）而不只是当天 CTR。
