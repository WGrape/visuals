注意力变体：FlashAttention / MQA / GQA 为什么出现

标准自注意力复杂度 O(n²)，显存和速度都吃不消长序列。为降本提速，派生出 FlashAttention（IO 感知）、MQA/GQA（共享 KV）、稀疏/线性注意力。本文讲清每种解决什么、代价是什么。

一句话回答

标准注意力的瓶颈是 O(n²) 的显存与算力。三条优化路线分别打不同痛点：FlashAttention 解决「显存带宽」、MQA/GQA 解决「KV Cache 太大」、稀疏/线性注意力 解决「n² 计算本身」。

标准注意力的瓶颈

对长度 n、维度 d：每个头的注意力要算 n×n 的分数矩阵，复杂度和显存都随 n² 增长。

显存: O(n²·h)    算力: O(n²·d)

更致命的是显存带宽：标准实现要把巨大的 n×n 中间矩阵写回 HBM 再读回来算 softmax，GPU 大部分时间在「搬数据」而非「算」。长上下文（32k/128k）下这事直接炸。

FlashAttention：不写出完整矩阵

FlashAttention（Dao 2022）的核心是 IO-aware：把 Q/K/V 切块（tiling），在 GPU 高速缓存（SRAM）里一块一块算 softmax 并累加，全程不把 N×N 中间矩阵写回显存。需要重算（recomputation）反向时的中间值，用「算力换带宽」。

收益：显存从 O(n²) 降到 O(n)，速度数倍提升，且数值完全等价于标准注意力（不是近似）。是长上下文和高效训练推理的基石，v2/v3 进一步优化。
FlashAttention 不改数学结果，只是更聪明的「搬运+计算」顺序。它和下面的 MQA/GQA 是正交的——可以叠加。

MQA（Multi-Query Attention）：共享 KV

标准 MHA 里，每个注意力头有自己的一套 Q、K、V。推理时每个 token 都要缓存一份 K、V（KV Cache），头数一多，缓存巨大、且读取 KV 的显存带宽成为瓶颈。

MQA（Shazeer 2019）：所有头共享同一份 K 和 V，只保留多套 Q。KV Cache 直接缩小 h 倍。

代价：质量略降、训练可能不稳；但推理提速明显，PaLM 等采用。

GQA（Grouped-Query Attention）：折中方案

GQA（Ainslie 2023）是 MHA 和 MQA 的折中：把 h 个头分成 g 组，每组共享一份 K、V。g=1 就是 MQA，g=h 就是 MHA。

Llama 2/3、Mistral、Qwen 等几乎都用 GQA。它几乎不掉点，却把 KV Cache 和推理延迟压下来一大截，是「质量-效率」的最优平衡点。一般取 g = 头数 / 若干（如 8 头分 4 组）。

稀疏 / 线性注意力：砍掉 n² 计算

前面几种大多只优化常数。若要真正摆脱 O(n²)，得限制「每个 token 看多少个」：

稀疏注意力
只算局部窗口 + 少量全局 token（Longformer、BigBird），复杂度降到 O(n·√n) 或 O(n·w)。
线性注意力
用核函数把 softmax 重排，先算 V·Kᵀ 再乘 Q，复杂度 O(n·d²)，与 n 线性（Linear Attention、RetNet、Mamba 类）。
代价：稀疏/线性会损失全局交互能力，质量或长程依赖上通常弱于稠密注意力，工业落地不如 FlashAttention+GQA 普遍。

总结

  • 标准注意力 O(n²) 卡在显存带宽和KV 缓存。
  • FlashAttention = 更聪明的计算顺序（不写大矩阵），精确且快。
  • MQA/GQA = 共享 KV，直接压推理缓存与延迟，GQA 是性价比之王。
  • 稀疏/线性 = 真·降复杂度，但质量权衡大，落地面较窄。
  • 现实中常叠加：GQA + FlashAttention + 分页 KV Cache（PagedAttention）。

四种注意力：KV cache 是分水岭

变体Query 头数KV 头数KV cache 倍数代表模型
MHA（多头）hh（一一对应）1×（最大）GPT-3、Llama 1、BERT
MQA（多查询）h1（全部共享）1/h（最小）PaLM、Falcon、StarCoder
GQA（分组查询）hg（分组共享）g/hLlama 2/3、Qwen、Mistral
MLA（多头潜在）h低秩压缩潜向量约 1/10 – 1/5DeepSeek-V2/V3

为什么 KV cache 这么重要：自回归生成时，每生成一个 token 都要把之前所有 token 的 K、V 参与计算，所以必须缓存。KV cache 随序列长度线性增长，是推理显存的主要占用者——常常比模型权重本身还大。

KV cache 显存：手算一遍

模型结构每 token KV cache4K 上下文总占用
Llama 2 7B32 层，32 头，head_dim 1282 × 32 × 4096 × 2 B ≈ 0.5 MB约 2 GB
Llama 2 70B（MHA）80 层，64 头2 × 80 × 8192 × 2 B ≈ 2.6 MB约 10.7 GB
Llama 2 70B（GQA, 8 KV 头）80 层，8 KV 头2 × 80 × 8 × 128 × 2 B ≈ 0.33 MB约 1.3 GB（降到 1/8）

计算公式：KV_cache = 2 × 层数 × KV头数 × head_dim × 序列长度 × 字节数。乘 2 是因为 K 和 V 各一份；字节数 fp16 = 2，fp8 = 1，量化后还能再砍一半。

KV cache 计算

# KV cache 显存计算（可直接跑）
def kv_cache_bytes(n_layers, n_kv_heads, head_dim, seq_len, dtype_bytes=2, batch=1):
    return 2 * n_layers * n_kv_heads * head_dim * seq_len * dtype_bytes * batch

# Llama 2 70B: 80 层, GQA 8 个 KV head, head_dim=128
b = kv_cache_bytes(80, 8, 128, 4096)
print(f"GQA  4K 上下文: {b/1024**3:.2f} GB")     # 约 1.34 GB

# 如果是 MHA（64 个 KV head）
b = kv_cache_bytes(80, 64, 128, 4096)
print(f"MHA  4K 上下文: {b/1024**3:.2f} GB")     # 约 10.7 GB  -> 差 8 倍

# 实用结论：
#   70B 模型 fp16 权重 = 140 GB（需多卡）
#   MHA 时 batch=8 + 4K 上下文 -> KV cache 85 GB -> 显存直接爆
#   GQA 时只要 10.7 GB -> 可以跑起来
# 这就是 GQA 成为大模型标配的原因

常见误解澄清：GQA 不是“性能更差”的妥协。实测在相同参数量下，GQA 与 MHA 的效果非常接近（差距通常 < 1%），但显存和速度有数量级优势。真正折损较大的是 MQA（只有 1 个 KV 头），所以主流选择了中间的 GQA。

FlashAttention：为什么又快又省

维度标准 AttentionFlashAttention
显存复杂度O(N²)（要物化整个 N×N 矩阵）O(N)（分块计算，不落盘）
HBM 读写量O(N²d + N²)O(N²d²/M)（M = SRAM 大小）
2K 序列显存N² × 2 B ≈ 8 MB/头接近 0
8K 序列显存约 128 MB/头接近 0
速度（相比标准）1×2 – 4×（FA2 再快约 2×）
数学结果—完全一致（不是近似算法）

核心洞察：Attention 慢的瓶颈不是计算量，而是显存带宽。标准实现要把 N×N 的注意力矩阵写回显存再读出来做 softmax，而 SRAM（片上缓存，A100 约 20 MB）比 HBM（约 1.5 – 2 TB/s）快一个数量级。FlashAttention 用分块（tiling）+ 在线 softmax，让整个计算在 SRAM 内完成，永远不把 N×N 矩阵写回 HBM。

FlashAttention 用法

# 使用 FlashAttention（PyTorch 2.0+ 内置）
import torch.nn.functional as F

# 方式一：自动选择后端（推荐）
out = F.scaled_dot_product_attention(q, k, v, is_causal=True)

# 方式二：强制指定后端（调试 / benchmark）
from torch.nn.attention import sdpa_kernel, SDPBackend
with sdpa_kernel(SDPBackend.FLASH_ATTENTION):
    out = F.scaled_dot_product_attention(q, k, v, is_causal=True)

# 检查可用后端
from torch.backends.cuda import flash_sdp_enabled, mem_efficient_sdp_enabled
print("Flash:", flash_sdp_enabled(), "MemEfficient:", mem_efficient_sdp_enabled())
# 都是 False 时检查：CUDA 版本、GPU 架构（FA 需 Ampere+，即 A100 / RTX 30 系以上）

# 安装原版（需要更多控制时）
pip install flash-attn --no-build-isolation

# 实测对比（seq=8192, batch=8, 16 heads）：
#   标准 attention : 约 20 GB 峰值显存
#   FlashAttention : 约 2.5 GB 峰值显存  -> 省 8 倍，速度快约 3 倍

FlashAttention 不是近似算法——输出与标准注意力数值完全一致。它通过在线 softmax（逐块归一化 + 累积修正因子）避免了“要看完整行才能 softmax”的限制。

其他重要变体速览

变体解决的问题复杂度现状
Sparse Attention长序列 O(N²) 太贵O(N√N) 或 O(N log N)部分被线性/Flash 方案替代

PagedAttention 的洞察：传统 KV cache 为每个请求预分配最大长度的连续显存，实际只用了 20 – 40%。它借鉴操作系统虚拟内存分页——把 KV cache 切成固定块（如 16 个 token 一块）按需分配、非连续存储，利用率提到 90% 以上，同等显存下吞吐提升 2 – 4 倍。这是 vLLM 流行的根本原因。

深入自检

为什么现在的大模型都用 GQA 而不是 MHA？

核心是推理成本。训练时两者计算量差别不大，但推理时KV cache 差 h/g 倍。70B 模型 4K 上下文：MHA 要 10.7 GB，batch=8 就是 85 GB——单卡放不下；GQA（8 KV 头）只要 1.3 GB，batch=8 才 10.7 GB，轻松跑起来。而质量损失实测很小（通常 < 1%）。这个交换非常划算。

FlashAttention 对所有情况都更快吗？

不是。短序列（< 512）时优势很小甚至略慢——它的收益来自减少 HBM 读写，而短序列时 N×N 矩阵本来就小，读写量不大，反而多了分块和在线 softmax 的开销。另外有硬件要求：需要 Ampere 架构以上（A100/H100/RTX 30 系+），且对 head_dim 有限制（常见支持 64/128）。短序列或老显卡上标准实现可能更快。

长上下文（128K、1M）是怎么做到的？

四层技术叠加：① FlashAttention 解决显存；② GQA / MLA 把 KV cache 压到 1/8 甚至 1/10；③ RoPE 外推 / YaRN / 长上下文微调让位置编码支持更长；④ PagedAttention + prefix caching 提高利用率与复用。再往上是稀疏/线性注意力和检索增强。注意：即使技术可行，长上下文的注意力质量会下降（lost in the middle），且成本线性上升——能用 RAG 解决就不要硬堆上下文。

MLA（DeepSeek）相比 GQA 强在哪？

MLA 对 KV 做低秩联合压缩：不直接缓存 K、V 矩阵，而是缓存一个低维潜向量（如 512 维而非 8192 维），推理时再上采样还原。官方数据：KV cache 相比 MHA 减少 93.3%，比 GQA（通常降 8 倍 = 87.5%）更进一步，同时保持更好的效果。代价是实现复杂（要改注意力的数值流）且与部分现有推理优化不兼容。这是 DeepSeek 能以低成本提供长上下文的关键。
