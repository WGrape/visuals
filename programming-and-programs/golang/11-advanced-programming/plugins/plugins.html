插件（plugin）

用 buildmode=plugin 在 Linux/macOS 动态加载 Go 编译的共享库。一篇讲清能力与坑。

概述编译插件加载使用限制
概述

运行时加载 Go 代码

plugin 包配合 -buildmode=plugin，把 Go 包编译成 .so，主程序在运行期打开并调用其导出符号。

适用场景：热插拔策略、可扩展的过滤器；不适合跨语言或强隔离需求。
编译插件

-buildmode=plugin

用 go build -buildmode=plugin 产出 .so；只有导出的函数/变量（首字母大写）能被外部 lookup。

// plugin.go
package main
var Hello = func() string { return "hi" }
func Add(a, b int) int { return a + b }

# 编译：
go build -buildmode=plugin -o p.so plugin.go
加载使用

plugin.Open + Lookup

plugin.Open 打开 .so，Lookup 取出符号并断言成具体类型后调用；失败需处理错误。

p, _ := plugin.Open("p.so")
sym, _ := p.Lookup("Add")
add := sym.(func(int, int) int)
add(1, 2)
限制

平台与版本约束

仅 Linux/macOS 支持；主程序与插件必须用同一 Go 版本与相同依赖构建，否则符号不匹配；不支持 Windows。

⚠️ 插件对构建环境极其敏感，版本/依赖不一致会运行时报错；多数场景用进程内接口+配置更稳。
