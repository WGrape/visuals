📊 一、数据表示与运算

🔢

数制与转换

  • 二进制、八进制、十进制、十六进制
  • 任意进制转十进制：按权展开
  • 十进制转其他进制：除基取余/乘基取整
  • 二进制与八/十六进制快速转换
➕➖

带符号数表示

  • 原码：符号位 + 绝对值
  • 反码：正数同原码，负数除符号外取反
  • 补码：正数同原码，负数反码+1
  • 移码：补码符号位取反
🎯

定点数与浮点数

  • 定点数：小数点位置固定
  • 浮点数：阶码 + 尾数 (IEEE 754)
  • 规格化：尾数最高位为1
  • 精度丢失与溢出判断

🧮 二、运算器与ALU

⚙️

ALU 组成

  • 算术运算：加/减/乘/除
  • 逻辑运算：与/或/非/异或
  • 移位运算：逻辑/算术/循环
  • 标志位：CF/ZF/SF/OF
🔄

乘法除法器

  • 原码乘法：符号单独处理
  • 补码乘法：Booth算法
  • 恢复余数法 / 加减交替法
  • 阵列乘法器并行实现
🔢

定点运算

  • 溢出判断：双符号位法
  • 补码加法：直接相加
  • 补码减法：变补操作
  • 移位配合实现乘除

💾 三、存储器层次结构

🏔️

层次结构

  • 寄存器 → Cache → 主存 → 磁盘 → 磁带
  • 容量：越来越大
  • 速度：越来越慢
  • 成本：越来越低
🎯

主存组织

  • 存储单元：字节/字为单位
  • 地址译码：单译码/双译码
  • 刷新：定期刷新保持数据
  • 带宽 = 频率 × 数据总线宽度
⚡

Cache 缓存

  • 映射方式：直接/组相联/全相联
  • 替换算法：LRU/FIFO/RAND
  • 写策略：Write Through / Write Back
  • 命中率与平均访问时间

📝

指令格式

  • 操作码 + 地址码

  • 定长/变长指令格式
  • 指令字长与机器字长的关系

⚡ 七、性能指标

📈

基本指标

  • 时钟周期：CPU最小时间单位
  • 机器周期：完成一次基本操作
  • 指令周期：执行一条指令的时间
  • CPI：每条指令平均时钟周期数
🧮

性能公式

  • 程序CPU时间 = 指令数 × CPI × 时钟周期
  • IPS = 时钟频率 / CPI
  • FLOPS = 浮点运算次数 / 时间
  • MIPS = 每秒百万条指令
⚖️

Amdahl定律

  • Speedup = 1 / (1-F + F/S)
  • F：可改进部分比例
  • S：改进加速比
  • 系统加速比有理论上限

核心速览

核心思想存储程序：指令和数据都放内存冯·诺依曼结构的基石
五大部件运算器、控制器、存储器、输入、输出现代 CPU 把前两者合在一起
执行循环取指 → 译码 → 执行 → 访存 → 写回一条指令的完整生命周期
性能公式CPU 时间 = 指令数 × CPI × 时钟周期优化永远从这三处下手

冯·诺依曼结构

混在一起存放③ 控制器取指、译码、发出控制信号④ 运算器ALU 做算术与逻辑运算⑤ 输出设备把结果送出去
五大部件通过总线连接，指令与数据共享同一存储器（这就是瓶颈的来源）

一条指令的旅程

经典五级流水线：理想情况下每周期流出一条指令

性能指标怎么算

CPU 时间 = 指令条数 × CPI × 时钟周期时间 = IC × CPI × 1/f 例：程序有 1e9 条指令，CPI = 1.5，主频 3 GHz CPU 时间 = 1e9 × 1.5 / 3e9 = 0.5 秒 三个优化方向： - 减少 IC：编译优化、更优算法（指令数变少） - 降低 CPI：流水线、乱序、分支预测、更好的缓存 - 提高 f：制程与架构（受功耗墙限制，近年提升缓慢） MIPS = 主频 / CPI / 1e6 （每秒百万条指令） 注意：MIPS 高不代表真的快，指令集不同不能直接比

层次化存储：为什么要分这么多层

层次典型容量访问延迟每 GB 成本谁来管理
寄存器几百字节~0.3 ns极高编译器
L1 Cache几十 KB~1 ns高硬件
L2 / L3MB 级几 ns ~ 几十 ns较高硬件

SSD / 磁盘TB 级几十 μs ~ ms低OS + 应用

三个衡量视角

① 吞吐 vs 延迟吞吐是「单位时间干多少活」，延迟是「一个活多久干完」。批处理看吞吐，在线服务看延迟（尤其长尾）。
② 单核性能 vs 并行度单核性能受限于指令级并行；并行度取决于能否拆成可并行的任务。
③ 峰值 vs 实际理论峰值（如 FLOPS）几乎达不到，实际取决于内存带宽与数据局部性。

深入自检

冯·诺依曼瓶颈是什么？

指令和数据共用同一条总线与存储器，CPU 每周期都要从内存取指令与数据，而内存速度远慢于 CPU。缓解手段就是缓存、指令预取、以及把常用数据放进寄存器。

哈佛结构和它有什么区别？

哈佛结构把指令存储与数据存储分开，可并行取指与取数，吞吐更高，常用于 DSP 与单片机。现代 CPU 在 L1 层其实是「改进的哈佛」：指令缓存与数据缓存分开，但主存仍统一。

主频越高就一定越快吗？

不一定。还要看 CPI 与指令数。更重要的是，主频受功耗墙限制，所以近年性能提升主要靠多核、向量指令与专用加速器，而不是堆主频。

为什么缓存能带来数量级的性能差异？

因为 DRAM 访问约 100 ns，而 L1 约 1 ns，差了百倍。若程序局部性好，绝大多数访问命中缓存，等效访存时间就接近缓存而不是内存。

CPI 和 IPC 是什么关系？

IPC（每周期指令数）= 1 / CPI。标量流水线理想 IPC=1；超标量、多发射可以让 IPC > 1。说「某 CPU IPC 提升 20%」等价于 CPI 降低约 17%。
