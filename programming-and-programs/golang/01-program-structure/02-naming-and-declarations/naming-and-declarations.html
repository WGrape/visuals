命名

名字可见性：大写导出，小写包内

Go 没有 public/private 关键字，标识符是否「导出」完全由首字母决定。这是包封装的第一道闸门。

package model

// Exported：首字母大写，其他包可访问
type User struct { ID int; Name string }

// 未导出：首字母小写，仅本包可见
func validate(u *User) bool { return u.Name != "" }

// 包级变量同样适用该规则
var DefaultTimeout = 30 // 导出
var debugMode = false    // 包内私有
惯例：导出名字用「能读懂的缩写」即可（如 ID、HTTP），未导出名字可更短。不要靠下划线前缀（如 _foo）表达私有——Go 不鼓励这种写法。
声明

四种声明：var / const / type / func

声明把「名字」绑定到「实体」。Go 是静态类型语言，声明时类型通常已知（可省略让编译器推断）。

var x int = 10          // 完整写法
var y = 10              // 类型推断为 int
var z int               // 零值 0

const Pi = 3.14159      // 常量，编译期确定

type Point struct { X, Y int }  // 类型声明

func add(a, b int) int { return a + b }  // 函数声明

零值才是关键

Go 中每个变量声明后都有一个确定的零值：数值为 0，布尔为 false，字符串为 ""，指针/接口/切片/map/chan 为 nil。这意味着变量「声明即可用」，不存在未初始化垃圾值。

变量与赋值

变量与赋值：:= 与 = 的区别

短声明 := 仅能在函数内使用，左侧至少包含一个新变量；= 是纯赋值，要求变量已存在。

func main() {
    name := "go"        // 短声明：声明+赋值
    var age int = 18    // 标准声明
    age = 19            // 赋值（已存在）
    name, err := foo()  // 至少一个新变量(name已存在,err新)也合法
    const c = 1         // 函数内也能用 const
}
⚠️ 在 if / for 头部用 := 创建的变量，作用域仅限于该语句块；常见的坑是「本想复用外层 err，却新建了一个同名的局部 err」，导致外层 err 始终为 nil。
作用域

词法作用域：名字在哪生效

作用域由「词法块」决定：全局块、包块、文件块、函数块、语句块。内层可看见外层，外层看不到内层，同名时内层遮蔽外层。

var x = "package"   // 包级

func f() {
    x := "local"      // 遮蔽包级 x
    {
        x := "block" // 再遮蔽
        fmt.Println(x) // 输出 block
    }
    fmt.Println(x)    // 输出 local
}
「遮蔽（shadow）」容易引发隐蔽 bug。工具 go vet 与 shadow 检查器能帮你抓出意外的变量遮蔽。

声明形式的对照与限制

形式能否在函数外是否必须显式类型注意
var x int = 1可以可省略（靠初始值推导）包级变量声明
var x = 1可以否类型由右值推导
x := 1不可以否仅函数内；且左侧至少有一个新变量
const c = 1可以否编译期常量，无类型常量可隐式转换
x, y := 1, 2不可以否多值短声明
var ( a int; b string )可以是分组声明，常用于包级变量

声明

package main

import "fmt"

var (
    MaxRetries = 3        // 包级：导出常量风格 MixedCaps
    timeout    = 30       // 包级私有
)

func main() {
    x := 1                     // 短声明，仅函数内
    x, y := 2, 3               // 合法：y 是新变量
    // x, err := 4, err        // 常见坑：左侧全是已声明变量会报 no new variables
    fmt.Println(x, y)

    var _ = unused             // 空白标识符：显式丢弃（也可用于触发 init）
}

// 空白标识符的三种典型用法
var _ Interface = (*Impl)(nil)  // 编译期断言：Impl 实现了 Interface

深入自检

Go 的可见性为什么只用首字母大小写？

语言设计取舍：省掉 public/private 关键字，让可见性在调用处一眼可见（大写即跨包）。代价是粒度只有包一级，同包内无隐私；好处是规则极简、无需记忆修饰符。

为什么 Go 里未使用的局部变量是编译错误？

设计者认为未使用的变量与导入几乎总是笔误或遗留代码，编译期报错能强制保持代码整洁，也加快编译（无需做无用代码分析）。包级变量与函数不受此限制。

:= 和 var 怎么选？

函数内首选 :=（短、类型推导）；需要零值声明（var b bytes.Buffer）、需要显式类型（var n int64 = 1）、或在函数外声明时用 var。注意 := 左侧至少要有一个新变量。

如何避免 err 被遮蔽的经典 bug？

在内层作用域用 := 声明 err 会创建新变量，外层 err 不被赋值，导致 if err != nil 判断的是新变量。做法：外层先 var err error，内层用 =；或用工具（staticcheck、shadow）检查。

导出标识符为什么必须写注释？

因为 godoc 以注释作为文档来源，规范是注释以标识符名开头（如 // Client is ...）。没有注释的导出符号会被 golint/revive 报 warning，也让自动生成的文档缺失。

进阶层 · 变量声明与作用域的坑

Go 的声明语法很简洁，但短变量声明 := 和作用域规则藏着好几个高频 bug。

写法适用坑
var x T包级变量、需要零值—
var x = expr包级，类型推断—
var x T = expr显式指定类型—
x := expr函数内，最常用只能在函数内；会遮蔽外层变量
var ( ... )批量声明（包级）—
const常量常量是无类型的（除非显式指定）

Go 代码

// —— 坑 1：:= 的变量遮蔽（shadowing）——
var err error
if true {
    result, err := doSomething()   // 【新声明了一个 err】遮蔽了外层
    _ = result
    // 这里的 err 是新的，外层的 err 没被赋值
}
// 外层的 err 仍然是 nil！【这是经典 bug】
// 正确写法：
var result string
result, err = doSomething()        // 用 = 而不是 :=

// —— 坑 2：:= 至少要有一个新变量 ——
a := 1
a, b := 2, 3        // OK（b 是新的）
a, b := 4, 5        // ❌ 编译错误：no new variables on left side
a, b = 4, 5         // ✅ 用 = 赋值

// —— 坑 3：if/for 里的短声明作用域 ——
if v, err := f(); err != nil {
    // v 和 err 只在这个 if 块内有效
} else if v2 := g(); v2 > 0 {
    // v 在这里【仍然可见】（Go 的作用域规则）
}
// v 在这里不可见

// —— 坑 4：循环变量的捕获（Go 1.22 已修复）——
var fns []func()
for _, v := range []int{1, 2, 3} {
    fns = append(fns, func() { fmt.Println(v) })
}
//   Go < 1.22：三个函数都打印 3（共享同一个 v）
//   Go >= 1.22：每次迭代是【新变量】，正确打印 1,2,3
//   兼容性写法：v := v

// —— 坑 5：包级变量的初始化顺序 ——
var a = b + 1       // Go 会自动处理依赖顺序
var b = 1
//   a 的值是 2（Go 按依赖顺序初始化，不是按书写顺序）
//   【但不能有循环依赖】：var a = b; var b = a  -> 编译错误

// —— 坑 6：init() 的执行顺序 ——
//   同一个文件：按声明顺序
//   同包多文件：按【文件名】顺序（不保证！不要依赖）
//   不同包：先初始化依赖包
//   【建议】init() 只做必需的注册，逻辑放显式调用的 Init()

最高频的 bug：:= 在 if/for 块内遮蔽了外层的 err，导致外层检查不到错误。用 = 或预先声明。

进阶层 · 命名约定与可见性

规则说明例子
首字母大写 = 导出包外可见func Do() vs func do()
包名小写、单词不用下划线、不用驼峰package httputil
接口加 -er单方法接口的惯例Reader、Writer、Closer
Receiver 名短1~2 个字母，不要用 this/selffunc (u *User) Name()
Receiver 类型统一同一类型不要混用值和指针要么全 *T 要么全 T
Getter 不加 GetGo 的惯例user.Name() 而非 GetName()
错误变量 Err 开头—var ErrNotFound
常量不用全大写Go 用驼峰（导出即大写首字母）MaxRetries 而非 MAX_RETRIES
  • 可见性是包级的，不是文件级：同一个包内所有文件共享，小写标识符在同包内都能访问。这常被误认为「文件内私有」。
  • internal 目录提供真正的「包外私有」：a/internal/x 只能被 a/ 子树内 import，这是编译器强制的。
  • Receiver 用值还是指针：① 要修改接收者 → 指针；② 结构体很大（>几十字节）→ 指针（避免拷贝）；③ 含互斥锁等不可拷贝字段 → 必须指针；④ 其余（小结构体、基础类型的包装）→ 值。同一类型要统一，混用会让方法集出问题。
  • 方法集的坑：值类型 T 的方法集只包含值接收者的方法；指针类型 *T 的方法集包含值和指针接收者的全部方法。所以如果某个接口方法用了指针接收者，那么只有 *T 满足该接口，T 不满足——这是「为什么 []T 不能传给 []Interface」的常见原因之一。
  • 空标识符 _：忽略返回值、忽略 import（_ "pkg" 只为触发 init）、占位。不要用它忽略错误。
