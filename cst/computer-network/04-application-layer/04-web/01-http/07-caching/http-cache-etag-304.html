HTTP 缓存与条件请求：200、304、强缓存怎样选择

用一张静态图片的更新过程拆开 Cache-Control、ETag、Last-Modified 和 CDN 缓存。

缓存先解决什么问题

浏览器、代理和 CDN 可保存 HTTP 响应，后续请求从近处复用内容，减少延迟与源站压力。缓存能否复用，取决于请求方法、状态码、响应头、缓存键以及资源是否对该用户可见。公共静态图片可以被共享缓存使用，带个人信息的响应则需谨慎控制私有性。不能只因为 URL 相同就默认两个用户看到的内容相同。

缓存判断分两层：新鲜期间可直接使用已存副本，过期后可以向源站发条件请求验证副本是否仍有效。条件请求收到 304 Not Modified，表示可继续使用本地正文，304 响应本身一般不携带完整资源正文。它仍发生了一次网络往返，因此“304 命中”与完全不发请求的强缓存体验不同。

箭头表示本例中的处理次序；每个环节的状态都要分别验证，不能由前一环节成功推断后一环节成功。

Cache-Control 的常见组合

`max-age=600` 表示响应可在相应缓存语义下保鲜约十分钟；浏览器看到仍新鲜时通常直接使用本地副本。`private` 限制共享缓存存储，适合与用户相关但可在浏览器缓存的响应；`no-store` 要求不要存储；`no-cache` 名字容易误导，它通常表示使用前必须向源站验证，而不是绝对不能保存。`s-maxage` 可为共享缓存设置与浏览器不同的寿命。

`public` 不等于资源没有访问控制，带认证信息的资源仍要根据授权语义审慎设计。缓存键通常涉及 URL、方法及 Vary 指定的请求头；若响应随语言或压缩编码变化，应正确设置 Vary。把租户 ID 或用户权限遗漏在缓存区分逻辑之外，可能造成跨用户数据泄漏。

逐步推演

首次获取

200 + 正文 + ETag v17，存入缓存。

新鲜期内

浏览器直接使用副本，不发网络请求。

过期验证

If-None-Match v17 发给服务器。

返回结果

未变则 304；已变则 200 + 新正文。

ETag 与条件验证

服务器第一次返回图片正文和 `ETag: "v17"`。十分钟后副本过期，浏览器发送 `If-None-Match: "v17"`。如果服务器当前版本仍是 v17，返回 304，浏览器继续使用原正文；若改为 v18，则返回 200 和新正文及新 ETag。ETag 是服务器定义的资源版本标识，可以是内容哈希或其他稳定标识，不应假定必然就是 MD5。

若同时存在 ETag 与 Last-Modified，HTTP 条件处理有优先级规则，具体服务器实现仍需测试。Last-Modified 时间精度可能不足以区分同一秒内多次更新，而弱 ETag 可以表达语义等价但字节不完全相同。比较时要明确目标是字节一致还是表示上可复用。

一次 CDN 与浏览器双层缓存

用户请求 `/logo.png`，浏览器缓存未命中；CDN 节点若有新鲜副本，会直接返回，源站看不到请求。若 CDN 副本过期，它可能向源站条件验证，源站回 304 后 CDN 再按自身策略响应用户。浏览器与 CDN 的缓存期限可以不同，因此“源站日志没有请求”并不说明用户没有访问。分析故障要从浏览器响应头、CDN 日志和源站日志三处对齐。

CDN 失效指令和普通 TTL 也不是同一个机制。发布新版本时使用文件名哈希，例如 `app.a1b2.js`，可以给不可变资源设置长缓存；HTML 入口保持短缓存或可验证，引用新文件名。覆盖写同一个长 TTL 文件名，再期待所有边缘和浏览器立即更新，容易产生版本混用。

304 与其他状态的边界

304 是对条件 GET 或 HEAD 的“资源未修改”回答，不能把它当作所有缓存失效请求的统一返回。若资源已删除，应按真实状态返回 404 或 410；若用户权限被撤销，不应因为客户端拿着旧 ETag 就继续返回可用正文。身份验证和授权检查必须在适当位置执行，不能让缓存验证绕过权限。

缓存层的错误还可能表现为 200 响应了旧正文，这比 304 更容易误导排查。需要记录资源版本、Age、ETag、Cache-Control 和边缘节点标识，再判断旧内容来自浏览器、CDN 还是源站。无论命中率多高，业务都要定义最大可容忍陈旧时间。

动手验证一个资源

浏览器开发者工具里先清空缓存请求一次，记录状态 200、正文、ETag 与 Cache-Control；随后不刷新或普通刷新，看是否直接用内存/磁盘缓存；待新鲜期过后看是否发送 If-None-Match 并收到 304。改动资源后再次请求，应看到 200 与新版本。测试时区分开发者工具“禁用缓存”开关，它会改变正常路径。

如果服务经 CDN，再分别直连源站与访问公开域名，对照响应头和版本。用真实用户身份与另一用户身份测试私人资源，确保缓存键不会串数据。

自检

响应头写了 no-cache，浏览器是否绝对不能保存正文？

不是。no-cache 通常允许保存，但复用前必须验证；no-store 才是不要存储的指令。
