定义与语义

值 struct 与指针 struct

struct 是值类型，赋值整体拷贝；通常会用指针（*User）来共享、修改、避免拷贝。字段零值初始化。

type Point struct {
    X, Y int
}

p1 := Point{1, 2}      // 值
p2 := &Point{X: 3}     // 指针，常用
p2.Y = 4

// 匿名结构体
u := struct{ Name string }{Name: "go"}
嵌入：组合优于继承

把类型当字段嵌入，提升字段与方法

Go 没有 class 继承，用「嵌入」把另一个类型作为匿名字段，其字段和方法被「提升」到外层，像继承但不共享状态。

type Animal struct { Name string }
func (a *Animal) Eat() { fmt.Println(a.Name, "eat") }

type Cat struct {
    Animal   // 嵌入，字段 Name 与方法 Eat 被提升
    Breed string
}

c := Cat{Animal: Animal{Name: "Mimi"}, Breed: "Persian"}
c.Eat()              // 直接调用提升的方法
fmt.Println(c.Name)  // 直接访问提升的字段
嵌入是「组合」：Cat 持有一个 Animal，而非「是 Animal 的子类」。如需多态，配合接口（见类型系统篇）使用。
结构体标签 tag

反射读取的元数据

tag 是附在字段后的字符串，encoding/json、validator 等通过反射读取它来控制序列化名、校验规则。

type User struct {
    ID   int    `json:"id"`
    Name string `json:"name" validate:"required"`
    Pwd  string `json:"-"`         // 序列化忽略
}

嵌入：Go 的组合机制

嵌入（匿名字段）让外层结构体「获得」内层的方法与字段，看起来像继承，实质是组合 + 方法提升。

type Logger struct{ prefix string } func (l *Logger) Log(msg string) { fmt.Println(l.prefix, msg) } type Service struct { *Logger // 嵌入（匿名） name string } s := &Service{Logger: &Logger{prefix: "[svc]"}, name: "order"} s.Log("started") // 方法被提升，可直接调用 s.Logger.Log("x") // 也可以显式访问 // 字段提升同理 type Base struct{ ID int64 } type Child struct { Base Name string } c := Child{Base: Base{ID: 1}, Name: "a"} fmt.Println(c.ID) // 提升自 Base
特性嵌入（组合）继承（其它语言）
复用方式持有实例并提升方法父子类关系
多态靠接口实现，不靠嵌入子类可替代父类
多重可以嵌入多个通常单继承
冲突处理同名时外层优先，需显式指定才访问内层由语言规则决定
语义has-ais-a

关键区别：嵌入不产生多态。把 *Child 传给要求 *Base 的函数是不行的——Go 的类型系统里它们是不同类型。多态由接口承担。

tag、比较性与内存布局

结构体 tag

tag 是编译期保留的元数据，靠反射读取。

type User struct { ID int64 `json:"id" db:"id"` Name string `json:"name" db:"name"` Token string `json:"-"` // 不被 JSON 输出 } // 读取 tag t := reflect.TypeOf(User{}) f, _ := t.FieldByName("Name") fmt.Println(f.Tag.Get("json")) // name fmt.Println(f.Tag.Lookup("db")) // name true

tag 只是字符串，语义完全由使用方（encoding/json、ORM 等）解释。

可比较性

  • 所有字段都可比较 → 结构体可用 ==
  • 含 slice/map/function 字段 → 不可比较
  • 不可比较的结构体不能作 map 的 key
  • 需要比较时用 reflect.DeepEqual 或 cmp
type A struct{ X int; Y string } // 可比较 type B struct{ S []int } // 不可比较 a1, a2 := A{1, "x"}, A{1, "x"} fmt.Println(a1 == a2) // true // b1 == b2 // 编译错误：[]int 不可比较

内存布局

  • 字段按声明顺序排布，中间可能有填充
  • 把大字段放前、同尺寸归堆可减少填充
  • 用 unsafe.Sizeof / Offsetof 观察
  • 只有大量实例时才值得优化

深入自检

嵌入能替代继承吗？

在「复用实现」上可以：嵌入会提升字段与方法，写起来很像继承。但它不提供「is-a」的多态——外层类型不能当成内层类型使用。Go 用接口表达多态，用嵌入表达复用，两者分工明确。

什么时候该用指针接收者？

需要修改接收者、结构体较大（避免拷贝）、或类型内部含互斥锁等不可拷贝字段时用指针接收者。若同一类型混用值与指针接收者，容易埋下方法集不一致的坑，建议保持一致。

结构体tag 会影响性能吗？

tag 本身只是编译期保留的字符串，运行时不参与结构布局，不影响字段访问性能。开销只出现在用反射读取 tag 的时候（如 JSON 编解码），这也是反射型序列化比代码生成慢的原因之一。

为什么建议零值可用？

零值可用的结构体不需要构造函数就能工作，减少「忘记初始化」的错误，也让组合更自然。典型例子是 bytes.Buffer、sync.Mutex——声明后直接使用即可。

嵌入接口有什么用？

在结构体里嵌入接口可以「部分实现」另一个接口，常用于测试桩：只实现关心的方法，其余通过嵌入的接口满足编译。它也常用于包装器模式，让包装类型自动满足被包装者的接口。

第二层 · 参数·命令·量化：嵌入的规则与内存布局

规则说明易错点
匿名字段提升嵌入类型的字段/方法被「提升」到外层与外层同名字段时外层优先（遮蔽）
*T 嵌入嵌入指针，零值是 nil调用其方法会 panic
T 嵌入嵌入值，零值是 T{}安全，但不能为 nil
接口嵌入interface { Reader; Writer }方法集取并集
JSON 序列化匿名字段默认被展平加 json:"-" 或具名字段可避免

嵌入与内存布局

// 1) 值嵌入 vs 指针嵌入
type Base struct{ Name string }
func (b Base) Hello() {}

type A struct{ Base }        // 值嵌入：零值可用
type B struct{ *Base }       // 指针嵌入：零值 nil，调用方法会 panic

var a A; a.Hello()           // 安全
var b B; b.Hello()           // panic: nil pointer（b.Base 是 nil）

// 2) 字段遮蔽：外层优先
type Outer struct {
    Base
    Name string               // 遮蔽了 Base.Name
}
o.Name        // Outer.Name
o.Base.Name   // 显式访问被遮蔽的

// 3) JSON 展平问题
type User struct {
    Base                      // 匿名 -> JSON 里被展平成 {"Name": ...}
    Age  int
}
type User2 struct {
    Base Base `json:"base"`   // 具名 -> JSON 里是 {"base": {...}}
    Age  int
}

// 4) 内存对齐（影响结构体大小）
import "unsafe"
unsafe.Sizeof(struct{ a bool; b int64; c bool }{})   // 24（不是 10）
// 调整字段顺序可减少 padding
unsafe.Sizeof(struct{ b int64; a bool; c bool }{})   // 16（更省）

量化参考：字段顺序影响结构体大小。把大类型放前面、相同类型放一起，能显著减少 padding。上例中同样的三个字段，顺序不同差 8 字节（33%）——在百万级对象下就是几 MB 到几十 MB。

第四层 · 原理与取舍：嵌入 vs 具名字段 vs 接口

方式语义优点代价
嵌入（组合）「有一个」+ 提升方法复用实现，代码短不是继承；命名冲突需显式指定
具名字段明确的「有一个」语义清晰、无遮蔽要手写转发方法
接口「能做什么」解耦、可 mock需定义接口，多一层
Go 的嵌入是继承吗？

不是。Go 没有继承。嵌入是「组合 + 语法糖」：外层类型获得内层的方法，但不存在多态——把 Outer 传给接受 Base 的函数是不行的。真正要实现多态必须用接口。

什么时候该用嵌入？

当你想「复用一组实现，并让外层直接暴露它们」时。典型如 sync.Mutex 嵌入（让结构体自带 Lock/Unlock）、Base 模型嵌入。若只是持有依赖、不想暴露其方法，用具名字段更清晰。

为什么嵌入指针要小心？

因为零值是 nil。var b B 后 b.Base 是 nil，此时调用提升上来的方法会 panic（值接收者也会，因为要先解引用）。所以：要么用值嵌入，要么确保在构造函数里初始化指针。

JSON 被展平了怎么处理？

两种办法：① 改成具名字段（Base Base），JSON 里就是嵌套对象；② 给匿名字段加 json:"-" 忽略它，再手动把需要的字段提出来。
