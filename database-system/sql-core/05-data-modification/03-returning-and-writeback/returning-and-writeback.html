RETURNING 与写后取数

INSERT/UPDATE/DELETE 如何直接返回受影响行、OUTPUT 与 RETURNING 的方言差异、用 CTE 做读写一体

RETURNINGOUTPUT写后取数CTE 写回受影响行
① 动机② RETURNING③ OUTPUT④ CTE⑤ 对比

①为什么需要"写后取数"

典型场景：插入一行后要知道它的自增主键，或更新后要看被改成了什么、删除了哪些行。朴素做法是"先写再 SELECT 取回"，但两步之间可能被并发事务插入/修改，取回的不再是你要的那行。更好的办法是让写语句直接返回受影响行。

核心收益：把"写 + 读"合并成一条原子语句，消除先查后写/写后再查的竞态窗口，也少一次网络往返。

②RETURNING：PostgreSQL / SQLite / Oracle

PostgreSQL、SQLite、Oracle 支持在 INSERT/UPDATE/DELETE 后直接跟 RETURNING 返回任意列，包括刚生成的默认值与序列值。

-- PG：插入后直接拿到自增 id 与默认时间
INSERT INTO orders(user_id, amount) VALUES (42, 99.0)
RETURNING id, created_at;

-- 更新并返回改后的值
UPDATE accounts SET balance = balance - 10
WHERE id = 1 RETURNING balance;

-- 删除并返回被删行（审计/补偿常用）
DELETE FROM sessions WHERE expired < now()
RETURNING session_id, user_id;

③OUTPUT：SQL Server

SQL Server 用 OUTPUT 子句，语义类似，但要把结果落到一个表变量/临时表才能继续处理。

DECLARE @deleted TABLE (id int, user_id int);
DELETE FROM sessions
OUTPUT DELETED.session_id, DELETED.user_id INTO @deleted
WHERE expired < GETDATE();

-- 之后可基于 @deleted 做补偿/审计
SELECT * FROM @deleted;

④用 CTE 做"读写一体"

即使没有原生 RETURNING，也可以用 CTE 在一条语句里先定位再写再返回。PostgreSQL 还支持 UPDATE ... FROM ... RETURNING 关联更新。

-- PG：关联更新并带回结果
WITH target AS (
  SELECT id, balance FROM accounts WHERE user_id = 42 FOR UPDATE
)
UPDATE accounts SET balance = accounts.balance + 100
FROM target WHERE accounts.id = target.id
RETURNING accounts.id, accounts.balance;

-- MySQL（无 RETURNING）：单行用 LAST_INSERT_ID，批量要带业务键回查
SELECT LAST_INSERT_ID();

MySQL 没有 RETURNING：单行用 LAST_INSERT_ID()；批量插入要借助带序号的辅助列或先插后按业务键回查。批量 RETURNING 在 MySQL 8.0 仍不支持原生。

典型命令示例

-- PG：一条语句完成插入并拿到所有生成列
INSERT INTO t(a,b) VALUES (1,2)
RETURNING id, created_at, ctid;

-- SQL Server：OUTPUT 进表变量后再用
DELETE t OUTPUT DELETED.* INTO @d WHERE id = 5;

排障：MySQL 没有 RETURNING 怎么办

单行插入用 SELECT LAST_INSERT_ID()（连接级、线程安全）。

批量插入想拿每行的 id：MySQL 不保证连续，可靠做法是插入时带一个客户端生成的唯一业务键（如 UUID），插完用该键回查；或用支持 RETURNING 的中间层/换 PG。

OUTPUT INTO 必须存在目标表：SQL Server 的 OUTPUT 不能直接返回到客户端结果集，要 INTO 表变量。

自检 Q&A

RETURNING 能返回计算列吗？

能。RETURNING 后跟的列可以是最普通的列，也可以是表达式，例如 RETURNING balance, balance*0.9 AS after_discount。

FOR UPDATE 和 RETURNING 要一起用吗？

只有在“先读后写同一行”且要防并发修改时才需要 FOR UPDATE 锁住。纯 RETURNING 本身是语句级原子，不需要额外锁。

DELETE RETURNING 在分库分表环境能用吗？

中间件对 RETURNING 的支持参差不齐，先在目标中间件上验证。不确定时退化为“先按业务键 SELECT 出主键集合，再 DELETE，最后用主键集合回查”。
