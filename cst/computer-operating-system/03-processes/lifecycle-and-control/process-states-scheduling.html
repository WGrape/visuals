进程 状态 与 调度流转

从「调度器」的视角，把进程在生命周期里经历的每一种状态、以及状态之间如何切换，画成一张完整的状态机。配合可点击的流转模拟器，把抽象的并发调度看明白。

① 为什么进程要有「状态」

一个进程从被创建到消失，同一时刻只能处在一种状态。状态存在的根本原因是：CPU 只有一个（或少数几个），而进程有成百上千个——调度器必须知道「谁现在能用 CPU、谁在等 I/O、谁已经死了但还没被回收」，才能正确地分配处理器。

可以把进程状态机理解为调度器的工作看板：就绪队列里全是 READY，运行态最多等于 CPU 核数，阻塞态在等外部事件。状态切换的唯一「推手」就是各种事件（被调度、时间片到、I/O 完成……）。

资源分配视角

进程是资源分配的基本单位：地址空间、打开文件、PCB 在创建时就绪，状态描述它「走到哪一步」。

调度视角

调度器只从 READY 里挑进程送上 CPU；阻塞态不占 CPU，只等事件。

回收视角

退出后不能立刻消失，要等父进程 wait() 回收 PCB，于是有了僵尸态。

本文是《进程生命周期》一文的互补篇：那篇讲 fork/exec/PCB/内存/资源全景，本篇只聚焦「状态机 + 调度流转」这一条线，并把 Linux 里真实可见的状态字母（R/S/D/T/Z）对应到教科书模型。

④ 七状态模型：引入「挂起 / 换出」

当内存紧张时，中程调度（medium-term scheduler）会把暂时用不到的进程整个换出到磁盘（swap），于是就绪/阻塞又各多出一个「挂起」版本。这就是七状态模型：

挂起态解决的是「内存不够，但进程还活着」的问题：被换出的进程不在内存里，自然也不能被调度，必须 swap in（换入）回到内存中的 READY/BLOCKED，才能重新参与调度。Linux 的 swap 机制就是这个模型的体现。

⑤ 三级调度器：谁在推状态机

状态机的每一次切换，背后都是某一级调度器在干活。操作系统通常把调度拆成三层：

调度层级频率决定的切换典型算法
长程（作业/接纳）秒~分钟级NEW ↔ READY（是否让进程进内存）取决于系统负载、多道程序度
短程（CPU/分派）毫秒~微秒级READY ↔ RUNNING ↔ BLOCKEDCFS、RR、优先级、多级反馈队列
中程（内存）秒级↔ SUSPEND（换入/换出）基于内存压力、LRU 类换页
你平时写程序「卡顿」，多半是短程调度在 READY↔RUNNING 之间反复横跳；系统「内存爆了开始 Swap」，是中程调度把进程推进 SUSPEND。

⑦ Linux 里你真正能看到的状态

教科书模型是抽象，Linux 内核（include/linux/sched.h）的状态更细，ps/top 的 STAT 列用一个字母告诉你进程此刻在哪：

ps 字母内核状态对应教科书含义
RTASK_RUNNINGREADY+RUNNING正在 CPU 上，或在就绪队列等 CPU。Linux 不区分就绪与运行。
STASK_INTERRUPTIBLEBLOCKED可中断睡眠：等 I/O / 信号 / 锁，收到信号可被唤醒（最常见）。
DTASK_UNINTERRUPTIBLEBLOCKED不可中断睡眠：多在等磁盘/网络 I/O，连 SIGKILL 都不理，避免数据损坏。
T__TASK_STOPPED特殊被 SIGSTOP/Ctrl+Z 暂停；t 表示被调试器跟踪（ptrace）。
ZEXIT_ZOMBIETERMINATED僵尸：已退出但父进程还没 wait()，占着 PCB/PID。
XEXIT_DEAD消失彻底死了，资源已回收，瞬间即逝基本看不见。
ITASK_IDLE特殊空闲内核线程（如 PID 0），仅内核线程。
⚠️ 大量 Z 僵尸 = 父进程忘了 wait()，会耗尽 PID；大量 D 卡住 = 磁盘/网络 I/O 故障（D 态连 kill -9 都杀不掉，只能等 I/O 返回或重启）。一眼看状态是排障第一步。
# 看每个进程的状态字母
ps -eo pid,ppid,stat,wchan:24,cmd | head
# 只看僵尸
ps aux | awk '$8 ~ /Z/'
# top 里 S 列同样含义；STAT 第二位起是修饰（< 高优先级、N 低优先级、s 会话首、+ 前台进程组、l 多线程）

⑧ 每个状态到底是什么意思

新建 NEW

内核刚分配 PCB、正在建地址空间，还没进就绪队列，不能被调度。极短，几乎观察不到。

就绪 READY

一切就绪只差 CPU，呆在运行队列（runqueue）里。单核上同时可有成百个 READY，但只有一个 RUNNING。

运行 RUNNING

正在占用 CPU 执行指令。时间片耗尽或被更高优先级抢占时退回 READY；请求 I/O 则去 BLOCKED。

阻塞 BLOCKED

等某事件（I/O 完成、锁释放、信号）。不在就绪队列，不消耗 CPU。事件发生后由内核唤醒回 READY。

挂起 SUSPEND

被换出到磁盘，内存里没有它的映像。SUSPEND 态不能被直接调度，必须先 swap in 回内存态。

终止/僵尸 TERMINATED

进程已结束，但 PCB 留着给父进程收退出码（僵尸）。父进程 wait() 后才彻底消失、回收 PID。
