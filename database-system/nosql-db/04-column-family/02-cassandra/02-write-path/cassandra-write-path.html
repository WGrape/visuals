Cassandra 的一次写入怎样落盘？

区分协调节点、负责该分区的副本，以及确认写入与后台刷盘的时刻。

从客户端到副本确认

  1. 客户端可向任意节点发请求；该节点作为 coordinator，按分区键找到负责的副本。
  2. 副本把变更追加到 CommitLog，再更新内存中的 Memtable。写入达到要求的一致性级别后，coordinator 返回成功。
  3. Memtable 后台刷成不可变 SSTable；Compaction 再合并文件。成功确认不等于已经完成 SSTable 刷盘。
注意图中箭头：它表示数据最终进入 SSTable 的演进，不表示客户端必须等 SSTable 写完才收到确认；写入持久性取决于 CommitLog 与配置的确认级别。

为什么写快，读可能慢

写操作主要走日志顺序追加与内存结构，而读取可能需要合并 Memtable、多份 SSTable 与墓碑。频繁删除、过大分区或不合适的 Compaction 策略会放大读延迟，写入吞吐必须与后台合并能力一起测量。
