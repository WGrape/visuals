前缀和与差分

一个把区间求和压到 O(1)，一个把区间加减压到 O(1)

一句话
前缀和把「区间求和」变成 O(1)；差分把「区间加减」变成 O(1)
前缀和适用
区间求和频繁、数组不变
差分适用
区间整体加减频繁、最后才一次性求结果
二维扩展
二维前缀和公式：S[x2][y2]-S[x1-1][y2]-S[x2][y1-1]+S[x1-1][y1-1]

一、前缀和：把 O(n) 查询变成 O(1)

// 构造（注意用 1-based 更省心，S[0]=0 免去边界判断） S := make([]int, n+1) for i := 1; i <= n; i++ { S[i] = S[i-1] + a[i-1] } // 查询 [l, r] 闭区间的和（1-based） sum := S[r] - S[l-1] // 为什么 S[0] = 0 很关键？ // 查询从 1 开始的区间时，S[l-1] 会落到 S[0]， // 如果 S[0] 不是 0，就要额外写 if l == 0 的分支。

二、差分：把 O(n) 修改变成 O(1)

// 场景：对 [l, r] 区间整体加 v，共 m 次操作 // 朴素做法：每次遍历区间，O(m*n) // 差分做法：每次只改两个点，O(m) d := make([]int, n+2) for each op(l, r, v) { d[l] += v d[r+1] -= v // 区间右端的「下一个」减去，抵消影响 } // 最后对 d 做一次前缀和，还原出每个位置的真实增量 cur := 0 for i := 1; i <= n; i++ { cur += d[i] a[i-1] += cur } // 直觉：d 是「变化量的一阶导」，前缀和就是「积分还原」

一句话区分

前缀和 = 先算好、随时查（适合静态数组）；差分 = 先记账、最后算（适合批量区间修改）。如果既要频繁改又要频繁查，两者都不够，需要线段树或树状数组。

三、二维前缀和

二维要格外小心边界，推荐统一用 1-based 并牢记容斥公式：

// 构造 S[i][j] = a[i][j] + S[i-1][j] + S[i][j-1] - S[i-1][j-1] // 查询以 (x1,y1) 为左上、(x2,y2) 为右下的矩形和 sum = S[x2][y2] - S[x1-1][y2] - S[x2][y1-1] + S[x1-1][y1-1] // 记忆法：大矩形减掉两条，被减两次的角落要加回来（容斥原理） // // +-----------+ // | A | B | // +------+----+ // | C | D | 求 D = 전체 - A - B - C + (重复减掉的部分) // +-----------+

四、前缀和 + 哈希表：解决「和为 k 的子数组个数」

这是前缀和最巧妙的用法：把「枚举所有区间」变成「查找之前出现过的前缀和」：

// 求「和恰好为 k」的连续子数组个数（数组可有负数，窗口法失效） count := 0 seen := map[int]int{0: 1} // 前缀和 -> 出现次数，注意初始放 0 pre := 0 for _, v := range nums { pre += v // 若存在之前的某个前缀和 = pre - k，则它们之间的区间和为 k count += seen[pre-k] seen[pre]++ } // 为什么初始要放 seen[0] = 1？ // 为了处理「从第 0 个元素开始就满足条件」的情况。

五、深入自检

前缀和能处理数组被修改的情况吗？不能，任何单点修改都会让之后所有前缀和失效，需要 O(n) 重建。频繁修改 + 频繁查询的场景应该用树状数组（O(log n) 改、O(log n) 查）或线段树。
差分数组下标为什么要 r+1？因为加 v 的影响范围是 [l, r]，到 r+1 就必须停止。在 r+1 处减 v，正是为了在前缀和还原时把影响「截断」在 r 处。这也是差分数组要开 n+2 而不是 n+1 的原因。
二维前缀和为什么容易写错？主要是下标基准不一致：构造用 1-based、查询传的是 0-based 坐标时极易错位。建议全程 1-based，并在函数入口统一转换一次。
前缀和会不会溢出？会。数组元素较大或长度很长时，int 可能溢出。工程上用 int64，Python / Java 大整数则没有这个问题。
什么时候前缀和不如直接遍历？只查询一次的时候。前缀和需要 O(n) 预处理，只查一次的话直接遍历 O(n) 反而更省空间。前缀和的价值在查询次数远大于 n 时才体现。

什么性质可以做前缀

能做前缀的前提是运算可逆：加法逆是减法，异或逆是异或自身，乘法逆是除法。最大值没有逆运算，所以前缀最大值无法求区间最值 —— 这就是稀疏表（ST）存在的原因。

核心思想：把 O(n) 查询变成 O(1)

操作朴素做法前缀和后提升
区间和查询（静态数组）O(n) 逐项相加O(1)（S[r] − S[l−1]）n 倍
q 次区间和查询O(n·q)O(n + q)巨大
区间加减（批量修改）O(n) 逐项改O(1)（差分数组两个端点）n 倍
m 次区间加减 + 最后还原O(n·m)O(n + m)巨大

一句话理解：前缀和擅长“查”，差分擅长“改”。前缀和把区间查询压到 O(1)（代价是修改变贵）；差分把区间修改压到 O(1)（代价是查询要 O(n) 还原）。两者是互为逆运算：差分是前缀和的逆，前缀和是差分的逆。

一维前缀和：边界处理是唯一难点

一维前缀和实现

# 写法一：下标从 0 开始，S[i] = a[0..i] 的和
a = [1, 3, 5, 7, 9]
S = [0] * len(a)
S[0] = a[0]
for i in range(1, len(a)):
    S[i] = S[i-1] + a[i]
def query(l, r):
    return S[r] - (S[l-1] if l > 0 else 0)
# query(1,3) = S[3] - S[0] = 16 - 1 = 15 = 3+5+7 ✓

# 写法二（推荐）：多开一格，S[i] = a[0..i-1] 的和，彻底避免边界判断
n = len(a)
S = [0] * (n + 1)
for i in range(n):
    S[i+1] = S[i] + a[i]
def query(l, r):          # 闭区间 [l, r]
    return S[r+1] - S[l]
# query(1,3) = S[4] - S[1] = 16 - 1 = 15 ✓
# 好处：不需要 if l > 0，代码更短且不易错

# 复杂度：预处理 O(n)，单次查询 O(1)，空间 O(n)
# 适用：数组<b>不变</b>、查询很多（若频繁修改请改用树状数组/线段树，O(log n)）

最常见的越界 bug：S[l-1] 在 l=0 时，Python 会“聪明地”取到最后一个元素（负索引），结果错但不报错。用写法二（多开一格）可以从根上避免。

差分数组：区间批量加减

差分数组实现

# 差分数组：d[i] = a[i] - a[i-1]
# 关键性质：对 d[l] += v 且 d[r+1] -= v，还原后 a[l..r] 全部 +v

def build_diff(a):
    n = len(a)
    d = [0] * (n + 1)          # 多开一格，方便处理 r = n-1
    d[0] = a[0]
    for i in range(1, n):
        d[i] = a[i] - a[i-1]
    return d

def range_add(d, l, r, v):     # 给 a[l..r] 都加上 v
    d[l] += v
    d[r+1] -= v                # r+1 可能 == n，所以 d 要多开一格
    return d                    # O(1)！

def restore(d, n):             # 最后做一次前缀和还原
    a, cur = [0]*n, 0
    for i in range(n):
        cur += d[i]
        a[i] = cur
    return a

# 示例：m 次区间加，最后还原
a = [0]*10
d = build_diff(a)
range_add(d, 1, 4, 3)     # a[1..4] += 3
range_add(d, 3, 7, 5)     # a[3..7] += 5
print(restore(d, 10))
# [0, 3, 3, 8, 8, 5, 5, 5, 0, 0]  ✓

# 总复杂度：O(n + m) 而不是 O(n × m)
# 典型题：区间覆盖次数、会议室安排、航班预订统计

二维前缀和（矩阵版）

二维前缀和

# 二维前缀和：S[i][j] = 左上角 (0,0) 到 (i,j) 的矩形和
# 递推公式（容斥原理）：
#   S[i][j] = a[i][j] + S[i-1][j] + S[i][j-1] - S[i-1][j-1]
#
# 子矩阵查询 (x1,y1) 到 (x2,y2)：
#   sum = S[x2][y2] - S[x1-1][y2] - S[x2][y1-1] + S[x1-1][y1-1]

def build2d(mat):
    m, n = len(mat), len(mat[0])
    S = [[0]*(n+1) for _ in range(m+1)]     # 多开一行一列
    for i in range(1, m+1):
        for j in range(1, n+1):
            S[i][j] = (mat[i-1][j-1] + S[i-1][j]
                       + S[i][j-1] - S[i-1][j-1])
    return S

def query2d(S, x1, y1, x2, y2):             # 闭区间
    return (S[x2+1][y2+1] - S[x1][y2+1]
            - S[x2+1][y1] + S[x1][y1])

# 记忆口诀："大减小减，重复加回"
#   大矩形 - 上面一块 - 左边一块 + 左上角重复减掉的一块

# 复杂度：预处理 O(mn)，单次查询 O(1)
# 典型题：矩阵区域和、最大子矩阵、图像积分图

二维差分的四个点：给矩形 (x1,y1)-(x2,y2) 加 v，要对 d[x1][y1] += v、d[x2+1][y1] -= v、d[x1][y2+1] -= v、d[x2+1][y2+1] += v——四个角，符号是对角相同。

深入自检

数组会被修改时还能用前缀和吗？

不能直接用——因为修改一个元素会让后面所有前缀和失效，更新是 O(n)。此时应该用：① 树状数组（Fenwick Tree）——前缀和查询和单点修改都是 O(log n)，代码只有 20 行，性价比最高；② 线段树——支持区间修改 + 区间查询，也是 O(log n)，但代码长一倍；③ 如果修改是批量的、最后一次性查询，那差分数组仍是最佳选择（O(n+m)）。判断树：静态查询 → 前缀和；批量修改 → 差分；交替查询修改 → 树状数组/线段树。

前缀和只能用于求和吗？

不。前缀和的核心是“区间可减”——只要运算有逆运算就能用。常见的：① 异或前缀和（xor[l..r] = X[r] ^ X[l-1]，因为 a^a=0）；② 乘法前缀和 + 逆元（模意义下的区间积）；③ 计数前缀和（区间内某个值出现几次）。反过来，最值不支持前缀和（最大值没有逆运算），需要 ST 表 / 线段树。

怎么用前缀和 O(1) 判断“子数组和等于 k”？

用前缀和 + 哈希表：遍历时维护 seen 记录每个前缀和出现的次数。当处理到位置 i、前缀和为 S 时，若 S − k 在 seen 里，说明存在 j < i 使得 a[j+1..i] 的和为 k。关键初始化：seen = {0: 1}（处理从下标 0 开始的子数组）。复杂度 O(n)，这是从暴力 O(n²) 到最优的经典优化。注意：数组有负数时滑窗法失效，必须用这个方法。

差分数组能处理“区间赋值”吗？

不能直接——差分擅长加减，不擅长覆盖（赋值会覆盖掉之前的值，不可交换）。要做区间赋值需要：① 线段树 + 懒标记（正规解法，O(log n)）；② 并查集跳格（若只赋值一次，可用并查集跳过已染色的格子，均摊接近 O(n)）；③ ODT（珂朵莉树）——随机数据下用 set 维护颜色段，均摊很好但最坏会退化。竞赛里区间赋值通常用线段树；工程上如果只赋值一次，并查集技巧最简洁。
