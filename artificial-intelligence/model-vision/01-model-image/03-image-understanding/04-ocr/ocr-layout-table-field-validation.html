OCR 不只认字：发票表格从图像到可信字段要过哪些关

沿倾斜发票的检测、矫正、识别、版面重建和字段校验，解释“字对了”仍可能读错金额。

OCR 的输出目标常不是一串字

一张发票照片里可能有抬头、日期、商品表格、税额和总额。单纯把每个局部文字框识别正确，仍需知道它属于哪一行、哪一列、哪个字段。OCR 常分为图像预处理、文字区域检测、方向与透视矫正、行或词识别、阅读顺序和版面结构重建，最后才是字段解析与业务校验。产品若只测字符错误率，就可能忽视“把甲商品的金额贴到乙商品”这种更严重的结构错误。

图片的拍摄角度、反光、裁边、模糊和压缩伪影会逐段影响结果。故障诊断要保留中间可视化：原图、矫正图、文字框、识别文本、表格单元格和最终 JSON。只存最终字段值很难定位是哪一步错了。

图解：发票从照片到结构化字段

沿箭头逐步核对输入、变换和输出；下面的推演可以逐步切换。

先把文字找出来并摆正

检测器给出文字行或词的区域，可能是矩形，也可能是四边形。斜拍发票里一行文字呈梯形，先做透视变换再识别通常比直接裁一个水平矩形稳定。矫正也有风险：若角点估计错误，会把数字压扁；若盲目增强锐度，可能制造假笔画。对旋转 90°、倒置、弯曲纸张分别测试，不能只在平放扫描件上验收。

OCR 前处理应保留足够分辨率。缩到手机预览大小可能让小数点、发票号码和细线消失；过度放大不会恢复丢失的信息。模型输入尺寸、裁切方式和颜色通道要与训练/验证过程一致。

逐步推演

检测与矫正

定位倾斜文字行，按透视关系还原。

识别文字

保留每个框的文本、坐标和置信度。

重建结构

把金额放回正确商品行和字段。

业务复核

核总额、日期、编码与异常样本。

识别对了字还要恢复阅读顺序

双栏票据或表格中，若按“从上到下、从左到右”简单排序，可能把左列第一行和右列第一行拼成一句。表格要恢复行列边界、合并单元格和表头关系；表格线可能缺失，不能完全依赖画出的线条。发票“数量×单价=金额”的关系比文本顺序更重要：每个数值必须绑到正确商品行。

对于无表格线的收据，可结合文字框的纵向对齐、词间距和字段类型推断列。若一行的金额缺失，不应悄悄把下一行金额上移填补。系统需要保留坐标和置信度，并在无法可靠配对时标为待审核。

层级需要的证据失效表现
图像预处理方向、清晰度、裁边小数点被压缩或裁掉
文字检测每个文字行的框整行缺失，识别器无从处理
版面重建行列和字段归属把甲商品金额配给乙商品
业务校验金额关系与格式字段字符正确但业务不合理

一个小数点错误的代价

人工标注为“税额 12.50”，OCR 识别为“税额 1250”，字符层面只漏了一个小数点，CER 看起来很低，业务金额却差了 100 倍。对金额、日期、身份证号、商品编码等关键字段，要单独统计字段级完全匹配率和校验失败率。可用币种格式、金额上下限、明细求和与总额关系做规则复核，但规则不能凭空纠正所有错误；若识别“12.50”而真实是“72.50”，总额关系可能仍需人工核验。

字段归一化也要留下原始字符串。“2026/10/15”转成标准日期时，需区分日月顺序、时区和两位年份；把多个候选都默默转成一个值会隐藏不确定性。

置信度不是正确概率的保证

识别器给某字段 0.98 分，不代表同分段在生产中有 98% 正确率。置信分数需在代表性数据上校准，并按关键字段设阈值。低置信度应进入复核；高置信度但违反金额或校验位规则，也应触发复核。对账务类票据，错误接受的损失往往高于多做一次人工检查，应按业务成本选择阈值。

若检测框漏掉一行，识别器甚至不会产生该字段的置信度。质量控制要同时监控“字段缺失率”“检测覆盖率”和“识别正确率”，不能只筛已有字段的低分样本。

数据集与上线漂移

训练集若全是标准电子发票截图，上线遇到手机拍照、手写批注或新模板，性能会明显下降。评测按来源设备、清晰度、版式、纸质/电子、语言和金额范围切片。模板更新时，坐标规则可能失效；抽样保存脱敏截图和中间框可帮助发现漂移。涉及个人与财务信息的图像需控制存储、日志、访问权限和留存期限。

上线后应有人工纠错入口，纠错记录用于分析检测、识别或结构哪一环失败。不要把人工改过的最终字段直接当作模型原始预测来计算指标，否则会高估模型质量。

一次验收流程

准备一张斜拍发票，给每个关键字段标出真实框、文字和所属表格行。逐步比较矫正、检测、识别、表格重建和字段校验；故意遮住税额小数点、移除一条表格线、交换两行商品，查看系统是正确复原还是明确拒绝自动入账。最终报告字符错误率、关键字段完全匹配率、表格结构准确率和人工复核比例，并展示失败样本。

把“看上去能读字”推进到“可安全进入业务流程”，需要每个中间环节有证据和兜底。

OCR 精度指标体系

层级指标计算方式合格线
字符级CAR（字符准确率）1 - 编辑距离/总字符数> 0.98（印刷体）
行级行准确率完全匹配行数/总行数> 0.90
检测IoU 或 F1预测框与真值框交并比IoU > 0.5 视为命中
版面版面 F1区域类型+位置的联合匹配> 0.85
表格TEDS树编辑距离相似度> 0.90（简单表）
端到端字段抽取准确率关键字段完全正确率业务决定，常 > 0.95

TEDS（Tree-Edit-Distance-based Similarity）是表格结构的标准度量：把表格转成 HTML 树，算两棵树的编辑距离。它同时惩罚结构错误（行列错位）与内容错误，单纯文字对但格子错位的表格 TEDS 也会很低。

版面分析的区域类型与处理顺序

区域类型识别难点推荐处理方式
文本段多栏混排、跨栏先检测栏边界再切行
标题字号相近时误判结合字号+位置+加粗特征
表格无线表、合并单元格专用表格结构模型，不用通用检测
图片/公式与文本混淆单独分类，交给专用识别器或跳过
页眉页脚每页重复污染正文先剔除再识别

阅读顺序还原

# 版面分析后按阅读顺序排序（关键：不能只按 y 坐标排）
# 多栏文档的 y 排序会把左右栏混在一起
def reading_order(blocks, column_gap_threshold=50):
    # 1) 先按 x 聚类出栏
    xs = sorted(set(b['x0'] for b in blocks))
    cols, cur = [], [xs[0]]
    for x in xs[1:]:
        if x - cur[-1] > column_gap_threshold:
            cols.append(cur); cur = [x]
        else:
            cur.append(x)
    cols.append(cur)
    # 2) 栏内按 y 排，栏间按 x 排
    out = []
    for ci, col in enumerate(sorted(cols, key=lambda c: c[0])):
        col_blocks = [b for b in blocks if b['x0'] in col]
        out.extend(sorted(col_blocks, key=lambda b: (b['y0'], b['x0'])))
    return out

字段校验与后处理规则

OCR 输出不能直接进业务库，需要规则校验 + 格式规整，这是把准确率从 95% 提到 99.5% 的关键环节。

字段类型校验规则典型修正
日期正则 + 合法性（闰年、月份）O/0、1/l 混淆；统一为 ISO 格式
金额数值范围 + 两位小数小数点与千分位混淆
身份证/编号校验位（如身份证第 18 位）校验位不通过直接标为待人工
金额大写与小写金额互相印证不一致时以大写为准
合计明细求和 == 合计不等则触发复核

校验位实现

# 身份证校验位（ISO 7064 MOD 11-2），OCR 后必做的自检
def id_card_valid(s):
    if len(s) != 18: return False
    w = [7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2]
    codes = "10X98765432"
    try:
        total = sum(int(s[i]) * w[i] for i in range(17))
    except ValueError:
        return False          # 前 17 位混入了字母 → OCR 误识
    return s[17].upper() == codes[total % 11]

# 使用：校验不通过的字段标为“低置信”，进人工复核队列
# 经验：这一步能拦下约 60% 的静默写错（字符错但格式对）

置信度阈值不是越高越好：把阈值设到 0.99 会让大量正确结果进人工队列，成本飙升。合理做法是按字段重要性分层——金额、证件号用高阈值（0.95），描述性文本用低阈值（0.7）。

自检 Q&A

Q：为什么文字识别都对，但表格内容全错行了？

A：这是结构识别与文字识别分离导致的。文字框位置对，但行列归属判断错（尤其无线表和合并单元格）。解决：用专门的表格结构模型输出单元格坐标，再把文字框按几何中心落入分配到格子，而不是依赖阅读顺序。

Q：手写体准确率上不去怎么办？

A：先分清是切分错还是识别错。手写连笔时，检测框把整行当一个字送进识别器，必然错。做法是切到字符/词级别，并用带语言模型的解码（CRNN+CTC 或 Transformer+beam search）利用上下文纠正单字误识。纯视觉模型不看上下文，天花板通常就在 90% 左右。

Q：如何评估一个 OCR 服务该不该换？

A：建分层测试集：清晰印刷、扫描件、拍照倾斜、手写、表格各 100 份，分别测 CAR 与字段准确率。只看整体准确率会被清晰样本拉高、掩盖拍照场景的崩塌。同时测延迟与并发——准确率相同下，P95 延迟差 3 倍对线上体验影响很大。

Q：版面分析模型输出不稳定，同一份文档两次结果不同？

A：检查是否用了带随机性的后处理（如 NMS 阈值抖动、随机数据增强在推理时未关闭）。推理阶段必须 model.eval() 并固定所有随机种子。另外输入分辨率变化会显著改变检测结果——固定长边缩放尺寸（如 1280）比自适应更能保证稳定。

OCR 把“12.50”读成“1250”，CER 只多一个错误，能认为业务影响也很小吗？

不能。金额可能相差百倍，应单独评估关键字段并用明细、总额和人工复核检查。
