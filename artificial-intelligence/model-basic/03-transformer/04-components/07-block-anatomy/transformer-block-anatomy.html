04 · 组件拆解

拆开一个 Transformer Block：8 个矩阵、4 次归一化、2 条残差

前面几篇分别讲了注意力、FFN、归一化、残差，这一篇把它们拼回一个完整 block，逐项算清参数量、计算量、显存，并给出读 config.json 核对结构的清单——换模型时的 bug 九成出在这里。

一个 block 到底有几个零件

以 LLaMA-3 8B 为例：32 层，每层 7 个权重矩阵（q/k/v/o + gate/up/down），2 个 RMSNorm，2 个残差加号。没有 bias、没有 dropout、没有位置编码矩阵（RoPE 是运算不是参数）。

数据流全景：先混 token，再混通道

Pre-LN block 完整数据流：注意力从残差流读、算、写回；FFN 再读、算、写回

注意三个细节：RoPE 只作用在 q 和 k 上（v 不带位置信息）；softmax 前要加因果掩码；注意力的输出必须先 o_proj 回 d 维才能加残差——这也是所有子层「输入输出同维」的由来。

2N 公式什么时候失效

上下文越长，注意力打分的 4·n·d_head·seq 项越不可忽略：8K 时约占 30%，32K 时接近 60%。估容量和算力时先问一句「多长上下文」，再决定用不用 2N。

排障：五个换模型必踩的坑

  1. rope_theta 不一致：权重能加载、loss 也正常，但长文检索突然变差。先用 grep rope_theta config.json 核对，再决定是否需要 rope_scaling。
  2. qkv bias：Qwen2 系列 q/k/v 带 bias，LLaMA 不带。加载时报 size mismatch for q_proj.bias 就是这个。
  3. tie_word_embeddings：tied 模型只有一个 embedding 权重，untied 有两个。用错会看到「缺 lm_head.weight」或「多余的 lm_head.weight」。
  4. head_dim 独立于 d/n_heads：部分模型（如 Qwen2.5 大杯、Gemma-2）的 head_dim 不是整除结果，必须读字段而不是自己算。
  5. sliding_window：Mistral / Gemma-2 有滑动窗口注意力，忽略它会让显存估算偏小（实际 KV 被窗口截断，反而更省）。

原理与取舍：为什么是这个顺序

Pre-LN 的顺序（Norm → 子层 → 加残差）保证了残差路径上没有任何非线性或缩放，梯度可以直通；把 Norm 放在子层输入侧，等于让每个子层始终工作在「标准化过」的输入上，训练稳定。代价是残差流范数逐层增长，所以必须在最后一层之后补一个 final norm。

为什么 attention 和 FFN 之间还要再一个 Norm？

两个子层的输出量级不同（注意力是加权平均，FFN 是放大后的非线性），共用一个 Norm 会让其中一个输入分布不合适。分开归一化让两个子层各自工作在合适的尺度上。

可以把 o_proj 和 down_proj 合并吗？

不能。中间隔着残差加法，线性算子不能穿过加法合并。但可以把 RMSNorm 与相邻的线性层融合（pre-norm fusion），减少一次读显存。

为什么 block 里没有位置编码层？

RoPE 是作用在 q/k 上的旋转运算，没有参数、也不在 block 的权重里，所以从权重表看不到它——但它是结构的一部分，换模型时必须一起换。
