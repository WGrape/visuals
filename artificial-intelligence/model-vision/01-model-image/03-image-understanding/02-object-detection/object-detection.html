目标检测：把对象定位在图像里

类别、边界框、重叠处理与检测指标是一条完整的推理链。

学完能解释什么

  • 说清分类与检测在输出上的区别
  • 理解 IoU 和非极大值抑制 NMS 的使用条件
  • 阅读 precision、recall 与 mAP 而不误把置信度当准确率

逐步看机制

模型预测可能的目标位置

单阶段模型在特征图上密集预测，双阶段模型先生成候选区域；端到端集合预测也可直接输出有限个目标。

一个框包含哪些信息

检测输出通常是 (类别, 置信分数, 左上角, 右下角) 的集合，而不是单个整图标签。边界框只是矩形近似，无法精确表达发丝或透明物体的轮廓。图像缩放和裁剪后必须把模型坐标正确映射回原图，否则框看似“偏移”。

IoU 与 NMS 的玩具例子

IoU = 两个框的交集面积 / 并集面积。假设同类的框 A（分数 0.92）与 B（0.81）重叠 IoU 为 0.78，NMS 阈值设 0.50：先保留 A，再压掉 B，避免同一物体被报两次。若两框包围不同相邻物体，阈值过低可能误删真实目标；因此 NMS 不是“重叠就删除”的普适规则。

小目标因像素少，轻微偏移就会明显降低 IoU；检测难点也包括密集遮挡、尺度变化与类别混淆。

怎样读检测评估

调整分数阈值通常会改变精确率与召回率；AP 概括一类目标在不同召回位置的精确率表现，mAP 再汇总多个类别。评估时必须写清 IoU 阈值约定：AP@0.5 与跨 0.50—0.95 多阈值平均的指标不能直接当成同一个数比较。

除了总体分数，还应按类别、目标大小、遮挡和拍摄场景拆开看。产品只需要回答“有没有车”时可能不必支付检测框标注和定位计算的成本。

自检

两个高度重叠的检测框总要二选一吗？

不一定。传统同类框可按 NMS 阈值去重，但相邻真实目标可能高度重叠；端到端集合预测模型也可能不采用 NMS。

核心速览

输出形式一组 (类别, 置信度, 边界框)，而不是整图一个标签
边界框矩形近似；常见格式 (x1,y1,x2,y2) 或 (cx,cy,w,h)
IoU交并比 = 交集面积 / 并集面积，衡量框的重合程度
NMS非极大值抑制：同类重叠框只保留分数最高的
mAP先算每类 AP，再对类别取平均；必须写明 IoU 阈值

三类主流检测范式

范式代表做法优点缺点
两阶段 Two-StageR-CNN / Fast R-CNN / Faster R-CNN先生成候选区域（Region Proposal），再对候选分类与回归框精度高，定位准慢，两遍计算

端到端集合预测DETR 系列用 Transformer 直接预测有限个目标集合，二分图匹配做标签分配无需 anchor 与 NMS收敛慢、小目标弱

IoU 与 NMS 的具体过程

IoU 怎么算

IoU = 两框交集面积 ÷ 并集面积，取值 0~1。完全重合为 1，完全不交为 0。它同时是训练时的正样本判定标准（如 IoU>0.5 算正样本）和推理时的去重依据。

NMS 的步骤

  1. 按置信度从高到低排序所有预测框
  2. 取出分数最高的框，加入最终结果
  3. 计算它与其他框的 IoU，同类且 IoU > 阈值的删除
  4. 对剩下的框重复 2~3，直到为空

阈值怎么选

常用 0.5。阈值调低 → 去重更激进，密集相邻目标容易被误删（漏检）；调高 → 保留更多框，可能同一物体重复报（误检）。人群、货架这类密集场景往往需要调高到 0.6~0.7。

进阶：Soft-NMS

Soft-NMS 不直接删除重叠框，而是按 IoU 衰减它的分数（重叠越多分越低）。这样即便分数不够高也能保留下来参与后续排序，在密集场景通常比硬 NMS 的 mAP 更高。

评估指标怎么读

指标含义注意
Precision 精确率预测为正的里面有多少是真的受置信度阈值影响：阈值调高则精确率升、召回降
Recall 召回率真的正例里有多少被找出来同上，与精确率此消彼长
AP (Average Precision)某一类在 PR 曲线下的面积概括了所有阈值下的表现，比单点 PR 更公平
mAP所有类别 AP 的平均必须写明 IoU 阈值：mAP@0.5 与 mAP@0.5:0.95 数值差异巨大
FPS每秒处理帧数实时场景（视频监控、自动驾驶）与精度同等重要

常见坑与实践建议

❌ 置信度 ≠ 准确率0.9 分不代表 90% 概率正确，模型常过度自信，需要校准
❌ 框偏移缩放/letterbox 填充后没做坐标逆变换
❌ 跨类别 NMS对不同类别做了 NMS，导致重叠的不同类目标被误删
✅ 按尺度拆分评估小/中/大目标分开看 AP，小目标往往是短板
✅ 不一定需要检测只需回答「有没有车」时用分类即可，省掉框标注成本
✅ 数据增强针对性小目标多用 mosaic / 多尺度训练；密集场景调高 NMS 阈值

深入自检

分类、检测、分割三者的输出有什么区别？

分类输出整图一个类别标签；检测输出若干个「类别 + 边界框」，回答「是什么、在哪里」；分割输出像素级的类别掩膜，每个像素都被归类，能表达不规则轮廓。精度和代价依次递增：分割标注最贵、计算最重，但能给出检测框给不了的精确边界。

为什么两个高度重叠的框不一定要删掉一个？

NMS 的前提是「同类 + 高度重叠 = 同一个物体」。但现实中相邻的真实目标（并排站立的人、货架上紧挨的商品）也可能 IoU 较高，此时按阈值硬删就会漏检真实目标。另外端到端集合预测模型（如 DETR）本身就不需要 NMS。所以 NMS 是有适用条件的启发式，不是普适规则。

mAP@0.5 和 mAP@0.5:0.95 差多少？能直接比吗？

不能当同一个数比。mAP@0.5 只要求 IoU>0.5 就算命中，宽松；mAP@0.5:0.95 是在 IoU 从 0.5 到 0.95 每 0.05 取一个阈值各算一次再平均，对定位精度要求严苛得多。同一个模型前者常常比后者高 20~30 个百分点。COCO 的主指标是后者，写论文或做汇报时必须标明阈值约定。

小目标为什么难检测？

三个原因：①像素少——32×32 的物体在深层特征图上可能只剩 1~2 个像素，语义信息几乎被池化掉；②IoU 敏感——同样偏移 2 像素，大框 IoU 掉 2%，小框可能掉 20%，训练时容易被判成负样本；③anchor 不匹配——预设 anchor 尺度偏大，小目标匹配不到合适的 anchor。对策：多尺度特征融合（FPN）、专门的小目标检测头、提高输入分辨率、针对性数据增强。

检测模型怎么选？要实时怎么办？

先定硬指标：需要多少 FPS、允许的最低 mAP、部署在什么硬件上。要实时（视频流 25~30 FPS）通常选单阶段（YOLO 系列、SSD），在 GPU 甚至边缘设备上都能跑；要精度（医学影像、工业质检）选两阶段或大模型；要省事且不想调 anchor/NMS 可以试 DETR 系。实际落地还要量化、剪枝、TensorRT 加速，并注意输入分辨率对速度的影响是平方级的。

mAP 计算与 IoU

# mAP 怎么算（面试必考，手算流程）
#   1) 对每个类别：
#      a. 把所有预测框按置信度从高到低排序
#      b. 逐个与 GT 匹配：IoU >= 阈值(通常 0.5) 且该 GT 未被匹配 -> TP，否则 FP
#      c. 计算每个位置的 Precision/Recall
#         Precision@i = TP_i / (TP_i + FP_i) = TP_i / i
#         Recall@i    = TP_i / 该类别 GT 总数
#      d. PR 曲线下面积 = AP（VOC07 取 11 点插值，VOC10+ 取全部点）
#   2) mAP = 所有类别 AP 的平均
#      COCO 的 mAP = 对 IoU 阈值 0.5:0.05:0.95 共 <b>10 个</b>阈值分别算 AP 再平均
#      <b>COCO mAP@0.5</b> 只取 IoU=0.5，数值明显更高（约高 15~20 个点）

def iou(a, b):
    # a, b = [x1, y1, x2, y2]
    ix1, iy1 = max(a[0], b[0]), max(a[1], b[1])
    ix2, iy2 = min(a[2], b[2]), min(a[3], b[3])
    inter = max(0, ix2 - ix1) * max(0, iy2 - iy1)
    uni = (a[2]-a[0])*(a[3]-a[1]) + (b[2]-b[0])*(b[3]-b[1]) - inter
    return inter / uni if uni > 0 else 0.0
阈值作用常用值调大的效果
置信度 conf过滤低分预测框0.25~0.5（YOLO 默认 0.25）漏检增多、误检减少
NMS IoU去重：同类框 IoU 超阈值就删掉低的0.45~0.7（YOLO 默认 0.45）保留更多重叠框（密集场景要调大）
正样本 IoU训练时判断 anchor 是不是正样本0.5（COCO）/ 0.7正样本变少，学习更难
max_det单图最多检测框数300（YOLO 默认）密集场景要调大

NMS 与调参

# NMS 完整流程（手撕代码题）
import numpy as np
def nms(boxes, scores, iou_thr=0.5):
    order = scores.argsort()[::-1]          # 1) 按分数降序
    keep = []
    while order.size > 0:
        i = order[0]; keep.append(i)        # 2) 取最高分，保留
        if order.size == 1: break
        rest = order[1:]
        ious = np.array([iou(boxes[i], boxes[j]) for j in rest])
        order = rest[ious <= iou_thr]       # 3) 删掉 IoU 超阈值的
    return keep

# Soft-NMS（密集场景更好）：不硬删，而是按 IoU 衰减分数
#   线性: s_j = s_j * (1 - iou)
#   高斯: s_j = s_j * exp(-iou^2 / sigma)
#   效果：密集人群 AP 通常提升 1~3 个点

边缘设备 / 移动端YOLO-nano / SSD-MobileNet / YOLOv8n + INT8算力受限

  • 先确认瓶颈是漏检还是误检：漏检多 → 降 conf 阈值、加大输入分辨率、加数据增强；误检多 → 升 conf 阈值、加负样本、调小 NMS IoU。
  • mAP 高不等于线上好用：线上看的是「在你这个场景、这个阈值下的漏检/误检率」。一定要用自己的数据测，COCO mAP 只是参考。
  • 速度与精度的权衡点：YOLO 的 n/s/m/l/x 五档，同数据集上 mAP 大约差 3~5 个点一档，参数量和 FLOPs 差约 3~4 倍一档。通常选 m 档是性价比拐点。
  • 部署加速：ONNX → TensorRT（FP16 提速 2~3 倍、INT8 再提 2 倍），或 OpenVINO（Intel CPU）。注意 NMS 是否包含在导出图里（YOLO 的 end2end 导出会把 NMS 一起导出）。
两阶段为什么比单阶段准？

核心是类别不平衡。一张图里目标只占极小区域，单阶段要在几十万个 anchor 上直接分类，负样本压倒性多数（这就是 RetinaNet 要发明 Focal Loss 的原因）。两阶段先用 RPN 把候选框缩到一两千个，且正负比例被控制在 1:3 左右，分类器的学习难度大幅下降。代价是多了一次前向，速度慢。

anchor 是什么，现在还需要吗？

anchor 是预设的参考框（不同尺度、不同长宽比），模型学的是「相对 anchor 的偏移量」而不是绝对坐标，这让回归更容易学。它的缺点是带来一堆超参（数量、尺度、比例）且要按数据集聚类。现在的主流（YOLOv8+、FCOS）已经转向 anchor-free：直接预测框的中心和边界，超参更少，泛化更好。

怎么判断模型该换还是该加数据？

看学习曲线：如果训练集上还在欠拟合（训练集 mAP 也低），换更大模型有用；如果训练集 mAP 高但验证集低（过拟合），加数据/增强更有效。另外做个错误分析：人工看 100 个错误案例，分类统计是「背景误检」「同类混淆」「定位不准」「小目标漏检」——不同原因对应完全不同的解法。
