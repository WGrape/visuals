幂等设计

同样的请求重复发多次，结果和发一次一样——分布式系统的必答题。

为什么必须幂等 Idempotency

重试/消息重投/双击都会让同一操作到达多次

在分布式环境下，<b>超时重试、消息重投、用户双击</b>都会让同一个语义的请求到达多次。若『扣款』被重复执行，灾难就来了。<b>幂等</b>保证：无论执行 1 次还是 N 次，业务效果相同。

常见实现手段

  • 唯一幂等键：请求带 clientId+seq，服务端用唯一索引去重。
  • 状态机：已支付则忽略重复支付。
  • 乐观锁/版本号：update ... where version=N。
  • Token 机制：先取令牌，提交即消费，重复提交无令牌被拒。

面试高频问答

Q：GET 天然幂等，POST 不幂等，怎么处理？
A：REST 语义上 GET/PUT/DELETE 应幂等，POST 不幂等。对必须安全的写操作，用『幂等键 + 去重表』把非幂等接口变成幂等，或改用 PUT（带资源标识）。
Q：幂等键存多久？
A：至少要覆盖『请求可能重复到达』的窗口（通常几小时到一天），并定期清理；同时配合业务状态机，即使键过期也能靠状态兜底。
