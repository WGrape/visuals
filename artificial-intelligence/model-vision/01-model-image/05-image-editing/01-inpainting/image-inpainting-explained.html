图像编辑

局部重绘与图像编辑：掩码、上下文与一致性怎么保证

编辑不是「擦除再贴上去」，而是「把指定区域炸掉重新生成」。本文讲清 Inpainting / Outpainting 的原理、掩码与边距处理、保证边缘连贯的技巧，以及超分与风格迁移等其他编辑范式。

编辑的本质：带约束的生成

给模型一张图 + 一个掩码（哪块要改）+ 一个目标描述，模型在保留未掩码区域的前提下，重新生成掩码区域的内容。

所以编辑质量取决于三件事：掩码准不准、上下文够不够、以及模型能不能尊重约束。

局部重绘 Inpainting

典型流程

  • 用户提供掩码（或由分割模型/点击自动生成）
  • 把原图按掩码留出待生成区域，未掩码区域作为已知条件
  • 在 latent 空间反复去噪，但每一步都把未掩码区域用原图覆盖回去
  • 解码得到结果，必要时做边缘融合（羽化）
扩大掩码 + 羽化边缘
掩码边缘留几像素渐变，避免生硬的接缝
保留更多上下文
喂给模型的裁剪框要比掩码大一圈，模型才知道周围是什么
典型失败：边缘色差 / 光照不一致 / 生成内容与原图风格冲突。解决方向是提供更多上下文、使用更强的结构约束（如 ControlNet 类条件），或先做局部调色融合。

扩图 Outpainting

把画布向外延展，让模型「脑补」画框外的部分。难点是保持透视、光照、风格与已存在的画面一致。

实用技巧：分步外扩（每次扩一小条而非一次扩很大），并在每一步重新对齐原有区域的色调，成功率明显高于一次性大幅外扩。

超分辨率、风格迁移与其他编辑

范式目标关键点
超分辨率提升分辨率、补全细节容易"脑补"出错误细节（尤其在文字、人脸）；证据保真与感知质量的权衡
风格迁移保留内容、替换风格分离内容与风格表征（Gram 矩阵 / AdaIN 等思路）
结构受控生成按边缘/深度/姿态精确控制构图把结构图作为额外条件注入（ControlNet 类方法）
图像修复去划痕、去噪、去水印传统方法与生成式方法结合

面试速记卡

  • 本质：编辑 = 带掩码/条件的重新生成，而非像素涂抹。
  • Inpainting：掩码指定区域、每步去噪后回填未掩码部分；边缘羽化 + 保留上下文是关键。

三种技术路线

路线代表原理优点缺点
传统方法PatchMatch、Criminisi从图像其他区域找相似 patch 复制过来无需训练，快只能处理重复纹理，语义常常错
GAN 方案DeepFill v1/v2、LaMa编码器-解码器 + 对抗损失（有的加傅里叶卷积）快，可实时，高分辨率友好复杂语义和大面积缺失较弱
扩散方案Stable Diffusion Inpainting、SDXL在潜空间只对 mask 区域去噪，已知区域作为条件语义最合理，支持文本控制慢，需要迭代

扩散 Inpainting 的原理

原图按时刻 t 加噪的结果 （真实内容，不改动） → 提供上下文与边界约束 待填充区域（mask 内） 用模型预测的去噪结果 （逐步从噪声变清晰） → 受文本 prompt 控制 拼接后送入 U-Net U-Net 能看到完整图像 所以生成的边缘自然衔接 循环 T 步 → 完整图 关键点：每一步都把「已知区域」按当前噪声水平重新加噪后拼回去，保证强度一致，边界才不会出现硬边
图：扩散 inpainting 每一步都保留已知区域作为上下文，这是边界无缝的关键

常见失败与对策

边界有明显接缝

原因：mask 边缘太硬、或已知区与生成区的噪声水平不一致。对策：①mask 做羽化（blur）留出过渡带；②扩大 mask 让模型有更多余地；③提高去噪步数。

语义不合理（生成了奇怪物体）

原因：文本 prompt 太弱或与上下文冲突。对策：①写清 prompt 描述希望填充的内容；②降低 denoise strength（0.5~0.7），让模型更多参考原图；③用 inpainting 专用模型而非通用模型。

风格/色调不一致

原因：模型按自己的先验生成，与原图色调不符。对策：①在 prompt 里描述色调光照；②使用 IP-Adapter 或参考图控制风格；③后期做色彩匹配（把生成区的颜色统计对齐到周边）。

大面积缺失（超过一半画面）

这实际上已经接近「重新生成」了。对策：分步填充（先填结构后填细节）、用 outpainting 方式逐圈扩展、或用 ControlNet 提供结构约束。

Outpainting 扩图

是什么把画面扩展到原图边界之外，凭空生成新内容
做法把画布放大，把原图放在一角，其余区域当作 mask 做 inpainting
关键prompt 要描述扩展后的整体画面，而不是只描述原图
常用技巧逐圈扩展（每次扩 10~20%），比一次性扩很大质量好得多
坑多次扩展后累积误差会让画风漂移；可用固定 seed 缓解

深入自检

图像修复（Inpainting）的核心难点是什么？

要同时满足三个要求：①语义合理——填进去的东西符合场景逻辑（街道上的洞应该填路面，不是天空）；②纹理连贯——纹理的方向、频率、尺度要和周边一致；③边界无缝——接缝处不能有颜色或结构的突变。传统 patch 方法只能做到②（复制相似纹理），语义常常错；深度学习方法才能同时兼顾三者，其中扩散模型在①上表现最好。

为什么扩散模型做 inpainting 效果比 GAN 好？

根本原因是语义理解能力更强。扩散模型在大规模图文数据上预训练，知道「街道上的洞应该是什么」，还能通过文本 prompt 精确指定要填什么。GAN 方案主要靠局部纹理与对抗损失，对大面积缺失和复杂语义常常只能生成「看起来像纹理但语义不通」的糊状内容。代价是扩散需要几十步迭代，慢得多——所以实时场景（直播去水印）仍然用 GAN 方案。

denoise strength 该怎么调？

它控制「模型有多大程度自由发挥」。1.0：完全重新生成 mask 区域，最贴合 prompt 但可能与原图风格不符；0.5~0.7：更多参考原图上下文，衔接自然但创新不足；0.3 以下：几乎只做轻微修补。实践建议：去水印/小面积修补用 0.5~0.7（保留原图风格），换物体/大面积重绘用 0.8~1.0（需要模型发挥）。

为什么修复结果的边缘常有接缝？怎么消除？

两个常见原因：①mask 边缘太硬——二值 mask 直接切，模型没有过渡空间。对策是对 mask 做羽化（高斯模糊 3~8 像素），让边缘有个渐变带，模型会自然过渡；②噪声水平不一致——已知区域如果用原图（零噪声）而生成区是纯噪声，两者强度差异巨大，U-Net 会「看出」边界。正确做法是每一步都把已知区按当前时刻 t 重新加噪后再拼回，强度就一致了（现代实现已内置）。另外适当扩大 mask、提高步数也有帮助。

去水印和去物体是一回事吗？

技术上都是 inpainting，但目标不同。去水印要求「看不出修改痕迹」，填充内容通常是背景纹理的延续，对语义要求低但对纹理连贯与无缝要求极高，且常常需要保持原图分辨率。去物体（如去掉画面里的路人）则需要「填补被物体遮挡的背景」，涉及遮挡推理——要知道物体后面是什么，语义难度更高。实践中去水印常用轻量 GAN 方案（快、保真），去物体用扩散方案（语义强）。

图像修复的方法与代价

方法原理适用与代价
传统：纹理合成（PatchMatch）从图像其他区域找最相似 patch 填背景/纹理好；语义完全不懂
传统：偏微分方程（Telea/NS）从边界向内部扩散小区域快；大洞会糊
CNN 自编码（Context Encoder）编码器压缩 + 解码器重建能懂一点语义；边界有明显接缝
部分卷积 / 门控卷积卷积时按 mask 归一化比普通卷积好很多；主流基线
Attention / transformer远距离patch 注意力大洞修复最好；显存 O(n²)
扩散模型（Stable Diffusion inpainting）在 mask 区域去噪生成当前最优；慢（20~50 步），内容可控性有随机性
LaMa（傅里叶卷积）大感受野，靠频域大分辨率（2K）效果好且快
参数典型值说明
mask 膨胀（dilate）5~15 px扩散 inpainting 必须膨胀 mask，否则边缘有硬边
扩散步数20~5020 步质量已可接受；50 步更精细
guidance_scale7~12文本约束强度；太高会出现伪影
strength0.9~1.0（inpainting）低了改不动，高了完全重画
分辨率512×512 或 768×768SD 系列在训练分辨率附近效果最好
显存512×512 约 4~8 GB开 attention slicing 可降到 3GB

核心难点：为什么修复大洞这么难：小洞（< 5% 面积）靠周围像素扩散就够；大洞（> 30%）必须凭语义生成——模型要「猜」洞里原来是什么。这时传统方法必然失败，只有生成式模型（GAN/扩散）能做，但生成的内容是不可控的。
