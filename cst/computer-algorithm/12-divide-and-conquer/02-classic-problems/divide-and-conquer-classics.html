第 12 章 · 分治

代价在合并还是在划分

归并排序代价在合并、快排代价在划分，最近点对展示了跨分界线也能常数代价，Strassen 与 Karatsuba 则用加法换乘法改进指数。

归并排序：代价全在「合并」

分解是 O(1)（算个中点），递归求解两个子区间，真正的功夫在合并：两个已排序的子数组用双指针每次取较小者，线性扫一遍即可。

def merge_sort(a):
    if len(a) <= 1: return a
    m = len(a) // 2
    left, right = merge_sort(a[:m]), merge_sort(a[m:])
    i = j = 0; out = []
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:   # <= 保证稳定性
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]
  • 复杂度：T(n) = 2T(n/2) + Θ(n) → Θ(n log n)，且最好最坏平均都是它。
  • 稳定（相等时先取左边），但需要 O(n) 额外空间。
  • 适合外排序：数据大到内存放不下时，归并的顺序读特性对磁盘极其友好。

快速排序：代价全在「划分」

快排先花 Θ(n) 把数组按基准值划分成两半，然后递归。它不需要合并步骤，也几乎不占额外空间，但代价是：划分得好不好直接决定复杂度。

  • 平均：T(n) = 2T(n/2) + Θ(n) → Θ(n log n)。
  • 最坏（每次基准都是最大或最小，如已排序数组取首元素）：T(n) = T(n−1) + Θ(n) → Θ(n²)。
  • 应对：随机选基准、三数取中、三路划分（大量重复元素时）、小规模切换插入排序。
  • 不稳定、原地（递归栈 O(log n)~O(n)）。

工程上的默认排序几乎都是快排的变体（内省排序 introsort 会在递归过深时切换成堆排序，保证最坏 O(n log n)）。

最近点对：分治的精髓在「跨中线」

平面 n 个点求最近距离。暴力是 O(n²)，分治做法：

  1. 按 x 排序，从中间切开，分别求左右两侧的最近距离 δ。
  2. 跨中线的点对只在距离中线小于 δ 的竖条里可能更近。
  3. 关键观察：竖条内每个点只需检查常数个（约 6~7 个） y 序上的后继——因为同侧任意两点距离已 ≥ δ。

保持 y 序的归并技巧让第 3 步线性完成，总复杂度 T(n) = 2T(n/2) + Θ(n) → Θ(n log n)。

这一步是分治里最漂亮的证明之一：它说明「跨分界线的合并」不一定是昂贵的，只要利用子问题已经给出的信息（δ）就能把候选项压到常数。

Strassen 与 Karatsuba：少做一次乘法

Strassen 矩阵乘法

两个 n×n 矩阵分块相乘原本需要 8 次子乘法，Strassen 用 7 次特定线性组合的乘法凑出结果：T(n) = 7T(n/2) + Θ(n²) → Θ(n2.81)，优于 Θ(n³)。代价是常数大、数值稳定性略差，实际只在 n 很大时使用。

Karatsuba 大整数乘法

两个 n 位整数原本需要 4 次 n/2 位乘法，Karatsuba 用 3 次：T(n) = 3T(n/2) + Θ(n) → Θ(n1.585)，优于小学竖式的 Θ(n²)。

这两者的共同思路：用加法换乘法。加法是 Θ(n)，乘法才是瓶颈，所以减少乘法次数就能改进指数。

第一层 · 概念与判定：什么问题能用分治

一句话判据：能把原问题拆成若干个「结构相同、规模更小、互不重叠」的子问题，且子问题的解能合并。

特征分治动态规划贪心
子问题是否重叠不重叠（各自独立）重叠（需记忆化）每步只看当前最优
子问题是否独立求解✅ 是❌ 需要共享中间结果✅ 是
是否需要合并✅ 必须有合并步骤由状态转移完成❌ 无合并
典型题归并排序、快排、最近点对、大整数乘法背包、最长公共子序列、编辑距离活动选择、哈夫曼、Dijkstra
  • 信号一：问题规模 n 能对半砍，且两半互不依赖 → 分治。
  • 信号二：递归式形如 T(n) = a·T(n/b) + f(n) → 分治，用主定理算复杂度。
  • 信号三：如果子问题会被重复计算（如斐波那契）→ 那是 DP 不是分治。

最容易混的地方：分治与 DP 的区别在于子问题是否重叠，不在于「是否递归」。归并排序是分治；记忆化搜索斐波那契是 DP。

分治模板与归并排序

# 分治模板（三段式：拆 -> 解 -> 合）
def divide_conquer(problem):
    if base_case(problem):          # 1) 终止条件：规模足够小直接算
        return solve_directly(problem)

    sub_problems = split(problem)   # 2) 拆：分成若干结构相同的子问题
    sub_results = [divide_conquer(p) for p in sub_problems]
    return merge(sub_results)       # 3) 合：把子问题的解合并

# 归并排序：最标准的分治
def merge_sort(a):
    if len(a) <= 1: return a
    mid = len(a) // 2
    left  = merge_sort(a[:mid])
    right = merge_sort(a[mid:])
    return merge(left, right)       # 合并是 O(n) 的两路归并

量化提醒：合并步骤的复杂度决定了整个算法的复杂度量级。归并排序合并是 O(n)、拆分是 O(log n) 层，所以总 O(n log n)；如果合并写成 O(n²)，总复杂度就变成 O(n²)。

第三层 · 排障与边界：递归与合并的坑

坑后果正确做法
忘记终止条件或写错无限递归 / 栈溢出明确 if len <= 1: return
子问题规模没有变小死循环确保每次递归 n 严格减小（如 n//2）
合并步骤写成 O(n²)整体退化合并要线性扫描，别嵌套循环
递归深度过大爆栈（Python 默认递归深度约 1000）分治通常 log n 层，安全；但链表式划分可能到 n 层
原地分治时下标算错漏元素或重复明确区间是闭区间还是半开，全程统一
  • 排查顺序：先确认终止条件 → 再确认规模递减 → 再看合并复杂度 → 最后测空数组 / 单元素 / 两元素。
  • 边界一：快排的划分可能极不平衡（已排序数组取首 pivot），导致递归深度 n 层而爆栈——用三数取中或随机 pivot。
  • 边界二：分治的「合」往往是最难写对的部分（如最近点对要处理跨中线的带状区域）。
  • 边界三：不要为了分治而分治——如果子问题重叠，用 DP 记忆化能省掉指数级重复计算。

一、经典题一：归并排序

func MergeSort(a []int) []int { if len(a) <= 1 { return a } // 递归基 mid := len(a) / 2 left := MergeSort(a[:mid]) // 分解 right := MergeSort(a[mid:]) return merge(left, right) // 合并：O(n) } // 主定理：T(n) = 2T(n/2) + O(n) -> O(n log n) // 归并的合并是线性的，这是它比快排慢的原因之一（需要额外数组）

二、经典题二：快速排序

快排也是分治，但分解是难点、合并是免费的，和归并正好相反：

归并排序快速排序
重心合并在 merge分解在 partition
复杂度稳定 O(n log n)平均 O(n log n)，最坏 O(n²)
稳定性稳定不稳定
额外空间O(n)O(log n) 递归栈
最坏场景无（总是二分）已排序数组 + 取首元素作 pivot

三、经典题三：最近点对

平面上 n 个点中距离最近的一对。暴力是 O(n²)，分治能降到 O(n log n)：

1) 按 x 坐标排序，从中线分成左右两半 2) 递归求左半最短 dL、右半最短 dR，取 d = min(dL, dR) 3) 关键：只需检查中线两侧宽度为 d 的竖条内的点 - 若存在跨中线且距离 < d 的点对，两点必都在这个竖条内 - 而这个竖条内的点，按 y 排序后每个点只需向后检查常数个（通常 7 个） 4) 合并步因此是 O(n)，总复杂度 T(n) = 2T(n/2) + O(n) = O(n log n) // 这个「竖条内只需检查常数个」的证明，是分治里最漂亮的一步
分治最难的地方

往往不是分解，而是证明「跨子问题的情况」可以在线性时间内处理完。最近点对、最大子数组和、凸包都是这类：难点全在合并步骤的剪枝证明上。

四、经典题四：最大子数组和

// 分治解法：跨中线的最大和 = 左半最大后缀 + 右半最大前缀 func MaxSub(a []int, l, r int) int { if l == r { return a[l] } mid := (l + r) / 2 left := MaxSub(a, l, mid) right := MaxSub(a, mid+1, r) cross := maxSuffix(a, l, mid) + maxPrefix(a, mid+1, r) return max(left, right, cross) } // T(n) = 2T(n/2) + O(n) -> O(n log n) // 但这个问题有更优的 O(n) 解法：Kadane 算法 // 说明：分治不一定是最优解，它只是「把复杂度从 n² 降到 n log n」的通用武器

六、深入自检

分治和递归是一回事吗？

不是。递归是实现手段，分治是思想。分治通常用递归实现，但递归也可能是纯递推（如阶乘），没有「分解-合并」结构。

分治和 DP 的边界在哪？

看子问题是否重叠。子问题不重叠 -> 分治（归并排序、最近点对）；子问题重叠 -> DP（斐波那契、背包、最长公共子序列）。重叠时如果用分治会做大量重复计算。

递归深度会不会爆栈？

分治的深度通常是 O(log n)，很安全。但快排在最坏情况下深度是 O(n)，这就是为什么工程实现要加「小数组切换插入排序」和「随机化/三数取中选 pivot」。

什么时候分治不如直接迭代？

当「合并」代价很高、或者子问题规模下降很慢时。比如 T(n) = T(n-1) + O(n) 这种下降，其实是 O(n²)，不如直接写循环。

分治能并行吗？

非常适合——子问题互不依赖，天然可并行。Fork/Join 框架、Go 的 errgroup、MapReduce 都是分治思想的并行化落地。
