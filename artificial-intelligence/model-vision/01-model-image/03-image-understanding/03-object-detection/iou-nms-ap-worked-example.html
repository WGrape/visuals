目标检测手算：IoU、NMS 与 AP 为什么回答不同问题

用两个候选框和三处真实目标，逐步区分框重叠、重复抑制与整套模型的排序评估。

一张图里先分清三类东西

目标检测输出通常包含类别、边界框坐标和置信分数；标注集则给出需要找到的真实目标。边界框可能以左上和右下坐标表示，也可能用中心点、宽高表示，计算前要转换到同一像素坐标系。IoU 衡量两个框的几何重叠；NMS 用框间重叠处理一堆重复预测；AP 用按分数排序的预测和真实标注评估检测能力。把三者写成同一个“准确率”会丢失重要区别。

分类分数高不代表框位置准，框位置准也不代表类别正确。一个行人被框住却标成自行车，对该类别评估仍是错误。预处理缩放和补边后若忘记把框映射回原图坐标，模型可能看似识别了对象，实际展示位置却整体偏移。

图解：检测框从几何到评估

沿箭头逐步核对输入、变换和输出；下面的推演可以逐步切换。

两个框手算 IoU

框 A 从 (0,0) 到 (100,100)，框 B 从 (10,10) 到 (110,110)，两者面积都是 10000。相交矩形从 (10,10) 到 (100,100)，宽高各 90，交集面积 8100；并集面积为 10000+10000−8100=11900，IoU=8100/11900≈0.681。若 B 换成 (50,50) 到 (150,150)，交集只有 2500，并集 17500，IoU≈0.143。计算时坐标是否把边界像素包含在内需统一约定，本例采用连续坐标面积模型。

IoU 只衡量两个框的相对几何位置，不知道它们是否属于同一真实对象。两个不同的相邻人可能互相遮挡，预测框 IoU 很高；同一长条物体的两个局部框 IoU 可能不高。阈值只是任务上的匹配规则，不是视觉真相本身。

NMS 怎样删重复预测

假设 A、B 都预测“行人”，分数分别 0.92 和 0.85，采用同类别 NMS 且阈值 0.5。先保留分数较高的 A，计算它与 B 的 IoU≈0.681，高于阈值，因而抑制 B。若两个框预测类别不同，常见类别内 NMS 不会互相抑制；若业务要求跨类别互斥，需要额外规则。若图中确有两名紧贴的人，硬 NMS 也可能误删第二人；可调整阈值或采用 Soft-NMS 等方案，并以实际召回率检验。

NMS 是推理后处理，解决同一物体出现多个候选框的问题。它不能修复模型根本没产生的目标，也不能把错误类别自动改正。调低分数阈值可能增加候选与召回，但也会增加误报和 NMS 计算量。

阶段输入输出常见误判
IoU两个框的坐标0–1 的几何重叠值把重叠当类别正确
NMS同类候选分数与 IoU保留的一组候选误删相邻目标
AP排序预测与真实标注一类的 PR 表现只看单一分数阈值
mAP类别和评测 IoU 口径平均检测质量不说明阈值和数据集

AP 从排序而来

假设一张或多张图共标注 3 个真实行人，模型按分数从高到低给出预测：第 1 个匹配一名真实行人，记 TP；第 2 个没有匹配，记 FP；第 3 个匹配另一名尚未匹配的行人，记 TP。处理到第 1 个时 precision=1/1、recall=1/3；到第 2 个时 precision=1/2、recall 仍为 1/3；到第 3 个时 precision=2/3、recall=2/3。继续降低分数门槛会增加召回，也可能带来更多 FP，得到一条 precision–recall 曲线。AP 概括这条曲线，具体插值与积分规则依评测协议。

一个真实目标通常只能匹配一个预测；后续重复框即使位置很准，也可能算 FP。IoU 匹配阈值越高，对定位要求越严格；AP@0.50 和更严格阈值下的 AP 不可混作同一指标。

mAP 的口径必须写全

mAP 常表示多个类别 AP 的平均，但不同基准还可能在多个 IoU 阈值上平均。例如 COCO 常报告从 0.50 到 0.95 的多阈值平均，以及 AP50、AP75 和按目标大小分组的结果。只写“mAP=0.6”无法判断类别集合、IoU 阈值、置信度筛选、最大检测数和目标尺寸规则。小目标漏检与大目标重复框可能需要不同改进方向。

若数据集只有大量容易的白天街景，而上线有夜景和遮挡，整体 mAP 高也不能证明真实场景稳定。应按光照、尺寸、遮挡、设备和地域拆分评估，并查看漏检与误报样本。

一次标注与坐标排障

模型输出框经图像缩放后全部偏右，先确认输入是否使用了 letterbox 补边、模型坐标是否归一化到 [0,1]、后处理是否正确减去补边并按原图比例放大。然后随机选样本把真实框与预测框叠在原图上，检查坐标、类别和分数。若 IoU 很低但视觉位置接近，可能是坐标格式、整数取整或标注边界规则不一致。

改 NMS 阈值前保存同一批候选原始输出，在固定验证集上比较 AP、每图预测数和漏检类型。不能只在一张图上挑出最好看的阈值就上线。

IoU / NMS / AP 的计算与阈值

概念公式 / 阈值要点
IoU交集面积 / 并集面积0~1。判正负样本常用 0.5（VOC）或 0.5:0.95（COCO）
正样本判定IoU ≥ 0.5 且类别一致COCO 还按面积分 small/medium/large
NMS IoU 阈值常用 0.5（0.6~0.7 用于密集场景）阈值越高保留的框越多，召回高但误检多
Soft-NMS 高斯sigma0.5不硬删框而是衰减分数，密集场景 mAP 常 +1~2 点
置信度阈值0.001（算 mAP 时）/ 0.25~0.5（部署时）算 mAP 要极低阈值以画出完整 PR 曲线
AP（VOC）11 点插值 PR 曲线均值recall ∈ {0, 0.1, ..., 1}
AP（COCO）101 点插值，IoU 0.5:0.05:0.95 取平均比 VOC 严格，数值通常 低 10~20 点

手算 IoU：框 A=(0,0,10,10)、框 B=(5,5,15,15)（x1,y1,x2,y2）。交集 = (5,5)-(10,10) = 5×5 = 25；面积各 100；并集 = 100+100-25 = 175；IoU = 25/175 ≈ 0.143。两个框看着重叠不少，IoU 却只有 0.14——这是 IoU 对偏移很敏感的直观例子，也是后来引入 GIoU/DIoU/CIoU 的原因。

可执行代码

import numpy as np

def iou(box, boxes):
    """box:(4,) boxes:(N,4) 均为 x1,y1,x2,y2"""
    ix1 = np.maximum(box[0], boxes[:, 0])
    iy1 = np.maximum(box[1], boxes[:, 1])
    ix2 = np.minimum(box[2], boxes[:, 2])
    iy2 = np.minimum(box[3], boxes[:, 3])
    inter = np.maximum(0, ix2 - ix1) * np.maximum(0, iy2 - iy1)
    area_b = (box[2]-box[0]) * (box[3]-box[1])
    area_s = (boxes[:,2]-boxes[:,0]) * (boxes[:,3]-boxes[:,1])
    union = area_b + area_s - inter
    return inter / np.maximum(union, 1e-6)      # 防除零

def nms(dets, scores, thr=0.5):
    order = scores.argsort()[::-1]              # 分数从高到低
    keep = []
    while order.size > 0:
        i = order[0]; keep.append(i)
        if order.size == 1: break
        rest = order[1:]
        ov = iou(dets[i], dets[rest])
        order = rest[ov <= thr]                 # 只保留重叠不超阈值的
    return keep
# Soft-NMS（高斯惩罚）：不删框，按重叠度衰减分数
def soft_nms(dets, scores, sigma=0.5, thr=0.001):
    dets, scores = dets.copy(), scores.copy()
    keep = []
    for _ in range(len(scores)):
        if scores.size == 0: break
        i = int(np.argmax(scores)); keep.append(i)
        ov = iou(dets[i], np.delete(dets, i, axis=0))
        idx = np.delete(np.arange(len(scores)), i)
        scores[idx] *= np.exp(-(ov ** 2) / sigma)   # 重叠越大衰减越狠
        scores[i] = -1
        drop = idx[scores[idx] < thr]
        dets = np.delete(dets, drop, axis=0)
        scores = np.delete(scores, drop)
    return keep

AP 手算与常见坑

手算 AP（VOC 11 点）：假设一张图 5 个预测框，按分数排序后累计 TP/FP：

#分数IoU判定累计TPPrecisionRecall
10.950.85TP11.000.20
20.900.60TP21.000.40
30.800.30FP20.670.40
40.700.75TP30.750.60
50.600.20FP30.600.60
  • 真实框共 5 个（Recall 分母=5），只召回 3 个 → 最大 Recall 0.6。
  • 11 点插值：对每个 recall 阈值 r，取 recall ≥ r 时的最大 precision，再取平均。
  • 坑 1：一个真实框只能被一个预测框匹配（其余同框预测算 FP），这是 NMS 存在的前提。
  • 坑 2：算 mAP 时置信度阈值要设很低（0.001），设成 0.5 会让 PR 曲线残缺、AP 虚高。
  • 坑 3：COCO 的 mAP@0.5 与 mAP@[.5:.95] 差别很大，论文对比必须指明是哪一个。

深入自检

IoU 阈值取 0.5 合理吗？

VOC 传统是 0.5，但 IoU=0.5 的框定位其实很松。COCO 用 0.5:0.05:0.95 的 10 档平均，对定位精度敏感得多。做高精度定位（如工业检测）应直接看 mAP@0.75 或 mAP@[.5:.95]。

NMS 阈值调高会怎样？

保留更多框 → 召回升高、误检也升高。密集人群场景常用 0.6~0.7；一般场景 0.5；若同类物体天然贴近（如货架商品），0.5 会误删，需调低到 0.3~0.4。

Soft-NMS 一定比 NMS 好吗？

不一定。Soft-NMS 在密集重叠场景（行人、车辆）能涨 1~2 点 mAP，但在稀疏场景几乎无差别，且多一个 sigma 超参要调、推理略慢。

为什么我的 mAP 很高但线上效果差？

常见原因：① 验证集与线上分布不一致；② 看的是 mAP@0.5 而线上需要 0.75 的定位精度；③ 没做 NMS 或线上阈值/阈值与评测时不一致；④ 小目标 AP 被大目标拉高的 mAP 掩盖了——要分开看 small/medium/large。

自检

两个框 IoU 很高，就能断言它们一定对应同一真实物体吗？

不能。相邻或遮挡的两个不同物体也可能有高度重叠的预测框，应结合类别、标注与任务评估。
