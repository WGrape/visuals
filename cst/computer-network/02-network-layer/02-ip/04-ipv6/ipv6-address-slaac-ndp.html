IPv6 地址、SLAAC 与邻居发现

从主机接入网络开始，推演地址形成、默认路由、邻居解析和双栈访问。

IPv6 地址的阅读方法

IPv6 地址有 128 位，用八组十六进制数表示；连续零组可用 :: 压缩一次。例如 2001:db8:1::20 可展开为 2001:0db8:0001:0000:0000:0000:0000:0020。前缀 /64 常见于普通局域网，表示前 64 位是网络前缀。IPv6 没有 IPv4 那种全网段广播，很多发现流程使用组播。地址空间更大并不意味着可以不用规划前缀、权限或日志。

常见作用域包括链路本地地址 fe80::/10、全球单播和用于内部场景的 ULA。链路本地地址仅在当前链路有效，常用于邻居发现和下一跳；向外访问通常需要合适的全球单播或其他可路由地址。接口可以同时持有多个 IPv6 地址，如稳定地址与临时隐私地址。排障必须记录实际选用的源地址，而不是只看接口上第一条地址。

主机如何得到地址和网关

主机加入链路后可形成链路本地地址，并通过 Router Solicitation 请求路由器通告，或等待 Router Advertisement。RA 可以发布前缀、默认路由、有效期以及指示是否使用 DHCPv6 获取某些配置。SLAAC 让主机根据通告前缀形成地址；接口标识可采用不同生成策略，并非总能从 MAC 地址直接推导。默认网关信息通常来自 RA，而不是简单照搬 IPv4 DHCP 的经验。

地址投入使用前通常需要执行重复地址检测，防止与同链路节点冲突。若 RA 被错误设备伪造，主机可能获得错误前缀或默认路由，因此交换网络可结合 RA Guard 等措施。RA、DHCPv6 和 DNS 配置各有职责，不能认为“拿到 IPv6 地址”就证明名称解析和外网访问都正常。

NDP 如何替代 ARP 的角色

IPv4 主机用 ARP 查询同链路 IP 对应的 MAC；IPv6 使用基于 ICMPv6 的邻居发现。主机向目标对应的 solicited-node 组播发送 Neighbor Solicitation，邻居通过 Neighbor Advertisement 回答其链路层地址。NDP 还承担路由器发现、重复地址检测等任务，范围比单纯地址映射广。

如果把所有 ICMPv6 都当作“可选 ping 流量”挡掉，邻居发现、路径 MTU 等关键功能可能失效。防火墙应按类型和来源制定规则，而不是一刀切。遇到“IPv6 有地址但不能通信”，要分别看 RA、邻居缓存、ICMPv6 报文和默认路由。

一个双栈访问过程

浏览器访问同时有 A 与 AAAA 记录的网站。解析器拿到 IPv4 与 IPv6 候选，客户端可能并行或交错尝试连接，以减少某一路径失效带来的等待。若 IPv6 有地址却路由不通，表现可能是首次访问很慢，最后退回 IPv4；不同客户端的回退策略不同。测试应分别强制 IPv4 和 IPv6 路径，再看正常双栈表现。

DNS 返回 AAAA 只表示有 IPv6 地址记录，不保证网络中每一跳都可达。服务端监听 IPv4 的 0.0.0.0 不必然等于监听 IPv6 的 ::，具体取决于系统与 socket 配置。上线双栈时要分别验证监听、路由、负载均衡、安全组、证书与日志源地址。

前缀和地址变更

路由器可以发布新前缀并逐步废弃旧前缀；主机可能在过渡期同时保留新旧地址。优先使用哪条源地址受地址选择策略和有效期影响。若防火墙只放行旧前缀，新连接可能突然失败；若日志仅记录地址而不关联设备身份，临时地址会让追踪更难。网络管理应记录前缀分配与租户归属，而非依赖 IPv6 地址永久不变。

在容器、VPN 和隧道网络中，额外封装会减小有效路径 MTU。IPv6 路由器不会像 IPv4 那样在途中替主机分片，源端要依靠路径 MTU 发现或其他机制调整包大小。不能因“IPv6 地址够用”就忽略 MTU、ICMPv6 和安全策略的协同。

可复现的排查清单

先看接口是否有链路本地和全球地址，再看 RA 获得的前缀、默认路由和邻居表。随后对同链路邻居、默认网关和外部 IPv6 地址逐级测试，最后测 AAAA 解析和业务端口。每一步都记源地址与出口接口。若能 ping 网关但访问外部失败，重点检查路由、防火墙和上游 IPv6 连通性。

练习双栈故障时，不要只做一次普通域名访问；分别用 IPv4、IPv6 和完整域名测试。这样可以区分“IPv6 链路坏了”“AAAA 记录错了”和“应用没有监听 IPv6”三种完全不同的修复方向。

IPv6 排查命令

# 查看/配置
ip -6 addr show
ip -6 route show
ip -6 neigh show                 # 邻居表（取代 ARP）

# 连通性测试
ping6 2001:db8::1                 # 或 ping -6
traceroute6 -n 2001:db8::1
curl -6 https://ifconfig.co

# 抓 NDP（取代 ARP 的 ICMPv6 报文）
tcpdump -i any -nn 'icmp6' -v
#   type 133 = Router Solicitation (RS)
#   type 134 = Router Advertisement (RA)
#   type 135 = Neighbor Solicitation (NS)   ← 取代 ARP Request
#   type 136 = Neighbor Advertisement (NA)  ← 取代 ARP Reply
tcpdump -i any -nn 'icmp6 and ip6[40] == 135'

# 临时禁用/启用 IPv6
sysctl -w net.ipv6.conf.all.disable_ipv6=1

SLAAC、NDP 与落地坑

机制取代谁协议说明
NDP 地址解析ARPICMPv6 NS/NA（135/136）用多播代替广播，效率更高
SLAAC 无状态自动配置DHCPICMPv6 RA（134）路由器发前缀，主机自己生成后 64 位
DAD 重复地址检测免费 ARPICMPv6 NS配置前先确认地址无人使用
DHCPv6 / RA 的 M、O 标志DHCPRA 中的标志位M=1 用 DHCPv6 取地址；O=1 只取其它配置（DNS 等）
  • SLAAC 的地址生成：早期用 EUI-64（由 MAC 地址推导，会泄露 MAC 且可追踪），现代系统默认用隐私扩展（RFC 4941）生成临时地址并定期更换。所以要区分“稳定地址”（用于对外服务）和“临时地址”（用于主动外访）。
  • DNS 服务器怎么来：SLAAC 本身不提供 DNS。靠 RDNSS（RA Option 25）或 DHCPv6 下发。这是 IPv6 部署最常见的坑——“拿到地址了但没有 DNS，什么都访问不了”。
  • Happy Eyeballs（RFC 8305）：双栈客户端应先尝试 IPv6，250 ms 内没建立连接就并行发起 IPv4。没有这个机制时，IPv6 不通会硬等数秒——这是“开了 IPv6 反而变慢”的根因。
  • 防火墙要放行 ICMPv6：IPv6 重度依赖 ICMPv6（PMTUD、NDP、RA）。像 IPv4 那样粗暴禁 ICMP 会导致 IPv6 完全不可用。必须放行类型 1–4、128–137 等。
  • 排查顺序：① 有 link-local 吗（接口是否 UP）；② 有 global 地址吗（RA 是否收到）；③ 有默认路由吗（ip -6 route）；④ DNS 解析出 AAAA 吗；⑤ ping6 通吗。
为什么 IPv6 配好了，还是上不了网？

最常见两条：① 没有 DNS 服务器（SLAAC 不下发，需 RDNSS 或 DHCPv6）；② 防火墙禁了 ICMPv6，导致 PMTUD/NDP 失效。其次是上游没有真正的 IPv6 出口。

IPv6 地址后面的 %eth0 是什么？

那是 scope id（区域标识）。link-local 地址（fe80::）在每个接口上都可能重复，必须指定接口才能唯一确定，所以写成 fe80::1%eth0 或 %12。

自检

拿到了全球 IPv6 地址，就能证明域名访问一定走 IPv6 吗？

不能。还需要可达的默认路由、AAAA 解析、客户端地址选择、服务端 IPv6 监听以及沿途放行。
