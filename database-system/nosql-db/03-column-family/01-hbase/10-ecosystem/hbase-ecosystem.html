Phoenix、Hive、Spark、Kafka 与 HDFS

Phoenix：把 SQL 带到 HBase

Apache Phoenix 是 HBase 之上的 SQL 层：把 SQL 编译成 HBase 的 scan/get，并提供二级索引、聚合、Join（有限）。适合「已用 HBase、又想要即席 SQL 查询」的团队。

Hive on HBase

  • 通过 Storage Handler 把 HBase 表映射成 Hive 外部表，用 HiveQL 做批量分析。
  • 适合离线分析，不适合低延迟在线查询。

Spark / Hadoop MR

  • Spark（或 MapReduce）可直接读写 HBase（用 saveAsHadoopDataset / Spark-HBase Connector），做大规模 ETL 与特征工程。
  • 批量导入大块数据推荐用 Bulk Load（直接生成 HFile 再加载），绕过 WAL/MemStore，速度最快。

Kafka → HBase：实时入库

典型管道：Kafka（消息）→ Flink/Spark Streaming/Storm（实时计算）→ HBase（落地）。如实时指标、用户行为画像、IoT 时序等。

与 HDFS 的关系

HBase 的所有数据最终存放在 HDFS 上（WAL、HFile 都是 HDFS 文件）。HDFS 的多副本保证了数据可靠性，HBase 自己不重复做副本——它负责「怎么组织与快速访问」这些数据。

💡 选型一句话：在线按 key 实时读写 → HBase；即席 SQL/索引 → Phoenix；离线批分析 → Hive/Spark；全文检索 → 旁路写 ES。 让每个组件待在自己最擅长的位置。
