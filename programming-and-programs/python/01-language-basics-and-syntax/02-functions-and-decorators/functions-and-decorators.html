函数与装饰器

Python 把函数当成「一等公民」：能赋值、能传参、能返回、能嵌套。装饰器不过是把「函数包函数」这件事语法糖化——理解它，才算真正入门 Pythonic 写法。

一等公民

函数可以像变量一样被对待

「一等公民（first-class）」指函数能被赋给变量、作为实参传入、作为返回值、存进容器。这是装饰器和很多高级写法的基础。

📦
赋值
把函数绑到另一个名字，原名字仍在
➡️
传参
把函数当回调传给 map/sorted/别的函数
🏭
返回
函数里 return 另一个函数（工厂/闭包）
def greet(name): return f"hi {name}"

say = greet          # 赋值给变量
print(say("a"))       # hi a

def run(f, x): return f(x)   # 作为实参传入
print(run(greet, "b"))  # hi b

fs = [greet, len]      # 存进容器
print([f("xy") for f in fs])  # ['hi xy', 2]

函数也是对象（详见名称绑定与对象语义）：它身上挂着 __name__、__doc__、闭包变量等属性，所以装饰器才能「读改写」它。

参数解构

*args 收集位置参数，**kwargs 收集关键字参数

Python 用 * 和 ** 把「任意数量」的参数聚成元组 / 字典，反过来也能把它们「打散」传给别的函数。这是写装饰器、包装函数的必备技能。

def f(a, b, *args, **kwargs):
    print(a, b, args, kwargs)

f(1, 2, 3, 4, x=5)   # 1 2 (3, 4) {'x': 5}

# 反向打散：把序列/字典拆成实参
nums = [1, 2, 3]
print(range(*nums))     # range(1, 2, 3)
d = {"x": 1, "y": 2}
f(0, 0, **d)         # 0 0 () {'x': 1, 'y': 2}
⚠️ 危险顺序（Python 3 强制）：位置 / *args / 仅关键字 / **kwargs。关键字-only 参数要写在 * 之后，例如 def f(a, *, b)——调用时 b 必须显式写名字。
可变默认参数的坑（列表当默认值会被共享）放在语言特性篇讲过；这里只需记住：默认值在定义时求值一次，别用可变对象当默认。
闭包

内层函数「记住」了外层变量

闭包 = 内层函数 + 它捕获的外层作用域变量。即使外层函数已经返回，这些变量依然活着。装饰器正是建立在闭包之上。

def make_adder(n):
    def add(x):
        return x + n      # add 捕获了外层的 n
    return add

plus3 = make_adder(3)
print(plus3(10))      # 13 —— n=3 被记住了
print(plus3.__closure__)  # 闭包单元，存着 n

闭包捕获的是变量本身不是当时的值，所以循环里挂闭包要小心「延迟绑定」（见作用域与命名空间的坑）。想冻结值，用默认参数：def f(x=i): ...。

装饰器

@ 只是「函数包函数」的语法糖

@deco 等价于 func = deco(func)：把原函数塞进一个包装函数，再把这个包装函数绑回原名。包装函数里先做事、再调用原函数、可改返回值。

import functools, time

def timer(func):
    @functools.wraps(func)      # 保留原函数的 __name__/__doc__
    def wrapper(*args, **kwargs):
        t0 = time.time()
        r = func(*args, **kwargs)  # 调用原函数
        print(f"{func.__name__}: {time.time()-t0:.3f}s")
        return r
    return wrapper

@timer
def slow():
    time.sleep(0.1)

slow()   # slow: 0.100s
带参装饰器是「三层嵌套」：外层收参数返回真正装饰器。常见套路 def deco(arg): def deco2(f): ... return deco2。永远记得 @functools.wraps(func)，否则原函数的名字和文档会被包装函数覆盖，调试时很坑。
内置装饰器

四个最常用的「语言级」装饰器

这些是 Python 标准库直接提供的装饰器，理解它们能少写很多样板代码。

装饰器作用典型用途
@property把方法当属性访问（只读）计算型字段、惰性属性
@staticmethod不绑定实例/类的方法工具函数，放类里只为归类
@classmethod首参是类 cls工厂方法、替代重载构造
@functools.lru_cache记忆化缓存返回值斐波那契、递归、查表
class Circle:
    def __init__(self, r): self.r = r
    @property
    def area(self): return 3.14 * self.r ** 2

    @classmethod
    def unit(cls): return cls(1)   # 工厂

c = Circle(2)
print(c.area)          # 像属性一样访问，不用 c.area()
u = Circle.unit()      # 类方法构造

装饰器不是魔法，本质就是「接收函数、返回函数」的高阶函数。把这一篇和作用域、对象语义串起来看，Python 的函数模型就通了。

参数形式用法

# 完整签名：def f(pos_only, /, standard, *, kwd_only)
def connect(host, port, /, timeout=10, *, ssl=True, retries=3):
    #  host, port   : 仅位置（调用方不能写 host=...，这样以后改名不会破坏兼容）
    #  timeout      : 常规（两种都行）
    #  ssl, retries : 仅关键字（必须写名字，避免 ssl 和 retries 传反）
    ...

connect("localhost", 5432, 30, ssl=False, retries=5)   # ✅
connect(host="localhost", port=5432)                    # ❌ TypeError: 仅位置参数

# 为什么要有"仅位置"？
#   库作者在 2.0 版本想把 host 改名为 hostname
#   如果是仅位置参数，用户代码 connect("x", 1) 不受影响
#   如果允许关键字，用户的 connect(host="x") 就挂了 -> 破坏性变更

# 解包调用
args = [1, 2, 3]
kwargs = {"a": 1, "b": 2}
f(*args)              # 位置解包
f(**kwargs)           # 关键字解包
f(*args, **kwargs)    # 混合

# 字典合并运算符（3.9+）与函数参数的配合
defaults = {"timeout": 10, "retries": 3}
final = defaults | {"timeout": 30}      # 后者覆盖前者
connect(**final)

装饰器：执行时机是最容易搞错的

问题答案
装饰器什么时候执行？定义时（模块导入时）立即执行，不是调用时
被装饰的函数何时被调用？每次调用时，执行的是 wrapper
多次装饰的顺序？从下往上应用，从上往下执行
为什么要用 @wraps？否则 __name__/__doc__ 丢失，影响文档与调试

装饰器模板

import functools, time

# ① 标准装饰器骨架（记住这个模板）
def timer(func):
    @functools.wraps(func)            # 必加！保留 __name__ / __doc__ / __annotations__
    def wrapper(*args, **kwargs):
        t0 = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            print(f"{func.__name__} 耗时 {time.perf_counter()-t0:.3f}s")
    return wrapper

@timer
def slow():
    '''文档字符串'''
    time.sleep(0.1)

slow.__name__      # 'slow'（有 wraps）；无 wraps 则是 'wrapper'
slow.__doc__       # '文档字符串'

# ② 带参数的装饰器 = 三层嵌套
def retry(times=3, delay=1.0):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for i in range(times):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    if i == times - 1: raise
                    time.sleep(delay * (2 ** i))    # 指数退避
        return wrapper
    return decorator

@retry(times=3, delay=0.5)
def call_api(): ...

# 理解：@retry(times=3) 先执行 retry(3) 得到 decorator，
#       再用 decorator(call_api)  -> 等价于 call_api = retry(3)(call_api)

# ③ 多次装饰的顺序
@d1
@d2
def f(): ...
# 应用顺序：f = d1(d2(f))   （离函数近的先应用）
# 执行顺序：d1 的 wrapper 先执行，内部再调 d2 的 wrapper

# ④ 类装饰器（或装饰类的装饰器）
def singleton(cls):
    instances = {}
    @functools.wraps(cls)
    def get(*a, **kw):
        if cls not in instances:
            instances[cls] = cls(*a, **kw)
        return instances[cls]
    return get

@singleton
class Config: ...

最常见的坑：装饰器在导入时就执行，所以如果装饰器里做了依赖运行时状态的事（如读配置、连数据库），会在 import 阶段就崩。装饰器里只做“包装”，不要做副作用。

闭包与 late binding（最容易踩的坑）

闭包陷阱

# ⚠️ 经典陷阱：闭包捕获的是"变量"而不是"值"
funcs = []
for i in range(3):
    def f():
        return i          # 捕获的是变量 i，不是当时的值
    funcs.append(f)
print([g() for g in funcs])    # [2, 2, 2]  <- 全是最后一次的值

# ✅ 解法①：用默认参数"钉住"当前值
for i in range(3):
    def f(i=i):           # 默认参数在定义时求值
        return i
    funcs.append(f)
print([g() for g in funcs])    # [0, 1, 2]  ✅

# ✅ 解法②：用工厂函数（每次调用创建新的作用域）
def make_f(i):
    def f():
        return i
    return f
funcs = [make_f(i) for i in range(3)]

# 原理：Python 的闭包是"晚绑定（late binding）"
#   函数体内引用的变量，在函数<b>被调用时</b>才去查找
#   循环结束后 i=2，所以三次调用都拿到 2

# 同样的坑也出现在 lambda 里
[lambda: i for i in range(3)]        # ❌ 全是 2
[lambda i=i: i for i in range(3)]    # ✅

为什么设计成 late binding：这是 Python 的变量作用域规则决定的——闭包捕获的是变量绑定而非值，这样闭包才能看到变量的后续变化（这在计数器等场景是有用的）。只是用在循环里时反直觉。

lru_cache：最实用的内置装饰器

参数默认值说明
maxsize128缓存条目上限；设为 2 的幂最快；None = 无上限
typedFalseTrue 时 1 和 1.0 算不同 key
cache_info()—查看命中率（必须监控）
cache_clear()—清空缓存（测试时用）

lru_cache 用法

from functools import lru_cache

@lru_cache(maxsize=1024)          # 2 的幂，命中率最高
def fib(n):
    if n < 2: return n
    return fib(n-1) + fib(n-2)

fib(50)                            # 无缓存要算几十年，有缓存瞬间完成
print(fib.cache_info())
# CacheInfo(hits=48, misses=51, maxsize=1024, currsize=51)
# 命中率 = 48/(48+51) = 48%  -> 太低说明缓存没起作用（或 maxsize 太小）

# ⚠️ 三个使用前提（缺一不可）：
#   ① 函数必须是<b>纯函数</b>（相同输入 -> 相同输出，无副作用）
#   ② 参数必须<b>可哈希</b>（list/dict/set 不行，要转成 tuple/frozenset）
#   ③ 结果不是超大数据（缓存会一直占内存，直到进程结束）

# ❌ 错误用法：缓存了可变对象或依赖外部状态
@lru_cache
def get_user(uid):
    return db.query(uid)           # ❌ 数据库更新后永远返回旧值！

# ✅ 要么不缓存，要么加 TTL（标准库没有，用 cachetools）
from cachetools import TTLCache
cache = TTLCache(maxsize=1000, ttl=300)    # 5 分钟过期

# 3.8+ 的 cached_property（实例级别缓存，比 lru_cache 更适合方法）
from functools import cached_property
class Order:
    @cached_property
    def total(self):
        return sum(i.price for i in self.items)   # 只算一次，之后复用

深入自检

装饰器有什么真实应用场景？

最常见的六类：① 计时/日志（性能埋点）；② 缓存（lru_cache）；③ 重试/熔断（@retry）；④ 权限校验（Web 框架的 @login_required）；⑤ 路由注册（Flask 的 @app.route，本质是往路由表登记）；⑥ 注册机制（把函数注册进插件系统）。理解本质：装饰器 = 在不修改原函数的前提下，给它套一层逻辑，这是 AOP（面向切面编程）在 Python 里的轻量实现。

为什么 wraps 这么重要？

不加 @wraps 时，被装饰函数的 __name__ 会变成 'wrapper'，__doc__ 丢失。三个实际后果：① 日志和错误信息里显示的是 wrapper 而非真实函数名，排查困难；② help() 和自动生成文档内容为空；③ 依赖 __name__ 的框架（如 Flask 路由、pytest）可能无法正常工作。functools.wraps 本质是复制 __module__、__name__、__qualname__、__doc__、__dict__ 等属性。写装饰器就养成加 wraps 的习惯，没有例外。

默认参数为什么不能用可变对象？

因为默认参数在函数定义时求值一次，之后所有调用共享同一个对象。def f(x, lst=[]) 中的 [] 在模块加载时就创建好了，每次调用 lst.append() 都是在往同一个列表里加。这是 Python 最有名的坑之一。标准解法：用 None 做哨兵——def f(x, lst=None): lst = lst if lst is not None else []。同理，默认参数不要用 datetime.now()——它会固定为导入时的时间，而不是调用时。

怎么写一个既带参数又能不带参数的装饰器？

用可选参数技巧：让装饰器既能接收函数，也能接收参数。标准写法是检查第一个参数是否为 callable：def deco(arg=None): → 若 callable(arg) 则直接返回 decorator(arg)，否则返回 decorator。这样 @deco 和 @deco(times=3) 都能用。不过实践中建议明确二选一——这种“两用”写法增加了理解成本，除非你在写公共库需要兼顾两种调用习惯。

进阶层 · 装饰器的四个硬骨头

会用 @decorator 只是入门。真正会踩坑的是这四点：保留元信息、带参数的装饰器、装饰器的执行时机、以及装饰器叠加顺序。

问题现象解法
元信息丢失func.__name__ 变成 wrapper@functools.wraps(func)
装饰器要带参数@retry(times=3) 怎么写三层嵌套（外接收参数，内接收函数）
执行时机装饰器在导入时就执行了注册类装饰器要注意副作用时机
叠加顺序多个装饰器的顺序反直觉从下往上应用

代码

import functools, time

# —— 1) 保留元信息（必写）——
def timing(func):
    @functools.wraps(func)          # 【必写】否则 func.__name__ 变成 wrapper
    def wrapper(*args, **kwargs):
        t = time.time()
        try:
            return func(*args, **kwargs)
        finally:
            print(f'{func.__name__} took {time.time()-t:.3f}s')
    return wrapper

# —— 2) 带参数的装饰器 = 三层嵌套 ——
def retry(times=3, delay=0.1, exceptions=(Exception,)):
    def decorator(func):            # <- 这一层接收【函数】
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for i in range(times):
                try:
                    return func(*args, **kwargs)
                except exceptions:
                    if i == times - 1:
                        raise       # 最后一次还失败就抛出
                    time.sleep(delay)
        return wrapper
    return decorator                # <- 外层返回【装饰器】

@retry(times=3, delay=0.5)
def call_api(): ...

# —— 3) 装饰器在【导入时】执行 ——
registry = {}
def register(name):
    def decorator(func):
        registry[name] = func       # <- 这行在 import 时就跑了
        return func
    return decorator

@register('handler_a')              # import 本模块时即注册
def handler_a(): ...
#   【坑】如果模块从未被 import，注册就不会发生
#   解法：显式 import 或改用 entry_points / 插件发现机制

# —— 4) 叠加顺序：从下往上应用 ——
@dec_a
@dec_b
def f(): ...
#   等价于 f = dec_a(dec_b(f))
#   所以执行时：先 dec_b 的逻辑，再 dec_a
#   例：@login_required 放在 @cache 下面 -> 先缓存后鉴权 = 【安全漏洞】！

# —— 既能当 @dec 又能当 @dec() 用（可选参数）——
def flexible(func=None, *, times=1):
    def decorator(f): ...
    if func is None:
        return decorator            # @flexible(...)
    return decorator(func)          # @flexible

最容易出安全事故的一条：叠加时把鉴权装饰器放在缓存装饰器下面——会先返回缓存再鉴权，等于鉴权失效。顺序必须想清楚。

进阶层 · 参数传递的坑与性能

  • 可变默认参数（Python 第一大坑）：def f(x, items=[]) 里的 [] 是函数对象创建时创建的同一个列表，多次调用会累积。正确写法：def f(x, items=None): items = items or []。同理 {}。
  • 默认参数在定义时求值：def f(t=time.time()) 的时间戳是定义时的，不是调用时的。要动态默认值用 None + 函数内计算。
  • *args, **kwargs 的顺序：必须是 def f(a, b, *args, **kwargs)。Python 3 还支持仅关键字参数：def f(a, *, b) 表示 b 必须用关键字传。
  • 参数解包的坑：f(*args, **kwargs) 转发参数时，如果原函数有仅限位置参数（Python 3.8+ 的 / 语法），可能报错。
  • 装饰器的性能开销：每次调用多一层函数调用（约 0.1~0.5μs）。在每秒百万次的内层循环里，几层装饰器会累积成可观的开销。但 HTTP 请求级（ms 级）完全无感。
  • functools.lru_cache 的坑：① 参数必须可哈希（列表/字典不行）；② 缓存的是函数对象级的，长期运行会占内存（用 maxsize 限制）；③ 带副作用的函数不要缓存。
  • 闭包延迟绑定：[lambda: i for i in range(3)] 三个函数都返回 2。解法：lambda i=i: i。
