01管道：内核里的一条环形缓冲区

第一层

概念与判定

pipe() 返回两个 fd：读端和写端。内核维护一个环形缓冲区（默认 64KB，Linux），读写遵循生产者-消费者语义。

#include <unistd.h>
int fd[2];
pipe(fd);            // fd[0] 读端, fd[1] 写端
if (fork() == 0) {  // 子进程读
    close(fd[1]);
    char buf[128];
    read(fd[0], buf, sizeof(buf));
} else {            // 父进程写
    close(fd[0]);
    write(fd[1], "hello", 5);
}
必须关掉不用的那一端：若读端没关，写端 read 永远不会收到 EOF（因为还有写者存在），会永久阻塞。这是新手最常踩的坑。
特性说明
容量默认 64KB（/proc/sys/fs/pipe-max-size 可调）
原子性写入 ≤ PIPE_BUF（4096B）保证不与其他写者交错
半双工历史上单向；Linux 上可双向但语义不保证
EOF所有写端关闭后，读端 read 返回 0
SIGPIPE读端全关后写 → 收到 SIGPIPE

02FIFO：有名字的管道

FIFO（命名管道）让无亲缘关系的进程也能通信——它就是一个出现在文件系统里的特殊文件：

# 创建
mkfifo /tmp/myfifo

# 进程 A 写（阻塞直到有读者）
echo "hello" > /tmp/myfifo

# 进程 B 读
cat /tmp/myfifo
打开 FIFO 时若没有对端会阻塞。用 O_NONBLOCK 打开可避免（读端打开立即成功，写端无读者时返回 ENXIO）。

03共享内存：把同一块物理页映射进两个地址空间

图：共享内存的本质是两个页表项指向同一物理页帧。
# SysV 方式
ipcmk -M 4096              # 创建 4KB 共享内存
ipcs -m                    # 查看

# POSIX 方式（更推荐）
int fd = shm_open("/demo", O_CREAT | O_RDWR, 0600);
ftruncate(fd, 4096);
void *p = mmap(NULL, 4096, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);
共享内存不提供任何同步。两个进程同时写同一位置会互相覆盖，读到「半个更新」的撕裂数据。必须配信号量/互斥锁/原子操作。

04共享内存 + 信号量：生产者消费者

// 伪代码：用 POSIX 信号量保护共享缓冲
sem_t *empty = sem_open("/empty", O_CREAT, 0600, N);
sem_t *full  = sem_open("/full",  O_CREAT, 0600, 0);

// 生产者
sem_wait(empty);
buf[in] = item; in = (in+1) % N;
sem_post(full);

// 消费者
sem_wait(full);
item = buf[out]; out = (out+1) % N;
sem_post(empty);
同步对象放哪说明
互斥锁 pthread_mutex共享内存里（需 PTHREAD_PROCESS_SHARED）临界区互斥
信号量 sem_t命名信号量或共享内存计数/通知
文件锁 flock配套文件粗粒度，简单

05排障与边界

第三层

排障与边界

  • 共享内存泄漏：POSIX 共享内存要 shm_unlink，否则 /dev/shm 被占满，新进程 shm_open 失败（ENOSPC）。
  • mmap 后忘记 msync：文件映射写入不保证落盘，崩溃可能丢数据；需要 msync 或 fsync。
  • 管道死锁：双方都先读后写、或都没关不用的端 → 互相等待。
  • 大页对齐：共享内存映射到大页上性能更好，但地址/大小需对齐（2MB）。

06速记卡

管道三要素

环形缓冲、64KB、单向；关掉不用的端。

PIPE_BUF

4096B 以内的写保证原子。

共享内存

最快（零拷贝），但同步全靠自己。

泄漏点

shm_unlink / msgctl(IPC_RMID) / ipcrm。

SIGPIPE

往无读者的管道写会被杀，记得忽略。
