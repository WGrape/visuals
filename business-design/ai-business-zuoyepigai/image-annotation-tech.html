示意图（不是真实学生作文）：绿色波浪线、橙色矩形框、圆形序号 —— 都是覆盖层。

它由三层叠加而成

① 底层 · 原图（baseLayer）

用户上传的作文照片（手机拍的、扫描的都有），绝对定位、铺满容器、原样展示。

② 中间层 · 标注层（overlay）

SVG / Canvas / DOM 三选一。绿波线、橙色方框、序号气泡、写出来的评语文字……全部在这一层。它的坐标和原图共享同一套相对坐标。

③ 顶层 · 交互层（hitLayer）

透明的 <div> + JavaScript，用来捕获点击 / 拖拽。点击"在图上画一条线"就是它接住的事件，再把坐标写进标注层。

核心思想：标注 = 一份独立于像素的结构化数据（JSON / Protobuf），由前端用矢量方式重新渲染，原图本身不动。这样存数据、做编辑、做多端回放都轻松。

2数据结构：标注在代码里长什么样

后端落库、网络传输、前端渲染都共用同一份 Schema。下单 → 渲染 → 编辑都靠它。

// Annotation: 单条标注（波浪线、方框、序号、文字…）
interface Annotation {
  id: string;                // uuid
  type: "wave"               // 绿波线
      | "underline"          // 横线
      | "highlight"          // 荧光笔高亮
      | "rect"               // 方框
      | "circle"             // 圆形（包字）
      | "tag"                // 带序号的圆形（"1""2""3"）
      | "text";              // 写在图上的文字评语
  color: string;             // "#10b981"
  geometry:
    | { kind:"polyline"; points:{x:number,y:number}[] }      // 一组连续折线点
    | { kind:"box"; x:number; y:number; w:number; h:number } // 矩形
    | { kind:"circle"; cx:number; cy:number; r:number }      // 圆心 + 半径
    | { kind:"text"; x:number; y:number; fontSize:number; content:string };
  comment?: string;          // 给老师的便条（悬停可见）
  authorRole: "system" | "teacher" | "student";
  createdAt: number;
  updatedAt: number;
}

// 一次批改产出：原图 + 标注列表
interface GradedImage {
  imageId: string;
  imageUrl: string;          // 原始图（CDN）
  imageWidth: number;        // 原始像素宽
  imageHeight: number;       // 原始像素高
  annotations: Annotation[];
  score?: number;            // 右上角的综合分
  version: number;           // 编辑一次 +1，做乐观锁
}

关键点 所有坐标都用 0~1 的相对值（归一化坐标），这样不管手机 4K 图、扫描 600dpi 图、网页缩放多少，标注都不会错位（详见 §7）。

为什么坐标必须归一化？ 同一张图，用户可能 360×640 缩略图、1200×1600 高清屏、原图 3024×4032 三种尺寸下都要正常显示。如果存绝对像素，回放一定偏移；如果存归一化值（x=0.12, y=0.33），任意尺寸下乘容器宽高就是正确位置。

TypeScript：从 Annotation[] 渲染到 DOM

type Pt = { x: number; y: number };   // 0~1 归一化
interface Annotation { type:string; color:string; geometry:any }

function renderOverlay(svg: SVGSVGElement, ann: Annotation[]) {
  svg.innerHTML = ann.map(a => {
    switch (a.type) {
      case "wave": {
        const pts = a.geometry.points as Pt[];
        const d = pts.map((p,i)=> (i?"L":"M") + p.x + "," + p.y).join(" ");
        return `<polyline points="${d}" fill="none" stroke="${a.color}"
                  stroke-width="0.003" stroke-linecap="round"/>`;
      }
      case "rect": return `<rect x="${a.geometry.x}" y="${a.geometry.y}"
        width="${a.geometry.w}" height="${a.geometry.h}"
        fill="none" stroke="${a.color}" stroke-width="0.003"/>`;
      case "circle": return `<circle cx="${a.geometry.cx}" cy="${a.geometry.cy}"
        r="${a.geometry.r}" fill="none" stroke="${a.color}"
        stroke-width="0.003"/>`;
      case "tag": return `
        <circle cx="${a.geometry.cx}" cy="${a.geometry.cy}" r="0.018" fill="${a.color}"/>
        <text x="${a.geometry.cx}" y="${a.geometry.cy+0.004}" font-size="0.016"
              text-anchor="middle" fill="#fff" font-weight="700">
          ${a.geometry.label ?? ""}
        </text>`;
      case "text": return `<text x="${a.geometry.x}" y="${a.geometry.y}"
        font-size="${a.geometry.fontSize}" fill="${a.color}" font-weight="600">
          ${escapeHtml(a.geometry.content)}
        </text>`;
    }
    return "";
  }).join("");
}
SVG viewBox 的细节： 用 viewBox="0 0 1 1" + preserveAspectRatio="none"，所有坐标都是 0~1 的相对值。再用 CSS 把 svg 撑成 100% 宽高 → 任意分辨率下都不会变形。stroke-width 也写相对值（0.003 这种），避免粗细随图大小变化。

SVG 方案的优缺点

优点缺点
矢量，永远不糊；每个标注都是 DOM 节点，可单独加事件 / class / CSS标注太多（>5000）时会卡，DOM 太重
存的就是 JSON 结构化数据，可直接 fetch / 持久化不能做"像素级涂抹"那种自由画笔
打印无损、zoom 无损、文本可以被屏幕阅读器读出需要手写 SVG 字符串拼装，不够大型项目用 D3/React 当 DSL

4前端实现 B：Canvas / Konva（拖拽编辑）

当用户要"亲手在图上画"——比如老师用红笔自由涂抹、像改试卷那样——SVG 就吃力了，得用 Canvas 方案。

原生 Canvas 实现思路

const canvas = document.querySelector("#overlay");
const ctx = canvas.getContext("2d");

function fitCanvasSize() {
  const rect = img.getBoundingClientRect();
  const dpr = window.devicePixelRatio || 1;
  canvas.width  = rect.width  * dpr;
  canvas.height = rect.height * dpr;
  canvas.style.width  = rect.width  + "px";
  canvas.style.height = rect.height + "px";
  ctx.scale(dpr, dpr);
  redraw();
}

// 鼠标按下→记录起点，move 时画到临时层，松开放回 annotation[]
canvas.addEventListener("mousedown", e => {
  drawing = true;
  current = [ { x: e.offsetX/rect.width, y: e.offsetY/rect.height } ];
});
canvas.addEventListener("mousemove", e => {
  if (!drawing) return;
  current.push({ x: e.offsetX/rect.width, y: e.offsetY/rect.height });
  redraw();      // 性能：每帧重画全部，但节流到 requestAnimationFrame
});
canvas.addEventListener("mouseup", () => {
  drawing = false;
  annotations.push({ type:"polyline", points: current });
  current = [];
  redraw();
});

function redraw() {
  ctx.clearRect(0,0,canvas.width,canvas.height);
  [...annotations, ...(current?[current]:[])].forEach(a=>{
    ctx.strokeStyle = a.color;
    ctx.lineWidth   = 2.5;
    ctx.beginPath();
    a.points.forEach((p,i)=> i?ctx.lineTo(p.x*rect.width, p.y*rect.height)
                              :ctx.moveTo(p.x*rect.width, p.y*rect.height));
    ctx.stroke();
  });
}

6后端实现：怎么把标注烧进一张新图

很多场景（导出 PDF / 分享到家长微信 / 离线海报图 / 学生没登录看缓存）需要"一张完整图带标注"，这时候后端得离线合成一张 PNG。三条路线，按需选用。

路线 A · Pillow 图像合成

Python · 最常用 · 完全可控
  • 读原图 + 解坐标 + 在图层上画线、画方框、写字
  • 矢量精确，颜色 dpi 完全控制
  • 缺点：中文字体要 .ttf 文件
  • 高 DPI 原图（3024×4032）也能处理

路线 B · Playwright html2img

Node · 复用前端样式 · 视觉一致
  • headless Chromium 把整段 HTML 渲染成 PNG
  • CSS、SVG、emoji 全部一致
  • 缺点：启动慢（2~3s）、内存大、字体回退可能不一致
  • 适合需要"前端什么效果图就什么图"

路线 C · SVG → PNG (svg2png)

纯函数 · 最快 · 最易缓存
  • 前端把视图序列化成完整 SVG（包含底图 <image href>）
  • 后端 librsvg / resvg 渲染为 PNG
  • 缺点：嵌入位图会很大；中文渲染需字形

Pillow 写法（详细注释）

from PIL import Image, ImageDraw, ImageFont, __version__
print("Pillow", __version__)

def compose_with_annotations(
    bg_path: str,
    annotations: list,
    target_width: int = 1080,
    score: int | None = None,
):
    base = Image.open(bg_path).convert("RGBA")
    ow, oh = base.size
    scale = target_width / ow
    new_h = int(oh * scale)
    canvas = base.resize((target_width, new_h), Image.LANCZOS).convert("RGBA")
    overlay = Image.new("RGBA", canvas.size, (0,0,0,0))      # 透明叠加层
    draw    = ImageDraw.Draw(overlay)
    font_path = "/usr/share/fonts/truetype/wqy/wqy-zenhei.ttc"   # 中文字体
    fnt_sm = ImageFont.truetype(font_path, int(target_width*0.022))
    fnt_lg = ImageFont.truetype(font_path, int(target_width*0.04))

    for a in annotations:
        g = a["geometry"]
        # 坐标转换：归一化 → 像素
        def X(v): return int(v * target_width)
        def Y(v): return int(v * new_h)
        if a["type"] == "wave":
            pts = [(X(p["x"]), Y(p["y"])) for p in g["points"]]
            for i in range(len(pts)-1):
                draw.line([pts[i], pts[i+1]], fill=a["color"], width=4, joint="curve")
        elif a["type"] == "rect":
            draw.rectangle([X(g["x"]), Y(g["y"]), X(g["x"]+g["w"]), Y(g["y"]+g["h"])],
                           outline=a["color"], width=4)
        elif a["type"] == "circle":
            r = int(g["r"] * target_width)
            draw.ellipse([X(g["cx"])-r, Y(g["cy"])-r, X(g["cx"])+r, Y(g["cy"])+r],
                         outline=a["color"], width=4)
        elif a["type"] == "tag":
            r = int(g["r"] * target_width)
            draw.ellipse([X(g["cx"])-r, Y(g["cy"])-r, X(g["cx"])+r, Y(g["cy"])+r],
                         fill=a["color"])
            label = str(g.get("label",""))
            bbox = draw.textbbox((0,0), label, font=fnt_lg)
            tw, th = bbox[2]-bbox[0], bbox[3]-bbox[1]
            draw.text((X(g["cx"])-tw//2, Y(g["cy"])-th//2 - int(target_width*0.005)),
                      label, fill="white", font=fnt_lg)
        elif a["type"] == "text":
            draw.text((X(g["x"]), Y(g["y"])), g["content"], fill=a["color"], font=fnt_sm)

    # 右上角打分卡片
    if score is not None:
        s = str(score)
        bbox = draw.textbbox((0,0), s, font=fnt_lg)
        sw, sh = bbox[2]-bbox[0], bbox[3]-bbox[1]
        pad = int(target_width*0.03)
        bx0, by0 = target_width - sw - pad*3, pad
        bx1, by1 = target_width - pad, pad + sh + pad
        draw.rounded_rectangle([bx0, by0, bx1, by1], radius=pad*0.6, fill="#4f46e5")
        draw.text(((bx0+bx1-sw)//2, (by0+by1-sh)//2 - int(target_width*0.005)),
                  s, fill="white", font=fnt_lg)

    return Image.alpha_composite(canvas, overlay).convert("RGB")

7坐标系、抗缩放、多分辨率

标注层能不能稳定，坐标系选择占八成功夫。生产里踩的坑几乎全在这。

用 0~1 归一化（强烈推荐）

// 录入时（用户点一下图）
function pickPt(evt, imgEl) {
  const rect = imgEl.getBoundingClientRect();
  return {
    x: (evt.clientX - rect.left) / rect.width,    // 永远是 0~1
    y: (evt.clientY - rect.top)  / rect.height,
  };
}
// 渲染时（任意尺寸都能用）
function px(p, w, h) { return { x: p.x * w, y: p.y * h }; }

不同分辨率下的换算公式

场景源坐标系渲染到 / 落库前
前端 SVG（CSS 尺寸）0~1直接给 viewBox
Pillow（任意 PNG）0~1× 目标宽高
iOS 端（pt 单位）pt÷ device scale = 相对 0~1
OCR 回写（像素）原图像素÷ 原图宽高
高清大图导出（4K）0~1× 4096 → 像素

窗口缩放 / retina 屏的坑

坑 1：图片实际像素和 CSS 像素不是一回事。 比如 3024×4032 图放在 50% container 里：
  • CSS 尺寸：1512×2016（给 viewBox / canvas 用）
  • 设备像素（retina ×2）：3024×4032（canvas 内部要乘 devicePixelRatio）
  • OCR 给出的 bbox：是原图像素，必须先 ÷ 原图宽高 → 归一化，再 × 当前 CSS 尺寸

旋转 / EXIF 朝向问题

// 后端存入图前就要 EXIF 矫正，否则 OCR 与标注坐标系错位
import piexif
from PIL import Image

def normalize_orientation(img: Image.Image) -> Image.Image:
    raw = img.info.get("exif")
    if not raw: return img
    exif = piexif.load(raw)
    ori  = exif.get("0th", {}).get(piexif.ImageIFD.Orientation, 1)
    rotations = { 3: 180, 6: -90, 8: 90 }
    if ori in rotations:
        img = img.rotate(rotations[ori], expand=True)
        # 把 Orientation 重置成 1，避免前端再做一次
    return img

9前后端完整分工与通信契约

最后落回工程交付 —— 谁负责做什么，用什么 API 串起来。

9.1 前后端职责一图分层

层前端负责后端负责
数据Annotation 录入（点 / 拖拽）、本地图层实时合并Annotation 持久化、版本号、权限校验

9.3 协作编辑（多端实时）的三个关键设计

  1. 乐观锁： annotation 带 version，写入冲突时 409，前端 merge 后重试
  2. CRDT / OT： 多老师同时改同一行时，用 Y.js (CRDT) 自动合并，比手写 OT 简单
  3. SSE 而非轮询： AI 自动评语异步产出，用 SSE / WebSocket push，前端只渲染增量

9.4 失败兜底矩阵

失败兜底
前端 SVG 渲染失败（极少见）降级为 <canvas> 重画，再失败降级为 div + 提示
后端 Pillow 没装中文字体回退到英文字体 + 占位符，并日志告警
图片上传失败前端走分片重传 + Resume，后端 OSS 直传签名降级
WebSocket 断退化为 5s 轮询 + IndexedDB 本地合并，恢复时同步差量
总结一句话：「标注」本质上是一份独立于像素的结构化 JSON，由前端 SVG/Canvas 实时渲染，由后端 Pillow 兜底合成。三层叠加（底图 + 标注层 + 交互层） + 相对坐标 + 单 Schema 多渲染，是这种页面工程上稳的关键。
