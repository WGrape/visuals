🌨️ 缓存雪崩：一大批 key 同时倒下

同一时刻大量 key 集体过期，或缓存集群整体宕机，导致所有流量瞬间压到数据库。

🌨️

定义

大批 key 同时失效

🎲

随机 TTL

给过期时间加抖动

🏗️

多级缓存

本地缓存兜一层

🔌

熔断降级

保住数据库不崩

先建立直觉：大坝同时开了所有闸门

击穿是一扇门坏了，雪崩是整排闸门同时打开。原本被缓存拦住的水（流量）在一瞬间全部倾泻到下游的数据库上——下游根本来不及泄洪，直接被冲垮。

两种典型成因：

为什么雪崩比击穿危险得多？击穿是一个 key 的问题，数据库只多承受一个 key 的查询量；雪崩是全部 key 同时失效，数据库要承受平时缓存挡住的 100% 流量——这个量级通常是数据库承载能力的几十上百倍，往往直接宕机，且容易引发连锁故障（数据库挂 → 应用线程池打满 → 上游服务超时 → 整个链路雪崩）。

解法一：给 TTL 加随机抖动（治成因 A）

这是最便宜、最有效的一招。批量写入时不要给相同的 TTL，而是在基准值上叠加一个随机量，把过期时间打散。

// 错误：所有 key 都是 300 秒，到点一起失效
redis.SetEX(key, 300, val);

// 正确：基准 300 秒 + 0~300 秒随机抖动
ttl := 300 + rand.Intn(300)        // 300 ~ 600 秒之间随机
redis.SetEX(key, ttl, val);
为什么有效？原本 10 万个 key 在同一秒失效，数据库要扛 10 万次查询；打散到 300 秒窗口后，平均每秒只多约 333 次，完全在承载范围内。同样的总量，分散到时间轴上就不构成冲击。

同理，避免在系统低峰期做大规模缓存预热后集中失效；预热也要带抖动。

解法二：多级缓存（治成因 B）

Redis 挂了之后，如果还有一层本地缓存（Caffeine / Guava / Ehcache）挡在前面，大量请求仍能在应用进程内命中，不会全部打到数据库。

层级位置Redis 宕机时
L1 本地缓存应用进程内存✅ 仍能命中部分请求
L2 分布式缓存Redis 集群❌ 全部失效
L3 数据库MySQL承受剩余穿透流量
多级缓存的代价：一致性更难（本地缓存无法主动失效所有节点），需要靠短 TTL + 消息广播失效来收敛。且本地缓存占应用内存，要控制容量。

解法三：熔断降级 + 限流（最后的保命层）

当数据库压力超过阈值，主动拒绝一部分请求而不是让所有人一起死。这就是熔断与降级：

  • 熔断：错误率/延迟超阈值时，快速失败，不再打数据库，给它喘息时间。
  • 降级：返回兜底数据（默认值、静态页、上次快照），保证「能用」而非「准确」。
  • 限流：只放行数据库能承受的量，多余的排队或拒绝。
核心理念：雪崩场景下，「部分可用」远优于「整体崩溃」。宁可让 30% 的请求拿到降级结果，也不要让数据库挂掉导致 100% 不可用。

解法四：Redis 高可用（从源头减少成因 B）

  • 集群 + 主从 + 哨兵：单点故障自动切换。
  • 持久化：宕机重启后能恢复数据，避免冷启动空缓存。
  • 异地多活：机房级故障时仍有缓存可用。

一整套防线

层次手段防的是
写入时TTL 随机抖动成因 A
架构上多级缓存（本地 + Redis）成因 A、B
架构上Redis 集群 + 持久化成因 B
运行时熔断、降级、限流已经发生时的止损

🎯 面试问答

Q：雪崩和击穿的本质区别是什么？
A：看失效 key 的数量：击穿是一个热点 key 过期（点），雪崩是一大批 key 同时过期或整个缓存集群不可用（面）。后果量级差几十上百倍：击穿只是多了一个 key 的查询量，雪崩是数据库直面全部流量。另外击穿通常只影响使用这个 key 的接口，雪崩会让整个系统不可用。

Q：TTL 随机抖动的随机范围怎么定？
A：经验做法：在基准 TTL 上叠加 0~基准值 的随机量（如基准 300s，实际 300~600s）。随机窗口越宽，过期越分散，数据库越安全；但窗口太宽会让数据陈旧程度差异变大。一般让窗口不短于「数据库重建全部数据所需时间」即可。

Q：Redis 整个集群挂了，本地缓存能救多少？
A：取决于本地缓存的命中率。本地缓存容量小（通常只放最热的数据），可能只能挡住 30%~60% 的请求。但这已经足够救命——数据库只要不被 100% 流量砸中，就还有活下来的机会。所以本地缓存 + 熔断降级是雪崩场景的标准保命组合。

Q：缓存预热会不会反而引发雪崩？
A：会，这是很常见的自伤。如果在大促前批量预热 100 万个 key 且给了相同的 TTL，那么这些 key 会在同一秒集体失效，人为制造一次雪崩。正确做法：预热时同样加随机抖动；或者对预热数据不设 TTL（靠后续更新）；再或者分批预热，错开时间。
