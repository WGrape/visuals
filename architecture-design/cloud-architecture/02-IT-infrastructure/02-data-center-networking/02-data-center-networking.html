数据中心网络

从接入到骨干，理解现代数据中心如何做到无阻塞与可预测延迟

TOR/LeafSpine收敛比液冷

一句话：现代数据中心用 Spine-Leaf 取代传统三层网络，把任意两台服务器之间的跳数固定为 3 跳，从而支撑云时代爆发式的“东西向”流量。

为什么不用传统三层网络

传统“核心—汇聚—接入”三层架构为“南北向”流量（用户→服务器）设计。但虚拟化之后，一台物理机上的多个 VM/容器互相通信，流量大量在机柜之间横向流动（东西向）。三层架构下跨汇聚的流量要经过核心层，跳数不固定、易拥塞、难预测延迟。Spine-Leaf 正是为解决这个问题而生。

Leaf（接入）

每个机柜顶部一台（TOR），下联服务器，上联所有 Spine。

Spine（核心）

只做 Leaf 间的高速转发，不直连服务器；横向扩展只需加 Spine。

固定 3 跳

任两台服务器：服务器→Leaf→Spine→Leaf→服务器，东西向恒定 3 跳，延迟可预测。

关键指标：收敛比与带宽

指标含义取值
收敛比（Oversubscription）下行总带宽 / 上行总带宽1:1 无阻塞（贵）；3:1 可接受（普通业务）
接入带宽服务器网卡→Leaf10/25 Gbps 主流，AI 训练 100 Gbps+
骨干带宽Leaf→Spine100/400/800 Gbps
AI 训练集群GPU 集合通信对网络的要求必须 1:1，否则 all-reduce 被网络拖垮

经验：普通 Web 业务 3:1 收敛比足够且省钱；但分布式训练、存储复制等“大象流”场景必须 1:1，否则 GPU 空转等网络。

高密度与液冷

AI 机柜单柜功率已从传统 8 kW 升到 20–80 kW，风冷逼近极限，必须液冷（冷板/浸没）。液冷带来新的网络布线挑战：管路与光模块共存，要求更短的链路预算和更密的连接器。

概念与判定

  • Spine-Leaf 是什么：两层 Clos 网络，Leaf 接服务器、Spine 只做 Leaf 间转发；相对传统三层，跳数固定、易横向扩展。
  • 何时用：机柜数多、东西向流量大（云/虚拟化/AI 集群）必用；小型单柜机房传统三层也够。

排障与边界

  • TCP Incast：大量服务器同时回一个节点，交换机 buffer 溢出丢包→启用 ECN/DCTCP 或减小 fan-in。
  • 排查：ethtool eth0 看速率/双工；ip -s link 看丢包/错包；ss -tin 看 TCP 重传与 RTT。

原理与取舍

  • 三层 vs Spine-Leaf：三层省钱但东西向不可预测；Spine-Leaf 成本高但可预测、易扩展。
  • 存算分离的网络瓶颈：计算无状态化后，数据走网络，网络从“管道”变成“瓶颈”，所以收敛比和带宽要按需给足。
