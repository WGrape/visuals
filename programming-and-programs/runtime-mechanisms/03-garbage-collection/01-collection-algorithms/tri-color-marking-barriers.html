三色标记与写屏障：并发 GC 如何避免漏标

沿对象图的一次指针更新，理解白、灰、黑三种状态和写屏障维护的不变量。

三色只是标记算法中的抽象状态

白色表示本轮尚未发现，灰色表示已发现但其引用尚未全部扫描，黑色表示已扫描完成。GC 从根集合出发，把可达对象逐步染灰、扫描引用后染黑；结束时仍为白色的对象可作为不可达候选。根通常包括栈、寄存器、全局变量和运行时维护的引用。具体实现可能用位图或其他数据结构，颜色是帮助推理的概念，不要求对象头里真的存三个颜色字节。

单线程停顿标记时，对象图在扫描期间不变，推理较简单；并发标记允许应用线程继续修改引用。如果黑对象新增指向白对象的边，而那条边没被记录，白对象可能错误地留到回收阶段。这是并发 GC 必须处理的核心风险之一。写屏障在指针赋值时记录必要信息，帮助标记器保持“可达对象不能被漏掉”的不变量。

逐步推演

发现根

把栈、全局变量等根可达对象加入待扫描队列。

扫描三色

灰对象扫描引用后变黑，新发现对象变灰。

拦截写入

应用改变指针时，写屏障记录新边或旧边所需信息。

终止与清扫

确认灰队列和并发记录处理完毕，再回收剩余白对象。

一个漏标风险的具体路径

设根指向对象 A，A 已被扫描为黑色；对象 B 仍为白色。应用线程执行 A.child = B。如果标记器永远不再扫描 A，也没有写屏障记录 B，B 可能在这一轮结束时被当成垃圾。更复杂的情况是应用删除一条旧边、添加一条新边，不同并发标记算法需要记录旧引用或新引用以维持各自的不变量。

动作可能风险机制目的
黑对象指向白对象新边无人扫描记录新引用或重新扫描
删除旧引用快照中的对象可能失去可见路径记录旧引用
分配新对象颜色初始状态不一致按本轮策略初始化
进入回收阶段仍在标记队列的对象被误回收等待并发标记完成与终止检查

两类写屏障思路

增量更新风格关注“新出现的黑到白引用”：写入新指针时把目标纳入标记队列，避免黑对象藏住白对象。快照起始风格关注“本轮开始时可达的对象”：覆盖旧指针时记录旧目标，使旧图中的对象不因并发删除而被漏掉。真实运行时可能混合策略，并对栈、堆、分配对象采用专门规则。不要把某种语言某一版本的实现直接当成所有 GC 的通用协议。

写屏障让每次相关指针写入多一些工作，因此并发标记减少停顿并不意味着没有成本。还可能有短暂初始停顿、最终标记停顿、后台标记 CPU 和额外内存保留。若分配速率持续高于回收速率，GC 仍可能追不上；应同时观察暂停时间、GC CPU、堆大小和分配速率。

如何排查并发标记问题

  1. 先确认对象是否真的不可达，再看弱引用、终结器和运行时对象生命周期规则。
  2. 对比标记开始、写屏障启用、终止标记和清扫时间线，确认写入发生在哪个阶段。
  3. 用图示列出根、黑对象、灰队列、白对象和每次指针赋值，检查哪条边可能丢失。
  4. 性能分析同时统计暂停、后台 CPU、写入屏障开销和堆增长，避免只优化单个指标。

练习：A 已黑，B 仍白，应用让 A 指向 B。若采用增量更新风格，你希望写屏障至少记录什么？若使用快照起始风格，为什么删除旧边时也可能需要记录旧目标？

根扫描与安全点仍需要协调

并发 GC 并不表示完全没有停顿。运行时需要在某些时刻获得线程栈和寄存器中的根引用，并确认所有待处理的标记队列已经清空；这些步骤可能要求线程到达安全点或短暂停止。若一个线程长期不进入可安全扫描的位置，标记阶段也可能被拖长。设计写屏障时还要考虑栈上指针与堆上指针的更新方式，不同运行时会选择不同协议。

弱引用和终结器进一步改变“可达”的判断。只被弱引用指向的对象可能被回收；带终结器的对象可能在回收过程中延迟释放，并可能出现复杂的复活行为。用三色图分析时先限定为普通强引用，再把这些特殊机制单独加入，避免把“对象有一个引用”直接等同于“对象本轮一定存活”。

测 GC 时不能只看最大暂停时间。写屏障增加应用写入成本，后台标记占用 CPU，保留更多对象增加内存；吞吐、尾延迟和峰值内存是不同目标。调整参数前应明确业务更在意哪一个，并在代表性分配模式下测试。

观察误差

对象在一次 GC 后仍存活，不一定是内存泄漏：可能本轮标记开始时可达、被写屏障保守保留，或仍被缓存和闭包引用。应结合多轮 GC 后的堆趋势、根路径和分配速率判断，而不能拿单次回收后的对象数下结论。

新分配对象在并发标记中如何着色，也是正确性协议的一部分；不能默认它们一律从白色开始，否则可能在尚未扫描时被错误回收。

三色不变式与两种屏障

概念定义含义
白色未访问（候选垃圾）标记结束后仍是白色即可回收
灰色已访问但其引用未扫描完待处理队列
黑色已访问且引用已扫描完确定存活
强三色不变式黑色对象绝不指向白色对象最严格，需插入屏障
弱三色不变式黑色指向白色时，该白色必须存在一条从灰色经若干白到它的路径更宽松，需删除屏障
丢失对象的条件同时满足：① 黑→白引用被建立；② 灰→白（或白→白）路径被切断两条同时发生才会漏标

屏障的作用就是破坏这两个条件之一：保证不会把存活对象误判为垃圾。

插入屏障 vs 删除屏障

屏障触发时机做法代价 / 特点
插入屏障（Dijkstra）建立「黑 → 白」引用时把新引用的白色对象置灰（或把黑色回退为灰）保守：存活对象不会被漏标，可能产生浮动垃圾
删除屏障（Yuasa）删除「灰/白 → 白」引用时把被删除的目标置灰快照式（SATB）：需记录删除前的值，精度高
混合屏障（Go 1.8+）插入 + 删除都拦两者结合，保证堆上对象不会被漏标只需在标记结束时重扫栈一次，STW 大幅缩短

Go 1.8 之前需要在 GC 开始时 STW 并扫描全部栈；引入混合屏障后，栈上的写不需要屏障，只需在标记终止阶段重扫一次 goroutine 栈，STW 从「随栈数增长」降到亚毫秒级。

各语言的落地对照

语言 / 收集器屏障类型STW 阶段典型目标
Go（并发三色）混合屏障 + 栈重扫标记开始/终止各一次（很短）STW 亚毫秒级
Java G1SATB（删除屏障）+ 写前记录初始标记、最终标记（短暂）暂停目标 -XX:MaxGCPauseMillis（默认 200 ms）
Java ZGC读屏障 + 染色指针几乎全并发暂停 < 10 ms（与堆大小无关）
JVM CMS写屏障 + 增量更新初始/重新标记已废弃（JDK 14 移除）

深入自检

并发标记为什么会漏标对象？

因为用户线程与 GC 同时运行，可能同时发生两件事：① 一个黑色对象新增了指向某个白色对象的引用（黑→白）；② 原本从灰色到该白色对象的路径被删除。两者同时成立时，该白对象既不会被扫描也不会被当作存活，就会被误回收。

插入屏障和删除屏障分别破坏哪个条件？

插入屏障破坏条件①：建立黑→白引用时把白色置灰（或把黑色回退为灰），于是黑色永远不会指向白色；删除屏障破坏条件②：删除引用时把目标置灰，保证仍有一条可达路径被继续扫描。

Go 的混合屏障为什么能缩短 STW？

因为它同时拦截插入与删除，保证堆上的对象不会被漏标，只剩下栈上的写无法拦（栈写无法逐条插屏障，代价太高）。所以只需在标记终止阶段 STW 并重扫一次 goroutine 栈，而不必在 GC 开始时 STW 扫描全部栈——STW 时间不再随栈数量线性增长。

浮动垃圾是什么？要紧吗？

指本轮 GC 中被屏障保守置灰、但实际已经死亡的对象。它们会存活到下一轮才被回收。这是并发 GC 的正常代价，通常不严重；代价是堆占用略高、下一轮前不能用这部分内存。

强三色不变式和弱三色不变式有什么区别？

强三色要求黑色对象绝不指向白色（最严格，插入屏障即可满足）；弱三色允许黑色指向白色，但要求该白色仍可从某个灰色对象经白色路径到达（删除屏障配合）。弱三式约束更松，通常能减少屏障开销，但需要更仔细的终止条件。

自检

灰色对象和黑色对象的差别是什么？

灰色对象已发现但引用尚未全部扫描；黑色对象的引用已扫描完成。

并发 GC 的写屏障主要防什么？

防止应用并发修改引用时，可达对象逃过本轮标记而被误回收。
