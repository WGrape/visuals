声码器与音频编解码

声码器为什么存在、传统 / 神经声码器 / 神经音频 token 三条路线、采样率与码率的取舍、传输侧为什么实时链路选 Opus，以及六类音质问题的定位方法。

声码器在链路上的位置

文本→声学模型→中间表示（mel 谱 / 音频 token）→声码器→波形

声学模型输出的是压缩过的中间表示（通常是 mel 频谱，帧率远低于采样率）， 人耳不能直接听。声码器（vocoder）负责把它还原成逐采样点的波形。

为什么不能直接输出波形
16 kHz 采样意味着每秒 16000 个采样点，直接建模序列太长、太难。 mel 谱把一秒压成约 100 帧 × 80 维，既好建模又保住了听感所需的信息。
声码器决定什么
它不改变"说什么""什么语调"，决定的是音质、清晰度与合成速度。 同一个声学模型换声码器，听感可以差很多。

三条技术路线

路线原理特点
传统信号处理（Griffin-Lim 等）从幅度谱迭代估计相位无需训练，速度慢、音质有金属感，现在多作为基线
神经网络声码器（HiFi-GAN 一类）用卷积/ GAN 直接从 mel 生成波形音质好、推理快，长期以来的主流选择
神经音频编解码（codec / 音频 token）把波形离散成 token 序列，模型直接预测 token与语言模型天然统一，端到端语音模型的基石，可同时承载语义与声学信息
第三条路线是当前的关键变化：当语音被离散成 token 后， "生成语音"和"生成文本"在模型看来是同一类任务，可以用同一个自回归模型处理。 这也是端到端语音对话模型得以成立的前提之一。

关键参数：采样率、位深、码率

传输侧：音频编解码

注意区分两个"codec"：神经音频编解码（模型内部表示）与传输编解码（网络传输压缩）。 后者关心的是带宽与抗丢包。

编码定位适用
PCM（未压缩）原始采样，质量无损局域网、服务端内部处理
Opus低延迟、抗丢包强、自适应码率实时通话的首选，WebRTC 默认
AAC / MP3成熟、兼容性好，延迟较高点播、录制文件分发
传统语音编码（G.7xx 系）电话网遗留，码率极低对接传统电话系统
实时语音链路选 Opus，几乎不会错。 它专为交互式语音设计，支持帧长自适应与丢包隐藏， 在弱网下的表现远好于为音乐设计的编码。录制文件分发再考虑 AAC/MP3。

音质问题怎么定位

现象可能的环节
整体发闷、像打电话采样率过低，或传输码率压得太狠
有金属声、机械感声码器能力不足，或 mel 与声码器训练配置不匹配
偶发爆音、咔哒声流式合成的块边界不连续，或缓冲区拼接错误
音量忽大忽小缺少响度归一化，或不同音色模型混用
首尾被切掉VAD 裁剪过头（见「VAD 与打断」篇）
背景有嗡嗡声采样率转换未做抗混叠，或电源/接地噪声
定位方法：把链路中间产物dump 出来分别听。 先听声学模型输出的 mel 转成的波形（可先用简单声码器），再听最终输出。 两者都差 → 问题在声学模型；mel 好而最终差 → 问题在声码器或后处理。 没有中间产物 dump 的能力，音质排查就只能靠猜。

两个容易混淆的概念

这两个词都带「编码」，但干的活完全不同。把它们放在一起看，反而更容易记住：

声码器 Vocoder

输入是声学特征（通常是梅尔频谱），输出是波形采样点。它是 TTS 的最后一步，负责把中间产物还原成能播放的声音。

核心难点是相位 —— 频谱丢掉了相位信息，而波形必须要有正确的相位。

音频编解码 Audio Codec

输入是波形，输出是压缩后的比特流或离散 token，解码端再还原成波形。

传统 codec 为「节省带宽」设计，神经 codec 额外还能产出离散 token 序列，让语言模型可以直接对音频做建模。

上路补相位，下路做离散化的差别

声码器的一小段演化

代表机制速度音质
Griffin-Lim迭代估计相位，纯信号处理方法较快有明显金属感，多作为兜底
自回归波形模型逐采样点预测，条件于全局/局部特征极慢质量好但难以上线
流 / 扩散类用归一化流或去噪方式生成波形中等到慢质量高，推理步数可调
GAN 类（HiFi-GAN 系）生成器 + 多尺度判别器实时倍率可达数十倍目前工业界主力

为什么 GAN 类路线会成为主流：它一次性（非自回归）地并行产出整段波形，能在 CPU 上实时；判别器专门在「多尺度/多周期」上挑刺，恰好解决了语音里最容易被听出来的那类失真（周期性、辅音清晰度、频谱平滑）。

挑选时的三个指标：RTF（real-time factor，合成 1 秒音频需要多少秒计算，必须明显小于 1）、听感 MOS、以及对训练域外数据（童声、叫喊、歌唱、口音）的稳健性。

神经 codec 的关键：残差向量量化 RVQ

RVQ 的思想很像「逐级逼近」：先用一个小码本粗略表示，把误差再交给下一个码本，一层层把残差压下去。

原始向量 x ↓ 第 1 层码本：选最近的码字 q1，残差 r1 = x − q1 ↓ 第 2 层码本：选最近的码字 q2，残差 r2 = r1 − q2 ↓ ... ↓ 第 N 层：残差已足够小 最终表示 = (i1, i2, ..., iN) ← N 个整数 层数 N：常见 4~16 层 比特率 ≈ N × log2(码本大小) × 帧率 例如 8 层 × 10bit × 50Hz = 4 kbps 量级

这种结构带来两个好处：① 比特率可调 —— 只用前几层就是低码率版本，全部用上就是高质量版本（ scalable 特性）；② 天然分层 —— 粗层承载内容与音色轮廓，细层承载细节音质，方便模型按层建模（很多语音大模型先从粗层生成，再逐层补细节）。

选型与实践

场景用什么理由
TTS 最后一步还原波形GAN 类实时声码器速度与音质平衡最好
实时通话传输传统通信 codec（Opus 系）抗丢包、低延迟、生态成熟
把音频喂给语言模型神经 codec（EnCodec / SoundStream / DAC 系）产出离散 token，支持结构化建模
存储/分发音乐传统音频 codec压缩率高、解码省电、兼容性好
自研语音大模型神经 codec + 自定义 token 词典token 词表规模与采样率要与模型容量匹配

几个必须知道的数字：采样率常见 16kHz（语音足够）与 24/44.1/48kHz（音乐）；帧长通常 10~20ms；位深 16bit 是语音的常规选择。做实时链路时，这些参数决定了每帧的字节数与缓冲延迟 —— 20ms 一帧意味着链路里每经过一个缓冲就多 20ms。

深入自检

为什么不能直接对波形样本做自回归生成？

因为太密了：48kHz、16bit 意味着每秒 48000 个整数，一首歌几百万 token，序列长度远超当前模型的经济处理范围。压缩到每秒几百到几千个 token 后，语言模型才可能用合理的算力建模长时结构。这就是 codec 在语音大模型里的核心地位。

梅尔频谱到底是什么，为什么大家爱用它作为中间表示？

它是把波形分帧后做时频变换，再把频率轴按梅尔刻度（更接近人耳对不同频率的分辨力）压缩成几十到上百个通道的结果。它去掉了相位，比原始波形稀疏得多，又保留了足够被人耳与时域模型利用的信息，因此成为 TTS 与语音任务里事实上的通用中间层。

神经 codec 会取代通信 codec 吗？

短期不会。通信 codec 在工程上极其成熟：极低延迟、强抗丢包、弱网表现、硬件解码、标准兼容 —— 这些都是实时通话的硬指标。神经 codec 目前的强项在于重建质量与 token 化，更适合作为模型侧的表征工具，两者服务的是不同目标。

怎么判断 codec 质量够不够？

从三个角度：① 重建失真（波形层/频谱层误差、 perceptual 指标如 PESQ / ViSQOL）；② 语义是否保留（把 codec 还原后的音频送去 ASR，看识别率掉多少）；③ 说话人是否被保留（说话人 embedding 相似度）。第二条尤其重要 —— 很多 codec 听起来不错，但语义信息被抹掉了，下游任务会很吃亏。
