01USE 方法与工具分层

第一层

概念与判定

OS 性能观测的黄金法则是 USE 方法（Utilization / Saturation / Errors）：对每一类资源（CPU、内存、磁盘、网络、总线）逐一问三个问题——利用率高不高？饱和（排队）严不严重？有没有错误？先排除非瓶颈，再深入。

图：USE 法对每类资源快速体检。
层次工具
全局top/htop、vmstat、mpstat、free
磁盘iostat、iotop、blktrace
网络ss、ip、sar -n、tcpdump
内核级perf、ftrace、eBPF(bpftrace)
进程pidstat、/proc、strace
自上而下 vs 自下而上：先 top 看哪类资源吃紧（自下而上用 USE），再 perf 看热点函数（自上而下）。strace 看 syscall 次数/耗时，定位「是不是卡在系统调用」。

02常用命令与指标

第二层

参数·命令·量化

常用命令速查

top -H                 # 看线程级 CPU（H=线程）
vmstat 1                # procs/r b, memory, si/so, io/bi bo, cpu/us sy id wa
mpstat -P ALL 1         # 每核利用率，找单核打满
iostat -xz 1            # 磁盘 await/svctm/%util, aqu-sz(队列)
sar -n DEV 1           # 网卡 rx/tx 速率与错误
pidstat -d 1            # 每进程 IO
perf top                # 实时热点函数
perf record -g -p ; perf report   # 采样+调用栈
strace -p  -e trace=network -T     # 跟系统调用耗时
指标含义 / 判据
r (vmstat)运行队列长度，>CPU 核数说明饱和
wa (cpu)等 IO 的 CPU，高=磁盘瓶颈
si/so换入换出，非零=内存压力
%util (iostat)设备忙时占比，100% 常=瓶颈
aqu-sz平均 IO 队列深度，高=饱和
perf 采样有开销：高频采样（如 -F 999）-g 调用栈会显著拖慢目标进程；生产先低频率，确认范围再加密。

03排障与边界

第三层

排障与边界

  • CPU 高但 us 低、sy 高：大量时间在内核（syscall/锁/中断）。用 perf 看内核函数，可能是锁竞争或系统调用风暴。
  • load average 高但 CPU 空闲：进程在等 IO / 锁（D 状态），vmstat 的 b 列高。看 iostat 与 wa。
  • strace 自己拖慢程序：strace 用 ptrace，每次 syscall 都陷一次，吞吐可能掉几倍。只用于临时诊断，别挂生产核心链路。
  • 容器里指标是宿主机的：容器内 top/free 很多时候看到的是宿主机视图（除非正确隔离 cgroup），要用 cgroup 暴露的值判断。
  • 缓存干扰：看到 cache 大就以为内存够是错的，要看 available 和具体 cgroup 限额。

04原理与取舍

第四层

原理与取舍

观测工具分两代：传统 /proc + 采样（低开销但粗），与 eBPF（内核可观测性，零侵入、细粒度）。eBPF 能在不重启、不改代码下挂到任意内核函数/追踪点，是现代可观测性的底座（bpftrace / bcc / Pixie）。

手段粒度开销
/proc + 采样进程/秒级极低
perf函数/调用栈中
strace单 syscall高（ptrace）
eBPF内核任意点低（JIT）

深入 Q&A

Q：load average 到底算不算 CPU 用满？
A：不算。它是「可运行 + 不可中断睡眠（D）进程数」的指数移动平均。D 状态多是等 IO/锁，此时 CPU 可能很闲——所以高 load 低 CPU 是典型 IO 瓶颈信号。

Q：eBPF 为什么零侵入还低开销？
A：字节码在内核 JIT 执行，只在内核事件触发时跑一小段，不像 ptrace 那样每次陷用户态；且不必改应用代码。
