梯度下降与优化器：SGD / Momentum / Adam / AdamW 到底差在哪

反向传播告诉你"往哪走"，优化器决定"怎么走、走多快"。从最朴素的 SGD 到今天大模型预训练标配的 AdamW + 余弦退火 + warmup，本文讲清每一步演进解决的是什么问题。

梯度下降的三种"喂数据"方式

方式每次更新用多少数据优点缺点
批量梯度下降 BGD全量训练集梯度方向稳定、最准确一次更新就要扫全量数据，大模型根本跑不动
随机梯度下降 SGD1 条样本更新极快梯度噪声巨大，loss 剧烈抖动
小批量 Mini-batch （实际唯一在用的）32～数千条噪声适中，且能并行吃满 GPU需要调 batch size
注意术语混乱：日常说"用 SGD 训练"，实际指的都是 Mini-batch 梯度下降；而优化器名字里的 "SGD" 特指那个不带自适应学习率的更新规则。

SGD 的问题：峡谷里来回震荡

朴素 SGD 对每个参数用同一个学习率。但损失地形往往是"狭长峡谷"：某个方向陡峭、另一个方向平缓。统一学习率会导致：

学习率调大
陡峭方向直接冲过谷底，来回震荡甚至发散
学习率调小
平缓方向爬得极慢，训练遥遥无期

演进一：Momentum（动量）

引入"速度"变量 v，把历史梯度做指数加权平均，再用它去更新参数：

v ← β·v + (1-β)·g   ,   θ ← θ - lr·v
效果：方向一致的维度，速度不断累积 → 加速；方向来回翻转的维度，正负抵消 → 抑制震荡。典型 β = 0.9。

演进二：Adam（自适应学习率）

Momentum 解决了"震荡"，但仍对所有参数用同一学习率。Adam 再引入二阶动量 v（梯度平方的滑动平均），给每个参数单独缩放步长：

m ← β₁·m + (1-β₁)·g  (一阶/方向)  ·  v ← β₂·v + (1-β₂)·g²  (二阶/幅度)
θ ← θ - lr · m̂ / (√v̂ + ε)
√v̂ 大的参数
历史梯度一直很大 → 步长被缩小，走得更谨慎
√v̂ 小的参数
历史梯度很小（稀疏特征） → 步长被放大，不至于停滞
默认 β₁=0.9, β₂=0.999, ε=1e-8。因为做了偏差修正（m̂, v̂），训练初期估计不会偏小。

演进三：AdamW —— 大模型的实际标配

Adam 有个著名缺陷：它把 L2 正则（weight decay）和自适应缩放耦合在一起了。原始实现里 weight decay 加在梯度上，于是它也会被 √v̂ 缩放，导致不同参数的实际衰减强度不一致，正则效果被削弱。

AdamW 的修法：把 weight decay 从梯度里拿出来，直接作用在参数更新那一步，解耦二者：

θ ← θ - lr·( m̂/(√v̂+ε) + λ·θ )
这就是大模型预训练几乎一律用 AdamW 的原因：收敛更快、泛化更好、weight decay 真正生效。
优化器显存
Adam 要为每个参数存 m 和 v 两份状态 → 优化器状态常占训练显存的大头（fp32 下约 8 字节/参数）
8-bit Adam
把 m/v 量化到 8 bit 存，显存大幅下降
Adafactor
用低秩分解近似二阶动量，去掉显存开销

学习率调度：warmup + 余弦退火

光有好优化器不够，学习率 lr 本身也要随时间变。大模型训练的标准配方：

  • Warmup（预热）：前几百～几千步把 lr 从 0 线性升到峰值。训练刚开始时参数是随机的、梯度很大，一上来就用大 lr 会直接训崩；warmup 让模型先"稳住"。
  • 余弦退火：之后按余弦曲线缓慢降到接近 0，后期细粒度收敛。
  • 梯度裁剪（常配合 warmup）：按范数截断过大梯度，进一步防止训崩。

面试速记卡

  • SGD → Momentum → Adam → AdamW：分别解决「震荡」「方向不稳」「各参数尺度不同」「weight decay 与自适应耦合」。
  • Adam 的两个动量：一阶 m 管方向，二阶 v 管步长缩放；每参数自适应。
  • AdamW 与 Adam 的唯一区别：weight decay 解耦，直接作用在参数更新上。
  • 优化器显存：Adam 的 m/v 状态是训练显存大头，引出 8-bit Adam / Adafactor / ZeRO。
  • 大模型标配配方：AdamW + warmup + 余弦退火 + 梯度裁剪。

优化器速查：更新规则、默认超参、显存开销

这四类优化器的差别，本质上是要不要累积历史梯度（动量）和要不要按参数自适应缩放步长这两个开关的组合。

优化器动量自适应步长默认超参额外显存（每参数）
SGD✗✗lr（0.1 / 0.01）0
SGD+Momentum✓✗lr=0.1, momentum=0.94 B（1 份动量）
AdaGrad✗✓lr=0.014 B
RMSProp✗✓（滑动平均）lr=1e-3, α=0.994 B
Adam✓✓lr=1e-3, β=(0.9,0.999), ε=1e-88 B（m + v 两份）
AdamW✓✓lr=1e-3, weight_decay=0.018 B
Lion✓（符号）✓lr=1e-4（比 Adam 小 10 倍）4 B（只存动量）

更新规则与显存估算

import torch

# Adam 的完整更新（记住这三行就够理解所有自适应优化器）
#   m = b1*m + (1-b1)*g                 <- 一阶动量（方向平滑）
#   v = b2*v + (1-b2)*g^2               <- 二阶动量（幅度估计）
#   m_hat = m/(1-b1^t);  v_hat = v/(1-b2^t)     <- 偏差修正（前几步很关键）
#   theta = theta - lr * m_hat / (sqrt(v_hat) + eps)

# 显存估算：7B 模型 AdamW 训练（BF16 参数 + FP32 主权重 + Adam 状态）
#   参数  BF16: 2 x 7e9  = 14 GB
#   梯度  BF16: 2 x 7e9  = 14 GB
#   主权重 FP32: 4 x 7e9 = 28 GB
#   Adam m+v FP32: 8 x 7e9 = 56 GB
#   -----------------------------------
#   合计 ≈ 112 GB   -> 这就是为什么「训练显存 ≈ 推理显存的 8~16 倍」

opt = torch.optim.AdamW(model.parameters(), lr=1e-3, betas=(0.9, 0.999),
                        eps=1e-8, weight_decay=0.01)

# 标准调度组合：warmup + cosine
from torch.optim.lr_scheduler import LambdaLR
warmup = 2000
def lr_fn(step):
    if step < warmup: return step / warmup
    p = (step - warmup) / (total - warmup)
    return 0.5 * (1 + math.cos(math.pi * p))     # cosine 到 0
sched = LambdaLR(opt, lr_fn)

# 梯度裁剪（大模型必备）
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)

Adam vs AdamW 的关键差别只有一处：weight decay 怎么加。Adam 是把 L2 惩罚加进梯度里（会和自适应步长耦合，导致 decay 实际效果被缩放）；AdamW 是直接在参数上减（θ -= lr·wd·θ），解耦了。所以现在默认用 AdamW，尤其 Transformer 训练。

学习率怎么定、训练出问题怎么调

现象可能原因调整
loss 一步就 nan / inflr 太大 + 无 warmuplr 降 10 倍；加 1000~2000 步 warmup；加 grad clip
loss 缓慢下降但很慢lr 太小做 lr 扫描（1e-5 → 1e-1 对数取点，跑几千步看下降最快那个）
loss 上下剧烈震荡lr 太大 或 batch 太小lr 减半 / batch 翻倍
train loss 降但 val loss 反弹过拟合weight_decay 从 0.01 提到 0.1；加 dropout；早停
后期 loss 卡住不降lr 没衰减上 cosine / step decay，末期 lr 要降到初始的 1%~0.1%
BatchNorm 模型小 batch 崩BN 统计量不稳batch ≥ 16，或换 GroupNorm / LayerNorm

scaler.unscale_(opt); torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
scaler.step(opt); scaler.update()
为什么大模型训练一定要 warmup？

因为训练初期 Adam 的二阶动量 v 估计极不准（样本极少），m/√v 会给出异常大的步长，一步就把参数推到不可逆的坏区域。warmup 让前几千步用小 lr 把 v 估计稳。另一个原因是 Transformer 初期梯度方差大。经验值：warmup 步数取总步数的 1%~5%，或固定 1000~4000 步。

SGD 和 Adam 到底选哪个？

CV 任务（ResNet、检测、分割）SGD+Momentum 泛化更好，是长期经验结论；NLP / Transformer / 大模型基本只用 AdamW（梯度稀疏、不同层量级差异大，自适应步长收益明显）。强化学习、GAN 也偏 Adam。若追求极致泛化（如刷榜），常见做法是「AdamW 快速收敛 → 最后阶段切 SGD 微调」。

batch size 越大越好吗？

不是。batch 增大意味着每步梯度更准但步数变少，同样 epoch 下总更新次数减少，且大批次容易收敛到尖锐极小值（泛化差）。经验：显存允许下取 32~256 较稳；大批次（>4K）必须配更大的 lr 和 warmup，且监控验证集指标别只看训练 loss。
