API 网关架构模式

系统的统一入口：聚合、路由、鉴权、限流，把通用横切关注点收口到一处。

网关的位置 Gateway

所有外部请求先到网关，再路由到后端服务

网关是<b>客户端与微服务之间的唯一入口</b>，承担：路由转发、身份认证、限流熔断、请求聚合、协议转换、日志审计。客户端不再直连几十个服务。

网关 vs 反向代理

Nginx 可作网关的底层，但网关是更高层的概念

注意点

  • 别把业务逻辑塞进网关——网关应『薄』，重逻辑下沉服务。
  • 网关是单点，需高可用+横向扩展。
  • 聚合过多接口会让网关变慢，谨慎使用『API 聚合』。

面试高频问答

Q：为什么需要网关而不是让前端直连各服务？
A：直连会让前端耦合大量服务地址、各自做鉴权限流，重复且难治理；网关统一收口后，前端只面对一个入口，安全与流量策略集中可控。
Q：网关会不会成为性能瓶颈？
A：会。所以网关要无状态、可水平扩展，且只做轻量横切（路由/鉴权/限流），重逻辑交给后端；高并发下常配合多级缓存。
