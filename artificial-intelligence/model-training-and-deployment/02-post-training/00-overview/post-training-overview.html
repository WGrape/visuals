大模型工程化 · 后训练全景

大模型后训练
Post-training 到底是什么

预训练让模型"会说话"，但它只会续写最可能的文本，不会按你的要求做事。 后训练就是在预训练模型的基础上做二次加工，把它从"通才续写机"变成"听话、对齐、能推理的助手"。 下面用一张全景图讲清它包含哪四类方法，以及每类方法各自在解决什么问题。

第 1 步 · 定义

什么是后训练？

一句话：预训练之后、上线之前，所有为了让模型"更好用"而做的训练，统称后训练（Post-training）。 它的输入是一个只会续写的基座模型（Base Model），输出是一个能听懂指令、符合偏好、能推理的对话模型（Instruct / Chat Model）。

预训练在做的事
在数万亿 token 的通用文本上学"下一个词是什么"。目标是压缩世界知识，产出一个"什么都知道一点、但不听指挥"的基座模型。
后训练在做的事
在十万到千万量级的高质量、有结构的数据上学"该怎么回答"。目标是改变行为与偏好，把能力导向用户真正想要的形式。
图 1：预训练负责"有知识"，后训练负责"会使用"——两者是上下游关系，不是替代关系
关键认知：后训练几乎不增加模型的知识上限，它改变的是"调用已有知识的方式"。所以如果你要模型记住公司内部的大量新事实，靠后训练硬灌往往不如检索增强（RAG）可靠——这点后面在 CPT 那篇会详细展开。
第 2 步 · 动机

为什么光有预训练不够？

因为预训练的目标函数是"让下一个 token 的概率最大"，而不是"给用户一个有用的回答"。这两个目标并不一致。

① 不听话
你问"帮我总结这段话"，它可能接着续写"帮我总结这段话的方法有以下三种……"——把指令当文本续写。
② 不安全
互联网文本里什么都有。基座模型会平静地续写出有害、违法或错误的内容，因为它只是在模仿语料分布。
③ 不好用
不会拒绝、不会追问、不按格式输出、不会分步骤推理。这些"使用体验"没有任何一项是预训练能教会的。

同一个问题的两种回答

输入：用一句话解释什么是梯度下降

基座模型可能输出

"用一句话解释什么是梯度下降 用一句话解释什么是梯度下降是什么意思 这句话怎么翻译……"

→ 它把输入当成"一段要续写的文本"，而不是"一条要执行的指令"

后训练之后

"梯度下降就是沿着损失函数下降最快的方向，一小步一小步地调整参数，直到损失降到最低。"

→ 学会了"指令 = 任务"这个约定，并按人类期望的形式作答

第 3 步 · 全景

后训练的四大方法

工程上最常被提到的就是下面四种。它们不是"选一个用"，而是按顺序叠加、各管一段：越往下，介入越深、越贴近"人类想要什么"。

图 2：后训练四大方法——CPT 改知识面、SFT 改行为、DPO 改偏好、RL 改策略
01 · CPT 继续预训练 →

在领域语料上继续做"预测下一个词"。适合：法律/医疗/金融等专业领域，或需要吸收大量企业内部文档。
02 · SFT 监督微调 →

用高质量的"指令—回答"示范教模型怎么答。几乎所有对话模型的第一道后训练工序。
03 · DPO 直接偏好优化 →

只给"哪个回答更好"，不用奖励模型也不用 PPO。工程上比 RLHF 简单得多，是目前最主流的人工偏好对齐手段。
04 · RL 强化学习 →

用奖励信号直接优化策略。RLHF 用人类偏好训练奖励模型；近年的 RLVR / GRPO 用"答案对不对"做奖励，专门练推理。
第 4 步 · 流水线

它们是怎么串起来的？

真实工程里，这四步是一条流水线，而不是四个并列选项。CPT 是可选的"补知识"前置步骤；SFT 是必经的"会做事"；DPO / RL 是后面的"调偏好"。规模越大的厂商越可能全做，规模小的团队通常只做 SFT + DPO。

图 3：典型后训练流水线——CPT 可选，SFT 必经，DPO/RL 用来做最后的偏好对齐
别把顺序搞反：CPT 是"继续预训练"，不是"提前微调"。它用的数据和目标函数都与预训练一致（自监督的下一词预测），所以它放在 SFT 之前。如果先做 SFT 再做 CPT，SFT 辛苦教出来的对话格式会被下一词预测冲刷掉。

怎么选：三个判断问题

① 缺的是知识还是行为？
缺知识 → CPT 或 RAG；缺行为 → SFT。这一条能过滤掉一半的错误选型。
② 有"标准答案"吗？
有标准答案 → SFT 直接学；只有"哪个更好" → DPO / RLHF。
③ 能自动判对错吗？
数学、代码这类可验证任务 → RLVR（用对错做奖励），效果比 DPO 更强。
成本递增顺序：SFT < DPO < CPT < RL（含奖励模型）。小团队的最优起手式几乎都是：先 SFT，再看效果决定要不要 DPO，CPT 与 RL 只在明确有需求时再上。
第 6 步 · 一句话

小结速记

后训练 = 预训练之后的"再教育"。它不负责让模型"知道更多"，而负责让模型把已经知道的，按人类想要的方式说出来。

四句话记住四种方法：

CPT 补知识（继续预测下一个词）→ SFT 教格式（模仿标准答案）→ DPO 调偏好（拉大好坏的差距）→ RL 练策略（用奖励逼出更强的推理）。

工程顺序基本固定：CPT（可选）→ SFT（必须）→ DPO 或 RL（按需）。跳过 SFT 直接做偏好对齐，几乎一定失败——因为模型还不具备"按指令作答"这个基本能力。

后训练方法速查：数据、目标、成本

预训练给的是「会接话」的基座，后训练给的是「会听话」的助手。四类方法的差别在需要什么数据和要不要额外训练一个奖励模型。

方法需要的数据训练目标额外开销典型规模
SFT 监督微调(指令, 好回答) 对最大化标准回答的似然（普通 CE）无1 万~100 万条，2~3 轮
RM 奖励模型(指令, 好回答, 差回答) 三元组学好/差排序（pairwise loss）多训一个模型10 万~100 万对比对
RLHF / PPO指令 + RM 打分最大化 RM 分数 + KL 惩罚约束不跑偏同时驻留 4 个模型（actor/critic/RM/ref）1 万~10 万 prompt
DPO同 RM 的偏好对直接用偏好对优化策略，隐式建模奖励只需 policy + ref 两个模型同 RM 数据量
GRPO（DeepSeek）可规则验证的任务（数学/代码）组内相对优势，不要 critic 网络省掉 value model适合推理类
RLAIF用模型代替人标注偏好同 DPO/PPO，只是标注来源换成 AI省人工标注成本降到 1/10

显存估算与训练命令

# 显存账（以 7B 为例，BF16）
#   SFT:  参数 14GB + 梯度 14GB + 主权重 28GB + Adam 56GB ≈ 112 GB
#   DPO:  需要在显存里同时放 policy 和 ref
#         ref 不训练只需前向：14GB（参数）+ 激活
#         总计 ≈ 112 + 20 ≈ 132 GB
#   PPO:  actor(112) + critic(112, 通常与 actor 同规模) + RM(14) + ref(14)
#         ≈ 250 GB+   -> 这就是为什么小团队用不起 PPO

# LLaMA-Factory 一键训练（最常见的一行命令）
llamafactory-cli train \
  --stage sft --model_name_or_path meta-llama/Llama-3-8B \
  --dataset alpaca_en --template llama3 \
  --finetuning_type lora --lora_rank 8 --lora_alpha 16 \
  --per_device_train_batch_size 4 --gradient_accumulation_steps 4 \
  --learning_rate 1e-4 --num_train_epochs 3 --bf16

# 切到 DPO 只需改两处
llamafactory-cli train \
  --stage dpo --pref_beta 0.1 \
  --dataset dpo_en --finetuning_type lora ...

# TRL 的 DPOTrainer（HuggingFace 生态）
from trl import DPOTrainer
trainer = DPOTrainer(model, ref_model, beta=0.1,
                     train_dataset=pref_ds,   # 含 prompt/chosen/rejected
                     args=TrainingArguments(learning_rate=5e-7, ...))

LoRA 是后训练的默认选择：rank 常取 8~64（越大容量越大、越接近全参微调），alpha 常取 rank 的 2 倍，target modules 一般覆盖所有线性层（q,k,v,o,gate,up,down）。7B 模型 LoRA 训练显存可降到 24GB 以内，单张 4090 就能跑，这是后训练能普及的关键。

回复变短/变长数据分布偏移检查 SFT 数据的长度分布，做长度均衡
评测涨但人觉得差过拟合到评测集（如 MT-Bench）用 held-out 集 + 人工盲评
  • 数据质量 > 数据数量：LIMA 论文用 1000 条精选数据就达到了不错的效果，而百万条爬取的指令数据反而更差。实践优先级：去重 → 人工/模型打分过滤 → 难度分层 → 多样性采样。
  • 模板必须一致：训练时的 prompt 模板（如 <|im_start|>user ...）必须和推理时逐字符相同，不一致会让效果直接归零。这是 SFT 最常见的翻车点。
  • loss mask：只对回答部分算 loss，prompt 部分 mask 掉（train_on_prompt=False）。多轮对话尤其重要，否则模型会去学「用户会说什么」。
  • 先 SFT 后对齐的顺序不能颠倒：直接在 base 模型上做 DPO/PPO 效果很差，因为模型根本不会按指令格式输出。
DPO 为什么能取代 PPO？

核心洞察是最优策略有闭式解：给定奖励函数，RLHF 的最优策略可以解析地写成 π*(y|x) ∝ π_ref(y|x)·exp(r(x,y)/β)。把这个关系反解出 r，再代回偏好模型（Bradley-Terry），就能把「训练 RM + RL 采样」两步合成一步监督学习。省掉了 RM 训练和 RL 采样循环，显存和工程复杂度都降一个量级，效果通常与 PPO 接近或更好。

什么时候必须用 PPO 而不是 DPO？

① 奖励信号无法写成偏好对（如代码要跑单元测试、数学要判对错）——这时需要在线采样，GRPO/PPO 更合适；② 需要在线探索的任务（DPO 只在固定的离线数据上优化）；③ 奖励是多步/过程性的（过程奖励 PRM）。反过来说，偏好数据充足且质量高时，DPO 性价比最高。

后训练需要多少数据才够？

看目标：格式对齐（让模型会按 JSON/特定格式输出）几百到几千条就够；能力对齐（提升某领域表现）需要 1 万~10 万条高质量数据；价值观/安全性对齐需要覆盖各类风险场景，量不大但覆盖面要全。经验：先用 1000 条跑通全流程看效果曲线，再决定是否加量，盲目堆数据不如清洗数据。
