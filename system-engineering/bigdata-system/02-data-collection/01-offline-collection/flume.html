核心模型

Flume 的最小部署单元是 Agent，每个 Agent 由三部分串联：

  • Source：接收数据（如 tail 日志、Avro 端口、Kafka）。
  • Channel：源与目的地之间的缓冲队列（Memory / File）。
  • Sink：把数据写到下一跳（HDFS、Kafka、另一个 Agent）。

为什么需要 Channel

Channel 把“生产速度”和“消费速度”解耦。Source 突然涌入大量日志时，Sink 可以按其节奏慢慢写，避免压垮下游。File Channel 还能在 Agent 重启后不丢数据。

可靠性

Channel 类型优点缺点
Memory吞吐高宕机可能丢数据
File持久化、可恢复吞吐较低

Flume vs Logstash

Flume 偏向“把日志搬进 Hadoop 生态”（HDFS/Kafka），Logstash 偏向“采集 + 丰富转换 + 进 ES”。两者也可组合：Flume 负责搬运，Logstash 负责清洗。

🎯 面试问答

Q：Flume 如何保证至少一次（at-least-once）？
A：事务化的 Source→Channel 与 Channel→Sink 提交，失败回滚重放；因此可能重复但不易丢。
Q：多 Agent 怎么级联？
A：用 Avro Sink + Avro Source 把多个 Agent 汇聚到收集层，形成分层采集拓扑。
