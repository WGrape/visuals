🚀 进阶：过滤/协处理/索引

Filter、Coprocessor、二级索引与事务

过滤器 Filter

在服务端过滤数据，减少返回 Client 的数据量（比「全拉回来再筛」高效得多）。可单独用，也可用 FilterList 组合多个。

过滤器作用
RowFilter按 rowkey 比较（=、前缀、范围等）
FamilyFilter / QualifierFilter按列族 / 列限定符过滤
ValueFilter按值过滤（慎用，需扫描）
PrefixFilter按 rowkey 前缀匹配（常见且高效）
PageFilter返回前 N 行，做分页
SingleColumnValueFilter按某列的值过滤整行
Scan scan = new Scan();
scan.setFilter(new PrefixFilter(Bytes.toBytes("user_001")));  // 只扫 user_001 前缀

协处理器 Coprocessor

类似「数据库里的存储过程/触发器」，把计算下推到 RS 执行，避免把数据拉到 Client 算。

👁️

Observer

钩子式：在特定事件（put/delete/get/compact 等）前后插入逻辑，类似触发器——常用于权限校验、审计、二级索引维护。

⚙️

Endpoint

RPC 式：在 Region 上执行自定义计算并聚合结果——常用于行数统计、求和、去重等聚合（避免全表拉回）。

二级索引

HBase 没有原生二级索引，必须自己建。常见方案：

方案原理权衡
Phoenix 全局索引建独立索引表，写时由 Phoenix 自动双写/协处理器维护查询最方便(SQL)，写入有额外开销
Phoenix 本地索引索引数据与原表同 Region 存放读快、写稍轻，但与主表共 Region
自建索引表应用层或协处理器维护「被查字段→rowkey」的映射表灵活但要自己保证一致性

事务与原子操作

  • HBase 只有行级原子，没有跨行 ACID 事务。
  • 单行的原子/条件操作：checkAndPut（满足条件才写）、increment、append、checkAndMutate。
  • 需要跨行一致：用应用层两阶段、或 Phoenix 提供的有限事务（基于 MVCC + 冲突检测）。
✅ 二级索引的本质：用额外空间换查询维度。维护索引会增加写入成本，所以只对真正高频、且无法用 rowkey 前缀表达的非主键查询建索引。
