梯度累积与激活检查点：训练显存如何换算

用全局批量和一次前后向传播，分清显存节省、计算增加与优化器更新语义。

先分清四类训练显存

训练显存通常包括模型参数、梯度、优化器状态和前向传播保存的激活。减小 microbatch 主要减少激活内存，不能让完整参数和优化器状态自动消失。梯度累积则在多个 microbatch 上逐次计算梯度，暂不更新参数，等累积完成后才执行一次优化器 step。激活检查点进一步只保留部分中间结果，反向传播时重算其余激活，用更多计算换较少显存。

设数据并行进程数为 D，每进程 microbatch 为 B，累积步数为 K，则不考虑最后不满批的情况时全局 batch = D×B×K。例如 D=8、B=4、K=2，全局 batch 是 64。若目标是对 64 个样本求平均梯度，常见做法是每个 microbatch 的 loss 按累积步数缩放，并在同步时按数据并行组正确归约。具体框架对平均和求和的默认行为不同，必须查看实现。

逐步推演

确定目标 batch

按数据并行进程数、microbatch 和累积步数计算 D×B×K。

累积梯度

每个 microbatch 做前后向，但暂不更新参数，注意 loss 权重。

同步并更新

在正确时机归约、反缩放、裁剪并执行一次优化器 step。

测量取舍

比较峰值显存、吞吐、通信等待和更新后的梯度范数。

一次训练更新的时间线

每个进程先清空梯度，依次处理两个 microbatch：前向、计算缩放后的 loss、反向把梯度累到同一参数缓冲。第二个 microbatch 完成后，进行必要的跨卡梯度归约、梯度裁剪和优化器更新，再清空梯度开始下一轮。若每个 microbatch 都调用优化器 step，学习率调度和权重都会提前变化，已不等价于同一全局 batch。若最后一轮只有部分样本，固定除以 K 也可能导致梯度缩小，应按实际样本权重处理。

手段主要节省主要代价
减小 microbatch单次激活显存设备利用率可能下降
梯度累积在小 microbatch 下获得大有效 batch更多次前后向；更新次数减少
激活检查点中间激活显存反向时重算，训练变慢
ZeRO/参数分片参数、梯度或优化器冗余通信和实现复杂度增加

与混合精度、裁剪和同步的交互

使用动态 loss scaling 时，梯度在裁剪前需要按框架要求反缩放；否则裁剪阈值针对的是放大的数值。数据并行训练若每个 microbatch 都做一次 all-reduce，通信开销可能大幅增加；一些框架支持累积期间延迟同步，到更新前才归约。延迟同步不能改变数学上要聚合的样本和权重，否则实际全局 batch 与预期不符。

梯度累积与一次性大 batch 也不总严格相同。BatchNorm 的统计依单个 microbatch，dropout 使用随机掩码，数值加法顺序会造成浮点差异；变长序列若按“每批平均 token loss”再简单平均，还可能让短批与长批权重相同。要明确优化目标是按样本平均还是按有效 token 平均，并记录实际 token 数。

如何判断值得换显存

  1. 先测峰值显存发生在前向、反向还是优化器 step；不同峰值对应不同手段。
  2. 记录 tokens/s、训练 step 时间、GPU 利用率和通信等待。显存下降若吞吐大幅下降，可能不划算。
  3. 用固定随机种子和一小段数据检查累积前后 loss、梯度范数及参数更新是否接近预期。
  4. 把学习率调度按优化器更新次数或处理过的 token 数定义清楚，不要在每个 microbatch 意外前进一步。

练习：4 卡、每卡 microbatch=2、累积 8 次，全局 batch 是多少？若某卡最后只得到一半有效样本，仍简单除以 8 是否保持按样本平均？请说明需要记录哪些计数。

显存账本如何帮助选手段

先用 profiler 区分峰值来自激活、参数、梯度还是优化器状态。若峰值主要是激活，减 microbatch 或启用激活检查点通常更有针对性；若参数与优化器状态占绝大部分，单纯增加累积步数不会让副本消失，应考虑状态分片、参数精度或模型并行。估算时还要给通信缓冲、临时算子工作区和内存碎片留余量，不能把设备标称显存全部当成可用预算。

验证数学等价时，取一个小模型和固定样本，比较“一个大 batch 一次更新”与“多个 microbatch 累积一次更新”的参数差异，并分开统计 dropout、归一化和浮点加法顺序造成的变化。若差异远超预期，先检查 loss 缩放、梯度清零、同步时机和学习率调度，而不是直接归因于随机性。

自检

梯度累积能节省参数和 Adam 优化器状态的完整副本吗？

通常不能。它主要允许减小单次 microbatch 激活；参数和优化器状态需靠分片、量化等其他手段处理。

检查点重算为什么会让训练变慢？

反向传播时需要重新运行部分前向计算来恢复未保存的激活。
