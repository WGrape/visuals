精确 LRU

双向链表 + 哈希表：访问移首、淘汰尾，读写 O(1)。实现清晰但每个对象需额外指针。

近似 LRU / 时钟算法

给每个缓存项一个访问位，时钟指针轮询：访问位置 1，淘汰时遇到 0 则淘汰、遇到 1 清 0 继续。近似 LRU，省去链表移动开销。

Redis 的 LRU

Redis 不维护完整 LRU 链表，而是随机采样 N 个 key 淘汰最久未用的，用少量采样近似效果，换取内存与 CPU 效率。

🎯 面试问答

Q：为什么用近似 LRU？
A：精确 LRU 维护链表开销大，近似足够好且省内存。
Q：Redis LRU 采样数在哪设？
A：maxmemory-samples，越大越接近精确 LRU。
Q：时钟算法优点？
A：无需移动链表，O(1) 且内存小。
