GPU 虚拟化与设备直通

为什么 GPU 比 CPU 难虚拟化：API 拦截、vGPU、SR-IOV 与 MIG

CPU 虚拟化有 VT-x/EPT，GPU 却难得多：数万条图形 API、显存与上下文状态庞大。这一页讲清 API 拦截、设备直通、SR-IOV/MIG 三条路。

一、为什么 GPU 比 CPU 难虚拟化

GPU 暴露的是庞大的驱动/API 面（CUDA、图形栈），不是干净的指令集；显存巨大、上下文切换重；而且很多工作负载要求近裸金属性能。

二、三条路径

🔀

API 拦截/半虚拟化

vGPU、GPU-PV：Hypervisor 截取 API 调用做调度与切分，兼容性好、可超卖，但有虚拟化开销。

🔌

设备直通 Passthrough

PCIe passthrough（VFIO）把整张卡直接给 VM，性能近裸金属，但一张卡只能给一个 VM。

✂️

SR-IOV / MIG 切分

把一张物理 GPU 切成多个独立实例（SR-IOV 虚拟功能 / NVIDIA MIG 切片），多 VM 共享且隔离。

方式隔离性能密度
API 拦截/vGPU软件级中（~90%+）高（可超卖）
Passthrough物理级近裸金属低（1:1）
SR-IOV/MIG硬件级高中（按切片）

概念与判定

  • 选哪种看需求：要最强单 VM 性能用 passthrough；要多租户高密度用 vGPU/SR-IOV/MIG；能接受开销换灵活优先 vGPU。
  • 容器场景：K8s 里常用 device-plugin + 时间片/切分，比 VM 直通更轻。

参数·命令·量化

  • NVIDIA MIG 可把 A100 切成最多 7 个实例，各带独立显存与算力配额。
  • Passthrough 需主板/CPU 支持 IOMMU（Intel VT-d / AMD-Vi）与 vfio-pci 绑定。
  • vGPU 性能通常达裸金属 90%~98%，但受帧调度与编码影响。

排障与边界

  • 直通设备争用：同一 PCIe 设备被多 VM 抢会导致绑定失败，需确认 ACS/隔离。
  • 显存超卖：vGPU 超卖后某 VM 爆显存会拖垮邻居，按配额硬限。

原理与取舍

  • 软件切分 vs 硬件切分：软件（vGPU）灵活可超卖但开销大；硬件（MIG/SR-IOV）隔离强、开销小但粒度固定。
  • GPU 虚拟化 ≠ CPU 虚拟化：没有等价 EPT 的"显存二级地址转换"通用方案，故更依赖 API 层或硬件切片。
