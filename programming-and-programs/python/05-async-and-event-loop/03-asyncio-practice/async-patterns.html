异步模式与常见坑

会用 async/await 只是第一步。异步上下文管理器、异步迭代器、同步阻塞代码污染事件循环、忘了 await——这些才是异步项目里真正的「坑王」。这篇帮你把异步写稳。

异步上下文

async with：异步资源的安全开关

需要「异步地」开/关资源（数据库连接、HTTP 会话、文件）时，用 async with。它调用对象的 __aenter__ / __aexit__（注意是 a 前缀，和同步的 __enter__ 不同）。

class Conn:
    async def __aenter__(self):
        await self.connect(); return self
    async def __aexit__(self, *exc):
        await self.close()

async with Conn() as c:    # 进/出都走异步
    await c.query()
同步的 with 调用的是 __enter__/__exit__；异步对象若实现的是 __aenter__，必须用 async with，混用会直接报错。
异步迭代

async for 与异步生成器

async for 遍历「异步迭代器」（有 __aiter__ / __anext__）；async def 里用 yield 就是「异步生成器」，适合流式吐数据（如分片读大响应）。

async def fetch_pages():
    for i in range(1, 4):
        await asyncio.sleep(0.1)
        yield i                 # 异步生成器

async for page in fetch_pages():   # 每条都 await 取
    print(page)

这和同步生成器是同一套心智模型（见迭代器与生成器），只是「产出」的过程本身也能 await。它天然适配「边等网络边吐数据」的流式场景。

阻塞污染

一个 time.sleep 卡死整个事件循环

事件循环是单线程，协程只在 await 点让出。若在协程里调了同步阻塞函数（time.sleep、重 CPU 计算、同步 requests.get），循环在这期间没法切走，所有并发任务全卡住。

async def bad():
    time.sleep(3)        # 同步阻塞！整个循环冻结 3 秒

async def good():
    await asyncio.sleep(3)  # 正确：挂起，循环去跑别的

# CPU 密集 / 同步库：丢进线程池，别占循环
async def offload():
    r = await asyncio.to_thread(sync_cpu_task)  # 3.9+
    # 或 loop.run_in_executor(ThreadPoolExecutor(), f)
⚠️ 用 asyncio.to_thread（3.9+）或 run_in_executor 把阻塞调用挪到别的线程，循环才能继续调度其它协程。这是异步性能的第一红线。
忘了 await

调用协程却没 await = 什么都没发生

协程函数不加 await 调用，返回的是个「没被执行的协程对象」，不会报错但逻辑完全没跑。这是最隐蔽也最高频的 bug。

async def save():
    await db.write()

save()            # ❌ 返回 coroutine，啥也没存
await save()       # ✅ 真正执行

# 运行时告警：coroutine 'save' was never awaited
⚠️ 在 async 函数里调别的 async 函数，必须 await；在普通函数里要并发跑，得用 asyncio.run / create_task。类型检查器（mypy + 异步插件）能提前抓出这类遗漏。
实战

并发抓取：aiohttp + gather

异步最经典的场景就是高并发网络 I/O。用 aiohttp 的异步会话，配合 gather 并发几十上百个请求，吞吐远超同步 requests。

import aiohttp, asyncio

async def fetch(session, url):
    async with session.get(url) as resp:
        return await resp.text()

async def main():
    async with aiohttp.ClientSession() as s:
        tasks = [fetch(s, u) for u in urls]
        htmls = await asyncio.gather(*tasks)
    return htmls

把本篇和任务与并发连起来：gather 编排并发、async with 管会话生命周期、to_thread 兜住阻塞、别忘了 await。选型上它对应并发选型里的「高并发网络用协程」。

① 扇出汇聚 + ② 限流（最常用组合）

扇出 + 信号量限流

import asyncio, aiohttp

# 扇出：并发抓取 1000 个 URL，但限制同时只有 50 个在跑
async def fetch_all(urls, concurrency=50):
    sem = asyncio.Semaphore(concurrency)
    timeout = aiohttp.ClientTimeout(total=10, connect=3)

    async def one(session, url):
        async with sem:                        # 进入前获取信号量
            try:
                async with session.get(url, timeout=timeout) as r:
                    return url, r.status, await r.text()
            except Exception as e:
                return url, 0, str(e)          # 失败不中断整体

    connector = aiohttp.TCPConnector(limit=concurrency, limit_per_host=10)
    async with aiohttp.ClientSession(connector=connector) as s:
        return await asyncio.gather(*[one(s, u) for u in urls])

# 为什么并发 50？——经验值推导：
#   目标 QPS = 并发数 / 单请求耗时
#   单请求 200ms，想达到 250 QPS -> 并发 = 250 * 0.2 = 50
# 调太大：打挂下游 / 本机 fd 耗尽；调太小：吞吐上不去

两个限流层次别搞混：Semaphore 限制的是同时进行的请求数；TCPConnector(limit=) 限制的是连接池大小（复用连接）。两者通常设成相同值，前者防打挂下游，后者防本机资源耗尽。

③ 竞速 + ④ 超时兜底

竞速、兜底与熔断

# 竞速：同时问三个镜像源，谁先返回用谁
async def fastest(urls):
    tasks = {asyncio.create_task(fetch(u)): u for u in urls}
    done, pending = await asyncio.wait(
        tasks.keys(), return_when=asyncio.FIRST_COMPLETED)
    for t in pending: t.cancel()          # 关键：取消落败的
    return done.pop().result()

# 超时兜底：拿不到就用缓存/默认值，绝不无限等
async def get_with_fallback(key, default=None):
    try:
        return await asyncio.wait_for(remote_get(key), timeout=0.2)  # 200ms
    except asyncio.TimeoutError:
        return default if default is not None else local_cache.get(key)

# 熔断：连续失败 N 次后直接短路（不发出请求）
class CircuitBreaker:
    def __init__(self, threshold=5, reset_after=30):
        self.fails = 0; self.threshold = threshold
        self.reset_after = reset_after; self.opened_at = None
    async def call(self, fn, *a):
        if self.opened_at and time.time() - self.opened_at < self.reset_after:
            raise Exception("circuit open")     # 快速失败
        try:
            r = await fn(*a); self.fails = 0; return r
        except Exception:
            self.fails += 1
            if self.fails >= self.threshold: self.opened_at = time.time()
            raise

队列与定期任务

# 生产者-消费者：用 Queue 解耦（背压天然存在）
async def crawler():
    q = asyncio.Queue(maxsize=1000)          # 有界队列 = 背压，防止内存爆炸

    async def producer():
        for url in get_seeds():
            await q.put(url)                 # 队列满时自动等待
        for _ in range(WORKERS): await q.put(None)   # 毒丸：通知消费者结束

    async def consumer(i):
        while True:
            url = await q.get()
            if url is None: break
            await process(url)
            q.task_done()

    await asyncio.gather(producer(), *[consumer(i) for i in range(WORKERS)])

# 定期任务：注意用 sleep 而不是忙等，且要能取消
async def heartbeat(interval=30):
    while True:
        try:
            await send_heartbeat()
        except Exception as e:
            log.error("heartbeat failed: %s", e)
        await asyncio.sleep(interval)        # 不要用 time.sleep！

# 更精确的做法：补偿执行耗时，避免漂移
async def periodic(interval):
    while True:
        t0 = asyncio.get_running_loop().time()
        await job()
        elapsed = asyncio.get_running_loop().time() - t0
        await asyncio.sleep(max(0, interval - elapsed))   # 减去执行时间

# 压测用 locust 或自己写
import asyncio, aiohttp, time
async def bench(url, total=10000, concurrency=200):
    sem = asyncio.Semaphore(concurrency)
    ok = fail = 0
    async def one(s):
        nonlocal ok, fail
        async with sem:
            try:
                async with s.get(url) as r:
                    await r.read()
                    if r.status == 200: ok += 1
                    else: fail += 1
            except Exception: fail += 1
    conn = aiohttp.TCPConnector(limit=concurrency)
    t0 = time.time()
    async with aiohttp.ClientSession(connector=conn) as s:
        await asyncio.gather(*[one(s) for _ in range(total)])
    dt = time.time() - t0
    print(f"QPS={total/dt:.0f}  成功={ok} 失败={fail}")

深入自检

Semaphore 和连接池的 limit 冲突吗？

不冲突，但会互相叠加。若 Semaphore(50) 而 TCPConnector(limit=10)，实际并发只有 10（连接池成了瓶颈）。建议两者设成相同值，或者理解清楚：limit 是总连接数，limit_per_host 是单域名连接数（防止把所有连接都打给同一个 host）。抓多个域名时 limit_per_host 要设小一些。

asyncio.Queue 的 maxsize 该设多大？

原则：让它成为背压阀门，而不是无底洞。经验值 maxsize = 消费者数 × 10 ~ 100。设 0（无限）会导致生产远快于消费时内存暴涨；设太小（如 1）会让生产者频繁阻塞，吞吐下降。关键是要有监控：q.qsize() 持续接近 maxsize 说明消费者是瓶颈，该扩容了。

怎么优雅关闭 asyncio 服务？

三步：① 捕获 SIGTERM，设置一个 stop_event；② 停止接收新请求，给在途请求一个 grace period（通常 10 – 30 s）；③ cancel() 所有任务，然后 await gather(*tasks, return_exceptions=True) 等待清理逻辑跑完。最后一点最容易漏——直接退出会让 finally 里的清理代码来不及执行。

异步代码怎么测试？

用 pytest-asyncio：给测试加 @pytest.mark.asyncio。三个技巧：① 用 asyncio.sleep 而非 time.sleep，测试会快很多；② 需要测超时/取消时用 asyncio.wait_for 包一层；③ 时间相关的逻辑注入一个 clock 接口，测试时替换成假时钟（而不是真等 30 秒）。另外 unittest.IsolatedAsyncioTestCase 是标准库自带的方案，无需额外依赖。
