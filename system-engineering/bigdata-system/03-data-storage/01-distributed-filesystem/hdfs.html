HDFS 分布式文件系统

大数据存储底座：分块、副本与高吞吐

副本

默认 3 份

架构

NameNode 管理命名空间与块映射（元数据），DataNode 真正存数据块。Client 写数据先问 NameNode 块放哪，再直接连 DataNode 写。

分块与副本

文件被切成固定大小的数据块（默认 128MB），每个块默认存 3 个副本分布在不同节点，既容错又支持并行读取。

写流程（管线写）

Client 向 NameNode 申请块位置，拿到一组 DataNode，数据以流水线方式依次写入各副本，全部确认后 NameNode 记录元数据。

高可用

单 NameNode 有单点风险，生产用 HA（主备 + 共享存储/JournalNode）；超大规模可用 Federation 把元数据分片。

🎯 面试问答

Q：为什么块这么大（128MB）？
A：减少元数据量、降低寻址开销、利于顺序大文件吞吐；太小会增加 NameNode 压力。
Q：副本放哪？
A：跨机架策略：一个本地、一个同机架另一节点、一个不同机架，兼顾带宽与容灾。
Q：HDFS 适合存小文件吗？
A：不适合，海量小文件会撑爆 NameNode 内存，应合并或用 HBase/对象存储。
