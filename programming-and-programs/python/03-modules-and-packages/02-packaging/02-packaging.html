Python 打包与发布

从 setup.py 到 pyproject.toml：构建 wheel 并发布到 PyPI

pyprojectwheelPyPIuv

一句话：把零散的 .py 变成可被 pip install 的包，现代做法是 pyproject.toml + 构建后端（hatchling/setuptools），再用 uv 或 twine 发布到 PyPI。

包结构

mypkg/
  pyproject.toml
  src/
    mypkg/
      __init__.py
      core.py

推荐 src 布局：测试导入的是“已安装”的包，避免误用工作区里的源码。

pyproject.toml：一个文件管全部

段作用
[build-system]声明构建后端（hatchling/setuptools）
[project]名称、版本、依赖、入口点
[tool.xxx]各工具配置（ruff/pytest/hatch）

已取代旧的 setup.py + setup.cfg + requirements.txt 三件套，成为事实标准（PEP 517/518/621）。

构建与发布

  • 构建：python -m build 产出 *.whl（wheel）与 *.tar.gz（sdist）。
  • 发布：twine upload dist/*，或新晋 uv publish。
  • 依赖：uv 或 poetry 做可复现锁文件，告别手工 requirements。

概念与判定

  • wheel vs sdist：wheel 是预编译/可直接装的二进制包；sdist 是源码，安装时要现场构建。
  • 何时发包：代码要被别人 import 或做成命令行工具时；内部脚本用 venv 即可不必发包。

参数·命令·量化

  • 版本号遵循 PEP 440：1.2.3、1.2.3rc1、2.0.0a1。
  • python -m build 同时产出 wheel + sdist。
  • 入口点：[project.scripts] mycli = "mypkg.cli:main" 生成可执行命令。

排障与边界

  • ImportError / 循环依赖：src 布局 + 绝对导入通常能规避；出现循环就拆模块或延迟导入。
  • 装了却 import 不到：确认 packages 配置含该包，且用可编辑安装 pip install -e . 调试。

原理与取舍

工具特点
setuptools老牌、兼容最好
hatchling现代、零配置友好
poetry依赖+打包+发布一体
uv极快，含 publish
