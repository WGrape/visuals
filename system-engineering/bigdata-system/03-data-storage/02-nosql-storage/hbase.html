数据模型

表由行键（RowKey）+ 列族 + 列 + 时间戳定位一个单元格。列族是物理存储单位，同一列族的数据存在一起；列可以动态增删，所以表是“稀疏”的。

架构

表按行键范围切成 Region 分布到多个 RegionServer；底层数据持久化在 HDFS 上。HMaster 负责调度与故障转移。

行键设计

设计原因
高位散列避免写入热点集中
有序字段靠后兼顾范围扫描
长度适中减少存储与寻址开销
行键是 HBase 唯一索引，所有查询都从行键开始，设计好坏直接决定性能。

与关系型对比

关系型适合事务与复杂 Join；HBase 适合海量单行/范围读写、写多读少的场景（如时序、画像）。

🎯 面试问答

Q：HBase 为什么写很快？
A：写入先进内存 MemStore 并写 WAL（HLog），LSM 树批量刷盘，把随机写变成顺序写。
Q：Region 过大怎么办？
A：Region 达到阈值会自动 分裂（Split）成两个，由 HMaster 重新分配。
