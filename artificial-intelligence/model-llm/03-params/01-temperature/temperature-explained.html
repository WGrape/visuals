Temperature 温度：控制随机性的总开关

同一个模型，为什么有时回答一板一眼、有时天马行空？温度是所有采样参数里最核心的一个。

定位

温度是加在 softmax 之前的"锐化旋钮"

模型每一步输出的是整个词表上的概率分布。温度（Temperature）在 softmax 之前把 logits 除以 T：分布不变时，T 决定了"选词时的犹豫程度"——T 越小分布越尖（确定性），T 越大分布越平（多样性）。

公式

一行公式说清楚

P(token_i) = exp(logit_i / T) / Σ_j exp(logit_j / T)

T → 0⁺ : 分布趋于 one-hot，等价贪心解码（argmax）
T = 1  : 原始 softmax 分布，模型"本色"
T > 1  : 低概率词被抬升，长尾被放大，输出更发散
直觉：logits 差距是固定的，除以 T 就是"把差距缩小或放大"。T=0.5 把差距放大一倍，弱者更难翻身；T=2 把差距减半，冷门词也有机会。

误区

两个高频误区

T=0 并不保证完全确定：GPU 浮点非结合性、batch 内并行、MoE 路由抖动都会带来微小数值差异，T=0 时这些差异会被 argmax 放大成不同的输出。想要更稳，可固定 seed 并关掉部分并发优化。
温度不是"创造力"旋钮：T 太高输出的是胡言乱语（采样到不通顺词），不是创意。创意来自模型本身的能力 + 好提示词，温度只是放大或收敛分布。
面试问答

高频问题

Q1：温度的数学本质是什么？
softmax 前 logits 除以 T。T<1 放大 logits 差距使分布更尖（趋近 argmax），T>1 缩小差距使分布更平（更随机）。它不改变候选集合，只改变分布形状。
Q2：T=0 和贪心解码是什么关系？
T→0 时 softmax 退化为 one-hot，采样等价于 argmax，即贪心解码。但注意浮点数值抖动可能让 T=0 也不完全可复现。
Q3：温度和 top-p 冲突吗？先调哪个？
不冲突，作用维度不同：截断（top-k/top-p）决定候选范围，温度决定范围内的随机度。官方建议避免同时大幅调整；实践中常见组合是固定 top-p=0.9，按任务调温度。
Q4：为什么代码任务建议低温度？
代码的正确答案空间小、语法约束强，低概率候选几乎都是错的；低温让输出集中在高置信度 token 上，提高语法与逻辑正确率。
Q5：温度越高模型越聪明吗？
不是。温度不改变模型能力，只改变采样随机性；过高反而放大错误、破坏语法。能力由模型与提示决定，温度只影响"从分布里怎么挑"。

Temperature 到底改了什么

模型每一步输出的不是「一个词」，而是词表上几万到几十万个候选的概率分布。Temperature 做的事只有一件：在采样之前把这个分布捏尖或捏平。它不引入新的随机性，随机性本来就来自「按概率抽样」这一步；它决定的是抽样时各候选之间的差距有多大。

公式很朴素 —— 把 logits 除以 T 再过 softmax：

原始： p_i = exp(z_i) / Σ_j exp(z_j) 加 T： p_i = exp(z_i / T) / Σ_j exp(z_j / T) 两个候选的比值： p_i / p_j = exp((z_i - z_j) / T) T=1 → exp(z_i - z_j) 原样 T=0.5 → exp(2(z_i - z_j)) 差距放大 T=2 → exp(0.5(z_i - z_j)) 差距缩小

所以 T 越小，差距被放大，分布越尖；T 越大，差距被压缩，分布越平。T 趋于 0 时只剩最大的那个 token（等价于贪婪）；T 趋于无穷时所有候选几乎等概率。

温度越低越集中、越高越发散；注意横条高度差（差距）的变化

几条必须刻在脑子里的性质

不改变排序除以同一个正数再过 softmax 是单调变换，原本排第一的词依然排第一。T 影响的是「第二名有多大机会被抽到」。
不等于确定性T=0.1 只是让长尾概率极小，偶尔仍会抽到冷门词。要真正稳定必须配合贪婪解码或 seed（若 API 支持）。
不是创造力旋钮T 提高的是不确定性，不是灵感。写诗时高 T 带来的「意外」通常是语病而不是佳句。
作用于每一步生成是逐 token 的，每个 token 都会重新采样一次。长文本里高 T 的偏差会逐步放大。

典型取值怎么定：

和其它参数谁先谁后

很多人的直觉是「T 和 top_p 互相独立」，实际上它们在一次采样的流水线里是按固定顺序生效的，理解顺序才能预判效果。

① logits（模型算出的原始分数） ↓ ② ÷ temperature ← 先整形 ↓ ③ 截断：top_p / top_k ← 再裁掉长尾 ↓ ④ 惩罚：repetition / frequency / presence ↓ ⑤ 重新归一化，按概率抽样

由此得到两条实用结论：

  • 先整形再截断，所以两者会叠加。T=1.5 已经把分布压得比较平，此时再设 top_p=0.95，候选集会非常大；反过来 T=0.3 时分布极尖，即使 top_p=1 也几乎只抽得到第一名。
  • 通常只动一个。业内常见做法是二选一：绝大多数 API 文档都写着「建议修改 temperature 或 top_p 之一，不要同时改」。同时调整会让效果难以复现与回归。

深入自检

温度 0 就等于「正确答案」吗？

不等于。T→0 只是把采样变成近似贪婪：每一步都取当前概率最高的 token。但模型对这些概率的判断本身可能就是错的，贪婪解码照样会一本正经地一路错到底，而且因为没有随机性，它连「换个说法试试」的机会都没有。它提升的是可复现性，不是正确性。

为什么同一个 prompt、同一个 T，两次结果还是不一样？

因为采样本身是随机的：即便第一名有 80% 概率，仍有 20% 抽到别的。想压掉这一点，要么把 T 调到 0 走贪婪路径，要么在支持 seed 参数的服务上固定随机种子（通常还需要同时固定服务端版本与批处理，才有机会复现）。注意很多商用 API 并不保证严格可复现。

高 T 一定导致「幻觉」吗？

不是因果，但是强相关。幻觉的本质是模型在不确定时仍给出了确定答案；高 T 会放大低概率分支被采到的机会，于是不确定的地方更容易「编出」内容。缓解办法不是一味降温，而是：给足上下文（RAG）、要求标注不确定、用结构化输出限制自由度、把事实判断拆成提取而非生成。

调 T 时要不要同时改 top_p？

默认不要。先固定一个（比如把 top_p 保持默认 1 或 0.95），单独扫 T，找到可接受的区间；只有在 T 达标但仍有明显长尾噪声时，才小幅收紧 top_p。每次只动一个参数才有 regression baseline。
