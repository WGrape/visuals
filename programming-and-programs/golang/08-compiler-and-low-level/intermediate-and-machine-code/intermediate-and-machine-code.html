SSA 中间表示

每个变量只赋值一次

SSA 形式下每个变量只被定义一次，极大方便数据流分析（如常量传播、死代码消除）。Go 的编译器大量基于此。

// 普通: x = 1; x = 2
// SSA:  x1 = 1; x2 = 2   (x 被拆成不同版本)
中端优化

函数内联是重头戏

包括逃逸分析（配合栈分配）、函数内联、边界检查消除、常量折叠等。内联能把小函数展开、消除调用开销。

内联有阈值控制；太激进会膨胀代码。go build -gcflags=-m 能看哪些函数被内联、哪些逃逸。
Lowering 到机器码

适配目标架构

优化后的 SSA 被 lowering 成目标架构的指令（amd64/arm64…），再做寄存器分配、指令选择、调度。

// 伪: SSA 的 Add 节点
// amd64 lowering -> ADDQ 指令
// arm64 lowering -> ADD 指令
生成目标文件

链接前的产物

最终产出 .o 目标文件（含机器码、符号表、重定位信息），交给链接器拼成可执行文件或归档。

⚠️ Go 默认静态链接，生成的二进制自带 runtime 与依赖，部署简单但体积偏大；可用 -ldflags 裁剪。
