DHCP DORA、租约续期与中继：电脑怎样拿到网络配置

沿新电脑接入办公网的过程理解广播、地址池、网关、DNS、续租与跨网段 DHCP Relay。

开机时主机缺少什么

一台新电脑接入以太网后，需要知道自己的 IP 地址、子网掩码或前缀、默认网关、DNS 服务器等配置，才能正常访问其他网络。DHCP 让服务端从地址池临时分配这些信息，并规定租约期限。DHCP 是应用层协议，IPv4 常通过 UDP 67/68 端口传输；初始客户端还没有可用地址，因此发现阶段常使用广播。网卡链路已连接，只证明二层有信号，尚不代表三层配置正确。

自动地址配置的目标是避免手工给每台设备填 IP，但服务端地址池、保留地址、网关和 DNS 仍需管理员规划。若给两个终端分配了同一地址或错误网关，DHCP 消息看似“成功”，业务却可能间歇失败。

箭头表示本例中的处理次序；每个环节的状态都要分别验证，不能由前一环节成功推断后一环节成功。

DORA 四步时间线

客户端发 DHCPDISCOVER 寻找服务端；服务器返回 DHCPOFFER 提议地址和配置；客户端发 DHCPREQUEST 表示接受哪个提议；服务器发 DHCPACK 确认租约。可把 DORA 记成“发现、报价、请求、确认”，但别误以为每一步都必然只出现一个包：可能有多个服务器报价、重传或中继转发。客户端要用事务标识等信息把应答与自己的请求对应起来。

若收到 DHCPNAK，说明租约请求被拒绝，客户端应重新开始配置；若收到错误网段地址，要检查接入 VLAN、DHCP Relay 与地址池选择。抓包时看客户端 MAC、事务 ID、请求地址、服务器标识和返回选项，不能只数四个包就宣布正确。

逐步推演

Discover

无地址客户端广播寻找 DHCP 服务。

Offer

服务端提出地址、网关、DNS 和租期。

Request

客户端声明接受哪个报价。

ACK 与续租

租约生效，在到期前按 T1/T2 尝试续期。

租约不是永久拥有

租约带有有效期，客户端通常会在有效期内尝试续租。常见 T1、T2 时点分别引导向原服务器单播续租和更广泛的重新绑定；实际时间可由服务端提供或按协议默认规则计算。若第一次续租失败，地址并不会立刻在 T1 失效；客户端可继续尝试直到租约到期。到期仍未续上时，继续使用旧地址可能造成冲突，系统应停止把它当作有效配置。

服务端重启或切换后，客户端可能仍持有有效租约。排障要记录租约开始、到期、T1/T2、服务器标识及实际续租响应。简单重启网卡有时让问题消失，却也抹掉了原始续租失败的证据。

DHCP Relay 为什么需要

DHCP 初始发现常是本地广播，普通路由器不会把它无条件广播到别的网段。大型网络可在每个 VLAN 网关设置 DHCP Relay，把客户端请求转发给集中 DHCP 服务器，并标明请求来自哪个网段，便于服务端选择相应地址池。服务端的回复再经中继送回客户端。若某 VLAN 独独拿不到地址，先检查该 VLAN 的中继配置、到服务器的路由和地址池容量。

中继处理不等同于把广播原样泛洪到整个企业网络。服务端可以根据网关或中继提供的信息决定租约范围；具体选项也可能携带更细的接入信息。错误中继可能给终端发到其他子网的地址，进而导致能上网的设备与不能上网的设备混在一起。

地址冲突与安全边界

非授权 DHCP 服务器可能抢先向客户端报价，给出恶意 DNS 或网关，让流量误入其他路径。交换机可在合适网络中配置 DHCP Snooping 等机制限制可信服务器端口，但要正确标记中继与上联，否则会误封合法回复。客户端拿到地址后也可做冲突检测；仅依赖服务端“地址池没有重复”不足以防御静态地址碰撞。

DNS 和默认网关是最值得核对的选项。拿到正确 IP 但错误 DNS，会表现为能 ping IP 不能访问域名；拿到正确 DNS 但网关错误，可能只能访问同一子网。按问题形态分别测试局域网、网关、外部 IP 和域名，可以快速定位配置项。

一次完整验收

从全新或释放租约的终端开始，抓取 DORA 四类消息，核对分配地址落在预期 VLAN 子网、网关可达、DNS 可查询。缩短测试租约观察 T1/T2 续租，但不要把测试值直接用于生产。跨 VLAN 时再核对 Relay 的请求来源标识与地址池选择。最后拔掉 DHCP 服务器模拟续租失败，观察客户端在租约到期前后的状态。

生产监控除了地址池剩余量，还要看 OFFER 后未 ACK 的比例、NAK、续租失败和异常服务器报价。池子用尽不是唯一故障；中继路由、防火墙和错误选项都会让“自动获取 IP”失败。

DORA 四步与端口

步骤报文源 → 目的地址要点
1DHCPDISCOVER客户端 → 广播0.0.0.0:68 → 255.255.255.255:67客户端还没有 IP，只能广播
2DHCPOFFER服务器 → 广播/单播服务器:67 → :68提供一个候选 IP 与租期
3DHCPREQUEST客户端 → 广播:68 → :67广播是为了告知其它服务器“我选了谁”
4DHCPACK服务器 → 客户端:67 → :68正式确认，附带全部配置选项
时间点占比行为
T1（续租）租期的 50%向原服务器单播 DHCPREQUEST 续租
T2（重绑定）租期的 87.5%原服务器无响应则广播找任意服务器
租期到期100%停止使用该 IP，重新走 DISCOVER

举例：租期 86400 s（1 天）→ 12 小时后（T1）开始续租，21 小时后（T2）广播重绑。客户端重启后通常直接发 REQUEST 请求沿用之前的 IP（init-reboot 状态），服务器确认即可，无需完整 DORA。

DHCP 排查

# 抓 DHCP 报文
tcpdump -i any -nn -vvv 'udp port 67 or udp port 68'

# Linux 手动释放/续租
sudo dhclient -r eth0        # 释放
sudo dhclient -v eth0        # 重新获取（-v 能看到 DORA 全过程）
cat /var/lib/dhcp/dhclient.leases     # 看已获得租约与选项

# systemd 环境
networkctl status eth0
resolvectl status            # 看 DHCP 下发的 DNS

# macOS
sudo ipconfig set en0 DHCP
ipconfig getpacket en0       # 看服务器下发的完整选项
ipconfig getoption en0 router

Option名称说明

6DNS ServerDNS 服务器列表

53DHCP Message Type1=Discover 2=Offer 3=Request 5=Ack 6=Nak
54Server Identifier服务器标识，客户端据此选服务器
82Relay Agent Information中继代理信息（含 circuit-id / remote-id，用于精确分配）
121Classless Static Route无类静态路由

中继（Relay Agent）：DHCP 靠广播，跨网段就不通了。中继代理（通常在三层交换机或路由器上）监听广播，把请求单播转发到指定 DHCP 服务器，并填入 giaddr（中继接口 IP）——服务器据此判断该从哪个地址池分配。回复也经中继转回客户端。

  • 跨网段必须配中继：ip helper-address 10.0.0.1（Cisco）或 dhcrelay（Linux）。忘配则客户端永远拿不到 IP。
  • Option 82：中继插入电路/远程 ID，让服务器能按交换机端口精确分配 IP 和策略；也常用于防私接 DHCP 服务器。
  • IP 冲突：服务器分配前应先发 ICMP Echo 探测（部分实现）；客户端拿到后会发免费 ARP（Gratuitous ARP）检测冲突，冲突则发 DHCPDECLINE 重新申请。
  • DHCP Snooping：交换机上只允许信任端口发 DHCP 服务器响应，防止内网私接 DHCP 服务器做中间人攻击。
  • 排障顺序：客户端发得出 Discover 吗（抓包）→ 服务器收到了吗（giaddr 对不对）→ 有地址池可用吗（是否耗尽）→ Offer 能回到客户端吗（中继/防火墙）→ 客户端接受了吗（REQUEST/ACK）。
为什么客户端拿到 169.254.x.x？

这是 APIPA / link-local 地址，说明 DHCP 全程失败后客户端自己随机挑了一个。排查方向：链路、VLAN、中继、地址池是否耗尽。Windows 上叫“自动专用 IP 寻址”。

DHCP 服务器在另一个网段，客户端为什么拿不到？

广播无法跨三层。需要在客户端所在网段的网关上配置 DHCP 中继（ip helper-address），并确保服务器上有对应 giaddr 网段的地址池。

自检

终端拿到了 IP，却只能访问同子网，最先应核对什么？

核对子网掩码和默认网关是否正确且可达，再看网关后的路由与访问策略。
