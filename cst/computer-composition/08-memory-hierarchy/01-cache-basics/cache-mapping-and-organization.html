Cache 的组织方式：直接映射、组相联与地址怎么切

「缓存命中」听起来像魔法，其实是一次地址切分 + 并行比较。为什么 32KB 8 路缓存的 index 是 6 位？为什么步长刚好等于缓存大小会全部冲突？算一遍就都清楚了。

一句话定位：用地址的一部分当地址簿目录

缓存把内存按固定大小的「行」（通常 64 字节）搬运。为了快速查找，用地址中间的几位当「组号」直接定位到某个组，再在组内并行比较 tag——这就是「组相联」。组内只有 1 路叫直接映射，只有 1 组叫全相联。

行大小64 字节最常见（也是伪共享的粒度）
直接映射1 路，硬件最省，冲突最多
组相联常见 4/8/12/16 路，折中方案
全相联只有 TLB、小 cache 用，比较器太多
地址三段：tag 用于确认，index 用于定位，offset 用于取字节

把位数算出来（考试与面试高频）

组数 = 容量 ÷ (行大小 × 路数)　　index 位数 = log₂(组数)　　offset 位数 = log₂(行大小)
容量 / 路数 / 行大小组数index 位offset 位tag 位（32 位地址）
32KB / 8 路 / 64B646620
32KB / 4 路 / 64B1287619

256KB / 8 路 / 64B5129617

tag 的比较是并行的

组内 8 路意味着 8 个 tag 比较器同时工作——这就是「8 路」的成本。路数越多，命中率越高，但比较与选择电路的延迟也越大，所以 L1 常用 8 路，L2/L3 用 12~16 路。

冲突 miss 是怎么发生的

两个内存块如果 index 相同、tag 不同，就会争抢同一个组。最经典的例子是「步长 = 缓存大小」的数组访问：每次访问都落在同一组，8 路缓存只能容纳 8 个块，第 9 个就把第一个踢掉，命中率瞬间归零。

访问模式32KB 8 路 64B 缓存的表现原因
顺序遍历 1MB 数组命中率高（空间局部性）相邻行依次载入
步长 64B（每行一个元素）正常每个块只用一次，cold miss 为主
步长 32KB（= 缓存大小）命中率接近 0全部映射到同一组，互相踢
矩阵按列遍历（行优先存储）命中率低跨行跳跃，破坏空间局部性
二维数组分块（tiling）命中率显著提升把工作集缩到缓存容量内

for (j = 0; j < N; j++)
  for (i = 0; i < N; i++)
    sum += a[i][j];        // 每次跨 16KB，缓存行只用 4/64 字节

// 改法一：交换循环顺序（行优先访问）
// 改法二：分块，让一块数据留在缓存里
for (ii = 0; ii < N; ii += 64)
  for (jj = 0; jj < N; jj += 64)
    for (i = ii; i < ii+64; i++)
      for (j = jj; j < jj+64; j++)
        sum += a[i][j];

3C 模型：miss 的三种来源

类型全称能不能消除手段
强制 missCompulsory（cold）不能（第一次访问必然）预取、增大行大小
容量 missCapacity只能缓解分块、减少工作集、换更大缓存
冲突 missConflict能（增加相联度或改数据布局）padding、改变访问步长

诊断方法：把同一程序放到「全相联 + 无限容量」的模拟器里跑，剩下的 miss 就是强制 miss；再用有限全相联跑，多出来的就是容量 miss；真实缓存的差额就是冲突 miss。

原理与取舍：为什么要「组」这个概念

全相联命中率最高，但需要与所有行比较，硬件不可行；直接映射只需一个比较器，但冲突严重。组相联是「用 N 个比较器换 N 路灵活性」的折中——它把「冲突」的概率从「必然」降到了「同组内超过 N 个才发生」。缓存设计的本质，就是在命中率、延迟、面积三者间找平衡点。

为什么行大小是 64 字节而不是更大？

行越大，空间局部性利用越充分，但「一次搬更多无用数据」的浪费也越大，且冲突粒度变粗。64B 是实测折中，也是 DRAM burst 与缓存一致性的自然单位。

L1 为什么分 I-Cache 和 D-Cache？

取指与数据访问的模式完全不同（顺序 vs 随机），分开可以各自优化，也消除了结构冒险（同周期取指又读数据）。

缓存能被人为「预热」吗？

能。把热点数据先读一遍（或显式 prefetch）可以让后续访问命中。但要注意预热本身的开销，以及多核下数据可能在其他核的缓存里。
