NUMA 与大页：运维配置与绑核实战

看拓扑、绑核、透明大页 THP 与标准大页配置

NUMA大页THP绑核运维
拓扑 绑核 THP 大页
NUMA 与大页解决的是「内存离 CPU 有多远」和「地址转换开销」两个问题。这一页给可直接执行的运维命令：看拓扑、绑核、配置透明大页与标准大页。

01先看拓扑

# 每个 NUMA node 有哪些 CPU 和内存
numactl --hardware
# 系统级 NUMA 概览
lscpu | grep -i numa
# 各 node 内存分配/命中统计
numastat

目标：确认进程的内存是否大多落在「本地 node」。跨 node 访问延迟通常是本地的 1.5~2 倍。

02绑核与内存就近

# 让进程只在 node0 的 CPU 上跑，且优先用 node0 内存
numactl --cpunodebind=0 --membind=0 ./app
# 仅绑定 CPU（不限内存位置）
taskset -c 0-7 ./app
# 内存跨 node 时交错分配（降低单 node 压力）
numactl --interleave=all ./app
要点：数据库/缓存这类吃内存带宽的程序，绑核 + 内存就近能把尾延迟明显压下来；但绑死也可能让别的 node 闲置，要先测。

03透明大页 THP

# 查看当前策略（多是 [always] madvise never）
cat /sys/kernel/mm/transparent_hugepage/enabled
# 关闭 THP（MySQL/Redis 官方建议关，避免碎片与停顿）
echo never > /sys/kernel/mm/transparent_hugepage/enabled
# 持久化：写进 /etc/rc.local 或 grub 加 transparent_hugepage=never

THP 对大堆、长生命周期内存（JVM、Redis、MySQL buffer pool）反而容易引起 khugepaged 停顿，生产上通常建议关。

04标准大页配置

# 预留 2048 个 2MB 大页
 sysctl -w vm.nr_hugepages=2048
# 查看大页池
hugeadm --pool-list
# Oracle/PostgreSQL/DPDK 等按文档把共享内存映射到 hugetlbfs
对比透明大页 THP标准大页
是否需改应用否，自动是，需显式映射
典型收益通用、省心减少 TLB miss，延迟更稳
风险碎片/停顿占内存、配置繁琐
问：什么时候该上大页？

当程序的「工作集」很大且 TLB miss 成为瓶颈（如大 buffer pool、JVM 大堆、DPDK）。小内存或短生命周期进程上大页纯属浪费。

第一层 · 概念与判定：NUMA 与大页解决什么

NUMA 是多路服务器内存分节点、本地访问快、跨节点慢的架构；大页（2MB/1GB）减少 TLB miss、降低页表开销。两者都面向大内存、低延迟场景（数据库、DPDK、JVM 大堆）。

你的情况要管不用管
单机多路 + 大内存 DBNUMA 绑核绑内存—
吞吐敏感、TLB miss 高大页—
小内存普通服务OS 默认即可折腾反而降性能
短生命周期批处理默认收益不抵复杂度

NUMA 与大页查看/配置

# 查看 NUMA 拓扑与内存分布
numactl --hardware
numactl --show                      # 当前进程的绑核绑内存

# 预留 1024 个 2MB 大页（共 2GB）
sysctl -w vm.nr_hugepages=1024
grep Huge /proc/meminfo             # HugePages_Total/Free, Hugepagesize

# 透明大页：数据库场景常关，避免碎片抖动
echo never > /sys/kernel/mm/transparent_hugepage/enabled

# 让某进程只用节点 0 的内存与 CPU
numactl --cpubind=0 --membind=0 /usr/bin/mydb

数量级：跨 NUMA 节点访存延迟约为本地的 1.5–2 倍；2MB 大页相比 4KB 小页，TLB 覆盖提升约 512 倍，能显著压低 TLB miss 率。

第三层 · 排障与边界：四个坑

  • 进程跨节点跑：没绑核也没绑内存，OS 调度把线程放到节点1、内存却分配在节点0，访存延迟翻倍
  • 透明大页（THP）抖动：always 模式下后台做规整（khugepaged）造成 CPU 尖刺和时延毛刺，DB 常被建议关
  • 大页预留不足或过多：预留少了应用起不来，预留多了普通内存被锁死、别的应用 OOM
  • 只在启动后改 nr_hugepages：内存已碎片化可能分配不出连续大页，应在开机/低负载时预留

第四层 · 原理与取舍

为什么跨 NUMA 节点访存会明显变慢？

NUMA 下内存控制器按节点分布，访问本地节点内存走直连通道，跨节点要先过 QPI/UPI 互连，延迟和带宽都打折。当线程在节点1、数据在节点0，每次访存都跨互连，延迟约 1.5–2 倍、带宽也降。所以「计算靠近数据」——绑核同时绑内存——是 NUMA 调优的核心。

静态大页和透明大页（THP）怎么取舍？

静态大页（nr_hugepages）是启动时锁定的连续物理页，无运行时开销、稳定，但占用后不能挪作他用、配置不灵活；THP 由内核自动把小页合并成大页，省心，但 khugepaged 规整会带来 CPU 抖动和时延毛刺。数据库/低延迟场景通常选静态大页或关 THP；普通应用可开 THP 图方便。

为什么大页能降低 TLB miss？

TLB 缓存的是「虚拟页→物理页框」的映射，条目有限。4KB 小页时，一个 TLB 条目只覆盖 4KB，大内存工作集要海量条目，频繁 miss 回页表；2MB 大页一条目覆盖 512 倍内存，同样 TLB 能映射大得多的工作集，miss 率骤降、访存更快。
