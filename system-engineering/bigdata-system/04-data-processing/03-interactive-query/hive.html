定位

Hive 让熟悉 SQL 的人也能分析 Hadoop 上的海量数据。它把 HiveQL 编译成底层的 MapReduce / Tez / Spark 作业，屏蔽了分布式计算的细节。

架构

Metastore 存表结构、分区、列类型等元数据（通常放 MySQL）；真正的数据在 HDFS。查询时编译器读元数据生成执行计划。

内部表 vs 外部表

类型删除表时适用
内部表连数据一起删Hive 托管数据
外部表只删元数据数据在外部（如 HDFS 既有文件）

分区与分桶

分区按目录裁剪（如按天），避免全表扫描；分桶按哈希把数据打散到固定桶，利于采样和 Join。

🎯 面试问答

Q：Hive 适合实时查询吗？
A：不适合，早期跑 MR 很慢；交互式低延迟场景用 Presto/Trino 或 Impala。
Q：Hive 和关系型数据库的区别？
A：Hive 延迟高、擅长海量批处理、不支持事务更新（早期），本质是“SQL on Hadoop”而非 OLTP。
