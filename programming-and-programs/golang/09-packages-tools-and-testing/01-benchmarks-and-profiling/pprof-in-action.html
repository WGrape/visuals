基准采 CPU、运行时采堆、常用子命令与排障清单

pprof性能调优Go
类型 CPU HTTP 子命令 火焰图 清单
pprof 内置在标准库，无需第三方依赖。它采集的是『采样』而非全量，所以优先看占比最高的函数。

1有哪些 profile 可采

类型采集方式排查什么
cpugo test -cpuprofile / runtimeCPU 时间花在哪
heap堆分配采样内存分配热点 / 泄漏
goroutine协程栈快照协程泄漏 / 阻塞
block阻塞事件锁 / channel 争用
mutex锁持有采样锁竞争热点
trace执行时间线调度 / GC / 系统调用

2基准测试采集 CPU

# 跑基准并把 CPU profile 落到文件
go test -bench=. -benchmem -cpuprofile=cpu.out

# 进入交互式分析，按累计耗时排序看前 20
go tool pprof cpu.out
(pprof) top20
(pprof) web        # 生成调用图（需 graphviz）
(pprof) list main.doWork
要点：默认采样频率 100Hz（每 10ms 一次）。函数太短或调用太分散时可能采不到，属正常。

3运行时采集 HTTP 服务的堆 / goroutine

import _ "net/http/pprof" // 注册到 /debug/pprof/

func main() {
    go func() { log.Println(http.ListenAndServe("localhost:6060", nil)) }()
    // ... 业务服务
}

# 采集 30s 的堆分配
go tool pprof http://localhost:6060/debug/pprof/heap
# 看当前 goroutine 数量与栈
go tool pprof http://localhost:6060/debug/pprof/goroutine
要点：生产环境不要长期对外暴露 6060；用临时开关或带鉴权的 sidecar。

4最常用的 pprof 子命令

(pprof) top            # 按 flat 排序
(pprof) top -cum      # 按累计（含子调用）排序
(pprof) list 函数名   # 看该函数逐行开销
(pprof) web           # 调用图 SVG（需 graphviz 的 dot）
(pprof) png           # 导出图片
(pprof) peek 函数名   # 谁调用它 / 它调用谁

5火焰图（可视化）

# 直接起本地 Web，自动开火焰图
go tool pprof -http=:8080 cpu.out
  • 横轴是采样占比、纵轴是调用栈深度；越宽的函数越值得优化。
  • 火焰图里『平顶山』（没有子调用的大块）就是热点本身。

6实战排障清单

  • 内存只增不减 → 看 heap 的 inuse_space，定位未释放的对象与引用链。
  • 协程数飙升 → 看 goroutine profile，找 chan receive / semacquire 卡住的栈。
  • CPU 跑满 → cpu profile 的 top -cum，顺调用链往下找到叶子热点。
  • 怀疑锁竞争 → 开 mutex / block profile 对比加锁前后。
