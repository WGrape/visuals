🧩 Region 管理

分裂、合并、均衡、预分区与热点

Region 分裂（Split）

当某个 Region 的大小超过阈值（hbase.hregion.max.filesize，默认约 10GB），HBase 会自动将其一分为二（daughter regions）。

  • 过程：先在原 Region 写一层「引用文件」(reference) 指向父 Region 的 HFile 区间；两个 daughter Region 上线服务；旧父 Region 下线。
  • 引用清理：这些引用文件会在后续 Compaction 时被解析、重写，最终父 Region 数据被真正拆分。
  • 分裂由 RS 自己决定、HMaster 协调元数据，期间短暂有 Region 不可用（秒级）。

Region 合并（Merge）

当大量 Region 都很小（如预分区过细或删除数据后），Region 数量膨胀会带来管理开销（MemStore/文件/调度放大）。可手工合并相邻的小 Region 以减少元数据与开销。

负载均衡

HMaster 内置 Balancer：在 Region 数量不均或 RS 上下线时，把 Region 在 RS 之间迁移，使各 RS 负载尽量均衡。触发时机包括：建表、RS 宕机、定期（默认 5 分钟）。

预分区（Pre-splitting）

建表时通过 SPLITS 指定一组 split keys，让表一开始就分成多个 Region，避免「初期全表单 Region → 写入集中 → 触发连锁分裂 → 抖动/热点」。

# Shell：按 10 个预分区键建表
create 'orders', 'cf', {SPLITS => ['10','20','30','40','50','60','70','80','90']}

热点与解决

根因：rowkey 单调递增（如时间戳、自增 ID 做前缀）会使新写入永远落在最后一个 Region，造成热点。解法在「行键设计」篇：加盐、哈希、反转、打散。

⚠️ 自动分裂虽省心，但突发写入 + 大表时会产生「分裂风暴」：瞬间大量 Region、Compaction 与迁移齐发，集群抖动。生产上常配合预分区把分裂提前做掉。
