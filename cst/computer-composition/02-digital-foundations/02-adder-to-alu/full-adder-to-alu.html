从全加器到 ALU：一位逻辑怎样组成整数运算

沿半加器、全加器和进位链路，理解硬件为何能执行加法、减法与条件标志计算。

一位加法的输入不止两个

半加器只处理两个输入位 A、B：和位为 A 异或 B，进位为 A 与 B。多位整数相加时，低位可能向高位产生进位，所以每一位还需要接收 Cin。全加器有 A、B、Cin 三个输入，输出 Sum 与 Cout。Sum = A ⊕ B ⊕ Cin；Cout 在三个输入中至少有两个为 1 时为 1，可写成 A·B + Cin·(A⊕B)。逻辑表达式说明加法不是神秘指令，而是布尔门的组合。

把多个全加器串起来，低位 Cout 连接到高位 Cin，就得到多位加法器。最简单的涟波进位结构必须等待进位逐位传递，位数增加时关键路径可能变长。更快的进位预测、前缀网络等结构以更多门和布线换较短延迟。不同处理器实现会综合面积、功耗和时序，而非永远使用最复杂的电路。

逐步推演

两位相加

半加器计算 A、B 的和位与进位。

加入进位

全加器接收 Cin，输出 Sum 与 Cout。

串接多位

低位 Cout 进入高位 Cin，形成整数加法。

扩展 ALU

通过补码与操作选择复用算术逻辑，并产生条件标志。

手算 4 位加法

计算 0111 + 0001。从最低位开始：1+1 得到和位 0、进位 1；第二位 1+0+1 再得 0、进位 1；第三位同理；最高位 0+0+1 得 1、进位 0。因此结果为 1000。按无符号数解释是 7+1=8；按 4 位二进制补码解释，0111 为 +7，1000 为 -8，此时产生有符号溢出。相同位模式的数学解释取决于数据类型，电路本身只给出位与标志。

标志如何理解常见误区
Carry最高位向外的进位不等于有符号溢出
Overflow补码结果超出有符号范围不能仅看结果符号
Zero结果所有位为 0与是否有进位无关
Negative结果最高位为 1需结合数据解释

减法为何可以复用加法器

在 n 位补码中，A−B 可按 A+(按位取反 B)+1 计算。硬件可以用控制信号决定是否将 B 与 1 异或，再把最低位 Cin 设为 1，于是同一条加法链可完成加法或减法。比较两个整数也常通过减法后的标志判断大小；无符号比较与有符号比较所用的标志组合不同。不要把“最高位是 1”一概解释成负数，内存中的位串没有自带类型。

ALU 还可以选择按位与、或、异或、移位等结果。控制逻辑根据指令的操作码选择输出，并产生供条件跳转使用的状态标志。真实 CPU 的整数执行单元可能有多条并行路径，不一定是一块单独、统一的“盒子”；全加器链仍是理解基础算术数据通路的有效模型。

验证电路的三类测试

  1. 枚举一位全加器的八种 A、B、Cin 组合，核对 Sum 与 Cout。
  2. 对 4 位无符号加法测 1111+0001，预期结果 0000 且有最高位进位。
  3. 对 4 位补码加法测 0111+0001，预期结果 1000 且有符号溢出。
  4. 对减法测 A−A 是否为零，检查 Zero 标志和借位解释。

练习：为什么 1111+0001 的 Carry=1，但按补码解释的 -1+1=0 并不发生有符号溢出？请分别使用无符号和有符号范围回答。

进位标志与溢出标志的两组对照

对 4 位无符号运算，1111+0001 得到 0000，向第 5 位产生进位，因此 Carry=1；无符号范围只有 0 到 15，16 无法装进 4 位。若同一位串按补码解释，1111 表示 -1，-1+1=0 在 -8 到 +7 范围内，不发生有符号溢出。反过来，0111+0001 得到 1000，没有向外进位，却把 +7+1 编码成 -8，因此 Overflow=1。这两组例子说明两个标志判断的是不同数值解释。

减法也会影响标志。A−B 被实现为 A+~B+1 时，最高位进位和“借位”的对应方式可能受指令集定义影响；汇编里不能只凭电路图猜一个条件跳转的含义，应查具体 ISA 对 carry/borrow 的约定。ALU 产生标志后，控制单元可以执行“若相等则跳转”“若无符号小于则跳转”等条件指令；同一比较结果对有符号与无符号数需使用不同标志组合。

真值表自检

当 A=B=Cin=1，全加器输入总数是 3，二进制表示为 11，因此 Sum=1、Cout=1；当三个输入只有一个为 1，Sum=1、Cout=0。用这两行检查逻辑式，可快速发现把“异或”和“或”混用的错误。

全加器真值表与标志位的完整对照

ABCinSumCout说明
00000无进位输入，和为 0
00100仅进位输入，本位为 0 不再产生进位
010101 个 1，和为 1
01101两个 1：本位 0、进位 1
100101 个 1，和为 1
10101两个 1：本位 0、进位 1
11001两个 1：本位 0、进位 1
11111三个 1：本位 1 且进位 1

由此得：Sum = A ⊕ B ⊕ Cin，Cout = A·B + Cin·(A⊕B)。

标志含义判定式典型用途
CF（进位）无符号数溢出最高位 Cout多精度加法、无符号比较
OF（溢出）有符号数溢出Cin ⊕ Cout（最高位）有符号运算结果是否有效
ZF（零）结果为 0所有结果位取或非条件跳转 beq/bne
SF（符号）最高位为 1结果最高位有符号比较

关键陷阱：同一条 ADD 指令同时产生 CF 与 OF，但无符号比较看 CF、有符号比较看 OF，用错标志会得到相反的分支结果。

进位结构的延迟与面积权衡

结构关键路径（门级）位数依赖面积/布线典型使用
涟波进位 RCAn × 2 级O(n)最省低速、面积受限、教学
组内 CLA（4/8 位）组数 × 常数O(n / 组宽)中等经典 ALU 折中
Kogge-Stone 前缀log2n × 2 级O(log n)最大（布线密集）高性能整数加法器
Brent-Kung 前缀约 2·log2n − 2 级O(log n)比 KS 省布线折中高性能实现
进位选择 CSel约 √n 级O(√n)面积翻倍中等位宽加速

量化对比（64 位）：RCA 关键路径约 64×2 = 128 级门延迟；Kogge-Stone 约 6×2 = 12 级，快一个数量级，但前缀网络带来约 3~4 倍的门数与更密集的长线布线。所以真实处理器常在低位用 CLA、高位用前缀或选择结构混合。

可仿真的 Verilog 实现

门级与 RTL

// 1) 一位全加器
module full_adder(input  a, b, cin,
                  output sum, cout);
  assign sum  = a ^ b ^ cin;
  assign cout = (a & b) | (cin & (a ^ b));
endmodule

// 2) 4 位涟波进位加法器
module rca4(input  [3:0] a, b,
            input        cin,
            output [3:0] sum,
            output       cout);
  wire [3:0] c;
  genvar i;
  generate
    for (i = 0; i < 4; i = i + 1) begin : g
      if (i == 0) full_adder fa(a[0], b[0], cin,     sum[0], c[0]);
      else        full_adder fa(a[i], b[i], c[i-1],  sum[i], c[i]);
    end
  endgenerate
  assign cout = c[3];
endmodule

// 3) 超前进位的 P/G 与组进位
//    P = a ^ b     (propagate)
//    G = a & b     (generate)
//    c1 = G0 | (P0 & c0)
//    c2 = G1 | (P1 & G0) | (P1 & P0 & c0)

ALU 与标志

// 4) 带标志位的简易 ALU（补码减法复用加法器）
module alu32(input  [31:0] a, b,
             input  [2:0]  op,     // 000 add / 001 sub / 010 and / 011 or / 100 slt
             output reg [31:0] y,
             output reg zf, cf, of, sf);
  wire [31:0] bb = (op == 3'b001) ? ~b + 1 : b;   // 减法：取反加一
  wire [32:0] ext = {1'b0, a} + {1'b0, bb};       // 扩一位取真实进位
  wire        cin_msb = (op == 3'b001) ? 1'b1 : 1'b0;
  always @* begin
    case (op)
      3'b000, 3'b001: y = ext[31:0];
      3'b010:         y = a & b;
      3'b011:         y = a | b;
      3'b100:         y = ($signed(a) < $signed(b)) ? 1 : 0;  // SLT 用有符号比较
      default:        y = 32'b0;
    endcase
    cf = (op == 3'b001) ? ~ext[32] : ext[32];     // 减法借位取反才是 CF
    of = (a[31] == bb[31]) && (y[31] != a[31]);   // 同号输入异号结果
    zf = (y == 32'b0);
    sf = y[31];
  end
endmodule

深入自检

半加器能否直接串成多位加法器？

不能。半加器只有 A、B 两个输入，没有 Cin 端口，低位产生的进位无处接入。多位加法必须使用全加器（A、B、Cin → Sum、Cout）。

为什么 OF 不能用最高位 Cout 判定？

最高位 Cout 描述的是无符号溢出（CF）。有符号溢出关心的是“两个同号数相加得到异号结果”，判据是 Cin⊕Cout。例如 4 位补码 0111(7)+0001(1)=1000(−8)：Cout=0 但结果确已溢出，此时 Cin=1、Cout=0，异或为 1 正确报警。

减法为什么能复用加法器？

因为补码体系下 A − B = A + (~B + 1)。硬件只需要一个取反器和把 Cin 置 1，就能用同一套全加器完成减法，代价是多一个多路选择器和一位进位控制。

ALU 的 SLT 为什么还需要加法器？

典型实现是做一次 A − B 再看符号位与溢出：小于 = SF ⊕ OF。直接用比较器也可以，但复用已有加法器更省面积。

把加法器做成 Kogge-Stone 一定能更快吗？

逻辑级数一定更少（O(log n) 对 O(n)），但前缀网络门数与长线布线显著增加，在位数较小（如 ≤16 位）时布线电容可能吃掉逻辑收益。是否更快要看目标工艺下的实际时序报告，而不是只看级数。

自检

半加器为什么不能直接串成完整多位加法器？

高位需要接收低位传来的 Cin，必须使用能处理三个输入的全加器或等价逻辑。

Carry 和 Overflow 是否同一个标志？

不是。Carry 反映无符号进位，Overflow 反映补码有符号结果越界。
