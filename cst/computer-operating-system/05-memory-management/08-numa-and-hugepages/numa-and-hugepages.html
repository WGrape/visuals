01UMA、NUMA 与本地/远程

第一层

概念与判定

多路服务器上，每个 CPU 有自己的本地内存。访问本地内存快，访问别的 CPU 的内存慢——这就是 NUMA（Non-Uniform Memory Access）。

图：双路服务器两个 NUMA node。跨 node 访问要走互连（UPI/Infinity Fabric）。
判据本地远程
延迟~80 ns~120–160 ns（1.4–2×）
带宽满带宽受互连限制
怎么判断numastat -p 看 local_node 占比numa_miss 高说明跨 node
虚拟机里 numa 常常是假的：vNUMA 与物理拓扑不匹配，可能导致 Guest 内「以为本地」实则跨 node。要紧的性能场景要给 VM 绑定正确的 vNUMA 拓扑。

03大页与 TLB

('
第三层

排障与边界

大页：减少 TLB miss 与页表层级

类型大小分配方式特点
普通页4 KB按需页表项多，TLB 易 miss
THP（透明大页）2 MBkhugepaged 自动合并无需改代码；可能造成碎片/延迟抖动
hugetlbfs2 MB / 1 GB预留（vm.nr_hugepages）确定性好，需预先分配

TLB 覆盖对比

4KB 页：一个 2MB 区域需要 512 个页表项；2MB 大页只需 1 个。TLB 只有几百项，大页能把「TLB 能覆盖的内存」放大 512 倍。
  • THP 的抖动：khugepaged 后台合并会占用 CPU，且合并瞬间可能引入毫秒级延迟。延迟敏感服务常设 madvise 模式或关闭 THP。
  • 大页碎片：运行久了物理内存碎片化，无法凑出连续 2MB。看 /proc/buddyinfo，必要时提前预留或重启。
  • 1GB 大页：必须在启动时预留（hugepagesz=1G hugepages=N），运行时无法分配。
',)

04原理与取舍

第四层

原理与取舍

NUMA 与大页解决的是两个不同层次的「距离」问题：NUMA 是物理距离（跨 socket 的延迟），大页是翻译距离（TLB 覆盖不足导致的页表遍历）。

优化收益代价
NUMA 本地绑定延迟降 20–40%失去跨 node 弹性，需容量规划
THPTLB miss 减少，吞吐升延迟抖动、碎片
hugetlbfs确定性最好需预留，运维复杂
内存交错（interleave）带宽最大化单线程延迟变差

深入 Q&A

Q：什么时候该禁用 THP？
A：延迟敏感的数据库/交易系统，THP 合并与拆分会造成不可预测的停顿。改用 hugetlbfs 或 madvise 模式。

Q：NUMA 绑定一定更好吗？
A：不一定。绑死后该 node 内存不够会 OOM，即使另一个 node 还有空。要按峰值容量规划。
