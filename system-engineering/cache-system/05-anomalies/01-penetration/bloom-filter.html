原理

初始化一个位数组（全 0）。写入 key 时经 k 个哈希函数映射到 k 个位置置 1；查询时若任一位置为 0，必定不存在；若全为 1，可能存在（有误判）。

误判与权衡

误判率随位数组大小与哈希个数变化：空间越大、哈希越多，误判越低，但查询越慢。误判只会“说有其实无”，不会“说无其实有”，配合空值缓存兜底。

应用：缓存穿透

在缓存前加布隆过滤器存储“可能存在的 key”，非法 key 直接拦截，保护 DB。

🎯 面试问答

Q：布隆会漏判吗？
A：不会漏判存在性：说无必无。
Q：误判怎么处理？
A：误判的 key 查库返回空，配合空值缓存。
Q：为什么省空间？
A：位数组 + 多哈希，不存原值。
