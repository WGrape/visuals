冒泡排序
Bubble Sort

通过重复遍历数组，比较相邻元素并在必要时交换位置，像气泡一样将最大/最小的元素逐步"冒泡"到序列的一端。

O(n²)
时间复杂度
O(1)
空间复杂度
稳定
排序稳定性
for i in range(n):
    for j in range(n-i-1):
        if arr[j] > arr[j+1]:
            arr[j], arr[j+1] = arr[j+1], arr[j]
🟡
选择排序
Selection Sort

在未排序的部分中找到最小（或最大）元素，将其放到已排序序列的末尾。重复此过程，直到整个数组有序。

O(n²)
时间复杂度
O(1)
空间复杂度
不稳定
排序稳定性
for i in range(n):
    min_idx = i
    for j in range(i+1, n):
        if arr[j] < arr[min_idx]:
            min_idx = j
    arr[i], arr[min_idx] = arr[min_idx], arr[i]
🟢
插入排序
Insertion Sort

将数组分为已排序和未排序两部分，逐一取出未排序元素，在已排序部分中找到合适位置插入，类似整理扑克牌。

O(n²)
时间复杂度
O(1)
空间复杂度
稳定
排序稳定性
for i in range(1, n):
    key = arr[i]
    j = i - 1
    while j >= 0 and arr[j] > key:
        arr[j+1] = arr[j]
        j -= 1
    arr[j+1] = key
🟣
归并排序
Merge Sort

采用分治策略，将数组递归地分成两半分别排序，然后合并两个有序子序列。保证完全排序且稳定。

O(n log n)
时间复杂度
O(n)
空间复杂度
稳定
排序稳定性
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    return merge(left, right)
🩷
快速排序
Quick Sort

选择一个基准元素，将数组分为两部分：小于基准的和大于基准的，然后递归排序两部分。是实际应用中最快的排序算法之一。

O(n log n)
时间复杂度
O(log n)
空间复杂度
不稳定
排序稳定性
def quick_sort(arr, low, high):
    if low < high:
        pi = partition(arr, low, high)
        quick_sort(arr, low, pi-1)
        quick_sort(arr, pi+1, high)

三个必须记住的结论：① 比较排序的时间复杂度下界是 O(n log n)（决策树证明）；② 快排最坏 O(n²)（有序输入 + 首个元素做 pivot），但平均最快（常数小、缓存友好）；③ 归并是唯一稳定且 O(n log n) 最坏保证的通用排序，代价是要 O(n) 额外空间。

import random, time, sys
sys.setrecursionlimit(10000)

def quicksort(a):
    if len(a) <= 1: return a
    p = a[len(a)//2]
    return (quicksort([x for x in a if x < p]) +
            [x for x in a if x == p] +
            quicksort([x for x in a if x > p]))

data = [random.randint(0, 10**6) for _ in range(100000)]
for name, fn in [("快排", quicksort), ("内置sorted(Timsort)", sorted)]:
    a = data[:]
    t = time.perf_counter(); fn(a)
    print(f"{name:22s} {(time.perf_counter()-t)*1000:7.1f} ms")

稳定性：什么时候必须关心

场景为什么需要稳定例子
多关键字排序先按次要键排，再按主键排先按姓名排，再按班级排 → 同班内按姓名有序
保留原有顺序相等元素的相对位置有意义日志按级别排序，同级保持时间顺序
UI 表格排序用户点击列排序时，等值行不该乱跳Excel 式排序

稳定性实战

# 多关键字排序的正确做法（利用稳定性）
students = [("三班","张三",85), ("一班","李四",90), ("三班","王五",85)]

# ① 先按次要键（姓名）排序
students.sort(key=lambda s: s[1])
# ② 再按主键（班级）排序 —— 稳定排序保证同班内姓名仍有序
students.sort(key=lambda s: s[0])
# 结果：一班李四 / 三班王五 / 三班张三  （三班内按姓名：王五 < 张三 ✓）

# 或者一次搞定（用元组作为 key）
students.sort(key=lambda s: (s[0], s[1]))       # 等价且更快

# Python 的 sorted 保证稳定（Timsort）
# 验证：
items = [("a",1), ("b",0), ("a",0), ("b",1)]
print(sorted(items, key=lambda x: x[0]))
# [('a',1), ('a',0), ('b',0), ('b',1)]   <- 相等 key 保持原顺序 ✓

深入自检

为什么工业界用 Timsort 而不是纯快排？

因为真实数据不是随机的。Timsort（Python/Java 对象排序的默认）会检测输入中已有的有序片段（run），然后合并它们——对部分有序的数据（现实中最常见：日志按时间近似有序、增量更新后的列表）能达到接近 O(n)。同时它是稳定的且最坏 O(n log n)。Tim Peters 2002 年为 Python 写的这个算法，后来被 Java 采纳——它代表了“工程实践优于理论最优”的典型。

什么时候用非比较排序（计数/桶/基数）？

当数据范围有限且分布已知时，可以突破 O(n log n) 下界：① 计数排序——数据是小范围整数（如年龄 0-150、成绩 0-100），O(n+k)；② 桶排序——数据均匀分布在某个区间（如 0-1 的浮点数），O(n)；③ 基数排序——固定位数的整数或字符串，O(d×(n+k))。典型场景：1 亿个手机号排序用基数排序（11 位数字）比快排快得多。代价：需要额外空间且对数据类型有要求。

快排的 O(n²) 最坏情况真的会发生吗？

会，而且比你想象的多。三种触发场景：① 输入已排序或近乎有序 + 取首/尾元素做 pivot（这在现实数据中很常见）；② 大量重复元素 + 没有做三路划分（所有元素都进一边）；③ 恶意构造的输入（攻击者可以精心构造让服务端 O(n²) 卡死，这是真实的 DoS 向量）。防护：① 随机化 pivot；② 三数取中；③ 三路划分（< / == / >，Dijkstra 的荷兰国旗法）；④ 用内省排序（递归超深就切堆排，保证最坏 O(n log n)）。

排序的“空间复杂度”到底算不算递归栈？

要看语境。原地（in-place）通常指不需要与 n 成正比的额外空间，所以快排的 O(log n) 递归栈算“原地”（平均情况）；但如果递归退化（最坏 O(n²) 时间），栈也可能是 O(n)。归并排序的 O(n) 辅助数组是确定的，所以不算原地。面试/文档里说“快排空间 O(log n)”指平均递归深度；严格说最坏是 O(n)。工程实现（内省排序）会把递归深度限制在 2×log₂n 以内，从而保证栈空间也是 O(log n)。
