第 15 章 · 贪心

局部选择何时通向最优解

贪心每一步只保留一个选择；真正困难的部分是证明这个选择不会排除全局最优解。

核心速览

贪心选择性质局部最优选择可以纳入某个全局最优解
最优子结构做出选择后，剩余子问题的最优解 + 该选择 = 全局最优
交换论证证明贪心正确的主流方法
反例思维找不到反例不等于正确，需要证明

先建立直觉：贪心是「不后悔」

面对一个多步决策问题，动态规划会把所有可能都算一遍再取最优；贪心则每一步只看眼前，做出当前最好的选择，然后永不回头。

找零钱：要凑 37 元，有 25、10、5、1 四种硬币。贪心做法是「每次取不超过剩余金额的最大面额」：25 → 10 → 1 → 1，共 4 枚，恰好也是最优解。

但换个面额组合，贪心就可能失效——这正是贪心算法的全部难点：它看起来总是对的，但只在特定条件下成立。

成立的两个条件

一个贪心策略能保证得到全局最优解，必须同时满足：

  1. 贪心选择性质（Greedy Choice Property）：可以通过一系列局部最优选择达到全局最优。换句话说，存在一个最优解，它包含了我们这一步的贪心选择。
  2. 最优子结构（Optimal Substructure）：做出贪心选择后，剩余子问题的最优解 + 这一步的选择 = 原问题的最优解。
这两条要分开理解。「最优子结构」是动态规划也要求的性质（所以有最优子结构不代表能用贪心）；真正把贪心和动态规划区分开的是「贪心选择性质」——它断言「不用考虑其他选择，眼前这个就是安全的」。

怎么证明：交换论证

证明贪心正确性最主流的方法是交换论证（Exchange Argument），套路固定：

  1. 任取一个全局最优解 OPT。
  2. 如果 OPT 已经包含我们的贪心选择 → 证明完成。
  3. 否则，把 OPT 中的某个元素替换成我们的贪心选择，得到 OPT′。
  4. 论证 OPT′ 依然可行，且代价不比 OPT 差（不会更差）。
  5. 于是 OPT′ 也是一个最优解，且它包含了贪心选择 → 贪心选择是安全的。
以「活动选择」为例（选最多的互不重叠的区间）：贪心选结束时间最早的活动 a₁。任取最优解 OPT，设它第一个活动是 b。因为 a₁ 结束最早，所以 end(a₁) ≤ end(b)；用 a₁ 替换 b 后，a₁ 结束得更早，不会与 OPT 中剩下的任何活动冲突，且活动数量不变。于是 OPT′ 仍是最优解且包含 a₁ —— 贪心选择安全。
交换论证的核心直觉：「把别人的选择换成我的选择，不会让情况变糟，也不会破坏可行性」。一旦能论证这一点，就可以放心地一步步贪心下去（配合数学归纳法完成整体证明）。

经典可贪心问题

问题贪心策略为什么对
活动选择每次选结束最早的结束越早，留给后续的时间越多
分数背包按单位价值降序取物品可分割，单位价值高的永远更划算
Huffman 编码每次合并频率最小的两棵子树频率低的应该放最深层
Dijkstra 最短路每次取距离最小的未确定节点边权非负，绕道只会更远
Prim / Kruskal 最小生成树每次取最小边切割性质 / 回路性质
零钱兑换（特定面额）每次取最大面额仅当货币体系「规范」时成立

贪心失效的经典反例

问题贪心会错在哪正确做法
0-1 背包（物品不可分割）按单位价值贪心会留下背包空隙，局部最优不等于整体最优动态规划
找零（非规范面额）如面额 {1,3,4}、要凑 6：贪心取 4+1+1 = 3 枚，最优是 3+3 = 2 枚动态规划
最短路径（含负权边）Dijkstra 的贪心前提被破坏，先确定的节点可能被刷新Bellman-Ford
旅行商问题 TSP「每次去最近的未访问城市」会陷入局部最优NP-hard，用 DP 或近似算法
最实用的判别技巧：拿小规模样例手动试，或者问自己「这一步的选择会不会限制后面的选择？」如果会（比如 0-1 背包里选了大件就装不下别的），通常就不能贪心。另一种思路：如果能举出一个反例，立即排除贪心。

贪心 vs 动态规划

维度贪心动态规划
每步做法只保留一个最优候选保留所有候选状态
决策依据只看当前（局部最优）枚举所有转移后取最优
复杂度通常 O(n log n) 甚至 O(n)通常 O(n²) 或 O(n·W)
正确性需要专门证明（交换论证）由状态转移方程天然保证
适用满足贪心选择性质有重叠子问题 + 最优子结构
关系总结：贪心是动态规划的一个特例。当一个问题同时满足「最优子结构」和「贪心选择性质」时，DP 的所有转移里只有一个分支是有效的，于是可以省掉枚举，直接选那一个——这就是贪心。贪心更快，但适用范围窄得多，且必须证明。

🎯 面试问答

Q：贪心算法成立需要哪两个条件？

A：① 贪心选择性质：存在一个全局最优解，它包含我们这一步的局部最优选择（即「眼前这个选择是安全的」）；② 最优子结构：做出选择后，剩余子问题的最优解加上这一步的选择，就是原问题的最优解。注意最优子结构是动态规划也要求的，真正把贪心与 DP 区分开的是第 ① 条。

Q：交换论证（Exchange Argument）是怎么回事？

A：证明贪心正确性的主流方法，套路固定：① 任取一个全局最优解 OPT；② 若 OPT 已包含贪心选择则证毕；③ 否则把 OPT 中的某个元素替换成贪心选择；④ 论证替换后仍然可行且代价不会变差；⑤ 于是得到了一个「包含贪心选择的最优解」，说明贪心选择安全。以活动选择为例：贪心选结束最早的活动 a₁，用它替换 OPT 的第一个活动 b 后，因为 end(a₁) ≤ end(b)，不会与后续活动冲突，数量也不变，所以仍是最优解。

Q：为什么 0-1 背包不能用贪心，而分数背包可以？

A：核心差别是物品能否分割。分数背包里物品可以切开，按单位价值降序取总能把背包装满且单位价值最高，所以贪心最优。0-1 背包里物品是整体的，按单位价值贪心很可能在最后留下装不下任何物品的空隙，导致总价值不是最大——局部最优不等于整体最优。反例：容量 10，物品 A(重 6, 值 12)、B(重 5, 值 9)、C(重 5, 值 9)。贪心按单位价值取 A(2.0) + 剩下 4 装不下 B/C = 12；最优是 B+C = 18。0-1 背包必须用动态规划。

Q：贪心和动态规划是什么关系？

A：贪心是动态规划的特例。两者都要求「最优子结构」，但 DP 会枚举所有转移并保留多个候选，而贪心每步只保留一个候选。当一个问题还满足「贪心选择性质」时，DP 的所有转移分支中其实只有一个是有效的，于是可以省掉枚举直接选它——这就是贪心。所以贪心更快（少枚举），但适用范围窄得多，而且正确性必须单独证明（通常用交换论证）；DP 只要状态转移方程写对，正确性天然成立。

Q：怎么快速判断一个题能不能用贪心？

A：三个实用技巧：① 举反例——先拿小规模样例手动试，能构造出反例就立即排除贪心（最快的方法）；② 问「这一步的选择会不会限制后面的选择」——如果会（如 0-1 背包选了大件就装不下别的），通常不能贪心；③ 尝试交换论证——如果没法论证「把别人的选择换成我的不会变糟」，就说明贪心不成立。记住：找不到反例 ≠ 正确，正式场合必须给出证明。

Q：Dijkstra 算贪心吗？它为什么要求边权非负？

A：算——它每步取「当前距离最小的未确定节点」并永久确定它，是典型的贪心。要求边权非负，是因为这个贪心的正确前提正是：「节点一旦取出，其距离不可能再被刷新」。这个前提只在所有边权 ≥ 0 时成立（任何绕道都要多走非负的边，只会更长）。一旦存在负权边，先取出的节点可能被后续经过负边的路径改短，而它已不会再被更新，结果就错了。含负权边要改用 Bellman-Ford（O(VE)，还能检测负环）。

贪心算法的正确性判据

问题贪心策略正确性
活动选择按结束时间排序，选最早结束的正确（有最优子结构）
分数背包按价值密度排序正确
0-1 背包按价值密度排序错误！必须用 DP
找零（特定面额）每次取最大面额面额规范时正确；非规范面额错误
Huffman 编码每次合并最小的两个正确
最小生成树Kruskal/Prim 取最小边正确（切割性质）
Dijkstra每次取距离最小的点正确（非负权）
区间调度（加权）按权重贪心错误，需 DP
旅行商问题最近邻错误，且无多项式解

贪心成立的两个条件：① 贪心选择性质——局部最优选择能导致全局最优；② 最优子结构——问题的最优解包含子问题的最优解。两个都满足才能用贪心。0-1 背包不满足贪心选择性质（拿高密度物品会占用空间，导致后面放不下更优组合），所以必须 DP。

反例与证明方法

# 反例 1：0-1 背包用贪心会错
# 容量 W=50
# 物品：A(重10, 值60, 密度6)  B(重20, 值100, 密度5)  C(重30, 值120, 密度4)
# 贪心(按密度)：选 A + B = 重30，值160。剩下 20 装不下 C
# 最优：      B + C = 重50，值220    <- 比贪心好 60
# 结论：0-1 背包必须 DP，O(nW)

# 反例 2：找零的非规范面额
# 面额 {1, 3, 4}，要凑 6
# 贪心：4 + 1 + 1 = 3 枚
# 最优：3 + 3     = 2 枚      <- 贪心错
# 人民币 {1,5,10,20,50,100} 是规范面额，贪心正确

# 反例 3：最短路径有负权时 Dijkstra 错
# 因为 Dijkstra 假设「已确定的最短距离不会再被更新」，负权打破了这个假设
# 贪心正确性的两种证明方法

# 方法 1：交换论证（活动选择问题）
# 设最优解 S 的第一个活动是 a_k，贪心选的是 a_1（最早结束）
# 因为 a_1 结束时间 <= a_k 结束时间，把 a_k 换成 a_1 不影响后续活动的可行性
# -> 存在一个最优解包含贪心选择 -> 归纳可得全局最优

# 方法 2：切割性质（最小生成树）
# 对任意切割（把顶点分成两部分的划分），横跨切割的最小权边一定属于某棵 MST
# Kruskal/Prim 每次取的正是这样的边 -> 正确

# 快速判断能不能用贪心的技巧：
# 1) 先想反例（试着构造让「眼前最优」导致全局变差的例子）
# 2) 若能构造出来 -> 贪心不成立，改 DP
# 3) 若构造不出且能说出「为什么局部最优就是全局最优」 -> 大概率可以

排障清单

症状原因处理
贪心结果不是最优问题不满足贪心选择性质改用 DP；或先验证两个条件
0-1 背包用贪心混淆了 0-1 背包和分数背包0-1 背包 O(nW) DP；分数背包才用贪心
有多个贪心策略不知道选哪个排序键不同结果不同每个都试反例；能举出反例的淘汰
边界情况错没处理空输入/相等情况特别注意相等时的稳定性（排序要稳定或显式定义）
区间问题漏解排序后没正确更新当前位置画时间轴验证；注意闭区间/开区间
贪心很慢每次选择都要重新扫描用堆（优先队列）维护候选，O(log n) 取最优

最实用的判断流程：遇到问题先问「能不能举出让贪心失败的反例」。举得出来就用 DP；举不出来且能说清「为什么局部最优不会害了全局」，才用贪心。贪心的代码简单，但正确性的论证才是难点。

没有正确性论证的“总是选最大的”，只是猜测。
