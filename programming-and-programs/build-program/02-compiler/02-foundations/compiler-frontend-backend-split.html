编译器为什么分前后端：IR 与三段结构

从 N×M 到 N+M 的拆分动机、三段职责划分、IR 的三种形态与 SSA，以及 Pass 流水线

编译器IR前端后端LLVMSSA
① 为什么分段 ② 三段职责 ③ IR 形态 ④ Pass ⑤ 疑问
一句话总结：编译器分成前端、中端、后端三段，根本原因是把「N 种语言 × M 种目标」变成「N + M」。实现这个拆分的关键是 IR（中间表示）——前端只管把语言翻译成 IR，后端只管把 IR 翻译成机器码，优化器在 IR 上做一次即可复用到所有组合。

01为什么要分段：从 N×M 到 N+M

分段让编译器数量从乘法变成加法，IR 是关键中间层

如果没有 IR，每种语言要为每种 CPU 写一套完整编译器。有了 IR：

  • 新语言：只写前端（把语言翻译成 IR），自动获得所有后端和优化。
  • 新 CPU：只写后端（把 IR 翻译成机器码），自动支持所有语言。
  • 新优化：在 IR 上写一次，所有语言 × 所有目标都受益。
要点：LLVM 是这个思路最成功的实践：Clang（C/C++）、Rust、Swift 的前端各不相同，但都产出 LLVM IR，共享同一套中端优化和后端。

02三段各自负责什么

段输入 → 输出核心工作与目标机器有关吗
前端源码 → AST → IR词法分析、语法分析、语义检查、类型检查、报错定位无关
中端IR → IR（优化后）常量传播、死代码消除、内联、循环优化无关
后端IR → 目标机器码指令选择、寄存器分配、指令调度、目标相关优化完全相关
  • 前端负责「程序写对了没有」：语法错误、类型错误、未定义符号都在这里报，并且要给出准确的行列位置。
  • 中端负责「让程序跑得更快」：与目标无关，所以可以做得很通用、很激进。
  • 后端负责「落到具体 CPU」：寄存器有多少、指令集长什么样、流水线怎么排。
要点：判断一个编译器问题属于哪一段：报错信息不对 → 前端；性能不及预期 → 中端/后端；在某款 CPU 上崩 → 后端。

03IR 长什么样：三种形态

形态例子特点用途
树形 / AST语法树最接近源码，保留结构前端内部，语义分析
三地址码 / 线性 IRt1 = a + b; t2 = t1 * c接近机器但仍是抽象的指令序列便于做数据流分析
SSA 形式LLVM IR每个变量只赋值一次，配 φ 节点处理分支合并现代编译器的主流选择，极大简化优化
; LLVM IR 示例：一眼能看出它的特点
define i32 @add_mul(i32 %a, i32 %b, i32 %c) {
entry:
  %t1 = add nsw i32 %a, %b        ; 三地址码：一个操作，一个结果
  %t2 = mul nsw i32 %t1, %c
  ret i32 %t2
}

; SSA 的核心约束：每个虚拟寄存器只被赋值一次
;   %t1 = ... 出现第二次就是非法的，必须改名（%t1.1 %t1.2）
; 好处：定义与使用是一一对应的，做数据流分析不用考虑"这个变量现在是什么值"

; 分支合并用 phi 节点表示
define i32 @max(i32 %a, i32 %b) {
entry:
  %cmp = icmp sgt i32 %a, %b
  br i1 %cmp, label %then, label %else
then:
  br label %merge
else:
  br label %merge
merge:
  %m = phi i32 [ %a, %then ], [ %b, %else ]    ; 从哪条边来就取哪个值
  ret i32 %m
}
要点：SSA 看似麻烦（要插入 φ 节点），但它把「变量在某个点的值是什么」变成了静态可查的事实，这是绝大多数优化能高效实现的前提。

04Pass：优化是怎么组织的

每个优化是一个独立的 Pass（一遍扫描 + 变换），编译器把很多 Pass 串成流水线。这种结构让优化可以自由组合、按需开关（对应 -O0/-O1/-O2/-O3）。

类别代表 Pass做什么
简化类常量传播、常量折叠、死代码消除把能算的先算掉，删掉没用的
内联类函数内联把调用展开，为后续优化创造机会
循环类循环不变量外提、循环展开、向量化减少循环开销、利用 SIMD
内存类公共子表达式消除、别名分析避免重复计算、判断能否重排访存
后端类指令选择、寄存器分配、指令调度落地到具体 CPU
# 看 LLVM 的优化过程（直观理解 Pass 流水线）
clang -O2 -S -emit-llvm demo.c -o demo.ll       # 产出 IR
opt -O2 -S demo.ll -o demo_opt.ll               # 只跑中端优化
llc -O2 demo_opt.ll -o demo.s                   # 后端：IR → 汇编

# 看某个 Pass 单独的效果
opt -passes='inline' -S demo.ll -o after_inline.ll
opt -passes='instcombine' -S demo.ll -o after_ic.ll

# 看优化报告（为什么没内联/没向量化）
clang -O2 -Rpass=inline -Rpass-missed=inline demo.c
要点：调试「优化后行为变了」这类问题的标准手法：逐级降低优化等级（-O2 → -O1 → -O0）定位是哪一级引入的，再用 -Rpass 系列看编译器做了什么决定。

05常见疑问

问：为什么我的代码开了 -O2 行为就变了？

绝大多数情况是源码里有未定义行为（数组越界、有符号溢出、使用未初始化值），优化器基于「未定义行为不会发生」的假设做变换，于是行为就变了。先修未定义行为，而不是关掉优化。

问：IR 和字节码是一回事吗？

不是。IR 是编译期的中间表示（如 LLVM IR），编译完就没了；字节码是运行期的分发格式（如 Java bytecode、Python bytecode），要被虚拟机执行。两者的设计约束完全不同。

问：写一个新语言要自己写后端吗？

通常不用。产出 LLVM IR 就能复用它的后端与优化，这样你只需要专注前端（语法、类型系统、语义）。这也是 Rust/Swift 等语言的做法。

问：前端和后端哪个更难？

难点不同：前端难在语言设计与语义正确性（类型系统、报错体验）；后端难在工程深度（寄存器分配、指令调度、目标相关的细节非常多）。中端优化则是两者之间的算法密集区。
