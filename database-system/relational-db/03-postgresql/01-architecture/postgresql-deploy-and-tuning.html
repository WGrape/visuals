01连接与访问控制

# 改监听（postgresql.conf）
listen_addresses = '0.0.0.0'
port = 5432

# 改访问控制（pg_hba.conf），最小开放
# 本地信任、应用网段 md5
local   all   all                 trust
host    appdb  appuser  10.0.1.0/24   md5
# 改完 reload
sudo -u postgres pg_ctl reload

02关键参数（按内存量级调）

参数常见值控制什么
shared_buffers物理内存 25%共享缓冲，缓存数据页
effective_cache_size物理内存 50~75%优化器估算的系统缓存
work_mem16~64MB/算子排序/哈希内存，过大会 OOM
max_connections100~500最大连接数，配连接池可压低
wal_buffers16MBWAL 写入缓冲
checkpoint_timeout5~15min检查点频率，影响写抖动
要点：max_connections 别盲目开到几千：每个连接都占内存。正解是前面架 pgbouncer，应用连池子，PG 只保持少量真实连接。

03慢查询与膨胀排查

膨胀大就 VACUUM（或 autovacuum 没跟上时手动 VACUUM FULL，但会锁表，挑低峰做）。

-- 1) 找慢 SQL：先开 auto_explain 或手动 EXPLAIN ANALYZE
EXPLAIN ANALYZE SELECT * FROM orders WHERE user_id=123;

-- 2) 看锁等待
SELECT pid, usename, state, wait_event_type, query
FROM pg_stat_activity WHERE wait_event_type='Lock';

-- 3) 看表/索引膨胀（粗略）
SELECT schemaname, relname, n_dead_tup, n_live_tup
FROM pg_stat_user_tables ORDER BY n_dead_tup DESC LIMIT 10;

04备份与基础运维

  • 物理备份：pg_basebackup 做基础备份 + WAL 归档做 PITR。
  • 逻辑备份：pg_dump 单库/单表，便于跨版本迁移。
  • 监控：pg_stat_statements 统计最耗时 SQL（需提前 CREATE EXTENSION）。
问：为什么改了参数没生效？

很多参数是 `postmaster` 级，要重启；`sighup` 级只需 reload；`user`/`superuser` 级可在会话内 SET。改前先看 `pg_settings.context`，别白等 reload。
