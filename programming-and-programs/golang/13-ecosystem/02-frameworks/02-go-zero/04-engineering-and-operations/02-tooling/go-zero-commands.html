go-zero 常用命令速查

go-zero 的 CLI 叫 goctl。记住这几条，从建工程到上容器一条龙。每条都配了命令与说明。

安装 api 命令 rpc 命令 model 命令 docker / kube 速查表
准备

先装上 goctl

所有命令都来自 goctl，先确保它在 PATH 里。

安装

go install github.com/zeromicro/go-zero/tools/goctl@latest

装完验证：

goctl --version # 输出版本号即成功
macOS/Linux 记得把 $GOPATH/bin 加进 PATH：export PATH=$PATH:$(go env GOPATH)/bin
最常用 ①

goctl api —— 生成 HTTP 服务

写完 .api 文件，一键产出完整 rest 服务骨架。

生成 Go 服务

goctl api go -api user.api -dir .

-api 指定描述文件，-dir 指定输出目录。会生成 handler/logic/svc/types + main + yaml。

顺手生成 Dockerfile

goctl api docker -o user-api/Dockerfile

从文档反向生成 api 文件（可选）

goctl api format -w user.api # 格式化
最常用 ②

goctl rpc —— 生成 RPC 服务

写完 .proto，生成 gRPC 桩 + zrpc 封装 + 配置 + main。

核心命令

goctl rpc protoc user.proto \ --go_out=. \ --go-grpc_out=. \ --zrpc_out=. \ -m # -m 生成 main.go 和 etc 配置

三个 out 分别产出消息、gRPC 接口、zrpc 服务端/客户端封装。-m 让 goctl 顺便把 main 和 yaml 也生成好。

从已有 .proto 只更新代码

goctl rpc protoc user.proto --zrpc_out=. # 重跑即可覆盖生成
手动改过的 logic 不会被覆盖（logic 是手写的），但 pb.go、grpc.pb.go 会被重新生成，不要在生成物里手写代码。
最常用 ③

goctl model —— 生成数据访问层

把 SQL 表结构变成带缓存的 CRUD 代码，再也不手写 SQL 拼装。

从 SQL 文件生成

goctl model mysql ddl \ -src user.sql \ -dir ./internal/model \ -c # -c 开启缓存

从数据库直连生成

goctl model mysql datasource \ -url "user:pass@tcp(127.0.0.1:3306)/db" \ -table user,order \ -dir ./internal/model \ -c
生成的方法形如 Insert / FindOne / FindOneByXxx / Update / Delete。带 -c 时 FindOne 自动走缓存 + singleflight 防击穿。
最常用 ④

goctl docker / kube —— 上容器

生成多阶段 Dockerfile 与 K8s 部署清单，省去手搓 yaml。

Dockerfile

goctl docker -go user-api.go \ -o Dockerfile

多阶段构建，最终镜像只有二进制 + 极简基础镜像。

K8s 部署

goctl kube deploy \ -name user-api \ -namespace default \ -image user-api:v1 \ -port 8888 \ -o user-api.yaml

产出 Deployment + Service，改镜像即可上集群。

命令分类与易错点

类别命令易错点

API 生成goctl api go -api x.api -dir .会覆盖 handler/types，不会删已有 logic

流程与报错

# 完整的一条新服务流程（照抄即可）
goctl api new user                     # 1. 建骨架
cd user && vim user.api                # 2. 写 API 定义
goctl api go -api user.api -dir .      # 3. 生成代码
go mod tidy                            # 4. 拉依赖
go run user.go -f etc/user-api.yaml    # 5. 跑起来

# RPC 侧（注意 go_package 必须写，否则生成路径会错）
# user.proto 开头：
#   syntax = "proto3";
#   package user;
#   option go_package = "./userclient";
goctl rpc protoc user.proto --go_out=. --go-grpc_out=. --zrpc_out=.

# Model 生成（带缓存）
goctl model mysql datasource \
  -url="root:pwd@tcp(127.0.0.1:3306)/db" \
  -table="user" -dir ./model -cache=true

# 常见报错对照
#   "protoc not found"          -> 装 protoc 并加入 PATH
#   "--go_out: protoc-gen-go: program not found" -> go install protoc-gen-go
#   "missing go_package option" -> proto 里补 option go_package
#   "unable to determine import path" -> 在 module 目录下执行
  • goctl 生成的东西分两类：handler/types/pb 是生成物，改了会被覆盖；logic 是给你写的，不会被删。
  • .api 文件是唯一真相源：所有接口变更先改 .api 再重新生成，不要手改 handler。
  • 提交前跑 goctl api format：保持 .api 格式统一，减少 diff 噪音。
  • 版本要对齐：goctl 版本与 go-zero 框架版本应尽量一致，跨大版本生成的代码可能不匹配。
  • 生成后一定要 go build：生成失败往往不会报错，只在编译时才暴露。

CI 与部署

# CI 里建议固定这几步（按顺序）
go mod tidy && git diff --exit-code go.mod go.sum   # 依赖是否已 tidy
gofmt -l .                                          # 格式
go vet ./...                                        # 静态检查
staticcheck ./...                                   # 更严格（可选）
go test -race ./...                                 # 竞态检测（并发服务必开）
go build ./...                                      # 编译

# Dockerfile 要点（goctl docker 生成后建议手动补）
FROM golang:1.22-alpine AS builder
ENV CGO_ENABLED=0 GOOS=linux
WORKDIR /app
COPY . .
RUN go build -ldflags "-s -w" -o app .

FROM alpine:3.19
RUN apk add --no-cache ca-certificates tzdata
COPY --from=builder /app/app /app/app
COPY --from=builder /app/etc /app/etc
EXPOSE 8080
CMD ["/app/app", "-f", "/app/etc/user-api.yaml"]

# 健康检查与优雅退出是 K8s 部署的必备项
#   readinessProbe / livenessProbe 打 /health（自己加）
#   优雅退出：监听 SIGTERM，先摘流量再关连接
改了 .api 后新增的接口没有 logic 文件？

goctl 会为新接口生成空的 logic 文件（含 TODO），检查是否被 .gitignore 排除或生成目录不对。

goctl model 生成的缓存怎么失效的？

生成的 Update/Delete 会自动删缓存，FindOne 会自动写缓存，一致性由框架保证——但强一致场景（库存）不要用它，直接走 DB。

为什么本地 goctl rpc 一直报 protoc 相关错？

90% 是环境不齐：protoc 本体、protoc-gen-go、protoc-gen-go-grpc 三个都要装且都在 PATH 里。goctl env check -i -f 可以一键检查并安装。
