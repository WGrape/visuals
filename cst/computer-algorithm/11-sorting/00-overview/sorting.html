第 11 章 · 排序

不只比较运行时间

排序方法还要比较稳定性、额外空间、最坏情形，以及输入是否已有序。

核心速览

四种排序的复杂度、稳定性与适用场景
稳定性相等元素的相对顺序是否保持
原地性是否只用 O(1) 额外空间
比较 / 非比较能否突破 O(n log n) 下界
适应性输入接近有序时是否更快

评价排序算法的六个维度

只盯「平均时间复杂度」是不够的，实际选型要看六件事：

  1. 平均 / 最坏 / 最好时间复杂度——快排最坏会退化到 O(n²)。
  2. 空间复杂度——归并需要 O(n) 辅助数组，快排是 O(log n) 递归栈，堆排序 O(1)。
  3. 稳定性——相等元素的原有相对顺序是否保持。
  4. 是否原地——内存紧张时很重要。
  5. 适应性——输入已部分有序时能否更快（插入排序接近有序时是 O(n)）。
  6. 常数因子与缓存局部性——同样 O(n log n)，实际速度可能差几倍。
「稳定性」为什么重要？举例：先按「年龄」排序，再按「部门」排序。如果第二次排序不稳定，同一部门内原本的年龄顺序就会被打乱。多关键字排序必须依赖稳定性——这也是为什么很多语言的内置排序（如 Java 对象排序、Python sorted）都保证稳定。

还有一类非比较排序，可以突破 O(n log n) 下界，但有前提：

算法复杂度前提空间稳定

为什么比较排序最快只能是 O(n log n)？因为 n 个元素有 n! 种排列，比较排序本质是「用二叉判定树区分这 n! 种可能」。树高至少 log(n!)，由斯特林公式 log(n!) = Θ(n log n)。所以任何只靠两两比较的排序都不可能比 O(n log n) 更快——这是信息论下界，不是工程问题。

三个核心算法的工作方式

归并排序：先分开排好，再合并

分治的典型。把数组一分为二，分别排序（递归），然后把两个已有序的数组合并成一个。合并时用两个指针分别扫两边，每次取较小的放入结果——O(n)。

递推式：T(n) = 2T(n/2) + O(n)（两个子问题 + 线性合并）→ 由主定理得 O(n log n)。关键：无论输入如何，递归树形状固定，所以最坏也是 O(n log n)。

代价是需要 O(n) 辅助空间，且不是原地的——这是它相对快排的主要劣势。

快速排序：选基准，把小的放左边、大的放右边

也是分治，但把主要工作放在「分」而不是「合」：选一个基准（pivot），用分区（partition）把数组重排成「左 ≤ pivot ≤ 右」，然后只递归两侧，不需要合并步骤。

递推式：T(n) = T(k) + T(n−k−1) + O(n)。分区均衡时是 O(n log n)；但若每次都选到最大或最小元素作基准，一侧为空，递推退化为 T(n) = T(n−1) + O(n) = O(n²)。
为什么实际中快排通常最快？三个原因：① 原地分区，不需要额外数组；② 分区是顺序扫描，缓存局部性极好；③ 常数因子小。但必须防退化：随机选 pivot、三数取中、或在递归深度过大时切换到堆排序（这就是 introsort，C++ std::sort 的做法）。

堆排序：建堆 + 反复取最值

先 O(n) 建大顶堆，然后重复「把堆顶（最大）与末尾交换 → 堆大小减一 → 对新堆顶下沉」，n 次后数组即升序。

堆排序的独特价值：最坏也是 O(n log n)，且只用 O(1) 额外空间——这两点是快排和归并做不到的。代价是缓存局部性差（跳跃式访问数组），也不稳定，所以实践中通常比快排慢一些。

🎯 面试问答

Q：排序算法的「稳定性」是什么意思？为什么重要？

A：指相等元素在排序后的相对顺序是否与排序前一致。重要性体现在多关键字排序：先按年龄排、再按部门排，只有第二次排序稳定，同一部门内才会保持年龄顺序。归并、插入、冒泡、计数、基数稳定；快排、堆排、选择不稳定。这也是为什么 Java 对对象排序、Python 的 sorted 都保证稳定。

Q：快排最坏为什么会退化成 O(n²)？怎么避免？

A：快排的递推是 T(n) = T(k) + T(n−k−1) + O(n)。如果每次选到的 pivot 恰好是当前区间的最大或最小值，分区后一侧为空、另一侧 n−1 个，递推退化为 T(n) = T(n−1) + O(n)，求和得 O(n²)。最容易触发的情况是对已排序数组总是选第一个元素做 pivot。避免办法：① 随机选 pivot；② 三数取中（首、中、尾的中位数）；③ 递归深度超限时切换堆排序——这就是 C++ std::sort 采用的 introsort。

Q：归并排序为什么最坏也是 O(n log n)？

A：因为它的递归树形状与输入数据无关——无论数组内容如何，都严格地「对半分」到单个元素，树高固定为 log n，每层的合并总代价是 O(n)，所以总共 O(n log n)。这跟快排形成鲜明对比：快排的划分比例取决于 pivot 选得好不好，因此最坏会退化。代价是归并需要 O(n) 辅助空间且不是原地排序。

Q：为什么比较排序最快只能是 O(n log n)？

A：这是信息论下界。n 个元素有 n! 种可能的排列，排序结果要能区分出其中唯一正确的那一种。只做两两比较的算法等价于一棵二叉判定树，叶子数至少 n!，树高至少 log₂(n!)。由斯特林公式 log(n!) = Θ(n log n)，所以任何仅基于比较的排序都不可能比 O(n log n) 更快。要突破必须利用键值的额外结构（如计数排序利用「小整数范围」），即非比较排序。

Q：堆排序相对快排有什么优缺点？

A：优点：最坏情况也是 O(n log n)（快排最坏 O(n²)），且只需要 O(1) 额外空间（归并需要 O(n)）。缺点：不稳定；缓存局部性差——堆的操作在数组里跳跃式访问（下标 i ↔ 2i+1），而快排的分区是顺序扫描，缓存命中率高得多。所以虽然两者都是 O(n log n)，实践中堆排序通常比快排慢。堆排序的价值在于「保证最坏性能 + 省内存」这两个硬约束场景。

Q：实际工程中应该选哪个排序算法？

A：绝大多数情况直接用标准库，不要自己写。标准库用的是混合策略而非单一算法：C++ std::sort 用 introsort（快排为主 + 深度超限切堆排 + 小区间切插入）；Java 对基本类型用双轴快排、对对象用 TimSort（归并+插入的稳定混合）；Python 用 TimSort。自己选型时：通用 → 快排；要稳定 → 归并；内存紧张且要保证最坏 → 堆排；小数组或基本有序 → 插入排序；小范围整数 → 计数排序。

第一层 · 概念与判定：排序算法怎么选

一句话判据：工程上直接用语言内置的 sort（快排/归并/堆排的混合实现）；手写算法只在面试与特定约束下才有意义。

算法平均复杂度最坏空间稳定什么时候用
冒泡 / 选择O(n²)O(n²)O(1)选择否 / 冒泡是仅教学
插入排序O(n²)O(n²)O(1)✅近乎有序的小数组最快（n<20 时内置排序常切到它）
快排O(n log n)O(n²)O(log n) 递归栈❌平均最快，工程默认
归并排序O(n log n)O(n log n)O(n)✅要稳定 / 链表排序 / 外部排序

  • 信号一：要稳定（相等元素保持原顺序）→ 归并，或 Python/Java 的稳定内置排序。
  • 信号二：内存极紧 → 堆排序（原地，但缓存不友好）。
  • 信号三：数据是整数且范围小（如 0～1000）→ 计数排序，O(n) 碾压比较排序。

关键定理：基于比较的排序下界是 O(n log n)。计数/桶/基数之所以能突破，是因为它们「不比较」，代价是要求数据有特殊性质（整数、值域有限）。

第二层 · 参数·命令·量化：内置排序与关键参数

各语言内置排序

# Python：Timsort（归并 + 插入的混合），稳定
a.sort()                                  # 原地
b = sorted(a)                             # 返回新列表
a.sort(key=lambda x: x[1])                # 按第二列
a.sort(key=lambda x: (-x[0], x[1]))       # 多关键字：先降后升
a.sort(key=lambda x: x.age, reverse=True)

# Java：基础类型用双轴快排（不稳定），对象用 TimSort（稳定）
Arrays.sort(intArr);                      // 双轴快排
Arrays.sort(objArr, comparator);          // 稳定
Collections.sort(list, comparator);

# C++：introsort（快排 + 堆排 + 插入的混合），不稳定
std::sort(v.begin(), v.end());            // 不稳定
std::stable_sort(v.begin(), v.end());     // 稳定（归并）
std::partial_sort(v.begin(), v.begin()+k, v.end());   // 只要前 k 个

# Go：pdqsort（Go 1.19+），不稳定
sort.Slice(a, func(i, j int) bool { return a[i] < a[j] })
sort.SliceStable(a, func(i, j int) bool { return a[i].age < a[j].age })

插入排序切换阈值n < 16～32小区间用插入排序，常数更小

第三层 · 排障与边界：比较器与稳定性

坑后果正确做法
比较器不满足严格弱序结果错乱甚至崩溃（如 C++ 的 UB）a < b 即可，不要写 <=
比较器里做了重计算排序慢几倍预先算好 key（ Schwartzian transform）
以为内置排序是稳定的，实际不是相等元素顺序被打乱明确用 stable 版本（sorted() / stable_sort / SliceStable）
多关键字排序写成多次稳定排序逻辑反了多次排序时最后一次是主关键字；或直接用元组 key
递归过深爆栈快排极端情况用 introsort 或先随机化（shuffle）
  • 排查顺序：先确认比较器是严格弱序 → 再看是否需要稳定 → 再看 key 计算是否过重。
  • 边界一：严格弱序要求 comp(a,a) == false，所以比较器里写 <= 会让等价关系失效。
  • 边界二：浮点排序要小心 NaN——它与任何值比较都是 false，会破坏严格弱序。
  • 边界三：快排的 O(n²) 最坏情况在已排序数组 + 取首元素做 pivot 时触发；工程实现靠「三数取中」或「随机 pivot」规避。

比较器优化

# 预计算 key 提速（避免在比较器里重复计算）
# 慢：每次比较都算一次 len(x)
a.sort(key=lambda x: x[1])

# 快：当 key 计算很重时，先算好再排
decorated = [(heavy_compute(x), i, x) for i, x in enumerate(a)]
decorated.sort()
a = [x for _, _, x in decorated]

# 多关键字：先按次要排，再按主要排（稳定排序才成立）
a.sort(key=lambda x: x.name)      # 次要
a.sort(key=lambda x: x.age)       # 主要（最后排的说了算）

第四层 · 原理与取舍：为什么工程排序都是「混合」的

没有任何单一算法在所有场景最优，所以工业级实现都是混合策略：大区间用快排/归并，小区间切插入排序，递归太深切堆排，遇到已有序段直接利用。

实现核心算法混合了什么稳定用在
Timsort归并插入排序 + 识别已有序 run✅Python / Java(对象) / Android
Introsort快排深度超限切堆排 + 小区间插入❌C++ std::sort
pdqsort快排模式识别（已排序/全相等） + 随机化❌Go 1.19+ / Rust
双轴快排快排两个 pivot 三分❌Java（基础类型）
为什么小区间要切插入排序？

因为插入排序的常数因子极小：n 很小时 O(n²) 的实际指令数比 O(n log n) 还少，且它是原地的、缓存友好、对近乎有序的数据接近 O(n)。实测阈值通常取 16～32。

稳定性为什么重要？

当排序对象有多个字段时，稳定排序能让你「先按次要字段排、再按主要字段排」得到正确结果。不稳定排序下这个技巧失效，必须一次性用复合 key。

什么时候手写排序？

几乎不用。例外：① 面试考察；② 极端性能场景（如已知数据分布、要自定义分区）；③ 外部排序（数据放不进内存，必须归并到磁盘）。日常一律用内置。

先明确输入和约束，再选排序算法。
