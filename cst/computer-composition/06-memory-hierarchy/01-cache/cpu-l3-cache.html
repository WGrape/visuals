📌 为什么 L3 最大？

  • → L1/L2 追求极速，面积成本高，只能做小
  • → L3 需要服务所有核，必须足够大
  • → L3 是最后防线，Miss 才去 RAM
  • → L3 命中率直接影响整机性能
  • → 3D 堆叠技术正在突破 L3 容量上限

🔑 L3 共享的三个核心价值

  • Core 0 写入数据后，Core 1 可以直接从 L3 读取，无需去 RAM
  • L3 是 MESI 缓存一致性协议的协调节点，防止多核数据不一致
  • 一个核心频繁用的数据"留"在 L3，其他核切换到此任务时直接命中
  • L3 Miss 率是多核程序性能调优的关键指标（perf stat 可测量）

三级缓存：用层次把「慢内存」伪装成「快内存」

CPU 与主存之间有数量级的速度差。Cache 的思路是：用小而快的存储器，暂存最近/最可能用到的数据，靠程序的局部性（时间局部性：刚用过还可能再用；空间局部性：用了附近的也可能用）把命中率做到 90%+，从而让平均访问时间接近最快的一层。

L1最小最快，几十 KB，通常分指令/数据两路，每核独占
L2几百 KB 到几 MB，每核独占（部分架构共享）
L3几 MB 到上百 MB，同插槽多核共享，是核间通信的通道
缓存行64 字节，缓存与内存交换的最小粒度
命中率决定平均访问时间的关键，90% 与 99% 差很多
包含关系多为 inclusive（L3 包含 L2/L1 内容），也有 exclusive 设计

缓存的三种失效与组织方式

维度类型含义对策
失效原因（3C）Compulsory 冷失效第一次访问必然缺失预取、提前warm up
失效原因（3C）Capacity 容量失效工作集超过缓存容量减小工作集、分块处理（loop tiling）
失效原因（3C）Conflict 冲突失效映射到同一组的行互相挤掉提高相联度、改变数据布局
映射方式直接映射每个内存块只有一个固定位置简单快，但冲突多
映射方式全相联可放任意位置冲突最少，但查找成本高
映射方式组相联（主流）分成若干组，组内全相联折中方案，现代 Cache 普遍使用
写策略Write-through写同时更新缓存与内存一致性简单，写流量大
写策略Write-back只写缓存，淘汰时才写回写流量小，需维护脏位（dirty bit）

替换策略：LRU（最近最少用）最常见，但真 LRU 成本高，实际多用伪 LRU 或随机。L3 上还会用更智能的策略以对抗扫描型负载污染。

写出 Cache 友好的代码

① 顺序优于随机

  • 数组/连续容器（vector、数组）比链表快，即使链表理论上操作是 O(1)。
  • 原因：连续内存命中缓存行与硬件预取，链表节点跳跃导致大量 miss。
  • 数据结构选择：优先连续布局；必要时用对象池让节点聚集。

② 缩小工作集

  • 循环分块（tiling/blocking）：把大矩阵切成能装进 Cache 的小块处理。
  • 矩阵乘法、图像处理这类算法收益极大（可快数倍）。
  • 冷热数据分离：不要让大冷数据把热数据挤出缓存。

③ 避免伪共享

  • 多线程写同一缓存行的不同变量 → 行在核间反复失效。
  • 对策：按缓存行填充（padding）或 alignas(64) 对齐。
  • 典型：per-thread 计数器数组、生产者/消费者的 head/tail 索引。
  • 用 perf c2c 可以定位伪共享热点。

④ 注意访问步长

  • 步长为 1 最快；大步长（如按列遍历行主序数组）每次访问都跨行。
  • 二维数组遍历顺序要与存储顺序一致（C 是行主序）。
  • 结构体数组（AoS）vs 数组结构体（SoA）：只用到少数字段时 SoA 更省带宽。

深入自检

为什么 L3 是多核共享的？

因为共享带来两个好处：一是容量更大、命中率更高；二是核间通信可以通过 L3 快速完成（不需要绕道内存）。代价是不同核的工作集会互相挤占，某些场景需要把 L3 按核簇划分（如 AMD 的 CCD 设计）来降低干扰。

缓存行为什么是 64 字节？

这是权衡的结果：行太小则每次传输的开销（地址、命令）占比高、无法充分利用空间局部性；行太大则浪费带宽（只用一个字节也搬 64 字节）且冲突更多。64 字节在实践中表现最好，成为 x86 的事实标准。部分架构（如 Apple Silicon）使用 128 字节行。

什么是伪共享，怎么发现？

两个核分别写同一缓存行内的不同变量，虽然逻辑上无冲突，但缓存一致性协议会让整行在两核间来回失效，性能可能下降一个数量级。发现方法：perf c2c 工具能显示「HITM」（命中已修改行）热点；也可对比加锁/填充前后的吞吐差异。解决方式是让变量各自独占缓存行。

为什么链表比数组慢？

即便渐进复杂度相同，链表节点在内存中分散，每次访问几乎都是一次缓存缺失（可能 200 周期），而且硬件预取器无法预测指针跳转。数组连续布局则一次缓存行可服务多次访问并触发预取。实测中遍历同样数量的元素，数组常比链表快数倍到十倍。

缓存一致性会不会拖慢多线程程序？

会。MESI 协议保证各核看到一致的数据，但写共享数据会使其他核的副本失效，导致「一致性流量」。真正的问题通常不是协议本身，而是程序写了本不该共享的数据（伪共享）。设计原则：尽量让数据私有、减少跨核写共享、必要时按核分片。

如何量化 Cache 的影响？

用 perf：perf stat 看 cache-misses 占比，perf record/report 定位到函数与行；perf c2c 定位伪共享。也可以做受控实验：改变遍历顺序、改变数据布局，对比耗时。经验阈值：cache-miss 率超过 5% 通常就值得优化。
