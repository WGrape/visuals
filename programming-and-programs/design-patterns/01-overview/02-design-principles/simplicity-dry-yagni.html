04 · 把原则写进代码

最小伪代码

function exportPdf(data) { validatePdf(data); renderPdf(data) }
function exportCsv(data) { validateCsv(data); renderCsv(data) }
// 先保留独立语义。若共同审计规则重复出现：
function withAudit(exporter, data) {
  audit.start(data)
  return exporter(data)
}

从代码中带走三件事

  1. DRY 指不要多处维护同一条知识。
  2. KISS 要求当前设计尽量容易理解。
  3. YAGNI 要求不为尚未证实的需求预付复杂度。
05 · 原则不是教条

对应哪些模式？什么时候收手？

  • 工厂方法：产品种类真的扩展时再引入
  • 策略：算法真的需要互换时再抽出
  • 建造者：参数复杂到影响可读性时再使用

“重复三次再抽象”只是启发式，不是硬规则。安全修复或核心业务不变量即使只重复两处，也可能值得统一。

两段代码看起来一样，就应该立刻抽成一个函数吗？

不一定。先看它们是否表达同一知识、是否因同一原因变化；只看文本相似容易得到错误抽象。
