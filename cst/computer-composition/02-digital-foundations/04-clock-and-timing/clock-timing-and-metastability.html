时钟树、偏斜与亚稳态：跨时钟域为什么总要打两拍

时钟不是一个理想的方波：它要走线、要分配、会有偏斜和抖动。当两个不同频率的时钟互相采样时，就必然出现「采样点落在变化沿上」的时刻——这就是亚稳态，也是所有 CDC 问题的起点。

一句话定位：时钟是分布式的，不是全局的

一颗 CPU 的时钟要送到上亿个触发器，走线长度不同、负载不同，到达时间就不同。这种差异叫偏斜（skew）；时钟源本身的周期抖动叫 jitter。两者都直接吃掉时序余量，所以高频芯片的时钟树设计（H-tree、网格、去偏斜缓冲）和逻辑设计同等重要。

偏斜 skew同一时钟沿到达不同寄存器的最大时间差
抖动 jitter周期长度逐周期的随机波动（PLL 带来）
时钟树H-tree / 网格 / CTS 平衡，把 skew 压到周期的 5% 内
PLL倍频、锁相、去抖，是现代芯片的时钟源
亚稳态的形成：采样点落在数据变化窗口内

MTBF：两级同步器到底够不够

MTBF = etr/τ / (T0 × fclk × fdata)

t_r 是留给触发器「决议」的时间（约等于一个周期），τ 是工艺相关的亚稳态衰减常数（先进工艺约 10~30 ps）。每多一级同步器，t_r 翻倍，MTBF 按指数增长。

同步级数相对 MTBF（示意）工程判断
0（直接采样）秒级甚至更短不可接受
1 级数小时~数天仅用于「不会同时发生」的场景
2 级数百年绝大多数设计的标准做法
3 级天文数字超高频或高可靠场景
数字是示意，不是常数

MTBF 对 τ 极其敏感：τ 从 20ps 变到 15ps，MTBF 可能差几个数量级。所以可靠的做法是「按规范打两拍」，而不是「算出来够用就少打一拍」。

跨时钟域的三套标准解法

数据类型方案原理代价
单 bit 电平信号两级触发器同步让亚稳态有时间衰减2 个周期延迟
单 bit 脉冲脉冲展宽 / 握手保证被采到时足够宽延迟不确定
多 bit 计数值格雷码 + 同步相邻值只变 1 位，不会采到中间态只适用于连续计数
多 bit 数据异步 FIFO / 握手用指针同步 + 双端口存储面积与延迟
复位信号异步复位、同步释放避免释放沿亚稳态一个复位同步器
// 两级同步器（打两拍）
always @(posedge clk_dst) begin
  sync1 <= async_in;
  sync2 <= sync1;      // 使用 sync2，绝不用 sync1
end

// 异步复位、同步释放
always @(posedge clk or negedge rst_n) begin
  if (!rst_n) {rst_s1, rst_s2} <= 2'b00;
  else        {rst_s1, rst_s2} <= {1'b1, rst_s1};
end

时钟与功耗：为什么频率不再是无脑往上加

动态功耗与频率成正比、与电压平方成正比（P ∝ C·V²·f）。要把频率提 20%，往往要加压，功耗涨 40% 以上；而散热能力有限，于是出现「功耗墙」：堆频率不如堆核心、堆专用单元。这就是 2006 年之后主频停在 3~5GHz 的根本原因。

排障：CDC 与时钟问题的典型故障

现象原因处理
偶发丢包/丢计数多 bit 信号没做格雷码或握手改异步 FIFO 或加握手
上电偶尔起不来复位释放未同步加复位同步器
高低温表现不同PLL 锁定时间与 jitter 变化查 PLL 锁定窗口与时钟余量
两个模块数据错位一拍skew 被当成 0 计算做时序分析时给 skew 留余量
综合后时序不收敛跨时钟域路径被当同步路径优化加 false_path / async 约束

原理与取舍：为什么不能消灭亚稳态

亚稳态不是设计缺陷，而是双稳态电路的物理属性：当输入在窗口内变化时，触发器内部的正反馈需要时间才能收敛到 0 或 1。我们能做的只有两件事——给它时间（打拍）和别让它影响下游（隔离、握手）。任何声称「消除亚稳态」的方案，实质都是把概率压到可接受范围。

打两拍之后还需要做别的吗？

要。同步后的信号仍有 1~2 个周期的延迟不确定性，所以只能用于电平或已编码的数据；多 bit 数据必须用 FIFO/握手，否则会采到「新旧混合」的值。

为什么格雷码能解决多 bit 同步？

因为相邻两个码字只差 1 位，采样时最多错成相邻值，不会出现「一半新一半旧」的乱码。代价是只能表示连续序列。

时钟频率越高，MTBF 会变差吗？

会。f_clk 在分母上，且 t_r 变小（周期变短），两个因素同时恶化。高频设计里三级同步器并不罕见。

写给工具的约束：CDC 到底怎么约束

亚稳态不能靠「小心」避免，只能靠约束 + 结构 + 属性三件套让工具替你检查。下面这套写法在 Vivado / Quartus / Design Compiler 上都通用，只是命令名略有差异。

SDC / XDC 约束模板

# 1) 声明两个时钟异步：让 STA 不再对它们之间的路径做建立/保持检查
set_clock_groups -asynchronous -group [get_clocks clk_a] -group [get_clocks clk_b]

# 2) 只想放开个别路径时用 false path（比 set_clock_groups 更窄、更安全）
set_false_path -from [get_clocks clk_a] -to [get_clocks clk_b]

# 3) 总线跨时钟域不能逐位同步（各位延迟不同会采到「中间值」），
#    必须用格雷码或握手，并给出允许的位间 skew 上限
set_bus_skew 4.0 [get_cells *gray*]
set_max_delay 6.0 -from [get_clocks clk_a] -to [get_clocks clk_b] -datapath_only

# 4) 关键：把两级同步器的两个触发器标记为 ASYNC_REG，工具会把它们放得尽量近
set_property ASYNC_REG TRUE [get_cells sync_ff*]
命令作用典型取值用错的后果
set_clock_groups -asynchronous整组放开跨时钟路径的时序检查两个真实异步时钟对确实同步的时钟用会漏检真违例
set_false_path仅放开指定起止点个别可证明安全的路径范围写太宽等于关掉检查
set_max_delay -datapath_only给跨时钟路径一个明确上限（不减时钟 skew）源时钟周期的 1~1.5 倍不设则路径延迟完全不受控
set_bus_skew限制多位总线各位到达时间差≤ 目标时钟周期的 1 个周期不设时慢快位混采出错值
ASYNC_REG / PRESERVE标记同步器，防止被优化或放远TRUE不标记时两级 FF 可能被重定时拆开，MTBF 骤降

常见错误：用 set_clock_groups -asynchronous 覆盖所有跨时钟路径，结果把本来就同源（分频/使能）的路径也放开了。同源时钟应该用 create_generated_clock 让工具自己算。

签核读数：报表里的数字怎么看

时序签核只看几个数：WNS（最差负裕量）、TNS（总负裕量）、违例路径条数。WNS 是单条最差路径的裕量，TNS 是所有违例之和 —— 修优先级按 TNS 排，因为它是「总工作量」。

指标含义健康值不健康时怎么办
WNS（setup）最差建立时间裕量> 0，建议 ≥ 周期的 5%降频 / 插流水级 / 优化组合逻辑级数
WNS（hold）最差保持时间裕量> 0，且不能靠降频解决插缓冲、调时钟树 skew（保持违例降频没用）
TNS所有负裕量之和0按贡献排序，先修前 10 条路径
Unconstrained paths没有被约束覆盖的路径0补 set_max_delay 或生成时钟
CDC 未同步路径跨时钟域但无同步器0补两级同步 / 握手 / 异步 FIFO

签核常用命令

# Vivado：跨时钟域交互总览（签核前必看）
report_clock_interaction -delay_type min_max -significant_digits 3
report_cdc -details -file cdc_report.txt

# 时序报告：只看最差 50 条，避免被几千条淹没
report_timing -setup -max_paths 50 -nworst 5 -input_pins -file setup_worst.rpt
report_timing -hold  -max_paths 50 -nworst 5 -input_pins -file hold_worst.rpt

# 快速拿到 WNS/TNS 两个数
report_timing_summary -warn_on_violation -file timing_summary.rpt

上板前逐条核对：

  • 所有跨时钟路径必须先分类：真异步 / 同源分频 / 使能时钟，三类处理方式完全不同。
  • 两级同步器的两个 FF 必须标 ASYNC_REG，否则布局可能把它们放得很远，MTBF 反而更低。
  • 多位总线禁止逐位同步，转格雷码（仅适用于连续递增）或改用握手 / 异步 FIFO。
  • 同步器两级之间不能有任何组合逻辑，连一个 buffer 都不行。
  • 保持违例不能靠降频解决，只能改布局或插缓冲——这是新人最常犯的判断错误。
  • 签核要跑全部工艺角（慢-慢、快-快、慢-快、快-慢），只跑典型角会漏掉极端情况。
  • 复位释放也要当跨时钟域处理：异步断言、同步释放。
  • report_cdc 报的未同步路径必须逐条确认，不能整体 waive。
