start 参数还是 used 数组

子集与组合用 start 参数只能往后取，排列用 used 数组每层从头扫；重复元素靠排序加同层跳过，剪枝有三类常用手段。

三种模板：子集、组合、排列

回溯的共同骨架是「做选择 → 递归 → 撤销选择」，差别只在怎么限定候选范围：

# ① 子集：每个元素选或不选，start 逐层推进
def subsets(nums):
    res, path = [], []
    def dfs(start):
        res.append(path[:])
        for i in range(start, len(nums)):
            path.append(nums[i])
            dfs(i + 1)          # 不能回头取，避免重复子集
            path.pop()
    dfs(0); return res

# ② 组合：限长 k，配合剪枝
def combine(n, k):
    res, path = [], []
    def dfs(start):
        if len(path) == k: res.append(path[:]); return
        need = k - len(path)
        for i in range(start, n - need + 2):   # 剩余不够就别试
            path.append(i); dfs(i + 1); path.pop()
    dfs(1); return res

# ③ 排列：每层都从头选，用 used 去重
def permute(nums):
    res, path, used = [], [], [False] * len(nums)
    def dfs():
        if len(path) == len(nums): res.append(path[:]); return
        for i in range(len(nums)):
            if used[i]: continue
            used[i] = True; path.append(nums[i])
            dfs()
            path.pop(); used[i] = False
    dfs(); return res

一句话区分：子集/组合用 start 参数（只能往后取），排列用 used 数组（每层从头扫）。顺序不同的方案算同一种时用 start，算不同种时用 used。

重复元素怎么去重

输入含重复元素（如 [1,1,2]）时，直接回溯会产生重复结果。标准做法：先排序，再在同一层里跳过与前一个相同的元素。

nums.sort()
for i in range(start, len(nums)):
    if i > start and nums[i] == nums[i - 1]: continue   # 同层去重
    # ... 做选择、递归、撤销

条件是 i > start 而不是 i > 0。前者只跳过同一层内的重复分支，后者会误伤不同层的选择（导致 [1,1] 这种合法解被剪掉）。

复杂度与可行性边界

问题解的数量级n 的可行范围
子集2nn ≤ 20~25
组合 C(n, k)随 k 变化，最大在 k = n/2n ≤ 30（k 小时更宽松）
全排列n!n ≤ 10~11

n! 增长极快：10! ≈ 363 万还行，12! ≈ 4.8 亿就已经不可接受了。看到排列类问题且 n > 12，几乎一定需要换思路（DP、贪心、数学构造）。

剪枝：三类常用手段

  1. 可行性剪枝：剩余元素数量不足以填满 → 直接返回（上面组合模板里的 need 判断）。
  2. 上下界剪枝：当前已超预算 / 即使把剩下的全加上也达不到最优 → 返回。
  3. 对称性剪枝：同一层的重复元素只试一次（就是上面的同层去重）。

剪枝必须证明「被剪掉的分支里一定没有答案」，否则就是把正确答案剪掉了。不确定时先用小规模对拍验证。

回溯与 DP 的关系

两者都是在决策树上搜索，区别在于：

维度回溯DP / 状态压缩
输出枚举所有（或部分）具体方案通常只求最优值或计数
重复子问题不缓存，直接展开缓存，每个状态算一次
适用规模n ≤ 20~25（2n）或 ≤ 11（n!）状态数可控即可，指数状态时 n ≤ 20
典型例子全排列、N 皇后、子集枚举子集和、TSP、背包

一个简单的判断：要「列出方案」用回溯，只要「一个数值」就往 DP 想。两者也可以结合——用 DP 预处理出可行性剪枝的条件，再回溯枚举具体方案。

三种模式的模板与复杂度

子集、组合、排列的区别只在一个地方：要不要 start 下标（避免重复选）和要不要 used 数组（允许乱序）。记住这张表就不会再写错。

问题结果数量要不要 start要不要 used去重手段
子集（Subsets）2^n要（每次从 start 往后选）不要元素不重复则天然无重
子集 II（有重复元素）< 2^n要不要先排序，同层跳过已用过的相同值
组合（Combinations）C(n,k)要不要加 len(path)==k 剪枝
组合总和（可重复选）视 target不要（从 i 开始，允许再选自己）不要排序 + 按 target 剪枝
全排列（Permutations）n!不要要used 标记已选
全排列 II（有重复）< n!不要要排序 + if i>0 and nums[i]==nums[i-1] and not used[i-1]: continue

两套通用模板

# 通用模板（Python）
def subsets(nums):
    nums.sort()                 # 有重复元素时必须先排序
    res, path = [], []
    def dfs(start):
        res.append(path[:])     # 每个节点都是答案 —— 子集的关键
        for i in range(start, len(nums)):
            if i > start and nums[i] == nums[i-1]:
                continue        # 同层去重：跳过本层已用过的相同值
            path.append(nums[i])
            dfs(i + 1)          # start 往后，保证不重复选 -> 组合/子集
            path.pop()
    dfs(0); return res

def permute(nums):
    nums.sort()
    res, path = [], []
    used = [False] * len(nums)
    def dfs():
        if len(path) == len(nums):
            res.append(path[:]); return   # 只有叶子是答案 —— 排列的关键
        for i in range(len(nums)):
            if used[i]: continue
            if i > 0 and nums[i] == nums[i-1] and not used[i-1]:
                continue        # 去重：保证相同值的相对顺序固定
            used[i] = True; path.append(nums[i])
            dfs()
            used[i] = False; path.pop()
    dfs(); return res

最常错的一行是去重条件里的 not used[i-1]。它是「同一层跳过」的意思：used[i-1]==False 说明前一个相同值在本层已经回溯撤销了，本次若再选 nums[i] 就会和它产生完全相同的排列。写成 used[i-1]（True）就变成「同一路径跳过」，会漏解。

剪枝：把指数级降到可接受

技巧适用能省多少
排序 + 可行性剪枝组合总和等有约束的问题往往从 2^n 降到远低于此
上下界剪枝最优化类（如装载、分配）视数据，常能省 90%+
可行性剪枝：剩余元素不够组合（n - start < k - len(path)）省掉大量无效分支
记忆化重叠子问题（本质是 DP）指数 → 多项式
位运算枚举子集n ≤ 20 的子集枚举常数优化，代码更短

剪枝示例

# 组合的必备剪枝：剩下的元素不够凑满 k 个，直接返回
def combine(n, k):
    res, path = [], []
    def dfs(start):
        if len(path) == k:
            res.append(path[:]); return
        # 剪枝：还需 need 个，但只剩 n-start+1 个可选
        need = k - len(path)
        if n - start + 1 < need: return
        for i in range(start, n - need + 2):    # i 的上界也能收紧
            path.append(i); dfs(i + 1); path.pop()
    dfs(1); return res

# 组合总和：排序后一旦超过 target 就整枝剪掉
def combination_sum(cands, target):
    cands.sort(); res, path = [], []
    def dfs(start, rest):
        if rest == 0: res.append(path[:]); return
        for i in range(start, len(cands)):
            if cands[i] > rest: break          # 后面更大，整枝砍掉
            path.append(cands[i]); dfs(i, rest - cands[i]); path.pop()
    dfs(0, target); return res

# 位运算枚举全部子集（n<=20 时最快）
for mask in range(1 << n):
    sub = [nums[i] for i in range(n) if mask >> i & 1]
回溯和 DP 怎么区分？

看有没有重叠子问题 + 最优子结构。有 → 用 DP（记忆化也行，本质就是 DP）；没有、只是要枚举所有可行解 → 回溯。另一个实用判据：要输出所有方案通常用回溯（DP 只给数量/最优值）；只问数量或最优值优先想 DP。

n 多大就不能用回溯了？

粗算：2^20 ≈ 100 万、2^25 ≈ 3300 万、10! ≈ 360 万、12! ≈ 4.8 亿。以 Python 每秒约 10^6~10^7 次递归为界，子集/组合 n ≤ 20~25、全排列 n ≤ 9~10 是常见上限。超过就必须剪枝、记忆化或换算法（如用 DP 计数、用启发式求近似）。

递归深度会不会爆栈？

Python 默认递归上限 1000，回溯深度通常 = n（远小于 1000），一般不会爆。但 C/C++ 要注意栈大小；Go 的 goroutine 栈会自动增长（初始 2KB，最大默认 1GB），基本不用担心。若 n 真的很大（如 10^5 的链式回溯），要改迭代 + 显式栈。

要方案用回溯，要数值想 DP；去重条件是 i > start 而不是 i > 0。
