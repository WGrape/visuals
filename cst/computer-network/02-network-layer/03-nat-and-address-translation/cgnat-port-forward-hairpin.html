端口映射、CGNAT 与 NAT 回环：内网服务为何外面连不上

用家用路由器发布 NAS 的例子分清公网地址、端口映射、双重 NAT 与同网访问。

从一个映射表项开始

家中 NAS 是 192.168.1.10:8080，路由器有公网地址 203.0.113.7。若配置 203.0.113.7:443 → 192.168.1.10:8080，外部客户端连接公网 443 时，路由器在入口改写目的地址和端口，并保留连接跟踪信息；NAS 返回流量再按映射改写源地址与端口。端口映射只是让流量找到内网主机，NAS 自身防火墙、监听地址、认证和上游运营商策略仍要允许访问。

不建议仅因为“端口能映射”就把管理界面直接暴露公网。应先评估服务更新、强认证、TLS、访问控制和日志能力，必要时使用 VPN 或受控代理。抓包时分别在公网入口、路由器 LAN 口和 NAS 上观察，才能找出在哪一段被丢弃。

CGNAT 的关键判断

有些家庭路由器 WAN 口拿到的仍是私有或共享地址，公网地址在运营商 CGNAT 设备上。此时用户在自己的路由器上配置端口映射，外部连接仍先到运营商 NAT；用户通常无法控制该层的入站映射，因此不能靠家里再开一个端口解决。判断时对比路由器 WAN 地址与外部网站看到的地址，并识别常见私有及共享地址范围；地址不一致也可能是其他代理或多层出口，要结合拓扑验证。

CGNAT 并不妨碍大部分主动出站连接，但会让直接被动接收入站连接困难。可申请真正可入站的公网地址、使用支持的 IPv6、建立反向隧道或由云端中继。每种方案都要考虑认证、可用性和费用，不能把 STUN 打洞当作对所有 NAT 类型都可靠的万能方法。

逐步推演

确认服务

先在 NAS 与同网段测试监听和防火墙。

确认公网入口

比较 WAN 地址与外部可见地址，识别 CGNAT。

检查映射

逐层核对 TCP/UDP 规则及回程网关。

分场景验收

真正外网测试入站，同网域名另测 NAT 回环。

双重 NAT 与回程

家里先有运营商光猫路由，再接自己的无线路由：NAS 位于第二层 LAN。外部请求需要在光猫和自有路由两层都设置正确映射，或让其中一层改成桥接等明确拓扑。只在内层设备开放端口，包可能根本到不了它。回复也必须沿可匹配连接跟踪状态的路径返回；若 NAS 默认网关配置错误，入口可见 SYN，客户端仍可能永远收不到 SYN-ACK。

端口转发规则还要匹配协议 TCP 或 UDP。对只监听 TCP 的 Web 服务映射了 UDP，不会因为端口数字相同而成功。若公网入口做 TLS 终止，内网 NAS 监听的协议和端口也需对应，不能把 HTTPS 直接原封不动交给只支持明文 HTTP 的入口而不做处理。

NAT 回环的特殊现象

同一 Wi-Fi 下，手机用内网地址能访问 NAS；改用家庭公网域名却不能访问，这可能是 NAT 回环或 hairpin NAT 未启用。内网客户端连接路由器公网地址时，路由器需把流量转回内网 NAS，并让回复经过自己维护的映射状态。若 NAS 直接回复同网段手机，手机看到的来源与它连接的公网目标不一致，连接可能失败。

有些路由器实现 NAT 回环，有些不实现。也可让内网 DNS 把相同域名解析到内网地址，即分视图 DNS，但要保证证书主机名和应用 Host 路由仍一致。“内网域名不通”与“外网用户也不通”需要从真正外部网络分别测试，不能在同一 Wi-Fi 下代表公网验收。

IPv6 不等于无防火墙

IPv6 主机可能直接拥有全球可路由地址，少了 IPv4 NAPT 的入站映射环节，但家庭网关和主机防火墙仍可能默认拒绝入站。即使 IPv6 地址可达，也必须确认 DNS AAAA、前缀稳定性、服务监听和入站策略。把“有 IPv6”误当作“任何人都可访问”或“无需安全控制”都不准确。

若上游前缀变化，硬编码在 DNS 的旧 IPv6 地址会失效。对长期发布的家庭服务，应有地址更新与故障监测，不只看一次成功连接。

排障顺序

先在 NAS 本机和同网段设备确认服务监听，随后从真正外部网络连路由器 WAN 地址及端口。核对路由器 WAN 是否真是可入站公网地址，再查每层 NAT 规则、协议、主机防火墙和回程网关。只有内网使用公网域名失败时，再重点查 NAT 回环或内网 DNS。用时间戳和四元组对齐抓包，避免把无关扫描流量误认成测试请求。

验收除了“某次连接成功”，还应测路由器重启、租约变化、IPv4/IPv6、不同运营商网络和认证失败场景。若外部访问一会儿通一会儿不通，检查动态公网地址、映射超时、CGNAT 状态和上游防护策略。

自检

家用路由器已经做端口映射，但 WAN 地址在运营商 CGNAT 后，外网一定能连接吗？

不能。入站流量先到运营商 NAT，用户控制的映射无法自动穿越那一层。
