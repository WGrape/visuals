架构 · 架构模式

整洁架构 / 洋葱架构

用同心圆表达依赖规则：外层依赖内层，内圈永远不知道外圈的存在。

依赖规则 Dependency Rule

源码依赖只能由外指向内，内圈不引用任何外圈

<b>整洁架构</b>（Robert Martin）与<b>洋葱架构</b>（Jeffrey Palermo）几乎同构：最内是实体(企业规则)，往外是用例(应用规则)、接口适配器、最外是框架与驱动。铁律：<b>依赖只能向内</b>，内层绝不 import 外层。

四圈职责

  • 实体：最通用、最不易变的企业业务规则。
  • 用例：特定应用的业务流程（一个用例一个交互）。
  • 接口适配器：把数据在『用例格式』与『框架格式』间转换。
  • 框架与驱动：最易变的东西（Web 框架、数据库驱动）。

面试高频问答

Q：为什么内圈不能依赖外圈？
A：为了让最珍贵的业务规则不被易变的框架/数据库绑死。DB 换了、Web 框架换了，只要适配器跟上，核心一行不用动。这是『稳定依赖原则』的体现。
Q：整洁架构和分层架构冲突吗？
A：不冲突，是互补。分层讲『纵向切职责』，整洁架构讲『依赖方向』；实际项目常把整洁架构的圈再按分层细化。
