VACUUM 与 autovacuum

为什么 PG 必须定期 vacuum：回收死元组、更新统计、冻结事务ID。

为什么需要三种 vacuumautovacuum 调优监控

① 为什么 PG 必须 vacuum

MVCC 的 UPDATE/DELETE 只标记旧版本为死元组，不会立即释放空间。死元组堆积会：拖慢扫描、撑大表文件（膨胀）、并让事务 ID 不断前进逼近回卷阈值。VACUUM 负责回收这些空间、更新可见性映射、冻结老事务 ID。

② 三种 vacuum

命令作用锁
VACUUM回收空间给本表复用（不还给 OS），更新统计不排他
VACUUM FULL重建表、真正收缩文件还给 OS排他（锁表！）
VACUUM ANALYZE回收 + 更新优化器统计信息不排他
别滥用 VACUUM FULL：它锁全表且需 2 倍磁盘，日常交给 autovacuum 即可；仅在严重膨胀时择机执行。

③ autovacuum 调优

后台守护进程按阈值触发：autovacuum_vacuum_scale_factor（默认 0.2）+ autovacuum_vacuum_threshold（默认 50）。大表可单独设置：

ALTER TABLE orders SET (autovacuum_vacuum_scale_factor = 0.05);

写频繁的大表建议 调小 scale_factor，避免死元组堆积过快。

④ 监控

SELECT relname, n_dead_tup, last_vacuum, last_autovacuum
FROM pg_stat_user_tables ORDER BY n_dead_tup DESC LIMIT 10;
SELECT datname, age(datfrozenxid) FROM pg_database;  -- 回卷风险
