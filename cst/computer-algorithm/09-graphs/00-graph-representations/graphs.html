第 09 章 · 图

节点之间的一般关系

图不要求唯一父节点，也允许环；先明确边是否有方向、权重，再决定怎样存储与遍历。

核心速览

有向 / 无向边是否有方向：关注/跟随 vs 好友关系
带权 / 无权边是否带代价：距离、耗时、费用
度 Degree无向图的邻居数；有向图分入度与出度
连通性无向图的连通分量；有向图还有强连通分量

树是图的特例

树要求「每个节点只有一个父节点、且无环」。图把这些约束全部去掉：允许多个前驱、允许环、允许任意连接。所以图能表达的现实关系远比树丰富——社交关注、道路网络、任务依赖、状态转移，本质上都是图。

一句话区分：树是「无环 + 恰好 n−1 条边 + 连通」的图。图 = 顶点集 V + 边集 E，除此之外没有别的约束。

两种存储方式：邻接矩阵 vs 邻接表

这是图最基础的选择，直接决定算法复杂度。

存储空间判断 u→v 是否存在遍历 u 的所有邻居适合
邻接矩阵O(V²)O(1)O(V)（要扫一整行）稠密图、需要频繁判断边是否存在
邻接表O(V+E)O(degree(u))O(degree(u))稀疏图、需要频繁遍历邻居（绝大多数场景）
现实中的图几乎都是稀疏的——社交网络里一个人关注几百人，但全站有上亿用户，V² 完全不可行。所以默认选邻接表；只有当图非常稠密（E 接近 V²）时才考虑矩阵。
# 邻接表（最常用）：每个顶点挂一个邻居列表
graph = {
    "A": ["B", "C"],
    "B": ["C"],
    "C": ["A"],          # 有向图：C 也可以指回 A，形成环
}
# 带权图：邻居用 (to, weight) 元组
graph_w = {"A": [("B", 5), ("C", 2)], "B": [("C", 1)]}

# 邻接矩阵：matrix[u][v] = 权重 或 0/inf 表示无边
matrix = [[0, 5, 2], [0, 0, 1], [3, 0, 0]]

BFS 与 DFS：两种遍历哲学

维度BFS（广度优先）DFS（深度优先）
数据结构队列栈（或递归）
探索方式一层一层向外扩散一条路走到黑，走不通再回溯
能求什么无权图最短路径、最小步数、层序连通性、拓扑排序、环检测、路径本身
空间O(V)（队列可能很宽）O(V)（递归深度）
BFS 求最短路的直觉：从起点出发，第一次「扩散」到的点是距离 1，第二次是距离 2……因为是逐层推进，第一次到达某个点时走过的步数一定是最少的。这就像水池里的涟漪，最先被波纹触碰到的地方就是最近的。
# BFS：无权图最短距离
from collections import deque
def bfs_dist(graph, start):
    dist = {start: 0}
    q = deque([start])
    while q:
        u = q.popleft()
        for v in graph[u]:
            if v not in dist:          # 首次到达 = 最短距离
                dist[v] = dist[u] + 1
                q.append(v)
    return dist
visited 数组至关重要。图可能有环，不标记访问过的节点就会无限循环。入队（或入栈）时就标记，而不是出队时才标记，否则同一个节点可能被重复入队多次。

建图前先问清四个问题

  1. 边有方向吗？「关注」是有向的，「好友」是无向的。搞错会得到完全错误的答案。
  2. 边有权重吗？权重是什么含义？距离、时间、费用、容量——不同含义决定能否直接相加。
  3. 图有多大？稀疏还是稠密？决定用邻接表还是矩阵，以及 O(V³) 的算法能不能跑。
  4. 要的是「路径存在性」还是「最优路径」？前者 BFS/DFS 就够，后者才需要 Dijkstra 等。
最常见的建模错误：把「状态」当成节点、把「转移」当成边，却忘了状态里还包括隐含条件。例如迷宫问题里「位置 (x,y)」不是完整状态，如果钥匙会改变可达性，状态必须是 (x, y, 已获得的钥匙集合)。

🎯 面试问答

Q：邻接矩阵和邻接表怎么选？

A：看图的密度和主要操作。邻接矩阵判断「u 到 v 有没有边」是 O(1)，但空间 O(V²)，且遍历邻居要扫一整行 O(V)；邻接表空间 O(V+E)，遍历邻居只要 O(degree(u))，判断某条边则要扫邻居列表。现实中的图几乎都是稀疏的（社交网络、网页链接），所以默认用邻接表；只有图非常稠密、或需要频繁做「边是否存在」的判断时才用矩阵。

Q：BFS 为什么能求无权图的最短路？

A：因为 BFS 是逐层推进的：第 1 轮访问到的是距离 1 的点，第 2 轮是距离 2 的点，依此类推。由于所有边权相等（都算 1 步），第一次到达某个节点时所走的步数必然是最少的——不可能存在另一条更短的路，否则那条路上的点会更早被访问。这就像水池里的涟漪，最先被波纹触碰到的地方一定最近。注意：边权不等时 BFS 失效，要用 Dijkstra。

Q：visited 为什么要在入队时标记，而不是出队时？

A：如果出队时才标记，同一个节点可能在被发现后、被处理前，被多个不同的前驱重复加入队列多次，队列长度可能膨胀到 O(E) 甚至指数级。在入队（入栈）的瞬间就标记，能保证每个节点恰好进出一次，队列规模控制在 O(V)。这是 BFS/DFS 正确性和效率的关键细节。

Q：拓扑排序的前提是什么？有什么用？

A：前提：图必须是有向无环图（DAG）。有环意味着「A 依赖 B，B 又依赖 A」，无法排出先后顺序，此时拓扑排序会失败（Kahn 算法最后剩余的节点就是环上的节点）。用途：任务调度（有依赖关系的任务顺序）、编译顺序（源文件依赖）、课程安排（先修课约束）、构建系统（Makefile）。

Q：Dijkstra 为什么不能处理负权边？

A：Dijkstra 的正确性依赖一个前提：当一个节点从优先队列中取出时，它的距离已经是最短的，可以「永久确定」。这个前提由「所有边权非负」保证——因为任何绕道都必须经过额外的非负权边，只会让路径更长。一旦存在负权边，先取出的节点可能被后续经过负边的路径「刷新」成更短，而它已经被标记为已确定、不会再被更新，结果就错了。含负权边要用 Bellman-Ford（O(VE)，还能检测负环）。

Q：图的建模最容易犯什么错？

A：最典型的是状态定义不完整。图搜索题里，节点应该是「完整的状态」，而不是「表面上的位置」。例如迷宫问题，如果钥匙会改变可达区域，那么 (x, y) 不是完整状态，必须是 (x, y, 钥匙集合)；否则会出现「同一个格子第二次到达时情况已不同，却被 visited 挡住」的错误。其次是混淆有向/无向——「关注」是有向的，「好友」是无向的，搞错会得到完全错误的答案。
