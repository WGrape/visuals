线程 状态 与 调度流转

线程是「轻量级进程」，状态机和进程几乎同构，但多了一层「等别的线程」的等待态。本文用 Java 的六态模型把每个状态画清楚，并演示锁竞争时的状态流转，最后讲清用户态/内核态调度下状态机落在哪。

① 线程状态：比进程「轻」在哪

线程和进程共用同一套状态语义（就绪 / 运行 / 阻塞 / 终止），区别在于：

共享地址空间

同一进程内的线程共享代码、堆、全局变量；只有栈和寄存器是各自的。切换线程几乎不换页表，比进程切换便宜得多。

多了一个「等待」维度

线程除了等 I/O，还会等别的线程（锁、join、条件变量），于是有了 BLOCKED / WAITING / TIMED_WAITING 的细分。

调度对象可能不同

1:1 模型下线程就是内核调度实体；M:N（如 Go）下「用户态协程」由运行时调度，内核看不见它的状态。

本文是《线程架构》一文的互补篇：那篇讲用户级/内核级线程模型全景，本篇只聚焦「线程状态机 + 流转 + 锁竞争」，并用 Java 这一最具体的实现把状态讲透。

② 通用线程状态机

抛开具体语言，一个线程在其生命周期里经历：新建 · 就绪 · 运行 · 阻塞/等待 · 终止。和进程状态机同构，只是「阻塞」常常细分成「等锁」「等条件」。

关键认知：同一进程里一个线程进入 BLOCKED，不会拖垮其他线程（在 1:1 内核线程模型下，每个线程有独立内核栈与调度实体）。这是线程相比「多进程」最大的优势。

③ Java 的六态模型（最具体可对照）

JVM 在 java.lang.Thread.State 里定义了 6 个精确状态，跨平台一致，是学习线程状态最好的「标本」：

Java 把「就绪」和「运行」合并成同一个 RUNNABLE：JVM 不区分线程是在 CPU 上跑还是在就绪队列等 CPU，都算 RUNNABLE。所以在 Java 里你看不到单独的「RUNNING」态——这正是它和教科书五态模型最大的区别。

④ 三种「停住」到底差在哪

BLOCKED、WAITING、TIMED_WAITING 看上去都在「等」，但等的对象和唤醒方式完全不同，这是面试高频点：

BLOCKED

等监视器锁（synchronized）。别人正持有锁，你进不去同步块。锁一释放自动抢，不需要别人唤醒。

WAITING

等别的线程主动通知：wait()/join()(无参)/park()。必须别人 notify()/unpark() 或 join 的目标结束才醒。

TIMED_WAITING

带超时的等：sleep(ms)/wait(ms)/join(ms)/parkNanos。时间一到自动醒，也可被提前唤醒。

⑦ 线程状态机落在哪一层调度

状态机「长什么样」取决于线程是哪种实现模型：

1:1 内核级线程（Java/Linux 默认）

每个 Java 线程 = 一个内核 LWP（轻量级进程，clone(CLONE_THREAD)）。状态机就是进程的 R/S/D/T 那一套：阻塞态由内核管理，一个线程阻塞不影响同进程的其他线程。

// Linux 下看线程（与进程同态）
ps -eLf | head      # LWP 列 = 内核线程
cat /proc/PID/task/*/stat  # 每个线程一个 task

M:N 用户态调度（Go goroutine）

G（goroutine）由 Go 运行时调度，内核只看到 M（内核线程）。G 的状态：_Grunnable/_Grunning/_Gwaiting/_Gsyscall。一个 G 等在 channel/网络上时，M 不阻塞，去跑别的 G。

// goroutine 在等 channel 时进入 _Gwaiting
// 此时内核线程 M 仍可执行其他 _Grunnable 的 G
select { case <-ch: ... }  // G 让出，不阻塞 M
⚠️ N:1 用户级线程（green thread）的坑：多个用户线程映射到一个内核线程，若一个线程做阻塞系统调用，整个进程（所有用户线程）都被内核卡住。现代运行时（Go/Java）都已避开此模型。

⑧ 每个状态到底是什么意思

NEW

Thread 对象已建，但还没 start()。不占系统资源，不能重启已终止的线程。

RUNNABLE

已 start，正在 CPU 上执行或在就绪队列等 CPU（JVM 不区分二者）。native I/O 阻塞时 Java 仍报 RUNNABLE。

BLOCKED

想进 synchronized 块但锁被别人拿着。锁释放后自动竞争，无需别人唤醒。

WAITING

无限等待别的线程：wait()/join()(无参)/park()。需 notify()/unpark() 或 join 目标结束才醒。

TIMED_WAITING

带超时的等：sleep()/wait(ms)/join(ms)/parkNanos。超时自动醒，也可被提前唤醒。

TERMINATED

run() 正常结束或抛未捕获异常。终态，不可再 start()，需新建 Thread 对象。
