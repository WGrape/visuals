HBase 与 Cassandra：大数据存储怎么选

先看已有基础设施、读写形态和跨地域要求，再比较数据库内部机制。

🐘

HBase

依托 Hadoop/HDFS，按 RowKey 范围组织 Region，适合已有 Hadoop 生态的海量稀疏宽表。

🌐

Cassandra

对等节点与多数据中心复制，适合跨地域持续写入和按分区键访问的负载。

📏

共同前提

先定义分区键、访问模式、数据保留期、目标延迟及故障恢复要求，再用真实数据压测。

选型维度

问题更偏向 HBase更偏向 Cassandra
现有平台已有 HDFS、Hive、Spark 等 Hadoop 生态希望部署独立集群，跨数据中心复制是核心需求
主要访问按 RowKey 定位及连续范围扫描按分区键和预先设计的查询路径访问
一致性要求强调单行强一致读写需要按请求配置读写一致性级别，并评估延迟与可用性
容量风险检查 RowKey 热点、Region 分裂与 HDFS 运维成本检查分区热点、修复任务、跨机房流量与副本成本
不要仅凭“写得快”或“支持海量数据”决定产品。构造真实查询、冷热分布和故障场景，分别测吞吐、尾延迟、恢复时间与总成本。
