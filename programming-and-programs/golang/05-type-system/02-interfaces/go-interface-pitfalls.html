nil 接口陷阱、断言与类型开关、运行时表示与泛型取舍

接口interfaceGo易错点
nil陷阱 断言 表示 泛型 问答
接口在 Go 里是『值类型 + 类型信息』的组合。最常见的三个坑：nil 接口不等于 nil、断言 panic、类型开关和断言选错。

1nil 接口陷阱

type MyErr struct{}
func (e *MyErr) Error() string { return "boom" }

func do() error {
    var p *MyErr = nil
    return p // 返回的 error 接口 != nil！动态类型 *MyErr 非空
}

func main() {
    err := do()
    if err != nil {        // 进入这里：接口含 (类型=*MyErr, 值=nil)
        fmt.Println("got err:", err) // 输出 boom
    }
}
要点：判断『真错误』时返回 error 接口要直接写 return nil，不要返回 (*MyErr)(nil)。

2类型断言 vs 类型开关

v, ok := iface.(string) // 断言失败 ok=false，不 panic
fmt.Println(v, ok)

if s, ok := iface.(string); ok {
    fmt.Println("string:", s)
} else if n, ok := iface.(int); ok {
    fmt.Println("int:", n)
}

switch x := iface.(type) { // 类型开关，x 在分支里已收窄类型
case string:
    fmt.Println("len", len(x))
case nil:
    fmt.Println("it is nil")
default:
    fmt.Printf("%T\n", x)
}
  • 不确定类型 → 用『逗号 ok』两值断言，避免 panic。
  • 多个分支判断 → 用 switch x := i.(type)，比一串 if 断言清晰。

3接口的运行时表示

结构组成典型场景
eface(类型指针, 数据指针)空接口 interface{}
iface(itab, 数据指针)带方法的接口如 error
itab缓存接口与实现类型的匹配接口调用方法时查表
要点：每次接口方法调用都要经过 itab 查表；热点路径可持有具体类型避免装箱开销。

4空接口 vs 泛型怎么选

  • 容器 / 算法需要类型安全且 Go 1.18+ → 优先泛型，编译期检查、无装箱。
  • 需要异构集合（任意类型混装）→ 仍可用 interface{}，但遍历时要断言。
  • 只在边界处（反序列化、插件）用 interface{}，内部尽量收窄到具体类型。

5高频问答

问：为什么 fmt.Println 能打印任何类型？

因为参数就是 interface{}，内部再用 reflect 取出动态类型与值。

问：实现接口要写 implements 吗？

不用。Go 是结构化的：只要方法集匹配就自动实现，无需声明。
