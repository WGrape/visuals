SQLite 性能优化

事务批量写、WAL、索引、预编译语句、PRAGMA 调优等实践要点。

批量写WAL 与同步查询优化PRAGMA

① 用事务批量写

SQLite 的瓶颈常是 每条语句一次 fsync。把大量 INSERT 包进单个事务，速度可提升几个数量级：

BEGIN;
INSERT INTO log VALUES (...);  -- x 一万次
COMMIT;                        -- 一次持久化

② WAL 与同步模式

PRAGMA效果
journal_mode=WAL读写并发，性能与并发俱佳
synchronous=NORMALWAL 下几乎安全且更快（每 checkpoint 而非每写 fsync）
synchronous=FULL最安全但慢（断电不丢）

③ 查询优化

  • 用 整数主键 直接按 ROWID 定位，最快。
  • 为高频过滤/连接列建索引；避免 SELECT * 拉大行。
  • EXPLAIN QUERY PLAN 看是否走索引（出现 SCAN 即全表）。
  • 用 预编译语句（prepared statement / 参数化）避免重复解析 SQL。
EXPLAIN QUERY PLAN SELECT * FROM users WHERE email='a@b.c';

④ 关键 PRAGMA

PRAGMA journal_mode=WAL;
PRAGMA synchronous=NORMAL;
PRAGMA cache_size=-8000;      -- 约 8MB 页缓存
PRAGMA foreign_keys=ON;       -- 默认关，需手动开
PRAGMA busy_timeout=5000;     -- 锁等待
移动端/嵌入式：SQLite 在本地单文件场景下极快；真正要规避的是“高频小事务”和“并发写”。把写合并、读用 WAL，基本能覆盖 99%% 场景。
