📖 二、核心术语速查表

术语含义常见误解
命中 / 未命中key 存在于缓存并返回 / 不存在需回源把"key 存在但已逻辑过期"当成命中——那是逻辑过期方案，不算真正命中
回源未命中时穿透到数据源查询并回填以为回源只发生在 key 不存在时；key 被淘汰、过期、缓存宕机都会回源
命中率命中次数 / 总查询次数只看比例不看回源绝对量（见「收益与代价」）
TTLTime To Live，写入后经过多久失效与 TTI 混淆
TTITime To Idle，多久没被访问就失效与 TTL 混淆。热点数据用 TTI 可以长期驻留，用 TTL 会被无谓地清掉
淘汰 / 驱逐内存达到上限时按策略移除 key与"过期"混为一谈。过期是时间到了，淘汰是空间不够
穿透查询根本不存在的数据，缓存永远不命中与击穿混淆
击穿单个热点 key 过期瞬间，大量并发同时回源与穿透、雪崩混淆
雪崩大批 key 同时失效或缓存集群整体不可用只理解成"同时过期"，忽略了集群宕机这种更致命的情况
预热上线/大促前主动把数据灌进缓存只预热不校验，结果灌进去的 key 格式和线上读的不一致
大 key / 热 key单 key value 过大 / 单 key 访问量过高以为集群能自动分散——热 key 只会打到一个分片上

🔀 三、最容易混淆的四组概念

① 过期（expire） vs 淘汰（evict）
过期是时间维度——key 到了 TTL 就该失效；淘汰是空间维度——内存满了必须腾地方。 一个 key 可能还没过期就被淘汰（内存不足），也可能过期了还占着空间（没到删除时机）。 配置时要分别设：maxmemory + maxmemory-policy 管淘汰，EXPIRE 管过期。
② 穿透 vs 击穿 vs 雪崩
穿透＝查不存在的数据；击穿＝一个热点 key 刚好过期；雪崩＝一批 key 同时失效或缓存整体挂了。 判断口诀：看"有多少个 key"和"这个 key 到底存不存在"。 详见 缓存异常总览。
③ 本地缓存 vs 分布式缓存
本地缓存快（无网络）但每个实例一份、互不可见、容量受堆限制； 分布式缓存慢一点（一次网络 RTT）但全局一份、容量可独立扩展。 答案通常不是二选一，而是多级（见 多级缓存架构）。
④ 一致性 vs 可用性
缓存只要存在，就必然有"数据源已变、缓存未变"的窗口。 能做的只是缩短窗口（延迟双删、binlog 订阅）或缩小影响面（版本号、短 TTL）， 不可能做到"永远一致"。声称缓存能做到强一致的方案，通常要么没有真正并发写入，要么在某个角落仍有窗口。

🎤 五、面试怎么串起来讲

面试官问"讲讲缓存"，最稳的三段式：

📘
第一段：为什么用。"缓存是用一致性和复杂度换速度。我们先量化了回源成本和命中率，确认划算才上。"
第二段：怎么保证不出事。"三个经典问题：穿透用布隆过滤器和空值缓存，击穿用互斥重建或逻辑过期，雪崩用随机过期时间＋熔断降级。 一致性上我们用的是 Cache-Aside ＋延迟双删。"
第三段：怎么知道它健康。"看命中率、回源量、内存水位三个指标，命中率突降会告警； 另外定期排查大 key 和热 key。"

能主动补一句"缓存宕机时我们会降级成限流直查，避免回源打爆数据库"，基本就是满分答案—— 因为这句话说明你意识到了缓存是放大器而不只是加速器。
