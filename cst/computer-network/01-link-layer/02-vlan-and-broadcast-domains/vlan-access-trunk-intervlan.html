VLAN、Access 与 Trunk：广播域如何划分

用两个部门共用交换机的拓扑解释 802.1Q 标签、跨 VLAN 路由和常见配置故障。

同一台交换机可以有多个广播域

VLAN 在二层把一台交换机的端口或流量划入不同逻辑广播域。财务 VLAN 10 的广播不会因为同在一台物理交换机上就自动发给研发 VLAN 20。交换机查找 MAC 表时也要带上 VLAN 范围；同一 VLAN 中可以学习不同端口的 MAC。VLAN ID 是链路中的标识，不是 IP 子网本身：通常一个 VLAN 配一个 IP 子网以便管理，但两者属于不同层。

划分 VLAN 的目的可能是缩小广播范围、分隔部门或便于策略管理。不过 VLAN 隔离不能代替防火墙与主机权限控制；跨 VLAN 路由若放行所有流量，部门仍可在三层互访。需求应先说明哪些主机需要相互访问，再设计路由与访问控制。

Access 端口与 Trunk 链路

接普通终端的 Access 端口通常属于一个 VLAN，终端发送和接收的帧一般不带 802.1Q 标签。交换机在入口把它归入配置的 VLAN，转发到另一个 Access 端口时按该 VLAN 的成员范围处理。交换机之间要同时承载 VLAN 10 和 20 时，可用 Trunk；线上帧带 802.1Q 标签来标明所属 VLAN。标签位于源 MAC 与 EtherType 附近，含 VLAN ID 等字段。

Trunk 的允许 VLAN 列表必须两端一致。若一端允许 VLAN 20，另一端未允许，财务 VLAN 10 可能正常，研发 VLAN 20 却跨交换机不通。Native VLAN 的未标记帧处理也要一致，否则可能出现错域或安全问题。抓包时要确认网卡是否剥离了 VLAN 标签，不能仅凭本机抓包没有标签断定 Trunk 没打标签。

逐步推演

入口分类

Access 端口把无标签主机帧归入 VLAN 10。

跨交换机

Trunk 为 VLAN 10 的帧携带 802.1Q 标记。

出口交付

远端交换机只向 VLAN 10 成员端口送出。

跨域访问

去往 VLAN 20 的 IP 包必须经三层路由与策略。

一个跨交换机算例

交换机 S1 的端口 1 接财务主机 A（VLAN 10），端口 2 接研发主机 B（VLAN 20）；S1 与 S2 间为允许 10、20 的 Trunk。S2 上财务主机 C 在 VLAN 10。A 发 ARP 广播查 C 的 MAC，S1 只在 VLAN 10 范围传播，并通过 Trunk 带 VLAN 10 标签送到 S2；S2 再向 VLAN 10 的端口送出。B 在 VLAN 20，不应收到 A 的 ARP 请求。

如果 A 与 B 互访，单靠二层交换不够。A 会把跨网段的 IP 包交给 VLAN 10 的网关；三层设备按路由与策略决定是否转到 VLAN 20，然后重新封装。此时源和目的 IP 代表端到端通信，MAC 地址在跨路由时改变。

排障顺序

同 VLAN 不通，检查终端 IP/掩码、Access VLAN、Trunk 允许列表、MAC 学习与 ARP。只有跨 VLAN 不通时，重点查两侧网关接口是否启用、是否有路由、ACL 或防火墙是否放行。不要把 Trunk 正常等同于跨 VLAN 路由正常，它只传多种二层 VLAN。也不要把能 ping 网关等同于业务端口已通。

看现象时按“同交换机同 VLAN—跨交换机同 VLAN—跨 VLAN”三组测试，差异能缩小故障范围。若 VLAN 10 跨交换机通、VLAN 20 不通，优先查 Trunk 允许列表及两侧 VLAN 20 配置，少去改全网路由。

VLAN 标签与安全边界

802.1Q 标签携带 VLAN ID，但不会加密或验证业务身份。把终端可控端口误配为 Trunk，或对 Native VLAN 处理不一致，会扩大可进入的 VLAN 范围。接入端口应按需要限制类型，交换机管理面也要单独保护。VLAN hopping 等风险具体取决于交换机配置，不能把所有带标签帧都简单看作攻击成功。

若使用 VXLAN 等 overlay，外层又加入新的网络封装；物理交换机看到的可能是隧道端点而非原始租户 MAC。此时故障定位要区分 underlay 物理网络和 overlay 虚拟广播域，不要用一个 VLAN ID 解释整个数据中心。

配置变更如何验收

变更前记录端口所属 VLAN、Trunk 允许列表、网关地址和 ACL。变更后分别测试同 VLAN 单播、ARP 广播范围、跨 VLAN 业务端口和不能访问的目标。对不应互通的两部门，拒绝测试与放行测试同样重要。若只测一个 ping 成功，不能证明隔离和业务流量都符合预期。

搬迁主机后还要检查交换机 MAC 表是否收敛到新端口，以及 DHCP 地址是否来自正确 VLAN。旧 MAC 表项、错误 DHCP 中继或 DNS 缓存都可能使“换端口后不通”看起来像同一个故障。

Native VLAN 的坑：Trunk 上 Native VLAN（默认 VLAN 1）的帧不打 tag。两端 Native VLAN 不一致会导致 VLAN 1 的流量“串”到另一个 VLAN —— 既是故障源也是安全漏洞（VLAN hopping 攻击）。最佳实践：① 两端显式配置一致；② 把 Native VLAN 改成一个不使用的 ID；③ 开启 vlan dot1q tag native（全局打 tag）。

VLAN 配置与验证

# Linux 上创建 VLAN 子接口
ip link add link eth0 name eth0.100 type vlan id 100
ip addr add 192.168.100.1/24 dev eth0.100
ip link set eth0.100 up

# 看 VLAN 配置
ip -d link show eth0.100         # -d 显示 vlan 协议与 id
cat /proc/net/vlan/config

# 网桥 VLAN 过滤（现代做法）
ip link add br0 type bridge vlan_filtering 1
bridge vlan add dev eth0 vid 100
bridge vlan show

# 抓带 tag 的帧
tcpdump -i eth0 -nn -e 'vlan 100'
tcpdump -i eth0 -nn -e 'vlan and ip'

# 测试 VLAN 间是否隔离
arping -I eth0.100 192.168.100.5

VLAN 间路由与故障排查

VLAN 隔离广播域，所以不同 VLAN 之间二层不通，要互通必须走三层（路由器或三层交换机）。三种做法：

方式做法优点缺点
单臂路由（Router-on-a-Stick）路由器一个口做 Trunk，起子接口省端口所有跨 VLAN 流量挤一条链路，带宽瓶颈
三层交换机 SVI交换机上为每个 VLAN 起 VLANIF 接口线速转发，推荐需要三层交换机
每条 VLAN 一条物理链路路由器多口分别接不同 VLAN简单直观浪费端口，规模受限
  • VLAN 1 不要瞎用：它是默认 VLAN、默认 Native VLAN，且很多管理协议（STP、CDP）默认跑在上面。用业务 VLAN 承载数据，管理 VLAN 单独一个。
  • VLAN 数量规划：4094 个看似很多，但要考虑 STP 实例数（每 VLAN 一个 STP 实例会拖垮设备，所以用 MSTP 把多个 VLAN 映射到一个实例）。
  • 常见故障 1：配了 VLAN 但不通 → 检查中间所有 Trunk 是否都放行了该 VLAN（交换机默认可能只放 VLAN 1）。
  • 常见故障 2：部分 VLAN 通部分不通 → Native VLAN 不匹配，或 Trunk 的 allowed VLAN 列表不一致。
  • 常见故障 3：能 ping 通网关但访问不了别的 VLAN → 网关没开路由，或对方主机防火墙拦了。
  • 私有 VLAN（PVLAN）：同一网段内再隔离（如酒店/IDC 多租户），isolated 端口之间不能互访但都能访问网关。
VLAN 能隔离攻击吗？

能隔离广播和二层泛洪，但跨 VLAN 的三层流量仍会被防火墙/路由器看到。真正的安全隔离要靠 ACL 和防火墙策略，VLAN 只是最基础的划分手段。另外 VLAN hopping 攻击（利用 Native VLAN 或 DTP 自动协商）可以跨越 VLAN，需关闭 DTP、固定端口模式。

为什么服务器网卡要打 tag？

服务器需要承载多个 VLAN 的业务（如管理网、业务网、存储网各一个 VLAN）。在网卡上起多个 VLAN 子接口，一根线就能跑多个逻辑网络，节省网卡和交换机端口。虚拟化/K8s 环境尤其常见。

自检

把两台主机放在不同 VLAN，仅配置 Trunk 就能互相通信吗？

不能。Trunk 只传送多个二层 VLAN；跨 VLAN 的 IP 通信还需要三层网关、路由和相应放行策略。
