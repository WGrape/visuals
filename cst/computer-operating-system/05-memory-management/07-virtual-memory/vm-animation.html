什么是虚拟内存？

核心概念：虚拟内存是操作系统提供的一种内存管理技术，它为每个进程提供一个连续、独立且看似无限的地址空间。

多级页表设计

为什么多级？单级页表占用太大！多级页表只为使用的地址分配页表，大幅节省内存。

动画演示：两级页表地址翻译

示例（32位系统）：
地址 = [高10位:L1索引 | 中10位:L2索引 | 低12位:Offset]
优点：未使用的区域不需要分配二级页表！

地址转换的每一步都值得看清楚

程序用的是虚拟地址，内存条只认物理地址，中间的翻译由 MMU 完成：把地址拆成「页号 + 页内偏移」，查页表得到物理页框，再拼上偏移。为了不让每次访存都多查几次内存，硬件用 TLB 缓存最近的转换结果。

页 / 页框虚拟内存的固定块（通常 4KB）/ 物理内存的对应块
页表项 PTE记录物理页框号 + 权限位（读写执行、用户/内核、存在位）
TLB地址转换缓存，命中则几乎零开销
多级页表只为已使用区域建表，节省内存
缺页异常页表项无效时触发，由内核补页或终止进程
页表隔离每进程独立页表，是内存保护的基础
TLB 命中与未命中的两条路径

机制之外：内存管理的整体图景

① 为什么需要虚拟内存

  • 隔离：每个进程看到独立地址空间，互不可见。
  • 简化链接与装载：每个程序可以用相同的起始地址。
  • 超越物理内存：不常用的页换出到磁盘（swap）。
  • 内存映射文件：把文件直接映射到地址空间（mmap）。
  • 共享：同一份库代码可被多进程共享（节省内存）。

② 页面置换

  • 内存不足时要选一页换出：FIFO、LRU、LFU、Clock 等。
  • Linux 用改进的 LRU（活跃/非活跃链表 + 二次机会）。
  • 抖动（thrashing）：工作集大于内存，反复换入换出，性能崩溃。
  • 对策：减少工作集、加内存、限制并发、关闭 swap 或调 swappiness。

③ fork 与 COW

  • fork 时不复制内存，只是把页表标记为只读共享。
  • 父子任何一方写入 → 触发 COW 缺页 → 复制该页 → 各自可写。
  • 所以 fork 很快，代价随「实际写入量」产生。
  • Redis 的 BGSAVE 正是依赖 fork + COW。

④ 大页与性能

  • 4KB 页 + 大内存 → 页表巨大、TLB 未命中频繁。
  • HugePage（2MB/1GB）：减少页表项与 TLB 压力。
  • THP（透明大页）自动聚合，但可能带来延迟抖动与内存碎片。
  • 数据库、JVM 大堆常显式配置 HugePages 并关闭 THP 的碎片整理。

深入自检

为什么每个进程都能用同样的地址（如 0x400000）？

因为它们用的是虚拟地址，各自的页表把相同虚拟地址映射到不同物理页。链接器只需按固定的虚拟布局生成代码，装载时由内核建立各自的映射。这就是虚拟内存带来的「地址空间独立」，也是 ASLR（地址随机化）能工作的基础。

TLB 未命中到底有多贵？

在 4 级页表的 x86-64 上，一次 TLB 未命中可能需要额外访问 4 次内存来遍历页表（虽然各级页表项通常被缓存，但仍可能多出几十到几百个周期）。对访存密集的程序，TLB 命中率与 Cache 命中率同样重要，这也是大页能带来可观收益的原因。

fork 之后父子进程的内存是共享的吗？

逻辑上是「写时复制共享」：fork 瞬间双方共享同一份物理页且都标记为只读；任何一方写入时，内核复制那一页并交给写方。所以读多写少的场景几乎不产生额外内存，但一旦大量写入就会真的复制（这也是 Redis BGSAVE 期间内存可能上涨的原因）。

什么是内存抖动，怎么发现？

抖动指系统的工作集超过可用内存，导致页面被反复换出又换入，CPU 大量时间花在缺页处理上，实际吞吐接近零。识别信号：si/so（vmstat 换页）持续非零、磁盘 IO 高但业务 IO 低、系统响应极慢。解决：加内存、减少并发进程、降低 swappiness、限制单个进程的内存用量。

mmap 和普通 read 有什么区别？

read 是「把数据从内核缓冲拷贝到用户缓冲」；mmap 是「把文件页直接映射到用户地址空间」，访问时按需触发缺页调入，省一次拷贝且可随机访问。但 mmap 的缺页开销、回收时机不可控，小文件的顺序读通常 read 更快。数据库类程序常用 mmap 或自己管理缓冲池（如 InnoDB）。

为什么有时候明明有空闲内存，程序还是被 OOM Kill？

可能原因：① 空闲的是可回收的 page cache，但内核判断无法及时满足分配；② cgroup/容器设置了内存上限，进程触达的是自己的 limit 而非整机内存；③ 内存碎片导致无法分配连续页；④ OOM Killer 按打分选择牺牲进程，未必是占用最多的那个。排查要看 dmesg 的 OOM 记录、容器的 memory.events 与 cgroup 统计。
