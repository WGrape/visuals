1. 物理内存碎片是什么

内核分配高阶页框时，通常需要一段连续物理页。即使总空闲页数足够，若空闲页散落在多个不相邻位置，也可能无法满足请求。这是物理页层面的外部碎片；按固定大小或 2 的幂次分配时，实际用量小于拿到的块大小，则会产生内部碎片。

假设每格代表一个物理页： [已用][空闲][已用][空闲][已用][空闲][空闲][已用] 空闲共 4 页，却只有一段连续 2 页；申请连续 4 页会失败或触发规整。

普通用户进程的连续虚拟地址不一定要求连续物理页；透明大页、部分 DMA 或其他高阶页框分配才更直接受物理碎片影响。具体失败路径还取决于可回收页、内存区域和分配标志，不能仅凭总空闲量断言一定触发 OOM。

2. 伙伴系统：分裂与合并

Linux 以伙伴系统管理物理页框。空闲块按 order 分类，order 为 n 的块有 2n 个连续页；没有合适块时可以分裂更大块，释放时只有同阶且空闲的伙伴才能合并。它能快速管理页框，但相邻页若被占用，分散的小块就无法凭合并得到大块。

分配 4 页：查 order 2 → 若无空闲块，分裂 order 3 的 8 页块。 释放 4 页：检查相邻的同阶伙伴 → 两者都空闲才合成 8 页块。 若伙伴仍在使用，空闲总量增加也无法合成连续 8 页。
关键取舍：伙伴系统通过分裂与合并减少碎片，但 3 页需求通常会占用 4 页块，形成内部浪费；长期混合不同生命周期的页仍会形成外部碎片。

3. 内核对象缓存与内部碎片

内核需要频繁分配 inode、dentry 等对象。Slab/SLUB 等对象缓存按对象类型或大小管理槽位，复用已分配的页，降低小对象分配成本。它处理的是内核对象，与伙伴系统管理物理页框的层级不同。

伙伴系统提供物理页 → 对象缓存把页划成槽位 → 相同大小的内核对象复用槽位。 对象释放后槽位可重用；只有满足回收条件的空页才能交还页框分配器。

固定槽位减少对象间的外部碎片，却可能留下槽位内部浪费和未完全释放的对象页。它不能直接保证高阶页框分配成功。

4. 页面迁移与内存规整

当需要连续物理页时，Linux 可尝试把可移动页迁移到其他空闲页，调整页表映射，从而聚合出较大的连续空闲区域。内核也按页的可迁移性组织页块，减少不可移动页把区域切碎的机会。

规整前： [可移动][空闲][不可移动][可移动][空闲][空闲] 迁移可移动页后：部分空闲页得以相邻；不可移动页仍可能阻断连续空间。

规整有复制、页表更新和延迟成本，也不能移动所有页。透明大页等场景可能触发后台或直接规整；是否值得开启相关策略，应按业务延迟和高阶分配需求判断。
