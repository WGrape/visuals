复杂度类 P / NP / PSPACE：可计算之后的关键问题

一个问题即使可判定，也可能慢到无法使用。复杂度理论按「需要多少时间和空间」给问题分类，其中最著名的悬问是 P 是否等于 NP。

核心速览

P

确定性多项式时间可解：排序、最短路、匹配

NP

解可在多项式时间验证：SAT、TSP、背包、团

NP 完全

NP 中最难的一族，任一获多项式算法则 P=NP

PSPACE / EXP

多项式空间 / 指数时间；包含关系 P ⊆ NP ⊆ PSPACE ⊆ EXP

复杂度类全景

P 与 NP：求解 vs 验证

理解 NP 的关键是「验证」而非「求解」：

P（Polynomial）

能在多项式时间找到答案。n 增大时，运行时间按 nᵏ 增长。

NP（Nondeterministic Polynomial）

给定一个候选解，能在多项式时间验证它是否正确。等价于「非确定性图灵机多项式时间可解」。

为什么叫「非确定性」

可以想象机器能同时尝试所有分支，只要有一条路径接受就接受——这是「猜测 + 验证」的抽象。

举例：数独

求解很难（试错组合爆炸），但给定一个填好的九宫格，检查是否合法只需 O(n²) → 数独在 NP 中。

# 验证 vs 求解的对比：以「子集和」为例
# 问题：给定 n 个数，是否存在子集其和恰好为 T？

def verify(nums, T, candidate):        # 验证：多项式时间 O(n)
    return sum(nums[i] for i in candidate) == T

def solve_bruteforce(nums, T):         # 求解：枚举 2ⁿ 个子集，指数时间
    n = len(nums)
    for mask in range(1 << n):
        if sum(nums[i] for i in range(n) if mask >> i & 1) == T:
            return True
    return False

# 这就是 NP 的本质：验证容易、搜索困难
# 注意：子集和虽有 O(nT) 的伪多项式 DP 解，但 T 很大时仍不可行
# （它是 NP 完全但「弱」NP 完全的，因为存在伪多项式算法）
P vs NP 的通俗表述：「如果验证一个答案很快，那么找到答案也一定很快吗？」直觉上显然不是（做数学题比检查答案难得多），但七十余年无人能证明。这就是千禧年大奖难题之一，奖金百万美元。

NP 完全：NP 中最难的一族

定义：语言 L 是 NP 完全的，当且仅当 ① L ∈ NP；② 任意 NP 问题都能多项式归约到 L（L 是 NP-hard）。

关键结论：所有 NP 完全问题在多项式意义下等价——只要有一个被攻破，全部都被攻破（P = NP）。这就是为什么「证明你的问题是 NP 完全的」是一个有力信号：别再找通用精确算法了。

证明 NP 完全的标准流程

  1. 证明 L ∈ NP：给出一个候选解（证书），说明能在多项式时间验证；
  2. 选一个已知的 NP 完全问题 A（如 3-SAT、顶点覆盖、子集和）；
  3. 构造多项式时间的归约 f：x ∈ A ⟺ f(x) ∈ L；
  4. 证明归约的正确性（两个方向）与多项式时间。
# 经典归约：3-SAT ≤ 团问题（CLIQUE）
# 给定 3-CNF 公式 φ，有 m 个子句，每个 3 个文字。
# 构造图 G：
#   · 每个子句的每个文字建一个顶点（共 3m 个）
#   · 两个顶点之间连边 ⟺ 它们来自不同子句 且 不互补（不是 x 与 ¬x）
# 结论：φ 可满足 ⟺ G 有大小为 m 的团
#
# 证明（⟹）：若 φ 可满足，每个子句各取一个为真文字，
#            这 m 个文字互不互补（否则矛盾）且来自不同子句 → 构成 m 团
# 证明（⟸）：若 G 有 m 团，因同子句内顶点无边，这 m 个点必来自 m 个不同子句，
#            且互不互补 → 可以给这些文字赋真，使 φ 满足
# 构造规模 O(m²)，多项式时间 ∎
常用「归约源」适合归约到
3-SAT最通用，几乎所有组合问题
顶点覆盖 / 独立集 / 团图论问题
子集和 / 划分数值与调度问题
哈密顿路径 / TSP路径与排列问题
图着色分配与划分问题

# 顶点覆盖的 2-近似（经典且优雅）
def vertex_cover_2approx(edges):
    """反复任取一条边，把它的两个端点都加入覆盖，删掉所有被它们覆盖的边"""
    cover = set()
    E = [tuple(e) for e in edges]
    while E:
        u, v = E.pop()
        if u in cover or v in cover: continue
        cover.add(u); cover.add(v)
        E = [(a, b) for a, b in E if a not in (u, v) and b not in (u, v)]
    return cover
# 近似比 = 2：每次选的边互不相交，最优解至少要取每条边的一个端点（≥ |M|），
# 而算法取了 2|M| 个点 ⟹ 不超过最优解的 2 倍
「NP 完全」不等于「实践中不可解」：工业实例往往有结构，现代 SAT 求解器（CDCL + 子句学习 + 启发式）能处理百万变量；TSP 的 Concorde 求解器能精确解数千城市。理论是最坏情况，实践取决于实例。

常见误区

  • 「NP 就是非多项式」——错。NP = Nondeterministic Polynomial（非确定性多项式），不是 Non-Polynomial。NP 完全问题也可能有多项式解（若 P=NP）。
  • 「NP 完全问题一定没有高效解」——只在 P≠NP 时成立，而这是未证明的。更准确的说法是「目前没有已知的多项式算法」。
  • 「近似算法能解决一切」——有些问题难以近似（如一般 TSP 除非 P=NP 否则无常数近似，团问题难近似到 n^(1−ε)）。
  • 「伪多项式 = 多项式」——子集和的 O(nT) DP 是伪多项式（依赖数值 T 而非输入位数），T = 2ⁿ 时仍指数。
  • 「P 问题一定比 NP 完全快」——复杂度是渐近的：O(n¹⁰⁰) 的 P 问题实际远慢于 O(1.1ⁿ) 但 n 很小的指数算法。

🎯 常见问法与答题要点

Q：P 和 NP 的区别是什么？NP 为什么不是「非多项式」？

A：P = 确定性图灵机多项式时间可求解的问题；NP = 给定一个候选解，能在多项式时间验证其正确性（等价于非确定性图灵机多项式时间可解）。关键：NP 是 Nondeterministic Polynomial 的缩写，不是 Non-Polynomial。所有 P 问题都在 NP 中（能求解就能验证），但反过来是否成立（P = NP？）至今未解。记住：P 关乎「找答案」，NP 关乎「验答案」。

Q：什么是 NP 完全？证明某问题是 NP 完全有什么意义？

A：NP 完全指满足两条：① 属于 NP（解可多项式验证）；② NP-hard——所有 NP 问题都能多项式归约到它（它至少和 NP 中任何问题一样难）。意义：① 所有 NP 完全问题难度等价——任一获得多项式算法就证明 P = NP；② 它是停止寻找通用精确算法的信号，应转向近似、参数算法、启发式或利用实例结构；③ 它解释了为什么这么多看似无关的问题（SAT、TSP、背包、图着色）几十年来都无人找到高效算法——它们本质上是同一个难题。

Q：P 是否等于 NP？如果 P = NP 会发生什么？

A：至今未解，是千禧年大奖难题之一（百万美元奖金），多数专家倾向于 P ≠ NP。若 P = NP：① 现代公钥密码学崩塌——RSA 的因数分解、ECC 的离散对数都在 NP 中，将变得可解；② 但优化、调度、药物设计、电路设计、定理证明将迎来革命——所有「验证容易」的问题都变得「求解也容易」。若 P ≠ NP（更被相信）：NP 完全问题确实没有多项式算法，近似与启发式是唯一出路。注意：即使 P = NP，也可能只是存在渐近意义上的多项式算法而常数巨大，实践中未必更快。

Q：遇到 NP 完全问题，工程上该怎么办？

A：五条实用路线：① 近似算法——多项式时间且有近似比保证（如顶点覆盖 2-近似、集合覆盖 ln n-近似）；② 参数算法（FPT）——若某参数 k 小，复杂度 f(k)·n^O(1)（如顶点覆盖按解大小参数化）；③ 启发式/元启发式——贪心、局部搜索、模拟退火、遗传算法，无保证但实践常好；④ 精确算法 + 剪枝——分支限界、状态压缩 DP（n ≤ 25）、SAT/SMT 求解器（工业实例常可解）；⑤ 利用特殊结构——限制到树、平面图、有界树宽等子类，可能有多项式解。核心原则：先确认是 NP 完全，再按实例特征选策略，别死磕通用精确解。

Q：归约的方向到底怎么记？

A：记 A ≤ B 表示「A 不比 B 难」，即用 B 的解法可以造出 A 的解法。要证明 B 是难的（NP-hard），就要把已知的难题 A 归约到 B：A ≤ B。逻辑是——若 B 容易，则 A 也容易，与 A 已知是难的矛盾，故 B 也难。易错点：直觉上会想「把 B 变成 A」，方向正好相反；正确做法是构造一个多项式变换 f，使 x ∈ A ⟺ f(x) ∈ B，也就是「用解 B 的机器来解 A」。助记：证难时，箭头从「已知难题」指向「目标问题」。

Q：为什么「NP 完全」不等于「实践中不可解」？

A：因为复杂度是最坏情况分析，而真实实例往往有结构。典型反例：① SAT——理论上是第一个 NP 完全问题，但现代 CDCL 求解器（冲突驱动子句学习 + 变量选择启发式 + 随机重启）能解百万变量级的工业实例，广泛用于硬件验证、软件验证、依赖求解；② TSP——Concorde 求解器用分支切割法能精确求解数千城市的实例；③ 许多图问题在稀疏图、平面图、有界树宽上多项式可解。结论：NP 完全只说明「没有通用的高效算法」，不排除「针对实际实例的有效解法」。

Q：什么是伪多项式时间？它和多项式时间有什么不同？

A：多项式时间按输入长度（比特数）度量；伪多项式时间按输入数值的大小度量。例如子集和的 O(nT) DP：n 是元素个数、T 是目标和。若 T = 2ⁿ，则输入长度只有 n + log T = O(n) 比特，但算法要 2ⁿ 步——是指数的。只有当 T 是 n 的多项式时，O(nT) 才是多项式的。强 NP 完全问题（如 TSP、3-SAT）即使数值很小也困难，不存在伪多项式算法（除非 P=NP）；弱 NP 完全问题（子集和、背包）有伪多项式 DP，数值小时实际可用。

Q：PSPACE 和 NP 是什么关系？它包含哪些典型问题？

A：NP ⊆ PSPACE——因为多项式时间的计算不可能使用超过多项式的空间；反向是否成立未知（一般认为 PSPACE 严格更大）。PSPACE 是「多项式空间可解」的问题类，允许指数时间。典型 PSPACE 完全问题：① QBF/TQBF（量词布尔公式：∃x∀y∃z… 是否可满足）——它是 NP 中 SAT 的量词化推广；② 广义棋类（n×n 棋盘上的围棋、国际象棋的必胜判定）；③ 规划问题（在有限状态空间中寻找动作序列）。直觉：NP 是「存在一条路径」，PSPACE 是「在博弈树中搜索」——后者需要记忆与回溯，空间成为瓶颈。
