第 12 章 · 分治

比较叶子代价与合并代价

把分治写成 T(n) = aT(n/b) + f(n)，用主定理三种情形（叶子主导、逐层相当、根主导）直接读出复杂度，并识别它不适用的场景。

分治的代价是一句递推式

分治把一个规模 n 的问题分成 a 个规模 n/b 的子问题，再用 f(n) 的代价把子问题的解合并起来，于是复杂度就是递推式：

T(n) = a·T(n/b) + f(n)        a ≥ 1, b > 1
  • a：子问题个数（归并排序 a=2，二分查找 a=1，Strassen a=7）。
  • b：规模缩小倍数（通常是 2）。
  • f(n)：分解 + 合并的总代价（归并排序是 O(n) 的合并，二分查找是 O(1) 的比较）。

写递推式时最容易错的是 f(n)：它不含递归调用本身，只含「拆」和「合」这两步的代价。

主定理：比较合并代价与子问题总量

令 c = logb a，也就是递归树叶子层的量级。主定理说：T(n) 由 nc 与 f(n) 谁更大决定。

情形条件结论直觉
情形 1f(n) = O(nc−ε)，ε > 0T(n) = Θ(nc)叶子层主导：合并很便宜，代价全在递归到底
情形 2f(n) = Θ(nc)T(n) = Θ(nc log n)每层代价相当：树高 log n，每层都贡献一份
情形 3f(n) = Ω(nc+ε) 且 a·f(n/b) ≤ k·f(n)（k<1）T(n) = Θ(f(n))根节点主导：分解合并就够贵了
归并排序：a=2, b=2, c=1, f(n)=Θ(n) → 落在情形 2 → T(n) = Θ(n log n)。
二分查找：a=1, b=2, c=0, f(n)=Θ(1) → 情形 2 → Θ(log n)。

常见递推式速查

递推式对应算法结论
T(n) = 2T(n/2) + Θ(n)归并排序Θ(n log n)
T(n) = T(n/2) + Θ(1)二分查找Θ(log n)
T(n) = 2T(n/2) + Θ(1)树上的平衡遍历Θ(n)
T(n) = 7T(n/2) + Θ(n²)Strassen 矩阵乘法Θ(nlog₂7) ≈ Θ(n2.81)
T(n) = 3T(n/2) + Θ(n)Karatsuba 大整数乘法Θ(n1.585)
T(n) = T(n−1) + Θ(n)最坏快排、插入排序不适用主定理，Θ(n²)

主定理不适用的三种情况

  1. 子问题规模不是等分的：如 T(n) = T(n−1) + T(n/2) + n，b 不固定，用递归树或 Akra–Bazzi 通式。
  2. 每种情形之间恰好卡在边界：比如 f(n) = Θ(nc log n)，属于情形 2 的扩展，结论是 Θ(nc log² n)，不能硬套基本形式。
  3. 情形 3 的正则条件不满足：f(n) 增长得不够平滑（例如振荡函数），此时主定理给不出结论。

更通用的工具是 Akra–Bazzi 方法：解出满足 Σ aᵢbᵢp = 1 的 p，则 T(n) = Θ(np(1 + ∫₁ⁿ f(u)/up+1 du))。考试与面试里掌握主定理三种情形 + 递归树足够。

最容易踩的两个坑

  • 把平均情况和最坏情况混在一句递推式里：快排平均是 T(n) = 2T(n/2) + Θ(n)，最坏是 T(n) = T(n−1) + Θ(n)。写递推式前先声明分析的是哪种情况。
  • 忘记 f(n) 里还包含分解代价：快排的划分本身是 Θ(n)，不是 Θ(1)。写成 2T(n/2)+Θ(1) 会得出 Θ(n) 的错误结论。
