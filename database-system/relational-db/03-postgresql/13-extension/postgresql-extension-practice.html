理论页讲了 PG 扩展机制。本页给实操：CREATE EXTENSION、用 pg_stat_statements 抓慢 SQL、常用扩展清单与排障。

01安装与启用扩展

扩展以 contrib 包形式提供，先装系统包再在库内 CREATE EXTENSION。

# 系统层（Debian 举例）
apt-get install postgresql-16-contrib

# 库内启用扩展（每个库独立）
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
CREATE EXTENSION IF NOT EXISTS pgcrypto;
CREATE EXTENSION IF NOT EXISTS postgis;

# 查看已装扩展
SELECT extname, extversion FROM pg_extension;
要点：扩展是按数据库启用的，不在 template1 里建就不会随新库自动有；想默认有，在 template1 建一次。

02pg_stat_statements：抓慢 SQL

这是性能排查第一扩展，聚合所有 SQL 的执行统计，定位慢查询和全表扫描。

-- 先确保 postgresql.conf 加载
shared_preload_libraries = 'pg_stat_statements'
pg_stat_statements.max = 10000
pg_stat_statements.track = all

-- 重启/reload 后查询最耗时 SQL
SELECT query, calls, total_exec_time,
       mean_exec_time, rows
FROM pg_stat_statements
ORDER BY total_exec_time DESC
LIMIT 10;

-- 重置统计（对比前后）
SELECT pg_stat_statements_reset();
  • track=all 才统计 PREPARE/PL/pgbench 类；默认 top 只统计顶层
  • total_exec_time 是累计值，看增量要 reset 后对比
  • 结合 EXPLAIN (ANALYZE, BUFFERS) 看单条 SQL 的执行计划
要点：pg_stat_statements 是 shared 内存结构，max 越大占内存越多；生产设 5000~10000 足够，别贪大。

03常用扩展清单

扩展用途
pg_stat_statementsSQL 统计/慢查询
pgcrypto加解密/hash
postgis空间地理
pg_trgm模糊搜索/trigram 索引
hstore键值对类型
pg_hint_plan强制执行计划 hint
pg_repack在线表重组（替代 VACUUM FULL 锁表）
  • 模糊搜索场景用 pg_trgm + gin 索引，LIKE '%关键词%' 也能走索引
  • 大表重组用 pg_repack，避免 VACUUM FULL 长时间锁表
  • pg_hint_plan 是最后手段，优先让优化器自己选

04排障清单

  • CREATE EXTENSION 报 could not open extension control file => 系统 contrib 包没装
  • pg_stat_statements 查不到数据 => shared_preload_libraries 没加载，需重启
  • 扩展版本升级：ALTER EXTENSION xxx UPDATE; 但要注意兼容性
  • 想禁用某扩展先确认没有对象依赖它，否则 DROP 失败
问：pg_stat_statements 统计的 query 是怎么归一化的？

PG 把字面量（常量值）替换成 $1/$2 这样的占位符，所以同一模板不同参数的 SQL 会聚合到一条，便于看这类查询的总体开销而非单条。
