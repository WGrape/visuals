多模态大模型架构（VLM）

聚焦架构选型：视觉编码器、投影器和语言模型如何组合，分别带来怎样的视觉 token 成本、分辨率能力与训练取舍。

01三大组件的选型变量

① 视觉编码器

比较 CLIP / SigLIP 等视觉主干的分辨率、特征质量和视觉 token 数；冻结可降低训练成本，微调可适配特殊图像域。

② 投影器 (Projector)

MLP 实现简单，但通常保留更多视觉 token；Q-Former、Resampler 可压缩视觉序列，代价是额外参数与训练复杂度。

③ 语言模型

选定 LLM 的上下文窗口、推理成本与指令能力后，再决定视觉 token 预算；高分辨率、多图任务尤其受上下文长度约束。

02代表架构对比

BLIP-2 / Q-Former

用 Q-Former（一组可学习 query）从 ViT 抽取固定数量视觉 token，再喂 LLM。轻量、视觉 token 少。

LLaVA

ViT + 一个线性/MLP Projector + LLM，结构极简。视觉 token 数 = patch 数（较密）。开源社区事实标准。

Qwen-VL

ViT + 交叉注意力 Resampler 压缩视觉 token，支持高分辨率与多图、 grounding（框选定位）。

区别主要在两点：投影器形态（MLP 简单但 token 多 / Q-Former 压缩但多训一层）与视觉 token 数量（影响 LLM 上下文长度与成本）。

03VLM 的部署与能力代价

输入变长

一张图动辄几百个视觉 token，极大的上下文与 KV Cache 压力（呼应《推理部署》）。

分辨率权衡

切得越细看越清，但 token 越多越贵；动态分辨率/分块是常见解法。

幻觉更顽固

VLM 易「看见不存在的物体」，因视觉特征与文本生成弱耦合。

评测更杂

除对话外还有 OCR、定位、图表理解、视频时序等多维能力。

04架构选型速记

统一骨架

ViT 编码 → Projector 对齐 → LLM 生成；视觉 token 拼到文本序列后。

CLIP 角色

对比学习对齐图文空间，是 VLM 与文生图的共同底座。

架构差异

主要是投影器（MLP vs Q-Former vs Resampler）与视觉 token 数。

两阶段训练

先对齐 Projector（冻 LLM），再微调（解冻 LLM）做对话。

交互式切块、CLIP 匹配、视觉 token 输入和两阶段训练过程见《多模态大模型如何识别图片》。

第一层 · 三件套与识别信号

所有 VLM（视觉语言模型）都是同一个骨架：视觉编码器 + 投影层（Connector）+ LLM 主干。差异全在三者怎么选、怎么连、怎么训。

组件作用常见选择输出
视觉编码器把图像变成一组向量CLIP ViT、SigLIP、DINOv2、EVA-CLIPN 个 patch token（如 576 个）
投影层 Connector把视觉 token 映射到 LLM 的语义空间MLP（2 层）、Q-Former、Pixel Shuffle、ResamplerM 个 token（可压缩到 64~144）
LLM 主干接收「视觉 token + 文本 token」做推理LLaMA/Qwen/Vicuna/InternLM文本输出
  • 关键数字：一张图要多少个 token？：ViT-L/14 @336px → 24×24 = 576 个 patch；若用 Pixel Shuffle 压缩 4 倍 → 144 个；若用 Q-Former → 固定 64~256 个。这个数字直接决定显存和推理成本。
  • 高分辨率怎么来的：把大图切成多个子图分别编码（动态分辨率 / AnyRes），一张 1344×1344 的图可能切成 5~9 块，token 数直接翻几倍——这是长图理解慢的根本原因。
  • 视频怎么做：抽帧（每秒 1~2 帧）后当多张图处理，token 数 = 帧数 × 每帧 token。这就是视频理解贵的原因：10 秒视频就可能 3000+ token。

成本估算

# —— 一张图到底占多少显存/算力？自己算 ——
def vlm_cost(img_size=336, patch=14, llm_dim=4096, layers=32,
             compress=1.0, n_images=1):
    patches = (img_size // patch) ** 2                 # 576
    vis_tokens = int(patches * compress)               # 576（不压缩）
    # KV Cache：视觉 token 与文本 token 一样要缓存
    kv_per_token = 2 * layers * llm_dim * 2            # 2(K,V) * 层 * 维 * 2字节(fp16)
    return vis_tokens * n_images, vis_tokens * kv_per_token / 1024**2

t, mb = vlm_cost()
print(f'每图 {t} token -> KV Cache {mb:.0f} MB')       # 576 token -> 约 302 MB

# 对比：文本 token 通常 1000~4000；一张图 = 576 token 相当于 500+ 个汉字
# 高分辨率(AnyRes, 1344x1344, 5 块) -> 576*5 = 2880 token -> 约 1.5 GB

# —— 关键参数经验值 ——
#   视觉编码器分辨率：336（LLaVA-1.5）/ 448（SigLIP）/ 动态（LLaVA-NeXT）
#   Connector：2 层 MLP 在大多数场景就够，Q-Former 训练更难但压缩更狠
#   训练阶段：① 预训练对齐（只训 Connector，冻结其余）
#             ② 指令微调（解冻全部或部分）
#   学习率：对齐阶段 1e-3；微调阶段 2e-5（LLM 部分要小）

记住这个换算：一张 336px 的图 ≈ 576 个 token ≈ 500 个汉字。所以「多图输入」和「长视频」的显存压力远大于纯文本对话。

第三层 · 排障清单

  • 模型「看不见」图里的细节（OCR 差、数不清物体） → 视觉编码器分辨率不够（336px 下小字直接糊了）。解法：换高分辨率编码器（SigLIP @384/448）、开动态分辨率/切块、或对关键区域做裁剪放大。
  • 显存爆掉 → 算一下 token 数：多图 + 高分辨率很容易上万个 token。解法：① 减少同时输入的图片数；② 用压缩更强的 Connector（Q-Former/Resampler）；③ 开 Pixel Shuffle 压缩；④ 用 PagedAttention（vLLM）管理 KV Cache。
  • 模型会「幻觉」出图里没有的东西 → 典型的多模态幻觉。三个来源：① LLM 的语言先验太强（看图说话时倾向于补全常识）；② 视觉 token 被压缩太狠丢了信息；③ 训练数据里图文不对齐。缓解：降低温度、加强视觉编码器、用 RLHF/DPO 专门抑制幻觉、或要求模型先描述再回答。
  • 纯文本能力下降（灾难性遗忘） → 多模态微调后模型在纯文本任务上变差。解法：混合一定比例的纯文本数据（通常 20~50%）、冻结 LLM 只训 Connector、或用 LoRA 限制更新幅度。
  • 图文不对齐（说的和图的区域对不上） → 缺少定位能力。解法：训练时加入 grounding/指代表达数据（带 bbox 的描述），或输出时带坐标。
  • 推理很慢 → 瓶颈通常在预填充（prefill）：几千个视觉 token 要一次性过 LLM。解法：① 减少视觉 token 数；② 视觉 token 的 KV 可以缓存复用（同一张图多轮对话只算一次）；③ 投机解码。
  • 训练不收敛 → 常见原因：Connector 学习率太大（视觉特征被破坏）、LLM 学习率太大（灾难性遗忘）、数据质量差（图文不匹配）。标准做法：两阶段训练，第一阶段只训 Connector 且学习率较大，第二阶段全参微调但 LLM 学习率压到 2e-5 以下。

第四层 · 原理与取舍

VLM 的全部设计取舍集中在一条：视觉 token 数与信息保留量的权衡。token 越少越省算力，但压缩必然丢信息；token 越多信息越全，但显存和延迟呈线性甚至平方增长。

Connector 方案压缩率信息保留训练难度适用
直接 MLP（LLaVA）1×（不压缩）最好最低大多数场景的默认选择
Pixel Shuffle4×~16×好（重排空间信息）低高分辨率图（InternVL）
Q-Former（BLIP-2）可配置（如 9×）中（learnable query 会丢细节）高（要预训练）需要极致压缩
Perceiver Resampler可配置中中视频/多帧（Flamingo）
直接投影（Linear）1×好最低早期方案，现在多用 MLP
  • 为什么 LLaVA 的「两层 MLP」能成为主流：因为它不压缩，信息零损失，而 576 个 token 对现代 LLM（上下文 4K~128K）来说完全可接受。既然上下文窗口够用，就没必要为了省 token 牺牲信息——这个取舍在长上下文普及后发生了逆转。
  • 什么时候必须压缩：① 视频（几十帧 × 576 token 直接爆掉）；② 超高分辨率文档（AnyRes 切块后 token 数暴涨）；③ 端侧部署（算力受限）。这三个场景下 Q-Former/Resampler 才有意义。
  • 视觉 token 的一个反直觉优化：多轮对话中视觉 token 只需算一次。因为图像不变，其 KV Cache 可以跨轮复用。好的推理实现会把视觉部分的 prefill 结果缓存下来，第二轮起只处理新增的文本 token。
  • 「视觉编码器越大越好」吗：不是无脑的。InternVL 用了 6B 的视觉编码器确实带来提升，但收益递减且成本陡增。经验上视觉编码器规模 ≈ LLM 的 1/10 ~ 1/5 比较划算（如 7B LLM 配 300M~1B 的视觉塔）。瓶颈更多在于分辨率和训练数据质量，而不是编码器参数量。
Q-Former 和 MLP 到底差在哪？现在该选哪个？

结构差异：MLP 是逐 token 独立映射（576 进 576 出），Q-Former 是用一组可学习的 query（如 64 个）去「问」视觉特征，通过交叉注意力把 576 个 patch 压缩成 64 个 token。所以 Q-Former 能大幅省 token（9×），代价是：① 训练更难（要单独预训练，且容易不收敛）；② 压缩有损——64 个 token 装不下 576 个 patch 的细节（小字、细微物体会丢）；③ 结构复杂，调试成本高。现在的建议：默认用 MLP，除非你有明确的「token 预算硬约束」（视频、端侧）。这个建议和 2023 年相反——因为 LLM 上下文窗口变长、推理算力变便宜后，「不压缩」的整体性价比反超了。

多模态幻觉为什么比纯文本更难治？

因为它有两个独立的来源，而纯文本只有一个。纯文本幻觉主要来自参数知识的错误/编造；多模态还多一层：视觉信息没能正确传递到语言输出。具体有三种失效：① 视觉编码丢信息（小字没编码进去，模型只能靠猜）；② 跨模态注意力被语言先验压过（LLM 太强，倾向于按常识补全而不是看图）——这是主因，实测中「模型说图里有只猫但图里没有」多属此类；③ 训练数据图文不对齐造成系统性偏差。所以治理要三管齐下：提高视觉分辨率（解决①）、用 RLHF/DPO 专门惩罚「描述图中不存在的物体」（解决②）、清洗训练数据（解决③）。单纯的「降低温度」只能有限缓解。

VLM 的推理成本怎么估算？

分三部分：① 视觉编码——一次前向，ViT-L 约几十 GFLOPs，通常 <100ms；② 预填充（视觉 token + 文本 prompt 一起过 LLM）——这是大头，几千 token 的 prefill 在 7B 模型上约几百毫秒到 1 秒；③ 解码——每 token 约 20~50ms（7B，batch=1）。所以关键结论：视觉 token 数决定了 prefill 成本，而 prefill 在多图/视频场景会成为绝对瓶颈。优化优先级：先减少视觉 token（压缩/降分辨率），再考虑用投机解码加速生成部分。另外别忘了多轮复用——同一张图的后续问答可以省掉①和视觉部分的②，这是投入产出比最高的优化。

VLM 的骨架其实很固定

尽管名字繁多（LLaVA、Qwen-VL、InternVL、BLIP-2…），主流 VLM 的结构几乎都是三段式：视觉编码器 → 对齐投影 → LLM 主干。差异主要在三处：用哪个视觉编码器、投影层怎么设计、以及视觉 token 如何压缩与排列。理解了这三处，看任何一篇 VLM 论文都能迅速定位它的创新点。

视觉编码器通常是预训练好的 ViT / CLIP / SigLIP，多数冻结或轻量微调
投影层把视觉特征映射到 LLM 的词嵌入空间（维度对齐 + 语义对齐）
LLM 主干承担推理与生成，是能力上限的主要来源
视觉 token一张图通常几百个 token，是成本与延迟的主要来源
分辨率策略动态分辨率 / 切片（tile）能提升小字与小物体识别
训练两阶段先对齐预训练（大量图文对），再指令微调（高质量指令数据）

工程落地要点

① 控制视觉 token 成本

  • 按任务选分辨率：问答用低分辨率，文档/表格用高分辨率。
  • 能用一图说清就别传十图；多图要问自己「是否真的都需要」。
  • 视频抽帧：关键帧采样，而不是逐帧全送。
  • 缓存：同一张图多次提问时复用视觉 token（prefix caching）。

② 提升识别准确率

  • 含文字的图（文档、截图、表格）优先选支持高分辨率/动态切片的模型。
  • OCR 需求重的场景，考虑「OCR 结果 + 原图」双通道输入。
  • 小目标与密集场景：提高分辨率收益通常大于换模型。

③ 输出结构化

  • 要求返回 JSON 时给出明确 schema 与示例。
  • 抽取类任务（表单、票据）要定义字段与缺失时的行为。
  • 用约束解码/JSON mode 提升格式稳定性。

④ 评测与监控

  • 构造业务验证集：真实截图、真实光照、真实长尾。
  • 分任务统计：VQA、OCR、计数、定位分别看准确率。
  • 监控拒答率与幻觉率，而不只看整体正确率。
  • 记录输入图的分辨率与 token 数，用于成本归因。

深入自检

为什么 VLM 里视觉编码器通常用 CLIP/SigLIP 而不是随便一个 ViT？

因为它的特征已经和文本语义空间对齐过了（在图文对比学习中）。直接用一个纯图像分类的 ViT，其特征虽然含语义，但没有与语言对齐，投影层需要学非常困难的映射，效果差且收敛慢。所以「已经对齐过的视觉编码器」是 VLM 的关键起点。

投影层为什么不能省掉？

因为视觉编码器的输出维度与分布，和 LLM 词嵌入的维度与分布完全不同。投影层做两件事：维度变换 + 分布对齐。没有它，LLM 看到的是完全陌生的向量，等同于输入乱码。这也是为什么 VLM 必须先做「对齐预训练」。

视觉 token 太多有什么后果？

三重代价：① 显存与算力随 token 数增长（注意力是平方级）；② 首 token 延迟明显变长；③ 长上下文里视觉 token 会挤占文本上下文，导致有效信息被稀释。所以 token 压缩是高价值优化方向。

Q-Former 之类压缩方案会不会丢信息？

会，压缩必然有损。损失最明显的是细粒度信息：小字、小物体、密集布局。所以文档理解类任务通常倾向保留更多 token 或采用动态分辨率，而不是激进压缩。选择取决于你的任务对细节的敏感度。

多图输入时模型为什么经常搞混？

因为若没有明确的图标识与位置编码（如 、 与对应的分隔），模型难以区分哪些 token 属于哪张图。工程上要用模型支持的多图格式显式标注，并在 prompt 里按图编号提问。

自研 VLM 的合理起点是什么？

除非有强定制需求，不建议从零预训练。务实路线：选一个开源 VLM（如 LLaVA/InternVL/Qwen-VL 系），① 先用领域数据做指令微调（LoRA 即可）；② 若视觉域差异大，再解冻视觉编码器；③ 最后才考虑换主干。绝大多数业务收益来自第一步与数据质量。
