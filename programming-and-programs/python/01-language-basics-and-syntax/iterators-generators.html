迭代器与生成器

for 循环、列表推导、sum() 全都建立在「迭代协议」之上。生成器用 yield 把「一次性算完」变成「要一个算一个」——这是处理大文件、无穷序列、流式数据的核心武器。

迭代协议

可迭代对象 ≠ 迭代器

可迭代对象（iterable）有 __iter__，调用它返回一个迭代器；迭代器（iterator）额外有 __next__，每调用一次吐出下一个值，没了就抛 StopIteration。

📜
Iterable
str / list / dict / set / tuple / range / 文件对象；能放进 for
👉
Iterator
有状态的「游标」，记住走到哪了；只能前进不能回退
s = "abc"
it = iter(s)        # 可迭代 → 迭代器（调用 __iter__）
print(next(it))    # a
print(next(it))    # b
print(next(it))    # c
print(next(it))    # StopIteration 异常
判断技巧：迭代器一定是可迭代的（它也有 __iter__ 且返回自身），但可迭代对象不一定是迭代器。用 iter(x) is x 可区分。list 的迭代器是独立的 list_iterator 对象。
for 底层

for 循环就是「不断 next 直到 StopIteration」

手写 for 的等价展开，能看清协议全貌。for x in obj 实际是：先 it = iter(obj)，再循环 next(it)，捕获 StopIteration 退出。

# 下面两段完全等价
for x in [1, 2, 3]:
    print(x)

# 手写等价版
it = iter([1, 2, 3])
while True:
    try:
        x = next(it)
    except StopIteration:
        break
    print(x)

所以任何对象只要实现了 __iter__（或老式 __getitem__），就能进 for 循环。这也是自定义容器「变成可迭代」的标准做法。

生成器

含 yield 的函数就是生成器

调用含 yield 的函数不会执行函数体，而是返回一个生成器对象；每次 next() 推进到下一个 yield 并「挂起」，保留所有局部状态。它是迭代器最方便的写法。

def countdown(n):
    while n > 0:
        yield n        # 在这里暂停，返回值 n
        n -= 1

g = countdown(3)    # 没执行函数体，只拿到生成器
print(next(g))      # 3  （推进到 yield 3，暂停）
print(next(g))      # 2
print(list(g))      # [1]（把剩下的取完）
yield from 用于把另一个可迭代对象「逐个委托」出来，写嵌套生成器/递归生成器时很省事：yield from sub_gen 等价于 for x in sub_gen: yield x。
生成器表达式

把方括号换成圆括号就「懒」了

列表推导 [x for x in ...] 一次性生成整个 list；生成器表达式 (x for x in ...) 返回一个生成器，元素按需产生，不占额外内存。

lst = [i*i for i in range(1000000)]   # 立刻生成 100 万个元素
gen = (i*i for i in range(1000000))   # 只占一个对象

print(sum(gen))   # 流式累加，内存几乎不变

# 链式管道：每个环节都是惰性生成器
lines = (line.strip() for line in open("big.log"))
errs  = (l for l in lines if "ERROR" in l)
for e in errs: print(e)   # 一行行处理，不把整文件读进内存
⚠️ 生成器是「一次性」的：取完就没了，不能二次遍历。需要多次遍历就转成 list，或重新创建生成器。
为什么省内存

惰性 = 不必把所有数据同时放在内存里

生成器适合三种场景：数据量极大、无限序列、流水线处理。它和异步里的协程思想同源——都是「每次只取一步」，只是前者为了省内存，后者为了不阻塞。

场景list 推导生成器
读 10GB 日志❌ 内存爆✅ 逐行流式
斐波那契无穷序列❌ 无法表示✅ yield 无限产出
多步数据清洗每步都建中间 list✅ 管道式惰性

生成器是「同步」的惰性计算；想要「并发地」产出值，就升级到异步生成器（async def + yield）。两者共享同一套「惰性产出」心智模型。
