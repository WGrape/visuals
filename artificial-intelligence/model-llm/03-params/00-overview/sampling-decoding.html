LLM 生成与推理

解码与采样：temperature / top-k / top-p 怎么调

生成是「逐步从概率分布里采样」。greedy 贪心、beam search、temperature、top-k、top-p(nucleus) 各自在「确定性 vs 多样性」之间取舍。本文讲清每种何时用、默认值怎么来。

一句话回答

LLM 是自回归的：每生成一个 token，都从 softmax 出的概率分布里「采一个」出来，再喂回去。解码策略决定怎么从这个分布里选——greedy/beam 偏确定、偏保守；temperature/top-k/top-p 控制多样性。代码/事实要低随机，创意要高随机。

自回归生成回顾

模型输出的是「下一个 token 的 logits」，过 softmax 变成概率分布 p。生成第 t 个 token 就是从这个分布里挑一个：

p(token | 前文) = softmax(W · h_t)

Greedy（贪心）：每步取最大概率

token = argmax(p)
完全确定、可复现；适合「有标准答案」的场景（代码补全、抽取、分类标签）。
缺点：单调、易陷入重复循环（"好的好的好的…"），缺乏多样性，开放生成很"无聊"。

Beam Search：保留 top-b 条路径

不只要一条最优，而是每步保留 b 条（beam width）当前累计概率最高的候选序列，最后选整体最优。

翻译、摘要、语音识别等「有唯一较优解」的任务效果好，输出流畅不跑偏。
开放对话/创意里 beam search 反而「太安全」、句式雷同；且 b 越大算力越贵。LLM 对话一般不默认用它。

Temperature：缩放分布"尖锐/平滑"

在 softmax 前把 logits 除以温度 T：

p = softmax(logits / T)
  • T → 0：分布极尖锐，趋近 argmax（= greedy），确定性高。
  • T = 1：原始分布。
  • T 大（如 0.8~1.2 常见，更高更野）：分布变平滑，低概率 token 也有机会，更发散、更随机。

Top-k / Top-p（nucleus）：截断低概率

不想让极小概率的"胡说"token 被采到，就在采样前先截断：

Top-k
只保留概率最高的 k 个 token，其余置零后再采样。k 小更稳，k 大更多样。但 k 固定，可能对"本来就很确定"的分布也硬塞 k 个。
Top-p（nucleus）
按概率从高到低累加，取到总和 ≥ p 就停（如 p=0.9）。动态决定候选集大小，更自适应，比 top-k 常用。
实战常组合：temperature 调"发散度" + top-p 控"候选范围"，两者一起用。top-k 常与 top-p 二选一或叠加。

怎么选 & 默认值

场景策略说明
代码/SQL/JSON/事实问答greedy 或 T≈0 + top-p 小要准确、可复现
翻译/摘要beam search 或低 T有较优解、要流畅
聊天/文案/头脑风暴T 0.7~1.0 + top-p 0.9要多样自然
极度发散/写诗T 1.0+ + top-p 0.95鼓励惊喜
默认值心智模型：OpenAI 系默认 temperature≈0.7~1.0、top-p≈1；但"严谨任务"应调低到 0~0.3。别在要"唯一正确答案"的任务上用高 T。

总结

  • 生成 = 逐步采样；策略决定"怎么从分布里挑"。
  • greedy/beam 确定保守；temperature/top-k/top-p 控多样性。
  • top-p 比 top-k 自适应；常配 temperature 一起用。
  • 选参看任务：严谨低 T、创意高 T。

四种主流策略

策略做法特点适合
贪心 Greedy每步取概率最大的确定、快，但容易重复呆板抽取、分类、代码补全
随机采样按概率分布抽有多样性，可能跑偏创意写作、对话

温度到底改变了什么

原始 logits: [2.0, 1.0, 0.5] softmax(T=1.0): [0.63, 0.23, 0.14] # 原始分布 softmax(T=0.5): [0.82, 0.13, 0.05] # 更尖锐，更确定 softmax(T=2.0): [0.47, 0.29, 0.24] # 更平坦，更随机 # 直觉：T -> 0 等价于贪心；T 越大长尾越容易被抽到 # 注意：T 只改分布形状，不改变候选的相对顺序

参数怎么搭配

① 要稳定复现temperature=0（或接近 0）+ 固定 seed，输出基本确定。
② 通用对话temperature 0.7 ~ 0.9，top_p 0.9，二选一调即可。
③ 创意写作temperature 1.0 ~ 1.2，可叠加 frequency_penalty 防词重复。
④ 代码 / JSONtemperature 0 ~ 0.2，必要时加 structured output 约束。
⑤ 别同时猛调temperature 与 top_p 同时大幅调整会难以复现与回归，建议只动一个。

束搜索与采样的取舍

维度束搜索 Beam Search采样 Sampling
确定性高（除并列外）低（每次不同）
多样性低，容易趋于模板化高
计算开销保留 k 条路径，显存与算力 ×k只走一条，开销小
适合翻译、摘要等有明确最优解的任务对话、写作等开放式生成

深入自检

temperature 设为 0 会完全确定吗？

接近确定但不绝对。多数实现里 T=0 会退化成贪心，但浮点计算的并行归约顺序、批处理中其他样本的影响、以及硬件差异仍可能带来极小的差异。要严格可复现需固定 seed 与批次。

top_k 和 top_p 该用哪个？

优先 top_p。因为合适的 k 依赖分布形状：分布尖锐时 k=50 可能全是低概率噪声，分布平坦时 k=50 又可能切掉太多合理候选。top_p 用累积概率自适应地决定候选集大小，更稳。

为什么长文本生成会出现重复段落？

因为模型在「信息已说完但长度没到」时，最可能的续写就是重复已有内容。缓解手段：repetition_penalty / frequency_penalty，或提高 temperature，或从系统层面缩短目标长度。

Beam Search 一定比采样好吗？

不一定。研究表明在开放式生成（故事、对话）中束搜索反而更差 —— 它倾向于生成高频、安全、空洞的文本。有明确参考答案的任务（翻译、摘要）才是它的主场。

采样参数会影响输出长度吗？

间接会。分布更平坦时长尾 token（包括 EOS）更容易被抽到，可能提前结束；更尖锐时更容易沿着高概率路径一直写下去。真正控制长度要靠 max_tokens 与 stop。
