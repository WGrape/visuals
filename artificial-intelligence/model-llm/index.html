这一章解决什么问题

大语言模型这一章回答的是：它是怎么做出来的、怎么被切成 token、怎么决定下一个词、怎么被引导去思考与规划、怎么调用工具。前一半是原理，后一半是使用方式，两边合起来才能解释清楚「为什么同样的模型，用法不同效果差很多」。

原理侧发展脉络、缩放规律、分词、采样与解码
使用侧提示词、上下文管理、思考链、规划、工具调用
核心认知模型本质是「按上文预测下一个 token」的机器
为什么重要所有使用技巧都是在给这个预测过程搭更好的舞台
一次生成的完整链路：切分 → 计算 → 分布 → 采样 → 拼接

模块关键内容常见误区

规划与工具任务分解、函数调用、外部能力接入以为模型会主动纠错

为什么提示词能起作用

因为模型做的是条件概率预测，你给的上文就是在限定它接下来最可能说什么。提示词的本质不是「下命令」，而是把任务描述成模型见过的那种文本模式。

为什么长上下文不等于都用上

窗口能装下不代表每个位置都被充分利用。模型对开头与结尾通常更敏感，中间部分容易被忽略。所以重要信息要放在显著位置，并且尽量精简而不是堆量。

高频问题

token 和字数大概什么关系？

中文通常一个字接近一到两个 token，英文常见词大约一个 token 出头，具体取决于分词器与文本。所以计费与长度限制都按 token 算，不能用字数直接换算。

温度到底该调多少？

需要稳定、可复现的任务（提取、分类、代码）用低温；需要多样性的任务（创意、改写、起名）可以调高。它控制的是分布的陡峭程度：低温让高概率选项更突出，高温让长尾也有机会。

为什么要求「一步步思考」会有用？

因为直接给答案相当于一次性跳跃，而写出中间步骤把难题拆成了若干简单步，每一步都更容易预测对。代价是输出更长、耗时更多。

思维链输出变长就代表推理更强吗？

不一定。长度只是表象，关键是每一步是否真的推进了问题。出现循环论证、重复改写、看似在推理其实在铺垫的情况都很常见，最终仍要以答案正确性为准。

工具调用为什么需要结构化输出？

因为外部系统需要确定的参数，而不是自由文本。模型要输出符合约定的调用结构，由程序解析后执行，再把结果作为新的上下文回喂。这把「会说」变成了「能做」。

本质是预测一切技巧都在影响预测
token 不是字长度与费用按 token 计
温度控分布不是创造力开关
提示是搭舞台不是下命令
长上下文要精简装得下不等于用得好
