三种形态，别搞混

Redis 的「集群」这个词有好几种含义，先分清它们解决的分别是什么问题：

形态解决的问题是否分片谁负责故障切换
主从复制数据冗余、读写分离否（每个节点都有全量）人工或外部脚本
哨兵 Sentinel在主从之上加自动故障切换否哨兵进程自动选主
Cluster数据分片 + 高可用，突破单机内存上限是节点间 Gossip 协议自动完成

判断标准很简单：如果你的数据量单机放得下，只需要高可用，用「主从 + 哨兵」就够了；如果数据量或写吞吐超过单机上限，才需要 Cluster。

Cluster 的核心：16384 个槽

槽是分片与迁移的最小单位
槽总数固定 16384这是协议常量，不能改 —— 所以理论上最多 16384 个主节点（实际建议远少于此）。
主节点各管一段槽到节点的映射由集群维护，扩缩容就是重新分配这些段。
每个主节点有副本从节点复制对应槽的数据，主挂了顶上去。
客户端缓存映射表智能客户端本地保存槽→节点映射，绝大多数请求直接命中正确的节点。

为什么是 16384：这是个折中 —— 足够多以便把数据分得足够细（迁移粒度小），又不会让集群状态里「谁负责哪些槽」的位图过大（16384 位 ≈ 2KB，在节点间心跳消息里传播代价可接受）。

客户端怎么找到正确的节点

客户端请求一个不属于当前节点的 key 时，Redis 会返回一个重定向错误：

响应含义客户端该怎么做
MOVED这个槽永久归别的节点了更新本地的槽映射表，以后直接去找新节点
ASK这个槽正在迁移中，这一次去新节点找先发送 ASKING 再执行命令，且不要更新本地映射表
CROSSSLOT一次请求里的多个 key 不在同一个槽拆开请求，或用 hash tag 让它们同槽

为什么一定要智能客户端：如果每次都随机连一个节点再等 MOVED 重定向，每个请求都会变成两次往返。智能客户端在本地缓存映射表，只有映射变化（或刚启动）时才需要一次额外跳转。

hash tag：让一批相关 key 强行同槽 CRC16 只计算 key 里<b>第一对花括号之间</b>的内容 user:{1001}:profile → 只算 "1001" user:{1001}:orders → 只算 "1001" → 两者 CRC16 相同 → 同槽 → 可以做多键操作、事务、Lua 代价：如果业务 ID 分布不均，会造成数据倾斜。 所以 hash tag 要用，但不要把所有 key 都用同一个 tag。

Cluster 的限制与常见坑

  1. 多键操作必须同槽。MGET、事务、Lua 里涉及的多个 key 若分属不同槽会直接被拒。
  2. 只支持 db0。Cluster 模式下不能用 SELECT 切换数据库。
  3. 热 key 无法靠分片解决。某个 key 被疯狂访问，压力全在它所在的那个节点上 —— 分片救不了它，要在业务侧做本地缓存或拆 key。
  4. big key 迁移困难。一个几百 MB 的 list/hash 在槽迁移、持久化、删除时都会造成卡顿。
  5. 扩容仍有代价。槽迁移期间网络与 CPU 都有额外开销，应在低峰进行并限速。
  6. 批量命令要按节点分组。前面提到的 pipeline 必须按节点拆分。

容量规划的一条经验：主节点数不要过多（常见做法是几个到十几个），单节点内存控制在能在一两分钟内完成持久化与故障恢复的量级。节点越多，Gossip 消息与故障判断的复杂度越高 —— 分片不是越多越好。

深入自检

为什么集群最少需要三个主节点？

故障判定依赖多数派投票：只有当大多数主节点都认为某节点失联时，才把它标记为 FAIL 并触发故障转移。两个节点无法形成可靠的「多数」，也无法区分「对方挂了」和「自己被网络隔离了」。所以生产环境通常至少三个主节点，且每个配一个从节点。

主从复制是同步还是异步？

默认是异步：主节点先把结果返回客户端，再异步把写命令传播给从节点。因此主节点宕机时，最后一小段尚未传播的写入可能丢失。这是 Redis 在性能与一致性之间的取舍 —— 需要更强保证时可以使用 WAIT 命令等待指定数量的副本确认，但要清楚它会增加延迟，且仍不等于强一致。

Cluster 模式下事务还能用吗？

能，但前提是事务里的所有 key 都落在同一个槽（通常用 hash tag 保证）。由于不存在跨节点事务，Redis 没有也不需要分布式事务 —— 这个限制本质上是为了避免实现两阶段提交带来的复杂度与延迟。需要跨片原子性时，通常要在业务层设计（如补偿、幂等）。

为什么有时候明明节点都活着，集群却不可用？

常见情形：某个槽区间没有任何主节点负责（例如该主节点宕机且从节点也没能顶上来），此时涉及这段槽的请求就会失败。另外如果大量主节点同时不可用，无法形成多数派，整个集群也会进入不可用状态。监控要看「槽覆盖率」而不只是节点存活。
