04 · 组件拆解

Dropout 与正则化：为什么现代 LLM 预训练几乎不用它

原版 Transformer 每个子层后面都有 dropout=0.1，但 GPT-3 之后的大模型预训练基本把它关成 0。同一套组件、两种截然相反的配置，背后的判断标准是「数据量 vs 参数量」。

一句话定位：正则化是给「拟合能力过剩」踩刹车

Dropout 在训练时随机把一部分激活置零，逼迫网络不依赖特定神经元，等价于对指数多个子网络做集成。它有用与否，取决于模型是否有能力把训练集背下来。

训练行为按概率 p 置零，保留值除以 (1-p)（inverted dropout，推理端不用缩放）
推理行为完全关闭，等价于全网络前向
LLM 预训练dropout = 0（GPT-3 / LLaMA / Qwen / DeepSeek 全系）
小数据微调0.05 ~ 0.1 常有正收益，但会让收敛变慢
训练时每次前向都是不同子网，推理时用完整网络——这就是 dropout 的集成解释

三个位置，三个不同结论

位置原版 Transformer现代 LLM说明
残差 dropout（子层输出后）0.10大模型预训练数据远超参数容量，加它只会拖慢收敛
注意力权重 dropout0.10会破坏长距离依赖的学习，长上下文任务尤其敏感
Embedding dropout0.10对词表稀疏的场景有用，对大规模预训练反而有害
分类头 / 微调阶段0.10.05~0.1小数据集上仍是有效正则
判断标准只有一个

训练 token 数 ÷ 参数量。GPT-3 是 300B token / 175B 参数 ≈ 1.7；LLaMA-3 是 15T / 8B ≈ 1875。比值越大，模型越「欠拟合」而不是过拟合，正则越该关掉。

代码：开关在哪、怎么配

# PyTorch 里三个 dropout 位置 attn_out = self.attn_drop(attn_weights) # 注意力权重上 x = x + self.resid_drop(self.attn(norm(x))) # 残差分支上 x = self.emb_drop(token_emb + pos_emb) # embedding 之后 # 现代 LLM 的典型配置 dropout = 0.0 # 小数据 SFT 的典型配置 dropout = 0.05 # 再大容易欠拟合，注意和 label smoothing 叠加

除 dropout 外，LLM 还有三件常开的「隐式正则」：weight decay（AdamW 0.1，但 bias 与 norm 参数不 decay）、梯度裁剪（1.0）、z-loss（约束 logits 的 log-sum-exp，PaLM 用 1e-4）。它们和 dropout 是替代关系而非叠加关系。

排障：dropout 引发的四个怪现象

现象根因处理
训练 loss 正常，评测掉点train/eval 模式没切换，推理时还在丢确认 model.eval()，或检查自定义 forward 里是否用了 F.dropout(training=True)
微调后输出重复、卡壳dropout 与低学习率叠加导致欠拟合先把 dropout 降到 0.05 或 0，看是否恢复
同一输入两次生成不同结果（temperature=0）不是 dropout，而是 kernel 非确定性 / bf16 归约顺序开 deterministic 模式或换 greedy 实现验证
分布式训练 loss 与单卡不一致dropout 随机种子不同固定 seed，或确认各 rank 的 RNG 状态

原理与取舍：为什么「集成」在超大模型上不再划算

dropout 的收益来自方差削减，代价是有效容量下降。当数据量足够大时，方差已经不是瓶颈，削减方差就等于白白降低容量；同时 15T token 的训练里，每次前向丢一半激活会让收敛慢 10%~20%，这笔算力账远比一点正则收益贵。

那为什么 BERT 时期 dropout 是标配？

BERT 预训练只有 3.3B token / 110M 参数 ≈ 30，且下游微调数据小（几万条），过拟合风险真实存在。配置是跟着数据规模走的，不是跟着模型结构走的。

dropout 会不会影响 KV Cache？

推理时 dropout 已关闭，所以不影响。但如果你在「训练时用 dropout 做长上下文外推」（如某些 attention dropout 变体），要保证训练和推理的 mask 行为一致，否则位置对齐会错。

什么时候该用 weight decay 而不是 dropout？

大模型预训练用 weight decay（作用在权重上，不改变前向计算图，对吞吐零影响）；小数据微调用 dropout（作用在激活上，抑制协同适应）。两者可以同时用，但要各自调。

第一层 · 概念与判定：三种正则手段怎么用

手段作用位置解决什么问题Transformer 里常见吗
Dropout训练时随机置零一部分神经元过拟合（记忆训练集）原始 Transformer / BERT：用；现代 LLM：多不用
Weight Decay优化器里对权重衰减权重过大、泛化差普遍使用（AdamW 的 decoupled 版本）
Label Smoothing把 one-hot 标签软化过度自信、校准差原始 Transformer 用 0.1
Layer Norm / RMSNorm归一化激活值训练稳定性（不是防过拟合）必用
数据增强 / 规模增加数据多样性最有效的正则大模型靠数据量本身
  • 信号一：训练集 loss 持续降、验证集 loss 反弹 → 过拟合，加正则。
  • 信号二：验证 loss 都降不下去 → 欠拟合，别加 dropout，要加模型容量或数据。
  • 信号三：训练不稳定（loss 尖刺、发散）→ 那是归一化/学习率问题，不是过拟合。

重要区分：Dropout 防过拟合，LayerNorm 保稳定。很多人把两者混为一谈——训练发散要调学习率和归一化，加 dropout 只会让它更难收敛。

Dropout 的实现与配置

import torch
import torch.nn as nn

# PyTorch 的 Dropout 用的是 inverted dropout：
# 训练时以概率 p 置零，并把保留的值除以 (1-p)  —— 期望值不变
# 推理时（model.eval()）自动关闭
m = nn.Dropout(p=0.1)
out = m(x)                    # 训练时随机会有约 10% 置零，其余 ×1/0.9

# 关键：eval 时必须切换模式，否则结果带随机性
model.eval()
with torch.no_grad():
    y = model(x)              # 此时 dropout 不生效

# Transformer 里的三处 dropout（原始论文）
# 1) 注意力权重上：softmax(QK^T/sqrt(d)) 之后
# 2) 残差连接前（每个子层输出上）
# 3) FFN 内部

# HuggingFace 配置
from transformers import BertConfig
cfg = BertConfig(
    hidden_dropout_prob=0.1,          # 隐藏层 dropout
    attention_probs_dropout_prob=0.1, # 注意力 dropout
)

量化参考：p=0.1 意味着训练时每个神经元有 10% 概率被临时丢弃，等价于每次前向都在训练一个「不同的子网络」，最后相当于集成了这些子网络——这是它能防过拟合的直觉解释。

第三层 · 排障与边界：Dropout 的坑

坑后果正确做法
推理时忘了 model.eval()输出带随机性，结果不可复现推理前必须 model.eval()
eval() 后忘了 train()继续训练时 dropout 没生效训练循环里显式 model.train()
把 dropout 当稳定器用训练更难收敛发散要调 LR / warmup / 归一化
在现代 LLM 上加 dropout通常没有收益甚至有害大模型靠数据量正则，LLaMA 等都不用
dropout 率设太大（如 0.5）严重欠拟合Transformer 场景 0.1~0.3 为宜
  • 排查顺序：先确认 eval/train 模式切换正确 → 再确认过拟合是真的（看验证 loss） → 最后确认 dropout 率。
  • 边界一：Dropout 只在训练时生效，推理时是恒等映射（配合训练时的缩放，期望值不变）。
  • 边界二：与 BatchNorm 同用时顺序有讲究（现在 Transformer 多用 LayerNorm，不涉及）。
  • 边界三：Dropout 会让训练 loss 看起来更高（因为加了噪声），这是正常的，不要误判为模型变差。

Dropout 生效自检

# 自检：确认 eval 模式下 dropout 真的关了
model.eval()
xs = torch.randn(1, 16)
o1, o2 = model(xs), model(xs)
assert torch.allclose(o1, o2), "eval 模式下两次前向结果不同 —— 忘了 eval()？"

# 确认 train 模式下确实有随机性
model.train()
o1, o2 = model(xs), model(xs)
assert not torch.allclose(o1, o2), "train 模式下结果完全一样 —— dropout 没生效？"

第四层 · 原理与取舍：为什么现代 LLM 不用 Dropout

原始 Transformer（2017）在机器翻译上用 dropout 0.1，因为当时数据量有限、模型相对小。到 LLM 时代情况变了：数据量极大（ trillion 级 token）、且通常只训练 1 个 epoch——模型根本没机会「记住」训练数据，过拟合风险很低，而 dropout 带来的噪声反而会拖慢收敛。

场景用 Dropout?理由
小数据 + 大模型（微调）✅ 可以试 0.1容易过拟合
大数据预训练（LLM）❌ 不用数据本身就是最好的正则；只训 1 epoch
BERT 时代预训练✅ 用 0.1沿用原始 Transformer 配置
LLaMA / Qwen / Mistral❌ 不用已验证不加更好
视觉 Transformer（ViT）⚠️ 视规模而定常配合其他正则（如 stochastic depth）
为什么 dropout 后要除以 (1-p)？

这叫 inverted dropout。目的是让训练时的期望输出等于推理时：训练时约 (1-p) 的神经元被保留、且值放大 1/(1-p)，期望不变；推理时不丢弃任何神经元，也就不需要缩放。如果不做这个缩放，推理时激活值会比训练时大 (1-p) 倍，需要额外补偿，容易出错。

dropout 和 weight decay 有什么区别？

作用机制不同：dropout 是随机噪声，强制网络不依赖特定神经元；weight decay 是惩罚大权重，让模型偏好更平滑的解。两者常一起用，但 weight decay 在 LLM 里更普遍（AdamW 默认带），dropout 则被大量 LLM 抛弃。

怎么判断该不该加 dropout？

看训练/验证 loss 曲线：训练 loss 远低于验证 loss 且差距在扩大 → 过拟合，加；两条曲线都还在一起降 → 没过拟合，别加（加了只会拖慢）。这是唯一的判断依据，不要凭模型大小猜。
