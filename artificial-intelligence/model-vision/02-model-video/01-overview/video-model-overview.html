概览

视频大模型全景：理解、生成、编辑与实时链路

视频比图像多了一个时间维度，于是多了时序建模、体积爆炸和低延迟三重难题。本文铺开视频智能的技术地图：从帧与编解码基础，到理解、生成、编辑三条主线，以及流媒体与实时链路，作为后续章节的索引。

相比图像，视频到底多了什么

时间维度
要建模帧与帧之间的运动和因果，而不只是单帧内容
数据量爆炸
一段 10 秒 30fps 的视频就是 300 帧，直接按图像处理成本极高
延迟约束
实时场景（直播、对话）要求端到端低延迟，与生成耗时天生冲突
一句话：视频任务的所有设计取舍，几乎都围绕「如何用最少的帧/算力表达足够的时间信息」展开。

三条主线 + 一条实时链路

主线输入输出关键技术
理解视频 → 语义/动作/检索结果抽帧 + 时空建模；行为识别、时序定位、视频检索
生成文本/图 → 视频时空扩散、时序注意力；核心难点是时序一致性
编辑视频 + 意图 → 视频插帧、超分、消除替换；难点是闪烁与抖动
实时链路采集 → 传输 → 推理 → 呈现流媒体协议、码率自适应、边缘推理

视频怎么喂给模型

抽帧 + 图像模型
把视频当若干张图分别编码再聚合。
优点：可复用图像模型、便宜
缺点：时序关系弱
时空联合建模
在注意力里同时建模空间与时间（时空注意力 / 3D 卷积）。
优点：时序强
缺点：算力与显存开销大
工程上最常见的是折中路线：稀疏抽帧 + 轻量时序模块，并对长视频做分段再聚合，以控制成本。

成本为什么是视频的核心命题

  • 比特率 × 时长决定存储与带宽，编解码是必修课
  • 视觉 token 数随「帧数 × 分辨率」增长，直接决定推理费用
  • 生成类任务还要乘上扩散步数，成本远高于图像生成
做视频方案时第一件事应是估算单条视频的 token/算力成本，再倒推能支持多长、多清晰、多少并发。

面试速记卡

  • 三大难题：时序建模、数据量爆炸、低延迟约束。
  • 四条线：理解、生成、编辑、实时链路。
  • 建模范式：抽帧复用图像模型（省）vs 时空联合建模（强），工程上常折中。
  • 成本公式：帧数 × 分辨率 × 扩散步数，做方案前先算账。

视频为什么比图像难一个量级

① 数据量

一段 10 秒 30fps 的 1080p 视频有 300 帧，原始数据量是单张图的 300 倍。即便稀疏采样，成本仍然高一个数量级。

② 时序一致性

图像只要单张好看；视频要求上百帧都好看且彼此连贯。逐帧处理必然闪烁，必须建模帧间关系。

③ 长程依赖

模型一次只能看几秒，而视频动辄几分钟甚至几小时。跨越这个鸿沟需要分段、记忆或层级结构。

④ 标注成本

视频标注（尤其带时间边界的）极其昂贵，导致数据集规模远小于图像领域，更依赖自监督预训练。

深入自检

视频任务的第一步应该做什么？

先确定粒度，再选模型。只要「整段视频在做什么」→ 动作识别（分类），标注和模型都最简单；要「什么时候发生」→ 时序动作定位，标注成本翻几倍，模型复杂度也上一个台阶；要「回答问题或找内容」→ 检索/问答，需要跨模态编码器 + 向量库。很多项目失败是因为一开始就要最细的粒度，结果标注做不完、模型训不动。建议先用粗粒度跑通闭环，验证价值后再细化。

为什么明明模型很强，线上视频效果却不好？

常见原因有三：①抽帧策略不对——关键动作发生在被跳过的帧里（均匀采样的典型问题）；②压缩伪影——线上视频经过重压缩，模型在清晰数据上训练，遇到块状伪影就崩；③数据分布不一致——训练集是公开数据集（电影、YouTube），线上是监控/UGC，风格差异巨大。排查方法：先把线上样本解码成帧看一眼，确认模型实际看到的是什么，再针对性做数据增强或换退化鲁棒的预训练。

视频领域为什么特别依赖预训练？

因为标注数据太贵、太少。最大的公开数据集 Kinetics-700 也只有几十万段，而图像领域有亿级标注。同时视频模型参数量大、更容易过拟合。所以自监督预训练（VideoMAE 的掩码重建、对比学习等）能从海量无标注视频里学到通用表示，再用少量标注微调就能达到不错效果。实践建议：永远从预训练权重出发，不要从零训练视频模型。

视频生成和理解能用一个模型吗？

趋势上是可以的（多模态统一模型），但目前工程上分开更高效。理解模型（编码器）追求高效提取语义，通常轻量、可批处理；生成模型（扩散）追求高质量输出，通常巨大、迭代慢。强行统一会让两边都变差。现实的多模态大模型（能看视频又能生成）往往是编码器 + LLM + 独立的生成模块拼起来的组合系统，而不是单一模型。

视频模型的任务与代价

任务输入 → 输出典型模型 / 代价
视频分类/理解视频 → 类别或描述I3D / VideoMAE / TimeSformer；采样 8~32 帧
行为识别片段 → 动作类别TSM / SlowFast；常用 16×4（16 帧 × 4 采样率）
时序定位长视频 → 动作起止时间需要长上下文，常先抽特征再定位

视频生成文本/图 → 视频扩散 + 时序注意力；最贵
插帧两帧 → 中间帧RIFE；实时可做
超分/修复低质视频 → 高质需考虑时序一致性
关键参数典型值说明
采样帧数8 / 16 / 32越多越准，代价线性增长
帧采样策略均匀 / 密集 / TSN 分段TSN 把视频分 K 段各取 1 帧，覆盖长时序
分辨率224×224（分类）/ 256~1024（生成）分类模型输入通常较小
25fps 视频 10 秒250 帧全处理太贵，必须采样
处理耗时（16 帧分类）约 20~100ms（GPU）比单图贵 10~30 倍
显存（16 帧 224²）约 3~10 GB与模型规模相关
视频 token 数帧数 × 每帧 token这是视频理解成本高的根本原因

为什么视频比图像贵一个数量级：一张 224×224 的图用 ViT 分块（16×16）是 (224/16)² = 196 个 token；一段 16 帧的同样分辨率视频就是 196 × 16 = 3136 个 token，16 倍。而注意力的计算量是 token 数的平方，所以直接套图像模型会贵 256 倍——这就是所有视频模型都要做时序压缩的原因。

常见做法与代码

# 视频抽帧（模型输入准备）—— 采样策略决定效果
import cv2, numpy as np

def sample_frames(video_path, num_frames=16, strategy="uniform"):
    cap = cv2.VideoCapture(video_path)
    total = int(cap.get(cv2.CAP_PROP_FRAME_COUNT))
    fps   = cap.get(cv2.CAP_PROP_FPS)
    if strategy == "uniform":                    # 均匀采样：简单，但可能漏掉短动作
        idxs = np.linspace(0, total - 1, num_frames).astype(int)
    elif strategy == "tsn":                      # TSN 分段采样：覆盖更全
        seg = total / num_frames
        idxs = [int(seg * i + seg / 2) for i in range(num_frames)]
    elif strategy == "dense":                    # 密集采样：看短时间窗内的运动
        step = max(1, int(fps) // 8)
        start = max(0, (total - step * num_frames) // 2)
        idxs = [start + i * step for i in range(num_frames)]
    frames = []
    for i in idxs:
        cap.set(cv2.CAP_PROP_POS_FRAMES, i)
        ok, f = cap.read()
        if ok: frames.append(cv2.cvtColor(f, cv2.COLOR_BGR2RGB))
    cap.release()
    return np.stack(frames)        # [T, H, W, C]
# 视频理解的标准 pipeline（以 CLIP 类视频检索为例）
# 1) 抽帧（16~32 帧）
# 2) 每帧过图像编码器 -> 帧级 embedding [T, D]
# 3) 时序池化：mean pooling / Transformer 聚合 -> 视频级 embedding [D]
# 4) 与文本 embedding 算余弦相似度

import torch.nn.functional as F

def video_embedding(frames, img_encoder, aggregator="mean"):
    frame_emb = img_encoder(frames)                 # [T, D]
    if aggregator == "mean":
        v = frame_emb.mean(dim=0)                   # 最省事
    elif aggregator == "attention":                 # 注意力池化，效果好一点
        q = torch.randn(1, frame_emb.size(-1))
        w = F.softmax(frame_emb @ q.T / (D ** 0.5), dim=0)
        v = (w * frame_emb).sum(dim=0)
    return F.normalize(v, dim=-1)                   # 检索必须归一化

sim = video_emb @ text_emb.T                        # 余弦相似度（已归一化）

排障清单

症状原因处理
短动作识别不出来采样帧数太少 / 均匀采样恰好跳过了动作增加帧数；用 TSN 分段采样；或用更高帧率的密集采样
长视频处理不动token 数爆炸先抽关键帧/镜头切分；两级处理（先粗筛片段再精分析）
显存 OOM帧数 × 分辨率太大降帧数（32→16）或分辨率；用梯度检查点；逐帧编码后释放
时序一致性差（闪烁）逐帧独立处理，没有时序约束加光流/时序注意力；对输出做时序平滑
推理太慢达不到实时模型重 + 帧数多用轻量模型（RIFE/TSM）；降分辨率；TensorRT
视频检索召回差池化丢失了时序信息用时序 Transformer 聚合而不是 mean pooling；或分片段检索再聚合
抽帧抽到黑帧/转场没做镜头切分先检测切镜点，在镜头内采样

成本控制的三个杠杆：① 减少帧数（最有效，线性降成本）；② 降低分辨率（平方级降成本）；③ 用轻量模型。实际项目里通常先砍帧数。
