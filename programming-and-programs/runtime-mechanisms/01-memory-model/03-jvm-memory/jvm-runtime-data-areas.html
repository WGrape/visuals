一句话：JVM 把内存分成「线程私有」（PC、虚拟机栈、本地方法栈）和「线程共享」（堆、方法区/元空间），再加上不受 GC 管理的堆外内存。

01运行时数据区总览

类加载后，JVM 按「线程私有 / 线程共享」划区。私有区随线程生灭；共享区被所有线程访问，由 GC 管理（堆）或由类加载器管理（元空间）。

区域是否私有存什么溢出表现
程序计数器 PC私有当前字节码指令地址不会 OOM
虚拟机栈私有栈帧：局部变量表/操作数栈/返回地址StackOverflowError / OOM
本地方法栈私有native 方法栈帧StackOverflowError / OOM
堆共享对象实例、数组OutOfMemoryError: Java heap space
方法区/元空间共享类元数据、常量、静态变量、JIT 代码Metaspace OOM（JDK8+ 元空间在本地内存）

02线程私有区

每个线程有独立 PC 与栈。方法调用压入栈帧，返回弹出；局部变量表中的对象引用指向堆。

📍 PC 程序计数器

字节码行号指示器；native 方法时为 undefined，唯一不会 OOM 的区域。

🧱 虚拟机栈

默认 1MB/线程（-Xss）；递归过深或栈帧过大触发 StackOverflowError。

🔌 本地方法栈

执行 native（C/C++）方法；HotSpot 与虚拟机栈合并。

03线程共享区：堆与元空间

堆是 GC 主战场，按分代划分（见 GC 页）。元空间（Metaspace）自 JDK8 取代永久代，存放类元数据，默认受本地内存上限约束（可用 -XX:MaxMetaspaceSize 限制）。

04堆外内存（Direct Buffer）

NIO 的 ByteBuffer.allocateDirect 直接在本地内存分配，不走 GC、减少一次内核态拷贝，但分配/回收更贵，且受 -XX:MaxDirectMemorySize 约束，满了报 OOM: Direct buffer memory。

// 堆外分配（0 拷贝网络/文件 IO 常用）
ByteBuffer buf = ByteBuffer.allocateDirect(1024 * 1024);
// 上限由 -XX:MaxDirectMemorySize 控制，默认约等于堆上限
// 回收依赖 Cleaner/PhantomReference，GC 才顺带释放，可能滞后

05常见误区

  • “栈溢出只在递归时”：任何导致栈帧超过 -Xss 的情况（大局部变量、过深调用链）都可能，不止递归。
  • “元空间不会 OOM”：类加载器泄漏（如热部署反复加载）会撑爆元空间，报 Metaspace。
  • “堆外内存不占 JVM 内存”：它占本地内存，总量仍受限，且 Full GC 才更易回收，监控要单独看。
  • “静态变量在堆里”：静态变量引用在，对象仍在堆；但类元数据在元空间。

06常见疑问

问：StackOverflowError 和 OOM 怎么分？

前者是单线程栈深度超限（几乎总是代码问题，如无限递归）；后者是申请不到内存（堆/元空间/直接内存各自有明确文案）。

问：为什么 JDK8 用元空间替代永久代？

永久代在堆内、大小难调、易 PermGen OOM；元空间用本地内存，随需增长，类元数据回收更自然，调优更简单。
