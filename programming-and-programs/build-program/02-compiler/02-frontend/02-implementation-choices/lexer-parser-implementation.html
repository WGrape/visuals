词法

词法分析：把字符流切成 Token

词法分析器（Lexer / Scanner）读入字符，输出 Token 序列：标识符、关键字、字面量、运算符、分隔符，并丢弃空白与注释。

// 典型手写实现：逐字符扫描 + 状态推进
type Lexer struct {
    input string
    pos   int
}

func (l *Lexer) NextToken() Token {
    l.skipWhitespace()
    ch := l.input[l.pos]
    switch {
    case isLetter(ch):  return l.readIdentifier()  // 关键字或标识符
    case isDigit(ch):   return l.readNumber()
    default:            return l.readOperator()
    }
}
实现要点：① 关键字通常先按标识符扫描，再查表区分；② 用最长匹配原则（如 == 不能拆成两个 =）；③ 记录行号列号以便报错。
路线

两条路线：手写 vs 生成

路线代表优点缺点
手写递归下降GCC 早期、Go 早期、V8错误信息友好、易调试、可随意加特例只适合 LL 类文法，左递归需改写
生成器Yacc/Bison、ANTLR、JavaCC处理能力强（可 LR）、文法变更快错误信息差、调试困难、生成代码难改
工业界趋势：现代主流语言（Go、Rust、TypeScript、V8）多选择手写递归下降——因为可控性强、错误提示好，而语言文法通常设计得便于手写分析。
实现

递归下降的三个要点

① 每个文法规则对应一个函数

// 文法：expr := term (('+' | '-') term)*
func (p *Parser) parseExpr() AST {
    left := p.parseTerm()
    for p.cur == PLUS || p.cur == MINUS {
        op := p.cur; p.next()
        right := p.parseTerm()
        left = &BinaryExpr{Op: op, Left: left, Right: right}
    }
    return left
}

② 用「优先级爬升」处理运算符优先级

把优先级低的规则放在外层、高的放内层（expr → term → factor），天然实现乘除优先于加减。

③ 前看（lookahead）决定分支

递归下降通常只需 1 个 Token 的前看即可选择产生式；若不够，说明文法不是 LL(1)，需要改写或增加前看。

体验

错误恢复：别让一个错刷屏

  • 恐慌模式（Panic Mode）：发现错误后跳过 Token 直到遇到同步点（如分号、右花括号），继续解析后续内容。
  • 错误产生式：在文法里显式写「常见错误形式」，给出更精确的提示。
  • 限制报错数量：连续错误过多就停止，避免刷屏。
  • 带位置信息：每个 Token 记录行列，报错才能指到源码位置。
好的编译器体验来自错误质量，而非解析算法多先进。能一次报出所有错误、每条都指到具体行列，是实用 Parser 的关键。
面试问答

高频问题

Q1：手写 Parser 和用生成器的取舍？
手写可控性强、错误提示友好、便于加特例，适合产品级语言实现（Go、V8、TypeScript 都手写）；生成器处理能力强、文法变更快，适合解析现成复杂文法（如 SQL），但错误信息差、调试难。
Q2：递归下降如何处理运算符优先级？
用「优先级爬升」：为每级优先级写一个函数，高优先级在低优先级的内层被调用。如 expr 调用 term，term 调用 factor，从而天然保证乘除优先于加减。
Q3：递归下降能处理左递归吗？
不能直接处理，左递归会导致无限递归。需要改写成右递归或迭代形式（如用 while 循环处理 expr := expr + term 这类规则）。
Q4：什么是 LL(1)、LR(1)？
LL(1) 从左到右扫描、最左推导、只需 1 个 Token 前看，适合手写递归下降；LR(1) 是最右推导的反向分析，表达能力更强（能处理左递归），常由 Yacc/Bison 这类生成器实现。
Q5：词法分析中关键字怎么识别？
通常先按标识符规则扫描出一串字符，再查关键字表判断是否保留字。这样避免为每个关键字单独写匹配规则。
Q6：什么是恐慌模式错误恢复？
发现语法错误后，跳过若干 Token 直到遇到同步记号（如分号、右括号），再继续解析。目的是一次扫描尽可能报出多个错误，而不是遇到第一个错就停止。

词法与语法分析：方法与代价

方法能力复杂度 / 适用
正则（re）只能描述正则语言词法分析足够，不能做括号匹配（需下推栈）
DFA正则语言，O(n) 无回溯词法分析首选；状态数通常 几十~几百
NFA→DFA 子集构造自动机等价转换最坏状态数 2^n 爆炸，实践中可控
递归下降LL(k)，手写友好Go/Rustc/V8 用它；不能处理左递归
LL(1) 分析表自顶向下，无回溯冲突少，但文法要改写（提左公因子、消左递归）
LR(1) / LALR(1)自底向上，能力最强yacc/bison；能处理左递归，表可能很大
Earley / GLR任意 CFG，含二义文法最坏 O(n³)，普通文法 O(n)；自然语言/C++ 用

为什么词法用 DFA、语法用下推自动机：词法单元（标识符、数字、关键字）是正则语言，DFA 线性时间搞定；而「括号配对」「if...else 嵌套」需要记住多少个未闭合，这是正则语言表达不了的（泵引理可证），必须有栈。

手写实现（可直接跑）

// 极简词法分析器：DFA 手写版（Go 风格伪码）
type Tok struct{ Kind, Val string }

func Lex(src string) []Tok {
    var out []Tok
    i := 0
    for i < len(src) {
        c := src[i]
        switch {
        case isSpace(c):
            i++
        case isDigit(c):                       // 数字：连续吃数字
            j := i
            for j < len(src) && isDigit(src[j]) { j++ }
            out = append(out, Tok{"NUM", src[i:j]})
            i = j
        case isAlpha(c):                       // 标识符/关键字
            j := i
            for j < len(src) && isAlnum(src[j]) { j++ }
            w := src[i:j]
            if isKeyword(w) { out = append(out, Tok{"KW", w}) } else {
                out = append(out, Tok{"ID", w})
            }
            i = j
        default:                               // 运算符
            out = append(out, Tok{"OP", string(c)})
            i++
        }
    }
    return out
}
# 递归下降：表达式文法（消除左递归后）
# 原文法（左递归，递归下降会无限循环）：
#   Expr   -> Expr '+' Term | Term
# 改写为（右递归 / 循环）：
#   Expr   -> Term (('+'|'-') Term)*
#   Term   -> Factor (('*'|'/') Factor)*
#   Factor -> NUM | '(' Expr ')'

def parse_expr(p):          # 优先级最低的在最外层，天然实现优先级
    node = parse_term(p)
    while p.peek() in ('+', '-'):
        op = p.next()
        node = BinOp(op, node, parse_term(p))
    return node

def parse_term(p):
    node = parse_factor(p)
    while p.peek() in ('*', '/'):
        op = p.next()
        node = BinOp(op, node, parse_factor(p))
    return node

def parse_factor(p):
    if p.peek() == '(':
        p.expect('('); node = parse_expr(p); p.expect(')')
        return node
    return Num(p.next().val)

排查与取舍

症状原因处理
递归下降栈溢出文法有左递归改写成循环：A → A α | β 变成 A → β α*
yacc 报 shift/reduce conflict文法有歧义（典型：dangling else）显式声明优先级 %left '+' %prec，或改写文法
正则匹配慢 / 卡顿回溯型引擎的灾难性回溯（如 (a+)+b）改用 RE2/DFA 型引擎（Go 的 regexp 就是 RE2，保证 O(n)）
错误的报错位置不准没记录 token 的 line/column每个 token 带上位置；AST 节点也带位置
NFA 转 DFA 状态爆炸复杂正则改用惰性 DFA（按需构造），实际只用到少量状态
关键字被当成标识符最长匹配优先级没处理好先按标识符规则吃满，再查关键字表（不是先匹配关键字）
  • 报错恢复：一次只报第一个错会很烦人，实用做法是「恐慌模式」——出错后跳到下一个同步 token（如 ;、}）继续解析，一次报多个错。
  • 手写 vs 生成：要精确的错误提示和 IDE 支持就手写（Clang、go/parser）；语法复杂且迭代快就用生成器。
