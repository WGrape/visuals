声码器与音频编解码

声学模型输出 mel 谱而非波形的原因、声码器决定的是音质而非内容；传统信号处理 / 神经声码器 / 神经音频 token 三条路线，以及离散 token 如何让语音与文本统一建模；16k / 24k / 48k 的适用场景与采样率不匹配这一隐性 bug；传输侧为什么实时链路选 Opus 而非 AAC；以及通过 dump 中间产物区分「声学模型问题」还是「声码器问题」的定位方法。
🧬

神经音频编解码器：EnCodec、SoundStream 与 RVQ

声码器只管「特征变声音」，神经 codec 管的是「声音变离散序列」——正是后者让语音能被语言模型直接读写。RVQ 串多个小码本逐级量化残差，天然形成「低层承载内容、高层承载音色」的分工，这是语音克隆与内容编辑能分开控制的根源。码率可用「帧率 × 层数 × 10 bit」量级估算，而实时链路最容易踩的坑是用了非因果 codec 引入固定前瞻延迟。
⚖️

音频编解码选型：码率、延迟与算力的三方权衡

通信 codec 追求「给定码率下听不出差别」，神经 codec 追求「把音频变成可建模的 token」，用音质单指标对比二者是最常见的误用。实时链路的延迟要拆成采集缓冲、编码算法延迟、网络抖动缓冲、播放缓冲四段分别测量——抖动缓冲常是最大头，只换 codec 往往感觉不到改善。码率存在可懂度平台、语音透明、收益递减三个拐点，超过透明点继续加码率只是白烧带宽。
🌏

语音翻译与同声传译

级联三段 / 语音直译文本 / 语音到语音三种实现各自的代价，选择关键在能否接受没有中间文本；同传「等上下文提高准确度」与「先输出降低延迟」的核心矛盾，以及增量输出加回改的工程解法；术语表、数字与单位校验、说话人分离、中英混用等实践要点；以及为什么语音翻译是实时语音对话的特例。
🔀

语音翻译的两条路线：级联与端到端

级联最危险的不是听不清，而是「听得很清楚但意思错了」——ASR 错一个词，MT 会忠实翻译这个错词，TTS 再清晰念出，听者毫无察觉。端到端没有显式文本因而无错误累积、延迟更低，但需要极度稀缺的「源语语音↔目标语语音」配对数据，实际能力上限常取决于伪标签质量。真实系统多用混合：实时预览走端到端求快，最终结果与存档走级联求准。
⏱️

同声传译策略：读多少才开口

同传的每个时刻都在做「再听一个词还是现在就翻」的决策，这个策略同时决定了延迟与质量，而两者天生冲突。wait-k 是最简基线（先读 k 个词再读写交替），但在英日这类语序倒置语言上容易译反；自适应策略让模型自己判断，把延迟-质量从一个固定点变成可调曲线。评测必须把首词延迟与平均滞后分开——平均滞后很低但每句开头等两秒，用户感受依然是慢。
