SQLite 动态类型

存储类、列亲和性（affinity），以及类型宽松带来的陷阱。

存储类列亲和性类型宽松陷阱

① 五种存储类

SQLite 是 动态类型：值自身携带类型，列只“建议”类型。存储类有：

存储类说明
NULL空
INTEGER有符号整数（1/2/3/4/6/8 字节）
REAL浮点（8 字节 IEEE）
TEXT文本（UTF-8/16）
BLOB二进制大对象

② 列亲和性（Affinity）

建表时写的 INTEGER / TEXT / REAL / NUMERIC / BLOB 只是“亲和性”——SQLite 会 尽量 把存入的值转换成该类型，但不强制。例如 TEXT 列也能存数字。

③ 类型宽松

与 MySQL/PostgreSQL 的静态强类型不同，SQLite 允许同一列混存不同类型，甚至能把字符串存进“整数”列。这让嵌入式场景灵活，但要求应用层自己保证类型正确。

CREATE TABLE t(a INT);
INSERT INTO t VALUES ('hello');  -- 允许！a 存成 TEXT

④ 陷阱

排序与比较：不同类型比较有固定规则（NULL < 数字 < 文本 < blob），混存会导致排序结果与预期不符；'10' < '9' 按文本比较为真。需要数值排序时务必保证存的是 INTEGER/REAL。
