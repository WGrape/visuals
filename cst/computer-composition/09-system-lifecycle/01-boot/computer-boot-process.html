📚 启动步骤详解

步骤 1: 按下电源按钮

当你按下计算机的电源按钮时，这是一个物理开关动作，会触发一系列硬件事件。

物理过程：
• 电源按钮连接主板的 POWER SW 引脚
• 按下后形成闭合电路，发送信号给电源供应器
• 这是一个低电压信号（通常 5V 或 3.3V）
• 主板芯片组检测到电源按钮信号

步骤 2: 电源供应器启动

电源供应器（PSU）接收到启动信号后，开始向计算机各组件供电。

供电过程：
• PSU 将交流电（AC 220V）转换为直流电（DC）
• 输出多种电压：+3.3V, +5V, +12V, -12V 等
• 首先输出 +5V Standby 电源（待机电源）
• 然后发送 POWER_GOOD 信号给主板
• 各组件开始接收电力，准备初始化

步骤 3: CPU 初始化

电源稳定后，CPU 从固定的内存地址开始执行指令，这是启动的关键一步。

CPU 启动过程：
• 电源 GOOD 信号触发 CPU RESET 引脚
• CPU 重置后，从固定地址读取第一条指令
• x86 架构：从 0xFFFF0 开始（BIOS 映射区域）
• CPU 跳转到 BIOS/UEFI 固件代码
• 此时内存尚未初始化，只能执行 ROM 中的代码

步骤 4: BIOS/UEFI 启动

BIOS（基本输入输出系统）或 UEFI（统一可扩展固件接口）开始执行，这是连接硬件和操作系统的桥梁。

BIOS/UEFI 功能：
• POST（加电自检）：检测硬件是否正常
• 初始化硬件组件（内存、CPU、显卡等）
• 建立系统资源映射表
• 提供硬件抽象层，供操作系统调用
• UEFI 相比 BIOS 支持更大硬盘、更快启动、图形界面

步骤 5: 内存检测与初始化

BIOS/UEFI 检测并初始化系统内存（RAM），为后续操作做准备。

内存初始化：
• 检测内存条数量、容量、类型（DDR4/DDR5）
• 测试内存读写是否正常
• 建立内存地址映射表
• 将 BIOS/UEFI 代码和数据复制到内存（Shadow RAM）
• 加速后续固件代码执行

步骤 6: 引导设备选择

BIOS/UEFI 根据启动顺序（Boot Order）查找可引导设备。

引导过程：
• 读取 CMOS 中保存的启动顺序设置
• 依次检测：硬盘、SSD、U盘、光盘等
• 查找引导扇区（Boot Sector）或 EFI 系统分区
• MBR（主引导记录）：位于硬盘第一个扇区
• GPT（GUID 分区表）：UEFI 模式使用
• 找到可引导设备后，加载引导加载程序

步骤 7: 操作系统加载

引导加载程序（Bootloader）加载操作系统内核，完成从固件到操作系统的切换。

操作系统启动：
• Bootloader（如 GRUB, Windows Boot Manager）：
- 加载操作系统内核到内存
- 传递启动参数给内核
• 内核初始化：
- 解压缩内核映像
- 初始化内核子系统（进程管理、内存管理等）
- 挂载根文件系统
• 启动第一个进程（Linux: systemd/init, Windows: wininit.exe）
• 系统服务启动，最终到达登录界面

按下电源之后，CPU 做的第一件事

刚加电时内存里空空如也，操作系统还没加载，现代的多级页表、缓存、中断机制都还没建立。CPU 只能从一个硬编码在硬件里的位置开始取指令。

加电 reset ↓ CPU 内部寄存器被初始化为固定值 CS:IP（或复位向量）指向固件 ROM 的入口 ↓ 执行第一条指令 —— 这是唯一「不需要被加载」的程序 （因为它烧在主板芯片里，加电即可用）
七步启动：从固件到用户态进程

MBR 与 GPT：怎么找到操作系统在哪

对比MBR（传统）GPT / UEFI（现代）
位置磁盘第一个扇区，512 字节分区表在 GPT 头，启动文件放在 FAT 格式的 ESP 分区里
容量限制寻址上限约 2TB几乎无限制（理论值极大）
分区数量最多 4 个主分区（要扩展分区才能更多）通常支持 128 个以上
冗余与校验单点损坏即无法启动头尾各保留一份备份 + CRC 校验
启动方式读取 512 字节里前面的引导代码UEFI 直接读取 ESP 中的 .efi 文件
安全无验证机制支持 Secure Boot 校验签名

MBR 那 512 字节是怎么用的：前 446 字节是引导代码，中间 64 字节是 4 个分区表项（每项 16 字节），最后 2 字节是魔数 0x55AA —— 固件用这最后两个字节判断「这个磁盘能不能启动」。

为什么放不下这么多事？—— 引导链的分段接力 MBR 前 446 字节 → 只够做一件事：加载下一段 ↓ 更复杂的中间阶段 → 认识文件系统，读取真正的启动管理器 ↓ GRUB stage2 → 有界面、能读配置、能加载各种格式的内核 ↓ kernel → 它有完整能力，可以解压自己、探测硬件、mount 根分区

这个「接力」的设计思路与 UEFI 直接从 FAT 分区读文件相比显得笨拙，但它解释了为什么引导修复（比如 grub install、boot-repair）总是围绕那几个字节做文章。

内核加载之后做了什么

  1. 解压自身。压缩存放的内核镜像展开到内存。
  2. 建立最基本的内存管理。从 firmware 提供的内存映射表接手物理内存，建立早期页表。
  3. 探测硬件与加载驱动。识别 CPU、总线、磁盘控制器、网卡等。
  4. 挂载根文件系统。这一步之前内核还没有「文件」的概念，靠的是临时的内存文件系统 initramfs/initrd 先顶一下。
  5. 启动第一个用户态进程。通常是 init/systemd，进程号 1。
  6. 由它拉起一切。挂载剩余文件系统、启动网络、拉起服务、进入登录或图形界面。

initramfs 存在的理由值得单独说：内核要挂载根文件系统，就必须有对应文件系统与磁盘控制器的驱动；但这些驱动可能打包在根文件系统里 —— 构成一个鸡生蛋问题。解决办法是先在内存里放一个极小的临时根文件系统，里面装必需的驱动模块，用它把真正的根挂起来。

启动慢怎么查

阶段看什么常见瓶颈
固件 / POST开机 logo 停留时间开启了不必要的设备自检、内存检测过久、启动顺序里试了不存在的设备
引导程序GRUB 菜单等待超时设得太长、扫描了所有磁盘
内核初始化启动日志里的时间戳某个驱动探测长期等待、硬件超时
用户态服务systemd-analyze blame绝大多数「开机慢」在这一步：串行依赖、不必要的服务、网络等待
图形 / 登录登录界面出现的时间桌面环境的自动启动项过多

一条实操建议：先用 systemd-analyze blame 看服务耗时排名，再用 systemd-analyze critical-path 看关键路径。绝大多数电脑上，「开机慢」根本不是硬件或内核的问题，而是用户态服务串得太多。

深入自检

UEFI 一定优于传统 BIOS 吗？

功能上是全面占优：更规范的接口、原生支持 GPT 与大硬盘、 Secure Boot、鼠标 graphical 界面、自带的网络能力。代价是复杂度上升，也带来一些新的兼容性问题（比如 Secure Boot 会拦未签名的系统与驱动）。实际使用中，如果是新机器且不需要装的老系统，优先 UEFI。

为什么有些系统要关闭 Secure Boot 才能安装？

Secure Boot 要求启动链上每一步（引导程序、内核）都带有被平台信任的签名。一些发行版或其驱动未被信任、或者用户自己编译了内核但未签名，就过不了校验。这时要么导入自己的密钥，要么暂时关闭 —— 代价是失去防rootkit的一道保护。

双系统为什么经常互相破坏引导？

常见原因是后安装的系统覆盖了同一份引导记录（MBR 或 EFI 启动项），或它按自己的理解重建了启动菜单而没有兼容前者的格式。GRUB 需要在安装后扫描所有已存在的操作系统并重新生成配置；Windows 的安装程序则可能直接把自己的启动管理器设为默认。

虚拟机和容器的「启动」也是这样吗？

不完全。虚拟机仍需走 firmware→引导→内核这条完整链路（虽然往往是简化版）。容器共享宿主的内核，跳过了前面所有步骤，直接准备 rootfs、命名空间、cgroup 然后执行入口命令 —— 这正是容器能做到「秒级启动」的根本原因：它没有 bootloader 也没在初始硬件。
