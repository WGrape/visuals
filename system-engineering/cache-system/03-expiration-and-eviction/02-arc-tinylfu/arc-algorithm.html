先建立直觉：自动调节的两格抽屉

你有一个抽屉，中间隔板可以左右滑动，分成两格：

  • 左格（T1）：放「只见过一次」的新东西；
  • 右格（T2）：放「见过多次」的老熟人。

ARC 的聪明之处在于：隔板会根据实际效果自己移动。如果发现「被淘汰的新东西很快就又被需要」（说明该多留新东西），隔板就往右挪，扩大左格；反之则往左挪。

核心价值：ARC 让你不必在 LRU 和 LFU 之间做选择——它根据负载自动找到合适的平衡点，且不需要手工调任何参数。

四个队列

队列内容是否占缓存
T1只访问过一次的数据是
T2访问过两次及以上的数据是
B1从 T1 被淘汰的 key（只记 key）否
B2从 T2 被淘汰的 key（只记 key）否

调节规则：幽灵命中驱动

参数 p 表示 T1 的目标大小（T2 就是 C - p）。调节逻辑非常直观：

  1. 访问的数据在 B1（从 T1 淘汰出去的）→ 说明「新数据淘汰太快了」 → 增大 p（给 T1 更多空间）。
  2. 访问的数据在 B2（从 T2 淘汰出去的）→ 说明「热数据淘汰太快了」 → 减小 p（给 T2 更多空间）。
  3. 访问的数据在 T1 → 移到 T2（它已经是「多次访问」了）。
  4. 新数据 → 进 T1。
为什么幽灵队列有效？它被淘汰后又被访问了，这就是「上一次淘汰决策是错的」的直接证据。ARC 不需要预测未来，只需要从过去的错误中学习。这是它自适应的本质。

与 LRU / LFU 的对比

算法优点缺点
LRU简单、O(1)、适应变化快易被批量扫描污染
LFU抗扫描、保护热点历史包袱、新数据饥饿、需调参
ARC自适应、免调参、兼顾两者实现较复杂、需额外幽灵队列内存
代价：幽灵队列要记录被淘汰的 key（通常各不超过 C 个），带来额外的内存开销和管理复杂度，大约是几个百分点的额外内存。

什么时候用 ARC

  • ✅ 负载特征不明或会变化：不知道该偏 LRU 还是偏 LFU，ARC 能自己找到平衡点。
  • ✅ 无法人工调参：嵌入式、存储系统底层（ZFS 的 ARC 就是著名应用）。
  • ❌ 负载简单稳定：纯 LRU 更省事，没必要引入复杂度。

🎯 面试问答

Q：幽灵队列为什么不直接存数据？
A：因为它的唯一作用是判断「上次的淘汰对不对」，只需要知道「这个 key 曾经存在过、被淘汰了」，不需要它的内容。存数据会白白占用缓存容量，违背设计目的。只记 key（或 key 的哈希）即可把开销降到很低。

Q：ARC 怎么知道该偏向 LRU 还是 LFU？
A：通过幽灵命中判断：如果刚从 T1（新数据区）淘汰的 key 又被访问，说明新数据淘汰得太快，就把调整参数 p 调大，给 T1 更多空间（更偏 LRU）；反之若从 T2（热数据区）淘汰的 key 又被访问，说明热数据没留住，就调小 p（更偏 LFU）。它靠的是「过去淘汰错了」的证据，而不是预测。

Q：ARC 需要调参数吗？
A：基本不需要，这正是它最大的卖点。参数 p 由算法根据幽灵命中自动调整。相比之下，LFU 的衰减速率、初始频次等都需要根据负载手工调，调错了效果反而更差。ARC 的实用价值就在这里：开箱即用、自适应。

Q：有哪些真实系统在用 ARC？
A：最著名的是 ZFS 文件系统的缓存（ARC 这个名字就出自这里），此外一些存储引擎和商业 CDN 也有采用。在应用层缓存中，Caffeine 的 W-TinyLFU 是更常见的选择——它用另一种方式（频次 sketch + 准入）达到了类似的甚至更好的效果，且内存开销更可控。

ARC 算法的结构与参数

组成部分作用大小关系
T1只被访问过一次的页（LRU 链表）T1 + T2 = c（总容量）
T2被访问过两次及以上的页（LFU 侧）T2 是「真正的热数据」
B1从 T1 被淘汰的页的键历史（ghost）|B1| ≤ c
B2从 T2 被淘汰的页的键历史|B1| + |B2| ≤ c
p自适应参数：T1 的目标大小0 ≤ p ≤ c
命中场景调整动作p 的变化
命中 T1 或 T2移到 T2 顶部不变
未命中，但键在 B1说明 T1 太小，p = min(p + δ, c)δ = 1（若 |B1|≥|B2|）否则 max(|B2|/|B1|, 1)
未命中，但键在 B2说明 T2 太小，p = max(p - δ, 0)δ = 1（若 |B2|≥|B1|）否则 max(|B1|/|B2|, 1)
完全未命中插入 T1；若超限则按规则淘汰不变

ARC 的核心思想：用 ghost 列表（B1/B2）记住「最近被淘汰的是谁」。如果一个刚被淘汰的 key 又被访问了，说明缓存容量分配错了——从 B1 回来说明该给 T1 更多空间（p 增大），从 B2 回来说明该给 T2 更多（p 减小）。这就是「自适应」的来源：不需要调参，算法自己根据访问模式调整 LRU/LFU 的比例。

ghost 列表只存键不存值，所以开销很小（每个键几十字节），但能让缓存「记住」自己犯过的错。这是 ARC 相比纯 LRU 的关键增量。

伪代码与实现要点

def arc_get(key):
    if key in T1 or key in T2:
        move_to_top(T2, key)              # 命中 -> 升到 T2（多次访问）
        return value[key]
    return None

def arc_put(key, value):
    if key in T1 or key in T2:            # 已在缓存
        move_to_top(T2, key); return

    if len(T1) + len(T2) >= c:            # 满了，先腾位置
        replace(key)

    if key in B1:                          # 从 B1 回来 -> 增大 T1 目标
        delta = 1 if len(B1) >= len(B2) else max(len(B2) // len(B1), 1)
        p = min(p + delta, c)
        replace_in(key, B1)
        append_top(T2, key)
    elif key in B2:                        # 从 B2 回来 -> 增大 T2 目标
        delta = 1 if len(B2) >= len(B1) else max(len(B1) // len(B2), 1)
        p = max(p - delta, 0)
        replace_in(key, B2)
        append_top(T2, key)
    else:                                  # 全新键
        if len(T1) + len(B1) >= c:
            if len(T1) < c:
                evict_lru(B1); replace(key)
            else:
                evict_lru(T1)
        append_top(T1, key)                # 第一次访问 -> 进 T1
# ARC 的 replace 规则（核心）
def replace(key_in_b2=None):
    if len(T1) >= 1 and (
        (key_in_b2 and len(T1) == p) or len(T1) > p
    ):
        # T1 太大：淘汰 T1 的 LRU 端，键记入 B1
        k = evict_lru(T1); append_mru(B1, k)
    elif T2:
        # 否则淘汰 T2 的 LRU 端，键记入 B2
        k = evict_lru(T2); append_mru(B2, k)

# 关键性质：
#   1) |T1| + |T2| <= c              缓存总量
#   2) |T1| + |B1| <= c              T1 与其历史
#   3) |T1| + |T2| + |B1| + |B2| <= 2c   总内存不超过 2c（ghost 只存键，实际开销小）

# ARC vs LRU 的实际效果
#   - 顺序扫描场景：ARC 命中率明显优于 LRU（扫描不会冲掉 T2 里的热数据）
#   - 稳定 Zipf 分布：与 LRU 相当或略优
#   - 开销：每次访问多几次链表操作，约比 LRU 慢 5~10%

  • ARC vs LRU：ARC 能抵抗顺序扫描污染（扫描的数据只在 T1 停留，不会冲走 T2 的热数据），且自适应无需调参。代价是实现复杂度和约 2c 的键存储。
  • ARC vs W-TinyLFU：ARC 用「访问次数」区分冷热（T1/T2）；W-TinyLFU 用频次估计（Count-Min Sketch）做准入控制，空间更省。Caffeine 选了后者，因为它对超大规模更友好。
