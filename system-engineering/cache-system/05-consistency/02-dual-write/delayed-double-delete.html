⏱️ 延迟双删详解

删除缓存 → 更新库 → 休眠 → 再删，缩小并发不一致窗口

兜底

时序

① 删除缓存 → ② 更新数据库 → ③ 休眠（如 500ms，覆盖并发读回填耗时）→ ④ 再删缓存。第二次删除清掉期间可能被回填的脏值。

为什么需要第二次删

第一次删后若读请求未命中，会查到更新前的旧 DB 值并回填缓存；休眠后再删一次，把这段窗口产生的脏值清掉。

休眠时长怎么定

取“读业务耗时”的经验上限，太短清不净、太长拖慢写。可结合消息队列在写完成后异步触发第二次删。

🎯 面试问答

Q：延迟双删解决了什么？
A：清掉并发读回填产生的脏缓存。
Q：休眠时间设多少？
A：读业务耗时经验上限，可异步化。
Q：还有更优方案吗？
A：Canal 订阅 binlog 失效缓存，业务无侵入。
