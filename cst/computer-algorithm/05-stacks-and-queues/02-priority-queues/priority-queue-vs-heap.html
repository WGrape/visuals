🔄 优先队列 vs 堆 🔍

通过动态可视化，让你彻底理解两者的关系

🌲 堆 (Heap)

数据结构——一种完全二叉树，每个节点的值都不大于（或不小于）其父节点的值。

• 最大堆：父节点 ≥ 子节点 → 根是最大值
• 最小堆：父节点 ≤ 子节点 → 根是最小值

📋 优先队列 (Priority Queue)

抽象数据类型——一种行为规范，规定"每次取出的元素是优先级最高的"。

• 只定义做什么（出队优先级最高的）
• 不规定怎么做（可以用堆、数组、链表实现）

🔗 两者的关系

堆是实现优先队列的一种方式（最常见、最高效的方式）。

打个比方：
• 优先队列 = "我想吃水果"（需求/接口）
• 堆 = "我买了苹果"（具体实现）
• 数组 = "我买了香蕉、草莓、葡萄"（其他实现方式）

💡 一句话总结

堆是一种数据结构，优先队列是一种行为规范（ADT）。
堆是实现优先队列最高效的方式，但不是唯一方式。

• 队列 = "先进先出" ← 行为规范
• 数组/链表 = 具体实现

• 优先队列 = "优先级高的先出" ← 行为规范

堆的典型应用

① Top-K 问题

  • 求最大的 K 个：维护大小为 K 的小顶堆，新元素比堆顶大就替换。
  • 复杂度 O(n log K)，空间 O(K) —— 十亿数据也能流式处理。
  • 注意方向：求最大用小顶堆（堆顶是当前最小、最该被淘汰的）。
  • 这也是「海量数据求 Top-K」的标准解法。

② 定时任务与延迟队列

  • 按触发时间建小顶堆，堆顶就是最近要执行的任务。
  • 线程只需 sleep 到堆顶时间，无需轮询全部任务。
  • 时间轮（Timing Wheel）是另一种方案：适合大量短时任务，精度要求不高时更高效。
  • Kafka、Netty 等都有各自的定时实现。

③ 中位数与双堆

  • 维护一个大顶堆（较小的一半）+ 一个小顶堆（较大的一半）。
  • 保持两堆大小差 ≤1，中位数即为堆顶之一或二者平均。
  • 插入 O(log n)，查询 O(1) —— 流式数据中位数的经典解法。

④ 合并 K 个有序序列

  • 把每个序列的首元素入堆，每次取最小并补入该序列下一个。
  • 复杂度 O(N log K)，N 为总元素数。
  • 应用：归并 K 个有序链表、多路归并排序（外部排序）、数据库归并连接。

⑤ 堆排序与它的特点

  • 建堆 O(n) + 反复取堆顶 O(n log n)，总体 O(n log n)。
  • 原地、不稳定、常数因子较大（缓存不友好）。
  • 实际很少作为首选排序，但「部分排序/保证最坏 O(n log n)」场景有价值。

深入自检

优先队列和堆是一回事吗？

不是。优先队列是抽象数据类型（定义「能做什么」），堆是具体的数据结构（定义「怎么做」）。堆是最常用的实现方式，但不是唯一。理解这个区别，才能在需要「删除任意元素」「修改优先级」等操作时，想到改用平衡树或带索引的堆。

建堆为什么是 O(n) 而不是 O(n log n)？

因为大部分节点在底层，它们的调整深度很小。严格求和：第 h 层有约 n/2^(h+1) 个节点、每个最多下滤 h 层，总和收敛到 O(n)。关键是「自底向上」地调整，而不是对每个节点做一次 O(log n) 的插入。

求最大的 K 个数，为什么用小顶堆？

因为小顶堆的堆顶是这 K 个候选里最小的那个，正好是「最该被替换掉」的元素。新元素只要比堆顶大，就说明它更有资格进入 Top-K，替换堆顶即可。若用大顶堆，堆顶是最大的，无法判断谁该被淘汰。

堆能保证整体有序吗？

不能。堆只保证「父节点优于子节点」，不保证左子树与右子树之间的顺序，同层节点之间也没有顺序关系。所以要得到完整有序序列，必须反复弹出堆顶（这就是堆排序的做法）。

需要修改某个元素的优先级怎么办？

普通二叉堆定位元素要 O(n)。解决方案：① 维护「元素 → 下标」的索引，修改后上滤或下滤（indexed heap）；② 用平衡树/跳表代替堆；③ 用「懒惰删除」：不真删，插入新值，弹出时检查是否过期（Dijkstra 常用这招）。

堆在缓存方面表现如何？

一般。数组表示虽然紧凑，但下滤时父子下标跳跃（i 与 2i+1），跨越距离随层数指数增长，深层访问会频繁 Cache Miss。改进方案有 d 叉堆（d=4 更缓存友好）、B-heap 等。这也是理论复杂度相同但实测有差距的原因之一。

第三层 · 排障与边界：优先队列的高频坑

坑后果正确做法
以为优先队列是有序的遍历顺序乱只有队首保证最值；要有序就反复出队
需要最大堆却建了最小堆取到最小值取负数（Python）/ 反向比较器（Java C++）
要删除中间元素标准 API 不支持用延迟删除：外部哈希表打标记，出队时跳过
对象的优先级变了却没重建队列顺序失效删除后重新插入（或改用支持 decrease-key 的实现）
Python 直接对堆用 sort()破坏堆性质只能经 heapq 的函数操作
堆里元素是元组且第一个相等继续比较第二个甚至第三个显式写成 (priority, tiebreak, obj)
  • 排查顺序：先确认只依赖队首 → 再确认大小顶方向 → 再看是否需要中途删除 → 最后看元素比较规则。
  • 边界一：优先队列不是有序容器。要前 k 个最值只能出队 k 次。
  • 边界二：标准库的优先队列大多不支持 decrease-key（Dijkstra 优化要用），替代方案是「重复插入 + 延迟删除」。
  • 边界三：Python 的 heapq 不是线程安全的；多线程场景要加锁或用 queue.PriorityQueue（带锁版本）。

延迟删除在 Dijkstra 中的应用

# Dijkstra 里的标准做法：重复插入 + 延迟删除（代替 decrease-key）
import heapq
dist = {s: 0}
pq = [(0, s)]
visited = set()
while pq:
    d, u = heapq.heappop(pq)
    if u in visited: continue        # 延迟删除：已处理过就跳过
    visited.add(u)
    for v, w in graph[u]:
        nd = d + w
        if nd < dist.get(v, float('inf')):
            dist[v] = nd
            heapq.heappush(pq, (nd, v))   # 不删除旧的，让它自然被跳过
优先队列和堆是一回事吗？

不是。优先队列是接口/抽象数据类型（定义「能插入、能取最值」），堆是实现它的一种数据结构。就像「栈」是接口、「数组」可以实现它一样。绝大多数语言的 PriorityQueue 内部就是二叉堆。

什么时候需要斐波那契堆？

当算法里有大量 decrease-key 操作时（如稠密图上的 Dijkstra）。它把 decrease-key 降到 O(1) 均摊。但它的常数因子很大，实际性能常常不如二叉堆——所以实践中「重复插入 + 延迟删除」的二叉堆方案反而更快。

Top-K 到底用大顶堆还是小顶堆？

求 Top-K 大用小顶堆（维持 k 个候选，堆顶是候选里最小的，新元素比它大才替换）；求 Top-K 小则反过来。记忆法：堆顶放「门槛」，新来的要比门槛更优才准入。
