栈内存管理

Go 的 goroutine 使用可增长的连续栈：初始很小，需要时复制扩容、不够时再缩。理解栈分配、逃逸分析与栈伸缩，有助于写出省 GC 的代码。对应左书 7.3。

栈扩容：复制式

不够就搬

当栈满，runtime 分配一块更大的新栈，把旧栈内容整体复制过去，更新所有指针——对 G 自身透明。

// 旧实现：分段栈（栈满跳到新段，return 再跳回）
// 现实现：连续栈（整体复制到更大连续块）
// 触发：函数入口检查栈剩余，不够则 morestack -> growstack
栈缩容

GC 时回收多余

栈在 GC 周期若发现只用了一小部分，会缩回更小的尺寸，避免长期占用。收缩同样复制内容。

因为可伸缩，Go 鼓励「多开 goroutine、局部变量随便用」；不必像 C 那样纠结栈大小。
逃逸分析

决定变量去哪

编译器分析变量生命周期：若可能逃出函数（如返回指针、被并发引用），就分配到堆；否则留在栈。栈对象随函数返回自动回收，零 GC 成本。

// 逃逸：返回局部变量指针 -> 分配堆
func f() *int { x := 1; return &x }

// 不逃逸：留在栈
func g() int { x := 1; return x }  // x 在栈

// go build -gcflags="-m" 查看逃逸结论
实践建议

减少堆分配

让临时对象留在栈、复用 buffer（sync.Pool）、避免不必要的指针传递，能显著降低 GC 压力。

⚠️ 逃逸分析是编译期启发式，并非百分百；用 -gcflags=-m 验证关键路径，别凭直觉。
