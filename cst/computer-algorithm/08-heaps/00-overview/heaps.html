第 08 章 · 堆

随时取出极值

堆只保证父子之间的局部顺序，不要求整棵树像搜索树那样全局有序。

核心速览

堆序性质父 ≥ 子（大顶堆）或 父 ≤ 子（小顶堆）
完全二叉树按层紧密填充，可用数组存储，无指针
堆顶 O(1)最大/最小值永远在根，取用无需查找
插入删除 O(log n)靠上浮 / 下沉沿一条路径调整

先建立直觉：堆是「永远能拿到最值」的结构

如果让你随时报出一组数里的最小值，你会怎么做？

  • 无序数组：每次扫描一遍，O(n)。
  • 有序数组：最值在两端，O(1) 拿到；但插入要搬移元素，O(n)。
  • 平衡搜索树：全部操作 O(log n)，但为了「只要一个最值」付出了完整有序的代价。
  • 堆：只维护「父子间的大小关系」，不维护全局有序，于是插入删除只要 O(log n)，取最值 O(1)。
核心取舍：堆放弃了「全序」，只保留「偏序」。它不关心第二小是谁，只保证最小的那个在堆顶。这个「少做一点事」的取舍，正是它比平衡树更快、更省的原因。

两条性质：形状 + 堆序

二叉堆必须同时满足：

  1. 结构性：是一棵完全二叉树——按层从左到右紧密填充，除最后一层外全满，最后一层靠左对齐。
  2. 堆序性：小顶堆中每个节点 ≤ 它的孩子；大顶堆中每个节点 ≥ 它的孩子。注意：左右孩子之间没有顺序要求。
关键认知：堆的数组表示不是有序数组。上例 [1,3,2,7,5,9,4] 中堆顶 1 最小，但整体并不升序（3 在 2 前面）。堆只保证「沿任意一条从根到叶的路径是递增的」，不同分支之间没有顺序。

两个核心操作：上浮与下沉

插入 → 上浮（sift up / percolate up）

  1. 把新元素放到数组末尾（完全二叉树的下一个空位），保证结构性。
  2. 它可能比父节点小，破坏了堆序性 → 与父节点交换，一路向上，直到父节点 ≤ 它或到达根。

因为只沿一条从叶到根的路径移动，路径长度 = 树高 = O(log n)。

删除堆顶 → 下沉（sift down / percolate down）

  1. 用最后一个元素顶替堆顶（直接删根会破坏完全二叉树的结构性）。
  2. 新的根可能太大 → 与两个孩子中较小的那个交换，一路向下，直到满足堆序或成为叶子。
为什么必须和「较小的孩子」交换？如果和较大的孩子交换，那个较大的孩子会变成它兄弟的父节点，而兄弟更小——父子关系又被破坏了。选较小的孩子当新父，两个分支都安全。
def sift_down(a, i, n):          # 小顶堆，n 为堆大小
    while True:
        l, r = 2*i+1, 2*i+2
        small = i
        if l < n and a[l] < a[small]: small = l
        if r < n and a[r] < a[small]: small = r
        if small == i: break       # 已满足堆序
        a[i], a[small] = a[small], a[i]
        i = small

def pop_min(a):                  # 取走最小值
    top = a[0]
    a[0] = a.pop()               # 末尾元素顶替堆顶
    if a: sift_down(a, 0, len(a))
    return top

建堆：O(n) 而不是 O(n log n)

一个常见误解：把 n 个元素逐个插入是 O(n log n)。但自底向上建堆（Heapify）可以做到 O(n)。

  1. 把数组直接视作一棵完全二叉树（结构性自动满足）。
  2. 从最后一个非叶子节点（下标 n//2 − 1）开始，从右往左、从下往上依次对每个节点执行下沉。
为什么是 O(n) 而不是 O(n log n)？因为大部分节点在底层，而下沉代价与高度成正比。底层有约 n/2 个叶子（代价 0），n/4 个高度 1 的节点（代价 1），n/8 个高度 2 的（代价 2）……求和 Σ (n/2^h)·h 收敛到 2n。所以是 O(n)——这是一个反直觉但必考的结论。

复杂度与典型应用

操作复杂度说明
取最值 peekO(1)就是数组首元素
插入 pushO(log n)上浮
删除最值 popO(log n)下沉
建堆 heapifyO(n)自底向上
删除任意元素O(log n)需额外维护 下标→位置 的映射
查找任意元素O(n)堆不擅长查找

典型应用：

  • Top-K 问题：维护一个大小为 k 的堆，扫一遍数据即可。求最大的 k 个用小顶堆（堆顶是这 k 个里最小的，新元素比它大就替换）；求最小的 k 个用大顶堆。复杂度 O(n log k)，内存只要 O(k)——海量数据求 Top-K 的标准解法。
  • 优先队列：Dijkstra 最短路、Prim 最小生成树、任务调度都依赖它。
  • 堆排序：建堆后反复 pop，得到有序序列，O(n log n) 且原地。
  • 中位数流：一个大顶堆存较小的一半 + 一个小顶堆存较大的一半，两个堆顶即中位数。
优先队列 ≠ 堆本身。「优先队列」是抽象接口（push / pop 最值），堆是最常见的一种实现（也可以用有序数组、平衡树实现）。工程上二者常被混用，但概念上要分清。

🎯 面试问答

Q：堆和二叉搜索树有什么区别？

A：核心区别是有序的程度。BST 维护全局有序：左子树 < 根 < 右子树，因此支持查找任意元素、范围查询、前驱后继，全是 O(log n)。堆只维护父子间的局部大小关系（父 ≤ 子），左右孩子之间没有顺序，所以它只能 O(1) 拿到最值，查找任意元素要 O(n)。取舍很清晰：只要最值 → 堆更省更快；需要查找或有序遍历 → 必须用平衡树。

Q：为什么堆必须是完全二叉树？

A：为了能用数组紧凑存储。完全二叉树按层紧密填充、没有空洞，按层序编号后父子下标可以直接算出来（左孩子 2i+1、右孩子 2i+2、父节点 (i−1)//2），不需要任何指针。这既省内存又提升缓存局部性。同时它也保证树高恰好是 ⌊log n⌋，使得上浮/下沉的代价稳定在 O(log n)。如果允许任意形状，数组会出现大量空洞，就必须改用指针存。

Q：删除堆顶时为什么用最后一个元素顶替，而不是直接删？

A：因为直接删除根节点会在中间留下一个空洞，破坏「完全二叉树」的结构性，数组表示就不再紧凑。做法是：把最后一个元素移到根位置（结构性恢复：仍然是一棵完全二叉树），此时它可能违反堆序性，再对它执行一次下沉（O(log n)）恢复堆序。同理，插入时把新元素放在末尾再上浮，也是为了先保住结构性。

Q：建堆为什么是 O(n) 而不是 O(n log n)？

A：因为自底向上（heapify）时，代价与节点高度成正比，而绝大多数节点都在底层。粗略地：约 n/2 个叶子高度 0（代价 0）、n/4 个高度 1（代价 1）、n/8 个高度 2（代价 2）……总代价 Σ (n/2^h)·h 收敛到约 2n，因此是 O(n)。而「逐个插入」的方式每个元素都要 O(log n)，总共 O(n log n)。结论：批量初始化用 heapify，别用逐个 push。

Q：Top-K 问题为什么求最大的 k 个要用小顶堆？

A：因为小顶堆的堆顶是候选集合里最小的那个，也就是「最容易被淘汰的」。扫描数据时：堆不满 k 个就直接放入；满了之后，若新元素 > 堆顶，说明它比候选里最差的强，弹出堆顶并放入新元素。这样堆中始终保留着目前见过的最大的 k 个。同理，求最小的 k 个要用大顶堆。复杂度 O(n log k)，空间只要 O(k)，是海量数据 Top-K 的标准解法。

Q：优先队列和堆是一回事吗？

A：不是。优先队列是抽象数据类型（接口），定义的操作是「插入元素」和「取出优先级最高/最低的元素」；堆是实现它的一种具体数据结构（最常见、最高效的一种）。优先队列也可以用有序数组、无序数组或平衡搜索树来实现，只是复杂度不同。概念上要分清：一个是「要做什么」，一个是「怎么做」。

第二层 · 参数·命令·量化：堆的数组表示与操作代价

堆之所以能用数组而不是指针节点表示，是因为它是完全二叉树——除最后一层外全满，最后一层靠左排列，于是下标可以算出来。

手写堆的核心操作

# 手写向下调整（sift down）——堆的核心操作
def sift_down(a, i, n):
    while True:
        l, r = 2 * i + 1, 2 * i + 2
        smallest = i
        if l < n and a[l] < a[smallest]: smallest = l
        if r < n and a[r] < a[smallest]: smallest = r
        if smallest == i: break           # 已满足堆性质
        a[i], a[smallest] = a[smallest], a[i]
        i = smallest

# 建堆：从最后一个非叶子往前做 sift down，O(n)
def build_heap(a):
    for i in range(len(a) // 2 - 1, -1, -1):
        sift_down(a, i, len(a))
    return a

# 堆排序：建堆后反复把堆顶换到末尾
def heap_sort(a):
    build_heap(a)
    for end in range(len(a) - 1, 0, -1):
        a[0], a[end] = a[end], a[0]       # 堆顶（最小）放到最后
        sift_down(a, 0, end)               # 注意区间缩小为 end
    return a[::-1]                         # 小顶堆得到降序，反转成升序

关键量级：建堆是 O(n) 而不是 O(n log n)——因为大部分节点在底层、调整距离为 0，把所有节点的调整代价求和后级数收敛到 O(n)。

第三层 · 排障与边界：堆的高频坑

坑后果正确做法
以为堆是有序数组用 h[1] 当第二小，结果错只有堆顶保证最值；要前 k 个必须删 k 次
逐个插入来建堆O(n log n) 而非 O(n)已知全部元素时用 heapify
把堆当数组直接 sort破坏堆性质堆只能经 push/pop 操作
需要最大堆却建了最小堆取到的是最小值取负数（Python）或自定义比较器
需要删除中间元素堆做不到 O(log n)用延迟删除：哈希表打标记，弹出时跳过
Top-K 先 push 再 pop堆大小超过 k，逻辑绕满了就 heapreplace（一步完成）
  • 排查顺序：先确认只依赖堆顶 → 再确认用 heapify 建堆 → 再看是否需要删除中间元素 → 最后确认大小顶方向。
  • 边界一：堆不是有序结构，只能保证「父 ≤ 子」。兄弟节点之间没有任何顺序关系。
  • 边界二：Python 的 heapq 只提供最小堆；存元组时按第一个元素比较，相等时继续比第二个。
  • 边界三：堆不支持 O(log n) 的「修改优先级」和「删除任意元素」，需要这些就上带索引堆或平衡树。

延迟删除

# 延迟删除：支持「中途删除任意元素」的标准做法
import heapq
from collections import defaultdict

class LazyHeap:
    def __init__(self):
        self.h, self.dead = [], defaultdict(int)
    def push(self, x):   heapq.heappush(self.h, x)
    def remove(self, x): self.dead[x] += 1        # 只打标记，O(1)
    def pop(self):
        while self.h:
            x = heapq.heappop(self.h)
            if self.dead.get(x):                  # 已被标记删除，跳过
                self.dead[x] -= 1
                continue
            return x
        raise IndexError("empty")
堆和二叉搜索树怎么选？

只关心最值、且只增删堆顶 → 堆（数组实现、常数小、省空间）。需要查找任意元素、按顺序遍历、删除中间元素 → BST / 平衡树。堆的功能很窄但很专。

为什么堆排序不如快排常用？

堆排序的时间复杂度虽是 O(n log n) 且最坏有保证，但它缓存不友好（跳跃访问数组），实际常数比快排大；且它不稳定。所以工程上快排/归并更常见，堆只在需要「动态取最值」时才登场。

堆顶有序，不代表整个堆数组有序。
