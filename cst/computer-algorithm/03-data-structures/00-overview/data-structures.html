第 03 章 · 数据结构

如何选择数据结构

数据结构把“存什么”与“怎样组织、访问和修改”连接起来；不存在所有操作都最快的万能结构。

核心速览

数组连续内存，按下标 O(1)；中间插入 O(n)
链表指针连接，已知位置插入 O(1)；按序查找 O(n)
哈希表按键 O(1)；无顺序
平衡树全部 O(log n)；有序

唯一的选型原则：看「最频繁的操作」

数据结构的选择不是看数据叫什么名字，而是看你要对它做什么。同一个「用户列表」，如果每次都是按下标随机访问，用数组；如果每次都在中间插入删除，用链表；如果每次都按 id 查，用哈希表；如果要按积分排名，用平衡树或堆。

具体步骤：① 列出所有操作；② 标出频率最高和性能要求最苛刻的那几个；③ 选一个让这些操作最快的结构；④ 检查其他操作是否还在可接受范围。没有「所有操作都最快」的结构，选型的本质就是取舍。

三条主要的取舍轴

抽象数据类型 vs 具体实现

这是很多人混淆的概念。ADT（抽象数据类型）定义「能做什么」，数据结构定义「怎么做到」。

抽象类型（接口）常见实现取舍
栈 Stack数组 / 链表数组更快更省（除非需要动态无界）
队列 Queue循环数组 / 链表定长用循环数组，不定长用链表
优先队列堆 / 平衡树 / 有序数组堆最常用（O(log n) 插入 + O(1) 取最值）
字典 Map哈希表 / 平衡树不需顺序用哈希，需要顺序用树
集合 Set哈希表 / 平衡树同上
并查集数组 + 路径压缩近乎 O(1) 的合并与查询
为什么要分清？因为同一个接口可能有多种实现，性能差别巨大。C++ 里 std::map（红黑树）和 std::unordered_map（哈希表）是同一个接口的两套实现，一个 O(log n) 一个 O(1)，但只有前者有序。选型时先确定接口需求，再挑实现。

组合使用才是常态

真实系统里几乎不会只用一种结构，而是组合多种结构来同时满足不同需求：

  • Hash + 双向链表 = LRU 缓存：哈希表保证 O(1) 查找，链表保证 O(1) 维护访问顺序。
  • 哈希表 + 跳表 = Redis ZSet：哈希表做 member→score 的 O(1) 映射，跳表按 score 排序支撑范围查询。
  • 两个堆 = 中位数流：大顶堆存较小的一半、小顶堆存较大的一半。
  • 数组 + 索引 = 数据库：数据顺序存放，B+ 树索引提供快速定位。
组合的思路：找出「哪几种操作各自需要什么结构」，然后让它们共享同一份数据（通常通过指针或下标互引），用空间换多种操作的高效。

选型决策树

  1. 需要按下标随机访问？→ 数组（或动态数组）。
  2. 只在一端进出？→ 栈 / 队列。
  3. 需要按键精确查找？
    • 还需要顺序 / 范围 → 平衡树
    • 不需要顺序 → 哈希表
  4. 只要最大/最小值？→ 堆。
  5. 频繁在中间插入删除？→ 链表（若位置已知）或平衡树。
  6. 需要前缀匹配（字符串）？→ Trie。
  7. 需要频繁合并/查询连通性？→ 并查集。
  8. 数据是层级关系？→ 树；是任意关系？→ 图。

🎯 面试问答

Q：选择数据结构的根本原则是什么？

A：看最频繁、性能要求最高的操作是什么，而不是看数据叫什么名字。步骤：① 列出所有操作；② 标出频率最高和最苛刻的那几个；③ 选让这些操作最快的结构；④ 检查其他操作是否仍可接受。不存在所有操作都最快的结构，选型本质就是取舍。例如同一个「用户列表」，按下标访问用数组、按 id 查用哈希表、按积分排名用平衡树或堆，选择完全不同。

Q：数组和链表最本质的区别是什么？

A：最本质是内存布局：数组连续，链表靠指针连接。由此派生出所有差异：数组按下标 O(1) 随机访问（offset = 基址 + i × 元素大小）且缓存局部性好（预取相邻数据），但中间插入删除要搬移后续元素 O(n)；链表已知位置插入删除 O(1)（只改指针）且无需连续内存，但按位置访问要 O(n) 逐个跳转，且每个节点有指针开销、缓存不友好。「O(1)」都有前提：数组的 O(1) 是按下标，链表的 O(1) 是已知位置。

Q：哈希表和平衡搜索树怎么选？

A：核心看是否需要「顺序」。只需要按 key 精确查找/插入/删除 → 哈希表，均摊 O(1) 更快。需要范围查询（查区间内的所有键）、前驱/后继、有序遍历、按排名访问 → 必须用平衡搜索树（红黑树、B+ 树），因为哈希表把键打散了，顺序信息彻底丢失。这也是数据库索引选 B+ 树而非哈希表的原因。另外哈希表可能需要扩容（有均摊成本）、内存开销更大；平衡树性能更稳定（最坏也是 O(log n)）。

Q：堆和平衡树都能取最值，怎么选？

A：看是否只需要最值。只要最大/最小 → 堆：取最值 O(1)、插入删除 O(log n)、可用数组实现、无指针开销、建堆 O(n)，明显更省。堆不维护全局有序，所以查找任意元素是 O(n)、不支持有序遍历。如果需要查找任意键、范围查询或有序遍历 → 必须用平衡树。一句话：只要极值用堆，要更多用树。

Q：什么是抽象数据类型（ADT）？和数据结构有什么区别？

A：ADT 定义「能做什么」（接口与语义），数据结构定义「怎么做到」（具体存储与算法）。例如「优先队列」是 ADT，规定「插入元素」和「取出最值」两个操作；而堆是实现它的一种数据结构（也可以用有序数组、平衡树实现，只是复杂度不同）。分清二者的意义在于：同一个接口可能有多种实现，性能差别巨大——C++ 的 std::map（红黑树，O(log n)，有序）和 std::unordered_map（哈希表，O(1)，无序）就是典型例子。先确定接口需求，再挑实现。

Q：为什么真实系统常常组合多种数据结构？

A：因为单一结构只能优化一种访问模式，而实际需求往往有多种。组合的思路是：找出「哪几种操作各自需要什么结构」，然后让它们共享同一份数据（通过指针或下标互引），用空间换多种操作的高效。典型例子：LRU 缓存 = 哈希表（O(1) 查找）+ 双向链表（O(1) 维护顺序）；Redis ZSet = 哈希表（member→score O(1)）+ 跳表（按 score 排序、支持范围查询）；中位数流 = 大顶堆 + 小顶堆。

第三层 · 排障与边界：选型与使用的高频坑

坑后果正确做法
用 list.pop(0) 当队列O(n) 出队，n 大时超时用 collections.deque.popleft()
在数组中间频繁插入O(n) 搬运改链表；或先收集后批量处理

遍历时修改容器行为未定义 / 漏元素遍历副本，或用下标倒序删
  • 选型顺序：先问「要不要随机访问」（要→数组）→ 再问「要不要有序」（要→平衡树）→ 再问「只查存在性吗」（是→哈希）→ 最后问「只关心最值吗」（是→堆）。
  • 边界一：数组的优势是缓存局部性——连续内存，同样 O(n) 的遍历，数组比链表快几倍。
  • 边界二：哈希表的 O(1) 是均摊的，扩容时要重哈希，单次插入可能 O(n)。
  • 边界三：并查集的 ≈O(1) 来自「路径压缩 + 按秩合并」两个优化，精确界是反阿克曼函数 α(n)，实践中视为常数。

# 哈希表的坑：可变对象不能做键
d = {}
d[(1, 2)] = 'ok'        # tuple 可以
# d[[1, 2]] = 'bad'     # list 会报 TypeError: unhashable type: 'list'

# 遍历时删除的正确做法（不要边遍历边 del）
a = [1, 2, 3, 4, 5]
a = [x for x in a if x % 2]        # 用列表推导生成新列表
# 或按下标倒序删除
for i in range(len(a) - 1, -1, -1):
    if a[i] % 2 == 0: del a[i]
数组和链表到底什么时候选哪个？

访问模式决定一切：随机访问多 → 数组（O(1) 下标 + 缓存友好）；已知位置的插入删除多 → 链表（O(1) 改指针，但要先 O(n) 找到位置）。实际工程中数组胜率更高，因为缓存效应很显著。

为什么 Python 的 list 插入是 O(n) 但 append 是 O(1)？

因为 list 是动态数组：append 在尾部，通常是 O(1)；只有容量满时才扩容（整体搬一次，但均摊下来仍是 O(1)）。中间插入必须把后面元素整体后移，所以是 O(n)。

什么时候该自己实现数据结构？

几乎不用。语言内置容器覆盖了 95% 的场景，且经过充分优化。例外：需要特殊操作（如带索引的堆、并查集、Trie、线段树）时，标准库没有，才自己写。

根据最频繁的操作选择结构，而不是根据名称选择。
