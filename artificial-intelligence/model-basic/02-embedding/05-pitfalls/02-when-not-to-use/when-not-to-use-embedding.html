2. 什么时候不该用 Embedding

Embedding 不是万能锤。下面几类场景，它要么效果差，要么有更便宜的方案。先判断'该不该上'，再谈怎么上。

2.1 不适合的场景

场景为什么 Embedding 不合适更合适的做法
精确结构化匹配（订单号/手机号）语义向量会模糊掉精确值数据库精确查询 / BM25
强时序 / 计数类向量丢了顺序与量级时间序列库 / 聚合查询
只有几条数据建向量库、调模型的成本高于收益直接规则 / 全文搜索
需要可解释的决策向量黑盒，说不清为什么近规则引擎 / 特征工程

2.2 用之前先问三个问题

  • 要的是'语义相近'还是'字面相等'？后者请用关键词/精确匹配。
  • 数据量够建库吗？几十到几百条，全文搜索或规则更快更准。
  • 能否接受'近似'？向量检索是近似最近邻（ANN），不保证全局最优点，金融/医疗等强一致场景要谨慎。

2.3 一个判断口诀

'同义改写多、字面少'→ 上 Embedding；'精确值、强顺序、要解释'→ 别上。 大多数业务是混合的，所以生产检索几乎都是'稠密 + 稀疏 + 重排'三件套，而不是单靠 Embedding。
