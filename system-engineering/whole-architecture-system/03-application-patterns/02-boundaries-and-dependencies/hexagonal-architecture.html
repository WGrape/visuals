什么时候适用？

判断信号：同一业务能力要接受多个输入入口，并能替换外部输出技术。

  • HTTP 与 CLI 共用下单用例
  • 仓储实现从 MySQL 切到内存测试
  • 外部支付供应商由适配器隔离

和相近方案怎么区分？

相近方案选择边界
整洁架构都保护业务核心；六边形用输入/输出端口明确交互点，整洁架构强调层级依赖。
GoF 适配器端口适配器可使用 Adapter 模式；六边形描述整个应用边界。

最小伪代码

interface PlaceOrderPort { place(items) }
interface OrderStore { save(order) }
class PlaceOrder implements PlaceOrderPort {
  constructor(store: OrderStore) { this.store = store }
  place(items) { this.store.save(Order.create(items)) }
}

边界：端口代表业务需要的能力；别把数据库客户端接口原样搬进核心。

端口与适配器 Ports & Adapters

领域在中心，外层是适配器；依赖方向永远指向中心

核心思想：领域逻辑不依赖任何框架。它只定义『端口』（需要什么能力、提供什么能力），外层用『适配器』把具体技术（MySQL、REST、Kafka）接到端口上。业务可脱离数据库/Web 单独测试。

为何又叫『端口适配器』

因为图形象征是把系统画成六边形，每条边是一个端口，外接一个适配器。本质是『依赖倒置』的彻底贯彻。

面试高频问答

Q：六边形架构和整洁架构有什么关系？
A：它们是同一思想（依赖朝向领域核心）的不同表达。六边形强调『端口/适配器』，整洁架构强调『同心圆依赖规则』，本质都要求领域不依赖基础设施。
Q：适配器会不会越写越多？
A：会，但这是优点：每个外部技术只是一个适配器，替换技术（如 MySQL 换 Postgres）只改适配器，核心不动。
