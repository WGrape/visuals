🔒 HTTPS 工作原理

HTTPS = HTTP + TLS/SSL，在传输层对数据进行加密，确保通信的机密性、完整性和身份认证

🔐

加密传输

所有数据通过 TLS 加密隧道传输，即使被截获也无法读取明文内容

📜

身份认证

通过数字证书（CA 签发）验证服务器身份，防止中间人伪造

✅

数据完整

MAC 消息认证码确保数据在传输过程中未被篡改

核心加密技术

HTTPS 综合使用非对称加密、对称加密和散列算法实现安全通信

🔤 非对称加密

用于握手阶段的密钥交换和身份认证

常用算法：
RSA
2048 / 4096 bit
ECDHE
椭圆曲线 DH
ECDSA
椭圆曲线签名
特点：公钥加密，私钥解密。速度慢，仅用于握手阶段交换会话密钥。ECDHE 支持前向安全（PFS）——即使长期私钥泄露，历史会话密钥也不会被推导。

⚡ 对称加密

用于握手完成后实际数据的加密传输

常用算法：
AES-128-GCM
AEAD 加密
AES-256-GCM
AEAD 加密
ChaCha20-Poly1305
AEAD 加密
特点：加密解密使用同一密钥，速度快（比非对称快 100-1000 倍）。GCM 模式同时提供加密和认证（AEAD），无需额外 HMAC。

🧮 散列 / 摘要算法

用于验证数据完整性和生成 MAC

常用算法：
SHA-256
SHA-384
HMAC-SHA256
作用：对传输数据生成摘要，接收方重新计算并比对，确保数据未被篡改。证书签名也依赖散列算法。

🔗 数字证书体系

PKI 信任链确保服务器身份可信

签发流程：
① 服务器生成 CSR（证书签名请求），包含公钥和域名
② CA 机构验证服务器身份（域名所有权等）
③ CA 用自己的私钥对 CSR 签名，签发数字证书
④ 客户端通过 CA 公钥验证证书签名 → 建立信任

HTTP vs HTTPS 对比

一目了然的区别

对比项 HTTP HTTPS
默认端口 80 443
安全性 明文传输 加密传输
证书要求 不需要 需要 CA 签发的 SSL/TLS 证书
加密类型 无加密 非对称加密（握手）+ 对称加密（传输）
数据完整性 无法验证，易被篡改 HMAC / AEAD 保证完整性
SEO 影响 搜索引擎会降权 Google / 百度优先收录
性能开销 无额外开销 握手增加 1-2 RTT，现代硬件影响可忽略

完整数据流

从浏览器输入 URL 到页面渲染的全过程

1️⃣ DNS 解析
域名 → IP 地址（可通过 DoH/DoT 加密 DNS 查询）
2️⃣ TCP 三次握手
SYN → SYN-ACK → ACK（建立可靠连接）
3️⃣ TLS 握手（如上图 7 步）
协商加密参数、验证证书、交换密钥、建立安全通道
4️⃣ 加密 HTTP 请求/响应
所有数据通过对称加密隧道传输（AES-GCM / ChaCha20）
5️⃣ 页面渲染
浏览器解析 HTML、加载资源、执行 JS → 显示页面 🎉

TLS 握手的轮次与耗时

版本握手轮次耗时（RTT 数）
TLS 1.2（首次）2 轮2 RTT + TCP 1 RTT = 3 RTT
TLS 1.2（会话复用）1 轮1 RTT
TLS 1.3（首次）1 轮1 RTT（总 2 RTT）
TLS 1.3（0-RTT）0 轮0 RTT，第一个数据包就带应用数据
QUIC/HTTP3（首次）合并1 RTT（传输+加密合并握手）
QUIC（恢复）0 轮0 RTT
参数 / 概念值说明
RSA 密钥交换TLS 1.2 及以前不支持前向保密；1.3 已移除
ECDHE 密钥交换主流支持前向保密；常用 X25519 / P-256
证书验证CA 链 + 域名匹配 + 有效期过期/域名不匹配会报错
OCSP Stapling服务端带上吊销状态省一次 OCSP 查询（省 100~300ms）
会话票证（Session Ticket）服务端加密的会话状态无需服务端存储；注意票据密钥要轮换
HSTS max-age常 31536000（1 年）强制 HTTPS，防降级攻击
证书有效期现在最长 398 天（约 13 个月）CA/B 论坛规定；Let's Encrypt 是 90 天

跨地域时握手的代价：北京↔上海 RTT 30ms，TLS 1.2 首次访问需要 3 个 RTT = 90ms 纯握手；TLS 1.3 只要 2 个 RTT = 60ms。对首屏来说这是纯损失。所以升级 TLS 1.3 + 会话复用 + 长连接是最有效的首屏优化。

诊断命令

# 1) 看握手详情
openssl s_client -connect example.com:443 -servername example.com -tls1_3
# 输出关键行：
#   Protocol  : TLSv1.3
#   Cipher    : TLS_AES_128_GCM_SHA256
#   Verify return code: 0 (ok)     <- 0 = 证书验证通过

# 2) 只看证书信息
openssl s_client -connect example.com:443 </dev/null 2>/dev/null \
  | openssl x509 -noout -dates -subject -issuer
#   notBefore / notAfter  <- 有效期
#   subject=CN=example.com

# 3) 测各阶段耗时
curl -w "dns=%{time_namelookup} tcp=%{time_connect} tls=%{time_appconnect} \
ttfb=%{time_starttransfer} total=%{time_total}\n" -o /dev/null -s https://example.com
# time_appconnect - time_connect = TLS 握手耗时
# time_starttransfer - time_appconnect = 服务器处理时间

# 4) 检查是否支持 TLS 1.3 / 0-RTT
openssl s_client -tls1_3 -connect example.com:443
# 或在线：SSL Labs 的 ssllabs.com/ssltest
# 5) Nginx 的 TLS 配置（现代最佳实践）
server {
    listen 443 ssl http2;
    ssl_protocols TLSv1.2 TLSv1.3;           # 禁用 TLS 1.0/1.1
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:...;
    ssl_prefer_server_ciphers off;

    ssl_session_cache shared:SSL:50m;        # 约能存 40 万会话
    ssl_session_timeout 1d;
    ssl_session_tickets on;                  # 会话票证，支持 0-RTT(1.3)

    ssl_stapling on;                          # OCSP Stapling，省一次查询
    ssl_stapling_verify on;

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    # HTTP/2 必须的 ALPN 由 nginx 自动处理
}

# 6) 自签证书（内网测试）
openssl req -x509 -newkey rsa:2048 -nodes -keyout key.pem \
  -out cert.pem -days 365 -subj "/CN=localhost"
# 客户端需要 -k 或把 cert 加入信任链

排障清单

症状原因处理
certificate has expired证书过期续期；设监控（提前 30 天告警）
hostname mismatch证书 CN/SAN 与访问域名不符证书要包含所有访问域名（用 SAN）
unable to get local issuer certificate缺中间证书（链不完整）证书文件要含完整链（leaf + intermediate）
首屏很慢TLS 1.2 + 无会话复用升 TLS 1.3；开 session ticket；用长连接
0-RTT 有安全风险0-RTT 数据可被重放只在幂等请求上用 0-RTT；关键操作禁用
客户端不支持 TLS 1.3老客户端/老 OpenSSL保留 TLS 1.2 兼容；监控客户端分布
握手偶发失败中间设备（防火墙/负载均衡）干扰检查是否做了 SSL 中间人；看 ALPN 协商

证书链不完整是最容易犯的错：只配置了 leaf 证书，浏览器能靠 AIA 扩展自动补全，但 curl、Java、Go 客户端往往会直接失败。配置时一定要把 fullchain.pem（leaf + intermediate）配上去。
