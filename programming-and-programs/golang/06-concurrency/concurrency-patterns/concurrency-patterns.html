Worker Pool

用缓冲 channel 当信号量

启动固定数量的 worker，任务通过 channel 分发，既限制并发又避免无节制创建 goroutine。

sem := make(chan struct{}, 10)  // 最多 10 并发
for _, job := range jobs {
    sem <- struct{}{}
    go func(j Job) {
        defer func() { <-sem }()
        process(j)
    }(job)
}
Pipeline

阶段间用 channel 串联

每个阶段是「接收-处理-发送」的 goroutine，用 channel 连接；上游慢下游不慌，天然背压。

func stage(in <-chan int) <-chan int {
    out := make(chan int)
    go func() {
        defer close(out)
        for v := range in { out <- v*v }
    }()
    return out
}
Fan-in / Fan-out

分叉并行，汇聚结果

Fan-out：多个 worker 消费同一输入提速；Fan-in：把多个 channel 合并成一个。二者常配合处理批量任务。

合并多个 channel 可用一个 select 循环，或把每个源用 goroutine 转发到统一输出再 close。
取消传播

用 context 统一撤收

长链任务把 ctx 一路传下去，父取消时所有子 goroutine 收到信号，及时退出、释放资源。详见 Context 篇。

ctx, cancel := context.WithCancel(parent)
defer cancel()
for i := 0; i < n; i++ {
    go worker(ctx, i)
}
// 某处 cancel() -> 所有 worker 的 <-ctx.Done() 解除阻塞
书中经典示例

从例子学模式

并发爬虫（用 channel 收集结果 + 去重）、并发目录遍历（递归 + goroutine + 同步等待）、聊天服务（广播 channel 给所有连接）——都是上述模式的组合。

并发循环

用闭包捕获循环变量会踩坑；把迭代变量作为参数传入 goroutine，或用 Go 1.22+ 的循环变量语义。
