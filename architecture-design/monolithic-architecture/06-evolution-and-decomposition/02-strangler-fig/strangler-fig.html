绞杀者模式：安全地拆单体

别搞“大爆炸“重写。绞杀者模式（Strangler Fig）像藤蔓缠树：在旧单体旁逐步长出新服务，按功能一块块接管流量，随时可停、可回退。

核心思路防腐层路由切换为何安全

🌿 一、核心思路

在旧单体旁边新建服务，用“路由“把越来越大的流量切到新服务，旧代码像被藤蔓绞死一样逐步退役。
入口路由
API Gateway
→
新服务
已抽出的模块
↘
旧单体
尚未迁移部分

每次只迁移一个功能域，验证无误再推进下一块。大重写被切成无数小步。

🛡️ 二、防腐层（ACL）

💡
防腐层（Anti-Corruption Layer）是新服务与旧单体之间的“翻译官”：把旧系统的脏模型、怪接口，隔离在边界之外，不让旧世界的混乱污染新服务的干净领域模型。
  • 新服务只认自己的模型，旧模型由 ACL 适配。
  • 即使旧单体很乱，新服务仍能保持清洁架构。

🔀 三、路由如何切换

阶段路由策略状态
初期该功能的请求仍走旧单体新服务在旁路就绪
灰度按路径/比例把流量导到新服务双写或读旧库验证
切换该功能 100% 走新服务旧代码标记废弃
退役删除旧实现绞杀完成

✅ 四、为什么它安全

  • 可回退：路由一改就能把流量切回旧单体，不必连夜救火。
  • 业务不停：迁移期间系统始终可用，没有“停机切换”。
  • 风险分散：每次只动一块，出事影响面小。
  • 价值早现：最先抽出的往往是收益最大的痛点模块。
✅
一句话：别重写，要绞杀。用路由和防腐层把风险锁在小步里，单体就能平滑地“长“出微服务。
