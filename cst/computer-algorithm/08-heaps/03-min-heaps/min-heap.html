第 08 章 · 小顶堆

让最小值始终处于堆顶

小顶堆维护“父节点 ≤ 子节点”；它是优先队列常用实现，也适合维护数据流中最大的 k 个数。

核心速览

堆序父 ≤ 子
堆顶 O(1)最小值永远在 a[0]
上浮 / 下沉插入变小就上浮，删除后下沉
Top-K 最大维护 k 个候选，堆顶是最该被淘汰的

小顶堆是什么

小顶堆（Min Heap）是一棵完全二叉树，满足每个节点的值 ≤ 它的孩子。由此推出：整棵树的最小值一定在根节点——沿任意路径往下走，值只会越来越大。

它不保证全局有序：左右孩子之间没有顺序要求，第二小的数在左还是在右都不确定。小顶堆只维护「父子之间的偏序」，不维护全序——这正是它比平衡搜索树更省、比有序数组更快的原因。

两个核心操作

插入 → 上浮（sift up）

  1. 新元素放到数组末尾（保住完全二叉树的形状）。
  2. 若它小于父节点，就与父交换，一路向上，直到父 ≤ 它或到达根。

删除堆顶 → 下沉（sift down）

  1. 用最后一个元素顶替堆顶（直接删根会破坏形状）。
  2. 新的根可能太大 → 与两个孩子中较小的那个交换，一路向下，直到满足堆序或成为叶子。
为什么必须和「较小的孩子」交换？如果和较大的孩子交换，那个较大的孩子就成了它兄弟的父节点，而兄弟更小——父子关系又被破坏。选较小的孩子当新父，两个分支都安全。
def sift_down(a, i, n):          # 小顶堆
    while True:
        l, r = 2*i+1, 2*i+2
        small = i
        if l < n and a[l] < a[small]: small = l
        if r < n and a[r] < a[small]: small = r
        if small == i: break
        a[i], a[small] = a[small], a[i]
        i = small

def pop_min(a):                  # 取走最小值
    top = a[0]
    a[0] = a.pop()
    if a: sift_down(a, 0, len(a))
    return top
建堆（heapify）是 O(n)：从最后一个非叶子节点（下标 n//2 − 1）开始，自底向上、从右往左依次下沉。底层节点多但高度小，总代价收敛到约 2n，优于逐个 push 的 O(n log n)。

典型应用一：优先队列

小顶堆是优先队列最常见、最高效的实现：每次出队的是优先级最高（值最小）的元素。

操作小顶堆有序数组无序数组
插入O(log n)O(n)（要搬移）O(1)
取走最小值O(log n)O(1)O(n)（要找）
查看最小值O(1)O(1)O(n)
建结构O(n)O(n log n)O(n)

典型场景：Dijkstra 最短路（每次取距离最小的节点）、Prim 最小生成树（每次取最短的横切边）、任务调度（按优先级）、事件驱动模拟（按时间先后）、合并 K 个有序链表。

Dijkstra 为什么非用优先队列不可？因为它的贪心策略要求「每次取出当前距离最小的未确定节点」。用数组每次要 O(V) 扫描找最小，总复杂度 O(V²)；用小顶堆则取最小 O(log V)，总复杂度降到 O((V+E) log V)。这是堆最经典的实战价值。

典型应用二：维护最大的 k 个数

思路（页脚那句话）：维护一个大小为 k 的小顶堆，堆顶是这 k 个候选里最小的——也就是「最该被替换的那个」。扫描数据时：堆不满就放入；满了之后，若新元素 > 堆顶，就弹出堆顶、放入新元素。扫完堆里就是最大的 k 个。
import heapq   # Python 标准库直接就是小顶堆

def largest_k(nums, k):
    heap = []
    for x in nums:
        if len(heap) < k:
            heapq.heappush(heap, x)
        elif x > heap[0]:               # 比堆顶（候选里最小的）大 → 替换
            heapq.heapreplace(heap, x)
    return heap                          # 堆里就是最大的 k 个（堆顶是其中最小的）
为什么不用排序？排序 O(n log n) 且需要全量数据常驻内存；小顶堆只要 O(n log k) 和 O(k) 内存。当 n 极大（几亿条）而 k 很小（Top 100）时，这个差距是决定性的——这就是海量数据 Top-K 的标准解法。

进阶：两个堆求中位数

对于数据流（元素一个个到来，随时问当前中位数），用一个堆解决不了，标准做法是两个堆：

  • 大顶堆 lo：存较小的一半，堆顶是这一半的最大值。
  • 小顶堆 hi：存较大的一半，堆顶是这一半的最小值。
  • 不变式：lo 的元素个数与 hi 相等或恰好多 1；且 max(lo) ≤ min(hi)。

于是中位数 = （元素总数为奇数时）lo 的堆顶，或（偶数时）两个堆顶的平均。每次插入后做一次再平衡（把一个堆的堆顶挪到另一个堆），代价 O(log n)，查询 O(1)。

🎯 面试问答

Q：小顶堆和大顶堆有什么区别？怎么选？

A：唯一区别是堆序方向：小顶堆「父 ≤ 子」，最小值在根；大顶堆「父 ≥ 子」，最大值在根。结构性（完全二叉树、数组存储、上浮下沉）完全一样，只是比较符号相反。选型口诀：让「最该被淘汰的」待在堆顶——求最大的 k 个 → 最该被替换的是候选里最小的 → 用小顶堆；求最小的 k 个 → 最该被替换的是候选里最大的 → 用大顶堆。

Q：求最大的 k 个数，为什么用小顶堆？

A：因为小顶堆的堆顶是候选集合里最小的那个，也就是「最该被替换的」。扫描数据时：堆不满 k 个就放入；满了之后，若新元素 > 堆顶，说明它比候选里最差的还强，于是弹出堆顶、放入新元素。扫完堆里就是最大的 k 个。复杂度 O(n log k)，内存只要 O(k)——当 n 极大而 k 很小时，这比排序的 O(n log n) + O(n) 内存有决定性优势。

Q：小顶堆怎么实现优先队列？复杂度是多少？

A：优先队列要求「插入元素」和「取出优先级最高（值最小）的元素」。小顶堆是最常见也最高效的实现：插入 O(log n)（上浮）、取走最小值 O(log n)（下沉 + 顶替）、查看最小值 O(1)（就是 a[0]）、批量建堆 O(n)。相比有序数组（插入 O(n)）和无序数组（取最值 O(n)），堆把两个操作都压到 O(log n)，综合最优。Dijkstra、Prim、任务调度、合并 K 个有序链表都依赖它。

Q：为什么 Dijkstra 必须用优先队列？

A：因为 Dijkstra 的贪心策略要求「每次取出当前距离最小的未确定节点」——这正是优先队列的「取最小值」操作。若用普通数组，每次要 O(V) 扫描找最小，总复杂度 O(V²)；改用小顶堆后，取最小值只 O(log V)（配合松弛后的 decrease-key），总复杂度降到 O((V+E) log V)。这是堆最经典、最有代表性的实战价值。

Q：怎么用两个堆求数据流的中位数？

A：维护两个堆：大顶堆 lo 存较小的一半（堆顶是这半的最大值），小顶堆 hi 存较大的一半（堆顶是这半的最小值）。不变式：lo 的元素个数与 hi 相等或恰好多 1，且 max(lo) ≤ min(hi)。于是中位数 = 奇数时 lo 的堆顶，偶数时两个堆顶的平均。每来一个新元素：先按大小放入其中一个堆，再把多出来的堆顶挪到另一个堆以恢复平衡。插入 O(log n)，查询 O(1)。

Q：堆适合做什么？不适合做什么？

A：适合：① 反复取最小/最大值（O(1) 看、O(log n) 取走）；② 优先队列（Dijkstra、Prim、任务调度）；③ 海量数据 Top-K（O(n log k) + O(k) 内存）；④ 堆排序（最坏 O(n log n) 且原地 O(1) 空间）；⑤ 两堆求中位数流。不适合：① 查找任意元素（O(n)，因为堆只有偏序）；② 有序遍历 / 范围查询（堆不维护全序）——这些要用平衡搜索树；③ 需要稳定的排序场景（堆排序不稳定）。

第一层 · 概念与判定：什么时候该用堆

一句话判据：只关心「最大/最小的那个」，且数据会动态变化——用堆。要排序或查找任意元素，别用堆。

需求用堆？更好的选择复杂度对比
动态取最小值（Top-K / 优先队列）✅ 最佳—堆 O(log n) vs 数组扫描 O(n)
求 Top-K 大的元素✅也可用快排划分堆 O(n log k)，k 小时极快
找第 k 大⚠️ 可以但慢快排划分 O(n) 平均堆 O(n log k)
查找/删除任意元素❌平衡树 / 哈希表 + 堆堆查找是 O(n)
把整个数组排序❌快排 / 归并堆排 O(n log n) 但常数大、缓存差
  • 信号一：题目说「每次取出最小的/最大的，然后可能再插入」→ 堆。
  • 信号二：n 很大但只求 Top-10 → 维持一个大小为 10 的堆，空间 O(k) 而非 O(n)。
  • 信号三：需要「中途删除某个元素」→ 单纯的堆不行，要配合哈希表做延迟删除。

关键认知：堆只保证「堆顶是最值」，不保证整体有序。它是「部分有序」——每个父节点 ≤ 子节点，兄弟之间无顺序关系。

第二层 · 参数·命令·量化：数组表示与核心操作

堆的数组表示与 Python heapq

# 下标关系（0-based 数组，最关键的四条）
# 父节点:   (i - 1) // 2
# 左孩子:   2 * i + 1
# 右孩子:   2 * i + 2
# 最后一个非叶子: len(heap) // 2 - 1

import heapq   # Python 的 heapq 就是最小堆

h = []
heapq.heappush(h, 5)
heapq.heappush(h, 2)
heapq.heappush(h, 8)
heapq.heappop(h)              # 弹出最小值 -> 2
h[0]                          # 只看堆顶，不弹出：O(1)

# 一次建堆：O(n)，比逐个 push 的 O(n log n) 更快
a = [5, 2, 8, 1, 9]
heapq.heapify(a)

# 最大堆：取负数（Python 常用技巧）
maxh = []
heapq.heappush(maxh, -x)      # 存 -x
-heapq.heappop(maxh)          # 取时再取负

# Top-K 大：维持大小为 k 的最小堆
def top_k(nums, k):
    h = []
    for x in nums:
        if len(h) < k:
            heapq.heappush(h, x)
        elif x > h[0]:                    # 比堆顶大才替换
            heapq.heapreplace(h, x)       # pop + push 一步完成
    return h
操作时间复杂度说明
建堆 heapifyO(n)自底向上向下调整；不是 O(n log n)
插入 pushO(log n)放到末尾，向上调整
弹出堆顶 popO(log n)末尾元素换到顶，向下调整
查看堆顶 peekO(1)直接取 h[0]
查找任意元素O(n)堆不维护全局顺序，只能遍历
删除任意元素O(n) + O(log n)先 O(n) 找到位置，再调整

量化参考：n=1e6、k=10 的 Top-K，用堆只需 O(n log 10) 且内存只占 10 个元素；排序需要 O(n) 内存。这是海量数据下唯一可行的做法。

第三层 · 排障与边界：堆的高频坑

坑后果正确做法
以为堆是有序数组取 h[1] 以为第二小，实际不是只有 h[0] 保证最小；要前 k 个必须 pop k 次
逐个 push 建堆O(n log n) 而非 O(n)用 heapify 一次性建堆
Python 里直接 h.sort()破坏了堆性质堆只能用 heappush/heappop 操作
需要最大堆却用最小堆结果反过来取负数 trick，或自定义比较（C++/Java）
Top-K 时先 push 再 pop堆会超过 k 个，逻辑绕满了就 heapreplace（一步完成）
要删除中间元素做不到 O(log n)用「延迟删除」：哈希表标记删除，弹出时跳过
  • 排查顺序：先确认只依赖堆顶 → 再确认用了 heapify 而非逐个 push → 再看是否需要最大堆 → 最后看是否需要删除中间元素。
  • 边界一：堆不是有序数组。前 k 小的元素只能通过 pop k 次得到，不能直接切片。
  • 边界二：heapq 是最小堆，且只支持「元素可比较」——存元组时按第一个元素比较，相等时比第二个。
  • 边界三：堆不支持 O(log n) 的「删除指定元素」和「修改优先级」。需要这些操作要用带索引的堆或平衡树（如 TreeSet）。

延迟删除实现

# 延迟删除：需要中途删除元素时的标准做法
import heapq
from collections import defaultdict

class LazyHeap:
    def __init__(self):
        self.h = []
        self.removed = defaultdict(int)
    def push(self, x):      heapq.heappush(self.h, x)
    def remove(self, x):    self.removed[x] += 1      # 只打标记
    def pop(self):
        while self.h:
            x = heapq.heappop(self.h)
            if self.removed[x]:
                self.removed[x] -= 1
                continue
            return x

第四层 · 原理与取舍：为什么建堆是 O(n) 而不是 O(n log n)

直觉上 n 个元素各做一次 O(log n) 的向下调整，应该是 O(n log n)。但大部分节点深度很浅：一半节点是叶子（深度 0 层调整），只有 1 个节点在根（深度 log n）。把所有节点的调整代价求和，级数收敛到 O(n)。

建堆方式复杂度做法什么时候用
自底向上（heapify）O(n)从最后一个非叶子往前向下调整已知全部元素时
逐个插入O(n log n)每个元素向上调整元素逐个到达（在线场景）
堆和二叉搜索树有什么区别？

堆只保证「父 ≤ 子」，不保证左右子树的大小关系，所以查找任意元素是 O(n)；BST 保证左 < 根 < 右，查找/插入/删除都是 O(log n)，但需要保持平衡。取舍：堆更省空间（可用数组）、常数小；BST 功能更强。

为什么 Top-K 用小顶堆而不是大顶堆？

因为要维持「当前候选的 k 个最大者」，堆顶是这 k 个里最小的那个——新元素只要比堆顶大，就说明它有资格进入候选集，替换掉堆顶。用小顶堆能让「淘汰」这个动作在 O(1) 判断 + O(log k) 完成。

什么时候不该用堆？

需要排序输出（用快排更快）、需要查找任意元素（用 BST 或哈希表）、需要按优先级动态修改（用带索引堆或平衡树）。堆的适用场景很窄但很专：反复取最值。

维护最大的 k 个值时，最小的候选最该被替换。
