01信号是什么：软件层面的异步中断

第一层

概念与判定

信号是内核发给进程的一个编号事件（1–64）。它不带数据，只表示「发生了某件事」，进程可以选择：忽略、执行默认动作、或安装 handler。

信号编号默认动作常见触发
SIGHUP1终止终端断开（守护进程常重载配置）
SIGINT2终止Ctrl-C
SIGKILL9终止（不可捕获/忽略）kill -9
SIGSEGV11终止 + core非法内存访问
SIGPIPE13终止写已关闭的管道/socket
SIGTERM15终止kill 默认，可捕获做优雅退出
SIGCHLD17忽略子进程状态变化
SIGSTOP19暂停（不可捕获）kill -STOP

02信号的三种状态：产生 → 挂起 → 递送

信号不是「立刻执行」的，它在进程的待处理集合（pending）里等待合适时机：

  1. 产生：kill()、硬件异常、终端、子进程退出。
  2. 挂起：若该信号被阻塞（sigprocmask），就进入 pending 集合等待。
  3. 递送：进程从内核态返回用户态时检查 pending，执行 handler 或默认动作。
标准信号（1–31）不排队：同一个信号连续来 10 次，pending 位只置 1 次，handler 只跑 1 次。要排队用实时信号（SIGRTMIN–SIGRTMAX，带 sigqueue 值）。

03handler 的严格限制：async-signal-safe

第二层

参数·命令·量化

handler 可能在任意时刻打断主流程，因此它只能调用异步信号安全的函数：

可以调用不能调用
write、read、_exit、kill、sigactionprintf、malloc、free、syslog
sem_post、waitpid（谨慎）大多数库函数（内部有锁）
handler 里 printf/malloc 会死锁：主流程可能正持有 stdio 或 malloc 的锁，handler 打断后再拿同一把锁 → 永久死锁。正确做法：handler 只 write 一个字节到 pipe，主循环 poll 到后再处理。
static int sigpipe[2];
void on_term(int sig) {           // 只做最简单的写
    char c = 1;
    write(sigpipe[1], &c, 1);     // write 是 async-signal-safe
}
// 主循环用 poll(sigpipe[0]) 感知，再做实际的清理

04signal() vs sigaction()

对比signal()sigaction()
可移植性各系统语义不一（BSD vs SysV）POSIX 标准，语义明确
信号屏蔽不自动屏蔽当前信号可设 sa_mask 屏蔽其他信号
重启行为不一定 SA_RESTART可显式指定 SA_RESTART
附加信息无SA_SIGINFO 拿 siginfo_t（发送者 pid 等）
struct sigaction sa = {0};
sa.sa_handler = on_term;
sigemptyset(&sa.sa_mask);
sa.sa_flags = SA_RESTART;        // 被信号打断的 syscall 自动重启
sigaction(SIGTERM, &sa, NULL);
生产代码一律用 sigaction，不要用 signal——后者在不同系统上行为不一致，是经典可移植性陷阱。

05排障与边界

第三层

排障与边界

  • SIGKILL / SIGSTOP 不可捕获不可忽略：任何声称「忽略所有信号」的说法都排除这两个。它们是最后的兜底。
  • 僵尸进程：子进程退出发 SIGCHLD，父进程不 waitpid 就留下僵尸。见「僵尸与孤儿」页。
  • errno 被 handler 改动：信号可能在任何 syscall 之间到达，handler 里的系统调用会改 errno。标准做法：进入 handler 先 int saved = errno;，退出前恢复。
  • 信号丢失：标准信号不排队，高频信号（如 SIGCHLD）可能合并。需可靠计数用 signalfd 或实时信号。
  • 多线程递送：信号送到「任意一个未阻塞它的线程」。要定向，用 pthread_sigmask 在除目标线程外全部阻塞。

06原理与取舍

第四层

原理与取舍

信号的设计哲学是极简：只传「事件编号」，不传数据，因此开销极小、实现简单。但代价是表达能力弱——需要传数据时得配共享内存/pipe。

替代方案何时用
signalfd把信号变成 fd，与 epoll 统一事件循环，避免 handler
eventfd轻量通知（计数器），比 pipe 省资源
实时信号 + sigqueue需要排队和携带一个整数/指针

深入 Q&A

Q：为什么 SIGKILL 不能捕获？
A：它是「内核强制终止」的最后手段，若可捕获，恶意/有 bug 的进程就杀不死，系统无法恢复。

Q：handler 执行时会被同一信号再次打断吗？
A：默认不会——进入 handler 时该信号自动加入屏蔽集（除非设 SA_NODEFER）。这避免了无限递归。
