①Schema-first 与六个层次

Weaviate 与 Milvus、Qdrant 最大的理念差异是Schema-first + 内置向量化：它假定「你告诉我要存什么对象、用哪个模型向量化」，剩下的向量生成、存入、检索它全包。

这个理念带来两个直接后果：上手极快（不用自己调 embedding API），以及耦合较深（换模型意味着全量重算，向量化在写入路径上）。

层组成说明
接入层REST / GraphQL / gRPCGraphQL 是主接口，与另两家风格不同
Schema 层Class（≈ 表）+ Property（≈ 字段）+ 交叉引用写入前必须定义 Schema（除非开 auto-schema）
索引层（双轨）HNSW 向量索引 + 倒排索引（BM25、过滤）同一个查询可同时用两条索引
存储层LSM-based 存储（对象 + 倒排）+ HNSW 文件写多读多都走 LSM
模块层text2vec-* / reranker-* / generative-*可插拔，编译进镜像或运行时配置
分布式sharding（默认 1）+ replication factor多租户走 tenant = shard 模型

②两个反直觉默认值

Weaviate 有两个反直觉的默认值，不知道就会误判性能表现：

参数默认值含义为什么重要
flatSearchCutoff40000对象数低于此阈值时不走 HNSW，直接暴力扫描小数据集上「改 ef 没反应」是正常的 —— 它在暴力扫
ef（查询）-1（动态）按结果数自动算 ef，受 dynamicEfMin(100) / dynamicEfMax(500) / dynamicEfFactor(8) 约束不显式设置时 ef 是自动的，手工调参前先关掉动态
{
  "class": "Doc",
  "vectorIndexConfig": {
    "distance": "cosine",
    "maxConnections": 32,          // 即 HNSW 的 M
    "efConstruction": 128,
    "ef": -1,                       // -1 = 动态 ef
    "dynamicEfMin": 100,
    "dynamicEfMax": 500,
    "dynamicEfFactor": 8,
    "flatSearchCutoff": 40000,      // 小于此对象数走暴力扫
    "vectorCacheMaxObjects": 1000000000000,
    "skip": false
  }
}
做性能对比时，把 flatSearchCutoff 设成 0 才能强制走 HNSW，否则在 3 万条数据上你会得出「Weaviate 的 HNSW 参数没用」的错误结论。

③部署形态怎么选

Weaviate 的运维复杂度高于单机版 Qdrant，但低于分布式 Milvus。需要关心的组件就三个：Weaviate 自身、模块依赖的外部服务（如 embedding API）、以及对象存储（备份用）。

部署形态适用说明
单容器 / 二进制开发、中小规模默认配置开箱即用
Docker Compose中小生产官方提供带模块的组合（如 Weaviate + transformers）
Kubernetes（Helm）中大生产官方 Helm chart，支持多副本
Weaviate Cloud不想运维托管，按用量计费

④分片与副本：desiredCount 的语义

Weaviate 的扩展单位是 shard 和 replica，与 Qdrant 类似但接口不同：

{
  "class": "Doc",
  "shardingConfig": {
    "desiredCount": 2
  },
  "replicationConfig": {
    "factor": 2
  },
  "vectorIndexConfig": { "distance": "cosine" }
}
desiredCount 是「期望分片数」，实际分片数会按集群节点数向上取整 —— 所以 3 节点集群里设 2，实际可能得到更多分片。这一点和 Qdrant 的「精确分片数」语义不同。

⑥速记卡

核心理念

Schema-first + 内置向量化：传文本即可搜。

代价

向量化在写入路径上，换模型 = 全量重算。

双轨索引

HNSW + 倒排（BM25/过滤），一次查询可并用。

反直觉默认①

flatSearchCutoff=40000：小数据直接暴力扫。

反直觉默认②

ef=-1：动态 ef，受 min/max/factor 约束。

主接口

GraphQL（不是 REST 优先，这点与另两家不同）。

分片语义

desiredCount 是期望值，实际按节点数取整。

选型一句话

想省 embedding 功夫选它；想极致性能选 Qdrant；想亿级选 Milvus。

Weaviate 的调参前提是先搞清它在走哪条索引：对象数低于 40000 时它根本不走 HNSW，此时调 ef 是白费力气。
