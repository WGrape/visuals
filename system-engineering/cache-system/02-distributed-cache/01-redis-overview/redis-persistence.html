RDB 原理

定时把内存全量快照写入二进制文件。恢复快、体积小，但可能丢失最后一次快照后的数据，且 fork 子进程有瞬时开销。

AOF 原理与重写

记录每条写命令，重启重放恢复。appendfsync 控制刷盘频次（always/everysec/no）。AOF 文件会膨胀，靠重写压缩成最小命令集。

选型对比

维度RDBAOF
数据丢失可能较多可秒级
恢复速度快慢（重放）
文件体积小大

生产常用 RDB+AOF 混合（4.0+）：AOF 头含 RDB 快照，兼顾速度与安全性。

🎯 面试问答

Q：RDB 和 AOF 怎么选？
A：要快恢复用 RDB；要少丢数据用 AOF；生产混合。
Q：AOF 重写做什么？
A：把历史命令压缩成最小命令集，缩小文件。
Q：appendfsync everysec 含义？
A：每秒刷盘一次，最多丢 1 秒。
