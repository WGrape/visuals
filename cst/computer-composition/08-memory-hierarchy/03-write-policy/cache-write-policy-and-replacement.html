写策略与替换算法：dirty 位、写分配与 LRU 的近似实现

读可以随便缓存，写不行——因为内存里还留着一份旧值。写直达还是写回、写未命中要不要先载入、dirty 位怎么维护、LRU 为什么在硬件里只能「近似」，这一篇讲清缓存写路径的全部选择。

一句话定位：写操作要决定「什么时候让内存知道」

写命中时可以选择立刻写穿到内存（write-through），也可以只改缓存、标脏、等被替换时再写回（write-back）。写未命中时还要决定要不要先把这块读进来（write-allocate）。两个维度组合出四种策略。

写直达每次写都同步到下一级，简单但流量大
写回只标 dirty，替换时回写，流量省但要一致性协议
写分配写未命中先载入该行，再改
非写分配直接写到内存，不进缓存
同一行连续写 16 次：写回把 16 次内存写压成 1 次

四种组合，各用在哪

写命中写未命中典型组合适用场景
写回写分配现代 CPU 的 L1/L2/L3 默认通用程序，写局部性好
写直达非写分配早期 CPU、某些嵌入式写少、实现简单
写直达写分配少见于数据缓存需要读回刚写的值
写回非写分配少见流式写（写一次不再读）
写分配为什么要先读？

因为缓存行是 64 字节，而一次写通常只有 4~8 字节。要保证整行数据正确，必须先把其余字节读进来。例外是「整行写」（如 memset 大块内存），硬件可以识别并跳过读——这叫 write-combining。

dirty 位与一致性：为什么写回更复杂

写回意味着「内存里的值可能是旧的」。多核场景下，其他核读这个地址时必须先让持有 dirty 行的核回写或直接转发数据——这正是 MESI 协议要解决的事。单核时 dirty 只影响替换时的回写，多核时它直接决定正确性。

操作写直达的开销写回的开销
单次写命中1 次内存/下级写0 次（只标脏）
同一行写 16 次16 次0 次（直到替换）
该行被替换0 次1 次回写
其他核读该行直接读内存（可能较慢）需要转发或回写（协议开销）

替换算法：LRU 为什么只能近似

真正的 LRU 要给每行维护时间戳并全局比较，硬件代价随路数平方增长。实际做法是「近似 LRU」：

算法实现精度用在哪
真 LRU每行一个年龄计数器，命中时更新全部最高小容量全相联（TLB）
伪 LRU（树形）每组一棵二叉树，用 1 位记录「上次用了哪半」接近 LRUL1/L2 主流
NRU只分「最近用过/没用过」粗简单实现
随机伪随机数选一路意外地不差大容量 LLC（省面积）
RRIP / 自适应按重用距离分级优于 LRU 在某些负载现代 LLC

反直觉的事实：在超大 LLC 上，随机替换常常接近 LRU。因为容量大时「谁被替换」影响变小，而 LRU 的维护成本与最坏情况（扫描型访问把缓存冲干净）反而更糟。

现象根因验证

原理与取舍：写回是「延迟一致性换带宽」

写回把「内存何时更新」推迟到替换时刻，用 dirty 位记录欠账。它把 N 次写合并成 1 次，代价是任何想读这块数据的核都要先跟持有者打交道。换句话说：写回优化了带宽，把复杂度转嫁给了缓存一致性协议。这也是为什么多核时代一致性协议成为芯片里最复杂的部分之一。

写直达一定比写回慢吗？

不一定。写少读多的负载里两者差别很小；写直达实现简单、无需 dirty 位与回写逻辑，某些嵌入式场景更划算。

为什么 L1 也用写回？

L1 写回可以减少对 L2 的写流量（L2 带宽有限）。早期有些设计用写直达 L1 + 写回 L2，现代多为写回。

LRU 的最坏情况是什么？

顺序扫描一个比缓存大的数组。LRU 会把整个缓存冲干净，之后热点数据全部 miss。这也是 RRIP 这类「抗扫描」算法出现的原因。
