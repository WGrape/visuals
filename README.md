**一句话约定：目录即导航，物理目录的层级就是知识的层级。** 知识内容不靠文件名、不靠卡片分组来假装分类，而是直接体现在目录树上——每篇课程都落在「一级知识根 → 二级学科 → 三级章节 → 四级专题（及更深）」这一棵真实的物理目录树上。

## 知识目录结构

目录同时是网站导航与知识分类：**物理目录的层级就是知识结构的层级**。

| 层级 | 含义 | 强制约定 | 例子 |
| --- | --- | --- | --- |
| **一级** | **知识根结构**（知识域） | 固定 5 个 | `artificial-intelligence/`（人工智能） |
| **二级** | 知识域下的**学科分类** | **必须有 `index.html`**；下面只能放三级目录，**不能直接放课程** | `model-llm/`（大模型） |
| **三级** | 分类下的**章节** | **必须以两位序号开头**（`00-`、`01-`…）；下面必须是四级专题目录，**不能直接放课程** | `model-llm/02-principle/` |
| **四级** | 章节下的**专题** | 真正承载课程（`.html`/`.md`）的第一层 | `02-principle/02-decoding/` |
| **五级+** | 专题继续细分 | 需要就继续加，不必强行压平 | `nosql/03-column-family/hbase/01-data-model/` |

**从二级分类目录开始，往下的所有子目录都属于这个分类自己的子结构。** 二级目录有两重身份：既是该分类的导航入口（`index.html`），也是「三级章节 → 四级专题 → 五级细分」这棵知识树的根。要知道某个分类有哪些内容，查这个二级目录的子树即可。

### 为什么至少四级

`一级 → 二级 → 三级 → 四级` 是**下限**而非目标。很多分类三层根本分不开：学科下要先切章节（如 MySQL 的架构/索引/事务/锁），章节下还要再切专题（索引下还有 B+树/覆盖索引/前缀索引）。三层装不下就会退化成"一个目录塞几十篇平铺文章"，既没法导航也看不出脉络。**至少四级；复杂主题继续加第五、第六级**（当前最深已到 6 级）。

### 一级知识根 → 二级分类

一级固定为下面 5 个，顺序与首页知识地图一致；`assets/`、`docs/` 是资源与文档目录，不参与知识层级。二级分类是各根下的学科子目录（每个必须有 `index.html`），完整清单以仓库目录树为准。

| 一级（知识根结构） | 含义 |
| --- | --- |
| `artificial-intelligence/` | 人工智能 |
| `system-engineering/` | 系统工程 |
| `database-system/` | 数据库系统 |
| `cst/` | 计算机科学基础 |
| `programming-and-programs/` | 编程与程序 |

> 站点还有若干**分组容器**（如 `business-design/`、`computer-principles/`）与资源目录（`assets/`、`docs/`），它们用于归并或承载资源，不算在上面的 5 个知识根之内。

## 内容组织规则

**目录**

- **先定位再落地**：先确定 5 个一级知识根之一，再定二级分类，再选三级编号章节，最后落到四级或更深专题目录。**不要新建一级目录**，也不要为放一篇课程而在二级目录新开一个与现有学科平行的目录。
- 每个二级学科必须有 `index.html` 和至少一个三级章节；**每个三级章节都必须带序号并包含至少一个四级专题目录**。课程不直接存放在二级或三级；概览课放 `00-overview/`。三级 `index.html` 仅作导航入口，不代替四级内容。
- 四级目录要表达**真实知识边界**（如基础概念、检索策略、评估优化）；同一主题复杂时继续细分。**不能用与上级同义的目录凑满四层**；章节已有独立主题（如数学的行列式、矩阵）时继续设第五级，不把章节只留在文件名里。单篇课程也可构成真实专题，不强行合并。暂无课程的专题用 `.gitkeep` 保留实体目录，不虚构课程页凑层级。

**课程归属**

- 每篇课程只有一个主要归属：通用原理放概念专题，产品实现放产品专题，跨主题比较归共同上位专题；其他学习路径通过正文或说明性链接关联，不复制课程、不把跨目录卡片塞入错误的 `data-path`。独立的历史与数学知识不放进"其他"兜底学科。
- 空占位保留在文件系统中用于规划，但不添加没有课程卡片的 `topic-group`，不让它在目录树里显示为可学习专题；完全没有课程的学科入口应标注"建设中"。

**索引与链接**

- 学科页 `data-path` 必须与真实目录一致；分组卡片应位于它声明的目录中。含 `assets/card-link-router.js` 的索引应设置与自身目录深度一致的 `<html data-app-root="…">`，并为新课程添加可见卡片。
- 移动文章时同时修正卡片、互链、资源路径、返回链接和跨学科链接。静态站点不自动转发旧 URL；目录迁移后原直达书签可能失效。课程与索引的旧→新路径见 [`docs/knowledge-relocations.json`](docs/knowledge-relocations.json)，**不是**站点重定向规则。

## 本地运行

课程页面自包含（内联样式与 SVG 图解），**直接打开 `index.html` 即可完整浏览**——站内脚本不依赖 `fetch`。如需以服务方式访问（如配合 `container.html` 子路径发布），在根目录运行 `python3 -m http.server 8000`，访问 <http://localhost:8000/>。

## 校验

新增/迁移内容后，在仓库根目录运行：

```bash
python3 -B check_knowledge_hierarchy.py
python3 -B check_topic_tree.py
bash check_html_link.sh
bash check_safe.sh
```

| 脚本 | 检查什么 | 何时失败 |
| --- | --- | --- |
| `check_knowledge_hierarchy.py` | 目录深度、三级编号、二级 `index.html`、课程是否越级存放 | **结构错误**；占位目录只提醒 |
| `check_topic_tree.py` | `data-path` 与真实目录、卡片所属目录、断链、重复入口 | 目录树与内容对不上 |
| `check_html_link.sh` | 每个页面是否被可达索引以卡片引用 | 存在未链接页面 |
| `check_safe.sh` | HTML 内部坏链、混入的非 HTML 文件、疑似密钥 | 坏链或敏感信息 |
