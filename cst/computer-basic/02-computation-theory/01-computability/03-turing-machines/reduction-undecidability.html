归约：把停机问题的不可判定性传递下去

证明一个新问题不可判定，要把已知难题转成它的输入。

核心机制

设 HALT 问题询问程序 M 在输入 w 上是否最终停机。若能把每个 (M,w) 有效地构造为新问题实例 f(M,w)，且答案相同，就得到 HALT ≤m 新问题。

假设新问题有总会停机的判定器，先计算 f，再调用该判定器，就能判定 HALT；这与 HALT 不可判定矛盾。方向必须从已知不可判定问题指向待证问题。

用一个例子看过程

目标问题 PRINT-OK：程序运行时是否最终打印 OK？
构造 P：模拟 M(w)；模拟结束后打印 OK。

构造实例

给定 M,w，生成程序 P；P 先模拟 M(w)，只有模拟结束才打印 OK。

证明等价

M(w) 停机当且仅当 P 最终打印 OK，两个方向都要说明。

推出矛盾

若 PRINT-OK 可判定，就用其判定器解决 HALT，不可能。

观察、原因与处理

观察原因或含义处理与验证
归约方向HALT → PRINT-OK目标问题至少同样难
构造要求f 必须可计算且总能完成不能在构造时偷用 HALT 答案
等价要求是/否实例都要保持答案只证明一边不足够

把归约写成三个必须验证的条件

  1. 构造可计算：给定 M 和 w，必须在有限时间内写出新程序 P。构造过程中不能先求出 M(w) 是否停机，否则已经偷用了待证明不存在的判定器。
  2. 是实例保持“是”：若 M(w) 停机，P 模拟结束并打印 OK，因此 PRINT-OK 的答案为是。
  3. 否实例保持“否”：若 M(w) 永不停止，P 一直停留在模拟阶段，永远不打印 OK，因此新问题的答案为否。

三个条件一起成立，才得到 HALT 到 PRINT-OK 的多对一归约。假设存在能对任意 P 正确回答且总会停机的 PRINT-OK 判定器，先构造 P 再调用它，便能判定 HALT，造成矛盾。

为什么方向不能写反

“A 可归约到 B”表示 B 至少足以解决 A。已知 HALT 不可判定，要推出 PRINT-OK 不可判定，必须让 PRINT-OK 的判定器能解决 HALT，即 HALT → PRINT-OK。若只得到 PRINT-OK → HALT，只说明 HALT 足以解决 PRINT-OK，并不能把 HALT 的不可判定性传给 PRINT-OK。写证明时可以先画箭头，再写一句“若 B 有算法，则 A 也有算法”检查方向。

对象在例子中的含义容易犯的错
已知难题 AHALT(M,w)把它放到归约终点
待证问题 BPRINT-OK(P)只证明一方向蕴含
构造 f(M,w) ↦ P在构造时试图运行到 M 停机

可识别与可判定仍有区别

对 PRINT-OK，可以运行 P 并在看到 OK 时回答“是”；但若 P 永远不打印 OK，观察可能永远持续。这说明“是”实例可被半判定，不等于存在对所有输入都停机的判定器。练习：如果把问题改成“是否最终打印 OK 或程序终止”，怎样改造 P，确保等价关系仍成立？先写清目标问题，再验证两个方向。

边界与误区

不可判定不表示所有具体程序都无法分析；它表示不存在对所有输入都正确且总会停机的通用判定算法。

区分不可判定与不可识别

“是否最终打印 OK”有一个简单的半判定过程：运行程序，看到 OK 就回答是。对会打印的程序，过程最终结束；对永远不打印的程序，过程可能无限等待。因此该问题可识别，却不可判定。这个区别很重要：不可判定不是说不能为任何具体实例给出答案，也不是说现实分析器毫无用处，而是说不存在对所有输入都正确且总会停机的通用判定算法。

实际静态分析通常选择保守近似。例如工具可以在能够证明某程序会触达一条打印语句时给出结论，也可能对复杂循环回答“未知”。允许“未知”使工具可以保持可靠；若要求它对所有程序都精确地回答是或否，便碰到不可判定性边界。教学中的归约给出严格的全称结论，工程工具则在有限场景中取得有用结果，两者并不矛盾。

把证明写成可复用的检查表

选择已知不可判定的问题 A 和目标问题 B；写出从 A 的任意输入 x 生成 B 的输入 f(x) 的有限算法；分别证明 A 的是实例对应 B 的是实例、A 的否实例对应 B 的否实例；最后假设 B 有总停机判定器，组合 f 与它得到 A 的判定器，导出矛盾。若目标问题问的是“不打印 OK”，答案方向会反转，需要重新证明等价，不能把旧箭头照搬。归约的价值在于把未知问题接到已知边界上，形式细节决定结论是否成立。

归约与不可判定：核心结论

问题可判定性说明
停机问题不可判定图灵 1936 证明；对角线法
赖斯定理所有非平凡的程序语义性质都不可判定如「程序是否输出 0」「是否死循环」
程序是否会崩溃不可判定赖斯定理的直接推论
程序是否等价不可判定归约到停机问题
P vs NP未解决≠ 不可判定；是可判定的，只是不知道是否多项式时间
NP 完全问题可判定但难解SAT/3SAT/顶点覆盖/旅行商
一阶逻辑有效性不可判定（一般情形）半可判定

归约的方向是核心：要证明 B 不可判定，需要「若 B 可解，则 A 也可解」，而 A 已知不可解 → 矛盾 → B 不可解。实现方式是构造一个把 A 的实例转换成 B 的实例的函数。方向搞反是最常见的错误。

证明模板与反例

【用停机问题归约证明「程序是否会输出 hello」不可判定】

已知：HALT(P, x) = 「程序 P 在输入 x 上是否停机」不可判定
要证：OUTPUT_HELLO(P, x) = 「P 在 x 上是否会输出 hello」不可判定

构造（归约函数）：
  给定任意 (P, x)，构造新程序 P'：
      P'(y):
          运行 P(x)              // 先跑原程序
          输出 "hello"           // 只有 P(x) 停机才会执行到这
  则：P(x) 停机  ⟺  P' 输出 "hello"

推导：
  若 OUTPUT_HELLO 可判定 -> 用它对 P' 判定 -> 就能判定 P(x) 是否停机
  -> 但 HALT 不可判定 -> 矛盾
  -> OUTPUT_HELLO 不可判定   ∎
【赖斯定理的直观表述】
「关于程序<b>行为</b>（语义）的任何非平凡性质都不可判定」
  - 非平凡 = 有些程序有此性质，有些没有（排除「总是真/总是假」）
  - 语义性质 = 关于「程序做什么」，而不是「程序长什么样」

  可作为赖斯定理的例子（都不可判定）：
    ✗ 程序是否对某些输入返回 0
    ✗ 程序是否死循环
    ✗ 两个程序是否等价
    ✗ 程序计算的函数是否是常数

  不适用赖斯定理的（这些是关于语法，可判定）：
    ✓ 程序是否包含 100 行代码
    ✓ 程序是否用了 while 循环
    ✓ 程序是否在 5 步内停机（有界，可模拟）

【常见错误】
✗ 归约方向写反：应该是「未知问题 -> 已知不可判定问题」的<b>逆向</b>
  正确：假设 B 可解 -> 构造出 A 的解 -> 与 A 不可解矛盾
✗ 把 NP 完全当成不可判定：NP 完全问题<b>可判定</b>，只是不知道是否多项式时间
✗ 认为「难解 = 不可判定」：不可判定是根本无算法；NP 难是有算法但可能指数时间

深入自检

不可判定和 NP 完全有什么区别？

不可判定 = 根本不存在算法（停机问题），任何机器都算不出来；NP 完全 = 有算法（暴力搜索），只是怀疑没有多项式时间的。这是两个完全不同层次的概念，常被混淆。

停机问题的证明用了什么技巧？

对角线法/自指：假设存在 HALT(P,x)，构造程序 D：「D 在自己上调用 HALT，若说停机就死循环，若说不停机就立即停」。于是 D(D) 停机 ⟺ D(D) 不停机，矛盾。

赖斯定理为什么这么强？

它一次性证明了无穷多个问题不可判定。只要你的问题是「程序是否具有某种行为」且这个性质不是恒真/恒假的，就不可判定。这解释了为什么静态分析工具永远不可能完全准确地分析程序行为。

这对工程实践有什么意义？

① 理解静态分析工具（lint、类型检查）必然有漏报或误报，它们只能做近似；② 不要指望「自动证明程序无 bug」；③ 编译器能检查的是语法/类型（可判定），不能检查语义（不可判定）。

P vs NP 为什么重要又难？

它问「验证容易的问题是否也求解容易」。若 P=NP，密码学、优化、调度会全部改观。目前主流猜想是 P≠NP，但 50 多年无人能证明，是 Clay 千禧年大奖难题之一。

自检

若证明 PRINT-OK 可以归约到 HALT，是否足以说明 PRINT-OK 不可判定？

不足以。要从已知不可判定的 HALT 归约到 PRINT-OK，才可把不可判定性传过去。
