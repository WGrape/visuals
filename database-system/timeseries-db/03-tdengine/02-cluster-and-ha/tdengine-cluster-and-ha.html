①TDengine 的集群角色

一个 TDengine 集群由几种进程组成：taosd（数据节点，真正存算）、taosAdapter（REST/WebSocket 接入，兼容 InfluxDB/OpenTSDB 协议）、taosKeeper/arbiter（监控与仲裁）。管理节点（mnode）通常内嵌在部分 taosd 中，负责元数据与调度。

上手最快的路径：单节点先跑通；要上集群时把多个 taosd 用 CREATE DNODE 加进来，数据节点之间自动组成存储层。

②数据分片：vnode 与 vgroup

TDengine 的切分单位是 vnode（虚拟节点）。一张超级表的数据按子表（每个设备一张）分散到不同 vnode，多个 vnode 组成一个 vgroup。vgroup 是副本与一致性的单位：同一个 vgroup 内的多个 vnode 互为副本。

概念含义类比
vnode最小数据分片单位一个分片
vgroup一组互为副本的 vnode副本组
子表每个设备一张，挂在超级表下一个设备的时间序列
mnode元数据/调度节点（多数派）集群大脑

③多副本与一致性

每个 vgroup 可配 1~3（或更多）个副本。写入需要多数派（quorum）确认才算成功：3 副本下允许 1 个节点宕机而不丢数据、不中断写。副本数 < 3 就没有高可用——1 副本挂了就没数据，2 副本挂 1 个就剩单点。

副本数建议：生产至少 3 副本。2 副本看似省资源，但任一节点维护/故障期间就变成单副本，风险极高。

④故障切换与脑裂

当某个数据节点失联，集群会把它名下的 vgroups 主副本切换到存活节点。多个 mnode 之间通过仲裁（arbiter/多数派）避免脑裂——网络分区时，只有拿到多数派的那个分区能继续服务，另一分区主动停止写入。

⑤扩容与负载均衡

新增 dnode 后，可用 BALANCE VGROUP 让集群把 vgroup 重新分布到新节点，实现在线扩容与负载均衡。因为切分单位是 vnode，扩容时只迁移部分数据，不必全量重分片。

-- 加入新数据节点
CREATE DNODE "tdnode-2:6030";
-- 创建 3 副本的 vgroup（通常按资源自动）
CREATE VGROUP 3;
-- 触发再均衡
BALANCE VGROUP;

集群部署与配置命令

# 各节点启动 taosd（配置 firstEp 指向首个节点）
taosd -c /etc/taos/taos.cfg

# 在客户端把节点加入集群
taos> CREATE DNODE "node2:6030";
taos> SHOW DNODES;

# 建库时指定副本与副本分布
CREATE DATABASE iot REPLICA 3 VGROUPS 10;

排障：脑裂、节点离线、单副本

脑裂：mnode 必须是奇数（3/5），靠多数派决策；不要把 mnode 和 data node 全放同一台机器。

节点离线：SHOW DNODES 看状态，离线节点恢复后会自动追增量；长期离线要从集群移除并重建。

副本数 < 3：任一节点维护期即单副本，期间该 vgroup 不可丢数据但也没冗余——扩容/维护前先用 BALANCE 确认分布。

自检 Q&A

TDengine 和 InfluxDB 集群模型最大的区别？

TDengine 用超级表+子表+标签的列式关系模型，按设备（子表）做 vnode 分片；InfluxDB 早期是单一 shard group 按时间分片。前者对“每设备一条线”的 IoT 场景聚合更快。

vgroup 数量怎么定？

通常按数据节点数 × 每节点 vgroup 上限来设，让 vgroup 尽量均匀落在各节点上。太少则并行度不足，太多则元数据开销上升。

3 副本下挂一个节点会怎样？

仍可正常读写（多数派还在）。但此时剩 2 副本，不能再挂第二个，否则脑裂且可能丢数据。应优先恢复故障节点。
