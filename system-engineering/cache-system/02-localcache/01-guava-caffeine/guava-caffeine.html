CacheLoader / get(key, callable) 缺失时自动加载并回填

基于大小/权重回收

maximumSize / maximumWeight 超限退出

🧠

高命中率

Caffeine 用 W-TinyLFU，命中率远高于 LRU

为什么用本地缓存

本地缓存位于应用进程内部，零网络开销、微秒级访问，适合读多写少、能容忍短暂不一致的热点数据。它是离用户最近的一层缓存。

为什么 Caffeine 更快

Guava Cache 用分段缓冲链表 + LRU；Caffeine 用改进的 ConcurrentHashMap，写时执行淘汰，结合 W-TinyLFU 频率筛选，命中率更高且扩缩容无锁争用。

回收策略

类型触发说明
size / weight超过上限按命中率/权重淘汰
expireAfterWrite写入后超时到期直接淘汰
expireAfterAccess最后访问后超时TTI，类似悠闲过期
weak/soft 引用GC依赖 JVM 型回收

🎯 面试问答

Q：新项目怎么选？
A：直接用 Caffeine；Guava Cache 仅在遗留代码兼容时保留。
Q：refreshAfterWrite 和 expireAfterWrite 区别？
A：前者到期后后台异步刷新，读仍返回旧值；后者过期直接淘汰，下次读触发加载。
Q：本地缓存和 Redis 怎么配合？
A：本地做 L1 抗热点，Redis 做 L2 共享，详见多级缓存章节。
Q：缓存击穿时本地缓存有用吗？
A：有用，本地缓存分散了 Redis 压力；但单 JVM 热点仍需处理。
