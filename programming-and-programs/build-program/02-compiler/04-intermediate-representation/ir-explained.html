定位

IR 是什么，为什么必须有它

IR（Intermediate Representation，中间表示）是源代码与目标机器码之间的一种程序表示形式。前端把它生产出来，中端在它上面做优化，后端把它翻译成机器指令。

🌉
解耦
前端不必关心目标机器，后端不必关心源语言
♻️
复用
优化只写一次，所有语言与平台共享
🔬
易分析
结构比源码规整，便于数据流与控制流分析
好的 IR 有三个标准：① 表达力强，能承载各种语言特性；② 结构规整，便于分析变换；③ 与目标机器保持适当距离，不能太贴近某一种架构。

重点

SSA：为什么它这么重要

SSA（Static Single Assignment，静态单赋值）要求：每个变量在程序中只被赋值一次，每次使用都能唯一追溯到它的定义。

// 普通形式：x 被赋值两次，用到 x 时不确定是哪一次
x = 1;
if (cond) { x = 2; }
y = x + 1;      // x 是 1 还是 2？取决于运行时

// SSA 形式：每次赋值生成新版本
x1 = 1;
if (cond) { x2 = 2; }
x3 = φ(x1, x2);   // φ 函数按分支来源选择版本
y1 = x3 + 1;
φ（phi）函数是 SSA 的关键：当控制流合并（如 if 的两个分支汇合）时，用 φ 函数「挑选」来自不同路径的变量版本，从而保持单赋值约束。
🎯

定义唯一，沿 def-use 链直接替换即可
🗑️

🔁

⚡

面试问答

高频问题

Q1：什么是 IR，为什么编译器要用它？
IR 是源码与机器码之间的中间程序表示。用它解耦前端与后端，使「N 语言 × M 机器」变为「N + M」，并让优化只需实现一次即可被所有语言/平台复用。
Q2：AST 和 IR 是一回事吗？
不是。AST 是树形、贴近源语言语法、便于类型检查；IR 通常更线性、更接近机器模型，便于数据流分析与优化。前端先建 AST，再 lowering 成 IR。
Q3：什么是三地址码？
一种线性 IR，每条指令形如 x = y op z，最多包含三个地址（两个源、一个目的）。结构规整、便于分析，是中端优化的经典形式。
Q4：SSA 是什么？带来什么好处？
静态单赋值：每个变量只赋值一次，控制流汇合处用 φ 函数选择版本。好处是定义-使用关系唯一，常量传播、死代码消除、寄存器分配等优化算法大幅简化且更高效。
Q5：φ 函数的作用是什么？
在控制流合并点（如 if 两分支汇合）根据执行路径选择对应的变量版本，保证 SSA 的「单赋值」属性不被破坏。
Q6：Java 字节码是 SSA 吗？
不是。JVM 字节码是栈式指令（操作数栈），不是 SSA。SSA 通常出现在 JIT 编译器（如 HotSpot C2）或 LLVM 这类中端优化 IR 中。

IR 的三种形态与取舍

形态结构优点 / 代表
树形 IR（AST 变体）树接近源码，便于报错；不利于优化
三地址码（TAC）x = y op z简单、易生成；临时变量多
SSA（静态单赋值）每个变量只赋值一次优化最方便；LLVM、Go、V8 都用它
栈式字节码push/pop紧凑；Java/.NET/Python
寄存器字节码指令带操作数比栈式快 20~30%；Lua 5+、Dalvik
SSA 的关键概念说明例子
φ 函数（phi）合并来自不同分支的值x = φ(x1, x2)
支配（dominance）从入口到 B 必经 A，则 A 支配 B支配树用于构造 SSA
支配前沿需要插入 φ 的位置Cytron 算法
变量版本每次赋值产生新版本x1 → x2

SSA 为什么是优化的基础：因为每个变量只有一个定义点，「定义-使用」关系直接就能看出来，不需要做复杂的数据流分析。常量传播、死代码消除、公共子表达式消除都因此变得简单。LLVM IR 强制是 SSA 形式，这是 LLVM 成功的关键设计之一。

IR 示例与构造

; LLVM IR 示例（SSA 形式）
define i32 @add(i32 %a, i32 %b) {
entry:
  %sum = add nsw i32 %a, %b
  ret i32 %sum
}

; 带分支与 phi
define i32 @max(i32 %a, i32 %b) {
entry:
  %cmp = icmp sgt i32 %a, %b
  br i1 %cmp, label %then, label %else
then:
  br label %merge
else:
  br label %merge
merge:
  %result = phi i32 [ %a, %then ], [ %b, %else ]    ; 从不同分支合并
  ret i32 %result
}

; 关键点：
;   1) %a %b 是「值」不是「变量」，只能被赋值一次
;   2) phi 指令必须在基本块的<b>开头</b>
;   3) 每个基本块以终结指令结尾（ret/br/switch...）
# 从非 SSA 到 SSA 的转换示意
# 原代码：
#   x = 1
#   if c: x = 2
#   print(x)

# SSA 形式：
#   x1 = 1
#   if c: x2 = 2
#   x3 = phi(x1, x2)      # 合并点插入 phi
#   print(x3)

# 如何确定 phi 插在哪里？——支配前沿（dominance frontier）
# 简易算法（Cytron 的简化版）：
#   1) 计算每个基本块的支配树
#   2) 对每个变量的所有定义点集合 D
#   3) 迭代：对 D 中每个块 B，在其支配前沿的每个块开头插 phi
#   4) 新插 phi 的块也是定义点，重复直到不动点

# 出 SSA（回到机器码）：
#   把 phi 变成「在各自前驱块里的 mov 指令」或「并行复制」
#   关键：phi 的语义是<b>并行</b>的，不能简单按顺序 mov
#   如果顺序错了（破坏并行语义），需要插入临时变量（这个坑叫 lost copy / swap problem）

排障清单

症状原因处理
phi 语义错了按串行顺序实现而非并行phi 的所有输入是同时取的；必要时插入临时变量
优化结果不对SSA 构造有遗漏（有变量没被重命名）检查支配树计算；用现成算法（Cytron/Braun 的简易版）
IR 太庞大编译慢每次变换都全量重建用原地修改；或用 mem2reg 减少不必要的 load/store
调试信息与 IR 对不上变换时没维护 debug info每条指令带位置；变换时同步更新
不知道该用哪种 IR需求不清要报错友好用树形；要优化用 SSA；要分发用字节码
常量传播没生效没在 SSA 上做SSA 上常量传播是 O(1) 的（查定义点即可），非 SSA 要做数据流分析

为什么编译器要多级 IR：前端用 AST（贴近语言），中端用 SSA（便于优化），后端用机器指令（贴近硬件）。每一级都为特定任务优化。LLVM 的经典设计就是「一种 IR + 多个前端 + 多个后端」，把 M×N 的工作量降到 M+N。
