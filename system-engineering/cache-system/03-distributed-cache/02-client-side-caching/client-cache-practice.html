01Cache-Control 指令详解

响应头 Cache-Control 决定浏览器/代理是否缓存、缓存多久、是否可复用。

指令含义
max-age=3600缓存 3600 秒
no-cache可缓存但每次需校验（协商）
no-store完全不缓存（敏感数据）
private仅客户端缓存，代理不存
public代理也可缓存
must-revalidate过期后必须回源校验
immutable期间绝不回源（哈希文件名资源）
要点：带内容哈希的文件名（app.a1b2c3.js）配 Cache-Control: public, max-age=31536000, immutable 是前端静态资源的最优解：永久缓存且永不失效。

02协商缓存：ETag / Last-Modified

服务端返回校验器，客户端下次带 If-None-Match / If-Modified-Since，未变则返回 304 不传 body。

# 服务端响应（首次）
HTTP/1.1 200 OK
ETag: "v1.2.3"
Last-Modified: Wed, 29 Oct 2026 00:00:00 GMT
Cache-Control: max-age=0, must-revalidate

# 客户端后续请求
GET /api/config HTTP/1.1
If-None-Match: "v1.2.3"
If-Modified-Since: Wed, 29 Oct 2026 00:00:00 GMT

# 未变 => 304 Not Modified，body 为空，省带宽
  • ETag 优先于 Last-Modified：秒级精度不够、内容不变但 mtime 变会误判
  • ETag 用内容哈希或版本号，避免 mtime 变但内容没变误失效
  • 动态接口想走协商缓存，必须自己算 ETag 并返回 304，框架默认不干
要点：no-cache 不是不缓存，而是缓存了但每次问服务端是否新鲜。真要完全不存用 no-store。

03应用侧客户端缓存（本地/Redis）

对于同一个 key 反复查下游的场景，在调用方加一层客户端缓存，直接挡掉重复请求。

# 伪代码：调用方本地缓存 + TTL + 单一飞（singleflight）
val = localCache.get(key)
if val is None:
    with singleflight.lock(key):   # 防止缓存击穿：同一 key 只放一个请求去查
        val = localCache.get(key) or backend.get(key)
        localCache.set(key, val, ttl=30s)
  • 缓存击穿：热点 key 失效瞬间大量请求打到后端 => singleflight 合并
  • 缓存穿透：查不存在的 key 永远 miss => 空值缓存或布隆过滤器
  • 缓存雪崩：大量 key 同时过期 => TTL 加随机抖动

04踩坑清单

  • 改了内容但客户端没更新：检查是否用了 immutable + 长 max-age 而文件名没变
  • 敏感接口返回被代理缓存：确认 private/no-store
  • ETag 用随机数：每次都变，协商缓存失效，等于没缓存
  • 本地缓存没设上限：内存泄漏，用 LRU 上限 + TTL
问：public 和 private 区别？

public 允许 CDN/代理缓存（适合公开静态资源），private 只允许最终用户浏览器缓存（适合带用户态的响应，如我的订单）。
