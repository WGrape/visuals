📐 关键数量级差距

🔢
L1 缓存 vs 内存
100× 差距
L1 命中 ~1 ns，内存访问 ~100 ns，差 100 倍。这就是为何 CPU 缓存如此重要。
🔢
内存 vs SSD
1,000× 差距
内存 ~100 ns，NVMe SSD ~100 µs，差约 1000 倍。数据库缓冲池的价值所在。
🔢
SSD vs HDD
100× 差距
NVMe SSD ~100 µs，HDD 随机寻道 ~10 ms，差约 100 倍。随机 IO 场景 SSD 碾压 HDD。
🔢
内存 vs 跨洋网络
百万× 差距
内存 ~100 ns，跨洋 RTT ~200 ms，差约 200 万倍。这正是缓存设计的根本动力。

记忆锚点：磁盘 IO 比内存慢约 10 万倍（100 ns → 10 ms），网络往返又比磁盘慢一个量级。任何“少一次 IO”的优化都远胜于优化单次 IO 的常数。

队列深度（QD）直接决定能否跑满设备：机械盘 QD=1 时只有约 150 IOPS，提高并发到 32 可显著提升总吞吐（NCQ/TCQ 重排），但单请求延迟会随排队变长。

测量命令与指标解读

fio

# 随机读 IOPS（队列深度 32，直写设备）
fio --name=randread --ioengine=libaio --rw=randread --bs=4k \
    --iodepth=32 --numjobs=1 --size=1G --runtime=60 --time_based \
    --direct=1 --group_reporting

# 顺序带宽
fio --name=seqread --ioengine=libaio --rw=read --bs=1m --iodepth=16 \
    --size=4G --runtime=30 --direct=1 --group_reporting

# 单次 fsync 延迟（同步写路径的真实成本）
fio --name=fs --ioengine=sync --rw=write --bs=4k --fsync=1 --size=256m --group_reporting

iostat

# 实时看设备指标：await 是关键
iostat -x 1
#   r/s w/s   每秒读写次数

# 定位到进程级别

深入自检

为什么顺序 IO 比随机 IO 快那么多？

机械盘上随机 IO 每次都要寻道+旋转延迟（5~10 ms），顺序 IO 摊掉了这部分；SSD 虽无机械延迟，但随机写会引发垃圾回收与写放大，且页/块映射局部性更差。差距常在 10~100 倍。

%util 接近 100% 一定说明设备到瓶颈了吗？

在多队列（blk-mq）设备上不一定：%util 只要有请求在飞就算忙碌，高并发小 IO 可能让它显示 100% 而设备仍有余量。要结合 await、实际吞吐与 fio 基准对比判断。

为什么要用 O_DIRECT 测盘？

页缓存会掩盖真实设备性能：测出来的是内存速度。用 --direct=1 或 O_DIRECT 绕过页缓存才能测到设备本身的延迟与 IOPS。注意 O_DIRECT 有对齐要求（通常 512B 或 4K）。

队列深度怎么选？

看目标：要测单请求延迟用 QD=1；要压满吞吐用 QD=16~32（NVMe 可更高）。机械盘靠 NCQ 重排提高吞吐，QD 提高会让总 IOPS 上升但单请求延迟线性变长。

“减少一次 IO”具体有哪些手段？

四类：加缓存（命中就不落盘）、合并（小写攒成大块）、改数据布局（顺序化、列存、索引覆盖）、预取（顺序读提前加载）。按延迟数量级表，省一次磁盘随机读相当于省下约 10 万次内存访问的等价时间。
