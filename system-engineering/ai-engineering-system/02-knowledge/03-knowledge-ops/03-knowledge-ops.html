1上线才是开始

知识库建设（导入、切分、向量化）只是第一步。真正决定它有没有用，是上线后的运营：回答质量是否达标、内容是否在漂移、用户搜不到时问题出在哪。本文不谈检索/重排序（别处已覆盖），只谈"上线后怎么管"。

运营三件套：效果度量、内容漂移检测、召回诊断。

2运营指标框架

维度指标怎么取
效果答案准确率、相关性人工抽检 + 用户反馈
漂移文档过期率、命中旧版版本时间 vs 召回时间
召回无结果率、首条命中率日志统计

3漂移与召回诊断片段

from collections import Counter

def diagnose(logs):
    no_hit = [q for q in logs if not q["top1"]]
    drift = [q for q in logs if q["doc_age_days"] > 365]   # 命中超一年旧文档
    return {
        "no_result_rate": len(no_hit)/len(logs),
        "stale_hit_rate": len(drift)/len(logs),
        "top_queries_no_hit": Counter(q["query"] for q in no_hit).most_common(10),
    }

# 效果：对抽检样本算"答案是否基于召回内容"
def faithfulness(answer, ctx):
    return all(kw not in answer or kw in ctx for kw in key_facts(answer))

把"无结果的高频查询"和"命中旧文档"两类信号排进运营周报，是知识库持续可用的关键。

4运营闭环

图：度量→诊断→补内容→复测的运营闭环

第一层 · 概念与判定

判定运营是否到位：

  • 是否有可量化的质量基线（而非"感觉还行"）；
  • 是否监控文档年龄与命中版本；
  • 是否对"搜不到"的查询有归因；
  • 是否有定期复盘与内容更新节奏。

第二层 · 参数·命令·量化

量化指标建议：

指标健康线
无结果率< 5%
旧版命中率< 10%（视业务）
答案忠实度> 95%
用户负反馈率环比下降

第三层 · 排障与边界

排障：

  • 内容漂移：源文档更新但知识库没同步，建"源-块"版本映射；
  • 召回失败：查询措辞与文档不一致，补同义词/扩写；
  • 指标虚高：只抽简单问，应覆盖长尾；
  • 反馈无闭环：用户纠错未回流，需建标注通道。

第四层 · 原理与取舍

原理取舍：

  • 知识库质量随源变化衰减，必须持续运营而非一建了之；
  • 度量成本 vs 失控风险：轻量日志指标先行，重人工抽检抽样；
  • 召回诊断与检索优化解耦：先定位"是没召回还是召回了答不好"；
  • 结论：把知识库当"活系统"，用度量与闭环对抗内容漂移。
