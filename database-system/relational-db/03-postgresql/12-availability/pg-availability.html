高可用与连接池

Patroni / repmgr 故障切换，PgBouncer 连接池，读写分离与连接风暴。

高可用组件故障切换连接池读写分离

① 高可用组件

  • Patroni：基于 etcd/Consul/ZooKeeper（或 raft）的模板化 HA，自动选主、故障切换、防脑裂。
  • repmgr：轻量流复制管理 + 自动故障转移。
  • HAProxy / PgPool-II / PgBouncer：流量路由到主/备。

② 故障切换

主库宕机时，HA 组件在 DCS 中抢锁，把某个同步备提升为新主，更新 VIP/路由。关键是 防止脑裂（用分布式锁而非单纯超时）和 fencing。

③ 连接池（必配）

PG 每连接一进程，不用连接池会被高并发打爆。PgBouncer 用 transaction 模式把应用成百上千连接收敛为少量后端连接：

[databases]
app = host=pg-primary dbname=app
[pgbouncer]
pool_mode = transaction
max_client_conn = 5000
default_pool_size = 30
连接风暴：应用重启瞬间大量连接涌来，PgBouncer 的 default_pool_size 与 max_client_conn 是护城河；同时调大 OS max_connections 治标不治本。

④ 读写分离

读流量路由到异步备库做 读写分离；注意备库有复制延迟，强一致读仍走主。可借 PgPool-II 的 延迟感知 路由避免读到太旧的数据。
