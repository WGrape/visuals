跨语言 GC 对比：Go、Java、JS、Python

基础

所有 GC 都要解决的两件事

🔍
找出垃圾
从根集合（栈、全局变量等）出发做可达性分析，不可达的对象即垃圾。三色标记是其通用抽象：白（未访问）、灰（已发现待扫描）、黑（已扫描完）
🧹
回收内存
常见方式：清除（sweep）、复制（copying）、整理（compaction）。复制与整理能解决碎片，但成本更高
引用计数是另一条路：每个对象记录被引用次数，归零即释放。优点是即时回收、无 STW；致命缺点是无法处理循环引用，需要额外机制补救（Python 用专门的循环检测，Swift/Objective-C 靠 weak 打破环）。
对比

横向对比

运行时主策略是否分代停顿特征调优方向
Go并发三色标记 + 混合写屏障 + 非移动否停顿极短（亚毫秒级），追求低延迟减少分配、GOGC
Java（HotSpot）分代 + 多种收集器（G1/ZGC/Shenandoah）是G1 可控停顿；ZGC 极低延迟选收集器、堆大小、停顿目标
JS（V8）分代 + 增量标记 + 并发清扫是（新生代/老生代）增量执行，避免长停顿减少临时对象
Python（CPython）引用计数为主 + 分代循环检测是（仅用于循环检测）无传统 STW，但循环检测会暂停gc 模块、避免引用环
Rust（无 GC）所有权 + 编译期生命周期—无 GC 停顿编译期检查
Go

Go：为低延迟而生

  • 并发标记：标记阶段与用户协程并发执行，只在开始与结束有极短 STW。
  • 混合写屏障：保证并发标记期间对象引用变化不会漏标。
  • 非移动、非分代：不整理内存、不区分新老对象，换来实现简单与极短停顿，代价是内存占用相对高。
  • 触发时机：堆增长到上次存活堆的 GOGC（默认 100%）比例时触发。
调优直觉：Go 的 GC 压力主要来自分配速率。减少堆分配（复用对象、sync.Pool、预分配切片）比调 GOGC 更有效。
Java

Java：选择最多，侧重吞吐与可控停顿

📊
分代假说
绝大多数对象「朝生夕死」，所以把堆分成新生代/老年代，分别用不同策略，Minor GC 频繁但快
🎯
G1
把堆分成许多 Region，优先回收收益高的区域，可设定停顿时间目标
⚡
ZGC / Shenandoah
几乎全并发（染色指针/读屏障），停顿与堆大小基本无关，适合大堆低延迟
🧵
Parallel
吞吐量优先，停顿较长但总吞吐最高，适合离线批处理
选型逻辑：没有「最好」的收集器。批处理看吞吐（Parallel），在线服务看停顿（G1/ZGC），大堆低延迟看 ZGC。先定目标再选收集器，而不是照抄别人的参数。
Python

Python：引用计数 + 循环检测

CPython 以引用计数为主：对象引用数归零立即释放，因此内存释放是确定性、及时的。但循环引用会导致计数永不为零，所以额外用分代循环检测（gc 模块）定期找出环并回收。

  • 优点：对象不用时立刻释放，不存在长时间 STW。
  • 缺点：每个对象都要维护计数，分配与引用操作有额外开销；循环检测扫描也会带来周期性开销。
  • 实践：可用 weakref 打破环；对确定无环的场景可关闭循环检测以减少开销。
面试问答

高频问题

Q1：引用计数和可达性分析各有什么优缺点？
引用计数即时回收、无 STW，但无法处理循环引用且每次引用操作都有开销；可达性分析能处理循环引用、吞吐更好，但通常需要在标记阶段暂停或引入写屏障。
Q2：什么是三色标记？
白（未访问，可能是垃圾）、灰（已发现但字段未扫描完）、黑（已扫描完且确定存活）。标记过程就是把灰色对象的引用推进为灰色、自身变黑，最终白色对象即垃圾。
Q3：Go 的 GC 和 Java 的有什么主要区别？
Go 是非分代、非移动的并发三色标记，追求极短停顿（亚毫秒）；Java 是分代收集并可选择多种收集器，能在吞吐与停顿之间灵活权衡，ZGC 等也可做到极低延迟。
Q4：什么是分代假说？
绝大多数对象存活时间很短。据此把堆分为新生代与老年代：新生代频繁快速回收（Minor GC），长期存活对象晋升到老年代，减少整体回收成本。
Q5：为什么 Go 不做分代？
Go 通过并发标记与混合写屏障已经把停顿压到极低，非移动非分代换来实现简单与可预测性；代价是每次都要扫描全部堆，内存占用相对偏高。这是明确的取舍而非缺陷。
Q6：GC 调优的第一原则是什么？
先减少分配速率与对象生命周期，再谈调参。降低分配量能同时减少 GC 次数与停顿，比调整 GC 参数更有效。
