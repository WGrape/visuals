模运算：把无限整数折进有限环

取模是程序里最常见的数论操作：哈希寻址、环形缓冲、随机发生器、密码学全都建立在它的代数性质上。

核心速览

同余类

a mod m 把整数分成 m 个等价类，运算在类之间进行

封闭性

加减乘可以「先取模再算」，结果不变——防溢出的关键

除法=乘逆元

a / b mod m 要写成 a · b⁻¹，且要求 gcd(b, m) = 1

快速幂

二进制拆分，O(log n) 算出 aⁿ mod m

模运算的直观图像：一个会绕圈的计数器

把整数轴按长度 m 卷成一个环：走到 m 就回到 0。这就是「模 m」的世界，只有 0, 1, …, m−1 这 m 个位置。

两个容易踩坑的点：

  • 负数取模：数学定义下结果恒非负，但 C/Java 的 % 对负数返回负余数（-1 % 12 = -1），Python/Go 的 % 返回非负（Go 也是非负？——实际 Go 与 C 一致返回负）。跨语言移植时务必写 ((x % m) + m) % m。
  • 取模不保序：a < b 不意味着 a mod m < b mod m，所以不能对取模后的值做大小比较或排序。

三条代数性质：为什么可以「边算边取模」

(a + b) mod m = ((a mod m) + (b mod m)) mod m
(a − b) mod m = ((a mod m) − (b mod m) + m) mod m
(a · b) mod m = ((a mod m) · (b mod m)) mod m

这三条保证了中间结果永远不会超过 m²，所以在算 a·b·c mod m 时可以逐步归约，不必先算出可能溢出天文数字的乘积。这就是所有密码学库和「大数取模」实现的基本手法。

# 计算 (a * b * c) % m，全程不溢出
def mul3(a, b, c, m):
    r = a % m
    r = r * (b % m) % m      # 乘完立刻取模
    r = r * (c % m) % m
    return r

# 组合数 C(n,k) mod p（p 为素数，n 较小）——利用逆元把除法变乘法
def comb_mod(n, k, p):
    num = den = 1
    for i in range(1, k + 1):
        num = num * (n - k + i) % p
        den = den * i % p
    return num * pow(den, p - 2, p) % p     # 费马小定理求逆元

print(comb_mod(10, 3, 1000000007))    # 120
注意「除法」那一步：den⁻¹ 用的是 pow(den, p−2, p)，这是费马小定理在素数模下的直接应用。若 p 不是素数，必须改用扩展欧几里得，且分母与 p 必须互素。

快速幂：把 O(n) 压成 O(log n)

朴素做法是连乘 n 次；快速幂把指数拆成二进制，底数不断平方、遇到 1 的位就乘进答案。

def pow_mod(a, n, m):
    """迭代快速幂：O(log n) 次乘法，全程不溢出"""
    r = 1
    a %= m
    while n:
        if n & 1:            # 当前二进制位为 1
            r = r * a % m
        a = a * a % m        # 底数平方，进入下一位
        n >>= 1              # 右移，处理下一位
    return r

print(pow_mod(2, 100, 1000))          # 376
print(pow_mod(3, 1000000000000, 97))  # 十亿亿次乘法？不，只要 ~40 次

复杂度：循环次数 = n 的二进制位数 = ⌊log₂n⌋+1。因此把指数从 10³ 增到 10¹²，代价只从约 10 次乘法增到约 40 次——这是 RSA 能在毫秒级完成 2048 位模幂的根本原因。

模逆元的两种求法

方法条件复杂度代码
扩展欧几里得gcd(a, m) = 1（通用）O(log m)ext_gcd(a, m) 取 x mod m
费马小定理m 为素数 pO(log p)pow(a, p−2, p)
欧拉定理gcd(a, m) = 1O(log m)pow(a, φ(m)−1, m)
def ext_gcd(a, b):
    if b == 0: return a, 1, 0
    g, x1, y1 = ext_gcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

def mod_inv(a, m):
    g, x, _ = ext_gcd(a, m)
    if g != 1: raise ValueError(f"逆元不存在：gcd({a}, {m}) = {g}")
    return x % m

print(mod_inv(3, 7))     # 5   （3×5 = 15 ≡ 1 mod 7）
print(mod_inv(3, 6))     # 抛异常：gcd(3,6) = 3 ≠ 1
几何解释：在模 m 的环上，「乘以 a」相当于一次跳跃式重排。当 gcd(a,m)=1 时这个重排是一个置换（每个位置恰好被跳到一次），因而可逆；否则会多个输入撞到同一位置（如模 6 下乘 2：1→2、4→2），无法撤销。

常见陷阱清单

  • 负数取模：跨语言语义不一致，统一写 ((x % m) + m) % m。
  • 溢出：即使最终结果取模，中间乘法仍可能溢出；用 % 逐步归约或改用 128 位整数（__int128）。
  • 误用除法：模意义下没有除法，必须乘逆元且确认互素。
  • 指数未降幂：aⁿ mod p 中若 gcd(a,p)=1，可先把 n 对 p−1 取模；但这只在底数与模互素时成立，一般情况要用欧拉定理的推广形式。
  • 取模偏差：rand() % m 在 RAND_MAX+1 不是 m 的倍数时分布不均匀（密码学场景必须拒绝采样）。

🎯 常见问法与答题要点

Q：为什么可以「边乘边取模」而不改变结果？

A：因为同余关系与加法、乘法相容：若 a ≡ a′、b ≡ b′ (mod m)，则 ab ≡ a′b′ (mod m)。证明只需把 a = a′ + km、b = b′ + lm 代入相乘，含 m 的项全是 m 的倍数。这一性质让我们能把中间结果始终压在 m 以下，避免溢出，是所有大数模运算实现的基础。

Q：模意义下怎么做除法？

A：没有直接的除法，只能用乘以模逆元代替：a / b mod m = a · b⁻¹ mod m。逆元存在的充要条件是 gcd(b, m) = 1。求法：① 通用——扩展欧几里得解 bx + my = 1；② m 为素数 p——费马小定理 b⁻¹ = b^(p−2) mod p。若 gcd ≠ 1，逆元不存在（例如模 6 下 3 没有逆元，因为 3x mod 6 只能是 0 或 3）。

Q：快速幂的时间复杂度是多少？为什么这么快？

A：O(log n) 次乘法。原理是把指数写成二进制，每轮把底数平方（a → a² → a⁴ → …），并在指数对应位为 1 时把当前底数乘入结果。指数 n 只有 log₂n 个二进制位，因此指数从 10³ 增到 10¹²，乘法次数只从约 10 次增到约 40 次。这是 RSA 2048 位加解密能在毫秒级完成的根本原因。

Q：负数取模在不同语言里为什么不一样？

A：因为「取余」与「取模」的取整方向不同：C/Java/Go 的 % 是截断除法的余数（符号跟被除数，−1 % 12 = −1）；Python 的 % 是向下取整的模（结果恒与除数同号，−1 % 12 = 11）。跨语言移植数组索引、环形缓冲时极易出错，稳妥写法是 ((x % m) + m) % m。

Q：为什么竞赛题常用 1e9+7 作为模数？

A：三个原因：① 它是素数，保证除法可用逆元、满足费马小定理；② 小于 2³¹，两个取模后的数相乘约 10¹⁸，仍在 64 位整数范围内，不会溢出；③ 它的原根性质也不错，方便做卷积类操作。另一个常见选择 998244353 也具有 2²³ 的原根，专门支持 NTT 快速卷积。

Q：什么是模运算下的「循环群」和「原根」？

A：若 gcd(a,m)=1，则 a 的各次幂 a⁰, a¹, a², … 在模 m 下必然循环，构成一个循环子群；循环长度叫 a 的阶，它整除 φ(m)。原根是阶恰好等于 φ(m) 的元素——它的幂可以走遍所有与 m 互素的剩余类。素数模必有原根，这是 NTT（数论变换）取代 FFT 做精确卷积的前提（浮点 FFT 有精度误差，NTT 在模意义下完全精确）。

Q：LCG 随机数发生器是怎么用模运算的？

A：LCG 的递推是 xₙ₊₁ = (a·xₙ + c) mod m：乘、加、取模三步。它的周期长度由 Hull–Dobell 定理给出满周期 m 的条件：① c 与 m 互素；② a−1 可被 m 的所有素因子整除；③ 若 m 是 4 的倍数，则 a−1 也是 4 的倍数。低位比特周期远短于高位是 LCG 的经典缺陷（所以不要用低位取模），密码学场景必须用 CSPRNG。
