Apache Hudi 深度解析

Hudi（Hadoop Upserts Deletes and Incrementals）的看家本领是在数据湖上做高效的行级 upsert / delete 和增量拉取。它把「可变数据」带进湖里，是构建 CDC 入湖、近实时数仓的首选。

1它解决什么问题

传统数据湖是「只能追加、整批覆盖」的，没法按主键更新一行。Hudi 让数据湖具备「数据库般的更新能力」。

🔁 主键 Upsert

按 record key 插入或更新，CDC 数据可近实时同步进湖，不用整表重算。

📈 增量查询

read incremental 只取某时间点之后变更的数据，下游链路免去全量重跑。

🧾 时间旅行

基于 timeline 的提交历史，可读历史版本、做回滚与审计。

与 Iceberg 的差异定位Iceberg 重「开放表格式 + 大规模分析裁剪」；Hudi 重「upsert/增量处理」，对频繁更新的 CDC 场景更顺手。

2Timeline：一切提交的有序日志

Hudi 用一个 timeline 记录所有提交动作（commit / deltacommit / compaction / clean），每条带即时戳与状态（requested / inflight / completed）。查询只认 completed 的 instant，从而做到快照隔离。

Timeline 上的 instant 决定「哪些文件是表在某个时刻的内容」

3COW vs MOR：两种表类型

维度COW（Copy On Write）MOR（Merge On Read）
更新方式重写整个受影响文件写 delta 日志文件，读时合并
写放大高低
读开销低（直接读列存）需合并 base + log（读放大）
适用读多写少 / 批量写频繁 / 近实时 upsert
-- 建 MOR 表：适合 CDC 高频更新
CREATE TABLE trips (
  uuid STRING, ts BIGINT, fare DOUBLE
) USING hudi
TBLPROPERTIES (
  type = 'mor',
  primaryKey = 'uuid',
  preCombineField = 'ts');  -- 同 key 多条按 ts 取最新
MOR 读放大实时查询要合并 base 与若干 log 文件；若 log 堆积过多，需及时 compaction 把 log 合进 base，否则读延迟飙升。

4索引：upsert 怎么找到旧行

upsert 必须快速定位「这条 key 在哪个文件」，否则退化为全表扫描。Hudi 用 索引（Index）维护 record key → file 的映射：

  • Bloom Index / Simple Index：默认，按文件粒度的 Bloom 过滤，适合大批量写入。
  • HBase / RocksDB Index：精确映射，适合小批量高频 upsert（需额外存储）。
  • Bucket Index：用 hash 分桶，免外部存储，写入并行度友好。
全局 vs 非全局全局索引保证全表 key 唯一（跨分区 upsert 安全），但代价更大；非全局索引只在分区内保证，性能更好、需业务保证 key 不跨分区。

5增量处理：下游只吃变更

Hudi 的杀手锏是增量查询——下游链路不用每轮全量重算，只消费「上次到现在」的新增/变更。

-- Spark：只读取 commit C1 之后的变更
SELECT * FROM hudi_table
OPTIONS (hoodie.datasource.query.type = 'incremental',
         'hoodie.datasource.read.begin.instanttime' = 'C1');

这让「CDC → 湖 → 数仓 → 服务」可以做成分钟级端到端链路，而不是 T+1 全量。

6运维要点

⚙️ Compaction

MOR 必须周期跑 compaction，把 log 合进 base；用 inline 或异步调度，避免 log 无限堆积。

🧹 Clean

清理过期文件版本，控制存储与 listing 成本，但保留窗口要够下游增量读取。

📉 小文件

upsert 频繁产生小 base 文件；用 clustering（Z-order / 排序聚类）合并并提升剪枝效率。

Clustering vs CompactionCompaction 解决 MOR 的 log 合并；Clustering 解决小文件与数据布局（排序/聚簇）。两者都要配，否则 MOR 表既慢又贵。

7与 Iceberg / Delta 取舍

详细对比见表格式对比。一句话：要 CDC / 行级 upsert / 增量处理选 Hudi；要跨引擎大规模分析选 Iceberg；已被 Spark/Databricks 绑定选 Delta。

能力HudiIceberg
upsert 成熟度最强有 delete 文件
增量查询原生一流有限（snapshot diff）
非 Spark 引擎支持但偏 Spark最中立
典型入口CDC 入湖、近实时数仓超大规模分析
