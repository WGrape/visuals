后训练 · 方法一

CPT 继续预训练
Continued Pre-training

模型不懂你们行业的那套话？CPT 就是在领域语料上"接着预训练"， 让模型把专业知识、企业内部术语、专有表达吸收进参数里。它和微调最本质的区别是：它不改输出格式，只补知识底子。 下面从适用场景、数据配比、超参设置到防遗忘，把完整训练流程走一遍。

第 1 步 · 定义

CPT 到底在做什么

一句话：拿一个已经预训练好的模型，用领域语料继续跑「预测下一个词」这个任务。 注意——目标函数没变、数据格式没变（还是纯文本，不是问答对），变的只是数据分布。

同一个任务，换了一个语料池

L = − Σ log P( wt | w1 … wt−1 )

无论预训练还是 CPT，优化的都是这个交叉熵。区别只在于 w 来自哪里：

预训练语料
网页、百科、代码、书籍——通用、海量、噪声多
CPT 语料
裁判文书、病历、财报研报、产品手册、内部 wiki——垂直、干净、专业术语密集
图 1：CPT 卡在预训练与 SFT 之间——它还是"预训练式的训练"，只是语料换成了领域数据
第 2 步 · 场景

什么时候该用 CPT（以及什么时候别用）

✅ 适合 CPT
  • 领域有大量稳定语料：法律、医疗、金融研报、工业手册
  • 模型需要学会专业表达与术语的"用法"，而不只是查得到
  • 企业内部文档量很大（几十亿 token 级），且相对稳定
  • 需要适配新语言或强方言（通用模型覆盖很差时）
  • 希望模型"说话像行业里的人"，而不仅是能查到资料
⛔ 别用 CPT
  • 知识经常更新（价格、库存、政策条款）——CPT 训完就固化
  • 只是想让模型换个输出格式（JSON、表格）——该用 SFT
  • 语料只有几 MB——量级不够，只会过拟合
  • 需要可追溯、可引用来源的回答——该用 RAG
  • 算力紧张——CPT 比 SFT 贵一到两个数量级

CPT vs RAG：这是最容易选错的一组

维度CPT（写进参数）RAG（放进上下文）
知识更新要重训，慢改索引即可，秒级
可追溯否，说不清依据是，能给出出处
成本高（要 GPU 集群）低（检索 + 长上下文）
擅长术语用法、行业表达、隐性知识长尾事实、海量文档、频繁变动
典型失败训完记不住细节，还会编检索不到就答不出，上下文易被淹没
实用判据：如果这份知识"需要模型把它变成一种语言习惯"，用 CPT；如果这份知识"需要在回答时被引用"，用 RAG。两者也能叠加：CPT 打底 + RAG 补充，是不少行业模型的做法。
第 3 步 · 辨析

CPT、预训练、SFT 三者到底差在哪

预训练CPTSFT
数据形态纯文本纯文本（领域）指令—回答对
监督信号下一个词下一个词答案 token（带 mask）
改变什么从零获得语言能力知识面与术语分布输出格式与行为
数据量万亿 token十亿 token千~万条
学习率~1e-4 起1e-5 ~ 1e-4（更小）1e-5 ~ 2e-5
是否必做必做可选必做
一个高频误解："CPT 是不是就是喂更多数据继续训？"——不完全是。CPT 的关键不在"更多"，而在数据分布被刻意改成了领域分布。如果只是把通用网页再多喂一遍，那是继续预训练但没有领域化收益；如果把领域语料不加通用数据硬灌，模型会迅速遗忘通用能力（下一节讲）。
第 4 步 · 训练过程

CPT 的完整训练流程

五个环节：语料准备 → 配比混合 → 超参设置 → 训练 → 双轨评测。其中"配比混合"和"双轨评测"是决定成败的两步。

图 2：CPT 五步流程——②配比与⑤评测是最容易被省略、也最容易翻车的两步

为什么必须混入通用数据？

因为神经网络存在 灾难性遗忘（Catastrophic Forgetting）：在新分布上连续训练，参数会朝新任务漂移，旧能力被覆盖。领域语料越窄、训练越久，遗忘越严重。

图 3：混入通用数据的"回放"能显著压平通用能力的下滑曲线，代价是领域能力涨得稍慢
回放 Replay
把通用语料按比例混进训练集，最直接有效，推荐默认开启。
小学习率
LR 越大越容易把原参数"冲垮"，CPT 通常只用预训练的 1/5 ~ 1/10。
只训 LoRA
冻结主干只训练低秩旁路，天然限制遗忘，还能随时切回原模型。
第 5 步 · 实现

最小的可运行实现

CPT 在代码上就是一次标准的因果语言模型训练——把数据集换成领域语料即可。下面用 HuggingFace 生态写一个最小骨架。

from datasets import load_dataset, concatenate_datasets
from transformers import (AutoTokenizer, AutoModelForCausalLM,
                          TrainingArguments, Trainer, DataCollatorForLanguageModeling)

model_id = "Qwen/Qwen2.5-7B"          # 也可以换成 Instruct 版本，但注意先做回归测试
tok = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id, torch_dtype="bfloat16")

# 1) 领域语料 + 通用回放语料，按 8:2 混合
domain  = load_dataset("json", data_files="corpus/domain.jsonl")["train"]
general = load_dataset("json", data_files="corpus/general.jsonl")["train"]
domain  = domain.shuffle(seed=42).select(range(min(len(domain), 800_000)))
general = general.shuffle(seed=42).select(range(int(len(domain) * 0.25)))
train_ds = concatenate_datasets([domain, general]).shuffle(seed=42)

# 2) 拼成定长序列（CPT 不做问答 mask，整段文本都参与 loss）
def encode(ex):
    out = tok(ex["text"], truncation=True, max_length=4096)
    return out

train_ds = train_ds.map(encode, remove_columns=train_ds.column_names, num_proc=8)

# 3) 标准因果 LM 训练：labels 直接等于 input_ids
collator = DataCollatorForLanguageModeling(tok, mlm=False)

args = TrainingArguments(
    output_dir="ckpt/cpt",
    learning_rate=2e-5,              # ⚠ 比预训练小一个量级
    num_train_epochs=2,              # ⚠ 通常 1~3，多了必遗忘
    per_device_train_batch_size=1,
    gradient_accumulation_steps=32,  # 凑出大全局 batch
    warmup_ratio=0.03,
    lr_scheduler_type="cosine",
    bf16=True,
    logging_steps=20,
    save_strategy="steps", save_steps=500,
    save_total_limit=3,
    report_to="none",
)

Trainer(model=model, args=args, train_dataset=train_ds,
        data_collator=collator).train()
如果显存不够：把 AutoModelForCausalLM 换成 PEFT 的 LoRA 包装（只训练 adapter），并把 learning_rate 提到 1e-4 量级——LoRA 因为可训练参数少，通常能吃更大的学习率，同时遗忘风险更低。

评测要跑两轨，缺一不可

# 专业轨：领域任务是否真的变好（自建 200~500 题就够做趋势判断）
python eval_domain.py --ckpt ckpt/cpt/final --task legal_qa,term_extract

# 通用轨：通用能力掉了吗（指令遵循 + 常识 + 安全）
python eval_general.py --ckpt ckpt/cpt/final --bench mmlu,ifeval

# 判据：
#   专业轨 ↑ 且 通用轨 ↓ < 3%   → 通过
#   专业轨 ↑ 但 通用轨 ↓ > 8%   → 加大通用回放比例 / 降 LR 重训
#   专业轨没涨                     → 语料与任务不匹配，或量级太小
第 6 步 · 小结

踩坑清单与一句话总结

常见坑表现怎么解
灾难性遗忘领域问答变好，但通用对话、指令遵循明显退化混 10~30% 通用数据回放；降 LR；改 LoRA
语料量级不足训练 loss 很快降到很低，但效果没提升至少十亿 token 级；不足则改用 RAG 或 SFT
加了 CPT 却不做 SFT模型懂术语但不会对话，回答格式混乱CPT 后必须补 SFT
把易变知识灌进参数价格/政策类问题答错且自信这类知识改用 RAG，不进 CPT
只测领域不测通用上线后用户抱怨"变笨了"双轨评测，通用轨设硬门槛
数据没脱敏模型可能复述内部隐私信息训练前跑 PII 检测与脱敏

一句话：CPT = 在领域语料上继续做下一词预测，把行业知识"腌"进参数里。

它补的是知识底子，不是对话能力。所以：语料要够多够干净、学习率要小、必须混通用数据防遗忘、训完必须再做 SFT。如果知识会变、要可追溯，那这份知识就不该进 CPT，而该进 RAG。

CPT 实操清单：数据配比、学习率与灾难性遗忘

继续预训练（CPT）是把领域知识「灌」进模型的关键一步。核心难题不是怎么训，而是怎么训而不忘——领域语料训练总会让通用能力退化。

决策项推荐做法反例 / 坑
数据配比领域语料 15%~30% + 通用语料 70%~85%100% 领域语料 → 通用能力断崖式下跌
学习率预训练峰值的 10%~20%（如 1e-5 → 1e-6~2e-6）沿用预训练 LR → 直接学崩
训练量通常 1~3 个 epoch，总量几十亿 token 起领域语料少(<1B token)却训很多轮 → 过拟合
调度cosine 衰减 + warmup 2%~5%恒定 LR → 末期不收敛
验证集必须同时看「领域 loss」和「通用 benchmark」两条曲线只看领域 loss → 遗忘看不出来
现象判断依据处理
灾难性遗忘通用 benchmark（MMLU/C-Eval）掉 >3 分提高通用语料占比；降 LR；减少训练量
领域没学会领域验证 loss 不降，或领域问答仍答错检查数据清洗（重复/模板化）；提高领域占比到 40%
过拟合训练 loss 降但验证 loss 反弹减 epoch；加 dropout；扩数据
输出退化开始复读、格式崩坏检查数据里是否有大量重复模板；混入指令数据

超参配置

# 典型 CPT 超参（7B 模型，继续预训练）
learning_rate:    1e-6          # 预训练峰值(1e-4~3e-4)的 ~1%
lr_scheduler:     cosine
warmup_ratio:     0.03
num_train_epochs: 2
per_device_bs:    8
grad_accum:       8             # 有效 batch = 64 条序列
max_seq_len:      4096
bf16:             true
weight_decay:     0.0           # 大模型通常不加 weight decay
grad_clip:        1.0

# 数据混合示例（总量 20B token）
#   通用中文/英文语料  15B  (75%)
#   领域论文/文档       4B  (20%)
#   领域代码/结构化     1B  (5%)

# 监控：每 1000 步在两组验证集上算 loss
#   val_general_loss   <-- 必须基本持平
#   val_domain_loss    <-- 必须稳步下降
  • 数据质量 > 数据量：1B token 的干净领域语料通常好过 10B token 的爬虫垃圾。去重（MinHash/SimHash）、去模板、去低质量页是必须的预处理。
  • 先做小实验：拿 1%~5% 的数据跑一个「冒烟实验」，确认领域 loss 能降、通用 loss 不动，再上全量。能省掉大量算力。
  • 混一点指令数据（5% 左右）：能显著缓解「CPT 之后模型不会说话」的问题，让后续 SFT 更顺利。
  • 记录数据配比：每次实验把配比、LR、token 数记下来，最后效果好才复现得出来。
  • 不要期待 CPT 教会模型「做事」：CPT 只灌知识，「按指令回答」是 SFT 的活。两者目标不同，别混为一谈。
为什么 CPT 的学习率必须远小于预训练？

因为预训练末期模型已经收敛在比较好的位置，LR 也已经衰减到很小。此时突然用大 LR，等于把已经收敛的参数重新打散——表现就是 loss 先飙升、然后重新收敛到一个更差的点。经验值取预训练峰值的十分之一到五分之一（7B 常用 1e-6~2e-6），再配 cosine 衰减和短 warmup。如果你的领域语料非常大（>50B token），可以稍微提高，但一般不超过预训练峰值的 30%。

通用语料到底要混多少？

没有定值，取决于你的目标：① 要纯领域专家（如法律专精、可接受通用能力下降）→ 领域占比可到 40%~50%；② 要通用模型顺带懂领域（最常见）→ 领域 15%~30%；③ 只想让模型熟悉领域术语风格 → 5%~10% 即可。判据不是配比数字，而是两条验证曲线：领域 loss 要降，通用 benchmark 掉分不能超过 2~3 分。超了就往回加通用语料。

CPT 之后直接上线可以吗？

一般不行。CPT 后的模型虽然懂了领域知识，但不会按指令格式回答——它可能把你的问题当成文档续写，一直往下编。所以标准是 CPT → SFT → (可选 DPO/RLHF) 三段式。只有当你只是想增强 embedding/RAG 的检索底座、或者做纯补全类任务时，CPT 完就能直接用。
