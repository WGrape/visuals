深入理解SLB、CDN、源站的流量区别与计费逻辑

🔍 核心概念：三种流量要分清

SLB带宽

SLB 出流量

定义：负载均衡器发送给客户端的流量

✅ 包含：API响应、动态内容

❌ 不包含：CDN已缓存的静态资源

💰 收费方：SLB实例（公网）

CDN流量

CDN 出流量

定义：CDN节点发送给客户端的流量

✅ 包含：静态资源（JS/CSS/图片/视频）

❌ 不包含：未命中CDN的动态请求

💰 收费方：CDN服务（按流量计费）

回源流量

源站 回源流量

定义：CDN从源站拉取资源的流量

✅ 发生：CDN缓存未命中时

📉 越少越好（说明缓存命中率高）

💰 收费方：源站带宽/CDN（视配置）

🌐 流量路径可视化

核心速览

两种计费按流量（GB）vs 按带宽（Mbps）前者看总量，后者看峰值
选哪个流量平稳选流量，波峰尖锐选带宽取决于你的曲线形状
95 峰值去掉最高 5% 采样点后取最大给突发留了容错，常用于大客户
省钱核心提高命中率 + 压缩 + 减少回源这三件事贡献了大部分降本

两种计费方式对比

维度按流量计费按带宽峰值计费
计费单位元 / GB元 / Mbps·月（或日）
看的是什么累计传输总量峰值带宽
适合曲线全天平稳有明显低谷、峰值很高
突发代价突发只是多算流量一次突发决定整月账单
换算直觉1 Mbps 跑满一个月 ≈ 320 GB 左右低于此值按带宽划算，高于则按流量划算

95 峰值是怎么回事

95 峰值：给突发留出容错，比「日峰值」人性化，但仍要防止长时间高位

CDN 成本的四个杠杆

① 缓存命中率最有效。命中率从 90% 提到 98%，回源带宽直接降到五分之一。手段：合理 Cache-Control、忽略无关 query、预热热点。
② 内容压缩开启 Brotli / gzip，文本类资源通常能省 60%~80% 体积。
③ 图片与视频优化转 WebP/AVIF、按屏幕尺寸出图、视频转码降码率，静态大文件往往是带宽大头。
④ 减少回源回源是双向付费（CDN 到源站也走公网/专线）。用长缓存、分层缓存、源站就近部署来压低回源量。

容易被忽略的账单项

项目说明为什么容易被忽略

降本实操清单

# 1) 先看清楚钱花在哪 - 按域名/目录拆账单，找出 Top 消耗来源 - 区分「流量」与「带宽峰值」，判断计费方式是否最优 # 2) 提高命中率（收益最大） Cache-Control: public, max-age=31536000, immutable # 带指纹的静态资源 Cache-Control: public, max-age=300 # 首页等短缓存 - 忽略不影响内容的 query 参数（如 utm_*、随机数） - 热点资源主动预热，避免冷启动全部回源 # 3) 压缩与格式 - Brotli 优先，gzip 兜底 - 图片转 WebP/AVIF，按 DPR 与屏幕出多尺寸 - 视频用 H.265/AV1，并按清晰度分档 # 4) 控制峰值 - 大文件错峰分发，避免集中在晚高峰 - 限速与分时段下发（客户端更新、日志上报）

深入自检

按流量还是按带宽，怎么算更划算？

粗略换算：1 Mbps 持续跑满一个月约 320 GB。如果你的月流量 / 计费带宽 < 约 320，按带宽更划算；反之按流量。但真实曲线不是满跑，所以还要看峰值形状 —— 峰谷差大的更适合按流量。

为什么命中率高了，账单没降多少？

可能因为：① 账单大头是请求数而不是流量；② 命中率统计的是请求数命中率，而大文件（视频）的流量占比更高；③ 回源流量单独计费且没优化。要按「流量命中率」而不是「请求命中率」看。

大文件下载要不要走 CDN？

要谨慎。大文件（安装包、视频）流量巨大，CDN 单价可能高于直接走对象存储的流量费。常见做法是小文件走 CDN，大文件用对象存储直连 + 限速，或对比两者单价后决定。

95 峰值是不是就不用管突发了？

不是。去掉的 5% 大约只有 36 小时，如果长期高位（比如每天晚高峰都很高），这 5% 会被削掉但剩下的峰值仍然很高。真正有用的是削峰（错峰分发、限速）。

HTTPS 请求数费用怎么降？

合并小文件（雪碧图、资源打包）、启用 HTTP/2 多路复用减少连接、合理增大缓存时间减少重复请求、把心跳/埋点类高频小请求合并批量上报。
