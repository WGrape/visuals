1. 完全二叉树（Complete Binary Tree） 结构约束

定义：一棵二叉树，除最后一层外每一层都被完全填满，且最后一层的节点从左到右连续排列。

  • 前 n-1 层是满二叉树（每层 2k-1 个节点）
  • 最后一层节点靠左填充，中间不能有空缺
  • 可以用数组紧凑存储，不需要指针

✅ 完全二叉树

❌ 非完全二叉树（右子树缺左）

2. 二叉堆（Binary Heap） 结构 + 顺序

定义：二叉堆 = 完全二叉树 + 堆序性（Heap Order Property）。

  • 结构：用完全二叉树组织，保证可以用数组存储
  • 堆序性：每个父节点的值 ≥ 所有后代（大顶堆）或 ≤ 所有后代（小顶堆）
  • 注意：堆序性只约束父子关系，不约束兄弟大小
数组存储公式（下标从 0 开始）：
父节点下标：parent(i) = ⌊(i-1)/2⌋
左子节点：left(i) = 2i + 1　　右子节点：right(i) = 2i + 2

🔴 大顶堆（Max Heap）

父节点 ≥ 子节点，根节点是最大值

🟢 小顶堆（Min Heap）

父节点 ≤ 子节点，根节点是最小值

3. 堆（Heap）— 最抽象的概念 抽象数据类型

定义：堆是一个满足堆序性的树形数据结构，不限制分支数量。

  • 堆 是最抽象的概念，只要求"父节点和子节点满足某种大小关系"
  • 可以是二叉堆（每个节点最多 2 个子节点）
  • 也可以是多路堆（如 3-堆、4-堆、d-叉堆）
  • 还可以是斐波那契堆、左偏堆、二项堆等更复杂的结构

💡 一句话总结关系

日常说的「堆」几乎总是指「二叉堆」，而「二叉堆」的底层就是一个「完全二叉树」用数组存的。大顶堆和小顶堆只是二叉堆的两种排序方向，互为「镜像」关系。

📊 五者核心区别对比

概念 性质 结构约束 顺序约束 常见用途
堆 抽象数据类型 无（树形即可） 父与子满足大小关系 优先队列
二叉堆 堆的具体实现 完全二叉树 父 ≥ 子 或 父 ≤ 子 堆排序、优先队列
完全二叉树 树的结构分类 层满 + 从左填充 无 二叉堆的底层结构
大顶堆 二叉堆的一种 完全二叉树 parent ≥ child 找最大值（如调度器）
小顶堆 二叉堆的一种 完全二叉树 parent ≤ child 找最小值（如Dijkstra）

⏱ 二叉堆关键操作复杂度

操作 时间复杂度 说明
取顶（查看根） O(1) 数组第一个元素即为极值
插入 O(log n) 末尾追加 → 上浮（sift up）
删除堆顶 O(log n) 末尾换到根 → 下沉（sift down）
建堆 O(n) 从最后一个非叶节点逐个下沉
堆排序 O(n log n) 原地排序，不稳定

🎯 最后的澄清：常见误区

误区 真相
「堆是一个有序数组」 堆不是有序数组。只保证根是极值，左右子树没有全局有序性
「BST（二叉搜索树）和堆一样」 不同：BST 是中序有序，堆只保证父子大小关系
「堆的左子树一定 ≥ 右子树」 不一定。堆序性只约束父子，不约束兄弟
「完全二叉树就是满二叉树」 不同：满二叉树每层都满；完全二叉树最后一层可以不满但必须从左填充

核心速览

一句话一棵用数组存的完全二叉树，保证父节点一定不大于（或不小于）子节点
能干什么O(1) 看最值，O(log n) 插入删除；不能高效查找任意元素
两个操作上浮 siftUp（插入时）、下沉 siftDown（删除时）
典型用处优先队列、TopK、堆排序、中位数流
堆三要素：完全二叉树 + 数组存储 + 堆序性质

一、数组下标就是树的结构

// 用数组存完全二叉树，不需要指针 // 0 // / \ // 1 2 // / \ / // 3 4 5 parent(i) = (i - 1) / 2 left(i) = 2 * i + 1 right(i) = 2 * i + 2 // 为什么必须「完全」？ // 只有完全二叉树才能被密铺到数组里不留空洞； // 有空洞就意味着数组里有浪费的位置，父子下标公式也会失效。

二、两个核心操作

操作什么时候用做法复杂度
siftUp 上浮插入元素后新元素放末尾，与父比较，更小就交换，直到满足堆序O(log n)
siftDown 下沉删除堆顶后用末尾元素补位，与较小孩子比较，更大就交换，直到满足堆序O(log n)
buildHeap 建堆从无序数组建堆从最后一个非叶子节点往前依次 siftDownO(n) 而非 O(n log n)
peek 查最值看一眼最小值直接返回下标 0O(1)
建堆为什么是 O(n) 而不是 O(n log n)

直觉上 n 次 siftDown 每次 O(log n)，应该是 O(n log n)。但实际上越靠近叶子，子树高度越小：高度为 1 的节点约 n/2 个，高度为 2 的约 n/4 个……总代价是 n·(1/2 + 2/4 + 3/8 + ...) 收敛到 2n，即 O(n)。

三、堆能做什么、不能做什么

能：取最值O(1) 看堆顶，O(log n) 弹出
能：TopK维护 K 个元素的小顶堆，扫一遍即可
能：堆排序原地排序，但缓存不友好，实践中不如快排
不能：查找找某个值要 O(n)，堆不保证兄弟之间有序
不能：合并普通二叉堆合并是 O(n)，需要左偏树/配对堆

四、TopK 的经典写法

// 求最大的 K 个数：维护一个大小为 K 的<b>小顶堆</b> // 堆顶是当前 K 个里最小的，也就是「门槛」 func TopK(nums []int, k int) []int { h := make(MinHeap, 0, k) for _, v := range nums { if len(h) < k { heap.Push(&h, v) } else if v > h[0] { // 比门槛高，替换掉门槛 h[0] = v heap.Fix(&h, 0) } } return h // 时间复杂度 O(n log k)，空间只 O(k) } // 为什么是小顶堆求最大 K 个？ // 因为我们要频繁淘汰「最小的那个」，堆顶操作必须是 O(1)。

五、深入自检

大顶堆和小顶堆怎么选？

只取决于你要频繁淘汰/获取哪一端。求最大的 K 个用小顶堆（淘汰最小的）；求最小的 K 个用大顶堆（淘汰最大的）。

堆是稳定的吗？

不是。堆排序不保证相等元素的相对顺序，所以堆排序不是稳定排序。需要稳定性就得用归并。

为什么实际排序很少用堆排序？

虽然最坏 O(n log n) 且原地，但堆的父子下标跨度大、访问跳跃，缓存局部性差；而且它几乎总是比较「不相邻」的元素，分支预测命中率低。综合常数比快排大。

优先队列一定要用堆吗？

大多数情况是，因为只需要取最值和插入。如果需要合并两个队列或修改任意元素优先级，二叉堆就不够用了，需要配对堆或带索引的堆。

Go 的 container/heap 怎么用？

实现 heap.Interface 五个方法（Len/Less/Swap/Push/Pop），然后调用 heap.Init、heap.Push、heap.Pop。注意 Push/Pop 方法里要用指针接收者，且操作的是底层 slice 的最后一个元素 —— 这是最容易写错的地方。
