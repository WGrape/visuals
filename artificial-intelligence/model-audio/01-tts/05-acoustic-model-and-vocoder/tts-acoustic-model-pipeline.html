一句话总结：现代 TTS 是三段串联：文本前端把文字变成音素和韵律标记，声学模型把音素变成梅尔频谱，声码器把梅尔频谱还原成波形。这三段各自解决不同问题：读得对不对、像不像这个人、音质和速度。出问题时先定位是哪一段，比整体调参有效得多。

01三段流水线与各自职责

TTS 的标准三段：前端 → 声学模型 → 声码器
段输入 → 输出解决什么典型问题
文本前端文字 → 音素序列 + 韵律标记读得对不对：多音字、数字、缩写、断句"2026" 读成「二零二六」还是「两千零二十六」；"3.5" 读错
声学模型音素 + 说话人 → 梅尔频谱音色与自然度：韵律、停顿、情绪机械感、停顿诡异、长句后半段崩
声码器梅尔频谱 → 波形音质与合成速度电音感、金属声、高频毛刺、RTF 太高
要点：排障第一步永远是分段定位：把中间的梅尔谱画出来看。频谱本身有问题 → 声学模型；频谱没问题但声音难听 → 声码器；发音本身错了 → 前端。

02文本前端：最容易低估的一段

工业级 TTS 的质量差距，往往不在模型而在前端。因为用户最先感知到的错误就是「读错了」。

处理项例子规则/做法
数字读法2026 / 3.5 / 199元按上下文判定：年份 vs 数量 vs 价格；中文还要区分「二」和「两」
多音字银行(háng)/行动(xíng)、重(zhòng)要/重(chóng)复词典 + 词性/分词消歧；解决不了的用 SSML 或拼音标注兜底
缩写与英文AI / API / Wi-Fi / 3D字母读 vs 单词读，需要词表；中英混排还要处理语种切换
符号与单位% / ℃ / km/h / 1:3展开成完整读法，单位表要维护
韵律与断句长句的停顿位置按标点与句法树插入韵律层级（#1/#2/#3/#4）
特殊领域医药名、化学符号、地址领域词表优先级最高，通常要单独接入
-- 前端问题的兜底手段：SSML / 拼音标注（具体标签以所用引擎文档为准）

  本次会议于 2026-10-25 召开，
  预算为 199 元。
  银行 门口集合。
  
  请注意，重重要通知。


-- 工程建议：
--   1) 前端规则要能「热更新」，不要改一行规则就重新发版
--   2) 建立「badcase 词表」，线上报错的词优先加进词表
--   3) 对高风险文本（金额、日期、药品名）走人工审核或强制标注
要点：前端是规则密集的部分，模型帮不上太多忙。投入产出比最高的做法是把线上 badcase 沉淀成词表 + 提供 SSML 兜底通道。

03声学模型：自回归 vs 非自回归

类型代表怎么生成优点缺点
自回归Tacotron 2一帧一帧生成，当前帧依赖上一帧韵律自然、对齐靠注意力自己学慢、可能漏字/重复（注意力崩塌）
非自回归FastSpeech / FastSpeech2并行生成所有帧，用「时长预测器」决定每个音素占多少帧快（数十倍加速）、不会漏字重复依赖时长标注或蒸馏；韵律多样性略弱
端到端VITS变分推断 + 归一化流 + 对抗训练，直接从音素到波形音质好、一步到位训练复杂、可控性弱于两段式

为什么非自回归能快这么多：自回归每一帧都要等前一帧，帧数上千时串行步数就是上千；非自回归一次性输出整个矩阵，主要成本是矩阵运算（GPU 擅长）。代价是必须预先知道每个音素要持续多久——这就是时长预测器的作用。

要点：长句是自回归模型的典型失效场景：注意力在几百帧后容易漂移，表现是后半句吞字或重复。非自回归 + 时长预测基本根治了这个问题。

04中间产物：梅尔频谱是什么

声学模型输出的不是波形，而是梅尔频谱——一张「时间 × 频率」的二维图。它保留了人耳能感知的信息，丢掉了大部分相位信息，因此比波形好预测得多，也把「生成音频」这个难题拆成了「预测声学特征」+「还原波形」两步。

参数常见取值含义
采样率16 kHz 或 24 kHz每秒采样点数，决定音频上限频率
帧长 / 帧移1024 / 256 点（16kHz 下约 64ms / 16ms）每帧多长、每隔多久取一帧；帧移决定时间分辨率
梅尔通道数80 通道很常见频率被压缩成多少个「梅尔带」，80 是音质与规模的常用折中
为什么用梅尔刻度低频密、高频疏模拟人耳对频率的非线性感知，让模型把容量花在人耳敏感的地方
import librosa, numpy as np

# 典型的「波形 → 梅尔谱」参数（与多数开源 TTS 配方一致）
y, sr = librosa.load("a.wav", sr=16000)          # 统一采样率 16k
mel = librosa.feature.melspectrogram(
    y=y, sr=sr,
    n_fft=1024,        # 帧长 64ms
    hop_length=256,    # 帧移 16ms  → 每秒约 62.5 帧
    n_mels=80,         # 梅尔通道数
    fmin=0, fmax=8000  # 上限取采样率的一半（奈奎斯特）
)
logmel = librosa.power_to_db(mel, ref=np.max)     # 取对数，压缩动态范围

print(logmel.shape)   # (80, T)  T = 时长(s) × 62.5
# 一段 10 秒的音频 → 80 × 625 的矩阵，这就是声学模型要预测的目标
要点：从波形到梅尔谱是有损的（丢了相位），所以声码器必须「猜」回相位——这正是不同声码器音质差异的来源。

05声码器：从特征回到波形

声码器原理音质速度适用
Griffin-Lim迭代估计相位差（金属感明显）慢只用于快速验证，不用于生产
WaveNet自回归逐点生成波形很好极慢离线高质量，不适合实时
HiFi-GAN非自回归 + 对抗训练好快（可实时）当前主流，实时与离线都合适
神经编解码器离散 token + 解码取决于码率与码本快与大模型语音方案天然衔接
  • 实时场景要看 RTF（real-time factor）：合成耗时 / 音频时长。RTF < 1 才能实时，实际要留余量，通常要求远小于 1。
  • 首包延迟也要单独算：流式 TTS 的首个音频块延迟 = 前端 + 模型首次推理 + 声码器首块，三部分都要优化。
  • 音质与速度常要权衡：小模型/低梅尔通道更快但音质下降，要在目标设备上实测。
  • 采样率要全链路一致：训练数据是 16k 就整条链路用 16k，混用会明显劣化音质。

06常见疑问

问：为什么我换了更大的声学模型，听感还是不自然？

先确认瓶颈在哪一段。如果频谱本身没问题（可视化看频谱结构正常），那音质问题在声码器，换声学模型没用。反之如果频谱的韵律/时长就不对，才是声学模型的事。

问：自回归模型适合做实时吗？

通常不适合。逐帧生成决定了延迟随句长线性增长，且长句还有注意力漂移风险。实时场景一般用非自回归 + 流式声码器，把整句拆成块逐块合成。

问：声音克隆（voice cloning）改的是哪一段？

主要是声学模型的说话人条件（speaker embedding / 参考音频编码）。声码器通常不变——它只负责把频谱变波形，不负责「像谁」。

问：为什么必须有中间频谱，不能直接生成波形？

波形是每秒上万个采样点，直接建模极难、极慢。梅尔谱把数据压了几十倍（每秒约 60 帧 × 80 通道），而且去掉了相位这个难以预测的量，让「预测」变得可行。代价就是要额外一个声码器还原。
