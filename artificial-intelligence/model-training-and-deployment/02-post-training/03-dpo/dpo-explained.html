后训练 · 方法三

DPO 直接偏好优化
Direct Preference Optimization

想让模型"更讨喜"，又怕 RLHF 那套奖励模型 + PPO 太重？DPO 用一个巧妙的公式，直接拿"好回答 vs 差回答"这种偏好对来训，不用奖励模型、也不用 PPO。 它是目前最主流的人工偏好对齐手段。下面把 Bradley-Terry、参考模型、β 和完整训练过程讲清楚。

第 1 步 · 定义

DPO 到底在做什么

一句话：给模型看成对的"同一问题下的好回答 / 差回答"，让它拉大两者概率的差距——好回答更可能被生成，差回答更难被生成。它把"偏好对齐"化简成了一个普通的监督式分类损失，不再需要单独训练奖励模型，也不再需要强化学习的采样—打分—更新循环。

和 SFT / RLHF 的根本区别

SFT
给"标准答案"学模仿。模型不知道"还有没有更好的答法"。
DPO
给"好 vs 差"学比较。模型直接学到"在差答案之上，好答案更可取"。

RLHF 是"先训奖励模型 → 用 PPO 让模型去讨好奖励模型"；DPO 把这两步塌缩成一步：偏好数据本身就是监督信号。

第 2 步 · 动机

为什么 DPO 能取代 RLHF

RLHF 很强，但工程上很贵：要训一个奖励模型（RM），再用 PPO 在"奖励"上做强化学习，期间同时跑 actor / critic / reference / RM 四个模型，训练还容易不稳定。DPO 的核心洞察是：当用 Bradley-Terry 偏好模型时，最优策略有闭式解——于是"先 RM 再 PPO"的复杂流程，可以直接变成一个带参考模型约束的交叉熵损失。

RLHF（三步）
  • ① 用偏好数据训奖励模型 RM
  • ② 用 PPO 让策略去最大化 RM 分数
  • ③ KL 约束防止偏离 SFT 太远
  • 要同时加载 4 个模型，调参复杂
DPO（一步）
  • ① 直接用偏好对训策略
  • ② 隐含的"奖励"由策略与参考模型之差给出
  • ③ KL 约束直接写进损失里
  • 只需 2 个模型（策略 + 冻结参考）
前提：DPO 不是从基座直接来，而是站在一个已经 SFT 好的模型之上。参考模型通常就取这个 SFT 模型并冻结。"先 SFT 再 DPO"是事实标准顺序。
第 3 步 · 原理

DPO 损失在算什么

DPO 的"奖励"被定义成策略模型与参考模型的对数概率之差。损失鼓励"好回答"的差更大、"差回答"的差更小。关键的三个角色：

偏好对 (x, yw, yl)
x=问题，yw=被偏好的好回答，yl=被拒绝的差回答。
策略模型 πθ
正在训练的模型，目标是让 yw 比 yl 更可能。
参考模型 πref
冻结的 SFT 模型，用来锚定"别跑太偏"。
LDPO = − E [ log σ ( β · ( log πθ(yw|x) − log πref(yw|x) )
            − β · ( log πθ(yl|x) − log πref(yl|x) ) ) ]

两个量在控制什么

β（beta）· 偏好强度
β 越大 → 越贴近参考模型（保守、稳，但不敢学新偏好）；β 越小 → 越敢拉开好坏差距（学得猛，但容易偏离、甚至遗忘能力）。常用 0.05~0.2。
σ(·) · 概率化
把"好-差"的差距压成 0~1 的 sigmoid。差距越大，损失越小；当模型已经明显偏好 yw，该项趋近 0，训练自然收敛。
参考模型为什么不能省：如果没有 πref 做 KL 锚，模型为了"拉大好坏差距"会走捷径——把答案改得面目全非、或专挑短答案（因为短答案更好压低 yl 概率）。参考模型强制"在对齐的同时，别丢失 SFT 教出的基本能力"，这正是 RLHF 里 KL 惩罚的等价物。
第 4 步 · 训练过程

DPO 的完整训练流程

四个环节：构建偏好对 → 加载 SFT 模型作参考 → 训练（DPO loss）→ 评测（胜率 + 长度控制）。其中"偏好对质量"和"评测时盯住长度偏差"是最容易翻车的两步。

图 2：DPO 四步——偏好对是燃料，参考模型是刹车，β 是方向盘

偏好对怎么来

来源做法注意
人工标注标注员对同一问题排两个回答的优劣质量最高但贵，易有标注者偏差
强模型 vs 弱回答用强模型生成 yw，弱/旧模型给 yl便宜，但要确认"强"确实更优
AI 裁判用更强的裁判模型（如 GPT-4 级）打分选优可能继承裁判的偏见，需抽检校准
数据量：DPO 通常几千到几万对就够见到明显收益；但偏好对噪声大会直接把模型带偏——一对标错的 (yw, yl) 比少一万对更伤。先做一致性过滤比堆量重要。
第 5 步 · 实现

最小可运行实现

用 TRL 的 DPOTrainer，你只需准备偏好数据（含 prompt / chosen / rejected）和一个 SFT 起点模型，比手写 PPO 简单得多。

from datasets import load_dataset
from transformers import AutoTokenizer, AutoModelForCausalLM
from trl import DPOTrainer, DPOConfig

model_id = "Qwen/Qwen2.5-7B-Instruct"   # 必须是已 SFT 的模型
tok = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id, torch_dtype="bfloat16")

# 偏好数据：每条含 prompt / chosen(好) / rejected(差)
ds = load_dataset("json", data_files="data/prefs.jsonl")["train"]

cfg = DPOConfig(
    output_dir="ckpt/dpo",
    beta=0.1,                  # ⚠ 偏好强度：越大越保守
    learning_rate=5e-6,        # DPO 通常比 SFT 更小的 LR
    num_train_epochs=1,
    per_device_train_batch_size=2,
    gradient_accumulation_steps=16,
    bf16=True,
    report_to="none",
)

# DPOTrainer 内部自动把"当前模型"作策略、"初始模型"作冻结参考
DPOTrainer(
    model=model,
    ref_model=None,            # None 时自动用训练前的副本作参考
    args=cfg,
    tokenizer=tok,
    train_dataset=ds,
).train()
用 LoRA 更稳：DPO 也容易"学过头"——把回答改得越来越长、越来越套路。用 LoRA 只训低秩旁路，等价于给策略加了容量约束，天然缓解过拟合；配合较小的 β 与 LR 一起用。

评测必须盯住"长度偏差"

# DPO 最经典的作弊方式：把回答写长 → 更容易压低 rejected 概率
# 所以评测时除了"胜率",还要看:
#   1) 平均输出长度 vs SFT 基线（涨太多 = 预警）
#   2) 用长度无关的指标（如 AlpacaEval 的 length-controlled win rate）
#   3) 人工抽检:回答真的变好,还是只是变长/变套话
第 6 步 · 小结

踩坑清单与一句话总结

常见坑表现怎么解
没先 SFTDPO 直接站在 Base 上，学不会对话范式先有合格的 SFT 模型再 DPO
偏好对标反/噪声大模型越训越"诡异"、答非所问做标注一致性过滤，抽检 yw/yl 对错
长度作弊胜率涨了，但只是因为回答变长盯长度控制胜率，调大 β，加 LoRA
β 太小对齐猛但通用/能力明显退化调大 β（如 0.2），缩短训练

分布偏移偏好来源单一，模型只在该风格变好偏好数据覆盖多维度（帮助/诚实/无害）

一句话：DPO = 用"好/差回答"这种偏好对，靠一个带参考模型约束的 sigmoid 损失，把模型的输出分布直接掰向人类偏好。

它把 RLHF 的"奖励模型 + PPO"塌缩成一步监督训练，工程复杂度骤降，是当下最主流的偏好对齐手段。但它只调"偏好"，不擅长"练推理深度"——那件事要交给 RL（尤其是 RLVR / GRPO）。

DPO 调参清单与失败诊断

DPO 用一条公式绕过了奖励模型，但对超参比 SFT 敏感得多。beta 和 学习率 是最关键的两个。

参数推荐范围太大 / 太小的后果
beta (β)0.1 ~ 0.5（默认 0.1）太大 → 几乎不更新（贴死参考模型）；太小(0.01) → 过度偏离，输出崩坏
learning_rate5e-7 ~ 5e-6（比 SFT 小 5~20 倍）太大 → 一步就把模型推离参考模型，reward hacking
epochs1 ~ 2>3 轮几乎必然过拟合偏好数据
偏好对数量1 万 ~ 10 万对几千对也能work，但容易过拟合
sft_loss 权重0.01 ~ 0.1（可选辅助项）加一点能防止 chosen 的 logprob 一起掉
症状诊断信号解法
reward hackingreward 准确率飙升，但输出变短、变空话提高 beta；降 LR；加长度惩罚
chosen 和 rejected 的 logprob 一起掉implicit reward 上升但 language modeling 退化加 sft_loss 辅助项（RPO/DPO+NLL）
几乎没变化chosen-rejected 差距 <0.1beta 太大或 LR 太小；检查偏好标注质量
输出崩坏/复读生成长度异常、重复降 LR 到 5e-7；减 epoch；检查数据里有毒样本
过拟合训练 accuracy >0.9 但验证不涨减 epoch；加更多偏好对；降 rank(LoRA)

公式与配置

# DPO 核心公式（一行看懂）
# loss = -logsigmoid( beta * [ (logp_chosen - logp_ref_chosen)
#                             - (logp_rejected - logp_ref_rejected) ] )
#
# 直觉：让 chosen 相对参考模型的提升，大于 rejected 的提升。
# beta 控制「离参考模型多远就算过分」。

# 典型配置（LLaMA-Factory / TRL）
learning_rate: 5e-7          # 关键！比 SFT(1e-5) 小 20 倍
beta: 0.1                    # 常用 0.1；保守用 0.3~0.5
num_train_epochs: 1          # 通常 1 轮
per_device_batch_size: 2
gradient_accumulation_steps: 16
max_length: 1024
max_prompt_length: 512
bf16: true

# 可选的稳定化：加 NLL 辅助损失（RPO / DPO+SFT）
rpo_alpha: 1.0               # 在 DPO loss 上加 rpo_alpha * NLL(chosen)
  • 必须保留参考模型：DPO 需要同时跑两个模型（policy + reference），显存约 2 倍。LoRA 场景可以用 base adapter 当参考，省一份。
  • 偏好数据里 chosen 不能总是更长：如果标注有「长的就是好的」的系统性偏差，DPO 会直接学会「说更长」而不是「说得更好」。这是最常见的 reward hacking。可以做长度归一化或在数据构造时控制长度分布。
  • 先做好 SFT 再做 DPO：DPO 是在 SFT 模型上微调偏好，基座没训好，DPO 救不了。
  • 评估不能只看 reward accuracy：一定要人工或用强模型做 side-by-side 对比（A/B 盲评），胜率才是真实指标。
  • 迭代式 DPO：用当前最好的模型生成回复、标注偏好、再训一轮，通常比一次性训更好（类似 RLHF 的迭代版）。
beta 到底怎么调？

把它理解成「允许模型离参考模型多远」的惩罚系数。beta 大 → 惩罚重 → 模型不敢动 → 训练信号弱、效果不明显；beta 小 → 惩罚轻 → 模型放飞 → 容易 reward hacking（输出变短变空、或者开始说一堆套话骗分）。实践建议：从 0.1 起跑，看两个指标——① chosen 和 rejected 的 reward margin 是否稳步拉开；② 生成长度是否合理。如果输出明显变短/变水，把 beta 提到 0.3~0.5。

DPO 相比 PPO/RLHF 的取舍是什么？

DPO 的优势：简单、稳定、便宜——不需要单独的奖励模型、不需要在线采样、不需要复杂的 RL 训练循环，单卡就能跑。劣势：离线、上限较低——它只用固定的偏好对，无法像 PPO 那样探索新回复；对分布外的输入泛化较差；且对超参和数据质量更敏感，容易出现 reward hacking。所以业界常见路线是：SFT → DPO（快速拿到大部分收益）→ 需要冲顶时再做 PPO/GRPO。DeepSeek 的 GRPO 就是去掉了 critic 网络、用组内相对打分替代，把 RLHF 的成本降到了接近 DPO 的水平。

偏好数据怎么构造最划算？

三种方式按性价比排序：① 用强模型（GPT-4 级）对同一 prompt 生成多个回复，让标注者/强模型打分选优劣——最常用，成本可控；② 人工改写——把模型答得不好的地方改对，作为 chosen，原答作为 rejected，质量最高但贵；③ 用现成开源偏好数据集（如 UltraFeedback、HH-RLHF）——零成本，但域可能不匹配。建议：通用能力用开源数据，业务垂直能力自己造 3000~10000 对，后者对最终效果的边际贡献最大。
