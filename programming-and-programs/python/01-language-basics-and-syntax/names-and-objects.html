名称绑定与对象语义：一切皆对象

Python 没有指针，但有一套等价且更统一的「名字 → 对象」模型。搞懂 is 与 ==、可变与不可变、以及「传对象引用」，就能避开绝大多数诡异 bug。

概述

名字是「贴」在对象上的标签

Go 里变量是「一块有类型的内存」；Python 里变量只是名字，真正的对象在堆上，名字通过引用指向它。赋值 = 把名字贴到已有对象上，不是拷贝。

这套模型对应 Go 的「指针与值语义」那一篇（指针与值语义 · Go）。但 Python 不需要你写 * 和 &——引用是隐式的，代价是「可变性」变得格外重要（见下）。

名称绑定与重绑

赋值不拷贝，重绑不改动原对象

理解「名字指向对象」是第一步。a = b 让 a、b 指向同一个对象；之后给 a 重新赋值只是把 a 贴到别处，不影响 b。

a = [1, 2, 3]
b = a                  # b 和 a 指向同一个列表对象
print(a is b)        # True（同一对象）

a = [9]              # 把 a 重绑到新列表
print(b)              # 还是 [1,2,3]，b 没变

# 真正"改对象"要调用 mutating 方法
a = b                  # 重新指向同一对象
a.append(4)            # 原地修改
print(b)              # [1,2,3,4] —— b 也变了!
区分两种动作：重绑（a = ...，只动名字）和原地修改（a.append / a[0]=...，动对象本身）。重绑不影响别人；原地修改对所有指向该对象的名字都可见。
身份与相等：is vs ==

is 比身份，== 比值

is 比较两个对象是不是同一个（id 相同）；== 比较值是否相等（可重载 __eq__）。多数情况用 ==，只有判 None/单例才用 is。

a = [1, 2]; b = [1, 2]
print(a == b)         # True（值相等）
print(a is b)         # False（两个不同对象）

x = None
if x is None: ...     # 正确：判单例用 is
if x == None: ...       # 能跑，但规范上用 is
⚠️ 小整数（[-5,256]）和短字符串有缓存，可能让 is 意外返回 True（a=256;b=256;a is b → True）。绝不要依赖这点——判值永远用 ==，is 只用于 None、True/False 等真正单例。
可变与不可变

决定对象能不能"原地改"

不可变对象（int/str/tuple/frozenset/bytes）创建后不能改，任何"修改"都返回新对象；可变对象（list/dict/set/bytearray）可以原地改。这直接决定了能否当字典键、以及别名会不会互相影响。

s = "abc"
t = s.replace("a", "A")   # 返回新串，s 不变
print(s)              # 还是 "abc"

d = {"a": 1}
keys = (d,)            # 元组可作 dict 键（因不可变）
# m = {[1,2]: 3}      # TypeError：list 可变，不能作键
元组「不可变」但浅：元组里的元素若是可变对象（如 (1, [2,3])），那个列表仍可被原地改。需要深度不可变要用 frozenset 或拷贝。
传参：传对象引用

不是值拷贝，也不是指针，是「引用」

Python 传参是「传对象引用」（call by object reference / call by sharing）。函数收到的是原对象的引用，所以：改可变对象会反映到外面；重绑参数名不会影响外面。

def mutate(lst):
    lst.append(99)        # 改的是同一个对象

def rebind(lst):
    lst = [0]            # 只是把局部名字贴到新对象

xs = [1, 2]
mutate(xs); print(xs)   # [1,2,99] 外面被改
rebind(xs); print(xs)   # 还是 [1,2,99] 外面没变
动作对调用方可见吗
原地改可变对象（append/[]=）✅ 可见
不可变对象"修改"（返回新对象）❌ 需 return 拿回
参数名重绑 x = ...❌ 只动局部名
这和 Go 的「值类型整份拷贝、指针才改原值」视角不同：Python 里所有对象都通过引用传递，区别只在对象本身可变不可变。想把改动带回调用方，要么改可变对象、要么 return 新值。
常见坑

别名共享 + 可变默认参数

两个名字指向同一可变对象时，一处改处处改；再加上默认参数复用，是 Python 最易踩的两坑。

别名意外共享

b = a 后改 b 会影响 a。需要独立副本时用 b = a.copy()（浅）或 copy.deepcopy(a)（深），尤其嵌套结构。

⚠️ 默认参数用可变对象会在多次调用间共享状态（见语言特性·可变默认参数）——铁律：默认参数只用不可变对象。这两坑本质都来自「引用共享 + 可变性」。
