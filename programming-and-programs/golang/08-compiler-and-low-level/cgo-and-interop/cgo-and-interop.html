让 Go 复用 C 生态

cgo 在 Go 与 C 间架桥：你写 import "C"，就能声明并调用 C 函数、用 C 的类型。常用于调用系统库、已有 C SDK。

基本用法

注释里写 C，紧接 import C

紧贴在 import "C" 前的注释里写 C 代码/头文件包含；之后用 C.function 调用，C.type 引用类型。

/*
#include <stdio.h>
void hello() { printf("hi\n"); }
*/
import "C"

func main() { C.hello() }
跨语言开销

不是免费的

每次 Go 调 C 都要做一次栈切换与参数转换（runtime 进入 C 线程上下文），开销远高于普通 Go 调用；高频调用会成瓶颈。

cgo 调用无法被 Go 调度器管理，调用期间占用一个 OS 线程（g0/m 的 C 栈），大量并发 C 调用会吃光线程。
何时该用

有明确收益才上

成熟 C 库（图像处理、加密、硬件 SDK）、操作系统特有 API、性能关键且 C 实现远优于纯 Go 时，才值得引入 cgo。

用 cgo避免 cgo
必须用现有 C 库纯算法可用 Go 重写
系统级 API 无 Go 绑定仅图省事
一次性胶水代码整条热路径
限制与代价

影响构建与部署

启用 cgo 后交叉编译变复杂（需要目标平台 C 工具链）、二进制体积增大、构建变慢；CGO_ENABLED=0 可禁用（纯 Go）。

⚠️ 容器/交叉编译场景常设 CGO_ENABLED=0 以纯 Go 构建；这会丢失 cgo 依赖，需提前确认功能不受影响。
