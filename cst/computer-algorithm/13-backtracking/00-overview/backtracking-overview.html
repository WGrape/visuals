第 13 章 · 回溯

选择、探索、撤销

回溯在决策树上枚举候选解；剪枝让“不可能成功”的分支尽早停止。

核心速览

路径 path已经做出的选择序列
选择列表 choices当前这一步还能选什么
结束条件到达决策树叶子，path 即一个解
剪枝 pruning提前判断某分支必然无解，直接返回

回溯 = 决策树上的 DFS

回溯本质就是在一棵「决策树」上做深度优先遍历。每一层是一次选择，从根走到叶子就得到一个完整解。

「回溯」这个名字的由来：做完一层的选择、递归返回后，要把刚才的选择撤销（回退），让状态恢复到进入这一层之前的样子，才能正确地尝试下一个候选。「做选择 → 递归 → 撤销选择」这三步是所有回溯代码的骨架。

通用模板

def backtrack(path, choices):
    if 满足结束条件:            # 到达叶子
        result.append(path[:])  # 注意要拷贝！
        return
    for choice in choices:      # 枚举这一层的所有候选
        if 不合法(choice):       # ① 约束剪枝
            continue
        if 必然无解(choice):     # ② 可行性剪枝
            continue
        path.append(choice)                 # 做选择
        backtrack(path, 更新后的 choices)    # 递归进入下一层
        path.pop()                          # ← 撤销选择（回溯的精髓）
最容易忘的两点：① 递归后必须撤销（path.pop()），否则后续分支会带着前面的选择，结果全错；② 收集答案时要拷贝（path[:]），直接 append 的是同一个列表对象的引用，最后会被 pop 成空。

剪枝：回溯的生命线

回溯的复杂度通常是指数级（全排列是 n!），不剪枝基本不可用。剪枝分两类：

类型判断什么例子
约束剪枝（可行性）这一步的选择本身已经违反约束N 皇后：当前位置会被已有皇后攻击
限界剪枝（最优性）继续下去也不可能优于已有最优解回溯求最短路：当前长度已 ≥ 已知最短
组合总和的排序剪枝：先把候选排序，递归时只从「当前下标及之后」选（避免重复组合），并且在 剩余目标 < 当前候选值 时直接 break——因为后面的候选更大，必然也超，整层都不用试了。这就是典型的「利用单调性剪掉一整片分支」。
去重的两条常用手段：① 排序 + 跳过相同元素（if i > start and a[i] == a[i−1]: continue）；② 每层用一个 used 集合记录本层已试过的值。前者更省空间，后者不要求排序。

四类经典问题

问题决策树含义关键细节
子集每个元素「选 / 不选」每个节点都是解，不只叶子
组合（C(n,k)）选 k 个，不考虑顺序用 start 下标避免重复
全排列每一步选一个未用过的用 used 数组；有重复元素时要去重
N 皇后 / 数独逐行（逐格）放棋子约束剪枝是核心
# 子集：每个元素选或不选 → 2^n 个解
def subsets(nums):
    res, path = [], []
    def dfs(i):
        if i == len(nums):
            res.append(path[:]); return
        path.append(nums[i]); dfs(i + 1); path.pop()   # 选
        dfs(i + 1)                                      # 不选
    dfs(0)
    return res

什么时候不该用回溯

  • ❌ 子问题大量重复 → 用动态规划。判断方法：如果不同分支会走到「完全相同的状态」，加个 memo 就能大幅加速。
  • ❌ 只需计数不需要枚举 → 往往有组合数学公式或 DP，不必真去枚举。
  • ❌ n 较大（如 > 30）且无法有效剪枝 → 回溯会超时，需要考虑近似算法或改变建模方式。
回溯 vs 动态规划的判断：回溯是「枚举所有可能并检验」，DP 是「用状态转移复用子问题的答案」。当你发现不同分支会重复计算同一个状态时，就是该转向 DP 的信号——这也是记忆化搜索（memo + 回溯）成为两者桥梁的原因。

🎯 面试问答

Q：回溯的通用模板是什么？最容易错在哪？

A：三步骨架：① 判断结束条件（到达叶子就收集答案）；② 枚举本层所有候选，对每个候选「做选择 → 递归 → 撤销选择」；③ 递归返回后撤销。最容易错的两点：忘记撤销（path.pop()），导致后续分支带着前面的选择，结果全错；收集答案时没拷贝（应该 res.append(path[:])），直接 append 的是同一个列表引用，最后会被 pop 成空。

Q：什么是剪枝？常见的剪枝手段有哪些？

A：剪枝是提前判定某分支必然无解（或不可能更优）并直接返回，避免无谓的指数级枚举。分两类：约束剪枝（可行性）——当前选择本身已违反约束（如 N 皇后中该位置会被攻击）；限界剪枝（最优性）——继续下去也不可能优于已有最优解。常用手段：排序后利用单调性剪掉整层（如组合总和中剩余目标小于当前候选就 break）、排序 + 跳过重复元素去重、每层用 set 记录已试过的值。

Q：子集、组合、全排列的回溯写法有什么不同？

A：差别在「选择空间怎么缩小」：子集是「每个元素选/不选」共 2^n 种，每个节点都是一个解（不只叶子）；组合是选 k 个且不关心顺序，用 start 下标保证只往后选从而避免 [1,2] 和 [2,1] 重复；全排列关心顺序，每步从未使用过的元素里选，需要 used 数组，有重复元素时还要额外去重（排序 + 跳过同层相同值）。

Q：为什么收集答案时必须拷贝 path？

A：因为 path 是同一个列表对象，回溯过程中不断 append/pop。如果直接 res.append(path)，存进去的是引用，当回溯结束 path 被一路 pop 回空时，res 里所有元素也都会变成空列表。必须写成 res.append(path[:]) 或 list(path) 做浅拷贝，把当时的快照固定下来。这是初学回溯最常见的坑之一。

Q：回溯和动态规划怎么选？

A：核心判断是子问题是否重复。回溯是「枚举所有可能并检验」，适用于分支状态各不相同的场景；如果不同分支会走到完全相同的状态（如多次计算同一个子问题），就该用动态规划，或者用记忆化搜索（回溯 + memo）作为过渡——它在保留回溯写法的同时，用缓存避免重复计算。所以看到「重复状态」就是转向 DP 的信号。

Q：N 皇后问题怎么用回溯解？

A：按行递归：第 row 行尝试放在每一列 col，检查该列是否已有皇后、两条对角线是否已有皇后（这是约束剪枝）。合法则放置并递归下一行，返回后撤销。因为每行恰好放一个，天然避免了行冲突，只需要检查列和两个对角线。可用三个集合（列、主对角线 row−col、副对角线 row+col）在 O(1) 内完成冲突检查。这是约束剪枝发挥关键作用的经典例子——没有剪枝就是 n^n 的暴力枚举。

第一层 · 概念与判定：什么问题用回溯

一句话判据：要枚举所有（或部分）「由多步选择构成」的候选解，并在过程中能提前判定「这条路走不通」。

特征回溯暴力枚举动态规划
解的形式一系列选择构成的路径同上最优值 / 布尔
能否提前剪枝✅ 核心优势❌—
要枚举全部解还是求最优全部 / 任一全部只求最优值
复杂度量级通常指数级指数级多项式级（有重叠子问题时）
  • 信号一：题目要「所有方案 / 所有组合 / 所有排列」→ 回溯。
  • 信号二：可以画成一棵决策树（每步选什么）→ 回溯。
  • 信号三：只问「最少几步 / 最大价值」且有重叠子问题 → 那是 DP，别写回溯。

回溯与 DFS 的关系：回溯就是「带撤销操作的 DFS」——DFS 负责走到底，撤销（pop）负责回到上一步尝试别的分支。

第二层 · 参数·命令·量化：模板、剪枝与复杂度估算

回溯模板：全排列与组合

# 回溯通用模板（三段：做选择 -> 递归 -> 撤销选择）
def backtrack(path, choices):
    if is_solution(path):            # 1) 终止：得到一个完整解
        result.append(path[:])       #   注意要拷贝，path 会被复用
        return
    for c in choices:                # 2) 遍历本层所有可选项
        if not valid(c):             #    剪枝：不合法直接跳过
            continue
        path.append(c)               #    做选择
        backtrack(path, next_choices(c))
        path.pop()                   # 3) 撤销选择（回溯的精髓）

# 经典：全排列（用 used 数组避免重复选同一个元素）
def permute(nums):
    res, path, used = [], [], [False] * len(nums)
    def dfs():
        if len(path) == len(nums):
            res.append(path[:]); return
        for i, v in enumerate(nums):
            if used[i]: continue
            used[i] = True;  path.append(v)
            dfs()
            path.pop();      used[i] = False
    dfs(); return res

# 经典：组合（用 start 下标避免顺序不同的重复解）
def combine(n, k):
    res, path = [], []
    def dfs(start):
        if len(path) == k:
            res.append(path[:]); return
        # 剪枝：剩下元素不够凑齐 k 个，直接停
        for i in range(start, n - (k - len(path)) + 2):
            path.append(i); dfs(i + 1); path.pop()
    dfs(1); return res
剪枝手段做法收益
可行性剪枝当前选择已违反约束就停砍掉整棵子树
上下界剪枝剩余元素已凑不够 / 已超过最优组合题常用，效果显著
去重剪枝排序后跳过本层相同元素避免重复解（含重复元素的排列/组合）
记忆化记录已算过的状态有重叠子问题时从指数降到多项式

复杂度估算：回溯的时间 ≈ 决策树的节点数。n 个元素的全排列是 O(n·n!)，子集是 O(n·2^n)——所以回溯只适用于 n 较小（通常 n ≤ 20）的场景。

第三层 · 排障与边界：最容易写错的地方

坑后果正确做法
res.append(path) 没拷贝结果全是空列表必须 path[:] 或 list(path)
忘记 path.pop()路径越加越长，死循环撤销与做选择必须成对
含重复元素没去重结果里有重复解先排序，再 if i>start and nums[i]==nums[i-1]: continue
组合写成排列（或反之）解的数量不对组合用 start 下标；排列用 used 数组
没有剪枝，n 稍大就超时指数爆炸加可行性/上下界剪枝，或改用 DP
  • 排查顺序：先确认 append 时拷贝了 → 再看 pop 是否配对 → 再确认去重逻辑 → 最后评估是否需要剪枝。
  • 边界一：path 是同一个列表对象被反复修改，所以必须拷贝快照——这是新手最常踩的坑。
  • 边界二：「组合」与「排列」的区别只在是否考虑顺序：组合用 start 下标保证升序，排列用 used 数组允许任意顺序。
  • 边界三：n > 20 时回溯基本不可行，需要换DP / 贪心 / 启发式。

去重模板

# 去重模板：含重复元素时避免重复解
nums.sort()                      # 1) 先排序
def dfs(start, path):
    if len(path) == k:
        res.append(path[:]); return
    for i in range(start, len(nums)):
        # 2) 本层中，与前一个相同的元素只取第一个
        if i > start and nums[i] == nums[i - 1]:
            continue
        path.append(nums[i]); dfs(i + 1, path); path.pop()

第四层 · 原理与取舍：回溯 vs 动态规划

两者都在「决策树」上搜索，区别在于子问题是否重叠：回溯的每个路径基本独立（所以只能一个个试），DP 的子问题会重复出现（所以能记忆化复用）。

维度回溯动态规划
解的形式要列出所有具体方案只要最优值 / 是否可行
复杂度指数级（决策树节点数）多项式（状态数 × 转移）
剪枝空间大（可行性、上下界、去重）小（状态压缩、单调队列优化）
n 的适用规模通常 ≤ 20可到数千
典型题全排列、N 皇后、数独、子集背包、LCS、区间 DP、状压 DP
什么时候该把回溯改成 DP？

当你只关心「最优值」而不是「具体方案」，且发现同一状态被反复计算时。判据：如果状态可以只用几个参数描述（如「第 i 个物品、剩余容量 j」），就该上 DP。

剪枝到底能省多少？

取决于问题。N 皇后用可行性剪枝能把 n=8 的节点数从 8^8 ≈ 1700 万 降到约 2 万，省了近千倍——这就是「能不能过」的差别。

回溯和分支限界有什么区别？

回溯求所有解或任一解；分支限界求最优解，它维护一个「当前最优值」作为界，任何不可能超过该界的分支直接砍掉（上界/下界剪枝）。求最优时分支限界更快。

每个剪枝条件都应能解释“为什么剩余分支无解”。
