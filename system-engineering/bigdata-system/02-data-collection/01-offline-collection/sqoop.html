定位

Sqoop 位于大数据采集层（离线批量），解决“业务库里的关系型数据怎么进 Hadoop”的问题。它把一条导入/导出命令翻译成多个 Map 任务并行执行，充分发挥集群算力。

导入原理

导入时 Sqoop 通过 JDBC 连接源库，按切分列（通常是主键）把数据划分成若干段，每段由一个 Map 任务负责，并行读取并写入 HDFS。导出（export）方向相反：从 HDFS 读到 Map，批量 INSERT/UPDATE 回数据库。

增量导入

模式依据适用场景
append自增 ID 最大值日志类只追加数据
lastmodified时间戳列会更新的业务表
全量整表首次初始化 / 小表

增量导入避免每次全量搬运，是生产环境同步业务库的常规手段，通常配合调度系统每天跑一次。

🎯 面试问答

Q：Sqoop 为什么用 Map 而不是 Reduce？
A：导入只需把源库数据并行搬进 HDFS，是“读-写”映射，无需跨节点汇聚，因此只有 Map 阶段。
Q：切分列怎么选？
A：选分布均匀、有索引的列（如自增主键）；若分布倾斜，单个 Map 会拖慢整体。
Q：导出的事务一致性如何保证？
A：Sqoop 批量提交，失败可重跑；它不是强一致迁移工具，需业务侧配合低峰期操作。
