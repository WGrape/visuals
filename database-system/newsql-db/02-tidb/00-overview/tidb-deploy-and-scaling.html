TiDB 部署与扩缩容实战

用 TiUP 拉起最小集群，搞清楚 PD / TiKV / TiDB 的角色与扩容路径

TiDB 用 TiUP 一条命令拉起集群。理解 PD / TiKV / TiDB 三类角色，以及「扩 TiDB=提并发、扩 TiKV=提存储与写入」的扩容逻辑，比背概念更有用。

02最小部署（TiUP）

# 1) 准备拓扑文件 topo.yaml
tiup cluster deploy tidb-test v7.5.0 ./topo.yaml --user root -p
# 2) 启动
tiup cluster start tidb-test
# 3) 查看状态
tiup cluster display tidb-test
# topo.yaml 关键片段
pd_servers:
  - host: 10.0.0.1
  - host: 10.0.0.2
  - host: 10.0.0.3
tidb_servers:
  - host: 10.0.0.4
  - host: 10.0.0.5
tikv_servers:
  - host: 10.0.0.6
  - host: 10.0.0.7
  - host: 10.0.0.8
要点：本地尝鲜用 `tiup playground` 可一键起一套伪集群，不用写拓扑文件。

03扩缩容

# 扩容 TiDB（提升 SQL 并发与连接数）
tiup cluster scale-out tidb-test scale-tidb.yaml
# 扩容 TiKV（提升存储容量与写入吞吐）
tiup cluster scale-out tidb-test scale-tikv.yaml
# 缩容某个节点（TiKV 会自动先迁移其上 Region）
tiup cluster scale-in tidb-test --node 10.0.0.6:20160
要点：扩 TiDB 只加 SQL 接入能力；扩 TiKV 才加存储与写入。缩容 TiKV 前集群会自动 transfer Region，无需手动停写。

05常见疑问

问：单机能不能跑 TiDB？

能，`tiup playground` 在本机起 PD+TiKV+TiDB 伪集群，适合本地验证语法与特性。

问：扩容为什么有时看不到吞吐提升？

可能瓶颈在 TiKV 磁盘或 Region 分布不均；先用 `tiup cluster display` 看各节点负载，再决定是否扩对应角色。

第一层 · 概念与判定

TiDB 是存算分离的 NewSQL：TiDB（无状态 SQL 层）+ TiKV（分布式 KV 存储，Raft 多副本）+ PD（调度/元数据）。扩容可在 SQL 层与存储层独立进行。

  • TiDB 节点无状态，加节点即可提升计算/连接能力。
  • TiKV 按 Region（默认 96MB）分片，PD 自动调度均衡。
  • 判定：写/读压力大或 Region 不均 → 加 TiKV；连接/SQL 计算瓶颈 → 加 TiDB。

第二层 · 参数·命令·量化

扩容与关键参数：

组件扩容动作关注点
TiDB加无状态实例连接数/SQL 算力
TiKV加存储节点Region 再均衡、磁盘
PD3/5 奇数部署元数据高可用
Region默认 96MB过小→元数据膨胀

示例

# 查看 Region 分布与调度
pd-ctl store          # 各 store 容量/region 数
tidb-admin show table t regions   # 表落在哪些 region

# 手动调度（必要时）
pd-ctl operator add transfer-region <id> <store-id>

第三层 · 排障与边界

  • 热点 Region：自增主键或单点写入导致 Region 集中在某 TiKV；用 AUTO_RANDOM 或打散热点 key。
  • Region 调度抖动：频繁 transfer 影响延迟；调 store limit 限速调度。
  • 扩容后未均衡：PD 调度有速率限制，大规模扩容需时间；观察 pd-ctl store 收敛。
  • PD 选主异常：PD 必须奇数（3/5），偶数会在脑裂时不可用。

第四层 · 原理与取舍

存算分离让计算（TiDB）与存储（TiKV）独立伸缩：SQL 层无状态可水平堆，存储层靠 Region+PD 调度实现自动分片与均衡。Raft 保证每个 Region 多数派一致，代价是写需跨节点复制。Region 大小是「调度粒度 vs 元数据量」的权衡。

为什么自增主键会热点？

连续自增使新写入总是落在最后一个 Region，无法分散；用 AUTO_RANDOM 打散到多个 Region。

TiDB 和 TiKV 扩容为何分开谈？

TiDB 只算 SQL、无状态，加实例即扩算力；TiKV 存数据，加节点后要等 PD 把 Region 迁移均衡才生效，两者节奏不同。
