回源流程

用户请求到边缘节点，未命中缓存则回上层/源站拉取资源，缓存后返回。后续同区域请求直接命中边缘。

回源合并/降级

同一资源大量并发未命中时，边缘做回源合并（仅一个回源，其余等待），避免源站被“回源穿透”打垮；源站异常时可返回旧缓存（stale-while-revalidate）。

源站保护

通过边缘缓存命中、回源合并、较长边缘 TTL，把源站压力降到最低。

🎯 面试问答

Q：回源合并是什么？
A：同一资源并发未命中只回源一次。
Q：stale-while-revalidate？
A：返回旧缓存同时后台刷新。
Q：边缘 TTL 设长有风险吗？
A：内容更新不及时，需配合刷新。
