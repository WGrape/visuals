🧠 什么是中断？

中断是硬件或软件发出的异步信号，强迫 CPU 暂停当前任务，转去执行对应的中断处理程序（ISR），处理完再恢复原任务。

📋 完整工作流程

  • 1. 中断请求：外设发出 IRQ 信号
  • 2. 中断判优：中断控制器仲裁优先级
  • 3. 响应中断：CPU 完成当前指令，发出 INTAR
  • 4. 保存现场：FLAGS/CS/IP 压栈
  • 5. 执行 ISR：跳转到中断处理程序
  • 6. 恢复现场：IRET 弹出寄存器
  • 7. 继续原任务：恢复原程序执行

🔑 关键概念

  • IRQ：中断请求信号线
  • ISR：Interrupt Service Routine
  • 中断向量表：存放 ISR 入口地址
  • 上下文切换：保存/恢复寄存器现场
  • 中断屏蔽：IF 标志位控制可屏蔽中断
  • NMI：不可屏蔽中断（硬件故障）

📊 中断分类

  • 硬件中断：外设 → IRQ → CPU（键盘、磁盘、网卡）
  • 软件中断：INT 指令主动触发（系统调用）
  • 异常：CPU 执行指令时检测到错误（除零、缺页）

中断：让 CPU 不必轮询等待

没有中断时，CPU 想知道键盘有没有按下，只能反复查询（轮询），绝大部分查询都是白费。有了中断，设备主动「举手」，CPU 暂停当前工作去处理，处理完再回到原处继续。这是现代计算机能同时处理 I/O 与计算的基础机制。

中断、异常、系统调用的区别

类别产生源时机是否可屏蔽典型例子处理后
外部中断（ interrupt）外设硬件异步，随时发生可屏蔽（NMI 除外）网卡收到包、键盘按下、定时器到点返回下一条指令
异常（exception / trap）CPU 执行指令时内部产生同步，确定位置不可屏蔽除零、缺页、非法指令、断点视类型：处理后返回或终止进程
陷入（trap）程序主动触发同步，有意安排——系统调用（syscall/int 0x80）、调试断点返回下一条指令
不可屏蔽中断 NMI硬件严重事件异步不可屏蔽内存校验错、硬件看门狗紧急处理或宕机转储

关键区别：中断是异步的（与当前指令无关），异常是同步的（由当前指令触发）。缺页异常尤其特殊：它是异常，但处理后要回到原指令重新执行，而不是执行下一条。

工程要点

① 为什么 ISR 要短

  • ISR 执行期间同级中断被屏蔽，太长会丢中断。
  • Linux 中 ISR 不能睡眠（没有进程上下文、不能被调度）。
  • 所以拆成上下半部：上半部只做确认与搬运，下半部做协议处理。
  • 网卡收包的典型流程就是：ISR 触发 NAPI 轮询，软中断里做协议栈处理。

② 中断亲和与多核

  • 中断可以绑定到特定 CPU 核（smp_affinity）。
  • 多队列网卡 + RSS 把不同队列的中断分散到不同核，提高并行度。
  • 绑核要考虑 Cache 局部性：尽量与消费该数据的进程同核或同 NUMA 节点。
  • 观察：/proc/interrupts 看各 CPU 上的中断分布是否均衡。

③ 中断风暴

  • 现象：CPU 大量时间花在中断上（si 占用高）、吞吐反而下降。
  • 原因：低速设备频繁中断、驱动未合并中断、硬件故障持续报错。
  • 对策：中断合并（coalescing）、NAPI 轮询模式、修复硬件。
  • 曾经的经典问题：早期网卡每个包一次中断，千兆下直接把 CPU 打满。

④ 与轮询的取舍

  • 低频率事件：中断更省 CPU。
  • 极高频率事件（10G+ 网络）：中断开销大于收益，改用轮询（NAPI/DPDK busy poll）。
  • 现代做法是混合：中断唤醒 + 轮询批量处理（NAPI 正是如此）。
  • DPDK/io_uring 等追求极致性能的方案，本质是减少或绕开中断与系统调用开销。

深入自检

中断处理函数为什么不能睡眠？

因为中断处理不绑定任何进程上下文，没有可调度实体，睡眠后没有任何机制能把它唤醒；而且它运行时关闭了同级中断，长时间不返回会丢失中断并拖垮系统。所以需要耗时操作时，必须交给下半部（workqueue 等有进程上下文、可睡眠的机制）去做。

缺页异常和一般中断有什么不同？

缺页是异常（同步），由当前指令访问内存触发；处理完成后需要回到触发异常的那条指令重新执行，而不是执行下一条——因为这条指令还没成功完成。外部中断则是执行完当前指令后转去处理，返回时执行下一条指令。

为什么多线程程序也需要中断？

线程的并发是软件层面的抽象，真正让 CPU 感知外部事件的还是中断：时钟中断驱动抢占式调度，I/O 中断通知设备完成，缺页异常支撑虚拟内存。没有中断，操作系统就无法主动收回 CPU，也就无法实现抢占式多任务。

中断向量表放在哪里？

x86 实模式下中断向量表（IVT）固定在内存最低的 1KB；保护模式后改为中断描述符表（IDT），位置由 IDTR 寄存器指定，由操作系统在启动时建立。每个表项包含处理程序地址与特权级等信息。

什么是中断延迟，怎么降低？

中断延迟 = 从中断发生到 ISR 开始执行的时间。影响因素：关中断时间过长、中断被更高优先级占用、内核不可抢占区域、Cache/TLB 缺失。降低手段：缩短关中断临界区、使用实时内核补丁（PREEMPT_RT 把大部分下半部线程化）、绑核隔离、关掉省电与频率抖动。

/proc/interrupts 能看出什么问题？

可以看：各 IRQ 在每个 CPU 上的触发次数（判断是否均衡、是否有中断风暴）、中断类型（如 MSI-X 边沿触发）、设备名。若某 IRQ 计数集中在 CPU0 且增长极快，通常意味着多队列未配置或中断亲和未设置，是网络性能调优的常见入手点。
