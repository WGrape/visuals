TiDB TiFlash 副本：一份写入怎样服务事务与分析

沿订单写入、Raft 复制和分析查询，理解行存 TiKV 与列存 TiFlash 的不同职责。

HTAP 问题从混合负载开始

电商系统要按订单 ID 毫秒级更新状态，也要按省份和日期扫描上亿订单计算销售额。前者是点查与小范围写入，后者是大范围列扫描与聚合。如果都挤在同一组事务节点上，分析查询可能读取大量数据、占用 CPU 和 IO，影响在线交易。TiDB 的常见 HTAP 架构把事务处理主要交给 TiKV，把分析读取交给 TiFlash 列存副本，SQL 层根据代价与可用副本选择执行路径。

TiFlash 不是把另一套无关的报表库手工同步一次。它作为与 TiKV 同一逻辑数据的副本参与复制与读取；具体复制、应用日志和一致性实现随版本演进。需要先为表配置 TiFlash 副本，并等待副本就绪，再期待优化器使用它。没有就绪副本、查询选择性很高或统计信息不准时，分析查询未必走 TiFlash。

图解：订单写入与分析查询的两条路径

沿箭头逐步核对输入、变换和输出；下面的推演可以逐步切换。

从一条订单写入追踪到列扫描

用户创建订单，SQL 由 TiDB 节点解析与规划，事务写入落到 TiKV 的相关 Region。Region 的日志按副本协议复制，TiFlash 接收并组织成适合列读取的形式。报表只需日期、省份和金额三列时，列存能减少其他列的读取，并在批量执行中高效聚合。它的收益来自少读列、批量算和分布式并行，不是“所有 SQL 都比行存快”。

如果查询 `WHERE order_id = ?` 后更新一行，TiKV 的索引与行式访问通常更贴近需求；若 `GROUP BY province` 扫描多天金额，TiFlash 更有机会发挥。一个复杂查询还可能混合不同算子，执行计划应通过 EXPLAIN 和真实执行统计验证。SQL 文本相同，副本状态、统计信息、过滤率和数据规模变化后，计划也可能改变。

副本一致性要问具体读语义

“实时分析”不等于任意时刻、任意副本都已经应用最新写入。事务读需要满足系统承诺的快照一致性和副本安全读取条件。分析查询选择的时间戳、TiFlash 已应用的进度、查询是否等待副本追上，都会影响可见性与延迟。不要把普通异步 ETL 的延迟模型直接套在副本读取上，也不要把“有副本”误解成“零等待”。用一条已提交订单立即查询报表时，应按目标产品版本验证读语义。

分析结果还可能因业务口径而看似“滞后”：订单刚创建但尚未支付，统计口径只计支付订单；退款事件尚未处理。排查时区分复制进度、事务提交时间与业务状态变化。给报表记录查询快照时间及口径，比只看“几秒前下单现在没看到”更准确。

资源隔离不是副本天然保证

TiFlash 能减轻 TiKV 事务节点的列扫描压力，但两者仍可能共享 TiDB SQL 节点、网络、存储集群预算或上游流量入口。一次超大报表查询若耗尽 SQL 层线程、内存或网络带宽，在线请求仍会受影响。需要结合资源组、并发限制、查询超时、报表排队和容量规划。为所有表盲目增加 TiFlash 副本会增加存储与复制成本，还会拉长副本构建与维护时间。

当新增大表副本时，先估算数据量、复制流量、构建峰值、磁盘与后台任务竞争。线上观察 TiKV 写入延迟、TiFlash 副本追赶进度、分析查询等待时间和 SQL 节点资源。试验要覆盖白天写入高峰与夜间大报表，不能只在空库测一条聚合语句。

选择计划的实操顺序

先写清查询的业务结果与过滤条件，再看访问行数、读取列数和聚合基数。用 EXPLAIN 检查是否使用 TiFlash、是否有大规模数据交换以及聚合是否下推。若没有按预期走列存，先检查副本是否可用、统计信息是否新鲜、谓词是否可下推，再考虑测试性地约束执行引擎。强制计划可能在数据分布变化后退化，正式使用要有对照基准与回退方案。

扫描只有十行时，列存读取和分布式调度开销可能超过收益；扫描十亿行只取三列时优势才更明显。可把原查询与按日期分区、预聚合物化结果的方案一起比较，记录 P95、CPU 秒、读取字节和报表新鲜度。HTAP 不代表无需数据建模或治理。

一次完整验收

准备 100 万订单，包含用户、日期、省份、金额、状态等列。先执行订单 ID 点查与更新，再执行按日期和省份的销售额分组；分别检查两类查询的执行计划与节点资源。在 TiFlash 副本未就绪时记录计划；副本就绪后重跑并比较读取字节与延迟。然后在持续写入下做相同对照，观察报表对事务 P99 的影响。

练习：报表计划走了 TiFlash，但在线交易仍变慢。列出至少三个可能共享的瓶颈，并说明每个瓶颈该查哪项指标。

自检

配置了 TiFlash 副本后，按订单 ID 更新单行就应该强制走 TiFlash 吗？

不应。点查更新通常适合事务路径；是否使用列存应看查询形态、副本状态与真实执行计划。
