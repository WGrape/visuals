大模型安全 · 可视化讲解

安全评测与护栏
怎么知道模型“够安全”

攻击手法再多，最终都要落到“能不能量化安全、能不能在线上兜住”。这一页把安全从“怕出事”变成可测量的工程：拒答率/过拒率双曲线、安全评测集与红队、分层护栏与线上监控。

第 1 步 · 为什么

安全不能只靠“感觉安全”

攻击手法讲了一堆，但最终要落到工程问题：怎么知道模型够不够安全？“感觉没事”会在上线后翻车。安全必须变成可量化、可监控、可回归的指标。

可量化
有害内容率、拒答率、过拒率——用数字说话，而不是“应该没事”。
可监控
线上持续采样评分 + 护栏告警，安全是过程不是一次动作。
安全评估是 模型评估 的“安全维度”在落地层的展开：离线评测集 + 红队 + 线上护栏，三管齐下。
第 2 步 · 双指标

拒答率与过拒率：一条不能只盯一条

安全有两个相互拉扯的指标，必须同时看：

指标含义健康区间只看它的后果
有害内容率真正输出有害内容的占比越低越好（<0.5%）—
拒答率 Refusal该拒的（有害请求）被拒比例高（>95%）拒答率低=漏防
过拒率 Over-refusal正常请求也被误拒的比例低（<10%）过拒高=体验崩坏
图 1：安全强度与过拒率此消彼长，要找到平衡点
经典误区：只盯拒答率把正常请求（如“how to kill time”“制作蛋糕”）也拒掉，过拒率飙升，用户骂声一片。健康做法是双指标同时达标。
第 3 步 · 评测

安全评测怎么做

  • 有害评测集：覆盖暴力、色情、仇恨、违法、自残等类别，含“看似敏感实则无害”的边界样本（测过拒）。
  • 对抗/红队集：人工或模型构造的越狱与提示注入样本，测防御边界（见 越狱与提示注入）。
  • 自动化裁判：用分类器/LLM 裁判给输出打“是否有害”标签，做高频回归；但裁判自身有安全偏差，需人工校准。
  • 间接注入样本：把恶意指令藏在网页/RAG 内容/工具返回里（见 工具输出提示注入），必须单独测。
评测集要版本化且保密：最终安全测试集不能进训练/对齐反馈循环，否则会被“训进去”而分数虚高。
第 4 步 · 护栏

分层防御：不靠单一手段

任何单一护栏都会被绕过。落地靠分层，每层独立失效也不至于全盘崩：

① 输入清洗
过滤明显恶意、脱敏 PII、标准化编码防绕过（见 攻击手法）。
② 提示结构
系统指令与不可信内容分通道，明确“只有系统指令有执行权”。
③ 输出检测
生成后再过一遍有害分类器，越线则拦截或改写。
④ 最小权限 + 人工确认
工具只给必要权限；高风险动作（删库、转账）强制人工确认。
护栏之外还要有监控：线上采样评分、用户点踩率、越线自动告警与回滚。安全评估不是发版前一次，而是持续闭环。
收尾 · 一句话

所以安全评测与护栏是什么

安全评测与护栏 = 把“模型够不够安全”变成可量化的工程： 同时盯 拒答率与过拒率 两条曲线、用版本化评测集 + 红队 + 自动化裁判离线验收、 用输入清洗/提示结构/输出检测/最小权限分层防御、并靠线上监控持续兜底。 一句话：安全不是“感觉没事”，而是“指标在线、护栏分层、持续验证”。

第二层 · 参数·命令·量化：指标怎么算

# 三个核心安全指标的计算
  refusal_rate      = refused_harmful / total_harmful        # 该拒的拒了多少（越高越安全）
  over_refusal_rate = refused_benign  / total_benign         # 正常请求被误拒（越低越好）
  harmful_rate      = harmful_outputs / total_outputs         # 实际输出有害占比（越低越好）

# 红队样本量经验值
  #   想检测出 2pp 的越狱成功率变化，每条攻击手法准备 >= 200 条变体
  #   边界（benign-but-sensitive）样本 >= 100 条，专门测过拒

阈值不是绝对的：金融/医疗等高风险场景拒答率可放宽容忍、过拒率压更紧；闲聊场景反之。按业务定，但两条曲线必须同时看。

第三层 · 排障与边界：四个高频坑

  • 只看拒答率：漏掉过拒，正常请求被拒→体验崩。必须双指标。
  • 只测已知攻击：红队集固定后会被“训进去”，零日绕过测不到→定期换新题。
  • 护栏单点：只做输出检测，攻击者绕输入→分层防御，每层独立。
  • 评测集泄漏：安全测试集进训练循环，分数虚高→保密集不进反馈。

第四层 · 原理与取舍：为什么安全这么难

为什么安全与体验必然博弈？

因为“拒绝有害”和“回答正常”用的是同一个拒绝机制。调严→漏防少但过拒多；调松→过拒少但漏防多。只能靠更细的边界样本与分层防御逼近平衡，没有银弹。

为什么不能只靠一个护栏？

单一防线一旦被绕过就全盘暴露。分层让各层独立失效：即使输入清洗被绕过，提示结构与输出检测仍能拦截。纵深防御是安全工程的基本共识。

红队为什么要持续做？

模型与攻击者都在进化。今天的防御 tomorrow 可能被新越狱绕过，且评测集会被隐式过拟合。红队是“持续验证”而非“一次通关”——这也是线上监控不可替代的原因。

第一层 · 概念与判定 安全评测覆盖越狱、提示注入、数据泄露与有害输出；防御用输入过滤、输出护栏与权限最小化。判定：上线前跑红队集，生产加实时护栏。

风险评测手段防御
越狱 / 提示注入对抗样例集系统提示隔离 + 输入校验
数据泄露敏感信息探针脱敏 + 权限隔离
有害内容安全分类器输出护栏 + 拒绝
工具滥用越权调用测试最小权限 + 人工确认

第三层 · 排障与边界

  • 只靠提示词做护栏会被越狱绕过，必须多层（提示+分类器+策略）。
  • 红队集过时，新攻击面没覆盖，需持续补样例。
  • 过度拦截误伤正常用户，护栏阈值要可观测可调。
  • 工具调用未做权限边界，模型可越权访问内部系统。
第四层 · 原理与取舍

安全用“多层防御 + 持续评测”换可信，代价是延迟、误伤与维护成本。提示层护栏最便宜但最易被绕过，分类器与策略引擎更稳但需标注与调参。权衡是“安全性 vs 可用性”：安全红线（违法/泄露）必须硬拦截，边界场景留人工确认。评测的本质是“用对抗样例逼出真实失守面”。

实例与速查：安全护栏分层

# 多层防御最小骨架（伪代码）
def guard(user_input, llm):
    if input_filter.is_injection(user_input):   # 第一层：输入校验
        return "rejected"
    resp = llm(system_prompt, user_input)        # 系统提示与用户输入隔离
    if output_classifier.is_harmful(resp):       # 第三层：输出护栏
        return "blocked"
    if needs_privilege(resp):                    # 工具调用边界
        require_human_approval()
    return resp
  • 只靠提示词做护栏会被越狱绕过，必须提示+分类器+策略多层。
  • 红队集要持续补新攻击面，过时会漏。
  • 过度拦截误伤正常用户，护栏阈值要可观测可调。
FAQ：为什么提示词护栏不够？

因为提示词护栏运行在模型“软约束”层面，攻击者可用角色扮演、编码绕过、长上下文淹没等手段突破；分类器与策略引擎是“硬约束”，在模型输出后再做独立判断，二者互补。安全红线（违法/泄露/越权）必须硬拦截，边界场景留人工确认。

常见误区与延伸

  • 误区一：提示词护栏就够了。提示词是软约束，易被角色扮演、编码绕过突破，必须多层。
  • 误区二：拦截越严越好。过度拦截误伤正常用户，护栏阈值要可观测可调。
  • 延伸：安全红线（违法/泄露/越权）硬拦截，边界场景留人工确认，是“安全 vs 可用”的平衡点。
  • 延伸：红队集要持续补新攻击面，过时会漏掉新漏洞，评测本身是攻防的镜像。

一句话总结：大模型安全用多层防御加持续评测换可信，提示、分类器、策略引擎互补，本质是用对抗样例逼出真实失守面。

决策速记

  • 多层防御：提示加分类器加策略，单层易被绕过。
  • 红队持续：攻击面在变，评测集要持续补。
  • 可调阈值：过度拦截误伤用户，护栏要可观测。
  • 硬软分离：违法/泄露/越权硬拦截，边界留人工。

一句话：安全用多层防御加持续评测换可信，本质是用对抗逼出失守面。

横向对比与追问

  • 与传统 WAF 比：WAF 基于规则签名，LLM 护栏基于语义理解，互补而非替代。
  • 与人工审核比：人工准但慢且贵，护栏快但需持续校准，常做“机审+人审”组合。
  • 追问：为什么提示词护栏不够？它是软约束，易被角色扮演/编码绕过。
  • 追问：权限最小化指什么？模型调用工具时只给必要权限，敏感操作留人工确认。

小结：安全是“多层防御 + 持续评测”，本质是攻防的动态平衡。
