3. 切块策略：检索质量的隐形天花板

很多时候 RAG 效果差，不是模型不行，而是'切错了块'。切块决定了向量里装的到底是'一段完整语义'还是'半句话的碎片'。

3.1 为什么切块这么重要

Embedding 是对'一个文本块'产出单个向量。如果块里混了多个主题，向量就四不像；如果块太小，又丢了上下文。两者都让检索召回错内容。

3.2 常见策略与取舍

策略做法优点缺点
固定长度按 Token / 字符数硬切简单、均匀切断句子/段落，语义破碎
按分隔符遇段落 / 标题 / 句号断开保留句边界块大小不均
语义切块用模型判断'该不该断'语义最完整慢、贵，需额外模型
父子块大块存原文+小块向量，命中后回退大块兼顾精准与上下文存储翻倍

3.3 经验参数

  • 长度：检索为主 256~512 Token；问答为主 128~256 Token。
  • 重叠（overlap）：10%~20%，避免'答案被切到两块边界'而两边都召回不全。
  • 标题/元数据拼接：把'文档标题 + 小节标题'拼到每块前面，显著提升检索命中率。
父子块（parent-child）是性价比极高的做法：用小块向量做精准召回，真正喂给 LLM 的是它对应的'大块原文'。这样既不丢上下文，又不让向量太糊。
