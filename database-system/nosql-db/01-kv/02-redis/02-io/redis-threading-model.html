6.0 多线程

网络 IO

为什么单线程也快

瓶颈在网络带宽与内存，不在 CPU。单线程避免了锁竞争与上下文切换，配合 IO 多路复用（epoll）同时处理海量连接，命令执行串行无并发问题。

6.0 多线程 IO

Redis 6.0 把网络读写放到多个 IO 线程并行处理，命令执行仍单线程，既提升吞吐又不引入执行期并发复杂度。

哪些命令会阻塞

大 key 删除、keys *、复杂 Lua、全量 RDB fork 等会阻塞主线程，应规避或拆分。

🎯 面试问答

Q：为什么 Redis 用单线程？
A：避免锁竞争，简单且足够快，瓶颈在 IO/内存。
Q：6.0 多线程改了什么？
A：只并行化网络 IO，命令执行仍单线程。
Q：大 key 为什么危险？
A：删除/序列化阻塞主线程，拖慢所有请求。
