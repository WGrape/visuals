🔤 Cypher 查询语言

用 ASCII 艺术描述图模式：MATCH / CREATE / MERGE / 可变长路径与性能要点

Cypher 的核心思想

Cypher 是声明式的图模式匹配语言。它让你用 ASCII 符号把「图长什么样」画出来，引擎负责找匹配。节点用圆括号、关系用方括号加箭头：

(a:Person)-[:KNOWS]->(b:Person)
 │      │       │         │      │
 │      │       │         │      └─ 另一个节点的标签
 │      │       │         └──────── 变量 b
 │      │       └────────────────── 关系类型 + 方向
 │      └────────────────────────── 标签（Label）
 └───────────────────────────────── 变量 a
🌰 记忆法：圆括号 () 像圆圈代表节点，方括号加箭头 -[]-> 像一支箭代表关系。你画什么形状，它就找什么形状。

五大子句

子句作用说明
MATCH匹配图模式相当于 SELECT ... FROM，核心子句
WHERE过滤对属性/路径加条件
RETURN返回结果可返回节点、属性、路径、聚合
CREATE / MERGE创建 / 「有就用没有就建」MERGE 是幂等写入的关键
SET / DELETE / REMOVE改属性 / 删节点关系 / 删标签属性删节点前必须先删关系

读：从简单到复杂

// ① 基础：找 Alice 认识的人
MATCH (a:Person {name:'Alice'})-[:KNOWS]->(f)
RETURN f.name, f.age

// ② 无向匹配（不关心方向）
MATCH (a:Person {name:'Alice'})-[:KNOWS]-(f) RETURN f.name

// ③ 多跳：可变长路径 *1..3（1 到 3 跳）
MATCH (a:Person {name:'Alice'})-[:KNOWS*1..3]->(f)
RETURN DISTINCT f.name

// ④ 任意深度（慎用！可能爆炸）
MATCH (a)-[:KNOWS*]-(b) RETURN b

// ⑤ 最短路径
MATCH p = shortestPath((a:Person {name:'Alice'})-[*..6]-(b:Person {name:'David'}))
RETURN p, length(p)

// ⑥ 所有最短路径
MATCH p = allShortestPaths((a)-[*..6]-(b)) RETURN p

// ⑦ 聚合 + 分组
MATCH (p:Person)-[:WORKS_AT]->(c:Company)
RETURN c.name, count(p) AS headcount, avg(p.age) AS avgAge
ORDER BY headcount DESC LIMIT 10

// ⑧ 可选匹配（LEFT JOIN 语义）
MATCH (p:Person)
OPTIONAL MATCH (p)-[:WORKS_AT]->(c:Company)
RETURN p.name, c.name          // 没公司的返回 null

// ⑨ 路径模式 + 环检测
MATCH p = (a:Account)-[:TRANSFER*2..5]->(a)   // 回到自己 = 环路
RETURN p LIMIT 20

写：CREATE vs MERGE

语句行为幂等吗何时用
CREATE无条件新建否（重复执行会产生重复数据）确定不存在时；批量导入
MERGE存在就用，不存在就创建是ETL、重复执行的数据同步
CREATE UNIQUE（已废弃）——用 MERGE 替代
// MERGE 保证幂等：跑多少次都只有一条
MERGE (a:Person {name:'Alice'})
ON CREATE SET a.createdAt = timestamp()
ON MATCH  SET a.lastSeen = timestamp()
RETURN a

// 关系也要 MERGE，否则会重复建关系
MATCH (a:Person {name:'Alice'}), (b:Person {name:'Bob'})
MERGE (a)-[r:KNOWS]->(b)
ON CREATE SET r.since = 2020
RETURN r

// 改属性 / 删关系 / 删节点
MATCH (a:Person {name:'Alice'}) SET a.age = 31
MATCH (a:Person {name:'Alice'})-[r:KNOWS]->(b) DELETE r       // 只删关系
MATCH (a:Person {name:'Alice'}) DETACH DELETE a                // 删节点+其所有关系
⚠️ DELETE 节点前必须先删它的关系，否则报错。用 DETACH DELETE 一次搞定（先删关系再删节点）。生产上大批量删除要分批处理，避免单个事务过大撑爆内存。

可变长路径：威力与风险

⚠️ 永远给可变长路径加上限：[:KNOWS*1..3]，不要写 [:KNOWS*]。平均度数 d、深度 n 的路径数量约 dn，在社交网络这种高度数图上，* 会瞬间耗尽内存。

性能要点

要点做法为什么
用参数MATCH (p:Person {name:$name})避免每次重新编译查询计划，命中缓存
起点要能定位起点的标签+属性上建索引否则 MATCH 从全库扫描开始
限定深度*1..3防止路径爆炸
尽早过滤把 WHERE 放在遍历前能过滤的位置减少遍历的分支
分页用 SKIP/LIMIT配合 ORDER BY深翻页同样昂贵
批量写分批提交CALL {} IN TRANSACTIONS（每批 1 万条）避免单事务撑爆内存
看执行计划EXPLAIN / PROFILE找全扫描与行数爆炸的位置
// 建索引（加速起点定位）
CREATE INDEX person_name FOR (p:Person) ON (p.name);
CREATE CONSTRAINT company_name FOR (c:Company) REQUIRE c.name IS UNIQUE;

// 用参数（可复用查询计划）
:param name => 'Alice'
MATCH (p:Person {name:$name})-[:KNOWS]->(f) RETURN f.name

// 看执行计划
PROFILE MATCH (p:Person {name:'Alice'})-[:KNOWS*1..3]->(f) RETURN f
// 关注：NodeIndexSeek（好） vs NodeByLabelScan（全扫，坏）、Rows 是否爆炸

// 批量写：分批提交
LOAD CSV WITH HEADERS FROM 'file:///people.csv' AS row
CALL {
  WITH row
  MERGE (p:Person {name: row.name}) SET p.age = toInteger(row.age)
} IN TRANSACTIONS OF 10000 ROWS;

🎯 常见问法与答题要点

Q：Cypher 里 () 和 [] 分别是什么？

A：圆括号 () 表示节点，方括号 [] 表示关系。写起来就是：(a:Person)-[:KNOWS]->(b:Person)——节点用 ()，中间的类型写在 [] 里，箭头表示方向。变量（a、b）可以在后续子句里引用。这就是所谓「ASCII 艺术」：你画出的形状就是你要匹配的形状。

Q：MATCH 和 OPTIONAL MATCH 有什么区别？

A：MATCH 是内连接——匹配不到就整行不返回；OPTIONAL MATCH 是左外连接——匹配不到时变量为 null，主节点照样返回。例如「列出所有人及其公司（没有公司的也列出）」就必须用 OPTIONAL MATCH，用 MATCH 会把没公司的人过滤掉。

Q：CREATE 和 MERGE 该用哪个？

A：看是否需要幂等。CREATE 无条件新建，重复执行会产生重复节点/关系；MERGE 是「有就用、没有就建」，重复执行结果一致。ETL 与数据同步脚本一律用 MERGE（配合 ON CREATE / ON MATCH 分别设置创建时和匹配时的属性）。批量导入确定无重复时用 CREATE 更快。

Q：为什么删除节点前要先删关系？

A：因为关系在 Neo4j 里是独立的存储记录，节点记录里还存着指向关系的指针。直接删节点会留下悬空的关系记录，所以引擎会拒绝。两种做法：①先 MATCH (n)-[r]-() DELETE r 再 DELETE n；②直接用 DETACH DELETE n，它会先删关系再删节点。

Q：可变长路径为什么要加深度上限？

A：因为路径数量随深度指数爆炸。平均度数 d、深度 n 时约 d^n 条路径：一个平均 50 个好友的社交网络，4 跳就是 50⁴ = 625 万条路径，5 跳 3 亿条——瞬间耗尽内存。所以必须写 [:KNOWS*1..3] 这样的有界形式，绝不要写 [:KNOWS*]。

Q：Cypher 查询慢怎么排查？

A：三步：①用 PROFILE 看执行计划，重点看起点是 NodeIndexSeek（走索引，好）还是 NodeByLabelScan（全扫，坏）；②看各步骤的 Rows，哪一步突然放大就是瓶颈（通常是可变长路径没限深度，或笛卡尔积）；③给起点标签+属性建索引，限定路径深度，用参数化查询命中计划缓存。

Q：为什么推荐用参数而不是拼接字符串？

A：两个原因：①性能——字面量每次都不同，Neo4j 要重新编译查询计划；用 $param 时计划可缓存复用。②安全——拼接字符串有注入风险（类似 SQL 注入）。所以 MATCH (p:Person {name:$name}) 永远优于直接拼 {name:'Alice'}。

Q：怎么批量导入大量数据？

A：三种方式按速度排序：①neo4j-admin database import（离线批量导入，最快，但要求库是空的或离线的，适合初始化）；②LOAD CSV + CALL {} IN TRANSACTIONS（在线导入，每批 1 万条提交，避免单事务过大）；③逐条 CREATE（最慢，仅调试用）。导入前记得给要 MERGE 的字段先建约束/索引，否则 MERGE 会退化成全表扫描，慢到无法接受。
