单核高 vs 整体高

两种形态，两种思路

单核 100% 多为某个死循环或热点函数；多核整体高可能是并发设计问题、锁竞争或 GC 风暴。先区分再深入。

常见原因速查

  • 死循环 / 条件写错导致无限迭代
  • 频繁 GC（对象分配过快）
  • 锁竞争、CAS 自旋
  • 正则回溯、大对象序列化
  • 频繁系统调用与上下文切换
问题 1
CPU 高怎么系统排查？

按「整机 → 进程 → 线程 → 热点」逐级下钻：先用 top 看哪台机器、哪个进程；pidstat -u -t 1 分线程定位；再用 perf top/record 抓热点函数并生成火焰图，看最宽的栈帧是谁。

问题 2
单核 100% 和整体 100% 区别在哪？

单核高通常是某一个线程的死循环或热点函数；整体高往往是并发设计问题、全局锁竞争或 GC 风暴。前者下钻到线程，后者要看锁与 GC 指标。

问题 3
怎么判断 CPU 高是 GC 引起的？

看 GC 日志 / 监控里 GC 耗时与频率，若 CPU 高与 GC 时间高度重合、且对象分配速率很高，基本是 GC 压力。对策是减少临时对象、复用缓冲、调 GC 参数。

问题 4
死循环导致的 CPU 高有什么特征？

某个线程长期 100%、火焰图顶部是同一个业务函数、且代码里存在条件永远满足的循环。用 py-spy / pprof 抓栈一眼能看出卡在哪一行。
