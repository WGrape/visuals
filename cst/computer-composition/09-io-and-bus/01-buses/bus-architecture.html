🔬 总线系统架构图

📍

地址总线

Address Bus
  • 传输内容内存地址 / I/O端口地址
  • 传输方向单向：CPU → 内存 / I/O
  • 总线宽度决定可寻址空间（32位→4GB）
  • 发出方CPU（主设备）发出地址
  • 三态特性高阻态 / 低电平 / 高电平
  • 关键特点地址在总线周期开始时稳定
💾

数据总线

Data Bus
  • 传输内容指令代码 / 操作数 / 数据
  • 传输方向双向：CPU ⇄ 内存 / I/O
  • 总线宽度决定每次传输数据量（64位=8B）
  • 发送方写操作：CPU发；读操作：内存/I/O发
  • 三态特性支持多设备共享总线
  • 关键特点数据在总线周期中间阶段有效
🎛️

控制总线

Control Bus
  • 传输内容各类控制信号和状态信号
  • 传输方向多根单向线组成（有入有出）
  • CPU 发出读/写命令、时钟、复位等
  • 外设发出中断请求、DMA请求、就绪等
  • 关键特点协调总线周期和同步各部件
  • 仲裁机制总线仲裁决定哪个设备使用总线

🎛️ 控制总线 — 常见信号及来源

信号名称 方向 发出方 接收方 功能说明
MEMR#CPU→CPU内存存储器读命令，通知内存送出数据
MEMW#CPU→CPU内存存储器写命令，通知内存写入数据
IOR#CPU→CPUI/O设备I/O读命令，从端口读取数据
IOW#CPU→CPUI/O设备I/O写命令，向端口写入数据
CLKCPU→时钟发生器/CPU所有部件时钟信号，同步总线操作
RESET#CPU→CPU/复位电路所有部件复位信号，使系统回到初始状态

HOLD←外设DMA控制器CPU总线请求信号，请求获得总线控制权

🚌 总线传输权限 — 谁可以在哪些总线上传输？

📍 地址总线 — 谁可以传输？

CPU — 正常模式下，CPU是地址总线的唯一主设备，输出内存/I/O地址
DMA控制器 — 获得总线控制权（HLDA响应后），可驱动地址总线
内存/I/O设备 — 不能驱动地址总线（地址是CPU提供的输入）

💾 数据总线 — 谁可以传输？

CPU — 写操作时，CPU向数据总线发送数据
内存 — 读操作时，内存向数据总线发送数据
I/O设备 — 读操作时，I/O设备向数据总线发送数据
DMA控制器 — 获得控制权后，可在数据总线上传输数据

🎛️ 控制总线 — 谁可以发出信号？

CPU 发出：MEMR#、MEMW#、IOR#、IOW#、CLK、RESET#、INTA#、HLDA、ALE、M/IO#
外设/内存发出：INTR、NMI、HOLD、READY#、WAIT#
DMA控制器发出：HOLD（请求总线）、地址信号（获授权后）
时钟发生器：CLK（系统时钟信号）

📋 核心要点总结

📍 地址总线

  • 只传输地址，不传输数据
  • 单向：CPU → 内存/I/O
  • 宽度决定系统最大寻址空间
  • CPU（或DMA）是唯一主设备
  • 地址在 T1 周期（第一个时钟）送出

💾 数据总线

  • 传输实际数据/指令
  • 双向：CPU ⇄ 内存/I/O
  • 宽度决定每次传输数据量
  • 多个设备可分时驱动（三态门）
  • 数据在 T2~T3 周期有效

🎛️ 控制总线

  • 传输同步/控制/状态信号
  • 由多根单向线组成（有入有出）
  • CPU和外设均可发出控制信号
  • 总线仲裁决定使用权归属
  • 是整个总线系统的"交通警察"

带宽换算：把总线速率算成 GB/s

总线参数里最容易被误读的是传输率（GT/s）≠ 带宽（GB/s）：前者是每秒传输多少次，还要乘每次的比特数和编码效率，最后除以 8 才是字节带宽。

总线速率编码每时钟位数有效带宽（单向）
PCIe 1.0 x12.5 GT/s8b/10b（80%）1≈250 MB/s
PCIe 3.0 x18 GT/s128b/130b（98.5%）1≈985 MB/s
PCIe 4.0 x116 GT/s128b/130b1≈1.97 GB/s
PCIe 4.0 x1616 GT/s128b/130b16≈31.5 GB/s
PCIe 5.0 x1632 GT/s128b/130b16≈63 GB/s
PCIe 6.0 x1664 GT/s（PAM4）242b/256b + FEC16≈121 GB/s
SATA III6 Gbps8b/10b1≈550 MB/s（实测峰值）
USB 3.2 Gen210 Gbps128b/132b1≈1.2 GB/s
USB4 / 雷电40 Gbps—1≈5 GB/s（隧道复用后更低）
DDR5-48004.8 GT/s无（并行）64≈38.4 GB/s（单通道）

公式记一条就够：带宽 = 速率 × 通道数 × 编码效率 ÷ 8。例如 PCIe 4.0 x16：16 GT/s × 16 × (128/130) ÷ 8 ≈ 31.5 GB/s。注意这是单向，PCIe 是双向全双工，双向合计约 63 GB/s。

实测链路与带宽

# Linux 上确认 PCIe 实际链路速率与宽度（买回来跑不满先查这个）
lspci -vv | grep -A2 -i 'LnkCap\|LnkSta'
#   LnkCap: Speed 16GT/s, Width x16     <- 插槽能力
#   LnkSta: Speed 8GT/s,  Width x8      <- 实际协商结果（降速了！）
# 常见原因：插在了 x8 电气的槽位、金手指脏、显卡省电模式

# 实时带宽（部分平台支持）
sudo lspci -vvv | grep -i 'lnksta'
# NVMe 实测带宽
sudo nvme smart-log /dev/nvme0 | grep -i 'data_units'
sudo fio --name=seqread --rw=read --bs=1m --size=4g --numjobs=1 \
         --ioengine=libaio --direct=1 --filename=/dev/nvme0n1
串行总线速率档位典型设备特点
I²C100 kbps / 400 kbps / 1 Mbps / 3.4 Mbps传感器、EEPROM、RTC两线、多主、带寻址，速度慢但极省引脚
SPI几 MHz ~ 数十 MHzFlash、显示屏、ADC四线、全双工、靠片选，无寻址
UART常见 9600 ~ 921600 bps调试串口、GPS、蓝牙模块最简单，需双方约定波特率
CAN125 kbps ~ 1 Mbps汽车、工业现场差分信号、抗干扰、有仲裁
USB1.5 Mbps ~ 40 Gbps外设主从结构、轮询式、支持热插拔
PCIe2.5 ~ 64 GT/s显卡、NVMe、网卡点对点、可聚合通道、支持热插拔

总线带宽买回来跑不满，第一嫌疑永远是链路协商降速（LnkSta 低于 LnkCap），第二嫌疑是 DMA 或驱动没走满队列深度（fio 要加 iodepth 与 numjobs）。

时序参数与检查清单

总线传输不是「把数据放上去就完事」，而是严格的四拍：仲裁 → 寻址 → 数据传输 → 总线释放。每一步都有对应的时序参数。

时序参数含义典型量级不满足的后果
Tsu（建立时间）数据在时钟沿到来前必须稳定的时间几 ns采到错误数据或亚稳态
Th（保持时间）时钟沿之后数据必须继续保持的时间几 ns同上
总线周期完成一次传输所需时间几个时钟周期决定最大吞吐
仲裁时间多个主设备竞争总线的耗时1~数周期主设备越多，等待越长
Turnaround读写方向切换的间隔1~2 周期防止总线冲突，必须留
传输延迟信号在总线上传播的时间与长度相关（约 5 ns/m）长总线必须降频
仲裁方式原理优点缺点用在哪
菊花链授权信号依次传递，离仲裁器近的优先实现最简单，引脚少不公平，远处设备可能饿死早期总线、简单外设
集中独立请求每个设备单独一对请求/授权线可设优先级，公平可控引脚多，仲裁器复杂现代 SoC（AXI、AHB）
自举分布式设备自己检测总线空闲后抢占无需中央仲裁器冲突检测与重试开销I²C、CAN、以太网 CSMA/CD

设计与排障逐条核对：

  • 先确认链路实际速率（LnkSta），不要相信标称值。
  • GT/s 不是 GB/s：换算要乘通道数、编码效率、再除以 8。
  • PCIe 是双向全双工，厂商标称的有时是双向合计，比较时要注意口径。
  • 共享总线要算仲裁开销：设备越多，每个设备的平均等待越长。
  • 高速信号看走线等长：差分对长度差过大（> 数 mm）会导致眼图闭合。
  • 长总线必须降频：传播延迟与线长成正比（约 5 ns/m）。
  • 总线宽度与频率是取舍：并行总线频率高不了（skew 问题），所以现代总线都走高速串行（SerDes）。
  • 读写的 turnaround 周期不能省，否则总线会出现双向驱动冲突。
  • 热插拔总线要有静电与浪涌保护，且需要带外检测引脚（如 PCIe 的 PRSNT#）。
  • 带宽瓶颈要端到端查：CPU → 内存 → PCIe → 设备，任何一环不足都会跑不满。
