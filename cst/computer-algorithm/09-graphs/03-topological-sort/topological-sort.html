拓扑排序

如何给一张「有先后依赖」的图排一个不矛盾的先后次序？这正是拓扑排序要解决的问题。

一、从「先穿袜子还是先穿鞋」说起

拓扑排序（Topological Sort）只作用于有向无环图（DAG，Directed Acyclic Graph）——通俗地说，就是一张「箭头有方向、且不会绕回自己」的关系图。

把任务当作节点，依赖关系当作有向边 A → B 表示「A 必须在 B 之前完成」。比如早晨流程：穿袜子 → 穿鞋，刷牙 → 洗脸。这些箭头不允许出现环，否则「A 等 B，B 等 A」谁都动不了——这就是死锁的雏形。

直觉：拓扑排序就是给 DAG 里的节点排一个线性顺序，使得所有边都「从左到右」。这个顺序不唯一。

示例 DAG：A→B→D→E，A→C→D→E，A→C→F→E。任意合法拓扑序都需保持这些方向，例如 A,B,C,D,F,E。

二、算法一：Kahn 算法（基于入度队列）

核心思想极其自然：每次挑一个「没有前置依赖」的节点（入度为 0）输出，然后把它发出的所有边删掉，这会让它下游节点的入度减一，可能解锁新的可输出节点。

步骤

1. 统计所有节点入度。

2. 入度为 0 的入队。

3. 出队并输出，删边、更新下游入度。

4. 重复直到队列空。

环检测

若最后输出的节点数 < 总节点数，说明图里有环——剩下的节点互相「卡住」，永远没有入度为 0 的节点可出。

def kahn(graph):
    indeg = {u: 0 for u in graph}
    for u in graph:
        for v in graph[u]:
            indeg[v] += 1
    q = [u for u in graph if indeg[u] == 0]
    order = []
    while q:
        u = q.pop(0)
        order.append(u)
        for v in graph[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order if len(order) == len(graph) else "有环！"

三、算法二：DFS 后序逆序法

另一种经典做法：对图做深度优先搜索，当一个节点的所有后继都访问完时，把它压入栈顶，最后把栈倒序即得拓扑序。这利用了「后序遍历里，父节点总在子节点之后完成」的性质。

def dfs_topo(graph):
    visited, stack = set(), []
    def dfs(u):
        visited.add(u)
        for v in graph[u]:
            if v not in visited:
                dfs(v)
        stack.append(u)          # 后序：自己最后入栈
    for u in graph:
        if u not in visited:
            dfs(u)
    return stack[::-1]           # 逆序即为拓扑序

两种算法时间复杂度均为 O(V+E)，其中 V 为节点数、E 为边数。Kahn 更适合在循环中流式输出；DFS 法实现更紧凑。

它在回答什么问题

有一堆任务，某些任务必须在另一些之前完成。请把它们排成一个合法的先后顺序。

这个问题抽象成图就是：把任务当点，把「A 必须先于 B」当作一条从 A 指向 B 的有向边。拓扑排序要做的就是给所有点排一个线性序列，使得每条边的起点都排在终点之前。

有向无环图的一种线性排法
适用前提必须是有向无环图（DAG）。有环就无解。
核心价值把一个「谁依赖谁」的网络压成一条可执行的顺序。
复杂度两种主流算法都是 O(V + E)。
副产品顺手可以检测图中是否有环。

方法一：Kahn 算法（BFS，最常写）

思路极其直观：不断输出当前「没有任何前置依赖」的点。

from collections import deque def topo_sort(n, edges): # n：节点编号 0..n-1；edges：[(u, v)] 表示 u 必须先于 v graph = [[] for _ in range(n)] indeg = [0] * n for u, v in edges: graph[u].append(v) indeg[v] += 1 # v 多了一个前置条件 q = deque(i for i in range(n) if indeg[i] == 0) # 起点：入度为 0 order = [] while q: u = q.popleft() order.append(u) for v in graph[u]: indeg[v] -= 1 # u 已完成，v 少一个前置 if indeg[v] == 0: q.append(v) # 前置全部满足，可以开工了 return order if len(order) == n else None # None 表示有环

三个容易踩的点：

  1. 入度要在建图时顺便统计，不要之后单独再扫一遍边。
  2. 有环怎么判断：结果列表长度小于节点数就说明有环（环上的点永远进不了队列）。这是最常用的判环方式。
  3. 想要字典序最小（或最有「优先级」）的序列：把普通队列换成优先队列（最小堆），每次取编号最小的可用点。

方法二：DFS 后序反转

另一个等价思路：深度优先走到走不动为止，然后把它塞进结果 —— 最后把结果整体反转。

def topo_dfs(n, edges): graph = [[] for _ in range(n)] for u, v in edges: graph[u].append(v) state = [0] * n # 0 未访问 / 1 在递归栈上 / 2 已完成 order = [] def dfs(u): state[u] = 1 for v in graph[u]: if state[v] == 1: return False # 遇到回边 → 有环 if state[v] == 0 and not dfs(v): return False state[u] = 2 order.append(u) # 完成时才追加 return True for i in range(n): if state[i] == 0 and not dfs(i): return None order.reverse() # 关键一步 return order

为什么反转之后就对了：DFS 完成时，一个点的所有后继都已经先被加进列表；反转之后，它们自然就排到了这个点之后。直觉上是「谁依赖别人，谁就得后走」。

这个版本的额外好处：三色标记（0/1/2）天然支持立刻发现环 —— 在递归栈上遇到了标记为 1 的节点，就是一条回边。

缺点：递归写法的栈深可能很大，点数很多时容易爆栈；Kahn 的迭代写法更稳妥。

一个重要变种：如果图里有环怎么办？现实业务往往允许环（互相调用的服务）。此时通常找强连通分量、把整个 SCC 缩成一个点再拓扑排序，或者在环中间人为断一条边。「现实数据有环」是工程里最常见的意外。

深入自检

拓扑排序的结果一定是唯一的吗？

通常不是。只有当图中存在哈密顿路径（每一步都只有一个可选节点）时才唯一。比如所有点排成一条链，结果才唯一。工程上如果需要确定性输出，就把普通队列换成优先队列，得到一个按指定规则的最小序列。

怎么判断「有没有环」？

两种方法中任选：① Kahn 跑完后看结果长度是否等于节点数；② DFS 时用三色标记检测回边。前者更简洁，后者能在发现的第一时间就报错（便于定位环的具体位置）。

如果节点很多，哪种实现更合适？

优先 Kahn（迭代）。DFS 递归版在点数上万时容易触及递归深度限制，虽然可以改成显式栈的模拟递归更麻烦。此外大规模场景要注意邻接表（而不是邻接矩阵）来建图，否则空间会是 O(V²)。

能不能处理「有权重」的依赖顺序？

拓扑排序本身不关心权重，它只保证边的先后约束。如果你想在满足约束的所有结果里挑一个最「好」的（比如让总工期最短），那是另一类问题 —— 关键路径法（CPM），它常常先做拓扑排序再在上面做动态规划。
