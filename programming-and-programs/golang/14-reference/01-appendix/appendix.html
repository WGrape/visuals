什么时候用 build tag

  • 不同平台有不同实现
  • 调试版与发布版的差异代码
  • 可选功能模块的开关
  • 测试专用桩代码

常见坑

  • tag 必须在 package 之前，且与包声明之间有空行
  • 没有空行就会被当成普通注释
  • go vet 会检查 tag 语法
  • 自定义 tag 不会自动生效，要 -tags 指定

工程管理建议

  • 平台差异优先用文件名后缀，更直观
  • 功能开关用 tag，但要控制数量避免组合爆炸
  • 在 Makefile 里固化常用 tag 组合

深入自检

go get 和 go mod tidy 有什么区别？

go get 用于添加或调整某个依赖的版本；go mod tidy 用于整体整理——删除未使用的依赖、补齐缺失的依赖，并同步 go.sum。日常改动依赖后应跑一次 tidy。

构建出问题第一步做什么？

先 go clean -cache 清理构建缓存，再重试。缓存损坏是很多「明明没改代码却构建失败」的原因。其次检查 go.sum 是否完整、依赖是否下载完整。

为什么交叉编译会失败？

最常见是启用了 cgo——它需要目标平台的 C 工具链。设置 CGO_ENABLED=0 即可纯 Go 交叉编译；若确实需要 cgo，就得准备对应平台的交叉编译器，复杂度高很多。

GODEBUG 能在生产用吗？

gctrace=1 这类输出开销很小，短时排查可以开；但持续输出会污染日志并产生 I/O 压力。schedtrace 输出更密集，只建议短时使用。用完记得关。

二进制太大怎么处理？

按顺序：加 -ldflags='-s -w' 去掉符号与调试信息；确认 CGO_ENABLED=0 与静态链接；用多阶段构建只拷贝二进制到极小基础镜像。一般能把几百 MB 降到十几 MB。

标准库包用途常记的坑
syncMutex / WaitGroup / Once / Pool / MapWaitGroup 的 Add 要在 goroutine 外调用
context取消、超时、请求级数据必须 defer cancel()；别存进结构体
net/httpHTTP 服务端与客户端客户端要复用 Transport；响应 Body 必须 Close
encoding/jsonJSON 编解码字段要导出（大写）；用指针区分「零值」与「未传」
time时间与定时器格式化用 2006-01-02 15:04:05 这个固定时间
database/sql数据库抽象层连接池要设 MaxOpenConns/MaxIdleConns
errors / fmt错误包装用 %w 包装、errors.Is/As 判断
os / io文件与 IO用 io.Copy 而不是自己循环 Read/Write

数字与常见错误码速查

项典型值
goroutine 初始栈2 KB（按需增长，最大默认 1 GB）
GOMAXPROCS 默认等于 CPU 逻辑核数
GC 触发堆达到上次 GC 后存活大小的 2 倍（GOGC 默认 100）
GC 目标停顿通常 < 1 ms（STW 主要为两次很短的暂停）
channel 无缓冲同步；缓冲满则发送阻塞
map 删除delete(m, k)；Go 的 map 不会自动缩容
slice 扩容小于 1024 元素时翻倍，之后约 1.25 倍增长
interface 比较两个 nil 接口的 == 为 true；typed nil 装入接口后 != nil

错误对照

# 常见编译/运行时错误对照（看到就知道改哪）
#   "declared and not used"            未使用的变量/导入
#   "cannot use x (type T) as type U"   类型不匹配，常见于 int 与 int64
#   "assignment to entry in nil map"    map 没 make 就写
#   "index out of range"                slice 越界（注意 cap 与 len 的区别）
#   "nil pointer dereference"           指针没初始化
#   "all goroutines are asleep - deadlock!"  死锁（WaitGroup 少 Done 或 channel 没人收）
#   "concurrent map writes"             并发写 map，必须加锁或用 sync.Map
#   "context deadline exceeded"         超时，看是不是下游太慢或超时设太短
#   "too many open files"               fd 泄漏，检查有没有 Close
#   "sql: database is closed"           连接池被提前关了
GOGC 要不要调？

默认 100 适合大多数场景。想用内存换 CPU（减少 GC 次数）就调大（如 200），想用 CPU 换内存就调小，或者用 SetMemoryLimit（Go 1.19+）更直接。

怎么快速定位 goroutine 泄漏？

起 net/http/pprof，对比两个时间点的 goroutine profile。泄漏的特征是某个调用栈的 goroutine 数持续增长且不回落。
