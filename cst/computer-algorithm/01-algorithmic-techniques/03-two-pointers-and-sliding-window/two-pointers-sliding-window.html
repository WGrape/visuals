双指针与滑动窗口

把两层循环压成一层：两个下标协同移动，每个元素最多进出一次

一句话
用两个下标在数组/字符串上协同移动，把两层循环压成一层
适用信号
求连续区间、求满足条件的最长/最短子数组、原地分区
复杂度收益
O(n²) -> O(n)，因为每个指针最多走 n 步
两种形态
对撞指针（首尾相向）与快慢指针（同向）

一、三种指针形态

形态移动方式典型题目关键
对撞指针l 从左、r 从右，相向而行两数之和（有序）、反转、回文判断利用有序性或对称性排除一半
快慢指针fast 先走、slow 后走，同向链表判环、找中点、删除倒数第 k 个间距固定或速度成倍
滑动窗口r 扩张、l 在条件破坏时收缩最长无重复子串、和为 k 的最短子数组窗口内维护一个可增删的状态

二、滑动窗口的通用模板

func slidingWindow(s string) int { l, ans := 0, 0 state := map[byte]int{} // 窗口内状态：计数、和、最值…… for r := 0; r < len(s); r++ { state[s[r]]++ // 1) 右端进窗口 for !valid(state) { // 2) 条件被破坏就收缩 state[s[l]]-- if state[s[l]] == 0 { delete(state, s[l]) } l++ } ans = max(ans, r-l+1) // 3) 此时窗口合法，更新答案 } return ans } // 关键性质：l 和 r 都只增不减，每个元素最多进一次、出一次 // 所以总操作是 O(n)，而不是看起来那样的 O(n^2)

为什么嵌套循环还是 O(n)

看代码是两层循环，容易被误判成 O(n²)。判断方法是看指针的移动总量：外层 r 从 0 到 n 共 n 步；内层 l 虽然在内层，但全程只从 0 走到 n，总共也是 n 步。两者加起来是 2n，这就是摊还分析的经典例子。

三、什么时候窗口不能滑

情况原因替代方案
状态不可撤销收缩时无法 O(1) 移除左端元素（如求窗口最大值用简单变量）单调队列、线段树、前缀和
存在负数和不再随窗口单调，无法用收缩判断前缀和 + 哈希表
求恰好等于 k 的个数窗口是「至多」语义，需要转化转化为 atMost(k) - atMost(k-1)
需要覆盖所有元素不是求最优子区间而是全覆盖双端队列或贪心覆盖

五、深入自检

滑动窗口和双指针是同一个东西吗？滑动窗口是双指针的一个子集。双指针泛指「用两个下标协同遍历」，滑动窗口特指「两个下标围成一个区间、且区间需要满足某条件」。对撞指针和快慢指针都不维护区间，所以不算窗口。
窗口一定要用 while 收缩吗？如果每次只需要收缩一步（比如固定窗口大小），用 if 就行；如果需要收缩到重新满足条件，必须用 while。用 if 会漏掉需要连续收缩多步的情况。
有负数时为什么窗口法失效？窗口法的正确性依赖「右端扩张时状态单调变坏、左端收缩时状态单调变好」。有了负数，加一个元素可能让和变小，破坏单调性，收缩条件就不再成立。此时应该改用前缀和。
如何判断一道题该不该用窗口？三个信号同时满足：① 答案是一个连续区间；② 区间需要满足某个性质；③ 区间的扩张/收缩对性质的影响是单调的。缺任何一条都要换方法。
定长窗口和不定长窗口写法差别大吗？定长更简单：先加满 k 个，之后每次「加一个、减一个」保持长度不变，不需要 while 收缩。定长窗口常用于「长度为 k 的子数组的某某最值」。

记住一句

两层循环不等于 O(n²)

核心性质

每个元素最多进出各一次

失效信号

状态不可撤销 / 有负数

写窗口三步

扩张 -> 收缩 -> 记录

六、三道递进练习题

题目解法要点易错点
两数之和（有序数组）对撞指针：和大则 r--，和小则 l++数组必须先有序，否则不成立
长度最小的子数组窗口和 >= target 时先记录再收缩用 while 不是 if，可能要连续收缩
盛最多水的容器对撞指针，每次移动较矮的那一端移动高的那端不可能变好，必须用单调性论证

七、判断流程：拿到题怎么选

  1. 答案是不是一个连续区间？不是就别硬套窗口。
  2. 区间性质是否单调（加元素只会变好或只会变坏）？有负数要警惕。
  3. 状态能否 O(1) 增删？不能就考虑前缀和或单调队列。
  4. 确定是定长窗口还是不定长窗口，定长不需要 while 收缩。
  5. 写代码时先想清楚循环不变量：循环结束时窗口处于什么状态。

四类模板与复杂度

类型适用移动方式复杂度
相向双指针有序数组两数之和、反转、回文判定left++ / right-- 向中间靠O(n)
三数之和有序数组 + 固定一个 + 相向双指针外层 for + 内层相向O(n²)
快慢指针链表环（Floyd）、原地去重、删除倒数第 k 个fast 走 2 步 / slow 走 1 步O(n)
定长窗口窗口长度固定为 k整体右移一步，加新的减旧的O(n)
不定长窗口最长/最短满足某条件的子区间right 扩张，不满足则 left 收缩均摊 O(n)

为什么不定长窗口是 O(n) 而不是 O(n²)：left 和 right 各自最多向右移动 n 次，总移动次数 ≤ 2n。看着像两层循环，其实是均摊 O(1) 每步。

Python 模板

# 定长窗口模板（长度固定 k）
def fixed_window(a, k):
    if k > len(a):
        return None
    cur = sum(a[:k])
    best = cur
    for r in range(k, len(a)):
        cur += a[r] - a[r - k]      # 加进来的 - 滑出去的
        best = max(best, cur)
    return best

# 不定长窗口模板（求最长，满足 check 就扩张，不满足就收缩）
def longest_window(s):
    from collections import Counter
    cnt = Counter()
    left = 0
    best = 0
    for right, ch in enumerate(s):
        cnt[ch] += 1
        while cnt[ch] > 1:                 # 收缩条件：出现重复
            cnt[s[left]] -= 1
            left += 1
        best = max(best, right - left + 1)
    return best

# 求最短（LeetCode 76 最小覆盖子串的核心）
def min_window(s, t):
    from collections import Counter
    need, win = Counter(t), Counter()
    valid = 0                              # 记录「已满足的字符种类数」
    left = 0; best = float('inf'); start = 0
    for right, ch in enumerate(s):
        if ch in need:
            win[ch] += 1
            if win[ch] == need[ch]:
                valid += 1
        while valid == len(need):          # 全满足才收缩
            if right - left + 1 < best:
                best = right - left + 1; start = left
            d = s[left]
            if d in need:
                if win[d] == need[d]:
                    valid -= 1
                win[d] -= 1
            left += 1
    return "" if best == float('inf') else s[start:start + best]

经典题映射与边界坑

题目窗口 / 指针定义收缩条件坑
无重复字符的最长子串字符计数cnt[ch] > 1空串返回 0；注意是最长子串不是子序列
最小覆盖子串need + valid 计数valid == len(need)要记录最短时的起点，别只返回长度
长度最小的子数组（和 ≥ target）窗口和cur >= target有负数时单调性被破坏，滑窗失效
至多包含 k 个不同字符字符种类数len(cnt) > kk = 0 的边界
字母异位词（定长）长度固定 = len(p)定长滑动用数组而非 Counter 更快（26 个小写字母）
三数之和排序 + 固定 i + 相向双指针和 > 0 则 right--要去重：跳过相邻的相同 i 和相同 left
  • 返回值约定：无解时是最长返回 0、最短返回 0 还是 -1？先和题目对齐再写，这是最常见的 WA。
  • 边界：空数组、k > len(a)、k = 0、单元素，四个都要过一遍。
  • 负数：只要窗口和不再随 right 单调增，「和 ≥ target」类滑窗就失效，改用前缀和 + 二分。
  • 计数用数组：字符集固定（小写字母、ASCII）时用长度 26 / 128 的数组，比哈希表快一个量级。
什么时候滑窗失效？

当「窗口扩大 → 条件单调变化」不成立时。最典型是数组里有负数（和不再单调）；此时前缀和 + 二分是通用替代。

滑窗和前缀和怎么选？

只求最长/最短子数组长度且不关心具体位置 → 滑窗 O(n)；要数「有多少个子数组满足条件」→ 前缀和 + 单调栈/二分；数组有负数 → 前缀和 + 有序结构。

为什么我的滑窗比暴力还慢？

多半是收缩条件写成了内层 for 遍历整个窗口（例如每次重新 sum(window)），那就退化成 O(n·k)。要用增量维护窗口状态。
