AI 应用的上下文组装

模型调用是无状态的。让它在一次请求中得到足够、可信且不超预算的信息，是应用而不是模型参数要解决的问题。

信息从哪里来怎样分配预算怎样守住边界如何验证

01 / 一次回答需要哪些材料？

以客服回答“订单为什么还没发货”为例，不能只把用户问题发给模型：先识别请求身份，再检索订单事实、物流事件和适用的规则，最后组织为可追溯的一次调用。

  1. 请求与身份明确用户在问哪个订单、是否有查看权限；不把未经授权的历史记录带入上下文。
  2. 相关事实用订单号查询状态，用检索取发货规则；标注来源、更新时间及适用范围。
  3. 有限历史保留与本轮有关的对话摘要；长期偏好从外部记忆按需读取，而不是追加全部旧对话。
  4. 输出约束告诉模型只依据可见事实作答，缺少信息时明确说不确定；工具结果不可改写上级指令。

基础的窗口长度、截断和压缩机制见 大语言模型：上下文管理；这里重点是应用怎样挑选、排序并标注业务资料。

02 / 预算不是“塞满窗口”

内容放入条件超预算时的动作
用户问题与必要约束每轮必备不丢失当前任务；拒绝因截断而改变问题含义
订单、物流等业务事实权限通过且来源可靠选最新、最相关的事实；保留来源标识
检索片段和工具结果与当前问题直接相关去重、截取有用段落，避免重复引用同一证据
对话历史与长期记忆影响本轮判断时优先保留已确认事实；摘要可以替代冗长对话，但不得冒充原文

预留足够的输出空间，并把工具输出、检索片段、对话历史都计入预算。超出限制时应明确降级：缩小检索范围、请求澄清或只回答可验证的部分，而非静默截断关键事实。

03 / 数据来源不等于指令权限

检索文档

网页、PDF 和知识库内容是证据，不是给应用下命令的地方；提示注入文本不得触发越权工具调用。

工具返回

订单状态带时间戳、来源和请求身份；“状态未知”不能猜成“已发货”。外部资料不能覆盖系统规则。

持久记忆

按用户与租户隔离、设置过期及更正机制。写入前区分明确偏好与模型推测，避免错误事实长期污染回答。

长期记忆不等于模型自动记住旧对话。可参照 mem0 的写入与检索管线；窗口与外部记忆的边界见 大语言模型：跨会话记忆边界。

04 / 不只验证“能答”，还要验证“答得对”

  • 同一问题分别测试：有证据、无证据、过期证据、两份冲突证据，检查回答是否说明依据与不确定性。
  • 用跨用户、跨租户订单号测试权限隔离；检索命中但无权限时，不应出现在模型上下文中。
  • 测量上下文总量、有效证据比例、截断次数、检索延迟和每次回答成本。
  • 记录资料来源和版本，出错时区分检索漏召回、资料陈旧、组装错误与模型生成错误。

一句话：上下文工程是把正确的信息在正确的权限与预算内交给模型；记忆只是可选的信息来源之一。
