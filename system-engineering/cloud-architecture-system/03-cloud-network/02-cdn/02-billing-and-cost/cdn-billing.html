1主流计费模式

① 按流量计费

按实际下行流量（GB）× 阶梯单价。用多少付多少，单价随用量递减。最直观，适合流量平稳、可预估的业务。

② 按带宽峰值计费

按月 95 峰值带宽（Mbps）× 月单价。突发型业务友好——只看峰值不看均值，详见第 2 节。

③ 按请求数计费

按 HTTP 请求次数 计费（常叠加在流量费之上）。海量小请求（如 API、埋点）要注意此项。

④ 资源包 / 预付

先买流量包（如 1TB/年），包内免额、超出按量。用量大且稳定时单价更低，相当于批发。

⑤ 混合 / 保底

保底带宽 + 超量按流量，或「带宽包 + 流量包」组合。大客户谈判常用，平衡突发与成本。

⑥ 增值服务

HTTPS 请求、QUIC、WAF、专属节点等常单独计费，别只看「流量单价」就下结论。

计费维度区分：「流量(GB)」是总量，「带宽(Mbps)」是瞬时速率。1 Mbps 跑满 30 天 ≈ 0.32 TB 流量。两者通过时间换算，但计费口径不同。

295 计费法：为什么对突发友好

把一个月按 5 分钟采样，得到约 8640 个带宽点，从小到大排序，去掉最高的 5%（约 432 个点），取剩下的最高值作为「月 95 峰值」来计费。也就是——你每天偶发的那几次尖峰不算钱。

3加速流量 vs 回源流量（别算错账）

加速流量（下行）

CDN 边缘节点响应给用户的流量，是账单大头，按 CDN 单价计。

回源流量

边缘未命中、向源站拉取产生的流量，通常也计费（且源站出口带宽/对象存储读也可能单独收费）。提升命中率 = 同时省两笔钱。

易踩的坑：只盯着「CDN 加速流量费」，忽略了回源流量 + 源站出口费 + 对象存储读费，月底发现「CDN 不贵但源站账单爆了」。算总账要看「用户侧下行 = 加速 + 回源」全链路。

经验公式：平均带宽(Mbps) ≈ 月流量(GB)×8 ÷ (30×24×3600)。若平均带宽 ≪ 95 峰值（突发明显）→ 选带宽计费更省；若两者接近（平稳）→ 选流量计费或资源包更省。下一节计算器直接给你答案。

5成本优化：省流量的正确姿势

① 提升缓存命中率

命中率每升一点，加速+回源同时下降。长缓存不变资源、避免缓存键爆炸。

② 开启压缩

gzip/brotli 让文本体积降 60%~80%，直接少计流量。

③ 资源合并 / 去冗余

合并小文件、删无用资源、用雪碧图/字体子集，减少请求数与字节数。

④ 冷热分离

极热资源用 CDN，冷数据放对象存储直链或低频存储，避免为低频访问持续付费。

⑤ 资源包 + 监控

用量稳就买资源包摊薄单价；实时监控命中率与 TOP URL，异常及时止损。

⑥ 防盗链 / 限频

别人盗刷的流量最终算在你账上，防盗链即省钱（见安全篇）。
