作用域与命名空间

为什么函数里能读到外面的变量、却改不了？为什么循环里挂的闭包全是最后一个值？答案都在「命名空间 + LEGB 查找规则」里。这是 Python 运行时最容易被忽略、却天天在踩的底层机制。

命名空间

命名空间 = 名字到对象的映射表

每个函数调用、每个模块都有自己的命名空间（本质是个 dict）。不同命名空间互相隔离，所以不同函数里的局部变量 x 互不干扰。

def f():
    x = 1               # 局部命名空间
    print(locals())    # {'x': 1}

x = 99               # 全局命名空间
f()
print(globals()["x"])  # 99

「一切皆对象」的延伸：函数、模块、类各自带着命名空间。赋值（=）是在当前命名空间里创建/覆盖一个名字→对象的绑定（见名称绑定与对象语义）。

LEGB 规则

读变量时，按 L→E→G→B 顺序找

查找顺序：Local（当前函数）→ Enclosing（外层函数，闭包）→ Global（模块）→ Built-in（内置）。找到第一个就停。

a = "global"
def outer():
    a = "enclosing"
    def inner():
        # 这里没有 local a，向外找到 enclosing
        print(a)        # enclosing
    inner()
outer()
关键点：LEGB 是静态作用域——查找顺序在「定义时」就由代码结构定好了，和「在哪调用」无关。这与 JavaScript 的闭包一致，区别于动态作用域语言。
global / nonlocal

想改外层变量，得先「声明」

在局部里直接 x = 1 只是新建一个局部变量，不会动到外层的 x。要修改全局用 global，要修改闭包外层用 nonlocal。

count = 0
def inc():
    global count      # 声明：我要改的是全局 count
    count += 1

def outer():
    n = 0
    def inner():
        nonlocal n     # 声明：改的是外层函数的 n
        n += 1
    inner(); print(n)  # 1
⚠️ global 会让函数带上「隐藏副作用」，难测试、难并发。能传参返回就别用 global；真要共享状态优先用类属性或模块级单例。
闭包陷阱

循环里挂闭包，全部捕获到最后一个值

闭包捕获的是变量不是值。循环结束后变量停在终值，所有闭包读到的都是它——这就是经典的「延迟绑定」坑。

funcs = []
for i in range(3):
    funcs.append(lambda: i)   # 都引用同一个 i

print([f() for f in funcs])   # [2, 2, 2] —— 不是期望的 [0,1,2]

# 修复：用默认参数把「当前值」冻结
funcs = []
for i in range(3):
    funcs.append(lambda i=i: i)  # i=i 把值绑定到局部默认
print([f() for f in funcs])   # [0, 1, 2] ✅

这个坑和函数与装饰器里的闭包是同一个机制。记住一句口诀：闭包记住的是名字，不是那一刻的值。

查找顺序：四层作用域一层层往外找

读一个名字时，解释器按固定顺序查找：局部 → 外层 → 全局 → 内置，找到就用，四层都没有就报错。这条规则几乎解释了所有作用域相关的现象。

名字查找的四层顺序：由内向外，找到即停
层对应什么什么时候创建什么时候销毁
局部函数内部绑定的名字函数调用时函数返回时
外层外层函数中绑定的名字外层函数调用时没有被闭包引用才销毁
全局模块顶层定义的名字模块被导入时通常随解释器结束
内置语言自带的函数与类型解释器启动时解释器退出时

关键区别：读名字会自动向外找，但写名字默认只写在最内层。所以「读得到」和「改得动」是两件事，这就是为什么要引入声明。

想改外层变量：两种声明的分工

x = 0 def f(): x = 1 # 这只是创建了一个局部变量，并没有改全局的 x def g(): global x # 声明：接下来的 x 指的是全局那个 x = 1 def outer(): y = 0 def inner(): nonlocal y # 声明：指的是外层函数的 y y = 1 inner() return y # 1 # 两者的区别： # global 指向模块全局 # nonlocal 指向最近的外层函数作用域，不能指向全局 # 为什么需要声明？ # 因为「函数里赋值」默认就是新建局部变量， # 如果没有声明，解释器无法区分「新建局部」和「修改外层」， # 索性规定赋值即新建，需要改外层就显式声明。

什么时候会报「赋值前引用」

当函数里后面有赋值语句，解释器就把它判为局部变量，但你在赋值之前先读了它，于是报「局部变量在赋值前被引用」。这与全局变量同名也救不了你，因为判定发生在编译期。

为什么推荐少用全局声明

因为函数行为依赖外部状态后，就不再是独立的单元：调用顺序会影响结果，测试要重置状态，并发下还会出错。更好的做法是把状态作为参数传入、作为返回值传出。

两个最容易踩的特殊作用域

为什么类里定义的方法访问不到类的其他变量？

因为类体在定义时只是一个临时作用域，它不会成为方法的外层作用域。方法里要访问类属性，必须通过实例或类名。这与函数嵌套不同，是最容易混淆的地方之一。

推导式里的变量会泄漏到外面吗？

不会。推导式有自己独立的作用域，它内部的循环变量不会污染外部。这与普通的 for 循环不同，普通循环的变量会留在当前作用域里。

循环里创建闭包为什么都拿到最后一个值？

因为闭包捕获的是变量本身，而不是当时的值。循环结束后变量停在最后一个值，所有闭包看到的都是它。解法是把它作为默认参数绑定到函数上，或者再包一层工厂函数。

模块级变量和全局变量是一回事吗？

在单个模块里基本可以这么理解：模块的顶层就是全局作用域。但要注意每个模块都有自己独立的全局命名空间，所以严格说是「模块级」而不是整个程序共享一个全局。

为什么不建议在函数里修改传入的可变对象？

因为调用方看不到函数签名上说它会改，容易产生意外副作用。要么明确返回新对象，要么在文档里写清楚会原地修改。

内置名字被覆盖了怎么办？

如果你用内置函数名做了变量名，就会遮住它。在模块级这样做影响整个模块，在函数内只影响该函数。解决方法是改名，或者删除该绑定后恢复。

读自动向外找四层依次查找，找到即停
写默认写最内赋值即新建局部，除非声明
全局声明改模块级名字
外层声明改最近的外层函数名字
类体不成闭包方法里访问类属性要走实例或类名
推导式独立作用域循环变量不泄漏
闭包捕获变量不是捕获当时的值
少用全局状态函数越独立越好测

LEGB 规则与四个关键字

LEGB

x = "global"

def outer():
    x = "enclosing"
    def inner():
        x = "local"          # 只在这里创建局部变量，不影响 outer 的 x
        print(x)             # local
    inner()
    print(x)                 # enclosing

# 查找顺序 L -> E -> G -> B
#   Local      函数内部
#   Enclosing  外层函数（闭包）
#   Global     模块顶层
#   Builtin    len / print / sum ...
关键字作用不加会怎样
global声明在函数内使用/修改模块级变量赋值会被当成创建局部变量，读取时可能 UnboundLocalError

核心规则一句话：Python 在编译期就决定了每个名字的 scope。只要函数体内某处对 x 做了赋值，x 就在整个函数体内都是局部变量——所以「先 print 再赋值」也会报 UnboundLocalError。

三个必踩的坑

三个经典坑

# 坑 1：UnboundLocalError —— 赋值发生在后面也算
c = 1
def f():
    print(c)      # UnboundLocalError! 因为下面有 c = 2，c 已被判定为局部
    c = 2

# 坑 2：闭包的 late binding（循环里建函数最经典）
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])        # [2, 2, 2]  不是 [0, 1, 2]！

# 修法 A：默认参数在定义时就绑定
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])        # [0, 1, 2]

# 修法 B：闭包工厂
def make(n):
    return lambda: n
funcs = [make(i) for i in range(3)]

# 坑 3：类作用域不参与闭包
class A:
    x = 1
    vals = [x for _ in range(3)]    # NameError: name 'x' is not defined
    # 类体不是闭包作用域，推导式里访问不到类级名字
    # 对比：函数里的推导式可以访问闭包变量
  • 可变对象的「修改」不算赋值：lst.append(1) 不需要 global，但 lst = [...] 需要。这是很多人困惑的根源。
  • globals() / locals()：分别返回全局与局部命名空间字典；注意在函数体内修改 locals() 的返回值不影响真实局部变量（CPython 有优化）。
  • 模块级 __all__ 只影响 from m import *，不影响作用域解析。
  • 推导式有自己的作用域（Python 3）：列表推导式内的变量不会泄漏到外面，但生成器/集合/字典推导式同理。

记忆口诀：读不用声明，写才需要 global / nonlocal；闭包记住的是变量本身而不是当时的值，这就是 late binding 的本质。

自检

为什么改列表不用 global，改整数就要？

因为 lst.append() 是「调用方法修改对象」，没有绑定新名字；而 x = x + 1 是「把新对象绑定到名字 x」，属于赋值，会触发局部判定。

nonlocal 和 global 能同时用吗？

不能用于同一个名字。nonlocal 必须能在外层函数作用域里找到该名字，否则 SyntaxError。

循环里创建的闭包为什么都拿到最后一个值？

闭包捕获的是变量引用，循环结束时 i 已经是最后的值。用默认参数 lambda i=i: 或工厂函数在定义时把值固定下来。
