控制流：if / for / while / match / with / try

缩进即结构

Python 不用花括号，用缩进决定块的范围——这强迫代码整洁，但也意味着「少一个空格」就会改语义。循环只有 for / while 两种；分支用 if / match。

和 Go 对比：Go 用 switch 做多分支且默认不穿透；Python 3.10 之前靠一串 if/elif，之后用 match。Python 没有 do-while，也没有 C 风格的三段式 for(i=0;i<n;i++)——但推导式和内置函数往往让你根本不需要它。

if / elif / else

冒号 + 缩进，条件可省括号

分支用 elif（即 else-if），最多一个 else 收尾。条件两端括号可写可不写，但冒号必须有。

score = 85
if score >= 90:
    level = "A"
elif score >= 60:
    level = "B"
else:
    level = "C"

# 三元（真正的"一行 if"）
level = "A" if score >= 90 else "B"

# 链式比较：1 < x < 10 等价于 1 < x and x < 10
if 0 <= x < 10:
    print("范围内")
相比 Go 的 if v, err := do(); err != nil，Python 没有「带初始化的 if」，需要先赋值再判断；但三元表达式让简单分支很紧凑。
for：遍历可迭代对象

没有三段式，但比三段式强

for 直接遍历任何「可迭代对象」（list/str/dict/生成器/range…）。配合 enumerate 拿下标、zip 并行遍历、items 遍历字典。

fruits = ["a", "b", "c"]
for i, v in enumerate(fruits):
    print(i, v)              # 0 a / 1 b / 2 c

for a, b in zip(xs, ys):    # 并行遍历，短者为准
    print(a, b)

for k, v in d.items():     # 遍历字典
    print(k, v)

# for-else：循环"没被 break"才走 else
for n in nums:
    if n == 0:
        break
else:
    print("列表里没有 0")   # 常用于"找一遍没找到"
⚠️ for-else 的反直觉点：else 绑的是「循环正常结束」，一旦 break 就跳过。它常用来替代「设 flag 再判断」，但可读性有争议——团队里要么都用、要么都不用，保持一致。
while：条件循环

条件为真就转，也有 else

while 在条件为真时循环；同样支持 break/continue 和 while-else。Python 没有 do-while（至少执行一次）。

n = 5
while n > 0:
    print(n)
    n -= 1
else:
    print("自然结束（非 break 跳出）")

# 想要 do-while 效果：用 break 兜底
while True:
    do_work()
    if done():
        break
match-case：模式匹配（3.10+）

比 switch 强：能解构

match 像 switch，但 case 后面是「模式」——能匹配字面量、解构元组/列表、捕获变量、用 _ 兜底。替代一长串 if/elif 尤其清爽。

match point:
    case (0, 0):
        print("原点")
    case (x, 0):              # 解构并把第一个元素绑给 x
        print(f"在 x 轴上：{x}")
    case (0, y):
        print(f"在 y 轴上：{y}")
    case _:                     # 通配兜底
        print("其他")
旧版本（<3.10）没有 match，只能写 if/elif 链或用 dict 做分派表。生产代码若需兼容老版本，优先用字典映射。
with：上下文管理器

离开块自动回收资源

with 用于「进入要做准备、退出要清理」的资源（文件、锁、连接）。它靠对象的 __enter__/__exit__，等价于 try/finally 但更干净，且异常也能正确清理。

with open("a.txt", "r", encoding="utf-8") as f:
    data = f.read()          # 离开 with 自动 f.close()

# 同时管理多个资源
with open("in") as fin, open("out", "w") as fout:
    fout.write(fin.read())
⚠️ 别用裸 f = open(...) 不关——异常时文件句柄泄漏。用 with 或显式 finally: f.close()。自己写的类也可用 @contextmanager 装饰器快速变成上下文管理器。
try / except / else / finally

精确捕获，别裸 except

try 包裹可能出错的代码；except 按异常类型捕获；else 在无异常时执行；finally 无论怎样都执行（常用于清理）。

try:
    r = 1 / x
except ZeroDivisionError as e:   # 精确类型
    print("除零", e)
except (TypeError, ValueError):     # 多类型合并
    print("类型/值错误")
else:
    print("没有异常才走")
finally:
    print("一定执行（清理）")
⚠️ 禁止写裸 except:——它会连 KeyboardInterrupt、SystemExit 一起吞掉，导致 Ctrl-C 都停不下程序。至少写 except Exception，最好精确指定异常类型。
推导式：一行生成容器

替代 map / filter 的 Pythonic 写法

列表 / 字典 / 集合推导式，加上生成器表达式（惰性）。可带 if 过滤，也能嵌套。推导式有独立作用域（Python 3），循环变量不会泄漏到外层。

squares = [x*x for x in range(10) if x % 2 == 0]
d = {k: v for k, v in items if v > 0}
s = {x for x in nums}            # 集合去重
gen = (x*x for x in range(10))   # 生成器，惰性计算

# 等价写法：
squares = list(map(lambda x: x*x, filter(lambda x: x%2==0, range(10))))
推导式更可读，但别嵌套超过两层——三层以上的推导式可读性急剧下降，不如老老实实写 for 循环。生成器表达式用圆括号，适合处理大数据（边算边用，不全放内存）。

for/else 与 while/else：被低估的语法

规则：else 在循环正常结束（没有被 break）时执行。一句话记忆：“没 break 就走 else”。

写法用 else不用 else评价
查找后判断是否找到for x in a: if ok: break
else: print("没找到")		用标志变量 found = Falseelse 版本少 3 行
提前退出检测循环完没 break = 全部满足需要额外计数器语义更直接

for/else 用法

# 经典用法：查找（替代标志变量）
for item in items:
    if item.id == target:
        print("找到了")
        break
else:
    print("没找到")            # 只有循环完整跑完（没 break）才执行

# 等价的"标志变量"写法（多 3 行且容易漏）
found = False
for item in items:
    if item.id == target:
        print("找到了")
        found = True
        break
if not found:
    print("没找到")

# while/else 同理：常用于"重试直到成功，全失败则报错"
for attempt in range(3):
    if connect():
        break
else:
    raise ConnectionError("3 次都失败")

# 注意：continue 不影响 else（只有 break 会跳过）
for i in range(3):
    if i == 1: continue
else:
    print("仍会执行")          # continue 不算中断

try/except/else/finally：执行顺序与陷阱

块执行时机典型用途
try被保护的代码可能抛异常的操作
excepttry 里抛异常时异常处理
elsetry 没抛异常时成功后的后续逻辑（不该被 except 捕获的部分）
finally总是执行释放资源（文件、锁、连接）

异常处理陷阱

# 完整结构
try:
    f = open("data.txt")
    data = f.read()
except FileNotFoundError:
    print("文件不存在")
    return
except PermissionError as e:
    print(f"无权限: {e}")
else:
    # 只有 try 成功时才执行（放这里的好处：这里的异常不会被上面的 except 吃掉）
    process(data)
finally:
    f.close()                # 无论成功失败都执行

# ⚠️ 陷阱①：finally 里的 return 会"吞掉"异常！
def f():
    try:
        raise ValueError("原始错误")
    finally:
        return "ok"          # ❌ 异常被丢弃，返回 "ok"
print(f())                   # 输出 "ok"，ValueError 不见了！

# ⚠️ 陷阱②：except 顺序，子类必须在父类前面
try:
    ...
except Exception as e:      # ❌ 写在前面会拦截所有异常
    ...
except ValueError as e:     # 永远不会执行（Unreachable）
    ...

# ✅ 正确：从具体到宽泛
except ValueError: ...
except (TypeError, KeyError): ...
except Exception: ...

# ⚠️ 陷阱③：不要裸 except
except:                     # ❌ 会捕获 KeyboardInterrupt/SystemExit，Ctrl+C 都失效
except Exception:           # ✅ 但不捕获 SystemExit/KeyboardInterrupt
except BaseException:       # 极少数场景才用

finally 里放 return 是最隐蔽的 bug 之一：它会静默吞掉所有异常，导致问题被掩盖、排查时完全看不到原始堆栈。永远不要在 finally 里 return。

短路求值与三元表达式

技巧写法等价注意
短路取值x = a or ba 为真取 a，否则取 ba 为 0/''/[] 时会误判
安全取值x = a if a is not None else b显式判断 None推荐
短路调用cond and do()cond 假则不调 do()可读性差，慎用
三元x = a if cond else b—不要嵌套超过 1 层
海象 :=（3.8+）if (n := len(a)) > 10:先赋值再判断减少一次重复调用

短路与海象

# ⚠️ 经典陷阱：or 用在数值/字符串上
count = 0
display = count or "无"      # ❌ 0 是假值 -> display = "无"（不是 0！）
display = count if count is not None else "无"   # ✅ 正确

# 同理
name = ""
greet = name or "匿名"        # ❌ 空字符串被替换（可能不是你要的）

# 想保留 0 和 "" 就用显式判断
if x is not None: ...

# 海象运算符（3.8+）：减少重复计算
# ❌ 重复调用
data = load()
if len(data) > 100:
    print(f"共 {len(data)} 条")      # len 算了两次

# ✅ 海象
if (n := len(data)) > 100:
    print(f"共 {n} 条")

# 在 while 里特别好用
while (chunk := f.read(8192)):       # 读到空串自动结束
    process(chunk)

# 列表推导里也能用
results = [y for x in data if (y := transform(x)) is not None]

海象运算符的价值：把“计算一次、判断、再用结果”压缩成一行，避免了重复计算或先声明 None 变量的丑写法。但不要滥用——如果表达式很复杂，拆成两行更易读。

深入自检

for/else 是不是应该避免使用？

不是不能用，而是要团队达成共识。争议在于 else 这个词有误导性（很多人以为是 if/else 的 else）。推荐用法：只在明确的“查找 / 重试 / 验证”场景下用，且加一行注释说明语义（如 else: # 没 break = 没找到）。如果团队不熟悉，用早返回（early return）的等价写法更稳妥——把查找逻辑抽成函数，找到就 return，函数末尾写“没找到”分支，这样完全不需要 else。

异常应该捕获得宽还是窄？

原则：只捕获你能处理的异常。捕获太宽（except Exception）会掩盖真正的 bug——比如把 AttributeError（代码写错了）当成业务异常吞掉，排查时完全看不到线索。推荐做法：① 优先捕获具体类型（ValueError、KeyError）；② 顶层可以有一个兜底的 except Exception，但必须记录完整堆栈再处理；③ 用 logger.exception() 而非 logger.error()（前者自动带 traceback）。

为什么 Python 推荐 EAFP 而不是 LBYL？

EAFP（Easier to Ask Forgiveness than Permission，先做再说）= try/except；LBYL（Look Before You Leap，先检查）= if 判断。Python 推崇 EAFP，原因：① 避免竞态——检查和使用之间状态可能变（典型：os.path.exists() 后再 open 仍可能失败）；② 代码更简洁——一次 try 覆盖多种失败；③ 性能——Python 中异常在不触发时几乎零成本，而每次都做前置检查有固定开销。典型对照：d[k] + except（快） vs if k in d: d[k]（查两次）。

怎么写出易读的复杂条件判断？

四个手段：① 提取布尔函数——把长条件抽成 def is_eligible(u): return ...；② 用 all()/any() 替代多条件 and/or 链；③ 早返回（guard clause）——把不满足的情况先 return，避免深层嵌套（这是最有效的）；④ 字典分发——把 if/elif 链换成 {case: handler} 字典查表，在分支多于 3 个时尤其清晰。目标：让每个函数的嵌套层级 ≤ 2。
