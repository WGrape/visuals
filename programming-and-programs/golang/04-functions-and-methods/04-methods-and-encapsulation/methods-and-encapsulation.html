方法声明

值接收者与指针接收者

接收者是值：操作副本；是指针：操作原值且可修改。两者可共存于同一类型。

type Counter struct{ n int }

func (c Counter) Get() int { return c.n }      // 值接收者
func (c *Counter) Inc() { c.n++ }             // 指针接收者，可改

var c Counter
c.Inc(); c.Inc()
fmt.Println(c.Get())  // 2
选值还是选指针

一致性优先，再谈语义

经验：需要修改接收者、或结构体较大避免拷贝时用指针；否则用值。同一类型的多个方法接收者风格必须统一。

方法会修改接收者只读且不关心副本

嵌入扩展类型

复用字段与方法（组合）

把已有类型匿名嵌入，外层可直接调用其方法，实现「has-a 复用」而非继承。结合接口可形成多态。

type Logger struct{}
func (l Logger) Log(s string) { fmt.Println(s) }

type Server struct {
    Logger   // 嵌入
    Addr string
}

s := Server{Addr: ":8080"}
s.Log("started")   // 调用提升的方法
方法值与表达式

方法也可当值传递

「方法值」绑定了具体接收者；「方法表达式」把方法变成普通函数，第一个参数变成接收者，常用于泛型式调用。

c := Counter{}
f := c.Inc        // 方法值（已绑定 c）
f()

// 方法表达式：func(*Counter)
g := (*Counter).Inc
var c2 Counter
g(&c2)
封装

小写即私有

通过只暴露大写的方法、隐藏小写字段，控制外部如何读写内部状态——这就是 Go 的「封装」。

示例

类型提供 GetX()/SetX() 方法校验输入，内部字段 x 小写，外部无法直接篡改，保证不变量成立。

方法与接收者

type User struct { name string age int } // 值接收者：得到副本，改不了原对象 func (u User) Name() string { return u.name } // 指针接收者：能修改原对象 func (u *User) SetAge(a int) { u.age = a } // 调用时 Go 会自动取址或解引用 u := User{} u.SetAge(18) // 等价于 (&u).SetAge(18) p := &User{} p.Name() // 等价于 (*p).Name() // 但接口满足性不同！ type Namer interface{ Name() string } var _ Namer = User{} // ✅ 值类型满足 var _ Namer = &User{} // ✅ 指针类型也满足（指针方法集包含值方法）

最实用的规则：同一个类型上不要混用值接收者与指针接收者。混用会让方法集难以判断，也是很多「为什么它不满足接口」问题的根源。

方法集规则：最容易混淆的一条

方法集决定「哪个类型满足哪个接口」。规则只有两条，但组合起来容易绕。

类型 T 的方法T 的方法集*T 的方法集
值接收者方法包含包含
指针接收者方法不包含包含
type T struct{} func (t T) ValMethod() {} func (t *T) PtrMethod() {} // T 的方法集：{ValMethod} // *T 的方法集：{ValMethod, PtrMethod} type I interface { ValMethod() PtrMethod() } var _ I = &T{} // ✅ *T 满足 // var _ I = T{} // ❌ 编译错误：T 没有 PtrMethod // 可寻址性：只有能取地址的值才能调用指针方法 T{}.ValMethod() // ✅ // T{}.PtrMethod() // ❌ 不可寻址 t := T{} t.PtrMethod() // ✅ 变量可寻址，自动取址

记忆口诀：*T 的方法集更大（包含 T 的全部方法）；T 只包含值接收者方法。

封装：靠大小写而不是 private

包级可见性

Go 只有两级：大写导出、小写包内可见。没有 protected，没有 friend。

  • 小写字段在包外不可访问
  • 同包内互相可见，靠约定约束
  • 用 getter/setter 控制访问与校验
  • internal 目录提供跨包的可见性边界
type User struct { id int64 // 包外不可见 Name string // 导出 } func (u *User) ID() int64 { return u.id } // 只读访问 func (u *User) SetAge(a int) error { // 带校验的写入 if a < 0 || a > 150 { return ErrBadAge } u.age = a return nil }

用接口隐藏实现

返回接口而非具体类型，是实现细节隔离的关键。

type Store interface { Get(id int64) (*User, error) Save(u *User) error } func NewStore(dsn string) Store { // 返回接口 return &mysqlStore{dsn: dsn} // 具体类型不导出 } // 调用方只依赖接口，替换实现不影响业务代码 // 测试时可传入内存实现

这是 Go 里最常见的封装手段，比访问控制更实用。

封装的边界

  • 不要为了封装而封装：小结构体的公开字段没问题
  • 暴露会破坏不变式的字段才是要藏的
  • 零值可用性比强制构造函数更重要
  • 包是内聚的单位，别把一个包拆得太碎

深入自检

什么时候必须用指针接收者？

三种情况：方法需要修改接收者；结构体较大，拷贝代价明显；类型含有不可拷贝的字段（如 sync.Mutex，拷贝它会复制锁状态导致错误）。除此之外，值接收者更简单也更安全。

为什么 T 不满足含指针方法的接口？

因为 T 的方法集只包含值接收者方法。接口要求的方法若是指针接收者声明的，只有 *T 才有。这是编译期检查，编译器会明确指出缺少哪个方法。

调用指针方法时为什么有时能、有时不能？

取决于值是否可寻址。变量、切片元素、结构体字段可寻址，Go 会自动取址；而字面量、map 元素、函数返回值不可寻址，直接调用指针方法会编译失败。

Go 没有 protected，怎么约束同包代码？

靠约定与目录划分。把需要隔离的实现放到 internal 目录，外部包根本无法导入；同一包内则依赖代码评审与清晰的分层。这是 Go 的取舍：用更简单的可见性规则换取更少的语言复杂度。

每个字段都写 getter/setter 好吗？

不必。只有当访问需要校验、转换或维持不变式时才值得。为每个字段机械地生成 getter/setter 会增加大量样板，反而掩盖真正需要控制的地方。
