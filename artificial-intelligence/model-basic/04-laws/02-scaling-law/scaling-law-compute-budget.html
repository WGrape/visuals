01三个公式先摆出来

C ≈ 6 N D          # 训练计算量：每个 token 每个参数约 6 FLOPs
L ∝ N^(-a),  a≈0.076   # Kaplan：损失随参数幂律下降
L ∝ D^(-b),  b≈0.095   # Kaplan：随数据幂律下降
# Chinchilla：在固定 C 下，最优 N 与 D 满足  D ≈ 20 N

也就是说，Chinchilla 告诉我们：大多数早期模型「喂的数据不够」，应该把算力和数据都加大而不是只堆参数。

03训练 FLOPs 估算

def train_flops(N, D):
    return 6 * N * D     # 正向+反向约 6 ND

# 7B 模型，训 1T tokens
N, D = 7e9, 1e12
print(train_flops(N, D))   # ≈ 4.2e22 FLOPs
# 用 H100 约 1e15 FLOPs/s、利用率 40%：
# 需要时间 ≈ 4.2e22 / (1e15*0.4) / 3600 ≈ 2.9e4 小时
要点：实际训练往往比 6ND 略高（激活重算、通信），量级估算用 6ND 够用。

04触顶与何时停

  • 数据耗尽：高质量语料是有限的，继续加 N 而 D 不涨，收益锐减。
  • 收益递减：到一定规模后，同样算力换来的能力提升越来越小。
  • 转向数据质量 / 架构：指令数据、合成数据、MoE/长上下文等往往比纯堆参数更划算。
问：为什么现在流行「小模型 + 多数据」而不是一味堆参数？

Chinchilla 定律说明参数和数据要等比例涨；当数据受限时，把算力更多给数据、控制参数规模，单位算力收益更高。这也是很多 7B~13B 模型表现接近大模型的来源。

第一层 · 概念与判定：Scaling Law 到底在说什么

Scaling Law 指模型性能（loss）随参数量 N、数据量 D、算力 C 增长呈幂律下降，不是线性。用它来回答两个问题：给定预算该买多少算力、训多大模型、喂多少数据。

你想决策用哪条规律
今年算力固定，训多大模型C 决定 N 与 D（Chinchilla）
数据已定，堆参数有用吗D 固定看 N 的边际
要不要继续加数据看是否已到 data 饱和点
小模型能否追平看是否还在幂律区

# Chinchilla 最优：算力 C 给定时
# N_opt ≈ 0.5 * (C/6)**0.5 ;  D_opt ≈ 0.5 * (C/6)**0.5
# 即参数和 token 大致同量级缩放（都是 C^0.5）

数量级：典型大模型训练在 1e23–1e25 FLOPs；幂律意味着「翻倍数据/参数」只带来可预测、但递减的 loss 下降，边际收益递减是铁律。

第三层 · 排障与边界：四个误用

  • 数据不够硬堆参数：Chinchilla 证明早期大模型严重训练不足——参数涨了但 data 没跟上，掉进欠拟合区间白烧算力
  • 忽略数据质量/去重：重复 token 会让有效 D 远小于名义 D，幂律估算失真
  • 拿幂律外推到极域：幂律在「同分布、未饱和」成立；到数据/容量饱和点或分布突变就失效
  • 漏算通信开销：多卡并行的实际墙钟时间远 > C/单卡峰值，利用率（MFU）常只有 30%–50%

第四层 · 原理与取舍

Chinchilla 为什么推翻了 Kaplan 的结论？

Kaplan 2020 建议「参数越多越好、数据相对少」；Chinchilla 2022 用同等算力做对照实验发现：之前模型普遍训练严重不足，在固定算力下，把预算更多分给数据（data:param ≈ 20:1）比堆参数 loss 更低。本质是 Kaplan 那代没训到幂律的「数据饱和点」，Chinchilla 把这个点找了出来。

为什么训练算力能粗略用 C ≈ 6ND 估算？

前向每 token 约 2N 次 FLOPs（N 个参数各乘加一次），反向约 2× 前向 = 4N，合计约 6N 每 token；再乘 D 个训练 token 得 C ≈ 6ND。这是理论算术量，不含通信、激活重算、并行效率损失——实际墙钟要再除以 MFU（常 0.3–0.5）。

Scaling Law 的边界在哪，为什么不能无限外推？

幂律只在同分布、未饱和、容量与数据匹配区间成立。一旦数据耗尽（重复/低质）、或模型容量触达当前架构的表达上限、或任务本身有不可约误差（irreducible loss），曲线会偏离幂律甚至平台。所以用它做「同量级规划」可靠，拿去赌「10 倍参数必超人」就过头了。
