时序逻辑：触发器、时钟与那条决定频率的不等式

组合逻辑只会算，不会记。CPU 之所以能保存 PC、累加中间结果，是因为有了带状态的时序电路。而「一个周期能跑多快」，完全由两个寄存器之间的最坏路径决定。

一句话定位：靠时钟把「算」切成一段段

组合逻辑的输出只取决于当前输入；时序逻辑的输出还取决于历史状态。最基本的记忆单元是 D 触发器：在时钟上升沿把 D 采进 Q，其余时间保持不变。整块芯片就变成「寄存器 → 组合逻辑 → 寄存器」的重复结构，每一段就是一级流水。

锁存器 Latch电平敏感：使能期间输入直通，关闭时保持
触发器 Flip-Flop边沿敏感：只在时钟沿采样，抗毛刺
建立时间 t_setup数据必须在时钟沿之前稳定这么久
保持时间 t_hold时钟沿之后数据还要稳定这么久
clk ≥ t_cq + t_comb(max) + t_setup + t_skew 这条不等式决定了这颗芯片的最高频率，也是流水线为什么要切分的原因
时序方程：T 是周期，四条路径延迟之和决定最高频率

把不等式算一遍

Tclk ≥ tcq + tcomb + tsetup + tskew
参数含义5nm 典型值变大意味着什么
t_cq时钟沿到 Q 输出有效30~50 ps触发器本身慢，工艺问题
t_comb中间组合逻辑最长路径由逻辑深度决定逻辑层级多 → 频率低
t_setup采样窗口前置时间20~40 ps工艺与电压相关
t_skew两个寄存器的时钟到达差周期的 5%~10%时钟树不平衡，白扣频率

算例：30 + 250 + 25 + 45 = 350 ps → 最高频率 2.86 GHz。若把这段逻辑拆成两级流水（各 130 ps），周期降到约 230 ps，频率升到 4.3 GHz——代价是多一级寄存器、多一个周期的延迟，以及流水线冒险。

保持时间违例不能靠降频修

建立时间违例（路径太长）可以降频解决；保持时间违例（路径太短）降频只会更糟，必须加缓冲延迟或调整时钟树。这也是为什么「同一版 RTL 换个工艺就崩」常见于 hold 违例。

结构实现要点典型用途坑
D 触发器 + 使能enable 时采样，否则保持寄存器堆、流水线寄存器使能信号本身要先满足 setup

// 带同步复位的 D 触发器
always @(posedge clk) begin
  if (rst) q <= 1'b0;
  else     q <= d;
end

// 一个流水级：寄存器 + 组合逻辑 + 寄存器
always @(posedge clk) stage2 <= alu_out(stage1);

毛刺为什么会被「采」进去

组合逻辑的每条路径延迟不同，输入同时变化时输出会出现短暂的错误值（毛刺）。如果这个毛刺恰好落在下一级触发器的 setup/hold 窗口里，就会被采样，表现为偶发的、极难复现的错误。三条防线：

  1. 用边沿触发的触发器而不是电平敏感的锁存器；
  2. 让毛刺在时钟沿之前就稳定下来（缩短组合路径、加流水级）；
  3. 跨时钟域时用同步器，而不是指望「应该来得及」。

原理与取舍：为什么不用锁存器省面积

锁存器比触发器小（约 4~6 个晶体管 vs 20+），但电平敏感意味着「使能期间输入直通」，时序分析要同时检查电平窗口两端，工具很难做；而且毛刺会直接穿过。工业界用触发器换来「只在边沿动作」的简单模型，这是用面积换可验证性。

为什么流水线能提频率却不能提总延迟？

切分把长路径拆成短路径，频率上去了，但每级多一个寄存器延迟（t_cq + t_setup），指令的总延迟反而略微增加。吞吐提升、单条延迟变差，这是流水线的本质权衡。

同步复位和异步复位怎么选？

同步复位不占额外时序、抗毛刺，但需要时钟在跑；异步复位能「无时钟也能复位」，但释放必须同步，否则第一拍可能亚稳态。工业做法：异步复位、同步释放。

触发器为什么能存住值？

正反馈：两个反相器首尾相连形成双稳态，只要供电就在两个稳定点之一。这也是亚稳态的根源——它卡在两个稳定点之间。

代码怎么写：三种时序积木的 RTL 模板

同一件逻辑，写法不同，综合出来的时序与复位行为差别很大。下面三个模板覆盖了 90% 的场景。

VHDL 模板（Verilog 同理）

-- 1) 最常用：同步复位 D 触发器（复位只在时钟沿生效，天然满足 recovery/removal）
process(clk) begin
    if rising_edge(clk) then
        if rst = '1' then  q <= '0';
        else               q <= d;
        end if;
    end if;
end process;

-- 2) 异步复位、同步释放（复位可以立刻生效，撤离必须对齐时钟沿）
process(clk, rst_n) begin
    if rst_n = '0' then
        rst_meta <= '0'; rst_sync <= '0';
    elsif rising_edge(clk) then
        rst_meta <= '1';            -- 第一级：仍可能与时钟沿冲突
        rst_sync <= rst_meta;       -- 第二级：已经稳定
    end if;
end process;

-- 3) 带使能的触发器：用 en 门控，不要用「时钟门控 + 组合逻辑」自己造
process(clk) begin
    if rising_edge(clk) then
        if en = '1' then q <= d; end if;   -- 综合器会映射成带 CE 的 FF 或 ICG
    end if;
end process;
写法综合结果时序影响什么时候用
同步复位复位信号进 D 端逻辑占用数据路径裕量，但无 recovery/removal 问题现代 FPGA（FF 资源丰富）首选
异步复位同步释放复位进 FF 的异步端撤离沿必须满足 recovery 时间要求上电立刻进入确定态
带 CE 的 FF映射到 FF 的使能脚或 ICG几乎无额外延迟需要保持旧值的所有场景
门控时钟（自己写与门）时钟上出现组合逻辑产生毛刺与 skew，STA 难以收敛不要用，改用 ICG 单元
锁存器（电平敏感）Latch电平期间透明，无法做单边沿 STA仅在特定低功耗/锁存阵列中

Verilog 里最容易踩的一条：always @(posedge clk) 块内对某信号只在部分分支赋值，综合器会插出锁存器（或保留旧值形成 FF 使能），这往往不是你想要的。给每个分支都赋值。

时序约束与排障清单

约束是「告诉工具这个设计该跑多快」。没有约束，工具按默认 0 要求跑，报出来的「无违例」毫无意义。

SDC 最小可用约束集

# 主时钟：周期 10ns（100MHz），占空比 50%
create_clock -period 10.000 -name clk -waveform {0 5} [get_ports clk]

# 派生时钟：让工具自己算，不要手工 create_clock（否则 skew 算错）
create_generated_clock -name clk_div2 -source [get_pins clk] -divide_by 2 \
    [get_pins div_reg/Q]

# 输入/输出延迟：告诉工具外部芯片的时序预算（按 datasheet 填）
set_input_delay  -clock clk -max 3.0 [get_ports data_in*]
set_input_delay  -clock clk -min 1.0 [get_ports data_in*]
set_output_delay -clock clk -max 4.0 [get_ports data_out*]

# 时钟不确定性：抖动 + 时钟树 skew 的预算
set_clock_uncertainty -setup 0.3 [get_clocks clk]
set_clock_uncertainty -hold  0.1 [get_clocks clk]

出现下面六个症状时，按对应方向查：

  • 上电后状态随机：复位没有覆盖所有 FF，或复位脉冲宽度小于 FF 要求的最小脉宽（通常 ≥ 1 个时钟周期）。
  • 仿真过、上板挂：典型是毛刺被采进去或 X 传播；检查复位撤离沿是否对齐时钟。
  • 只在高温/低压失败：建立时间裕量不足，慢工艺角下暴露；看 WNS 是否小于 5% 周期。
  • 只在低温/高压失败：保持时间违例，降频无效，必须插缓冲或调布局。
  • 同一批板子部分失败：亚稳态或时钟抖动边界，提高同步级数或放宽 set_clock_uncertainty 后再收敛。
  • 逻辑偶尔丢一个脉冲：快时钟域的脉冲宽度 < 慢时钟周期，需要脉冲展宽或握手，两级同步也救不了。
  • 综合出意外锁存器：条件分支赋值不全，或 case 缺少 default。
  • 跨时钟数据偶发错位：多位总线逐位同步，位间 skew 导致采到中间态。
