锁与同步原语：线程安全的正确姿势

「GIL 不是线程安全的万能锁」——这是最大的误区。GIL 只保证字节码级不崩溃，不保证你的「读-改-写」不被另一个线程打断。共享可变状态要自己加锁，否则 count += 1 都会丢更新。

竞态条件

GIL 不保护你的「读改写」

count += 1 在字节码层面是「取→加→存」三步。两个线程可能都取到旧值、各自存回，结果只 +1 而不是 +2。GIL 让单条字节码原子，但保不住多步操作。

import threading
counter = 0
def inc():
    global counter
    for _ in range(100000):
        counter += 1          # 非原子：会丢更新

ts = [threading.Thread(target=inc) for _ in range(2)]
[t.start() for t in ts]; [t.join() for t in ts]
print(counter)            # 经常 < 200000
⚠️ 最大误区：以为「有 GIL 就线程安全」。GIL 防的是解释器崩溃，不是业务逻辑竞态。任何「检查再修改」「读改写」共享状态，都要同步。
Lock / RLock

用 with 锁住临界区

Lock 是互斥锁，同一时刻只放一个线程进临界区；用 with lock: 自动加锁/释放，最安全。RLock 可重入，同一线程能多次acquire而不死锁（递归函数常用）。

counter = 0
lock = threading.Lock()
def inc():
    global counter
    for _ in range(100000):
        with lock:        # 进入临界区才允许改
            counter += 1

# RLock：同线程可重入，适合调用链里多次加锁
rlock = threading.RLock()
def a():
    with rlock: b()   # b() 再次 acquire 不会死锁
def b():
    with rlock: pass
临界区越小越好——只在「确实改共享状态」的那几行加锁，别把整个函数包住，否则多线程退化成串行，白用线程。
其它原语

不止 Lock：按语义选工具

信号量限制并发数、Event 做线程间信号、Condition 做「等条件满足」，各有适用场景。

原语语义典型用途
Lock/RLock互斥保护临界区
Semaphore最多 N 个同时进限流、连接池大小
Event一次性信号广播主线程通知工作线程启动/停止
Condition等某个条件成立生产者-消费者就绪通知
sem = threading.Semaphore(3)   # 同时最多 3 个线程进入
def work():
    with sem:
        do_io()

这些原语都来自标准库 threading。它们解决「共享内存」的同步；如果你用多进程（各自内存独立），要换成 multiprocessing 里的同名原语或通过 Queue/共享内存通信。

Queue 首选

多数场景：用 Queue 代替手搓锁

queue.Queue 是线程安全的「生产者-消费者」管道，内部已加锁。把「共享状态」变成「通过队列传递数据」，能大幅减少自己加锁出错的概率。

import queue, threading
q = queue.Queue(maxsize=10)

def producer():
    for i in range(20): q.put(i)   # 满则阻塞

def consumer():
    while True:
        item = q.get()              # 空则阻塞，自带锁
        process(item)
        q.task_done()

for _ in range(3): threading.Thread(target=consumer, daemon=True).start()
经验法则：能用 Queue / 不可变数据 / 每线程独享状态解决的问题，就别用 Lock。锁越多，死锁和性能坑越多。
死锁

两个锁互相等待，谁都不放

线程 A 持锁1等锁2、线程 B 持锁2等锁1，永久卡住。避免法：固定加锁顺序、用 with 保证释放、必要时 acquire(timeout=) 设超时。

l1, l2 = threading.Lock(), threading.Lock()

# 危险：两个线程以相反顺序加锁 → 死锁
def t1():
    with l1:
        with l2: work()

# 安全：所有路径统一先 l1 后 l2
def safe():
    with l1:
        with l2: work()

# 或加超时，避免无限等
if l2.acquire(timeout=1):
    try: work()
    finally: l2.release()

选型与同步是并发的两根支柱：先读线程/进程/协程选型定模型，再用本篇的锁/队列保证线程安全。协程（asyncio）则基本不用这些锁，靠「单线程不抢占」天然避开竞态（见异步模式）。
