输出头与 Softmax：4096 维隐状态怎么变成 12 万个候选词

每个 token 生成前，模型要做一次「4096 → 128256」的巨型投影，再 softmax 成概率。这一步的参数量在 8B 模型里占 7%，计算量却比一层 FFN 还贵三倍——它是被严重低估的性能与量化热点。

一句话定位：把隐状态当查询，去词表里找最像的

输出头就是一个没有 bias 的线性层：logits = h · Eᵀ。它把当前的隐状态和词表里每个 token 的嵌入向量做点积，点积越大说明越相似，这个相似度就是该 token 的分数。

形状E: V×d（V=词表大小），logits: V
是否共享权重GPT-2 / LLaMA / Gemma 共享（tied）；Qwen2.5 等大模型不共享
参数量V×d，8B 模型里 128256×4096 = 525M（约 7%）
为什么能共享输入「查表」和输出「打分」本质是同一个语义空间的两次使用
输出头一步：隐状态 → logits → 概率分布（采样策略见另一篇）

数值：softmax 必须减 max

softmax(z)_i = exp(z_i - max(z)) / Σ_j exp(z_j - max(z))

不减 max 直接 exp，bf16 下 logits 一旦超过 88 就溢出成 inf，减完则最大项恒为 exp(0)=1，数值永远安全。这是所有框架的实现方式，但自己写推理内核时最容易忘。

词表膨胀的隐性税

词表从 32K 涨到 128K，输出头参数涨 4 倍、单 token 计算涨 4 倍。对小模型来说这可能是 30% 的参数，直接决定它能不能塞进端侧内存。

计算量为什么比 FFN 还贵

一层 FFN（LLaMA-3 8B）单 token 是 352 MFLOPs，输出头是 2 × 4096 × 128256 ≈ 1.05 GFLOPs，是三倍。但因为只有最后一个位置需要算，摊到整段序列上占比就小了：4K 上下文下，输出头只占 1/4096 的位置。

量化与并行：两个必须知道的工程事实

  1. 输出头通常不跟着 4bit 量化。它直接决定 logits，量化噪声会放大成「选错词」。llama.cpp 的做法是 output.weight 单独用 Q6_K，embedding 用 Q4/Q5。
  2. 输出头按词表切分做张量并行。V 维切开后每卡只算自己那段 logits，再 all-gather 拼起来；如果只做贪心解码，可以只 all-reduce 出 argmax，省掉整段传输。
  3. tied 权重时要注意缩放。共享 embedding 与 lm_head 会让 logits 幅度偏大，Gemma 系的做法是先乘 √d 再算 logits，训练更稳。

原理与取舍：为什么「共享」是常态

embedding 学的是「token → 语义向量」，输出头学的是「语义向量 → token 分数」，两者是同一张表的正反用。共享等于给每个 token 的向量加了「输入输出一致」的约束，在参数紧张时几乎总是正收益；当模型足够大、词表足够大时，解耦能带来一点表达自由度，代价是多一份 500M 参数。

logits 和概率有什么区别？

logits 是未归一化的实数分数（可正可负、无上界），概率是 softmax 后和为 1 的分布。温度、top-k、top-p 都是作用在 logits 或其后分布上的操作，见「解码策略」一篇。

为什么 softmax 要转 fp32？

exp 会放大误差：bf16 只有 8 位有效位，exp 后相近的分数差距会被抹掉，导致采样结果偏离 fp32 参考实现。推理框架通常只在这一步上转 fp32，成本可以忽略。

训练时的 label smoothing 和 z-loss 是干什么的？

label smoothing（0.1）防止模型过度自信；z-loss 惩罚 log-sum-exp 的平方，抑制 logits 整体漂移，PaLM 用 1e-4，对大模型训练稳定性帮助明显。
