概述

数组是值，切片是视图

数组长度写在类型里、是值类型；切片是对底层数组的一段「视图」，是 Go 里最常用的序列结构。

数组：定长值类型

长度属于类型的一部分

[3]int 和 [4]int 是不同类型，不能互赋；数组赋值是整份拷贝；可比较（元素可比时）。

var a [3]int = [3]int{1, 2, 3}
b := a          // 整份拷贝，b 与 a 独立
b[0] = 9
fmt.Println(a[0]) // 1（a 不受影响）

// 作为参数会整体拷贝，通常改用切片
func sum(s [3]int) int { ... }
切片：三元组

ptr 指向底层数组，len 可见长度，cap 到数组末尾

切片本身很小（约 24 字节），操作高效。len 是你能访问的元素数，cap 是从起始位置到底层数组末尾的总数。

s := []int{1, 2, 3}      // 字面量，自动建底层数组
fmt.Println(len(s), cap(s)) // 3 3

s2 := make([]int, 2, 8)    // len2 cap8

s3 := s[1:3]              // 切片表达式，共享底层数组
fmt.Println(len(s3), cap(s3)) // 2  (cap: 从索引1到末尾=2)
扩容 append

超容量会分配新数组

append 在 cap 足够时复用底层数组；不够时分配更大的新数组并拷贝，返回指向新数组的切片。这正是「为什么有时改得到、有时改不到」的根源。

s := make([]int, 0, 2)
s = append(s, 1, 2)
p := &s[0]
s = append(s, 3)   // 超出 cap，换底层数组
// 此时 *p 仍是旧数组的元素，与 s[0] 不再同一份
扩容策略大致为：小切片翻倍，大切片按约 1.25 倍增长（具体随版本调整）。预知规模时用 make 指定 cap 能显著减少拷贝。
共享底层数组的陷阱

切片表达式会共享，修改互相影响

用 s[i:j] 得到的子切片和原切片共享底层数组，一处修改另一处可见——这既是性能优势，也是 bug 温床。

a := []int{1, 2, 3, 4}
b := a[1:3]   // b = [2,3]，共享底层
b[0] = 99
fmt.Println(a) // [1 99 3 4]  原数组被改！

// 想要独立副本
c := make([]int, len(b))
copy(c, b)
