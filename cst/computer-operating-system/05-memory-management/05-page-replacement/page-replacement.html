💾 内存页面淘汰算法详解

📚 什么是页面淘汰算法？

在操作系统内存管理中，当内存已满但需要加载新的页面时，需要选择某个页面将其换出到外存，这个选择策略就是页面淘汰算法（Page Replacement Algorithm）。

目标：减少页面缺页率，提高系统性能。

🎯 主要页面淘汰算法

1. OPT（最佳置换算法）

原理：选择未来最长时间内不再被访问的页面淘汰。

特点：理论上的最优算法，但无法实现（需要预知未来）。

作用：作为其他算法的性能基准。

2. FIFO（先进先出算法）

原理：选择最早进入内存的页面淘汰。

实现：使用队列管理页面。

缺点：可能淘汰频繁使用的页面（Belady异常）。

3. LRU（最近最少使用算法）⭐

原理：选择最近最久未使用的页面淘汰。

实现：维护访问时间戳或使用栈。

优点：性能接近OPT，实际应用中常用。

缺点：需要硬件支持，开销较大。

4. LFU（最不经常使用算法）

原理：选择访问次数最少的页面淘汰。

实现：为每个页面维护访问计数器。

缺点：某些页面初期频繁访问但之后不再使用，难以淘汰。

5. Clock（时钟算法）

原理：环形队列+CLOCK指针，近似LRU。

实现：每个页面有一个访问位，淘汰时检查：

  • 访问位=0：淘汰该页
  • 访问位=1：置0，继续检查下一页

优点：开销比LRU小，性能较好。

💻 LRU算法代码实现示例

// JavaScript实现LRU算法
class LRU {
    constructor(capacity) {
        this.capacity = capacity;
        this.cache = new Map(); // 维护插入顺序
    }

    access(page) {
        if (this.cache.has(page)) {
            // 页面命中，删除后重新插入（更新到最新）
            this.cache.delete(page);
            this.cache.set(page, true);
            return 'HIT';
        } else {
            // 页面缺失
            if (this.cache.size >= this.capacity) {
                // 内存已满，淘汰最近最少使用的页面（Map的第一个元素）
                const oldestPage = this.cache.keys().next().value;
                this.cache.delete(oldestPage);
                console.log(`淘汰页面：${oldestPage}`);
            }
            this.cache.set(page, true);
            return 'FAULT';
        }
    }
}

// 使用示例
const lru = new LRU(3);
const sequence = [1, 2, 3, 4, 1, 2, 5, 1, 2, 3];
let faults = 0;

sequence.forEach(page => {
    const result = lru.access(page);
    console.log(`访问页面${page}：${result}`);
    if (result === 'FAULT') faults++;
});

console.log(`总缺页次数：${faults}`);

🎓 知识点总结

关键概念：

  • 缺页中断（Page Fault）：访问的页面不在内存中
  • 页面命中（Page Hit）：访问的页面在内存中
  • 缺页率：缺页次数 / 总访问次数
  • Belady异常：FIFO算法增加内存块数可能反而增加缺页率
  • 工作集：某段时间内进程实际访问的页面集合

🔗 实际应用场景

LRU的应用

  • 操作系统：虚拟内存页面置换
  • 数据库：缓冲池管理
  • Web缓存：浏览器缓存淘汰
  • 分布式缓存：Redis、Memcached的淘汰策略
  • CPU缓存：Cache替换策略

页面置换算法对照

算法实现代价命中率 / 特点
OPT（最优）不可实现（需预知未来）理论上限，用作评估基线
FIFO队列，O(1)简单但可能比随机还差；有 Belady 异常（帧数增加命中率反而下降）
LRU链表/哈希，O(1)；硬件需计数器接近 OPT，通用性好；对顺序扫描表现差
LFU计数器适合访问分布稳定的场景；历史热点会「粘住」不被淘汰
Clock / NRU循环队列 + 访问位LRU 的低成本近似，Linux 实际使用的思路
CLOCK-Pro / LIRS多级链表对数据库/文件系统的扫描型访问抵抗性好
工作集（Working Set）按时间窗口记录保证活跃页集合在内存，防抖动

Belady 异常举例：访问序列 1,2,3,4,1,2,5,1,2,3,4,5。3 个帧时 FIFO 缺页 9 次，4 个帧时反而缺页 10 次——这就是增加物理内存反而降低性能的著名反例。只有 FIFO 类算法会出现，LRU/OPT 是栈算法，不会出现。

手算示例

访问序列: 7 0 1 2 0 3 0 4 2 3 0 3 2   物理块 = 3

【FIFO】淘汰最早进入的
  7  -> [7]            miss
  0  -> [7,0]          miss
  1  -> [7,0,1]        miss
  2  -> [2,0,1]        miss (淘汰7)
  0  -> [2,0,1]        hit
  3  -> [2,3,1]        miss (淘汰0)
  0  -> [2,3,0]        miss (淘汰1)
  4  -> [4,3,0]        miss (淘汰2)
  2  -> [4,2,0]        miss (淘汰3)
  3  -> [4,2,3]        miss (淘汰0)
  0  -> [0,2,3]        miss (淘汰4)
  3  -> [0,2,3]        hit
  2  -> [0,2,3]        hit
  FIFO: miss = 10, hit = 3, 命中率 = 3/13 ≈ 23%

【LRU】淘汰最久未用的
  7  -> [7]            miss
  0  -> [7,0]          miss
  1  -> [7,0,1]        miss
  2  -> [2,0,1]        miss (7最久未用)
  0  -> [0,2,1]        hit  (0提到最近)
  3  -> [3,0,2]        miss (1最久未用)
  0  -> [0,3,2]        hit
  4  -> [4,0,3]        miss (2最久未用)
  2  -> [2,4,0]        miss (3最久未用)
  3  -> [3,2,4]        miss (0最久未用)
  0  -> [0,3,2]        miss (4最久未用)
  3  -> [3,0,2]        hit
  2  -> [2,3,0]        hit
  LRU: miss = 9, hit = 4, 命中率 = 4/13 ≈ 31%

本例 LRU 优于 FIFO，但差距不大。LRU 的优势在局部性明显的序列上会拉开——循环访问一个比内存大的数组时，FIFO 命中率接近 0，LRU 也接近 0，两者都失效，这正是 LIRS 要解决的问题。

抖动与系统调优

症状原因处理
抖动（thrashing）：CPU 利用率骤降、磁盘狂响并发进程的工作集总和 > 物理内存降低并发度（挂起部分进程）、加内存、或减少单进程内存占用
sar 显示 pgscank/pgsteal 持续高内核正在回收页sar -B 1 看 pgscank/s；持续 > 0 说明内存紧张
swap 使用量涨但 CPU 空闲大量换页调低 swappiness（默认 60，数据库机器常设 1~10）
OOM Killer 杀进程内存耗尽看 dmesg 的 Out of memory: Kill process；给关键进程设 oom_score_adj
数据库缓冲池命中率下降缓冲池小于工作集，或被全表扫描污染InnoDB 用 改进的 LRU（midpoint insertion，新页先放 5/8 处），就是防扫描污染的设计
madvise / mmap 后性能差预读策略不匹配顺序访问用 MADV_SEQUENTIAL，随机用 MADV_RANDOM
  • Linux 用 活跃/非活跃 LRU 双链表 + swappiness 控制回收倾向，不是教科书式的纯 LRU。
  • 判断内存是否真的不够，看 available 而不是 free——Linux 会把空闲内存用作 page cache，free 很小是正常的。
