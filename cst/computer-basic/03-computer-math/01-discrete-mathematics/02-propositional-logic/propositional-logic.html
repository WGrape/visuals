命题逻辑：真值、连接词与范式

命题逻辑把陈述句抽象为真/假，用与或非组合出复杂判断——它是布尔电路、条件判断、SQL 谓词与 SAT 求解的共同基础。

核心速览

命题

能判断真假的陈述句；原子命题不可再分

五个连接词

¬ 非、∧ 且、∨ 或、→ 蕴含、↔ 等价

重言式 / 矛盾式

恒真 / 恒假；可满足式是「至少有一行真」

范式

DNF（积之和，易构造）、CNF（和之积，SAT 输入格式）

从句子到符号

命题是能判断真假的陈述句。疑问句、祈使句、含未定变量的开句（如「x > 3」）都不是命题——后者是谓词，属于谓词逻辑的范畴。

句子是否命题原因
北京是中国的首都✅ 真可判真假
1 + 1 = 3✅ 假可判真假
x + 1 > 2❌含自由变量，真假取决于 x
请把门关上❌祈使句，无真假
这句话是假的❌说谎者悖论，自指导致无一致真值

五个连接词与真值表

蕴含的四个容易混淆的概念：原命题 p→q；逆命题 q→p；否命题 ¬p→¬q；逆否命题 ¬q→¬p。只有逆否命题与原命题等价——这正是反证法的逻辑依据。

公式的分类

类型真值表特征例子意义
重言式（永真）所有行皆真p ∨ ¬p（排中律）逻辑定律，恒成立的优化依据
矛盾式（永假）所有行皆假p ∧ ¬p不可能满足（UNSAT）
可满足式至少一行真p ∧ qSAT 问题的判断对象
def truth_table(expr, n):
    """枚举 n 个变量的真值表，统计可满足/永真/永假"""
    rows = []
    for mask in range(1 << n):
        vals = [(mask >> i) & 1 for i in range(n)]   # 变量取值
        rows.append((vals, expr(*vals)))
    results = [r[1] for r in rows]
    kind = ("永真" if all(results) else
            "永假" if not any(results) else "可满足")
    return rows, kind

rows, kind = truth_table(lambda p, q: (not p) or q, 2)
print(kind)                       # 可满足（p→q 不是永真）
rows, kind = truth_table(lambda p: p or (not p), 1)
print(kind)                       # 永真（排中律）
命题逻辑是可判定的：n 个变量只有 2ⁿ 行，穷举真值表就能判断永真/可满足。虽然 2ⁿ 是指数级（SAT 因此是 NP 完全），但判定性有保证——这与谓词逻辑的不可判定形成鲜明对比。

等值式：化简的工具箱

名称公式用途
双重否定¬¬p ≡ p去掉多余的否定
德摩根律¬(p∧q) ≡ ¬p∨¬q；¬(p∨q) ≡ ¬p∧¬q否定下推
分配律p∧(q∨r) ≡ (p∧q)∨(p∧r)展开/提取公因式
吸收律p∧(p∨q) ≡ p；p∨(p∧q) ≡ p消冗余
蕴含等值p→q ≡ ¬p∨q消去蕴含

归谬律(p→q)∧(p→¬q) ≡ ¬p反证法
# 化简实例：证明 (p→q) ∧ (p→¬q) ≡ ¬p
# (p→q) ∧ (p→¬q)
#   ≡ (¬p∨q) ∧ (¬p∨¬q)        （蕴含等值）
#   ≡ ¬p ∨ (q ∧ ¬q)            （分配律逆用，提取 ¬p）
#   ≡ ¬p ∨ F                   （矛盾式）
#   ≡ ¬p                       （同一律）∎
# 语义解释：若 p 能推出 q 又能推出 ¬q，则 p 必不成立

范式：两种标准形

DNF 析取范式

「积之和」：(p∧¬q) ∨ (¬p∧r)。从真值表中输出为真的行读出，每行写成一个合取式（极小项），再全部析取。易构造。

CNF 合取范式

「和之积」：(p∨¬q) ∧ (¬p∨r)。从输出为假的行读出，每行写成一个析取式（子句 clause），再全部合取。是 SAT 求解器的标准输入。

为什么 SAT 用 CNF

CNF 的「子句都是必须满足的约束」，天然适合逐个约束检查 + 冲突学习（CDCL）；而且 Tseitin 变换可把任意公式线性地转成等可满足的 CNF。

转换代价

同一个布尔函数从 DNF 转 CNF 可能指数级膨胀。不要手工互相转换，用 Tseitin 变换引入辅助变量。

# 从真值表构造 DNF：对每个输出为真的行写一个极小项
# 例：p q | f        f = T 的行：(T,F) 和 (F,T)
#     T T | F   →   (p ∧ ¬q)
#     T F | T   →   (¬p ∧ q)
#     F T | T
#     F F | F
# f ≡ (p ∧ ¬q) ∨ (¬p ∧ q)       这正是「异或 XOR」！

# Tseitin 变换：给每个子公式引入新变量，线性地生成 CNF

功能完备集：最少需要几个门

连接词集合是否完备说明
{¬, ∧, ∨}✅标准完备集
{¬, ∧}✅∨ 可用德摩根律消去
{¬, ∨}✅同理
{¬, →}✅p∧q ≡ ¬(p→¬q)

NAND 单独完备意味着：理论上整台 CPU 都能只用 NAND 门搭出来。工程上 NAND 结构在 CMOS 里晶体管更少、速度更快，因此标准单元库与 NAND Flash 都偏爱它——理论完备性与工程经济性恰好一致。

🎯 常见问法与答题要点

Q：命题和谓词有什么区别？为什么「x > 3」不是命题？

A：命题是可以判断真假的陈述句（如「1+1=3」是假命题）。「x > 3」含自由变量，真假取决于 x 取什么，因此本身没有确定真值，称为开句或谓词。只有给 x 赋值（如 x = 5）或加上量词（∀x / ∃x）之后，它才变成命题。这是命题逻辑与谓词逻辑的分界线，也是为什么谓词逻辑需要额外的量词规则。

Q：为什么 p→q 在 p 为假时是真？这不会导致奇怪结论吗？

A：因为蕴含等价于 ¬p ∨ q：只要前件为假，整个式子的值为真。语义上，「若 p 则 q」只在承诺被违背（p 真而 q 假）时为假；p 没发生时承诺没被违背。确实会产生反直觉的「空真」结论：「若太阳从西边升起，我就给你一百块」逻辑上恒真。工程影响：形式化验证中，断言可能因触发条件永不出现而「通过」，需要用覆盖检查排除这种 vacuous pass。

Q：什么是逆命题、否命题、逆否命题？哪个与原命题等价？

A：原命题 p→q；逆命题 q→p；否命题 ¬p→¬q；逆否命题 ¬q→¬p。只有逆否命题与原命题等价（p→q ≡ ¬q→¬p）。逆命题与否命题互相等价，但都不与原命题等价。记忆法：逆否 = 既逆又否，两次翻转回到等价。这是反证法的逻辑基础：要证 p→q，可假设 ¬q 推出 ¬p。

Q：DNF 和 CNF 有什么区别？为什么 SAT 求解器偏爱 CNF？

A：DNF 是「积之和」（(p∧¬q)∨…），由真值表中输出为真的行读出，容易构造但可能很长；CNF 是「和之积」（(p∨¬q)∧…），由输出为假的行读出。SAT 偏爱 CNF 的原因：① 每个子句都是一个必须满足的约束，便于增量检查；② 冲突时容易定位到具体子句，支撑 CDCL 冲突驱动子句学习；③ Tseitin 变换能把任意公式线性地转成等可满足的 CNF，避免指数膨胀。

Q：为什么 {∧, ∨} 不完备，而 {NAND} 单独就完备？

A：因为仅用 ∧ 与 ∨ 无法表达否定：任何只含 ∧、∨ 的公式在全 0 输入下输出必为 0，无法表示 ¬p（p=0 时输出 1），所以不完备。而 NAND 单独完备：¬p ≡ p NAND p；(p ∧ q) ≡ (p NAND q) NAND (p NAND q)；有了 ¬ 与 ∧ 就能表达一切（德摩根律给出 ∨）。工程意义：理论上整台 CPU 都能只用 NAND 搭建，且 CMOS 中 NAND 结构晶体管更少、更快，所以标准单元库与 NAND Flash 都偏爱它。

Q：命题逻辑可判定，为什么还说 SAT 是 NP 完全的？

A：两者不矛盾：「可判定」指存在算法能给出答案，「NP 完全」指该算法的最坏时间复杂度是指数级（除非 P=NP）。命题逻辑可判定，因为 n 个变量只需穷举 2ⁿ 行真值表；但 2ⁿ 增长太快，因此对大公式不可行。Cook-Levin 定理证明 SAT 是第一个 NP 完全问题，即所有 NP 问题都能归约到它。实践中现代 CDCL 求解器配合子句学习与启发式，已能解决百万变量级的工业实例——这是「理论难 ≠ 实践不可用」的经典例子。

Q：短路求值和命题逻辑有什么关系？有什么坑？

A：短路求值正是 ∧、∨ 真值表的直接实现：p∧q 在 p 为假时无需看 q，p∨q 在 p 为真时无需看 q。好处：既省时间，又能写出安全表达式（if (x != 0 and 10/x > 2) 靠短路避免除零）。坑：① 若右侧表达式有副作用（计数、日志、状态修改），短路会让它不执行；② 并非所有语言/环境都保证短路与求值顺序（如某些 SQL 优化器会重排条件，某些向量化计算会两侧都算）——跨语言移植时要显式确认语义。

Q：德摩根律在代码和 SQL 里怎么用？

A：把否定推入复合条件：¬(p∧q) ≡ ¬p∨¬q，¬(p∨q) ≡ ¬p∧¬q。用法：① 可读性：if (!(a && b)) → if (!a || !b)，便于逐项短路；② SQL 索引友好：把 WHERE NOT (city='BJ' AND age<18) 改写为 OR 形式，让优化器有更多机会用上索引；③ 电路化简：NAND/NOR 互换以减少门级数；④ 量词对偶：¬∀x P ≡ ∃x ¬P，是 SQL 中用 NOT EXISTS 表达「所有」的依据。
