第 10 章 · 搜索

怎样缩小候选范围

搜索不只是查一个值：核心是用输入性质排除不可能的候选，直到答案落在可验证的范围。

核心速览

顺序查找O(n)，无任何前提，最后的兜底
二分查找O(log n)，要求有序 / 单调
哈希查找O(1) 均摊，要求可哈希、不需顺序
搜索剪枝在状态空间上排除不可能的分支

搜索的本质：不断排除

所有搜索算法都在回答同一个问题——「答案在哪一半？」。差别只在于用什么性质来判断该排除哪一半。

方法排除依据每次能排除复杂度
顺序查找逐个比对，无法排除1 个O(n)
二分查找有序性 / 单调性一半O(log n)
哈希查找哈希值直接定位几乎全部O(1) 均摊
二叉搜索树左小右大的不变量一棵子树O(h)
BFS / DFS已访问标记避免重复O(V+E)
页脚那句话是判别标准：「每次舍弃候选之前，要能说明答案为什么不在其中。」说不出理由的排除就是错的——这是搜索算法正确性的唯一检验方式。

二分查找：不只是「查一个值」

大多数人只把二分当成「在有序数组里找一个数」，但更本质的理解是：

二分查找的本质是：在一个单调的判定函数上，找到「真/假」的分界点。

也就是说，只要存在一个性质 P(x)，它关于 x 是单调的（x 小的时候恒为假、x 大的时候恒为真，或反之），就可以二分找到临界值——哪怕 x 并不是数组下标，而是一个「答案」。这就是所谓「二分答案」。

形式单调的是什么例子
标准二分数组元素随下标递增在 [1,3,5,7,9] 里找 7
边界二分「是否 ≥ target」找第一个 ≥ target 的位置（lower_bound）
二分答案「x 是否可行」关于 x 单调「在 x 天内能否修完所有路」→ 求最小天数
# 二分答案模板：找到满足 check(x) 为真的最小 x
lo, hi = 下界, 上界          # 需保证 check(hi) 为真、check(lo) 为假
while lo < hi:
    mid = (lo + hi) // 2
    if check(mid):
        hi = mid             # mid 可行，但可能还能更小
    else:
        lo = mid + 1         # mid 不可行，必须增大
return lo
两个必踩的坑：① mid 溢出——某些语言里 (lo + hi) / 2 可能溢出，应写 lo + (hi − lo) / 2；② 死循环——lo = mid 与 mid = (lo+hi)//2 搭配时，若 hi − lo = 1 则 mid 恒等于 lo，会无限循环。统一用「lo = mid + 1」配合「下取整 mid」最安全。

搜索策略的层次

越往上越快，但依赖的前提越强。哈希要求「可哈希 + 不需要顺序」；二分要求「有序 / 单调」；剪枝要求「存在可判定的约束」。如果输入不满足这些性质，就只能用下一层的方法——选搜索方法的第一步是检查输入具有什么性质，而不是凭习惯。

字符串搜索：KMP 为什么快

朴素匹配的问题：失配时把模式串右移一格，从头再比，之前比对过的信息全丢了，最坏 O(n·m)。

KMP 的核心洞察：失配时，模式串已匹配的那部分本身含有信息——它的「前缀」和「后缀」如果有重合，就可以直接把模式串滑动到重合位置，而不是只移一格。

模式串 ABABC，在 ABABD 处失配。已匹配的 ABAB 有真前缀 AB = 真后缀 AB，长度 2。于是可以直接把模式串前移，让开头的 AB 对齐已匹配的尾部 AB，从模式串第 3 位继续比较，而不必回到开头。

这个「每个位置的最长相等真前后缀长度」被预处理成 next / lps 数组，之后匹配过程主串指针永不回退，总复杂度 O(n + m)。

KMP 的思想和二分一脉相承：都是「不浪费已经获得的信息」。朴素算法把已知信息丢掉重来，KMP 则分析「已匹配部分的结构」，从而安全地跳过那些必然失配的位置。

选型速查

场景方法复杂度
有序数组精确查找二分O(log n)
无序数组精确查找（一次）顺序扫描O(n)
无序数组多次查找先建哈希表（或先排序）建表 O(n) + 查询 O(1)
找第 k 大 / 中位数快速选择（快排分区思想）平均 O(n)
图中路径 / 连通性BFS / DFSO(V+E)

子串匹配（多模式）Trie / AC 自动机O(n + 总模式长)
最优解空间搜索回溯 + 剪枝 / 分支限界指数级（靠剪枝）

🎯 面试问答

Q：二分查找的本质是什么？

A：更本质的理解是：在一个单调的判定函数上找「真/假」的分界点，而不只是「在有序数组里找一个数」。只要存在一个性质 P(x) 关于 x 单调（小的一边恒假、大的一边恒真，或反之），就可以二分找临界值——即使 x 不是数组下标，而是一个候选答案。这就是「二分答案」：例如「x 天内能否修完所有路」关于 x 单调，于是可以二分出最小天数。判断能否用二分，就看能不能构造出这个单调的 check 函数。

Q：二分查找怎么写才不会死循环？

A：统一采用「下取整 mid + lo = mid + 1」的组合最安全。关键规则：① 计算 mid 用 lo + (hi − lo) // 2 而不是 (lo + hi) // 2（后者在某些语言可能整数溢出）；② 当 mid 不可行时写 lo = mid + 1——如果写成 lo = mid，当 hi − lo = 1 时 mid 恒等于 lo，会陷入死循环；③ 循环条件用 while lo < hi，退出时 lo == hi 即答案。这个模板可以统一处理「找第一个 ≥ target」「找最后一个 ≤ target」等各种边界变体。

Q：什么是「二分答案」？和二分查找有什么区别？

A：二分查找是在数组下标上二分（有序性来自数组本身）；二分答案是在候选答案的值域上二分（单调性来自「x 是否可行」这个判定函数）。例如「木头切割」问题：check(x) = 「能否切出至少 k 段长度为 x 的木头」，x 越大越难满足，因此单调，可以二分出最大的可行 x。识别技巧：当题目问「最大的最小 / 最小的最大」且可行性随答案单调变化时，就适合二分答案。

Q：哈希查找和二分查找怎么选？

A：看是否需要顺序，以及查找次数。哈希平均 O(1) 更快，但不支持范围查询、前驱后继、有序遍历，且需要额外空间和处理冲突；二分 O(log n) 稍慢，但原地、支持范围与边界查询（lower_bound / upper_bound）。另外：如果只查一次，对无序数组直接顺序扫描 O(n) 可能比「先排序再二分」的 O(n log n) 更划算；如果要查很多次，才值得先建哈希表或先排序。

Q：KMP 为什么能到 O(n + m)？核心思想是什么？

A：核心思想是「不浪费已经获得的信息」。朴素匹配失配时只把模式串右移一格并从头再比，之前比对的结果全丢了，最坏 O(n·m)。KMP 观察到：已匹配的那部分模式串，其「真前缀」和「真后缀」若有重合，就可以直接把模式串滑动到重合位置继续比较，而不是回退到开头。把这些重合长度预处理成 next / lps 数组后，主串指针永不回退，总复杂度 O(n + m)。这与二分一脉相承——都是分析已有信息的结构，从而安全地跳过必然失败的候选。

Q：在无序数组里查找，最优策略是什么？

A：取决于查找次数：只查一次 → 直接顺序扫描 O(n)，没必要先排序（排序本身 O(n log n) 更贵）；查多次（m 次） → 先建哈希表 O(n)，之后每次 O(1)，总计 O(n + m)；或者先排序 O(n log n) 再二分，总计 O(n log n + m log n)。通常建哈希表更划算。如果还需要范围查询，则选排序 + 二分。
