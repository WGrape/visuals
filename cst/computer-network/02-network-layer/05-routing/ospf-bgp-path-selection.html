OSPF 与 BGP 分别解决什么：路由学习、策略和收敛

从企业内网到两个运营商出口，解释域内最短路径与域间策略为何是两套问题。

转发表从哪里来

路由器最终按目的前缀查转发表，但前缀可能来自直连接口、静态配置、OSPF、BGP 等来源。OSPF 主要在一个管理域内传播链路状态，让路由器计算到达域内网段的路径；BGP 在自治系统之间交换可达前缀并表达路由策略，也可在同一自治系统内部传播外部路由。二者都不是“更高级的最长前缀匹配”：协议负责学习和选择候选路由，真正转发仍要依赖生效表项和下一跳。

例如企业有总部、分支和两个互联网出口。内网各路由器要知道总部网段可经哪条内部链路到达，OSPF 可以处理；企业对外发布前缀、选择经哪个运营商接入和对不同目的偏向哪条出口，则涉及 BGP 策略。网络规模、设备与管理要求决定是否真的需要两种协议，小网络静态路由也可能足够。

OSPF 如何形成域内视图

OSPF 邻居交换链路状态信息，路由器在同一区域内构建链路状态数据库，再以自己为根计算最短路径树。路径成本可由接口配置和实现规则决定，不应把它机械等同于实时延迟；一条低成本链路若实际拥塞，OSPF 未必自动改走未拥塞链路。若邻居建立失败，先检查网络连通、区域号、认证、定时器和接口类型等配置。

区域用于控制链路状态传播与计算范围，但错误划分可能造成路由不可达或故障分析困难。链路断开后，邻居状态变化、链路状态通告传播和 SPF 重算都需要时间；业务感知的中断还包含转发表更新和应用重试。不要用单个“OSPF 已收敛”的日志替代端到端业务测试。

BGP 为什么更看重策略

BGP 传播前缀及路径属性，用于域间路由选择。AS_PATH 可帮助识别路径经过哪些自治系统并防环；LOCAL_PREF 常用于本 AS 内选择出口；MED 等属性可能影响对方如何看待入口，但是否被对方采用取决于其策略。所谓“最短路径”在 BGP 里不是简单的地理距离或 RTT 最小，它首先是满足策略的路径。

两个运营商都能到达某目的时，企业可能因成本、容量或业务地域选择出口 A，即使某次 ping 的 RTT 略高。BGP 出口策略要与回程、NAT、公网地址归属和防火墙状态相配合。某出口失效后，路由撤销与传播需要时间，短时间不通可能是收敛过程，也可能是错误前缀过滤。

一个双出口算例

企业持有一个对外服务前缀，出口 A 与出口 B 都有连接。内部用户访问互联网时，可用 LOCAL_PREF 让多数流量优先走 A；服务被外部访问的入口则由外部网络自己的策略决定，不能仅靠本地偏好强制全球流量从 A 进来。若 A 故障，BGP 需撤销或失去 A 路径，内部设备也要把出口路径切到 B。若外部仍在把包送向 A，需看前缀宣告和上游传播，而不只是本机路由表。

静态默认路由指向 A 而 BGP 已切到 B，可能让企业内的转发仍走坏出口。设计时要明确“路由如何进入全网”和“谁是权威默认出口”，避免协议状态正确但静态表项抢先转发。

常见误判

看到 BGP 邻居状态 Established，只能证明会话建立，不证明收到所需前缀或把它安装进转发表；看到 OSPF 邻居 Full，也不证明下游防火墙放行。可按“邻居—数据库或收到前缀—策略过滤—路由表—下一跳—实际报文”逐层检查。若某个更具体前缀被错误发布，它可能覆盖健康的聚合前缀，把局部流量导入黑洞。

路由泄漏或劫持的风险来自错误宣告、过滤与授权不足。对外发布前缀应有明确允许列表、变更审查和异常监控；对收到的前缀也要限制范围。网络稳定性取决于控制面与数据面共同正确，不只是协议选型。

怎样做故障演练

搭一个三路由器内部拓扑，再接两个模拟出口。先断开一条内部链路，测 OSPF 邻居变化、到目标网段的新下一跳和业务恢复时间；再断开一个外部出口，测 BGP 前缀变化、默认路由切换、外部用户能否访问服务。每次记录去程与回程，以及收敛期内的丢包和连接重试。

考试题常问“OSPF 与 BGP 谁更快、谁更短”，真实答案要写清范围、配置与策略。OSPF 在域内根据链路状态和成本计算路径，BGP 在自治系统边界按策略选路；不能只拿两个协议名字比较一个抽象的速度。

BGP 选路的完整顺序

BGP 只在前缀长度相同的多条路径间按以下顺序比较（厂商实现略有差异，这是 Cisco 的经典顺序）：

顺序属性比较规则常用吗
1Weight（Cisco 私有）大者优先，仅本地有效常用
2Local_Preference大者优先，AS 内传播最常用（控制出口）
3本地起源本机产生的优先（network > aggregate > redistribute）少用
4AS_Path 长度短者优先常用（默认行为）
5Origin 类型IGP > EGP > Incomplete少用
6MED小者优先（跨 AS 比较，需配置）常用（影响入向）
7eBGP 优于 iBGP外部学到的优先默认
8到 NEXT_HOP 的 IGP metric小者优先默认
9Router ID / 邻居地址小者或最老的连接胜出（打破平局）兜底
  • Local_Pref 控制出向流量（我怎么出去）：值越大越优先，在 AS 内传播，是控制出口的首选手段。
  • MED 影响入向流量（别人怎么进来）：告诉邻居“从我这里进来更近”。但邻居完全可以忽略（MED 不跨 AS 传播，且比较范围有限）。真正控制入向要靠 AS_Path Prepend（把自己的 AS 号重复几次，人为变长）。
  • AS_Path Prepend：如 65001 65001 65001，让路径看起来更长从而降低优先级。这是多宿主（multihoming）场景控制入向流量的实际标准做法。
  • 路由反射器 / 联邦：iBGP 要求全互联（N² 个会话），规模大时用 Route Reflector 打破；这是数据中心 BGP（如 Calico、K8s 网络）的常见形态。
  • 黑洞与 Route Leak：BGP 没有内建的合法性校验，一次错误的宣告就能把流量劫持走（历史上多次全球性事故）。生产必须用 ROA/RPKI 校验 + max-prefix 限制（防止邻居误发全表撑爆内存）。
BGP 为什么不选最快的路？

BGP 是策略驱动而非性能驱动：它默认按 AS_Path 长度等属性选路，完全不知道带宽、延迟、丢包。要按性能选路需要额外注入 metric（如基于延迟的 Local_Pref）。

OSPF 和 BGP 该用哪个？

自治系统内部用 OSPF/IS-IS（自动发现、快速收敛）；跨组织/跨 AS 用 BGP（策略可控、规模巨大）。数据中心内部现在也流行用 BGP（CLOS 架构 + eBGP），因为它简单且可扩展。

自检

BGP 邻居 Established，能证明某业务前缀已可达吗？

不能。还需核对前缀接收、策略过滤、生效转发表、下一跳和实际去回程流量。
