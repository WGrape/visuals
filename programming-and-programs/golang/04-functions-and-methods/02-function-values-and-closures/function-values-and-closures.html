存表、传参、返回

函数类型变量可以像 int 一样使用，常用于策略表、中间件链。

var ops = map[string]func(int, int) int{
    "add": func(a, b int) int { return a + b },
    "sub": func(a, b int) int { return a - b },
}
ops["add"](3, 4)  // 7
匿名函数

就地定义，常配合 defer/goroutine

匿名函数没有名字，常用于一次性逻辑；可直接调用，也可赋值或传给别处。

func() {
    fmt.Println("immediately")
}()

// 作为 goroutine
go func() { doWork() }()
闭包：捕获变量

注意「捕获的是变量，不是值」

闭包持有外部变量的引用，而非创建时的值。在循环里启动 goroutine 时，这个细节极易引发 bug。

for i := 0; i < 3; i++ {
    go func() { fmt.Println(i) }()  // 可能都打印 3
}
// 正确：把 i 作为参数传入（值拷贝）
for i := 0; i < 3; i++ {
    go func(n int) { fmt.Println(n) }(i)
}
defer 与闭包配合

资源释放的惯用法

defer 后跟匿名函数或方法调用，函数返回前执行，适合关闭文件、解锁、记录耗时。配合命名返回值还能修改最终返回。

func read() (err error) {
    f, err := os.Open("x")
    if err != nil { return }
    defer f.Close()        // 返回前关闭
    defer func() { log(err) }()  // 读取最终 err
    // ...
}

函数是一等公民意味着什么

函数可以赋值给变量、作为参数传递、作为返回值、放进结构体与 map。这让 Go 能在没有继承与注解的情况下表达「行为参数化」。

// ① 赋给变量 f := strings.ToUpper f("go") // GO // ② 作为参数（行为参数化） func Map[T, R any](in []T, f func(T) R) []R { out := make([]R, 0, len(in)) for _, v := range in { out = append(out, f(v)) } return out } Map([]int{1, 2}, func(x int) string { return strconv.Itoa(x) }) // ③ 作为返回值（工厂） func multiplier(n int) func(int) int { return func(x int) int { return x * n } } double := multiplier(2) double(5) // 10 // ④ 放进 map 做分发表 handlers := map[string]func(string) error{ "create": createHandler, "update": updateHandler, } // ⑤ 定义函数类型并给方法 type HandlerFunc func(w http.ResponseWriter, r *http.Request) func (f HandlerFunc) ServeHTTP(w http.ResponseWriter, r *http.Request) { f(w, r) // 让普通函数满足接口 }
可赋值函数像普通值一样传递。
可返回闭包让工厂与配置化成为可能。
可适配接口函数类型加方法即可满足接口。
nil 可判断函数可以是 nil，调用前要检查。

闭包：捕获了什么，什么时候捕获

闭包会引用外部变量而不是复制它。这是它强大的地方，也是最容易出错的地方。

// 闭包捕获的是变量本身，不是当时的值 n := 0 inc := func() { n++ } inc(); inc() fmt.Println(n) // 2，外部的 n 被改了 // 经典陷阱：循环里启动 goroutine for _, v := range []int{1, 2, 3} { go func() { fmt.Println(v) }() // 可能全打印 3 } // 修复一：作为参数传入 for _, v := range []int{1, 2, 3} { go func(v int) { fmt.Println(v) }(v) } // 修复二：在循环内创建新变量 for _, v := range []int{1, 2, 3} { v := v go func() { fmt.Println(v) }() } // Go 1.22 起循环变量每次迭代都是新变量，上述陷阱基本消失 // 但显式传参仍是更清晰的写法
捕获引用闭包持有变量，不是快照
会延长生命周期被捕获的变量会逃逸到堆
循环捕获传参或复制到局部
defer 里也要注意同循环变量问题

闭包的四个典型用法

回调与钩子

  • 注册回调：onSuccess(func() {...})
  • 遍历时传入处理函数
  • 排序的比较函数
  • 注意回调里的错误处理与并发安全

中间件与装饰器

接收一个函数、返回一个增强版函数。

func WithRetry(n int, f func() error) func() error { return func() error { var err error for i := 0; i < n; i++ { if err = f(); err == nil { return nil } } return err } } run := WithRetry(3, doWork) run()

选项与配置

函数式选项本质就是闭包：捕获配置值，稍后应用到目标对象。

type Option func(*Server) func WithTimeout(d time.Duration) Option { return func(s *Server) { s.timeout = d } // 捕获 d } func NewServer(opts ...Option) *Server { s := &Server{} for _, o := range opts { o(s) } return s }

延迟资源清理

  • defer 配合闭包做收尾
  • 注意捕获变量在 defer 执行时的值
  • 闭包内 recover 是标准写法

深入自检

闭包会导致内存泄漏吗？

可能。闭包持有外部变量会让它的生命周期延长到闭包本身结束为止。如果一个长期存活的结构体（如全局注册表）持有一个捕获了大对象的闭包，那个大对象就无法被回收。注意及时释放不再需要的闭包。

Go 1.22 之后循环变量还需要 v := v 吗？

通常不需要了——Go 1.22 起每次迭代的循环变量都是新变量，闭包捕获各自的值。但如果你需要兼容旧版本，或者代码要被旧工具链编译，显式传参或复制仍是稳妥做法，且可读性更好。

闭包一定会导致变量逃逸到堆吗？

不一定，但很常见。只要闭包的生命周期可能超过当前栈帧（比如被返回、被存到长期结构中），被捕获的变量就会逃逸。若闭包只在当前函数内调用且编译器能证明，仍可能留在栈上。

函数值能比较吗？

函数值不能用 == 比较（除了与 nil 比较），因此不能作为 map 的 key。若需要标识函数，通常用 reflect 取指针，或者干脆用字符串/枚举作为 map 的 key。

闭包和接口怎么选？

只需要一个行为时用函数或闭包最轻量；需要一组相关行为、或需要携带状态时用接口。很多库的做法是两者都提供：既接受接口，也提供一个函数适配器（如 http.HandlerFunc）。

闭包的开销与逃逸

项目数值/行为说明
直接函数调用2 – 5 ns，可内联最快
函数值调用5 – 10 ns间接跳转，无法内联
闭包调用5 – 15 ns同上 + 访问捕获变量
闭包创建（捕获变量）约 20 – 40 ns（若逃逸则堆分配）捕获的变量会逃逸到堆
方法值（method value）约 10 nsf := x.Method 会拷贝接收者
方法表达式同普通函数T.Method 需显式传接收者

闭包会让捕获的变量逃逸到堆：因为闭包的生命周期可能长于创建它的函数，编译器必须把被捕获的变量放到堆上（否则函数返回后变量就没了）。这是闭包最主要的隐藏成本。

闭包陷阱与验证

# 经典陷阱 1：循环变量捕获（Go 1.22 之前的行为）
for _, v := range items {
    go func() {
        fmt.Println(v)      # Go < 1.22：所有 goroutine 打印最后一个 v！
    }()
}
# Go 1.22 起：每次迭代创建新变量，上面的代码是安全的
# 兼容旧版本或明确意图的写法：
for _, v := range items {
    v := v                  # 显式创建副本（阴影变量）
    go func() { fmt.Println(v) }()
}
# 或传参（最清晰）
for _, v := range items {
    go func(v Item) { fmt.Println(v) }(v)
}

# 经典陷阱 2：defer 在循环里（延迟到函数返回才执行）
for _, f := range files {
    f, _ := os.Open(f)
    defer f.Close()         # 循环 1000 次 = 1000 个 defer 堆积！
}
# 正确：包一层函数，让 defer 在每次迭代结束时执行
for _, name := range files {
    if err := func() error {
        f, err := os.Open(name)
        if err != nil { return err }
        defer f.Close()
        return process(f)
    }(); err != nil { return err }
}

# 验证逃逸
go build -gcflags="-m" ./... | grep -E 'captured|closure'
# ./main.go:12:9: func literal escapes to heap
# ./main.go:12:20: &v escapes to heap

函数式用法与建议

  • 闭包最常用的三个场景：① 回调函数（http.HandleFunc、sort 的比较器）；② 中间件/装饰器（func(next Handler) Handler）；③ 工厂函数（返回带有预置状态的函数，如 func WithTimeout(d time.Duration) Option）。
  • 方法值 vs 方法表达式：f := x.Method 会拷贝接收者（如果是指针接收者则拷贝指针），之后 f() 一直用这个副本——修改不会反映到原对象。f := T.Method 则需要显式传接收者 f(x, args)。
  • defer 的开销：Go 1.14 后引入了开放编码（open-coded）defer，无循环的简单 defer 几乎零开销（直接内联在函数末尾）；但循环内的 defer 仍走传统路径（堆分配链表）。热路径要留意。
  • 不要用闭包做大对象持有：闭包捕获了对象就让它一直存活（内存泄漏的一种）。尤其注意闭包被存到全局 map、注册到定时器里的情况。
  • 性能敏感时用接口或泛型替代：如果只是为了“传一段行为”，在热路径上用接口（可内联的方法调用）或直接内联代码，比闭包更快。Go 1.18 的泛型也能在很多场景替代闭包工厂。
  • 排障：闭包相关的 bug 几乎都是变量捕获问题。检查：① 循环里起 goroutine；② 循环里 defer；③ 闭包被长期持有（内存泄漏）。用 -race 能发现很多。
Go 1.22 的循环变量改动具体改了什么？

之前 for i := 0; i < 3; i++ 里 i 是整个循环共用一个变量，闭包捕获的是同一个；1.22 起每次迭代创建一个新变量，闭包各自捕获自己的。这让绝大多数循环闭包 bug 自动消失。注意：需要 go.mod 里的 go 版本声明 ≥ 1.22 才生效。

闭包捕获切片/映射会逃逸吗？

会。闭包捕获任何变量都会让它逃逸（除非编译器能证明闭包不逃逸，比如立即调用且不传出）。所以 func() { use(slice) }() 这种立即执行的闭包，编译器通常能优化掉。
