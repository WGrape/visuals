先建立直觉：用几个桶估算人流

要精确统计每个访客来过多少次，需要给每个人建一个档案（内存爆炸）。但如果你只需要粗略知道「谁来得最多」，有个巧妙办法：

准备几排桶，每排桶用不同的哈希函数把访客分到桶里。访客每来一次，就在每一排对应的桶里 +1。要查询某人的访问次数，就看他对应的几个桶，取最小值。

取最小值是关键——因为哈希冲突会让某些桶被别人「顺带加过」，所以真实值一定不超过最小值（只会高估，不会低估）。

Count-Min Sketch 结构

为什么取最小值

核心性质：哈希冲突只会让别人也往你的格子里加数，所以格子的值 = 你的真实频次 + 别人的干扰 ≥ 真实值。因此取最小值是最接近真值的估计，且保证不会低估。这种「宁可高估、绝不低估」的特性，恰好适合频次统计——我们只关心「谁更热」的相对关系。

更新与重置

// 访问 key 时：在每一行对应的格子 +1
for i := 0; i < d; i++ {
    table[i][hash_i(key) % w]++
}

// 查询：取所有行的最小值
estimate := MAX
for i := 0; i < d; i++ {
    estimate = min(estimate, table[i][hash_i(key) % w])
}
饱和问题：随着访问量增长，所有格子都会涨到很大，最终彼此接近，区分度消失。解决办法是定期重置：每累计一定访问量后，把所有计数减半（或右移一位）。这同时起到了老化作用——久未访问的数据计数快速衰减。

在缓存中的用法：准入判断

TinyLFU 不直接用于「淘汰谁」，而是用于「新数据能不能进来」（准入）。典型流程：

  1. 新数据到来，缓存已满；
  2. 用 Count-Min Sketch 分别估算新数据的频次和被淘汰候选（LRU 尾部）的频次；
  3. 谁的频次高谁留下——新数据频次高就替换进去，否则拒绝。
为什么这样有效？一次性批量扫描进来的冷数据频次只有 1，PK 不过已经在缓存里的热数据，会被直接挡在门外，根本污染不了缓存。这正是 LRU 做不到的。
W-TinyLFU 在此之上再加一个小的 Window 区（LRU），专门接纳新数据，避免它们因为频次低而永远进不来（解决新数据饥饿）。这就是 Caffeine 高命中率的秘密。

三种频次统计方案对比

方案内存精度适用
精确 HashMap 计数高（每 key 一个计数）精确key 数量可控

🎯 面试问答

Q：为什么取最小值而不是平均值或最大值？
A：因为冲突只会做加法：格子的值 = 真实频次 + 其他 key 的干扰，一定 ≥ 真实值。取最小值是受干扰最小的那个估计，也保证了「绝不低估」。平均值会被极端冲突拉偏，最大值受干扰最严重。想提高精度就增加行数 d（多几个独立哈希，取最小后更接近真值）。

Q：计数饱和了怎么办？
A：定期重置（减半）。当累计访问量达到阈值（通常是 w 的若干倍）时，把所有计数器右移一位（即除以 2）。这既防止饱和，又天然实现了老化——久未访问的数据在几次重置后迅速趋近 0，新热点则能持续保持高值。Caffeine 就采用这种「定期减半」策略。

Q：TinyLFU 是淘汰算法吗？
A：严格说它是准入（admission）策略，不是淘汰算法。它决定「新来的能不能进来」，而「进来之后淘汰谁」通常由 LRU 段负责。二者配合：TinyLFU 把关入门（按频次 PK），LRU 负责内部排序（按时间）。W-TinyLFU 再加一个 Window LRU 区保护新数据，就形成了完整方案。

Q：误差有多大，会影响缓存效果吗？
A：Count-Min Sketch 会高估频次（冲突越多高估越多），但缓存准入只需要比较「新数据 vs 候选者谁更热」的相对关系，少量高估通常不改变比较结果。通过增大 d（行数）和 w（列数）可以把误差压得很低。实践上 Caffeine 用极小的内存开销换到了显著高于 LRU 的命中率。

TinyLFU 与 Count-Min Sketch 的参数

组件参数默认值 / 建议
Count-Min Sketch宽度 w（列数）w ≈ 条目数 / 4；10 万条用 32768（2 的幂便于位运算）
深度 d（哈希函数个数）4；d 越大误差越小，开销越大
空间占用4 bits / 计数器 × w × dw=32768, d=4 时 = 64 KB，可统计 10 万级频次
误差特性只会高估不会低估多次哈希碰撞累加导致；所以对低频项不友好
TinyLFU 准入比较策略新项频率 > 被驱逐项频率 才准入
W-TinyLFU（Caffeine）Window 占比1%（可自适应调整）
Main 区划分Protected 80% / Probation 20%命中过的从 Probation 升到 Protected
老化（reset）计数达到 sampleSize 时全体减半防历史热点永久占据

Count-Min Sketch 为什么省空间：要精确统计 100 万个 key 的频率，哈希条约需 100万 × (key 8字节 + 计数 4字节) ≈ 几十 MB；而 CMS 用 32768 × 4 个 4-bit 计数器 = 64 KB，空间差了 1000 倍。代价是频率会高估。

实现代码

import mmh3, math

class CountMinSketch:
    """4-bit 计数器的 CMS：每字节存 2 个计数器，极致省内存"""
    def __init__(self, width=32768, depth=4):
        self.w, self.d = width, depth
        self.mask = width - 1                       # 要求 width 是 2 的幂
        self.table = bytearray((width * depth + 1) // 2)   # 4 bits * w * d
        self.size = 0                               # 累计插入数，用于判断何时 reset

    def _idx(self, key, i):
        return mmh3.hash(key, i) & self.mask        # 位运算取代取模，更快

    def _get(self, row, col):
        b = self.table[(row * self.w + col) // 2]
        return b >> 4 if (row * self.w + col) % 2 == 0 else b & 0x0F

    def _incr(self, row, col):
        pos = row * self.w + col
        byte_i, half = pos // 2, pos % 2
        v, b = self._get(row, col), self.table[byte_i]
        if v < 15:                                  # 4-bit 上限 15，饱和了就不增
            self.table[byte_i] = (b + 16) & 0xFF if half == 0 else (b & 0xF0) | ((v + 1) & 0x0F)

    def add(self, key, n=1):
        for i in range(self.d):
            self._incr(i, self._idx(key, i))
        self.size += n

    def estimate(self, key):                        # 取 d 个计数器的最小值
        return min(self._get(i, self._idx(key, i)) for i in range(self.d))
# TinyLFU 准入判断：新项频率 vs 受害者频率
def admit(cms, candidate, victim, window, main_protected):
    freq_c = cms.estimate(candidate)
    freq_v = cms.estimate(victim)
    # W-TinyLFU 的规则：
    #   若候选来自 window 区且 window 已满 -> 与 main 的 probation 队首比较
    #   频率高者留，低者淘汰
    return freq_c > freq_v

# 老化（aging）：防止「曾经很热、现在很冷」的项永久占着位置
def reset(cms, sample_size):
    if cms.size >= sample_size:                     # sample_size 常设为 10 * capacity
        cms.table = bytearray(len(cms.table))       # 或者所有计数器 >>= 1（减半，更平滑）
        cms.size = 0
# Caffeine 用「每次达到 sampleSize 就全体右移 1 位」，等价于平滑衰减

排障与取舍

症状原因处理
命中率反而不如 LRU访问模式是一次性扫描（无局部性）TinyLFU 的价值在抗扫描污染；纯顺序访问 LRU 与 LFU 都失效
新热点进不来（冷启动慢）LFU 的历史频次把新项挡在外面W-TinyLFU 的 Window 区就是为此设计；调大 window 到 5~20%
频率统计不准CMS 会高估；w 太小w 取 容量/4 以上；深度 d=4 通常够
内存比预期大w 或 d 设太大w = 2 的幂且 ≈ 容量/4；d=4
老热点永不淘汰没有老化机制加 reset（全体减半），Caffeine 默认开启
4-bit 计数溢出单项计数超过 15饱和后不再增长（这是可接受的设计）；或改用 8-bit
  • TinyLFU 的本质：用一个极低成本的频次估计器做「准入控制」——决定新项有没有资格进入缓存，从而保护缓存不被一次性扫描污染。
  • 对比：LRU 对扫描敏感（扫描会把热数据全挤出去）；纯 LFU 对变化不敏感（老热点下不去）。W-TinyLFU 用 window（扛新热）+ main（LFU 准入）+ 老化（去旧热）三者组合解决。
