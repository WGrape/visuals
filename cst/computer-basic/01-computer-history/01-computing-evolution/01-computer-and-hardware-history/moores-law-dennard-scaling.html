摩尔定律与功耗墙：CPU 为何转向多核

把晶体管数量、功率密度与单核性能分开，理解频率增长放缓后的架构转向。

两条常被混在一起的历史观察

摩尔定律描述集成电路上可经济集成的晶体管数量随时间增长的行业观察与目标，并不直接保证程序每隔固定时间自动快一倍。Dennard 缩放讨论器件缩小时电压、电流等如何随之缩放，使功率密度可以维持在可控范围。两者曾共同支持更复杂、更高频的处理器，但并非同一个定律。晶体管更多，只有在能供电、散热并有效利用时，才可能转化为应用性能。

动态功耗可用近似关系 P∝C·V²·f 帮助理解：开关电容 C、电压 V 和频率 f 都影响功耗。降低制程尺寸不再能等比例降低电压时，继续提高频率会推高功率与热密度，单核频率增长因而受限。真实芯片还有漏电、缓存、布线和制造成本等因素，简单公式只是解释趋势的模型。

逐步推演

区分观察

分开晶体管数量增长与功率密度缩放。

识别功耗墙

用电容、电压、频率近似关系理解高频代价。

选择架构

把新增晶体管分配给核心、缓存或专用单元。

验证收益

用真实负载和 Amdahl 定律区分单线程与并行收益。

从高频单核到多核的取舍

当频率提升越来越昂贵，设计者可把新增晶体管用于更多核心、更大缓存、SIMD 单元、专用加速器或片上互联。多核让可并行任务获得更高总吞吐，但单个串行线程不会因为核心翻倍就自动快一倍。Amdahl 定律提醒：若 20% 工作必须串行，即使并行部分无限加速，总体加速上限也只有 5 倍。应用软件需要线程划分、同步和内存局部性，才能用好更多硬件。

变化可能收益限制
提高时钟频率单线程延迟下降功耗、发热和频率墙
增加核心并行吞吐提升串行比例与同步开销
扩大缓存减少访存等待面积与命中率收益递减
专用加速器特定算子能效更高适用负载有限、数据搬运成本

为什么“晶体管更多”仍有价值

性能不只由主频决定。乱序执行、更宽发射、更好的分支预测与缓存层级可以提高每周期完成的有效工作；向量单元与 GPU 适合大量相似操作；片上系统还集成编解码、安全与 I/O 逻辑。不同工作负载受 CPU、内存带宽、缓存未命中或数据搬运约束，新增晶体管投到不同模块，收益也不同。

芯片设计还受经济因素影响。更先进工艺可能带来更高制造与设计成本，良率、供电和封装也成为瓶颈。Chiplet 和先进封装可把不同功能拆成多个晶粒组合，但跨晶粒通信仍有延迟和能耗，不能简单等同于一块无限大的单片芯片。讨论技术演进时应把工艺、架构和软件并行性放在一起。

用基准测试验证历史叙事

  1. 比较单线程与多线程性能，区分延迟和吞吐，不只引用核心数量。
  2. 对照频率、每周期指令数、缓存未命中与功耗，解释性能来自哪里。
  3. 选可并行与串行两类任务，验证 Amdahl 上限与同步成本。
  4. 记录处理器代际、散热条件和编译器版本，避免用不公平环境下的分数推断架构优劣。

练习：一个程序 25% 时间串行、75% 可并行。即使并行部分在无限多核上瞬间完成，理论最大加速是多少？若实际只有 2 倍，可能还受到哪些缓存和同步因素影响？

读历史数据时的三个陷阱

第一，不同年代的性能基准和编译器不同，不能把主频直接当作跨代性能。第二，工艺节点的商业名称不等同于某一物理尺寸，不能仅凭“几纳米”推算晶体管密度。第三，功耗数字要注明是峰值、典型值还是整机测量。把这些口径写清，才能比较技术路线而不是比较宣传标签。

用 Amdahl 定律算一次上限

若程序 25% 时间必须串行、75% 可以并行，给并行部分无限多计算资源，总耗时仍有原来的 25%，理论最大加速为 4 倍。若增加到 8 个相同核心，理想化加速为 1/(0.25+0.75/8)，约 2.91 倍；真实系统还会受锁、内存带宽和任务调度影响。这个算例解释了为何晶体管预算改投多核后，软件需要重新组织并行工作，也解释了为何单线程基准不能代表整机吞吐。历史上的频率放缓并未停止性能改进，只是把改进来源转向更多架构与软件协同。

比较手机与服务器芯片时，峰值性能也不能直接类比：散热空间、持续功耗和电池约束不同。手机处理器可能短时间达到高频，随后降频；服务器更看重持续吞吐与每瓦性能。历史趋势要结合工作负载和持续时间解释。

“功耗墙”说明单位面积可承受热量有限，不表示所有处理器都停止进步。专用计算、封装与软件并行化继续改变性能曲线，只是不能再依赖单一路线。

评价新架构时，应同时给出性能、功耗和成本口径。

这也解释了架构演进为何不能只画一条主频曲线。

摩尔定律与登纳德缩放的量化事实

登纳德缩放失效是 CPU 发展史的分水岭：在此之前，晶体管变小 → 电压降低 → 功率密度不变 → 可以不断提高频率（1990 年代主频从 33MHz 涨到 3GHz，100 倍）。2005 年后漏电电流占比上升，继续提高频率会导致芯片烧毁，频率被迫停在 4GHz 左右。产业界的应对就是转向多核——这也是为什么「并发编程」从可选技能变成了必备技能。

Amdahl 定律的实际计算

# Amdahl 定律：加速比 = 1 / (s + (1-s)/N)
# s = 串行部分占比，N = 处理器核数
def speedup(s, N):
    return 1.0 / (s + (1 - s) / N)

for s in (0.0, 0.01, 0.05, 0.1, 0.2):
    row = [f"s={s:.0%}"]
    for N in (2, 4, 8, 16, 64, 1024):
        row.append(f"N={N}:{speedup(s,N):.2f}")
    print("  ".join(row))

# 输出（示意）：
# s=0%     N=2:2.00  N=8:8.00  N=64:64.00  N=1024:1024.00   <- 完全并行，线性
# s=1%     N=2:1.98  N=8:7.48  N=64:39.02  N=1024:91.09     <- 上限 100
# s=5%     N=2:1.90  N=8:5.93  N=64:16.00  N=1024:19.75     <- 上限 20
# s=10%    N=2:1.82  N=8:4.71  N=64:9.14   N=1024:9.91      <- 上限 10
# s=20%    N=2:1.67  N=8:3.33  N=64:4.88   N=1024:4.98      <- 上限 5

# 结论：即使只有 5% 的串行部分，1024 核也只能加速 19.75 倍（理论上限 20）
# 这就是为什么「堆核数」的边际收益递减得这么快
# Gustafson 定律（更乐观的视角）
# 现实中问题规模会随算力增长（不是固定工作量）
# 加速比 = N - s*(N-1)   （s 是串行占比，N 是核数）
def gustafson(s, N):
    return N - s * (N - 1)

# s=5% 时：N=1024 -> 1024 - 0.05*1023 = 972.85
# 与 Amdahl 的 19.75 天差地别！
# 区别：
#   Amdahl  = 固定工作量，看能快多少（强扩展）
#   Gustafson = 固定时间，看能做多大的问题（弱扩展）
# 实践：大数据/AI 场景更符合 Gustafson（数据变多而不是要求变快）

深入自检

摩尔定律死了吗？

严格意义上（每 2 年翻倍）已经明显放缓。3nm 之后每代提升约 15~20% 而非 100%，且成本急剧上升。产业界转向先进封装（Chiplet）和专用加速器来延续性能增长。

为什么 CPU 主频停在 4GHz？

登纳德缩放失效后，功耗 P ∝ C·V²·f，提高频率 f 会线性增加功耗，而散热能力有物理上限（芯片表面功率密度约 100 W/cm²，接近电炉）。所以只能降电压、堆核心。

多核能一直解决性能问题吗？

不能，受 Amdahl 定律限制。串行部分哪怕只有 5%，加速上限就是 20 倍，再多的核也没用。所以优化的重点往往是减少串行部分（拆锁、分片、无锁化），而不是加核。

为什么现在都在做专用芯片（GPU/TPU/NPU）？

通用 CPU 的能效比差。同样的矩阵乘法，GPU 的能效比 CPU 高 10~100 倍，因为去掉了乱序执行、分支预测等通用逻辑，把晶体管全用在算数单元上。这是摩尔定律放缓后的必然选择。

这些对写代码的我有啥影响？

① 别指望单核变快，并发是刚需；② 优化串行瓶颈（锁、单点）比加机器有效；③ 计算密集型任务考虑用 GPU/向量化指令；④ 数据量增长时按 Gustafson 思路扩展。

自检

摩尔定律能直接推出单线程性能翻倍吗？

不能。晶体管数量、频率、功耗和软件可利用程度是不同变量。

多核为什么不能无限加速所有程序？

串行部分、同步、通信和内存瓶颈会限制整体收益。
