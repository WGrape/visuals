2Python：生成器协程

def gen():
    x = yield "start"   # 这里挂起，外部 send(x) 恢复并赋值
    yield x * 2

g = gen()
print(next(g))      # start
print(g.send(10))   # 20

3Go：goroutine

go func() {
    for i := 0; i < 3; i++ {
        fmt.Println(i)
    }
}()  // 立即返回，函数并发执行
要点：Go 的 goroutine 由 runtime 调度到少量 OS 线程；阻塞系统调用时 runtime 把其他 goroutine 移到别的线程，不卡住。

4栈归属：为什么重要

  • 无栈协程（Python async / C++20）：切换不换栈，状态存在堆上，单线程内并发。
  • 有栈协程（Go）：每个 goroutine 有自己的栈，能调用任意深度的同步代码而不爆栈。
  • 有栈使你能在 goroutine 里写『看起来同步』的代码，runtime 在底层帮你异步化。

5怎么选

问：想写同步风格却要并发？

Go 的 goroutine 最自然：直接 go func()，runtime 接管调度。

问：单线程高并发 IO？

Python asyncio / Node 事件循环足够，且无需考虑数据竞争。

第一层 · 概念与判定：协程到底是什么

协程是用户态的轻量并发单元，切换不进内核，开销远小于线程。但它有三种形态，差异比「都叫协程」大得多。

形态代表栈

无栈协程Python async / C++20 co_await共享栈/状态机，靠 await 让出
生成器式Python generator最简，只能单向 yield

Go 百万协程 vs Python asyncio 示例

// Go：轻松起百万 goroutine（栈按需增长）
for i := 0; i < 1_000_000; i++ {
    go func(id int) { do(id) }(i)
}
// Python：asyncio 单线程，await 才让出
async def main():
    await asyncio.gather(*[do(i) for i in range(100_000)])

数量级直觉：线程默认 8MB 栈，开 1000 个就是 8GB；goroutine 2KB 起步，100 万也才约 2GB，且多数用不到。

第三层 · 排障与边界：三个高频坑

  • goroutine 泄漏：开了没退出（channel 没人收/context 没 cancel），数量只涨不跌——用 pprof 看 goroutine 数
  • 阻塞事件循环：asyncio 里写了同步重活或 time.sleep，整个循环卡死，所有协程等它
  • 忘记取消：context 没传下去，超时/退出时子协程继续跑
  • 共享变量竞态：无栈协程在 await 点可能切换，await 之间的非原子操作会交错——该加锁加锁

第四层 · 原理与取舍

为什么「栈归属」在协程里这么重要？

有栈协程（Go）每个单元独立栈，调度器可抢占，写起来像同步代码、不怕阻塞；代价是栈内存与调度开销。无栈协程（Python/C++20）不单独占栈，靠 await 显式让出，零栈开销、可海量，但必须主动 await，一旦在协程里跑同步重活就阻塞整个循环。选型先看「你的负载是 IO 等待多还是计算多」。

Go 为什么能轻松开百万 goroutine？

因为 goroutine 初始栈仅 2KB 且动态增长，调度在用户态（G-M-P 模型），切换不进内核；而线程 8MB 栈 + 内核调度，开几千就内存/上下文切换爆了。百万 goroutine 的前提是大部分时间在 IO 等待，真在计算它们也会占满 CPU。

无栈协程（async/await）的致命限制是什么？

它没有自己的调用栈，不能在内层函数里「挂起后回到外层」——所有 await 必须在 async 函数链上显式写出。所以同步库、阻塞调用在协程里会卡死整个事件循环，必须全程 async 化或用 run_in_executor 丢到线程池。这是无栈协程轻量但「侵入性强」的根源。
