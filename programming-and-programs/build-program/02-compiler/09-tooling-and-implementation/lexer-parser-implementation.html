词法

词法分析：把字符流切成 Token

词法分析器（Lexer / Scanner）读入字符，输出 Token 序列：标识符、关键字、字面量、运算符、分隔符，并丢弃空白与注释。

// 典型手写实现：逐字符扫描 + 状态推进
type Lexer struct {
    input string
    pos   int
}

func (l *Lexer) NextToken() Token {
    l.skipWhitespace()
    ch := l.input[l.pos]
    switch {
    case isLetter(ch):  return l.readIdentifier()  // 关键字或标识符
    case isDigit(ch):   return l.readNumber()
    default:            return l.readOperator()
    }
}
实现要点：① 关键字通常先按标识符扫描，再查表区分；② 用最长匹配原则（如 == 不能拆成两个 =）；③ 记录行号列号以便报错。
路线

两条路线：手写 vs 生成

路线代表优点缺点
手写递归下降GCC 早期、Go 早期、V8错误信息友好、易调试、可随意加特例只适合 LL 类文法，左递归需改写
生成器Yacc/Bison、ANTLR、JavaCC处理能力强（可 LR）、文法变更快错误信息差、调试困难、生成代码难改
工业界趋势：现代主流语言（Go、Rust、TypeScript、V8）多选择手写递归下降——因为可控性强、错误提示好，而语言文法通常设计得便于手写分析。
实现

递归下降的三个要点

① 每个文法规则对应一个函数

// 文法：expr := term (('+' | '-') term)*
func (p *Parser) parseExpr() AST {
    left := p.parseTerm()
    for p.cur == PLUS || p.cur == MINUS {
        op := p.cur; p.next()
        right := p.parseTerm()
        left = &BinaryExpr{Op: op, Left: left, Right: right}
    }
    return left
}

② 用「优先级爬升」处理运算符优先级

把优先级低的规则放在外层、高的放内层（expr → term → factor），天然实现乘除优先于加减。

③ 前看（lookahead）决定分支

递归下降通常只需 1 个 Token 的前看即可选择产生式；若不够，说明文法不是 LL(1)，需要改写或增加前看。

体验

错误恢复：别让一个错刷屏

  • 恐慌模式（Panic Mode）：发现错误后跳过 Token 直到遇到同步点（如分号、右花括号），继续解析后续内容。
  • 错误产生式：在文法里显式写「常见错误形式」，给出更精确的提示。
  • 限制报错数量：连续错误过多就停止，避免刷屏。
  • 带位置信息：每个 Token 记录行列，报错才能指到源码位置。
好的编译器体验来自错误质量，而非解析算法多先进。能一次报出所有错误、每条都指到具体行列，是实用 Parser 的关键。
面试问答

高频问题

Q1：手写 Parser 和用生成器的取舍？
手写可控性强、错误提示友好、便于加特例，适合产品级语言实现（Go、V8、TypeScript 都手写）；生成器处理能力强、文法变更快，适合解析现成复杂文法（如 SQL），但错误信息差、调试难。
Q2：递归下降如何处理运算符优先级？
用「优先级爬升」：为每级优先级写一个函数，高优先级在低优先级的内层被调用。如 expr 调用 term，term 调用 factor，从而天然保证乘除优先于加减。
Q3：递归下降能处理左递归吗？
不能直接处理，左递归会导致无限递归。需要改写成右递归或迭代形式（如用 while 循环处理 expr := expr + term 这类规则）。
Q4：什么是 LL(1)、LR(1)？
LL(1) 从左到右扫描、最左推导、只需 1 个 Token 前看，适合手写递归下降；LR(1) 是最右推导的反向分析，表达能力更强（能处理左递归），常由 Yacc/Bison 这类生成器实现。
Q5：词法分析中关键字怎么识别？
通常先按标识符规则扫描出一串字符，再查关键字表判断是否保留字。这样避免为每个关键字单独写匹配规则。
Q6：什么是恐慌模式错误恢复？
发现语法错误后，跳过若干 Token 直到遇到同步记号（如分号、右括号），再继续解析。目的是一次扫描尽可能报出多个错误，而不是遇到第一个错就停止。
