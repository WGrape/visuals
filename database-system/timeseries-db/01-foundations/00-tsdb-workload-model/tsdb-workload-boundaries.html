什么时候需要时序数据库？

从持续写入、时间窗口聚合和历史保留成本判断专用时序引擎的价值。

不是所有时间戳数据都必须迁库

Q：监控数据什么时候需要从 MySQL 转向 TSDB？
A：MySQL 可以承载一定规模的监控数据，分区表、批量写入和合理索引也能延长适用范围。若持续写入、长时间保留和时间窗口聚合使索引维护、存储或历史清理成本过高，再用真实负载比较专用 TSDB；不能仅凭产品类别断言 MySQL 一定写不动或删不掉。

若现有关系库经分区和批量写入已满足 SLO，先测量真实瓶颈；专用 TSDB 的价值来自大规模时间线和保留策略的整体成本。
