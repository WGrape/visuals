①Range：数据分布的最小单位

CockroachDB 把整张表（以及所有索引）按主键顺序切成一段段连续的键值区间，每段叫一个 Range， 默认达到阈值就分裂，变小了会合并。每个 Range 是一个独立的 Raft 组，有自己的副本集合。

Range 是调度、分裂、副本放置的共同单位
与 TiDB 的 Region 概念几乎一一对应（都是按主键有序切段 + Raft 组 + 自动分裂调度）， 但术语不同：CockroachDB 叫 Range + Leaseholder，TiDB 叫 Region + Leader。 具体阈值与默认副本数请以所用版本文档为准，不要照抄旧资料里的数字。

②Leaseholder：读写走谁

每个 Range 的 Raft 组里有一个 Leaseholder（租约持有者），它不同于 Raft Leader 但通常重合：

  • 所有读写请求都先打到 Leaseholder，由它负责一致性读与写入提案。
  • 写仍需走 Raft 达成多数派提交；读在租约有效期内可直接本地返回，省掉一轮 Raft 往返。
  • 租约会过期与迁移。节点挂掉后要等租约超时才能把 lease 转走，这决定了故障恢复时间。
  • Leaseholder 分布不均会造成读热点，需要通过负载均衡或打散主键缓解。
Follower Reads：允许从非 Leaseholder 的副本读取略旧的数据 （例如 AS OF SYSTEM TIME 指定一个过去的时间戳）。 代价是牺牲实时性，收益是不用跨区访问 Leaseholder——在多区域部署下能把读延迟从跨洲降到本地。 适合报表、对账、历史查询这类容忍几十秒~分钟级延迟的场景。

③一致性、时钟与事务重试

混合逻辑时钟（HLC）

CockroachDB 用 HLC 而非 TrueTime：物理时钟 + 逻辑计数器， 节点间时钟偏差超过阈值会触发告警。它不能消除时钟偏差的影响， 只是把偏差限制在可观测范围内。

Serializable 是默认隔离

默认提供最强的可串行化隔离，而不是常见的「读已提交」。 好处是没有幻读与写偏斜，代价是写冲突更常见、必须处理重试。

40001 重试错误

事务因冲突被中止时返回特定错误码，应用层必须重试整个事务。 这是使用 NewSQL 最容易踩的坑：把重试逻辑漏掉，就会随机报错。

幂等是前提

重试意味着同一事务可能被执行多次（或部分执行后回滚）。 写入必须是幂等的，或依赖事务原子性保证「要么全成要么全不成」。

-- 客户端侧重试伪代码（各语言驱动有现成封装）
for attempt := 0; attempt < maxRetry; attempt++ {
    err := txn(ctx, func(tx *Tx) error {
        // 整段业务逻辑必须放在闭包里，重试时会整体重跑
        ...
    })
    if err == nil { return nil }
    if isRetryable(err) { continue }   // 40001 类错误
    return err
}
不要把重试放在事务内部，也不要只重试单条语句。 可串行化下被中止的是整个事务，重试单条语句会产生部分写入。 标准做法是「整个业务闭包 + 指数退避重试 + 幂等键」三件套。
