A/B 测试手算：1000 人各一组，10% 与 12% 能宣布胜利吗

用转化率差、标准误和近似置信区间解释样本波动、反复偷看与决策门槛。

先把观察值和真实效果分开

A 组 1000 人中 100 人转化，观察转化率 10%；B 组 1000 人中 120 人转化，观察转化率 12%。页面上 B 比 A 高 2 个百分点，按相对比例是 20% 提升，但这只是这批样本的观察差，不等于真实长期效果精确为 2 个百分点。随机分组也会产生自然波动，需要估计不确定性。宣称“B 获胜”还要事先定义主指标、最小有意义效果、样本量和停止规则。

检查样本分配比：若计划 50:50，实际却严重偏向一组，可能是分流、埋点或过滤条件出了问题。随机化单位也要和指标一致；按请求随机却按用户统计，会让一个人跨组，污染结果。

图解：两组转化率的粗算路径

沿箭头逐步核对输入、变换和输出；下面的推演可以逐步切换。

粗算一次区间

两组独立且每人只计一次转化时，观察差是 0.12−0.10=0.02。近似标准误可按 sqrt[0.10×0.90/1000 + 0.12×0.88/1000] 计算，约为 0.0140。用正态近似，95% 区间大致是 0.02±1.96×0.0140，即约 −0.74 到 +4.74 个百分点。区间包含 0，按常见双侧 5% 门槛，这批数据不足以排除“真实差为 0”。这也不证明两组完全相同；它只是说明目前数据还不够精确。

这个近似依赖随机独立样本、足够事件数和普通二项模型。若用户在多个设备重复出现、团队或城市集群随机化、低基数转化、序贯设计等，标准误计算要调整。财务指标还常有长尾分布，不能把转化率的二项公式套到客单价。

逐步推演

记录样本

A:100/1000，B:120/1000。

算观察差

B 比 A 高 2 个百分点。

估不确定性

标准误约 1.40 个百分点。

给出区间

近似 95% 区间约 −0.74 到 4.74 个百分点。

p 值不是“B 为假的概率”

在零假设“真实转化率相同”及检验模型成立时，p 值描述观察到当前或更极端数据的概率。它不是“零假设为真的概率”，也不等于“B 上线后有多大概率成功”。本例按普通近似双侧检验，标准化差约 1.4，未达到常见 1.96 阈值；不同精确检验与修正方法数值可能略有差异。不要看到 12% 大于 10% 就跳过不确定性。

即使统计上显著，也要问商业上是否值得。若提升只有 0.1 个百分点，却引入昂贵系统复杂度或损害留存，可能不该上线。反过来，样本不足而区间很宽，不应把“未显著”说成“没有效果”。报告应同时给绝对差、相对差、区间和样本量。

量本例数值解释
绝对差2 个百分点12%−10%
相对差20%2/10
标准误约 1.40 个百分点抽样波动尺度
近似 95% 区间约 −0.74～4.74 个百分点仍包含 0

每小时偷看会发生什么

若设计的是“固定样本量后检验一次”，却每小时查看一次 p 值，一旦低于 0.05 就停，假阳性概率会高于单次检验标称值。因为多次观察给了随机噪声更多越过阈值的机会。要么预先固定样本量与观察终点，要么采用适当的序贯检验或持续监控设计；不能临时挑一个最漂亮的时刻截图。

同时试十个按钮颜色、三个用户群、两个转化口径，最后只汇报最好的一个，也会放大偶然发现。应预先定义主指标和关键分层，对多重比较采取合适处理，并保留所有尝试的记录。探索性结果可以帮助生成下一次实验假设，但不宜伪装成事先确认的结论。

上线决策还要看护栏

B 组主转化率略高，却可能增加退款、延迟或客服投诉。实验应设护栏指标并检查分层效果：新老用户、端点、地区等重要群体是否出现有害退化。分层样本少时区间更宽，不能因为某个小群体的极端数值就武断判断。实验持续时间还应覆盖周内周期与典型高峰，避免仅测一晚就推断全月。

日志要记录分流 ID、曝光时点、转化归因窗口、重复用户处理和排除规则。若实验开始后才不断修改指标定义，分母变化可能制造虚假的改善。

回到 100 与 120

观察 B 多 20 个转化，但在 1000 人每组的样本下，近似区间跨过零。下一步应检查试验是否按计划运行、样本量是否达到预设目标、数据口径是否可靠，再按既定规则决定继续采样或结束。不能仅凭“增加了 20 个转化”断言长期必胜，也不能把试验延长到恰好显著为止。

练习：把两组样本量都扩大到 10000，比例仍为 10% 和 12%。估算标准误会缩小到原来的约多少？为何同样 2 个百分点差更容易被统计检测到？

第一层 · 概念与判定：偷看为什么是错的

偷看（peeking）指在实验还没跑完时反复查看结果，一旦看到显著就提前停止。它的问题不是「不好看」，而是把假阳率从 5% 抬高到 30% 以上。

做法假阳率（名义 5%）结论可靠性
跑到预定样本量，只看一次5%正确
中途看了 2 次约 8 – 10%已开始失真
每天看一次，看到显著就停20 – 30%严重失真
持续监控、随时可停（无校正）> 50%基本不可信

原理一句话：每多看一次，就多一次「撞上随机波动」的机会。就像抛硬币 100 次，总会出现连续 5 个正面 —— 如果你盯着等它出现，就一定能等到，但这不证明硬币有问题。

第二层 · 参数·命令·量化：样本量要多少

要检测的指标变化基线转化率每组所需样本量（约）说明
相对提升 10%5%约 3 万 每组常见电商场景
相对提升 5%5%约 12 万 每组小提升代价很高
相对提升 2%5%约 75 万 每组只有大流量业务能做
相对提升 1%5%约 300 万 每组通常不现实

计算 A/B 实验所需样本量

# 用 Python 计算 A/B 实验所需样本量
from statsmodels.stats.power import NormalIndPower
from statsmodels.stats.proportion import proportion_effectsize
import math

power = NormalIndPower()

def sample_size(p1, lift, alpha=0.05, power_=0.8):
    p2 = p1 * (1 + lift)
    es = proportion_effectsize(p2, p1)
    n = power.solve_power(effect_size=es, alpha=alpha,
                          power=power_, ratio=1, alternative='two-sided')
    return math.ceil(n)

print('基线 5%%，提升 10%% 时每组需要:', sample_size(0.05, 0.10))
print('基线 5%%，提升 5%%  时每组需要:', sample_size(0.05, 0.05))
print('基线 5%%，提升 2%%  时每组需要:', sample_size(0.05, 0.02))

# 注意：样本量随「要检测的提升幅度」呈平方反比
# 提升幅度减半，样本量约变为 4 倍

关键公式：每组样本量 n ≈ 16 × p(1−p) ÷ (提升量)²（80% 检验功效、5% 显著性）。分母是平方项 —— 这就是小提升如此昂贵的原因。

第三层 · 排障与边界

高频坑清单：

  • ① 偷看并提前停止：最常见的错误，会把假阳率抬高数倍
  • ② 样本量没算就开跑：跑到一半发现要 100 万样本，实验永远结束不了
  • ③ 只看 p 值不置信区间：p<0.05 只说「有差异」，不说「差多少」
  • ④ 同时测多个指标：测 20 个指标，必然有 1 个显著（多重比较问题）
  • ⑤ 中途改实验：换了文案或调了流量，前后数据不可合并
  • ⑥ 忽略新奇效应：新功能初期数据会异常，要跑满一个完整周期

正确做法清单：

  • ① 开跑前先算样本量，并写死预计结束时间
  • ② 想中途看，就用序贯检验（如序贯概率比检验）或贝叶斯方法，它们允许持续监控
  • ③ 否则必须固定样本量，跑完再看
  • ④ 报告结果时必须给置信区间，而不只是 p 值
  • ⑤ 同时测多个指标时做多重比较校正（如 Bonferroni）
  • ⑥ 实验至少跑满一到两个完整业务周期（通常 1–2 周）

第四层 · 原理与取舍

为什么必须跑满样本量？不能看到显著就上线吗？

因为显著性是概率意义上的，不是确定性的。固定样本量下 p<0.05 意味着「如果真的没差异，有 5% 概率误判为有差异」。但如果你每天看一次、看到就停，相当于给了随机波动多次机会去触碰那条线 —— 即使 A 和 B 完全一样，跑久了也总会有一刻 p<0.05。这时你上线的其实是噪声。

置信区间为什么比 p 值更有用？

因为 p 值只回答「有没有差异」，而置信区间回答「差异可能有多大」 —— 后者才是决策需要的。比如「提升 0.1%，95% CI [−0.5%, +0.7%]」告诉你的信息是：可能有提升也可能没有，即使显著也不值得上线；而「提升 8%，95% CI [+6%, +10%]」才是真正该上的。只看 p 值会让你为统计显著但业务上无意义的变化付出成本。

实在想提前结束怎么办？

用为「随时可停」设计的统计方法，不要硬套固定样本量检验：① 序贯检验（SPRT、mSPRT）—— 在保持误差率的前提下允许边看边停；② 贝叶斯 A/B —— 直接输出「B 更好的概率」与「预期损失」，业务上更直观，且天然支持持续监控；③ Always-valid 置信区间 —— 任意时刻查看都有效。主流实验平台（Optimizely、Google）现在都默认用这类方法。

自检

B 的观察转化率比 A 高 20%（相对值），就能宣称 B 的真实效果一定为正吗？

不能。本例近似 95% 差值区间跨过 0，还要核对样本量、分流与停止规则。
