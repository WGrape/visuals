概述

显式优于魔法

Go 的元编程刻意克制：没有宏与模板元编程，主要靠运行时反射与编译期代码生成两条可控路径。

反射回顾

能不用就不用

reflect 在运行时检视/构造类型，灵活但慢且易 panic；仅当类型在写代码时尚不确定时才上（如通用序列化）。

能用泛型/接口表达的逻辑，优先它们；反射是最后手段。
生成优先

编译期更稳

代码生成把「不确定」在编译期变成「确定的 Go 代码」，可读、可调试、零运行时开销，是 Go 的首选元编程。

//go:generate stringer -type=Op
// 生成 op_string.go，运行期直接查表
语法树

解析与改写

go/ast + go/parser 可读取并分析源码，用于 lint、代码生成、自动重构；gofmt 本身也基于它。

fset := token.NewFileSet()
f, _ := parser.ParseFile(fset, "a.go", nil, 0)
ast.Inspect(f, func(n ast.Node) bool {
    if id, ok := n.(*ast.Ident); ok { println(id.Name) }
    return true
})
如何选择

看时机

编译期已知结构 → 代码生成；类型在运行期才确定 → 反射；想分析/改写代码 → go/ast。

⚠️ 反射绕开类型系统，维护成本高；能用生成的就别反射，能用接口的就别反射。
