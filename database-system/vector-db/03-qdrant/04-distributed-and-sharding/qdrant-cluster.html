①shard / replica / 写一致性的三个旋钮

Qdrant 的分布式设计与 Milvus 完全不同：它不做存算分离，而是把同一套段模型搬到多节点上，用 Raft 维护集群元数据的一致性。理解这一点，才能理解它的一致性语义和扩展边界。

概念含义默认值影响
shard（分片）集合数据按点 id 哈希切成的份数sharding_method 自定义时设置，常规默认 1决定单个集合能否分散到多节点
replica（副本）每个分片的拷贝数replication_factor 默认 1读吞吐与高可用
write_consistency_factor写入需多少副本确认默认 1写延迟 vs 写后可见性
shard_number建集合时确定，之后修改代价高1建集合前必须想清
Qdrant 的分片数在建集合时就定下来了，事后调整需要重分片（1.8+ 提供分片迁移能力，但代价不小）。经验做法：预估最终数据量，按「单分片 100 万~500 万点」倒推 shard 数，宁多勿少。

②单机与分布式两套形态

单机版和分布式版不是开关切换，而是两套部署形态：

形态怎么跑数据上限（经验）高可用
单机一个容器 / 一个二进制千万级以内，受单机内存限制无（靠快照恢复）
分布式多节点 + 集群模式，节点间 Raft亿级，随节点线性扩展靠 replication_factor ≥ 2
Qdrant Cloud托管，含 hybrid cloud视套餐平台负责
# 起一个三节点集群（docker 示例）
docker run -p 6333:6333 -p 6335:6335 \
  -e QDRANT__CLUSTER__ENABLED=true \
  -e QDRANT__CLUSTER__P2P__PORT=6335 \
  -e QDRANT__CLUSTER__CONSENSUS__TICK_PERIOD_MS=100 \
  -v $(pwd)/node1:/qdrant/storage qdrant/qdrant

③读取为什么是最终一致

这是选型时最需要说清的一点：Qdrant 的读取是最终一致的。写入成功返回，不代表所有副本都能立刻读到。

操作语义需要注意
写（upsert）写入 leader 分片，按 write_consistency_factor 等待副本确认默认只等 1 个，其他副本异步
读（search）可路由到任一副本刚写入的点可能读不到
删除标记删除 → vacuum 异步清理删除后仍可能被召回，直到 vacuum 跑完
应对办法和 Milvus 的 Session 一致性是同一个思路：写后读的场景不要依赖向量库自身的可见性，而是在业务层用「写入返回的 id 直接回表」或短暂等待。RAG 场景里刚上传的文档搜不到，多半就是撞在这里。

④多租户三种方案与越权风险

多租户在 Qdrant 里有三种做法，代价差异很大：

方案隔离强度开销适用
payload 过滤（tenant_id）逻辑隔离低（需建 payload 索引）租户多、单租户数据少（默认选择）
每租户一个 collection物理隔离高（每个 collection 有固定开销）租户少、单租户数据大、需独立配置
multitenancy 模式 + 自定义分片物理隔离中大客户单独分片，长尾共享
payload 过滤的最大风险不是性能而是越权：只要有一个查询忘了带 tenant_id 条件，就会跨租户返回数据。务必在 SDK 封装层强制注入租户条件，而不是指望每个调用点都记得写。

⑤扩展瓶颈会依次转移到哪

水平扩展不是加机器就完事，瓶颈会依次转移。按经验顺序排查：

阶段瓶颈现象对策
1 万 → 100 万基本无瓶颈单机即可别急着上集群
100 万 → 1000 万单机内存 / HNSW 构建时间导入后索引建得久量化 + 提高索引并发
1000 万 → 1 亿内存与查询并发p99 抖动，QPS 上不去多副本 + shard 分散
1 亿以上全量重建与运维成本重建要数小时考虑 DiskANN 类磁盘索引或分业务拆库

⑥速记卡

shard 数建时定

shard_number 事后调整代价大，宁多勿少。

replica 决定读

replication_factor ≥ 2 才有高可用。

写一致性

write_consistency_factor 默认 1，其他副本异步。

读取最终一致

刚写入的点可能读不到；写后读别依赖向量库。

删除同理

标记删除 + vacuum，删完还可能被召回。

多租户默认

payload 过滤 + 强制注入 tenant 条件。

越权风险

忘记加租户条件就跨租户，必须在 SDK 层兜住。

扩展节奏

千万级前单机就够，别提前上集群。

上集群的前提是单机真的扛不住了。千万级以内的 RAG 用单机 Qdrant 加量化，往往比维护一套集群更省心也更快。
