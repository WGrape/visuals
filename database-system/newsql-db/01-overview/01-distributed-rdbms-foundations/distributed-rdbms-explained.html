一句话总结：当单机 MySQL 扛不住时，传统做法是「分库分表 + 中间件」—— 把分布式复杂性甩给应用层。NewSQL（原生分布式关系型数据库）的做法相反： 让数据库自己解决分片、分布式事务、全局一致性读与弹性扩缩容，对应用伪装成一个单机库。

01单机数据库的三个天花板

💾 容量天花板

单实例通常 2～5 TB 是运维舒适区。再大，备份、DDL、故障恢复时间都会失控。 数据量到几十 TB 就必须拆。

⚡ 写入天花板

单机写受限于主库 binlog 顺序写与 redo 刷盘。 主从架构下写无法水平扩展——加再多从库也只解决读。

🧮 连接与 CPU

单机 CPU 核数有限，复杂查询、高并发事务会打满。 连接数也有上限，几千连接就接近瓶颈。

于是有了两条路线：中间件分库分表（ShardingSphere、MyCat）与原生分布式数据库（TiDB、OceanBase、CockroachDB）。

02路线一：分库分表 + 中间件

问题说明
分片键决定一切查询必须带分片键才能路由到单分片；不带就全分片扫描再归并，性能灾难。

本质问题：中间件方案里，数据库本身仍然不知道自己是分布式的。 所有分布式的复杂性（路由、事务、一致性、扩缩容）都压在中间件和应用层。

03路线二：原生分布式（NewSQL）

NewSQL 的目标是在分布式的前提下，仍然提供完整的 SQL + ACID 事务—— 对应用透明，像用单机 MySQL 一样用。

图 2：原生分布式——存储层自带分片、复制与自动均衡
关键差异：存储层自己知道数据在哪、如何复制、如何迁移。 扩容只需加机器，系统自动把 Region 迁过去做均衡——无需人工数据迁移，无需改分片规则。

04NewSQL 的四大关键技术

① 自动分片（Range / Hash）

数据被切成小块（TiDB 叫 Region，OceanBase 叫 Partition），默认 96～144 MB 一块。 按 Range 分片自动分裂：Region 超过阈值就一分为二。范围查询友好，且不需要预先规划分片数。

② 多副本一致（Raft / Paxos）

每个分片有多个副本（通常 3 个），通过Raft 一致性协议同步。 写入需多数派确认，少数派故障时自动选主恢复——RPO=0、RTO 秒级。 这是 NewSQL 高可用能力的来源。

③ 分布式事务（2PC + 乐观/悲观锁）

跨分片事务用两阶段提交：Percolator 模型（TiDB）或标准 2PC（OceanBase）。 关键是全局授时服务 TSO 提供单调递增的时间戳，配合 MVCC 实现 全局一致性快照读——这是单机 MySQL 都很难做到的。

图 3：2PC——要么都提交，要么都回滚；协调者故障会导致事务悬挂，需靠日志恢复

④ HTAP：一套数据，两种负载

传统架构要维护「行存主库 + 列存分析库」两套数据和同步链路。 HTAP 在同一份数据上同时支持：行存副本服务 TP、列存副本服务 AP， 通过 Raft 日志实时同步，物理隔离但逻辑一致。

TiDB 的做法

TiKV（行存）服务事务，TiFlash（列存）作为 Raft Learner 异步复制， 优化器按代价自动选择走行存还是列存。

OceanBase 的做法

同一份基线数据（SSTable）之上，既有行存内存增量也有列存副本， 通过分布式计划同时利用两类副本。

重要提醒：NewSQL 不是万能的。它用网络开销换扩展性与高可用。 单分片内的点查点写，TiDB 的延迟一定高于单机 MySQL（多一跳网络 + 分布式事务）。 数据量没到瓶颈时，不要为了"先进性"上分布式——单机 MySQL 更简单也更快。

06常见疑问

Q：什么时候该考虑从单机 MySQL 迁移到 TiDB？
A：三个信号——① 单表数据量到几千万～上亿且还在快速增长； ② 主库写入已经打满（加从库解决不了）； ③ 做过分库分表但被跨片查询/扩容折磨。 反之如果只是读压力大，读写分离 + 缓存就够了，别过度设计。
Q：NewSQL 的分片键还需要设计吗？
A：需要，但目的变了。NewSQL 按 Range 自动分片，不需要预先规划分片数； 但如果表是自增主键，写入会全部集中在最后一个 Region，形成写热点。 解法是用 SHARD_ROW_ID_BITS 打散、或用 UUID/雪花 ID 作为主键。 这是 TiDB 上最常见的性能问题。
Q：既然有分布式事务，跨分片 JOIN 就能随便用了吗？
A：不能。跨分片 JOIN 需要把数据在网络间搬运（Shuffle Join），代价远高于本地 JOIN。 正确做法仍是让高频 JOIN 的两张表按相同规则分布（TiDB 的分区表 + placement rules 或 Doris 的 Colocate）， 把跨节点 JOIN 变成本地 JOIN。
