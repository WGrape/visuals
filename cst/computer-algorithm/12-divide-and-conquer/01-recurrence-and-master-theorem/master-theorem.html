第 12 章 · 分治

比较叶子代价与合并代价

把分治写成 T(n) = aT(n/b) + f(n)，用主定理三种情形（叶子主导、逐层相当、根主导）直接读出复杂度，并识别它不适用的场景。

分治的代价是一句递推式

分治把一个规模 n 的问题分成 a 个规模 n/b 的子问题，再用 f(n) 的代价把子问题的解合并起来，于是复杂度就是递推式：

T(n) = a·T(n/b) + f(n)        a ≥ 1, b > 1
  • a：子问题个数（归并排序 a=2，二分查找 a=1，Strassen a=7）。
  • b：规模缩小倍数（通常是 2）。
  • f(n)：分解 + 合并的总代价（归并排序是 O(n) 的合并，二分查找是 O(1) 的比较）。

写递推式时最容易错的是 f(n)：它不含递归调用本身，只含「拆」和「合」这两步的代价。

主定理：比较合并代价与子问题总量

令 c = logb a，也就是递归树叶子层的量级。主定理说：T(n) 由 nc 与 f(n) 谁更大决定。

情形条件结论直觉
情形 1f(n) = O(nc−ε)，ε > 0T(n) = Θ(nc)叶子层主导：合并很便宜，代价全在递归到底
情形 2f(n) = Θ(nc)T(n) = Θ(nc log n)每层代价相当：树高 log n，每层都贡献一份
情形 3f(n) = Ω(nc+ε) 且 a·f(n/b) ≤ k·f(n)（k<1）T(n) = Θ(f(n))根节点主导：分解合并就够贵了
归并排序：a=2, b=2, c=1, f(n)=Θ(n) → 落在情形 2 → T(n) = Θ(n log n)。
二分查找：a=1, b=2, c=0, f(n)=Θ(1) → 情形 2 → Θ(log n)。

主定理不适用的三种情况

  1. 子问题规模不是等分的：如 T(n) = T(n−1) + T(n/2) + n，b 不固定，用递归树或 Akra–Bazzi 通式。
  2. 每种情形之间恰好卡在边界：比如 f(n) = Θ(nc log n)，属于情形 2 的扩展，结论是 Θ(nc log² n)，不能硬套基本形式。
  3. 情形 3 的正则条件不满足：f(n) 增长得不够平滑（例如振荡函数），此时主定理给不出结论。

更通用的工具是 Akra–Bazzi 方法：解出满足 Σ aᵢbᵢp = 1 的 p，则 T(n) = Θ(np(1 + ∫₁ⁿ f(u)/up+1 du))。考试与面试里掌握主定理三种情形 + 递归树足够。

最容易踩的两个坑

  • 把平均情况和最坏情况混在一句递推式里：快排平均是 T(n) = 2T(n/2) + Θ(n)，最坏是 T(n) = T(n−1) + Θ(n)。写递推式前先声明分析的是哪种情况。
  • 忘记 f(n) 里还包含分解代价：快排的划分本身是 Θ(n)，不是 Θ(1)。写成 2T(n/2)+Θ(1) 会得出 Θ(n) 的错误结论。

主定理速算

# 用递归树验证主定理（以 T(n) = 2T(n/2) + n 为例）
# 第 0 层（根）: n
# 第 1 层:       n/2 + n/2      = n
# 第 2 层:       n/4 * 4        = n
# ...
# 共 log n 层，每层 n  ->  总计 n log n   （情形②）

import math
def master(a, b, f_growth):
    """f_growth: f(n) 的指数，如 f(n)=n 传 1，f(n)=1 传 0"""
    c = math.log(a, b)
    if f_growth < c - 1e-9:   return "Theta(n^%.2f)" % c                 # ①
    if abs(f_growth - c) < 1e-9: return "Theta(n^%.2f * log n)" % c      # ②
    return "Theta(f(n))"                                                  # ③

print(master(2, 2, 1))   # -> Theta(n^1.00 * log n)   归并排序
print(master(1, 2, 0))   # -> Theta(n^0.00 * log n)   二分查找
print(master(2, 2, 0))   # -> Theta(n^1.00)           二叉树遍历

关键量级直觉：n^c 是「叶子层」的总代价，f(n) 是「根层」的代价。谁大谁主导；一样大就乘以层数 log n。

第三层 · 排障与边界：主定理用不了的四种情况

情况为什么不行怎么办
a 不是常数（如 T(n)=n·T(n/2)）主定理要求 a 固定用递归树或代入法
子问题规模不相等（如 T(n)=T(n/3)+T(2n/3)）不是 n/b 的均匀划分用递归树 / Akra-Bazzi 定理
情形③ 的正则条件不满足存在反例改用递归树验证
f(n) 与 n^c 差的是对数因子不落在任何情形用扩展情形②：Θ(n^c · log^k n)
  • 排查顺序：先确认形式是不是 a·T(n/b)+f(n) → 再算 c = log_b a → 再比较 f(n) 与 n^c → 最后检查是否落在三种情形。
  • 边界一：b 必须 > 1，a 必须 ≥ 1，且 f(n) 需渐近为正。
  • 边界二：情形③ 要求 a·f(n/b) ≤ k·f(n)（某个 k < 1），即「子层代价严格小于本层」——否则可能有反例。
  • 边界三：实际算法里 n/b 常常是取整的（⌊n/2⌋），严格说要用 Akra-Bazzi，但主定理的结论通常仍然成立。

扩展情形

# 扩展情形②：f(n) 与 n^c 只差对数因子
# T(n) = 2T(n/2) + n log n   ->  c=1, f(n)=n log n
# 属于扩展情形②：T(n) = Theta(n * log^2 n)

# 递归树求和验证：每层 2^i 个子问题，每个规模 n/2^i
# 第 i 层代价 = 2^i * (n/2^i) * log(n/2^i) = n * (log n - i)
# 对 i=0..log n 求和 -> n * log^2 n / 2  -> Theta(n log^2 n)
为什么要比较 f(n) 和 n^(log_b a)？

因为 n^(log_b a) 正好是「所有叶子节点的总代价」：递归树有 a^(log_b n) = n^(log_b a) 个叶子。而 f(n) 是根这一层的代价。所以这个比较本质是「叶子层 vs 根层，谁更大」。

主定理和递归树有什么区别？

主定理是递归树求和的现成结论，能套就套，快但适用范围窄。递归树是通用方法，任何递归式都能画出来求和，但需要自己算级数。主定理用不了时退回递归树。

快排的复杂度能用主定理算吗？

平均情况可以：T(n) = 2T(n/2) + O(n) → O(n log n)。但最坏情况 T(n) = T(n-1) + O(n) 不符合 n/b 的形式（子问题规模是 n-1 不是 n/b），所以要单独算，结果是 O(n²)。

主定理解决什么问题

分治算法的代价天然写成一个递推式：把规模 n 的问题拆成 a 个规模 n/b 的子问题，加上拆与合的额外开销 f(n)。

T(n) = a · T(n / b) + f(n) a 子问题个数 n / b 每个子问题的规模 f(n) 拆分 + 合并的代价 例：归并排序 T(n) = 2·T(n/2) + O(n) 二分查找 T(n) = 1·T(n/2) + O(1)

主定理做的事就是：不需要真的把这个递推式解出来，只要比较 f(n) 和 n 的某个幂次，就能直接读出答案。那个关键的幂次叫临界项：

临界项： n^(log_b a) 直观含义： 所有子问题的叶子层一共有 a^(log_b n) = n^(log_b a) 个节点 换句话说，它就是「光把问题拆到最碎，需要多少个工作」

三种情况，一张图记住

临界项与 f(n) 的三档关系
情况条件结论读懂它的一句话
Case 1f(n) = O(n^(log_b a − ε))，多项式地更小T(n) = Θ(n^(log_b a))叶子层是瓶颈：子树数量多，合并很便宜
Case 2f(n) = Θ(n^(log_b a))，同阶T(n) = Θ(n^(log_b a) · log n)每层代价相同：乘上层数 log n
Case 3f(n) = Ω(n^(log_b a + ε)) 且满足正则条件T(n) = Θ(f(n))根层是瓶颈：合并/拆分太贵，占主导

正则条件（Case 3 必须检验）：需要存在常数 c < 1，使得对所有足够大的 n 都有 a·f(n/b) ≤ c·f(n)。它的作用是保证「子问题层面的代价不会反超」。绝大多数常见函数都满足，少数病态构造会不满足。

第四行特别值得记住：它说明了主定理的价值 —— 把一个看起来复杂的算法代价，变成一次「指数比大小」。Strassen 之所以更快，本质就是它的 a 足够大（7 个子问题），让临界指数超过了朴素的 3 次项。

快速手工套用法 ① 先算 log_b a，得到指数 ② 把 f(n) 写成 n^k 的形式（忽略 log 因子暂不考虑） ③ 比大小： 指数 > k → 答案 n^(log_b a) 指数 = k → 答案 n^k · log n 指数 < k → 答案就是 f(n)，但要检查正则条件

什么时候不能用主定理

  • a 不是常数。例如 T(n) = n·T(n/2) + n，子问题个数随 n 变化，主定理不适用。
  • 子问题规模不等。像 T(n) = T(n/3) + T(2n/3) + n 这种不均匀拆分不在标准形式内（可用 Akra–Bazzi 之类的推广方法）。
  • 落在「缝隙」里。f(n) 与临界项只差一个对数因子而非多项式因子时，三条情况都可能不满足（这就是常说的不适用区间）。
  • f(n) 不规则。函数剧烈震荡、不满足多项式差要求时无法判定。

遇到这些情况的撤退路线：画递归树。把每层的工作量写下来（第 i 层通常有 a^i 个节点、每个节点规模 n/b^i、每层代价 a^i · f(n/b^i)），看它是等比递减、等比递增还是常数和 —— 这个直觉本身就足以推出大多数答案，也是主定理背后的真正逻辑。

深入自检

n/b 不整除怎么办？

实用上直接忽略取整：把一个规模不是整数的问题写成 T(⌈n/b⌉) 或 T(⌊n/b⌋)，最终得到的渐进阶与忽略取整时相同。在严谨求解时需要多做一些技术处理，但对我们判断复杂度阶而言没有影响。

为什么 Case 2 会多出一个 log n？

因为各层代价几乎都一样。共有 log_b n 层，每层都是 Θ(n^(log_b a))，乘起来就多了一个 log 因子。归并排序是最好懂的例子：每一层合并的总代价都是 Θ(n)，一共有 log n 层，于是是 Θ(n log n)。

主定理和递归树哪个更值得掌握？

都值得，但顺序是先递归树后天主定理。递归树是理解力：它让你看到「谁在主导开销」的物理图像；主定理是解题速度：熟悉之后几秒钟出答案。而且主定理失效时，递归树仍然是可靠的退路。

它在实际工程里有用吗？

有，但更常用的形态是它的直觉：当你写一个递归/分治流程时，能立刻判断「近似瓶颈在哪一层」。比如归并阶段如果用了代价 O(n²) 的合并实现，主定理会告诉你整体退化到 O(n²)，提示你真正的优化点不在递归本身，而在合并实现上。
