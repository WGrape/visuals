SSD 内部：FTL、垃圾回收与写放大

SSD 没有「覆盖写」这回事：NAND 只能按页写、按块擦。于是固件里跑着一个类似文件系统的映射层（FTL），用垃圾回收搬运数据。写放大就是这场搬运的账单，它决定了寿命，也解释了「SSD 用久了变慢」。

一句话定位：用映射表把「覆盖写」翻译成「写新页 + 标旧页」

NAND 的物理约束是：读按页、写按页（且只能写空白页）、擦按块。要支持「原地改一个字节」，FTL 维护一张逻辑块地址（LBA）到物理页地址（PBA）的映射表，每次写都落到新页并更新映射，旧页变成垃圾。

页 / 块页 4~16KB，块 256 页左右（约 4~8MB）
写入单位页；擦除单位是整块
映射表1TB / 4KB = 2.5 亿项，每项 4B ≈ 1GB 内存
预留空间 OP消费级 7%，企业级 28%
从主机 4KB 写到 NAND 实际写入的放大链路

写放大怎么算、怎么降

WA = NAND 实际写入量 ÷ 主机写入量　　TBW ≈ 容量 × DWPD × 365 × 年数
负载模式典型 WA原因
大块顺序写1.0~1.2整块写满，几乎不产生垃圾
4K 随机写（OP 7%）2~4GC 频繁搬迁有效页
4K 随机写（OP 28%）1.3~2预留空间多，GC 有腾挪余地
长期接近写满5~10空闲块不足，GC 反复搬运
混合读写 + TRIM 生效下降 30%~50%TRIM 让 FTL 提前知道哪些页是垃圾

算例：1TB 消费级 SSD、DWPD=0.3、5 年 → TBW ≈ 1TB × 0.3 × 365 × 5 ≈ 547TB。若 WA=4，主机实际只能写 ≈ 137TB。这就是「标称寿命要除以写放大」的意思。

TRIM 为什么重要

删除文件时文件系统发 TRIM 告诉 SSD「这些 LBA 不再有效」，FTL 可以直接把对应页标为垃圾，而不用等到「被覆盖」才知道。没有 TRIM，GC 会把早已删除的数据当有效页搬来搬去，WA 直接翻倍。

寿命、性能与「用久了变慢」

现象机制缓解
新盘快、用久了写变慢空闲块减少 → GC 更频繁、更被动留 10%~20% 未分配空间（OP）
SLC 缓存用完后掉速缓存写满要直写 TLC/QLC大文件持续写会看到阶梯掉速
随机写 IOPS 远低于标称标称通常是 QD32 顺序/随机混合看稳态（steady state）指标
写入延迟毛刺GC 与主机写争抢 NAND 通道企业盘靠更多 OP 与后台 GC

选型时看三个数而不是一个：稳态随机写 IOPS、DWPD/TBW、稳态写延迟 P99。消费级标称的「峰值」只在 SLC 缓存未满时成立。

磨损均衡：为什么不能只写热点块

NAND 每个块的擦写次数有限（TLC 约 1000~3000 次）。如果反复写同一批逻辑块，对应物理块会先坏掉。磨损均衡把写请求均匀摊到所有块上：动态均衡只搬「冷数据」，静态均衡会主动把冷块里的数据搬走，让冷块也参与轮换。

排障：SSD 相关的性能问题

现象根因验证
数据库 commit 延迟高每次 fsync 都要等 NAND 落盘 + GC用带掉电保护的盘；批量提交
写入吞吐只有标称一半SLC 缓存耗尽或 WA 高看 SMART 的 host_writes vs nand_writes
删除大量文件后仍慢TRIM 未开启（如某些虚拟化层）检查 discard 挂载选项
盘快满了就卡空闲块不足触发被动 GC保留 OP，监控剩余空间
SMART 显示寿命骤降WA 过高（随机小写）改写入模式，加 OP

原理与取舍：为什么 SSD 不能像 HDD 那样原地覆盖

HDD 可以原地改一个扇区，因为磁头能定位到任意位置重写；NAND 的编程是「把电子注入浮栅」，只能单向把 0 变 1 的方向（实际是只能写、不能清零），要清零必须整块高压擦除。这个物理约束逼出了整个 FTL/GC 体系——所有「SSD 的怪现象」几乎都能追溯到这里。

为什么 SSD 的随机读比随机写快这么多？

读只需定位页并返回；写要先擦块（或找新页）、更新映射、可能触发 GC。写路径上有串行的物理操作与固件开销。

QLC 为什么不适合写密集场景？

QLC 每单元 4 bit，擦写寿命只有几百次，写速度也慢；它适合「写一次读多次」的冷数据（如内容分发、备份）。

RAID 能提升 SSD 寿命吗？

不能直接提升单盘寿命，但能通过冗余容忍单盘失效。反而要注意：RAID 重建会全盘读，对已经磨损的盘是压力测试。

第一层 · 概念与判定：闪存的三个固有约束

闪存（NAND）有三个和磁盘完全不同的性质，SSD 的所有复杂机制都是为了绕开它们。

性质含义带来的后果
写前需擦除不能直接覆盖写，必须先擦产生了垃圾回收（GC）
读写单位 ≠ 擦除单位页 4–16 KB，块含数百页（几 MB）擦大块要搬走其中的有效数据
擦写有寿命P/E 次数有限（TLC 约 1000–3000 次）需要磨损均衡（Wear Leveling）

FTL（Flash Translation Layer）是 SSD 内部的「翻译层」：把主机看到的逻辑地址映射到真实的物理页，主机以为在覆盖写，实际是写到新页 + 更新映射表。它同时负责 GC 与磨损均衡。

第二层 · 参数·命令·量化：写放大到底多大

写放大（Write Amplification, WA）= 实际写入闪存的数据量 ÷ 主机请求写入的数据量。WA = 1 是理想情况（写多少就存多少），随机小写入会让 WA 远大于 1。

写入模式WA 典型值说明
大块顺序写接近 1整块写满，几乎无需搬数据
4 KB 随机写（空闲盘）3 – 5需要搬移有效页
4 KB 随机写（满盘）5 – 15空间紧张，GC 频繁，最坏情况
有 OP 预留空间可降到 2 – 4预留空间给 GC 喘息
稳态企业级 SSD通常 < 3大 OP + 强 FTL 算法

测量写放大与 SSD 磨损

# 用 fio 测随机写的写放大（对比主机写入量 vs NAND 写入量）
fio --name=randwrite --ioengine=libaio --rw=randwrite --bs=4k \
    --size=10G --numjobs=4 --iodepth=32 --runtime=300 \
    --time_based --direct=1 --group_reporting --output=fio.log

# 读取 SMART 中的 NAND 实际写入量（不同厂商字段不同）
smartctl -a /dev/nvme0 | grep -iE 'data units written|host writes|percentage used'
# NVMe 常见字段：
#   Data Units Written       : 以 512B×1000 为单位
#   Host Write Commands      : 主机发起的写命令数
# 计算：WA = (Data Units Written × 512000) / (主机实际写入字节数)

# 看 SSD 已用寿命百分比
smartctl -a /dev/nvme0 | grep -i 'percentage used'
# 100 表示已超出标称寿命（不代表立刻坏）

# 手动触发 TRIM / discard，帮助 GC 提前回收
fstrim -v /

寿命直觉：一块 1 TB、标称 600 TBW 的 SSD，若 WA = 5、每天写 100 GB 主机数据，实际每天消耗 500 GB 寿命 —— 600 TBW ÷ 0.5 TB/天 = 1200 天，约 3 年多。WA 从 5 降到 2.5，寿命直接翻倍。

第三层 · 排障与边界

现象原因处理方向
写入延迟突然飙高GC 在搬数据（写放大发作）留 OP、避免满盘、改用顺序写
用了很久后写变慢空闲块耗尽，每次写都要先 GC做 TRIM、降低使用率到 80% 以下
SSD 寿命掉得快WA 高 + 写入量大检查是否有不必要的小随机写
顺序读写也慢不是 GC 问题，可能是温度过高降频查温度、检查散热
读延迟抖动大GC 与读操作争抢闪存带宽减少前台 GC 频率、留 OP

降低写放大的实操清单：

  • ① 别把盘写满：使用率控制在 70–80% 以下，留空间给 GC
  • ② 留 OP 预留空间：企业盘常见 7–28% OP，消费盘可手动留
  • ③ 开启 TRIM / discard：让 SSD 知道哪些块可以提前回收
  • ④ 批量写代替零散写：把小写合并成大写，WAL 类场景尤其注意
  • ⑤ 对日志类数据考虑单独盘：高频小写单独放，避免拖累主盘 GC
  • ⑥ 监控 Percentage Used，提前规划更换

第四层 · 原理与取舍

为什么 SSD 不能直接覆盖写？

因为 NAND 的物理特性：写（program）以页为单位，擦（erase）以块为单位，且擦除的粒度远大于写入。要改一个页里的数据，不能只擦那一页，必须整个块擦掉，而块里其他页的有效数据会一起被抹掉。所以只能把有效数据搬走、擦块、再写回 —— 这一整套就是 GC，多出来的写入就是写放大的根源。

OP（预留空间）为什么能降写放大？

因为 GC 需要空的块作为搬运目的地。盘接近写满时，几乎找不到空块，每一次小写入都要先搬走一整块的有效数据，WA 陡增。留出 10–20% 的 OP 后，GC 总能找到空块直接写新数据，不必频繁搬运。代价是可用容量变小，这是拿容量换性能与寿命的交易。

TRIM 到底做了什么？

文件系统删除文件时，只是标记删除，不会通知 SSD。SSD 一直以为那些页还有数据，GC 时会老老实实搬走它们 —— 白搬。TRIM 就是告诉 SSD「这些逻辑地址已经作废」，SSD 收到后可以把对应页标记为无效，GC 时直接跳过。所以定期 fstrim 能显著降低 WA、延长寿命。现代系统多用 discard 挂载选项或定时 TRIM。
