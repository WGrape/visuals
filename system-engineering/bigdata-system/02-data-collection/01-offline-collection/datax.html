架构

DataX 一个作业就是一个独立进程：Reader 从源端拉数据，写入内存中的 Channel；Writer 从 Channel 读数据，推到目标端。通过配置多个并发 Channel 实现并行。

插件生态

每种数据源实现一个 Reader 和一个 Writer 插件，任意两种数据源可自由组合（MySQL→HDFS、HDFS→ES、Oracle→MySQL……），不依赖 Hadoop。

与 Sqoop 对比

维度DataXSqoop
定位通用异构同步RDBMS↔Hadoop

速度内存通道快受 MR 调度开销

结论：只在 RDBMS 与 Hadoop 之间搬用 Sqoop 顺手；任意异构源互导用 DataX 更灵活。

🎯 面试问答

Q：DataX 和 Sqoop 能互相替代吗？
A：部分场景可以，但 Sqoop 深度绑定 Hadoop、适合海量批导；DataX 轻量、适合多源异构，二者常并存。
Q：脏数据如何处理？
A：Writer 写入失败的记录计入脏数据阈值，超过比例作业报错，便于及时发现源端质量问题。
