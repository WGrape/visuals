异构计算：CPU、GPU、NPU 各自该干什么

CPU 强在延迟与通用性，GPU 强在吞吐，NPU 强在能效。真正的工程问题不是「谁更快」，而是「这段计算该放在哪、数据要搬几次、搬运的代价有没有超过计算本身」。

一句话定位：延迟优化 vs 吞吐优化

CPU 用大缓存、乱序、分支预测把「单条指令的延迟」压到最低；GPU 用几千个简单核心 + 高带宽显存把「单位时间完成的操作数」推到最高。同一个矩阵乘，CPU 可能 90% 时间在等数据，GPU 则能靠并行把算力吃满。

CPU几十个强核，适合控制流与串行依赖
GPU数千 SIMT 核心，适合规则并行
NPUMAC 阵列 + INT8/INT4，适合固定形状推理
关键约束数据搬运能耗与带宽，往往比计算更贵
四种算力的分工不是性能排序，而是「问题形状」的匹配

峰值 TOPS 的水分

标称 TOPS 通常按「理想形状 + 最低精度 + 全流水」计算。真实模型里有 LayerNorm、Softmax、转置等非矩阵算子，NPU 要么不支持、要么效率极低，实际利用率常常只有峰值的 20%~40%。

数据搬运才是大头

操作能耗量级相对值
一次 INT8 乘加~0.1 pJ1×

从 L1 读 1 bit~1 pJ10×

这张表解释了为什么「把模型切成两半分别放 CPU/GPU」经常更慢：中间结果的搬运成本可能超过省下的计算。也解释了为什么端侧强调「一次加载、多次复用」，以及为什么大模型推理的瓶颈是显存带宽而不是算力。

x = preprocess(x)            # CPU：控制流、前后处理

原理与取舍：为什么要「专用」

通用处理器把面积花在缓存、乱序、分支预测上，这些对规则并行毫无用处。专用加速器把面积全给 MAC 阵列与片上缓存，于是同样的功耗下算力高一个数量级——代价是失去通用性：形状变了、精度变了、算子不支持了，就要回退，回退的代价往往比不用加速器还高。

GPU 能替代 CPU 吗？

不能。GPU 的执行模型要求「同一段代码作用在大量数据上」，遇到分支发散、串行依赖、频繁系统调用就退化。异构的本质是让合适的单元做合适的事。

NPU 和 GPU 的差别到底在哪？

GPU 保留可编程性（能跑任意 kernel），NPU 把数据流固化（卷积/矩阵乘的专用流水线），所以 NPU 能效更高但只对特定算子高效。

Chiplet 为什么突然流行？

因为大芯片良率随面积指数下降，把大 die 拆成小 die 分别制造再封装，成本更低；同时可以混用不同工艺（计算用先进工艺、IO 用成熟工艺）。
