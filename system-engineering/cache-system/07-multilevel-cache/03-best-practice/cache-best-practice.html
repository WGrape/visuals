大 key

单个 value 过大(如 big list) → 网络/序列化慢、阻塞；拆分或压缩。

热 key

单 key 极高 QPS → 单节点瓶颈；本地缓存副本、key 加随机后缀分片。

预热与监控

上线/重启预热避冷启动击穿；监控命中率、内存、慢查询。

🎯 面试问答

Q：什么是大 key，怎么处理？
A：体积或元素过多的 key；拆分、压缩、分批。
Q：热 key 怎么发现？
A：监控/Redis 命令统计/Proxy 上报，识别 QPS 异常 key。
Q：命中率多少算健康？
A：看业务，读多写少场景应 >90%，低于则需调容量/策略。
