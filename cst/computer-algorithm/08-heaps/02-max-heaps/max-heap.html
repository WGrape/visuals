第 08 章 · 大顶堆

让最大值始终处于堆顶

大顶堆维护“父节点 ≥ 子节点”；它不仅能反复取最大值，还能筛选数据流中最小的 k 个数。

核心速览

堆序父 ≥ 子（与最小堆相反）
堆顶 O(1)最大值永远在 a[0]
上浮 / 下沉插入变大就上浮，删除后下沉
Top-K 最小维护 k 个候选，堆顶是最该被淘汰的

大顶堆是什么

大顶堆（Max Heap）是一棵完全二叉树，满足每个节点的值 ≥ 它的孩子。由此推出：整棵树的最大值一定在根节点——因为沿着任意路径往下走，值只会越来越小。

注意它不保证全局有序：左右孩子之间没有顺序要求，第二大的数可能在左子树也可能在右子树。大顶堆只维护「父子之间的偏序」，不维护全序。这正是它比平衡搜索树省、比有序数组快的原因。

两个核心操作

插入 → 上浮（sift up）

  1. 新元素放到数组末尾（保住完全二叉树的形状）。
  2. 若它大于父节点，就与父交换，一路向上，直到父 ≥ 它或到达根。

只沿一条从叶到根的路径移动，代价 O(log n)。

删除堆顶 → 下沉（sift down）

  1. 用最后一个元素顶替堆顶（直接删根会破坏完全二叉树形状）。
  2. 新的根可能太小 → 与两个孩子中较大的那个交换，一路向下，直到满足堆序或成为叶子。
为什么必须和「较大的孩子」交换？如果和较小的孩子交换，那个较小的孩子会变成它兄弟的父节点，但兄弟更大——父子关系又被破坏。选较大的孩子当新父，两个分支都安全。
def sift_down(a, i, n):          # 大顶堆
    while True:
        l, r = 2*i+1, 2*i+2
        big = i
        if l < n and a[l] > a[big]: big = l
        if r < n and a[r] > a[big]: big = r
        if big == i: break
        a[i], a[big] = a[big], a[i]
        i = big

def pop_max(a):                  # 取走最大值
    top = a[0]
    a[0] = a.pop()               # 末尾元素顶替堆顶
    if a: sift_down(a, 0, len(a))
    return top
建堆（heapify）是 O(n) 而不是 O(n log n)：从最后一个非叶子节点（下标 n//2 − 1）开始，从右往左、自底向上依次下沉。因为底层节点多但高度小，总代价 Σ (n/2^h)·h 收敛到约 2n。批量初始化请用 heapify，别逐个 push。

典型应用一：筛选最小的 k 个数

这是大顶堆最经典的用法（也是页脚「淘汰谁，就让谁待在堆顶」的含义）。

思路：维护一个大小为 k 的大顶堆，堆顶是这 k 个候选里最大的——也就是「最该被淘汰的那个」。扫描数据流时：堆不满 k 个就直接放入；满了之后，若新元素 < 堆顶，说明它比候选里最差的还小，于是弹出堆顶、放入新元素。扫完后堆里就是最小的 k 个数。
import heapq   # Python 标准库只提供小顶堆，用「取负」模拟大顶堆

def smallest_k(nums, k):
    heap = []                       # 存负值 → 效果上是大顶堆
    for x in nums:
        if len(heap) < k:
            heapq.heappush(heap, -x)
        elif x < -heap[0]:          # 比堆顶（候选里最大的）小 → 替换
            heapq.heapreplace(heap, -x)
    return sorted(-v for v in heap) # 堆里就是最小的 k 个
为什么不用排序？排序要 O(n log n) 且需要全部数据常驻内存；大顶堆只要 O(n log k) 和 O(k) 内存。当 n 极大（如 10 亿条日志）而 k 很小（如 Top 100）时，这个差距是决定性的——这是海量数据求 Top-K 的标准解法。

典型应用二：堆排序（升序用大顶堆）

  1. 先 O(n) 建大顶堆，最大值在 a[0]。
  2. 重复 n 次：把 a[0] 与当前最后一个元素交换（最大值就位），堆大小减 1，再对新的 a[0] 下沉。
  3. 全部完成后，数组升序排列。
堆排序的独特价值：最坏也是 O(n log n)，且只需要 O(1) 额外空间（快排最坏 O(n²)，归并要 O(n) 辅助数组）。代价是不稳定且缓存局部性差（下标 i ↔ 2i+1 的跳跃访问），所以实践中通常比快排慢，但在「必须保证最坏性能 + 内存紧张」的场景不可替代。

大顶堆与小顶堆怎么选

目标用什么堆为什么
反复取最大值大顶堆最大值在堆顶，O(1) 取用
反复取最小值小顶堆最小值在堆顶
求最小的 k 个大顶堆（容量 k）堆顶是候选里最大的 = 最该淘汰的
求最大的 k 个小顶堆（容量 k）堆顶是候选里最小的 = 最该淘汰的
求中位数流两个堆大顶堆放较小的一半，小顶堆放较大的一半
记忆口诀：堆顶放「最该被淘汰的那个」。要最小的 k 个 → 淘汰最大的 → 用大顶堆；要最大的 k 个 → 淘汰最小的 → 用小顶堆。想清楚「淘汰谁」，就不会选反。

🎯 面试问答

Q：大顶堆和小顶堆有什么区别？

A：唯一区别是堆序的方向：大顶堆满足「父 ≥ 子」，最大值在根；小顶堆满足「父 ≤ 子」，最小值在根。两者的结构性（完全二叉树、数组存储、上浮下沉操作）完全一样，只是比较符号相反。工程上如果语言只提供小顶堆（如 Python 的 heapq），可以用存负值来模拟大顶堆。

Q：求最小的 k 个数，为什么要用大顶堆而不是小顶堆？

A：因为要让「最该被淘汰的那个」待在堆顶。求最小的 k 个时，候选集合里最大的那个最该被淘汰（它最不可能属于答案），所以要用大顶堆，让最大值在堆顶：新元素只要 < 堆顶 就替换掉它。反之求最大的 k 个时，最该被淘汰的是候选里最小的，所以用小顶堆。想清楚「淘汰谁」就不会选反。复杂度 O(n log k)，空间 O(k)。

Q：为什么删除堆顶要用最后一个元素顶替？

A：因为直接删除根节点会在中间留下空洞，破坏「完全二叉树」的形状，数组表示就不再紧凑。做法是：把最后一个元素移到根位置（形状恢复：仍是完全二叉树），此时它可能违反堆序，再对它执行一次下沉（O(log n)）恢复堆序。同理，插入时把新元素放在末尾再上浮，也是为了先保住形状。

Q：堆排序为什么用大顶堆能得到升序？

A：因为大顶堆的堆顶是最大值。做法是重复「把 a[0]（当前最大值）与末尾元素交换 → 堆大小减 1 → 对新堆顶下沉」：每轮把当前最大值放到数组末尾，n 轮后最大的在最后、次大的在倒数第二……于是整个数组就是升序。若用升序数组做堆排序，应该用大顶堆；若要降序则用小顶堆。

Q：建堆为什么是 O(n) 而不是 O(n log n)？

A：因为自底向上（heapify）时，下沉代价与节点高度成正比，而绝大多数节点都在底层。约 n/2 个叶子高度 0（代价 0）、n/4 个高度 1、n/8 个高度 2……总代价 Σ (n/2^h)·h 收敛到约 2n，所以是 O(n)。而「逐个 push」每个都要 O(log n)，总共 O(n log n)。结论：批量初始化用 heapify，别用逐个插入。

Q：大顶堆能做什么？复杂度是多少？

A：典型用途：① 反复取最大值（O(1) 看、O(log n) 取走）；② 从海量数据中筛最小的 k 个（O(n log k)，只需 O(k) 内存，这是排序做不到的）；③ 堆排序（升序，O(n log n) 且原地 O(1) 空间）；④ 与一个小顶堆配合求数据流中位数。复杂度：取最值 O(1)、插入/删除 O(log n)、建堆 O(n)、查找任意元素是 O(n)（堆不擅长查找）。

第二层 · 参数·命令·量化：最大堆的实现与操作代价

最大堆与最小堆结构完全相同，只差比较方向：父 ≥ 子。所以实现上只改一处比较符号。

对比最大堆最小堆
堆性质父 ≥ 子父 ≤ 子
堆顶最大值最小值
向下调整与较大的孩子交换与较小的孩子交换
用途Top-K 小、最大优先队列Top-K 大、最小优先队列、Dijkstra

最大堆实现与语言差异

import heapq

# Python 的 heapq 只有最小堆 —— 最大堆用「取负数」技巧
maxh = []
heapq.heappush(maxh, -x)          # 存 -x
top = -maxh[0]                    # 看最大值：取负还原
mx  = -heapq.heappop(maxh)        # 弹出最大值

# 手写最大堆（向下调整，注意比较方向）
def sift_down(a, i, n):
    while True:
        l, r = 2 * i + 1, 2 * i + 2
        big = i
        if l < n and a[l] > a[big]: big = l      # 注意这里是 >
        if r < n and a[r] > a[big]: big = r
        if big == i: break
        a[i], a[big] = a[big], a[i]
        i = big

# C++ / Java 直接支持最大堆
# C++:  std::priority_queue<int> pq;                       // 默认最大堆

# Java: new PriorityQueue<>(Collections.reverseOrder());
操作时间复杂度说明
建堆O(n)自底向上，从 n//2 - 1 往前
插入O(log n)末尾追加后向上调整
弹出堆顶O(log n)末尾换顶后向下调整
查看堆顶O(1)a[0]

Top-K 方向速记：求 Top-K 小用大顶堆（堆顶是候选里最大的，新元素比它小才替换）；求 Top-K 大用小顶堆。堆顶 = 门槛。

第三层 · 排障与边界：最大堆的坑

Python 里忘了取负拿到的是最小值push 存 -x，pop 后 -res

Top-K 大小顶用反了结果集错误记住堆顶是「门槛」，新元素必须比门槛更优
以为堆可以 O(log n) 查找实际 O(n)需要查找就换平衡树
  • 排查顺序：先确认堆顶方向 → 再确认取负数是否成对还原 → 再看 Top-K 的替换条件。
  • 边界一：最大堆同样不是有序数组，只有堆顶保证最大。
  • 边界二：Python 用取负数实现最大堆时，若元素本身可能是 float('inf') 之类，取负仍成立但要注意 NaN。
  • 边界三：比较方向改动只影响 sift_down/sift_up，下标关系完全不变（父 (i-1)//2，孩子 2i+1 / 2i+2）。

Top-K 最小元素

# Top-K 最小元素：维持大小为 k 的最大堆
import heapq
def top_k_smallest(nums, k):
    h = []
    for x in nums:
        if len(h) < k:
            heapq.heappush(h, -x)              # 大顶堆（取负）
        elif x < -h[0]:                        # 比堆顶（当前第 k 小）更小
            heapq.heapreplace(h, -x)           # 替换
    return sorted(-v for v in h)
最大堆和最小堆能互相转换吗？

可以，把比较方向反过来即可，结构完全一样。Python 因为只有最小堆，习惯用「存负数」来模拟最大堆——这招对数值有效，对自定义对象不适用（那时要用 dataclass 定义 __lt__ 或用 C++/Java 的比较器）。

什么时候用最大堆？

① 求 Top-K 最小的元素；② 需要「每次取当前最大」的调度场景（如任务优先级）；③ 中位数维护里的「大顶堆存较小的一半」（配合小顶堆存较大的一半）。
