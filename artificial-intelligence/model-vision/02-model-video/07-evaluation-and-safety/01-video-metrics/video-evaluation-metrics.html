视频生成评测：画质、运动与语义分开看

FVD 是批次分布指标，逐帧清晰度不能代替时间连贯性。

学完能解释什么

  • 区分视频级分布指标与逐帧图像指标
  • 设计检测闪烁、动作错误和指令违背的样本
  • 让模型比较使用相同采样和人工盲评口径

逐步看机制

固定提示词、时长和采样条件

同一任务下锁定分辨率、帧率、剪辑长度和生成次数；生成后插帧会改变比较口径。

FVD 到底回答什么

Fréchet Video Distance 将真实与生成视频经过视频特征网络，比较两组特征分布的统计距离。它通常需要足够样本和统一预处理；特征网络、片段长度、帧率和参考集变化都会影响结果。FVD 不能给一条视频判“真假”，也不能单独证明文本指令中的人数、左右关系和动作完成了。

逐帧好看，连续看却可能崩

逐帧图像质量指标会漏掉脸部跨帧变形、闪烁、手臂突然穿过物体等时间错误。可结合跟踪主体的一致性、运动补偿后的区域差异与人工连续播放检查；但过度惩罚帧间变化会偏好静止或模糊视频，所以必须同时测运动幅度、合理性与任务事件。

可复现的评测单

  1. 公布生成任务与提示词分层、样本数、时长、分辨率、原生帧率和是否后处理。
  2. 在相同数据与视频特征提取条件下比较 FVD，报告波动与失败率。
  3. 按人物身份、快速动作、镜头切换和文本-事件对齐分别检查。
  4. 人工盲评随机化顺序，观看整段并记录原因，而非只选择好看的首帧。

音画一体生成还要评价语音与口型同步、声音质量和事件时序；图像分数不能代替这些维度。

自检

一个视频 FVD 很低，能断定单个片段没有闪烁吗？

不能。FVD 是两组视频的分布统计，可能掩盖局部失败；要另查时序和个体案例。

为什么视频不能只抄图像指标

图像评测只看「这一张像不像真实照片」，视频多了一个维度：时间。一段 16 帧视频，逐帧看都很清晰，但人物第 7 帧换了一张脸、杯子把手在第 9 帧凭空消失——这种「帧内完美、帧间崩坏」的失败，FID 完全测不出来。所以视频评测必须分三层：帧画质（静态）→ 时序一致性（动态）→ 语义叙事（内容）。

FVD视频版 FID，在视频特征空间算分布距离，同时含运动信息
FID（逐帧）只看单帧分布，测不出抖动与漂移
CLIPSIM每帧与文本算 CLIP 相似度取均值，衡量文本对齐
光流/扭曲误差用相邻帧预测下一帧，误差大说明运动不连续
身份一致性人脸/主体 embedding 在帧间的相似度是否稳定
人工评分最终标准，尤其对「闪烁感」「诡异感」无可替代
三层指标：缺任何一层，评测结论都会失真

主流指标怎么算、怎么读

指标输入数值方向优点局限
FVD视频片段集合 vs 参考集越小越好同时覆盖画质与运动，最常用需足够样本量，16 帧 × 2048 段起步；对不同域不可比
FID（逐帧）抽帧后当图像算越小越好实现简单，和图像模型横向可比完全无视时序，会给出虚高分数
IS (Inception Score)单帧分类分布越大越好不需要参考集对真实度不敏感，容易被模式崩溃刷分
CLIPSIM / CLIP-F帧 + 文本越大越好衡量文本对齐，与人类判断相关性好对细粒度动作、数量、空间关系不敏感
LPIPS / 光流误差相邻帧对越小越好直接量化抖动与形变真实视频本身也有较大光流，需与真实集对照

读分技巧：FVD 100 与 300 的差距，通常肉眼非常明显；FVD 300 与 320 的差距基本没有意义。跨论文比较时必须确认三件事：帧数、帧率、分辨率是否一致，参考集是否同一个（UCF-101 / Kinetics-600 / 自采），以及特征抽取模型是否一致（I3D / VideoMAE）。这三项任一不同，数字不可比。

搭一套能用的评测流水线

① 固定 prompt 集

  • 至少 200 条，覆盖：单物体、多物体、人物动作、镜头运动、文字、抽象风格。
  • Prompt 必须固定并公开，否则每次跑出来的分都不可比。
  • 每条固定随机种子，避免「运气好」拉高均值。

② 分层打分再汇总

  • 先算画质分（FID）、再算时序分（FVD/光流）、再算语义分（CLIPSIM）。
  • 分别看均值与最差 10%：均值好但尾部崩，是最常见的上线事故。
  • 再做 100 组人工二选一，作为最终裁决。

③ 常见失败模式清单

  • 身份漂移：人脸在第 N 帧变成另一个人。
  • 背景呼吸：静止的背景在缓慢蠕动。
  • 物体增生/消失：手指数量变化、杯柄消失。
  • 运动量不够：几乎静止的视频 FVD 反而好看。

④ 别踩这些坑

  • 用压缩过的视频算指标：H.264 伪影会被当成画质问题。
  • 只用 8 帧评估 32 帧模型：会低估时序问题。
  • 拿自然视频做参考集去评动画风格生成：分布天然不匹配。
  • 只看均值不看方差：抖动型模型均值可能不差但体验极差。
样本量≥2048 段才有稳定 FVD
帧数评估帧数必须等于生成帧数
种子固定种子，报告方差
参考集与目标域一致

深入自检

FVD 很低但人看着很假，可能是什么原因？

通常是时序被「保守化」了：模型生成近乎静止、运动幅度极小的视频，FVD 会很好看但毫无可用性。对策是加一个「运动量」指标（平均光流幅度），要求不低于真实视频的某个分位，否则视为退化。

为什么视频评测一定要固定随机种子？

同一条 prompt 换种子，结果差异往往大于换模型的差异。不固定种子，你测到的是噪声而不是模型能力。规范做法是每条 prompt × N 个固定种子，报告均值与方差。

CLIPSIM 高就代表视频符合 prompt 吗？

不完全。CLIP 对「数量」「左右方位」「时序先后」几乎不敏感，「一只猫追一只狗」和「一只狗追一只猫」得分接近。涉及这些维度的 prompt 需要额外结构化检查或人工判分。

人工评测怎么设计才不白花钱？

用成对比较 + Elo 积分，而不是绝对打分（人对 1-5 分的标定极不稳定）。每次只问一个维度（画质 / 对齐 / 流畅），不要混问。随机化左右顺序，插入重复对检测标注者一致性，剔除一致性低于 70% 的人。

能不能用一个总分排序模型？

可以做加权总分，但一定要同时公开各分项。因为不同业务权重不同：广告素材看重画质，产品演示看重文本对齐，影视预演看重时序一致性。只给总分会掩盖关键短板。

评估数据集应该自己采还是用公开集？

公开集（UCF-101、Kinetics、MSR-VTT）适合横向对比论文；真正上线前必须自采一批贴合业务的视频作参考集，否则指标和业务体感会长期背离。

第一层 · 三层指标：画质 / 运动 / 语义

视频生成的评测必须分开三个维度，混在一起评会得出错误结论。一个视频可能画质很好但物体会变形，也可能语义正确但抖动剧烈。

维度回答什么问题代表指标特点
画质（帧级）单帧清不清晰、像不像真实照片FID、FVD、PSNR/SSIM（有参考时）不评估时序
运动（时序）动得连不连贯、有没有抖动/突变FVD、光流一致性、warping error视频特有
语义（文本对齐）内容符不符合文字描述CLIP-SIM、人工评测依赖 CLIP 能力
人工整体好不好看MOS / 偏好对比最终标准
  • 最关键的一条：FID 只看单帧分布，完全不评估时序。一个每帧都很美但帧间完全跳变的视频，FID 可以很好——但它根本不是合格的视频。所以视频评测必须有 FVD 或类似的时序指标。
  • FVD 是什么：把视频片段喂给一个预训练的 3D 网络（I3D）提取特征，然后计算生成集与真实集特征分布的 Frechet 距离。它同时编码了外观和运动信息。越低越好。
  • 指标要和人工对齐：所有自动指标都只是代理。发布前必须做人工评测，并定期检查「自动指标与人工评分的相关性」——如果相关性低，这个指标就没有指导意义。

第二层 · 怎么测、怎么读数字

指标计算方式方向经验阈值
FID（图像）Inception 特征的 Frechet 距离越低越好UCF-101 上 <30 算不错
FVD（视频）I3D 特征的 Frechet 距离越低越好几百到一千量级，与数据集强相关
CLIP-SIM帧特征与文本特征的余弦相似度越高越好0.25~0.35 区间常见
IS（Inception Score）分类置信度 + 多样性越高越好容易被刷，现在少用
PSNR / SSIM需参考视频（有 GT）越高越好PSNR >30dB 通常可接受
LPIPS感知相似度（需参考）越低越好比 PSNR 更接近人眼
光流一致性帧间光流的平滑度越低越好检测抖动/闪烁

原理与命令

# —— FVD 的计算流程（理解原理用）——
# 1) 用预训练 I3D 模型提取特征（输入通常是 16 帧的片段）
#    features_real  = I3D(videos_real)     # [N, 400]
#    features_fake  = I3D(videos_fake)     # [N, 400]
# 2) 假设特征服从多元高斯，估计均值与协方差
#    (mu_r, sigma_r), (mu_f, sigma_f)
# 3) Frechet 距离：
#    FVD = ||mu_r - mu_f||^2 + Tr(sigma_r + sigma_f - 2*(sigma_r @ sigma_f)^0.5)
# 含义：既比较【平均特征】(第一项)，也比较【分布形状/多样性】(第二项)
#    -> 所以 FVD 能同时惩罚「质量差」和「多样性不足（模式坍塌）」

# —— 实践中的坑：样本量 ——
# FVD 需要【足够的样本】才稳定。经验：至少 256~2048 个视频片段
#   样本太少（如 16 个）-> 协方差估计极不准 -> 数字波动巨大且不可比
#   不同论文用的样本数不同 -> 跨论文比较 FVD 数字【没有意义】

# —— 评测集构建清单 ——
# 1) 固定随机种子（否则每次结果不同，无法对比）
# 2) 固定分辨率/帧数/帧率（512x512、16帧、8fps 等，与训练设置一致）
# 3) 覆盖多类 prompt：单物体、多物体、人物动作、镜头运动、复杂场景
# 4) 每个 prompt 生成多个样本（评估多样性）
# 5) 人工评测：至少 20 名评测者 × 每人 30 组对比

跨论文比较 FVD 基本没有意义——样本数、I3D 权重、帧数、分辨率任何一个不同，数字就不可比。只能在同一套评测设置下比较自己的模型。

第三层 · 排障清单

  • FID 好但视频看起来很差 → 典型的「指标与感知脱节」。FID 只看单帧，帧间抖动它完全不管。必须补 FVD 和人工评测。
  • FVD 数字波动大、不可复现 → 样本量不足，或没固定随机种子。把样本数提到 256+ 并固定 seed。
  • CLIP-SIM 高但内容不对 → CLIP 的语义能力有限（对空间关系、数量、否定词的理解都弱）。它只能捕捉粗粒度的语义匹配。精细的语义正确性必须靠人工或更强的评判模型（如用多模态 LLM 打分）。
  • 模型在评测集上很好但用户觉得差 → 评测集与真实分布不符（prompt 太简单、场景太单一）。解法：扩充 prompt 多样性，加入对抗性用例（复杂场景、多物体交互、手部动作等）。
  • 只报自动指标不发人工结果 → 这是评测不完整的信号。视频生成的金标准仍是人工偏好对比。
  • 评测数字被「刷」了 → IS（Inception Score）尤其容易被对抗样本刷高，现在基本不用。FID/FVD 也可以通过「挑最好的样本」作弊（只生成简单场景）。要报告评测集的构成和采样方式。
  • 忽略时序长度的影响：16 帧的视频和 64 帧的视频，FVD 不可比。长视频的错误会累积（身份漂移、物体变形），需要额外的长时一致性指标。
  • 没有失败案例分析：只看平均分掩盖了「20% 的视频完全崩了」。要分桶统计（好/中/差各占多少），并人工检查最差的样本。

第四层 · 原理与取舍

视频评测的根本困难：「好视频」没有唯一定义——画质、运动合理性、语义正确性、美学是多个正交维度，且彼此可能冲突（如运动幅度大通常更「生动」但更容易出现形变）。

指标类型优点缺点适用
分布距离（FID/FVD）无需参考视频、自动、可批量与人类感知相关性中等、样本量敏感模型迭代期的快速比较
有参考指标（PSNR/SSIM/LPIPS）精确、可解释需要 Ground Truth（生成任务通常没有）视频重建/压缩任务
语义相似度（CLIP-SIM）能评估文本对齐语义能力有限、可被刷辅助指标
人工偏好对比金标准贵、慢、有主观性最终验收
LLM/多模态评判比 CLIP 更懂语义、可批量有位置偏差、可能自说自话新兴方向，需校准
  • 为什么 FID/FVD 用「分布距离」而不是逐样本比较：因为生成任务没有 Ground Truth（同一个 prompt 可以有很多正确答案）。所以只能比较「生成集合的分布」与「真实集合的分布」是否接近。Frechet 距离的妙处在于它同时比较均值（质量）和协方差（多样性与相关性）——这正好对应了生成的两个核心要求「质量高」和「不坍塌」。
  • 模式坍塌能被 FVD 捕捉：如果生成器只会输出一种视频，那么生成特征的协方差会很小，Tr(sigma_r + sigma_f - 2(sigma_r·sigma_f)^0.5) 这一项会变大 → FVD 升高。这是它相比逐样本指标的巨大优势。
  • 为什么「人工偏好对比」比「绝对打分」好：让人给视频打 1~5 分，不同人的尺度差异极大（有人严格有人宽松）；而「A 和 B 哪个更好」的二选一则一致性高得多，且更接近真实的产品决策。这就是为什么主流评测用 side-by-side 对比 + 胜率。
  • 用 LLM 做评判的三个已知偏差：① 位置偏差（倾向选第一个或两个都选）；② 长度偏差（倾向更长的回答/描述）；③ 自我偏好（倾向与自己风格相似的输出）。缓解：随机化顺序、双向测试、用多个模型交叉、定期与人工结果校准。
为什么视频评测比图像评测难这么多？

三个本质困难：① 多了一个时间维度——图像只需判断「这一帧好不好」，视频还要判断「帧与帧之间连不连贯、运动合不合理、长时身份是否一致」。时序质量无法用任何单帧指标衡量；② 没有 Ground Truth——同一个 prompt 可以生成无限多种合理的视频，所以 PSNR/SSIM 这类有参考指标完全用不上，只能用分布距离（FVD）或语义相似度（CLIP-SIM），而这两者与人类感知的相关性都有限；③ 维度正交且可能冲突——画质、运动、语义是三个独立的轴，一个视频可以「画质极佳但物体在变形」或「语义准确但抖动严重」。所以要分开评估，且最终仍需人工综合判断。这三点叠加，导致视频生成的自动评测至今没有公认的可靠方案，人工偏好对比仍是金标准。

FVD 到底怎么读？多少算好？

绝对数值没有意义，只有相对比较有意义。FVD 的数值取决于：视频分辨率、帧数、I3D 的输入预处理、样本数量、参考数据集本身。同一个模型在不同设置下 FVD 可以差好几倍。所以：只能在同一套评测管线（固定 seed、固定片段数、固定 I3D 权重、同一参考集）下，比较不同模型或不同迭代版本。经验区间（UCF-101 类数据集、16 帧）：早期方法数千、当前较好模型几百到一千出头、SOTA 可能到几百以下——但这些数字跨论文不可比。实践建议：① 建立自己的固定评测集（如 2048 个 prompt × 固定 seed）；② 每次迭代跑同一套评测，看相对变化；③ 同时跑人工评测校准——如果 FVD 降了但人工评分没变，说明你的 FVD 已经不能反映真实质量了（可能模型在「骗」指标）。

自己搭评测体系该怎么做？

五步：① 建固定评测集——200~500 个 prompt，覆盖你产品的真实场景分布（不要只用玩具 prompt），固定 seed 和采样参数；② 自动指标每日/每版本跑——FVD（时序）、FID（画质）、CLIP-SIM（语义），三个都要，且记录分位数而不只是均值（看最差的 10% 有多差）；③ 人工评测定期做——每次重要版本，20+ 评测者 × 每人 30 组 side-by-side 对比，算胜率；④ 校准——定期算自动指标与人工胜率的相关性（Spearman 相关系数）。如果相关性 <0.5，说明自动指标失效，要换；⑤ 失败案例库——把每次评测中最差的样本归档分类（形变/闪烁/语义错/身份漂移），这比任何数字都更能指导改进。最后一点很重要：不要只优化指标——指标是代理，产品体验才是目标，两者背离时要相信人工。
