DFA 最小化手算：哪些状态看起来不同却能合并

用四状态奇偶自动机演示可达性、接受状态分组、分割细化与 Myhill–Nerode 直觉。

先问状态代表什么未来

有限自动机读完一段输入后停在某个状态。两个状态能否合并，关键不在名称、画图位置或到达它们的前缀是否相同，而在“未来继续读任意字符串时，接受结果是否总相同”。如果存在某个后缀能让一个状态接受、另一个拒绝，这个后缀就把它们区分开，二者绝不能合并；如果对所有后缀的结果都一样，它们对识别语言来说等价。DFA 最小化就是把所有等价状态合并，同时保留原语言。

开始前先移除从初态根本到不了的状态。不可达状态即使被画在图上，也不会参与任何实际输入的运行；把它留在分组里会让“最小状态数”虚高。输入字母表必须明确，本课只用 0 和 1；缺少转移时要按完整 DFA 的要求处理死状态，不能悄悄把失败边忽略。

沿箭头逐步核对输入、变换和输出；下面的推演可以逐步切换。

四个状态读二进制串

设计 A、C 为接受状态，表示目前读到的 1 的数量为偶数；B、D 为拒绝状态，表示奇数。转移为：A 遇 0 到 C、遇 1 到 B；C 遇 0 到 A、遇 1 到 D；B 遇 0 到 D、遇 1 到 A；D 遇 0 到 B、遇 1 到 C。初态 A。读入“101”时 A→B→D→C，最终接受，因为两个 1 为偶数。四个状态都可由某些输入到达，却有冗余：0 会在 A/C 或 B/D 内来回切换，并未改变“1 的奇偶性”。

若只凭“状态 A 和 C 转移目标不同”就判定不可合并，会漏掉目标本身也可能等价。最小化比较的是目标落在哪个等价组，而不是目标字母名称是否相同。

逐步推演

剔除不可达

从初态沿 0、1 探索，只保留可能运行到的状态。

先分接受性

A/C 接受，B/D 拒绝，空后缀可区分两组。

检查目标组

同组状态读 0、1 后总落到相同的组。

合并并验证

A/C 合为偶态，B/D 合为奇态，再抽样测试。

分割细化一步步做

初始分组先按是否接受切成 {A,C} 与 {B,D}，因为空后缀就能区分接受与拒绝。接着检查同组状态对每个输入符号的目标组：A 和 C 遇 0 都仍在接受组，遇 1 都到拒绝组，因此暂时不用拆；B 和 D 遇 0 都在拒绝组，遇 1 都到接受组，也不用拆。再做一轮仍无变化，分组稳定，合并 A/C 为 E、B/D 为 O。

得到的两状态 DFA 是：E 遇 0 留 E，遇 1 到 O；O 遇 0 留 O，遇 1 到 E，E 是初态和接受态。它精确识别“1 的个数为偶数”的语言。随便抽测空串、0、1、10、101、111，与原四状态机逐条比较，可以帮助发现手算转移写错。

什么情况要继续拆组

设同一当前组中的 P 和 Q，读符号 1 后 P 到接受组、Q 到拒绝组，那么后缀“1”就直接区分 P 与 Q，必须拆开。分割后，其他组原本看似相同的状态可能因为它们指向 P/Q 的不同新组而被下一轮拆开。因此算法需反复细化直到稳定，不能只做第一轮。构造等价类时每轮都以当前分组为准，避免在一次扫描中随意使用半更新状态产生难以复核的结果。

表填充法从状态对出发，先标记接受/拒绝不同的对，再传播“某输入转到已标记的一对”的区别；它和分割细化表达的是同一等价关系。小题手算可任选一种，但答卷应写出为何不能合并的后缀或稳定分组。

Myhill–Nerode 的意义

从语言本身看，两个前缀等价，指的是它们后面接任何后缀，是否属于语言的答案都一致。对于奇偶 1 的语言，所有前缀只分成“偶数个 1”和“奇数个 1”两类，所以最少需要两个状态。空串与“1”不同类，空后缀就能区分：空串被接受，“1”不被接受。这个观点解释了为什么任何识别同一语言的 DFA 最小状态数都相同，尽管状态名字和画法可以不同。

若某语言能产生无限多个两两可区分的前缀，它就不能由有限状态数的 DFA 识别。这是判断非正则语言的另一种思路，但使用时必须证明“对任意不同前缀都有某个区分后缀”，不能只举几个例子。

与 NFA、正则表达式的边界

NFA 可以同一符号走多条边，也可有 ε 转移；直接套本课的 DFA 分组表会遗漏非确定性。常见路线是先把 NFA 子集构造成 DFA，去掉不可达状态，再最小化。子集构造在最坏情况下可能指数膨胀，实际实现可按需要生成可达子集。正则表达式同样可以编译成自动机，词法分析器常合并并最小化状态以减少转移表空间。

最小 DFA 优化的是状态数量，不保证运行时每个输入最省内存或最快：稀疏转移存储、Unicode 字符类别和生成器实现仍会改变开销。验收时首先确保语言保持不变，再比较实际性能。

自检

A 遇 0 到 C、C 遇 0 到 A，目标状态名字不同，能否仅据此断定 A/C 不等价？

不能。应比较目标落入的等价组；A 和 C 遇 0 后都仍在接受组，遇 1 后都到拒绝组。
