日常高性能服务几乎都建立在 IO 多路复用（select/poll/epoll/kqueue） 或 异步 IO 之上。

Reactor 与 Proactor

事件驱动两兄弟

Reactor：事件就绪后由应用自己读（如 epoll + 非阻塞读写）；Proactor：内核完成 IO 后回调（如 Windows IOCP、Linux io_uring）。前者生态成熟，后者延迟更低。

epoll 为什么高效

select/poll 每次都要把全量 fd 拷进内核并线性扫描；epoll 用内核红黑树管理 fd，只返回「就绪」的集合，复杂度从 O(n) 降到 O(就绪数)。

问题 1
阻塞和非阻塞到底差在哪？

阻塞调用会一直挂起线程直到数据就绪；非阻塞立刻返回，没数据就报错，需要你之后轮询或等事件通知。非阻塞让一个线程能照看成百上千个连接。

问题 2
同步 IO 和异步 IO 怎么区分？

同步 IO 在数据就绪后，读/写动作仍由你的线程完成；异步 IO 连读写的拷贝都交给内核，做完再通知你。所以 epoll 属于同步（你亲自 read），io_uring 更接近异步。

问题 3
epoll 为什么比 select 快？

select 每次调用都要把全部 fd 从用户态拷进内核并线性遍历；epoll 在内核维护就绪队列，只把「真有事件」的 fd 给你，省去了重复拷贝和全量扫描。

问题 4
Reactor 和 Proactor 怎么选？

Linux 上 Reactor（epoll + 非阻塞）生态最成熟、最常用；追求极致低延迟且内核支持时，可用 io_uring 风格的 Proactor。业务层通常无感知，由框架封装。
