①NULL 到底表示什么

NULL 的语义是「值未知 / 不适用」，而不是「空」「0」「空字符串」。 这个区分是理解所有 NULL 行为的起点：既然未知，那么任何对它的比较都只能是「不确定」， 于是有了三值逻辑。

NULL / 空串 / 零值 是三种不同的「没有」

②NULL 在不同语境下的行为

语境NULL 的行为后果与应对
WHERE 比较结果为 UNKNOWN，行被丢弃<> 'x' 会漏掉 NULL 行
NOT IN子查询含 NULL → 整体永远空集改用 NOT EXISTS
聚合函数SUM/AVG/COUNT(col) 忽略AVG 的分母不含 NULL，与「算 0」不同
COUNT(*)数行数，不忽略COUNT(*)-COUNT(col) 即 NULL 个数
DISTINCT / UNION多个 NULL 视为相等，合并成一份与 = 的三值逻辑相反
GROUP BY所有 NULL 归为同一组与 DISTINCT 一致
ORDER BY位置由实现决定，跨库不同显式写 NULLS FIRST/LAST
唯一索引允许多个 NULL（多数实现）想严格唯一要加 NOT NULL 或部分索引
外连接补行未匹配侧全部填 NULL用 WHERE 右键 IS NULL 找「没有」的记录
CHECK 约束表达式为 NULL → 视为通过必须同时加 NOT NULL
字符串拼接CONCAT(a, NULL) 结果为 NULL（多数库）用 COALESCE(a,'') 或 CONCAT_WS
最反直觉的一条是「聚合忽略 NULL，但去重认为 NULL 相等」。 这两条规则方向相反，却都是标准规定的。写统计 SQL 时务必明确： 「用户数」到底要不要把 phone IS NULL 的人算进去。

③处理 NULL 的函数

函数作用示例
COALESCE(a, b, ...)返回第一个非 NULLCOALESCE(nickname, username, '匿名')
NULLIF(a, b)相等则返回 NULLNULLIF(cnt, 0) 避免除零 → 结果为 NULL 而非报错
IFNULL / ISNULL / NVL各库的 COALESCE 双参数版跨库写 SQL 优先用标准 COALESCE
IS NULL / IS NOT NULL判断唯一正确的 NULL 判断方式
IS DISTINCT FROMNULL 安全的「不等」PG / SQL 标准；MySQL 用 <=> 的否定
-- 除零保护：cnt=0 时结果为 NULL，不会报错
SELECT total / NULLIF(cnt, 0) AS avg_value FROM t;

-- 多列兜底展示
SELECT COALESCE(nickname, username, CONCAT('user_', id)) AS display FROM users;

-- 「状态不是 done」包含 NULL 的完整写法
SELECT * FROM t WHERE status IS DISTINCT FROM 'done';
不要在 WHERE 里对列用 COALESCE 兜底。 WHERE COALESCE(status,'') = 'done' 会把列包进函数，索引直接失效。 正确写法是 WHERE status = 'done'，让 NULL 自然被过滤掉； 或者 WHERE status = 'done' OR status IS NULL（若两者都要）。

④设计取舍：什么时候允许 NULL

允许 NULL 的理由

语义上确实「不适用」（如「删除时间」对未删除记录）； 外连接补行无法避免；加列时存量数据没有值，用 NOT NULL DEFAULT 会写入一个假值。

禁用 NULL 的理由

三值逻辑让每个查询都要额外考虑；聚合语义容易算错； 应用层语言（Java Integer、Go *T）要额外处理空指针； NOT IN、拼接、比较全是坑。

一条实用原则：核心业务字段（金额、状态、时间、外键）默认 NOT NULL + 明确默认值； 只有「语义上确实未知」的字段才允许 NULL。 对于「可选的文本字段」，团队内统一约定要么全是 NULL、要么全是空串—— 混用是数据质量问题的高发区。用 NOT NULL DEFAULT '' 统一成空串通常更好处理 （避免三值逻辑，且拼接、比较都正常）。
Q：为什么 SELECT * FROM t WHERE col NOT IN (SELECT ...) 返回空？
A：子查询只要出现一个 NULL，x NOT IN (a, b, NULL) 就恒为 UNKNOWN。 改成 NOT EXISTS (SELECT 1 FROM ... WHERE ...)——它对 NULL 是安全的。
Q：AVG 遇到 NULL 时分母算不算它？
A：不算。AVG(col) = SUM(col) / COUNT(col)，两者都忽略 NULL。 想让 NULL 当 0 参与平均，必须显式写 AVG(COALESCE(col, 0))—— 这两个结果含义完全不同，务必先明确业务口径。
Q：唯一索引允许多个 NULL，怎么让它严格唯一？
A：三种办法：① 列加 NOT NULL（最直接）； ② 建部分唯一索引 CREATE UNIQUE INDEX ... WHERE col IS NOT NULL（PG、SQL Server 支持）； ③ MySQL 无部分索引，可用生成列或把「空」表达成确定的哨兵值。

三值逻辑真值表

SQL 的逻辑运算不是二值而是三值：TRUE / FALSE / UNKNOWN。NULL 参与比较的结果是 UNKNOWN，而 WHERE 只保留 TRUE 的行——这是所有 NULL 陷阱的根源。

NOT IN 陷阱

-- 经典陷阱：NOT IN 遇到 NULL 会返回空集
SELECT * FROM t WHERE id NOT IN (1, 2, NULL);
-- 展开为 id<>1 AND id<>2 AND id<>NULL
--               TRUE  AND TRUE  AND UNKNOWN  → UNKNOWN → 一行都不返回！

-- 正确写法 1：先过滤掉 NULL
SELECT * FROM t WHERE id NOT IN (SELECT id FROM s WHERE id IS NOT NULL);

-- 正确写法 2：用 NOT EXISTS（对 NULL 安全，且通常更快）
SELECT * FROM t WHERE NOT EXISTS (SELECT 1 FROM s WHERE s.id = t.id);

聚合与分组中的 NULL

场景行为要点
COUNT(*)计入 NULL 行统计行数用这个
COUNT(col)跳过 NULL统计非空值个数
SUM/AVG(col)跳过 NULLAVG 分母也是非 NULL 个数
SUM 全为 NULL返回 NULL不是 0！需 COALESCE(SUM(x),0)
GROUP BYNULL 归为一组所有 NULL 视为相等，与 = 行为不同
DISTINCTNULL 视为一个值同上，多个 NULL 去重为一个
ORDER BYNULL 位置随实现MySQL/Oracle 最前，PostgreSQL 最后；用 NULLS LAST 显式指定

聚合兜底

-- 陷阱：全 NULL 分组的 SUM 返回 NULL，参与算术会让整行变 NULL
SELECT dept, SUM(bonus) FROM emp GROUP BY dept;
--  bonus 全 NULL 的部门 → NULL，后续 NULL + 100 还是 NULL

-- 正确：用 COALESCE 兜底
SELECT dept, COALESCE(SUM(bonus), 0) AS total FROM emp GROUP BY dept;

NULL 与约束、索引

  • 唯一索引允许多个 NULL：MySQL/PostgreSQL 中 UNIQUE(col) 可以有多行 col 为 NULL（SQL 标准行为，SQL Server 例外只允许一个）。
  • 主键列隐含 NOT NULL，无需显式声明。
  • 外键值可以为 NULL：表示该行尚未关联，且不受外键约束检查。
  • 普通 B+ 树索引会存 NULL 值，但 WHERE col IS NULL 能否走索引取决于优化器与选择性——NULL 占比高时通常走全表。
  • CHECK 约束中 NULL 让检查结果为 UNKNOWN，视为通过，所以 CHECK(age > 0) 挡不住 NULL。

自检 Q&A

Q：为什么 WHERE col <> 'A' 查不到 col 为 NULL 的行？

A：因为 NULL <> 'A' 的结果是 UNKNOWN，WHERE 只保留 TRUE。要包含 NULL 行必须写成 WHERE col <> 'A' OR col IS NULL，或用 COALESCE(col,'') <> 'A'。

Q：COUNT(*) 和 COUNT(1) 有区别吗？

A：没有，现代优化器完全等价（COUNT(1) 中的常量非空，等价于统计行数）。真正有区别的是 COUNT(col)，它会跳过 NULL。性能上三者在同一引擎里执行计划相同。

Q：左连接后如何判断“没有匹配”？

A：在右表的非空列上判 IS NULL：LEFT JOIN s ON ... WHERE s.id IS NULL。注意必须挑右表的主键或声明为 NOT NULL 的列——如果挑的列本身允许 NULL，会把“匹配到了但值为 NULL”的行也误判为未匹配。

Q：COALESCE 和 IFNULL 怎么选？

A：COALESCE 是标准 SQL且可接多个参数（返回第一个非 NULL）；IFNULL 是 MySQL 方言，只接两个。跨库项目统一用 COALESCE。注意两者都会让该列上的索引失效（因为函数包裹），高频过滤场景要谨慎。
