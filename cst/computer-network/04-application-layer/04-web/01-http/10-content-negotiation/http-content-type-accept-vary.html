Content-Type、Accept、Accept-Encoding 与 Vary：同一 URL 为什么有不同响应

用 JSON API 与压缩页面解释请求期望、响应格式、缓存变体和 406/415。

四个头分别回答不同问题

客户端用 `Accept` 表示希望接收哪些媒体类型，如 `application/json`；请求体本身的 `Content-Type` 表示发给服务器的数据是什么格式。响应的 `Content-Type` 则告诉客户端收到的正文是什么格式。`Accept-Encoding` 表示客户端支持 gzip、br 等内容编码，响应的 `Content-Encoding` 告诉客户端实际正文如何压缩。把媒体类型和内容编码混在一起，会出现“明明是 JSON，却解不出来”的错误。

例如 POST JSON 时客户端发送 `Content-Type: application/json` 和 JSON 正文；服务器回复 `Content-Type: application/json`。若请求体实际是表单却标成 JSON，服务器应根据协议契约拒绝或明确转换，而不应盲猜。浏览器 `fetch` 发送 JSON 字符串时也要正确设置请求头，否则服务端解析器可能走错分支。

Accept 与 406

假设同一路径 `/report/7` 可返回 HTML 或 JSON。客户端声明 `Accept: application/json`，服务器选择 JSON；声明只接受服务端不支持的格式时，可返回 406 Not Acceptable。很多 API 只支持一种表示，可能按自己的契约忽略过宽的 Accept，但不能把服务端返回了 JSON 就解释为客户端发的 Content-Type 正确。

`Accept` 可带质量权重，例如浏览器更偏好 HTML、也接受其他类型；实际选择还取决于服务器支持。做版本迁移时不要在相同 URL 上随意改变默认格式，旧客户端可能把新正文当旧格式解析。接口文档应写清接受的请求类型和可能的响应类型。

Content-Type 与 415

客户端向只支持 JSON 的接口发送 `Content-Type: text/plain`，服务器可以返回 415 Unsupported Media Type。415 针对请求正文的表示格式，406 针对响应表示与 Accept 无法协商，两个方向不同。服务端不能只因正文第一个字符是 `{` 就把任意文本当成可信 JSON；必须检查大小、编码、结构与业务字段。

文本还涉及字符编码。现代 JSON 通常使用 UTF-8，但历史接口可能在 `Content-Type` 里声明 charset。客户端若按错误编码解读，即使 HTTP 200 也可能出现乱码或解析失败。压缩后的字节先按 Content-Encoding 解码，再按媒体类型和字符编码解释。

压缩怎么协商

客户端发送 `Accept-Encoding: br, gzip`，服务器可选择 brotli 或 gzip，回复对应 `Content-Encoding`；未压缩时不应乱写 gzip。压缩可降低传输字节数，但需要 CPU；对很小或已压缩的图片再压缩可能收益小。动态压缩高并发时还要测 CPU 与首字节时间。代理和 CDN 可能替源站压缩或解压，因此排障要对齐实际响应体与响应头。

若服务器发送 gzip 字节却漏写 Content-Encoding，浏览器会把压缩数据当成原始 JSON；若写了 gzip 但正文未压缩，解码会报错。某些客户端库会自动解压并改写可见响应头，抓包和程序输出不一致时要注意库的行为。

Vary 是缓存安全的一部分

同一 URL 可因 `Accept-Encoding` 返回 gzip 与 br 两种字节表示，缓存必须区分客户端支持能力。响应可用 `Vary: Accept-Encoding` 告诉共享缓存该请求头会影响表示选择。若同一 URL 还按语言返回内容，可使用相应 Vary 维度。Vary 过多会降低缓存命中率，漏写又可能把不适合某客户端的表示交给它。

用户身份与租户信息不能仅寄希望于 Vary 自动隔离。带个人数据的响应应按权限与缓存策略决定是否可进入共享缓存，必要时使用 private/no-store 等指令。缓存键的实际行为还依 CDN 配置，须用两个用户和两种编码实测。

一次端到端检查

用命令行分别请求 `Accept: application/json`、`Accept: text/html`，观察 200/406、响应 Content-Type 与正文是否一致；发送错误 Content-Type 测 415。再分别发送 `Accept-Encoding: gzip` 和 `br`，检查返回字节、Content-Encoding、Vary 与缓存命中。若 CDN 参与，比较源站和边缘响应，确认两种编码没有交叉缓存。

最终验收不是“返回头看起来正确”，而是客户端能按协商结果成功解码，旧客户端仍能接受兼容表示，缓存不会跨语言、编码或用户边界串内容。

自检

请求头 Content-Type 和 Accept 都写 application/json，含义一样吗？

不一样。Content-Type 描述请求正文格式，Accept 表示客户端希望接收的响应格式。
