🔢 训练·对比学习 3. 对比学习

对比学习：SimCSE / E5 / BGE

Word2Vec / GloVe 是'词'时代。到了'句 / 段'时代，主流方法是对比学习：构造正例（同义、邻近句）与负例（随机句），训练模型让正例向量更近、负例更远。

3. 对比学习：现代句向量是怎么炼成的

3.1 核心损失：InfoNCE

对比学习的标准损失把'在 N+1 个候选里找出唯一正例'变成分类问题：

L = −log [ exp(sim(a,p)/τ) / ( exp(sim(a,p)/τ) + Σ exp(sim(a,nᵢ)/τ) ) ]

温度 τ 控制分布的尖锐程度；分子是正例相似度，分母是'正例 + 所有负例'。模型被迫把正例相对负例拉得足够高。

3.2 经典套路：SimCSE、E5、BGE 怎么做的

方法正例怎么来特点
SimCSE同一句过两次 dropout，得到两个略不同的向量互为正例无需标注，无编码器改造，极简
E5 / BGE人工构造 'query: …' / 'passage: …' 对，用大规模检索对训练需标注/弱标注对，检索效果强
SBERT用孪生网络 + 回归/分类目标，句对微调早期句向量主流，现多被对比法超越
为什么'句式前缀'（query: / passage:）那么重要？因为检索时查询和文档长度、风格差异巨大。显式前缀让模型在训练时就区分'我要查'和'我是资料'，否则同一句当查询和当文档向量会混在一起，检索崩盘。

3.3 最常见的坑：负例太弱 / 批太小

  • 负例全是随机句：太容易被推开，模型学不到细粒度区分。好系统用'in-batch negatives'（同一批里其他句当负例）扩大负例数。
  • 批大小直接决定负例数：批太小→负例少→容易过拟合到'拉开随机句'这种无聊目标。BGE 类常用大 batch（上千）。
  • 难负例（hard negatives）：与正例相关但不同的句子（同主题不同答案）最能提升效果，需要专门挖掘。
