常用设计模式（Go 视角）

Go 不强调经典 23 种模式，而是用接口、组合与并发原语自然表达。一篇讲清 Go 里真正常用的几种。

概述

用组合代替继承

Go 没有继承，模式靠接口 + 结构体嵌入 + 函数实现。很多经典模式在 Go 里被语言特性直接消解。

例如策略/模板方法，用函数字段或接口字段即可，无需一层层抽象类。
创建型

选项模式最常见

构造函数用「选项模式」（可变参数函数）逐步配置；单例多用 sync.Once 或包级变量懒初始化。

func NewServer(opts ...Option) *Server {
    s := defaultServer()
    for _, o := range opts { o(&s) }
    return s
}
s := NewServer(WithPort(8080), WithTLS(true))
结构型

装饰即包装

中间件/装饰器用函数包装 Handler/接口；适配器用单方法接口对接异构实现；组合（embedding）实现「has-a」。

type Logger struct{ next Handler }
func (l Logger) Handle(r Req) { log(r); l.next.Handle(r) }
行为型

接口解耦

策略=接口字段；观察者=注册回调切片；状态机=状态接口切换。Go 的接口隐式实现让这些格外轻量。

隐式接口

实现方无需声明「我实现了 X」，只要方法集匹配，天然解耦调用方与实现方。

并发型

Go 的拿手好戏

fan-in/fan-out、worker pool、pipeline、or-channel 取消，都是用 channel + goroutine 组合而成，远超传统模式的表达力。

这些并发模式在标准库与社区库中反复出现，是 Go 工程师的必备套路。
