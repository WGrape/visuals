查询执行流程与 EXPLAIN

从 SQL 文本到元组的四阶段，以及如何用 EXPLAIN 读懂执行计划。

四阶段执行计划节点EXPLAIN 实战常见扫描/连接

① 查询处理四阶段

  • Parser：词法/语法分析，生成解析树。
  • Rewriter：应用规则与视图展开（含视图、规则）。
  • Planner（优化器）：基于成本的 CBO，枚举计划估算代价，选最优。
  • Executor：按计划树逐层拉取（火山模型）产出元组。

② 执行计划节点

计划是一棵树，叶子是扫描节点，上层是连接/聚合/排序。每个节点向父节点 按需拉取 元组（迭代器模型）。

③ EXPLAIN 实战

EXPLAIN ANALYZE
SELECT * FROM orders WHERE user_id = 42 ORDER BY created_at DESC LIMIT 10;

输出解读要点：

  • (cost=0.29..8.31 rows=10)：启动代价..总代价，优化器估计行数。
  • actual time=... rows=...：真实耗时与行数（加 ANALYZE 才有）。
  • 若 actual rows 远大于 estimated rows，说明统计信息过期 → 跑 ANALYZE。

④ 常见扫描与连接

节点含义何时出现
Seq Scan全表扫描无合适索引 / 大比例数据
Index Scan索引定位 + 回表命中索引且需列多
Index Only Scan仅索引覆盖索引
Bitmap Scan位图合并多条件 + 索引
Nested Loop / Hash / Merge Join三种连接小表驱动 / 哈希 / 已排序
排错顺序：先看是否走了预期索引；再看 rows 估计是否失准（统计信息）；最后看是否有多余的排序/物化。
