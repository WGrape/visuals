开机那几秒里发生了什么

按下电源到出现登录界面，计算机走过一条固定的链路：上电复位 → 固件（BIOS/UEFI）→ 硬件自检 → 定位启动设备 → 引导加载程序 → 内核 → 用户态初始化。每一步失败都有对应的现象，看懂这条链路，开机故障就不再神秘。

固件主板上的 BIOS/UEFI，CPU 复位后执行的第一段代码
POST加电自检：检查内存、CPU、外设是否正常
MBR / GPT磁盘分区表，决定从哪个分区启动
BootloaderGRUB 等，负责把内核与 initramfs 载入内存
initramfs临时根文件系统，内含启动根分区所需的驱动
1 号进程systemd/init，之后由它拉起所有服务

BIOS 与 UEFI

对比项传统 BIOSUEFI
出现年代1980 年代，16 位实模式2000 年代后，支持 32/64 位
分区表MBR，最大 2TB、最多 4 主分区GPT，支持超大磁盘与更多分区
启动方式读取磁盘首个扇区（MBR）并跳转直接读取 EFI 分区中的 .efi 启动文件
安全能力无Secure Boot：校验启动文件签名，防恶意引导
界面与扩展文本界面、扩展困难图形界面、支持网络与模块化驱动
兼容性老系统与老硬件通过 CSM 兼容模式启动老系统，但新系统建议纯 UEFI

实务提示：装系统时若出现「Windows 用 UEFI、Linux 用 Legacy」的混装，会导致双系统引导失败；统一启动模式是第一步。移动硬盘装系统也常卡在这里。

各阶段故障与排查

① 固件阶段

  • 现象：风扇转但屏幕无显示、主板蜂鸣报警。
  • 原因：内存未插好、显卡故障、CMOS 设置错误。
  • 排查：听蜂鸣码、清空 CMOS、最小化硬件（只留 CPU/内存/显卡）。

② 找不到启动设备

  • 现象：No bootable device / 进入 UEFI Shell。
  • 原因：启动顺序错误、硬盘未被识别、引导记录损坏。
  • 排查：进固件看是否识别硬盘；用安装盘修复引导（bootrec / grub-install）。

③ 引导程序阶段

  • 现象：grub rescue 提示符、找不到内核。
  • 原因：分区 UUID 变化、/boot 被误删、配置文件损坏。
  • 排查：grub 命令行手动指定内核与 initrd 启动，进入系统后重装 grub 并更新配置。

④ 内核与用户态

  • 现象：kernel panic、卡在挂载根文件系统、循环重启。
  • 原因：initramfs 缺驱动（如 RAID/加密/新硬盘控制器）、根分区 UUID 错误。
  • 排查：内核参数加 init=/bin/bash 或进单用户模式；查看 dmesg 与 journalctl。
  • 服务器：通过 IPMI/KVM 或云控制台查看串口输出。

深入自检

为什么开机时只能访问 1MB 内存？

因为 x86 CPU 复位后处于实模式（为了兼容 8086），地址线只有 20 位，可寻址 1MB。固件先在这 1MB 里跑起来，之后由操作系统把 CPU 切到保护模式（32 位）或长模式（64 位），才能使用全部内存。

initramfs 是干什么用的？

它是一个被临时挂载为根文件系统的小型内存文件系统，里面放了启动真正的根分区所必需的驱动与工具。因为根分区可能在 RAID、LVM、加密卷或特殊控制器上，内核本身不认识这些，需要先加载驱动才能挂载。

UEFI 的 Secure Boot 会阻止装 Linux 吗？

主流发行版（Ubuntu、Fedora、Debian 等）都提供签名的引导程序，可以直接通过 Secure Boot。自编译内核或小众发行版可能需要手动签名，或在固件里临时关闭 Secure Boot。

双系统为什么经常装完就进不去？

最常见是两个系统用了不同启动模式（一个 UEFI、一个 Legacy），或者后装的系统覆盖了引导记录、没有正确识别另一个系统。解决方式是统一为 UEFI + GPT，装完后更新 GRUB 让其自动探测。

服务器开机卡住看不到画面怎么办？

优先用带外管理（IPMI/iDRAC/iLO）或云厂商的 VNC/串口控制台，它们能在没有 OS 的情况下看到画面与串口输出。同时配置内核串口控制台（console=ttyS0），这样启动日志可以远程采集与留存。

为什么有时开机很慢？

常见原因：固件自检时间长（内存训练、外接设备扫描）、网络启动（PXE）等待超时、磁盘检测与 fsck、systemd 中某个服务超时（可用 systemd-analyze blame 定位）。
