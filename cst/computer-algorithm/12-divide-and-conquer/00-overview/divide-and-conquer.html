第 12 章 · 分治

分解、求解与合并

把规模为 n 的问题拆成更小的同类问题，递归求解，再以明确的规则组合答案。

核心速览

分解 Divide把原问题拆成结构相同的子问题
求解 Conquer递归解决；足够小时直接算
合并 Combine把子答案按规则组合成原答案
主定理由 T(n)=aT(n/b)+f(n) 直接得复杂度

三步走：分、治、合

分治不是某个具体算法，而是一种组织递归的思路。它固定包含三步：

  1. 分解（Divide）：把规模为 n 的问题拆成 a 个规模约为 n/b 的同类子问题。
  2. 求解（Conquer）：递归地解决子问题；规模足够小（base case）时直接求解，不再递归。
  3. 合并（Combine）：把子问题的答案按明确规则组合成原问题的答案。
判断一个问题能否用分治的三条标准：① 子问题与原问题结构相同（才能递归）；② 子问题之间相互独立（不重叠，否则应该用动态规划）；③ 存在明确的合并规则。

三种典型形态

关键观察：三种形态的差别全在「子问题数 a」和「合并代价 f(n)」上。归并 a=2 且合并 O(n) → O(n log n)；二分 a=1 且合并 O(1) → O(log n)。复杂度几乎完全由递推式决定，所以写分治算法时，先把递推式写出来。

主定理：直接读出复杂度

对于形如 T(n) = a·T(n/b) + f(n) 的递推（a ≥ 1 个子问题，每个规模 n/b，合并代价 f(n)），主定理给出三种情况：

情况条件（比较 f(n) 与 n^(log_b a)）结果例子
① 合并更便宜f(n) = O(n^(log_b a − ε))T(n) = Θ(n^(log_b a))二分查找、Karatsuba 乘法
② 两者同阶f(n) = Θ(n^(log_b a))T(n) = Θ(n^(log_b a) · log n)归并排序、快排（平均）
③ 合并更贵f(n) = Ω(n^(log_b a + ε)) 且满足正则条件T(n) = Θ(f(n))某些分治卷积
归并排序：a=2, b=2 → n^(log₂2) = n；f(n) = O(n) —— 同阶，落在情况 ②，所以 T(n) = Θ(n log n)。
这里最关键的是 n^(log_b a)：它代表「递归树所有叶子的总代价」。主定理本质上就是在比较「叶子层的总代价」和「每层合并的代价」谁占主导。理解这一点比背公式有用得多。

分治 vs 动态规划

维度分治动态规划
子问题相互独立、不重叠大量重叠
做法递归求解，不管重复记忆化 / 填表，每个子问题只算一次
复杂度子问题数决定，可能指数级状态数 × 转移代价
例子归并排序、快排、二分、最近点对斐波那契、背包、最长公共子序列
判断口诀：画出递归树，如果两个分支里出现了「同一个子问题」，就该用动态规划（加个 memo 就能把指数级降到多项式）。经典例子：朴素递归算斐波那契是指数级，加记忆化后是 O(n)。

经典应用

# 快速幂：分治最漂亮的小例子
def pow_fast(a, n):
    if n == 0: return 1
    half = pow_fast(a, n // 2)
    return half * half * (a if n % 2 else 1)
# T(n) = T(n/2) + O(1) → O(log n)，而循环乘 n 次是 O(n)

🎯 面试问答

Q：分治的三步是什么？判断能否用分治的标准是什么？

A：三步：分解（把规模 n 的问题拆成 a 个规模约 n/b 的同类子问题）、求解（递归解决，规模足够小时直接算）、合并（把子答案按规则组合）。三条判断标准：① 子问题与原问题结构相同（才能递归）；② 子问题之间相互独立、不重叠（重叠就该用动态规划）；③ 存在明确的合并规则。

Q：主定理怎么用？

A：对形如 T(n) = a·T(n/b) + f(n) 的递推，比较 f(n)（每层合并代价）与 n^(log_b a)（所有叶子的总代价）：① f(n) 更小 → T(n) = Θ(n^(log_b a))；② 同阶 → T(n) = Θ(n^(log_b a) · log n)；③ f(n) 更大（且满足正则条件）→ T(n) = Θ(f(n))。例如归并排序 a=2、b=2 → n^(log₂2)=n，f(n)=O(n) 同阶，落在情况 ②，得 Θ(n log n)。理解「n^(log_b a) 就是叶子层总代价」比死记公式更重要。

Q：分治和动态规划的核心区别是什么？

A：子问题是否重叠。分治的子问题相互独立、不重叠（归并排序的左右两半完全是不同数据），所以直接递归求解即可。动态规划的子问题大量重叠（如递归算斐波那契时 F(n−2) 被反复计算），朴素递归会做指数级重复劳动，必须用记忆化（memo）或自底向上填表把每个子问题只算一次，从而降到多项式。判断口诀：画出递归树，若两个分支里出现同一个子问题，就该用动态规划。

Q：为什么快速幂是 O(log n)？

A：因为利用 a^n = (a^(n/2))²（n 为偶数）或 a·(a^(n/2))²（n 为奇数），每次把指数减半，只递归一侧。递推式 T(n) = T(n/2) + O(1)，展开得 log n 层，每层常数代价，所以是 O(log n)；而循环乘 n 次是 O(n)。这是分治里最简单也最实用的例子，很多库（如 Python 内置 pow(a, n, mod)）都用它。

Q：分治和减治（减而治之）有什么不同？

A：严格说分治要求分解成多个子问题并合并（如归并排序分两半再合并）；减治则是每步把问题规模减小、只保留一个子问题、不需要合并，典型是二分查找（丢掉一半后只需处理剩下那一半）和欧几里得求最大公约数。教材里常把减治归入分治的简化情形，但分清两者有助于理解递推式：分治是 T(n) = aT(n/b) + f(n)（a > 1），减治是 T(n) = T(n/b) + f(n)（a = 1）。

Q：递归的 base case 该怎么写？

A：base case 是递归的终止条件，必须保证：① 问题规模确实在变小并朝 base case 收敛；② base case 能直接给出答案而不再递归。遗漏或写错 base case 会导致无限递归（栈溢出）或错误结果。写分治时建议先写 base case（如 if lo >= hi: return、if n == 0: return 1），再写分解和合并——先想清楚「最小的问题是什么」，再想怎么拆。

分治模板与归并排序

# 分治三段式模板
def divide_conquer(problem):
    if is_small(problem):                       # 1) 规模足够小，直接解
        return solve_directly(problem)
    subs = split(problem)                       # 2) 拆成结构相同的子问题
    results = [divide_conquer(s) for s in subs]
    return merge(results)                       # 3) 合并子问题的解

# 归并排序：最标准的分治（拆 O(1)、合 O(n)、共 log n 层 -> O(n log n)）
def merge_sort(a):
    if len(a) <= 1: return a
    m = len(a) // 2
    L, R = merge_sort(a[:m]), merge_sort(a[m:])
    i = j = 0; out = []
    while i < len(L) and j < len(R):            # 合并是线性的两路归并
        if L[i] <= R[j]: out.append(L[i]); i += 1
        else:            out.append(R[j]); j += 1
    return out + L[i:] + R[j:]

量化提醒：合并步骤的复杂度决定总量级。归并排序合并 O(n) × log n 层 = O(n log n)；若合并写成 O(n²)，整体就是 O(n²)。

第三层 · 排障与边界：递归与合并的坑

坑后果正确做法
终止条件缺失或写错无限递归 / 栈溢出明确 if len <= 1: return
子问题规模没变小死循环确保每次递归 n 严格减小
合并写成 O(n²)整体退化合并要线性扫描
递归深度过大爆栈（Python 默认约 1000 层）分治通常 log n 层安全；链表式划分可到 n 层
区间开闭不统一漏元素或重复全程统一用闭区间或半开区间
  • 排查顺序：先确认终止条件 → 再看规模是否递减 → 再评估合并复杂度 → 最后测空 / 单元素 / 两元素。
  • 边界一：快排若总取首元素做 pivot，已排序数组会退化到 O(n²) 且递归 n 层爆栈——用三数取中或随机 pivot。
  • 边界二：分治最难的往往是「合」这一步（如最近点对要处理跨中线的带状区域）。
  • 边界三：子问题重叠时不要用分治，会指数级重复计算——改记忆化或 DP。

分治和 DP 到底怎么区分？

看子问题是否重叠：不重叠 → 分治（各自独立求解再合并）；重叠 → DP（记忆化复用）。归并排序的子区间互不重叠，是分治；斐波那契递归的子问题大量重复，是 DP。

分治一定要递归吗？

不必然，但递归是最自然的表达（问题定义本身就是自相似的）。可以写成迭代（自底向上的归并排序就是），但代码通常更绕。

递推式应写出子问题数量、规模与合并代价。
