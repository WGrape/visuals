神经网络地基

架构演进：从 MLP / CNN / RNN / LSTM 到注意力

为什么最后是 Transformer 赢了？因为每一代架构都在解决上一代的一个致命瓶颈：MLP 不懂结构、CNN 不懂长程、RNN 不能并行、LSTM 仍受限于串行。本文顺着这条演进线讲清每种结构的归纳偏置与它解决的核心问题。

演进全景

核心脉络：谁能更好地利用"结构先验"，同时还能并行计算，谁就赢。

MLP：不懂结构

每个输入维度连到每个神经元，没有任何关于"数据长什么样"的假设。

问题：① 参数量随输入维度爆炸；② 对图像来说，把像素顺序打乱它照样学，完全浪费了"相邻像素相关"这一先验；③ 对序列来说，输入长度必须固定。所谓"归纳偏置太弱"。

CNN：局部性 + 权值共享

卷积核只扫一小块区域，且同一个核在全图复用。两大先验：

局部性：相邻像素才有强相关，远端像素不必一上来就连。
→ 层数加深后感受野逐层扩大，等价于"先看边角、再拼部件、最后成物体"。
平移不变 / 权值共享：同一个特征（比如"竖边"）出现在图的哪个位置都用同一套参数识别。
→ 参数量暴降，且天然泛化。
CNN 的局限：感受野有限，不擅长建模长程依赖；而且它本质是为网格数据设计的，处理文本序列很别扭。

RNN：为序列而生，但有两个致命伤

按时间步逐步推进，把上一步的隐藏状态传给下一步，理论上能处理任意长度：

h_t = f(W·x_t + U·h_{t-1})
伤一：长程遗忘
信息要穿过一连串矩阵乘法才能传到远处，梯度消失导致学不会远距离依赖。
伤二：无法并行
h_t 依赖 h_{t-1}，必须一步步串行算。训练速度被序列长度卡死，没法用 GPU 大规模堆数据。

LSTM / GRU：用门控修长程依赖

LSTM 引入一条"细胞状态"的高速公路，并用三个门来控制信息流：

遗忘门
决定丢弃多少旧记忆
输入门
决定写入多少新信息
输出门
决定对外暴露多少
因为记忆主要在一条加法通道上传（而不是反复矩阵乘），梯度能相对顺畅地流动，长程依赖问题解决了一大半。GRU 是它的简化版（两个门），更快、参数更少。
但 串行计算这个伤没治好：LSTM 依然是逐步推进的，训练吞吐上不去。这是它被 Transformer 取代的根本原因——不是能力不够，而是不适合规模化。

Attention 的第一次登场：给 Seq2Seq 解瓶颈

Seq2Seq（编码器-解码器）要把整个句子压成一个定长向量再解码，长句信息必然挤爆。注意力机制的解法很直接：

别压缩了——解码每一步时，让解码器直接去看编码器的所有位置，并按相关性加权取用。

Attention(Q, K, V) = softmax( QKᵀ / √d_k ) · V

Transformer：把注意力当主干，彻底丢掉循环

2017 年的关键洞察是：既然注意力这么好，为什么还要 RNN？ 于是直接用纯注意力 + FFN 堆叠：

任意两位置距离都是 1
不再需要信息穿过多层传递，长程依赖天然解决
全序列可并行
所有位置同时算，训练吞吐彻底释放，才有了后来"堆数据、堆参数"的规模化可能
丢掉循环也丢掉了顺序信息，所以必须显式加位置编码；代价是注意力的计算和显存随序列长度呈 平方 增长，这才引出后续 FlashAttention、MQA/GQA、KV Cache、长上下文外推等一系列工程优化。

面试速记卡

  • MLP：无结构先验，参数爆炸。
  • CNN：局部性 + 权值共享 + 平移不变；擅长网格数据，不擅长长程。
  • RNN：天然序列，但梯度消失 + 无法并行。
  • LSTM/GRU：门控 + 加法记忆通道，修好长程遗忘，但串行依旧。
  • Attention 首次登场：解决 Seq2Seq 定长向量瓶颈。
  • Transformer：纯注意力，任意位置距离 1 + 全并行 → 规模化成为可能；代价是 O(n²) 与需显式位置编码。

注意力计算量

# 自注意力的计算量（理解 n^2 的来源）
# Q, K, V : (n, d)   n=序列长度, d=维度
# Attention = softmax(Q @ K^T / sqrt(d)) @ V
#   Q @ K^T  : (n,d) x (d,n) -> (n,n)   计算量 O(n^2 * d)
#   @ V      : (n,n) x (n,d) -> (n,d)   计算量 O(n^2 * d)
# 总计 O(n^2 * d)，而 FFN 部分是 O(n * d^2)

# 数值示例：GPT-3 规模
# n = 2048, d = 12288
# 注意力部分: 2 * 2048^2 * 12288 ≈ 1.0e11 FLOPs per layer
# FFN 部分:   2 * 2048 * 12288^2 ≈ 6.2e11 FLOPs per layer
# => 短序列时 FFN 占大头；序列变长后注意力占比快速上升

# FlashAttention 的优化点：不减少 FLOPs，而是减少 HBM 读写
# 把 Q/K/V 分块载入 SRAM，在线 softmax 融合
# 效果：相同结果，显存从 O(n^2) 降到 O(n)，速度提升 2-4x

为什么 Attention 胜出

  • 并行为王：RNN 必须按时间步串行（第 t 步依赖第 t−1 步的隐状态），训练时长随序列长度线性增长，且无法充分利用 GPU 的并行能力。Transformer 一次矩阵乘法算完整个序列——这是它能训练千亿参数模型的根本前提。
  • 路径长度 O(1)：序列中任意两个位置的交互，RNN 需要 O(n) 步传递（信息在传递中衰减），CNN 需要 O(n/k) 层堆叠，而自注意力一步直达。这直接解决了长距离依赖问题。
  • 代价是归纳偏置变弱：CNN 的局部性与平移等变、RNN 的时序性都是“先验知识”，让模型在小数据上更容易学。Transformer 几乎没有先验，所以需要海量数据才能发挥——这也是“大模型 + 大数据”范式的技术根源。
  • CNN 并没有消失：① 视觉任务中 CNN 仍有效率优势（ViT 需要更多数据）；② 卷积被用作 Transformer 的补充（如 ConvNeXt、Swin Transformer 的局部窗口）；③ 很多多模态模型的视觉编码器仍是 ViT/CNN 混合。
  • RNN 的现代回归：Mamba、RWKV 等状态空间模型（SSM）在 2023 年兴起，用线性复杂度 O(n) 达到接近 Transformer 的效果，解决了长序列的 n² 问题。这是当前最活跃的方向之一。
  • 选型建议：图像分类/检测 → CNN 或 ViT（看数据量）；短序列 NLP → Transformer；超长序列（100K+） → 稀疏注意力、SSM（Mamba）或分块方案；语音/时序 → 曾经是 RNN，现在也大量转向 Transformer/Conformer。
Transformer 完全取代 RNN 了吗？

在主流大模型中基本取代了。但 RNN/LSTM 仍活跃在：① 边缘设备（推理时只需 O(1) 的隐状态，不需要缓存整个 KV）；② 实时流式处理（来一个处理一个，无需等完整序列）；③ 极长序列（避免了 n² 与 KV 缓存）。另外 Mamba 等 SSM 正在复兴“循环”思想。

n² 复杂度真的那么致命吗？

对短序列（< 4K）不致命，因为 FFN 的 O(n·d²) 也很大。但当序列到 32K、128K 时，注意力部分会主导，且 KV 缓存显存按 n 线性增长（GPT-3 规模下每 token 约 800 KB 的 KV）。实用的长上下文必须靠 FlashAttention、MQA/GQA、滑动窗口、稀疏化等组合手段。
