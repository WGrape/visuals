图像理解

图像理解四大任务：分类、检测、分割与 OCR

同样是「看懂一张图」，输出粒度和标注成本完全不同。本文对比分类、目标检测、语义/实例分割、OCR 四类任务的输出形态、评价指标与典型网络结构，并说明工程上如何选型。

从整图到逐像素：粒度越细，标注越贵

任务输出常用指标
图像分类整图一个（或几个）类别Accuracy / Top-5
目标检测每个物体的框 + 类别mAP、IoU、召回率
语义分割每个像素的类别（不区分个体）mIoU、像素精度
实例分割每个像素的类别 + 个体编号mAP（mask 级）
OCR文字区域 + 文本内容准确率、编辑距离
粒度排序：分类 < 检测 < 实例分割，标注成本与模型复杂度同步上升。选型原则是够用即可——能用检测解决就别上分割。

分类：骨干网络的演进

CNN 时代
VGG→ResNet（残差解决深层退化）→EfficientNet（复合缩放）
ViT 时代
切 patch 当 token；数据足够时上限更高
弱监督路线
CLIP 类图文对比预训练，零样本迁移能力强
迁移学习是分类任务的标配：用 ImageNet 预训练骨干 + 少量自有数据微调，通常远好于从零训练。

检测：一步还是两步

两阶段 Two-stage
先出候选框，再分类与回归（Faster R-CNN 系）。
精度高，速度慢
单阶段 One-stage
直接在网格上预测框与类别（YOLO / SSD 系）。
速度快，精度略逊但已追平

核心难点：密集/小目标、遮挡、长尾类别。工程手段包括锚框（anchor）设计或无锚（anchor-free）、多尺度特征融合（FPN）、以及针对难样本的损失（Focal Loss）。

指标陷阱：mAP 的实现版本（COCO vs VOC）与 IoU 阈值不同会导致分数不可直接比较。

分割与 OCR：各自的特殊难点

分割
语义分割不区分个体；实例分割要区分。
难点：边缘精度、小物体、显存（高分辨率特征图很吃显存）
OCR
通常拆成文字检测（框）+ 文字识别（内容）两段。
难点：弯曲/竖排文字、模糊、复杂背景、多语言
近年趋势：多模态大模型（VLM）在 OCR 与开放词汇检测上表现突出，尤其在版面理解、表格还原这类需要语义的任务上超过传统流水线。

面试速记卡

  • 任务递进：分类（整图标签）→ 检测（框）→ 分割（像素）→ 实例分割（像素+个体）。
  • 指标：分类看 Accuracy/Top-5；检测看 mAP/IoU；分割看 mIoU。
  • 检测两派：两阶段精度高、单阶段速度快；难点是密集小目标与长尾。
  • 分割：语义不区分个体、实例区分；高分辨率很吃显存。
  • OCR：检测+识别两段式；VLM 在版面与表格场景优势明显。

四大视觉理解任务的关系

任务输出粒度回答什么问题标注成本典型应用
图像分类整图一个标签这张图是什么？低（打标签）相册分类、内容审核
目标检测类别 + 边界框有什么？在哪？中（画框）安防、自动驾驶、计数
语义分割像素级类别每个像素属于什么类？高（勾轮廓）医学影像、遥感、背景虚化
实例分割像素级 + 个体 ID每个物体个体在哪、什么形状？最高机器人抓取、细胞计数

通用的技术底座

骨干网络 Backbone

所有视觉任务共享的特征提取器：ResNet、EfficientNet、Swin Transformer、ViT 等。通常在 ImageNet 上预训练，再迁移到具体任务。选它决定了模型的上限与速度。

特征金字塔 FPN

把深层的强语义特征与浅层的高分辨率特征融合，得到多尺度特征图。这让同一模型能同时检测大目标和小目标——是现代检测/分割的标配组件。

迁移学习

在大数据集上预训练 → 在小数据集上微调。视觉领域最重要的实践技巧，让几千张标注也能训出可用模型。

注意力机制

让模型学会「看哪里」。从 SE/CBAM 这类通道-空间注意力，到 ViT 的全局自注意力，本质都是动态加权重要区域。

落地时的取舍

精度 vs 速度输入分辨率对速度是平方级影响；先降分辨率往往比换小模型更立竿见影
标注成本分类 < 检测框 < 分割掩膜，先想清楚最小够用的任务
部署环境云端 GPU vs 边缘 NPU，决定能否用大模型；量化能省 2~4 倍算力
数据分布训练数据与线上数据不一致是效果差的第一大原因
可解释性检测/分割的框与掩膜本身提供了一定可解释性，分类则较难

深入自检

图像分类、检测、分割该怎么选？

按两个问题决策：①需不需要知道位置——不需要就用分类（最省事，标注成本最低）；需要则继续问②框够不够用——够用就做检测，需要精确轮廓才做分割。分割的标注成本通常是检测的 5~10 倍（要逐像素勾轮廓），如果业务只是「画面里有没有人」「有几辆车」，检测就够了，不要过度设计。

为什么所有视觉任务都能共享同一个骨干网络？

因为底层视觉特征是通用的。无论最终任务是分类、检测还是分割，网络前几层学到的都是边缘、角点、纹理、简单形状——这些与具体任务无关。在 ImageNet 上预训练的骨干已经把这些学好了，后面的任务只需要在此基础上加一个专门的「头」（分类头、检测头、分割头）。这就是迁移学习奏效的根本原因，也是视觉领域最重要的工程实践。

FPN 特征金字塔解决了什么问题？

解决多尺度目标问题。深层特征图语义强但分辨率低（小目标可能只剩 1 个像素），浅层特征图分辨率高但语义弱（不知道那是「人」）。FPN 把深层特征上采样后与浅层特征逐元素相加，得到一系列既有语义又有分辨率的多尺度特征图，然后在不同尺度的特征图上分别检测不同大小的目标（大目标用深层，小目标用浅层）。这让小目标检测性能大幅提升。

模型线上效果比测试集差很多，通常是什么原因？

最常见的是数据分布不一致（domain shift）：训练集是网上爬的清晰规整图片，线上是手机拍摄的模糊、逆光、带角度的图片。其次是预处理不一致：训练时做了归一化、Resize、色彩空间转换，线上漏做或参数不同（这是非常高频的低级错误）。第三是评估集有泄露或与线上分布不同。排查方法：拿真实线上数据建一个小测试集，按场景（光照、角度、清晰度）拆开分别看指标，能快速定位短板。

视觉模型部署到边缘设备有哪些提速手段？

按性价比排序：①降低输入分辨率（速度提升近似平方级，但精度损失也快，要权衡）；②模型量化（FP32→INT8，算力省 2~4 倍，精度损失通常 <1%）；③换更小的骨干（MobileNet、ShuffleNet、EfficientNet-Lite）；④结构化剪枝（砍掉冗余通道）；⑤用硬件专用推理引擎（TensorRT、OpenVINO、NCNN、CoreML）；⑥批处理与流水线并行。实践上通常先量化 + 换推理引擎，这两步投入产出比最高。

任务难度递进：分类只需判断「是什么」；检测要额外给出「在哪」（定位）；分割要精确到「每个像素」；关键点要定位「语义明确的点」。标注成本也随之暴涨：分类每张图 1 个标签，检测 几十个框，实例分割要逐像素描边（每张图常需 1~5 分钟）。

迁移学习与微调的实用参数

# 迁移学习：用 ImageNet 预训练权重微调自己的分类任务
import torch, torchvision
from torch import nn

model = torchvision.models.resnet50(weights="IMAGENET1K_V2")
model.fc = nn.Linear(model.fc.in_features, num_classes)     # 只换最后一层

# 分层学习率： backbone 小，新头大（最有效的技巧之一）
optimizer = torch.optim.AdamW([
    {"params": model.layer4.parameters(), "lr": 1e-4},      # 靠近输出的学习率稍大
    {"params": model.layer1.parameters(), "lr": 1e-5},      # 底层特征通用，几乎不动
    {"params": model.fc.parameters(),     "lr": 1e-3},      # 新头从零学，最大
], weight_decay=1e-4)

# 数据量与学习率的经验对应关系
#   样本 < 1千   : 冻结 backbone，只训分类头，lr=1e-3
#   样本 1千~1万 : 解冻最后 1~2 个 stage，lr=1e-4 ~ 1e-5
#   样本 > 10万  : 全部解冻，lr=1e-4，或从头训练
# 数据增强（分类任务最有效的几项）
from torchvision import transforms
train_tf = transforms.Compose([
    transforms.RandomResizedCrop(224, scale=(0.6, 1.0)),   # 随机裁剪+缩放
    transforms.RandomHorizontalFlip(0.5),
    transforms.ColorJitter(brightness=0.3, contrast=0.3, saturation=0.3, hue=0.1),
    transforms.RandomErasing(p=0.3, scale=(0.02, 0.2)),    # 随机遮挡，抗遮挡很有效
    transforms.ToTensor(),
    transforms.Normalize(mean=[0.485,0.456,0.406], std=[0.229,0.224,0.225]),
])
# 注意：Normalize 必须用与预训练相同的 ImageNet 统计量，否则预训练权重失效

# 检测/分割不能用 RandomErasing（会破坏框），要用 bbox 同步变换的增强

症状原因处理
