🐘 HBase 概览

构建在 HDFS 之上的列式 NoSQL 数据库

什么是 HBase

HBase 是一个构建在 HDFS 之上的、分布式的、面向列族的开源 NoSQL 数据库，灵感来自 Google 的 BigTable 论文。它用廉价机器横向扩展，存储数十亿行 × 数百万列的稀疏宽表，主打海量数据的实时随机读写。

📊

列式 / 稀疏

数据按列族物理聚簇，空单元格不占空间，适合宽而稀疏的表与按列扫描。

🚀

海量写入

基于 LSM 树，写吞吐极高，PB 级数据、毫秒级点查是典型场景。

🔑

强一致行级

单行内的操作是原子的；没有跨行 ACID 事务（2.x 起有有限的多行事务）。

🧱

依赖 HDFS

数据最终落在 HDFS，可靠性（多副本）与扩展性由 HDFS 提供。

数据模型一句话

HBase 的表本质是一个多维、稀疏、有序的映射：

(rowkey, column-family:qualifier, timestamp)  →  value
  • rowkey：行键，唯一标识一行，按字典序全局有序（这是最重要的设计对象）。
  • column-family:qualifier：列族:列限定符，列族是物理存储与权限的单位，限定符可动态、任意多。
  • timestamp：版本号（默认写入时间），同一 cell 可保留多个版本。

适用 vs 不适用

✅

适合

时序/监控、日志、消息、用户画像、推荐特征等「写多读少、按 key 查询」的海量场景。

⚠️

不适合

多维度即席查询、复杂 Join、低延迟小数据事务——这些更适合 ES / OLAP / RDBMS。

在 Hadoop 生态中的位置

💡 建议学习顺序：先吃透「数据模型」与「架构」，再理解「存储引擎」与「读写流程」，然后重点练「Region 管理」和「行键设计」——这两点直接决定系统好不好用；最后才是运维、进阶与生态集成。
