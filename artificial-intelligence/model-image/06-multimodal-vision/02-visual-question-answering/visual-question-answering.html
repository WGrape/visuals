多模态视觉

视觉问答 VQA：让模型看着图片回答自然语言问题

VQA 要求模型同时理解图像内容与自然语言问题，并给出答案。它是检验「多模态真正看懂没有」的经典任务，也是今天多模态大模型（VLM）的核心能力之一。本文讲清任务形态、技术演进与评测陷阱。

VQA 到底在考什么

输入：一张图 + 一个自然语言问题；输出：答案（可以是单词、短语、选择题选项，或一句话解释）。

例如："图里有几只猫？"、"这个人正在做什么？"、"为什么 这条路是湿的？"

真正的难点在于：不能只靠语言先验蒙答案——模型必须真的从图中读取信息。

从两段式流水线到端到端 VLM

早期流水线
CNN 提图像特征 + RNN/LSTM 编码问题 → 融合后分类到答案词表
注意力融合
用问题去「 attend 」图像区域，聚焦相关局部
大模型时代 （当前）
视觉编码器 + 投影层 + LLM，图文在同一序列里统一推理
现代做法：把图片当作一串视觉 token 直接拼进大模型的上下文，由此顺带获得了解释、推理、多轮对话等能力，远超早期固定答案词表的形态。

评测陷阱：语言先验与幻觉

语言先验陷阱
数据集分布不均导致「不看图也能答对」（如问颜色总答白色）。
对策：构造平衡数据集 / 设计反例样本
多模态幻觉
模型编造图中不存在的物体或关系。
对策：要求输出依据（引用区域）、视觉定位校验、人工抽检
单纯刷准确率会高估能力：务必在同一问题上换图测试（改变图片答案是否跟着变），才能验出模型是真看懂还是背答案。

落地要点

  • 分辨率 vs 成本：视觉 token 数随分辨率增长，长上下文成本敏感任务需要在清晰度与开销间取平衡
  • OCR 与图表：文档、表格、图表场景建议先做版面检测再分块提问
  • 结构化输出：抽取类问答应要求 JSON 并做 Schema 校验，避免"答了但机器用不了"
  • 视频 VQA：本质是抽帧 + 时序，成本随帧数线性上升

面试速记卡

  • 任务：图 + 自然语言问题 → 答案，考察跨模态理解而非语言猜测。
  • 演进：CNN+RNN 流水线 → 注意力融合 → 视觉 token 拼进 LLM 的统一范式。
  • 两大陷阱：语言先验（不看图也能答）与多模态幻觉（编造图中内容）。
  • 验证方法：换图测试、要求给出依据区域、平衡数据集。
  • 工程：注意分辨率成本、OCR/图表先做版面、抽取类用结构化输出。
