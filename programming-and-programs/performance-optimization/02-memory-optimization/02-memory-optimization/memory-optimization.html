大对象与缓存策略

大对象优先用流式/分块处理，避免一次性载入；缓存要有上限与淘汰（LRU/TTL），否则会从「省时间」变成「吃内存」。

问题 1
如何降低服务的常驻内存？

先取样看对象分布；删掉无限增长的缓存、给缓存加 TTL/LRU；复用缓冲、预分配切片；大对象用流式处理；必要时换更紧凑的序列化（如 protobuf 替代 JSON）。

问题 2
对象池适合什么场景？

适合高频、短生命周期、可安全复用的对象（缓冲区、临时结构体）。但池子本身有上限，复用前必须重置状态，否则会串数据。

问题 3
零拷贝为什么省内存又省 CPU？

它减少用户态与内核态之间的数据复制，少一次缓冲分配，也少一次拷贝带来的 CPU 与缓存开销。典型如 sendfile、mmap、splice。

问题 4
GC 太频繁和内存有什么关系？

分配速率越高，GC 触发越频繁，STW 与回收成本越高。降低分配量（复用、预分配）能同时减小内存峰值与 GC 压力。
