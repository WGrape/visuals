解释器中的词法作用域与环境链

变量查找沿定义位置建立的环境链进行；闭包需要保留这条链。

核心机制

解释器可用环境对象保存一层作用域的变量，并用 parent 指向外层环境。遇到变量名时从当前层向外查找，首次命中即停止；赋值则要按语言规则找到应修改的绑定。

函数定义时捕获词法环境，调用时新建局部环境并连接到定义环境。若误连到调用者环境，就会变成动态作用域，产生与源码嵌套关系不符的结果。

用一个例子看过程

let x = 1;
function read() { return x; }
function call() { let x = 9; return read(); }
call(); // 词法作用域结果为 1

创建闭包

定义 read 时记录其外层环境，其中 x 绑定为 1。

进入调用

call 的局部 x=9 只位于 call 的环境中。

解析变量

read 查自己的局部环境，再沿定义环境找到 x=1。

定义环境与调用环境各自做什么

定义 read 时，解释器把函数体与当时的词法环境一起组成闭包。调用 read 时，新建一个保存参数和局部变量的调用环境，并把它的父环境指向函数的定义环境。执行 return x 时，先查 read 的局部环境，再沿定义环境找到 x=1；call 内的 x=9 不在这条链上。若错误地把父环境接到调用者 call，就会得到 9，这相当于意外实现了动态作用域。

函数每调用一次都需要独立的局部绑定；否则递归或并发调用会互相覆盖参数。闭包离开定义函数后仍可能继续使用被捕获变量，所以环境对象的生命周期不能简单等同于调用栈帧的生命周期。实际实现可以用堆对象、上值或其他表示优化，但必须保留相同语义。

赋值比读取更容易出错：x = 2 是修改找到的外层绑定，还是在当前层创建新绑定，取决于语言语义。实现解释器时应把“声明新变量”“读取变量”“赋值已有变量”设计为不同操作，而不是共用一个随意写入的字典方法。

闭包练习与内存边界

考虑函数 makeCounter 创建局部 count=0，返回一个每次把 count 加一的函数。调用 makeCounter 两次，应得到两个互不影响的计数器；同一计数器调用两次则依次返回 1、2。请画出两个闭包各自指向的环境对象。如果实现把所有闭包都指向同一个全局 count，就会出现状态串扰。

闭包捕获可能延长对象寿命。若环境中还引用很大的缓存，而闭包只需要一个小整数，某些实现会额外保留缓存。排查内存增长时应检查捕获范围与环境引用链，同时不改变语言要求的可观察行为。

边界与误区

具体语言还可能有块级作用域、提升、暂时性死区或按值捕获等规则；环境链只说明词法查找的基础模型。

从 AST 到环境对象的实现草图

解释变量表达式时执行 lookup(name)，沿当前环境与 parent 链查找；解释声明语句时在当前环境 define(name,value)；解释赋值语句时按语言规则找到已有绑定并更新。函数表达式产生的值不仅包含参数与函数体，还要持有定义时的环境引用。调用表达式先计算函数值和实参，再创建以定义环境为 parent 的新局部环境，把参数绑定进去，最后执行函数体。这里的关键是“定义环境”，不是“调用表达式所在环境”。

实现测试可以用三组程序：局部变量遮蔽外层变量、函数返回后闭包继续读写变量、两个独立闭包各自维护状态。再加入递归和错误路径，确认异常退出时局部环境不会污染下次调用。对于按值捕获的语言，闭包保存的可能是定义时的值或特殊单元，而不是整个可变环境对象；具体实现仍须符合该语言对赋值和生命周期的规定。

环境链的两个实现选择

直接用链表式环境字典最容易解释和实现，但每次变量查找可能逐层向外走。编译器或解释器可在静态解析阶段为变量确定“向外几层、该层第几个槽位”，运行时直接按位置访问；这样更快，但闭包捕获和可变绑定仍须保持正确。若一个函数只捕获外层的两个变量，也可把捕获值或引用放在专门的闭包对象里，避免保留整个大环境。优化前先用遮蔽、递归、独立闭包和赋值测试语义，再比较查找开销与内存占用。

自检

read 在 call 中被调用，为什么不读取 call 的 x=9？

词法作用域使用 read 定义时的外层环境，call 的局部环境不是它的父环境。
