02限流：令牌桶与漏桶

令牌桶允许一定突发（桶里攒的令牌），漏桶则强制恒定速率。下面的伪代码是令牌桶核心。

rate = 1000      # 每秒放 1000 个令牌
burst = 2000     # 桶容量
def allow(now):
    tokens = min(burst, tokens + rate*(now-last))
    last = now
    if tokens >= 1:
        tokens -= 1; return True
    return False

03热点 key 打散

  • 本地缓存 + 短 TTL，且 TTL 加随机抖动，避免同时失效（防雪崩）。
  • 对热点 key 做分桶（key + hash%N），把单点压力拆到 N 份。
  • 回源合并：同一 key 的并发回源合并成一次（singleflight）。

04重试退避与 jitter

import random
base, cap = 0.1, 5.0
def backoff(n):
    return min(cap, base * (2**n)) + random.uniform(0, base)
# 第 n 次失败后等 backoff(n) 再试，抖动避免同时重试
要点：没有 jitter 的指数退避，会在同一时刻引发「重试风暴」把下游打挂——抖动是必须的。

05熔断与超时预算

  • 错误率/延迟超阈值就「打开」熔断，直接失败或走降级，不再打下游。
  • 半开状态放少量流量探测是否恢复，OK 则关闭。
  • 超时逐级预算：DNS+连接+TLS+读写各自有上限，总和不超过总截止时间，避免级联等待。
问：限流和熔断有什么区别？

限流是「入口守门」，控制进来的量；熔断是「出口保险」，在依赖已经不稳时主动断流，保护下游也保护自己。两者通常叠加使用。

第一层 · 概念与判定：先给异常定类型

流量异常大致四类：突发洪峰、慢调用扩散、恶意刷子/爬虫、级联雪崩。类型不同处置手段完全不同，先定性再动手。

现象类型首选手段
QPS 暴涨但 RT 正常突发洪峰限流
RT 慢慢变长、线程耗尽慢调用扩散熔断 + 超时
少数 IP 高频刷子/爬虫黑名单 + 限速
一个依赖挂、全链路变慢级联雪崩降级 + 熔断

第二层 · 参数·命令·量化：三道闸的阈值

手段典型参数触发条件
限流（令牌桶）QPS 上限、突发超过预设容量
熔断错误率>50% + 窗口请求数依赖持续失败
超时下游 < 上游超时调用过久
降级返回兜底/缓存非核心不可用时

限流/熔断/超时典型配置

# 限流：令牌桶，允许短时突发
# Sentinel/网关示例：单机 QPS=1000, 突发=2000
flow:
  qps: 1000
  burst: 2000

# 熔断：10 秒内错误率 > 50% 且请求 >= 20 则打开
circuit:
  errorRatio: 0.5
  minRequests: 20
  window: 10s
  openDuration: 30s

# 超时：下游超时必须小于上游给的总时间，避免层层叠加

数量级：熔断错误率阈值常设 50%、窗口 10s 且最小请求 20 才统计；级联里一层超时 200ms，若 5 层无短路会叠加到 1s+，所以每层都要有独立超时与熔断。

第三层 · 排障与边界：四个坑

  • 熔断后不恢复探测：一直开着把流量全掐死——要有半开态试探，恢复后渐进放量
  • 限流误杀正常流量：阈值按峰值定太低，正常高峰也被拦——留突发余量、按实例容量算
  • 超时层层叠加：A→B→C 每层都设 1s 超时，总允许 3s，远超用户耐心且资源空耗——下游超时必须 < 上游
  • 只限入口不限依赖：网关拦了入口，但内部某个慢依赖仍把线程池拖垮——限流/熔断要下钻到依赖层

第四层 · 原理与取舍

限流、熔断、降级三者怎么分工？

限流是入口节流（别让超过系统容量的请求进来）；熔断是故障隔离（依赖挂了就快速失败，不把线程/连接耗在等它上）；降级是保核心（非关键功能直接返回兜底，腾资源给主链路）。三者层级不同：限流防过载、熔断防扩散、降级保可用，通常要一起上。

为什么熔断要有「半开」状态，而不是开/关两态？

因为故障恢复后需要试探性地放一点流量验证依赖是否已好，而不是一次性全量恢复（可能依赖只是抖动，全量回来又被打挂）。半开态放少量请求，成功则关闭熔断、失败则继续打开——这是避免「恢复即被冲垮」的关键。

为什么超时层层叠加是大忌？

因为每多一跳，用户感知的延迟是各层超时之和，而资源（线程/连接）被占用的时间也是叠加的。一层 200ms 看似温和，5 层链路就是 1s，且每层都在等，连接池/线程池被长时间占用，极易引发雪崩。正确做法：下游超时严格小于上游分配的时间，并配熔断做快速失败。
