先建立直觉：给方法贴「缓存标签」

不用缓存时，每个方法都要手写「查缓存 → miss 就查库 → 回填」。有了 Spring Cache 抽象，你只需在方法上贴个标签：

@Cacheable(value = "userCache", key = "#id")
public User getUserById(Long id) {
    return userMapper.selectById(id);   // 只有 miss 时才真正执行
}

Spring 会用 AOP 在方法调用前后插入缓存逻辑：先查缓存，命中就直接返回，不执行方法体。

三个核心注解

注解作用典型场景
@Cacheable查询：命中返回缓存，未命中执行方法并回填查询接口
@CachePut总是执行方法，并用返回值更新缓存更新接口（保证缓存同步）
@CacheEvict删除缓存（可 allEntries=true 清空）删除/更新接口
@CachePut(value = "userCache", key = "#user.id")     // 更新：写库同时更新缓存
public User updateUser(User user) {
    userMapper.updateById(user);
    return user;
}

@CacheEvict(value = "userCache", key = "#id")        // 删除：移除缓存
public void deleteUser(Long id) {
    userMapper.deleteById(id);
}

// 复合操作：一次定义多个缓存动作
@Caching(evict = {
    @CacheEvict(value = "userCache", key = "#user.id"),
    @CacheEvict(value = "userListCache", allEntries = true)
})
public void updateAndInvalidate(User user) { ... }

接入 Ehcache（Spring Boot）

① 加依赖

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-cache</artifactId>
</dependency>
<dependency>
    <groupId>org.ehcache</groupId>
    <artifactId>ehcache</artifactId>
</dependency>

② 指定配置文件

# application.yml
spring:
  cache:
    type: ehcache
    ehcache:
      config: classpath:ehcache.xml

③ 写 ehcache.xml

<config xmlns="http://www.ehcache.org/v3">
  <cache alias="userCache">
    <key-type>java.lang.Long</key-type>
    <value-type>com.example.User</value-type>
    <expiry>
      <ttl unit="minutes">10</ttl>
    </expiry>
    <heap unit="entries">1000</heap>
    <offheap unit="MB">100</offheap>
  </cache>
</config>

④ 启用缓存

@SpringBootApplication
@EnableCaching      // 别忘了这一行
public class App { }

四个常见坑

① 同类内部调用，注解无效。Spring Cache 基于 AOP 代理，只有通过代理对象调用才会走缓存逻辑。在同一个类里 this.method() 调用，不会走代理，缓存完全失效。这是最高频的坑。解法：把方法拆到另一个 Bean；或注入自身代理；或用 AopContext.currentProxy()（需开启 exposeProxy）。
② key 设计不当导致冲突或失效。默认 key 由所有参数生成。若方法有多个参数，要注意参数顺序；用 SpEL 明确指定更安全：key = "#user.id"。另外 key 必须正确实现 equals/hashCode。
③ 缓存了 null。默认情况下 @Cacheable 会缓存 null 结果（Spring 认为「返回 null 也是结果」）。这可能导致「数据库里没有，缓存里一直是 null，后来插入了也读不到」。解法：加 unless = "#result == null" 不缓存空值，或配合空值缓存的短 TTL 策略。
④ 更新时忘记同步缓存。只写 @Cacheable 而不写 @CachePut/@CacheEvict，更新数据后缓存仍是旧值。建议：写操作统一带上 @CachePut 或 @CacheEvict，并配合合理 TTL 兜底。

注解方式 vs 手动方式

方式优点缺点
@Cacheable 注解零侵入、代码简洁、统一治理受 AOP 限制（自调用失效）、复杂逻辑难表达
手动 CacheManager完全可控、可做复杂逻辑代码侵入、易遗漏
建议：简单 CRUD 用注解；需要精细控制（如加载保护、空值策略、多级缓存）时用手动方式或直接集成 Caffeine 的 get(key, loader)。

🎯 面试问答

Q：为什么我在同一个类里调用 @Cacheable 方法，缓存没生效？
A：因为 Spring Cache 基于 AOP 代理。只有通过代理对象发起的调用才会经过缓存拦截逻辑；类内部的 this.foo() 是直接调用，绕过了代理，注解自然失效。解决办法：① 把该方法移到另一个 Service 类；② 注入自身的代理 Bean 再调用；③ 用 AopContext.currentProxy()（需配置 exposeProxy=true）。这是使用 Spring 缓存最常见的坑。

Q：@Cacheable 和 @CachePut 有什么区别？
A：@Cacheable 是「能不执行就不执行」——先查缓存，命中就直接返回，方法体完全不执行。@CachePut 是「一定执行」——每次都会调用方法，然后用返回值更新缓存。所以查询用 @Cacheable，更新用 @CachePut（保证库改了缓存也跟着改）。两者放在同一个方法上通常没有意义。

Q：如何避免缓存穿透？
A：用 unless = "#result == null" 不缓存空结果会导致穿透（每次都查库）；反之缓存 null 又可能造成长期返回空。推荐做法：允许缓存 null，但给该缓存配置较短的 TTL（1~5 分钟），并在数据真正创建时用 @CacheEvict 主动清除。更彻底的做法是在服务层加布隆过滤器或参数校验，把不存在的 key 挡在外面。

Q：Spring Boot 默认用的是哪个缓存实现？
A：Spring Boot 会按 classpath 上存在的依赖顺序自动选择：Generic → JCache(JSR-107) → EhCache 2 → Hazelcast → Infinispan → Couchbase → Redis → Caffeine → Simple。Spring 5+ / Boot 2+ 中，如果引入了 Caffeine，它通常会被优先选用（因为 Caffeine 性能最佳）。想明确指定，就设置 spring.cache.type=caffeine 或 =ehcache。

Ehcache 的分层与关键参数

层级配置说明
堆内（on-heap）heap: 1000（条目数）最快，但受 GC 影响；所有条目都在堆里
堆外（off-heap）offheap: 1GB不被 GC 扫描；需序列化，约慢 2~5 倍
磁盘（disk）disk: 10GB最慢（ms 级），但容量大、进程重启可保留
组合示例heap 1000 + offheap 1GB + disk 10GB热数据在堆，温数据在堆外，冷数据落盘
参数默认值说明
timeToLive（TTL）不过期创建后固定时长过期
timeToIdle（TTI）不过期空闲时长过期；每次访问重置
maxEntriesLocalHeap0（不限）堆内条目上限，必须设置否则 OOM
memoryStoreEvictionPolicyLRU另有 LFU、FIFO
eternalfalsetrue 时忽略 TTL/TTI（慎用）
overflowToOffHeapfalse堆满后溢出到堆外
diskPersistentfalse重启后是否保留磁盘层
copyOnRead/copyOnWritefalse开启可防外部修改缓存对象，有拷贝开销

堆内条目数怎么定：粗略估算 条目数 × 单条大小 不超过堆的 10~20%。例如堆 4GB、每条 10KB，则上限约 4GB × 0.15 / 10KB ≈ 60000 条。放太多会引发频繁 Full GC，反而比不缓存还慢。

Spring 集成配置

// 1) 开启缓存
@Configuration
@EnableCaching
public class CacheConfig { }

// 2) 使用（Spring Cache 抽象，换实现只需改配置）
@Cacheable(value = "user", key = "#id", unless = "#result == null")
public User getUser(Long id) { return userMapper.selectById(id); }

@CachePut(value = "user", key = "#user.id")      // 更新后写入
public User update(User user) { userMapper.update(user); return user; }

@CacheEvict(value = "user", key = "#id")          // 删除
public void delete(Long id) { userMapper.delete(id); }

@CacheEvict(value = "user", allEntries = true)    // 清空整个缓存
public void clearAll() { }

// 3) 注意：同类内部调用不会触发缓存（Spring AOP 代理的限制）
//    self.getUser(1L) 不会走缓存 -> 必须注入自己的代理或用 AopContext
# application.yml（Boot 2.x + ehcache3）
spring:
  cache:
    type: jcache
    jcache:
      config: classpath:ehcache.xml
    cache-names: user, order

# ehcache.xml
<config xmlns='http://www.ehcache.org/v3'>
  <cache alias="user">
    <key-type>java.lang.Long</key-type>
    <value-type>com.demo.User</value-type>
    <expiry>
      <ttl unit="minutes">10</ttl>          <!-- 写后 10 分钟过期 -->
    </expiry>
    <heap unit="entries">10000</heap>       <!-- 堆内 1 万条 -->
    <offheap unit="MB">256</offheap>        <!-- 堆外 256MB，需序列化 -->
    <disk-store thread-pool-size="2"/>
  </cache>
</config>

排障清单

症状原因处理
缓存没生效同类内部调用（AOP 代理失效）；或方法非 public改为注入自身代理调用；方法必须 public；final 类/方法无效
Full GC 频繁堆内缓存条目太多减小 heap 条目数；改放 offheap
存入的对象被外部改了缓存的是对象引用开 copyOnRead/copyOnWrite；或存不可变对象
序列化失败堆外/磁盘层要求可序列化实现 Serializable；或配置序列化器
缓存穿透（每次都查 DB）查询结果为 null 时没缓存unless = "#result == null" 会跳过缓存 null，导致穿透；去掉 unless 并缓存空值
过期时间不生效eternal=true 或 TTL/TTI 互斥检查 eternal；TTL 与 TTI 同时配时取更严格的
多实例不一致本地缓存不共享用 Redis；或用消息总线失效（Ehcache 有 JMS/RMI 复制，但复杂）

Spring Cache 的核心限制：它基于 AOP 代理，所以 ① 同类内部调用不生效；② 方法必须 public 且非 final；③ 自调用要注入代理。这三条占了「缓存没生效」问题的绝大多数。
