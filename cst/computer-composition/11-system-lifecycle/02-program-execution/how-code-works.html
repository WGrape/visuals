CPU指令执行周期（取指-解码-执行）
💡 核心概念：CPU通过不断的"取指-解码-执行"循环来运行程序。 程序计数器(PC)指向下一条要执行的指令，每条指令都要经过这几个阶段。

指令执行周期：
1. 取指(Fetch): 从内存读取指令到IR(指令寄存器)

5. 更新PC: PC指向下一条指令
内存层次结构与数据流动
💡 核心概念：计算机采用分层存储结构，从最快最小的寄存器到最慢最大的硬盘。 程序运行时，数据在不同层级间移动，CPU优先访问速度快的存储层。
存储层次（从上到下，速度递减，容量递增）：
1. 寄存器: CPU内部，最快，容量极小(<1KB)
2. L1缓存: CPU内部，极快，约32-64KB
3. L2缓存: CPU内部，很快，约256KB-1MB
4. L3缓存: 多核共享，快，约4-30MB
5. RAM(内存): 主板上，较快，几GB到几十GB
6. SSD/硬盘: 外部存储，慢，几百GB到几TB

💡 局部性原理：程序倾向于访问最近访问过的数据附近的数据， 所以数据会以"块"为单位在层次间移动（如缓存行64KB）。

一行 print 背后的整条链路

你写下的 printf("hi")，要经历预处理 → 编译 → 汇编 → 链接 → 装载变成内存里的进程，再由 CPU 逐条取指执行；想输出到屏幕，还要通过系统调用进入内核、经驱动写设备、等待中断返回。理解这条链路，是把「高级语言的直觉」和「机器的真实行为」对上的关键。

编译源码 → 汇编，做词法/语法/语义分析与优化
汇编汇编指令 → 机器码，生成可重定位目标文件 .o
链接合并多个 .o 与库，解析符号、重定位地址
装载把可执行文件映射进内存，建立进程与地址空间
运行CPU 取指执行，需要 OS 服务时发起系统调用

三种执行方式对比

方式代表语言中间产物启动速度运行速度特点
编译执行C / C++ / Go / Rust机器码可执行文件快最快直接跑在硬件上；平台相关，需分别编译
字节码 + 虚拟机Java / C#.class / IL 字节码中（需启动 VM）接近原生（JIT 后）一次编译到处运行；JIT 可按运行时信息优化
解释执行Python / Shell / JS(早期)无（边读边执行）最快较慢灵活、跨平台、易调试；热点可用 JIT 提速
混合（JIT）JS / Python(PyPy) / Java运行时编译热点中接近原生先解释启动，热点代码动态编译成机器码
转译（Transpile）TypeScript / Babel另一种源码——把新语法转成目标环境能跑的旧语法

常见误解：「解释型语言一定慢」。现代 JS 引擎与 PyPy 都用 JIT，热点代码会被编译成机器码；真正慢的往往是动态类型的查表开销和无法跨函数优化，而不是「解释」本身。

从虚拟地址到物理内存

① 程序看到的是虚拟地址

  • 每个进程有独立的虚拟地址空间，彼此隔离。
  • 每次访存由 MMU 查页表把虚拟地址转成物理地址。
  • TLB 缓存最近转换结果，命中则几乎无开销。
  • 页表没映射 → 缺页异常 → 内核补页或杀进程（段错误）。

② 为什么需要系统调用

  • 用户态程序不能直接访问硬件与内核内存（特权级保护）。
  • 需要 OS 服务（读写文件、发网络包、创建进程）时，通过 syscall 陷入内核。
  • 代价：特权级切换 + 寄存器保存 + 可能的调度，开销远大于函数调用。
  • 优化思路：批量（writev、io_uring）、减少次数、用 mmap 替代 read。

③ 进程是怎么被创建的

  • fork：复制进程描述符，页表写时复制（COW），几乎零成本拷贝。
  • exec：用新程序替换地址空间（装载、建栈、设入口）。
  • 动态链接：装载器先跑 ld.so，解析并加载共享库。
  • 所以「fork + exec」是 Unix 启动程序的经典组合。

④ 内存布局

  • 代码段（text）：只读、可共享。
  • 数据段：已初始化全局/静态变量；BSS：未初始化（零填充，不占文件体积）。
  • 堆（heap）：malloc/new 动态分配，向高地址增长。
  • 栈（stack）：函数调用与局部变量，向低地址增长，有大小限制。
  • 共享库与内存映射区：mmap 区域。

深入自检

编译型语言一定比解释型快吗？

不一定。现代解释型语言大多带 JIT，热点代码会编译成机器码，性能可以接近编译型。真正的差距通常来自：动态类型带来的运行时检查、对象模型导致的额外间接寻址、以及无法做跨模块静态优化。另外启动速度与内存占用上，编译型通常仍有明显优势。

为什么 printf 不能直接写屏幕？

因为用户态程序运行在低特权级，不能直接访问硬件寄存器与显存。必须通过系统调用进入内核态，由内核的终端驱动把字符写入对应的设备（可能是真实的显卡/串口，也可能是伪终端或文件）。这层保护正是操作系统能保证多程序安全共存的基础。

什么是缺页异常，它是错误吗？

不是错误，而是虚拟内存的正常机制。程序访问的虚拟页尚未映射到物理内存时触发，内核负责分配页框、可能还要从磁盘（swap 或文件）读入，然后回到原指令重新执行。只有访问了未分配且非法的地址，才会变成真正的段错误（SIGSEGV）。

动态链接和静态链接怎么选？

静态链接：产物自包含、启动略快、部署简单（尤其容器 scratch 镜像），但体积大、库升级要重新编译。动态链接：节省磁盘与内存（库可共享）、升级方便，但存在依赖地狱与版本兼容问题。Go 默认静态链接倾向部署简单；C/C++ 服务端常动态链接以便安全更新。

为什么函数调用比系统调用快得多？

函数调用只是跳转与栈操作，全程在用户态；系统调用要切换特权级、保存/恢复大量寄存器、可能触发调度与 TLB 刷新。实测中系统调用开销通常是函数调用的数十到上百倍，所以高性能程序会尽量减少 syscall 次数（批量 I/O、io_uring、用户态协议栈）。

程序启动时为什么要动态链接器 ld.so？

因为程序依赖的共享库在编译期并不知道最终会被加载到哪个地址。内核装载时先执行动态链接器，由它找到所有依赖库、完成符号解析与重定位（GOT/PLT 填表），最后才跳转到程序入口。延迟绑定（lazy binding）还能把函数地址解析推迟到首次调用。
