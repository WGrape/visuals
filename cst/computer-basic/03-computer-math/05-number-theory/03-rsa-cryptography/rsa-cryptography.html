RSA：把安全建立在大数分解的困难上

RSA 用「乘法容易、分解困难」这一不对称性构造公钥密码：加密谁都会，解密只有掌握私钥的人能做到。

核心速览

密钥生成

选两大素数 p、q → n = pq，φ = (p−1)(q−1)，选 e，求 d = e⁻¹ mod φ

加解密

c = mᵉ mod n（加密），m = cᵈ mod n（解密）

正确性

欧拉定理保证 (mᵉ)ᵈ = m^(ed) ≡ m (mod n)

安全性

从 n 推 φ 需要分解 n——经典算法次指数级，2048 位不可行

核心思想：单向陷门函数

RSA 的精妙在于一个不对称：把两个大素数相乘只要几微秒；但给你乘积 n，想找回 p、q，在经典计算机上要花上宇宙年龄量级的时间。这个不对称构成了「单向」；而知道 p、q 的人能算出 φ(n) 从而推出私钥，这就是「陷门」。

密钥生成的六个步骤

步骤操作说明
1随机选两个大素数 p、q用 Miller–Rabin 测试；各 1024 位（2048 位密钥）
2n = p × q模数，公开
3φ(n) = (p−1)(q−1)欧拉函数，必须保密
4选 e 使 1 < e < φ 且 gcd(e, φ) = 1常用 65537 = 2¹⁶+1（素数、二进制只有两个 1，幂运算快）
5d = e⁻¹ mod φ(n)扩展欧几里得求出，私钥核心
6公钥 (e, n) 公开，私钥 (d, n) 保密p、q、φ 用完即弃（或仅保留用于 CRT 加速）
def gen_keys(bits=1024):
    import random
    def rand_prime(b):
        while True:
            x = random.getrandbits(b) | (1 << (b - 1)) | 1   # 保证位数与奇数
            if is_prime_mr(x): return x
    p, q = rand_prime(bits), rand_prime(bits)
    while q == p: q = rand_prime(bits)
    n = p * q
    phi = (p - 1) * (q - 1)
    e = 65537
    while gcd(e, phi) != 1: e += 2
    d = mod_inv(e, phi)                 # 扩展欧几里得
    return (e, n), (d, n)               # 公钥、私钥

def encrypt(m, pub):  e, n = pub; return pow(m, e, n)   # Python 内置快速幂
def decrypt(c, priv): d, n = priv; return pow(c, d, n)
为什么 e = 65537？它是素数（易满足互素），二进制为 10000000000000001（只有两个 1，幂运算只要 17 次乘法），且足够大以抵抗低指数攻击。选 e = 3 虽然更快，但在小消息、无填充时容易被直接开三次方破解。

正确性证明：为什么解出来就是原文

由构造知 e·d ≡ 1 (mod φ(n))，即 ed = 1 + k·φ(n)。于是：

cᵈ = (mᵉ)ᵈ = m^(ed) = m^(1 + kφ(n)) = m · (m^φ(n))ᵏ ≡ m · 1ᵏ = m　(mod n)

最后一步用的是欧拉定理 m^φ(n) ≡ 1 (mod n)（要求 gcd(m, n) = 1）。对于 gcd(m,n) ≠ 1 的情况（m 恰好是 p 或 q 的倍数，概率约 2/√n，可忽略），可用中国剩余定理单独证明结论依然成立。

注意这里的 ≡ (mod n)：等式在模 n 意义下成立。只要明文 m < n，取模后就是唯一的原值，解密精确无误。这就是 RSA 是「精确」而非「近似」的原因——整个运算都在整数环上进行。

安全性分析：攻击面在哪里

攻击方式思路防御
分解 n分解出 p、q 即可算 φ 与 d用足够长的密钥（≥2048 位）
小指数攻击e=3 且 m 很小时，直接对 c 开三次方用 65537 + 填充（OAEP）
共模攻击同一 n 发给两人、e 互素 → 可恢复明文每个用户独立生成 n
选择密文攻击构造 c′ = c·2ᵉ 诱使解密使用 OAEP 等抗 CCA 填充
时序/功耗侧信道从解密耗时反推 d 的比特常数时间实现、盲化
量子计算（Shor）多项式时间分解大整数迁移到后量子密码（格密码等）
随机数缺陷两设备生成相同 p使用高质量 CSPRNG
教科书 RSA（直接用 mᵉ mod n）是不安全的：它是确定性的（同一明文永远同一密文，可被字典攻击），且对选择密文攻击毫无抵抗力。真实系统必须使用 OAEP 填充（引入随机性 + 结构化冗余），签名则要用 PSS。

性能：RSA 为什么慢，怎么用才对

一次 2048 位 RSA 私钥运算大约需要几毫秒——比 AES 慢 3～4 个数量级，且能加密的数据长度受限于模数长度（2048 位密钥最多加密约 190 字节，还要减去填充开销）。因此实际系统几乎从不直接用 RSA 加密数据：

  • 混合加密（TLS 的实际做法）：用 RSA（或 ECDHE）协商/加密一个随机会话密钥，之后用 AES-GCM 等对称算法加密真正的数据。
  • CRT 加速：私钥运算可用中国剩余定理分别在模 p、模 q 下做，再合并，提速约 3～4 倍（这也是 p、q 通常要保留的原因）。
  • 签名 vs 加密：签名是「用私钥加密哈希值」，用于身份认证与不可否认；加密是「用公钥加密」，用于保密。两者方向相反，不要混用。

RSA 与 ECC 的对比

维度RSAECC（椭圆曲线）
安全基础大整数分解困难椭圆曲线离散对数困难
等价强度的密钥长度3072 位256 位
计算速度签名验证快，签名与解密慢整体更快、更省电
密钥/签名体积大小（适合移动设备与区块链）
实现复杂度相对简单，好理解复杂，易出现实现漏洞
量子威胁Shor 算法可破解同样可被 Shor 破解
趋势：新系统普遍优先选择 ECDHE + ECDSA/EdDSA；RSA 因兼容性和成熟实现仍在广泛使用，但密钥长度建议 ≥2048 位（长期保密数据用 3072 位以上）。两者都不是后量子安全的，NIST 已标准化格密码方案（如 ML-KEM）用于迁移。

🎯 常见问法与答题要点

Q：RSA 为什么是安全的？它的安全性建立在什么假设上？

A：建立在大整数分解的困难性上：攻击者拿到公钥 (e, n) 后，若能分解 n = p·q，就能算出 φ(n) = (p−1)(q−1) 从而求出私钥 d。目前经典计算机上已知最好的分解算法（数域筛 NFS）是次指数级的，2048 位 n 的分解代价不可行。关键点：这是困难性假设，不是数学证明——从未有人证明分解必须困难。

Q：e 和 d 为什么可以互换？加密和签名是什么关系？

A：因为 e·d ≡ 1 (mod φ(n)) 是对称的：m^(ed) ≡ m^(de) ≡ m (mod n)。所以「用私钥 d 变换、用公钥 e 还原」同样成立——这就是数字签名：签名者对消息哈希做私钥运算（s = hᵈ mod n），任何人用公钥 e 验证 sᵉ ≡ h。加密用公钥、解密用私钥（保密）；签名用私钥、验证用公钥（认证与不可否认），方向正好相反。

Q：为什么 e 通常取 65537？

A：三个理由：① 它是素数，容易满足 gcd(e, φ) = 1；② 二进制只有两个 1（2¹⁶+1 = 1000…0001），快速幂只要 17 次乘法，加密极快；③ 足够大，能抵抗低加密指数攻击（e = 3 时若明文很小且未填充，攻击者直接对密文开三次方就能还原明文）。

Q：为什么不能直接用 RSA 加密大文件？

A：两个原因：① 长度限制——明文必须小于模数 n，2048 位密钥扣掉 OAEP 填充后只能装约 190 字节；② 极慢——一次私钥运算约毫秒级，比 AES 慢 3～4 个数量级。所以实际采用混合加密：用 RSA 加密一个随机的会话密钥（几十字节），再用 AES-GCM 加密真正的数据。TLS 握手正是这么做的。

Q：教科书式 RSA 有什么漏洞？生产环境要怎么做？

A：教科书 RSA（直接 c = mᵉ mod n）是确定性的，同一明文永远得到同一密文，可被字典/重放攻击；且它是可延展的（c·2ᵉ 对应明文 2m），对选择密文攻击毫无抵抗力。生产环境必须：① 加密用 OAEP 填充（引入随机性 + 冗余校验）；② 签名用 PSS；③ 密钥 ≥2048 位；④ 使用成熟库（OpenSSL / libsodium），绝不自己实现。

Q：CRT 为什么能让 RSA 快 3～4 倍？

A：解密 m = cᵈ mod n 中的模数是 2048 位；用中国剩余定理可把它拆成两个1024 位的小运算：先在模 p 下算 m₁ = c^(d mod (p−1)) mod p，再在模 q 下算 m₂，最后合并。模数位数减半，而模幂代价约为位数的三次方，所以总代价约降到 1/4（实测 3～4 倍）。这也是私钥里通常同时保存 p、q 的原因。

Q：量子计算机对 RSA 的威胁有多大？现在该怎么办？

A：Shor 算法能在多项式时间内分解大整数，足够规模的量子计算机一旦出现，RSA 与 ECC 都会被彻底破解。目前量子计算机的规模远远不够（分解 2048 位需要数百万个高质量逻辑比特）。应对策略：① 关注「现在窃取、将来解密」风险——长期保密数据应尽快迁移；② 采用后量子密码（NIST 已标准化 ML-KEM 等格密码方案）；③ 使用混合密钥交换（经典 ECDHE + 后量子 KEM 组合），逐步过渡。

Q：RSA 和 ECC 该怎么选？

A：新系统优先 ECC：256 位 ECC ≈ 3072 位 RSA 的安全强度，但密钥与签名更小、运算更快、更省电，特别适合移动端、IoT 与区块链。RSA 的优势是实现简单、兼容性好、验证速度快，在证书体系里仍广泛存在。两者都不是后量子安全的，长期规划都要考虑向后量子算法迁移。
