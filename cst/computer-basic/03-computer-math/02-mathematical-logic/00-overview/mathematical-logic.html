数理逻辑：把推理本身变成可计算的对象

命题逻辑处理「句子真假」，谓词逻辑加进量词与变量，形式系统则把「证明」变成可机械检查的符号操作。

核心速览

命题逻辑

处理由与/或/非连接的陈述句，真假二值，可完全判定

谓词逻辑

引入变量与 ∀/∃ 量词，表达力大增但不可完全判定

形式系统

公理 + 推理规则 = 可机械验证的证明（完备性、一致性）

与计算的联系

SAT 是 NP 完全；类型论与程序验证同构（柯里-霍华德）

命题逻辑：真值的代数

命题是能判断真假的陈述句。五种基本连接词：

名称符号含义程序对应
否定¬p非!p
合取p ∧ q且（两者都真才真）p && q
析取p ∨ q或（至少一个真即真）p || q
蕴含p → q若 p 则 q!p || q
等价p ↔ q同真同假p == q
蕴含最容易踩的坑是「前件为假时整个命题为真」（vacuous truth）。比如「如果太阳从西边升起，我就给你一百块」——因为前件永远为假，这句话逻辑上恒真。程序里的对应物：if (false) { ... } 分支里的任何断言都不会被触发。

等值式与范式：化简的两套标准形

常用等值式（化简与证明的基础）：

定律表达式
德摩根律¬(p∧q) = ¬p∨¬q　　¬(p∨q) = ¬p∧¬q
双重否定¬¬p = p
分配律p∧(q∨r) = (p∧q)∨(p∧r)
蕴含等值p→q = ¬p∨q
逆否等值p→q = ¬q→¬p　（反证法的依据）
吸收律p∧(p∨q) = p　　p∨(p∧q) = p

任何布尔函数都能写成两种标准形：

DNF（析取范式）

「积之和」：(p∧¬q) ∨ (¬p∧r)。由真值表中输出为真的行直接读出，易于构造但可能很长。

CNF（合取范式）

「和之积」：(p∨¬q) ∧ (¬p∨r)。由输出为假的行读出，是 SAT 求解器的标准输入格式。

转换代价

一般布尔函数从 DNF 转 CNF 可能指数级膨胀，所以不能随意转换。

完备性

{∧, ∨, ¬} 是完备集；{¬, ∧} 或 {¬, ∨} 单独也完备；NAND 一个门就完备（所以理论上整个 CPU 可只用 NAND 搭出来）。

谓词逻辑：加进变量与量词

命题逻辑无法表达「所有整数都…」这类含变量与范围的命题。谓词逻辑引入谓词 P(x) 与两个量词：

∀x P(x)：对所有 x，P(x) 成立　　　∃x P(x)：存在某个 x 使 P(x) 成立
自然语言形式化关键
所有素数都大于 1∀x (Prime(x) → x > 1)全称量词常配蕴含
存在偶素数∃x (Even(x) ∧ Prime(x))存在量词常配合取
没有最大的自然数∀x ∃y (y > x)量词顺序不能随意交换
每个人都有一位母亲∀x ∃y Mother(y, x)≠ ∃y ∀x Mother(y, x)
量词顺序是初学者最常犯的错：∀x∃y 与 ∃y∀x 含义完全不同。前者「每人都有（各自的）母亲」，后者「存在一个人是所有人的母亲」。另外量词的否定遵循对偶律：¬∀x P = ∃x ¬P，¬∃x P = ∀x ¬P——否定会翻转量词。

推理规则：从前提到结论的合法步骤

规则形式说明
假言推理 MPp→q, p ⟹ q最基础，肯定前件
Modus Tollensp→q, ¬q ⟹ ¬p否定后件，反证法的基础
假言三段论p→q, q→r ⟹ p→r链式推理
析取三段论p∨q, ¬p ⟹ q排除法
全称实例化∀x P(x) ⟹ P(a)从「所有」得到「某个」
存在推广P(a) ⟹ ∃x P(x)从「某个」得到「存在」

两种经典无效推理（务必避免）：

  • 肯定后件：p→q 且 q 为真 ⟹ p 为真 ❌（下雨地会湿，地湿≠下雨，可能是洒水）
  • 否定前件：p→q 且 p 为假 ⟹ q 为假 ❌（不下雨地也可能湿）

形式系统的三大性质与哥德尔

可靠性 Soundness

凡能被证明的都是真的——「不会证出假命题」，是对系统最基本的要求。

完备性 Completeness

凡真的都能被证明——「不会漏掉真命题」。哥德尔 1929 年证明一阶逻辑是完备的。

一致性 Consistency

不能同时证出 P 与 ¬P——系统不能自相矛盾。

可判定性

是否存在算法判断任意命题的真假。一阶逻辑不可判定（丘奇-图灵），但命题逻辑可判定（真值表/SAT）。

哥德尔不完备定理（1931）：任何包含基本算术的一致形式系统，都存在既不能证明也不能否证的命题——即系统无法自证其全部真理。注意这与「一阶逻辑完备性定理」并不矛盾：后者说「语义真 ⟹ 可证」，前者说「存在语义上为真但任何递归公理系统都抓不住的算术命题」。这个结果的 CS 版本就是停机问题不可判定。

从逻辑到计算：三条关键桥梁

桥梁内容意义
SAT 与 NP 完全判断布尔公式是否可满足——第一个被证明的 NP 完全问题（Cook-Levin）所有 NP 问题都能归约到它；现代 SAT Solver 已能解百万变量级实例
柯里-霍华德同构命题 ↔ 类型，证明 ↔ 程序，化简 ↔ 执行类型检查即定理证明；依赖类型（Coq/Agda/Lean）可写出可验证正确的程序
模型检测在有限状态模型上自动验证时序逻辑公式硬件验证、协议验证（如 TLA+、Alloy）
# 逻辑与程序的对应：布尔表达式化简（编译器优化的基础）
# 吸收律：  p and (p or q)  ==  p
# 德摩根：  not (p and q)   ==  (not p) or (not q)
# 短路：    p and q 中若 p 为假则不求 q（既是优化也可能有副作用差异）

# SQL 的 WHERE 子句就是谓词逻辑
# SELECT * FROM users WHERE age > 18 AND city = 'Beijing'
# 语义：{ u ∈ users | Age(u) > 18 ∧ City(u) = 'Beijing' }

🎯 常见问法与答题要点

Q：命题逻辑和谓词逻辑的区别是什么？

A：命题逻辑把陈述句当作不可再分的原子，只研究用 ∧∨¬→ 连接后的真假，可完全判定（真值表/SAT）。谓词逻辑引入个体变量、谓词与量词 ∀/∃，能表达「所有整数都…」「存在某人…」这类命题，表达力大幅增强但代价是不可判定（丘奇-图灵定理）。取舍：表达力 vs 可判定性。数据库查询、程序验证需要谓词逻辑；电路设计、SAT 求解停留在命题逻辑。

Q：为什么「p → q」在 p 为假时是真？

A：这叫空真（vacuous truth）。因为蕴含的语义等价于 ¬p ∨ q：只要前件为假，整个析取式就为真。语义上的理解是：「若 p 则 q」只在承诺被违背（p 真而 q 假）时为假；p 根本没发生时，承诺没被违背，所以为真。程序中的体现：if (false) { ... } 里的任何断言都不会失败；形式化验证中 vacuous 通过也是常见的验证盲区，需要用「覆盖」检查来排除。

Q：德摩根律为什么重要？

A：因为它把否定穿透进复合条件，是化简布尔表达式、化简 SQL 条件、化简代码分支的核心工具：¬(p∧q) = ¬p∨¬q，¬(p∨q) = ¬p∧¬q。工程价值：① 把 !(a && b) 改写成 !a || !b 以便短路优化；② 在 SQL 中把 NOT (A AND B) 转成更友好的形式以命中索引；③ 电路设计中把与非门转成或非门组合；④ 量词否定时同样遵循对偶律：¬∀x P = ∃x ¬P。

Q：全称量词为什么常配蕴含，存在量词为什么常配合取？

A：因为要表达的语义不同：① ∀x (P(x) → Q(x)) 表示「凡是 P 的都是 Q」，如「所有素数都大于 1」= ∀x(Prime(x) → x>1)。若错写成 ∀x(Prime(x) ∧ x>1)，就变成了「所有东西都是素数且大于 1」，明显错误。② ∃x (P(x) ∧ Q(x)) 表示「存在同时满足两者的 x」，如「存在偶素数」。若错写成 ∃x(P(x) → Q(x))，则任何一个不是 P 的东西都能让它为真（空真），语义完全跑偏。这是形式化表达里最高频的错误。

Q：什么是 vacuous truth？它在工程里有什么影响？

A：指前件为假导致条件命题自动为真的现象。工程影响集中在形式化验证与测试：一个断言可能因为「触发条件从未发生」而通过，造成虚假的安全感。例如在模型检测中，若规范写成「∀ 请求：若超时则必须重试」，而模型里根本没有超时状态，验证会通过但什么也没证明。对策是覆盖率/可达性检查（mutation testing、coverage），确认真有反例路径被检查过。

Q：哥德尔不完备定理和「一阶逻辑完备性」矛盾吗？

A：不矛盾，说的是两件事。哥德尔完备性定理（1929）：一阶逻辑中「语义上永真」的公式一定能用推理规则证明——即推理系统对「逻辑真」是完备的。哥德尔不完备定理（1931）：任何足以表达算术的一致公理系统，都存在该系统内既不能证也不能驳的命题——即任何固定的递归公理集无法穷尽算术真理。前者谈推理规则与语义的关系，后者谈公理集的表达极限。对应的 CS 结论就是停机问题不可判定。

Q：SAT 为什么重要？它不是指数级难的吗？

A：SAT 是第一个被证明的 NP 完全问题（Cook-Levin 定理），理论上最坏情况指数级。但实际工业实例往往有结构，现代 CDCL（冲突驱动子句学习）求解器配合子句学习、变量选择启发式、随机重启，能解百万变量级的实例，广泛用于硬件验证、软件验证（符号执行）、调度、依赖求解（如包管理器）。这就是「理论难 ≠ 实践不可用」的经典例子。

Q：柯里-霍华德同构说了什么？

A：它揭示了逻辑与计算的深层同构：命题 ↔ 类型、证明 ↔ 程序、证明化简 ↔ 程序执行。例如「A → B」既是蕴含命题，也是函数类型；构造一个 A→B 的证明，就等价于写一个 A → B 的函数。实际意义：类型检查本质上就是定理证明，所以强类型系统能在编译期排除一大类 bug；而依赖类型语言（Coq、Agda、Lean）把这个同构用到极致，可以写出携带正确性证明的程序。
