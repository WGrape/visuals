缩放定律 Scaling Laws：大模型为什么越大越聪明

Scaling Laws 揭示：模型性能随参数量/数据量/算力平滑提升且可预测。Kaplan 说「越大越好」，Chinchilla 纠正为「数据和参数要等比例涨」。本文讲清幂律、Chinchilla 启示与「涌现」的关系。

一句话回答

Scaling Laws：在足够大的范围内，测试loss 随参数量 N、数据量 D、算力 C 各自呈幂律下降——可预测、平滑、没有突然的拐点。这解释了「堆资源就能变强」。但「涌现能力」是另一回事（见下）。

Kaplan 2020：三个独立幂律

OpenAI 早期发现，只要另两个固定，loss 与每个变量都满足幂律：

L(N) ∝ N^{-α}    L(D) ∝ D^{-β}    L(C) ∝ C^{-γ}

指数 α,β,γ 都是小常数（约 0.05~0.1）。含义：翻倍资源，loss 只降一点点——但持续堆，确实一直在降。

当时结论偏向「模型越大越好」，于是一度流行训超大模型但数据喂不够。

Chinchilla 2022：数据也要等比例涨

DeepMind 的 Chinchilla 论文纠正了一个关键误区：在固定算力预算下，最优不是「超大模型+少量数据」，而是模型大小 N 和训练数据 D 近似等比例增长。

给定算力 C：N_opt ∝ C^{0.5}    D_opt ∝ C^{0.5}
著名结论：70B 参数的模型，最优训练数据应是约 1.4T tokens（而不是 GPT-3 的 300B）。Chinchilla 用更少参数+更多数据，效果反超同算力的超大模型。如今"数据不够"是大模型训练的主要瓶颈之一。

涌现能力（Emergent）：和 Scaling 是两件事

有些能力（多步推理、算术、翻译小语种）在模型小的时候几乎为 0，跨过某个规模阈值后突然「出现」——这叫涌现。

争议：有研究认为「涌现」部分是评测指标非线性（如精确匹配 0/1）造成的假象；若用平滑指标（如交叉熵），很多能力其实也是平滑提升的。所以「涌现」≠「违背 Scaling Law」，二者是「平滑 loss」与「能力突现观感」的不同切面。

实践启示

误区纠正
模型越大越好固定算力下，N、D 应等比例（Chinchilla）
数据随便堆数据质量与足量同样关键，脏数据有害
涌现=魔法拐点多为指标非线性，底层仍平滑可预测
loss 降就够下游能力看具体任务，需配合评测

总结

  • Scaling Laws：loss 随 N/D/C 幂律平滑下降，可预测。
  • Chinchilla：固定算力下 N、D 等比例最优，数据不足是大忌。
  • 涌现是能力层面的「跳变观感」，底层未必违背幂律。
  • 工程上：堆算力要 N、D 同涨，且重数据质量。

一句话理解缩放定律

缩放定律（Scaling Law）说的其实是一件很朴素的事：模型的损失（预测误差）与参数量、数据量、算力之间，存在稳定的幂律关系。在多个数量级的跨度上画在对数坐标里，近似一条直线。

幂律形式： L(N) ∝ N^(-α) 换成对数： log L = -α · log N + const ↓ 双对数坐标下是一条直线，斜率 = -α α 越大 → 每增加一倍参数，损失下降得越多

之所以重要，是因为它把「炼大模型」从玄学变成了可预算的工程：在花大钱训练之前，先用小模型跑几个点，拟合出这条线，就能外推出「买 10 倍算力大概能把损失压到多少」。

双对数坐标下的幂律：直线可外推，拐点意味着方法失效

三个自变量与「不可能三角」

损失同时受三件事约束：参数量 N、训练 token 数 D、算力预算 C。三者并不独立 —— 算力大致正比于 N × D（再乘常数），于是变成了「给定预算 C，怎么在 N 和 D 之间分配」。

阶段主流结论对实践的提示
Kaplan 等（2020）'在固定预算下应优先增大参数'，当时估算 N ∝ C^0.73 量级导致了一系列「参数巨大、数据不足」的大模型
Chinchilla（2022）'参数和数据同等重要'，指出当时的大模型普遍训练不足，给出约 20 tokens/param 的计算最优点70B 量级模型应配 1.4T 级别 tokens，而非几百 B
近两年实践'tokens 比参数更稀缺'，引入重复 epoch 的收益递减、数据质量权重上升数据清洗、去重、配比的重要性超过单纯堆量

为什么「20 tokens/param」这个数字会流传：Chinchilla 用 400 多个不同配置拟合出最优轨迹，得到的最优比例量级是 —— 训练 token 数约为参数量的 20 倍。它不是物理常数，会随数据质量、架构、Tokenizer 效率变化，但它提供了一个量级正确的直觉：参数每多一个，就需要二十来个 token 去「喂」。

缩放定律能回答的四个问题

① 该不该继续加参数？

能。看 ε 拟合出的指数 α：如果每 10 倍算力带来的损失下降已经压到目标以下（比如下游任务指标提升不足以覆盖成本），就该停手，转向数据质量与对齐（alignment）。

② 有多少算力就配多大的模型？

给定算力预算 C，用 C ≈ 6·N·D 的近似关系（FLOPs 估算），配合 20 tokens/param 的比例，可以直接反解出 N 与 D 组合。

③ 小模型上验证的方法能迁移到大模型吗？

大部分能，这正是缩放定律存在的价值：很多架构改动在小模型上的排序，在放大后基本保持。但也有例外（某些注意力变体在小尺度不显、大尺度才收敛更稳），所以关键改动仍要补中等规模的验证。

④ 什么时候该怎么办？

当实测点明显偏离拟合直线时（图里的红色虚线），说明遇到了新的瓶颈：数据被吃完了、模型容量不够、优化器不稳定、或评测集已被覆盖。此时继续加参数的收益会骤降。

常见误读

  • 「缩放定律 = 越大越好」。它说的是边际收益可预测，不是无限增长。每翻一倍算力带来的提升在递减，工程上要算的是「这次投入换来的指标提升值不值」。
  • 「损失降了指标就一定涨」。预训练损失是代理指标。某些任务（如需要精确Unicode操作、少样本格式跟随）并不随损失平滑改善。
  • 「过了某个门槛会突然开窍」。这属于「涌现」的讨论范畴，而且近年来受到很大质疑（见姊妹篇）。多数能力在合适的连续度量下是平滑出现的。
  • 「数据可以重复 epoch 补量」。重复数据仍会消耗算力但收益显著低于新数据，通常认为重复到第 3~4 个 epoch 后边际收益已经很低。

深入自检

为什么一定要画在对数坐标上？

因为幂律在双对数坐标下才是直线。线性坐标下你会看到一条迅速贴近 X 轴的曲线，几乎看不出 X=10^9 到 10^11 之间还有多大差别；对数坐标把「每翻十倍」压缩成等距，趋势与斜率才变得可读可比。

FLOPs ≈ 6·N·D 这个公式怎么来的？

粗略估算：前向传播时每个参数参与约 2 次浮点运算（一次乘法一次加法），反向传播的乘加约为前向的 2 倍，合计约 6 次运算/参数/token。这是估算训练算力的惯例算法，忽略了激活重计算、注意力额外开销等，量级正确但非精确账单。

既然这样，为什么大家还训那么大的模型？

因为推理是长期成本、训练是一次性的。大模型在同等预算下虽然「训练不足」，但推理时激活的参数量小（尤其是 MoE 架构），长期服务成本低。同时大模型在 few-shot、指令跟随上表现更平滑。这是产业现实与理论最优点之间的取舍。

缩放定律对小团队还有用吗？

非常有用，甚至更有用：它让你在 100M~1B 这种能跑得起的小尺度上做完消融实验，再决定是否把结论迁移到真实规模。真正的门槛从来不是公式，而是有没有稳定的评测基线来做拟合。
