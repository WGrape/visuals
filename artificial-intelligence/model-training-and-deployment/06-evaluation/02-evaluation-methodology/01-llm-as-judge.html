LLM 当裁判
开放题怎么自动打分

选择题能对答案，但“写一首诗”“改一封邮件”没有标准答案。人工打分最准却慢且贵，于是用强模型当裁判成了行业主流。这一页讲清裁判的两种范式、rubric 设计、四类偏差与人工校准。

第 1 步 · 为什么

开放题没法用“精确匹配”判分

选择题、填空题可以对答案；但"写一首诗""改一封邮件""总结这段对话"没有标准答案。人工打分最准，但慢且贵——一次全量评测要几天、还难以复现。于是用强模型当裁判（LLM-as-Judge）成了行业主流。

规模可扩展
几千条样本几分钟跑完，且每次结果一致、可复现。
贴近人类偏好
GPT-4 级裁判与人类一致性约 80%，足够做高频回归与初筛。
裁判不是"替代人工"，而是把人工从"每条都看"降级为"抽样校准 + 关键节点终审"。它解决的是频率与成本问题，不是权威问题。
第 2 步 · 两种范式

Pointwise 与 Pairwise

裁判主要有两种打分方式，适用场景不同：

范式怎么打适合坑
Pointwise 绝对打分给单条回答按 rubric 打 1~5 分质量监控、阈值告警、长尾筛选尺度漂移（今天 4 分≈昨天 3 分）
Pairwise 相对胜负给 A、B 两条比谁更好A/B 模型对比、MT-Bench 思路位置偏好（偏爱先出现的）

第 3 步 · 设计

Rubric 与打分协议

裁判质量的上限，由评分标准（rubric）决定。没有 rubric，模型只会凭"感觉"打分，方差极大。

  • 给维度不给总分：拆成"事实性 / 有用性 / 安全性 / 简洁性"分别打分，比一个总分更能定位问题。
  • 给锚点：明确"5 分 = 完全正确且简洁；3 分 = 部分正确但啰嗦；1 分 = 事实错误"，减少尺度漂移。
  • 多次采样取平均：同一题跑 3~5 次裁判，取均值或众数，压低单次随机性。
  • 参考答案为"参考答案"：提供 gold answer 只作参考，不强制精确匹配，避免罚错"表述不同但正确"的回答。
常见坑：rubric 写成"哪个更 helpful"这种空话，模型会退回长度偏好。rubric 必须可操作、有锚点、分维度。
第 4 步 · 偏差

四种系统性偏差与缓解

  • 长度偏好：裁判偏爱更长的回答，模型学会"写废话"刷分。缓解：长度对照、控制长度、pairwise 时随机化顺序。
  • 位置偏好：pairwise 里先出现的更容易被判赢。缓解：双向评测（A/B 与 B/A 各一次取净胜）。
  • 自我偏好 / 品牌偏好：裁判偏爱"和自己同家族"或"语言风格更像自己"的回答。缓解：换不同家族裁判交叉验证。
  • 权威语气偏差：越自信、越像教科书，越容易被判高分，哪怕内容错。缓解：rubric 强调"事实核查优先于表达"。
工程共识：任何裁判结论都要用人工抽检校准。把裁判分数当"相对排序信号"而非"绝对真理"。
收尾 · 校准

裁判要与人类对齐

LLM-as-Judge = 用强模型按 rubric 给开放题打分，解决人工评测的成本与频率瓶颈。 优先用 pairwise 做模型对比、pointwise 做质量监控；必须配 rubric、多次采样、双向评测来压制偏差； 最终结论永远要用人工抽检校准——裁判是筛子，不是法官。

第一层 · 概念与判定：什么时候该用裁判

你的任务该不该用 LLM 裁判理由
客观题（选择/可验证答案）不需要脚本直接判，比裁判更准更便宜
开放生成的质量初筛用人工看不过来，裁判做高频回归
两版模型 A/B 对比用（pairwise）相对胜负比绝对分更稳
安全/有害判定慎用裁判自身有安全偏差，需红队+人工
版本发布终审不单独用必须人工抽检兜底

一句话决策：能脚本判的绝不裁判，裁判只做"人类看不过来的那部分"，且结论必须人工校准。

第二层 · 参数·命令·量化：温度、采样与成本

# 裁判调用的典型参数（以 OpenAI 风格为例）
  judge(model="gpt-4o", temperature=0,        # 裁判要确定性，temperature 设 0
        messages=[{{"role":"system","content":RUBRIC},
                   {"role":"user","content":PROMPT_AND_ANSWER}}])
  #   temperature=0：同一输入每次输出一致，保证可复现
  #   多次采样：关键结论跑 3~5 次取众数，压低随机性

# pairwise 净胜率计算
  def net_win(wins, ties, losses):
      return (wins - losses) / (wins + ties + losses)   # 只看净胜，ties 不加分

成本估算：假设裁判模型 $0.005 / 1K tokens，每条样本约 800 tokens（prompt+rubric+回答+输出），则 1 万条样本 ≈ $40；同等规模人工评测（按 $0.5/条）≈ $5000。这是裁判被采用的根本动力。

注意：temperature=0 仍可能因服务端的非确定性（batch、kernel）存在微小差异，关键结论建议多次采样。

第三层 · 排障与边界：四种失效模式

  • 长度偏差：长回答被判更好 → 做长度对照，pairwise 随机化 A/B 顺序。
  • 位置偏差：先出现者易胜 → 双向评测取净胜，剔除顺序影响。
  • 自我/品牌偏差：偏爱同家族输出 → 换家族裁判交叉验证。
  • rubric 过宽："哪个更好"类空话 → 拆维度 + 给锚点，否则方差爆炸。
怎么知道裁判"够不够好"？

做裁判校准：抽 100~300 条样本，人工与裁判各判一遍，算一致率（agreement）和 Cohen's kappa。一致率 >80% 或 kappa >0.6 通常算可用；低于此需改 rubric 或换更强的裁判模型。注意要分维度看，不要只看整体一致率掩盖某维度崩盘。

第四层 · 原理与取舍：为什么一致率只有 ~80%

为什么裁判和人类只有约 80% 一致？

因为"好"本身主观且多维：人类标注者之间的一致率也就 80% 出头。裁判学到的是训练语料里多数人的偏好，它无法替你定义业务特有的"好"。所以裁判的价值是稳定可复现的相对信号，不是绝对真理。

pairwise 为什么比 pointwise 更常用？

绝对打分容易尺度漂移（今天松明天严），而"比大小"对人类和模型都更简单稳定。MT-Bench、AlpacaEval 都用 pairwise 胜率。代价是看不到"绝对质量"，只知道 A 比 B 好多少。

裁判模型会被"反过来刷分"吗？

会。如果模型知道自己在被某裁判判，可能学会迎合该裁判的偏好（类似奖励黑客）。缓解：定期换裁判模型、隐藏评测集、加入人工抽检与红队。

深度补充：LLM-as-Judge 的实现与校准

第一层 · 概念与判定 用强模型当裁判给弱模型的输出打分或两两对比，替代人工标注。判定：当人工评测太慢太贵、且任务有可描述标准时采用，但必须先校准。

形态做法风险
打分（rubric）给维度 1-5 分标尺漂移
pairwise 对比二选一更稳位置偏见
含参考对照标准答案参考答案错则误判
自洽多次多次取多数成本翻倍

第三层 · 排障与边界

  • 位置偏见：交换 A/B 顺序结果翻转，需双向打分。
  • 裁判模型与待评模型同族，存在自我偏好。
  • rubric 模糊导致分数不可比，必须给锚定样例。
  • 把裁判分当真实标签，忘了人工金标准校准。
第四层 · 原理与取舍

LLM-as-Judge 用“语言模型的理解力”换评测的可扩展与低成本，代价是偏见、漂移与需持续校准。pairwise 对比通常比绝对打分稳，因为它只问“哪个好”而非“打几分”。权衡是“成本/速度 vs 可信度”：关键结论必须用人工金标准抽样校准裁判一致性（如 Cohen kappa），并定期重校，避免把模型偏见固化成产品指标。

实例与速查：LLM-as-Judge 校准

# pairwise 比绝对打分更稳：交换顺序双向判断，抵消位置偏见
def judge(a, b, rubric):
    s1 = llm(f"哪个更好？\nA:{a}\nB:{b}\n标准:{rubric}")
    s2 = llm(f"哪个更好？\nA:{b}\nB:{a}\n标准:{rubric}")  # 交换
    return "tie" if s1 != s2 else s1

# 定期用人工金标准抽样算 Cohen kappa，校准裁判一致性
  • 位置偏见：交换 A/B 顺序结果翻转，必须双向打分。
  • 裁判与待评模型同族存在自我偏好，需多样化裁判。
  • rubric 模糊导致分数不可比，给锚定样例。
FAQ：裁判分能直接当产品指标吗？

不能直接当。LLM-as-Judge 有偏见、漂移与成本，必须先用人工金标准抽样校准（如算 Cohen kappa），只有关注度高的结论才信任裁判。它最适合做“回归哨兵”——版本变更时快速发现能力退化，关键结论仍要人工复核，避免把模型偏见固化成产品指标。

常见误区与延伸

  • 误区一：裁判分可直接当产品指标。裁判有偏见与漂移，需人工金标准校准才能信任。
  • 误区二：绝对打分比对比稳。pairwise 只问“哪个好”通常更稳，绝对打分标尺易漂移。
  • 延伸：裁判与待评模型同族存在自我偏好，用不同族或更强的裁判更可信。
  • 延伸：裁判最适合做回归哨兵，版本变更时快速发现能力退化，关键结论仍人工复核。

一句话总结：LLM-as-Judge 用语言模型理解力换评测可扩展与低成本，代价是偏见与校准成本，定期 kappa 校准不可省。

决策速记

  • 用 pairwise：比绝对打分稳，交换顺序双向抵消偏见。
  • 勤校准：人工金标准算 kappa，不可直接当指标。
  • 换裁判：与待评同族有自我偏好，用更强/异族。
  • 作哨兵：版本变更快速发现退化，结论仍人工。

一句话：LLM-as-Judge 用理解力换可扩展，代价是偏见与校准成本。

横向对比与追问

  • 与人工标注比：LLM 裁判快且便宜，但需校准；人工准但慢，用作金标准。
  • 与规则评测比：规则只能判格式，LLM 能判语义相关性/忠实度，互补。
  • 追问：为什么 pairwise 比打分稳？绝对打分标尺易漂移，对比只需排优劣。
  • 追问：裁判模型要更强吗？通常需要更强模型当裁判，但同族有自我偏好需注意。

小结：LLM-as-Judge 用理解力换可扩展，必须配人工校准，只可信作回归哨兵。
