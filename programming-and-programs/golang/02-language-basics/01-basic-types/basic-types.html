整型

平台相关 vs 固定位宽

int/uint 的位宽跟随平台（64 位机为 64 位）；需要确定位宽时用 int32/int64 等固定类型。

var a int = 10          // 平台相关
var b int64 = 1<<40     // 固定 64 位
var c byte = 255        // byte = uint8
var r rune = '中'        // rune = int32（见字符串篇）

// 必须显式转换，无隐式
var x int64 = int64(a)
⚠️ 在序列化、网络协议、跨平台文件中，务必用固定位宽类型，否则 32 位与 64 位机器上 int 行为不同，导致数据错位。
浮点数

float32 与 float64 的精度差异

float32 约 7 位十进制有效数字，float64 约 15 位。金钱、计数等场景不要用浮点，改用整数分或 decimal 库。

var f1 float32 = 0.1
var f2 float64 = 0.1
fmt.Println(f1 == 0.1)  // 可能为 false（精度误差）

// 比较浮点请用误差范围
func close(a, b float64) bool { return math.Abs(a-b) < 1e-9 }
复数

complex64 / complex128

复数由实部+虚部构成，complex128 精度更高。常见于信号、图像处理。

var z complex128 = complex(3, 4) // 3+4i
fmt.Println(real(z), imag(z))   // 3 4
fmt.Println(cmplx.Abs(z))       // 5
布尔型

只有 true / false

Go 的 bool 不能和 0/1 互转，也没有「非零即真」。条件表达式必须返回 bool。

var ok bool = true
if ok { }            // 合法
// if 1 { }          // 非法：1 不是 bool
常量与 iota

编译期常量与枚举模拟

常量在编译期确定，可用 iota 在 const 块里生成自增枚举值。

const (
    A = iota // 0
    B        // 1
    C        // 2
)

// 常用：定义带前缀的枚举
type Weekday int
const (
    Mon Weekday = iota + 1 // 1
    Tue                   // 2
)
字符串基础

字符串是只读字节序列

Go 字符串底层是 UTF-8 字节切片，不可变；按「字符」处理要理解 rune。更深的 Unicode/字节视角我们单独写了 Rune 篇。

s := "Go语言"
fmt.Println(len(s))                  // 8（字节数）
fmt.Println(utf8.RuneCountInString(s)) // 4（字符数）
// 字符串不可变，只能生成新字符串
ns := s + "!"

整数类型速查与选择建议

Go 的整数类型很多，但日常只需要记住一条：默认用 int，需要明确位宽或与外部协议对齐时才用定长类型。

类型位宽与范围典型用途
int / uint与平台有关，32 位或 64 位默认选择：计数、索引、循环变量
int8 到 int64固定位宽，明确取值范围与外部协议、文件格式、数据库字段对齐
uint8 / byte0 到 255字节流，byte 是 uint8 的别名
int32 / rune一个 Unicode 码点rune 是 int32 的别名，表示字符
uintptr能存下指针的整型底层编程，日常业务几乎不用
float32 / float64约 7 位 / 约 15 位有效数字默认用 float64
complex64 / 128实部与虚部各 32 / 64 位科学计算、信号处理
为什么默认 int它在该平台上通常是最高效的，且不需要考虑溢出边界
什么时候必须定长序列化到文件或网络、与 C 交互、数据库字段有明确宽度时
byte 与 rune 是别名byte 即 uint8，rune 即 int32，只是语义更清晰
不要怕定长类型转换Go 不做隐式转换，显式写类型转换反而让边界清晰

字符串、byte 与 rune：一个最容易搞混的地方

Go 的字符串是只读的字节序列，源码是 UTF-8 编码。这句话解释了几乎所有关于字符串的困惑。

字符串的三层视角：字节、码点、字符
s := "你好, Go" len(s) // 字节数：中文每个字 3 字节 // 你=3 + 好=3 + 逗号=1 + 空格=1 + Go=2，合计 10 utf8.RuneCountInString(s) // 码点数：6 s[0] // 第一个字节，不是「你」这个字 // 正确遍历字符的方式 for i, r := range s { // i 是字节偏移，会跳：0, 3, 6, ... // r 是 rune，即码点 } // 需要按下标取字符时，先转 rune 切片 rs := []rune(s) rs[0] // 「你」 string(rs) // 转回字符串 // 字符串不可变，不能对某个下标赋值 // 要修改就先转 []byte 或 []rune，改完再转回 string // 代价：每次转换都会拷贝，别在循环里反复做

浮点、常量与零值：三个高频坑

浮点不能精确表示十进制小数

因为二进制无法精确表示 0.1 这类值，累加会引入误差。比较浮点不要直接用等号，应该比较差值是否小于一个很小的阈值；涉及金额时用整数（以分为单位）或专门的十进制库，不要用 float。

常量是无类型的

Go 的常量在参与运算前不绑定具体类型，精度是任意的，只有在赋给变量或用于需要类型的场合时才定型。好处是常量可以声明非常大的数而不溢出，但赋给变量时如果超出该类型范围，仍然会编译报错。

零值可用声明即有一个可用的零值，不需要显式初始化
数值零值0
布尔零值false
字符串零值空串，不是 nil
指针切片映射零值nil，但 nil 切片可直接 append
浮点比较用差值阈值，不用等号
金额用整数分，不用 float
类型转换必须显式，不存在隐式提升

深入自检：基础类型的六个问题

int 到底是 32 位还是 64 位？

取决于目标平台：在 64 位平台上通常是 64 位，32 位平台上是 32 位。写跨平台代码时，如果需要确定的范围，用 int64 而不是 int。同样，uintptr 的大小也随平台变化，但它只用于底层指针运算。

byte 和 uint8 有区别吗？

没有，byte 就是 uint8 的别名，只是语义上强调这是一个字节。同理 rune 是 int32 的别名，强调这是一个字符码点。用哪个取决于你想表达什么，编译器一视同仁。

字符串为什么设计成不可变？

因为不可变带来了几个好处：可以安全地共享底层字节，截取不需要拷贝；天然线程安全；作为 map 的键可靠。代价是拼接会产生新对象，所以要避免在循环里用加号反复拼接字符串。

循环里拼接字符串应该怎么做？

用 strings.Builder 或 bytes.Buffer。它内部维护一个可增长的字节缓冲，最后一次性转成字符串，避免了反复分配与拷贝。如果能预估长度，先用 Grow 预留容量效果更好。

常量表达式会在编译期求值吗？

会。由常量组成的表达式在编译期就算出结果，这也是为什么常量可以声明非常大的数，超出任何整型范围也不报错，只要它不被赋给具体类型的变量。一旦赋值，编译器就会检查是否溢出。

类型转换会丢数据吗？

会，而且是静默的：把 int64 转成 int32，超出的高位直接被截断。Go 不做隐式转换，也不检查运行时溢出，只有常量在编译期检查。所以大范围转小范围时，要自己先判断边界。
