红黑树插入修复手推：什么时候只变色，什么时候需要旋转

用插入 10、5、1、15 的过程解释红叔叔、黑叔叔、旋转方向与黑高不变量。

五条性质背后是一条高度约束

红黑树是一种二叉搜索树：左子树键更小、右子树键更大，同时用颜色限制路径长度。常见定义要求每个节点为红或黑、根为黑、空叶 NIL 为黑、红节点不能有红孩子，以及从任一节点到所有后代 NIL 的路径具有相同黑节点数。由此最长路径不会超过最短路径的两倍，查找、插入、删除能保持 O(log n) 高度。不同教材对“黑高是否计入起点”口径可能不同，但只要同一题内一致即可。

插入时先按普通二叉搜索树规则找到位置，通常把新节点染红。红色不会增加经过该节点的黑高；若父亲是黑色就结束，若父亲也是红色，就违反“红红不能相连”，需要看祖父和叔叔的颜色。根最终要恢复黑色。

图解：红黑树插入的两种修复

沿箭头逐步核对输入、变换和输出；下面的推演可以逐步切换。

先插 10、5、1

插入 10 成根，着黑；插入 5，作为 10 左孩子着红，性质仍成立。插入 1，作为 5 左孩子着红，于是 5 与 1 红红相连。此时祖父 10 为黑，叔叔是右侧空 NIL，可视为黑；形状是左左。对祖父 10 做一次右旋，让 5 升到局部根、10 成为右孩子，再把 5 染黑、10 染红，1 保持红。结果是根 5 黑，左右孩子 1 与 10 都红。

旋转必须保持二叉搜索树中序顺序：原来 1<5<10，修复后仍是 1<5<10。只把颜色改掉而不旋转会让经过左侧 1 的路径与右侧空路径黑高不一致；只旋转不变色则可能仍有红红冲突。每一步都要同时检查搜索树顺序与颜色约束。

逐步推演

插入 10、5

10 黑为根，5 红为左孩子。

插入 1

出现左左红红，黑叔叔；右旋 10 并变色。

插入 15

父亲 10 红、叔叔 1 红；先变色并把根恢复黑。

检查不变量

中序有序、红不连红、到 NIL 黑高相等。

再插 15 看红叔叔

现在把 15 插在 10 的右侧，新节点 15 红，父亲 10 红，祖父 5 黑，叔叔 1 也红。此时不需要先旋转：把父亲 10 和叔叔 1 染黑，把祖父 5 染红，相当于把局部的一层黑色“向上推”。因为 5 是整棵树的根，再把根染黑，修复结束。最终 5 黑，1 黑，10 黑，15 红。新旧路径的黑节点数量仍一致。

如果祖父上面还有红色父节点，变色可能把冲突继续向上带，不能只处理一层就停。标准插入修复在循环中重新把祖父当作当前节点检查，直到父亲黑或抵达根。

新节点位置叔叔颜色典型动作
左左 / 右右黑对祖父旋转并变色
左右 / 右左黑先旋父节点成同侧，再旋祖父并变色
任意形状红父叔变黑、祖父变红，继续向上检查
到达根不适用根恢复黑色

左右、内外形状怎样统一

黑叔叔时还可能是左–右形状：新节点是父亲的右孩子，父亲是祖父的左孩子。通常先对父亲左旋，把它变成左–左，再对祖父右旋并适当变色。右–左是镜像，先对父亲右旋再对祖父左旋；右–右则对祖父左旋。不要死背四段代码，而应问“新节点与父亲是否在祖父同一侧”。同侧可直接围绕祖父旋转，异侧先转成同侧。

旋转改变局部指针和父子关系，工程实现还需正确更新根指针、子树挂接和 NIL 哨兵。图上看着对，指针写错可能形成环或丢失子树。每次旋转后用中序遍历和父指针一致性检查验收。

为什么黑高能保持

红叔叔变色时，父亲与叔叔从红变黑，祖父从黑变红；对从祖父往下的每条路径，新增黑色与失去的黑色相抵。黑叔叔旋转加变色时，局部根换了位置，但每条穿过局部子树的路径仍经过相同数量的黑节点。这是修复正确性的中心，不是“树看起来比较平”就算完成。NIL 叶也要纳入路径比较，漏算空叶容易误判。

红黑树不要求每个节点左右子树高度只差 1；那更接近 AVL 树的严格平衡。红黑树允许一定高度差，减少某些更新时的旋转压力。查找只需要对数高度，不需要完美平衡。

删除比插入更难在哪里

删除黑节点可能让某条路径少一个黑色，产生“双重黑”式的记账问题；修复要看兄弟、兄弟孩子颜色及旋转/变色。不能把插入的“新节点染红”流程直接套在删除上。本课先掌握插入时的红红冲突，再学删除时的黑高缺口。不同实现使用 NIL 哨兵或空指针，代码分支会不同，但最终不变量相同。

验收可依次插入 10、5、1、15、12，并在每次操作后检查中序有序、根黑、无红红、各 NIL 路径黑高一致。最后随机插入去重键并与排序数组比较，既能测值正确，也能测结构约束。

红黑树的五条约束与插入修复的三种情形

编号约束违反时的直观表现
1每个节点非红即黑颜色未初始化的新节点
2根为黑插入第一个节点后忘记染黑
3所有叶子（NIL）为黑把 NIL 当成红会误判路径
4红节点的子节点必为黑（无连续红）新插入红节点挂在红父下
5任一节点到其所有后代 NIL 的黑节点数相同（黑高 bh）旋转/变色后局部黑高被破坏

插入一个新红节点只会违反第 2、4 条（黑高不变）。修复按叔叔节点颜色分三种情形：

情形条件动作后续
1叔叔 u 为红父与叔染黑、祖父染红，然后把祖父当作新的 z 继续向上最坏上溯 O(log n) 层，不需要旋转
2叔叔 u 为黑，且 z 是外侧孩子（左左 / 右右）父染黑、祖父染红，对祖父做一次旋转一次旋转即结束
3叔叔 u 为黑，且 z 是内侧孩子（左右 / 右左）先对父节点旋转，转化为情形 2共两次旋转后结束

关键量化结论：插入修复最多做 2 次旋转（情形 3 转 2），其余只是变色；删除修复最多 3 次旋转。旋转次数与树高无关，这也是红黑树比 AVL 更适合频繁增删的原因。

  • 插入 7 个节点后树高为 4（含 NIL 层），而同样数据插入普通二叉搜索树会退化成高度 7 的链。
  • 黑高 bh = 2 意味着任意根到叶路径上恰好有 2 个黑节点（不含根时另计），这正是第 5 条约束的校验点。
  • 校验方法：对每条根到叶路径数黑节点数，全部相等且不存在父子双红，即为合法红黑树。

可执行的验证代码

合法性校验

RED, BLACK = True, False

def check_rb(root):
    """返回 (是否合法, 黑高)：同时校验五条约束。"""
    def dfs(n):
        if n is None:
            return True, 1                      # NIL 计为黑
        if n.color == RED and n.parent and n.parent.color == RED:
            return False, -1                    # 违反第 4 条
        ok_l, bh_l = dfs(n.left)
        ok_r, bh_r = dfs(n.right)
        if not (ok_l and ok_r) or bh_l != bh_r:
            return False, -1                    # 违反第 5 条
        add = 0 if n.color == RED else 1
        return True, bh_l + add
    ok, bh = dfs(root)
    return (ok and root.color == BLACK), bh     # 第 2 条：根为黑

# 性质：n 个内部节点的红黑树高度 h <= 2*log2(n+1)
# 例：n=7 -> h <= 2*log2(8) = 6；n=1000 -> h <= 2*log2(1001) ≈ 19.9

修复骨架

# 插入修复的最小骨架（只列情形判断，省略旋转实现）
def fixup(root, z):
    while z.parent and z.parent.color == RED:          # 只有父为红才需修复
        g = z.parent.parent
        if z.parent is g.left:
            u = g.right
            if u and u.color == RED:                    # 情形 1：叔叔红
                z.parent.color = BLACK
                u.color = BLACK
                g.color = RED
                z = g                                   # 继续上溯
            else:

                g.color = RED
                rotate_right(root, g)
        else:
            pass                                        # 对称分支：left/right 互换
    root.color = BLACK                                  # 根恒为黑

深入自检

为什么新插入的节点要染红而不是黑？

染红不增加任何路径的黑节点数，只可能违反“不能连续红”；染黑会立刻让该路径黑高 +1，直接违反第 5 条且更难修。染红把破坏范围限制在局部。

插入修复为什么最多两次旋转？

情形 1（叔叔红）只做变色，然后向上继续；一旦进入情形 2/3，经过至多两次旋转后该子树根变黑，局部性质恢复，循环立即终止。旋转次数与树高无关，只有变色可能上溯 O(log n) 层。

红黑树的高度上界是多少？

含 n 个内部节点时 h ≤ 2·log₂(n+1)。因为黑高 bh ≥ h/2，而黑高为 bh 的子树至少含 2^bh − 1 个内部节点。这意味着查找、插入、删除最坏都是 O(log n)。

红黑树和 AVL 树该怎么选？

AVL 更严格平衡（高度约 1.44·log₂n），查找略快但插入/删除旋转更多；红黑树放宽到 2·log₂(n+1)，插入最多 2 次旋转、删除最多 3 次，更适合插入删除混合频繁的场景（如 C++ std::map、Java TreeMap、Linux CFS 调度队列）。

手算时怎么快速判断是情形 2 还是情形 3？

看 z 与父、祖父三者的方向是否一致：连续同向（左左或右右）是外侧→情形 2，一次旋转；方向拐了一次（左右或右左）是内侧→情形 3，先转父再转祖父。

自检

插入 1 后 10–5–1 构成左左红红，叔叔为黑，只把 5 染黑就足够吗？

不够。还要围绕祖父 10 右旋，并按规则调整 10 与 5 的颜色，保持黑高和搜索顺序。
