# Visuals

以动态可视化为核心特色的计算机在线学习平台。

**核心理念：目录即知识层级。** 物理目录的层级就是知识的层级——每篇课程都落在「一级技术标题 → 二级分类卡片 → 三级知识分层 → 四级及更深专题」这棵真实目录树上，不靠文件名或卡片分组假装分类。

目录：[目录层级](#目录层级) · [内容组织规则](#内容组织规则) · [本地运行](#本地运行) · [校验](#校验)

## 目录层级

| 层级 | 名称 | 是什么 | 关键约定 | 示例 |
| --- | --- | --- | --- | --- |
| **一级** | 技术标题（知识域） | **固定 5 个**，对应根目录 `index.html` 的 5 个大标题 | **本身不建 `index.html`**——由根目录 `index.html` 代管：大标题下的「分类卡片」直接指向该域各二级目录 | `artificial-intelligence/` |
| **二级** | 分类卡片（学科分类） | 某一域下的分类，即首页大标题下的「分类卡片」所指向的目录 | **必须有 `index.html`**（唯一强制索引层）；只放三级目录，**不放课程文件** | `model-llm/` |
| **三级** | 知识分层（章节） | 分类下的章节 | 必须以两位序号 `NN-` 开头；只放四级目录，**不放课程文件** | `model-llm/02-params/` |
| **四级+** | 知识分层（专题） | 专题及其进一步细分 | 真正承载课程（`.html`/`.md`）；**至少四级** | `02-params/00-overview/` |

要点：

- **`index.html` 只建在二级**（脚本强制，缺了或越级建索引都会报错）。一级由根目录 `index.html` 统一索引；原有三级索引已并入对应二级索引，三级及以下直接承载分层内容。
- 三级及更深层都叫「知识分层目录」。从三级起，知识点必须继续落在分层子目录里，**至少四级**；复杂主题可继续到第五、第六级，不要强行压平——否则会退化成"一个目录塞几十篇平铺文章"，既没法导航也看不出脉络。
- 三级及更深目录都要以 `00-`、`01-`、`02-` 等两位序号开头；同层序号不得重复或断档，概览专题用 `00-overview/`。
- 一级固定为 **5 个**（与 `check_knowledge_hierarchy.py` 的 `ROOTS` 一致，见下表）；`assets/`、`docs/` 是资源目录，不参与知识层级。

| 一级（技术标题 / 知识域） | 含义 |
| --- | --- |
| `artificial-intelligence/` | 人工智能 |
| `system-engineering/` | 系统工程 |
| `database-system/` | 数据库系统 |
| `cst/` | 计算机科学与技术 |
| `programming-and-programs/` | 编程与程序 |

**实例路径：** `artificial-intelligence/`（一级）→ `model-llm/`（二级）→ `02-params/`（三级）→ `00-overview/`（四级，承载课程）。

## 内容组织规则

- **先定位再落地**：先定一级知识域 → 二级分类 → 三级编号章节 → 四级或更深专题目录。不要新建一级目录，也不要为单篇课程新开与现有学科平行的二级目录。
- **课程只落深处**：课程文件（`.html`/`.md`，且非 `index.html`）只放在四级或更深目录；不放在一/二/三级。概览课放 `00-overview/`。
- **层级完整性**：每个二级必须有 `index.html` 且至少一个三级；每个三级必须编号且至少一个四级专题目录；一级和三级及以下不得另建 `index.html`。
- **真实边界**：目录要表达真实知识边界（如基础概念、检索策略、评估优化）；单篇课程也可构成真实专题，不强行合并；暂无课程的专题用 `.gitkeep` 占位，有内容后移除该标记，不虚构课程页。
- **链接可达**：每篇课程必须被某个可达 `index.html` 以 `<a class="card">` 卡片链接，否则校验报「未链接」；移动文章时同步修正卡片、互链、资源路径与返回链接。
- **专题名称可区分**：同一学科索引中的不同 `data-path` 应使用不同的 `data-title`；跨产品重复的专题名和课程卡片名要带产品名，概览与专题实践要写清差异。

## 本地运行

课程页面自包含（内联样式与 SVG 图解），**直接双击 `index.html` 即可完整浏览**——站内脚本不依赖 `fetch`。如需以服务方式访问（如配合 `container.html` 子路径发布），在根目录运行 `python3 -m http.server 8000`，访问 <http://localhost:8000/>。

## 校验

新增/迁移内容后，在仓库根目录运行：

```bash
python3 -B check_knowledge_hierarchy.py   # 目录层级、编号连续性、索引层级、课程是否越级
python3 -B check_topic_tree.py            # data-path 与真实目录、卡片所属目录一致性
bash check_html_link.sh                   # 页面是否被可达索引以卡片引用
bash check_safe.sh                        # 本地坏链与敏感内容
python3 -B check_knowledge_relocations.py # 活跃旧路径映射目标是否存在
```

| 脚本 | 检查什么 | 何时失败 |
| --- | --- | --- |
| `check_knowledge_hierarchy.py` | 目录深度、三级及更深目录编号与连续性、`00-overview` 命名、只在二级建立 `index.html`、课程是否越级存放 | 结构错误（占位目录只提醒） |
| `check_topic_tree.py` | `data-path` 与真实目录、卡片所属目录、断链、重复入口及重复展示名 | 目录树与内容对不上 |
| `check_html_link.sh` | 每个页面是否被可达索引以卡片引用 | 存在未链接页面 |
| `check_safe.sh` | HTML 内部坏链、混入的非 HTML 文件、疑似密钥 | 坏链或敏感信息 |
| `check_knowledge_relocations.py` | 活跃历史映射的目标、自指与已记录 Git 归档对象 | 活跃目标失效、错误映射或归档记录不完整 |
