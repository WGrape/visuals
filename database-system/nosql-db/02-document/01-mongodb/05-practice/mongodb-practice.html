🛠️ MongoDB 实践

调优、事务与坑

实践要点

🧱

合理嵌套

别无限嵌套；超大数组会拖慢文档读取。

🧾

事务

4.0+ 支持多文档事务，但跨分片事务成本高，能避免就避免。

📉

慢查询

开 profiler，关注全表扫描与缺失索引。

常见坑

  • 无模式变无纪律：放任字段随意变化，后期清洗痛苦——用 validation 兜底。
  • 大文档：BSON 单文档上限 16MB，超大内容应拆表或存对象存储。
  • 热点 shard key：单调递增 key（如时间戳）会导致写入集中在一个分片。
💡 MongoDB 适合快速迭代、结构易变、读多写少或需要水平扩展的业务；强一致、复杂事务、固定schema的场景仍考虑关系型。
