方式扩缩容代价数据倾斜典型
取模 hash % N大（几乎全迁移）无简单缓存
一致性哈希小（邻域迁移）需虚拟节点Memcached/客户端
哈希槽中（槽迁移）无Redis Cluster

Redis Cluster 的槽

把 key 的 CRC16 映射到 16384 个槽，槽再分配到节点。扩缩容迁移的是槽而非单 key，运维可控、对调用方透明。

🎯 面试问答

Q：取模为什么扩缩容代价大？
A：N 变化导致绝大多数 key 重新映射。
Q：Redis Cluster 为什么用槽？
A：槽是迁移与管理的逻辑单元，对客户端透明。
Q：一致性哈希还要虚拟节点吗？
A：要，否则物理节点少会倾斜。
