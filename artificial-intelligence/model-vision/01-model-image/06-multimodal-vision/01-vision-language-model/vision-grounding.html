视觉语言模型：让回答落在图像证据上

从高分辨率输入、视觉 token 到空间定位，专注“看到了什么”的可靠性。

学完能解释什么

  • 解释视觉输入如何转换成供语言模型使用的表示
  • 分清图文相关、区域定位与真正的视觉证据
  • 设计能揭露语言先验和视觉幻觉的评估样本

逐步看机制

尺寸与切块决定小目标可见性

高分辨率图可缩放或切成局部 crop；全图上下文和局部细节都要保留，不能凭增多 token 保证看清小字。

“能看图说话”不是“能精准定位”

视觉语言模型通常将图像编码为视觉 token，通过投影或交叉注意力与语言表示结合，再生成回答。架构细节已在 LLM 的 VLM 原理课程讲解；这里重点是视觉证据的粒度。整图问答可以靠场景线索回答，但“第几行左侧按钮写了什么”需要足够分辨率与区域对应。对小字、密集物体或多面板图片，缩小整图会丢失信息，切块又可能失去全局位置，因此需把全局视图与局部区域共同设计。

图文相关不等于 grounded

一个模型回答“街景里有车”可能是视觉识别，也可能受到常见街景文本先验影响。要检验 grounding，可设计只改图像不改问题的反事实样本：把红色按钮改蓝色、调换左右位置、遮住目标，再看答案是否相应变化。若任务要求位置，输出可核对的区域框或坐标并进行图像回看；注意框位置和语言答案都可能出错。

评估可靠性的分层任务

先测“是否看到目标”，再测“是哪一个”、属性、空间关系，最后测文字读取和多步推断。OCR、计数、图表细节在高压缩和低分辨率下特别脆弱。评价时按分辨率、目标尺寸、遮挡及反事实替换分组，区分看不清导致的不确定与模型凭空编造。面向真实业务时可提供局部放大、引用图块和人工复核，但引用图块本身也应从原图验证。

自检

模型正确描述大街常见物体，是否足以证明它看清了图中的按钮文字？

不足。场景常识与细粒度 OCR 是不同能力；需要在局部图块、反事实图像和真实文字标注上单独验证。

典型工作流

① 开放词汇检测

给定任意文本（可以是短语、属性组合、甚至一句话），直接输出所有匹配区域的框。Grounding DINO 是这一类的代表，工程上非常实用。

② 框 → 掩膜

Grounding 通常只给框，需要精确轮廓就把它作为 prompt 送给 SAM，得到高质量掩膜。这个"DINO 出框 + SAM 出掩膜"的组合是目前最实用的开放词汇分割方案。

③ 自动数据标注

用 Grounding 模型对无标注图像自动打框，人工只做修正——能把标注成本降低 60%~80%。这是当前最有价值的应用之一。

④ 指代与消解

处理「左边那只猫」「穿红衣服的人」这类需要结合上下文的指代，通常需要 VLM 理解语义后再调 Grounding。

实践要点

prompt 很重要描述越具体越好；「红色汽车」优于「车」
阈值调节box_threshold / text_threshold 控制召回与精度的权衡
不支持的类别极罕见概念、抽象概念（「孤独感」）难以定位
与检测互补固定类别高频场景仍用专用检测模型（更快更准）
批量标注先自动打标再人工修，是性价比最高的用法

深入自检

Grounding 和目标检测有什么区别？

核心区别是类别是否开放。传统检测器在训练时就把类别定死了（如 COCO 的 80 类），推理时只能输出这 80 类，想加一个新类别必须重新标注数据、重新训练。Grounding（开放词汇检测）把「类别」换成了任意文本描述，在推理时给定——你输入「戴红色安全帽的工人」，它就能定位，而这个类别训练时从没见过。机制上，Grounding 模型把文本和图像区域编码到同一个语义空间（靠大规模图文对比学习），定位就变成了「算哪个区域和这段文本最像」。

Grounding DINO 和 SAM 该怎么配合？

它们解决的是不同粒度的问题，组合起来最实用。Grounding DINO 做开放词汇检测：输入文本，输出边界框（知道「在哪里、是什么」）。SAM 做提示式分割：输入点/框/文本，输出像素级掩膜（知道「精确的轮廓」），但它不输出类别。所以组合工作流是：文本 → Grounding DINO 出框 → 把框作为 prompt 给 SAM → 得到带类别的精确掩膜。这是目前开放词汇分割最实用的方案，也被广泛用于自动数据标注。

Grounding 模型能定位任何东西吗？有哪些局限？

不能，有明显边界：①概念要可视觉化——「红色的车」可以，「性价比高的车」「孤独感」这类抽象概念不行；②罕见概念弱——如果某个概念在图文预训练数据里从没出现过，模型没有对应的语义表示；③组合理解有限——「左边那只不是黑猫的猫」这类复杂逻辑常常失败；④小目标与密集场景弱——与所有检测模型一样；⑤属性敏感度不均——颜色、大小尚可，材质、数量常常出错。实践建议：用它做常见开放概念的定位与自动标注，但对于高精度要求的固定类别任务，还是训练专用检测器更靠谱。

怎么用 Grounding 模型降低标注成本？

典型流程：①用 Grounding 模型（如 Grounding DINO + SAM）对无标注图像批量自动打标，输出框/掩膜 + 类别；②人工在标注工具里只做修正（删错的、补漏的、微调框）；③用修正后的数据训练专用检测/分割模型；④用新模型再对更多数据打标，形成迭代。实践效果：通常能减少 60%~80% 的人工标注时间。注意事项：自动标注的质量取决于概念是否常见；一定要抽检评估自动标注的准确率；用作训练数据时最好人工过一遍，避免错误标签被放大。

多模态大模型（如 GPT-4V）能做 Grounding 吗？和专用模型比如何？

分两类能力：①坐标输出型——部分 VLM（Qwen-VL、Ferret 等）能把坐标当 token 输出，可以给出框，但精度通常不如 Grounding DINO 这类专用模型；②隐式理解型——多数 VLM 能理解「图左边有只猫」并用语言描述位置，但不给出精确坐标，无法直接用于需要框的任务。所以工程实践通常是组合：用 VLM 做语义理解与指代消解（理解用户到底在问哪个物体），再把解析出的文本描述交给专用 Grounding 模型精确定位——各用所长。直接用 VLM 输出坐标做生产级定位，精度和稳定性目前还不够。

Grounding 任务与表示

Grounding 指把语言中的指代表达定位到图像的具体区域，输出通常是边界框或分割 mask。

子任务输入输出典型指标
REC（指代表达理解）图像 + 一句描述一个框IoU > 0.5 命中率
RES（指代表达分割）图像 + 描述maskmIoU / oIoU
Phrase Grounding图像 + 整句多个短语各自的框F1@IoU0.5
Grounding 对话多轮对话带框的文本回复人工评测为主

坐标还原

# 坐标表示：多数模型输出归一化坐标，需还原到像素
# 常见三种格式，混用是集成时最常见的 bug
#   1) [x1, y1, x2, y2]        归一化到 0~1000 或 0~1
#   2) [x, y, w, h]           中心点 + 宽高
#   3) [x1, y1, x2, y2]       像素绝对值

def denormalize(box, img_w, img_h, scale=1000, fmt="xyxy"):
    if fmt == "xyxy":
        x1, y1, x2, y2 = [v / scale for v in box]
        return [x1 * img_w, y1 * img_h, x2 * img_w, y2 * img_h]
    raise ValueError("先确认模型输出的是哪种格式！")

# 必做校验：x2 > x1 且坐标在 [0, W/H] 内
# 模型偶尔输出越界或反序框，直接用会画出奇怪区域

主流方案对照

方案做法优点缺点
两阶段检测器出候选框 + CLIP 匹配可复用现成检测器，零训练候选框质量决定上限
端到端微调VLM 直接输出坐标 token精度高，支持复杂描述需标注数据微调
开放词汇检测OWL-ViT / Grounding DINO零样本，任意类别长句理解弱于微调模型
LLM + 工具LLM 调检测 API可组合、可解释依赖工具召回，链路长

选型判据：类别是否固定。固定类别（如“找到所有缺陷”）用专用检测器 + 微调精度最高；类别开放、描述多样（如“左边那个穿红衣服的人”）用 Grounding DINO 类零样本方案。

精度影响因素与调优

因素影响程度应对
目标尺寸极大，小目标最容易漏提高输入分辨率；小目标单独裁剪放大
描述歧义大（多个同类物体）要求描述含唯一区分特征（位置/颜色/相对关系）
遮挡中分割 mask 比框更抗遮挡
输入分辨率大384→768 通常明显涨点，但显存平方增长
候选框数量中大（两阶段方案）候选越多召回越高但匹配噪声增加

阈值调优

# Grounding DINO 关键阈值
# box_threshold      : 框置信度阈值，默认 0.35；小目标或模糊描述可降到 0.25
# text_threshold     : 文本-区域匹配阈值，默认 0.25
# 经验：宁可 box_threshold 调低让候选多一点，再用文本相似度重排，
#       而不是一开始就卡高阈值导致漏检

boxes, logits, phrases = predict(
    model=model, image=image, caption=caption,
    box_threshold=0.30, text_threshold=0.25
)
# phrases 会返回每个框对应的文本片段，用它可判断匹配是否落在正确的词上

自检 Q&A

Q：Grounding 和开放词汇检测是一回事吗？

A：高度相关但粒度不同。开放词汇检测的输入是类别词列表（“cat, dog, car”），输出所有该类实例；Grounding 的输入是完整句子或短语，需要理解“左边那只”“正在跳的”这类限定，输出通常唯一。后者对语言理解的要求高得多。

Q：为什么模型对小物体定位不准？

A：两个原因——① 视觉特征图分辨率不足（ViT patch 是 14×14 像素，小于这个尺度的物体几乎没有独立特征）；② 训练数据中小目标样本占比低。实用缓解：对疑似小目标区域裁剪放大后二次推理（两阶段由粗到细），比单纯拉高全局分辨率更划算。

Q：坐标输出不稳定，同一张图两次结果不同？

A：确认推理时关闭了随机性（model.eval()、torch.no_grad()、固定种子）。若已关闭仍抖动，多半是输入预处理不一致——resize 的插值方式、是否做 padding、归一化参数不同都会改变结果。把预处理固化成函数，别在多个地方各写一遍。

Q：如何评估 Grounding 模型好不好？

A：标准指标是 Accuracy@IoU0.5：预测框与真值框 IoU 超过 0.5 记为正确。但只看总准确率不够，必须分层——按目标面积（小/中/大）、按描述类型（属性类/空间关系类/唯一指代类）分别统计。RefCOCO 系列数据集就是按“含空间关系词”等维度划分的，这样才知道模型到底弱在哪。
