视频扩散模型：在潜空间里生成连续帧

从加噪、时空去噪到分段采样理解质量、显存和长时漂移。

学完能解释什么

  • 区分图像扩散和视频扩散需要的时间约束
  • 解释潜空间与时空模块怎样降低计算量
  • 知道分块推理为什么容易出现边界漂移

逐步看机制

从像素帧得到潜变量

视频编码器把空间甚至时间维度压缩，减少去噪序列长度；压缩太强会损坏小字和快速运动。

“图像扩散 + 时间”增加了什么

图像扩散学习从噪声逐步恢复一张图；视频扩散要恢复带时间关系的多帧潜序列。模型可以使用时空联合注意力、空间/时间分解模块或混合结构，使同一人物和场景在不同帧共享证据。若各帧独立采样，即使每张都很漂亮，也可能在播放时随机闪烁。

潜空间不是免费午餐

直接对大量高分辨率像素帧做去噪十分昂贵，通常先用 VAE 等编码器压缩到潜空间，再在潜变量上训练去噪网络。可降低 token 数与显存压力，但压缩器也可能模糊文字、细节与高速运动。生成时还要多次模型前向传播，步数、帧数与分辨率共同推高成本；更快的采样器和蒸馏是取舍，不意味着没有画质代价。

长视频的条件与误差

训练窗口有限时，长视频常分块生成或续写。参考帧、文本脚本与压缩的跨段记忆帮助衔接；若上一段角色身份略有偏差，连续续写会把误差传下去。比较模型时要明确一次生成的时长、帧率、分辨率、采样步数和后处理插帧方式，否则“更长更清晰”可能只是不同口径。

评估除单帧质量和文本遵循外，还要看运动真实性、时间一致性、片段边界和失败概率。与自回归等生成方案的取舍取决于延迟、控制粒度和训练数据，不能只比精选演示片段。

自检

对每一帧独立运行同一个图像扩散模型，是否自然得到稳定视频？

不能保证。独立采样没有跨帧的身份、几何和运动约束，容易产生闪烁与角色漂移。

控制与条件注入

文本条件

与图像一样用 CLIP 文本编码 + 交叉注意力。但视频还需要描述动作与镜头运动，prompt 通常要写明（如「镜头缓缓推进」）。

图像条件（图生视频）

给定首帧生成后续。做法：把首帧编码到潜空间，作为额外的条件通道拼接到噪声上，或用参考注意力让每帧都参考首帧。这是目前最实用的模式（可控性远高于纯文生视频）。

运动强度控制

常见有 motion_bucket_id 之类的参数控制运动幅度：值小画面几乎静止，值大运动剧烈但容易崩。这是图生视频里最重要的调节旋钮。

结构控制

ControlNet 扩展到视频：输入深度图序列、姿态序列、边缘序列来精确控制构图与运动轨迹。

成本估算

显存与「帧数 × 分辨率² × 通道」成正比，是最硬的约束
时间扩散步数 × 帧数 × 每步成本；通常几十秒到几分钟生成 2~4 秒视频
降本手段潜空间压缩、时域压缩 VAE、少步采样器（DPM-Solver）、蒸馏、LCM
实用建议先生成短片段（2~4 秒），再用插帧/超分扩展，性价比最高

深入自检

视频扩散模型和图像扩散模型的结构区别在哪？

本质是把噪声张量从 3 维 [C,H,W] 扩成 4 维 [F,C,H,W]，然后在网络里增加能处理时间维的模块。具体做法：①把 2D 卷积「膨胀」成伪 3D 卷积（在时间维也有核），但通常用时空分离形式（先 2D 空间卷积再 1D 时间卷积）以控制参数；②在空间自注意力之后插入时间自注意力，让同一空间位置在不同帧之间交互；③用预训练图像模型的权重去初始化这些新模块，并把新加的时间层初始化为恒等映射，这样训练初期行为与图像模型一致，收敛更快更稳。

为什么视频生成常常先生成短片段再扩展？

因为显存是硬约束。时空扩散的显存占用大致与「帧数 × 高 × 宽 × 通道」成正比，一次生成 16 帧 1024×1024 的潜变量就要几十 GB，消费级硬件根本跑不了。所以工业方案普遍采用级联：先在低分辨率（如 256×256）生成 16~24 帧的基础视频 → 用时域插帧把帧数翻几倍 → 用空间超分把分辨率提上去。这样每一步的显存需求都可控，最终得到高清流畅的长视频，性价比远高于端到端硬冲。

图生视频和文生视频哪个更实用？

目前图生视频更实用。因为纯文生视频的可控性差——同一个 prompt 每次生成的构图、主体、色调都可能完全不同，很难满足具体需求（比如「让这张产品图动起来」）。图生视频给定了首帧，构图与主体被锁定，模型只需要生成合理的运动，可控性和可用性都高得多，也更符合实际工作流（先出一张满意的图，再让它动起来）。所以生产中大量使用图生视频，文生视频更多用于创意探索。

motion_bucket_id 这类参数该怎么调？

它控制生成视频的运动幅度。调小（如 20~50）：画面几乎静止，只有轻微变化，适合做「照片轻微呼吸感」或产品展示，最不容易出错；中等（100~130）：有明显但不夸张的运动，是最常用的区间；调大（180+）：运动剧烈，容易出构图崩坏、物体变形、画面撕裂。实践建议：从 100 起步，觉得动得不够再加，但一般不超过 150；如果画面崩了就往回调。另外它和 prompt 里描述的动作强度要匹配——写「缓慢推进」却设大 motion 值会冲突。

视频扩散模型的主要局限是什么？

四条：①时长——端到端通常只能生成几秒，长视频要靠级联或续写，且容易漂移；②成本——显存与算力的需求远高于图像，推理慢（几十秒到几分钟）；③物理与因果——模型不理解真实物理，常出现物体凭空出现/消失、穿模、违反重力的运动，长期一致性差；④可控性——精确控制镜头运动、多个主体的交互、特定时序事件仍然很难，需要 ControlNet 类方法或大量试错。这些也是当前研究的热点方向。

想做一个视频生成应用，工程上要注意什么？

①先定场景——图生视频（产品/营销）还是文生视频（创意）？前者更可控、更容易做出可用的产品；②成本控制——用潜空间模型 + 少步采样器 + 半精度，必要时用蒸馏/LCM 模型；③异步队列——生成耗时几十秒以上，必须做成任务队列 + 回调，不能同步等待；④参数默认值——给用户几个预设档位（静止/轻微/明显运动）而不是裸露的参数；⑤后处理——插帧提升流畅度、超分提升清晰度、裁切统一尺寸；⑥内容安全——必须有审核环节。

推理

# Stable Video Diffusion 风格的最小推理（diffusers）
python - <<'PY'
import torch
from diffusers import StableVideoDiffusionPipeline
from diffusers.utils import load_image, export_to_video

pipe = StableVideoDiffusionPipeline.from_pretrained(
    "stabilityai/stable-video-diffusion-img2vid-xt",
    torch_dtype=torch.float16, variant="fp16")
pipe.enable_model_cpu_offload()          # 显存不足时把不用的模块挪到 CPU

image = load_image("first_frame.png")
frames = pipe(image, decode_chunk_size=8,     # 分块解码，避免一次性爆显存
              num_frames=25,
              fps=7,
              motion_bucket_id=127,           # 运动幅度：0 静止 ~ 255 剧烈
              noise_aug_strength=0.02,        # 对首帧加噪，越小越贴合原图
              num_inference_steps=25).frames[0]
export_to_video(frames, "out.mp4", fps=7)
PY

两个最容易忽略的旋钮：motion_bucket_id 控制运动幅度（过大导致形变，过小像静止图），decode_chunk_size 控制 VAE 解码的分块大小（决定峰值显存）。

深入自检

视频扩散比图像扩散多了什么？

多了一个时间维：潜空间从 H/8×W/8 变成 F×H/8×W/8，主干要能建模帧间关系（3D 卷积或时序注意力），并额外引入运动模块、相机控制等条件。代价是计算与显存随帧数线性增长。

步数从 50 降到 20 会怎样？

速度约提升到 2~2.5 倍，质量（细节与一致性）会下降，但配合更好的采样器（如 DPM-Solver、一致性/LCM 蒸馏模型）可以把损失压到很小。工程上常用 20~25 步作为质量与速度的平衡点。

为什么长视频要分段生成？

因为模型在训练时只见过有限帧数（如 16~25 帧），直接要求更长会出现时序漂移与内容崩坏。做法是把上一段的最后一帧作为下一段的首帧，链式调用图生视频，代价是误差会累积、主题可能漂移。

FVD 高一定说明视频难看吗？

不必然。FVD 衡量的是生成视频分布与真实视频分布的距离，对样本量敏感（通常需要上百到上千个片段才稳定），且与单条视频的观感不完全对应。应结合 CLIPSIM（语义贴合）、warping error（稳定性）与人工盲评一起判断。

如何控制生成视频的运动幅度？

主要靠两个参数：motion_bucket_id（数值越大运动越剧烈）与提示词中的动作描述；此外 noise_aug_strength 决定对首帧的贴合程度（越小越像原图静止，越大越自由发挥）。三者要一起调。
