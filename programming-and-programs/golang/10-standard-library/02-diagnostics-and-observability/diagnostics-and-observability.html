日志

标准库日志

log 包输出带前缀与时间；多实例用 log.New 自定义。Go 1.21 起标准库还提供 log/slog 结构化日志，如何组织字段与级别见工程实践课程。

log.SetPrefix("[app] ")
log.Println("started")
l := log.New(os.Stdout, "[api] ", log.LstdFlags)
指标暴露

开箱即有的指标

expvar 在 /debug/vars 暴露 JSON 指标（含 GC、goroutine 数等）；也可注册自定义计数器，方便被采集。

var hits = expvar.NewInt("hits")
hits.Add(1)
// 访问 /debug/vars 可见
运行时指标

runtime/debug & metrics

runtime.NumGoroutine、debug.ReadGCStats 等给出运行态；runtime/metrics 提供稳定命名的指标读取接口。

n := runtime.NumGoroutine()
var st runtime.MemStats
runtime.ReadMemStats(&st)  // 分配/GC 统计
pprof 端点

线上也能剖

import _ "net/http/pprof" 后，/debug/pprof/ 暴露 CPU/堆/goroutine 等端点，可远程取样本定位问题。

⚠️ 生产暴露 pprof 需做好访问控制（内网/鉴权），避免泄露运行细节。

可观测性的三根支柱

「能登录机器看日志」在分布式系统里不再可行。可观测性由三类信号构成，各自回答不同问题。

日志、指标、链路各自回答什么问题
日志离散事件，成本随量增长，适合事后还原。
指标可聚合的数值，成本低，适合告警。
链路跨服务因果，适合定位延迟来源。
剖析进程内部的 CPU 与内存画像。

结构化日志：log/slog 怎么用

import "log/slog" // 生产用 JSON，开发用易读格式 logger := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{ Level: slog.LevelInfo, })) slog.SetDefault(logger) // 带结构化字段 slog.Info("order created", "order_id", 12345, "user_id", 678, "amount", 99.9, ) // 分组：同类字段归到一起 slog.Info("request done", slog.Group("http", "method", "GET", "status", 200), "duration_ms", 12, ) // 输出（JSON 形式便于日志系统检索） // {"level":"INFO","msg":"order created","order_id":12345,"amount":99.9}
用键值不用拼接拼接字符串无法检索与聚合
级别要克制Error 用于需要人处理的问题
带上 trace id才能与链路、其它服务关联
别打敏感信息密码、令牌、完整身份证要脱敏
热路径少打日志高频日志本身会成为瓶颈
错误只记一次要么记要么返回，避免重复刷屏

RED 与 USE：两套现成的指标框架

RED（面向服务）

  • Rate：每秒请求数
  • Errors：每秒错误数
  • Duration：耗时分布（看 P99 不是平均值）

适合每个对外接口都配齐这三项，是服务健康检查的最小集。

USE（面向资源）

  • Utilization：资源繁忙比例
  • Saturation：排队程度
  • Errors：错误事件数

适合 CPU、内存、连接池、磁盘这类资源型组件。

告警怎么设

  • 对症状告警（错误率、延迟），不对原因告警
  • 用分位数而非平均值，平均值会掩盖长尾
  • 告警要可行动，无法行动的告警等于噪音
  • 配好黄金指标后，原始数据留着做排查

深入自检

日志打得多是不是更安全？

不是。过量日志会拖慢服务、抬高存储成本，并让真正重要的信息被淹没。正确做法是默认精简、错误与关键路径充分、支持按 trace id 或动态级别临时加量。

为什么平均值会骗人？

平均值会被大量正常请求拉平，掩盖少数极慢请求。用户感受到的恰恰是长尾。应当看 P95 / P99，甚至最大值的分布。

pprof 和 trace 有什么区别？

pprof 是采样统计，回答「时间花在哪些函数上」，开销小可常开；trace 是事件记录，回答「某一段时间内调度器发生了什么」，开销大，适合短时抓取分析延迟抖动。

线上该不该常开 pprof 端口？

可以常开，但要限制访问范围：只监听内网、或通过独立的管控端口、加鉴权。它提供的排查价值很高，风险在于暴露内部信息与被滥用抓取。

有了监控还需要日志吗？

需要。监控告诉你「有问题」，但无法告诉你「具体是哪个请求、什么参数、走了哪条分支」。日志提供个体视角，指标提供群体视角，两者不可互相替代。
