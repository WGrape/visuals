Transformer 架构

三种架构范式：BERT / GPT / T5 怎么选

Encoder-only（BERT）、Decoder-only（GPT）、Encoder-Decoder（T5）本质区别在「注意力能看到多远」和「要不要生成」。本文用掩码图讲清，并解释为什么 LLM 时代 Decoder-only 胜出。

一句话回答

三种范式由注意力掩码决定：Encoder-only 双向看全句（理解型）、Decoder-only 只能看过去（生成型）、Encoder-Decoder 编码器双向 + 解码器因果 + cross-attention（Seq2Seq）。LLM 时代 Decoder-only 几乎通吃。

Encoder-only（BERT 系）

双向自注意力：每个 token 能看前后所有 token。适合「给一段文本，抽信息」的理解型任务。

擅长：分类、NER、抽取式问答、语义相似度、检索召回。
代表：BERT、RoBERTa、DeBERTa。
不擅长：自由生成（它没有「续写」的训练目标）。

Decoder-only（GPT 系）

因果注意力（causal mask）：位置 i 只能看 ≤ i 的 token，看不到未来。天然适配「自回归生成」——这正是 LLM 的本职。

擅长：文本生成、对话、代码、推理、Few-shot/ICL/CoT 全建立在这之上。
代表：GPT 系列、Llama、Qwen、DeepSeek、Claude、Gemini。

Encoder-Decoder（T5/BART 系）

编码器双向理解源文本，解码器因果生成，两者通过 cross-attention 连接（解码器 query 去查编码器输出）。适合「输入一段、输出一段」的转化任务。

擅长：翻译、摘要、改写、问答生成。
代表：T5、BART、mT5、FLAN-T5。

注意力掩码对比

为什么 LLM 时代 Decoder-only 胜出

  • 生成统一：对话/代码/推理全是「续写」，Decoder-only 天生适配，不必为每种任务切换结构。
  • Scaling 友好：单一目标（next-token）最简单，海量文本直接训，规模上去能力涌现。
  • KV Cache 简单：因果掩码下缓存天然有序，配合 GQA/FlashAttention 高效。
  • ICL/CoT 载体：Few-shot、思维链都依赖「在上下文里续写」，只有 Decoder-only 顺。Encoder-Decoder 的 cross-attn 在这些范式上反而别扭。
理解型任务（如检索召回、分类）仍常用 BERT 类小模型，便宜又快；但「通用对话大模型」几乎全是 Decoder-only。

对比与选型

范式注意力强项代表选型建议
Encoder-only双向理解/抽取BERT分类、NER、召回
Decoder-only因果生成/通用GPT/Llama对话/代码/推理（默认）
Encoder-Decoder双向+因果+crossSeq2SeqT5/BART翻译/摘要/改写

总结

  • 范式差异 = 注意力掩码差异 = 能看多远。
  • BERT 理解强、GPT 生成强、T5 转化强。
  • LLM 时代 Decoder-only 因生成统一、易 scaling、KV 简单而胜出。

三种范式，本质是「谁能看见谁」

Transformer 家族看起来有很多成员，但从信息流的角度看，只有三种结构。它们的差别可以用一句话概括：每个位置能看见哪些其它位置。

注意力可见范围的三种约束

对照表：能力边界与典型用途

范式可见性预训练目标最擅长不擅长
Encoder-only双向（无掩码）掩码预测 / 对比学习分类、序列标注、句向量、检索召回开放式生成
Decoder-only因果（下三角）下一个 token 预测生成、对话、代码、多轮任务需要在同等成本下同时做双向理解时略吃亏
Encoder-Decoder编码器双向 + 解码器因果 + 交叉注意力带噪声重建 / 序列到序列翻译、摘要、结构化改写等有条件生成参数与推理成本偏高，通用对话生态较弱

一个容易混淆的点：Encoder-only 模型也能「输出文本」，比如在填空任务里给出被遮住的词。但它缺乏自回归结构，不适合逐 token 连续生成；反过来 Decoder-only 也能做分类（给它一个 prompt，看它输出什么标签），只是在同等规模与训练成本下，专门的双向量编码器通常在「句向量质量 / 检索召回」上更划算。

工程上怎么选

要做语义检索/RAG 召回优先选专门的句向量模型（通常基于 Encoder-only 思路训练），向量质量与吞吐都更好。
要做生成Decoder-only。目前生态、工具链、量化推理支持都最完善。
要翻译/摘要这类输入输出明确对应Encoder-Decoder 依然有优势，尤其是对低资源语言或长度受限的场景。
要一套模型干所有事Decoder-only。把任务改写成「接着写」的统一形态，工程复杂度最低。

关于 KV Cache 的一个实际差别：Decoder-only 因为严格因果，前缀相同就能完全复用缓存，这使得多轮对话、批量前缀（prompt cache）非常高效。Encoder-Decoder 中虽然解码器也能缓存，但交叉注意力部分与编码器输出强绑定，工程优化的空间与工具链成熟度都不如前者。这是今天大模型产品几乎清一色 Decoder-only 的重要工程原因，而不只是效果原因。

深入自检

为什么 Decoder-only 训练目标「更简单」反而是优势？

因为它的目标函数直接对齐「预测下一个 token」，不需要构造任何人为任务（比如随机遮盖比例是多少、替换哪些片段）。这意味着：全部 tokens 都能参与损失计算，数据利用率高；目标统一使得不同数据源可无差别混合；损失是所有 NLP 任务的自然下界（语言建模）。因此在海量数据、超大算力下，它最容易把规模优势吃到极致。

双向注意力不是信息更多吗，为什么生成模型不用？

训练阶段双向确实信息更多，但会带来训练与推理的不一致：生成时右边的词还不存在，模型没法看。若强行用双向训练去做自回归任务，模型会学到依赖未来 token 的模式，推理时性能塌陷。Decoder-only 的因果掩码虽然「少看一半」，但保证了训练与推理的分布完全一致。

交叉注意力在干什么？

它是编码器与解码器之间的桥桥：解码器每生成一个 token 时，除了看自己已生成的部分（因果自注意力），还通过交叉注意力去「查询」编码器输出的那份输入表示，从而把源文信息引入当前步的预测。这是序列到序列任务里最有代表性的机制。

多模态模型常见的是哪种结构？

多数是 Decoder-only + 输入侧投影：图像/音频先由各自的编码器变成一串向量，通过一个投影层对齐到语言模型的嵌入空间，然后拼在文本 token 前面，整体当作「接着写」处理。这样做的好处是复用成熟的 LLM 训练与推理栈，代价是长序列下的显存与注意力开销较大。
