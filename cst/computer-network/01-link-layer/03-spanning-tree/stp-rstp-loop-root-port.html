交换环路、STP 与 RSTP：三台交换机为什么不能随便成环

用三角形拓扑推演广播风暴、根桥选举、阻塞端口和链路故障后的恢复。

二层环路为何危险

三台交换机 S1、S2、S3 两两相连形成三角形，主机 A 发出一个 ARP 广播。交换机通常会把广播复制到同一 VLAN 的其他端口；帧从 S1 到 S2、S3，又可能沿另一边返回 S1。以太网帧没有像 IP TTL 那样的逐跳寿命字段，环路里的副本可继续循环并扩增，占满链路和交换机处理能力。源 MAC 还会在不同端口反复出现，MAC 表不停抖动，普通单播也可能被错送。

不能把“广播风暴”只理解为网络里广播太多。未知单播和某些组播也可能在环路中被复制。排查现象包括链路接近满速、接口广播计数激增、MAC 地址漂移、CPU 升高和管理连接不稳定。此时随意再插一根冗余线，可能让故障更严重。

生成树的基本目标

STP 允许物理连接保留冗余，却让每个 VLAN 或实例的活动二层转发路径在逻辑上没有环。交换机交换 BPDU 以确定根桥，再为非根桥选择通往根桥的最佳根端口，并为每段链路确定指定端口；剩余会造成环路的端口不参与普通数据转发。根桥选择通常先比较 Bridge ID 中的优先级和 MAC 等字段，配置更低的有效优先级可影响选举。

“阻塞”不是把物理线拔掉：控制信息仍可能用于维护拓扑。根桥也不必然是业务流量最多的设备，但根桥位置会影响路径，应按网络设计显式规划，而非任由偶然的 MAC 地址决定。不同生成树变体对实例、VLAN 映射和收敛机制有差别，配置时要看设备实现。

逐步推演

出现环路

一个 ARP 广播被复制后沿三角形反复返回。

选根桥

BPDU 比较 Bridge ID，假设 S1 获胜。

形成树

S2、S3 选根端口，冗余一侧停止普通转发。

故障切换

主链路断开，备用端口参与转发并重新学习。

手推三角形拓扑

假设 S1 被选为根桥，S2 和 S3 各有一条直连 S1 的低成本路径。S2、S3 朝 S1 的端口成为根端口；S2 与 S3 之间的链路只保留一侧作为该网段指定端口，另一侧成为备用或丢弃数据的角色。于是 A 的广播从 S1 出发可到达 S2 与 S3，但不会沿 S2—S3—S1 绕回来。精确哪一侧被选中还受路径成本、桥 ID 和端口 ID 的比较影响。

若 S1—S3 链路断开，原先的备用路径可参与转发，让 S3 通过 S2 到根桥。恢复时间取决于 STP/RSTP 版本、拓扑角色、邻接状态及设备配置。不要只记“生成树会自动恢复”，还要量测业务中断时间和 MAC 表重新学习过程。

RSTP 与收敛

经典 STP 的端口状态转换可能较慢；RSTP 使用更明确的端口角色、点对点协商和快速切换机制，在合适拓扑下可更快收敛。快并不代表零丢包，连接重选期间仍可能有短暂丢帧和 MAC 表变化。边缘端口接终端时可快速进入转发，但必须避免把连接其他交换机的端口误当作边缘端口，否则可能绕过必要的环路防护。

BPDU Guard 等保护可在边缘端口收到 BPDU 时采取阻断动作，防止用户私接交换设备改变拓扑。具体行为和恢复方式依设备配置，生产前要演练。链路聚合把多条物理线视作逻辑连接，是另一种冗余和增带宽手段，不可把多根平行线简单当作免环路的理由。

观察与排障

先定位哪个 VLAN 或实例出现问题，查看根桥 ID、各交换机根端口、指定端口和被丢弃端口。对照实际物理拓扑，检查是否有未登记的新线、端口误配为边缘、BPDU 被过滤或链路聚合两端配置不一致。MAC 表中同一 MAC 在端口间高频漂移，是追踪环路的线索，但虚拟机迁移也会造成短暂漂移，需看持续时间和广播量。

有环路风险时优先按既定应急方案隔离可疑链路，保留日志与接口计数，然后恢复稳定拓扑。修复后要测试单点链路故障与回切，确认备份路径确实启用且收敛时间符合业务容忍度。只看拓扑图“还有一条线”不能证明它能承载目标 VLAN。

与三层环路的区别

IP 层的错误路由也会形成循环，但 IP TTL/Hop Limit 会在每跳减少，最终丢弃；二层广播帧没有同等机制。路由协议、最长前缀和生成树处理的是不同层的环路。大规模网络常通过三层边界缩小二层广播域，减少生成树故障范围，但跨网段通信需要路由与访问控制。

自检

二层环路为什么比普通 IP 路由环路更容易形成广播风暴？

以太网广播帧没有 IP TTL 那样的逐跳寿命，交换机又会在广播域内复制帧，环路可使副本持续增长。
