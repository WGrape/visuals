Temperature 温度：控制随机性的总开关

同一个模型，为什么有时回答一板一眼、有时天马行空？温度是所有采样参数里最核心的一个。

定位

温度是加在 softmax 之前的"锐化旋钮"

模型每一步输出的是整个词表上的概率分布。温度（Temperature）在 softmax 之前把 logits 除以 T：分布不变时，T 决定了"选词时的犹豫程度"——T 越小分布越尖（确定性），T 越大分布越平（多样性）。

公式

一行公式说清楚

P(token_i) = exp(logit_i / T) / Σ_j exp(logit_j / T)

T → 0⁺ : 分布趋于 one-hot，等价贪心解码（argmax）
T = 1  : 原始 softmax 分布，模型"本色"
T > 1  : 低概率词被抬升，长尾被放大，输出更发散
直觉：logits 差距是固定的，除以 T 就是"把差距缩小或放大"。T=0.5 把差距放大一倍，弱者更难翻身；T=2 把差距减半，冷门词也有机会。
实践

常见取值参考

场景建议 T理由
代码生成 / SQL / 数学0 ~ 0.3答案基本唯一，错误代价高
结构化抽取 / 分类0 ~ 0.2要的是稳定可解析
客服问答 / RAG 引用0.3 ~ 0.7稳定为主，稍留自然度
通用对话0.7 ~ 1.0平衡连贯与自然
创意写作 / 头脑风暴0.9 ~ 1.2鼓励低概率表达
配合

与 Top-K / Top-P 的分工

温度管"形状"
重塑整个分布的平坦程度，作用于所有候选词
Top-K / Top-P 管"截断"
先把长尾候选砍掉，防止低质量词被采到
常见顺序
先截断（top-k → top-p），再在剩余候选上做温度缩放采样
误区

两个高频误区

T=0 并不保证完全确定：GPU 浮点非结合性、batch 内并行、MoE 路由抖动都会带来微小数值差异，T=0 时这些差异会被 argmax 放大成不同的输出。想要更稳，可固定 seed 并关掉部分并发优化。
温度不是"创造力"旋钮：T 太高输出的是胡言乱语（采样到不通顺词），不是创意。创意来自模型本身的能力 + 好提示词，温度只是放大或收敛分布。
面试问答

高频问题

Q1：温度的数学本质是什么？
softmax 前 logits 除以 T。T<1 放大 logits 差距使分布更尖（趋近 argmax），T>1 缩小差距使分布更平（更随机）。它不改变候选集合，只改变分布形状。
Q2：T=0 和贪心解码是什么关系？
T→0 时 softmax 退化为 one-hot，采样等价于 argmax，即贪心解码。但注意浮点数值抖动可能让 T=0 也不完全可复现。
Q3：温度和 top-p 冲突吗？先调哪个？
不冲突，作用维度不同：截断（top-k/top-p）决定候选范围，温度决定范围内的随机度。官方建议避免同时大幅调整；实践中常见组合是固定 top-p=0.9，按任务调温度。
Q4：为什么代码任务建议低温度？
代码的正确答案空间小、语法约束强，低概率候选几乎都是错的；低温让输出集中在高置信度 token 上，提高语法与逻辑正确率。
Q5：温度越高模型越聪明吗？
不是。温度不改变模型能力，只改变采样随机性；过高反而放大错误、破坏语法。能力由模型与提示决定，温度只影响"从分布里怎么挑"。
