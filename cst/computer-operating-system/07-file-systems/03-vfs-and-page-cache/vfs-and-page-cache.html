01VFS 抽象与四大对象

第一层

概念与判定

VFS（Virtual File System）是内核里的一层统一文件抽象：上层应用用同一套 open/read/write/close，下层可以是 ext4、XFS、tmpfs、甚至网络文件系统。应用不关心底层是什么。

图：VFS 屏蔽底层差异，页缓存把文件读写落到内存。
VFS 四对象含义
super_block一个已挂载文件系统的全局信息
inode一个文件的元数据（权限/大小/数据块位置）
dentry目录项缓存：路径成分→inode 的解析结果（加速查找）
file一次打开的「打开文件描述」(fd 背后)，含偏移
页缓存（Page Cache）是性能核心：文件读先查页缓存，命中就免磁盘；写通常先写缓存（write-back），由内核后台刷盘。所以「内存越大，文件缓存越多，I/O 越快」。

02缓存命中与回收

第二层

参数·命令·量化

缓存命中与回收

命令看什么
free -hbuff/cache 即页缓存占用
cachestat（perf-tools）每列命中/未命中速率
vmtouch某文件是否已缓存、预热
/proc/sys/vm/dirty_*脏页回写阈值
# 脏页回写：超过比例 / 字节就后台写回
cat /proc/sys/vm/dirty_background_ratio   # 默认 10%
cat /proc/sys/vm/dirty_ratio            # 默认 20%（应用写阻塞阈值）
cat /proc/sys/vm/dirty_expire_centisecs # 脏页最长停留

# 手动清缓存（测试用，生产慎用）
sync; echo 3 > /proc/sys/vm/drop_caches

# 看某进程用了多少文件缓存
vmtouch -v /path/to/bigfile
drop_caches 生产慎用：清掉页缓存后，所有文件读都打磁盘，可能造成瞬间 IO 风暴、延迟飙升。只用于 Benchmark 隔离。

03排障与边界

第三层

排障与边界

  • 缓存命中率低：大文件顺序扫描（如备份）会冲掉热点缓存。用 fadvise(DONTNEED) 或 posix_fadvise 提示内核别缓存。
  • 脏页堆积导致写阻塞：写超过 dirty_ratio 时，应用写会被强制同步刷盘，表现为偶发卡顿。调大或限速可缓解。
  • O_DIRECT：绕过页缓存直接读写磁盘，常用于数据库自管缓存；但要求对齐（块大小/偏移），否则报错。
  • dentry 缓存：海量小文件场景下 dentry 占用大量内存，slabtop 可见。
  • mmap 与页缓存共享同一份：多个进程 mmap 同一文件共享缓存，省内存；但写冲突要自己用文件锁。

04原理与取舍

第四层

原理与取舍

页缓存是「用内存换 IO」的典型：几乎所有文件读都走它，写默认延迟刷盘。代价是掉电可能丢脏数据、以及缓存与内存管理的耦合（缓存占满会触发回收，挤占匿名页）。

设计收益代价
页缓存读极快、写合并脏数据掉电风险
回写延迟吞吐高fsync 才有持久性
O_DIRECT自管缓存、可预测需对齐、失去缓存红利
dentry 缓存路径解析快占 slab 内存

深入 Q&A

Q：write 返回成功后数据还在磁盘上吗？
A：不一定。默认只是进了页缓存（脏页），真正落盘由回写线程异步完成。要保证持久，必须 fsync/fdatasync 或 O_SYNC。

Q：为什么 free 显示 available 比 free 大很多？
A：available 把可回收的页缓存也算作「可用」，所以系统「看起来内存少」往往是缓存多，并非真紧张。
