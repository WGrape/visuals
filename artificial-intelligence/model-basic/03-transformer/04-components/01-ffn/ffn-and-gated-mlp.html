04 · 组件拆解

前馈层 FFN：把「通道」搅一遍的那 2/3 参数

Transformer 里注意力负责 token 之间交换信息，FFN 负责在每个 token 内部做非线性变换。它占掉 65%~80% 的参数和约 2/3 的单 token 计算，是现代 LLM 里最贵、也最容易被换掉的一块。

一句话定位：注意力混 token，FFN 混通道

把残差流想成一条宽度为 d 的传送带：注意力从别的 token 往传送带上取东西（token mixing），FFN 则在当前 token 的位置上把 d 个数值重新组合一遍（channel mixing）。两者交替，缺一不可。

注意力干什么对每个位置，从序列里其它位置加权取信息，输出仍回到 d 维
FFN 干什么对每个位置独立地做「升维 → 非线性 → 降维」，不跨 token
为什么必须升维在更高维空间里做非线性组合，表达力更强；等价于一个 key-value 记忆
在块里的位置Norm → Attention → 残差 → Norm → FFN → 残差（Pre-LN）
一个判断技巧

看到「逐位置、不跨 token」的算子基本都是 FFN；看到「跨位置加权」的就是注意力。位置编码、归一化、残差都属于「旁路」，不改变这个分工。

尺寸与参数账：d_ff 是怎么定出来的

标准 FFN 是两个线性层夹一个激活：FFN(x) = W_down · act(W_up · x)，中间的 d_ff 一般是 4d；SwiGLU 这类门控结构多一个矩阵，于是把 d_ff 压到约 8d/3（向上取到 256 的倍数），让参数量与原版持平。

以 LLaMA-3 8B 为例：3 × 4096 × 14336 = 176.2M／层，32 层共 5.64B；注意力（GQA，n_kv=8）只有 4096×(4096+1024+1024)+4096×4096 = 41.9M／层，共 1.34B；embedding 0.53B。合计 7.5B，与标称 8B 对得上。

FFN 是参数大头：换 GQA、砍头数都动不了它，只有换 MoE 或改 d_ff 才动得了

门控变体：为什么现代 LLM 都用 SwiGLU

激活函数本身在另一篇讲，这里只看「结构」。门控 FFN 用两个上投影相乘，让网络可以自己学一个逐元素的开关：

# 原版（Transformer / BERT） h = W_down( gelu( W_up(x) ) ) # 2 个矩阵 # GLU 家族（PaLM 用 SwiGLU，LLaMA/Qwen/Mistral 全用 SwiGLU） g = silu( W_gate(x) ) # 门：0~1 的软开关 u = W_up(x) # 值 h = W_down( g * u ) # 3 个矩阵 # silu(x) = x * sigmoid(x)，无上界、有小负区，比 ReLU 平滑
结构公式矩阵数相对效果谁在用
ReLU FFNW2·relu(W1x)2基线原版 Transformer
GELU FFNW2·gelu(W1x)2略好于 ReLUBERT / GPT-2 / GPT-3
SwiGLUW2·(silu(Wg x) ⊙ Wu x)3同参数量下最优（PaLM 论文实测）LLaMA / Qwen / Mistral / Gemma
GeGLUW2·(gelu(Wg x) ⊙ Wu x)3与 SwiGLU 接近T5 v1.1 / 部分 ViT
别把 d_ff 照抄

换成 3 矩阵结构后如果还沿用 4d，参数会涨 50%。正确做法是取 d_ff ≈ 8d/3 再向上取整到 256 的倍数，这就是 11008、14336、18944 这些奇怪数字的来历。

计算与显存：中间激活比权重更容易撑爆

单 token 前向 FLOPs ≈ 2 × 参数量。FFN 每 token 约 2 × 3 × 4096 × 14336 ≈ 352 MFLOPs，注意力（4K 上下文）约 151 MFLOPs——FFN 仍是第一大头。

FFN 单 token FLOPs2 × 3·d·d_ff352 MFLOPs
FFN 权重显存（bf16）参数量 × 2B5.64B × 2B ≈ 11.3 GB
FFN 中间激活（bf16）batch·seq·d_ff·2B（×2 若存 gate 与 up）1×4096×14336×2B ≈ 117 MB／层
训练不重算时的激活总量上者 × 层数 × 2≈ 7.5 GB（这就是为什么需要 activation checkpointing）
推理时不用慌

推理只在当前层保留 gate/up 的中间结果，峰值就是 117MB 量级；真正吃内存的是权重（11GB）和 KV Cache。端侧部署时 FFN 权重的读取量决定了出词速度，这也是低比特量化对 FFN 收益最大的原因。

工程实现：融合、切分、量化三个动作

  1. 融合 gate 与 up：把 W_gate 和 W_up 沿输出维拼成一个 d → 2·d_ff 的矩阵，一次 GEMM 算完再 split，能少一次 kernel 启动和一次读 x（decode 阶段带宽受限，收益明显）。
  2. 张量并行切 d_ff：两个上投影按列切、下投影按行切，中间不通信，只在 down 之后做一次 all-reduce；d_ff 不能被 TP 度整除时要 padding，padding 部分必须在激活后置零否则污染结果。
  3. 量化优先动 FFN：FFN 占权重 3/4，把它压到 4bit 收益最大；实测 FFN 对量化比注意力更宽容（注意力里的 QK 对精度更敏感）。

原理与取舍：FFN 到底在存什么

把 FFN 看成 key-value 记忆：第一层把输入映射到 d_ff 个「键」，激活函数决定哪些键被命中，第二层把命中的「值」加权写回。d_ff 就是记忆槽位的数量——这解释了为什么加大 d_ff 比加宽注意力更能提升知识容量，也解释了 Mixtral / DeepSeek 把 FFN 拆成多个专家后总参数暴涨但计算量不变。

为什么 FFN 要升维再降维，不能直接 d→d？

两层 d→d 的线性变换等价于一个 d→d 矩阵，加非线性后也只是秩受限的非线性映射。升到 4d 才让「每个 token 有 4d 个特征槽」这件事成立，表达力和记忆容量都来自这个中间宽度。

注意力已经让 token 互相看过，FFN 还有必要吗？

有。注意力是线性加权（值向量按权重相加），本质是凸组合，做不了「与、或、条件」这类非线性组合。FFN 才是逐位置做非线性决策的地方，去掉它模型会退化成加权平均。

MoE 是把 FFN 换掉还是加一层？

换掉。MoE 的每个专家就是一个独立 FFN，路由器为每个 token 选 top-k 个专家，只算被选中的那些，所以总参数（所有专家）大、单 token 计算量（k 个专家）小。

为什么 LLaMA 的 d_ff 是 14336 这种数字？

8d/3 = 10922.7，向上取到 256 的倍数得 11008（LLaMA-2 用 2/3×4d 的另一套算法），LLaMA-3 提升到 3.5d 左右再对齐到 256，于是 14336。对齐的目的是让 GPU 的 tile 和 TP 切分整除。
