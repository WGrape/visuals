JVM GC 调优实战：参数、日志与排障

先量后调：-Xmx 给够，再选回收器，再设停顿目标

JVMGC调优参数日志排障
① 关键参数 ② GC 日志 ③ 读日志 ④ 场景 ⑤ 排障 ⑥ 疑问
一句话：GC 调优顺序是「先给够堆（-Xmx）→ 选回收器 → 设停顿目标 → 看日志验证」，不要一上来就调一堆旋钮。

01关键参数

参数含义建议
-Xms / -Xmx初始/最大堆设相等避免动态扩缩；按存活对象×3~4 估
-Xss线程栈默认 1MB；线程多可降到 256k~512k
-XX:NewRatio老年代:新生代默认 2；吞吐型可加大老年代
-XX:+UseG1GC选 G1JDK9+ 默认
-XX:MaxGCPauseMillisG1 停顿目标如 200ms，过激增 CPU
-XX:+UseZGC选 ZGC大堆低延迟
-XX:MaxMetaspaceSize元空间上限防类加载泄漏撑爆
-XX:MaxDirectMemorySize堆外上限Direct Buffer 上限

02开启 GC 日志

# JDK9+ 统一日志：把 GC 日志写到文件，含停顿/吞吐
java -Xlog:gc*:file=gc.log:time,uptime,level,tags:filecount=5,filesize=100M \
     -XX:+UseG1GC -Xmx4g -jar app.jar

# 老版本（-Xloggc 风格）
# -Xloggc:gc.log -XX:+PrintGCDetails -XX:+PrintGCDateStamps

03怎么读日志

  • 看吞吐量：非 GC 时间占比，目标 > 95%（即 GC 占比 < 5%）。
  • 看停顿：单次 STW 时长是否超 SLA；G1 看 “Pause young/mixed” 时长。
  • 看晋升：Promotion failed / 老年代增长过快 = 新生代太小或对象过早晋升。
  • 看并发失败：CMS/ZGC 出现 “concurrent mode failure” = 回收跟不上分配。

04典型场景

场景方向
延迟敏感（API）G1/ZGC + 设 MaxGCPauseMillis；减小 -Xmn 让 Minor 快
吞吐优先（批处理）Parallel；给大堆少 GC
元空间 OOM加 -XX:MaxMetaspaceSize，查类加载泄漏
GC 停顿超 SLA先查对象存活率（是否缓存泄漏），再调回收器/并发线程
堆外 OOM降 -XX:MaxDirectMemorySize 或排查 Buffer 未释放

05排障工具清单

  • jstat -gcutil <pid> 1000：实时看各代占用与 GC 次数/时间。
  • jmap -histo:live <pid>：按类看对象数/占用，定位大对象。
  • jmap -dump:live,format=b,file=heap.hprof <pid>：堆转储，MAT 分析泄漏。
  • jstack <pid>：线程栈，定位 STW 期间卡在哪。
  • jcmd GC.heap_dump / VM.native_memory：堆/本地内存诊断。

06常见疑问

问：GC 停顿突然变长？

先看是否大对象分配或一次性堆暴涨；再查并发是否被关闭；ZGC 停顿与堆大小基本无关，若变长常是系统页回收/日志干扰，需结合指标看。

问：是不是该把 -Xmx 调小？

不一定。堆太小会频繁 GC、每次更快但总开销更高；先按存活对象×3~4 给够，再谈调优。
