最小生成树

怎样用最少的「线」把一群点连成一张连通网，且总长度最小？这就是最小生成树（MST）的故事。

一、什么是生成树与最小生成树

在一张连通无向图里，生成树是选出一个包含所有 V 个节点、恰好 V−1 条边、且没有环的子图——它把整张网连起来，又不浪费任何一圈冗余连线。

最小生成树（MST）则是所有生成树中，边权之和最小的那一棵。类比：把若干栋楼接入局域网，布线要连通又不能成环（否则广播风暴），还要总长度最短、最省钱。

示例图（无向带权）。本页演示的 MST 边为 A-C(2)、D-E(2)、E-F(3)、A-B(4)、B-D(5)，总权 16。

二、Kruskal：贪心选边 + 并查集

Kruskal 的思路像「铺路工」：先把所有边按权值从小到大排序，然后依次尝试加入——只要这条边不会和已选边构成环就保留，否则丢弃。判断是否成环靠并查集（Union-Find）：两节点若已在同一连通块，再加边必成环。

def kruskal(edges, V):
    edges.sort(key=lambda e: e.w)     # 边按权升序
    uf = UnionFind(V)
    mst = []
    for u, v, w in edges:
        if uf.find(u) != uf.find(v):  # 不在同一连通块
            uf.union(u, v)
            mst.append((u, v, w))
    return mst

交互演示：点击「下一步」，逐条考察排序后的边。绿色表示选入 MST，红色虚线表示会成环被跳过。

准备开始：边已按权值排序。

三、Prim：从一点长出的树

Prim 是另一种贪心：先随便选一个起点，把它「种」进树里，之后每一步都从树外节点里挑一条连到树内代价最小的跨界边，把新节点接进来。用最小堆维护候选边，效率很高。它和 Kruskal 殊途同归——都依赖 MST 的两条性质。

切割性质

把节点分成两堆（一个切割），跨越切割的最短边必属于某个 MST。这是贪心的正确性根基。

环性质

任意一个环里最长的边一定不属于任何 MST，因为它可被环上更短的边替代。

第三层 · 排障与边界：MST 的坑

坑后果正确做法
图不连通却求 MST得到的是森林不是树先判连通性；不连通要按连通分量分别求
并查集没做路径压缩/按秩合并退化，常数变大两个优化都要做，才接近 O(1)
Kruskal 忘了判断成环结果不是树union 返回 False 就跳过该边
Prim 忘了判 visited重复入树，结果错弹出后立即检查并标记

  • 排查顺序：先确认图连通 → 再确认并查集有压缩 → 再确认 MST 边数 = V-1 → 最后用切分性质验证。
  • 边界一：MST 的边数一定是 V-1；如果不是，说明图不连通或实现有误。
  • 边界二：Kruskal 与 Prim 的结果总权重相同（都是最优），但具体选的边可能不同（边权有相等时）。
  • 边界三：MST 可以处理负权边，这与 Dijkstra（要求非负）不同——因为 MST 不累加路径，只挑边的集合。

MST 和最短路径有什么区别？

MST 最小化「连接所有点的总边权」（得到一棵树）；最短路径最小化「两点之间的一条路径」。目标完全不同：MST 关心整体连通代价，最短路关心单点对。

为什么 Kruskal 用并查集而 Prim 用堆？

Kruskal 按边考虑，需要快速判断「两端是否已连通」→ 并查集。Prim 按点扩展，需要快速取「离当前树最近的顶点」→ 优先队列。数据结构由算法的扩张方式决定。

边权相同时 MST 唯一吗？

不唯一，但总权重唯一。当所有边权互不相同时，MST 才是唯一的。所以验证 MST 时要比总权重，不要比具体的边集。

用最少的代价把所有人连起来

要在 n 个城市之间修路/架网络，让任意两点都能互通，且总成本最低——这就是最小生成树（MST）。结论很优美：只需选 n-1 条边（不能有环），且可以用贪心策略高效求解。两个经典算法：Kruskal（按边排序 + 并查集）和 Prim（从点出发逐步扩张）。

并查集：Kruskal 的左膀右臂

① 并查集的两个优化

  • 路径压缩：find 时把路径上所有节点直接挂到根下。
  • 按秩/按大小合并：小树挂到大树下，避免树退化成链。
  • 两者同时使用后，单次操作近似 O(1)（反阿克曼函数）。
  • 这也是「看似简单的数据结构，优化后性能差异巨大」的典范。

② Kruskal 的执行流程

  • 把所有边按权重升序排序。
  • 依次考察每条边：若两端点不在同一集合（不成环），选中并合并集合。
  • 选满 n-1 条边即结束。
  • 正确性由切分定理保证：不选这条最小边，一定可以用它替换掉环上更大的边得到更优解。

③ 典型应用

  • 网络/道路/管道的最小成本铺设方案。
  • 聚类：把「距离」当边权，构建 MST 后砍掉最大的 k-1 条边得到 k 个簇。
  • 电路布线、通信基站组网。
  • 图像分割（把像素当点、相似度当边权）。
  • 近似算法：旅行商问题（TSP）的一个 2 倍近似可由 MST 得到。

④ 常见误区

  • 误以为 MST 是「任意两点间最短路径」—— 那是 shortest path，MST 优化的是总边权。
  • 忽略图不连通的情况：此时得到的是最小生成森林。
  • 忽略负权边：MST 允许负权，算法依然成立（与最短路不同）。
  • 以为 MST 唯一：边权相同时可能有多棵，但总权重一定相同。

深入自检

为什么最小生成树一定只有 n-1 条边？

因为树的定义就是「连通且无环」：连通 n 个点至少需要 n-1 条边，而多于 n-1 条必然产生环。有环就可以去掉环上一条边、权重更小且仍连通，所以最小解一定无环，边数恰为 n-1。

Kruskal 为什么是对的？

由切分定理：把顶点分成「已连通的部分」与其余部分，跨越这个切分的最小边，必然属于某棵 MST。Kruskal 每次选的正是这样的边（当前最小且不产生环），因此可以用「交换论证」证明最终得到的就是 MST。

Prim 和 Dijkstra 看起来很像，区别在哪？

更新规则不同：Dijkstra 更新的是「从源点到该点的最短距离（累加）」，Prim 更新的是「该点连到已选集合的最小边权（单边）」。前者求单点最短路径，后者求全局最小连通代价。两者都用优先队列，容易混淆，但语义完全不同。

有负权边时 MST 还能求吗？

可以。Kruskal 与 Prim 都不要求边权非负，它们的正确性不依赖「路径越长越差」的性质。这与 Bellman-Ford/Dijkstra 不同——最短路问题里负权（尤其负环）会带来根本性困难。

如何用 MST 做聚类？

把所有样本两两连边、权重为距离，求 MST，然后砍掉最长的 k-1 条边，就自然分成 k 个连通分量。这叫「单链接聚类的 MST 等价形式」，好处是实现简单、能发现非凸形状的簇，但对噪声敏感（易形成链式簇）。

MST 能解决旅行商问题吗？

不能精确解决（TSP 是 NP-hard），但可以做近似：先求 MST，再对其做前序遍历并跳过重复点，在满足三角不等式时得到不超过最优解 2 倍的近似；用 Christofides 算法可改进到 1.5 倍近似。这是近似算法里非常经典的构造。
