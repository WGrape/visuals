01抖动与工作集

第一层

概念与判定

抖动（thrashing）：进程的工作集大于可用物理页，导致频繁缺页换入换出，CPU 大量时间耗在等 IO，真正计算的时间趋近于零。

图：随着分配页数增加，CPU 先升后降。下降段就是抖动。
概念定义
工作集（working set）进程在最近一个时间窗口 W 内实际访问过的页集合
驻留集当前在物理内存里的页集合
缺页率每秒缺页次数，抖动时急剧上升
工作集模型的核心思想：用「最近访问过什么」预测「接下来需要什么」。若分配给进程的页数 < 工作集大小，就必然抖动。

Linux 的回收水位

水位含义行为
min最低保留低于此值，只有内核可分配（不回收）
low低水位低于此值，kswapd 开始后台回收

直接回收（direct reclaim）：内核在分配内存时发现低于 min 水位，会让申请者自己去回收，表现为进程卡顿。看到 pgscan_direct 上升就要警惕。

03排障与边界

第三层

排障与边界

  • si/so 持续非零：正在换页，抖动前兆。若 so 很高且 CPU 不满，基本可以判定内存不足。
  • 缺页率与并发：盲目加并发会让抖动更严重（工作集总和超过物理内存）。应限制并发或加内存。
  • kswapd 打满 CPU：后台回收本身消耗 CPU，看 top 的 kswapd0。
  • 文件页 vs 匿名页：文件页可丢弃重读，匿名页要写 swap。没有 swap 时匿名页压力直接触发 OOM。
  • 工作集估算：/proc//smaps_rollup 的 Rss 是驻留，不等于工作集；可用 perf 或 page-types 工具采样。

04原理与取舍

第四层

原理与取舍

抖动是「局部性原理」被打破的表现：当工作集无法装进物理内存，每次访问都可能 miss，系统从「计算密集」退化为「IO 密集」。

手段效果代价
加内存最直接成本
降并发缩小总工作集吞吐下降
换更快的盘（NVMe）缺页延迟降低仍有 IO 开销
页面置换策略优化减少无效换出有限
工作集调度（WSClock）按工作集分配页实现复杂

深入 Q&A

Q：为什么加并发反而更慢？
A：每个线程有自己的工作集，线程数翻倍 → 总工作集翻倍 → 更快超过物理内存 → 抖动。这就是「并发不是越高越好」的内存侧解释。

Q：swap 能缓解抖动吗？
A：能推迟 OOM，但换页本身很慢（即使 NVMe 也比内存慢几个数量级）。swap 是「保命」不是「提速」。
