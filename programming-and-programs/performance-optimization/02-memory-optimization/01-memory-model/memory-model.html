内存模型与布局

虚拟内存、堆栈、对齐与缓存行——程序在内存里到底怎么摆。

虚拟内存解决了什么

用户进程看到的「虚拟地址空间」
MMU 页表：虚拟 → 物理
物理内存 / 磁盘 swap

虚拟内存让每个进程都以为自己独占整片内存，隔离了进程、支持了按需分页与 swap，也方便了共享库与地址随机化（ASLR）。

栈与堆的区别

维度栈堆
生命周期随函数进出自动管理手动或 GC 管理
速度极快（指针移动）较慢（分配/回收）
大小有限（易溢出）较大
碎片无可能产生

对象在内存里怎么排

对象通常含「对象头（类型指针、GC 标记、长度）+ 字段」。字段按声明与对齐规则排列，对齐填充（padding） 会悄悄吃掉内存。

缓存行与局部性

局部性就是性能

CPU 一次从内存取一个缓存行（通常 64 字节）。连续、紧凑、可预测的内存访问命中率高；随机跳转会让缓存反复失效，慢一个数量级。

问题 1
为什么要有虚拟内存？

隔离进程、简化编程模型（每个进程独立地址空间）、支持按需加载与 swap、提升安全性（ASLR）。没有它，程序得自己管理物理地址，且一个进程崩溃容易拖垮整个系统。

问题 2
栈和堆最根本的区别？

栈由编译器自动管理、随函数调用进出，速度极快但有大小上限；堆由程序员或 GC 管理、生命周期灵活但分配回收更慢且可能碎片化。

问题 3
结构体对齐填充会浪费内存吗？

会。为满足对齐，编译器在字段之间插入 padding；字段顺序不当会让同一结构多占几十字节。高频对象应按字段大小降序排列来压缩。

问题 4
为什么缓存行对齐对性能重要？

CPU 以缓存行为单位搬运数据。连续访问命中率高；跨缓存行或伪共享都会导致额外的总线同步，是隐藏的性能杀手。
