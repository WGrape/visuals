第 14 章 · 动态规划

一维数组里的遍历方向

01 背包倒序遍历保证每件只用一次，完全背包正序遍历允许重复取，多重背包用二进制拆分降到对数，三种问法对应不同初始化。

01 背包：每件只有一个，选或不选

容量 W，n 件物品，第 i 件重量 wi、价值 vi，每件只能用一次，求最大价值。

状态定义：dp[i][w] = 只考虑前 i 件、容量为 w 时的最大价值。转移就是第 i 件选还是不选：

dp[i][w] = max(dp[i-1][w],                    # 不选
              dp[i-1][w-wi] + vi)          # 选（需 w ≥ wi）

可以压缩成一维数组，但遍历顺序必须反过来：

def knapsack_01(W, wt, val):
    dp = [0] * (W + 1)
    for i in range(len(wt)):
        for w in range(W, wt[i] - 1, -1):   # 必须倒序！
            dp[w] = max(dp[w], dp[w - wt[i]] + val[i])
    return dp[W]

为什么必须倒序？倒序时 dp[w - wt[i]] 读到的是上一轮（i−1）的旧值，保证每件只用一次。若正序，dp[w - wt[i]] 可能已经在本轮被更新过，同一件物品会被反复装入——那就变成了完全背包。

复杂度 O(nW)，空间 O(W)。注意它是伪多项式：W 很大（如 10⁹）时即使 n 很小也跑不动。

完全背包：每件无限个，正序遍历

同一件可以取多次，转移变成 dp[i][w] = max(dp[i-1][w], dp[i][w-wi] + vi)——注意第二项用的是 dp[i] 而不是 dp[i−1]，正好对应一维数组下的正序遍历。

def knapsack_complete(W, wt, val):
    dp = [0] * (W + 1)
    for i in range(len(wt)):
        for w in range(wt[i], W + 1):   # 正序，允许重复取
            dp[w] = max(dp[w], dp[w - wt[i]] + val[i])
    return dp[W]

01 与完全背包的唯一代码差别就是内层循环方向。理解这一点比背模板重要：方向决定了你读到的是「上一轮」还是「本轮」的状态。

多重背包：二进制拆分降复杂度

第 i 件最多取 ci 个。朴素做法是把它展开成 ci 个独立物品跑 01 背包，复杂度 O(W·Σc)，c 大时不可行。

二进制拆分：把 c 拆成 1、2、4、…、2k 和余数，这些组能组合出 0~c 的任意个数，于是 c 件变成 log c 个「打包后的物品」，再跑 01 背包即可，复杂度降到 O(W·Σ log c)。

def knapsack_multi(W, wt, val, cnt):
    items = []
    for w, v, c in zip(wt, val, cnt):
        k = 1
        while k <= c:
            items.append((w * k, v * k)); c -= k; k *= 2
        if c: items.append((w * c, v * c))
    dp = [0] * (W + 1)
    for w, v in items:
        for cap in range(W, w - 1, -1):
            dp[cap] = max(dp[cap], dp[cap - w] + v)
    return dp[W]

三种变体与常见问法

问法改什么
最大价值dp 存价值，转移取 max（上面全是这种）
能否恰好装满dp 存布尔可行性，初始化只有 dp[0] = True
装满的方案数dp 存计数，转移改成累加；初始化 dp[0] = 1
输出具体选了哪些保留二维 dp，从 dp[n][W] 反推：若 dp[i][w] ≠ dp[i−1][w] 则选了第 i 件
二维费用（重量 + 体积）dp 开二维费用，两层倒序

「最大价值」和「恰好装满」的初始化不同：前者全部置 0（允许装不满），后者除 dp[0] 外全部置为不可达（-∞ 或 False）。混用会得出错误答案。

// 01 背包：容量必须倒序遍历（Go）
func knapsack01(w, v []int, C int) int {
	dp := make([]int, C+1)
	for i := range w {
		for c := C; c >= w[i]; c-- {   // 倒序：保证 dp[c-w[i]] 还没被本轮物品更新过
			if dp[c-w[i]]+v[i] > dp[c] {
				dp[c] = dp[c-w[i]] + v[i]
			}
		}
	}
	return dp[C]   // 含义：容量不超过 C 的最大价值（不是恰好装满）
}

// 完全背包：只改一个方向
func knapsackComplete(w, v []int, C int) int {
	dp := make([]int, C+1)
	for i := range w {
		for c := w[i]; c <= C; c++ {  // 正序：允许同一个物品被反复使用
			if dp[c-w[i]]+v[i] > dp[c] {
				dp[c] = dp[c-w[i]] + v[i]
			}
		}
	}
	return dp[C]
}

// 多重背包：二进制拆分，把 k 件拆成 1,2,4,... 份，退化成 01 背包
func split(k int) []int {
	var out []int
	for p := 1; k > 0; p <<= 1 {
		if p > k {
			p = k
		}
		out = append(out, p)
		k -= p
	}
	return out
}

// 恰好装满 vs 不超过：初始化不同
//   不超过：dp 全部初始化为 0
//   恰好装满：dp[0]=0，其余初始化为 -inf（不可达）
//   这是最容易写错也最难查的一点

空间优化为什么成立：二维 dp[i][c] 只用到上一行，所以可以压成一维；而遍历方向决定你读到的是「上一行」还是「本行已更新的值」，这正是 01 与完全背包的唯一差别。

第三层 · 六个高频错误与检查清单

  • 遍历方向写反：01 背包写成正序就变成完全背包，答案偏大且不报错 —— 这是最经典的坑。
  • 初始化混淆：0 初始化表示「容量不超过」，-∞ 表示「恰好装满」；两者答案不同。
  • 容量循环下界写错：01 背包应写到 c >= w[i]，写成 c >= 0 会越界。
  • 价值与容量维度搞反：「体积恰好为 j 的最小价值」这类变形要重新定义 dp 含义并改初始化。
  • 要输出方案却没记路径：一维优化后无法回溯；要输出方案就得保留二维或另存决策数组。
  • 复杂度误判：复杂度是 O(n × C)，不是 O(n)；当 C 很大（如 10^9）而 n 很小时，要换成按价值定义状态或搜索。
  • 检查清单：先写清 dp 定义 → 再定初始化 → 再定遍历方向与边界 → 最后用小样例手算验证。

调试技巧：打印整个 dp 数组，用小样例（3 个物品、容量 5）手算一遍对照。背包类错误的 90% 都能通过打印数组一眼看出来。

第四层 · 边界与变形

容量特别大（如 10^9）但物品很少，怎么办？

换状态定义：把「容量」和「价值」互换，定义 dp[价值] = 最小容量，复杂度变成 O(n × 总价值)，当价值范围远小于容量时可行；否则只能用搜索或近似。

背包和「可行性」问题怎么转换？

把求最大值改成布尔可达性：dp[c] = 是否能凑出容量 c，初始化 dp[0]=true，转移用或运算。这是判断子集和的标准做法。

为什么叫「背包」却总在考方案数？

因为求方案数只是把转移从 max 改成 求和，其余框架完全一样；这类题考的是同一套状态设计思路。

01 与完全背包只差一个遍历方向，方向决定你读到的是上一轮还是本轮。

01 背包倒序，完全背包正序。倒序保证每个物品只被用一次；正序允许同一物品被反复使用。这条规则覆盖了绝大多数背包变种。

五、深入自检

背包问题和贪心怎么区分？

分数背包（物品可切）可以用贪心按单位价值排序；01 背包不能贪心，因为「单位价值高」的物品可能刚好装不下，留下大量空隙。反例：容量 10，物品 A(6, 价值 7)、B(5, 6)、C(5, 6)，贪心选 A 得 7，最优是 B+C 得 12。

复杂度能再降吗？

O(nW) 已经是伪多项式——注意 W 是容量数值而不是输入长度。当 W 极大（比如 1e9）而 n 很小时，要换成按价值定义状态：dp[i][v] = 达到价值 v 所需的最小容量。

为什么叫伪多项式？

因为复杂度里含有输入数值 W，而输入长度是 log W。所以它不是真正的多项式时间，背包是 NP 完全问题，这一点恰恰体现在这里。

初始化为什么有的填 0 有的填 -inf？

取决于「不合法状态」的语义。求最大价值时，0 表示什么都不选也是合法解；求「恰好装满」时，除 dp[0] 外都不可达，必须设成负无穷，否则会把「装不满」当成合法答案。

多重背包怎么优化到 O(nW)？

二进制拆分：把数量 k 拆成 1、2、4、...、剩余，每组当成一个独立的 01 物品，就能用 O(log k) 个物品表示任意 1~k 的选择。再配合单调队列可进一步优化。
