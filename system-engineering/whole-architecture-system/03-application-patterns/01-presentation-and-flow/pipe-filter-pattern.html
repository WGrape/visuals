什么时候适用？

判断信号：数据可被拆成输入输出契约清楚的顺序处理阶段。

  • 日志解析、校验、脱敏、写出流水线
  • 编译器词法、语法、优化阶段
  • 媒体文件转码的多段处理

和相近方案怎么区分？

相近方案选择边界
责任链责任链的某环可终止或处理请求；管道过滤器重在每段转换数据并交给下一段。
工作流编排工作流可能有分支、等待和回退；线性管道更适合连续转换。

最小伪代码

records = readLines(source)
parsed = map(parseLine, records)
valid = filter(isValid, parsed)
write(sink, map(normalize, valid))

边界：每段应有明确输入输出契约；有状态过滤器和错误处理需要额外约定。

管道-过滤器 Pipe & Filter

每个过滤器只做一件事，可任意重组顺序

每个过滤器是无状态、独立的处理单元（如压缩、加密、日志、校验），管道负责把前者的输出接成后者的输入。Unix 的 `cat | grep | sort` 就是经典范例。

适用与优势

  • 高复用：过滤器可像乐高一样重组。
  • 并行友好：相邻过滤器可流水线并行。
  • 可演进：增删环节不影响其他。
  • 常用于编译器前端、ETL、多媒体处理。

面试高频问答

Q：管道-过滤器和职责链有什么区别？
A：管道-过滤器是『数据流经一串变换、产出新数据』；职责链是『请求在链上传递、由某节点处理或不处理』。前者变换数据，后者传递/拦截请求。
Q：过滤器为什么要求无状态？
A：无状态才能保证任意排序与并行都不影响结果，也便于水平扩展与故障重试。
