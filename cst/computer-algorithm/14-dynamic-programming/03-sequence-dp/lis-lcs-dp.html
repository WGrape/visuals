第 14 章 · 动态规划

以 i 结尾，还是前缀对前缀

LIS 用「以 i 结尾」定义状态并可优化到 O(n log n)，LCS 与编辑距离用「前缀对前缀」的二维转移，状态定义方式决定了能否写出转移。

LIS 的 O(n²) 定义：以 i 结尾

最长递增子序列。最自然的状态：dp[i] = 以 a[i] 结尾的最长递增子序列长度。

dp[i] = 1 + max(dp[j])   for all j < i and a[j] < a[i]
def lis(a):
    n = len(a); dp = [1] * n; pre = [-1] * n
    for i in range(n):
        for j in range(i):
            if a[j] < a[i] and dp[j] + 1 > dp[i]:
                dp[i] = dp[j] + 1; pre[i] = j
    k = max(range(n), key=lambda i: dp[i])
    path = []
    while k != -1: path.append(a[k]); k = pre[k]
    return max(dp), path[::-1]

状态里的「以 i 结尾」是关键约束：它让子序列有了固定的最后一个元素，转移才能只依赖更小的子问题。去掉这个约束（比如定义成「前 i 个的 LIS」）就写不出转移——因为不知道最后一个元素，无法判断新元素能否接上。

LIS 的 O(n log n)：维护 tails 数组

更快的做法维护 tails[len] = 长度为 len+1 的递增子序列中，结尾元素的最小可能值。结尾越小，后面越容易接上更长的序列。

import bisect
def lis_fast(a):
    tails = []
    for x in a:
        i = bisect.bisect_left(tails, x)   # 第一个 ≥ x 的位置
        if i == len(tails): tails.append(x)
        else: tails[i] = x                 # 用更小的结尾替换
    return len(tails)
a = [3, 1, 2]：读 3 → tails=[3]；读 1 → 替换 → [1]；读 2 → 追加 → [1,2]。最终长度 2。
注意 tails 本身不是一个真实的子序列，只有它的长度是答案；要输出具体方案还得回到 O(n²) 版本加前驱数组。

这个优化常被误称为「贪心」，但它的正确性来自 DP 状态 tails 的单调性（tails 严格递增，才能二分）。不要把它当成「LIS 可以贪心做」的通用结论。

LCS：两个序列的二维 DP

最长公共子序列（不要求连续）。dp[i][j] = a 的前 i 个与 b 的前 j 个的 LCS 长度：

if a[i-1] == b[j-1]:  dp[i][j] = dp[i-1][j-1] + 1
else:                 dp[i][j] = max(dp[i-1][j], dp[i][j-1])

「相等就 +1」这一步只对最后一个字符成立——因为 LCS 的最后一个字符必然同时是两边的最后一个匹配字符。若不等，则最后一个字符不可能同时来自两边，取两种舍弃方式的较大者。

编辑距离：三种操作取最小

dp[i][j] = a 的前 i 个变成 b 的前 j 个的最少操作次数（插入、删除、替换）：

dp[i][j] = min(dp[i-1][j]   + 1,      # 删除 a[i-1]
              dp[i][j-1]   + 1,      # 插入 b[j-1]
              dp[i-1][j-1] + cost)   # 替换/匹配，cost = 0 或 1
dp[0][j] = j;  dp[i][0] = i          # 边界：全插或全删

LCS 其实是编辑距离的特例：只允许插入和删除（不允许替换）时，最少操作数 = len(a) + len(b) − 2·LCS。

序列 DP 的状态定义套路

问题状态复杂度可否优化到更低
LISdp[i]：以 i 结尾的长度O(n²)O(n log n)（tails + 二分）
LCSdp[i][j]：前缀对前缀O(nm)一般不能（除非字符集小/有特殊性）
编辑距离dp[i][j]：前缀对前缀O(nm)空间可压到 O(min(n,m))
最长公共子串（要求连续）dp[i][j]：以 i、j 结尾的公共长度O(nm)滚动数组优化空间

判断该用「前缀」还是「以 i 结尾」的经验：需要连续、需要拼接下一个元素时用「以 i 结尾」；只需要计数/长度时用「前缀」即可。这是序列 DP 最容易写错的地方。

LCS 与空间优化

做法时间空间能否还原
二维 DP dp[i][j]O(n·m)O(n·m)能（回溯）

实现

import bisect

def lis_len(a):
    tails = []
    for x in a:
        i = bisect.bisect_left(tails, x)      # 严格递增用 bisect_left
        if i == len(tails):
            tails.append(x)                    # 可以接更长
        else:
            tails[i] = x                       # 用更小的结尾替换
    return len(tails)                          # O(n log n)

def lis_seq(a):
    """带前驱记录，能还原真实序列"""
    tails_idx, prev = [], [-1] * len(a)
    for i, x in enumerate(a):
        j = bisect.bisect_left([a[k] for k in tails_idx], x)
        if j > 0:
            prev[i] = tails_idx[j - 1]
        if j == len(tails_idx):
            tails_idx.append(i)
        else:
            tails_idx[j] = i
    seq, k = [], tails_idx[-1]
    while k != -1:
        seq.append(a[k]); k = prev[k]
    return seq[::-1]

def lcs(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[-1][-1]

深入自检

tails 数组里存的是什么？

tails[k] 存的是「长度为 k+1 的递增子序列的最小结尾元素」。维护这个最小值能给后续元素留出最大的接续空间。tails 始终严格递增，因此可以用二分在 O(log n) 内定位替换位置。

为什么 tails 的长度等于 LIS 长度，但 tails 本身不是答案？

因为 tails 的每个位置只保留「最小的那个结尾」，不同长度的最优结尾可能来自不同的子序列，拼起来未必构成一条合法递增序列。例如本例 tails 最终是 [2,3,7,18]，而真实 LIS 是 [2,3,7,101]。要得到真实序列必须记录每个位置的前驱下标再回溯。

严格递增和最长非递减子序列的写法差在哪？

差在二分函数：严格递增用 bisect_left（第一个 ≥ x 的位置被替换，相等元素不能接续）；非递减（允许相等）用 bisect_right（第一个 > x 的位置，相等元素可以接在后面）。

LCS 的空间怎么优化？

只求长度时用滚动数组：每行只依赖上一行，空间从 O(n·m) 降到 O(min(n,m))；若要还原具体序列，滚动数组会丢失历史，需要用 Hirschberg 分治算法（时间仍 O(n·m)，空间 O(min(n,m))，用递归把还原问题二分）。

什么时候该用 O(n²) 的 LIS 而不是 O(n log n)？

当 n 较小（几千以内）且需要清晰的 DP 定义与便于还原路径时，O(n²) 更直观；n 达到 10⁵ 量级时 O(n²) 不可接受，必须用二分版。工程上二分版是默认选择，需要还原序列时加一份 prev 数组即可。

序列 DP 先想清楚状态是「前缀」还是「以 i 结尾」，转移就自然出来了。
