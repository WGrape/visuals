分布式并行训练：数据并行 / 张量并行 / 流水线并行 / ZeRO

一个千亿参数模型根本塞不进单卡，必须切开。本文讲清四种并行方式的切法与通信代价、ZeRO 到底省了什么、混合精度怎么把显存再砍一半，以及"3D 并行"是怎么组合起来的。

先算一笔账：训练一个模型要多少显存

以 fp32 训练、参数量 P 为例，单卡显存大致由四块构成：

  • 参数：4P 字节（fp32）
  • 梯度：4P 字节
  • 优化器状态：Adam 的 m 和 v，8P 字节（最大头）
  • 激活值：随 batch size 与序列长度增长
粗估（fp32 + Adam）：约 16P 字节 + 激活
一个 70 亿参数模型：16 × 7e9 ≈ 112 GB 还不算激活 —— 单张 80GB 卡直接爆掉。这就是必须做并行与显存优化的原因。

数据并行 DP：最简单，但每卡都要放完整模型

优点：实现简单、几乎不改模型代码。缺点：每张卡都要放得下完整模型 + 优化器状态，模型一大就放不下。

模型并行：把模型本身切开

张量并行 TP（层内切）

把单个大矩阵按维度切成几块，每张卡算一部分，再通过 All-Reduce 合并结果。典型做法是把注意力的 Q/K/V 投影和 FFN 的中间层切开（Megatron-LM 风格）。

优点：单层的显存被分摊，能塞下更大的层
缺点：每层都要通信，对卡间带宽要求极高，基本只在单机内（NVLink）使用

流水线并行 PP（层间切）

把不同的层放到不同的卡上：GPU0 放第 1~8 层，GPU1 放第 9~16 层……数据像流水一样依次流过。

优点：通信只在"段与段"之间传激活，通信量小，可跨机
缺点：存在流水线气泡（bubble）——前段算完后段还没就绪、卡在空等，降低利用率
缓解气泡的办法：把 batch 再切成 micro-batch，让各段交错工作（1F1B 调度），把空等时间尽量填满。

ZeRO：把"冗余副本"省掉

数据并行最大的浪费是：每张卡都存了一份完整的参数、梯度和优化器状态。ZeRO 的思路是——既然大家在一个组里，就分片存储，谁用谁去取。

阶段分片内容显存节省通信增加
ZeRO-1优化器状态分片约 4 倍（省掉最大的那块）很少
ZeRO-2+ 梯度分片约 8 倍少量
ZeRO-3+ 参数分片与并行度成正比较多（用时要临时聚合参数）
ZeRO-Offload把不常用状态卸到 CPU 内存 / NVMe进一步扩展受 PCIe 带宽限制，慢
ZeRO 的本质：用通信换显存。它是今天能用有限显卡训大模型的关键支撑（DeepSpeed / FSDP 都基于此）。

混合精度：把显存和带宽再砍一半

用更低精度做计算，同时保留一份高精度"主权重"保证收敛：

  • fp32 主权重：更新时用它，避免小梯度被低精度抹掉
  • bf16 / fp16 计算：矩阵乘在低精度下跑，速度快、显存减半
  • 损失缩放 loss scaling（fp16 常用）：把损失放大，防止小梯度下溢成 0
fp16：范围小、易溢出，需要 loss scaling
bf16 （大模型首选）：指数位与 fp32 一致、不易溢出，基本不用 loss scaling
更低精度还有 fp8（新一代 GPU 支持），用于进一步提速，但需要更细致的数值稳定性处理。

3D 并行：实际怎么组合

工程口诀：
  • TP 放在单机内（带宽最高，扛住高频通信）
  • PP 放在跨机（通信量最小）
  • DP/ZeRO 用来扩大规模并消除状态冗余
并行度不是越大越好：切得太碎会让通信和气泡开销超过计算收益，需要实测吞吐（tokens/sec）来调。

面试速记卡

  • 显存构成：参数 4P + 梯度 4P + Adam 状态 8P + 激活（fp32 粗估 16P）。
  • DP：切数据，每卡完整模型，反向后 All-Reduce；缺点是放不下大模型。
  • TP：层内切矩阵，通信频繁，只在单机 NVLink 内用。
  • PP：层间切，通信少可跨机，但有气泡，用 micro-batch 缓解。
  • ZeRO：分片优化器状态/梯度/参数，用通信换显存；Offload 可卸到 CPU/NVMe。
  • 混合精度：bf16 计算 + fp32 主权重；bf16 不易溢出，是大模型首选。
  • 3D 并行：TP 单机内、PP 跨机、DP/ZeRO 扩规模。
