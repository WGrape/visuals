01竞态条件与临界区

第一层

概念与判定

同步要解决的是竞态条件（race condition）：多个执行流访问共享可变状态，结果依赖不可控的时序。

图：counter++ 看起来是一行，实际是 load/add/store 三步，两步之间可被抢占。
概念定义
临界区访问共享资源、必须互斥执行的代码段
原子性操作不可被分割，中间态对外不可见
可见性一个线程的写，另一个线程何时能看到
有序性编译器和 CPU 是否重排指令
先问三个问题再选原语：① 要不要阻塞等待？② 临界区多长？③ 是互斥（一次一个）还是计数（N 个名额）？

03排障与边界

第三层

排障与边界

  • 锁竞争不是「锁慢」，是「排队」：无竞争 mutex ~20ns，竞争时线程被挂起/唤醒要 µs 级，还伴随上下文切换。看 perf lock / /proc/lock_stat（需开 lockdep）。
  • 持锁做 IO：临界区里 read/网络调用会让锁持有几百 µs，把并发打成串行。
  • 锁粒度：一把大锁保护整个哈希表 → 所有操作串行。分桶锁（shard）能线性扩展。
  • 伪共享：两个线程改同一 cache line 的不同变量，缓存行来回失效，性能骤降。用 alignas(64) 填充。
  • 自旋锁睡眠：在自旋锁临界区里调用会睡眠的函数 = 死锁（持有锁的线程睡了，别人永远等不到）。

04原理与取舍

第四层

原理与取舍

同步原语的本质是在「等待的成本」上做选择：自旋用 CPU 时间换低延迟，睡眠用延迟换算力。选择取决于临界区长度与竞争程度。

场景推荐理由
临界区 < 1 µs、竞争低自旋锁 / 原子操作睡眠的 µs 级开销比自旋更贵
临界区长、可能阻塞mutex不能让 CPU 空转
读多写少读写锁 / RCU读并行
计数/限流信号量天然计数语义
等待条件变化条件变量避免忙等

深入 Q&A

Q：为什么无竞争 mutex 只要 ~20ns，和有竞争差 100 倍？
A：无竞争时走 futex 快路径，只在用户态做一次 CAS，完全不陷内核；有竞争才进内核挂起线程。

Q：原子操作就无锁吗？
A：不一定。单个 atomic_add 是原子的，但「读-判断-写」组合仍需锁或 CAS 循环。

05速记卡

竞态三要素

共享可变状态 + 并发访问 + 非原子操作。

自旋 vs 睡眠

短临界区自旋，长临界区睡眠。

condvar 用 while

防虚假唤醒与抢跑。

伪共享

同 cache line 多线程写 → 性能骤降。

锁粒度

大锁串行，分桶扩展。
