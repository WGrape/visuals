第 14 章 · 动态规划

把重复的子问题只算一次

动态规划的关键不是写二维数组，而是定义状态、证明转移覆盖所有选择，并安排合法的计算顺序。

核心速览

状态 State用一组参数唯一描述一个子问题
转移 Transition由已解决的子问题推出当前状态
边界 Base case最小子问题的直接答案
计算顺序保证算某状态时，它依赖的状态已算出

先建立直觉：为什么需要动态规划

看最经典的例子——递归算斐波那契：

def fib(n):
    if n <= 1: return n
    return fib(n-1) + fib(n-2)     # 朴素递归：O(2^n)

这棵树里有海量重复：算 fib(10) 时，fib(8) 被算了 2 次、fib(7) 被算了 3 次……越往下重复越严重，总代价 O(2ⁿ)。

动态规划的全部动机就一句话：既然这些子问题会被反复计算，那就只算一次，把答案存起来。存起来的答案要么是「备忘录」（记忆化搜索），要么是「表格」（自底向上填表）。加了缓存后，代价从 O(2ⁿ) 直接降到 O(n)。

四步法：动态规划的标准流程

  1. 定义状态：用一组参数唯一描述一个子问题。例如 dp[i] = 「前 i 个元素的答案」、dp[i][w] = 「前 i 个物品、容量 w 时的最大价值」。这一步是最难的，也是最关键的。
  2. 写出状态转移方程：dp[i] 如何由更小的状态推出。要保证枚举了所有可能的选择并取最优。
  3. 确定边界（base case）：最小子问题的直接答案，如 dp[0] = 0。
  4. 确定计算顺序：保证算 dp[i] 时，它依赖的状态都已经被算出来。这是正确性的硬性要求。
页脚的三步就是核心：定义状态 → 写出转移 → 确定边界与遍历顺序。很多人觉得 DP 难，是因为一上来就写二维数组，却没有想清楚「dp[i][j] 到底代表什么」。状态定义清楚，转移方程往往就自然浮现了。

两种写法：自顶向下 vs 自底向上

方式做法优点缺点
自顶向下（记忆化搜索）写递归 + 用 memo 缓存已算过的状态思路自然（直接翻译递推）；只算真正需要的状态递归栈开销；可能栈溢出
自底向上（填表）按拓扑顺序从小到大填 dp 数组无递归开销；可做空间压缩必须想清遍历顺序；可能算了无用状态
# 自顶向下：递归 + 备忘录
from functools import lru_cache
@lru_cache(None)
def fib(n):
    if n <= 1: return n
    return fib(n-1) + fib(n-2)

# 自底向上：填表，且可做空间压缩
def fib(n):
    if n <= 1: return n
    a, b = 0, 1
    for _ in range(2, n+1):
        a, b = b, a + b      # 只保留前两个状态 → O(1) 空间
    return b
建议初学时先写记忆化搜索（因为它就是递归 + 缓存，最接近思考过程），确认正确后再改成自底向上并做空间优化。两种写法的状态定义和转移方程是完全一样的，只是计算顺序不同。

经典模型：0-1 背包

这是理解 DP 最好的例子。问题：n 个物品，第 i 个重 w[i]、价值 v[i]，背包容量 W，每个物品只能选一次，求最大价值。

  1. 状态：dp[i][c] = 「只考虑前 i 个物品、容量 c 时能取得的最大价值」。两个参数（考虑到第几个 + 剩余容量）才能唯一描述子问题。
  2. 转移：对第 i 个物品，只有两种选择——
    • 不选：dp[i][c] = dp[i−1][c]
    • 选（且 c ≥ w[i]）：dp[i][c] = dp[i−1][c−w[i]] + v[i]
    取两者较大值。
  3. 边界：dp[0][*] = 0（没有物品，价值为 0）。
  4. 顺序：i 从 1 到 n 递增（保证 dp[i−1] 已算好）。
# 空间压缩：dp[i] 只依赖 dp[i−1]，可压成一维数组
# 注意：容量 c 必须「倒序」遍历，否则同一物品会被重复选取（那就成了完全背包）
dp = [0] * (W + 1)
for i in range(n):
    for c in range(W, w[i] - 1, -1):     # ← 倒序！
        dp[c] = max(dp[c], dp[c - w[i]] + v[i])
return dp[W]
「倒序遍历容量」是 0-1 背包最经典的坑。正序遍历时，dp[c − w[i]] 可能已经包含了第 i 个物品（同一轮里刚更新过），于是同一物品被重复选取，变成完全背包。倒序保证「每个物品只被考虑一次」。反过来，完全背包正是要正序遍历。

适用条件与常见模型

一个问题能用 DP，通常需要：

  • 重叠子问题：不同分支会重复计算同一个子问题（否则就是普通分治）。
  • 最优子结构：全局最优解由子问题的最优解组合而成。
  • 无后效性：当前状态一旦确定，后续决策不影响之前的状态，只依赖状态本身而不依赖「如何到达这个状态」。
模型状态定义典型题
线性 DPdp[i]：前 i 个爬楼梯、最大子数组和、打家劫舍
背包 DPdp[i][c]：前 i 个 + 容量 c0-1 背包、完全背包、目标和
区间 DPdp[i][j]：区间 [i, j]石子合并、最长回文子串、戳气球
二维网格 DPdp[i][j]：到达格子 (i,j)不同路径、最小路径和
序列 DP（双串）dp[i][j]：两串的前缀最长公共子序列、编辑距离
状态压缩 DPdp[mask]：用位掩码表示集合旅行商 TSP、铺地砖（n ≤ 20）
树形 DP在树上做后序遍历二叉树最大路径和、打家劫舍 III

优化：空间压缩

很多 DP 的 dp[i] 只依赖 dp[i−1]（或少数几行），因此不需要保存整个二维表。

依赖范围能压到做法
只依赖上一行 dp[i−1]O(n) → O(1)①滚动数组 / 一维倒序
依赖前两行保留 2 行滚动数组（i % 2）
依赖本行左侧（完全背包）一维正序就地更新

① 准确说：二维 n × W 压成一维 W，空间从 O(nW) 降到 O(W)。

压缩的前提是「想清楚依赖关系」。先看转移方程里 dp[i] 引用了哪些状态，再决定保留几行、是正序还是倒序遍历。压缩是优化手段，正确性永远来自状态定义和转移方程本身。

🎯 面试问答

Q：动态规划适用的条件是什么？

A：三个条件：① 重叠子问题——不同分支会重复计算同一子问题（否则就是普通分治，不需要 DP）；② 最优子结构——全局最优由子问题最优组合而成；③ 无后效性——当前状态一旦确定，后续决策只依赖这个状态本身，不依赖「是如何到达这个状态的」。第三条最容易被忽略，它也是状态设计的关键约束：如果影响的路径会影响结果，说明状态定义漏了维度。

Q：动态规划的四步是什么？

A：① 定义状态——用一组参数唯一描述一个子问题（如 dp[i][w] 表示「前 i 个物品、容量 w 时的最大价值」），这是最关键也最难的一步；② 写出状态转移方程——枚举当前所有可能的选择并取最优，保证覆盖完整；③ 确定边界——最小子问题的直接答案；④ 确定计算顺序——保证算 dp[i] 时它依赖的状态都已算出。状态定义清楚后，转移方程往往就自然浮现了。

Q：记忆化搜索和自底向上填表怎么选？

A：两者状态定义和转移方程完全相同，只是计算顺序不同。记忆化搜索（自顶向下）写起来就是递归 + 缓存，最接近思考过程，且只计算真正需要的状态，适合状态空间稀疏的问题；缺点是递归栈开销、可能栈溢出。自底向上无递归开销、可做空间压缩、常数更小；缺点是必须想清遍历顺序，且可能算了无用状态。建议：初学先用记忆化确认正确，再改成自底向上并做空间优化。

Q：0-1 背包为什么要倒序遍历容量？

A：因为一维压缩后，dp[c] 的更新会用到 dp[c − w[i]]。如果正序遍历容量，那么算 dp[c] 时，dp[c − w[i]] 已经在同一轮里被更新过——它可能已经包含了第 i 个物品，于是同一物品被重复选取，这就变成了「完全背包」。倒序遍历保证 dp[c − w[i]] 仍是「只考虑前 i−1 个物品」的旧值，从而每个物品只被考虑一次。反过来，完全背包正是要正序遍历，让物品可以重复选取。

Q：什么叫做「无后效性」？

A：指当前状态一旦确定，后续的决策只依赖这个状态本身，而不依赖「是如何到达这个状态的」。它是 DP 能成立的隐藏前提。例如「到达格子 (i,j) 的最小路径和」中，状态 dp[i][j] 只关心「在 (i,j) 且已花代价 d」，至于从上面还是左边来的并不影响后续决策——所以无后效性成立。如果发现「到达方式会影响后续结果」，说明状态定义漏了维度，必须把那个信息加进状态（例如迷宫问题里要把「已获得的钥匙集合」加入状态）。

Q：怎么优化动态规划的空间？

A：核心是看转移方程里到底依赖哪些状态。若 dp[i] 只依赖 dp[i−1]，可用滚动数组把二维 n × W 压成一维 W（空间 O(nW) → O(W)）；若依赖前两行就保留两行（用 i % 2 切换）。压缩后要特别注意遍历方向——0-1 背包必须倒序、完全背包必须正序。压缩只是优化手段，正确性来自状态定义与转移方程本身，不要本末倒置。
