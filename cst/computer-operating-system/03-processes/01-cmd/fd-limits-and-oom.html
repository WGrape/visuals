高并发服务最常见的两件事：fd 耗尽报 Too many open files，以及 OOM 被内核杀进程。两者都有明确的排查命令。

01文件描述符上限

  • 每个 socket、文件、pipe 都占一个 fd。
  • fd 耗尽 → accept/open 失败，报 Too many open files。
  • 有系统级(fs.file-max)与进程级(nofile)两道闸。
要点：连接数 = fd 数。长连接服务的 fd 上限要按预期并发连接数预留余量。

02ulimit 与系统参数

ulimit -n                 # 看当前进程软限
cat /proc/sys/fs/file-max # 系统级上限
cat /proc/sys/fs/file-nr  # 已分配 / 可用 / 上限
# /etc/security/limits.conf
* soft nofile 65535
* hard nofile 65535
要点：改 limits.conf 后需重新登录或重启服务才生效；systemd 服务要在 unit 里设 LimitNOFILE。

03OOM 排查

dmesg | grep -i 'killed process'   # 看谁被 OOM killer 杀
cat /proc//oom_score              # 当前 OOM 分数
cat /proc//oom_score_adj          # 可调保护(-1000~1000)
echo -500 > /proc//oom_score_adj  # 降低被杀概率
要点：OOM killer 在内存耗尽时按 oom_score 选进程杀；关键进程可调低 oom_score_adj 保命。

04cgroup 内存限制

# cgroup v2 限制某进程组内存
systemd-run --scope -p MemoryMax=512M ./myapp
# 容器内超限会触发容器内 OOM，而非整机 OOM
要点：容器内存限制本质是 cgroup；设太小且没留余量，应用会频繁被 OOM，表现为「莫名重启」。

05常见疑问

问：改了 limits.conf 不生效？

服务由 systemd 拉起时要在其 unit 设 LimitNOFILE；交互 shell 需要重新登录加载 PAM 限制。

问：怎么判断是 OOM 还是普通崩溃？

看 dmesg 是否有 Out of memory: Killed process，以及进程退出码；OOM 杀的进程通常没有 core。

第一层 · 概念与判定

文件描述符（fd）是内核为进程打开的文件/套接字/管道分配的非负整数句柄，数量有限；泄漏或上限过低会导致 "Too many open files" 或连接拒绝。

  • 三档限制：进程级（ulimit -n）、系统级（fs.file-max）、用户级（limits.conf）。
  • fd 耗尽与 OOM 不同：前者是句柄表满，后者是内存满，但 fd 泄漏常伴随内存泄漏。
  • 判定：服务在高并发下报 open files 错误或连接数上不去 → 查 fd。

第二层 · 参数·命令·量化

排查与设置：

示例

# 当前进程 fd 数
ls /proc/$PID/fd | wc -l
lsof -p $PID | wc -l

# 进程/系统上限
ulimit -n
cat /proc/sys/fs/file-max
cat /proc/sys/fs/file-nr   # 已分配/未用/上限

# systemd 服务提上限
# [Service] LimitNOFILE=65535

第三层 · 排障与边界

  • fd 泄漏：代码没关连接/socket/文件，长跑后缓慢涨到上限；用 lsof 看增长趋势定位未关点。
  • ephemeral 端口耗尽：客户端短时大量出连，TIME_WAIT 占满 3 万端口；调 tcp_tw_reuse 或连接池。
  • 改了 ulimit 不生效：systemd 服务需在 unit 里设 LimitNOFILE，光改 /etc/security/limits.conf 对服务无效。
  • file-max 过小：容器/轻量系统默认值低，高并发直接触顶；按比例上调。

第四层 · 原理与取舍

内核用位图/数组管理 fd，上限本质是为防止单进程拖垮系统而设的配额。epoll 把「监听海量 fd」从 O(n) 轮询降到 O(活跃数)，所以高并发靠 epoll + 足够 fd 上限，而非无限堆 fd。

fd 和端口是同一回事吗？

不是。fd 是进程内句柄（含文件/pipe/socket），端口是网络四元组的出口；客户端连太多会先耗端口，服务端主要耗 fd。

为什么容器里 ulimit 改了没用？

容器由 systemd/cgroup 管，limits.conf 只对登录 shell 生效；要在 service unit 设 LimitNOFILE。
