MLA：把 KV Cache 压成 576 维 latent 的低秩方案

GQA 靠「少几个 KV 头」省 Cache，本质是丢弃多样性；MLA 靠「低秩压缩 + 按需还原」省 Cache，理论上不丢信息。它让 DeepSeek-V2 的 KV 降了 93%，还顺带把推理吞吐抬了 5 倍。

一句话定位：缓存压缩表示，而不是缓存 K/V 本身

MHA 缓存每个头完整的 K 和 V；MLA 只缓存一个 512 维的联合 latent c_KV，再加 64 维专门承载 RoPE 的分量。真正做注意力时，再用上投影把 latent 还原成各头的 K/V。

缓存什么c_KV ∈ R^512 + k_rope ∈ R^64（每层每 token）
原方案2 × n_kv × d_head = 2048 个数（GQA 8 头）／8192（MHA 32 头）
压缩比约 1/57（对 MHA 1/14 对 GQA）
质量DeepSeek 实测优于同规模 MHA，而非「略差」
从「缓存完整 K/V」变成「缓存一个 latent」

数字账：为什么是 93%

方案每层每 token 缓存60 层 8K 上下文相对 MHA
MHA（32 头 × 128）2×32×128 = 8192 个数7.9 GB1×
GQA（8 组）2×8×128 = 2048 个数2.0 GB1/4
MQA（1 组）2×1×128 = 256 个数0.25 GB1/32
MLA（512+64）576 个数0.55 GB约 1/14（对 MHA 1/14，官方称 93.3%）
为什么官方说 93.3%

DeepSeek-V2 的对照基线是它自己若用 MHA 时的配置（128 头 × 128 维），单层每 token 是 32768 个数，压缩到 576 就是 98.2%；考虑 rope 分量与对齐后官方给出 93.3% 的综合值。不同基线算出来的比例不同，引用时要说清基线。

吸收：让 latent 不必真的展开

如果每次 decode 都把 512 维 latent 上投影成 32 个头的 K/V，那省下的带宽又被计算吃回去了。MLA 的关键技巧是把上投影矩阵「吸收」进相邻的权重：

score = q·(W_UK·c) = (q·W_UK)·c　⟹　把 W_UK 乘进 W_Q，注意力直接在 latent 空间做
# 训练时：显式物化多头 K/V（为了并行效率和梯度正确） k = c_kv @ W_UK # (s, h*d_head) v = c_kv @ W_UV # 推理时：吸收到 query / output 侧，避免展开 q_abs = q @ W_UK # 变成 (s, 512)，与 c_kv 直接做注意力 out = attn_out @ W_UV.T @ W_O # 预先合并 W_UV 与 W_O

和 RoPE 的冲突：为什么要单独留 64 维

RoPE 要对完整 K 的每一维做旋转，而 MLA 的 K 是「按需算出来的」，训练时无法对尚未存在的 K 施加位置旋转。DeepSeek 的解法是解耦：额外维护一个 64 维的 k_rope，只对它做 RoPE，再与 latent 还原出的部分拼接。这 64 维也因此必须进 KV Cache（它就是那 64 的来历）。

排障：MLA 相关的四个注意点

现象原因处理
显存估算对不上忘了 rope 分量的 64 维，或按 GQA 基线算压缩比统一到「每层每 token 多少个数」再乘
加载权重缺 keyMLA 的 W_UK/W_UV/W_KV 命名与 GQA 完全不同按 modeling_deepseek 的实现对齐命名
推理比预期慢没有做吸收，每步都在展开 latent确认使用了 absorb 路径
微调后长文变差只训了 latent 分支，rope 分支被冻结或学习率过低检查两组参数的学习率设置

原理与取舍：低秩压缩为什么不掉点

注意力真正需要的不是「每头独立的 128 维 K」，而是「能区分不同上下文片段的方向」。低秩假设认为这些方向落在一个 512 维的子空间里就够了——这和 LoRA 的思路同源，只是作用在 KV 上。GQA 是「硬共享」（几组头用同一份 K/V），MLA 是「软压缩」（共享一个更宽的潜空间再各自投影），后者表达能力更强，所以质量反超。

MLA 能直接套到别的模型上吗？

不能只改结构，需要从头训或大规模续训：压缩矩阵与注意力权重是联合学习的。

MLA 和 GQA 能叠加吗？

概念上冲突（一个靠减头、一个靠压缩），实践中 MLA 已包含「多头共享同一 latent」的性质，不需要再叠 GQA。

MLA 省的是显存还是带宽？

两者都省。KV Cache 变小 → 显存占用下降、长上下文可开更大 batch；每步读取的缓存字节变少 → decode 带宽压力下降，这才是吞吐提升的主要来源。
