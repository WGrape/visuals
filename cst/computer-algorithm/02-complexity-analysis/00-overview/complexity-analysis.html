第 02 章 · 复杂度分析

时间与空间复杂度

复杂度描述输入规模增长时的资源变化，不是某台电脑上测得的秒数。

核心速览

大 O（上界）最常用；描述「不超过」
大 Ω（下界）描述「至少」；比较排序下界 Ω(n log n)
大 Θ（同阶）上下界一致，精确刻画
均摊 O(1)单次可能很贵，但摊到多次后是 O(1)

复杂度到底在描述什么

复杂度不是运行时间，而是「当输入规模 n 增长时，资源消耗如何增长」——它描述的是增长趋势（增长率），与机器快慢、编程语言、常数因子无关。

最常见的误解：「O(n²) 一定比 O(n log n) 慢」。这句话只在 n 足够大时成立。n 很小时，常数因子和小项会主导实际耗时——比如 O(n²) 但常数极小的插入排序，在 n < 20 时比 O(n log n) 的快排更快（这也是标准库小区间切插入排序的原因）。

三种记号：别只说「大 O」

记号含义类比典型用法
O（大 O）上界：不超过 c·f(n)≤最常用，描述「最坏不会超过」
Ω（大 Ω）下界：至少 c·f(n)≥证明「不可能更快」，如比较排序 Ω(n log n)
Θ（大 Θ）同阶：上下界一致=精确刻画，如归并排序 Θ(n log n)
日常交流里大家习惯都用「大 O」泛指（比如「快排是 O(n log n)」其实想表达 Θ(n log n)），但在证明「下界」时必须用 Ω，否则表达是错的。

怎么算：四条实操规则

  1. 只看最高阶项，丢掉低阶项和常数系数。3n² + 10n + 100 → O(n²)。因为 n 足够大时最高阶项主导。
  2. 并列的代码段相加，嵌套的代码段相乘。两个独立的循环 O(n) + O(n) = O(n)；循环里套循环 O(n) × O(n) = O(n²)。
  3. 递归看递推式。写 T(n) = a·T(n/b) + f(n)，再用主定理或展开求解。
  4. 循环次数不固定时，看它实际执行了多少次。例如「外层 n 次、内层平均 n/2 次」仍是 O(n²)，但「每次把范围减半」就是 O(log n)。
# O(n²)：嵌套，且内层次数与外层相关
for i in range(n):
    for j in range(i, n):     # 总次数 ≈ n²/2 → 仍是 O(n²)
        ...

# O(n log n) 的「分治」：每层总共 O(n)，共 log n 层
def merge_sort(a):
    if len(a) <= 1: return a
    mid = len(a) // 2
    return merge(merge_sort(a[:mid]), merge_sort(a[mid:]))  # T(n)=2T(n/2)+O(n)

# O(log n)：每次把问题规模减半
while n > 1:
    n //= 2

三种分析场景

场景含义例子
最坏情况任意输入下的上界快排最坏 O(n²)
平均情况随机输入下的期望快排平均 O(n log n)
最好情况最有利输入插入排序对已有序数组 O(n)
均摊复杂度把偶发的高成本摊到一系列操作上动态数组/哈希表扩容，追加均摊 O(1)
「均摊」和「平均」不是一回事。平均情况是对不同输入取期望（依赖输入分布假设）；均摊是对同一序列中的多次操作做会计（不依赖任何概率假设，是最坏意义下的保证）。动态数组的扩容是典型例子：单次 O(n)，但摊到 n 次追加后每次 O(1)。

空间复杂度

空间复杂度衡量额外需要的内存（通常不计输入本身）。常见量级：

量级含义例子
O(1)原地，只用常数个变量堆排序、快排（不计递归栈）、双指针
O(log n)递归栈深度快排的递归栈、二分递归
O(n)与输入等规模的辅助空间归并排序的辅助数组、哈希表
O(n²)二维 DP 表很多动态规划
递归的栈空间容易被忽略。递归深度为 d、每层栈帧 O(1) 时，空间是 O(d)。快排平均递归深度 log n → O(log n)，最坏 n → O(n) 栈空间甚至栈溢出；这也是「尾递归优化」和「递归改迭代」的动机之一。

复杂度典型算法n=10⁶ 时大致可行？
O(1)数组下标访问、哈希查找✅ 瞬时
O(log n)二分查找、平衡树操作✅ 约 20 步
O(n)线性扫描、前缀和、滑动窗口✅

🎯 面试问答

Q：O、Ω、Θ 有什么区别？

A：O 是上界（不超过，类比 ≤）——最常用，描述「最坏不会超过」；Ω 是下界（至少，类比 ≥）——用于证明「不可能更快」，如比较排序的下界 Ω(n log n)；Θ 是同阶（上下界一致，类比 =）——精确刻画，如归并排序 Θ(n log n)。日常交流常把三者混称为「大 O」，但在陈述下界时必须用 Ω，否则表述是错的。

Q：为什么 O(n²) 的算法在小数据上可能更快？

A：因为大 O 忽略了常数因子和低阶项，只在 n 足够大时才由最高阶项主导。n 很小时，一个常数极小的 O(n²) 算法（如插入排序，内层只是简单比较和搬移）可能快过常数较大的 O(n log n) 算法（如快排的递归与函数调用开销）。这正是标准库的常见优化：小区间（n < 20 左右）切换成插入排序。

Q：「平均复杂度」和「均摊复杂度」有什么不同？

A：平均复杂度是对不同的输入取期望（依赖输入分布假设，比如「随机排列」）；均摊复杂度是对同一操作序列做会计，把偶发的高成本摊到相邻多次便宜操作上，不依赖任何概率假设，是最坏意义下的保证。典型例子：动态数组追加——单次扩容 O(n)，但它保护了接下来约 n 次 O(1) 追加，摊下来每次 O(1)。这和快排「平均 O(n log n)」是完全不同性质的结论。

Q：递归算法的空间复杂度怎么算？

A：主要看递归栈深度。递归深度 d、每层栈帧 O(1) 时，空间是 O(d)。例如：二分查找深度 log n → O(log n)；快排平均深度 log n → O(log n)，但最坏深度 n → O(n)，甚至栈溢出；归并排序除了 O(log n) 栈，还需要 O(n) 辅助数组。这也是「尾递归优化」和「深度大时递归改迭代」的动机。注意空间复杂度通常不计输入本身占用的空间。

Q：怎么根据数据范围反推该用什么复杂度？

A：按「1 秒能跑约 10⁷~10⁸ 次基本操作」估算：n ≤ 10⁶ → 可以 O(n) 或 O(n log n)；n ≤ 10³ → 可以 O(n²)；n ≤ 10² → 可以 O(n³)；n ≤ 20 → 才可以 O(2ⁿ)（状态压缩）；n ≤ 10 → 才可以 O(n!)（全排列）。看到题目给的数据范围，就能大致锁定可用的算法量级——这是最实用的解题技巧之一。

Q：分析复杂度有哪些常见错误？

A：四个高频错误：① 把嵌套循环一律算成 O(n²)——如果内层次数不随 n 线性变化要重新分析（如「每次减半」是 O(log n)）；② 忽略递归栈空间；③ 认为 O(1) 就是「一次操作」——哈希的 O(1) 是均摊且含哈希计算、冲突处理；④ 在最坏/平均/最好之间偷换——比较两种算法必须统一场景。此外链表的 O(1) 插入前提是「已知位置」，脱离前提谈复杂度会得出错误结论。

第二层 · 参数·命令·量化：怎么算

常见代码的复杂度

# 循环：看嵌套层数与每层次数
for i in range(n):            # O(n)
    pass
for i in range(n):
    for j in range(n):        # O(n^2)
        pass
for i in range(n):
    for j in range(i, n):     # 仍是 O(n^2)，系数约 1/2
        pass
i = n
while i > 0:                  # O(log n)：每轮减半
    i //= 2

# 递归：写递归式
# T(n) = 2T(n/2) + O(n)   ->  O(n log n)   （归并排序）
# T(n) = T(n-1) + O(1)    ->  O(n)
# T(n) = T(n-1) + T(n-2)  ->  O(2^n)（朴素斐波那契，有大量重复）

# 均摊：动态数组 append
# 单次扩容 O(n)，但扩容越来越稀疏
# 总代价 n + n/2 + n/4 + ... < 2n  ->  均摊 O(1)
代码形态复杂度例子
单层循环，步长 ×2O(log n)二分查找、快速幂
嵌套循环各 n 次O(n²)冒泡、选择排序
循环 + 内部二分O(n log n)排序 + 查找
递归每次减半 + O(n) 合并O(n log n)归并排序
递归每次减半 + O(1)O(log n)二分
枚举所有子集 / 排列O(2^n) / O(n!)回溯

均摊分析的关键：把一串操作的总代价加起来再除以次数。动态数组 append n 次的总代价 < 2n，所以均摊 O(1)——虽然某一次扩容是 O(n)。

第三层 · 排障与边界：分析时常犯的错

错误为什么错正确做法
把 O(n²/2) 写成 O(n²/2)常数系数可省写 O(n²)
忽略隐藏循环x in list 是 O(n) 不是 O(1)看清内置操作的代价
以为递归都是 O(log n)取决于规模怎么缩小写递归式算
只看最外层循环内层可能是 O(n)乘法不是加法
混淆 n 与输入规模如「值域」也是变量明确谁是 n
  • 排查顺序：先找出最内层的高频操作 → 数它被执行的次数（用乘法） → 再代入 n 的实际量级判断可行性。
  • 边界一：O(n²/2) 与 O(n²) 是同一个量级，常数系数在大 O 记号里被省略。
  • 边界二：Python 里 x in list 是 O(n)、x in set 是 O(1)、list.pop(0) 是 O(n)——内置操作的复杂度必须知道。
  • 边界三：空间复杂度同样要算：递归栈 O(深度)、临时数组 O(n)。

用实测反推复杂度

# 实测：用时间比反推复杂度（粗略但有效）
import time
def bench(f, n):
    t = time.time(); f(n); return time.time() - t

for n in (1000, 2000, 4000):
    t = bench(lambda n: sum(i for i in range(n)), n)
    print(n, round(t, 6))
# n 翻倍时间也翻倍 -> O(n)；n 翻倍时间约 4 倍 -> O(n^2)
O(1) 一定比 O(log n) 快吗？

理论上常数更优，但实际要看常数：n 很小或操作很重（如哈希冲突、缓存未命中）时，O(1) 未必更快。复杂度只描述增长趋势，不描述绝对耗时。

为什么动态数组 append 说是 O(1)，但有时很慢？

因为它是均摊 O(1)：绝大多数 append 是 O(1)，偶尔触发扩容（整体搬一次 O(n)）。把 n 次 append 的总代价 < 2n 平摊到每次，就是 O(1)。单次最坏仍是 O(n)。

空间复杂度怎么算？

看「额外」占用的内存是否随 n 增长：原地是 O(1)；新建一个同规模数组是 O(n)；递归深度 d 是 O(d)（栈）。注意递归的栈空间常常被忽略。
