大模型工程化 · 可视化讲解

优化器
那个决定万亿训练成败的"不起眼"组件

前向算完梯度后，是优化器拿着梯度真正去更新权重。小模型时代它就是个 Adam，没人care；但到了万亿 token 规模，优化器选错，训练会 loss spike、梯度爆炸、甚至回滚重训。DeepSeek-V3 全程零不可恢复暴涨、Kimi K2 零 loss spike，背后都有优化器的功劳。

第 1 步 · 角色

优化器到底在干嘛

反向传播给出每个权重的梯度 g = ∂L/∂θ（该往哪调、调多少）。优化器决定"怎么用这个梯度去更新 θ"。最简单的就是沿梯度反方向走一小步（学习率 η）：

θ ← θ − η · g   （这就是 SGD，随机梯度下降）

但纯 SGD 太"莽"：所有参数用同一个步长、容易被某些维度的剧烈梯度带偏、在峡谷地形里来回震荡。于是有了带动量、自适应学习率的进阶优化器。在训练的四步循环里，它是最后一步、却直接影响"损失能不能稳稳降"。

重要性被长期低估：在小模型上 Adam 和 SGD 差别不大；但在万亿规模上，优化器直接决定训练是否稳定、是否要回滚——这是个"平时没感觉，出事要命"的组件。
第 2 步 · 家族演进

SGD → Adam → AdamW

SGD
+ 动量：累积历史梯度方向，冲过平缓区、减小震荡。最省内存，但调参难、收敛慢。
Adam
对每参数维护"一阶矩(动量)+二阶矩(梯度平方)"，自适应学习率。收敛快、稳，是深度学习默认选择。
AdamW
Adam 的修正版，把权重衰减(L2 正则)与梯度解耦，正则更干净，泛化更好。预训练标配。
优化器关键机制记忆开销适用
SGD + 动量固定步长 + 动量最低（仅 momentum）小模型、追求极致泛化
Adam一/二阶矩自适应2× 参数（m, v）通用默认，收敛快
AdamW解耦权重衰减2× 参数大模型预训练事实标准
为什么是 AdamW 而非 Adam：Adam 把权重衰减混进梯度里，衰减强度会被自适应学习率"稀释"，正则效果打折；AdamW 把衰减单独作用在权重上，正则更可靠——这对大模型泛化影响明显。
第 3 步 · 为什么大模型更娇贵

loss spike 与梯度爆炸

模型越大、数据越多，训练越容易出岔子。两个典型故障：

Loss Spike
损失突然暴涨（俗称"尖刺"），多数能靠学习率预热/退火自行恢复，但严重时不可逆、必须回滚重训。万亿级训练里极痛苦。
梯度爆炸 / 消失
梯度范数骤增或趋零，权重更新失控。深层网络、长序列、注意力 logits 都可能是诱因。
图 1：正常损失平滑下降，途中可能出现 spike——优化器与学习率策略决定它能否自愈
缓解手段：学习率 warmup（先小后大） + 余弦退火、梯度裁剪（clip）、谨慎的初始化与混合精度（见 分布式训练）。但 Adam 家族在极端规模仍可能顶不住——这正是新优化器出现的理由。
第 4 步 · 新势力

Muon：比 Adam 更省 token 的优化器

2024 年提出的 Muon（MomentUm Orthogonalized by Newton-schulz），思路很不一样：它对权重矩阵（而非展平向量）做正交化更新，利用矩阵结构让更新方向更"有效"，从而在相同算力下用更少的 token 训到同等效果。

核心：对动量矩阵 M 做 Newton-Schulz 迭代求正交化近似 → 用其更新权重
  • 省 token：同等效果下数据效率更高，相当于变相降低预训练成本。
  • 矩阵感知：把权重当 2D 矩阵处理，比 Adam 的"逐元素"视角更贴合神经网络结构。
  • 代价：每步多一次矩阵正交化计算；直接放大到万亿规模会出现注意力 logits 爆炸。
Muon 证明了一件事：优化器不是"调参细节"，而是能直接改变训练效率与成本的杠杆。它已经在一些前沿训练中取代 AdamW。
第 5 步 · 工程落地

MuonClip：让万亿模型零 loss spike

2025 年 7 月，月之暗面发布 Kimi K2——一个 1.04 万亿参数的 MoE 模型，预训练用了 15.5T token，首次在万亿规模上用上自研的 MuonClip 优化器，整个预训练没有一次 loss spike。

Muon 放大到万亿规模时，注意力里的 Q、K 两个权重矩阵的 logits 会爆炸。 MuonClip 的解法：对注意力 Q、K 矩阵做裁剪（clip），把输出幅度限制在安全范围， 既保留 Muon 的省 token 优势，又压住了爆炸风险。结果：全程零不可恢复损失暴涨，无需回滚。

Muon 的红利
更高数据效率 → 同等能力更省 token / 算力。
MuonClip 的补丁
Q/K 裁剪 → 解决 logits 爆炸 → 万亿规模稳定。
启示：大规模预训练的"稳定"是工程 + 算法共同堆出来的。DeepSeek-V3 靠 FP8 混合精度 + 工程功底做到零回滚；Kimi K2 靠 MuonClip 做到零 spike。优化器这个"小部件"，在千亿/万亿级是直接决定成败的角色。
收尾 · 选型口诀

我该用哪个优化器

场景推荐理由
个人 / 小模型微调AdamW开箱稳、省心，社区默认
大模型预训练（常规）AdamW（warmup + 余弦退火）成熟可靠，配合混合精度
前沿大模型预训练（追效率）Muon / MuonClip更省 token；需处理大规模稳定性（如 Q/K 裁剪）
极致泛化 / 受限算力SGD + 动量内存最小，但需耐心调参
一句话：小模型用 AdamW 就够；想在大模型上抠效率与稳定性，优化器值得专门研究。它和损失曲线、回滚风险直接挂钩，是训练工程里最被低估、却最能"省钱省命"的一环。

大规模训练为什么优化器特别关键

大模型训练的优化器不只是「更新参数」，它直接决定能不能训得动（显存）和会不会训崩（稳定性）。

挑战表现优化器层面的对策
显存Adam 的 m+v 要 8 字节/参数，7B 就是 56GB8-bit Adam（状态量化，省 75%）、Adafactor（低秩分解）、Lion（只存动量，省 50%）
梯度噪声超大 batch 下噪声低但泛化差；小 batch 噪声大调 lr（线性/平方根缩放）；自适应步长
损失尖峰训练中途 loss 突然飙升再回落warmup + grad clip + 正确的 lr 调度
数值精度BF16 下小梯度被舍入掉FP32 主权重 + BF16 计算；Kahan 求和
通信开销分布式训练同步梯度占大量时间ZeRO（分片优化器状态）+ 梯度累积减少同步次数

更新规则与显存

# Adam 完整更新（理解它就理解所有自适应优化器）
#   m_t = b1*m_{t-1} + (1-b1)*g_t              一阶动量（方向平滑）
#   v_t = b2*v_{t-1} + (1-b2)*g_t^2            二阶动量（幅度估计）
#   m_hat = m_t/(1-b1^t);  v_hat = v_t/(1-b2^t)   偏差修正（前几步关键）
#   theta_t = theta_{t-1} - lr * m_hat / (sqrt(v_hat) + eps)

# AdamW 与 Adam 的唯一区别（weight decay 的位置）
#   Adam:  g_t = g_t + wd * theta       <- decay 加进<b>梯度</b>，被自适应步长缩放
#   AdamW: theta = theta - lr*wd*theta  <- <b>直接在参数上减</b>，解耦
#   结论：Transformer 训练一律用 AdamW

# 显存对比（7B 参数，FP32 状态）
#   SGD:              0     额外
#   SGD+momentum:     4 B/参数 = 28 GB
#   Adam/AdamW:       8 B/参数 = 56 GB
#   Lion:             4 B/参数 = 28 GB
#   8-bit Adam:       2 B/参数 = 14 GB  <- bitsandbytes 库

实践结论：大模型领域AdamW 是绝对主流（几乎所有开源 LLM 都用它），超参高度统一：lr=1e-4~3e-4、betas=(0.9, 0.95)（注意大模型常用 0.95 而非默认的 0.999）、wd=0.1、eps=1e-8、配 cosine 衰减 + warmup。这套配置几乎不用调。

稳定性清单与调优顺序

  • 调优顺序（按性价比）：① 先确认数据没问题（脏数据是最常见的崩溃源）→ ② 调 lr（最重要）→ ③ 加 warmup + grad clip → ④ 调 batch size → ⑤ 才考虑换优化器。
  • lr 扫描是唯一必做的实验：用 1e-5 ~ 1e-2 对数取 6~8 个点，各跑几千步，选「下降最快且没炸」的最大 lr，再往回退一档。
  • loss 尖峰不一定是坏事：大模型训练中偶发的尖峰（spike）后能自行恢复是常见现象；但如果连续多个尖峰且不回落，就要降 lr 或从 checkpoint 恢复。
  • 监控 grad norm：正常应在 0.1~10 之间平稳波动。突然超过 100 说明要炸了（此时 grad clip 会救你）。把 grad norm 画成曲线是最好的早期预警。
  • 8-bit 优化器省显存但引入误差：实测在 1B~10B 规模上效果几乎无损，但超大规模（>100B）要谨慎，建议先小规模验证。

lr1e-3 ~ 5e-4（全参）1e-4 ~ 3e-4越大越容易炸

为什么大模型训练一定要 warmup？

因为训练初期 Adam 的二阶动量 v 估计极不准（样本极少），m/√v 会给出异常大的步长，一步就把参数推到不可逆的坏区域。warmup 让前几千步用小 lr 把 v 估计稳。另一个原因是大模型初期梯度方差大、损失曲面陡峭。经验值：warmup 步数取总步数的 1%~5%，或固定 2000~10000 步（大模型通常取后者）。

Lion 优化器值得用吗？

看场景。Lion 的优势是只存动量（省一半显存）且更新用符号函数（更鲁棒），Google 的实验显示在某些任务上收敛更快。但它的 lr 要比 Adam 小 3~10 倍，且超参经验积累远不如 AdamW 丰富，社区验证也少。建议：显存紧张时可以试，但生产大模型训练仍优先 AdamW（可预测、有海量先例）。

梯度裁剪该设多少？

默认 1.0（按全局 L2 范数）就很好，几乎所有 LLM 训练都用这个值。它的作用是「防止单步更新过大」的安全网，而不是常规手段——如果经常触发裁剪，说明 lr 太大或数据有问题，应该去修根因。监控被裁剪的比例：正常 <1%，长期 >5% 就要降 lr。注意裁剪要在反向后、step 前做，且混合精度下要先 scaler.unscale_(opt) 再裁剪。
