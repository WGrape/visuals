锁机制

表级锁、行级锁（无间隙锁）、advisory lock，以及死锁处理。

表级锁行级锁与 FOR UPDATEadvisory lock死锁与排查

① 表级锁

PG 有 8 种表锁强度，从 ACCESS SHARE（SELECT）到 ACCESS EXCLUSIVE（DDL/DROP）。大多数 DML 只取 ROW EXCLUSIVE，互不阻塞；ALTER TABLE 取 ACCESS EXCLUSIVE，会阻塞读写。

② 行级锁（没有间隙锁！）

PG 的行锁由 SELECT ... FOR UPDATE / FOR SHARE 或 DML 隐式产生，锁信息存在行版本上（不是内存锁表）。PG 没有 MySQL 式的 Gap Lock / Next-Key Lock——它靠 MVCC 快照+写冲突解决幻读，所以行锁更轻。

BEGIN;
SELECT * FROM accounts WHERE id=1 FOR UPDATE;  -- 锁住该行
UPDATE accounts SET balance=balance-10 WHERE id=1;
COMMIT;
注意：并发更新同一行时，后者会等待前者的行锁；若两个事务互相等待对方持有的行锁，则死锁，PG 会检测并回滚其中一个。

③ Advisory Lock（应用级锁）

pg_advisory_lock(key) 是应用自定义的、不绑定到具体行的会话级锁，常用于分布式限流、任务抢占、防止重复执行。

SELECT pg_advisory_lock(12345);   -- 获取
-- 做临界区工作
SELECT pg_advisory_unlock(12345); -- 释放

④ 死锁与排查

PG 内置死锁检测（deadlock_timeout 默认 1s），一旦检出立即回滚一个事务并报 40P01。排查用：

SELECT * FROM pg_locks WHERE NOT granted;       -- 等待中的锁
SELECT pid, wait_event_type, query FROM pg_stat_activity WHERE wait_event_type='Lock';
