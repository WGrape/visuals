三种表示，不要混成一步

层次典型输入与输出负责的问题常见失误
文本前端原文、语言与控制标记 → 规范化文本、音素或子词多音字、数字读法、分句和停顿提示“12:30”被按错误语境朗读
声学模型文字表示、说话人和风格条件 → Mel 频谱或音频 token时长、音高、节奏、音色与语音内容字读对了，却语调僵硬或漏读
声码器 / 解码器声学表示 → PCM 波形或压缩音频帧把表示变成连续采样点与可听声音金属音、杂音、块边界爆音

“声码器”通常指从频谱等声学特征生成波形的模块。使用神经音频编解码器的模型可能生成离散音频 token，再由 codec decoder 恢复波形；有些端到端模型把这些阶段联合训练。图中的分层表达的是职责，不要求每个产品都采用同一套模块。

常见模型路线与取舍

路线生成方式适合先关注的约束
声学模型 + 神经声码器先预测 Mel 等特征，再恢复波形；非自回归声学模型可并行预测一段语音对齐、韵律与声码器质量；两阶段误差会传递
自回归音频 token按序生成离散音频 token，再由音频解码器播放上下文与表现力，以及逐 token 生成带来的首包和长音频成本
扩散或流匹配声学生成通过迭代或连续变换生成声学表示或波形采样步数、速度与音质；可结合蒸馏减少推理步骤

路线不是音质排名。实际效果还受训练数据、说话人条件、文本前端、采样策略和部署硬件影响；同一架构也可能有流式与非流式实现。

流式 TTS 的关键边界

  1. 先切可说的文本：短块能更早开始合成，但句子没结束时难以判断语气和停顿。标点、缓冲窗口与有限前瞻决定质量和等待时间。
  2. 让生成器持续输出：已播放的采样不能撤回。分块预测时需保留声学上下文，避免音色、音高或说话人状态突然改变。
  3. 无缝拼接：重叠、淡入淡出或模型内部连续状态可减少块边界的爆音；简单地把独立片段拼在一起通常不够。
  4. 分别量延迟和算力：首包延迟是请求到首段可播放音频的时间；实时因子 RTF = 合成耗时 / 生成音频时长。RTF 小于 1 表示处理速度快于播放速度，却不保证首包够快。

离线还要检查发音准确率、漏读/重复、音色相似度与主观自然度；在线需监测首包、卡顿、失败率和长文本音色漂移。单一主观分数不能覆盖这些故障。

模型机制与输入控制的边界

SSML 等标记用于向引擎指定发音、停顿和读法，是输入控制；它本身不预测声学表示，也不生成波形。具体标签支持情况取决于厂商、接口和模型版本。继续阅读 SSML 标记语言，可以看到控制条件怎样进入一次合成请求。

反方向的任务是把声音转成文字；需要区分声学编码、对齐和解码，可读 语音识别 ASR 基础。

自检

频谱或音频 token 已经是可直接播放的声音吗？

通常不是。频谱需要声码器生成波形，离散音频 token 需要相应的解码器。播放器最终消费的是音频采样或编码后的音频帧。

RTF 已经小于 1，为什么用户仍可能等很久才听到首字？

模型可能要先看完整句子、完成较长前处理或积累一整块音频才返回。RTF 衡量整体生成速度；首包延迟衡量多久能开始播放。

第一层 · 流水线与关键指标

现代 TTS 是一条三段流水线：文本前端（把文字变成音素）→ 声学模型（音素变成声学特征）→ 声码器（声学特征变成波形）。端到端模型把后两段合并，但理解三段有助于定位问题。

阶段输入 → 输出关键技术常见坑
文本前端文字 → 音素序列文本规范化（TN）、多音字、韵律预测数字/日期/缩写读错、多音字错误
声学模型音素 → 梅尔频谱FastSpeech2（非自回归）、VITS（端到端）韵律平淡、时长不准
声码器梅尔频谱 → 波形HiFi-GAN、BigVGAN、神经 codec音质瓶颈（机械音多源于此）
端到端文字 → 波形VITS、NaturalSpeech、Tortoise/Bark、GPT-SoVITS可控性差、推理慢
  • 三个必须量化的指标：MOS（音质主观分，1~5，4.0+ 才算可用）、RTF（实时率 = 合成耗时/音频时长，<1.0 才能实时，流式要求 <0.3）、首包延迟 TTFB（流式场景 <300ms 才有对话感）。
  • 采样率决定音质上限：16kHz（电话质量）、24kHz（多数开源 TTS）、44.1/48kHz（音乐级）。采样率翻倍，数据量翻倍、算力也翻倍。
  • 文本规范化（TN）是最容易被低估的环节：「2024年3月15日」「iPhone 15」「3.14」「￥199」怎么读？这些规则不做好，声学模型再好听起来也别扭。

量化与命令

# —— 音频基础量的换算（务必记牢）——
# 时长(秒) = 样本数 / 采样率
#   例：24000Hz 下，10 秒 = 240000 个样本
# 梅尔帧数 = 样本数 / hop_length
#   例：240000 / 256 = 937 帧   -> 10 秒音频对应 937 帧梅尔谱
# 帧率 = 采样率 / hop_length = 24000/256 = 93.75 帧/秒（每帧 10.7ms）

# —— 文件大小速算 ——
# WAV(16bit 单声道 24kHz) = 24000 * 2 = 48000 B/s = 48 KB/s ≈ 2.88 MB/分钟
# MP3(128kbps) = 16 KB/s ≈ 0.96 MB/分钟
# Opus(32kbps) = 4 KB/s ≈ 0.24 MB/分钟   <- 流式语音常用
# 对比文字：一句 20 字的话 ≈ 2 秒音频 = 96KB(WAV) / 8KB(Opus)

# —— 常用工具 ——
# 看音频信息
ffprobe -v error -show_format -show_streams input.wav 2>/dev/null | grep -E 'sample_rate|channels|duration'
# 重采样（统一到 24kHz 单声道，训练前必做）
ffmpeg -i input.mp3 -ar 24000 -ac 1 -sample_fmt s16 output.wav
# 切分静音（VAD 前后处理）
ffmpeg -i in.wav -af silenceremove=1:0:-50dB out.wav
# 计算音量（避免合成音频过小/过大）
ffmpeg -i in.wav -af volumedetect -f null /dev/null 2>&1 | grep mean_volume

# —— 评估音质（客观指标）——
#   MCD（梅尔倒谱失真）：越低越好，&lt;6 通常不错
#   PESQ / STOI：与参考音频的感知相似度
#   MOS：最终还是要人听（众包打分，20 人以上才有统计意义）

一个实用换算：1 秒音频（24kHz/16bit WAV）= 48KB。所以「合成 1 分钟语音」产出约 2.9MB，流式传输时务必用 Opus 压到 1/10。

第三层 · 排障清单

  • 读错数字/日期/英文缩写 → 文本前端（TN）问题，不是声学模型问题。解法：完善 TN 规则（正则 + 词典），对关键场景（金额、日期、手机号）单独写规则。不要用模型去猜——规则更可控。
  • 多音字读错（如「银行」vs「行走」） → 需要分词 + 词性标注才能正确判断。解法：接一个分词器，或维护多音字词典（高频词表覆盖 90% 的情况）。
  • 声音有机械感/金属音 → 通常是声码器问题或梅尔谱预测不准。解法：换更好的声码器（HiFi-GAN → BigVGAN）、检查训练数据质量（有没有噪声/削波）、确认梅尔参数（通道数/hop）与声码器匹配。
  • 语速不自然（忽快忽慢） → 时长预测器的问题。非自回归模型（FastSpeech）靠 duration predictor 决定每个音素多长，预测不准就会节奏怪异。解法：用真实对齐（teacher forcing）训练时长、或改用自回归/VITS。
  • 长句断句错误、该停的地方不停 → 韵律预测问题。解法：在文本前端插入韵律标记（如 #1 短停、#3 长停），或用标点+句法分析预测停顿。
  • 合成速度慢（RTF > 1） → 自回归模型（Tacotron2）天然慢；扩散模型步数太多。解法：用非自回归（FastSpeech2，RTF 可到 0.01）、减少扩散步数（配合 consistency model / 蒸馏）、或用 GPU 批处理。
  • 流式首包延迟高 → 瓶颈常在「等整句合成完」。解法：分句合成（按标点切分，第一句先出）、chunk 流式（声码器边生成边输出）、减少等待的音素数量。目标 TTFB <300ms。
  • 训练数据有噪声导致音质差 → 数据质量是 TTS 的第一要素。必须做：降噪、去除削波、统一响度（-23 LUFS 左右）、过滤掉低于 3 秒或高于 20 秒的样本、去掉背景音乐。10 小时干净数据 > 100 小时脏数据。

第四层 · 原理与取舍

TTS 的技术演进主线是：自回归 → 非自回归 → 端到端 → 大语言模型化。每一代都在解决上一代的核心痛点，但也带来新的取舍。

架构代表速度音质可控性主要痛点
自回归Tacotron2 + WaveNet慢（RTF 数秒）好中太慢、会跳字/重复
非自回归FastSpeech2 + HiFi-GAN极快（RTF ~0.01）好高（可控时长/音高）韵律略平淡
端到端VITS快最好（同参数量下）中训练难、可控性弱
扩散NaturalSpeech2/3慢（多步采样）极好中推理慢（可用蒸馏加速）
LLM 化VALL-E、Bark、GPT-SoVITS中好 + 零样本克隆低可控性差、可能胡说
  • 为什么要从自回归转向非自回归：自回归模型逐帧生成，合成 10 秒音频要跑几百到上千步，RTF 高达数秒——根本无法实时，且会累积误差导致跳字、重复（这是 Tacotron 时代的著名问题）。非自回归（FastSpeech）一次并行输出所有帧，RTF 降到 0.01 量级，且因为不依赖上一步输出，彻底消除了跳字和重复。代价是需要单独训练时长预测器，韵律的自然度略逊。
  • VITS 为什么效果好：它用变分自编码器 + 归一化流 + 对抗训练把声学模型和声码器端到端联合训练，避免了「两阶段训练目标不一致」的问题（声学模型优化的是梅尔谱的 MSE，而人耳关心的是波形质量——这两个目标并不完全一致）。所以同等数据量下 VITS 音质明显更好，且因为它内部有随机采样，同一个文本可以合成出不同的韵律变化，更自然。
  • LLM 化带来的质变：零样本音色克隆。VALL-E 把音频离散化成神经 codec token（如 EnCodec 的量化码本），让 LLM 像生成文本一样生成音频 token。好处是只需 3 秒参考音频就能克隆音色（传统方案需要几十分钟数据和微调）；代价是可控性变差——它可能合成出参考音频里没有的内容（幻觉），且难以精确控制时长和音高。
  • 「音质」的最后一公里是数据：所有架构对比在同等数据质量下才成立。实践中，把 10 小时录音做好降噪、切分、响度归一，比换一个更先进的架构带来的提升更大。数据 > 架构 > 调参，这是 TTS 领域的共识优先级。
为什么现在很多 TTS 用「神经 codec」而不是梅尔频谱？

因为 神经 codec（EnCodec、SoundStream、DAC）把音频压缩成了离散 token，让音频能像文本一样被 LLM 处理。梅尔频谱是连续的浮点矩阵，LLM 很难直接建模；而 codec token 是离散序列（类似文字），可以无缝接入现成的 LLM 架构——这就是为什么 VALL-E、Bark、GPT-SoVITS 这类模型能做到「零样本音色克隆」和「用自然语言描述声音」。codec 的另一个优势是压缩率高：24kHz 音频用 EnCodec 压到 6kbps（约 750 B/s）仍能保持可懂度，比 Opus 在低码率下音质更好。代价是：① codec 的量化会引入损失（低码率下有「金属音」）；② 离散化后难以做细粒度的韵律控制。所以目前是两条路线并存：追求可控和稳定用梅尔 + 声码器（FastSpeech2/VITS），追求零样本克隆和表现力用 codec + LLM。

流式 TTS 的首包延迟怎么压到 300ms 以内？

拆解延迟来源：① 等用户输入完（不可控）；② 文本前端处理（<10ms，可忽略）；③ 声学模型生成第一段的梅尔谱；④ 声码器合成第一段波形；⑤ 网络传输。压缩手段：① 分句——按标点把长文本切开，第一句先合成先返回（这是收益最大的一招，但对后端来说意味着「用户还没说完就开始合成」，需要增量输入）；② chunk 级流式——声学模型不需要生成完整句才开始声码，可以按 0.5 秒的 chunk 边生成边合成；③ 减少 lookahead——某些模型为了韵律平滑需要看后面几个音素，调小这个窗口；④ 声码器选用因果卷积（HiFi-GAN 可以，某些扩散声码器不行）；⑤ 传输用 Opus 且不等整段——边合成边推流。综合优化后，FastSpeech2 + 流式 HiFi-GAN 可以做到 TTFB 150~250ms。注意：扩散类声码器因为要迭代多步，很难做到低延迟，这是它在流式场景的硬伤。

TTS 评估到底看什么？

三层：① 客观指标——MCD（梅尔倒谱失真，<6 不错）、F0 RMSE（基频误差，衡量韵律）、CER/WER（把合成音频过 ASR 再识别，看字错率，衡量可懂度，这是最实用的自动指标）；② 主观 MOS——1~5 分，让人听并打分，至少 20 个听众、每人听 10 句以上才有统计意义。4.0 以上算「接近真人」，3.5 左右是「可用但明显是机器」，3.0 以下基本不能用；③ 场景指标——RTF（能否实时）、TTFB（流式体验）、音色相似度（克隆场景用 speaker embedding 余弦相似度，>0.8 算像）。实践中最大的坑是只看 MCD 不看 MOS——MCD 低不代表好听，因为它是逐帧的局部误差，而人耳感知的是整体自然度。所以发布前一定要做一轮人工 MOS 评测，这个环节无法省略。

核心速览

一句话把文字变成能听懂、听起来自然的人声波形
两段式声学模型产出声学特征（梅尔谱），声码器把特征还原成波形
三个质量维度可懂度（听得清）、自然度（像人）、相似度（像谁）

TTS 四段流水线：文本的坑全在前端，声音的坑全在声码器

一、文本前端：最容易被低估的一环

同一段文字，前端处理错了，后面模型再好也是错的。前端要做的事远比想象的多：

任务例子错了会怎样
文本正则化2024年 -> 二零二四年 / 两千零二十四年读成「二零二四」或「两千二十四」的怪异读法
多音字消歧银行(háng) vs 行动(xíng)读错字，非常刺耳
数字读法101 是「一百零一」还是「一零一」房间号、电话号码读法完全不同
标点与停顿逗号句号对应不同停顿时长一口气念完，听感极差
专有名词人名、地名、品牌名读错专名很出戏
语种混排中文里的英文单词用中文音系读英文
为什么前端值得单独下功夫

声学模型再强也无法纠正「把 3.14 读成三点十四还是三点一四」这类问题——它在训练数据里学到的就是映射关系。工业级 TTS 的前端规则往往有几千条，占整个系统代码量的一半以上。

二、声学特征：为什么是梅尔频谱

直接用波形做中间表示太难，因为波形是逐点振荡的，相邻样本几乎无关；而频谱把信号拆成「哪些频率、各有多强」，更符合听觉感知：

原始波形 -> STFT -> 幅度谱 -> 梅尔滤波 -> 对数压缩 -> 梅尔频谱 (逐点) (时频) (频率强度) (按人耳刻度压缩) (压缩动态范围) 梅尔刻度：人耳对低频分辨力高、对高频分辨力低 所以梅尔滤波器在低频密、高频疏 —— 用更少的维度保留听感信息 典型配置（因模型而异）： hop_length = 256 / 512 # 帧移，决定时间分辨率 n_mels = 80 / 128 # 梅尔通道数 sample_rate= 22050 / 44100 # 采样率 # 直觉：一帧约 11~23ms，正好是人耳能分辨的最小时间尺度

五、深入自检

TTS 和语音合成、语音克隆是一回事吗？

TTS 是总称。语音克隆（voice cloning）是 TTS 的一个子任务：用几秒参考音频提取音色，再合成任意文本。技术上多靠 speaker embedding 或 prompt 音频实现。

为什么合成的语音总是「没感情」？

因为韵律（停顿、重音、语调起伏）建模不足。早期模型平均化了韵律，听起来像念稿。改进方向：显式建模时长/基频/能量、用参考音频做风格迁移、或用大模型从上下文推断情绪。

延迟主要花在哪？

自回归模型的逐帧/逐点生成是主要开销。优化手段：非自回归并行生成（FastSpeech 类）、流式生成（边生成边播放）、模型量化与算子融合。实时对话场景通常要求首包延迟低于 500ms。

梅尔谱和波形能互转吗？

波形到梅尔谱是确定性的（有损，丢了相位）；梅尔谱到波形是一对多的，需要声码器去「猜」相位。这也是为什么声码器的好坏直接决定了最终音质。

怎么客观评价 TTS 质量？

主观用 MOS（五分制听感打分）仍是金标准；客观指标有 MCD（梅尔倒谱失真）、WER（合成音频识别回文本的错误率，衡量可懂度）、以及说话人相似度打分。
