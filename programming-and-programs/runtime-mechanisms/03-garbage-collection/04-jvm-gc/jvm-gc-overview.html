JVM 垃圾回收：分代模型与回收器全景

从可达性分析到 Serial / Parallel / CMS / G1 / ZGC / Shenandoah 的选型

JVMGC分代G1ZGC回收器
① 分代 ② 可达性 ③ 回收器 ④ 触发 ⑤ 误区 ⑥ 疑问
一句话：JVM 用「可达性分析」判定死对象，按「分代」假设（多数对象朝生夕死）组织堆，并提供从 Serial 到 ZGC 的一系列回收器，在吞吐与停顿间取舍。

01分代模型

堆分代建立在经验规律“大多数对象很快不可达”上。新生代（Eden + 2 个 Survivor）高频小回收（Minor GC），存活对象老龄化进入老年代；老年代低频大回收（Major/Full GC）。

区域作用回收频率停顿
Eden新对象诞生地高低（Minor）
Survivor S0/S1复制存活对象高低
老年代长命对象低高（Major/Full）
// 典型分代参数
-Xmn256m                       # 新生代大小
-XX:SurvivorRatio=8           # Eden:Survivor = 8:1
-XX:MaxTenuringThreshold=15   # 熬过多少次 Minor 进入老年代

02可达性分析

从 GC Roots（虚拟机栈引用、静态变量、JNI 引用等）出发，能到达的对象存活，不可达的回收。相比引用计数，它天然处理循环引用。

  • GC Roots 包括：栈帧局部变量、静态字段、常量池、JNI 全局引用。
  • 强/软/弱/虚引用决定回收时机：软引用内存不足才收，弱引用下次 GC 就收。

03回收器家族

回收器方式停顿适用
Serial单线程 STW长单核/客户端
Parallel多线程 STW长但快吞吐优先/批处理
CMS(已弃)并发标记清除中老中低延迟（碎片问题）
G1分 Region 增量可控(设目标)大堆+中低延迟主流
ZGC染色指针+读屏障亚毫秒超大堆+极低延迟
ShenandoahBrooks 指针+读屏障亚毫秒同 ZGC 路线
要点：选型口诀：小堆求简单用 Serial；吞吐用 Parallel；可预测停顿用 G1；超低延迟大堆用 ZGC/Shenandoah。

04回收触发

  • Minor GC：Eden 满时触发，只扫新生代，频繁但快。
  • Mixed/Full GC：老年代占用达阈值、或晋升失败、或显式 System.gc()（建议禁用）。
  • 并发模式失败：并发回收来不及，退化为 STW 全量回收——需监控。

05常见误区

  • “Full GC 一定会 STW”：是，Full GC 通常全停顿；但 G1/ZGC 把大部分工作并发化，Full GC 才是兜底。
  • “G1 没有停顿”：G1 停顿可控（设 MaxGCPauseMillis）但非零，目标过激会增大 CPU 开销。
  • “ZGC 万能”：用更高内存/CPU 换停顿，小堆反而 G1 更划算。
  • “System.gc() 能立刻回收”：只是建议，且可能触发昂贵 Full GC，生产禁用。

06常见疑问

问：为什么分代有效？

因为大部分对象短命，对新生代高频小回收成本低，老年代少回收，总体开销大降；代价是处理跨代引用（卡表/记忆集）。

问：ZGC 为什么亚毫秒？

着色指针标记对象状态、读屏障在访问时完成并发 relocation，几乎不 STW 搬移对象，停顿与堆大小基本无关。
