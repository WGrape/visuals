🌐 Memcached 分布式

客户端一致性哈希与无中心集群

服务端无集群

Memcached 服务端之间互不通信、没有主从、没有数据再平衡。『分布式』完全由客户端承担：客户端决定一个 key 落到哪个节点。

一致性哈希

为减少节点扩缩容时的缓存失效，客户端常用一致性哈希：把节点与 key 都映射到一个哈希环上，key 顺时针找最近节点。加入/移除一个节点只影响环上相邻的一段，而不是全部失效。

  • 虚拟节点（vnode）平滑各物理节点的负载。
  • 节点故障 = 该节点 key 全部 miss，回源数据库并重建，注意『惊群』（可加 singleflight / 请求合并）。
  • 扩缩容后命中率会抖动，建议分批、灰度操作。
💡 因为没有服务端复制，Memcached 节点挂掉意味着那部分缓存直接失效——它定位是『可丢失的加速层』，而非『数据源』。
