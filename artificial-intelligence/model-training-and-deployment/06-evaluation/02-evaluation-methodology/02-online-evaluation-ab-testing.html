线上评估与 A/B
离线涨分 ≠ 用户买账

离线评估测的是历史拟合，线上是闭环系统。任何模型改动上线前都要过 A/B，并看长期留存。这一页讲清离线-线上鸿沟、A/B 四环节、影子/金丝雀/灰度放量，以及上线后的漂移监测。

第 1 步 · 鸿沟

离线指标涨 ≠ 线上效果好

离线评估测的是"在历史数据上的拟合能力"；线上是闭环系统——模型改变用户行为，用户行为又变成新样本。所以离线涨 3 分，线上可能毫无波动甚至变差。

分布漂移
用户会适应模型的新回答方式，真实分布持续变化。
指标错位
离线看准确率，线上看留存/转化/介入率，二者常不相关。
铁律：任何模型改动上线前必须过 A/B 测试，且看长期指标（7 日/30 日留存），不只看当天点击率。
第 2 步 · A/B

A/B 测试怎么做

把流量随机拆成对照组（旧模型）与实验组（新模型），跑足够长时间，用统计检验判断差异是否显著。

环节要点常见错误
分流按用户/会话哈希稳定分流，保证同人同组按请求随机导致同人反复横跳
指标主指标 1 个 + 护栏指标多个（安全/延迟）同时看 20 个指标，必然有假阳性
周期覆盖完整周期（≥1~2 周，含周末）只跑 1 天，被周内效应误导
显著做显著性检验，看置信区间凭 2 个点差异拍脑袋上线
辛普森悖论：整体看实验组更好，但拆成新用户/老用户后可能两边都更差。务必分层看指标，不要只看聚合。
第 3 步 · 灰度

金丝雀 / 影子 / 灰度

  • 影子模式 Shadow：新模型并行跑但不返回结果，只比对输出，零风险验证。
  • 金丝雀 Canary：先放 1%~5% 流量，盯护栏指标（崩溃/延迟/有害率），没问题再放量。
  • 灰度 Gradual：5%→20%→50%→100% 逐步放量，每步观察足够时长。
  • 回滚开关：一键切回旧模型，护栏指标越线自动回滚。

第 4 步 · 漂移

上线后的退化监测

模型上线后会"悄悄变差"：分布漂移、用户习惯改变、或新版本引入回归。需要持续监测而非一测了之。

  • 输入漂移：用户 query 分布变化（突发热点）→ 监测 embedding 分布 / 主题占比。
  • 输出退化：定期抽样评分 + 人工抽检，设告警线。
  • 护栏指标：有害率、拒答率、P99 延迟、失败率，越线即告警/回滚。
  • 用户信号：点赞/点踩率、会话轮数、人工介入率，是"有没有用"的终极判据。
线上评估的闭环：离线实验 → 影子验证 → 金丝雀 → 灰度 → 全量 → 持续监测 → 发现退化 → 回到离线实验。评估不是一次动作，而是循环。
收尾 · 一句话

所以线上评估是什么

线上评估 = 用真实流量和真实用户行为，验证"离线涨的分到底有没有用"。 靠 A/B 测试 做因果判断、靠 影子/金丝雀/灰度 做安全放量、靠 漂移监测 兜住长期退化。 一句话：离线回答"模型会不会"，线上才回答"用户买不买账"——二者之间隔着整个闭环。

第一层 · 概念与判定：哪些改动必须 A/B

改动类型能否只靠离线原因
Prompt 模板微调否影响用户体验，需线上验证
模型换代否分布/延迟/成本全变
重排序/路由策略否直接改用户看到的结果

第二层 · 参数·命令·量化：样本量与周期

# 最小可检测效应（MDE）与所需样本量（简化）
  # 基线转化率 p=0.20，想检测 +1pp 的差异，双侧 α=0.05，power=0.8
  # 每组约需 ~15000 用户（用在线计算器或 statsmodels）
  from statsmodels.stats.power import NormalIndPower
  from statsmodels.stats.proportion import proportion_effectsize
  es = proportion_effectsize(0.21, 0.20)        # 效应量
  n  = NormalIndPower().solve_power(effect_size=es, alpha=0.05,
                                    power=0.8, ratio=1, alternative='two-sided')
  print(int(n))                                # 每组样本量

# 护栏：主指标未显著，但护栏越线 -> 不准全量
  guardrails = {{"harmful_rate": 0.01, "p99_latency_ms": 2000}}

经验值：差异越大样本越少；检测 1~2pp 通常需每组上万样本。流量小的新业务，A/B 周期要拉长或接受"只测明显退化"。

第三层 · 排障与边界：A/B 六个翻车点

  • 样本污染：同人跨组（按请求分流）→ 用用户/会话哈希稳定分流。
  • 周期太短：只跑 1 天被周内效应误导 → 至少覆盖 1~2 个完整周。
  • 多重比较：看 20 个指标必出假阳性 → 固定 1 主指标 + 少量护栏。
  • 辛普森悖论：聚合好但分层差 → 必做分层分析。
  • 新颖性效应：新模型刚上线用户好奇点击高，过阵子回落 → 周期拉够。
  • 护栏缺失：主指标涨但延迟爆 → 护栏越线即回滚。

第四层 · 原理与取舍：为什么需要"影子"先于"真实"

影子模式的意义是什么？

影子模式让新模型在真实流量上跑但不返回给用户，只比对输出与延迟。它能在零用户风险下暴露崩溃、超时、输出格式不兼容等问题，是上线前最便宜的一道保险。

为什么不能 50/50 直接开打？

因为新模型可能有未知故障模式（有害输出、无限循环、成本暴涨）。逐级放量把"可能的灾难"限制在 1%~5% 流量内，并靠护栏指标在扩大前拦截。

线上指标和离线指标为什么经常脱节？

离线是开环（固定数据集），线上是闭环（模型改变行为→行为成新数据）。用户会适应、会试探、会绕过，这些都不会出现在离线测试集里。所以线上才是最终的"真理来源"。

深度补充：线上评估与 A/B 测试参数

第一层 · 概念与判定 线上评估把新模型/提示放到真实流量做对照，A/B 测试是其中用随机分流做因果推断的方法。判定：离线指标提升但影响用户体验时，必须线上验证。

要素建议目的
分流比例5%~10% 起步控风险
样本量按最小可检效应算保证显著
核心指标留存 / 转化 / 时长业务对齐
护栏指标延迟 / 错误率 / 成本防退化

第三层 · 排障与边界

  • 样本不足就提前看数，结论不显著甚至反向误导。
  • 未隔离其他变量（同期改了 UI），归因错误。
  • 只盯短期指标，忽略长期留存与品牌损害。
  • 分流不随机（按用户群偏斜），两组不可比。
第四层 · 原理与取舍

A/B 用“随机对照”换可信因果，代价是时间、流量占用与工程复杂度（分流、埋点、统计）。离线评测快但偏离真实分布，线上评测准但慢且有风险。权衡是“速度 vs 真实”：离线先粗筛，线上小流量验证关键体验，护栏指标先行、核心指标再决。统计显著性（p 值/置信区间）是不可省略的闸门。

实例与速查：A/B 样本量

# 最小样本量（两比例检验）近似公式
import math
z = 1.96                      # 95% 置信
p = 0.10                      # 基线转化率
d = 0.01                      # 最小可检效应
n = (2 * z**2 * p * (1-p)) / d**2
print(int(math.ceil(n)))      # 每组约 6000+ 才显著

# 实操：5%~10% 小流量起步，护栏指标（延迟/错误率/成本）先行
  • 样本不足就提前看数，结论不显著甚至反向误导。
  • 隔离其他变量（同期别改 UI），否则归因错误。
  • 不只盯短期指标，看长期留存与品牌损害。
FAQ：小流量跑多久合适？

由样本量决定而非固定天数：用最小可检效应算出每组所需样本，除以日均流量得到天数。通常至少跑一个完整业务周期（如 1~2 周）以覆盖周季节性。护栏指标（延迟/错误率/成本）可即时看，核心指标需等显著性闸门通过再决策，不可中途手动喊停。

常见误区与延伸

  • 误区一：流量越大越快出结论。样本不足结论不显著甚至反向，要先算最小样本量。
  • 误区二：只看核心指标。短期指标可能掩盖长期留存与品牌损害，需搭配护栏指标。
  • 延伸：隔离其他变量（同期别改 UI/价格），否则归因错误，A/B 失去意义。
  • 延伸：护栏指标（延迟/错误率/成本）可即时看，核心指标等显著性闸门通过再决策。

一句话总结：A/B 用随机对照换可信因果，离线快但失真、线上准但慢且有风险，小流量验证关键体验、护栏先行。

决策速记

  • 算样本量：按最小可检效应先算每组所需，再定天数。
  • 隔离变量：同期别改其他东西，否则归因错。
  • 看护栏：延迟/错误率/成本先行，核心指标等显著。
  • 重长期：不只盯短期，看留存与品牌损害。

一句话：A/B 用随机对照换因果，离线快失真、线上准慢，小流量验关键体验。

横向对比与追问

  • 与传统报表比：A/B 是因果推断，报表是相关性描述，前者能回答“为什么增长”。
  • 与灰度发布比：灰度是逐步放量控风险，A/B 是分流做对照，二者可叠加。
  • 追问：为什么不能看实时数据就决策？样本不足结论不显著，可能反向误导。
  • 追问：护栏指标为什么先行？延迟/错误率/成本异常能即时发现，核心指标要等显著。

小结：线上评估用随机对照换可信因果，离线快失真、线上准慢，需配合。
