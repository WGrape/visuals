encoding/json 基础

Marshal / Unmarshal

导出字段（大写）才能被序列化；用 struct tag 指定 JSON 字段名，omitempty 可在空值时省略。

type User struct {
    ID   int    `json:"id"`
    Name string `json:"name,omitempty"`
    pwd  string // 小写，不序列化
}

u := User{ID: 1, Name: "go"}
b, _ := json.Marshal(u)     // {"id":1,"name":"go"}
var u2 User
json.Unmarshal(b, &u2)
⚠️ Unmarshal 到未初始化 map 时传入的必须是指针且 map 会被自动 make；目标 struct 字段类型不匹配会返回错误而非静默丢弃。
流式处理

Encoder / Decoder 处理大流量

对大文件或网络流，用 json.Encoder/Decoder 边读边写，避免一次性载入内存。

enc := json.NewEncoder(w)
enc.Encode(u)            // 写入 io.Writer

dec := json.NewDecoder(r)
for dec.More() {
    var u User
    dec.Decode(&u)       // 逐条解析
}
text/template 与 html/template

同一套语法，安全等级不同

两者语法一致（动作 {{ }}、管道、if/range）。区别：html/template 会对输出做上下文转义，防止 XSS；生成纯文本用 text/template。

const tpl = `Hello {{.Name}}{{if .Vip}}, VIP{{end}}`
t := template.Must(template.New("x").Parse(tpl))
t.Execute(w, map[string]any{"Name": "go", "Vip": true})

// 渲染 HTML 务必用 html/template（自动转义 < > &）
安全差异

为什么 Web 用 html/template

text/template 不转义，把用户输入直接拼进 HTML 会被注入脚本。html/template 根据插入位置（HTML/JS/CSS/URL）自动选择转义规则。

模板里用 {{.UserInput}} 即可获得安全转义；需要输出受信任的原始 HTML 才用 template.HTML 类型（谨慎）。

结构体标签：序列化的控制开关

标签写在字段后面，用反引号包裹，它决定了编解码时字段叫什么、要不要出现、以及特殊情况怎么处理。

标签写法含义典型用途
指定名字字段在报文中换成指定名字改成小写下划线风格
忽略标记完全忽略这个字段密码、内部状态
名字加空值省略值为空时省略该字段可选字段，减小报文
仅空值省略用原字段名，空值时省略保持命名一致
字符串形式用字符串形式表示数字兼容某些弱类型接口
不导出字段小写字段本就不参与编解码天然被忽略
type User struct { ID int64 `json:"id"` Name string `json:"name"` Email string `json:"email,omitempty"` // 空串时不输出 Password string `json:"-"` // 永远不输出 Age int `json:"age,omitempty"` } // 几个容易踩的点： // 1) 空值省略对 0、false、空串、nil、空切片都生效， // 所以 Age 为 0 时也会被省略，如果该字段有意义就不要用 // 2) 只有导出字段才会被编码，小写字段自动忽略 // 3) 时间默认序列化为 RFC3339 字符串 // 4) 映射的键会按字典序排序，输出是稳定的 // 反序列化时的几种选择 var u User json.Unmarshal(data, &u) // 一次性，需要完整数据在内存 dec := json.NewDecoder(r) // 流式，适合读大文件或网络流 dec.DisallowUnknownFields() // 遇到未知字段就报错，用于严格校验 err := dec.Decode(&u) enc := json.NewEncoder(w) // 流式写出 enc.SetIndent("", " ") // 美化输出 enc.Encode(u)

流式与一次性的区别：一次性方式要求数据全部在内存里，适合小对象；流式方式直接对接输入输出流，适合大文件、网络响应、以及需要逐个处理数组元素的场景。

两种模板的区别：安全策略不同

语法相同，安全策略不同

两者使用同一套模板语法，但网页模板会做上下文相关的自动转义：它知道当前处在文本、属性、还是脚本字符串里，并选择对应的转义方式。这正是 Web 场景要用它的原因。

为什么不能自己拼网页内容

手动拼接字符串时，任何一处忘记转义都可能形成注入。模板引擎的转义是自动且上下文感知的，比人工检查可靠得多。这也是不要在 Go 里用加号拼 HTML 的根本原因。

// 模板基本语法 const tpl = "Hello, {{.Name}}!\n" // {{.Field}} 取字段 // {{if .Cond}} ... {{end}} // {{range .List}} {{.}} {{end}} // {{with .X}} ... {{end}} 临时改变上下文 // {{/* 注释 */}} t := template.Must(template.New("m").Parse(tpl)) t.Execute(w, data) // 自定义函数要先注册 funcs := template.FuncMap{ "upper": strings.ToUpper, } template.New("m").Funcs(funcs).Parse(tpl) // 安全提示： // 网页模板会自动转义，但不会放行任意 HTML // 确实需要输出可信 HTML 时，用对应的类型显式标记 // 绝不要把用户输入标成可信 HTML

为什么字段没有被序列化？

最常见的原因是字段小写开头，未导出。其次是用了标签把它忽略，或者值恰好是零值且带了空值省略。检查顺序：导出性、标签、零值。

空值省略有什么副作用？

它无法区分没设置和设置成了零值。如果 0 或 false 本身有业务含义，就不要用空值省略，改用指针类型：nil 表示没设置，指向 0 的指针表示明确设为 0。

反序列化遇到类型不匹配会怎样？

会返回错误但会跳过该字段继续处理，不会整段失败。这与某些严格语言不同，所以不要假设没报错就说明所有字段都对。真正严格校验时应该禁止未知字段并做业务校验。

模板执行出错能捕获吗？

能。执行方法返回错误，但要注意错误可能在写出部分内容之后才发生，此时响应已经写了一半。更稳妥的做法是先把模板渲染到缓冲区，确认无误后再一次性写出。

一句话总结：序列化解决的是结构如何变成字节，模板解决的是数据如何变成文本。两者的共同原则是：让边界处理显式化，哪些字段对外可见用标签声明，哪些内容需要转义交给模板引擎。

Go 里 JSON 慢的根因是反射：encoding/json 每次都要通过反射读取结构体字段、查 tag、做类型转换。优化有三档——① 避免 Marshal 后再转 string（减少一次拷贝）；② 用 json.Encoder 直接写 io.Writer（省中间 []byte）；③ 换代码生成的库（easyjson、sonic、jsoniter），性能可提升 2~5 倍。

JSON 优化

// 常见性能陷阱：Marshal 后再转 string（多一次分配与拷贝）
b, _ := json.Marshal(v)
s := string(b)              // ✗ 额外拷贝
w.Write([]byte(s))          // ✗ 又一次

// 正确：直接编码到 Writer
enc := json.NewEncoder(w)   // ✓ 无中间 []byte
enc.SetEscapeHTML(false)    // 非 HTML 场景关闭转义，还能再省一点
enc.Encode(v)

// 关键 tag 用法
type User struct {
    ID       int64  `json:"id"`
    Name     string `json:"name"`
    Password string `json:"-"`                  // <strong>完全忽略</strong>
    Email    string `json:"email,omitempty"`    // 为空时省略
    Token    string `json:"token,omitempty"`
}
// 注意：omitempty 对 <strong>0、""、false、空切片/map</strong> 都生效
//   陷阱：ID=0 的合法值会被 omitempty 吃掉！

常见坑

// 坑 1：nil slice 序列化成 null，前端期望 []
var items []string
json.Marshal(items)         // → null
items = []string{}          // → []   <strong>初始化一下</strong>

// 坑 2：int64 超过 2^53 在 JS 里失真
//   Go: 9007199254740993 (2^53+1)
//   JS: 9007199254740992  ← 失真！
// 解法：大 ID 用 string 传输
type Resp struct {
    ID int64 `json:"id,string"`    // → "9007199254740993"
}

// 坑 3：金额用 float 会丢精度
//   0.1 + 0.2 != 0.3
// 解法：<strong>用分为单位的整数</strong>，或用 string
type Money struct {
    Amount int64 `json:"amount"`   // 单位：分
}

// 坑 4：time.Time 的零值不是 null
//   零值是 "0001-01-01T00:00:00Z"，容易让前端困惑
// 解法：用 *time.Time + omitempty

模板用法

// html/template 会自动按上下文转义（HTML/JS/CSS/URL 各不相同）
tmpl := template.Must(template.New("t").Parse(
    `<a href="{{.URL}}">{{.Name}}</a>`))
// 若 Name = "<script>alert(1)</script>"
//   输出：<a href="...">&lt;script&gt;alert(1)&lt;/script&gt;</a>   ✓ 安全
// 若 URL = "javascript:alert(1)"
//   输出：<a href="#ZgotmplZ">   ✓ URL 上下文也做了过滤

// 明确信任的内容（如已消毒的 HTML）用 template.HTML 类型
data := map[string]any{
    "Content": template.HTML(safeHTML),    // 只有这样才能输出原始 HTML
}

// 常用函数
{{.Name | html}}         转义 HTML
{{.Name | js}}           转义 JS
{{.Name | urlquery}}     URL 编码
{{if .Cond}}...{{end}}
{{range .Items}}{{.}}{{end}}
{{with .User}}{{.Name}}{{end}}
{{/* 注释 */}}

模板要预编译：template.ParseFiles 每次调用都会重新解析，应在服务启动时解析一次并复用（template.Must + 全局变量）。热路径里解析模板是常见的性能问题。

自检 Q&A

Q：什么时候该从 JSON 换 Protobuf？

A：看三个信号——① 性能敏感：JSON 的反射开销在高频调用下明显（编码耗时占比 > 10%）；② 内部服务通信：不需要人类可读，且两端都可控；③ 需要严格的 schema 演进：Protobuf 的字段号机制让前后兼容有明确规则。反之，对外 API、配置文件、调试友好的场景应保留 JSON。折中方案是内部用 Protobuf、对外用 JSON。

Q：结构体字段必须大写才能序列化？

A：是的。encoding/json 只能访问导出字段（首字母大写），小写字段会被静默忽略——不报错，只是不出现在输出里。这是 Go 新手最常见的困惑。如果需要小写字段名，用 tag：json:"name"。注意 tag 里的字段名可以是任意大小写，只有 Go 的字段名必须大写。

Q：omitempty 有什么陷阱？

A：它对所有「零值」都生效，无法区分「未设置」和「设置为零值」。比如 IsActive bool json:"is_active,omitempty"，当值为 false 时字段会被完全省略——但 false 可能是有意义的合法值。解决方案：① 用指针类型 *bool（nil 表示未设置）；② 不用 omitempty；③ 用 sql.NullXxx 类似的自定义类型。这在布尔和数值字段上尤其容易出问题。

Q：模板里访问 map 的 key 有大小写要求吗？

A：map 的 key 没有导出限制，{{.name}} 完全可以工作（字段名/方法名才要求大写）。但有个细节：如果 map 里没有该 key，模板会输出 <no value>（map 类型）而不是报错。可以用 {{if .name}} 先判断，或用 {{.name | default 「N/A」}}。另外访问不存在的字段（结构体）会直接报错，这与 map 的行为不同，容易混淆。
