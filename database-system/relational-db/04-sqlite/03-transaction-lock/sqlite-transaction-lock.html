SQLite 事务与锁

autocommit、五级锁状态、WAL 模式下的读写并发，以及写热点瓶颈。

事务模型五级锁WAL 模式写瓶颈

① 事务与 autocommit

SQLite 默认 autocommit：每条语句当作一个事务立即提交。显式 BEGIN 开启事务，COMMIT/ROLLBACK 结束。与 client-server 数据库不同，SQLite 的“事务”主要指 文件级锁的持有区间。

BEGIN;
UPDATE accounts SET balance=balance-10 WHERE id=1;
UPDATE accounts SET balance=balance+10 WHERE id=2;
COMMIT;

② 五级锁状态

SQLite 用 整个数据库文件 的锁（不是行锁），按强度递进：

状态含义
UNLOCKED无锁
SHARED读（可多人）
RESERVED准备写（唯一个，还未改数据）
PENDING等待现有读释放，准备独占
EXCLUSIVE独占写（别人不能读）
没有行锁：写操作会锁住整个库文件，这正是 SQLite 不适合高并发写的原因。

③ WAL 模式

默认 rollback journal 模式下一个写者会阻塞所有读者。开启 WAL 后，写追加到 -wal 文件，读不阻塞写、写不阻塞读（读者读旧页，写者写新页），并发大幅提升。

PRAGMA journal_mode=WAL;
PRAGMA wal_checkpoint;   -- 合并回主库

④ 写入热点瓶颈

即使 WAL，同一时刻仍只允许一个写者。高并发写（如计数器）会互相排队。应对：批量合并写、用 WAL + 更大 busy_timeout、或干脆把写放到单线程/队列。

PRAGMA busy_timeout=5000;  -- 锁等待而非立即报错
