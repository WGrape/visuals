第 06 章 · 哈希表

把键映射到存储位置

哈希函数让“按键找值”通常很快，但碰撞、负载率与扩容决定了它的实际边界。

映射不是唯一定位

哈希表先计算键的哈希值，再映射到桶。桶数 m 有限，键的可能取值远多于 m，碰撞不可避免。例如桶下标为 key % 8 时，5 和 13 都落在桶 5。查询不能只看桶号，还必须比较完整的键。

链地址法让一个桶管理多个键值对；开放寻址在其他桶继续探测。两者都要处理重复键更新与删除，开放寻址还要区分“从未占用”和“删除标记”，否则查找可能提前停止。

插入 (5, A)、(13, B) 后查找 13：先定位桶 5，再逐个比较键，跳过 5，命中 13，返回 B。相同桶号不意味着两个键相等。

负载率与复杂度

负载率 α = 元素数 / 桶数。随着 α 增大，冲突通常增多；扩容时分配更多桶并重新映射已有元素，一次迁移 O(n)，合理的倍增策略使连续插入的均摊成本通常为 O(1)。具体阈值取决于实现，并非所有哈希表都固定在 0.75。

操作均摊／期望情形不利情形
查询、插入、删除O(1)大量冲突时可能 O(n)
扩容重哈希不是每次插入都发生触发该次 O(n)

不能靠桶下标维持键的排序；需要有序遍历或范围查找时，应考虑平衡搜索树。

何时使用

去重、频率统计、键值索引适合哈希表。如果键可变，插入后修改参与哈希的字段会使原位置不再可定位；应使用稳定的键，或删除后重新插入。
