神经音频编解码器：把波形压成离散 token 的可微压缩器

传统 codec 靠心理声学模型丢掉「听不见」的信息，神经 codec 靠训练出来的编码器把波形压成一段离散 token 序列。它同时是「更省的传输格式」和「大模型能直接建模的表示」——这正是它取代声码器成为新一代语音系统底座的原因。

为什么语音系统需要另一个 codec

在神经 codec 之前，语音链路里有两套完全不同的东西：声码器（mel → 波形，只管合成，不管压缩）和通信 codec（Opus/AAC，只管压缩，不管语义）。两套东西互不相通，于是「压缩传输」和「模型生成」永远是两条路。

神经 codec 把二者合成了一个：编码器输出的是离散的整数 token，解码器把 token 还原成波形。离散意味着——它既能像 Opus 一样按码率传输，又能像文本 token 一样被语言模型自回归地预测。

波形 24 kHz→编码器 CNN→连续向量→RVQ 量化→离散 token→解码器→波形
一句话定位：声码器解决「怎么把特征变成声音」，神经 codec 解决「怎么把声音变成可被模型读写的序列」。后者是前者的超集，所以新系统普遍直接上 codec。

RVQ：为什么是「残差」向量量化

单个码本要把连续向量量化成离散下标，想要高保真就得要极大的码本（比如 1024 个向量完全不够，2^16 才勉强）。码本一大，训练就崩——大部分码字永远不被选中（码本坍缩）。

RVQ（Residual Vector Quantization）的解法是串多个小码本：第一层量化原始向量，算出残差；第二层量化这个残差；第三层再量化剩下的残差……最后把各层的下标叠起来。

层级分工是 RVQ 最有用的性质：低层 token 承载「说了什么」，高层 token 承载「像谁的声音」。语音克隆只需换高层、内容编辑只需动低层——这是传统 codec 给不了的粒度。
别把层数等同于质量。层数越多码率越高，但每层都要额外的解码计算；实时链路里 8 层常在 6 kbps 附近，再往上人耳收益递减很快。

码率、帧率与延迟：三个会互相打架的数

神经 codec 有三个独立的旋钮，改任何一个都会牵动另外两个：

  • 帧率（frame rate）：每秒产生多少组 token。常见 50 / 75 Hz。帧率越高时间分辨率越好，但序列越长，自回归模型的计算量线性上升。
  • 层数（n_q）：每组 token 用几个码本。层数越多码率越高、音质越好。
  • 码本大小：每层多少个码字，通常 1024（10 bit）。

最容易被忽略的一项：因果性与前瞻。codec 若为提升质量用了双向卷积，就会引入固定的前瞻延迟（常见数十毫秒）。做实时通话时必须选全因果（causal / streaming）版本，否则再低的码率也救不回交互体验。
上面是量级估算，用于建立直觉：1 层 10 bit、帧率 × 层数决定码率。实际数字受具体模型与熵编码影响，请以官方实现为准。

神经 codec 怎么接入 TTS / 语音大模型

接入方式有三条，复杂度与可控性各不相同：

① 两阶段：文本 → 语义 token → 声学 token
先由语言模型预测低层（语义）token，再用一个小的非自回归模型补全高层声学 token。
优点：主模型短、快；缺点：需要两套模型对齐。
② 直接自回归全部层
模型一次输出 n_q 层 token（常配合「延迟模式」把各层错开一步预测）。
优点：端到端；缺点：序列长 8 倍，推理慢。
③ codec 只做「最后一段」
模型仍输出 mel，用 codec 解码器替代声码器做 mel → 波形。
优点：改动最小；缺点：吃不到离散 token 的好处。
工程判断：想做「能用提示词控制语气、能克隆音色」的语音大模型，走 ①；只想把现有 TTS 的音质提上去，走 ③ 成本最低。

常见翻车点

换 codec 后音质变差，但客观指标没降

多数是采样率不匹配：24 kHz 的 EnCodec 解码出的波形被当成 48 kHz 播放，声音会变尖；或者训练用 24 k、推理喂 16 k。任何 codec 换型，第一步先对齐采样率与响度归一化。

自回归生成出现「循环吐字」

离散 token 的自回归和文本一样会陷入重复，**语音上表现为不断重复同一个音节**。缓解手段与 LLM 一致：温度、重复惩罚，以及在语义层加一个「已生成长度」的软约束。

实时性不达标

先分离三段延迟：算法前瞻（codec 是否因果）+ 首块大小（一次要攒多少帧才开始解码）+ 计算耗时。经验上实时链路里 codec 不是瓶颈，瓶颈常在第一段的等待策略与模型本身。

把神经 codec 当通用传输 codec 用

Opus 在 20 kbps 以下仍非常稳健、CPU 消耗极低、标准化程度高；神经 codec 在低码率更有潜力但算力高、兼容性差。纯通话传输场景，Opus 仍是默认答案。

一句话总结

神经 codec 的价值不在「压得更小」，而在把音频变成离散序列——这件事让语音第一次能被语言模型直接读写，于是 TTS、语音克隆、端到端语音对话、音乐生成全部统一到了同一套范式上。理解 RVQ 的层级分工和码率 = 帧率 × 层数 × 10 bit这两个点，就够判断绝大多数工程取舍了。

选型速记：语音大模型用 EnCodec；高保真/克隆试 DAC；纯传输继续用 Opus；实时链路务必确认 codec 是因果版本。
