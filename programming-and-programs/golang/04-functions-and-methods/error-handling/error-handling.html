概述

错误是值，不是异常

Go 把错误当作普通返回值处理，显式 if err != nil 让失败路径一目了然。panic 只用于真正不可恢复的程序错误。

error 接口

只要实现 Error() string

标准库 error 就是接口；函数返回非 nil 表示出错。自定义错误只需提供 Error 方法。

type error interface { Error() string }

// 自定义
type MyErr struct{ Code int }
func (e *MyErr) Error() string { return fmt.Sprintf("code %d", e.Code) }

// 快速构造
err := errors.New("something wrong")
错误包装与判定

Wrap 保留链，Is/As 做判断

用 fmt.Errorf("...: %w", err) 包装能保留原始错误；errors.Is 比较根因，errors.As 提取特定类型。

if err != nil {
    return fmt.Errorf("read config: %w", err)
}

// 调用方
if errors.Is(err, os.ErrNotExist) { ... }

var my *MyErr
if errors.As(err, &my) { fmt.Println(my.Code) }
不要只打 err 字符串就当成新错误返回——会丢失类型信息，导致上层无法用 Is/As 判定根因。
panic：中断执行

栈展开到 recover 或进程退出

panic 会立即停止当前函数、运行已注册的 defer，并向上展开；若无人 recover，程序崩溃并打印栈。

⚠️ 不要用 panic 处理可预期的普通错误（如用户输入非法）。panic 应保留给「程序员 bug / 不可恢复状态」。
recover：捕获 panic

只能在 defer 中生效

recover 必须在 defer 函数里直接调用才有效，用于把 panic 转成 error，常见于服务器防止单请求拖垮整体。

func safe(f func()) (err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("panic: %v", r)
        }
    }()
    f()
    return nil
}

经验法则

库函数几乎从不 panic（用 error 返回）；只在初始化阶段（如配置致命错误）或「不可能发生」的断言处 panic。主程序可用 panic 表达启动失败。
