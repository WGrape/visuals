执行器与并行查询

火山模型（迭代器）、计划节点类型，以及 Parallel / Gather 并行执行。

火山模型节点类型并行查询JIT

① 火山模型（Iterator）

执行器把计划树当成 拉取式（pull）迭代器：上层节点反复调用下层节点的 ExecProcNode() 获取“下一条元组”。每个节点实现 Init / Exec / Done。简单、统一，但每条元组一次函数调用开销大。

② 主要节点类型

类别节点
扫描Seq Scan / Index Scan / Bitmap Heap Scan / TID Scan
连接Nested Loop / Hash Join / Merge Join
聚合Agg（hash/sorted）/ GroupAggregate
排序Sort / Unique / Limit
物化Materialize / CTE Scan

③ 并行查询

大查询可并行：Gather 节点把工作分发给多个 Parallel Worker，各自做 Parallel Seq Scan / Parallel Hash，再汇总。受 max_parallel_workers、表大小阈值控制。

SET max_parallel_workers_per_gather = 4;
EXPLAIN SELECT count(*) FROM big_table;  -- 出现 Gather / Parallel Seq Scan

④ JIT 编译

PG 11+ 支持 LLVM JIT，把表达式求值、元组变形编译成机器码，在大扫描/多表达式查询中显著降低 CPU 开销（jit=on）。
