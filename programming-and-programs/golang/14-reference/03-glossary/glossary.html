并发与调度术语

术语含义要点
G（goroutine）用户态协程，由 Go 运行时调度栈从 2KB 起，可按需伸缩
M（machine）操作系统线程真正执行代码的实体
P（processor）逻辑处理器，持有运行队列数量默认等于 CPU 核数（GOMAXPROCS）
GMPG、M、P 三者组成的调度模型G 挂在 P 的队列上，由 M 取出执行
work stealing空闲 P 从其他 P 偷一半任务保证负载均衡，减少空转
抢占运行过久的 G 被强制让出 PGo 1.14 起支持异步抢占
channelgoroutine 间的通信管道有缓冲与无缓冲两种
netpoller网络 I/O 就绪通知机制让同步写法跑在异步实现上
sysmon运行时后台巡检线程负责抢占、网络轮询、强制 GC
G 轻量创建成本远低于线程。
P 决定并行度真正同时执行的 M 不超过 P 的数量。
channel 传所有权不要用它单纯做信号量而忽略同步语义。
阻塞要可唤醒阻塞操作必须能被运行时接管，否则会占住 M。

深入自检

接口值为 nil 的常见陷阱是什么？

接口由「动态类型 + 动态值」两部分组成，只有两者都为 nil 时接口才等于 nil。把一个类型化的 nil 指针赋给接口后，接口并不等于 nil——这是最经典的 Go 陷阱之一。

GMP 里的 P 到底起什么作用？

P 是「执行资源」的抽象，它持有可运行 G 的本地队列与 mcache。M 必须绑定一个 P 才能执行 Go 代码。因此 P 的数量（GOMAXPROCS）决定了真正的并行度上限。

defer 的参数什么时候求值？

在 defer 语句执行时求值，而不是函数返回时。因此 defer f(x) 里的 x 取的是当时的值。想延迟求值要写成 defer func() { f(x) }()。

什么时候该用 go.work？

当你同时开发多个相互依赖的 module，需要在本地联调但又不想频繁改 replace 时。它让多个 module 在本地被视为一个整体，提交前记得确认它不影响 CI。

size class 为什么能减少碎片？

分配大小被归并到有限档位后，一块被释放的空间总能被同档位的新请求复用；若按真实大小切分，会产生大量无法复用的不规则空隙。

并发与调度核心术语

术语含义关键数字 / 默认行为
Ggoroutine，用户态协程初始栈 2 KB，按需增长，最大 1 GB（64 位）
MOS 线程（machine）默认不限制，受 GOMAXPROCS 间接影响
P处理器，执行 G 的上下文数量 = GOMAXPROCS，默认等于 CPU 核数，1.25 起受 cgroup 限制
runqueueP 本地可运行队列本地容量 256，满则批量迁移一半到全局队列
work stealingP 空闲时从其他 P 偷一半 G偷取时被偷方让出一半，保证负载均衡
sysmon后台监控线程无 P 绑定，负责抢占与 netpoll 超时调度

GOMAXPROCS 不是“线程数上限”，而是同时执行 Go 代码的 P 的数量。阻塞在系统调用上的 M 不占 P，因此线程数可以远超它。

# 观察 GC 行为
GODEBUG=gctrace=1 ./app
# 输出字段：gc 1 @0.017s 3%: 0.026+1.4+0.021 ms clock,
#          0.32+0.68/1.1/0.05+0.25 ms cpu, 4->5->3 MB, 5 MB goal
# 关键：4->5->3 MB  = GC前堆 -> GC后存活 -> 目标堆；比例异常说明 GOGC 需调整

自检 Q&A

Q：GOMAXPROCS 设大一点能提速吗？

A：只对 CPU 密集任务有意义，且超过核数反而因上下文切换变慢。IO 密集场景瓶颈不在 P 的数量，加大它不会提升并发——goroutine 阻塞在 IO 时不占 P。

Q：GOGC 调大调小分别什么时候用？

A：调大（如 200）→ GC 次数减少、CPU 占用降低，但堆内存峰值升高，适合内存充裕、追求吞吐；调小 → 内存占用降低但 GC 更频繁，适合内存紧张。配合 GOMEMLIMIT 使用比单调 GOGC 更可控。

Q：map 的装载因子 6.5 是什么意思？

A：每个 bucket 存 8 个键值对，当平均每个 bucket 的元素数超过 6.5 时触发翻倍扩容。之所以不是 8，是为了留余量避免频繁触发；扩容采用渐进搬迁，单次操作只搬 1~2 个 bucket，避免 STW 尖刺。
