max_tokens 与停止序列：给生成装上刹车

输出预算怎么算、为什么会被截断、finish_reason 在说什么。

输出上限

max_tokens 限制的是"新生成"的 token

max_tokens 规定本次响应最多生成多少个新 token，不含输入。它不影响模型"想"多久，只限制输出长度——达到上限就停，哪怕话没说完。

命名演化：OpenAI 新接口已改名 max_completion_tokens，强调"补全部分"；Anthropic 叫 max_tokens 且必填；很多本地框架另有独立参数控制上下文总长。跨平台迁移时最容易踩这个坑。
预算

和上下文窗口一起算账

约束公式说明
窗口约束输入 + 输出 ≤ 上下文窗口部分 API 还要求 max_tokens 显式小于剩余空间
常见事故输入 7k + max_tokens 4k > 8k 窗口报错，或被 API 静默压缩
推理模型思维链也计入输出o1/R1 类模型的"思考 token"同样占 max_tokens，答非所问往往是预算被思考吃光
截断的两种姿势：话没说完被掐断时，流式输出会戛然而止、JSON 可能只剩半截。结构化输出场景要么留足预算，要么在代码里检测 finish_reason 并续写或重试。
停止序列

stop：遇到就停的"暗号"

stop（stop_sequences）是一组字符串，生成过程中一旦产出该序列即停止，且停止序列本身不会出现在输出里。经典用法：

对话轮次分隔
stop=["\nUser:"] 防止模型自导自演下一轮提问
截断追问
补全场景用 stop=["\n\n"] 只取第一段
工具调用边界
以特殊 token 作为函数调用的结束标记

值含义处理

面试问答

高频问题

Q1：max_tokens 会影响回答质量吗？
不影响"质量"本身，模型仍是逐 token 生成；但设太小会导致截断（finish_reason=length），长答案变半截，等效于"质量问题"。思维链模型还需预留思考预算。
Q2：输入 token 算不算 max_tokens？
不算。max_tokens 只限新生成部分；但输入 + 输出合计不能超过上下文窗口，所以留输出预算时要先扣掉输入长度。
Q3：stop 序列会被计入输出吗？
不会。命中 stop 后序列本身被剥离；但生成这些 token 的开销已经发生，也不返回。它控制的是"从哪停"，不是"省 token"。
Q4：JSON 输出被截断怎么兜底？
检测 finish_reason=length；策略包括：调大 max_tokens、让模型输出更紧凑的 JSON、流式中途检测并用代码补全括号，或携带已生成部分做续写重试。
Q5：为什么推理模型的输出"答案很短"？
很可能 max_tokens 预算被思维链 token 耗尽，思考完没额度输出最终答案。给推理模型要显著调大输出预算。
