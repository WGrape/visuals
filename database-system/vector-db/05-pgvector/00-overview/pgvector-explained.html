①扩展身份带来的优势与局限

pgvector 不是「又一个向量数据库」，它是 Postgres 的一个扩展。这个身份决定了它全部的优势和全部的局限：向量和业务数据在同一个事务里、同一个库里、同一套备份权限体系里；但也因此，它的向量检索性能永远追不上为此重写存储引擎的专用库。

它成为当下默认选择的原因很朴素：如果你的数据量在千万级以内、已经在用 Postgres，引入一个新系统的总成本（运维、同步、一致性、权限、备份）通常远大于性能收益。

你在意的事pgvector 怎么做专用向量库怎么做
数据一致性同一个事务，无需同步两侧需要业务层双写或 CDC 同步
过滤条件就是 SQL WHERE，任意复杂条件专用的过滤语法，能力受产品限制
既有体系复用备份、权限、监控、连接池另建一套运维体系
向量检索性能中（千万级内够用）高，为向量重写的存储引擎
索引构建速度慢（HNSW 构建可能数小时）快，支持并行与增量
超大规模亿级基本不现实可水平扩展

②四种向量类型与 2000 维硬限制

pgvector 用列类型表达精度与形态，共四种：

类型含义可建索引的维度上限典型用途
vector(n)float32 向量2000通用，维度不高时
halfvec(n)float16 半精度40003072 维大模型向量的唯一出路
bit(n)二值向量64000二值量化后检索
sparsevec(n)稀疏向量（存非零项）1000 个非零项SPLADE 类学习型稀疏检索
最常见的报错：column cannot have more than 2000 dimensions for hnsw index。OpenAI 的 text-embedding-3-large 默认 3072 维，直接用 vector(3072) 建索引必然失败。两个解法：用 halfvec(3072)，或调用时指定 dimensions=1536 降维。

③距离算子与索引 ops 的匹配

pgvector 的距离用操作符表示，且索引必须匹配对应的 ops 类，写错就用不上索引：

操作符距离索引 ops 类注意
<->欧氏距离（L2）vector_l2_ops——
<#>负内积vector_ip_ops返回负值，排序要 ORDER BY x <#> q 才是取大
<=>余弦距离vector_cosine_ops= 1 - 余弦相似度
<+>L1 曼哈顿vector_l1_ops0.7+ 支持
<~>Hammingbit_hamming_ops仅 bit 类型
余弦距离排序有两个等价写法，但只有一种能走索引：ORDER BY emb <=> $1（走 vector_cosine_ops）；写成 ORDER BY 1 - (emb <=> $1) DESC 往往退化为全表扫描 + 排序。

④只有两种索引，选择很简单

pgvector 只有两种索引，选择比专用库简单得多：

索引建索引速度查询速度内存适用
HNSW慢（数据量大时数小时）快高（索引常驻）默认首选；查询延迟敏感
IVFFlat快中低数据量大、构建窗口短、可接受召回波动
无索引（精确）——慢（全表扫）无数据量小、要求 100% 召回、做 ground truth
一个实用顺序：数据量 < 10 万先不建索引（顺序扫描往往比索引还快且召回 100%）；10 万以上建 HNSW；HNSW 构建窗口不可接受时改 IVFFlat。

⑤什么信号说明该迁走了

下列信号出现任何一个，说明该评估迁移到专用向量库了：

  • 向量条数超过 1000 万，或单表向量列占用超过实例内存的一半
  • p99 检索延迟要求 低于 10 ms，而当前 HNSW 已调到 ef_search 上限仍达不到
  • 需要 亿级规模，或需要按业务维度独立扩展查询能力
  • HNSW 重建窗口已经长到无法在维护窗口内完成（通常意味着 > 500 万条）
  • 写入吞吐成为瓶颈：向量插入 + HNSW 维护把主库拖慢，影响 OLTP 业务
  • 需要原生的多副本读扩展、分片、或跨区域部署
反过来也有大量场景根本不需要向量数据库：向量条数在十万级、QPS 不高时，Postgres 全表扫描加排序完全够用，此时引入专用库纯属增加复杂度。先量级、后选型，不要先选型再找理由。

⑥速记卡

它是什么

Postgres 扩展，不是独立数据库。

最大优势

与业务数据同事务，过滤就是 SQL WHERE。

最大限制

索引维度上限：vector 2000 / halfvec 4000。

3072 维怎么办

用 halfvec 或调 API 降维到 1536。

两种索引

HNSW（快但建得慢）与 IVFFlat（建得快但召回波动）。

小数据不建索引

< 10 万条顺序扫描常更快且召回 100%。

排序写法

余弦必须 ORDER BY emb <=> $1 才走索引。

迁移信号

千万级、p99 < 10ms、重建窗口不可接受。

pgvector 的正确用法是「先证明自己不够用，再迁走」。千万级以内的 RAG，它的性价比通常高于任何专用向量库。
