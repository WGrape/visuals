什么时候适用？

判断信号：流量超过容量或非核心能力过载，必须保护关键业务。

  • 秒杀入口按令牌桶限制请求
  • 推荐模块过载时只保留下单
  • 高峰期对低优先级接口返回简化结果

和相近方案怎么区分？

相近方案选择边界
限流决定哪些请求可进入，超额请求会被拒绝或排队。
降级接受请求但减少可选功能；二者可同时使用。

最小伪代码

if not bucket.tryTake(userId):
  return TooManyRequests(retryAfter=1s)
result = payment.process(order)
if recommendation.overloaded():
  return response(result, recommendations=[])
return response(result, recommendation.fetch(order))

边界：限流拒绝入口流量，降级缩减功能；需明确保护目标、优先级和用户可接受的结果。

限流算法 Rate Limiting

限流决定『放多少进来』

限流：在入口控制单位时间请求量，保护后端不被冲垮。令牌桶（有突发容量）与漏桶（平滑恒定速率）最常用；分布式场景需借助 Redis/网关统一计数。

降级策略 Degradation

  • 弃车保帅：关闭非核心功能（如推荐、评论），保住下单/支付。
  • 返回兜底：缓存值、默认值、静态页。
  • 读降级：查不到走默认；写降级：先入队异步处理。

三者配合

限流挡在门口 → 熔断切断故障依赖 → 降级保证核心可用。三者是高可用三件套。

面试高频问答

Q：令牌桶和漏桶分别适合什么？
A：令牌桶允许一定突发（攒令牌），适合有正常尖峰的 API；漏桶强制恒定速率输出，适合需要平滑流量的下游（如保护数据库写入）。
Q：限流应该放在哪一层？
A：越靠前越好：网关/接入层做全局限流，服务内再做更细的（按用户/按接口）限流，形成多层防护。
