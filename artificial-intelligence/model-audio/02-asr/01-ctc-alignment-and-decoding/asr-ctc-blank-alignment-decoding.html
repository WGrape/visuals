ASR 的 CTC 对齐与解码：为什么“妈”和“妈妈”需要空白符

从逐帧概率到文字序列，手推 blank、重复合并、路径求和与流式识别的边界。

声音帧比文字多得多

一句“你好”可能持续半秒，声学编码器每隔十几毫秒输出一组特征，得到几十个时间步；最终只有两个汉字。训练数据往往给出整句转写，却没有每个字从哪一帧开始、在哪一帧结束的人工标注。CTC 把“帧与字如何对齐”当作隐藏路径：每个时间步预测词表中的符号或专门的空白符 blank，再把一条路径折叠成最终文字。这个 blank 表示当前时间步不额外输出字符，不是句子里的空格或静音标签。

CTC 常在声学模型之上作为训练目标，模型可以先用卷积或 Transformer 处理上下文。音频采样率、分帧窗口、下采样倍率和输出词表共同决定时间步数；时间步必须足以容纳目标序列，尤其是连续重复的字。只看到最终文字会掩盖对齐和概率分布，因此诊断时要保留帧级或片段级的预测信息。

图解：一条 CTC 路径怎样变成文字

沿箭头逐步核对输入、变换和输出；下面的推演可以逐步切换。

手推“你好”和“妈妈”

折叠规则的顺序很重要：先把连续相同的非 blank 符号合并，再删除 blank。例如路径“_、你、你、_、好、好、_”先把相邻两个“你”合成一个、两个“好”合成一个，删除 blank 后得到“你好”。若目标是“妈妈”，路径“妈、_、妈”会保留两个“妈”，因为 blank 把重复符号隔开；路径“妈、妈”则只会得到一个“妈”。这里下划线只是本课表示 blank 的记号。

一个目标句可以由很多路径得到。例如“你、_、好”和“你、好、好”都折叠为“你好”。CTC 训练关注所有能折叠到目标句的路径概率之和，而不是只强迫模型学习一条固定对齐。这样不需要逐字时间戳，但也意味着最可能的单一路径未必对应概率最大的整句。

贪心与束搜索差在哪

贪心解码每个时间步只挑概率最高的符号，然后折叠，速度快、实现简单。束搜索保留若干有希望的前缀，累积不同对齐路径的概率，再结合语言模型或词典约束选择结果。若某一时刻“北京”和“背景”的声学概率接近，后续上下文可能改变整句排序；过早丢掉次优前缀，就无法利用这个信息。束宽越大通常计算和延迟越高，收益也依模型与场景而变。

“加大束宽就一定更准”也不成立：语言模型可能把罕见人名改成常见词，领域词表错误会放大偏差。要在姓名、数字、命令词和噪声场景分别测字错率与关键字段准确率，避免总体平均掩盖业务损失。

路线核心依赖工程取舍
CTC对齐路径求和；帧级符号与 blank训练目标清楚，搜索可简单也可配语言模型
Transducer声学帧与已输出前缀适合流式设计，训练与解码资源更复杂

与流式识别的关系

流式 ASR 要在句子尚未结束时输出部分结果。声学模型若依赖未来若干帧，必须等这些帧到达；束搜索前缀也可能被后续声音改写。因此屏幕上的“临时转写”与“最终结果”应区别展示。用户说“妈……”时，系统不能因为当前只看到一个“妈”就断言不会出现第二个“妈”；后续 blank 和帧序列可能把结果扩成“妈妈”。

端点检测决定何时认为一句话说完，CTC 本身不等于端点检测。若静音阈值过短，会把一句话切断；过长则让最终文字迟到。产品需同时记录首字出现时间、最终结果时间、修订次数和整句准确率，而不只报告一个模型推理耗时。

CTC、Transducer 与注意力路线

CTC 的帧输出在给定声学表示后采用较强的条件独立假设，路径求和与解码相对清晰；Transducer 让输出依赖已有文字前缀，常用于低延迟流式识别，但训练和搜索更复杂；注意力编码器解码器直接建模输出序列，也可以做流式变体，但具体延迟取决于架构和未来上下文。三者不是“新模型全面替代旧模型”的单线进化，取舍还包括设备算力、目标语言和领域词。

同一音频若被错误重采样、截断或做了与训练不一致的前处理，换解码算法也救不了。评估应固定采样率、切分、标点后处理和词表版本，才能把提升归因到模型或搜索策略。

排障与验收

先抽取一个错误样本，写出原始音频、人工转写、逐帧最高符号、折叠结果与束搜索候选。若重复字被吞，检查 blank 概率、下采样后时间步与解码折叠顺序；若专有名词被改写，比较纯声学候选和语言模型重排；若最终字对但延迟高，查未来上下文、束宽与端点等待。修复后在相同音频集合上同时比较字错率、关键字段命中率、首字延迟和最终延迟。

保留可解释的错误分类比只看“准确率 95%”更有用。替换、删除、插入三种错误可能由不同环节造成；本课的“妈妈→妈”更像删除一个重复字，而人名误识别可能涉及声学混淆与语言模型偏好。

CTC 的三条规则

概念定义例子
blank（∅）词表中的空标签，表示「这一帧不输出新字符」词表索引通常为 0
多对一映射多条对齐路径折叠后得到同一个标签序列∅aa∅b 与 a∅ab∅ 都折叠成 ab
折叠规则 B先合并连续重复，再删除 blankaa∅bb → ab；a∅a → aa（blank 隔开的重复不合并）
对齐数量长度 T 的帧序列对长度 L 的标签，路径数为组合量级T=100、L=20 时路径数极大，靠动态规划求和

CTC 损失：L = −log Σπ∈B⁻¹(y) P(π|x)，即对所有能折叠成目标 y 的路径概率求和再取负对数，用前向-后向算法在 O(T·L) 内计算。

帧长与词表的量化关系

项典型取值含义
帧率10 ms（每帧 hop 通常 10 ms）1 秒音频约 100 帧
下采样后帧率4 倍下采样后约 40 ms/帧1 秒音频约 25 帧（Conformer 常见）
词表规模中文字符级约 4000~6000；英文 BPE 约 几百~数千决定 softmax 维度
输出张量形状(T, batch, vocab_size)CTC 要求 时间维在前
对齐可行性前提T ≥ 目标标签长度 L否则无法对齐，loss 为 inf

硬约束：T ≥ L（帧数要多于标签数），因为每个字符至少要占一帧，重复字符还要额外插 blank。若不满足，CTC 损失为无穷大。

可运行的 CTC 代码

CTCLoss

import torch, torch.nn as nn

# 词表：index 0 必须是 blank
vocab_size, T, N = 5000, 100, 4          # 帧数 100，batch 4
blank_id = 0

log_probs = torch.log_softmax(torch.randn(T, N, vocab_size), dim=-1)  # (T, N, C)
targets   = torch.randint(1, vocab_size, (N, 30))                     # (N, S)
input_lengths  = torch.full((N,), T, dtype=torch.long)                # 每样本帧数
target_lengths = torch.randint(10, 30, (N,), dtype=torch.long)        # 每样本标签长度

loss = nn.CTCLoss(blank=blank_id, zero_infinity=True)(
    log_probs, targets, input_lengths, target_lengths)

# zero_infinity=True：把“不可能对齐”产生的 inf 梯度置 0，避免整批被 nan 污染
# 校验：assert input_lengths.max() <= log_probs.size(0)
#       assert (target_lengths <= input_lengths).all()

解码

# 贪心解码：取每帧 argmax -> 折叠（合并重复 -> 去 blank）
def ctc_greedy_decode(log_probs, blank_id=0):
    ids = log_probs.argmax(dim=-1)            # (T,)
    out, prev = [], None
    for i in ids.tolist():
        if i != blank_id and i != prev:       # 跳过 blank；合并连续重复
            out.append(i)
        prev = i
    return out                                 # 注意：合并重复要在去 blank 之前判断

# 束搜索 + 语言模型（torchaudio）
from torchaudio.models.decoder import cuda_ctc_decoder

症状原因处理

loss 不下降blank 概率饱和（模型全输出 blank）检查词表 blank 位置；降低初始 lr；看 blank 占比

input_lengths 报错长度超过实际帧数 T（下采样后）用卷积/下采样后的真实帧数，不是原始采样点数
训练快但识别差缺少语言模型或解码策略太弱加 beam search + LM；或改用 transducer/attention 方案
显存爆T×batch×vocab 三维很大降 batch；按长度排序组批；用帧下采样

深入自检

blank 的作用是什么？

两个：① 让模型可以在「没有新字符输出」的帧上输出 blank（解决帧数远多于字符数的问题）；② 作为分隔符——被 blank 隔开的相同字符不会被合并，所以 a∅a 折叠后是 aa 而不是 a，从而能表达重复字符。

CTC 的损失为什么要对所有路径求和？

因为语音与文本之间没有逐帧标注（不知道每个字符发生在第几帧），CTC 的做法是把「所有能折叠成目标序列的对齐路径」都算作正确，最大化它们的概率之和。这样无需对齐标注就能训练。求和用前向-后向动态规划在 O(T·L) 内完成。

T 必须大于 L 吗？

是的。每个字符至少要占一帧，若出现连续相同字符还需要插入 blank 分隔，因此要求帧数 T ≥ 标签长度 L（更严格地，需满足插入 blank 后的最小长度）。不满足时该样本无法对齐，损失为无穷大，通常需要过滤掉或用 zero_infinity=True 避免污染梯度。

折叠规则的实现顺序是什么？

标准顺序：先合并连续重复的非 blank 标签，再删除所有 blank。关键是「合并重复」要在删除 blank 之前判断——正因为 blank 会打断连续性，a∅a 中的两个 a 才不会被合并。实现时保持 prev 并逐帧扫描即可。

CTC 适合什么场景？有什么短板？

适合：无对齐标注的序列到序列训练、流式/低延迟、模型简单。短板：条件独立性假设（每帧独立预测，无显式语言建模），因此通常需要外接语言模型做束搜索；对长依赖与语言规律建模弱于 attention/transducer 方案；也无法直接给出精确的时间边界（需要强制对齐另算）。

自检

路径“妈、妈”与“妈、blank、妈”会输出同样文字吗？

不会。先合并连续相同符号再删除 blank，前者得到“妈”，后者得到“妈妈”。
