🔗 并查集 Union-Find 详解

近乎 O(1) 判断"他俩是不是一伙的"：路径压缩 + 按秩合并

一句话总结

并查集（Disjoint Set Union, DSU）维护一群元素的分组关系，只支持两个操作：union 合并两个集合 与 find 查询某元素属于哪个集合。它用一棵"代表元为根"的森林表示分组，靠路径压缩和按秩合并两个优化把单次操作压到近乎 O(1)——准确说是反阿克曼函数 α(n)，实际中不超过 5。

🌲

森林表示集合

每个集合是一棵树，树根的编号就是该集合的"代表"。

🔍

find(x)

沿 parent 指针一路向上找根，判断同属一个集合就看根是否相同。

🤝

union(x, y)

把 x 的根挂到 y 的根下面（或反之），两棵树合为一棵。

⚡

两个优化

路径压缩（find 时拉直）+ 按秩/大小合并，缺一不可。

class UnionFind: def __init__(self, n): self.parent = list(range(n)) # parent[i] = i 表示 i 是根 self.rank = [0] * n # 树的"秩"（近似高度） self.count = n # 连通分量个数 def find(self, x): # 路径压缩：把沿途所有节点直接挂到根上 if self.parent[x] != x: self.parent[x] = self.find(self.parent[x]) return self.parent[x] def union(self, x, y): rx, ry = self.find(x), self.find(y) if rx == ry: return False # 本来就同组（可用于判环） # 按秩合并：矮树挂到高树下，避免树长高 if self.rank[rx] < self.rank[ry]: rx, ry = ry, rx self.parent[ry] = rx if self.rank[rx] == self.rank[ry]: self.rank[rx] += 1 self.count -= 1 return True def connected(self, x, y): return self.find(x) == self.find(y)

二、两个关键优化

2.1 路径压缩（Path Compression）

2.2 按秩 / 按大小合并

💡 思路：永远把小树挂到大树下面（或矮树挂到高树下）。这样树的高度增长最慢。
按秩（rank）：rank 近似树高，只有两树 rank 相等时合并后 rank 才 +1。
按大小（size）：记录每个集合的元素个数，永远小的挂大的，同样能保证树高 O(log n)。
⚠️ 两个优化缺一不可：只用路径压缩，最坏仍是 O(log n) 级别；只用按秩合并，树高 O(log n)；两者同时使用才达到 α(n) 的摊还近乎常数。面试手写时两个都写上。

三、典型应用

3.1 判环（无向图）

遍历每条边 (u, v)：如果 u、v 已经连通，说明这条边会形成环；否则 union 它们。

def has_cycle(n, edges): uf = UnionFind(n) for u, v in edges: if uf.connected(u, v): # 两端已同组 → 再连就是环 return True uf.union(u, v) return False

3.2 连通分量计数（LeetCode 547 省份数量 / 200 岛屿）

def findCircleNum(isConnected): n = len(isConnected) uf = UnionFind(n) for i in range(n): for j in range(i + 1, n): if isConnected[i][j] == 1: uf.union(i, j) return uf.count # 剩下的集合数 = 省份数

3.3 Kruskal 最小生成树

把所有边按权重从小到大排序，依次尝试加入：若两端不连通就 union 并累计权重，否则跳过（会成环）。

def kruskal(n, edges): edges.sort(key=lambda e: e[2]) # 按权重升序 uf = UnionFind(n) total, used = 0, 0 for u, v, w in edges: if uf.union(u, v): # 返回 True 表示成功合并（不成环） total += w used += 1 if used == n - 1: # 生成树只需 n-1 条边 break return total

四、复杂度与对比

实现方式find / union 复杂度说明
朴素（不优化）O(n) 最坏树可能退化成链表
仅路径压缩O(log n) 摊还好很多但非最优
仅按秩合并O(log n)树高有界
压缩 + 按秩O(α(n))α 是反阿克曼函数，n 为宇宙原子数时 α ≤ 5，实际视为 O(1)
并查集 vs DFS/BFS：如果关系是静态的一次性查询（边全部给定后问连通性），两者都行。但如果边是动态逐步加入的（每加一条边就问"现在是否成环/有几个连通块"），并查集远优于每次重新 DFS——后者是 O(n) 每次，前者近乎 O(1)。
一句话记住：凡是题目里出现"连通""是否属于同一组""动态加边判断是否成环""合并集合"这类词，第一反应就该考虑并查集。

两种优化与复杂度

优化做法效果复杂度
无优化直接 parent[x]=y可能退化成链O(n)
按秩/大小合并小树挂到大树下树高 ≤ log nO(log n)
路径压缩find 时把节点直接挂到根摊平树O(log n)
两者都用union by size + path compression近乎常数O(α(n))

α(n) 是反阿克曼函数：对于宇宙中所有原子数量级的输入（约 10^80），α(n) < 5。所以实际可以认为并查集的每次操作是常数时间。

并查集实现

class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n          # 按大小合并
        self.count = n               # 连通分量数

    def find(self, x):
        # <strong>路径压缩</strong>：迭代版（避免递归深度问题）
        root = x
        while self.parent[root] != root:
            root = self.parent[root]
        while self.parent[x] != root:      # 第二次遍历：沿途全部挂到根
            self.parent[x], x = root, self.parent[x]
        return root

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False              # 已连通（<strong>可用于检测环</strong>）
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra           # 小树挂大树
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.count -= 1
        return True

# 典型用法：
#   1) 判断连通性：find(a) == find(b)
#   2) 检测环（无向图）：union 返回 False 说明形成了环
#   3) 统计连通分量数：count
#   4) Kruskal 最小生成树：按边权排序后依次 union

常见错误：只写路径压缩不写按大小合并（或反之）。单独用路径压缩的最坏情况仍是 O(log n)，两者组合才有 α(n)。另外递归版 find 在极端链状输入下可能栈溢出，用迭代版更稳。

典型应用与判据

问题如何建模关键
连通性判断边 → unionfind(a)==find(b)
最小生成树 Kruskal按权排序 + unionunion 失败则跳过（成环）
检测无向图环逐边 union返回 False 即有环
动态连通（加边）在线 union不支持删除
岛屿数量相邻陆地 union最后数 count
等式可满足性相等的合并，不等的记录先合并再检查不等

并查集的适用判据：只需要「是否连通」，不需要具体路径，且操作是不断合并。如果需要最短路径 → BFS/Dijkstra；如果需要删除边 → 并查集做不到（它是只增结构，删除需要重建或用其他结构）。

自检 Q&A

Q：路径压缩为什么是摊还 O(1) 而不是每次 O(1)？

A：单次 find 的代价取决于路径长度——第一次访问一条长链时，要遍历整条链才能找到根，代价是 O(链长)。但这次遍历会把链上所有节点直接挂到根，后续访问就都是 O(1) 了。所以「昂贵」的操作只发生一次，摊还到大量后续操作上就是常数。这正是摊还分析的经典案例——不能只看单次最坏，要看一系列操作的总代价。

Q：并查集能处理有向图吗？

A：不能，它只表达「等价关系」（对称、传递、自反）。并查集合并后不区分方向，A 连 B 与 B 连 A 结果一样。有向图的连通性（强连通分量）需要 Tarjan 或 Kosaraju 算法，它们基于 DFS。所以判据是：无向连通 → 并查集；有向强连通 → Tarjan。

Q：需要支持删除边怎么办？

A：并查集天然不支持（合并不可逆）。三种替代——① 离线处理：若所有操作已知，可倒序处理（把删除变成添加），这是「并查集 + 线段树分治」的套路；② 可撤销并查集：记录合并历史，用栈回滚（只能按栈序撤销，不能任意删除）；③ 换用动态连通性算法（如 Euler Tour Tree，实现复杂）。实践中 ① 最常用。

Q：为什么 Kruskal 用并查集而 Prim 不用？

A：因为两者的「加边判据」不同。Kruskal 是全局按权值从小到大选边，需要判断「这条边的两端是否已连通」——这正是并查集的专长。Prim 是从已选集合向外扩展，每次选一条连接「已选」与「未选」的最小边，这个过程是靠优先队列维护的，不涉及连通性判断（Prim 天然不会成环，因为每次只扩展一个新顶点）。

第二层 · 可运行代码与复杂度数字

带路径压缩 + 按秩合并的完整实现

class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))   # 父指针
        self.rank = [0] * n            # 按秩合并：树的高度上界
        self.count = n                 # 连通分量个数，直接维护

    def find(self, x):
        # 路径压缩：把 x 到根路径上的点直接挂到根下
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False               # 已连通，这次 union 无效（可用于判环）
        # 按秩合并：矮树挂到高树下，避免退化成链
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1
        self.count -= 1
        return True

    def connected(self, a, b):
        return self.find(a) == self.find(b)

# 判断无向图是否有环：加边时发现两端已连通，说明有环
def has_cycle(n, edges):
    uf = UnionFind(n)
    for a, b in edges:
        if not uf.union(a, b):
            return True
    return False
操作只用路径压缩只用按秩合并两者都用
find 最坏O(log n)O(log n)O(α(n)) 近似 O(1)
union 最坏O(log n)O(log n)O(α(n)) 近似 O(1)
n 次操作总代价O(n log n)O(n log n)O(n·α(n))
空间O(n)O(n)O(n)

α(n) 是反阿克曼函数，在 n 小于 265536 时 α(n) ≤ 4，所以工程上把带两个优化的并查集单次操作视为 O(1) 是完全合理的。

第三层 · 高频写错的地方

  • 只写路径压缩不写按秩合并：功能正确但最坏情况退化，竞赛或大输入下会超时。
  • 用 size 还是 rank 搞混：两种都能用，size 合并的是「节点数」，rank 合并的是「高度上界」；两者都要求把小的挂到大的下面，写反了优化失效。
  • 忘记初始化 parent[i] = i：少了这步所有点的根都是 0，结果全是「连通」。
  • 判环逻辑写反：find(a) == find(b) 说明两端已经连通，此时再加这条边才形成环，要返回 True。
  • 递归版 find 在 n 很大时爆栈：路径长时递归深度可能很大，改写成 while 循环版本更稳。
  • 二维数组转一维时下标算错：idx = r * cols + c，行列写反不会报错但结果全错。

调试技巧：打印每个集合的 parent 数组，检查根节点数量是否等于期望的连通分量数。

第四层 · 原理与取舍

并查集的两个优化解决的是同一个问题：树退化成链。按秩合并让树「长不高」，路径压缩让已经长出来的链「被压平」。两者叠加才有 α(n) 的复杂度 —— 只用其中一个只能保证 O(log n)。

需求方案复杂度
只判连通、动态加边并查集O(α(n)) 每次
静态图求连通分量并查集或 DFS/BFSO(n+m)
要具体路径DFS / BFSO(n+m)
需要拆集合并查集做不到，换其他结构—
带权并查集（维护相对关系）在 find 时累加权值O(α(n))
路径压缩和按秩合并必须都用吗？

不必须，但建议都用。只用路径压缩在多数数据下已经很快；只用按秩合并能保证 O(log n)。两者叠加才有摊还意义下的 α(n)，而且代码只多三行。

并查集能算连通分量的大小吗？

能。额外维护一个 size 数组，union 时把被合并方的 size 加到新根上，查询时对根节点读 size[find(x)] 即可。注意只有根节点上的 size 是有意义的。

为什么删边不支持？

因为路径压缩是不可逆的操作 —— 它把树压平后，原始结构信息就丢了。要支持删边需要用「可撤销并查集」（记录操作栈，配合分治/回滚），不能就地压缩。
