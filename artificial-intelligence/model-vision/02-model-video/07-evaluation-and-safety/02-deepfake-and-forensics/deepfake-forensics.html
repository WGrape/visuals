检测器发现的是统计线索

检测模型可寻找生成流程留下的频域、空间或时序特征，但传播平台转码、缩放和再次编辑会改变这些痕迹。新的生成方法也可能不符合训练数据分布；检测器的“疑似概率”不是来源身份或事件真相的直接证据。评测应按设备、分辨率、编解码、人物及生成来源分组，记录误报率与漏报率。

交叉核验比单帧截图可靠

可核对签名来源链、拍摄原件、相邻片段、人物与场景是否一致，以及是否存在已公开的原始素材。音频和口型、说话人身份与时间戳可提供辅助证据，但不同步也可能来自普通剪辑、网络延迟或译配。单帧面部边界异常可能是压缩伪影，不能直接下结论。

负责任的结论分级

建议区分“来源已验证”“证据支持经过编辑”“存在异常但无法确认”“来源缺失”。保留检测模型版本、输入、阈值、比对材料和人工复核记录，让结论可复查。对涉及私人个体、选举或突发事件的素材尤其谨慎：误把真实视频判为伪造，同样可能造成现实伤害。

水印或内容凭证若被移除只会使来源更难确认；它们的缺席不是伪造的充分条件。可参照图像溯源专题理解像素水印与签名声明的区别。

为什么检测越来越难

① 泛化差

检测器在训练用的生成模型（如某个 GAN）上能到 99% 准确率，换到另一个模型（或新版本扩散模型）可能直接掉到 60% 以下。这是领域偏移问题，也是目前最大的痛点。

② 压缩与传播

社交媒体必然重压缩，而绝大多数检测线索（尤其高频信号层）在压缩后消失。实测中，同一段伪造视频原图能检出，经微信/抖音转码后检出率大幅下降。

③ 攻防不对称

生成方可以自由迭代（开源模型人人可得），检测方需要追着跑。而且一旦检测方法公开，生成方可以针对性加入对抗损失规避。

④ 误判代价高

误报（把真实视频判为伪造）会造成严重后果——尤其是新闻、司法场景。所以实际部署时阈值必须设得很保守，这又降低了检出率。

深入自检

Deepfake 检测能可靠地识别伪造视频吗？

不能作为唯一依据。当前技术的核心问题是泛化差：检测器在训练所用的生成模型上准确率很高（95%+），但换到没见过的新模型或新版本，准确率可能暴跌。加上社交平台的重压缩会抹掉大部分检测线索，实际线上效果远低于论文数字。所以正确姿态是：把检测结果作为「可疑信号」而非「结论」，结合内容来源、发布者可信度、上下文佐证综合判断。尤其在新闻、司法场景，绝不能单靠算法判定真伪。

为什么视频比图像更容易被检测出伪造？

因为视频多了时间维度，生成器要保持跨帧一致性更难：①时序不连贯——逐帧生成会出现头部姿态微抖动、身份缓慢漂移、边缘闪烁；②生理信号不自然——眨眼频率、呼吸、心跳引起的肤色微变化（rPPG）很难伪造；③运动与光影——转头时的光照变化、头发与背景的交互容易露馅。所以视频伪造检测的有效线索比单张图像多，这也是为什么视频是取证的重点场景。但要注意：顶级生成（尤其端到端视频扩散）正在快速消除这些破绽。

主动防御（水印 / C2PA）为什么比被动检测更可靠？

因为两者的逻辑不同。被动检测是「事后找破绽」——需要猜生成器留下了什么痕迹，而生成器会不断消除这些痕迹，是永远落后的追击战。主动防御是「事前留凭证」——在内容产生时（拍摄或生成）就嵌入水印或签名，并沿着传播链保留。验证时只需要检查凭证，不依赖对生成技术的了解，因此不随生成器进步而失效。代价是需要产业链配合（相机厂商、生成平台、社交平台都支持），这正是 C2PA 这类标准在推动的事。

做内容安全，产品层面应该怎么做？

分层防御：①生成端——强制给 AI 生成内容加水印与标识（很多国家已立法要求）；②上传端——检查内容凭证（C2PA），无可信凭证的内容标记为「来源未知」；③检测端——跑伪造检测模型，但把结果当作风险分而非结论，高风险内容转人工审核或降权；④传播端——标注来源与 AI 生成标识，给用户上下文；⑤人工与流程——重大内容（新闻、财经、司法）必须有人工核实流程。关键是：不要承诺「算法能判定真伪」，而是提供可信的溯源信息与风险提示。

普通用户怎么初步判断一段视频可能是 AI 生成的？

几个可操作的观察点（都不是决定性的，但可综合判断）：①看边缘与细节——耳廓、发丝、牙齿、手指这些细节常被忽略，容易出现畸形或模糊；②看光影一致性——面部光照方向与背景光源是否矛盾；③看眨眼与口型——眨眼频率异常少、口型与声音不同步；④看时序稳定性——面部边缘是否轻微抖动、身份是否有细微漂移；⑤看来源——有无原始出处、是否被多个可信媒体交叉验证；⑥反向搜图——查是否有更早的原始版本。最重要的是：对无法核实来源的煽动性内容保持怀疑。

import cv2, numpy as np
def video_score(path, detector, sample_fps=2, agg="median"):
    cap = cv2.VideoCapture(path)
    fps = cap.get(cv2.CAP_PROP_FPS) or 25
    step = max(1, int(round(fps / sample_fps)))
    scores, i = [], 0
    while True:
        ok, frame = cap.read()
        if not ok: break
        if i % step == 0:
            face = detect_and_align(frame)          # 小脸直接跳过

        i += 1
    cap.release()
    if not scores: return None                      # 无有效人脸 -> 拒答
    return float(np.median(scores) if agg == "median" else np.mean(scores))

深入自检

检测模型和取证分析有什么区别？

检测是给出一个「是否伪造」的概率分数（数据驱动、可自动化、但会过时且可能跨库失效）；取证更强调可解释与可复核——找出具体证据（融合边界、光照不自洽、频域伪影、元数据与发布链路），并能说明判定依据。实际系统通常用检测模型做初筛，人工取证做确认。

为什么压缩会让检测性能大幅下降？

因为很多检测线索存在于高频细节里（融合边界、上采样频谱峰、纹理统计异常），而视频压缩恰恰优先丢弃高频信息。CRF 从 18 提到 32、分辨率从 1080p 降到 224p，都可能让准确率从 90% 以上掉到 60% 左右。因此报告指标必须注明压缩条件。

跨数据集性能下降说明了什么？

说明模型学到的可能是「某类伪造方法的特定伪影」而不是「伪造的本质特征」。训练数据里只见过几种换脸算法时，遇到新方法往往失效。缓解手段是多源训练、域适应/域泛化、以及用更本质的线索（生理信号、几何一致性）。

视频级判定为什么要聚合而不是看单帧？

因为单帧噪声大（模糊帧、遮挡、侧脸都会给出异常分），而伪造在时间维度上通常有持续痕迹。做法是均匀抽帧（如每秒 2 帧）逐帧打分，再用中位数或注意力池化聚合，稳定性显著高于单帧；无效帧（无脸/过小）应直接排除。

为什么要有「不确定/拒答」区间？

因为取证结论代价不对称：误判真视频为伪造可能损害声誉，误放伪造视频也有风险。设置不确定区间把低置信样本转人工复核，比强行二分类更稳妥；同时要给出可解释的热力图与判定依据，便于人工判断与事后复核。
