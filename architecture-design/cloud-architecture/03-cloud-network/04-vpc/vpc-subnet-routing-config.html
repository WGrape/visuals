01CIDR 规划实例

用 10.0.0.0/16 作为 VPC 网段，再拆成多个 /24 子网，每个子网可用 IP 约 251 个（减去网络地址、网关与保留）。

VPC     10.0.0.0/16     (65536 地址)
子网A   10.0.1.0/24   (可用 10.0.1.4~10.0.1.254)
子网B   10.0.2.0/24
子网C   10.0.3.0/24   (预留给数据层)
# 可用 IP = 2^(32-24) - 3 = 253 个
  • 不同层（Web / 应用 / 数据）放不同子网，便于用安全组隔离。
  • 预留一些 /24 给将来扩容，别把 /16 一次用满。

02路由表条目

目的网段下一跳含义
10.0.0.0/16localVPC 内互通，系统自动
0.0.0.0/0Internet Gateway出公网
10.0.0.0/16 之外Peering/VPN跨 VPC 或对端

注意：0.0.0.0/0 指向 IGW 才出公网；只进不出（无此条）的实例就是纯内网。

03安全组 vs 网络 ACL

对比安全组网络 ACL
状态有状态（回包自动放行）无状态（出入都要写）
作用对象实例级子网级
规则只写允许允许+拒绝
默认拒绝一切，显式放行拒绝一切，显式放行

04打通公网与跨 VPC

  • 出网：子网 + NAT 网关 + 0.0.0.0/0→NAT 路由；入网：弹性 IP / ALB 绑定实例。
  • 跨 VPC 互通：VPC Peering（同云）、VPN / 云企业网（跨地域/跨云）。
  • 安全组最小开放：只放通必要端口和来源 CIDR，数据库子网不对外暴露。
问：为什么推荐用安全组而不是 NACL 做主要隔离？

安全组有状态，写一条入站就够了，回包自动放；NACL 无状态要出入都写，容易漏。NACL 适合做整子网级别的「粗粒度防线」。
