📥 缓存读写模式

Cache-Aside / Read-Through / Write-Through / Write-Behind 的选型与对比

📥

Cache-Aside

旁路，最常用

📤

Read-Through

读穿透，缓存自己加载

✍️

Write-Through

写穿透，同步写缓存+库

📨

Write-Behind

写回，异步落库

为什么 Cache-Aside 最流行

简单、可控、缓存失效不影响数据库。读：缓存没有→查库→写缓存；写：先更新库→删缓存(或更新缓存)。

对比

模式写库时机一致性复杂度
Cache-Aside应用自己最终一致低
Read/Write-Through缓存层较高中
Write-Behind异步最终一致高

🎯 面试问答

Q：为什么 Cache-Aside 最流行？
A：简单、可控、缓存失效不影响数据库。
Q：Write-Through 和 Write-Behind 区别？
A：前者同步写库(可靠但慢)，后者异步(快但可能丢)。
Q：写时删缓存还是更新缓存？
A：通常删(懒加载)，避免并发写导致脏数据与双写不一致。
