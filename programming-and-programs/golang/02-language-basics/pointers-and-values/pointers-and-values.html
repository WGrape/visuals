指针基础

& 取地址，* 解引用

指针存的是变量的内存地址；通过指针可以修改原变量，也能在不拷贝大对象的前提下共享数据。

x := 10
p := &x          // p 的类型 *int，指向 x
*p = 20         // 通过指针改原值
fmt.Println(x)  // 20

// 指针的零值是 nil
var q *int       // nil，未指向任何变量
函数传参：值拷贝

为什么有时候改了、有时候没改

传值类型（struct/array）时，函数内改的是副本，不影响原值；传指针或引用类型时，副本仍指向同一份底层数据，所以能「改到」。

func inc(v int) { v++ }          // 改副本
func incp(v *int) { *v++ }      // 改原值

x := 1
inc(x);  fmt.Println(x) // 1
incp(&x); fmt.Println(x) // 2
引用语义类型

slice / map / chan 的头部含指针

它们本质是个「小头部（含指向底层数组/桶的指针、长度、容量）」。传参时头部被拷贝，但头部里的指针仍指向同一底层数据。

func appendTo(s []int) { s = append(s, 1) } // 可能换底层数组，原 slice 看不到
func change(m map[string]int) { m["k"] = 1 } // 改的是同一份桶，原 map 可见

// 安全做法：返回新的 slice
func add(s []int) []int { return append(s, 1) }
何时用指针

经验法则

需要「修改原值 / 避免大对象拷贝 / 表示可空 / 共享可变状态」时用指针；小的值类型直接传值更清晰。

场景建议
修改调用方变量用指针接收者/参数
大 struct（>几百字节）用指针避免拷贝
方法可能修改接收者用指针接收者
小值/想不可变用值
常见坑

nil 指针与逃逸

指针与逃逸的注意点。

⚠️ 解引用 nil 指针会 panic。map 的零值是 nil，读取可返回零值但写入必 panic；slice 的 nil 可直接 append（会分配）。另外，取地址的局部变量可能「逃逸」到堆上，由 GC 管理——这是编译器自动决定的。

指针接收者一致性

一个类型的多个方法，接收者风格要统一（要么全值、要么全指针），混用会让调用方困惑。
