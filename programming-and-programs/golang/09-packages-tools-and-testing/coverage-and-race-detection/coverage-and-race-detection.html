信心来自可观测

覆盖率和竞态检测是 CI 里最该常开的两项：一个衡量「测了多少」，一个捕捉「并发写冲突」。

覆盖率

看哪里没测到

-cover 给出整体比例；-coverprofile 生成明细，go tool cover -func 看逐函数，-html 可视化为网页。

go test -cover ./...
go test -coverprofile=c.out .
go tool cover -func=c.out     # 每函数覆盖率
go tool cover -html=c.out     # 浏览器高亮未覆盖行
竞态检测

专治并发幽灵

-race 在运行时插桩，检测对同一个变量的并发读写且无同步；能抓到大部分数据竞争，但会显著拖慢并增内存。

go test -race ./...

// 典型竞争：两个 goroutine 同时写同一变量
var x int
go func() { x++ }()
go func() { x++ }()   // race detector 会报
实践建议

CI 里默认开

把 -race 放进 CI 的测试步骤；覆盖率设阈值防止退化。竞态检测有开销，本地/CI 跑，生产二进制一般不带。

⚠️ -race 只能发现「实际触发」的竞争，并非证明无竞争；仍要结合设计（channel/锁）消除共享写。
