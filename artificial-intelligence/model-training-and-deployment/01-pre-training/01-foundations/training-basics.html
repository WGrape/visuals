训练基础
训练 vs 推理，以及那个四步循环

在钻进预训练、微调、对齐之前，先把最底层的概念钉死：训练是"造模型"，推理是"用模型"；而无论预训练还是 SFT、RL，底层都是同一个朴素到极点的四步循环。看懂这一页，后面整章都只是这个循环的"规模变体"。

第 1 步 · 一体两面

训练 vs 推理：造模型 vs 用模型

推理是上一个系列的主角——模型权重冻结，来一个请求做一次前向就出结果。训练正好相反：用海量数据一遍遍算损失、调权重，直到模型"学会"我们想要的本事。它们是一体两面。

对比项训练 Training推理 Inference
权重每一步都在更新固定不变
计算前向 + 反向传播只有前向
数据海量训练语料用户的单次输入
并行关注点几千张卡协同跑一个任务单请求低延迟、服务高吞吐
典型问题显存放不下梯度、损失不稳定（loss spike）KV Cache 太大、排队延迟高
优化目标让损失稳稳降下去算得快、算得省
一句话区分：推理是"用已有的脑子想问题"，训练是"把脑子练出来"。本系列讲前者如何被"造"出来；推理的那么多优化（KV Cache、连续批处理、投机解码）都是为了"用"得更省更快，详见本项目的部署章节。
第 2 步 · 核心机制（重点）

那个朴素到极点的四步循环

别被"大模型训练"吓到。无论预训练、SFT 还是 RL，每一轮都只是重复下面四步：拿一批数据算前向 → 比预测和答案的差距（损失）→ 反推每个权重该往哪调（反向）→ 真去调（优化器）。跑上几万亿 token，权重里就存下了规律。

图 1：所有训练阶段共享的通用四步循环（前向 → 损失 → 反向 → 优化器），唯一差别是"数据"和"损失怎么算"
前向传播 Forward
数据从输入层流到输出层，算出模型当前的预测结果（下一个 token 的概率分布）。
损失 Loss
一个数值，衡量预测与标准答案差多远，差得越远损失越大（常用交叉熵）。
反向传播 Backprop
从损失出发，算出每个权重对损失的梯度（gradient）——每个权重该往哪个方向调、调多少。
优化器 Optimizer
拿着梯度真正更新权重的算法：SGD、Adam、AdamW，以及后文会提到的 Muon。

用 PyTorch 写出来就是这几行

# model 是模型，dataloader 提供一批批数据，optimizer 是优化器
for batch in dataloader:
    logits = model(batch["input_ids"])   # ① 前向
    loss = loss_fn(logits, batch["labels"])  # ② 算损失
    loss.backward()             # ③ 反向传播
    optimizer.step()            # ④ 更新权重
    optimizer.zero_grad()        # 清空梯度，准备下一轮
代码层面朴素得和教科书一模一样。真正的复杂度不在循环本身，而在规模：DeepSeek-V3 这个循环要在 2048 张 GPU 上连续跑近两个月，中间任何一环出问题都会浪费大量算力。怎么把数据备好、怎么把计算摊到几千张卡、怎么让损失稳稳降下去，才是后面各篇要展开的真实问题。
第 3 步 · 为什么"阶段"不同

同一个循环，不同阶段只改两样东西

预训练、SFT、RLHF、DPO……听起来天差地别，但落到代码上，只是"喂什么数据"和"损失怎么算"两处不同。理解了这点，整章的"方法"就不再神秘。

阶段数据损失怎么算
预训练海量无标注文本下一词预测的交叉熵（文本自己当标签）
SFT人工问答对同是下一词预测，但只在某些位置算损失（loss mask）
RLHF（PPO）偏好排序 + 奖励模型打分策略梯度，奖励来自外部奖励模型
DPO偏好对（chosen / rejected）一个把"偏好"直接写进交叉熵的闭式损失，无需奖励模型
这页是整章的"地图入口"。顺着循环往回看：数据工程决定喂什么、预训练打地基、后训练调行为、最后 评估 验收——而 分布式训练 解决"放得下、训得快"。
收尾 · 一句话带走

所以，训练到底是什么

训练 = 反复执行"前向 → 损失 → 反向 → 优化器"这个四步循环，用数据把随机初始化的权重一点点调成"会做事的模型"。 它和推理是一体两面：推理权重冻结只做前向，训练每步都在改权重。 预训练、SFT、RL 只是这个循环的数据与损失函数变体—— 复杂度全在"规模"上，不在循环本身。看懂这一页，后面整章都是它的放大版。

训练 vs 推理：两条完全不同的链路

维度训练推理
目标调整参数，最小化 loss用固定参数算出输出
计算方向前向 + 反向传播 + 参数更新只有前向
瓶颈算力 + 显存（要存激活值）显存带宽（decode 时读 KV Cache）
显存量级推理的 8~16 倍1x（基准）
批处理大批次（提高 GPU 利用率）动态批（连续批处理）
数值精度FP16/BF16 + FP32 主权重FP16 / INT8 / INT4（可量化）
失败代价几天训练白跑（要 checkpoint）单次请求失败，重试即可
并行方式数据并行/张量并行/流水线并行/ZeRO张量并行 + 连续批处理

四步循环与显存

# 训练四步循环（所有深度学习框架都是这四步）
for batch in dataloader:
    # 1) 前向：算预测和 loss
    out  = model(batch.x)
    loss = criterion(out, batch.y)

    # 2) 清零梯度（PyTorch 默认<b>累加</b>，不清零就错了）
    opt.zero_grad(set_to_none=True)

    # 3) 反向：算梯度（loss 对每个参数求导）
    loss.backward()

    # 4) 更新参数
    opt.step()
#   可选第 5 步：梯度裁剪（大模型必备）
#   torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)

# 显存账（7B 模型 AdamW 训练，BF16 混合精度）
#   模型参数 BF16      2 x 7e9 = 14 GB
#   梯度     BF16      2 x 7e9 = 14 GB
#   主权重   FP32      4 x 7e9 = 28 GB
#   Adam m+v FP32      8 x 7e9 = 56 GB
#   激活值（与 batch/seqlen 相关）   10~30 GB
#   ---------------------------------------
#   合计 约 120~140 GB  -> 需要 2 x A100 80GB（配 ZeRO/张量并行）

# 对比：7B 推理 FP16 只需 ~16 GB（参数 14GB + KV/激活）

两个最关键的实践：① checkpoint 必须定期存——训练几天崩一次是常态，每次保存要包含模型权重 + 优化器状态 + 当前 step + 随机数种子，否则无法精确恢复；② 混合精度训练（BF16 计算 + FP32 主权重）是标配，省一半显存且更快，BF16 比 FP16 更稳定（指数位更多，不易溢出）——大模型训练基本都用 BF16。

训练稳定性的关键参数

现象原因处理
loss 一步变 nanlr 太大 / 无 warmuplr 降 10 倍；加 warmup；加 grad clip
loss 缓慢震荡lr 偏大或 batch 太小lr 减半 / batch 翻倍
训练后期 loss 突然飙升典型：lr 太大 + 数据里有脏样本降 lr；清洗数据；从最近的 checkpoint 恢复
grad norm 异常大梯度爆炸clip_grad_norm_(1.0)；检查 loss 缩放
BF16 下出现 inf数值溢出用 BF16 而非 FP16；或检查 loss scale
验证 loss 先降后升过拟合早停；加正则；扩充数据

超参与梯度累积

# 关键超参的起始值（可直接套）
#   学习率（Transformer 全参微调）：  1e-5 ~ 2e-5
#   学习率（LoRA）：                  1e-4 ~ 2e-4（比全参大一个量级）
#   学习率（预训练大模型）：          1e-4 ~ 3e-4，配 cosine 衰减到 10%
#   warmup：                          总步数的 1%~5%，或固定 1000~4000 步
#   weight decay：                    0.01（AdamW）或 0.1（BERT 类）
#   grad clip：                       1.0
#   batch size（全局）：              按显存定，越大越稳；小 batch 用梯度累积
#   Adam betas / eps：                (0.9, 0.999) / 1e-8（基本不动）

# 梯度累积（显存不够时的标准做法）
for i, batch in enumerate(loader):
    loss = criterion(model(batch.x), batch.y) / accum_steps   # 注意除
    loss.backward()                       # 梯度累加
    if (i + 1) % accum_steps == 0:
        opt.step(); opt.zero_grad()       # 每 accum_steps 才更新一次
#   效果等价于 batch = accum_steps x 原 batch
为什么反向传播需要存激活值？

因为链式法则要用到每一层的中间结果。算 dL/dW 需要该层的输入激活值和上游梯度，所以前向时必须把每一层的输出保存下来，显存占用与「层数 × batch × seq_len × hidden」成正比。这也是为什么训练显存远大于推理（推理可以边算边丢）。节省的办法：① 梯度检查点（checkpointing）——只存部分层的激活，其余在反向时重算，用 30% 的额外计算换 10 倍显存；② 减小 batch 或用梯度累积。

BF16 和 FP16 有什么区别，该用哪个？

位宽一样（16 位），但分配不同：FP16 = 1 符号 + 5 指数 + 10 尾数，BF16 = 1 + 8 指数 + 7 尾数。BF16 牺牲精度换取与 FP32 相同的指数范围，所以不会溢出，不需要 loss scaling，训练更稳定。代价是精度更低（尾数只有 7 位）。结论：训练用 BF16（A100/H100 原生支持），FP16 只在老卡（V100）上时配合 loss scaling 使用。

训练中断了怎么恢复？

前提是保存了完整的 checkpoint：model.state_dict() + optimizer.state_dict() + scheduler.state_dict() + 当前 epoch/step + 数据加载器的位置（或随机数种子）。恢复时全部 load 回去，并把 dataloader 跳到对应位置（或用 set_epoch + 相同种子重新打乱）。只存模型权重会导致优化器状态（动量、二阶矩）丢失，恢复后 loss 曲线会有跳变。另外建议每个 epoch 结束、或每 N 步存一次，并保留最近 2~3 个版本。
