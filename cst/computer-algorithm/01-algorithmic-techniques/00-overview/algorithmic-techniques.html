第 01 章 · 算法技巧

从问题特征选择算法技巧

技巧不是待背的代码模板：先找到约束，再确定遍历时始终成立的不变量。

核心速览

双指针两个下标同向或对向移动，把 O(n²) 降到 O(n)
滑动窗口维护一段连续区间，右扩左缩
前缀和 / 差分O(1) 回答区间和；区间批量加减
位运算用位掩码表示集合，压缩状态

技巧的本质：把「暴力枚举」缩小成「必要枚举」

几乎所有算法技巧都在做同一件事——证明某些候选根本不可能成为答案，从而安全地跳过它们。暴力法之所以慢，是因为它检查了所有可能；优化的本质是用问题的结构性约束排除掉绝大多数可能。

使用任何技巧前必须回答一个问题：「我凭什么可以跳过这些候选？」如果答不出来，这个优化就是错的。这也是本章页脚那句「先证明每次移动安全，再写优化后的代码」的含义。

技巧一：双指针

用两个下标在数组/链表上移动，代替两层循环。

形态做法典型题
对向双指针left 从头、right 从尾，向中间靠拢有序数组两数之和、反转、回文判定
同向双指针（快慢）两个指针同向走，速度不同链表判环、找中点、删除倒数第 k 个
读写双指针一个读、一个写，原地压缩原地删除指定元素、去重
有序数组两数之和为什么能 O(n)？设 sum = a[left] + a[right]。因为数组有序：sum 太小 → 只有增大 left 才可能变大（减小 right 只会更小）；sum 太大 → 只有减小 right 才可能变小。「有序」这个性质让我们能确定地排除一整行一整列的候选，所以两个指针合计只走 n 步。
双指针成立的前提通常是「单调性」——存在一个量随指针移动而单调变化，从而可以判断该往哪边走。没有单调性就无法确定移动方向，也就无法用双指针。

技巧二：滑动窗口

维护一个连续区间 [left, right]，right 不断右移扩张，当窗口不再满足条件时左移 left 收缩。每个元素最多进出窗口一次，所以是 O(n)。

def min_len_subarray(nums, target):      # 和 ≥ target 的最短连续子数组
    left = total = 0
    best = float("inf")
    for right, x in enumerate(nums):     # 右指针扩张
        total += x
        while total >= target:           # 满足条件 → 记录并收缩左边界
            best = min(best, right - left + 1)
            total -= nums[left]
            left += 1
    return best if best != float("inf") else 0
# 每个元素最多被加入一次、移除一次 → O(n)
适用条件不适用
✅ 求连续子数组/子串❌ 求子序列（不要求连续）→ 用 DP
✅ 窗口的「合法性」随加入/移除单调变化❌ 只增不减的量（如最小值）→ 需配合单调队列
✅ 求最长 / 最短 / 计数❌ 需要「全局最优组合」→ 可能要用 DP
常见陷阱：窗口内维护「最大值 / 最小值」时，滑动窗口不能直接 O(1) 更新（移除的元素可能正是当前最值）。这时要配合单调队列（如「滑动窗口最大值」一题），否则会退化成 O(n·k)。

技巧三：前缀和与差分

前缀和：O(1) 回答任意区间和

预处理 pre[i] = a[0] + … + a[i−1]，则 sum(l, r) = pre[r+1] − pre[l]。预处理 O(n)，查询 O(1)，代价是 O(n) 空间和数组不能频繁修改。

差分：O(1) 做区间批量加减

若要对区间 [l, r] 统一加 v，直接在差分数组上做 d[l] += v; d[r+1] −= v，最后求一次前缀和还原。m 次区间修改从 O(m·n) 降到 O(m + n)。

一句话记忆：前缀和是「查」，差分是「改」。频繁查询区间和 → 前缀和；频繁做区间统一加减 → 差分。两者互为逆运算（差分的前缀和 = 原数组）。

二维扩展：二维前缀和可 O(1) 求任意子矩阵和（容斥原理）；前缀异或可 O(1) 求区间异或（利用 x^x=0），是「子数组异或为 0」类问题的基础。

技巧四：位运算

写法含义典型用途
n & (n−1)清除最低位的 1统计 1 的个数、判断是否为 2 的幂
n & −n只保留最低位的 1（lowbit）树状数组
x ^ x = 0，x ^ 0 = x自反、归零不用额外变量交换、找出只出现一次的数
a ^ b ^ c（无进位加）异或和加法模拟、校验
位掩码 1 << k用整数表示集合状态压缩 DP、子集枚举
位运算最大的价值是「用整数表示集合」。一个 32 位整数可以表示 32 个元素的集合，集合运算（并/交/差/补）都变成单条 CPU 指令，且可以直接作为数组下标或哈希 key——这是状态压缩 DP 的基础（n ≤ 20 左右可行，因为 2^20 ≈ 100 万）。

技巧五：哨兵与哑节点

在链表头前加一个哑节点（dummy head），或在数组两端加哨兵，可以消除对「第一个元素」的特殊判断。

# 删除链表中所有值为 v 的节点：有 dummy 就不用单独处理头节点被删的情况
dummy = ListNode(0); dummy.next = head
cur = dummy
while cur.next:
    if cur.next.val == v:
        cur.next = cur.next.next    # 头节点也能统一处理
    else:
        cur = cur.next
return dummy.next
这是一类通用的「消除边界特判」技巧，不只是链表：二分查找里的左右哨兵、单调栈里预置的「无穷大」，都是同一思想——用一个人造的边界把「特殊情况」变成「一般情况」，代码更短也更不容易错。

🎯 面试问答

Q：双指针为什么能把 O(n²) 降到 O(n)？成立的前提是什么？

A：因为两个指针合计只走 n 步，从不回退，而不是两层循环各走 n 步。成立的前提是单调性——存在一个量随指针移动单调变化，从而能确定地判断该移动哪个指针、并安全排除一整片候选。例如有序数组两数之和：sum 太小就增大 left（减小 right 只会更小），太大就减小 right。没有单调性就无法确定移动方向，也就用不了双指针。

Q：滑动窗口适用于哪些问题？有哪些陷阱？

A：适用：求连续子数组/子串的最长、最短、计数；且窗口的「合法性」随加入/移除单调变化。不适用：求子序列（不连续）→ 用 DP。最大陷阱：窗口内维护最大值/最小值时，被移除的元素可能正是当前最值，无法 O(1) 更新——这时必须配合单调队列（经典题「滑动窗口最大值」），否则退化成 O(n·k)。另一个注意点是窗口收缩要用 while 而不是 if，因为可能要连续移除多个元素才重新合法。

Q：前缀和与差分有什么区别？分别什么时候用？

A：两者互为逆运算（差分数组的前缀和 = 原数组）。前缀和用于「查」：预处理 O(n) 后，任意区间和 sum(l,r) = pre[r+1] − pre[l] 是 O(1)，适合频繁查询、数组不常改。差分用于「改」：对区间 [l,r] 统一加 v 只需 d[l] += v; d[r+1] −= v，m 次区间修改从 O(m·n) 降到 O(m + n)。一句话：频繁查询用前缀和，频繁区间统一加减用差分。

Q：n & (n−1) 有什么用？

A：它的效果是清除 n 的二进制表示中最低位的那个 1。两个经典用途：① 统计有多少个 1——不断执行 n &= n−1 直到 n 变 0，循环次数就是 1 的个数（比逐位检查快，因为只遍历 1 的位数）；② 判断 n 是否是 2 的幂——2 的幂只有一个 1，所以 n & (n−1) == 0（且 n > 0）。类似的还有 n & −n（lowbit，只保留最低位的 1），是树状数组的核心操作。

Q：哑节点（dummy head）解决什么问题？

A：它消除对头节点的特殊判断。删除链表节点时，如果不用 dummy，「被删的是头节点」需要单独一套逻辑（因为头节点没有前驱）；加上 dummy 后，头节点也有了前驱，所有节点都能用同一套 cur.next = cur.next.next 处理，代码更短也更不容易漏 case。这是一类通用的「消除边界特判」思想——二分查找的左右哨兵、单调栈里预置的无穷大，都是同一个套路：用人造边界把特殊情况变成一般情况。

Q：学会技巧后，怎么判断一道题该用哪个？

A：先描述问题特征，再匹配技巧：有序数组 + 两数/配对 → 对向双指针；连续子数组 + 最值/计数 → 滑动窗口；频繁查询区间和 → 前缀和；频繁区间统一加减 → 差分；n ≤ 20 的集合枚举 → 状态压缩（位掩码）；链表判环/找中点 → 快慢指针；具有单调性、能「排除一半」 → 二分。更重要的是先问「我凭什么能跳过这些候选」——答不出来说明这个优化不成立。
