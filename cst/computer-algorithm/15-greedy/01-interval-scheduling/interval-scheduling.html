第 15 章 · 贪心

按结束时间排序，能选就选

活动选择按结束时间贪心并用交换论证证明；最少会议室用开始时间扫描加堆；区间覆盖在右端点放点。三类问题排序键各不相同。

活动选择：按结束时间最早选

有 n 个活动，各占区间 [start, end]，互相不重叠的前提下最多能安排几个？贪心策略：按结束时间升序排序，能选就选。

def max_activities(intervals):
    intervals.sort(key=lambda x: x[1])   # 按结束时间
    cnt, last_end = 0, -float("inf")
    for s, e in intervals:
        if s >= last_end:
            cnt += 1; last_end = e
    return cnt
活动 A[1,3]、B[2,5]、C[4,7]、D[0,6]。按结束时间排序 A(3)、B(5)、D(6)、C(7)。选 A，跳过 B（2<3）、跳过 D（0<3），选 C → 共 2 个。若贪心选「时长最短」会先选 A 然后卡住，同样 2 个；但换成其他数据就可能更差。

复杂度：排序 O(n log n) + 扫描 O(n)。

为什么「最早结束」是对的：交换论证

设贪心选了活动 g（结束最早），任意最优解选的第一个活动是 x。

  1. 因为 g 结束不晚于 x（g 是结束最早的），把 x 换成 g 后，后续活动的开始时间约束只会更宽松。
  2. 所以「g + 原最优解中剩下的活动」仍然是一个合法解，且活动数不变 → 仍然是最优解。
  3. 于是存在一个以 g 开头的最优解，问题规模缩小为「g 之后的子问题」，归纳成立。

这就是交换论证的标准形态：把最优解里的第一个选择换成贪心选择，证明解仍可行且价值不降。关键落脚点是「换完之后对后续的约束没有变紧」。

三类区间问题的不同策略

问题策略数据结构复杂度
最多安排几个互不重叠的活动按结束时间排序，能选就选排序 + 扫描O(n log n)
最少需要几个会议室按开始时间扫描，用堆维护当前会议的结束时间；能复用就复用小顶堆O(n log n)
用最少的点覆盖所有区间按结束时间排序，在每个未覆盖区间的右端点放点排序 + 扫描O(n log n)
合并所有重叠区间按开始时间排序，逐个合并排序 + 扫描O(n log n)

它们长得像，但排序键和决策点不同：要最大化数量就按结束时间排，要最小化资源就按开始时间扫。记混是这类题最常见的错误。

最少会议室：堆的入场时机

import heapq
def min_rooms(intervals):
    intervals.sort(key=lambda x: x[0])
    heap = []                       # 各会议室当前的结束时间
    for s, e in intervals:
        if heap and heap[0] <= s:
            heapq.heappop(heap)      # 最早结束的会议室可复用
        heapq.heappush(heap, e)
    return len(heap)

堆里元素的个数就是同时进行的最大会议数，也即答案的下界；算法每次复用最早空出来的房间，恰好达到这个下界。

第一层 · 概念与判定：三类区间问题与对应贪心

区间题的关键：先认清楚是「选最多」「排最少」还是「合并/求交」，三者的贪心策略完全不同。

问题目标贪心策略排序依据
区间调度（选最多）选出最多的互不重叠区间每次选结束最早且不与已选冲突的按结束时间升序
最少教室 / 分组把区间分成最少的组用最小堆维护各组最后结束时间按开始时间升序
合并区间把重叠的合并成一个能合就合（扩展右边界）按开始时间升序
区间覆盖用最少区间盖住目标段每次选能覆盖当前点且右端最远的按开始时间升序
求交集所有区间的公共部分取 max(left) 与 min(right)—
  • 信号一：「最多能安排几个会议」→ 按结束时间排序 + 贪心。
  • 信号二：「最少需要几个房间」→ 按开始时间排序 + 最小堆（不是贪心选，是模拟）。
  • 信号三：「合并重叠」→ 按开始时间排序 + 线性扫描。

最常见的混淆：「选最多」和「分组最少」是两类问题。前者按结束时间贪心，后者用堆模拟——答案数值上也不相等。

第二层 · 参数·命令·量化：模板与复杂度

三类区间问题的模板

# 1) 区间调度：选最多互不重叠的区间
def max_non_overlap(intervals):
    intervals.sort(key=lambda x: x[1])      # 按结束时间升序（关键）
    cnt, last_end = 0, float('-inf')
    for s, e in intervals:
        if s >= last_end:                   # 不冲突
            cnt += 1
            last_end = e                    # 更新右边界
    return cnt

# 2) 最少教室（会议室 II）：最小堆模拟
import heapq
def min_rooms(intervals):
    intervals.sort(key=lambda x: x[0])      # 按开始时间
    heap = []                               # 存每间房的「当前最后结束时间」
    for s, e in intervals:
        if heap and heap[0] <= s:
            heapq.heapreplace(heap, e)      # 有房间空出来，复用
        else:
            heapq.heappush(heap, e)         # 开新房间
    return len(heap)

# 3) 合并区间
def merge(intervals):
    intervals.sort(key=lambda x: x[0])
    res = [list(intervals[0])]
    for s, e in intervals[1:]:
        if s <= res[-1][1]:                 # 有重叠
            res[-1][1] = max(res[-1][1], e)
        else:
            res.append([s, e])
    return res
算法时间空间关键
区间调度（选最多）O(n log n)O(1)排序按结束时间
最少教室（堆）O(n log n)O(n)排序按开始时间
合并区间O(n log n)O(n)排序按开始时间
暴力（枚举子集）O(2^n)O(n)不可行

量化参考：n=1e5 时 O(n log n) 约 1.7e6 次比较，1 秒内可完成；暴力 O(2^n) 在 n>25 就不可行。

第三层 · 排障与边界：区间题的坑

坑后果正确做法
排序排错了字段整个贪心失效选最多按结束时间；分组/合并按开始时间
边界「相接」算不算冲突差一个结果明确 s >= last_end（相接不冲突）还是 >
把「选最多」和「分组最少」混为一谈答案不同这是两类问题，策略不同
合并时只比较相邻两个漏掉链式重叠用 res[-1] 动态扩展，别只比前一个
区间端点开闭不明确边界错统一用闭区间 [s, e] 并明确语义
  • 排查顺序：先确认问题类型 → 再确认排序字段 → 再确认端点是否相接算冲突 → 最后用最小样例验证。
  • 边界一：「结束时间等于下一个开始时间」通常不算冲突（会议 10-11 与 11-12 可连续），用 >=。
  • 边界二：合并区间时必须用 res[-1][1] = max(...)，因为新区间可能被前一个完全包含。
  • 边界三：带权区间调度（每个区间有权重）时，简单贪心失效，需要 DP + 二分。

对拍验证贪心正确性

# 对拍验证：贪心 vs 暴力（n 小时）
from itertools import combinations
def brute(intervals):
    best = 0
    for k in range(len(intervals) + 1):
        for sub in combinations(intervals, k):
            ss = sorted(sub)
            if all(ss[i][1] <= ss[i+1][0] for i in range(len(ss)-1)):
                best = max(best, k)
    return best

import random
for _ in range(200):
    iv = [(random.randint(0,10), random.randint(0,10)) for _ in range(6)]
    iv = [(min(a,b), max(a,b)) for a,b in iv]
    assert max_non_overlap([list(x) for x in iv]) == brute(iv), iv
为什么「选结束最早的」是最优的？

贪心选择性质：结束最早的区间为后续留下了最大的剩余时间。若存在最优解选了别的区间，把它替换成结束最早的不会减少后续可选数量——于是存在一个最优解包含该选择，递归即得全局最优。

「选最多」和「最少分组」答案有关系吗？

数值上：最少分组数 = 最大重叠数（某一时刻同时进行的区间数）；而最多可挑选数与之无关。例如 [1,3],[2,4],[3,5]：最多选 2 个（[1,3]和[3,5]），最多重叠 2 → 需 2 间房。两者恰好相等但含义不同。

带权区间调度怎么办？

简单贪心失效（权重与时长冲突）。正解是 DP + 二分：按结束时间排序，dp[i] = max(dp[i-1], dp[p[i]] + w[i])，其中 p[i] 是最后一个不与 i 冲突的区间（二分查找）。复杂度 O(n log n)。

把问题描述清楚

有一堆活动，每个占用一段时间区间 [开始, 结束)。你只能干一件事，最多能安排多少个互不重叠的活动？这就是经典的区间调度（活动选择）问题。

为什么「早收工」才是正确的贪心直觉
输入一组区间 [s_i, f_i)，相容 = 不相交。
目标选出最大的相容子集。
贪心准则按结束时间升序逐个考虑，能放就放。
复杂度排序 O(n log n)，之后线性扫描 O(n)。

为什么「最早结束」是对的

用交换论证的思路看一遍，逻辑非常干净：

  1. 设存在一个最优解 OPT（选了最多的活动）。
  2. 我们的贪心选择是 g（结束最早的那个活动）。如果 OPT 里已经含有 g，皆大欢喜，下一步递归处理剩下部分。
  3. 否则 OPT 里一定含某个活动 h 与 g 冲突。因为 g 结束最早，f(g) ≤ f(h)。
  4. 于是把 h 从 OPT 里拿掉、换上 g。数量不变，且 g 收工更早，不会破坏 OPT 里其它活动的相容性。
  5. 这就构造出另一个同样数量的最优解，但它包含了贪心选择。剩下的部分递归同理。
def activity_select(intervals): # intervals: [(start, finish), ...] xs = sorted(intervals, key=lambda x: x[1]) # 按结束时间排 picked, last_end = [], -inf for s, f in xs: if s >= last_end: # 与已选相容 picked.append((s, f)) last_end = f return picked # 时间：排序 O(n log n) + 扫描 O(n) 空间：O(n)（或不计输出则 O(1)）

核心直觉只有一句：为了让后面的机会最多，这一itoil predi时要尽早腾出时间。资源（时间）是共享的、一次性的，占用越少越好。

三个看起来合理但错误的贪心

贪心准则反例直觉为什么错
选开始最早的早上第一个活动一占就是一整天它把最宝贵的时间全吃了
选时长最短的一个极短的活动恰好横跨两个「黄金」时段短不等于位置好，冲突关系才是关键
选冲突最少的一群互不冲突的长活动 vs 少量安排得当的短活动局部社交关系不代表全局最优组合

做贪心题的一条经验：先写三个候选准则，然后为每个准则找一个能把它卡住的反例。能活下来的那个才值得去证明。很多人在这一步偷懒，直接拿第一个想到的准则去写代码，结果样例都过不了。

四个常见变体

变体策略复杂度备注
加权区间调度（每个活动有价值）不再贪心，改用动态规划O(n log n)贪心失效，因为「短而金贵」与「长而普通」难取舍
最少会议室 / 教室安排按开始时间扫描 + 最小堆记录结束时间O(n log n)等价于求「任一时刻的最大并发数」
区间覆盖（用最少线段盖住目标区间）每次选能覆盖当前点的最长线段O(n log n)贪心准则变成「向右延伸最远」
能否排下 k 个活动上面派的贪心，计数即可O(n log n)本质仍是原问题

一个重要的分水岭：一旦给活动加上「价值/权重」，贪心就不成立了，必须上动态规划。这是判断「能不能贪心」的一个非常实用的信号 —— 当选择之间出现了不同维度的权衡，往往意味着需要更一般的方法。

深入自检

为什么按结束时间排序，而不是按开始时间？

因为目标是在时间轴上塞下尽可能多的活动。选择「最早结束」等价于「为后续留出最大的剩余空间」，这个性质是可以不变量地保持下去的。而最早开始只会尽早占用资源，却不保证占用得短。

贪心证明一定要写那么长吗？

面试或写文档时不必像教科书那样完整，但要有两个关键点：贪心选择性质（存在一个最优解包含我的贪心选择）和最优子结构（做出选择后，剩下的是同类型的子问题）。说清这两点，论证就站得住。

这个贪心能不能推广到二维（比如会议室 + 讲师）？

会迅速变难。原问题之所以简单，是因为资源只有一维且结构规整；一旦每个资源都有独立约束，就变成匹配/调度类的组合优化问题，许多版本已经是 NP 难。这时通常要转向近似算法或启发式。

工程上这类模型用在哪？

很常见：会议室与工位排期、CI 流水线任务安排、直播排片、维修与巡检窗口安排、列车与机组排班。真实的业务通常会在纯贪心的基础上叠加优先级、固定时段、最小间隔等约束，此时常见做法是「先贪心出可行解，再用局部搜索或回退修补」。
