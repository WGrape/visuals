第 05 章 · 栈与队列

后进先出与先进先出

理解操作顺序，比记住底层使用数组还是链表更重要。

核心速览

栈 LIFO后进先出：只在栈顶一端进出
队列 FIFO先进先出：队尾进、队头出
双端队列两端都能进出，兼具二者
优先队列按优先级出队，底层通常是堆

先建立直觉：两种排队方式

栈和队列都是「受限的线性表」——它们只比数组/链表少了自由度，却因此更清晰、更安全、更高效。

为什么「限制」反而有价值？因为限制换来的是确定性和 O(1) 的代价。栈只允许在一端操作，所以只需维护一个 top 指针，push/pop 都是 O(1)；队列只需 head/tail 两个指针，入队出队也是 O(1)。自由度越小，能做的优化越多。

操作与复杂度

结构核心操作复杂度底层实现
栈push / pop / top均 O(1)数组（常用）或链表
队列enqueue / dequeue / front均 O(1)循环数组或链表
双端队列 Deque头尾都能 push / pop均 O(1)循环数组或双向链表
优先队列push / pop 最值O(log n) / O(1) 取最值堆
单调栈 / 单调队列在入栈入队时维护单调性均摊 O(1)栈 / 双端队列
队列用普通数组实现的陷阱：不断出队会让 head 一直后移，前面的空间白白浪费，最终「假溢出」。解法是循环队列——把数组看成环，用 (head + 1) % capacity 取模回绕。判空判满通常用「预留一个空位」或「记录元素个数」两种方式。

栈的典型应用

  1. 函数调用栈：每次调用把栈帧压栈，返回时弹出——这就是「调用栈」这个名字的由来，也是递归和栈溢出的根源。
  2. 括号匹配 / 表达式求值：遇左括号压栈，遇右括号弹出比对；表达式求值用「操作数栈 + 运算符栈」（或转后缀表达式）。
  3. DFS 的迭代实现：用显式栈模拟递归，避免递归深度过大导致栈溢出。
  4. 撤销（Undo）：每步操作压栈，撤销时弹出并反向执行。
  5. 浏览器前进/后退：其实是两个栈——后退栈 + 前进栈。
  6. 单调栈：见下节。
# 括号匹配：栈的经典用法
def valid(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    st = []
    for c in s:
        if c in "([{":
            st.append(c)
        elif c in pairs:
            if not st or st[-1] != pairs[c]:
                return False
            st.pop()
    return not st     # 最后栈必须为空（不能有多余的左括号）

单调栈与单调队列

这是两个高频进阶技巧，本质是在入栈/入队时主动维护单调性，从而把暴力 O(n²) 降到 O(n)。

技巧维护什么典型题
单调栈栈内元素保持单调（递增或递减），"破坏单调性的元素直接弹出且不回来"下一个更大元素、柱状图最大矩形、接雨水
单调队列双端队列内保持单调，同时按窗口滑出过期元素滑动窗口最大值/最小值
单调栈为什么是 O(n)？因为每个元素最多入栈一次、出栈一次，永不回头。以「下一个更大元素」为例：遍历数组，栈里存「还没找到更大元素的下标」；遇到新元素 x 时，把所有小于 x 的栈顶弹出——它们的「下一个更大元素」就是 x。弹出去的元素不会再回来，所以总操作次数是 O(n)。
# 下一个更大元素（单调递减栈）
def next_greater(nums):
    res = [-1] * len(nums)
    st = []                      # 存下标，对应值单调递减
    for i, x in enumerate(nums):
        while st and nums[st[-1]] < x:
            res[st.pop()] = x    # x 就是它们的下一个更大元素
        st.append(i)
    return res                   # 留在栈里的说明没有更大的，保持 -1

队列的典型应用

  1. BFS 层序遍历：队列是 BFS 的标准载体——出队一个节点、把它的邻居入队，天然实现「逐层推进」。
  2. 缓冲区 / 消息队列：生产者从队尾入、消费者从队头出，FIFO 保证顺序公平。
  3. 线程池任务队列：任务排队等待空闲线程。
  4. 滑动窗口：窗口左右边界的移动天然是队列的入队/出队。
为什么 BFS 用队列、DFS 用栈？因为队列的 FIFO 保证了「先被发现的先被处理」，于是天然形成「按距离逐层扩散」的效果——这正是 BFS 求无权图最短路的基础。而栈的 LIFO 让算法「一条路走到黑」，符合 DFS 的深入策略。结构的操作顺序决定了算法的遍历顺序。

优先队列：特殊的队列

普通队列按「到达时间」出队，优先队列按「优先级」出队——每次出队的是当前优先级最高（或最低）的元素。

注意：优先队列是抽象接口，不是具体实现。最常见、最高效的实现是堆（插入 O(log n)、取最值 O(1)、建堆 O(n)），但也可以用有序数组或平衡树实现，只是复杂度不同。接口与实现要分清。

典型应用：Dijkstra 最短路、Prim 最小生成树、任务调度（按优先级）、Top-K 问题、事件驱动模拟。

🎯 面试问答

Q：栈和队列的核心区别是什么？分别用在哪？

A：核心区别是出入顺序：栈是 LIFO（后进先出，只在一端进出），队列是 FIFO（先进先出，队尾进队头出）。栈用于函数调用、括号匹配、表达式求值、DFS 迭代、撤销操作、单调栈；队列用于 BFS 层序遍历、消息缓冲、任务排队、滑动窗口、单调队列。关键洞察：结构的操作顺序直接决定算法的遍历顺序——正因为队列 FIFO，「先被发现的先被处理」，才天然形成 BFS 的逐层扩散效果。

Q：为什么 BFS 用队列而 DFS 用栈？

A：因为队列的 FIFO 保证「先被发现的节点先被处理」，于是访问顺序天然按距离分层——第 1 轮出队的是距离 1 的节点，第 2 轮是距离 2 的，这正是 BFS 能求无权图最短路的原因。而栈的 LIFO 让算法总是先处理「最新发现的」节点，形成「一条路走到黑、走不通再回溯」的深度优先行为。结构的出入顺序决定了遍历顺序，这是二者配对关系的本质。

Q：队列用普通数组实现有什么问题？怎么解决？

A：问题是「假溢出」：不断出队会让 head 指针持续后移，前面腾出的空间无法复用，数组看起来满了但其实前面有大量空位。解法是循环队列——把数组逻辑上看成环，指针用取模回绕：head = (head + 1) % capacity。判空判满有两种常见做法：① 预留一个空位（(tail + 1) % cap == head 表示满）；② 额外记录元素个数 size。Python 的 collections.deque 和 Java 的 ArrayDeque 都是循环数组实现。

Q：单调栈是什么？为什么能把 O(n²) 降到 O(n)？

A：单调栈是在入栈时主动维护栈内元素的单调性：新元素入栈前，把所有「破坏单调性」的栈顶元素弹出，且这些元素弹出去就再也不会回来。它是 O(n) 的原因正是这一点——每个元素最多入栈一次、出栈一次，总操作次数线性。以「下一个更大元素」为例：栈里存「还没找到更大元素的下标」，遇到新元素 x 就把所有小于 x 的栈顶弹出（它们的答案就是 x），于是暴力法的 O(n²) 被压缩到 O(n)。同类应用还有柱状图最大矩形、接雨水。

Q：单调队列和单调栈有什么区别？

A：单调栈只在一端操作，用于求「下一个更大/更小元素」这类无窗口限制的问题；单调队列用双端队列，两端都能进出，除了维护单调性外还要按窗口滑动把过期元素从队头移除，专门用于滑动窗口最大值/最小值问题。滑动窗口之所以不能直接用普通最值，是因为被移除的元素可能正是当前最值，无法 O(1) 更新；单调队列通过「入队时从队尾弹出所有更差的候选」，保证队头始终是窗口最值，且每个元素进出一次，整体 O(n)。

Q：优先队列和堆是一回事吗？

A：不是。优先队列是抽象数据类型（接口），定义「插入元素」和「取出优先级最高的元素」两个操作；堆是实现它的一种具体数据结构（最常见也最高效的一种）。优先队列还可以用有序数组（插入 O(n)、取最值 O(1)）或平衡搜索树（全 O(log n)）实现，只是复杂度不同。工程上二者常被混称，但概念上要分清：一个是「要做什么」，一个是「怎么做」。
