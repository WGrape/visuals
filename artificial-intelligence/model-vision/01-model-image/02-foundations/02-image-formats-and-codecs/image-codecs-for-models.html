图像格式与编解码：模型输入之前发生了什么

从文件字节到像素张量，辨别压缩、透明度和色彩转换对模型的影响。

学完能解释什么

  • 区分文件格式、编解码器与解码后的像素表示
  • 解释有损压缩和色度抽样为何影响小字与细纹理
  • 设计可复现的方向、色彩和透明度预处理

逐步看机制

文件不是现成的 RGB 张量

文件包含容器头、元数据与压缩数据；先根据格式选择解码器，不要按后缀臆测真实编码。

三层概念别混用

格式是文件的组织方式，编解码负责压缩与恢复像素，张量是模型真正处理的数值数组。同为 1024×1024 的图像，PNG、JPEG、WebP 和 AVIF 文件大小不同，解码后却可能得到同形状的张量；数值也未必完全相同。有损压缩会改动像素，无损压缩不会在其支持的像素定义下故意丢弃信息。

JPEG 常用变换、量化和色度抽样压缩自然照片，无法保留透明通道；PNG 适合图标、截图和需要透明的素材；WebP/AVIF 可在特定质量下节省带宽，但实际耗时和兼容性仍需实测。

细节什么时候会被压没

色度抽样例如 4:2:0 减少色彩采样密度，对自然照片常可接受，却可能伤害彩色细字、边缘和 OCR。低码率有损压缩产生的振铃与块效应会影响检测或分割边界。模型若只在高质量 PNG 上训练、在重压缩图片上推理，准确率下降不能简单归咎于网络结构。

比较格式时控制原图、分辨率、色彩空间和主观/任务质量；把压缩后的样本加入验证集，按质量档位测模型性能，不能只报文件体积。

可复现的图像入口

  1. 识别实际格式并限制异常尺寸与解码资源；不要信任文件后缀。
  2. 处理 EXIF 方向、ICC 色彩配置、alpha 合成及 RGB/BGR 通道顺序。
  3. 明确缩放与裁剪规则，记录归一化均值/方差；训练与线上复用同一逻辑。
  4. 对关键场景（小目标、文字、深色边缘）做压缩质量分组测试。

涉及安全时使用受维护的图像库和输入大小限制；图像元数据可能包含地点等隐私信息。

自检

把 JPEG 改名为 .png，模型输入就变成无损了吗？

不会。改后缀不会改变已经编码的像素或真实格式；必须重新编码，而且之前丢失的细节无法凭改名恢复。

格式不是小事：它决定了模型看到什么

很多人以为「图片格式只是存盘方式，打开都一样」。对模型来说完全不同：一张 Q=60 的 JPEG，8×8 块边界上已经引入了肉眼可见的块效应，高频纹理被抹掉，色度被 4:2:0 抽样砍掉 3/4。这些不是「轻微噪声」，而是直接改变了输入分布。

关键提醒：语义分割的 mask 千万不要存 JPEG。块效应会让边界像素变成中间灰度，one-hot 标签被污染。mask 一律用 PNG（单通道）或 numpy 数组、PNG 索引色。

在模型工程里怎么选

① 训练数据怎么存

  • 照片类：JPEG Q=90-95 或 WebP 有损，体积与画质平衡点。
  • 含文字/线条/UI 的图：PNG 或高 Q 值 JPEG，压缩会毁掉细小文字。
  • 不要对同一批数据反复「打开-保存」，代际劣化不可逆。

② 标注与 mask

  • 分割 mask：PNG 单通道，每类一个灰度值。
  • 检测框：不存图，存 JSON/YOLO txt，避免和图像压缩耦合。
  • 需要 16bit 深度的任务（深度估计、医学）：PNG 16bit 或 TIFF。

③ 数据加载性能

  • JPEG 解码是 CPU 密集操作，容易成为 DataLoader 瓶颈。
  • 方案：提高 num_workers；或用未解码缓存（如 LMDB/TFRecord/Mosaic 的 raw bytes）。
  • 不要盲目转成「未压缩原始数组」，磁盘 IO 会反过来成为瓶颈。

④ 推理与传输

  • 上传端：客户端压缩到长边 ≤ 模型输入尺寸即可，省带宽。
  • 服务端：解码后立刻转 RGB 张量，尽量只解码一次。
  • 返回结果图用 JPEG/PNG，缩略图用 WebP。

深入自检

用 JPEG 训练会不会让模型变差？

轻度压缩（Q≥90）影响通常很小，甚至有正则化作用；重度压缩（Q≤50）会明显损伤小目标与纹理类任务。但如果训练用 JPEG、部署时输入也是 JPEG，分布一致反而更稳——最忌讳训练用高质量、线上喂重度压缩图。

为什么分割 mask 用 JPEG 存会出问题？

JPEG 是有损的，边界处会产生过渡灰阶，原本 0/1 的标签变成 0.37、0.82 这类中间值，模型会学到模糊边界，mIoU 明显下降。同时块效应会在 mask 内部引入噪点。

WebP/AVIF 值得全面替换 JPEG 吗？

看链路兼容性。存储与带宽敏感（CDN、移动端）收益明显；但若你的标注工具、数据集格式、推理 SDK 对格式支持不全，替换带来的工程成本可能大于省下的存储。建议新项目默认 WebP，老项目渐进替换。

图片读到内存后，格式还有区别吗？

解码成 RGB 数组后就没有「格式」了，只有像素值。区别只在于解码出来的像素是什么——JPEG 解码出的像素已经带了压缩伪影。所以格式的影响发生在解码之前，一旦解码完成就固化在像素里了。

如何快速判断一批训练图是否被过度压缩？

三个信号：① 放大看平坦区域（天空、墙面）是否有 8×8 块状噪点；② 看细线条文字边缘是否有振铃；③ 统计文件平均字节/像素比，低于 0.1 通常说明压得较狠。

16bit 医学/遥感图怎么喂给普通模型？

需要先做窗口化（windowing）把 12-16bit 映射到 8bit 或归一化浮点：截取有意义的灰度区间（如 CT 的 HU 窗宽窗位），再线性映射到 0-255。直接截断或简单除以 65535 会损失绝大部分对比度。
