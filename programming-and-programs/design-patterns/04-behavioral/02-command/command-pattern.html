🎮 命令

把一次操作包装成对象，方便排队、记录和撤销。

一句话记住遥控器按钮只知道“执行命令”，不关心灯或空调怎样工作。
问题从哪来图解协作动手试一试伪代码选型与边界
01 · 从问题出发

为什么会需要这个模式？

编辑器按钮直接操作文档，若要支持撤销、快捷键和操作历史，每个入口都需重复逻辑。

编辑器有工具栏按钮、快捷键、菜单入口都要执行“插入文本”。若三个入口直接改文档，后来要加撤销和操作历史，就要分别改三个入口，还可能行为不一致。

😵 直接写会怎样

button.onClick = () => doc.insert(cursor, text)
shortcut.onPress = () => doc.insert(cursor, text)
menu.onSelect = () => doc.insert(cursor, text)

💡 关键转折

命令对象保存接收者与参数，提供 execute；需要撤销时再定义 undo。

把“做什么”和“由谁触发”分开：触发器只持有 Command，命令保存执行所需的接收者与参数。

04 · 从图到代码

最小伪代码：把变化留在正确的位置

class InsertTextCommand {
  constructor(doc, pos, text) {
    this.doc = doc; this.pos = pos; this.text = text
  }
  execute() { this.doc.insert(this.pos, this.text) }
  undo() { this.doc.delete(this.pos, this.text.length) }
}
cmd = new InsertTextCommand(doc, cursor, "Hello")
cmd.execute()
history.push(cmd)
// history.pop().undo()

读代码时抓住三件事

  1. Command 保存接收者与参数，所以稍后仍能执行。
  2. execute 只表达一次操作，不依赖按钮来源。
  3. undo 不等于自动回滚，必须设计对应逆操作和状态快照。

换个业务场景，还能认出来吗？

任务队列可把发送邮件命令排队执行；但队列化命令要考虑序列化、重试和幂等，不要把持有内存对象的命令原样跨进程发送。

05 · 用对边界

什么时候用，什么时候收手？

判断信号

操作需要排队、记录、重放、撤销或被多种入口触发

三个具体场景

  • 编辑器插入文本后撤销
  • 菜单和快捷键执行同一操作
  • 任务队列保存待执行任务

不适合或要小心

撤销需要保存足够的前置状态；并非每种操作都能简单逆转，例如外部付款要用补偿操作。

外部副作用不一定可逆；撤销需保存足够状态或定义补偿

最容易混淆的相邻模式

模式真正的区别
备忘录保存状态快照供恢复；命令保存操作及可选逆操作。
策略选择一种算法完成当前任务；命令描述一次具体请求，可排队、记录、撤销。

区分时问自己：要保存“一次操作”，还是保存“某一刻的状态”？

落地前检查

  • 测试多个触发器执行同一个命令结果一致。
  • 撤销删除类命令前保存原数据。
  • 对支付等不可逆副作用使用补偿动作并处理重复执行。
06 · 自己说一遍

两道检验理解的小题

撤销删除文本时为什么要保存原文？

没有原文就无法恢复被删除的内容。

为什么付款命令的 undo 不能简单执行“负数付款”？

真实付款已产生外部副作用；撤销通常是退款等新的业务操作，必须考虑失败和幂等。
