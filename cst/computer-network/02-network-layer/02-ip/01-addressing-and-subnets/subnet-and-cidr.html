⚡ AND 运算规则：IP 和子网掩码逐位做与运算
规则
1 AND 1 = 1

结果

💡 主机号 = IP 地址中子网掩码为 0 的那部分。这里主机号就是最后的 .100（二进制 01100100）
⚠️ 主机号的特殊规则
主机号 含义 例子（/24 子网下） 用途
全部为 0 网络地址（网络号本身） 192.168.1.0 标识这个子网本身，不能分配给设备
全部为 1 广播地址 192.168.1.255 向子网内所有设备发消息，不能分配给设备
其他值 可分配的主机地址 192.168.1.1 ~ 192.168.1.254 分配给你的电脑、手机、服务器等设备
⚠️ 所以 /24 子网虽然有 256 个地址（0~255），但可用主机数 = 256 - 2 = 254 台
📝 计算公式
核心公式
网络号 = IP 地址 AND 子网掩码 （逐位与运算）
主机号 = IP 地址 AND (~子网掩码) （掩码取反后与运算）
广播地址 = 网络号 | (~子网掩码) （网络号 + 主机号全置1）
可用主机数 = 2^(32-n) - 2 （n=CIDR位数，减去网络地址和广播地址）
网关 = 网络号 + 1 （通常是网络号的下一个地址，但不是绝对的）
🧮 分步计算示例
题目：IP = 192.168.1.100，子网掩码 = 255.255.255.0（即 /24）
Step by Step
① 转二进制：IP = 11000000.10101000.00000001.01100100
② 转二进制：掩码 = 11111111.11111111.11111111.00000000
③ AND 运算：逐位相与 → 11000000.10101000.00000001.00000000
④ 转回十进制 → 网络号 = 192.168.1.0
⑤ 主机号部分 = 掩码为0的位 = 00000000.01100100 → 主机号 = 100
⑥ 广播地址 = 网络号 + 主机位全1 = 192.168.1.255
⑦ 可用主机数 = 2^(32-24) - 2 = 254 台（.1 ~ .254）
⑧ 网关通常 = 192.168.1.1

段CIDR地址数常见用途

云上的重要差异：AWS VPC 每个子网会预留 5 个 IP（网络地址、路由器、DNS、未来保留、广播），所以 /24 只有 251 个可用，不是 254。做容量规划时必须算进去——这是云上最常见的踩坑点。

子网计算工具

# AWS VPC 预留规则（/24 子网举例）
# 10.0.1.0   -> 网络地址（不可用）
# 10.0.1.1   -> VPC 路由器（不可用）
# 10.0.1.2   -> DNS 服务器（不可用）
# 10.0.1.3   -> 未来保留（不可用）
# 10.0.1.4   ~ 10.0.1.254  -> 可用（251 个）
# 10.0.1.255 -> 广播地址（不可用）

# Linux 侧计算工具
ipcalc 10.0.1.0/24
# Address:   10.0.1.0
# Network:   10.0.1.0/24
# HostMin:   10.0.1.1
# HostMax:   10.0.1.254
# Broadcast: 10.0.1.255
# Hosts/Net: 254

# Python 标准库就能算（无需装包）
import ipaddress
net = ipaddress.ip_network("10.0.1.0/24")
print(net.num_addresses)                  # 256
print(len(list(net.hosts())))             # 254
print(net.network_address, net.broadcast_address)

# 子网划分：把 /24 分成 4 个 /26
list(ipaddress.ip_network("10.0.1.0/24").subnets(prefixlen_diff=2))
# [10.0.1.0/26, 10.0.1.64/26, 10.0.1.128/26, 10.0.1.192/26]

# 判断 IP 是否在同一网段
ipaddress.ip_address("10.0.1.5") in ipaddress.ip_network("10.0.1.0/24")   # True

子网划分实操：三步法

步骤操作示例（把 192.168.1.0/24 分成 4 个子网）
① 确定需要几个子网按业务/机房/安全域划分需要 4 个（各约 50 台）
② 计算要借几位2^n ≥ 子网数2² = 4 → 借 2 位
③ 得到新前缀原前缀 + 借位数/24 + 2 = /26（每个 62 台）

路由聚合（CIDR 的真正价值）

场景不聚合聚合后收益
4 个连续 /24路由表 4 条1 条 /22路由表缩小 4 倍
8 个连续 /248 条1 条 /218 倍
16 个连续 /2416 条1 条 /2016 倍

CIDR 解决的历史问题：早期互联网用分类地址（A/B/C 类），一个需要 300 个地址的组织只能申请 B 类（6.5 万个），浪费 99%。CIDR 允许任意前缀长度，按需分配。同时带来的路由聚合能力，把全球路由表从爆炸边缘拉了回来——这是 CIDR 1993 年（RFC 1519）被快速采纳的原因。

聚合的前提：地址块必须连续且对齐。192.168.0.0/24 + 192.168.1.0/24 能聚合成 /23，但 192.168.1.0/24 + 192.168.2.0/24 不能——因为 /23 的边界必须是偶数网段开始。规划 IP 时就要考虑这点。

深入自检

为什么 /30 只有 2 个可用地址还能用？

因为点对点链路只需要两个端点——路由器 A 一个 IP、路由器 B 一个 IP，不需要广播（点对点没有广播概念）。所以 /30 的 4 个地址里：网络地址 + 2 个主机 + 广播地址，正好够用且最省。这在早期 IPv4 紧张时非常重要；现代的替代是 /31（RFC 3021），点对点链路只用 2 个地址、无网络/广播地址，利用率 100%。

怎么判断两个 IP 是否在同一子网？

把两个 IP 分别和掩码做按位与（AND），比较结果是否相同。例如 192.168.1.5/24 和 192.168.1.200/24：两者 AND 255.255.255.0 都得 192.168.1.0 → 同网段。但如果是 /25，.5 在 192.168.1.0/25，.200 在 192.168.1.128/25 → 不同网段，需要走路由。关键提醒：掩码不同，结论就不同——问“是否在同网段”必须同时给出掩码。

VLSM（变长子网掩码）有什么用？

允许同一个网络里用不同长度的掩码，按需分配。比如公司有 1 个 /24：总部 100 台 → 给 /25（126 个）；分部 50 台 → 给 /26（62 个）；点对点链路 → 给 /30（2 个）。这样一个 /24 能同时满足三种规模需求，利用率从固定划分的不到 50% 提到 90% 以上。这是现代网络规划的标准做法，也是 OSPF / EIGRP 等路由协议必须支持 VLSM 的原因。

IPv6 还需要 CIDR 吗？

概念相同但实践不同。IPv6 地址空间是 2^128（约 3.4×10³⁸），不再需要“省着用”——标准做法是给每个 LAN 分配 /64（1844 亿亿个地址），家庭宽带通常给 /56 或 /48。固定的推荐是：终端网段一律 /64（SLAAC 无状态配置要求 /64），站点分配 /48，聚合仍用 CIDR 表示法。所以 CIDR 的记法保留，但“精打细算省地址”的动机消失了。
