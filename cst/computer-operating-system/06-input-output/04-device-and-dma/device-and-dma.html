01设备抽象与 DMA

第一层

概念与判定

I/O 是 CPU 与外围设备之间的数据通路。设备千差万别，操作系统用统一的设备模型抽象它们：把设备看成「能读写的对象」，对外暴露文件式接口（Unix 一切皆文件）。

图：CPU 通过控制器与设备交互；DMA 让设备绕开 CPU 直接读写内存。
抽象代表特点
字符设备串口、键盘、终端无缓冲、按字节流式（read/write 顺序）
块设备磁盘、SSD有缓冲、随机寻址、按固定块（512B/4KB）
网络设备网卡走 socket/协议栈，不完全套用文件模型
DMA（Direct Memory Access）是关键：没有 DMA，数据要由 CPU 一个字节一个字节从设备寄存器搬进内存（PIO），CPU 被完全占用。有了 DMA，CPU 只下命令，设备控制器自己把数据搬进内存，搬完发一个中断通知 CPU。

02MMIO / 中断 / IOMMU

第二层

参数·命令·量化

MMIO、端口与中断

机制说明
MMIO设备寄存器映射到物理地址空间，CPU 用普通读写访问
Port I/Ox86 专用 in/out 指令，独立 64K 端口空间
中断号设备用 IRQ/msi 通知 CPU；/proc/interrupts 可见
IOMMU给 DMA 做地址翻译与隔离，类似 MMU 对 CPU
# 看设备与驱动绑定
lspci -nn
ls /sys/class/block/                 # 块设备
ls /sys/class/net/                  # 网络设备
cat /proc/interrupts | head         # 中断分布（每个 CPU 一行）

# DMA 与 IOMMU 状态（Intel VT-d / AMD-Vi）
dmesg | grep -i iommu
# 设备直通（VFIO）需要 IOMMU 开启
没有 IOMMU 的设备直通很危险：恶意/出错设备的 DMA 能读写任意物理内存。云厂商给 VM 做 GPU/网卡 passthrough 必须依赖 IOMMU 做隔离。

03排障与边界

第三层

排障与边界

  • 中断打满单核：高pps网卡把所有中断压到 CPU0，造成处理能力瓶颈。解法：irqbalance 或手动把中断亲和（smp_affinity）分散到多核。
  • MSI-X 比 MSI/INTx 好：支持每队列独立中断，才能做 RSS（接收端缩放）把流量摊到多核。
  • DMA 一致性：设备与 CPU 可能各有缓存，需 dma_sync_* / 一致性映射（coherent DMA）保证可见性，否则读到陈旧数据。
  • 64 位 DMA 掩码：老设备只能 DMA 到低 4GB，配错 dma_mask 会分配失败。
  • 设备树/ACPI：嵌入式靠 device tree 描述设备，x86 靠 ACPI；驱动探测不到常是描述缺失。

04原理与取舍

第四层

原理与取舍

设备模型要平衡「统一抽象」与「设备差异」：统一成文件/接口让应用简单，但忽略了块设备可寻址、网络设备面向报文的本质差异，所以网络走了 socket、块设备走了 bio/request_queue。

方案收益代价
DMA释放 CPU编程复杂、需缓存一致性处理
MMIO简单直接占用地址空间
IOMMUDMA 隔离/虚拟化地址翻译开销
轮询 vs 中断中断省 CPU、轮询低延迟需按负载选择

深入 Q&A

Q：为什么现代网卡要轮询（busy-poll / NAPI）？
A：中断在高速率下会「中断风暴」，每包一个中断 CPU 处理不过来。NAPI 在流量大时切到轮询（一次中断收一批包），流量小时回退到中断省 CPU。

Q：IOMMU 与 MMU 什么关系？
A：MMU 把虚拟地址翻成物理地址（给 CPU）；IOMMU 把设备用的「IO 虚拟地址」翻成物理地址（给 DMA）。二者都提供隔离与重映射。

05速记卡

两类设备

字符（流式）/块（可寻址）/网络（socket）。

DMA

设备自搬数据到内存，完事发中断。

IOMMU

DMA 的「MMU」，做隔离与重映射。

中断风暴

高pps要 MSI-X + 亲和 + NAPI 轮询。

缓存一致性

DMA 后需 sync，否则读到旧数据。
