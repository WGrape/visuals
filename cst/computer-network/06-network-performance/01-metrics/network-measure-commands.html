网络性能实测：iperf3 / ping / mtr 与关键阈值

带宽、延迟、丢包、抖动怎么测，以及它们之间的关系

网络性能iperf3pingmtrRTT
四个指标 iperf3 ping/mtr 指标关系
带宽、吞吐、延迟、丢包、抖动五个指标各管各的。iperf3 测吞吐，ping/mtr 测延迟与丢包，别用 ping 当带宽工具。

01四个核心指标

指标单位测什么
带宽bps链路物理容量（理论上限）
吞吐bps实际跑出来的速率（iperf3）
延迟 RTTms往返时间，主要是物理距离
丢包率%丢的包占比
抖动ms延迟的变化幅度
要点：吞吐永远 ≤ 带宽；延迟主要由光速决定，优化空间有限；丢包靠重传，对吞吐影响最大。

02iperf3 测吞吐

# 服务端
iperf3 -s -p 5201
# 客户端：正向 30 秒、8 并发流
iperf3 -c 10.0.0.1 -p 5201 -t 30 -P 8
# 反向（测上行）
iperf3 -c 10.0.0.1 -p 5201 -t 30 -P 8 -R
要点：单条 TCP 流受窗口限制测不满带宽；用 -P 多流聚合才能压满。CPU 软中断也可能成为瓶颈。

03ping / mtr 测延迟丢包

ping -c 100 10.0.0.1          # 看 avg/min/max RTT 与 loss%
mtr -n -c 100 10.0.0.1       # 逐跳看哪一层开始丢包
要点：丢包率 > 1% 就会明显拖累 TCP 吞吐；RTT 越大，带宽时延积(BDP)越大，需要更大的收发窗口。

04指标之间的关系

关系说明
BDP = 带宽 × RTT决定需要的窗口大小
吞吐上限 ≈ 窗口 / BDP窗口不够则喂不饱带宽
丢包 → 重传 → 有效吞吐骤降高丢包环境别只看带宽
要点：调优顺序：先解决丢包，再看窗口/缓冲，最后才是带宽。长距离链路延迟基本只能认命。

05常见疑问

问：iperf3 测不到网卡带宽？

检查单流 vs 多流(-P)、对端 CPU 软中断瓶颈、以及接收端窗口/缓冲大小。

问：ping 延迟很低但应用很慢？

可能是应用层处理慢或丢包导致的重传，用 mtr 看丢包、用应用层 trace 看耗时分布。

第一层 · 概念与判定

网络测量分四层关注：连通性/延迟/丢包、带宽、连接状态、报文细节，各有权威工具，别用错。

  • 连通/延迟/丢包：ping、traceroute、mtr。
  • 带宽：iperf3（端到端吞吐）。
  • 连接与抓包：ss/netstat、tcpdump、tshark。
  • 判定：用户说「网络慢」先分清是延迟高、丢包还是带宽满。

第二层 · 参数·命令·量化

常用命令：

示例

# 延迟+丢包综合（推荐替代裸 ping）
mtr -n -c 100 target

# 测端到端带宽（一端 -s 服务端，一端 -c 客户端）
iperf3 -s && iperf3 -c server -t 30 -P 4

# 看 established/time_wait 连接
ss -tan | awk '{print $1}' | sort | uniq -c

# 抓特定端口包
tcpdump -i any -nn 'tcp port 443' -w cap.pcap

第三层 · 排障与边界

  • ICMP 被挡误判：防火墙禁 ping 导致「不通」，实际 TCP 端口可达；改用 tcping / telnet 端口验证。
  • iperf3 单流跑不满：单 TCP 流受窗口限制；用 -P 多并发或确认网卡/RTO 限制。
  • 时间不同步：跨机抓包对时差导致时序错乱；先 chrony/ntp 对齐。
  • 本地回环干扰：测本机带宽受 loopback 优化影响，不能代表真实网卡。

第四层 · 原理与取舍

iperf3 用纯数据传输测真实吞吐，比 scp（受加密/磁盘 IO 影响）更准；mtr 把 ping 与 traceroute 结合并持续采样，能区分「哪一跳开始丢包」。tcpdump 是最后手段，开销大、需后处理。工具选择本质是「测哪一层就用那一层的探针」。

为什么测带宽不用 scp？

scp 受 SSH 加密与磁盘读写拖累，测得的是综合瓶颈而非纯网络带宽；iperf3 专测网络层。

mtr 比 ping+traceroute 好在哪？

mtr 持续向每跳发探测并统计丢包率，能定位「丢包发生在哪一跳」，一次性替代两轮操作。
