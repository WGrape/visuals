五阶段路线图

每个阶段都有明确产出物。跳过阶段直接学「高级主题」，往往学完用不上也记不住。

五个阶段各自的重点
①基础能写正确、地道的 Go 代码。
②并发能写并发安全且可控的程序。
③工程能交付可维护、可测试的项目。
④性能能定位并解决性能与稳定性问题。

每个阶段的练手项目

阶段练手项目检验标准
① 基础CLI 工具（待办清单、文件批处理）能拆分模块、写好错误处理与单元测试
② 并发并发爬虫、工作池、限流器能控制并发数、正确退出、无竞态
③ 工程带存储的 REST 服务有分层、有测试、有配置与日志、有 CI
④ 性能对上一步的服务做优化能给出前后对比的基准与 pprof 证据
⑤ 架构多服务协作的小系统有 RPC、有链路追踪、能优雅退出与灰度

项目不要贪大：一个能跑通、能讲清楚、能持续改进的小项目，胜过三个半成品。每完成一个阶段，把上一阶段的项目重构一遍，进步最快。

各阶段的常见误区

基础阶段

  • 用写 Java/Python 的习惯写 Go（比如滥用继承式抽象）
  • 忽略错误处理，习惯性 _ = err
  • 不读官方文档，靠二手博客建立认知
  • 过早追求「优雅」而忽视清晰

并发阶段

  • 以为开了 goroutine 就更快，忽略调度与同步成本
  • 不知道 goroutine 何时退出，造成泄漏
  • 用 channel 解决所有问题，不知道何时该用锁
  • 不看 -race 的报告，凭感觉改

进阶阶段

  • 过早引入框架，标准库还没吃透
  • 只学调优技巧，不先测量
  • 照搬大厂架构给小项目
  • 忽视可观测性，出问题时无从下手

深入自检

需要先学 C 或系统底层才能学好 Go 吗？

不需要。Go 的设计目标之一就是降低门槛。真正需要底层知识的是性能优化与运行时原理阶段，那时可以根据需要补，不必一开始就铺开。

并发难在哪里，怎么练？

难在「正确性不可见」——跑一百次都对不代表没问题。练法是：所有并发代码都开 -race 跑测试；写显式退出的循环；用 goroutine 数监控验证没有泄漏；多看 channel 与 sync 的标准用法模式。

什么时候该学框架？

当你已经能用标准库写出一个完整服务、并且明确感受到重复劳动时。先理解 net/http，再看框架解决了什么，才不会把框架当成黑盒。

性能优化该从什么时候开始学？

能交付稳定功能之后。过早优化会让你在错误的方向上花时间。但「测量意识」要从一开始就培养——写基准、看指标，比起背优化技巧更重要。

怎么检验自己到了什么水平？

用一个问题自检：能否独立把一个需求从「接口设计、数据存储、并发控制、错误处理、测试、日志、部署」完整落地，并能在出问题时用工具定位。能做到就是合格的工程能力。
