什么时候适用？

判断信号：下游持续失败或超时，继续调用会耗尽上游资源。

  • 支付供应商异常时快速失败
  • 推荐服务故障时回退空结果
  • 半开探测恢复后的下游

和相近方案怎么区分？

相近方案选择边界
重试重试尝试克服瞬时失败；熔断在持续失败时停止继续施压。
限流限流按流量控制进入量；熔断根据下游健康状态暂停调用。

最小伪代码

if breaker.state == OPEN:
  if not cooldownExpired(): return fallback()
  breaker.enterHalfOpen(maxProbes=1)
if not breaker.allowRequest(): return fallback()
try:
  result = callDownstream(timeout=500ms)
  breaker.recordSuccess()  // 探测成功可闭合
  return result
catch error:
  breaker.recordFailure()  // 超阈值或探测失败则断开
  return fallback()

边界：熔断不修复下游。阈值、窗口、半开并发和回退结果应按业务影响设置。

三态机 Circuit Breaker

打开态直接拒绝请求，给依赖喘息时间

调用方对某个易失败的依赖加装断路器：关闭态正常放行并统计失败率；超阈值转打开（直接快速失败，不发真实请求，避免线程堆积）；冷却后进入半开试探，成功则恢复，失败则继续打开。

为什么需要它

  • 防止一个慢/挂的依赖耗尽调用方线程池（舱壁外再加一道闸）。
  • 给故障服务恢复时间，而非持续被打。
  • 配合降级返回兜底数据。

面试高频问答

Q：熔断和降级是什么关系？
A：熔断是『切断故障链路』的机制；降级是『切断后给什么兜底』的策略。通常一起用：熔断打开 → 走降级逻辑（返回缓存/默认值）。
Q：熔断阈值怎么设？
A：常见：在 N 秒内失败率超过 X%（如 50%）且请求数达最小样本，则打开。阈值要按依赖的 SLA 与流量调，过严会误伤、过松则不护。
