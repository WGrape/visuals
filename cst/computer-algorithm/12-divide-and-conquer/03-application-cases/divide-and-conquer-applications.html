在合并步骤里顺手拿到答案

逆序对用归并时统计、第 k 大用快速选择做到平均线性、最大子数组必须穷尽跨中点情况、快速幂把指数二分。

逆序对计数：归并时顺手统计

逆序对是满足 i < j 且 a[i] > a[j] 的数对。暴力 O(n²)，用归并排序可以在合并时统计：

def count_inversions(a):
    def sort_and_count(arr):
        if len(arr) <= 1: return arr, 0
        m = len(arr) // 2
        L, c1 = sort_and_count(arr[:m])
        R, c2 = sort_and_count(arr[m:])
        i = j = 0; out = []; cross = 0
        while i < len(L) and j < len(R):
            if L[i] <= R[j]:
                out.append(L[i]); i += 1
            else:
                out.append(R[j]); j += 1
                cross += len(L) - i   # L 中剩下的都比 R[j] 大
        return out + L[i:] + R[j:], c1 + c2 + cross
    return sort_and_count(a)[1]
左边 [3,5]，右边 [1,4]。取 1 时左边剩 [3,5] 两个都比 1 大 → 贡献 2 个逆序对 (3,1)、(5,1)。取 4 时左边剩 [5] → 贡献 1 个 (5,4)。

为什么可以这样数？因为左右各自已经有序，一旦 L[i] > R[j]，L 中 i 之后的所有元素都 > R[j]，所以能一次加一整段，而不是逐个比较。

快速选择：平均线性的第 k 大

找第 k 大不必排完整个数组。快排的划分把数组分成「> 基准」和「≤ 基准」两块，只递归进入包含第 k 大的那一块：

def quick_select(a, k):            # k 从 0 开始
    lo, hi = 0, len(a) - 1
    while lo < hi:
        p = partition(a, lo, hi)      # 随机基准 + 三路划分更稳
        if k < p:   hi = p - 1
        elif k > p: lo = p + 1
        else:       return a[k]
    return a[lo]
  • 平均：T(n) = T(n/2) + Θ(n) → Θ(n)（等比数列求和）。
  • 最坏：Θ(n²)，靠随机化基准规避；需要严格保证时用 BFPRT（中位数的中位数）。

最大子数组：跨中点的第三种情况

最大连续子段和分三种情况：完全在左边、完全在右边、跨越中点。前两种递归求解，第三种只需从中点向左扫出最大后缀和、向右扫出最大前缀和，相加即可——线性。

总复杂度仍是 2T(n/2) + Θ(n) = Θ(n log n)。

实际工程里 Kadane 算法是 O(n) 且更简洁，但分治版本是理解「三种情况必须穷尽」的经典范例——很多分治正确性错误就出在漏掉跨分界线的情形。

快速幂：指数上的二分

算 an：若 n 为偶数则 an = (an/2)²，若为奇数则再乘一个 a。递归深度 log n，总复杂度 Θ(log n)。

def fast_pow(a, n, mod=None):
    res, base = 1, a
    while n:
        if n & 1: res = res * base
        base = base * base         # a, a^2, a^4, a^8 ...
        n >>= 1
        if mod: res %= mod; base %= mod
    return res

它本质上是在指数上做二进制分解，因此也叫二进制幂。矩阵快速幂是同一个思路，能把线性递推（如斐波那契）的第 n 项压到 O(log n)。

分治与动态规划的分界

特征分治动态规划
子问题是否重叠不重叠，各自独立大量重叠，需记忆化
递归树形态树（每层规模减半）有向无环图（重复节点）
典型例子归并排序、快速选择、快速幂背包、LCS、区间 DP
复杂度来源树高 × 合并代价状态数 × 转移代价

分治写成递归却出现重复计算（如朴素斐波那契 T(n)=T(n−1)+T(n−2)）时，复杂度是指数级，这时候它已经不是分治问题，而是动态规划问题。

Karatsuba 原理

# Karatsuba：为什么是 3 次而不是 4 次乘法？
# 两个 n 位数 x = a·B + b,  y = c·B + d   （B = 10^(n/2)）
# 朴素：x·y = ac·B² + (ad+bc)·B + bd    → 需要 4 次乘法：ac, ad, bc, bd
#
# Karatsuba 的关键恒等式：
#   ad + bc = (a+b)(c+d) - ac - bd
# 所以只需 3 次乘法：
#   z0 = ac
#   z2 = bd
#   z1 = (a+b)(c+d) - z0 - z2      ← 用一次乘法换出中间项
#   x·y = z0·B² + z1·B + z2
#
# 递推从 T(n)=4T(n/2) 变成 T(n)=3T(n/2)
#   复杂度：O(n²) → O(n^1.585)
#
# 实践：Python 的大整数乘法在超过 <strong>70 位</strong>时会自动切到 Karatsuba

分治 vs 其他范式的选择

范式适用特征典型问题
分治子问题独立且结构相同排序、最近点对、FFT
动态规划子问题重叠（会重复计算）背包、LCS、最短路径
贪心局部最优能推全局最优Huffman、活动选择
减治只递归一侧二分查找、快速选择

核心判据：子问题是否重叠。不重叠 → 分治（如归并排序的两半互不相干）；重叠 → 必须 DP（如斐波那契的 fib(n-1) 与 fib(n-2) 会重复算 fib(n-3)）。用分治解重叠问题会导致指数级复杂度。

重叠子问题

# 反例：用朴素分治算斐波那契 → O(2^n)，灾难
def fib_bad(n):
    if n <= 1: return n
    return fib_bad(n-1) + fib_bad(n-2)      # 子问题严重重叠

# 加记忆化（自顶向下 DP）→ O(n)
from functools import lru_cache
@lru_cache(maxsize=None)
def fib_good(n):
    if n <= 1: return n
    return fib_good(n-1) + fib_good(n-2)

# 实测：n=40 时，fib_bad 约 1 秒（3 亿次调用），fib_good 约 0.0001 秒
# 差距 <strong>10000 倍</strong>——这就是识别「子问题重叠」的价值

快排最坏情况的形成：每次选到的 pivot 都是最大或最小元素，划分成 1 和 n-1，递归深度变成 O(n)——100 万元素就是 100 万层递归，必然栈溢出。

# 3) 尾递归优化：只对较小的一侧递归，大的一侧循环处理
def quicksort(arr, lo, hi):
    while lo < hi:
        p = partition(arr, lo, hi)
        if p - lo < hi - p:            # 递归处理<strong>较小</strong>的一半
            quicksort(arr, lo, p-1)
            lo = p + 1                 # 大的一半用循环
        else:
            quicksort(arr, p+1, hi)
            hi = p - 1
# 效果：递归深度保证 ≤ log n，栈空间 O(log n)

自检 Q&A

Q：Strassen 算法更快，为什么实际不常用？

A：三个原因——① 常数因子大：Strassen 的加减法次数远多于朴素法，只有当 n 很大（通常 > 几百）时才真正更快，实践中会设阈值，小矩阵仍用朴素法；② 数值稳定性差：误差累积比朴素乘法大；③ 实现复杂且缓存不友好：递归划分导致内存访问模式差。所以它是理论上的重要突破，工程上只在特定大规模场景使用。

Q：分治一定要递归实现吗？

A：不一定。自底向上的归并排序就是迭代的：先两两合并长度为 1 的段，再合并长度为 2、4、8……完全是循环。迭代版的好处是无递归开销、无栈风险，且对链表特别自然（不需要随机访问）。递归版的好处是代码直观。选择上：数组用递归版更常见，链表的自底向上归并是标准做法。

Q：为什么归并排序需要 O(n) 额外空间，快排只需要 O(log n)？

A：因为合并的位置不同。归并排序的合并操作发生在两个已排序的子数组之间，需要一个临时数组把结果装下来，再拷回去——这个临时数组是 O(n)。快排的 partition 是原地交换，不需要额外数组，递归只消耗栈空间 O(log n)。所以内存受限时快排更优；但需要稳定性或保证 O(n log n) 时归并更优（快排最坏是 O(n²)）。

Q：如何在面试/工程中判断这道题该用分治？

A：三个信号——① 问题可以拆成结构相同的子问题（「一半的规模」）；② 子问题的解能合并成原问题的解；③ 子问题之间不重叠（重叠就该用 DP）。经典例子：排序、第 k 大（快速选择）、最近点对、线段树/区间查询、FFT。反过来说，如果拆分后子问题有共享部分，就别用分治——先想记忆化或 DP。

分治题的关键一步：问自己「跨分界线的情况有没有被穷尽」。
