ARP 概述页讲了 IP→MAC 是怎么解析的、免费 ARP、代理 ARP。这一页把它落成可执行的运维：看表、清表、绑定防欺骗、ARP 欺骗怎么查，以及 IPv6 下 NDP 的对应动作。

01查看与清理 ARP / 邻居表

Linux 下 IPv4 邻居缓存用 ip neigh 看，清空某条目会让内核重新发 ARP 请求解析。

# 查看 IPv4 邻居缓存（等价 arp -n）
ip neigh show
# 只看某网卡
ip neigh show dev eth0
# 删除某条目，让它重新解析
ip neigh del 10.0.0.1 dev eth0
# 清空全部（慎用，会触发一波广播）
ip neigh flush all

02静态绑定防 ARP 欺骗

把网关的 IP 与正确 MAC 静态绑定，避免被伪造的 ARP 响应劫持流量。

要点：静态绑定只防「本机被欺骗」；全网防护要靠交换机 DAI + DHCP Snooping，单靠主机绑定挡不住同网段其他主机被劫持。
# 静态绑定（重启后失效，需写进网络配置）
ip neigh add 10.0.0.1 lladdr 00:11:22:33:44:55 dev eth0 nud permanent
# 或写进 /etc/ethers + 启动脚本 arp -f /etc/ethers
# 交换机侧可开 DAI（Dynamic ARP Inspection）做端口级防护

03ARP 欺骗检测

  • arpwatch：监控 MAC↔IP 映射变化，异常变动告警。
  • 定时比对网关 MAC：脚本周期读 `ip neigh` 的网关条目，MAC 变了即报警。
  • arp-scan 全段扫描，列出真实 IP/MAC，与本地缓存交叉验证。
  • 抓包确认：tcpdump 'arp' 看是否有非网关 MAC 在回「我是网关」的应答。

04IPv6 的 NDP 对应动作

IPv6 没有 ARP，改用基于 ICMPv6 的邻居发现（NDP），功能类似但多了无状态地址与路由通告。

对比IPv4 / ARPIPv6 / NDP
解析方式广播 ARP 请求组播邻居请求（更省）
防欺骗DAI + 静态 ARPRA Guard + SeND（少部署）
额外能力仅地址解析还管地址自动配置与路由发现
问：为什么 IPv6 没沿用 ARP？

ARP 是链路层广播协议，和 IPv4 强耦合；IPv6 用 ICMPv6 的 NDP 把「解析 + 地址配置 + 路由发现」统一掉，且用组播替代广播，扩展性更好。

# 查看 IPv6 邻居
ip -6 neigh show
# 看路由器通告（RA）与默认网关
rdisc6 eth0        # 发包请求 RA
ndp -p            # *BSD 风格查看前缀/默认路由

第一层 · 概念与判定：ARP 与 NDP 干什么

两者都是把网络层地址解析成链路层 MAC 地址：ARP 服务 IPv4（广播问「谁有这 IP」），NDP 服务 IPv6（用组播+ICMPv6，功能更全，还管无状态地址/DAD）。

维度ARP（IPv4）NDP（IPv6）
查询方式广播组播（更省）
承载协议独立 ARP 报文ICMPv6
额外能力仅地址解析含 DAD/前缀发现/重定向
表项超时约 60s 后探测靠可达性探测

第二层 · 参数·命令·量化：查看与超时

动作命令看什么
看 ARP/邻居表ip neigh 或 arp -n状态 reachable/stale
手动加静态项ip neigh add 1.2.3.4 lladdr xx dev eth0避免广播

ARP/NDP 邻居表查看与静态绑定

# 查看邻居表（ARP/NDP 统一入口）
ip neigh show
# 输出: 10.0.0.1 dev eth0 lladdr 00:11:22:33:44:55 reachable

# 静态绑定（防 ARP 广播风暴或欺骗）
arp -s 10.0.0.1 00:11:22:33:44:55
# 或
ip neigh add 10.0.0.1 lladdr 00:11:22:33:44:55 dev eth0 nud permanent

# IPv6 同样走 ip neigh（NDP），状态含 stale/reachable/delay

数量级：ARP 表项默认 reachable 约 30–60s 后转 stale 并触发探测；大型二层网里广播 ARP 会形成风暴，静态绑定或 ARP 表上限是关键防线。

第三层 · 排障与边界：四个坑

  • ARP 表被打满：大二层/容器密度高时表项爆了，新解析失败、通信断——调大 gc_thresh 或加静态项
  • ARP 欺骗/中间人：广播模型下伪造应答即可冒充网关——上静态绑定或 DHCP snooping/DAI
  • NDP 不是 ARP 广播：IPv6 没广播，误用 arp 命令查不出邻居，得用 ip neigh；且依赖 ICMPv6 不能被防火墙误杀
  • DAD 冲突导致地址失效：IPv6 地址生成后要重复地址检测，被占用则地址不可用——排查「地址起不来」先看 DAD

第四层 · 原理与取舍

NDP 相比 ARP 改进在哪？

ARP 用链路广播问所有人，浪费且不安全；NDP 改用组播+ICMPv6，只问相关组、范围可控，还顺带实现了无状态地址自动配置（SLAAC）、重复地址检测（DAD）、路由器发现与重定向——一个协议顶 ARP+部分 DHCP+ICMP 重定向。代价是依赖 ICMPv6，安全策略上别把它一刀切禁掉。

为什么大二层里 ARP 广播是隐患？

因为每次未知 IP 解析都向整个广播域发报文，主机密度越高（如大容器网、云多租户），广播量线性涨，既占带宽又消耗每台主机的 CPU 去处理本不相关的 ARP。解决：缩小广播域（VLAN/子网）、用静态绑定、或上 ARP 表项上限与抑制。

ARP 表项为什么会从 reachable 变 stale，要管吗？

这是内核的可达性状态机：表项一段时间无通信就从 reachable 转 stale（标记「可能不可达」），下次要用时再探测。正常不用管，它本就是省资源的懒回收；但若 stale 后探测失败、且表项被 gc 清掉，下次通信又要重新广播解析，短暂延迟。高频通信的表项会一直保活，真正的痛点是表满和欺骗，而非状态机本身。
