问题所在

“先更新库再删缓存” 与 “先删缓存再更新库” 各有并发窗口导致不一致。例如 A 更新期间，B 读到旧值并回填缓存。

延迟双删

写流程：删缓存→更新库→ sleep 短暂→ 再删一次缓存，降低窗口。

基于 Canal

订阅 MySQL binlog，异步删除/更新缓存，与业务主流解耦，易集中处理。

🎯 面试问答

Q：先删缓存还是先更新库？
A：推荐先更新库再删缓存(仍需延迟双删先兆)，避免“更新期间旧值回填”。
Q：为什么还需延迟双删？
A：防“读请求在更新前加载旧值并回填”的竞态。
Q：Canal 方案优点？
A：业务代码无感、最终一致、可集中处理。
