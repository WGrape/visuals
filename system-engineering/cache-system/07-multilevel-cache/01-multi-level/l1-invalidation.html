多实例

一致

问题

本地缓存 L1 在每实例内存中独立存在，某一实例更新 DB 并清自身 L1，其他实例的 L1 仍是旧值，造成跨实例不一致。

广播方案

更新后通过消息（Redis Pub/Sub、MQ）广播“某 key 失效”，所有实例收到后清本地对应项；实现最终一致。

短 TTL 兜底

广播可能丢失，给 L1 设较短 TTL 作为兜底，即使漏广播也会自然过期重建，平衡一致性与性能。

🎯 面试问答

Q：为什么需要广播失效？
A：本地缓存在各实例独立，需要主动同步失效。
Q：广播丢失怎么办？
A：靠短 TTL 兜底自然过期。
Q：L1 TTL 设多长？
A：视一致性要求，通常秒级~分钟级。
