Python 并发选型实测：threading / multiprocessing / asyncio

三者对比、基准代码与典型数字

并发GIL线程进程Python
对比 基准 数字 决策
Python 的 GIL 决定了：CPU 密集型用多线程几乎无收益，IO 密集型才能靠并发起飞。下面用一组基准量化这个直觉。

1三者怎么选

模型受 GIL 影响适合场景开销
threadingCPU 不并行IO 密集（网络/磁盘）低
multiprocessing无 GILCPU 密集高（进程/内存）
asyncio单线程合作式大量 IO 且高并发低

2基准代码（CPU 密集求和）

import time, concurrent.futures as cf

def cpu_sum(n):
    return sum(i * i for i in range(n))

N = 4_000_000

t0 = time.time(); cpu_sum(N); print("single", time.time()-t0)

with cf.ThreadPoolExecutor() as e:
    t0 = time.time()
    list(e.map(cpu_sum, [N//4]*4)); print("thread", time.time()-t0)

with cf.ProcessPoolExecutor() as e:
    t0 = time.time()
    list(e.map(cpu_sum, [N//4]*4)); print("process", time.time()-t0)

3典型数字（4 核，N=400 万）

方案相对耗时说明
single1.0x基准
threading约 1.0xGIL 锁住，几乎无收益
multiprocessing约 0.3x4 进程近 4 倍加速
asyncio不适用IO 模型，不解决 CPU 密集
要点：数字随 CPU 核数 / 负载浮动，上表是方向性量级，不是精确值。

4决策表

  • 任务是网络请求 / 文件读写 / 数据库查询 → asyncio 或 threading。
  • 任务是数值计算 / 编解码 / 图像处理 → multiprocessing 或 C 扩展（释放 GIL）。
  • 并发量极大且多为等待 → asyncio 事件循环开销最低。
  • 简单脚本别过度设计：先单线程，瓶颈明确再上并发。
