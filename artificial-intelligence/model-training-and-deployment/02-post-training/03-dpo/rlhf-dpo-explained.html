Alignment · 面试核心

RLHF 与 DPO 对齐详解

预训练让模型「懂语言」，对齐让模型「听话、有用、无害」。面试官必问：RLHF 三步分别干嘛？奖励模型怎么训？DPO 为什么不用 RL 也能对齐？

01什么是对齐（Alignment）

大模型基座经过预训练 + SFT 后已能续写，但未必符合人类偏好（可能冗长、有害、不按要求）。对齐就是把模型输出分布调整到「人类真正想要的」：有用(Helpful)、诚实(Honest)、无害(Harmless)，即 3H 原则。

与 RL 的关系：RLHF 本质上是把「强化学习」用到语言模型上——把生成文本当作「动作」，把人类偏好当作「奖励信号」来优化策略（即 LLM 本身）。

02RLHF 经典三步法

  1. SFT：用人工示范数据让模型学会按指令回答（见 fine-tuning 目录）。
  2. 奖励模型（RM）：收集人类对同一提示多个回答的好坏排序，训出一个给回答打分的模型。
  3. RL 优化（PPO）：用 RM 当奖励，在「拿高分」与「别偏离 SFT 太远」之间优化策略。

03奖励模型怎么训

用成对偏好数据 (x, y_w, y_l)（x 是提示，y_w 好回答、y_l 差回答），训练 RM 输出标量分 r：

L_RM = −E[ log σ( r(x, y_w) − r(x, y_l) ) ]

即让「好回答分 − 差回答分」越大越好。训练好了，RM 就把「人类偏好」压缩成一个可微分数，供 PPO 优化。

04PPO 优化目标

max_π  E[ r_φ(x, y) ]  −  β·KL( π(y|x) ‖ π_ref(y|x) )

第一项用奖励模型给高分，第二项（KL 惩罚）约束新策略不要偏离参考模型 π_ref（通常是 SFT 模型）太远，防止乱套、保持语言能力。

PPO 工程很重：同时挂着策略、参考、奖励、价值四个模型，显存大、超参敏感、易训练不稳。这也是后来 DPO 流行的原因。

05DPO：不用 RL 也能对齐

DPO 证明：在 KL 约束下的最优策略可以解析写成偏好数据的损失，从而跳过 RM 和 RL，直接用偏好对训练：

L_DPO = −E[ log σ( β·log(π(y_w|x)/π_ref(y_w|x)) − β·log(π(y_l|x)/π_ref(y_l|x)) ) ]

它等价于在训练一个「隐式奖励」r(x,y)=β·log(π(y|x)/π_ref(y|x))。只要让好回答的相对概率高于差回答即可。

RLHF / PPO

需 RM + RL + 四模型，强但重、不稳。

DPO

单阶段、只需策略+参考两模型，稳定好实现，已成主流。

面试加分点：DPO 并非「没有奖励」，而是把奖励吸收进策略与参考模型的概率比里——省去了显式 RM 和 RL 循环。

06对齐的关键坑

奖励黑客

模型钻 RM 空子（如变谄媚/冗长）骗高分，而非真变好。需 KL 约束 + 迭代更新 RM。

对齐税

对齐提升安全/有用的同时，可能略微损伤原有能力（基准掉点）。靠数据覆盖与控 KL 缓解。

Constitutional AI

用「宪法原则」让模型自我批评自我修正，减少人工标注依赖（Anthropic 提出）。

07面试速记卡

三步

SFT → 奖励模型 → PPO；RM 学偏好、PPO 用奖励优化。

RM 损失

成对偏好 + Bradley-Terry，让好答案分更高。

PPO 目标

最大化奖励 − β·KL(策略‖参考)，防偏离。

DPO 优势

免 RM/RL，单阶段直接训偏好，稳定易实现。

关联：强化学习基础见《大模型强化学习 RL》；偏好数据构建与 SFT 见 fine-tuning 目录。

第二层 · DPO 的关键参数与数据要求

参数常见取值作用调错的后果
beta0.1 ~ 0.5偏离参考模型的惩罚强度太小 → 过度偏离、能力退化；太大 → 学不动
学习率5e-7 ~ 1e-6比 SFT 小一个量级太大会直接崩掉
epochs1 ~ 3偏好数据很容易过拟合超过 3 轮通常开始退化
batch size8 ~ 32（有效）配合梯度累积太小梯度噪声大
偏好对数量数千 ~ 数十万数据量决定对齐上限太少只学到表面风格
参考模型冻结的 SFT 模型提供 KL 约束的锚点更新它就失去约束意义
# DPO 损失的核心直觉（示意代码，非训练框架原样）
import torch

def dpo_loss(policy_chosen_logp, policy_rejected_logp,
             ref_chosen_logp, ref_rejected_logp, beta=0.1):
    # 策略模型相对参考模型的「相对优势」
    logits = (policy_chosen_logp - ref_chosen_logp) \
           - (policy_rejected_logp - ref_rejected_logp)
    # beta 越大，越不允许偏离参考模型
    return -torch.log(torch.sigmoid(beta * logits)).mean()

# 关键理解：DPO 不需要单独训练奖励模型
#   RLHF(PPO) 流程：SFT → 奖励模型 → PPO 强化学习（三阶段、四个模型）
#   DPO 流程     ：SFT → 直接在偏好对上优化（两阶段、两个模型）
#   这就是 DPO 更简单、更省显存的原因

# 数据格式必须是 (prompt, chosen, rejected) 三元组
sample = {
    'prompt':   '解释一下什么是索引',
    'chosen':   '索引就像书的目录……（详细且准确）',
    'rejected': '不知道。',        # 太差会导致模型只学到「别写太短」
}
# 注意：rejected 不要选「明显垃圾」的回答，否则模型学不到细粒度偏好

beta 的直觉：它控制「允许多大程度偏离 SFT 模型」。调小 → 更敢改，容易越过头导致能力退化；调大 → 更保守，几乎学不到偏好。实践上从 0.1 起步，配合监控胜率与通用能力是否退化。

第三层 · 五个高频坑

  • rejected 质量太差：偏好对差距过大，模型只学到「不要写废话」，没学到真正的偏好；要收集相近但有好坏之分的样本。
  • 学率沿用 SFT：DPO 对学习率极其敏感，通常要小一个量级（5e-7 量级）。
  • 训练轮数过多：偏好数据很快就会过拟合，常见现象是「胜率还在涨，但通用能力明显下降」。
  • 只监控胜率：还要同时看长度、拒答率、通用 benchmark，否则容易被长度偏置欺骗。
  • 参考模型被更新：DPO 的 KL 约束依赖冻结的参考模型；不小心一起训练会让约束失效。
  • 不做遗忘检查：对齐后要回测原有能力（数学、代码、推理），确认没有灾难性退化。

判断 DPO 是否成功的三条线：胜率上升、长度不失控、通用能力不下降。只有第一条不算成功。

第四层 · DPO 与 PPO 怎么选

DPO 会取代 PPO 吗？

在离线偏好数据场景，DPO 更简单更稳，已经成为主流选择；但 PPO 支持在线采样 + 奖励模型打分，在需要持续探索的场景仍有优势。

DPO 的代价是什么？

它依赖已有的偏好数据质量，且没有在线探索能力；数据分布覆盖不到的问题，DPO 学不会。另外它对超参更敏感，学习率与 beta 需要认真调。

为什么现在又有各种 DPO 变体？

因为基础 DPO 有几个已知弱点：对噪声偏好对敏感、容易过拟合、长度偏置。变体（如 IPO、KTO、ORPO 等）都是在针对这些点做修正。

偏好数据怎么来

# 一条偏好数据的结构 { "prompt": "用一句话解释什么是索引下推", "chosen": "索引下推是……（准确、简洁、无冗余）", "rejected":"索引就是把……（跑题、啰嗦、有事实错误）" } # 采集流程 1) 同一个 prompt 从模型采样 K 个答案（K=4~8，温度稍高保证多样） 2) 标注员按质量排序，或两两比较选更好的 3) 只保留差异明显的对（都不好的 vs 都很好的，信息量低） 4) 关键：<b>标注标准要写清楚</b>（有帮助、诚实、无害各自怎么判断） # 常见坑：标注员偏好「长而全面」的答案 # -> 模型学会啰嗦（长度偏置），需要用长度归一或显式约束

实践中的关键取舍

① 先 SFT 再对齐跳过 SFT 直接上 RLHF 效果通常很差 —— 模型连「按指令回答」都不会。
② 偏好数据质量 > 数量几万条高质量偏好对往往比几十万条噪声数据更有效。
③ 防止「对齐税」过度对齐会让模型在推理、代码等任务上变弱，需要混合通用数据缓解。
④ 长度偏置要处理标注者偏爱长答案，模型会学会灌水。可用长度惩罚或 DPO 的长度归一化变体。
⑤ 迭代比一次性更重要上线 → 收集真实偏好 → 再训练，多轮迭代的效果远好于一次堆数据。

深入自检

RLHF 和 DPO 该选哪个？

资源有限、数据量不大、追求稳定：DPO。有充足算力与工程能力、追求上限、需要在线探索：RLHF/PPO。近年也出现了两者折中的方法（如迭代式 DPO），先用 DPO 跑通再考虑升级。

为什么 RLHF 容易训崩？

因为要同时协调多个模型（策略、RM、参考、Critic）与多个超参（KL 系数、学习率、采样温度），任一环节失衡都会导致奖励黑客：模型学会骗过 RM 而不是真的变好。KL 约束就是用来防止模型跑太远的。

KL 约束是干什么的？

它限制新策略与原模型的分布距离，防止模型为了拿高分而越跑越偏（生成奇怪但 RM 喜欢的文本）。太大约束学不动，太小约束容易崩，是需要仔细调的超参。

奖励黑客（Reward Hacking）怎么防？

① 加强 KL 约束；② 持续改进 RM（用新的模型输出重新标注）；③ 用多角度的 RM 集成；④ 上线后持续监控输出质量，不要只看 RM 分数。

对齐之后模型变「笨」了是怎么回事？

这就是对齐税：对齐过程可能牺牲了部分通用能力。缓解手段：在对齐数据中混入一定比例的预训练/通用任务数据，并控制对齐强度（不要训太多轮）。
