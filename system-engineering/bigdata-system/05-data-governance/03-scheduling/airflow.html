核心概念

工作流用 DAG（有向无环图）描述：节点是 Task，边是依赖。Airflow 按时钟或外部触发，按依赖顺序执行任务。

架构

Scheduler 解析 DAG、决定何时跑；Worker 执行具体 Task；元数据库记录状态，Web UI 可视化查看与重跑。

为什么需要调度

数仓每天有几十上百个任务，存在先后依赖（先抽数→再清洗→再汇总）。调度系统保证按时、按依赖、失败可重试地跑完。

与 DolphinScheduler 对比

两者都是主流调度；DolphinScheduler 偏向可视化 DAG 拖拽、去中心化；Airflow 以 Python 代码定义 DAG、生态广。

🎯 面试问答

Q：DAG 为什么不能成环？
A：成环会导致任务互相依赖、永远跑不完；Airflow 会在解析期就报错。
Q：任务失败了怎么办？
A：配置 retries 与重试间隔自动重试；仍失败则告警，人工介入后可手动重跑单个任务。
