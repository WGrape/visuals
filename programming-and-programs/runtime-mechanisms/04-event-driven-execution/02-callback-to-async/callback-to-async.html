第一代

回调：简单直接，但会失控

// 回调地狱：层层嵌套，错误处理重复，逻辑难以阅读
readFile("a.txt", (err, data) => {
    if (err) return handle(err);
    writeFile("b.txt", data, (err) => {
        if (err) return handle(err);
        readFile("b.txt", (err, out) => {
            if (err) return handle(err);
            done(out);
        });
    });
});
回调的三个痛点：① 嵌套过深（回调地狱），可读性崩溃；② 错误处理重复，每层都要判 err；③ 控制流难以复用——想串行/并行/竞速都得手写。
第二代

Promise：把「未来的值」变成对象

Promise 表示一个尚未完成但最终会有结果的操作。它有 pending → fulfilled / rejected 三种状态，并可用 .then() 链式串联，从而把嵌套拉平成链条。

// 链式调用：扁平、可组合、错误统一捕获
readFile("a.txt")
    .then(data => writeFile("b.txt", data))
    .then(() => readFile("b.txt"))
    .then(out => done(out))
    .catch(err => handle(err));   // 一处捕获全链路错误

// 组合能力
Promise.all([p1, p2, p3])        // 全部完成
Promise.race([p1, p2])           // 取最快
Promise.allSettled([p1, p2])     // 无论成败都等齐
第三代

async/await：用同步写法表达异步

// 语法糖：本质是 Promise + 生成器，但写法跟同步代码一样
async function run() {
    try {
        const data = await readFile("a.txt");
        await writeFile("b.txt", data);
        const out = await readFile("b.txt");
        done(out);
    } catch (err) {
        handle(err);          // try/catch 直接捕获异步错误
    }
}

await 会「暂停」什么？它暂停的是当前 async 函数的执行，而不是整个线程。await 让出控制权后，事件循环继续处理其它任务；等 Promise 完成后再恢复该函数。所以单线程下依然能并发处理大量 I/O。

坑

常见误区

🐌
顺序 await 拖慢速度
多个互不依赖的异步任务被逐个 await，总耗时是串行之和。应改用 Promise.all 并发
🔒
同步代码阻塞事件循环
在异步函数里跑 CPU 密集的同步代码，会卡住整个循环。应拆分为小任务或交给工作线程
💥
忘记 await
拿到的是 Promise 而非结果，且异常不会被 catch 捕获，变成未处理的 rejection
♾️
并发 vs 并行混淆
单线程 async 是并发（交替处理），不是并行（同时执行）。CPU 密集任务需要多进程/多线程
面试问答

高频问题

Q1：Promise 解决了回调的什么问题？
把嵌套回调拉平成链式调用；提供统一的错误捕获（catch）；并提供 all/race/allSettled 等组合能力，使串行、并行、竞速等控制流可以简洁表达。
Q2：async/await 和 Promise 是什么关系？
async/await 是建立在 Promise 之上的语法糖。async 函数返回 Promise，await 等待一个 Promise。它不改变异步本质，只是让代码写法更接近同步。
Q3：await 会阻塞线程吗？
不会。await 只暂停当前 async 函数的执行并让出控制权，事件循环继续处理其它任务；Promise 完成后再恢复该函数。因此单线程下仍能高并发处理 I/O。
Q4：多个互不依赖的异步任务怎么写最快？
用 Promise.all 并发发起，再统一 await 结果。逐个 await 会串行化，总耗时等于各任务耗时之和。
Q5：并发和并行有什么区别？
并发是「交替处理多个任务」，宏观上同时进行、微观上切换；并行是「真正同时执行」，需要多核或多机。单线程 async 提供的是并发，不是并行。
Q6：为什么 async 函数里跑 CPU 密集代码会卡住？
因为事件循环是单线程执行的，同步的 CPU 密集代码会一直占用主线程，使其它任务和回调无法被处理。应拆分任务或交给工作线程/子进程。
