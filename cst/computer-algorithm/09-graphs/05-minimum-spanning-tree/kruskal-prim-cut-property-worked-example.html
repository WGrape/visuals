最小生成树手算：Kruskal 与 Prim 为什么都选出权重 6

用四点带权图演示排序、并查集、跨割最轻边和负权/不连通边界。

先分清 MST 与最短路径

最小生成树针对无向连通带权图，选出恰好 V−1 条边，连接所有顶点、没有环，并使选中边的总权重最小。它优化“整张网络的铺设成本”，不保证任意两点沿树走的路径最短。A 到 D 的最短路可能使用一条没有被 MST 选中的边，二者的问题目标不同。若图不连通，只能得到每个连通分量的最小生成树，合起来叫最小生成森林；不能声称已经把所有顶点连成一棵树。

本课用四点 A、B、C、D：边 AB=1、BC=2、CD=3、AC=4、BD=5。所有权重互不相同，所以这张图的 MST 唯一。手算时先画图或列边表，不能把无向边误记成只可单向走。

图解：四点图的最小生成树

沿箭头逐步核对输入、变换和输出；下面的推演可以逐步切换。

Kruskal 从最轻边开始

按权重排序：AB(1)、BC(2)、CD(3)、AC(4)、BD(5)。起初四个顶点各自一个连通分量。选 AB，把 A/B 合并；选 BC，把 C 并入；选 CD，把 D 并入。此时已选三条边，四点连通，权重和 1+2+3=6。若继续检查 AC，它的两端已经由 A–B–C 连通，加入会形成环，必须跳过；BD 同理。并查集可以高效回答“两端是否已在同一分量”，但它只维护连通关系，不替算法决定选哪条边。

若有多条同权边，排序时不同次序可能得到不同形状的 MST，但总权重应相同；若出现相同权重就宣称答案唯一是不严谨的。权重可以为负，Kruskal 仍按从小到大选边，只要问题仍是无向图的最小生成树。

Prim 从一个点向外生长

从 A 开始，已在树中的点集 S={A}。跨过 S 与外部的边是 AB=1、AC=4，选最轻 AB；S 变成 {A,B}，跨割边有 AC=4、BC=2、BD=5，选 BC；S 变成 {A,B,C}，跨到 D 的边有 BD=5、CD=3，选 CD。结果同样是 AB、BC、CD，总权 6。Prim 每轮选的是当前树到外部的最轻边，不是“从刚加入的那个点选它最轻的边”。后一种误解可能漏掉由更早树节点出发的更便宜连接。

若从其他点开始，选边过程可能不同；只要实现正确，最终总权仍是 6。用优先队列可以维护候选跨割边，弹出时要跳过两端都已在树内的旧候选。

跨割最轻边为何安全

把顶点划分为两个集合，连接两侧的边叫跨割边。对一个仍可与当前选择兼容的割，最轻跨割边是安全选择：设某棵最优生成树没有这条边，把它加进去会形成一个环，环上必有另一条跨同一割的边；用更轻或等重的边替换，不会使总权增加。这个交换论证是 Kruskal 和 Prim 贪心正确性的核心。

Kruskal 的割可以看成当前某个连通分量与其余顶点，Prim 的割是已经纳入树的点集与外部。两者看起来一个“全局排序”、一个“局部生长”，其实都在选安全跨割边。若边权相同，替换后的总权可相等，所以可能有多棵 MST。

负权、方向与约束

与 Dijkstra 不同，MST 允许负权边：若负权边有助于连接分量，按最轻优先选即可。但 MST 标准定义针对无向图；有向图要研究最小树形图等不同问题，不能把 Kruskal 直接套在有向道路网络。真实铺设场景还可能有“某两站不能直连”“必须经过网关”“不同边容量限制”等约束，这些会改变优化模型，未必仍是普通 MST。

如果边权表示距离，而某些道路只能单向行驶，那么一棵无向 MST 图形再好看，也未必给出合法交通路线。建模是否符合业务，比选对算法名字更重要。

复杂度与实现

Kruskal 主要成本在给 E 条边排序，常写作 O(E log E)，并查集操作接近常数均摊；适合边列表直接可得的场景。Prim 配邻接表和二叉堆，常见复杂度 O(E log V)，适合从某点逐步扩展。具体实现还受图稠密度、边权类型和输入存储形式影响。四点玩具图看不出性能差异，工程选型要考虑百万级边的内存和排序成本。

边权和可能超过 32 位整数范围，计算总权要避免溢出。输出不只要有总权，还应列出所选边，并确认数量恰为 V−1 且能覆盖所有顶点。

改一条边检验直觉

若把 AC 从 4 改为 0.5，Kruskal 会先选 AC，再选 AB，最后选 CD，结果权重 0.5+1+3=4.5；Prim 从 A 也会先选 AC、再选 AB、最后跨到 D 选 CD。若删掉 BC、CD、BD，D 变成孤立点，任何算法都只能报告不连通，不能输出一棵覆盖四点的树。请分别手算这两种改动，检查“安全边”与连通性条件。

两种算法的复杂度与适用

算法数据结构复杂度适合
Kruskal边排序 + 并查集（路径压缩 + 按秩合并）O(E log E) ≈ O(E log V)稀疏图、边已排序时

并查集的近乎常数代价：路径压缩 + 按秩合并后，单次 find/union 的摊还代价是 α(n)（反阿克曼函数），对任何实际规模都 ≤ 4，因此 Kruskal 的瓶颈实际在排序的 O(E log E)。

切割性质与环路性质

性质表述用途
切割性质（cut property）对任意切割，横跨该切割的最小权边必属于某棵 MSTPrim 的正确性依据：每次取连接已选集合与外部的最小边
环路性质（cycle property）任意环上最大权边不属于任何 MST（若唯一最大）Kruskal 的正确性依据：成环时丢弃当前最大边
唯一性所有边权互不相同时 MST 唯一边权相同时 MST 不唯一，但总权重相同

实现

def kruskal(n, edges):
    """edges: [(w, u, v)]，返回 (总权重, 选中的边)"""
    parent = list(range(n)); rank = [0] * n
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]      # 路径压缩
            x = parent[x]
        return x
    def union(a, b):
        ra, rb = find(a), find(b)
        if ra == rb:
            return False                        # 同集 -> 会成环
        if rank[ra] < rank[rb]: ra, rb = rb, ra
        parent[rb] = ra
        if rank[ra] == rank[rb]: rank[ra] += 1  # 按秩合并
        return True
    edges.sort(key=lambda e: e[0])
    total, chosen = 0, []
    for w, u, v in edges:
        if union(u, v):
            chosen.append((w, u, v)); total += w
            if len(chosen) == n - 1:            # 提前终止
                break
    return total, chosen

# 合法性校验：边数 == n-1 且不构成环（用并查集复查）

深入自检

Kruskal 为什么能贪心选最小边？

依据是切割性质与环路性质：按权升序扫描时，若一条边连接了两个不同连通分量，那么存在一个切割使它成为横跨该切割的最小权边，因此必属于某棵 MST；若它两端已连通，则它在当前生成树上形成环且是环上最大权边，必不属于 MST。

Prim 和 Kruskal 分别适合什么图？

Kruskal 的瓶颈是排序 O(E log E)，边越少越划算，适合稀疏图（E 在 O(V) 量级）；Prim 用二叉堆是 O((V+E) log V)，用邻接矩阵 + 线性扫描是 O(V²)，适合稠密图（E 接近 V²）。

边权相同时 MST 唯一吗？

不唯一。当存在相同权重的边时，可能有多个不同的边集都达到最小总权重。但总权重一定相同，所以比较算法结果时应比总权重而不是比具体边集。

如何验证得到的确实是一棵生成树？

两条：① 边数恰好 V−1；② 不含环（或等价地：所有点连通）。用并查集复查即可——把结果边依次 union，若出现同集说明有环；最后检查连通分量数是否为 1。

图不连通时算法会怎样？

会得到最小生成森林：每个连通分量一棵最小生成树，总边数为 V−c（c 为连通分量数）。Kruskal 天然支持这种情况，无需特殊处理；但要注意不要用「边数 == V−1」作为终止条件，否则会漏掉其它分量的边。

自检

MST 总权最小，是否保证树上 A 到 D 的路径也是原图中最短的？

不保证。MST 优化所有选中边的总权；两点最短路径是另一种优化目标。
