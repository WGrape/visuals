🧬 数据模型

表、行键、列族、列限定符与版本

多维映射表

把 HBase 的表想象成一个超大的、按行键排序的「三维坐标 → 值」字典。三维分别是 行(rowkey)、列(列族:限定符)、版本(timestamp)。任意组合唯一确定一个 cell。

核心概念

概念说明要点
表 Table多个列族的集合建表时就要声明列族，列族很少（2~3 个）
行键 RowKey每行的唯一主键字典序全局有序；是查询与分布的唯一索引
列族 ColumnFamily列的命名空间物理存储单位，不同列族存成不同文件；权限/属性按列族设
列限定符 Qualifier列族下的具体列可动态、任意多，无需建表声明
单元 Cell(rowkey,cf:q,ts) 对应的值没有类型，全是字节数组
版本 Version同 cell 的时间戳副本默认保留最近若干版本（VERSIONS）
命名空间 Namespace表的逻辑分组类似 RDBMS 的库；默认 default、hbase 系统空间

逻辑视图 vs 物理视图

逻辑上是一张「宽表」，但稀疏：某个 rowkey 只在它实际有值的列上有 cell，其余格子根本不存在（不占空间）。物理上，同一列族的所有列存在一起（列族聚簇），不同列族分文件存储。

rowkeycf1:namecf1:agecf2:score
user_001Alice30—（无此列）
user_002Bob—95

列族的物理意义

  • 列族是物理隔离的：一个列族对应一组 HFile 与独立的 MemStore/BlockCache 区域。
  • 列族过多 → MemStore / 文件 / 刷写放大，影响性能；一般 控制在 2~3 个以内。
  • 把「访问模式不同、成长速度不同」的列分到不同列族（详见模式设计篇）。
💡 HBase 没有「表级」或「行级」的固定列定义，列是「列族 + 任意限定符」动态拼出来的；这是它比 RDBMS 灵活、又比纯 KV 更结构化的原因。
