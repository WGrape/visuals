Weaviate 向量数据库原理

GraphQL 风格 Schema + 内置向量化模块：开箱即用的语义搜索数据库

WeaviateSchema/ClassGraphQL内置 Embedding混合检索
① 定位 ② Schema 数据模型 ③ 向量化模块 ④ 检索方式 ⑤ 上手示例 ⑥ 三者对比
一句话总结：Weaviate 的最大特色是 Schema-first + 内置向量化—— 你只需定义数据结构（Class）并指定用哪个模型， 存原始文本进去，向量化由 Weaviate 自动完成（支持 OpenAI、Cohere、HuggingFace 等）。 再加上原生 GraphQL 查询与混合检索（向量 + BM25），对应用开发者非常友好。

01定位与特点

🧩 内置向量化模块

支持 OpenAI、Cohere、HuggingFace、本地模型等。 写入文本即自动转向量，无需在应用层调用 embedding API。

📐 Schema-first

先定义 Class（类）与属性类型，数据强结构化。 类似 ORM / 图数据库的对象建模思维。

🔀 混合检索原生

内置 BM25 关键词检索 + 向量检索的融合（hybrid search）， 无需自己拼两套系统再融合。

🔗 交叉引用

对象之间可用 cross-reference 建立关联， 天然表达"文章→作者"这类关系，可跨对象检索。

适合：想快速搭建 RAG/语义搜索、不想自己管 embedding 流水线、偏好 GraphQL 的团队。

02Schema 数据模型

Weaviate 用「Class（类）→ 对象（Object）」组织数据， 每个 Class 有属性（property），并指定向量化器。

04三种检索方式

方式原理适用
向量检索
nearText / nearVector		 HNSW 近似最近邻，按语义相似度 语义模糊匹配、同义表达
关键词检索
bm25		 BM25 经典词频-逆文档频率打分 精确术语、专有名词、型号
混合检索
hybrid ⭐		 融合两者分数（可配 alpha 权重） 生产推荐：兼顾语义与精确匹配
为什么混合检索重要？纯向量检索对精确词（如错误码 "ERR_2049"、产品型号、人名） 表现很差——语义相似但字面不同就会漏掉。 纯 BM25 又无法处理同义词与语义泛化。 两者融合（hybrid）才是生产环境的标准答案，Weaviate 把它做成了原生能力。 
# GraphQL 混合检索示例
{
  Get {
    Article(
      hybrid: {
        query: "向量数据库 选型"
        alpha: 0.5          # 0=纯关键词, 1=纯向量, 0.5=各半
      }
      limit: 10
      where: {              # 结构化过滤
        path: ["publishedAt"]
        operator: GreaterThan
        valueDate: "2025-01-01T00:00:00Z"
      }
    ) {
      title
      content
      _additional { score }
    }
  }
}

过滤与检索的执行顺序

Weaviate 支持 where 过滤。它会在向量检索之前或之中应用过滤 （取决于过滤选择性），并对高选择性过滤做了专门优化。 与 Qdrant 类似，过滤过严会降低 ANN 效率，需要关注召回率。

05上手示例

// 1. 定义 Schema（REST）
POST /v1/schema
{
  "class": "Article",
  "vectorizer": "text2vec-openai",
  "moduleConfig": {
    "text2vec-openai": { "model": "text-embedding-3-small" }
  },
  "properties": [
    { "name": "title",   "dataType": ["text"] },
    { "name": "01-content", "dataType": ["text"] },
    { "name": "publishedAt", "dataType": ["date"] }
  ]
}

# 2. 写入（只需文本，向量自动生成）
import weaviate
client = weaviate.connect_to_local()
articles = client.collections.get("Article")
articles.data.insert({
    "title": "向量数据库选型指南",
    "01-content": "...",
    "publishedAt": "2026-01-15T00:00:00Z"
})

# 3. 查询（用文本查，也自动生成查询向量）
res = articles.query.hybrid(query="向量数据库", alpha=0.5, limit=10)
实践注意：① 换 embedding 模型必须重建全部向量（维度/语义空间变了）； ② 内置向量化会为每个写入产生一次 API 调用，批量导入前先评估成本； ③ 生产环境建议评估"数据是否允许出境"——合规敏感场景应改用本地模型或自带向量（BYOV）。
