CIDR 路由聚合手算：两个网段什么时候能合成一个

用二进制前缀检验超网边界，理解减少路由表与误聚合黑洞的代价。

聚合是用一个前缀代表多个网段

CIDR 前缀如 10.20.0.0/24 表示前 24 位固定，剩余 8 位可变化；聚合或超网把相邻且对齐的前缀合成一个更短前缀。10.20.0.0/24 与 10.20.1.0/24 的前 23 位相同，合成 10.20.0.0/23，覆盖第三段为 0 和 1 的地址。路由器少维护一条条细路由，上游只需知道“这两个 /24 都往这个方向走”。

“两个网段数字相邻”还不够，必须满足起点对齐和覆盖范围恰好匹配。比如 10.20.1.0/24 与 10.20.2.0/24 虽相邻，却不能单独用一个 /23 精确表示：10.20.0.0/23 覆盖 0、1，10.20.2.0/23 覆盖 2、3。若硬要用更大的前缀，会额外覆盖本不属于这组的地址。

二进制怎么判断

第三个八位组 0 是 00000000，1 是 00000001；二者前七位相同，加上前两个八位组共 23 位相同，得到 /23。第三组 2 是 00000010，与 1 的前七位并不相同，因此不能和 1 配成同一个 /23。一个 /23 的地址块大小为 512 个 IPv4 地址，起点必须在第三组的偶数边界，如 0、2、4。计算时先找共同前缀，再核对起点和终点，避免只把掩码数字减一。

再看 10.20.0.0/23 与 10.20.2.0/23，两者可合并成 10.20.0.0/22，覆盖第三组 0–3。若只有 0、1、2 三个 /24，单个 /22 会多包含 3；可以发布 /23 加一个 /24，或确认额外范围也确实由同一下一跳负责。路由最少不一定是唯一目标，正确覆盖更重要。

逐步推演

写二进制

比较两个 /24 的第三组高位。

找共同前缀

0 与 1 共享前七位，得到 /23。

核对边界

/23 从偶数第三组开始，覆盖两个 /24。

验证实际网络

确认全部覆盖范围都由同一下一跳负责。

聚合为什么有利

大规模网络若每个小网段都向上游发布独立路由，路由表、控制面更新和故障收敛成本都会上升。边界路由器把同一方向的多个网段聚合发布，降低上游看到的前缀数量。聚合通常放在清晰的拓扑和地址规划边界：例如一个园区拿到连续地址块并对外发布一条汇总路由。若地址分配散乱，事后强行聚合会包含不属于该园区的范围。

聚合本身不替代内部细路由。园区边界接到汇总范围的包后，内部仍要知道具体子网在哪；若内部只存在部分子网，可用更具体路由与丢弃路由配合，避免无意环路或把不存在地址转回上游。此设计需按设备策略验证。

误聚合造成什么

假设路由器 R 对外发布 10.20.0.0/22，但 R 实际只连接 0、1、2 三个 /24，第三组 3 属于别的网络。上游按聚合前缀把去 10.20.3.9 的包送到 R；R 不知道正确目的地，就可能丢弃或绕路。这个黑洞是地址覆盖错误，不是 DNS 缓存。若 R 的内部子网 1 发生故障，汇总路由可能仍对外存在，上游还会送包；是否撤销或细化发布取决于设计。

更具体路由可覆盖聚合路由。若上游同时有 10.20.0.0/22→R 和 10.20.3.0/24→S，去 10.20.3.9 会按最长前缀选 S；但若 /24 失效而 /22 未撤，流量可能被 R 接走。故障演练要覆盖这种退路行为。

实务规划与排障

给业务分配连续前缀前，估算站点数量、每站扩展和预留空间，并留好二进制边界。记录每个聚合前缀实际包含的具体网络和下一跳。变更时从聚合范围的首尾、已分配段和未分配空洞各选地址测试，检查路由表匹配及回程。不能只 ping 一个在 0 网段的地址就宣称整个 /22 正常。

查看路由时把“协议学习到的聚合前缀”和“实际安装的更具体前缀”分开。某地址不可达，先手算它是否被汇总覆盖，再查最长前缀、下一跳和内部细路由。练习用四个 /24 在纸上两两合并，比背“/22 是四个 C 段”更能避免边界错误。

自检

10.20.1.0/24 与 10.20.2.0/24 能精确合成一个 /23 吗？

不能。/23 必须从对齐的偶数第三组开始，1 与 2 跨越两个不同的 /23 块。
