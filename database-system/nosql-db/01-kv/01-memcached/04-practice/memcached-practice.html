🛠️ Memcached 实践

部署、监控与常见陷阱

部署与监控

📊

stats 命令

stats / stats items / stats slabs 查看命中率、evictions、各 slab 占用。

♻️

连接复用

客户端务必使用连接池，避免短连接风暴。

🔒

裸奔风险

默认无鉴权，务必放在内网 / 加 SASL。

常见陷阱

  • 大 value 阻塞：单线程处理单条命令，value 过大（接近 1MB）会拖慢其他请求——尽量控制 value 体积。
  • 热点 key：某个 key 被海量请求打到同一节点，形成单点瓶颈——客户端可做本地缓存或多副本。
  • 内存碎片化：value 尺寸分布杂乱导致 slab 浪费，关注 evicted / outofmemory。
  • 缓存与 DB 一致性：写后失效（delete）而非写后更新，避免并发写带来脏数据。
💡 Memcached 适合『简单、海量、可丢失』的缓存；若需要持久化、复杂结构或原子操作，交给 Redis。
