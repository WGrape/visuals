1从单 Skill 到多 Skill

当系统里注册了多个 Skill（能力模块）后，难点不再是"怎么写一个 Skill"，而是怎么在多个命中时路由、协同与消解冲突：用户一句话可能同时触发翻译、检索、计算三个能力，谁先谁后、结果怎么合并、互相打架怎么办。本文只谈多 Skill 编排。

聚焦：路由、组合、多 skill 命中时的冲突消解。

2编排三要素

要素问题手段
路由选哪个/哪些 Skill意图分类、置信度阈值
组合多 Skill 怎么串/并管线、DAG、结果聚合
冲突消解结果/副作用冲突优先级、投票、人工

3路由与冲突消解片段

def route(query, skills):
    scored = [(s, s.match(query)) for s in skills]
    hits = [s for s, sc in scored if sc >= s.threshold]
    if not hits:
        return []
    # 冲突消解：按 priority 保留高优，并列则取置信度高者
    hits.sort(key=lambda s: (-s.priority, -scored[[x[0] for x in scored].index(s)][1]))
    return hits

# 组合：把检索结果喂给摘要 Skill
def compose(hits, query):
    ctx = retrieve(hits[0]) if any(h.name=="retrieve" for h in hits) else ""
    for h in hits:
        ctx = h.run(query, ctx)
    return ctx

路由用"阈值+优先级"避免什么都触发；组合用管线把上游输出作为下游上下文，减少重复 LLM 调用。

4多 Skill 命中与消解

图：多个 Skill 命中后经优先级/投票消解再聚合

第一层 · 概念与判定

判定编排策略：

  • Skill 是否互相独立（可并行）还是强依赖（须串行）；
  • 多命中是否真有冲突（写操作 vs 只读）；
  • 是否允许低置信 Skill 触发（阈值设定）；
  • 是否需要人工兜底高风险组合。

第二层 · 参数·命令·量化

参数与命令：

项建议
路由阈值0.6–0.8，过低易误触发
优先级破坏性 Skill 高优前置校验
最大并发限制同时触发数，避免爆炸
# 列出已注册 skill 与置信度便于调试
for s in skills: print(s.name, s.match(query))

第三层 · 排障与边界

排障：

  • 全部误触发：阈值过低，收紧 match 规则；
  • 组合死循环：A 输出又触发 A，加执行深度限制；
  • 结果互相覆盖：未定义合并顺序，显式优先级；
  • 副作用冲突：两个 Skill 都写同一资源，串行化或拒绝。

第四层 · 原理与取舍

原理取舍：

  • 多 Skill 提升覆盖，但组合复杂度指数增长；
  • 路由越宽松越"聪明"却越易出错，需阈值平衡；
  • 冲突消解用优先级最简单但可能压错，投票更稳但慢；
  • 结论：把多 Skill 当"能力市场"，用路由+优先级+聚合三件套治理，而非堆砌。
