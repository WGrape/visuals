方案

热点 key 过期瞬间，大量并发到达。用分布式锁（如 Redis SET key uuid NX EX）保证只有一个线程去查 DB 重建缓存，其余线程等待或短暂重试取缓存。

锁实现与超时

获取锁的线程重建后释放；锁需设超时防崩溃死锁。其余线程可 sleep 后重试读缓存，或返回降级值。

问题

锁竞争会串行化回源，若重建慢会阻塞；需控制锁粒度（按 key）与超时，并配合逻辑过期进一步解耦。

🎯 面试问答

Q：为什么用分布式锁？
A：保证只有一个线程重建，避免惊群。
Q：锁超时怎么设？
A：大于重建耗时，防崩溃死锁。
Q：锁竞争有什么代价？
A：回源串行化，慢则阻塞。
