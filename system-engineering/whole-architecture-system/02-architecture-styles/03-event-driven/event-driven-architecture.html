事件驱动架构

以『事件』为骨架：生产者发出事件，消费者各自响应，彼此不知对方存在。

事件流模型 EDA

一个事件被多个消费者并行响应，生产者不感知消费者

核心角色：<b>事件</b>（『发生了什么』的事实，如 OrderCreated）、<b>生产者</b>（发出事件）、<b>经纪人/总线</b>（Kafka、RabbitMQ）、<b>消费者</b>（各自订阅关心的事件）。

两种典型模式

  • 事件通知：只通知『发生了什么』，消费者自己去拉详情（耦合低、需回查）。
  • 事件携带状态(Event Carried)：事件里带上完整数据（自治、但可能冗余）。
  • 事件溯源 Event Sourcing：状态由一连串事件重放得到，而非直接存当前值。

优缺点

面试高频问答

Q：事件驱动和事件溯源是一回事吗？
A：不是。事件驱动是『通信风格』（用事件解耦服务）；事件溯源是『存储风格』（用事件序列表达状态）。事件溯源是事件驱动的一种进阶用法。
Q：如何保证事件不丢、不重复消费？
A：不丢靠消息队列持久化+确认机制；不重复靠消费者幂等（用事件ID/业务唯一键去重）。顺序性靠分区键绑定。
