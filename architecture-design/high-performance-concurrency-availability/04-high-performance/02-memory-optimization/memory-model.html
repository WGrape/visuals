内存模型与布局

虚拟内存、堆栈、对齐与缓存行——程序在内存里到底怎么摆。

虚拟内存解决了什么

用户进程看到的「虚拟地址空间」
MMU 页表：虚拟 → 物理
物理内存 / 磁盘 swap

虚拟内存让每个进程都以为自己独占整片内存，隔离了进程、支持了按需分页与 swap，也方便了共享库与地址随机化（ASLR）。

栈与堆的区别

维度栈堆
生命周期随函数进出自动管理手动或 GC 管理
速度极快（指针移动）较慢（分配/回收）

对象在内存里怎么排

对象通常含「对象头（类型指针、GC 标记、长度）+ 字段」。字段按声明与对齐规则排列，对齐填充（padding） 会悄悄吃掉内存。

缓存行与局部性

局部性就是性能

CPU 一次从内存取一个缓存行（通常 64 字节）。连续、紧凑、可预测的内存访问命中率高；随机跳转会让缓存反复失效，慢一个数量级。

问题 1
为什么要有虚拟内存？

隔离进程、简化编程模型（每个进程独立地址空间）、支持按需加载与 swap、提升安全性（ASLR）。没有它，程序得自己管理物理地址，且一个进程崩溃容易拖垮整个系统。

问题 2
栈和堆最根本的区别？

栈由编译器自动管理、随函数调用进出，速度极快但有大小上限；堆由程序员或 GC 管理、生命周期灵活但分配回收更慢且可能碎片化。

问题 3
结构体对齐填充会浪费内存吗？

会。为满足对齐，编译器在字段之间插入 padding；字段顺序不当会让同一结构多占几十字节。高频对象应按字段大小降序排列来压缩。

问题 4
为什么缓存行对齐对性能重要？

CPU 以缓存行为单位搬运数据。连续访问命中率高；跨缓存行或伪共享都会导致额外的总线同步，是隐藏的性能杀手。

实践要点

① 怎么读 free

  • 不要看 free 列，看 available（可用）。
  • buff/cache 是可回收的，占用大不是问题。
  • swap 非零要警惕（说明曾经内存压力大）。
  • si/so（vmstat）持续非零 = 正在换页，性能已受损。

② 泄漏怎么查

  • 确认：多次采样 RSS 是否单调上涨且不回落。
  • GC 语言：堆转储 + 分析工具（MAT、pprof）看对象引用链。
  • C/C++：Valgrind、AddressSanitizer。
  • 堆外：pmap 对比、NMT（Java）、检查 DirectBuffer 释放。
  • 常见原因：静态集合、监听器未注销、线程池无界队列、缓存无上限。

③ 降低内存占用

  • 对象复用与池化，减少分配与碎片。
  • 紧凑数据结构（避免大量小对象与指针）。
  • 共享只读数据（mmap、共享库、单例）。
  • 缓存要有上限与淘汰策略（LRU + TTL + 容量上限）。
  • 限制线程数与队列长度。

④ 容器环境

  • 应用必须感知 cgroup limit（-Xmx、GOMEMLIMIT）。
  • RSS 目标通常设为 limit 的 70-80%（留余量给峰值与碎片）。
  • 监控容器的 memory.current 与 memory.events（OOM 次数）。
  • 注意 JVM/Go 默认按宿主内存自我配置的问题。

深入自检

free 显示内存快没了，是不是有泄漏？

大概率不是。Linux 会用空闲内存做页缓存（buff/cache），这部分是可回收的。判断应该看 available（可用内存）而不是 free。真正的问题是：available 很低、swap 持续增长、si/so 换页活跃、或某个进程 RSS 单调上涨。

RSS 一直涨但 GC 后堆很小，内存去哪了？

通常在堆外：DirectByteBuffer、mmap 映射、JNI 分配、压缩库的本地内存、或者线程栈（线程数 × 栈大小）。排查方法：pmap -x 看各段分布、Java 用 NMT（Native Memory Tracking）、Go 看 runtime.MemStats 的 Sys 与 HeapSys 差值。

为什么明明还有内存，进程还是被 OOM Kill？

可能原因：① 容器 cgroup 设置了 limit，进程触达的是自己的上限；② 内存碎片导致无法分配连续块；③ 内核为保护系统主动杀进程；④ OOM Killer 按打分选人，未必是占用最多的（可用 oom_score_adj 调整优先级）。看 dmesg 的 OOM 记录是第一步。

swap 一定要关掉吗？

不一定。swap 的作用是在内存压力时给系统缓冲时间，避免直接 OOM；但对延迟敏感的服务，换页会导致不可预测的卡顿。常见做法：数据库类服务关闭 swap 或把 swappiness 调到很低（1-10）；通用服务器保留少量 swap 做缓冲。关键是根据业务容忍度决定，并监控 si/so。

内存碎片怎么改善？

从三个层面：① 应用层——对象池、复用、减少大小不一的高频分配；② 分配器——换用 jemalloc/tcmalloc（对多线程与碎片更友好），或调 glibc 的 arena/释放策略；③ 系统层——开启内存规整、使用大页、必要时重启整理。先定位是外部碎片（空闲分散）还是内部碎片（对齐浪费）。

如何建立内存监控？

分三层：① 进程层——RSS/PSS、堆占用、GC 频率与停顿、线程数、堆外内存；② 系统层——available、swap、si/so、Slab、页缓存；③ 容器层——cgroup 的 current/max/events。告警建议：RSS 超过 limit 的 80%、GC 停顿 P99 超阈值、OOM 事件、以及 RSS 长时间单调增长的趋势告警。
