单调栈与单调队列

保持容器内元素单调，把「找第一个更大/更小」压到均摊 O(n)

一句话
栈/队列里保持元素单调，从而在遍历时 O(1) 找到「左边/右边第一个更大或更小」
单调栈解决
下一个更大元素、柱状图最大矩形、接雨水
单调队列解决
滑动窗口最大值（O(n) 而非 O(n log n)）
复杂度
每个元素最多进一次出一次，均摊 O(n)

一、单调递增栈 vs 单调递减栈

类型栈内顺序弹出时机用来找
单调递增栈栈底到栈顶递增遇到比栈顶更小的元素时弹出左边/右边第一个更小的元素
单调递减栈栈底到栈顶递减遇到比栈顶更大的元素时弹出左边/右边第一个更大的元素

记忆技巧

想找更大的元素，就用递减栈（大的在上面，新来的更大就把小的挤掉）；想找更小的元素，就用递增栈。名字和用途是反着的，最容易记混。

二、模板：下一个更大元素

// 求每个元素右边第一个更大的元素，没有则 -1 func nextGreater(nums []int) []int { n := len(nums) res := make([]int, n) for i := range res { res[i] = -1 } st := []int{} // 存下标而不是值，方便算距离 for i := 0; i < n; i++ { for len(st) > 0 && nums[i] > nums[st[len(st)-1]] { top := st[len(st)-1] // 当前元素就是 top 的「下一个更大」 st = st[:len(st)-1] res[top] = nums[i] } st = append(st, i) } return res } // 循环结束时栈里剩下的元素，说明它们右边没有更大的 —— 这正是初始值 -1 的含义

三、经典题一：柱状图最大矩形

技巧是在柱状图末尾补一个高度 0 的哨兵，强制把栈清空，避免写完主循环还要额外处理残留：

// 枚举每个柱子作为「矩形的最高高度」，向左右扩展到第一个更矮的位置 // 单调栈维护「递增的高度」，一旦遇到更矮的，就结算栈顶 heights = append(heights, 0) // 哨兵 st := []int{-1} // 哨兵下标，简化左边界计算 for i := 0; i < len(heights); i++ { for len(st) > 1 && heights[i] < heights[st[len(st)-1]] { h := heights[st[len(st)-1]] st = st[:len(st)-1] width := i - st[len(st)-1] - 1 // 左边界是弹出后的新栈顶 ans = max(ans, h*width) } st = append(st, i) } // 为什么是「递增栈」？因为一旦遇到更矮的， // 栈顶柱子的右边界就确定了 —— 这就是它能向右扩展的最远位置。

四、经典题二：滑动窗口最大值（单调队列）

// 队列里保存「可能成为最大值的候选」，从队首到队尾单调递减 type MonoQueue struct{ q []int } func (m *MonoQueue) Push(v int) { // 所有比 v 小的都不可能再成为最大值，直接淘汰 for len(m.q) > 0 && m.q[len(m.q)-1] < v { m.q = m.q[:len(m.q)-1] } m.q = append(m.q, v) } func (m *MonoQueue) Max() int { return m.q[0] } func (m *MonoQueue) Pop(v int) { if m.q[0] == v { m.q = m.q[1:] } // 只有队首恰好是滑出的元素才删 } // 复杂度 O(n)：每个元素最多进一次、出一次 // 对比：用堆是 O(n log k)，用暴力是 O(n*k)

五、深入自检

为什么存下标而不是值？因为很多题目要求输出「距离」「宽度」这类位置信息，值本身不够。而且存下标还能顺便判断元素是否还在窗口内。
栈里剩下未弹出的元素怎么处理？它们代表「找不到满足条件的答案」，正好对应初始值（比如 -1 或 0）。这也是为什么初始化 res 很重要，别写成全 0 就以为对了。
什么时候该用哨兵？当主循环结束后还需要统一结算栈内元素时。加一个「必定破坏单调」的哨兵（如高度 0、无穷大），能让结算逻辑复用同一段代码，避免重复。
单调栈和单调队列的区别？单调栈只在一端进出，解决「某个方向上的第一个更值」；单调队列在两端进出（队尾淘汰、队首弹出），解决「滑动窗口内的最值」。
能用二分代替单调栈吗？部分场景可以，但单调栈是 O(n) 且更直接。单调栈的本质是利用「一旦被更大元素挡住，小元素在之后就永远不可能成为答案」这一单调性质。

核心洞察：暴力解法的浪费在于同一个元素被反复比较。单调栈用“保持栈内单调、遇到破坏单调的元素就弹出”的策略，让每个元素最多进栈一次、出栈一次——总复杂度摊还到 O(n)。

模板代码：三种方向一次掌握

单调栈模板

# 模板①：找"下一个更大元素"（单调递减栈，存下标）
def next_greater(nums):
    n = len(nums)
    res = [-1] * n
    stack = []                        # 存下标，栈底到栈顶对应的值递减
    for i in range(n):
        # 当前元素比栈顶大 -> 它就是栈顶元素的"下一个更大"
        while stack and nums[i] > nums[stack[-1]]:
            res[stack.pop()] = nums[i]
        stack.append(i)
    return res
# next_greater([2,1,2,4,3]) -> [4,2,4,-1,-1]

# 模板②：找"下一个更小 / 上一个更小"（改成单调递增栈）
def prev_smaller(nums):
    res = [-1] * len(nums)
    stack = []                        # 栈内递增
    for i in range(len(nums)):
        while stack and nums[stack[-1]] >= nums[i]:
            stack.pop()               # 弹出所有 >= 当前的
        res[i] = stack[-1] if stack else -1
        stack.append(i)
    return res

# 模板③：每日温度（存下标，算距离而不是值）
def daily_temperatures(t):
    n = len(t)
    res = [0] * n
    stack = []
    for i in range(n):
        while stack and t[i] > t[stack[-1]]:
            j = stack.pop()
            res[j] = i - j            # 距离
        stack.append(i)
    return res
# daily_temperatures([73,74,75,71,69,72,76,73])
# -> [1,1,4,2,1,1,0,0]

# 记忆口诀：
#   找"更大" -> 递减栈 -> 遇到更大的就弹
#   找"更小" -> 递增栈 -> 遇到更小的就弹
#   比较符号 > 还是 >= ：取决于是否允许相等（有重复元素时用 >= 更稳妥）

循环数组（下一个更大元素 II）的处理技巧：把数组遍历两遍（for i in range(2*n)，用 i % n 取下标），但只在第一轮（i < n）入栈，这样既覆盖了环形又不会重复赋值。

接雨水：单调栈 vs 双指针

解法思路复杂度特点
单调栈按行计算：遇到更高的右墙就结算一层水O(n) 时间 / O(n) 空间直观，但栈略难写
双指针按列计算：每列的水 = min(左最高, 右最高) − 高度O(n) 时间 / O(1) 空间推荐，代码更短
前缀/后缀最大值预计算每列的左右最大值O(n) 时间 / O(n) 空间最容易理解

接雨水两解

# 双指针解法（最优：O(n) 时间 + O(1) 空间）
def trap(height):
    l, r = 0, len(height) - 1
    lmax = rmax = 0
    water = 0
    while l < r:
        # 关键：只处理"较矮的那一侧"，因为它能装多少由 lmax 决定
        if height[l] < height[r]:
            if height[l] >= lmax:
                lmax = height[l]        # 更新左最高
            else:
                water += lmax - height[l]
            l += 1
        else:
            if height[r] >= rmax:
                rmax = height[r]
            else:
                water += rmax - height[r]
            r -= 1
    return water

# 单调栈解法（按行累加）
def trap_stack(height):
    stack, water = [], 0
    for i, h in enumerate(height):
        while stack and h > height[stack[-1]]:
            bottom = stack.pop()          # 凹槽底部
            if not stack: break           # 左边没有墙，接不住
            width = i - stack[-1] - 1     # 左右墙之间的距离
            h_water = min(h, height[stack[-1]]) - height[bottom]
            water += width * h_water
        stack.append(i)
    return water

# trap([0,1,0,2,1,0,1,3,2,1,2,1]) -> 6

深入自检

单调栈为什么是 O(n) 而不是 O(n²)？

虽然代码里有 while 嵌套在 for 里看起来是 O(n²)，但用摊还分析看：每个元素最多入栈一次、出栈一次。总共 n 次入栈 + 最多 n 次出栈 = 2n 次操作，所以是 O(n)。这是算法分析里最经典的摊还分析例子——“内层循环的总执行次数被外层循环次数约束”的思路要掌握。

什么时候用单调队列而不是单调栈？

当问题涉及“滑动窗口的最值”时用单调队列——因为它需要两端操作：从队尾插入（维护单调性）、从队首弹出（窗口滑出过期元素）。单调栈只需要一端操作（栈顶），适合“找最近的更大/更小元素”这类无窗口限制的问题。典型：滑动窗口最大值（LeetCode 239）用单调队列，O(n)；下一个更大元素用单调栈，O(n)。

有重复元素时比较符号用 > 还是 >= ？

看题意。用 > 会保留相等元素（栈内可以有相等值）；用 >= 会把相等的元素也弹掉（栈内严格单调）。举例：数组 [2, 2] 找下一个更大元素——用 >：两个 2 都留在栈里，各自等待后面的更大值（结果相同）；用 >=：第一个 2 被第二个 2 弹掉（虽然值相等），适用于“找严格更大且最近”的场景。经验：求“下一个更大元素”用 >；求“柱状图最大矩形”这类需要边界的用 >= 更省事。

单调栈能解决哪些看起来不像的问题？

几个变形：① 字典序最小的子序列（316 题）——用单调递增栈 + 计数，保证每个字符只出现一次且字典序最小；② 股票跨度（901 题）——单调递减栈存价格，跨度 = 当前下标 − 弹出后栈顶；③ 最大矩形（85 题）——把每一行当作柱状图底部，对每行跑一次单调栈；④ 去除 K 位数字使结果最小（402 题）——单调递增栈 + 贪心弹出。共同点：需要“找到左边/右边第一个满足某种大小关系的元素”。

第二层 · 参数·命令·量化：方向、模板与复杂度

单调栈只有两个旋钮：递增还是递减、弹栈条件是 > 还是 >=。记住对照表就能覆盖所有变体。

要找什么栈的方向弹栈条件结算时机
下一个更大元素单调递减栈nums[i] > nums[st[-1]]弹出时，当前元素即答案
下一个更小元素单调递增栈nums[i] < nums[st[-1]]弹出时，当前元素即答案
上一个更大元素单调递减栈nums[i] > nums[st[-1]]压栈前，栈顶即答案
上一个更小元素单调递增栈nums[i] < nums[st[-1]]压栈前，栈顶即答案

三种方向的标准模板

# 三种方向一次掌握（存下标版）
def next_greater(nums):        # 下一个更大：递减栈，弹出时结算
    res = [-1] * len(nums); st = []
    for i, v in enumerate(nums):
        while st and v > nums[st[-1]]:
            res[st.pop()] = v
        st.append(i)
    return res

def prev_greater(nums):        # 上一个更大：递减栈，压栈前看栈顶
    res = [-1] * len(nums); st = []
    for i, v in enumerate(nums):
        while st and v >= nums[st[-1]]:
            st.pop()
        res[i] = nums[st[-1]] if st else -1   # 栈顶就是答案
        st.append(i)
    return res

def sliding_max(nums, k):      # 滑动窗口最大值：单调队列
    from collections import deque
    dq = deque(); res = []
    for i, v in enumerate(nums):
        while dq and nums[dq[-1]] <= v:       # 队尾维护递减
            dq.pop()
        dq.append(i)
        if dq[0] <= i - k:                    # 队首淘汰过期
            dq.popleft()
        if i >= k - 1:
            res.append(nums[dq[0]])
    return res

关键量级：单调栈能把 O(n²) 的「找左右第一个更大/更小」降到 O(n)。n=1e5 时这是从「必然超时」到「毫秒级」的差别。

第四层 · 原理与取舍：为什么弹栈不会被浪费

直觉上「弹栈」像是丢弃信息，但在单调栈里被弹出的元素已经找到了它的答案——它之所以被弹，正是因为遇到了第一个满足条件的元素。这就是 O(n) 的来源：每个元素一旦被弹出就永不再回来。

写法什么时候用优点代价
存下标需要距离 / 宽度（柱状图、接雨水）信息最全多一层间接
存值只要下个更大的值代码短算不了距离
哨兵（末尾加 -1 或 0）统一处理栈里剩余元素少写一段收尾循环要小心哨兵值与实际数据的冲突
为什么滑动窗口最大值要用双端队列而不是单调栈？

因为窗口会从左端淘汰过期元素，单调栈只能从栈顶弹出，没法从「栈底」按位置淘汰。双端队列两端都能操作，队首负责淘汰过期、队尾负责维护单调。

接雨水用单调栈还是双指针？

都能做。单调栈是「按横向一层层填」，思路直观、O(n) 时间 O(n) 空间；双指针是「按列累加」，O(n) 时间 O(1) 空间更省。面试写双指针更优雅，理解原理用单调栈更容易。

什么时候单调栈反而不合适？

当要找的是「区间内第 k 大」「全局 top k」这类不依赖单调性的问题，单调栈帮不上忙——那需要对顶堆或快速选择。单调栈只擅长「左右第一个满足单调关系的元素」。
