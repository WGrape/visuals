跳表结构

ZSet 用跳表维护分值有序，每个节点带随机层数（默认 1/4 概率升层），头插多层指针实现 O(log N) 查找、范围、排名。

为什么用跳表而非红黑树

跳表范围查询更高效（链表天然有序），实现更简单，且能轻松支持 ZRANK / ZRANGE 等区间操作；红黑树范围遍历较麻烦。

ziplist 优化

元素少且体积小的时候，Redis 用紧凑的 ziplist/listpack 存储以省内存，超过阈值再转成跳表+哈希。

🎯 面试问答

Q：ZSet 为什么用跳表？
A：范围查询高效、实现简单。
Q：跳表层数怎么定？
A：随机概率（约 1/4）升层，期望层数低。
Q：ziplist 何时转换？
A：元素数量或大小超阈值时转跳表结构。
