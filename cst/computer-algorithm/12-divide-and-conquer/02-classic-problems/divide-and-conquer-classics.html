第 12 章 · 分治

代价在合并还是在划分

归并排序代价在合并、快排代价在划分，最近点对展示了跨分界线也能常数代价，Strassen 与 Karatsuba 则用加法换乘法改进指数。

归并排序：代价全在「合并」

分解是 O(1)（算个中点），递归求解两个子区间，真正的功夫在合并：两个已排序的子数组用双指针每次取较小者，线性扫一遍即可。

def merge_sort(a):
    if len(a) <= 1: return a
    m = len(a) // 2
    left, right = merge_sort(a[:m]), merge_sort(a[m:])
    i = j = 0; out = []
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:   # <= 保证稳定性
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]
  • 复杂度：T(n) = 2T(n/2) + Θ(n) → Θ(n log n)，且最好最坏平均都是它。
  • 稳定（相等时先取左边），但需要 O(n) 额外空间。
  • 适合外排序：数据大到内存放不下时，归并的顺序读特性对磁盘极其友好。

快速排序：代价全在「划分」

快排先花 Θ(n) 把数组按基准值划分成两半，然后递归。它不需要合并步骤，也几乎不占额外空间，但代价是：划分得好不好直接决定复杂度。

  • 平均：T(n) = 2T(n/2) + Θ(n) → Θ(n log n)。
  • 最坏（每次基准都是最大或最小，如已排序数组取首元素）：T(n) = T(n−1) + Θ(n) → Θ(n²)。
  • 应对：随机选基准、三数取中、三路划分（大量重复元素时）、小规模切换插入排序。
  • 不稳定、原地（递归栈 O(log n)~O(n)）。

工程上的默认排序几乎都是快排的变体（内省排序 introsort 会在递归过深时切换成堆排序，保证最坏 O(n log n)）。

最近点对：分治的精髓在「跨中线」

平面 n 个点求最近距离。暴力是 O(n²)，分治做法：

  1. 按 x 排序，从中间切开，分别求左右两侧的最近距离 δ。
  2. 跨中线的点对只在距离中线小于 δ 的竖条里可能更近。
  3. 关键观察：竖条内每个点只需检查常数个（约 6~7 个） y 序上的后继——因为同侧任意两点距离已 ≥ δ。

保持 y 序的归并技巧让第 3 步线性完成，总复杂度 T(n) = 2T(n/2) + Θ(n) → Θ(n log n)。

这一步是分治里最漂亮的证明之一：它说明「跨分界线的合并」不一定是昂贵的，只要利用子问题已经给出的信息（δ）就能把候选项压到常数。

Strassen 与 Karatsuba：少做一次乘法

Strassen 矩阵乘法

两个 n×n 矩阵分块相乘原本需要 8 次子乘法，Strassen 用 7 次特定线性组合的乘法凑出结果：T(n) = 7T(n/2) + Θ(n²) → Θ(n2.81)，优于 Θ(n³)。代价是常数大、数值稳定性略差，实际只在 n 很大时使用。

Karatsuba 大整数乘法

两个 n 位整数原本需要 4 次 n/2 位乘法，Karatsuba 用 3 次：T(n) = 3T(n/2) + Θ(n) → Θ(n1.585)，优于小学竖式的 Θ(n²)。

这两者的共同思路：用加法换乘法。加法是 Θ(n)，乘法才是瓶颈，所以减少乘法次数就能改进指数。

什么时候该想到分治

信号例子
问题能切成结构相同的子问题排序、选择、最近点对
子问题之间不重叠分治与 DP 的分界线就在这里
合并步骤可以做到比暴力更省归并的线性合并、最近点对的常数候选
需要 O(n log n) 而不是 O(n²)逆序对、第 k 大

如果子问题大量重复（如斐波那契、背包），分治会指数爆炸，应该用动态规划或记忆化。
