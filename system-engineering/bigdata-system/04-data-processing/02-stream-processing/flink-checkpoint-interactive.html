四、Checkpoint 与精确一次（Exactly-Once）

Flink 的容错与精确一次语义建立在 Chandy-Lamport 分布式快照算法之上。核心思想是：在数据流中周期性注入屏障（Barrier），让所有算子对齐 barrier 后做一次一致性状态快照。

  • Barrier 随数据流动：Source 按 Checkpoint 间隔发出 barrier n，barrier 与业务数据一起沿 DAG 流动。
  • 算子对齐（Alignment）：对有多输入的算子（如 join、keyBy 后窗口），需等待所有上游通道的同一编号 barrier 都到齐才开始快照——先到的通道数据被缓存（对齐期间），避免混入下一快照的数据。
  • 状态快照：对齐完成后，算子把自身状态（如窗口聚合值）异步写入状态后端（Heap/RocksDB），并向 JobManager 的 Checkpoint Coordinator 汇报完成。
  • 两阶段提交（2PC）对外输出：对 Kafka 等 Sink，Flink 用 TwoPhaseCommitSinkFunction——barrier 通过时先预提交事务，等所有算子 Checkpoint 成功后由 JobManager 通知 Sink 正式提交，保证"状态与输出要么都成功要么都回滚"。
精确一次 vs 至少一次：至少一次（At-Least-Once）指每条数据被处理 ≥1 次，故障重放可能重复（如 1→2 次），需要业务幂等去重；精确一次（Exactly-Once）指每条数据对最终结果恰好生效一次——Flink 通过 barrier 对齐 + 状态快照 + 2PC Sink 实现"端到端精确一次"。注意这是结果精确一次，内部重放时数据可能被处理多次，只是副作用被抵消。
