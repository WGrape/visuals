🏗️ Ehcache 分层存储与持久化

堆内、堆外、磁盘三层如何协同，以及重启后如何让缓存数据不丢。

🏗️

三层模型

heap → offheap → disk

⬇️

降级

上层满了淘汰到下层

💾

持久化

磁盘层可跨重启保留

🔑

必须序列化

存非堆层的硬要求

先建立直觉：办公桌、抽屉、档案室

  • 堆内（heap）：办公桌面——最快，但地方小，而且要定期打扫（GC 扫描）。
  • 堆外（offheap）：办公桌抽屉——稍慢，空间大，不用打扫（不在 GC 范围）。
  • 磁盘（disk）：档案室——最慢，但容量大且关灯（重启）后东西还在。

数据在这三层之间自动流动：上层放不下就降级到下层，被访问时又会被提到上层。

分层结构

重要规则：容量必须逐层增大。下层容量必须大于上层（如 heap 1000 条、offheap 100MB、disk 1GB），否则下层装不下上层淘汰下来的数据，配置会报错或行为异常。

配置示例

// Java 配置
CacheManager cacheManager = CacheManagerBuilder.newCacheManagerBuilder()
    .with(CacheManagerBuilder.persistence("/var/data/ehcache"))  // ① 持久化目录
    .withCache("userCache",
        CacheConfigurationBuilder.newCacheConfigurationBuilder(
            Long.class, User.class,
            ResourcePoolsBuilder.newResourcePoolsBuilder()
                .heap(1000, EntryUnit.ENTRIES)        // 堆内 1000 条
                .offheap(100, MemoryUnit.MB)          // 堆外 100MB
                .disk(2, MemoryUnit.GB, true))        // 磁盘 2GB，true = 持久化
        .withExpiry(ExpiryPolicyBuilder.timeToLiveExpiration(Duration.ofHours(1)))
    ).build(true);
参数说明
heap(n, ENTRIES)堆内最多 n 条
offheap(n, MB)堆外最多 n MB
disk(n, GB, true)磁盘 n GB；末位 true 表示持久化（重启保留）
persistence(dir)磁盘数据的存放目录
disk 的第三个参数很关键：true 表示持久化（CacheManager 关闭后数据保留在磁盘，下次启动可恢复）；false 表示仅作为临时分层（关闭时清空）。想要「重启后缓存还在」必须设为 true。

持久化的注意事项

  • 必须显式关闭 CacheManager：调用 cacheManager.close()，否则数据可能没落盘。Spring 环境中通常由容器在销毁时调用。
  • key 和 value 都要可序列化：这是硬要求，否则存不进堆外/磁盘层。
  • 类结构变更会导致反序列化失败：给缓存对象加 serialVersionUID，并谨慎修改字段。
  • 磁盘 IO 会拖慢延迟：落到磁盘的数据访问要走 IO，毫秒级甚至更慢，不要让延迟敏感的链路依赖磁盘层。
不要指望磁盘层提供高性能。它是容量兜底而非加速层。真正需要低延迟的数据应该留在堆内/堆外；磁盘层的作用是「数据量大 + 可容忍慢 + 希望重启不丢」。

什么时候需要分层

场景建议配置
数据量小（几十 MB），追求速度只配 heap（或直接用 Caffeine）
数据量大（几百 MB~几 GB），GC 压力大heap + offheap
数据量超过内存，且可容忍慢 + 需重启保留heap + offheap + disk（持久化）

🎯 面试问答

Q：配置了 disk 层，重启后数据一定还在吗？
A：取决于两点：① disk 的第三个参数是否为 true（表示持久化）；② CacheManager 是否被正常关闭（close()）。如果进程被 kill -9 强杀，未完成落盘的数据会丢失。建议：应用关闭时通过钩子确保 cacheManager.close() 被调用；同时不要把持久化当作可靠存储，重要数据仍要以数据库为准。

Q：为什么我的对象存不进堆外层？
A：最常见原因是没有实现 Serializable。堆外和磁盘层存储的是字节，必须能序列化和反序列化。此外还要注意：对象内部引用的所有嵌套对象也必须可序列化；并且 Ehcache 3 默认使用自己的序列化器，对复杂对象可能有额外要求。建议给缓存类实现 Serializable 并声明 serialVersionUID。

Q：三层容量可以随便配吗？
A：不能。规则是下层容量必须大于上层。因为上层的淘汰数据要降级到下层，如果下层更小就装不下，Ehcache 会在初始化时报错。典型配置：heap（条数，最小）→ offheap（MB，中等）→ disk（GB，最大）。另外 heap 层通常按条目数限制，offheap/disk 按字节限制。

Q：分层的淘汰是怎么工作的？
A：数据优先放在最上层（heap）。当 heap 满了，被淘汰的数据降级到 offheap（不是直接丢弃）；offheap 满了再降级到 disk；disk 也满了才真正丢弃。访问时反向提升：在 disk 层被访问的数据会被提到上层。这本质上是一个单机内的多级缓存，热点自动上浮、冷数据自动下沉。
