数组：定长值类型

长度属于类型的一部分

[3]int 和 [4]int 是不同类型，不能互赋；数组赋值是整份拷贝；可比较（元素可比时）。

var a [3]int = [3]int{1, 2, 3}
b := a          // 整份拷贝，b 与 a 独立
b[0] = 9
fmt.Println(a[0]) // 1（a 不受影响）

// 作为参数会整体拷贝，通常改用切片
func sum(s [3]int) int { ... }
切片：三元组

ptr 指向底层数组，len 可见长度，cap 到数组末尾

切片本身很小（约 24 字节），操作高效。len 是你能访问的元素数，cap 是从起始位置到底层数组末尾的总数。

s := []int{1, 2, 3}      // 字面量，自动建底层数组
fmt.Println(len(s), cap(s)) // 3 3

s2 := make([]int, 2, 8)    // len2 cap8

s3 := s[1:3]              // 切片表达式，共享底层数组
fmt.Println(len(s3), cap(s3)) // 2  (cap: 从索引1到末尾=2)
扩容 append

超容量会分配新数组

append 在 cap 足够时复用底层数组；不够时分配更大的新数组并拷贝，返回指向新数组的切片。这正是「为什么有时改得到、有时改不到」的根源。

s := make([]int, 0, 2)
s = append(s, 1, 2)
p := &s[0]
s = append(s, 3)   // 超出 cap，换底层数组
// 此时 *p 仍是旧数组的元素，与 s[0] 不再同一份
扩容策略大致为：小切片翻倍，大切片按约 1.25 倍增长（具体随版本调整）。预知规模时用 make 指定 cap 能显著减少拷贝。
共享底层数组的陷阱

切片表达式会共享，修改互相影响

用 s[i:j] 得到的子切片和原切片共享底层数组，一处修改另一处可见——这既是性能优势，也是 bug 温床。

a := []int{1, 2, 3, 4}
b := a[1:3]   // b = [2,3]，共享底层
b[0] = 99
fmt.Println(a) // [1 99 3 4]  原数组被改！

// 想要独立副本
c := make([]int, len(b))
copy(c, b)

切片的三个字段与扩容规律

切片本身只是一个三字段的小结构：指向底层数组的指针、可见长度 len、到数组末尾的容量 cap。所有关于切片的行为，都可以从这三个字段推出来。

切片三要素：理解它们，就能预测所有切片行为
场景行为结果
append 后 len 不超过 cap直接写入底层数组，不分配快，但可能覆盖其他切片的可见元素
append 后超过 cap分配更大的新数组并拷贝返回的新切片与原数组脱钩
扩容（Go 1.18 及以后）容量小于 256 时翻倍，之后约按 1.25 倍增长再做内存规格向上取整
所需容量大于两倍 cap直接使用所需容量，不再翻倍一次性大追加时避免过度浪费

扩容后新数组与原数组不再共享，这是最容易踩的坑：如果你期望 append 影响原切片，一旦触发扩容，修改就丢失了。所以 append 的返回值必须被接收。

append 的共享陷阱与正确写法

两个切片指向同一段底层数组时，通过其中一个修改元素，另一个也会看到变化。这不是 bug，而是切片的本质，但它确实会造成意外。

a := []int{1, 2, 3, 4, 5} b := a[1:3] // b 与 a 共享底层数组，b = [2 3] b[0] = 99 // 改 b 会影响 a // a 现在是 [1 99 3 4 5] // 想彻底独立，必须显式拷贝 c := make([]int, len(b)) copy(c, b) c[0] = 7 // 不会再影响 a // 截取时的另一个坑：第三个参数限制容量 d := a[1:3:3] // len=2, cap=2，而不是 cap=4 // 这样 append(d, x) 一定会分配新数组，不会污染 a // 删除元素（保持顺序） i := 2 a = append(a[:i], a[i+1:]...) // 删除元素（不保持顺序，更快：用末尾元素覆盖） a[i] = a[len(a)-1] a = a[:len(a)-1] // 清空但保留容量，便于复用减少分配 a = a[:0] // 注意：a = nil 会连底层数组一起释放，两者用途不同

数组与切片的关键差异

赋值与传参行为完全不同

数组是值类型，赋值和传参都会整体拷贝，所以 三个元素的数组与四个元素的数组是两个不同的类型，长度写在类型里。切片赋值只拷贝那三个字段，传参开销恒定且很小。

什么时候该用数组

数组适合长度固定、需要在类型层面表达长度的场合，比如固定长度的哈希值、坐标、矩阵维度。日常绝大多数序列都应该用切片，因为它的长度可变且传参便宜。

数组是值赋值拷贝整个数组，长度属于类型
切片是视图三字段结构，拷贝只复制指针与长度
append 要接收返回值扩容后底层数组会变
截取共享底层数组改一个影响另一个
要独立就 copy显式拷贝才是真的独立
限制容量用三参数s[a:b:c] 可避免 append 污染
清空用 s[:0]保留容量便于复用
nil 切片可直接 append零值为 nil，但 append 仍可用

深入自检：关于切片的六个问题

为什么 append 后原切片没变？

因为 append 返回的是新的切片头。如果触发了扩容，数据被拷到新数组，原切片的 len 没变，所以看起来没变。即使没扩容，原切片的 len 也仍然不变，它只是不知道后面多了元素。所以必须用 s = append(s, x) 的形式。

for range 里取元素地址为什么都指向同一个？

因为 range 的第二个变量是每次循环复用的同一个变量。对它取地址得到的都是同一个地址，值就是最后一次迭代的值。正确做法是对切片元素取地址，或者在循环内创建一个局部副本。

切片作为函数参数能修改长度吗？

不能直接改调用方的长度。函数内 append 只会改自己的副本。想让调用方看到，要么返回新切片让调用方接收，要么传切片的指针，后者在需要原地增删时常用。

copy 的返回值是什么？

是实际拷贝的元素个数，等于两个切片长度的较小值。它不会自动扩容目标切片，如果目标长度不够，只会拷贝能装下的部分。所以拷贝前要确保目标已经 make 到足够长度。

大切片截取后不释放会内存泄漏吗？

会。如果你从一个很大的切片里截了一小段长期持有，底层的大数组会一直被引用而无法回收。解法是把需要的部分 copy 到一个新切片，然后放弃对原切片的引用。

二维切片怎么创建？

切片的元素类型可以是切片，所以是二维切片。注意每行是独立的底层数组，需要逐行 make 或用 append；直接声明只是外层切片，内层还是 nil，访问会 panic。

切片底层结构与扩容规则

创建与切分

// runtime 定义
type slice struct {
    array unsafe.Pointer    // 指向底层数组
    len   int               // 当前长度
    cap   int               // 容量
}
// 切片头是 <b>24 字节</b>（64 位），传参时<b>复制这 24 字节</b>，但<b>共享底层数组</b>

// 三种创建方式
var s []int                       // nil 切片，len=cap=0，ptr=nil
s := []int{1, 2, 3}               // 字面量
s := make([]int, 5)               // len=5, cap=5，元素为零值
s := make([]int, 0, 100)          // len=0, cap=100（预分配，推荐）
s := make([]int, 5, 10)           // len=5, cap=10

// 从数组/切片切
a := [5]int{1,2,3,4,5}
s := a[1:3]                       // len=2, cap=4（cap = 原cap - 起始下标）
s := a[1:3:3]                     // 三索引：len=2, cap=2（限制 cap，append 必重新分配）
扩容前 cap扩容后（Go 1.18+）说明
< 256×2小切片翻倍
≥ 256×1.25 左右（newcap += (newcap + 3*256) / 4）增长放缓，避免过度浪费
append 多个元素按需要的总量算，再套上面的规则

扩容与删除

// 扩容实测（Go 1.20+）
s := make([]int, 0)
prev := 0
for i := 0; i < 2000; i++ {
    s = append(s, i)
    if cap(s) != prev {
        prev = cap(s)
        if i < 600 { fmt.Println(i, cap(s)) }
    }
}
// 典型输出：0->1, 1->2, 2->4, 4->8, ... 256->512, 512->848(约1.66x), 848->1280
//   <b>注意：扩容会分配新数组 + 拷贝旧数据</b>，所以要预分配

// 预分配的收益
s := make([]int, 0, n)      // 一次分配
for i := 0; i < n; i++ { s = append(s, i) }
//   对比不预分配：n=100万 时，省掉约 20 次重新分配和拷贝，快 2~3 倍

// 删除元素（三种方式）
s = append(s[:i], s[i+1:]...)                 // 会移动后续元素，O(n)
s[i] = s[len(s)-1]; s = s[:len(s)-1]          // 无序删除，O(1)，<b>更快</b>
copy(s[i:], s[i+1:]); s = s[:len(s)-1]        // 同第一种
//   ⚠️ 删除后最后一个元素仍被底层数组持有 -> 若是指针会<b>内存泄漏</b>
s[len(s)-1] = nil                              // 先置零再截断

最常见的一个 bug：append 之后不接收返回值。append(s, x) 可能因为扩容返回了一个指向新数组的切片，原切片 s 的 len 不变。永远写 s = append(s, x)。另一个高频 bug：把切片传给函数后函数内 append，调用方看不到变化（只会改局部的 header）——要传指针 *[]T 或返回新切片。

共享底层数组引发的坑

坑场景解法
子串共享底层big[:10] 让 big 无法被 GCslices.Clone 或 append([]T(nil), s...)
append 覆盖两个切片同底层，一个 append 改写了另一个的数据三索引限 cap：a[0:2:2]
删除后残留引用截断后末尾元素仍被底层数组持有（指针/结构体）先置零再截断
循环里 append 到共享切片多个 goroutine 同时 append 同一底层数组加锁或每个 goroutine 独立切片
函数内 append 无效只改了局部 header传 *[]T 或返回

三大陷阱

// 经典陷阱 1：append 覆盖了另一个切片的数据
a := []int{1, 2, 3, 4, 5}
b := a[:2]                // b 与 a 共享底层，cap(b)=5
b = append(b, 99)         // 没扩容，直接写在底层数组第 3 位
fmt.Println(a)            // [1 2 99 4 5]  <- a 被改了！
fmt.Println(b)            // [1 2 99]

// 解法：三索引限制 cap，强制 append 时重新分配
b := a[:2:2]
b = append(b, 99)         // cap 已满 -> 新分配
fmt.Println(a)            // [1 2 3 4 5]  安全

// 经典陷阱 2：循环里用 append 收集结果时的共享
var res [][]int
row := []int{1, 2, 3}
for i := 0; i < 3; i++ {
    res = append(res, row[:2])      // 三个元素都指向同一底层数组！
}

// 经典陷阱 3：for-range 里取地址
var ps []*int
for _, v := range []int{1, 2, 3} {
    ps = append(ps, &v)             // <b>Go 1.22 前：三个指针都指向同一个 v</b>！
}
//   解法：v := v（重新声明）
for _, v := range s { v := v; ps = append(ps, &v) }
数组和切片到底有什么区别？

最本质的两点：① 数组是值类型，长度是类型的一部分——[3]int 和 [4]int 是不同类型，传参会复制整个数组；② 切片是引用语义的描述符——24 字节的 header 指向底层数组，传参只复制 header。所以实际代码里 99% 用切片，数组只在「固定长度且要值语义」的场景用（如哈希值 [32]byte）。

cap 到底该设多少？

原则：能预估就预估。make([]T, 0, n) 的成本只是一次分配，而扩容的成本是「分配 + 拷贝 + 旧数组待 GC」。经验值：① 明确知道 n 就直接写 n；② 从另一个集合转换时（如 len(keys)）用它当 cap；③ 完全无法预估时，让 append 自己扩（Go 1.18+ 的策略已经比较平缓）。注意别过度预分配——cap 设 1000 万会立刻占掉 80MB 内存。

copy 的返回值是什么？

返回实际拷贝的元素个数，等于 min(len(src), len(dst))。这个特性很有用：① copy(dst, src) 不会自动扩容 dst——如果 dst 太短，只拷贝一部分（这是常见 bug）；② 可以用它做「环形缓冲」和「滑动窗口」；③ copy(s[i:], s[i+1:]) 是原地删除的标准写法。另外 copy 对重叠内存是安全的（内部用 memmove）。
