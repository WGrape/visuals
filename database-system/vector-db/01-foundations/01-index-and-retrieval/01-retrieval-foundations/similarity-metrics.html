余弦相似度（Cosine Similarity）

衡量两个向量方向的一致程度，与长度无关。范围 [-1, 1]，越大越相似（1 完全相同方向，0 正交不相关，-1 反向）。

cos(A,B) = (A·B) / (||A|| · ||B||)

语义检索里最常用，因为"意思相近"更关心方向而非模长。例：长文档和短文档意思一样，余弦能对齐，纯内积会被长度带偏。

内积（Dot Product）与余弦的关系

A·B = ||A|| · ||B|| · cos(A,B)

内积 = 余弦 × 两个向量的模长。所以当 A、B 都做了 L2 归一化（模长=1）时，内积就完全等于余弦相似度：

若 ||A||=||B||=1，则 A·B = cos(A,B)

这就是为什么很多向量库默认要求你归一化：归一化后用内积检索，结果和余弦一致，但内积计算更快（少了两次开方/除法），且底层可以用内积专用的硬件加速（如 SIMD、GPU TensorCore）。

实践：文本检索 → 模型输出后先 L2 归一化 → 用内积（IP）建索引与查询。一行代码的事，但能避免一大类"相似度不对"的 bug。

欧氏距离（L2 / Euclidean）

||A-B|| = sqrt( Σ (A_i - B_i)² )

衡量向量在几何空间中的"直线距离"，同时受方向和长度影响。范围 [0, +∞)，越小越相似（注意方向与余弦相反）。适合对"绝对量"敏感的场景（如坐标、特征幅度有意义的任务）。在纯语义文本检索里用得比余弦少，因为它会被向量长度干扰。

一个有用的恒等式（归一化后）：

||A-B||² = 2 - 2·cos(A,B)　（当 ||A||=||B||=1）

也就是说，归一化之后 L2 排序与余弦排序完全等价——只是单调相反（L2 越小 ⇔ 余弦越大）。所以归一化后三种度量选哪个主要看计算效率与索引支持，而不是结果差异。

另外两种值得一知道的度量

曼哈顿距离 L1Σ|A_i - B_i|，各维度绝对差之和。对离群维度更"钝"，高维稀疏场景有时优于 L2
汉明距离 Hamming二进制向量间不同位的个数。用于二值化Embedding，1 字节能存 8 维，极省内存
Jaccard / Tanimoto集合交并比，适合"标签集合"型稀疏特征
汉明距离的典型用法：把浮点 Embedding 二值化（>0 记 1，否则 0）后，768 维向量从 3072 字节压到 96 字节——内存降 32 倍，用汉明距离做粗排，再用原始向量精排。这是大规模向量库常见的"两段式"方案。

怎么选度量（决策表）

你的数据推荐度量原因
语义文本（BGE/BERT 等）余弦 / 归一化内积只关心语义方向

图像/特征，幅度有意义L2 欧氏方向与长度都重要
需要"不相关=0、反向=-1"语义余弦有明确符号语义
超大规模、内存吃紧二值化 + 汉明内存降数十倍，粗排用
推荐系统（双塔模型）内积（不归一化）模长被训练成"热度"信号，有用
坑：同一个向量库里，建索引时用的度量和查询时用的度量必须一致。用内积建的 HNSW，查询却按余弦距离排序，结果会错（而且不会报错，只是结果 quietly 变差）。

为什么通常先归一化

  • 统一度量：归一化后内积 ≡ 余弦 ≡ L2 排序，避免"长度污染相似度"。
  • 数值稳定：向量模长差异巨大时，内积会被长向量主导，归一化消除这种偏差。
  • 加速：省去查询时的归一化除法，且能用内积专用硬件加速。
  • 注意：归一化会丢失"长度"信息。若你的任务恰恰需要长度（如双塔召回里模长被训练成热度），就不要归一化，改用原始内积。
import numpy as np
def l2_normalize(v):
    return v / np.linalg.norm(v, axis=-1, keepdims=True)

q = l2_normalize(model.encode("如何调优 MySQL"))   # 归一化一次
# 之后用内积检索，结果 == 余弦，且更快
scores = docs_matrix @ q      # 内积

五个高频踩坑

  • 度量不一致：建索引用 IP、查询用 cosine → 结果错但不报错。建库时就把度量写进配置并加断言。
  • 忘记归一化却用了 IP：长文档向量模长大，永远排在前面 → 召回全是长文。
  • 把 L2 当"越大越好"：L2 是距离，越小越相似；做 Top-K 排序时别用反了。
  • 模型换了但库没重建：不同 Embedding 模型的向量空间不兼容，换模型必须全量重建索引。
  • 归一化在写入侧做、查询侧漏做：只归一化了一边，等价于没归一化。两边都要做。

    • 🎯 常见问法与答题要点

    Q：余弦、内积、欧氏距离该怎么选？

    A：一句话：文本语义检索用余弦（或归一化后的内积）；图像/特征且幅度有意义用 L2；已归一化追速度用内积。更关键的是：归一化之后三者排序完全等价（L2² = 2-2cos），所以真正要决策的是「要不要归一化」——如果模长是有信息的信号（如双塔召回里的热度），就别归一化并用原始内积；否则一律归一化后用 IP，最快也最稳。

    Q：为什么归一化后内积等于余弦？

    A：因为内积的定义就是 A·B = ||A||·||B||·cos(θ)。当两个向量都 L2 归一化到模长 1 时，||A||·||B|| = 1，于是 A·B = cos(θ)。这不是近似，是恒等。所以「先归一化、再用内积检索」既拿到了余弦的语义（只比方向），又拿到了内积的速度（少两次开方和一次除法，还能用 SIMD/GPU 加速）。

    Q：建索引和查询用不同度量会怎样？

    A：结果会错，而且不报错——这是最坑的地方。索引结构（如 HNSW 的图连边、IVF 的聚类）是根据建索引时的度量构建的，查询时用另一个度量去走这张图，等于「用错误的尺子量距离」。表现通常是召回率莫名其妙偏低，且很难排查。防范：把度量写进配置常量，写入与查询共用同一份常量。

    Q：L2 距离越大越相似还是越小越相似？

    A：越小越相似。L2 是距离（distance）不是相似度（similarity），0 表示完全重合。做 Top-K 排序时要升序取最小的 K 个——与余弦/内积的降序相反。很多向量库 API 会统一成「分数越大越好」的语义（返回负距离或转换后的分数），用之前务必看清文档。

    Q：换 Embedding 模型后需要重建索引吗？

    A：必须全量重建。不同模型（甚至同一模型的不同版本/不同训练 checkpoint）产出的向量空间不兼容，768 维的 BGE 向量和 768 维的 M3E 向量在几何上没有任何对应关系。混在一起检索等价于用随机向量检索。所以换模型 = 重新 encode 全量文档 + 重建索引，这是向量库运维中最重的一个操作，要提前规划。

    Q：汉明距离用在什么场景？

    A：用在二值化 Embedding 上：把浮点向量按「>0 记 1、否则记 0」压成比特串，然后比较两个比特串有多少位不同。好处是内存极省——768 维浮点是 3072 字节，二值化后只有 96 字节，省 32 倍；距离计算也能用 CPU 的 popcount 指令一次处理 64 维。代价是有精度损失，所以通常做粗排（快速召回几百条），再用原始浮点向量精排。

    关系与手算

    import numpy as np

def cosine(a, b): return a @ b / (np.linalg.norm(a) * np.linalg.norm(b))

# 关键关系（背下来就能互推）：
#   若 a、b 已归一化（|a|=|b|=1）：
#       ||a - b||^2 = |a|^2 + |b|^2 - 2(a·b) = 2 - 2·cos(a,b)
#   即：<b>归一化后 L2 与余弦单调等价，排序结果完全一致</b>
#       cos = 1 - L2^2 / 2

a = np.array([1.0, 2, 3]); b = np.array([2.0, 4, 6])   # b = 2a，方向相同
print(cosine(a, b))            # 1.0     方向完全一致
print(np.linalg.norm(a-b))     # 3.74    距离却不小（因为模长不同）
#   => 只想比「方向/语义」用余弦；模长有意义时用内积或 L2

# 归一化（把向量变成单位长度，之后内积 == 余弦）
a_n = a / np.linalg.norm(a)

    实践结论：文本 embedding（如 BGE、OpenAI、Sentence-BERT）几乎都用余弦，因为语义相似度体现在方向上；且多数模型训练时就用了归一化，所以内积和余弦等价。工程上常用技巧：入库前归一化，然后用内积检索——内积计算最少（省掉两次开方），且多数向量库（FAISS 的 IndexFlatIP、Milvus 的 IP）对内积有 SIMD 优化。

    文本语义搜索余弦模长无意义，只看方向

    去重 / SimHash汉明距离二值向量
    异常检测L2 或马氏距离要考虑分布的用马氏
    余弦相似度会不会忽略重要信息？

    会——它丢弃了模长。在某些场景模长是有意义的：比如 embedding 模型的模长有时与「文本的确定程度/信息量」相关；推荐里用户向量的模长可能反映活跃度。判断方法：先跑一版余弦，再跑一版内积，对比召回结果的 NDCG。多数 NLP 场景余弦更好或持平。

    为什么我算的余弦和向量库返回的不一样？

    三种常见原因：① 没归一化就用了内积索引；② 向量库的 COSINE 实现有的是 1 - cos（距离形式，越小越像），有的是 cos（越大越像）——要看文档确认方向；③ 精度损失：PQ 量化或 FP16 存储会让分数有偏差，排序也可能微变。

    维度很高时（如 1536 维）余弦还可靠吗？

    可靠，但要注意维度灾难：高维空间中随机向量之间的余弦会趋近 0，距离区分度下降。实测上 768~1536 维的 embedding 仍然工作良好（因为真实数据分布是低维流形，不是均匀分布）。如果区分度差，可以：① 用 PCA 降维到 256~512 维（通常损失很小）；② 用 Matryoshka 类模型（支持截断维度）；③ 检查 embedding 模型本身是否合适。
