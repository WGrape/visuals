视频生成的时序一致性：让角色跨帧仍是同一人

把外观、几何、运动和片段边界当作不同约束处理。

学完能解释什么

  • 分辨闪烁、身份漂移与运动不连续三种错误
  • 说明跨帧条件与长时记忆在生成链路中的作用
  • 按运动、遮挡和跨镜头切换评估一致性

逐步看机制

固定主体、场景与故事条件

角色外观和道具作为持久状态，镜头变化和光照变化要与“身份改变”区分。

一致性不是“每帧都长得一样”

人转头、进入阴影或相机运动时像素当然会变化；错误在于无因由地变脸、衣纹随机闪烁、道具瞬间消失或运动方向突然反转。外观一致关注身份和纹理，几何一致关注物体位置与形变，运动一致关注速度与因果方向，三者要分别检查。

模型怎样共享跨帧信息

把帧作为时空 token 一起生成，可用时序注意力或特征传播关联同一主体；参考图、跟踪特征和显式相机/姿态条件能帮助锁定身份。邻帧光流或重投影可约束局部平滑，但遮挡、出画再入画和大运动会让对应关系失效。过强平滑又会让正常运动变成拖影，不能只最小化相邻像素差。

长视频为何更难

分块或自回归延展会扩大累积误差：早期的小偏差可能让后续人物、背景和镜头逐步漂移。分段边界可传递条件帧、压缩状态或主体特征，但记忆过久也可能压制场景变化。测试必须覆盖长镜头、遮挡、多个相似角色和跨镜头切换。

评估可结合对象跟踪稳定性、跨帧特征/重投影残差、动作文本对齐和人工盲评。指标低不一定表示画面好，例如完全冻结的视频也能“很稳定”。

自检

每帧完全相同是否意味着生成视频时序质量很高？

不意味着。冻结画面可能非常稳定却没有正确动作；要同时检查运动、指令遵循和主体一致性。

主流解法

解法做法效果代价
时序注意力在 U-Net 里加入跨帧的自注意力层，让每帧能参考其他帧效果好，是主流方案显存与算力增加明显
3D 卷积 / 时空 U-Net把 2D 卷积换成 3D，或时空分离注意力结构统一，易扩展参数量大
光流引导先估计帧间光流，用它把上一帧 warp 到当前帧做约束对大运动有效光流计算慢，误差会累积
潜空间传播把上一帧的潜变量部分保留/插值到当前帧简单高效长视频会漂移
分层生成先生成关键帧/低分辨率长序列，再插帧与超分适合长视频管线复杂
锚帧 + 插帧先生成首尾或关键锚帧，再补中间帧一致性最好中间帧受锚帧限制

实践中的取舍

短片段（2~4 秒）

直接在时空 U-Net 里加时序注意力，端到端一次生成全部帧。这是目前主流（如 Stable Video Diffusion 类方案）的做法，一致性已经不错。

长视频（几十秒以上）

显存撑不住一次生成所有帧。常见策略：滑动窗口——每次生成一小段，段与段之间保留重叠帧做平滑过渡；或锚帧 + 插帧；或自回归逐段续写（但容易累积漂移）。

漂移问题

自回归续写时，误差会逐段累积：第 100 帧的主角可能已经和第 1 帧不一样了（身份漂移）。对策：定期回到锚帧做校准、引入长期记忆、或在潜空间做全局一致性约束。

与插帧的区别

插帧（帧插值）是在已有两帧之间补中间帧，输入是真实的，一致性天然更好。视频生成是从无到有，没有真实帧可参考，一致性全靠模型内部约束，所以难得多。

怎么评估一致性

光流一致性用光流 warp 相邻帧，误差越小越连贯
CLIP 帧相似度逐帧 CLIP 特征的余弦相似度曲线，看是否有突降
像素级指标帧间 PSNR/SSIM（但过于严格，轻微合理运动也会被判差）
身份一致性检测人脸/主体特征，看是否发生身份漂移
人工评分最终标准，尤其对主观的「闪烁感」

深入自检

视频生成为什么比图像生成难这么多？

除了计算量（多一个维度）之外，最核心的是一致性约束：图像生成只要单张好看就行，视频生成要求几十上百帧都好看而且彼此连贯。逐帧独立生成时，每帧都是从噪声独立采样出来的，模型没有义务让第 t 帧和第 t-1 帧保持一致，于是出现颜色跳变、物体闪烁、身份漂移。解决它需要在模型内部建立跨帧的信息通道（时序注意力、3D 卷积等），而这又带来显存和算力的急剧增长——这就是视频生成的核心矛盾。

时序注意力是怎么保证连贯的？

它在 U-Net 的中间层插入跨帧的自注意力：对于第 t 帧的某个空间位置，注意力机制可以去「看」其他帧（尤其是相邻帧）对应位置的特征，并把它们的信息加权融合进来。这样一来，模型在生成第 t 帧时就明确知道第 t-1 帧长什么样，自然会生成与之接近的内容。代价是注意力复杂度随帧数增长，所以实践中常用时空分离注意力（先空间后时间）或局部时间窗口来控制成本。

长视频生成为什么会「越往后越不像」？

这是误差累积 / 漂移问题。自回归或滑动窗口生成时，每一段都以上一段的最后几帧为条件，任何微小的偏差都会被下一段继承并放大——就像传话游戏，传到第 10 个人时内容已经面目全非。表现为主角的脸慢慢变了、衣服颜色渐渐偏移、背景结构漂移。缓解办法：①锚帧机制——先生成若干关键帧作为「锚」，中间内容向锚对齐；②全局条件——让所有帧都共享同一个全局语义/身份向量；③定期校准——每隔 N 帧用第一帧做一次一致性约束。

插帧（帧插值）能解决一致性问题吗？

能部分解决，但适用面不同。插帧是在已存在的两帧之间生成中间帧，输入是真实的，所以一致性天然有保障，常用于提升帧率（24fps→60fps）和慢动作。做法通常是先估计双向光流再做形变与融合。视频生成则是从文本/噪声生成全新内容，没有真实帧可参考。实践中两者常组合使用：先生成稀疏的关键帧（保证长程一致性），再用插帧模型把它们补成流畅的高帧率视频——这样既省算力又保证连贯。

怎么判断一个生成视频的一致性够不够？

自动指标 + 人眼结合。自动方面：①光流 warp 误差——用估计的光流把第 t 帧 warp 到第 t+1 帧，重投影误差越小越连贯；②CLIP 帧相似度曲线——逐帧算 CLIP 特征余弦相似度，突降点就是「跳变」位置；③身份一致性——对有人物的视频做人脸识别，看 ID 是否切换。但这些都只是近似，人眼主观评分仍是最终标准——因为「闪烁感」是主观感知，有时指标正常但人看着就是不舒服。建议建立一个小的主观评测集（20~50 条）定期打分。

# 2) 光流重投影误差（需要 RAFT / SpyNet）
python - <<'PY'
import torch, cv2
def warp_error(prev, curr, flow):
    """flow: (2,H,W) 从 prev 到 curr 的光流"""
    h, w = curr.shape[:2]
    grid_x, grid_y = torch.meshgrid(torch.arange(w), torch.arange(h), indexing='xy')
    warped = torch.nn.functional.grid_sample(
        torch.from_numpy(prev).permute(2,0,1).float().unsqueeze(0),
        torch.stack([(grid_x + flow[0]).clone(), (grid_y + flow[1]).clone()], -1).unsqueeze(0)
            .mul(2).div(torch.tensor([w, h])).sub(1),
        mode='bilinear', align_corners=False)
    return (warped - torch.from_numpy(curr).permute(2,0,1).float()).abs().mean().item()

深入自检

为什么单帧指标好但播放很难看？

因为 PSNR/SSIM/LPIPS 都是逐帧计算的空间指标，它们完全不约束「相邻帧是否一致」。逐帧独立生成可以让每一帧都很清晰，但同一块纹理每帧生成出不同细节，播放时就成了闪烁。必须用时域指标（warping error、tLPIPS）与连续播放盲评。

warping error 怎么解读？

它是把第 t 帧按光流重投影到第 t+1 帧后与目标帧的像素差，衡量运动是否自洽。数值越低越稳。注意要把遮挡区域单独统计或排除——遮挡处本来就没有对应像素，误差天然高，混在一起会误判整体稳定性。

FVD 需要多少样本才可信？

通常需要上百到上千个视频片段才稳定（样本太少方差很大）。它衡量的是生成视频与真实视频在特征空间上的分布距离，反映的是整体真实感，而不是单条视频的时序稳定性；因此应与 warping error、tLPIPS 和人工盲评配合使用。

训练时和推理时提升一致性分别有什么手段？

训练侧：加时域损失（warping loss、相邻帧一致性约束）、使用时序注意力/3D 卷积、用视频数据而非单帧训练；推理侧：用传播/循环结构、光流对齐 + 遮挡检测、对静止区做时域平滑、固定帧率与编码参数。两者叠加效果最好。

时域后处理滤波有什么副作用？

它通过对相邻帧做加权平均来抑制闪烁，代价是运动区域出现拖影/运动模糊，快速运动场景尤其明显。因此通常只对检测为「静止」的区域做滤波，或根据运动强度自适应调整滤波权重。
