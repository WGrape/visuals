后训练 · 方法二

SFT 监督微调
Supervised Fine-Tuning

模型懂很多，但"不会按你的要求做事"？SFT 就是用成对的「指令—示范回答」教它怎么答。 它是几乎所有对话模型的第一道后训练工序——把只会续写的基座模型，变成会听指令的 Instruct 模型。 下面把"loss 到底算在哪几个 token 上""数据怎么拼""训练过程怎么走"一次讲清。

第 1 步 · 定义

SFT 到底在做什么

一句话：给模型看大量「指令 + 标准回答」的样本，让它学会"见到这种指令，就给出这种回答"。 数学上，它和预训练是同一个交叉熵损失——唯一的关键差别是：只让"回答部分"的 token 算 loss，指令部分不算。这个差别叫 loss mask。

和 CPT / 预训练只差在"算哪一段的 loss"

LSFT = − Σt ∈ 回答 log P( wt | w1 … wt−1 )

注意求和范围：只在"回答"那段 token 上累加。指令（prompt）那段被 mask 掉，模型"白看"但不为它付出梯度。这正是 SFT 能学会"格式"而不会过度改写世界观的原因。

图 1：SFT 卡在 CPT 之后、DPO/RL 之前——它是把基座变成对话模型的必经工序
第 2 步 · 动机

为什么光有预训练不够，必须 SFT

预训练教的是"语言规律与知识"，但从没教过"指令 = 任务"这个约定。SFT 干的就是这件事：把"人类想要的回答形式"钉进模型的行为里。

SFT 解决的是
  • 把指令当任务，而不是当文本续写
  • 统一输出格式（Markdown、JSON、分步骤、角色扮演）
  • 学会"拒绝不该答的"、学会"先澄清再答"
  • 把多轮对话、工具调用这类交互范式学会
SFT 解决不了的
  • 注入大量新事实——只会"假装记得"，该用 RAG
  • 让模型"更能探索、更会推理"——它只模仿示范
  • 精细的主观偏好（更幽默、更简洁）——得靠 DPO/RL
  • 知识更新——示范是写死的，改了要重训
一句话定位：SFT 给模型一个"标准样子"。它让模型的输出"大致对、格式对、能对话"，但"好不好、讨不讨喜"要靠后面的偏好对齐去打磨。跳过 SFT 直接做 DPO，几乎一定失败——因为模型还不具备"按指令作答"的基本能力。
第 3 步 · 数据

数据长什么样，loss mask 遮掉了什么

一条 SFT 样本 = 一段指令（prompt）+ 一段示范回答（response）。训练时整条文本一起 tokenize，但只有 response 的 token 带 label，prompt 的 label 被设为 -100（PyTorch 约定：-100 不参与 loss）。

图 2：loss mask——指令部分被遮住，模型只为"回答"付出梯度，这是 SFT 的核心机制

三种常见数据组织方式

组织方式结构何时用
单轮指令对1 个问题 + 1 个标准回答最通用，覆盖大多数任务型数据
多轮对话user / assistant 交替多轮，
每轮 assistant 都标 label		聊天机器人、需要上下文记忆的能力
系统提示 + 样本system 设定角色/规则 + 多轮想固化"人设"或"输出规范"时
最常见的两个数据坑：① 模板不统一——有的样本用 ### 分隔，有的用 JSON，模型会学到混乱的格式约定。建议全量统一一种对话模板（如 ChatML）。② 回答里混了"思考过程"却没标清——如果示范回答包含内部推理，要确认它确实是你想要的 output 形态，否则模型会把它当成必须输出的内容。
第 4 步 · 训练过程

SFT 的完整训练流程

四个环节：数据准备 → 格式化（含 loss mask）→ 训练（超参）→ 评测。其中"格式化时正确打 mask"和"数据质量筛选"是最容易翻车、也最影响上限的两步。

图 3：SFT 四步——②的 mask 打错，模型要么学不会格式，要么把指令也"背"下来

超参取多少

超参常见取值说明
学习率1e-5 ~ 2e-5比预训练小；LoRA 可提到 1e-4 量级
训练轮数1 ~ 3 epoch数据少更怕过拟合，轮数要更少
batch / 累积凑大全局 batch稳定梯度，小显存用 gradient accumulation
序列长度2048 ~ 8192按样本长度分布取，太长浪费算力
warmup + 衰减cosine标准配置，避免初期梯度爆炸
质量 > 数量：SFT 最反直觉的一点——几千条高质量、覆盖到位的数据，往往胜过几百万条噪声数据。高质量指：回答正确、格式统一、分布覆盖你关心的任务。重复、错误、模板混乱的样本会直接拉低天花板。
第 5 步 · 实现

最小可运行实现

SFT 的关键在 data_collator：它要把"指令"那段的 labels 置为 -100。下面用 HuggingFace 生态写一个最小骨架。

from datasets import load_dataset
from transformers import (AutoTokenizer, AutoModelForCausalLM,
                          TrainingArguments, Trainer)

model_id = "Qwen/Qwen2.5-7B-Instruct"   # 也可从 Base 起步，但 Instruct 更稳
tok = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id, torch_dtype="bfloat16")

# 模板：统一用 ChatML 组织指令与回答
def build(ex):
    msgs = [{"role":"user","content":ex["instruction"]},
            {"role":"assistant","content":ex["answer"]}]
    # apply_chat_template 会把对话拼成一段带特殊 token 的文本
    ids = tok.apply_chat_template(msgs, tokenize=True,
                                  add_generation_prompt=False)
    labels = ids.copy()
    # —— 关键：找到 assistant 回答开始的位置，之前全部 mask 成 -100 ——
    prompt_ids = tok.apply_chat_template(
        [{"role":"user","content":ex["instruction"]}],
        tokenize=True, add_generation_prompt=True)
    labels[:len(prompt_ids)] = [-100] * len(prompt_ids)
    return {"input_ids": ids, "labels": labels, "attention_mask": [1]*len(ids)}

ds = load_dataset("json", data_files="data/sft.jsonl")["train"]
ds = ds.map(build, remove_columns=ds.column_names)

args = TrainingArguments(
    output_dir="ckpt/sft",
    learning_rate=2e-5,              # ⚠ SFT 量级
    num_train_epochs=2,
    per_device_train_batch_size=2,
    gradient_accumulation_steps=16,
    warmup_ratio=0.03,
    lr_scheduler_type="cosine",
    bf16=True,
    logging_steps=20,
    save_total_limit=3,
    report_to="none",
)
Trainer(model=model, args=args, train_dataset=ds).train()
如果显存不够：用 PEFT 把模型包成 LoRA（只训 adapter），学习率提到 1e-4 左右，并把 model 设为 gradient_checkpointing=True 省显存。LoRA 还能让你在一条基座上挂多个任务的适配器，按需切换。

评测看三件事

# 1) 指令遵循：是否按要求完成（格式、约束都能对上）
# 2) 格式正确率：JSON 能否解析、Markdown 是否规范
# 3) 能力回归：通用能力/安全性不能因为 SFT 而掉（双轨思想同 CPT）
#
# 自动化可用 ifeval / MT-Bench；主观质量靠人工抽检胜率
第 6 步 · 小结

踩坑清单与一句话总结

常见坑表现怎么解
mask 打错模型把指令也"背"下来，或学不会格式核对 prompt 长度，确认只有 answer 标 label
数据质量差loss 降了但效果没提升先做质量筛选，去重去错，模板统一
过拟合训练集答对、新题答错，还会"复读"减 epoch、加早停、减数据重复、改用 LoRA
只模仿不探索回答"标准"但缺乏灵活性/推理深度复杂推理/探索交给 DPO 或 RLVR
能力回归某项通用能力因 SFT 数据偏斜而下降混入通用指令数据；双轨评测设门槛
用 SFT 灌事实答得自信但记错易变信息易变/需引用的事实交给 RAG

一句话：SFT = 用"指令—示范回答"调交叉熵，只让回答部分算 loss，把"按指令作答"这种行为钉进模型。

它给模型一个"标准样子"：会听指令、格式对、能对话。但它只模仿、不探索，也改不了主观偏好。所以 SFT 之后通常接 DPO/RL 做偏好打磨；而注入新知识不是它的活，那是 CPT 或 RAG 的事。

相关阅读：CPT 继续预训练 · LoRA 参数高效微调 · DPO 直接偏好优化 · 后训练全景

SFT 数据构建与训练参数

SFT 的效果 80% 取决于数据，20% 取决于超参。但超参里也有几个「错了就白训」的硬门槛。

参数常见取值（7B）说明
learning_rate1e-5 ~ 2e-5比 CPT 高一个量级；太小学不会格式，太大崩
epochs2 ~ 3指令数据通常几万到几十万条，2~3 轮足够；>5 轮开始复读
batch size有效 64~128 条小数据用小 batch + 多积累步
max_seq_len2048 / 4096 / 8192按你的数据长度分布定，截断会丢信息
loss 掩码只算 response 部分prompt 部分 mask 掉（mask_input）
packing可选把多条短样本拼到一条，提吞吐；要做 attention 隔离
数据问题表现处理
答案太短模型回复一两句就停筛掉 <50 字的样本；或加「详细回答」类指令
格式不统一输出格式随机统一模板；用同一个 system prompt
答案有错模型学了一堆错的人工抽审 100 条；用强模型打分过滤
多样性不足复读、套模板去重；混入多来源数据；降 epoch
指令过长训练慢、注意力被稀释截断或拆分；把长上下文放文件里
没做 loss mask模型学「续写问题」mask prompt，只让 response 参与 loss

配置示例

# LLaMA-Factory 风格 SFT 配置
model_name_or_path: Qwen/Qwen2.5-7B
stage: sft
finetuning_type: full          # 全参；资源不够用 lora
learning_rate: 1.0e-5
num_train_epochs: 3.0
per_device_train_batch_size: 4
gradient_accumulation_steps: 8   # 有效 batch = 32
lr_scheduler_type: cosine
warmup_ratio: 0.1
bf16: true
max_length: 4096
# 关键：只对 response 计算 loss
mask_input: true                 # 或者模板里指定 response 段

# LoRA（单卡 24G 可跑 7B）
#   finetuning_type: lora
#   lora_rank: 16~64        # 8 太小，128 以上接近全参
#   lora_alpha: 32~128      # 通常 alpha = 2 * rank
#   lora_target: q_proj,v_proj,k_proj,o_proj,gate_proj,up_proj,down_proj
#   learning_rate: 1.0e-4   # LoRA 的 LR 要高一个量级

# 数据格式（sharegpt）
# {"conversations":[
#    {"from":"human","value":"问题"},
#    {"from":"gpt","value":"回答"}],
#  "system":"你是一个..."}
  • 数据量不是越多越好：1000 条高质量数据常常好过 10 万条爬来的。LIMA 论文用 1000 条精心挑选的数据就达到了不错的效果。
  • loss mask 是最容易漏的一步：不 mask prompt，模型会去学「预测用户会问什么」，浪费一半算力还稀释了学习目标。
  • LoRA 的 LR 要高一个量级（1e-4 vs 全参 1e-5），因为新增参数是随机初始化的，需要更大的步长。
  • 先定评估再看 loss：SFT 的 loss 降到 0.5 不代表效果好。必须有一组人工或模型打分的测试题。
  • system prompt 要固定：训练和推理用同一个 system prompt，否则会有分布偏移。
  • 保留一部分「拒答」样本：全是可答样本训出来的模型，遇到不该答的问题也会硬答。
全参微调还是 LoRA？

看三件事：① 数据量——万条以上、要注入大量新知识，全参明显更好；几千条以内、只是调风格格式，LoRA 足够；② 算力——7B 全参 bf16 需要约 8×80G（或 2×80G + 各种 offload），LoRA 单卡 24G 就能跑；③ 部署——LoRA 可以合并回基座，也可以一个基座挂多个 adapter 热切换（多租户场景很有用）。经验：先 LoRA 快速验证数据和流程，确认有效后再上全参冲效果。

为什么训完模型开始复读？

三个常见原因：① epoch 太多——3 轮以上容易让模型记住数据的模式而不是内容，降到 2 轮；② 数据重复——同一段话在数据里出现多次，去重（n-gram 或 embedding 相似度）；③ 解码参数——repetition_penalty 设 1.0（不惩罚），或 temperature 太低（<0.3）会让 greedy 解码走进循环。先查数据，再调解码，最后才动训练。

SFT 数据要多少条才够？

分档看：① 调格式/风格（让它按 JSON 输出、按你的语气说话）→ 500~2000 条就够；② 单任务专精（如客服 FAQ、SQL 生成）→ 5000~2 万条；③ 通用对话能力 → 10 万条以上且要多任务混合。关键是覆盖度而不是条数：如果你的任务有 20 种输入形态，每种至少要有 50~100 条样本，否则那种形态就是盲区。
